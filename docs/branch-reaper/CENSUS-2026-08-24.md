## 1. `git branch --merged` is the wrong instrument here, and it is worth saying why

| probe | result |
| --- | --- |
| `git branch -r --merged origin/main` | **6** |
| `git branch -r --no-merged origin/main` | **3,620** |

Every PR in this repo lands via **squash merge**, which writes a *new* commit onto
`main` whose parent is `main`. The branch tip is therefore never an ancestor of
`main`, so a fully-landed branch reports as unmerged. The 3,620 is an artifact of
the merge strategy, not a backlog of unmerged work. A cleanup driven off
`--merged` deletes nothing; the same cleanup with the test inverted deletes
everything, including live work.

**The criterion used here is PR state read from the GitHub API**, with a content
check behind it.

when its PR is merged. Waiting a week costs nothing; racing an agent still pushing
to a just-merged branch costs a push.

## 3. Two generators, and neither is "we forget to delete branches"

`deleteBranchOnMerge` is **already `true`** on this repo. The accumulation has two
mechanical causes, both measured:

### 3a. `heartbeat/*` — 1,538 branches that cannot be deleted at all

Ruleset **"Heartbeat Branch Protection"** (id `16934633`, `active`) targets
`refs/heads/heartbeat/*` with a `deletion` rule and **zero bypass actors**.

So on every heartbeat flush PR merge, `deleteBranchOnMerge` fires and the ruleset
refuses it. The branch is stranded permanently. The counts confirm the chain:
**1,485 heartbeat flush PRs are MERGED and all 1,538 branches are still present.**

The namespace mixes two different lifetimes under one protection pattern:

- **durable lanes** — ~21 refs (`heartbeat/otto`, `heartbeat/tick-metrics`,
  `heartbeat/society`, and their `-buffer` twins). These park unflushed telemetry.
  Deleting one loses work. **Protection here is correct.**
- **ephemeral flush lanes** — ~1,517 refs matching `heartbeat/<persona>-flush-<sha>`
  (otto 524, alexa 523, soraya 470). These exist to carry one flush PR and are dead
  the moment it merges. **Protection here is the leak.**

### 3b. `automation/pr-archive-*` — 1,880 branches, the fifth accumulation

`.github/workflows/pr-archive-on-merge.yml` pushes one branch per archive run. Its
own header records four prior drains (~4,049 in #6879, 1,132 in #8043, 16 in #9059,
1,229 in #10346) and states of the PAT fix: *"this closes the generator."*

**That claim is falsified by measurement: 1,880 exist today, 1,264 of them with no
PR at all.** The PAT fix worked for what it targeted — archive PRs do now open (33
are open right now) — but opening a PR is not merging one, and an archive PR that
never merges strands its branch exactly as before.

## 5. A P0 found in the inherited gate

`triage-orphan-branches.ts` classifies a branch as safe iff it adds no file whose
basename is absent from `main`. It computes that with
`git diff origin/main...origin/<branch>` under an `allowFail` helper that returns
`""` on error.

`git diff A...B` requires a merge base. **On a shallow clone there is none**, the
command exits non-zero, the helper returns `""`, the absent-file list is empty, and
the branch is classified **SAFE TO DELETE on the basis of a diff that never ran.**

This reproduced here: the first census run on a shallow clone reported
`CONTENT_HELD = 0` across all 3,629 branches. That zero was not a finding — it was
the signature of a dead gate.

Two fixes, both in `branch-reaper.ts`:

1. **The gate fails closed.** A diff that cannot run yields bucket `UNCHECKABLE`,
   which is never reaped, instead of an empty absent-list that reads as safe.
2. **`census` refuses to run on a shallow clone** rather than emit a report whose
   safety column is fiction.

After `git fetch --unshallow`, the gate discriminates: **4 branches moved from
"safe to delete" to `CONTENT_HELD`.** They hold:

| branch | unlanded content |
| --- | --- |
| `agent-heartbeats` | 20+ `docs/agent-heartbeats/otto-windows/2026/05/30/*.md` telemetry files |
| `shadow/society-invariants-maximin-and-hat-residue` | `docs/handoffs/2026-08-01-shadow-to-lior-flat-society-enhancements.md` |
| `chore/081KLL7-post-8992-bookkeeping` | `src/Core.TypeScript/backlog/lint-no-b-refs.ts` |
| `claim/cross-lang-zset-isa-capstone` | six generated `.js` files |

The census also now prints a **vacuity control** — `CONTENT_HELD == 0` across
thousands of branches is indistinguishable from a broken gate, so the report states
whether the gate ever discriminated rather than letting a silent zero imply safety.

## 6. Reversibility, and the restore proof

Every planned deletion is recorded in `planned-deletions.jsonl` with its SHA and a
literal restore command, and **that manifest lands on `main` before any deletion
runs**. A manifest written after a crash-interrupted delete is worthless.

Executed on `dejan/pnpm-off-root-devdeps-to-pages-consumer`
(`a7ac97a61d2a9bd70d793e382a9274e4dc2984ae`):

| step | result |
| --- | --- |
| 1. confirm present | present at `a7ac97a6` |
| 2. `git push origin --delete` | `[deleted]` |
| 3. confirm gone | `ls-remote` returns 0 lines |
| 4. restore from manifest SHA | `[new branch]` |
| 5. confirm present | present |
| 6. diff pre/post `ls-remote` | **identical** |

**The proof caught a real defect on step 4.** The first restore attempt failed and
left the branch deleted: zsh applies its `:r` history modifier to an *unbraced*
parameter expansion, so `"$SHA:refs/heads/$BRANCH"` silently becomes
`<sha>efs/heads/<branch>`.

- literal string, as stored in the manifest — **safe**
- `"${SHA}:refs/heads/${BRANCH}"` — safe
- `"$SHA:refs/heads/$BRANCH"` — **corrupts silently**

Prefer `branch-reaper.ts restore <branch>`, which spawns git with no shell.
A recovery procedure nobody has executed is not a recovery procedure.

## 7. Recommendation for stopping the accumulation

Ranked. Items 1 and 2 are repo-settings changes and are **Aaron's call**.

1. **Narrow the heartbeat ruleset — largest single win, 1,517 refs.**
   Add `refs/heads/heartbeat/*-flush-*` to the ruleset's `exclude` list, keeping
   `deletion` protection on the ~21 durable lanes. `deleteBranchOnMerge` then
   reaps each flush lane on merge and the namespace stops growing.
   *Risk if wrong: a flush lane is deleted while holding unflushed commits. The
   exclude pattern must match only `-flush-` refs; the durable lanes and their
   `-buffer` twins do not contain that token.*

2. **Do not add a scheduled sweep as the primary fix.** A cron sweep treats the
   symptom on a timer and would have been the fifth such drain. Both generators are
   fixable at the source: (1) above, and merging archive PRs.

3. **Make the archive workflow's own branches self-cleaning.** An archive PR that
   is superseded should close *and* delete its branch, rather than leaving a ref no
   `deleteBranchOnMerge` will ever touch.

4. **Run `branch-reaper.ts census` on a cadence as a WATCHDOG, not a reaper** —
   report bucket counts and fail loudly when `NO_PR` or `PROTECTED` grows past a
   threshold. That catches the sixth accumulation in days rather than months.
