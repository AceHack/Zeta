# 081KRA5AR0008QG0R000CYY9ZN — Reversibility laws and FsCheck

## What (bounded slice)

Add FsCheck properties proving the join circuit is logically reversible:

- `reverse (forward wA wB) === (wA, wB)`
- No bit erasure (ancilla count == output count)
- Landauer bit accounting (0 erased bits)

## Deliverable

`ToffoliJoinLaws.fs` with 3-5 properties (green in CI).

## Evidence

- Depends on prior slices' types/encoding
- Validates the formal model before synthesis (.3) or measurement (.4)

Closes the formal gate-network model for join.

## Post-close finding (2026-08-16, shadow) — the zero-erasure acceptance criterion has no falsifier

`081M05M1R97087G0R0023Z4F9D`. The two `Landauer accounting reports zero erased bits` properties
cannot fail: `erasedWireCount` counts wire ids dropped from the wire map, but the interpreter ends
`Map.add step.Target target` and `Map.add` never removes a key, so the key set is invariant under
every possible gate sequence. Mutation-verified — deleting *every gate* leaves both assertions
satisfied.

This does not dispute the model; it records that the "0 erased bits" criterion above was discharged
by the allocator rather than by evidence. The sibling property `... forward then reverse restores
retained wires` is a real falsifier and carries the reversibility claim.

Context: `docs/research/2026-08-16-fpga-toffoli-zset-join-synthesis-design-bennett-uncompute-is-clean-ancilla-is-quadratic-and-cmos-cannot-measure-landauer.md` section 4.

## Post-close investigation (2026-08-16, shadow) — RECOMMENDATION ONLY, no status changed

`081M05M1R97087G0R0023Z4F9D` is now fixed, and the fix makes it possible to say exactly what
discharged each of this row's three acceptance criteria. **`status: closed` is untouched here and
this section changes no register field.** Register status is the maintainer's call; what follows is

### What each criterion actually rests on

| criterion, as written above | what discharged it | verdict |
|---|---|---|
| `reverse (forward wA wB) === (wA, wB)` | `... forward then reverse restores retained wires` / `Join circuit forward then reverse restores all wires` | **true, but insensitive to the circuit.** Every `ToffoliGateStep` is an involution (no step targets one of its own controls) and the reverse-order composition of involutions is the inverse — so this holds for *every* gate list, the empty one included. Mutation-verified 2026-08-16: it survives all five mutants, including delete-every-gate. The merged PR #10942 credited it as "a real falsifier … doing the work"; **that was over-generous and is corrected in §4.1 of the design doc.** |
| "No bit erasure (ancilla count == output count)" | the conjunct `Circuit.Ancilla = Map.count initial` | **not implemented as written; tautological as implemented.** `Ancilla` is `nextWire`, which counts `takeWire` calls, which is the map size — it compares capacity with itself. It never compares an ancilla count with an output count, and before today the model had no ancilla/output distinction to compare. |
| "Landauer bit accounting (0 erased bits)" | `erasedWireCount … = 0` | **vacuous, and now known to be FALSE of this row's deliverable.** |

### Does the corrected accounting discharge the row? The answer splits, and the split matters

- **`modelJoinCircuit` — the artifact this row shipped — has garbage > 0**, by construction. It is a
  keep-all-garbage circuit with no uncompute pass: every partial product and every carry ends dirty.
  So criterion 3 was not merely unmeasured. Measured correctly, **it is false of the deliverable.**
- **`modelJoinCircuitUncomputed` — added 2026-08-16 — has garbage = 0**, mutation-proven in both
  directions (M4 skip-uncompute and M5 dirty-ancilla both drive it positive; M1/M2/M3 are caught by
  the paired product oracle). Criterion 3 is true of *that*, dated **2026-08-16**, not 2026-06-19.

**The model is not wrong.** `modelWeightMul` is a valid reversible network and its own docstring
claims only that the retained wires carry the inverse function — which is true. The error is one of
**scope**: an internal-bijection statement was used to discharge a **boundary** criterion it does
not reach. Flagging that distinction rather than a model defect is the honest finding, and it is why
this was fixed rather than escalated.

### Recommendation (maintainer decides)

**Preferred: leave `status: closed`; amend the criteria in place rather than reopening.** The row's
deliverable exists and is green; the gap it left is filled as of today by a follow-on change that
carries its own evidence. Reopening would report the history inaccurately — the work was done, the
*criterion wording* was the defect. Concretely:

1. Restate criterion 3 as *"Bennett-scheduled join returns every ancilla to its allocation value,
   paired with an independent product oracle"* and record its discharge date as **2026-08-16**.
2. Retire criterion 2 (`ancilla count == output count`) as **never well-posed** — it is not a
   property anyone wants; the property wanted is criterion 3. Do not resurrect it.
3. Keep criterion 1, annotated as an interpreter-level theorem rather than a circuit-level
   falsifier, so nothing downstream cites it as evidence about the circuit again.

**The alternative** — reopen for criterion 3 — is defensible if the register's rule is that a row
may not stay closed on a criterion that was false at close time. That is a governance question, not
an engineering one, which is exactly why it is not decided here.

**Register:** the corrected accounting is `metered` as a **bit count** (falsifier demonstrated both
directions). It is not a joule measurement, and it changes nothing in §8 of the design doc.
