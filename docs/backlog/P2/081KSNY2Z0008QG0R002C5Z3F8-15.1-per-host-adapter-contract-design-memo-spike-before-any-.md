## Acceptance criteria

Design memo at `docs/research/2026-XX-XX-per-host-adapter-contract-design.md` covering:

1. **Adapter interface signature** — what every per-host adapter must implement (CI runtime invocation, status-check emission, branch-protection read/write, webhook delivery, authentication)
2. **Core-vs-adapter boundary discipline** — what the core CAN call into the adapter; what the adapter CANNOT inject back into core; how status events get normalized into core's vocabulary
3. **Anti-leak invariants** — explicit list of host-specific concepts that MUST NOT appear in core (e.g., "PR number," "MR IID," "pipeline ID" — replaced by Zeta-internal equivalents)
4. **Adapter test contract** — each adapter must pass the same observable-behavior test suite for the same agent-loop operations
5. **Failure-mode discipline** — how an adapter signals "this host doesn't support X" and how core gracefully degrades
