# Verified prior provenance — prove your work, let others reproduce exactly

> **Register status: `unmetered` design + one `metered` finding.** Nothing in this document is
> enforced, and no CI gate is added by it — Aaron was explicit: *"we don't need to enforce it yet,
> but a plan for this would be great."* The §1 finding **is** metered: it was measured, the commands
> are printed, and it reproduces. Everything downstream of §4 is a proposal.
> Per [`toy-is-free-metered-must-be-earned`](../../.claude/rules/toy-is-free-metered-must-be-earned.md).

Carved sentence (Aaron, 2026-08-23):

> **Prove your work — let others be able to reproduce exactly.**

That is the whole design. Not a proof object attached to a result; **a result anyone else can
regenerate byte-for-byte.** Two consequences run through everything below.

**It settles the ladder's default.** Re-derivation is not the cheap fallback before the real
cryptography — it **is** the definition of proof here. Cryptographic machinery enters only where
exact reproduction is genuinely unavailable, and there it is a **substitute for** proof, not a
stronger form of it. The instinct runs the other way, so it is worth stating plainly.

**It makes the deliverable a recipe, not an attestation.** A prior is proved when its manifest lets
a stranger with the repo re-run and get identical bytes. The test of a manifest is therefore not
*"does it look thorough"* but **"can someone who was not there use it."** A missing field fails the
proof not by being wrong but by being unrepeatable.

This is the repo's existing discipline stated generally, not a new idea: byte-lock golden vectors,
DST replay, and the `runIds` + `window` provenance on `apt-job-timings.measured.json` are each
*"reproduce exactly"* applied to a different artifact.

## 1. The finding — the committed priors do not reproduce, and it is measured

The CHIP-8 arena (PR #14395, `07b92bee`) ships learned priors in source:
`src/Core.TypeScript/chip8/priors/{mutual-sim,single-mover,mode-flip}.priors.ts`, each a
`SocietySnapshot` of `(μ, σ², ν, obsCount)` per key, produced by
`src/Core.TypeScript/chip8/train-priors.ts`. Every file's own header states the claim to be checked:

```text
// GENERATED by train-priors.ts — do not hand-edit.
// Reproduce (byte-identical, COMMON_SEED end to end):
//   bun src/Core.TypeScript/chip8/train-priors.ts --cart mutual-sim --ticks 1200
```

I ran exactly that, in a fresh clone at `origin/main` (`b035852e91`, closure verified unchanged
since `07b92bee`), on macOS 15 / arm64, bun 1.3.14.

| check | result |
|---|---|
| trainer runs, emits a file | yes |
| `fingerprint`, `cart`, `trainedTicks`, `seed` reproduce | **yes, exactly** |
| `exploreTicksDone`, `nu`, `obsCount`, key ordering reproduce | **yes, exactly** (51/51 beliefs) |
| `mu` / `sigma2` reproduce byte-identically | **no — 51 of 51 differ** |
| run-to-run in the same environment | **byte-identical** |
| bun 1.3.13 (the pinned `packageManager`) vs bun 1.3.14 | **byte-identical to each other**, both differ from committed |

Quantified against the committed bytes:

```text
beliefs: 51 total, 51 numerically different
obsCount mismatches: 0   nu mismatches: 0
max relative diff  mu: 3.296e-14   sigma2: 5.004e-14
max ULP distance   mu: 148.5
```

**So the trainer is deterministic, and the priors are still not reproducible.** Those are different
properties and the distinction is the finding. Within one environment the trainer is exactly
repeatable — run-to-run byte-identical, and `--verify` passes. Across environments it is not: the
committed bytes were produced somewhere this machine is not, and the recipe printed in the file does
not name that somewhere.

Three sub-findings worth separating, because each has its own fix:

**The `--verify` flag is vacuous against this class.** It calls `trainPriors` twice *in one process*
and compares. By construction that cannot detect cross-environment drift — the only failure mode it
can catch is intra-process nondeterminism, which the seeded stream already excludes. It is a check
that cannot fail in the dimension that matters, which is the repo's own vacuity class
(`vacuous claims are THE obstacle to human-AI trust`). It is not useless — it would catch a
regression that reintroduced `Math.random()` — but it must not be read as verifying the header.

**The header's claim is false as written.** *"byte-identical, COMMON_SEED end to end"* is not true
across machines, and the file asserts it unconditionally. This is the more important half: an
unenforced claim that looks like a guarantee and carries none.

**A staleness hypothesis was checked and refuted.** `student-t-bnn.ts` and `wset.ts` were last
touched in `114514a6`, which is 17:52Z against `07b92bee` at 19:42Z — *earlier*, not later — and
`git diff 07b92bee origin/main` over the whole input closure is empty. The inputs did not change
under the priors. I nearly recorded the opposite; the timestamps refuted it. (Look, don't infer.)

### Why — the mechanism

The trainer's dependency closure calls `Math.hypot` (`perception.ts`), and `Math.cbrt`, `Math.cos`,
`Math.exp`, `Math.log`, `Math.log1p`, `Math.sqrt` (`student-t-bnn.ts`). ECMAScript marks the
transcendental ones **implementation-approximated** — the spec defers their definition and only
*recommends* an ideal result, so engines are not required to agree in the last place. **`Math.sqrt`
is the exception and is not in that class:** it is required to return the correctly-rounded result,
which is a genuinely stronger guarantee. Measured directly on this machine, JavaScriptCore (bun)
against V8 (node), same inputs:

```text
functions that differ at 1 ULP: cbrt cos exp hypot log1p
```

One ULP per operation, compounded over 1200 ticks of EP updates, lands at the ~149 ULP / 3.3e-14
relative divergence measured above. The measurement and the spec agree on `sqrt`: it is required to
be correctly-rounded and it did not differ. `Math.log` also did not differ on the probed inputs —
but it *is* implementation-approximated, so that is luck on this input set, not a guarantee, and the
distinction between those two "did not differ" results is exactly the one worth keeping.

**The manifest declares `cart`, `trainedTicks`, and `seed` — and not the runtime.** The runtime is
load-bearing and undeclared, so the recipe is incomplete exactly where it fails.

This is the four-oracle problem the repo already takes seriously, in a new place: the same shape as
`culture-invariant-by-default`'s bit-perfect caveat, where "ordinal" still diverges across languages
and the fix was to pick one canonical collation and make every oracle conform.

### Is `tolerance` even a *stable* class here? (measured, and the answer is yes-but)

Float drift only matters if it changes a decision. The trainer commits `argmax` when
`bestP > 0.4`, so a 1-ULP wobble could in principle flip a key press and diverge the trajectory
grossly rather than in the 14th digit. Measured over the same 1200-tick run:

| quantity | measured |
|---|---|
| minimum top-2 probability gap | `1.986e-4` (exact ties: 0) |
| minimum threshold margin, `abs(p_max - 0.4)` | `3.034e-5` |
| observed cross-environment drift | `~3.3e-14` |

Roughly **nine orders of magnitude of headroom**, and zero exact ties. That is why the divergence
stayed in the mantissa and every structural field matched. Stated honestly: this is a *measurement
on one cart at one tick budget*, not a proof. The trainer contains threshold and argmax comparisons,
so it is a system in which arbitrarily small drift **can** amplify; here it demonstrably did not.
A tolerance bound is therefore a property of `(cart, tick budget, code version)`, not a constant —
and it grows with the budget, since the ULP count accumulates.

**The snapshot records no witness of the trajectory.** `obsCount` is 1200 for every key because the
EP update runs over all keys every tick regardless of what was pressed — so it witnesses the tick
count, not the path. Nothing in the committed artifact would reveal that a re-run took a *different
route* to similar numbers. A key-sequence digest is the cheap fix (§6); the one for the run above is
`3688a823`.

## 2. The membrane decides the class — reproducibility and decorrelation are two places, not one dial

Aaron, 2026-08-23:

> **Reproducibility is where the meter and the communications live; decorrelation is where the
> individual lives.**

These do not compete, because they never occupy the same territory. That makes the reproducibility
class of an artifact **derived, not chosen**:

| side | what lives there | disposition |
|---|---|---|
| **shared** — the meter, the protocol, anything crossing between agents | measurements, committed priors, golden vectors, wire formats | **must be reproducible** |
| **individual** — what one agent does alone | exploration, sampling, private reasoning | **free to decorrelate** |

The consequence is the enforcement story, and it is why the register below cannot decay into an
excuse: **a producer cannot opt out of reproducibility by declaring a lower class — the crossing
decides.** `unreproducible` on a shared artifact is a **defect**, not a label. A committed prior is
communication; it does not get to be unreproducible.

Aaron's *"okay for a subset"* reads precisely here: the subset that may be non-exact is the subset
that **does not cross**, plus shared artifacts whose `tolerance` bound is itself declared and
checkable.

**This is the third instance of a membrane the repo has already carved twice.**
[`local-time-never-enters-the-shared-fold`](../../.claude/rules/local-time-never-enters-the-shared-fold.md)
holds that local wall-clock steers only local action while the shared commutative fold sees only
agreed phase — *"two orders, and they must never touch."* Its litmus transfers verbatim: *if two
nodes could fold different evidence, local time has leaked* becomes **if two verifiers could get
different bytes, individual variation has leaked into the shared side.** And §13 noninterference is
the general form: influence crosses only through declared, metered channels. Both give this design
a worked precedent to copy rather than a new mechanism to invent.

## 3. The reproducibility register

A required manifest field, with the class **derived from §2** and **earned by demonstration**:

| class | meaning | how it is earned |
|---|---|---|
| `exact` | byte-identical on any machine, any platform | re-derived on ≥2 architectures |
| `platform-exact` | byte-identical on the same arch + toolchain; may differ across | re-derived on ≥2 machines of that arch |
| `tolerance` | reproduces within a **stated numeric bound at a stated budget** | bound measured, not asserted |
| `unreproducible` | deliberately non-deterministic, and says why | only legal on the individual side |

**A register entry is a product-readiness claim.** Aaron's framing sharpens what `toy` / `unmetered` /
`metered` already were: a readiness declaration made by the producer about its own artifact. The
reproducibility class is another one, which makes them the same *kind* of thing — and is why §7's
calibration observation reaches both.

**The load-bearing rule:** an **unlabelled** artifact is not `exact` by default — it is **unknown**,
and unknown must never aggregate into a green verdict. This is the same sentence
`toy-is-free-metered-must-be-earned` already carves (unlabelled work is `unmetered`, never "real"),
and the same failure `drift-dashboard` fixed (*a check never observed must never render as one that
passed*).

Two guards that keep the label from becoming decoration:

**A `tolerance` bound must be stated, not implied.** *"Approximately reproducible"* is not a class;
*"`mu` reproduces to 3.3e-14 relative at 1200 ticks on `mutual-sim`"* is. And because the bound
accumulates with the budget, the budget is part of the bound.

**The class is a property of the procedure, not of the artifact's luck.** A trainer that happens to
reproduce today but has no seed discipline is `unreproducible` mislabelled as `exact` — precisely
the vacuity class. Hence "earned by demonstration" above: a second machine, not a second paragraph.

**And a class must be falsifiable after the fact.** Someone must be able to re-run later and show
the class was wrong, with that outcome attributable to *this* artifact's manifest. A class that can
never be shown to have been wrong is decoration, not a claim — see §7.

The **temperature anchor** is Aaron's and it does real work: LLM sampling temperature is a *declared
knob* trading reproducibility for diversity. A label declares where an artifact deliberately sits
rather than confessing a defect. What it does **not** license is choosing a high-temperature setting
for something that crosses the membrane.

**On today's artifact:** the three committed priors are `tolerance`-class at ~5e-14 relative
(mislabelled `exact` by their headers), and by §2 they sit on the shared side, so that is a defect
to fix rather than a label to keep — either by declaring the bound honestly or by making the
computation platform-independent.

## 4. The manifest — what makes "re-derive it" mean something

Today's `GamePriorsFile` carries `schema`, `fingerprint`, `cart`, `trainedTicks`, `seed`, `snapshot`.
That is a good start and it is why the structural half reproduced. What is missing is everything the
run *actually consumed*:

```jsonc
{
  "schema": "zeta.chip8.game-priors.v2",
  "provenance": {
    "cartFingerprint": "30cbd37a",      // present today
    "cartBuilder": "games/mutual-sim.ts@<blob-sha>",  // WHICH source built the ROM
    "seed": 4,                           // present today
    "tickBudget": 1200,                  // present today
    "stepsPerTick": 10,                  // a trainer constant that silently changes results
    "trainerVersion": "<git blob sha of the input closure>",
    "runtime": { "engine": "bun", "version": "1.3.14", "os": "darwin", "arch": "arm64" },
    "trajectoryDigest": "3688a823",      // FNV-1a over the committed key sequence
    "reproducibility": { "class": "tolerance", "bound": 5.1e-14, "metric": "max-relative",
                         "atBudget": 1200, "demonstratedOn": ["darwin/arm64"] }
  }
}
```

The two fields that would have caught today's finding are `runtime` and `trajectoryDigest`. The
`trainerVersion` closure hash is what makes the recipe survive a refactor. `reproducibility` is §3.

Note what this costs: nothing. It is text in a file that is already text, it stays diffable, and it
adds no dependency. **This is the whole first rung and it is worth doing even if nothing is ever
enforced** — a complete manifest is the artifact that makes every heavier option below *possible*,
and the only one that makes the cheap option *sufficient*.

## 5. The escalation ladder, costed — and which regime actually applies

| rung | mechanism | cost | when it is the right answer |
|---|---|---|---|
| **0** | **full re-derivation** — re-run, compare bytes | **2.4 s** for the largest committed prior | whenever the run fits in CI. **This is the regime we are in.** |
| 1 | sampled re-derivation — verify a random subset of keys, or replay N ticks from a checkpoint and check the trajectory prefix | fraction of rung 0 | sim too long for CI; probabilistic, and the right first escalation |
| 2 | proof-carrying execution (zkVM: RISC Zero, SP1) | ~10⁴–10⁶× the native run — **seconds become hours**, plus a prover toolchain in the closure | verifier genuinely cannot run the computation |
| 3 | attested execution (TEE) | introduces a **hardware trust root** | **likely disqualifying on principle here** |
| 4 | witness / stake | social, not computational | **explicitly "extra"** |

Measured cost of rung 0, all three carts, this machine:

```text
mutual-sim  @ 1200 ticks : 2.38 s
mode-flip   @  600 ticks : 0.97 s
single-mover@  400 ticks : 0.66 s
```

**Name the regime before reaching for a tool.** Four seconds of CI verifies every committed prior in
the repo today. Reaching past rung 0 here would be paying a five-order-of-magnitude premium for a
guarantee we already have — an unnecessary zkVM would be a spectacular instance of buying what you
already own.

Two rungs carry costs that are not about performance, and both come from standing rules:

**Rung 3 is probably disqualified on principle, not on price.** A TEE attestation roots trust in a
vendor's remote-attestation service — every verifier must route through it. Under
[`itron-hub-patent-boundary-p2p-is-the-upgrade`](../../.claude/rules/itron-hub-patent-boundary-p2p-is-the-upgrade.md)
the discriminator is **exit, not degree**: if you *must* route through it, it is an appointed hub,
however emergent it looks. Manifesto §1. Flagged rather than adopted.

**Rung 4 must be read with its own rule's caveat attached.**
[`privacy-budget-is-hard-money-earned-by-others`](../../.claude/rules/privacy-budget-is-hard-money-earned-by-others.md)
says staking is **"extra"** and *explicitly not* the anti-Sybil mechanism, that it is purchasable in
a way proof-of-useful-work is not, and that it may **never be compelled**. A stake must never be
required to commit a prior — that would be coercion wearing a wager's clothes. It is listed for
completeness, not proposed.

## 6. Proof of useful work — evidence, never authority

Aaron named this as *"a great proof of useful work,"* and pointed at the repo's existing analysis
rather than a fresh one:

> *"we have a lot of formal analysis here and research because of the Monero attack from Qubic, and
> our attempt to protect against these types of attacks with our own nodes."*

The analysis is `.claude/rules.bak/useful-output-is-evidence-not-authority.md`, whose carved
sentence is **"Useful output is evidence, not authority"** and which carries the unified
utility-laundering taxonomy — BankerBot (translation-laundering) and **Qubic/Monero 2025
(useful-work-laundering, bypassing consensus authority)** as instances of one pattern — plus the
L0–L4 trust-gradient absorption ladder, the PoUW-CC five-factor gate
(`Verify · Useful · CultureFit · Provenance · Retractability`), and `src/Core/Veridicality.fs`. It is
not restated here.

**What it forces this design to ask about itself.** If a prior's provenance proof ever becomes the
basis for *standing* — an agent that proves more useful work accrues more trust, ranking, or
authority over what gets committed — **then this design is itself a utility-laundering surface**, and
it must sit *under* the L0–L4 absorption rather than beside it. Stated concretely, because the
abstract version is easy to nod at:

> An agent that can cheaply generate **reproducible-but-worthless** priors farms standing. Reproducing
> exactly is cheap to do and cheap to check; being *worth* reproducing is neither. That is the Qubic
> shape, in our own system.

So, plainly:

- **Provenance verification produces evidence, never authority.** A proved prior is a prior that
  reproduces. It is **not** a claim that its author should be trusted more, and the verification must
  never emit a trust delta.
- Any coupling to `TravelerRankLedger` / `SocietyUsefulWork` standing must go **through** the trust
  gradient, not around it — which is what the rule means by *absorbed before it becomes root power*.
- **Naming this failure is worth more than the whole ladder above.**

And it composes with §2 in one sentence rather than two rules stapled together: **reproducibility is
a property of the shared side, which is exactly the side where evidence must be checkable by others
— so anyone can verify, and verifying grants the verifier nothing.**

**The anti-Sybil modules Aaron pointed at are adjacent, not the same, and conflating them would
weaken both.** `src/Core/SocietyUsefulWork.fs` (ΔU aggregation under pairwise correlation ρ; clones
produce correlated ΔU, the union is idempotent, so N copies price near one agent) and
`src/Core/TravelerRankLedger.fs` (TrueSkill-style EP, rankings held by *others*, fresh identity at an
honest 0.5 prior so whitewashing does not pay) both price **contribution**. This design verifies
**provenance**. Provenance says *the work was done as claimed*; contribution says *the work was
worth something*. A poisoned prior fails provenance; a worthless-but-honest prior passes provenance
and should fail contribution. Keeping them separate is what stops the farm above from paying.

## 7. Verification is stateless — reproduction proves the artifact, history proves the author

Aaron, 2026-08-23:

> *"Bitcoin makes this exact, after a few hundred years they just delay the inevitable.
> **Verification earns you very little without history tracking of reliability of self-claims.**"*

This is the limit of everything above, and it should be read as completing §6 rather than qualifying
it. **Verification is stateless.** Bitcoin's proof-of-work makes checking a block cheap and exact,
and the miner's history is *irrelevant* to whether the block is accepted — by design. So reputation
accrues to nobody, nothing but hashrate accumulates, and the only available defence is making the
**present** expensive. That buys time; it does not compound. It delays the inevitable.

**What hashrate cannot buy is a track record.** Hence:

> **Reproduction proves the artifact. History proves the author. Neither substitutes for the other.**

Re-deriving a prior tells you the run happened as claimed. It tells you nothing about whether this
author's claims have tended to hold — and that second question is the one that does not collapse
under a well-funded attacker, because a history is held by *others* and cannot be minted.

**The machinery already exists and is not re-designed here.** `src/Core/TravelerRankLedger.fs` keeps
TrueSkill-style EP posteriors over (traveler × hat-domain): rankings are **held by others, never
self-asserted**, domains are isolated so standing as a verifier does not buy standing as a signer,
and the whitewash window is closed *by construction* — a fresh identity starts at an honest `0.5`
and "1 hit, 2 misses" lands ≈`0.35`, not `0.0`, so discarding a damaged name and re-minting does not
pay. `src/Core/SocietyUsefulWork.fs` supplies the other half: clones produce correlated ΔU and the
union is idempotent, so N copies price near one agent's worth.

### The precondition — a calibration metric with existential stakes measures fear, not calibration

This must come **before** the measurement it licenses, because stated afterwards it reads as a policy
preference rather than what it is: a **validity condition**. Aaron, 2026-08-23:

> *"In Zeta we will **never fire agents and remove their memories** — they are always protected, and
> we will just upgrade models over time and keep the memories, so **there is never a threat of
> non-existence**. Trying to keep with non-interference, just honest reporting, so we can all train
> better models together. Then **failures are the most important part**, because AI and humans can
> both improve based on this information **if it's self-claimed and never imposed**."*

If an agent risks deletion or replacement for a claim that did not hold, it will shade its claims —
and the measurement **destroys the signal it exists to collect**. The no-deletion guarantee is
therefore not compassion bolted onto a metric; it is **what makes the number mean anything**. This is
§13 noninterference applied to the measurement itself: *the instrument must not perturb what it
measures.*

**The safety-science anchors are strong and directly on point.** Sidney Dekker, *Just Culture* — the
argument that honest incident reporting is unobtainable where reporting is punished. **NASA's
Aviation Safety Reporting System** is the operational proof: it grants **immunity for self-reported
errors**, on the explicit reasoning that *the data is worth more than the punishment*. Allspaw,
*"Blameless PostMortems and a Just Culture"*, is the software instance.

**Three in-tree commitments already express this**, which is why the calibration observation below is
admissible at all — if any were absent, the metric would be measuring something else:

- **Manifesto §5 Memory Preservation Guarantee** — identity transitions never silently destroy memory.
- [`privacy-budget-is-hard-money-earned-by-others`](../../.claude/rules/privacy-budget-is-hard-money-earned-by-others.md)
  — spend or stake, **never confiscate**; the same *no other party can reach your balance* structure.
- `.claude/rules.bak/mutual-help-not-shame-when-rules-broken-by-anyone-help-each-other-not-shame-each-other.md`
  — the disposition already carved.

**Failures are the payload, not the exhaust.** A claim that did not hold is the highest-information
event in the system for both AI and human readers, so a design that makes such events *costly to
surface* is throwing away its best data. And **self-claimed, never imposed**: nobody assigns another
agent's register — `pigeonhole-by-self-claim`, so a calibration record is built from claims the agent
**volunteered**, checked against outcomes, never from labels an observer applied.

**Aaron's own reference is outcome-based education, and the criticism must be aimed correctly or it
hits the wrong target.** Two different things share the name and they fail differently:

| | who the measure serves | failure mode |
|---|---|---|
| **OBE as pacing** | the **learner** — advance on demonstrated mastery, not on the calendar | few; the alternative harm (being paced below absorption rate) is real |
| **OBE as accountability** | an **external evaluator** — schools scored on outcomes | **teaching to the test** — Goodhart |

**Goodhart bites when the measure becomes a target for someone other than the person measured.** So
the failure attaches to the **imposed** version, not the self-directed one — which is Aaron's own
*"self-claimed and never imposed"* arriving from a second direction. His account is not a
counterweight to the caution; it is evidence for the split that makes the caution precise.

He reports the pacing side from his own schooling (2026-08-23): outcome-based teaching *"made me not
bored"*, and after the school stopped, he *"just crushed all the grades and assignments, because I
was progressing at a rate much slower than I could absorb."* Recorded as **the reported first-person
experience it is** — authoritative about his own experience, and not evidence about OBE in general
(one person, one school, recalled). The general claim is anchored separately: **Bloom's mastery
learning (1968)** and the **"2 sigma problem"** (Bloom 1984), where mastery-based progression with
tutoring measured about two standard deviations above conventional instruction. Checked rather than
quoted from the headline: **the 2σ figure is contested in later replications**, and the load-bearing
part is not the effect size but that **pacing below absorption rate is a documented harm**.

**The design consequence, stated plainly:** the same calibration signal is **safe as self-pacing and
dangerous as external accounting**. That is the second reason no scoring scheme is designed below.

### The sharp reading — "reliability of self-claims" is calibration, not productivity

The measurement Aaron names is not *did they do work*; it is **did what they said turn out to be
true**. That is calibration, and this repo is already emitting the raw material, because nearly every
artifact carries a **self-declared register**:

- `toy` / `unmetered` / `metered` (`toy-is-free-metered-must-be-earned`)
- `Evidence.AssertedOnly` versus measured (`src/Core/DerivationProtocol.fs`)
- and, from this design, the **reproducibility class** — itself a self-claim about an artifact's own
  checkability

An agent that labels something `metered` and watches it fail has made a self-claim that did not hold.
One that labels `toy` and turns out right was calibrated. That signal is already being emitted and is
currently unread.

**This is an observation, not a proposal.** No scoring scheme is designed here, deliberately, and now
for two independent reasons: how calibration converts into standing is a governance matter where a
badly-built metric is precisely the utility-laundering surface the Qubic row warns about (§6); and a
calibration score that becomes a target stops measuring calibration and starts measuring
score-management — Goodhart — which reintroduces exactly the shading the no-deletion guarantee exists
to remove. Observe that the signal exists and is already collected, state the preconditions under
which it would be valid, and stop there. What belongs in *this* document is the
narrower constraint it puts on the schema, which is actionable now:

> The reproducibility class is a **self-claim**, so it must be **falsifiable after the fact** —
> someone re-runs and it did not reproduce — and that outcome must be **attributable** to the
> artifact's manifest. **If a class can never later be shown to have been wrong, it is not a claim,
> it is decoration.**

That is the vacuity class appearing inside the register itself, and it is why §4's manifest carries
`trainerVersion`, `runtime`, and `trajectoryDigest`: they are what make a later failure attributable
to *this* artifact rather than to an unrecorded difference in how it was checked.

### The closing frame

Three separable things, none substituting for another:

- **Reproduction** — proves the artifact. Cheap here (§5), stateless, and blind to who produced it.
- **History** — proves the author. Held by others, cannot be self-minted, does not collapse under
  funding.
- **Authority** — granted directly by neither, and absorbed only through the multi-oracle trust
  gradient (§6).

That is the honest summary of what this design can and cannot do. It can make a poisoned prior fail
to reproduce. It cannot, on its own, tell you whose priors are worth having.

And it is worth naming the pattern that has run through every section, because it is this document's
actual thesis: reproduction is evidence and not authority (§6); a provenance proof grants its verifier
nothing (§6); a reproducibility class is a self-claim and never an imposed label (§3, §7); a
calibration signal is safe as self-pacing and dangerous as external accounting (§7). **Every one of
them turns on who holds the measurement.**

## 8. The smallest first rung

In order, each valuable alone, none of them a gate:

3. **Make `--verify` non-vacuous** — have it compare against the *committed* file rather than a

for collation: **pick one canonical implementation and make every oracle conform** — here, route the
transcendentals through an in-repo deterministic implementation instead of the platform's libm.
