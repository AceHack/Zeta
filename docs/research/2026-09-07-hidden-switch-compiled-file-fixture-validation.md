The [file fixture module](../../src/Interp.Python/zeta_interp/hidden_switch_compiled_file_fixtures.py)
implements the remaining seven filesystem cases and eleven counted storage
operations. Setup, observations and explicit injected faults remain separately
recorded. Each operation returns its real typed API result before subsequent
audit steps. An after-observation failure retains that result and its completed
operation count. A crash, missing return or untyped return leaves the count zero
while retaining any observed return, fault events and file state.

The partial-write fixture writes the actual prefix `ori`, injects its primary
write failure, and observes the same prefix after a second exclusive write
refuses. The changed-read fixture changes `original` to same-length `ORIGINAL`
after the target's first actual metadata observation; the real reader refuses
the changed file. Hooks identify only the owned target inode, delegate unrelated
descriptors and restore the previous functions. A process-local lock prevents
overlapping fixture hooks. These untimed fault fixtures are not attack-rate or
storage-performance measurements.

The artifact cases exercise an actual owned symlink and an actual truncated
gzip file. Files and failed roots remain in place. Input/audit bytes are
finalized from the actual observations after they exist; callers must retain
each returned result before proceeding. OS identities and paths remain raw.
The helper limits observed file content to 256 bytes and finalized fixture JSON
to one MiB. The final coordinator's aggregate retention quota is separate.
