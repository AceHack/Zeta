## The One-Sentence Version

A compiled Bayesian inference program over categorical tensors is a `DynamicValue` — a value, not code — so it can be interned in an ephemeron table, collected by Shiva when unused, and regenerated by Brahma on demand, because the generator is the error-correcting code.

## Layer 1: The Computation — BNN over Categorical Tensors

The foundation is `WSet<'K,'W>` in `src/Core/WSet.fs`: a weighted set where the weight type `'W` lives in any `IStarRing<'W>`. The ring is a type parameter, not a hardcoded number type. Swap the ring and the same message-passing machinery computes different math:

| Ring | File | What it computes |
|---|---|---|
| `Real.algebra` | `src/Core/CayleyDickson.fs:90` | Standard Bayesian inference (float) |
| `ImaginaryStack.complex` | `src/Core/CayleyDickson.fs:122` | Quantum amplitude (Born probabilities) |
| `ProbabilitySemiring` | `src/Core/WSet.fs` | Exact rational probability |

The three wiring primitives on `WSet` form a comonoid (`WSet.Comonoid.Laws.Tests.fs` verifies the laws):

- `WSet.copy` (line 76): fan-out Δ — broadcast a value to multiple downstream factors
- `WSet.tensor` (line 88): Kronecker ⊗ — combine two WSets over the product key space
- `WSet.discard` (line 82): marginalise ε — project out all keys, summing weights

These are exactly the wiring primitives a neural network needs. A single factor-graph cell (`src/Bayesian/MinimalBnn.fs`) equipped with copy/discard/tensor is a composable layer. Stack N cells and you have a multilayer Bayesian neural network over categorical tensors.

The underlying algorithm is the **Generalized Distributive Law** (Aji–McEliece 2000): sum-product message passing over a commutative semiring. BP, EP (Minka 2001), and VMP are three approximation strategies applied to the same structure. The `MinimalBnn.update` function absorbs one observation and updates the posterior in a single call — training and inference are the same message pass.

**Honest scope boundary:** The multilayer composition (N-layer stack with full EP backward pass through all layers) is the next engineering step. `MinimalBnn.fs` is a one-layer cell. The claim "a multilayer factor graph over categorical tensors IS a BNN" is mathematically correct; the N-layer module is not yet shipped.

## Layer 2: The Compiler — Futamura Specialization as Data

The standard Futamura projections describe what a partial evaluator (mix) can do:

1. `mix(program, static-input)` → residual (a specialised program)
2. `mix(mix, interpreter)` → compiler (a specialised mix)
3. `mix(mix, mix)` → cogen (a compiler-compiler)

The Zeta move was to make the specializer's own rules — `MixIr.defaultMixDef`, `evalDef`, `specs` — `DynamicValue`, not baked code. This is the "mix-as-data" slices described in `src/Core/ShivaGc.fs` (Aaron, 2026-07-03).

`src/Core/MixIr.fs` implements the mix IR: ISA-agnostic load descriptors (`chip8Load`, `mos6502Load`) as `DynamicValue.Object` records. The materialization strategy (how to emit a load for a given ISA) is itself a `DynamicValue` — data that can be inspected, collected, and regenerated. `src/Core/SpecializationCache.fs` wraps the specializer in a `WeakReference<'TInput -> 'TOutput>`: the specialized function is weakly held, regenerated on GC collection.

The critical consequence: because the specializer's rules are `DynamicValue`, every residual — a specialised inference kernel, a compiled BNN cell — is also a `DynamicValue`. And `DynamicValue` is a value, not code. Values can be collected. This is why a GC over the seed can exist at all.

The `SpecializationCache<'TInput,'TOutput>` in `src/Core/SpecializationCache.fs` is the .NET-side primitive: `WeakReference<T>` holds the residual without keeping it alive. If the GC collects it, `GetOrRegenerate()` calls `specializer()` again. The cache tracks `Hits`, `Misses`, and `Errors` (errors are never cached — always retried).

## Layer 3: The Memory Model — Shiva-GC and Ephemerons

`src/Core/ShivaGc.fs` (Aaron, 2026-07-03) is a mark-sweep GC over `DynamicValue` objects in a content-addressed heap. The docstring names the duality directly:

> **The Trimurti duality.** The generator (Brahma — `gen/`, the free object) EMITS reified tables; Shiva (the destroyer) retracts (−1) when they fall out of the reachable set — the emit/retract duality over one content-addressed substrate.

`ShivaGc.mark` does a reachability traversal from a set of root ids over the `DynamicValue` heap. `ShivaGc.sweep` returns the live set and the collected set (the Z-set −1 retraction). The GC is deterministic (roots visited in sorted order), byte-lockable, and idempotent.

`src/Core/Ephemeron.fs` implements Hayes (1997) ephemeron semantics — the same structure as .NET's `ConditionalWeakTable<TKey,TValue>`. An ephemeron entry `(key, value)` survives iff the key is strongly reachable; the value is made reachable only through the key. The reachability fixpoint in `Ephemeron.reachable` handles chains: if key K₁ is strongly reachable, its ephemeron value V₁ becomes a new root, which may make key K₂ reachable, which makes V₂ a root, and so on. Ephemeron cycles with no external root collect entirely — the property plain `WeakReference` lacks.

The difference from .NET's `ConditionalWeakTable` is the **reconstructibility design invariant**. A plain .NET weak cache drops the value and you must have another way to recreate it. In Zeta the invariant `gen(gen) == gen` — the generator IS the error-correcting code — makes every residual reconstructible from the generator, so eviction is safe: Shiva reclaims any specialized residual, and Brahma re-mints it on demand. Forgetting is free. (This holds *given a deterministic, byte-lockable generator* — reconstructibility is a property of the generator being pure, not a runtime guarantee the cache enforces on its own.)

## How the Three Layers Connect

The connection is a single chain: **computation → compilation → memory**.

A compiled BNN inference program is a `DynamicValue` reification (Layer 1 output → Layer 2 input). Because it is a `DynamicValue`, it can be interned in an ephemeron table keyed by the model binding (Layer 3). When the model is no longer strongly reachable, Shiva collects the compiled residual (Layer 3 → Layer 2 feedback). When the model is needed again, Brahma regenerates it from the generator (Layer 2 → Layer 1 forward).

The three roles map to the Trimurti:

| Role | Name | Mechanism | File |
|---|---|---|---|
| Generator | Brahma | `gen/` — the free object, irreducible primitive | `src/Core/MixIr.fs` |
| Collector | Shiva | Mark-sweep GC, Z-set −1 retraction | `src/Core/ShivaGc.fs` |
| Cache | Vishnu (preserver) | Ephemeron table, `WeakReference<T>` | `src/Core/Ephemeron.fs`, `src/Core/SpecializationCache.fs` |

The keystone rule, stated precisely: **collapse the dated fact** (bank the residual — Shiva may reclaim it, it regenerates); **never freeze the re-run interpretation** (the generator stays a strong root). The interpreter/generator is always a strong root — never collected. The dated specialization/residual is a weakly-held ephemeron value — collectable precisely because it is re-derivable.

## The .NET Comparison, Made Exact

| Concept | .NET primitive | Zeta equivalent | Key difference |
|---|---|---|---|
| Weak hold without keeping alive | `WeakReference<T>` | `SpecializationCache<'TInput,'TOutput>` | Zeta adds `Hits`/`Misses`/`Errors` tracking; errors never cached |
| Value lives as long as key | `ConditionalWeakTable<TKey,TValue>` | `Ephemeron.entry` + `Ephemeron.reachable` | Zeta adds the reachability fixpoint for chains; handles cycles |
| Collect unreachable objects | `GC.Collect()` | `ShivaGc.mark` + `ShivaGc.sweep` | Zeta GC is deterministic, byte-lockable, over `DynamicValue` not CLR objects |
| Regenerate on eviction | No built-in | `gen(gen) == gen` design invariant | Reconstructible from a deterministic generator; .NET has no such property |

## What Is Not Yet Shipped (Honest Scope Boundary)

The **N-layer BNN composition** (stacking multiple `MinimalBnn` cells with a shared EP backward pass) is the next engineering step. The primitives are present; the module is not.

The **ExactProbRing** (middle-out float, exact streaming inference) is designed but not fully shipped.

The **Futamura third projection** (`mix(mix, mix)` = cogen) is described in the design intent but not yet a live module — `SpecializationCache` implements the first projection (specialise a function given a static input); the second and third projections are future work.

Everything else in this document — `WSet`, `IStarRing`, the comonoid structure, `MinimalBnn`, `MixIr`, `SpecializationCache`, `ShivaGc`, `Ephemeron` — is live in the codebase and verified against the actual source files.
