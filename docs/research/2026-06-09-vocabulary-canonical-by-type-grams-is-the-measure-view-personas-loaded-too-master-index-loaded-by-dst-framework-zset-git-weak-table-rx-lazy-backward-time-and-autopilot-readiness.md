## The structure (settled this turn — built, green)

- **Canonical homes = TYPE folders (real files):** `words/`, `letters/<language>/`, `shapes/`, `colors/`,
  `temperatures/`, **`personas/`** (Aaron: personas load like this too). The address is
  `<type>/<term>.md`. Uniqueness enforced (one canonical home per term).
- **`grams/` is NOT a home — it is the MEASURE / DIMENSION view** (generated symlinks): `grams/<n>/<term>`
  → the term's canonical home, sliced by the n-gram measure (token count). Case-insensitive-FS collisions
  discriminated by type prefix. Regenerated by `build-grams-view.ts` (`--check` gates).
- **`travelers/` = intake + index:** a new traveler starts as a real intake file here, moves to its
  natural type home, then becomes a symlink back (checked in).
- **Hierarchical index + master one-file cache:** `build-vocab-index.ts` emits a per-folder `INDEX.md`
  (composed from children) and the **master `docs/VOCAB-INDEX.md`** — one read = all 116 travelers.
- **Discriminator rule:** a term with >1 carved sentence (>1 sense) must carry a frontmatter
  discriminator (`context-policy`/`senses`) — enforced.
- **Enforcement (CI):** `vocab-hygiene.yml` runs uniqueness + grams-view freshness + master-index
  freshness + the master-index **load test** (`vocab-master-index.test.ts`, 3 pass).

## The DST framework loads the master index (Z-set + git-weak-table → lazy Rx backward-time)

Per "the DST test should load the master index as part of the test framework," the load model
(`vocab-master-index.test.ts` is the first, TS form of it):

### The F# type provider closes the test loop (compiler-enforced, drift-free — an easy loop)

> Aaron: "F# type providers could make this test test the test — matches the types that our test
> framework code matches our reified type system code — that's an easy loop."

The TS load test hard-codes `["traveler","room","balance","otto","policy",…]` and string-matches the
index. With the **F# reified type provider**, that hardcoding disappears — the vocab **reifies into
types**, and the test references the **generated types** (`Vocab.Words.traveler`, `Vocab.Personas.otto`).
Then it's **compiler-enforced**: remove a traveler from the vocab → the type vanishes → the test (and
the framework code) **fail to COMPILE**, not at runtime. So the loop closes:

```text
vocab (canonical files) ──reify──▶ F# types ──referenced by──▶ test  ✦ and ──▶ framework code
        ▲                                                         │
        └─────────────── all the same source; compiler checks ───┘   "an easy loop"
```

The **test, the framework code, and the reified type system all reference one source** (the vocab), so
the compiler enforces membership — "testing the test" is the type-check. This is interface≡proof /
Curry–Howard again (the type IS the assertion); the TS string-match test is a **placeholder** for the
compiler-enforced F# version. Drift-free by construction: you can't have a test that passes while the
vocab and the code disagree, because they're the same types. ("The compilers don't lie.")

- **Eager load (the present) = a Z-set.** On every run the framework **eagerly loads the master index
  (one-file read) into a Z-set** — the present state of all travelers (the load test does this in TS:
  master index → `Map<term, carved>`; the real one is a Z-set/DBSP collection).
- **git history = a weak-reference weak-table (the past).** The full history is **weakly referenced**
  (the weak-ref / observer-dependent discipline — out of the truth core; observe if reachable, not a
  durability guarantee). A **weak table** keyed to the index entries holds the link to history.
- **Backward-in-time = lazy Rx queries to git.** Touching a weak-ref entry **triggers an Rx query to
  git history** — **lazily** reconstructing the past state on demand (Time Warp / going backwards in
  time = Rx-over-git-as-event-store; GVT = the present frontier). Nothing historical is loaded until
  accessed.
- **Load policy (Aaron):** **cache what we can on every load (eager — the small, the master index),
  lazy the rest (history via the weak-table + large/unloaded stuff).** Small + hot = eager Z-set;
  big + cold + past = lazy Rx/git. (The vocab is small enough to cache everywhere; history + large
  artifacts stay lazy.) This is the realmodel's state-load shape; the Z-set/git/Rx/weak-table impl is
  F#/Core.

## When can `dotnet test` drive (and we just watch + correct + re-kick)? — the readiness checklist

Direct answer: **not yet — and here's the precise gate.** Today's work lays the **state-load
foundation** (master index + load test + the Z-set/git/Rx design). Full "dotnet test drives everything,
we watch + correct, re-kick on finish" (the prod=test self-merging autopilot) needs, in order:

1. **The finalizer framework (the engine)** — bounded tick → ephemeral branch → merge-to-main → re-kick,
   with metrics=test-history read + self-scale up/down. *This does not exist yet (it's design).* The
   single biggest prerequisite.
2. **Runaway guards proven** — 0-unbounded-tests enforced (Semgrep D1) + the shape-F runaway registry +
   scale-down finalizer, so **re-kick-on-finish converges, not fork-bombs.** (Soraya's self-scaling-
   convergence gap.) Without this, "kick the test off every time it finishes" is an infinite loop.
3. **OBJ4-1 — the human-authorization root (the BLOCKER)** — gated-class actions (budget, permanent
   WONT-DO, force-push, non-reversible) keep a human root even when the framework is governance. A
   self-driving polity must not self-authorize a gated action. **Must be answered before autopilot.**
4. **Privacy gate** — before the swarm goes live over real Reticulum (anonymity used; artifacts
   budget-gated; C15 summon-leak contained; §6 per-surface consent).
5. **CI-recursion + TOS safety** — merge-to-main → re-kick must not infinite-loop GitHub Actions
   (PAT-armed + `[skip ci]` + actor-guard + run-markers — documented) and the **heavy compute runs on
   our own runners**, not free Actions (trunk-based, TOS-clean).
6. **State load wired** — the master-index → Z-set + git-weak-table + lazy Rx backward-time (started
   today; the Z-set/git/Rx impl is F#/Core).
7. **Realmodel graduation** — math review (unbounded; O-1 NCI-derivation first) + the realmodel written
   + DST-green.

**The safe first step we *could* do soon (before all 7):** a **bounded, single-step, supervised** loop
— one bounded tick runs, we watch, correct, **manually** re-kick (not the unbounded self-merging swarm).
That's safe now-ish (it's basically my autonomous-loop tick, but for a `dotnet test` tick). Full
autopilot (auto re-kick on finish) waits on #1–#3 at minimum (the finalizer + the convergence guards +
the human-root). **Recommendation:** build the finalizer framework + prove convergence + answer OBJ4-1,
then flip to supervised auto-re-kick on a *small bounded* tick, then widen. Don't flip to the unbounded
swarm until #1–#7.
