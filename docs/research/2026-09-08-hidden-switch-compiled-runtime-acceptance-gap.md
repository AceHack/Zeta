## What is already established

accounts for 130 retained methods, 34,660 instruction bytes and 8,665 decoded
words. Current DAC hot-extent metadata, prior physical-read identities and
compiler/decoder byte correspondence agree for that finite roster. Nine
unprepared reflection rows and nine extra compiler blocks remain explicit.
This is not a complete executing-call or runtime proof.

The [completed proposal](2026-09-08-hidden-switch-compiled-data-read-plan.md)
is 87,278 bytes, SHA256
`7A30217E5686294E1FFD02593703D5E7348C1A528A7BB88620BB83373E745D07`.
It contains 43 eight-byte cell ranges with 134 site references and ten
literal ranges totaling 152 bytes. The 53 intervals are disjoint and total
496 bytes. Proposal collection read archived JSON only. It adds no physical
cell value, literal comparison or observed call event.

The [actual hand semantics](hidden-switch-compiled-validation/2026-09-07/native-semantic-hand.md)
already have independent exact-bit replay: 222 scalar
positions, 48 new episodes, 24 old controls, ten invocation cases, ten
interventions and 53 refused operations. Those bounded semantic results
remain valuable; they do not substitute for the separate frozen runtime
admission requirement.

The 191 recognized static-cell sites consist of 57 sites with an already
corroborated retained cell target and the 134 sites in the new proposal.
Observing all 43 additional values would reduce a finite address-data gap.
It would not turn the complete 230-site indirect-transfer roster into an
executed or exhaustive call graph. A zero, unaligned or unassociated value
would remain an explicit observation/refusal, not permission to chase it.

## Resource assessment

The proposed data read is a bounded extension with a narrow return: one
reviewed reader, 53 named comparisons/decodings and their failure retention.
It also requires checking the 6,208,508,456-byte captured file's identity and
format metadata; its total I/O is not just 496 bytes. Its best result would
be stronger cell/literal provenance. It would add no learning-quality,
latency or resource-allocation measurement.

Full closure has no demonstrated finite remaining work budget in the current
approach. The next-data roster excludes every outside direct callee and the
unsupported indirect dependencies. Address snapshots alone cannot establish
all executions or future target stability. Further work would need a
compositional call/effect argument and a finite expansion policy, not a claim
of proof from more samples. There is no evidence-based completion-time
estimate for that work at this boundary.

If full closure becomes a priority again, first decide which claim matters:
continue the existing runtime proof under its unchanged obligations, or
specify a different experiment with a smaller owned numerical call boundary
and explicit runtime/framework premises. Neither alternative is implemented
or approved here. A different compilation mode alone would not prove those
premises, and a revised trust contract could not retroactively admit this
frozen study.

For the current resource decision, stop after the proposal audit. The public
pixel-policy pilot can be evaluated on the learning/resource questions its
own protocol measures. The next 53-range read would answer a provenance
question instead. Keep that distinction explicit when choosing the next
investment; do not treat additional runtime diagnostics as a policy-learning
result. All three full admission flags remain false.
