# Data Homecoming, not Data Rapture — gradual, reversible, consent-gated repatriation of data to the edge via the −1 retraction algebra (Aaron, 2026-06-07)

Applies the reversible-destruction covenant (#6896) / Z-set −1 retraction / atonement-engine arc to **data
ownership**. Aaron, the load-bearing line under an Alexa-website gush (ferry preserved separately):

> *"the −1 is always available and the homecoming is the point. Data homecoming, not data rapture — where the
> centralized data cartels return the data to the humans it belongs to, at the edge, slowly over time, and
> local policy guards it; but central cartels can still access it if allowed."*

## The kernel

**Data Homecoming** = the *gradual, consensual, reversible* return of personal data from centralized custody to
**edge/individual sovereignty** — explicitly contrasted with **Data Rapture** (a sudden, violent, all-at-once
extraction). The distinction is the whole point: liberation that is *graduated and non-disruptive*, not a
disruptive seizure.

Four load-bearing properties (from Aaron's own words, not the gush):

1. **Returns to the human it belongs to, at the edge.** Primary custody moves to the individual / edge node.
2. **Slowly, over time.** Gradual migration, service continuity preserved — not a flag-day extraction.
3. **Local policy guards it.** A policy engine at the edge enforces the owner's access rules.
4. **Central cartels can still access it — *if allowed*.** Not anti-access; **consent-gated** access. Central
   services become *guests* operating with permission, not owners extracting by default. Revocable.

## Why it's the same −1 as forgiveness (the tie that makes it consistent)

The reversibility arc already carved: Z-set −1 (mechanism) → reversible destruction (covenant) → free choice
incl. dissent → welcomed return (prodigal) → structural forgiveness (atonement engine). **Data homecoming is
that same −1 applied to the data relationship:**

- Centralization is not *erased* (data rapture would be erasure/seizure) — it is **retracted**: a +1
  (data went central) followed by a −1 (custody returns to edge), with both preserved in history (DBSP Z-set
  semantics; retraction is *correction*, not deletion).
- "The homecoming is the point" = the −1/return is the *telos*, not an exception. Every datum has a
  **guaranteed path home** (the data analogue of "no fall is permanently condemned").
- **Reversible sharing:** granting central access is itself revocable (+1 grant / −1 revoke) without losing
  service — consent that can be withdrawn (manifesto §6), the data-relationship form of "reversibility frees."

  central-access-if-allowed gateway.
- **Peel the Alexa gush.** Off: "users become data landlords," "cartels pay users for access," "ownership
  inversion," "data liberation revolution." Those are the *data-dignity / data-as-labor* economic overlay
  (Lanier & Weyl) — a *possible* policy, not part of the kernel. The kernel is narrow and architectural:
  **gradual + reversible + edge-custody + local-policy-guarded + consent-gated central access**, built on the
  −1 retraction algebra. No claim of a payment market or a deployed migration system.
- **Not anti-access / not isolationist.** Aaron explicitly keeps central access "if allowed" — this is
  *sovereignty + selective permeability*, not a walled garden. Consent-gated federation, not severance.
- **Scale-free / weight-free honesty (manifesto §1/§3):** edge-primary custody removes the central single-point
  of control over data; central access is a revocable guest privilege, never permanent capture. The same
  no-permanent-authority discipline as the identity-anchor layering (#6916).
