## Confirmed defect

`AntiSybil.chshS` fills an unobserved setting bucket with zero. Its comment
claims this can only weaken a violation. That claim is false: the missing
bucket may be the subtractive term. Both calibrated classification APIs and
`DecorrelationMeter.classifyPair` accept the resulting apparent violation.
Total observations and outcome-product stationarity do not supply missing
setting evidence.

The [executable witness](../../../src/Research.FSharp/chsh-coverage-witness.fsx)
and [original receipt](chsh-coverage-pre-fix.json) retain three deterministic
cases from the actual Core assembly. The reviewed AntiSybil source SHA256 is
`20CC8F598BB12BF0FD2584D6C0B6710EE0775D22CCCFADF8D9B72C1AAA1C81FF`.
A [fresh Core build](core-build.txt) completed with zero warnings and errors.
The receipt records the actual loaded assembly SHA256/MVID separately; these
are artifact identifiers, not a reproducible-build proof.

1. Repeat setting pairs `(0,0),(1,0),(1,1)` one hundred times. Each side
   always returns `+1`, independent of the other side's setting. Actual
   counterfactual products for all four settings are `+1`; their CHSH contrast
   is `1-1+1+1=2`. The implemented incomplete score is `1-0+1+1=3`.
   At delta `.01`, the HAC margin is `.7008695693`; four-block stationarity
   passes even at tolerance zero. Both calibrated APIs collapse two streams
   to one component, and the meter reports `AboveClassicalBound`.
2. Add the missing `(0,1)` settings while keeping the same constant local
   response. The score is `2`, both calibrated APIs retain two components,
   and the meter remains within bound.
3. Use bucket counts `[1000,1,1000,1000]`, with the single `(0,1)` first.
   The local response functions are `A(0,t)=(-1)^(t+1)`, `A(1,t)=+1`, and
   `B(0,t)=B(1,t)=+1`. No response reads the remote setting. The resulting
   score is `3`, the current HAC margin is about `.356821`, and stationarity
   passes at tolerance `.01`. Both APIs again collapse the pair and the
   meter reports above bound. Merely requiring nonempty buckets would leave
   this adjacent failure in place.

These are deterministic witnesses, not estimates of false-positive frequency
under randomized settings. In particular, the sparse fixture has a fixed
setting schedule and time-varying local responses; it does not satisfy an
i.i.d. sampling model. Its role is to show that the public API admits that
input and that high total traffic does not establish adequate information in
every correlation estimate.

## Source review and mathematical boundary

The affected source locations at the reviewed commit are
`AntiSybil.fs:129-151` (zero filling), `:321-327` (HAC effective rounds),
`:383-408` and `:419-446` (calibrated components), and
`DecorrelationMeter.fs:107-113` (direct calibrated classification). Raw
`chshSybil`, `CoordinationSpectrum` and the scalar `classifyBand` can also
consume the incomplete statistic; its numerical value alone does not certify
measurement eligibility.

[CHSH (1969), p. 881](https://journals.aps.org/prl/pdf/10.1103/PhysRevLett.23.880)
specifies local response functions and a hidden-variable distribution
independent of the setting choices. The local bound concerns the complete
four-correlation contrast. Replacing an unobserved correlation with zero is
an additional model assumption, not a consequence of that bound.
[Gill's finite-statistics analysis, sections 2-3](https://arxiv.org/pdf/quant-ph/0301059)
uses explicit setting randomization and per-setting counts when defining
empirical correlations. A declared total sample size alone does not verify
that design or provide four accurately estimated correlations.

For independent bounded observations conditional on each setting count,
Hoeffding's exponential-moment calculation gives variance proxy
`sum_b 1/n_b` for the signed sum of four bucket means. Equal counts make
this `16/n`; unequal counts need not. Since
`sum_b 1/n_b <= 4/min_b(n_b)`, replacing effective rounds by at most
`4*min_b(n_b)` is a conservative information cap within that calculation.
The existing HAC estimate remains heuristic under general dependence. This
cap neither proves its calibration nor establishes randomized settings,
locality, source non-fungibility, or a device-independent false-alarm bound.
An absolute-tail guarantee would also need explicit two-sided accounting.

## Focused repair boundary

Preserve the raw descriptive `chshS` value. Before calibrated inference,
require valid paired settings in `{0,1}` and outcomes in `{-1,+1}`. Apply the
same truncated paired prefix used by the existing score. Missing settings
must make the margin infinite, so calibrated inference cannot merge the pair
or report above bound. Cap effective rounds by four times the smallest
observed bucket count, retaining the more conservative existing HAC estimate.
This shared margin boundary reaches both calibrated APIs and the direct meter.

Regression obligations include every omitted bucket, the exact constant
witness, sparse positive coverage, malformed paired settings/outcomes,
balanced local and conducted controls, unmatched suffixes, margin monotonicity
relative to the prior HAC formula, and both calibrated component paths.
An unchanged descriptive score is not an eligibility certificate. The scalar
band API cannot recover counts from `(score,n)`; callers still own that
precondition. A separate calibration study is needed before any general
finite-sample or physical-identity claim.

## Additional API-claim finding

The historical `DecorrelationMeter` header equated commit-DAG incomparability
with absence of signaling, treated arbitrary supplied probes as CHSH-valid,
and described HAC as resolving dependence. Its result comments diagnosed a
live channel or superdeterminism from threshold exceedance. Independent review
of the repair rejected those current API claims: recorded ancestry is not a
physical communication model, and an engineering margin does not validate its
own sampling assumptions. The pre-fix archive retains the original statements;
the repaired public comments describe only arithmetic observations and explicit
external assumptions.
