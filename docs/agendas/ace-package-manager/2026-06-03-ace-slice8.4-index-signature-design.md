# Ace slice 8.4 — index-signature (extract + cross-language golden vectors) (design)

> Fifth step of the cross-language Ace trust core (after slice 8 SHA-256, 8.1 canonical-JSON,
> 8.2 package_hash, 8.3 ed25519). The signed-registry-index sign/verify composition already
> works (`signIndex` / `verifyIndexSignature` / `canonicalIndexBytes` in `signing.ts`, wired
> into the load path at `registry-remote.ts` behind the signature → anti-rollback → freshness
> gates). This slice (1) **extracts** that trio into a dedicated trust-core module
> `tools/ace/index-signature.ts` (sibling of `canonical.ts` 8.1 + `package-hash.ts` 8.2), and
> (2) anchors it with a cross-language **golden-vector fixture** so a future Rust/F#/C# Ace
> verifies a signed index byte-identically. Brainstormed + approved with the operator
> 2026-06-03 (scope: formalize + golden vectors, TS, 4-lang parity spec'd; coverage:
> signature-core = canonical + envelope + invalid; module: extract).

## Goal

The signed index is the registry's authenticity root: a consumer accepts a registry's package
list only if the index was signed by the registry's pinned key over its canonical bytes. The
sign/verify primitive exists and is unit-tested (`signing.test.ts`, `registry-remote.test.ts`)
but has **no cross-language golden vectors** — slice 8 vectored SHA-256, 8.1 the canonical-JSON,
8.3 raw ed25519 + the manifest envelope, but nothing vectors the *index* envelope, so a future
non-TS Ace has no contract to match for index verification. This slice gives index-signature a
named module + the golden-vector contract.

## Canonical-gate status (operator 2026-06-03)

Per the canonical-primitive gate (proof **and** 4-language byte-lock): this slice makes
`index-signature` a named trust-core primitive but it stays **TS-only + proof-owed → NOT
canonical yet**. The golden vectors are the *data the eventual proof + 4-language byte-lock run
on*; the proof half lives in the formal-coverage / lean-proof lane. The new fixture is picked up
automatically by `tools/ci/cross-verify-all.ts` (it auto-discovers the dir and runs its
`cross-verify.ts`), so the byte-lock is CI-enforced the moment it lands.

## Decisions (this spec locks them; operator 2026-06-03)

1. **Extract `tools/ace/index-signature.ts`.** Move `IndexSignableContent`, `canonicalIndexBytes`,
   `signIndex`, `verifyIndexSignature` out of `signing.ts` into a dedicated trust-core module
   (named primitive, co-located with `canonical.ts` + `package-hash.ts`). The module imports the
   shared `AceSignature` / `VerifyResult` / `TrustEntry` / `keyId` / `RevocationMap` from
   `signing.ts`, `canonicalBytes` from `canonical.ts`, and `RegistryEntry` from `store.ts`.
   Dependency is **one-way** (`index-signature.ts` → `signing.ts`); `signing.ts` keeps manifest
   sign/verify + the shared primitives and gains no dependency on the new module (no cycle).

2. **Sweep every import site.** The index symbols are imported by `ace.ts`,
   `registry-publish.ts`, `registry-remote.ts`, `registry-revoke.ts`, and their `.test.ts` files
   (+ `signing.test.ts`). Each site's import of an index symbol moves to `./index-signature.ts`;
   imports of manifest/shared symbols stay on `./signing.ts` (split imports where a file uses
   both). `signing.ts` no longer exports the four index symbols.

3. **Coverage = signature core.** The fixture anchors the byte-lock surface only:
   - **canonical** — `IndexSignableContent` → `expected_canonical_json` (8.1 over the index
     shape). At least one vector WITH `revoked`/`quarantined` marks + one without, to anchor the
     richer shape's canonical bytes. **Marked vectors use `format_version: 2`** — `parseIndex`
     (`registry-remote.ts`) rejects `revoked`/`quarantined` on a v1 index, so a marked index must
     be `format_version: 2` to be a valid on-wire shape.
   - **envelope** — a fixed committed keypair signs a canonical `IndexSignableContent` (the
     marked, `format_version: 2` shape) via `signIndex` → expected `{ algo: "ed25519", key_id,
     sig }`; `verifyIndexSignature` accepts under a trust store containing the key.
   - **invalid** — `verifyIndexSignature` rejects with the expected reason: tampered-content →
     `bad-signature`, tampered-sig → `bad-signature`, untrusted-key → `untrusted-key`,
     unsupported-algo → `unsupported-algo`.
   The registry-remote 3-gate composition (pinned-key_id / anti-rollback / freshness) is OUT of
   scope — it stays covered by the existing `registry-remote.test.ts` (freshness is time-dependent,
   ill-suited to a deterministic golden vector).

4. **Independent verification (assert-don't-skip).** The envelope `sig` and the
   `expected_canonical_json` are re-derived independently (Python `cryptography` over the canonical
   bytes — same discipline as 8.3), so no layer is a TS-vs-TS tautology.

5. **No semantics change.** The extraction is move-only — no change to `canonicalIndexBytes` /
   `signIndex` / `verifyIndexSignature` behaviour or signature/identity semantics. Every existing
   assertion stays green.

## Architecture

```text
tools/ace/index-signature.ts                  # NEW: the extracted trio
  import { AceSignature, VerifyResult, TrustEntry, keyId, RevocationMap } from "./signing.ts";
  import { canonicalBytes } from "./canonical.ts";
  import type { RegistryEntry } from "./store.ts";
  export interface IndexSignableContent { ... }
  export function canonicalIndexBytes(content): Uint8Array      // = canonicalBytes(content)
  export function signIndex(content, privatePem): AceSignature
  export function verifyIndexSignature(content, signature, trustStore): VerifyResult

tools/ace/signing.ts                           # keeps manifest sign/verify + AceSignature/
                                               # VerifyResult/TrustEntry/keyId/RevocationMap;
                                               # the four index symbols removed.

tests/cross-verification/index-signature/
  vectors.json      # 3 layers: canonical[] · envelope[] · invalid[]
  cross-verify.ts   # imports signIndex/verifyIndexSignature/canonicalIndexBytes (+ keyId);
                    #   ASSERTS each vector; writes ts-output.json; exit!=0 on mismatch
  ts-output.json    # committed oracle output
```

## Testing

- **Unit (`index-signature.test.ts`):** round-trip (`signIndex` → `verifyIndexSignature` ok);
  reason rejections (tampered content / tampered sig / untrusted key / unsupported algo);
  canonical determinism (key-order-independent, inherited from `canonicalBytes`).
- **Golden-vector (`cross-verification/index-signature/`):** the TS oracle computes
  `canonicalIndexBytes` + `signIndex` + `verifyIndexSignature` for each vector and ASSERTS
  against the independently-derived expected values; writes `ts-output.json`; exits non-zero on
  any mismatch.
- **Independent re-derivation:** Python `cryptography` reproduces the envelope `sig` (sign the
  canonical index bytes with the fixed key) + the `expected_canonical_json`.
- **Behavior-preservation (load-bearing gate):** `bun test tools/ace/` stays green (extraction is
  move-only); `bun --bun tsc --noEmit -p tsconfig.json` exit 0; `bun tools/ci/cross-verify-all.ts`
  discovers + passes the new `index-signature` dir.
- **Gates:** the above + pure-LF + markdownlint on this doc.

## Scope / YAGNI

In scope: extract `index-signature.ts` + relocate unit tests + sweep imports; the signature-core
golden-vector fixture (canonical + envelope + invalid) with independently-verified expected
values. Out of scope: a live F#/C#/Rust index oracle (deferred until a non-TS Ace exists — 4-lang
parity is spec'd + anchored by the fixture); the registry-remote 3-gate (pinned-key / anti-rollback
/ freshness) golden vectors (stay in `registry-remote.test.ts`); any change to the
sign/verify/canonical mechanisms; the formal proof (formal-coverage / lean-proof lane); making
`cross-verify` a required branch-protection check (separate operator/devops step).
