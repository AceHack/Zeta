# Ace slice 8.8.2 — canonical-JSON: C# oracle (design)

> Completes the depth promotion begun in 8.8 (Rust) + 8.8.1 (F#). Adds the **fourth and final**
> oracle (**C#**) to the canonical-JSON byte-lock, so `compare.ts` enforces the **full
> TS + Rust + F# + C#** set. `compare.ts` already reads the `cs-output.json` slot (resilient-absent
> since 8.8), so this is a clean additive slice: a new C# production project + a cross-verify
> generator that writes `cs-output.json`. This closes the **4-language half** of the
> canonical-primitive gate for the canonical-JSON seam (the formal proof is still owed → not yet
> canonical). Approved with the operator 2026-06-03 ("8.8.2 — C# oracle").

## Goal

A non-TS Ace in C# must reproduce the Ace canonical seam (`tools/ace/canonical.ts` `canonicalBytes`)
byte-for-byte. This adds the C# oracle — the last of the four languages. **C# shares F#'s
advantage:** .NET strings are UTF-16, so `string.CompareOrdinal` is exactly JS
`Object.keys().sort()` (UTF-16 code-unit) order — C# gets the key-sort right natively, with no
astral-key special-case (unlike Rust 8.8, which had to sort by `encode_utf16()`).

## Why mirror F# (not Rust)

C# and F# share the **same .NET runtime + the same `System.Text.Json`**, so the C# oracle follows
the F# precedent (slice 8.8.1), NOT the Rust precedent:

- **Input is a `JsonElement`** (parsed by `System.Text.Json`), like the F# seam — not the shared
  `DynamicValue` model the Rust crate consumed. So the C# `AceCanonical` project has **zero project
  references** (BCL `System.Text.Json` only), exactly like the F# project.
- **Lone surrogates** are handled the same way F# handles them: `JsonDocument.Parse` of the whole
  `vectors.json` succeeds, but `System.Text.Json` throws at `.GetString()` / `.Name` on a lone
  surrogate → the generator catches per-vector → `"<rejected>"`. (Rust needed a hand-rolled parser
  because a Rust `String` cannot hold a lone surrogate; .NET strings can, so this is the runtime's
  job, surfaced as a throw.)
- **Hand-emit the flat output** (do NOT use `JsonSerializer` for the canonical strings): exactly the
  F# subtlety — `JsonSerializer` escapes astral chars as `😀` surrogate pairs and escapes
  `"`/`<`/`/`, which byte-diverges from the raw-UTF-8 ts/rust/fsharp outputs. Build the flat map and
  serialize it by hand to match.

## What C# must reproduce (the seam, from 8.8 / 8.8.1 / canonical.ts)

- **code-unit key sort** at every object level — `string.CompareOrdinal` (= UTF-16 = JS) on each
  object property name.
- **array order preserved** + recurse.
- **integers only, safe range** — accept iff the JSON number is an integer with |v| ≤ 2^53−1
  (`TryGetInt64` + range check against `9007199254740991`); reject a float / NaN / Infinity /
  out-of-range. int→string uses **`CultureInfo.InvariantCulture`** (locale-safe decimal, matching
  Rust `to_string` / F# `sprintf "%d"` / JS `String(n)`; the ZetaId C# generator already uses
  `InvariantCulture` for the same reason).
- **well-formed strings/keys** — reject a lone surrogate (a .NET `string` CAN hold one; rely on
  `System.Text.Json` throwing at `.GetString()`/`.Name`, caught per-vector as a reject).
- **minified, raw unicode** — `{"a":1,"b":2}` form, no spaces; non-ASCII raw (astral preserved);
  escape exactly as the shared TS `encodeString`: `"`→`\"`, `\`→`\\`, the C-style controls
  (`\b \f \n \r \t`) short-formed, other `< 0x20` as lowercase `\u00XX`; `/` is NOT escaped.

## Decisions (this spec locks them; operator 2026-06-03)

1. **Scope = add the C# oracle.** No change to `tools/ace/canonical.ts`, the Rust crate, the F#
   project, the TS generator, `compare.ts`, or `vectors.json`. `compare.ts` already reads
   `cs-output.json` (resilient slot) — once present, the byte-lock is the full TS+Rust+F#+C# set.
2. **New production project** `src/Core.CSharp.AceCanonical` (`Zeta.Core.CSharp.AceCanonical.csproj`
   + `AceCanonical.cs`), `net10.0`, `TreatWarningsAsErrors`, `Nullable` enable, `LangVersion` latest,
   **zero external/project deps** (uses only BCL `System.Text.Json`). Public seam:
   `Zeta.Core.CSharp.AceCanonical.AceCanonical.Canonicalize(JsonElement) -> string` that **throws**
   `AceCanonicalException` on reject (float / unsafe-int / unsupported shape; mirrors the TS seam's
   fail-loud `throw` and the F# seam's `Error`). Result-over-exception is the F#/Rust idiom; in C#
   the throwing seam is acceptable here because the cross-verify contract is only
   *canonical-string-or-rejected*, and throwing is the idiomatic C# fail-loud that the generator
   catches. (If a `Core.CSharp` Result/Option type is already the house pattern for new seams, the
   implementer may return that instead — the contract is unchanged.)
3. **Generator** `tests/Tests.CSharp/CanonicalJson/CrossVerifyTests.cs` (xUnit `[Fact]`): repo-root
   walk to `Zeta.sln` (the existing `RepoRoot()` pattern in `tests/Tests.CSharp/ZetaId/CrossVerifyTests.cs`);
   read `tests/cross-verification/canonical-json/vectors.json` via `System.Text.Json`
   (`JsonDocument.Parse`); for each canonical vector compute `Canonicalize` over its `value` element
   and assert == `expected_canonical_json`; for each invalid vector assert it rejects (a
   `System.Text.Json` throw at `.GetString()`/`.Name`, OR an `AceCanonicalException` from the seam);
   build a flat `Dictionary<string,string>` keyed `canonical:<id>` → canonical_json and
   `invalid:<id>` → `"<rejected>"`; **hand-emit** that map to `cs-output.json` (raw UTF-8, NOT
   `JsonSerializer`) normalized to LF, no-BOM, with a single trailing newline — byte-identical to the
   existing ts/rust/fsharp outputs; `Assert.Equal(0, mismatches)`.
4. **Wiring:** add `<ProjectReference Include="..\..\src\Core.CSharp.AceCanonical\Zeta.Core.CSharp.AceCanonical.csproj" />`
   to `tests/Tests.CSharp/Tests.CSharp.csproj` (the SDK-style csproj globs `*.cs`, so no explicit
   `Compile Include` is needed for the new generator); register the new production project in
   `Zeta.sln` (`dotnet sln add`). CI runs `dotnet build Zeta.sln -c Release` + `dotnet test Zeta.sln`.
5. **Byte-exactness anchor:** C#'s output for each vector must equal the `expected_canonical_json`
   already in `vectors.json` (Python-authored 8.5 / TS-reproduced 8.5 / Rust 8.8 / F# 8.8.1). The
   cross-check becomes **five-way at the data level**: Python ↔ TS ↔ Rust ↔ F# ↔ C#.
6. **No semantics change** to any existing primitive; the existing `dotnet test` suite stays green;
   `cross-verify-all` stays 9/9 (canonical-json `compare.ts` now reads all four `<lang>-output.json`).

## Testing

- **C# parity:** `dotnet test` (the new `[Fact]`) — every canonical vector's `Canonicalize`
  equals `expected_canonical_json`; every invalid vector rejects; writes `cs-output.json`;
  asserts 0 mismatches.
- **`compare.ts`:** now reads all four `<lang>-output.json` → asserts TS + Rust + F# + C# each equal
  expected per id + all agree; exits non-zero on mismatch.
- **Gate:** `bun tools/ci/cross-verify-all.ts` 9/9 (canonical-json `compare.ts` with 4 langs);
  `dotnet build Zeta.sln -c Release` clean (`TreatWarningsAsErrors`); `dotnet test Zeta.sln`;
  `bun --bun tsc --noEmit` 0; `bun test tools/ace/` pass; pure-LF; markdownlint.

## Scope / YAGNI

In scope: the C# production project + seam + cross-verify generator + csproj/sln wiring + committed
`cs-output.json`. Out of scope: promoting any OTHER primitive; the formal proof (formal-coverage /
lean-proof lane — this slice closes the *4-language* half of the gate, NOT the proof half); making
`cross-verify` a required branch-protection check (operator/devops).
