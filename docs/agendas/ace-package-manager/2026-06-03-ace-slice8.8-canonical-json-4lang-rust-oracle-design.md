# Ace slice 8.8 — canonical-JSON 4-language promotion: Rust oracle (design)

> First **depth** step (after the breadth slices 8.4–8.7). Per the canonical-primitive gate
> (proof **and** 4-language byte-lock), the breadth slices left the Ace seam primitives **TS-only, proof-owed → not canonical**. This slice begins converting the foundational one — the
> canonical-JSON seam (`canonicalBytes` / `toTagged`, slice 8.1/8.5) — from a TS-only golden-vector
> (`cross-verify.ts`) into a **multi-language byte-lock** (`compare.ts`), adding the second oracle
> (**Rust**) alongside TS. F#/C# follow in 8.8.1 / 8.8.2. Brainstormed + approved with the operator
> 2026-06-03 ("canonical-json, go"; recommended canonical-json first because it is the foundation
> and has no crypto dependencies).

## Why incremental (Rust first), not all-3-at-once

`tests/cross-verification/*/compare.ts` is **resilient to a missing language** (each language's
`<lang>-output.json` is read in a try/catch → `null`; absent languages are skipped, present ones
are asserted against the canonical vectors + cross-checked). It is *designed* for incremental
rollout. So this slice:

1. converts `canonical-json/` from the TS-only `cross-verify.ts` to the 4-language `compare.ts`
   shape (TS + Rust present; F#/C# slots resilient-absent), and
2. adds **Rust** — the language whose toolchain is present here (`cargo 1.96`), whose crates are
   zero-external-dep, and which is self-contained — so the slice is a complete, verifiable,
   reviewable unit (canonical-json 1-language → 2-language).

F#/C# are deferred to follow-up slices (their `<lang>-output.json` simply don't exist yet; the
oracle skips them and still enforces TS↔Rust↔canonical).

## Precedent-setting decisions (flagged for review — first Ace→Rust promotion)

These set the pattern every later Ace primitive promotion follows; calling them out explicitly:

1. **New standalone crate `src/Core.Rust.AceCanonical`.** No Cargo workspace exists (each
   `src/Core.Rust.*` is standalone); this follows suit. It depends (path) on
   `Core.Rust.DynamicValue` for the `DynamicValue` value type — reusing the shared value model, not
   inventing a new one.
2. **The seam takes an already-parsed value, like TS.** `canonicalBytes(value)` in TS takes a JS
   value (parsing is the caller's `JSON.parse`). The Rust production seam is
   `ace_canonical_json(&DynamicValue) -> Result<String, AceCanonicalError>` — sort + validate +
   emit; **zero external dependency.** The Ace seam is a *distinct, stricter* canonical than
   `DynamicValue::to_canonical_json` (which is order-*preserving* and *allows* floats), so it is a
   new function, not a reuse of that method.
3. **Zero-external-dep JSON parsing in the cross-verify test** (matching the sha256 test's
   "dogfood the internal YAML port, no external deps" discipline). `DynamicValue::from_canonical_json`
   only accepts *already-canonical* (sorted) input (fixed-point check), so it cannot parse the
   unsorted vector inputs. The test therefore carries a **small hand-rolled lenient JSON-value
   parser** (zero external dep) that parses each vector's `value` into a `DynamicValue` (rejecting
   floats and lone surrogates the same way the seam would). No `serde_json` / external crate.
4. **`compare.ts` over the two-layer structured output.** Unlike sha256's flat `{id: hex}`,
   canonical-json has a canonical layer (`{id: canonical_json}`) and an invalid layer
   (`{id: "<rejected>"}`). Each language's `<lang>-output.json` carries both, flat-keyed by id with
   a layer prefix or a unified map; `compare.ts` asserts every present language's result per id
   equals the expected (the `expected_canonical_json` from `vectors.json` for canonical ids, the
   `<rejected>` sentinel for invalid ids) and that all present languages agree.

## The Ace canonical seam (what Rust must reproduce, byte-for-byte)

The TS contract is the slice-8.5 fixture (`vectors.json`): for each canonical vector,
`expected_canonical_json` is the exact byte string; for each invalid vector, the seam **rejects**.
The seam rules (`tools/ace/canonical.ts`):

- **code-unit key sort** at every object level. JS `Object.keys().sort()` is UTF-16 code-unit
  order, so Rust sorts keys by `encode_utf16()` to match it for ALL keys. The vectors' keys are
  BMP/ASCII, where UTF-16 / byte / code-point orders all coincide (so the fixture stays
  Python-authorable); the astral-key divergence is locked by a crate unit test instead.
- **array order preserved** (only object keys sort) + recurse.
- **integers only, safe range** — reject a float, NaN, Infinity, or |int| > 2^53−1.
- **well-formed strings/keys** — reject a lone surrogate (in Rust this is automatic: a `String`
  cannot hold a lone surrogate, so the hand-rolled parser rejects a lone `\u` escape at parse
  time — same OUTPUT: rejected).
- **minified, raw unicode** — `{"a":1,"b":2}` form, no spaces; non-ASCII emitted raw (astral
  preserved); `"` and `\` escaped, the C-style controls (`\b \f \n \r \t`) short-formed, other
  `< 0x20` as lowercase `\u00XX` — exactly matching the shared TS `encodeString`. The
  `control-chars` vector added in this slice locks this byte-for-byte across TS + Rust.

## Decisions (this spec locks them; operator 2026-06-03)

1. **Scope = add the Rust oracle + convert to `compare.ts`.** F#/C# deferred (8.8.1 / 8.8.2). No
   change to `tools/ace/canonical.ts` (the TS impl is unchanged; this is a parity oracle).
2. **Crate:** `src/Core.Rust.AceCanonical` (`Cargo.toml` + `src/lib.rs` + `tests/cross_verify.rs`),
   path-dep on `Core.Rust.DynamicValue`, zero external deps (production AND test).
3. **Golden-file discipline:** `tests/cross_verify.rs` asserts the checked-in `rust-output.json`
   matches freshly-generated output; regenerate with `UPDATE_GOLDEN=1 cargo test` (matching the
   sha256 pattern). CI (`cross-verify-all.ts`) asserts the committed outputs; it does not run cargo.
4. **Byte-exactness anchor:** Rust's canonical output for each vector must equal the
   `expected_canonical_json` already in `vectors.json` (Python-authored + TS-reproduced in 8.5).
   So the cross-check is genuinely three-way: Python (authored 8.5) ↔ TS (reproduced 8.5) ↔ Rust
   (this slice) — no tautology.
5. **No semantics change** to any existing primitive; `bun test tools/ace/` stays green;
   `cross-verify-all` stays green (now running `compare.ts` for canonical-json).

## Architecture

```text
src/Core.Rust.AceCanonical/
  Cargo.toml                 # path-dep Core.Rust.DynamicValue; zero external deps
  src/lib.rs                 # ace_canonical_json(&DynamicValue) -> Result<String, AceCanonicalError>
                             #   (sort keys + reject float/unsafe-int + minified raw-unicode emit)
  tests/cross_verify.rs      # hand-rolled lenient JSON parse of vectors.json values -> DynamicValue;
                             #   run seam; write rust-output.json (golden); reject-aware

tests/cross-verification/canonical-json/
  vectors.json               # canonical[9] + invalid[5] (8.5's 8+4 plus 2 review-added this
                             #   slice: control-chars, lone-surrogate-bare)
  compare.ts                 # NEW (replaces cross-verify.ts): multi-language, two-layer oracle
  ts-output.json             # reshaped to the compare.ts flat-by-id form
  rust-output.json           # NEW (committed golden, generated by cargo test)
  cross-verify.ts            # REMOVED (superseded by compare.ts)
```

## Testing

- **Rust unit/parity:** `cd src/Core.Rust.AceCanonical && cargo test` (the repo has no Cargo
  workspace — crates are standalone; regenerate the golden with `UPDATE_GOLDEN=1 cargo test`) runs
  `cross_verify.rs`: every canonical vector's `ace_canonical_json` output equals
  `expected_canonical_json`; every invalid vector rejects; writes `rust-output.json`.
- **TS:** the TS side writes `ts-output.json` (same data the 8.5 oracle produced, reshaped).
- **`compare.ts`:** asserts TS + Rust (+ F#/C# when present) each equal the expected per id and
  agree with each other; exits non-zero on any mismatch.
- **Gate:** `bun tools/ci/cross-verify-all.ts` discovers `canonical-json/` (now `compare.ts`) and
  passes (still 9/9 primitive dirs); `bun --bun tsc --noEmit` 0; `bun test tools/ace/` 372 pass;
  pure-LF; markdownlint.

## Scope / YAGNI

In scope: the Rust crate + seam + cross-verify generator; the `compare.ts` conversion; the
reshaped `ts-output.json`; the committed `rust-output.json`. Out of scope: F#/C# oracles (8.8.1 /
8.8.2 — resilient-absent until then); promoting any OTHER primitive (package-hash / ed25519 / etc.
— later depth slices); control-character escaping vectors (the shared `canonicalJson`'s concern);
the formal proof (formal-coverage / lean-proof lane); making `cross-verify` a required
branch-protection check (operator/devops).
