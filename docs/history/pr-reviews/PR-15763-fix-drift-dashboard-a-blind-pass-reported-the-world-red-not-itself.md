## Description

## `observe` has failed 17/17 — 16 of them honestly, 1 of them falsely

Workflow `340212005` (`drift-dashboard-cadence`), job `observe`.

**Runs 1–16 are genuine and are not touched here.** They were real observation
passes — 62–73 of 66–78 checks covered, 44–60 green, and a real backlog of
red/flapping/unknown rows. `ok` requires `red=0 ∧ flapping=0 ∧ unknown=0 ∧
shortfall=0 ∧ sourceErrors=0`, and that bar has simply never been cleared. There
is no streak boundary because there was never a green.

**Run 17 is different in kind.** It observed *nothing* — 78 enumeration calls
failed inside 50 ms of wall time — and published `RED 12 · coverage 12/78 ·
green 0` with twelve lanes marked `STALE: newest verdict is 9h old`. Four of
those were sampled; each had run successfully within the hour.

That is **the vacuity class inverted**, and it is the dangerous direction. A
check that cannot fail is inert. A check that reports *the world is broken* when
only its own credential is gets believed, then distrusted, then ignored.

## What broke

#15694 tightened credential handling — a good instinct — and `asGithubAccessToken`,
its charset filter, is a real taint barrier that **stays untouched here**. One path
lost its resolver on the way past:

| | |
|---|---|
| **absent ≡ rejected** | The run reported `no GitHub token in ~/.config/zeta/auth/github.json or GH_TOKEN/GITHUB_TOKEN` on a runner whose own step env shows `GH_TOKEN: ***`. The token resolved; the filter refused its shape; one message covered both. |
| **the fast path stopped degrading** | `fetchGhApi` documents `null ⇒ caller uses the subprocess`, and returned `null` only for an *absent* credential. A shape-refused one produced an `auth-failure` Result, which `runGhAsync` handed straight back — so `gh`, installed and authenticated on the runner, was never reached. |

### What the charset filter actually rejects: I could not tell, and did not probe

That answer lives only in the live secret. Guessing at token-validation logic in
someone else's just-landed PR is precisely the failure this PR is about, so **the
fix does not depend on knowing.** The filter is unchanged; what changes is that a
refusal is loud, specific, and survivable.

What *is* established without observing the token: the run's error text is
reachable **only** through the filter, because an absent credential short-circuits
to the subprocess one frame earlier. So the credential resolved and the filter
refused it — that much is airtight; the shape is not.

## The changes

- `classifyTokenRejection` / `tokenRefusalMessage` — two conditions, two reports.
  Neither interpolates the credential: not its bytes, not its length, not its prefix.
- `fetchGhApi` returns `null` on a shape refusal, restoring the subprocess route,
  and says once per process why it went slow. Falling back is **strictly safer**
  than the fetch it replaces — no file-sourced bytes leave at all, so the CodeQL
  taint barrier loses nothing.
- `runGhAsync`: `Bun.spawn` throws *synchronously* for a missing binary and the
  launch sat outside the `try`, so the advertised `gh CLI not found on PATH` branch
  was **unreachable code**. Found by exercising the new fallback with `gh` off PATH.
- `foldDashboard` gains `blindSources`: a source that could not be asked yields
  `unknown{source-error}` for its checks instead of an absence-derived staleness
  verdict. The fold already had this sentence one branch up for the per-check case
  — *"we do not get to conclude 'correctly silent' about a question we failed to
  ask"* — with no way in for a whole-source outage. **The pass still fails**; it
  fails saying "I could not see."

### Three same-area defects, each visible in run 17's own log

1. `--write` **diverted** stdout instead of adding to it, so `$GITHUB_STEP_SUMMARY`
   received the single line `wrote db/…, docs/…` every tick since the lane existed.
   The receipt moves to stderr; stdout is always the report.
2. `sourceErrors` was collected, counted in the headline (`SOURCE ERRORS 1`) and
   written to artifacts — and its **text reached no log**. The line naming this
   outage existed the whole time and was never printed. A count is not a diagnosis.
3. The flush carried 2 of the 4 written artifacts. `docs/DRIFT-DASHBOARD.md` on
   `main` last changed **2026-08-24**, by a code commit, while the JSON beside it
   refreshed every 6 h. Both missing paths added.

## Falsifiers — both fail without the fix

Verified by mutation, not by assertion:

| mutation | result |
|---|---|
| collapse the two refusal messages back into one | 2 of 8 fail in `gh-cli.test.ts` |
| stub out the `blindSources` branch (`else if (false)`) | 2 fail in `fold.test.ts` |

`fold.test.ts` §*"a source that could not be asked"* carries the control **in the
same file**: the same roster and the same clock render **RED** when the silence is
the lane's and **UNKNOWN** when it is ours.

Fixtures are synthetic and no live secret is read. The first draft used a
`ghs_`-shaped literal and the pre-push secret floor blocked it — correctly; a
fixture that trips a secret scanner trains people to silence secret scanners. It
now uses the literal `resolve-stored-token.test.ts` already carries.
