## Description

`main` is red on `merge-heartbeats-to-main.test.ts:116` (17 pass, 1 fail, reproduced on a clean `origin/main`). **It is mine** — #10986 deliberately reversed the invariant that test pinned.

## Why it is stale, not a regression

The old assertion required the tick checkout to carry **no** `token:`, so branch writes rode the default `GITHUB_TOKEN`. #10986 reversed that on measured evidence: a `pull_request` run whose triggering actor is `github-actions[bot]` is created and immediately parked in `action_required`, so `gate (required)` never ran on a `heartbeat/*` flush PR.

The test was not wrong about what the code does. It was wrong about what the code *should* do.

## Not deleted — re-aimed

Deleting the assertion would trade a stale pin for **no coverage** over the exact credential split that cost the fleet ~16.75h in #10850. One property per assertion:

| assertion | the regression it catches |
|---|---|
| the `\|\|` ladder is present | an **absent** secret degrades to `GITHUB_TOKEN` rather than checking out an empty credential and killing every lane |
| preflight probes the real remote (`git push --dry-run`) | the **unauthorized** case the ladder cannot cover — precisely what #10850 shipped |
| preflight **re-probes** after the swap | the vacuity guard. #10913's fallback ran, logged that it ran, and was denied under the same identity |
| swap reachable **only** on a credential answer | a network or ruleset error hidden behind a credential story |
| degrade is visible (`::error::`), token is masked | a silent degrade is a lane that looks healthy and is not |
| push stays a plain push; **flush** checkout still carries no `token:` | #10850's second, latent break — that half of the original pin was always right and is kept |
