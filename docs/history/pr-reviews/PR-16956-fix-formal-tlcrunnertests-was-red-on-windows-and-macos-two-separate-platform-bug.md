## Description

`build-and-test` on `windows-2025` and `windows-11-arm` had failed **53 of 59 runs (89.8%, clean streak 0)** while `gate (required)` stayed **green** — so the required floor never saw it. The drift job reported it loudly and correctly; nothing blocked on it.

**Bisected, not guessed:** windows-2025 was `success` at `499cf18d` (13:45), `c36ac21bf` landed 13:48, red from then on. Both failing tests came from that commit — 2 of 6577. `Build FAILED, 0 Error(s)` plus `[blame] no Sequence_*.xml found` rules out both the known xUnit stdout flake and a toolchain break.

## The control run found a *second*, unrelated bug

Running the same filter against unmodified `main` failed the **same test on macOS for a different reason**. So it was red on two of three platforms, and only the Windows half was visible in the sustained drift band.

**1. macOS — ANSI colour in the captured pipe.** The assertion printed `Expected: "74140"` / `Actual: "74140"` — visually identical, differing at position 0. The retained scratch dir gave the bytes: `ESC[0m ESC[33m 74140 ESC[0m \n`. Bun **colourises numbers** in `console.log`, and `.Trim()` doesn't strip escapes. Fixed with `process.stdout.write(String(child.pid))` — exactly the bytes asserted, no dependence on TTY detection or `NO_COLOR`.

**2. Windows — the grandchild died with its launcher.** The fixture needs a process that inherits the launcher's stdout and **outlives** it, so the drain runs against a pipe with no EOF. `Bun.spawn(...)` + `child.unref()` gives that only on POSIX — `unref()` detaches from Bun's event loop, **not** from the OS. On Windows the grandchild stayed in the launcher's job object and was killed on launcher exit, so `Process.GetProcessById` threw `MissingProcess` before the drain ran at all. Redesigned to `node:child_process.spawn(..., { detached: true })` — `setsid` on POSIX, `DETACHED_PROCESS` on Windows — keeping `stdio: ['ignore','inherit','inherit']` so the inheritance property is unchanged.

**3. Windows — read-only cleanup.** `Directory.Delete(scratch, true)` on the one test that runs `git init`: git marks `.git/objects` read-only, Windows refuses to unlink read-only files, POSIX ignores the bit. Scoped to that single test — the other three scratch trees have no `.git` and keep the plain delete. Attribute-clearing is best-effort *before* the authoritative delete, so the swallow cannot hide a failure, only fail to prevent one.
