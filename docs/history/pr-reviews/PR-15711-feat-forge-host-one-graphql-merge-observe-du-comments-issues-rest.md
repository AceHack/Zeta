## Description

## Summary

Follow-on to #15705. Merge-blocking state (checks, threads, rebase) used
to cost `gh pr view` + `gh pr checks --required` — two token-metered
calls, and an agent that *chooses* which to run still works stale.

`observeMerge` is **one** `POST /graphql` that returns the merge DU
(`wait-ci` | `fix-failed-checks` | `resolve-threads` | `rebase` | `none`).
Tests pin `calls.length === 1`. Required-check names are not enumerated;
`mergeStateStatus` is the discriminator.

Comments, issues, auto-merge are REST on the same injected door (host-pinned,
token-validated). Webhooks (`check_suite` / `pull_request_review`) are the
next cost cut, optional, not an appointed hub.

Roadmap 8b: Harny closed tools are Xbox `ActionGrid` cells (DU-aware,
auto-refresh), not ad-hoc polls. Git/fs through ZetaFS stays item 1 —
another bootstrap.
