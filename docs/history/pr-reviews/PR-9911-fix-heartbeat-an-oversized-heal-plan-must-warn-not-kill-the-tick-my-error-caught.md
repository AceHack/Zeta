## Description

The blast-radius bound (#9891) fired for the first time in production and **worked exactly as designed**:

```
[tier-0] BLAST RADIUS EXCEEDED — 1005 files planned, bound is 25.
[heal] nothing written, tree untouched.
```

That refusal is correct. **What I did with it was not: `exit 1`.**

That failed the *whole* heartbeat job. otto's observe tick, flush, archive, codegen, and the newly-wired mutation runner all died because **one duty** had a large plan. The 18:30 tick shows otto **failed** while alexa and soraya **succeeded** — the only difference being otto holds healer duty.

## Two disciplines say this is wrong, and I applied both elsewhere today

- **Drift report, not a gate.** Every other detector added today (byte-lock, cadence, mutation runner) reports and continues. The healer bound shouldn't be the exception.
- **Fail closed, not off.** Your own rule on the presence signal: degrade behaviour, never stop members ticking. Killing the tick is the *off* direction.

The bound's job is to refuse the write and say so loudly — **not to stop the society.**

Now: `::warning::` plus an explicit *"continuing the tick"* line, no exit.

The finding itself is unchanged — **1005 files** (958 stale `.js` + 47 rewrites) still wants a deliberate decision. It's now surfaced without taking four other duties down with it.
