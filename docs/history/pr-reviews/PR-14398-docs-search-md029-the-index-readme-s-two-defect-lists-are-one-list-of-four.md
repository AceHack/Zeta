## Description

## `main` is red and it is mine — twice, from the same mistake

#14359 added `search-index-cadence.yml`, which runs `tools/setup/install.sh` and is therefore **governed** by `audit-apt-budget-fits-job-timeout.ts`. A governed job with no entry in `apt-job-timings.measured.json` fails that audit outright, and main's gate has been red on it since `86ff1331`.

The row was measured and committed **twice**. Neither commit reached main.

## The race, stated plainly

**With auto-merge armed, a push races the merge, and the pusher cannot see the race.** `git push` succeeds, and it is tempting to read that as *"the PR now contains this commit"*. It does not — GitHub merges whatever head was green when auto-merge fired.

| PR | armed | fired on | the commit that was lost |
|---|---|---|---|
| #14359 | early | `dc303a18` | `6ecf1e4a` — the timings refresh, pushed ~1 min later |
| #14386 | early | `ad6cb39e` | `e2b0e7c8` — the fix for the above, again ~1 min later |

Twice, identically. And the first time, I wrote *"arm auto-merge last, or re-read the PR's `headRefOid` after any subsequent push"* into the commit message — and then armed auto-merge early on the very next PR.

**Writing a lesson down is not the same as having a mechanism.** That is this repo's standing point, and I have just demonstrated it against myself rather than about someone else's code.

So: **this PR is not auto-merged on creation.** Push → verify `headRefOid` matches local HEAD → *then* arm.

The file's top-level `measuredAt` stays `2026-08-22` while this row is from the 23rd — deliberate, because provenance here is **per-row**: every row carries its own `window` and `runIds`, which is what makes it checkable rather than asserted.

**Honest limit the row cannot carry:** those three samples are `pull_request` runs, and that path skips `prepare` and `flush` (both gated on `github.event_name != 'pull_request'`). So 169s under-states a scheduled run by two git operations. The 20-minute timeout absorbs that with an order of magnitude of room, and the next refresh after a scheduled run will measure the real thing.
