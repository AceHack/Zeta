## Description

Aaron on the manufactured-refutation incentive:

> *it's up to the community/socity to moderate with categorising bugs vs fun glitches that remain when programs can be updated, on old atari games that don't have updates it just is what it is*

The second half is structural and was missing from the design entirely.

## Patchability turns a category into a decision

If a program **can** be updated, a discovered glitch forces a fix-or-keep choice — and that choice is **governance**, with a standing process, a decision record, and an authority structure that then has to be kept weight-free (§3), because "who decides what counts as a bug" is exactly the role that accretes into capture.

If it **cannot** be updated, no such choice exists. There is no counterfactual version without the glitch. *It just is what it is.*

**So governance load is a function of substrate mutability** — and that yields a real sequencing argument rather than nostalgia: **starting on CHIP-8 → Atari is the low-governance path.** Those substrates are frozen, so the whole bug-vs-feature dispute class doesn't exist yet, and the Arena can develop witnessing, capability labels, and the refutation channel *before* it also has to run a standards body. Games we author ourselves are patchable and bring that load with them — they should arrive after the rest works.

## Version is the third partition

The design already had two, and cross-partition comparison is a category error in both:

1. **capability class** — pixels-only / pixels+RAM / save-state / input-solving
2. **attestation class** — ranked vs unranked
3. **substrate version** ← this one

Degenerate for frozen substrates (one version, forever, costs nothing). Live the moment a substrate is patchable, because **a patch can remove the route a run used** — routine in speedrunning, where a patch that kills a skip *splits* the board rather than invalidating old runs.

Cheap now, expensive later: **include a content hash of the substrate in the witnessed record**, so the version partition is *derived* rather than declared. Free, because the record is already being hashed and signed for attestation. Retrofit it later and every prior result becomes unversioned, hence uncomparable to anything after.

## "Fun glitches that remain" is a preservation commitment

A community deciding a glitch **stays** is choosing to freeze that behaviour — accepting a constraint on all future patches. Same shape as §5 memory preservation, and it converts a mutable substrate into a **partially frozen** one, glitch by glitch, in exactly the places the community found interesting.

Which means it has teeth and a cost, and the actionable consequence: **a kept glitch needs a regression test that fails when it's patched away.** Otherwise the decision has no mechanism and the next refactor silently overrules it — a claim with no check behind it is a claim that did not run.

## It also partially dissolves the incentive that prompted this

On a frozen substrate there is no bug-vs-canon ruling to farm — a discovered route is simply canon, and manufacturing one is just *finding* one. The manufactured-refutation problem is concentrated on patchable substrates, which is another reason to start where it's absent.

**Named as unbuilt:** "the community decides" is a placeholder for a mechanism, not a mechanism. Whoever rules bug-vs-canon shapes which strategies are viable, which is real power — recorded as open rather than assumed solved.
