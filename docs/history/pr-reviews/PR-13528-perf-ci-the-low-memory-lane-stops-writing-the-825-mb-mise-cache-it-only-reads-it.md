## Description

## What

`low-memory.yml` switches its mise-runtime cache step from `actions/cache` (restore **and** save) to `actions/cache/restore` (restore only). Same action, same SHA pin, same `path:`, same `key:` — the save half goes away.

## Why, in measured numbers

Sample: 60 `low-memory` runs (2026-08-21 20:35 → 2026-08-22 02:34) plus 4 dispatched probes.

| | measured |
|---|---|
| mise cache entry size | **825 MB** (`Cache Size: ~825 MB (865502705 B)`, run 32549356483) |
| `Post Cache mise runtimes` | **0–246s**, p90 90s (max on run 32544861733) |
| runs killed at the 14-min cap | **9 of 60**; **2 of those died inside this save step** — 32517981607 (122s in), 32540421350 (105s in) |

The write buys this lane nothing: `gate.yml:build-and-test` writes the **identical** key (same `path:`, same `hashFiles('.mise.toml', '.mise.full.toml')`, same `runner.os`/`runner.arch`) on the same `push: [main]` trigger, from a 4-vCPU host. Two writers, one key — the slow one was paying for a cache the fast one already maintains.

Keeping *gate* as the writer is also the right direction: gate runs at the **full** host tier, so its entry is a superset of what a slim host needs. The slim lane writing it back replaced that superset with a subset, which the full-tier jobs then had to re-install. Restore-only makes the `ZETA_HOST_TIER` split hold at the cache layer too.

## This does not make it green by making it not run

No `continue-on-error`, no skip, no path filter, no `timeout-minutes` change. Every step that executed before still executes; `mise install` still provisions the same runtimes; the build and test steps are untouched.

## Cold path — verified, not inferred

A cache that only works warm fails on the first run after a key change. Run **32550223578** ran this exact step with a deliberately-unmatchable key so the miss was guaranteed:

```
Cache not found for input keys: mise-COLDTEST-shadow-081-Linux-X64-1e378247...
Restore mise runtimes  0s
Install toolchain      156s
Build Core smoke graph 155s
Test Core smoke graph  5s
```

Green in **343s of the 840s cap (2.45x headroom)**, and no `Post Cache mise runtimes` step in the run at all. Cold now costs today's cold path *minus* the write — never more, because the write is the only thing removed.
