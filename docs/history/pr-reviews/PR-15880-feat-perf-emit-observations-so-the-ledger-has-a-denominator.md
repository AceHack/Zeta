## Description

#15836 landed the fold and nothing emitted, so the live ledger was empty — it
correctly printed "this is not a clean bill of health" rather than a green table,
and it could not answer the question it was built for.

TWO GATES, NOT SIX. My earlier claim of "six perf-shaped test files" was an
over-broad grep, and enrolling all six would have been actively harmful rather
than merely noisy. Measured:

    Storage/ColumnLinearOps.Tests.fs:618   speedup >= gate   ENROLLED
    Storage/ColumnZSet.Tests.fs:302        speedup >= 1.5    ENROLLED
    Operators/Differentiate.Tests.fs        numerical CONVERGENCE ("faster than naive")
    ReceiptScheduler.Tests.fs               a computed profit multiplier
    TravelerRankLedger.Tests.fs             a comment
    TimeDilation.Tests.fs                   a comment

A deterministic assertion cannot flake, so every row it contributed would be a
guaranteed pass inflating the denominator — UNDERSTATING the flake rate of the
assertions that genuinely are timing-sensitive. The ledger's denominator must be
timing-sensitive observations only, and the emitter says so in place so the next
reader does not widen it by grep the way I nearly did.

PASSES ARE EMITTED TOO, which is the whole point. Emitting only on failure hands
the ledger a numerator over an unknown total. `pass` is a PARAMETER, never
re-derived from `measured` vs `gate`: this repository holds lower-bound gates
(speedup >= x) and upper-bound ones (allocations <= n), and re-deriving would
invent misses in every upper-bound test. The caller passes the same expression it
asserts on.

`ColumnZSet`'s bare `1.5` literal is now a `gate` binding used by the ledger call
AND the assertion AND the failure message, so the three cannot drift apart.

A CROSS-LANGUAGE FALSIFIER, because nothing else connects these halves. The
emitter is F# and the parser is TypeScript; if the sentinel is retyped, a field
renamed, or the instant format changed, the emitter keeps printing and the parser
keeps returning an EMPTY list — and an empty ledger renders as "no observations",
indistinguishable from a healthy quiet period. Both halves individually green,
jointly useless. The contract test reads the F# source and asserts against the
parser's actual behaviour.

TWO OF ITS OWN ASSERTIONS WERE VACUOUS, found by mutation and worth recording
because both are the class this file is about:

  * The instant test pinned that a `.NET "O"` string PARSES — true however the
    emitter formats. Changing the F# specifier to `ddd MMM d` left every
    assertion green while the ledger would have refused every row. Now the source
    is pinned too.
  * The enrolment test used `toContain("PerfObservation.emit")`, which happily
    matched its own corpse when the call was commented out. Now anchored to the
    call site including the argument that follows it.

19 pass, 0 fail. Mutants killed: prefix 1, field-rename 1, instant-format 1,
ColumnZSet-unenrolled 1, and the enrolment-rule prose. `dotnet build -c Release`:
0 warnings, 0 errors.
