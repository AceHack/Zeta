## Description

Files the follow-up Aaron pointed at, with the deciding fact **established rather than assumed**.

## The gap is papered twice, two different ways

Rust *is* declared (`.mise.toml` `rust = "1.87.0"`). What is not declared is everything that makes the toolchain usable:

1. **a comment as an instruction** — `.mise.toml`: `# After 'mise install', run: rustup target add wasm32-unknown-unknown`;
2. **a bespoke shell script** — `tools/setup/common/ensure-rust-components.sh` (`c32c27ea6`), calling `rustup component add rustfmt clippy` from `mise.sh:196`.

A comment is not a mechanism; a script is not a declaration.

## The finding: mise's `core:rust` backend DOES accept `components` / `targets` / `profile`

Checked by **negative control**, not by citation. A scratch config with a deliberately bogus component was passed straight through to rustup, which rejected it *by name*:

```
mise rust@1.87.0              [2/4] install
error: component 'definitely-not-a-real-component' for target 'aarch64-apple-darwin' is unavailable for download for channel '1.87.0'
mise ERROR rustup failed
```

Had mise ignored unknown options the install would have **succeeded** — the test can fail, so it is a check. (mise 2026.6.14 local; repo pins `min_version = 2026.6.12`, CI runs 2026.6.12. `mise config get tools.rust` also round-trips the options.)

So the decision tree collapses to its good branch: **declare it, delete the script, delete the comment** — the bash-retirement discipline *removes* a shell file instead of allowlisting one, and the `ensure-rust-components.sh` allowlist entry (#10991) is scaffolding to be retired, not a justification to harden.

This PR is the work-item only; no behaviour change.
