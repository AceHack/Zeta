## The finding

PR #10722 filed a divergence rather than hiding it: TypeScript's `TemperatureReadout` gained a required `fidelity` field that F#'s does not have, while **both still declare `zeta.temperature.readout.v1`**. Its report said no existing test could see it, because the treaty pins field *values*, not *key sets*.

**Verified before building anything. The report is correct.** With the divergence live on unmodified `main`:

```
bun test heat-signals.test.ts darkhall-room.test.ts batch-heat-bridge.test.ts
  51 pass  0 fail  exit 0
```

No cross-verification lane covers heat, and no hygiene check enumerates schema ids. So the gap is in the verification substrate, not in one type: a golden vector that fixes `temperaturePpm = 250000` passes whether the producing type has eight fields or nine.

## What this adds

`audit-schema-key-set-parity.ts` — compares key sets across oracles, keyed on the **declared schema id**, for every id bound to a type shape in more than one oracle.

- **TypeScript** binds via `interface … { readonly schema: typeof CONST }`; `extends` resolved, `?` read as optional.
- **F#** binds via a record construction **literal** — trustworthy because the compiler requires a literal to mention every field. Copy-updates (`{ r with … }`), exempt from that rule, are skipped.
- **A mention is not a binding.** `zeta.multisig.v1` is an F# signing domain whose only TS mention asserts a *different* domain is deliberately not equal to it. A string-intersection check pairs those; this one does not see them.
- **Version bumps are free.** The key is the whole id, so `v1` and `v2` are never compared. Divergence *within* a version is the defect.
- **Added-optional is compatible; added-required is breaking.** F# optionality is not detectable from a literal, so every F# key is conservatively treated as required — said out loud in the header rather than left to be discovered.

## Owned error

The first draft **manufactured nine divergences** in `zeta.darkhall.room-ui.v1`. `{ Schema = readout.Schema; … }` is a **pass-through** of another value's schema, not a declaration, and resolving its tail identifier against the file's `let Schema` bound four heat-shaped records to the room-ui id. Fixed by requiring a qualified path's qualifier to be module-shaped, and pinned by a regression test. The check reported the false finding plainly enough to catch — which is the only reason it was caught.

## On `fidelity` itself — declared, not resolved

An honest declared exception beats a guessed fix in a treaty. The resolution is a design call already owned by **081M010WYE5087G0R003J89QVF §2**, whose text asked for exactly this check; that work-item is updated rather than duplicated.

Input recorded there for whoever makes the call: `ChannelFidelity`'s `out-of-domain` case is motivated by JavaScript `number` admitting `NaN`/`Infinity`, which F#'s `int`-typed `ofPpm` **cannot produce** — but `saturated` and negative input are real on both sides, and F#'s `max 0 |> min MaxPpm` discards them exactly as silently as TS's clamp did before the fix. So `fidelity` is **not** purely encoder-local. Also: adding a required field to an already-published `v1` is a breaking change by the ordinary schema-evolution rule.

Declared exceptions are themselves checked — one that stops matching a live divergence is **stale** and fails, so the file cannot rot into a blanket mute.
