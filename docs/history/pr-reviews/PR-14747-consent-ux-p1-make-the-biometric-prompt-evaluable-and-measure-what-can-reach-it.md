## Description

## The sentence this is designed against

Aaron, 2026-08-24: *"I was pressing the biometric keys when they popped up, I was assuming it was necessary for the testing."*

> **You cannot withhold consent from a prompt that does not tell you what you are consenting to.**

The biometric IS the authorization here, and an authorization is a *decision*. A decision needs something to decide about. Pressing was the rational response to what was shown.

## The defect, executed rather than asserted

`ceremony-brief.test.ts` constructs two materially different operations and shows the operator-facing strings were **byte-identical**:

| | old prompt | what was in scope and withheld |
|---|---|---|
| revoke my laptop's cert | `revoke SSH device cert (KRL)` | cert path, CA, KRL, **the reason** |
| revoke a cert I think an attacker holds | `revoke SSH device cert (KRL)` | (same — a bare constant, interpolating nothing) |
| publish key A | `Publish zeta-aaron-mymac to GitHub` | the **fingerprint**, computed 3 lines above the gate |
| publish key B | `Publish zeta-aaron-mymac to GitHub` | (same) |

No finger-press distinguishes those. The gate was cryptographically fine and carrying no decision.

## The property that keeps this safe

**One object, not two derivations.** The one-line prompt and the block are both pure functions of a single `CeremonyBrief`, built from the objects the action itself consumes. The prompt cannot drift from the brief because it is *computed*, not authored beside it. `rotate.ts` keeps its performed-not-requested property: the operation id is read off `performing`, the same array the dispatcher consumes. `publish.ts`'s dry-run readout now quotes the real derived string instead of a hand-typed imitation that could drift.

**Fewer prompts, not more.** No prompt is added. `assertGatedCeremony` *removes* prompts — it throws rather than raising a dialog for an operation classified `unattended`.

**Declining is safe and stated.** `ifDeclined` is mandatory and validated non-empty; a brief that cannot say what refusal costs is refused at the call site, not shown to a human.

**Existing vocabulary.** Two persona-keys operations that raised prompts while being absent from the repo's only ceremony classification are now classified there via that file's own documented extension point. Both pin existing behaviour; neither changes a gate.

## Part B — what can reach the gate (the more important half)

`ceremony-reachability.test.ts` parses the CLIs and measures the **polarity of the safety default**:

- **7 CLIs are LIVE BY DEFAULT** (`dryRun = flag("--dry-run")`) — a bare invocation with no flags performs the real ceremony and can raise a real Touch ID dialog. `--dry-run` is opt-*out*, so forgetting it is not a typo, it is a ceremony.
- **6 are opt-in to live** (`dryRun = !confirm`) — a bare invocation plans only and never prompts.
- **`ca-cli.ts` is MIXED WITHIN ONE FILE**: `ca` and `cert` are live-by-default (lines 61, 98); `frost-ca` and `frost-cert` are opt-in (142, 165). The polarity is not learnable even per command.
- **No CI workflow invokes a ceremony CLI** — the reassuring half, now pinned so adding one fails a test rather than failing at 3am.

Flipping seven CLIs is a behaviour change to a security surface with a P1 in flight, so the state is **pinned exactly** rather than fixed here: a new live-by-default CLI fails the test, and a *fixed* one fails it too and must be moved into the safe list. The ratchet turns one way. This is deliberately not an assertion over a set that could quietly grow.

## Deliberately left alone

- **`biometric.ts` — untouched.** Nazar holds it in #14727 (absolute-path privilege elevators). No auth-mechanism change here.
- **`revoke.ts` gates on `if (opts.biometricAuth) { … }`** — so a programmatic caller that injects no door skips the gate entirely instead of failing closed, unlike `ca.ts`/`machine.ts` which call `requireBiometric` unconditionally. Reachable only programmatically (`revoke-cli.ts` always wires the door), but it is a genuine latent fail-open and it is auth-mechanism-adjacent. **Flagged, not touched** — it belongs with Nazar's in-flight work.
- **`rotate.ts` (leaf-only) and `ca.ts` (cert signing) prompt for operations `ceremony-gate.ts` calls `unattended`.** Not silenced; the brief now says so on the prompt. Dropping those prompts is a policy call for whoever owns the gate.
- **The macOS modal itself.** `pam_tid` renders it and its text is fixed by the OS; nothing in this layer can change it. Stated as a vacuity disclosure in the module rather than left as an implied guarantee — which is the standing argument for making a ceremony a deliberate foreground act.
