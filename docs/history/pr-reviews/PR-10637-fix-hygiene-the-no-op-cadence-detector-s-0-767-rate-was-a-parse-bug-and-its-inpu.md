## Description

## What this found

#10616 landed `--enforce` and recorded the calibration as **30 windows, 23 fires, rate 0.767**, correctly declining to arm enforcement on a number that high. That number is real — and it is **not a fleet behaviour**. It is a parse bug. Underneath it, the detector has been reading an abandoned directory since 2026-05-29.

Re-verified on the merged code before touching anything: `9f3fe8251` is an ancestor of this branch, and **no workflow invokes the tool** (checked `.github/` twice).

## The parse bug

`isMinimalObservation` classified a shard by `firstLine.split("|")[4].length < 600` — the summary **cell** of a markdown table row. Across the 1209 real shards:

| class | n | share | classified |
|---|---|---|---|
| heading-format (`# Tick shard …`) → no 5th pipe field → `body = ""` | 488 | 40.4% | **forced MINIMAL** |
| pipe row, summary cell < 600 chars (i.e. any normal cell) | 395 | 32.7% | **MINIMAL** |
| pipe row, cell ≥ 600 chars → regex actually consulted | 326 | 27.0% | judged |

The forced-minimal class has a **median size of 3843 bytes** — *larger* than the median of the class the code was willing to call non-minimal. The detector was most confident about its biggest shards.

## Measured false-positive rate

**Method 1 — commit ground truth** (CLAUDE.md's own externalized idle counter). Dated git history and tick shards overlap only on 2026-05-28/29 → 48 hourly windows. The detector fired on **48/48**, and **29 firings (60.4%)** coincided with substantive non-telemetry commits landing.

**Method 2 — content.** Of the 890 shards called "minimal", **622 (69.9%)** were ≥1500 bytes with no minimal-observation language anywhere in the file.

A first pass at method 1 over all of May returned 8.5% and was **discarded as vacuous**: git dates in this clone reach back only to 2026-05-28, so earlier windows scored "0 commits" from *absent data* rather than an idle fleet. Recording the discard because the broken measurement looked exactly like the working one.

## The deeper vacuity — the input surface is dead

`docs/hygiene-history/ticks/` has had **no shard since 2026-05-29** (77 days). A live run finds zero shards, judges nothing, and **exited 0** — success reported because the input vanished. `--enforce` could not have fired in production no matter what was wired to it.

That is now `surfaceEmpty`, and `--enforce` treats it as failure: *"I could not run"* must not be spelled the same way as *"I ran and it was fine"*. Live ticks are JSON telemetry at `data/tick-shards/**/*.json` with no prose body, so the minimal-observation half cannot simply be repointed — that routing call is filed as `081M00G3QRA087G0R003GB0P4X`, not made here.
