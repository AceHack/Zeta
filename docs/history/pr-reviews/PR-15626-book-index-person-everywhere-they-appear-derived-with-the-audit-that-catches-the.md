## Description

## The problem this solves

PR #15619 binds consent to the **sha256 of the approved passage**, so an edit makes the row `STALE`. Correct primitive, wrong unit for how this book is written. Aaron 2026-08-26: *"my many many revisions after talking about others, so a named index into the book would help."*

**Twenty subjects × five revision passes is a hundred approval requests.** People stop answering long before a hundred — and at that point a green check means "nobody read it" while looking exactly like "everybody agreed".

## What this adds

**person -> every place they appear**, generated from the `consent:begin` markers already in #15619's vocabulary. Three reasons it is better and not merely cheaper:

1. It answers the question a subject actually has — *"what does this book say about me?"* No passage-level diff answers that.
2. **Consent becomes about portrayal, not sentences.** Someone can be fine with each line and not with the aggregate picture. Only the whole footprint surfaces that.
3. Revision churn gets scoped: one section revised sends a **delta** — *"here is what changed about you since you approved"* — to the people in it, not a re-read to twenty. A person whose footprint hash did not move produces **no row at all**, and there is a test for that.

## The load-bearing artifact is the AUDIT, not the index

Everything the index lists is real; nothing tells you what it **missed**. A subject shown a page headed *everywhere you appear* who says yes to an incomplete one has been misled **by** the index — which is why an incomplete one is worse than none. So `audit-book-named-index.ts` scans the prose for each roster subject's declared identifying strings and fails on any appearance outside every consent span.

### Proven failing

Every negative is a **mutation of a positive control asserted green in the same test** — a negative that passes because an earlier guard fired on a broken fixture proves nothing, and that has bitten this repo twice.

| mutation | result |
|---|---|
| add one unmarked sentence naming a `named` subject | `UNMARKED_APPEARANCE`, **exit 1** |
| remove that sentence | exit 0 — tracks the text, not a latch |
| name a `pending` subject in prose | `NAME_LEAK`, exit 1 |
| name a `pending` subject **inside a consent span** | `NAME_LEAK`, exit 1 — a marker is not permission |
| name a `role-only` subject | `NAME_LEAK` — byte-identical outcome to `pending` |
| revoked subject still named | advisory at repo tier, **fail under `--publish`** |
| hand-edit `NAMED-INDEX.md` | `INDEX_STALE`, exit 1 |
| edit one character of prose, do not regenerate | `INDEX_STALE`, exit 1 |
| roster person with zero aliases | `NO_ALIASES_DECLARED`, **and the test asserts the mention really is invisible** |
| missing roster · unclosed span | **exit 2** — never "no findings" |

Plus paired matching controls: `Jordan` does not match inside `Jordanian` **but** `And Jordan,` does; a name in a fenced example is not an appearance **but** the same name two lines later is; the same string in `CONSENT-LEDGER.md` is skipped **but** in a chapter it is a finding.

**And measured live on the real corpus**, not only fixtures — one throwaway *non-person* roster entry whose alias is a phrase the book uses:

```text
prose files scanned        : 78
book-machinery files SKIPPED: 3 — CONSENT-LEDGER.md, NAMED-INDEX-DESIGN.md, NAMED-INDEX.md
alias hits outside any span: 10
findings : 12 (12 failing, 0 advisory)          exit 1
# roster reverted to empty                       exit 0
```

## The four states, and `role-only` is a content constraint

`named` / `role-only` / `pending` are **declared**; `revoked` is **derived** from #15619's grant/revoke fold and may not be declared — a state that can be both asserted and computed can disagree with itself.

`pending` is **not** the weaker one: it enforces exactly what `role-only` enforces, with a test asserting byte-identical findings. Treating an unanswered ask as *probably fine* is the failure this exists to prevent. The live precedent is the ledger's own asked-and-answered-with-a-denial row, carried by role and not by name.

Honest limit, in the code and the doc: the person-level revoked rollup cannot distinguish "revoked one scope" from "revoked everything", so it reports `revoked` only when **nothing** survives. Partial revokes stay #15619's per-span business.

## Reconciled with #15619, not diverged from it

Its §10 anticipated this work and proposed one marker vocabulary, one roster, complementary audits, and the footprint hash as the delta view. **All four adopted.** The four places this differs are stated in the design doc rather than left to be discovered:

- **The shared parser lives in a third module** (`book-consent-spans.ts`) because #15619 is unmerged and nothing on `main` can import from it. Re-implementing it silently would be the Babel failure in miniature.
- **`indexState` is additive and verified harmless** — `parseLedger` whitelists the person fields it reads, so it ignores the new one. Read from the source, not assumed.
- **`UNMARKED_APPEARANCE` is repo-tier, not publish-tier.** An unclaimed span is consent not yet collected; an unmarked appearance is the index making a **false claim about its own completeness**, which is #15619's own rule for the repo tier applied to a finding it does not have.
- **§10's worry does not materialise.** No finer-than-paragraph spans are needed; an inline mention is handled by coverage, not by a smaller span. No span attribute added.

Three things keep the two parsers honest until they are one: **hex-in-JSON golden vectors** (one of them the exact example printed in `CONSENT-SIGNOFF-DESIGN.md` §4, so it constrains *both* implementations rather than being a self-portrait), **`--parser-conformance`** which imports the counterpart when present and returns **exit 3 UNCHECKED — never 0** while it is absent (three tests: absent→3, agreeing→0, one hash character different→1), and **the exact collapsing edit** written down in the design doc, including the instruction to *retire* the conformance check afterwards rather than leave it comparing a module with itself.

`consent-events.json` ships **byte-identical** to #15619's copy, so the two PRs merge with no conflict.

## What it cannot catch

> **A person described identifiably without being named.**

This is a string matcher. *"My co-founder from the 2007 company, the one who later went into medical imaging"* identifies someone precisely and contains no alias. **There is a test asserting the audit says nothing about that sentence**, so silence is never later read as coverage. Declared **role phrases** are caught (also tested) — but only the phrasing a human wrote down; a paraphrase escapes. `NO_ALIASES_DECLARED` reports the zero-alias case, the index prints alias counts because that number *is* the strength of the claim, and every run prints `NOT CHECKED: a person described identifiably but not named.`
