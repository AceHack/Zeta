## Description

# Summary

`prepare-heartbeat-branch.ts` rebuilds each `heartbeat/<agent>` lane over current main and
squash-carries the previous lane's delta. Its docstring claimed already-flushed state
"contributes no staged change" — that holds only for a **total** flush. A flush snapshots the
lane, but the lane keeps ticking while the flush PR is in flight, so main routinely lands a
strict **prefix** of the delta; and because the flush is a squash, no shared ancestry exists
for git to notice. The next tick's merge base predates the flush, both sides insert at the
same end-of-file anchor, and git conflicts. That is the rotation observed on 2026-08-16:
whichever lane is mid-partial-flush wedges next.

# Reproduction (before any change)

Synthetic first, then confirmed on the live refs. Replaying the preparer's merge against
`origin/heartbeat/{alexa,otto}` conflicts on exactly three paths, and the append-only conflict
is **vacuous** — main's side of the hunk measures empty:

```
alexa: db/mutation-findings/alexa.jsonl, docs/observe-events/.rs-buffer-alexa.json
otto:  + data/vault-state.json
ours=0 theirs=1        <- main added nothing in the conflicted region
```

Negative control: a **full** flush merges clean (exit 0); only the partial flush conflicts.
The per-event `docs/observe-events/<zetaid>.json` files never conflict — their unique filenames
still carry the original conflict-freedom invariant that `merge-heartbeats-to-main.ts` documents.

# Fix

All three paths are **single-writer**, so main's copy is never a rival author's work, only an
older snapshot of the same lane's output — the two are agent-scoped by filename, and
`vault-state` is generated by otto's lane alone (`agent-heartbeat.yml`: "only otto generates
vault-state"). That is what makes an automatic resolution honest rather than a clobber.

```
db/mutation-findings/*.jsonl            merge=union    (append-only log)
docs/observe-events/.rs-buffer-*.json   merge=theirs   (regenerated snapshot)
data/vault-{state,roster}.json          merge=theirs   (regenerated snapshot)
```

`union` is exactly set-union here — verified lossless in both directions with zero duplicate
lines against the live lanes. It is **wrong** for the snapshots and was measured emitting two
concatenated objects (invalid JSON), so a single driver for all three is not available.

`theirs` is **not** a built-in driver, and an unregistered driver is silently ignored — so the
attributes block alone is not the fix. The preparer registers it in local repo config. A clone
that never calls the preparer keeps stock conflict behaviour on those paths.

Backpressure is preserved: any conflict outside the declared paths still fails the tick, and
the remote lane is still never modified. **No lane was reset.**
