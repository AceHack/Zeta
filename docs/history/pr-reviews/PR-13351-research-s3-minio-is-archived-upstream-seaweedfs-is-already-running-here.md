## Description

## What this is

Aaron asked: *"Only minio is current, and only because upstream stopped publishing in January 2025. should we be using an alternative to minio for our s3? We were looking at ceph or others."* — then sharpened it: *"we just want a s3 like interface cause so much other software works well with that interface. we can git rid of minio for sure if it's no longer being maintained."*

One research doc under `docs/research/`. **No manifest is changed.** The decision is the maintainer's.

## The premise holds — MinIO is unmaintained, measured not inferred

| fact | evidence |
|---|---|
| `minio/minio` is **archived / read-only** | `gh api repos/minio/minio` → `archived: true`, last push 2026-04-24 |
| Last release **2025-10-16** | `gh api repos/minio/minio/releases` |
| README: *"THIS REPOSITORY IS NO LONGER MAINTAINED"* | github.com/minio/minio |
| Chart 5.4.0 created **2025-01-02**, pins appVersion **RELEASE.2024-12-18** | charts.min.io/index.yaml (all 90 versions share that `created` stamp) |

**The chart and the server are not separable claims here.** The chart's source is `minio/minio/helm/minio` — *inside* the archived repo; there is no `minio/charts` (404). So the chart is archived too and can never receive a fix.

**Not in the brief, and the most consequential find:** the AGPL build carries **four unpatched HIGH advisories**, two of them *unauthenticated object write* (incl. CVE-2026-41145, CVSS 8.8). Every "fixed in" version is a proprietary **AIStor** release. Our pin predates all eight.

## Two corrections to the assumed picture, both measured in-tree

- **The S3 consumer set is TWO, not three.** Tempo uses `backend: local` (`tempo/Application.yaml:22-28`) and never opens an S3 connection.
- **Only ONE S3 path has ever run.** `mimir` and `tempo` are excluded from the `included` Synced+Healthy CI proof (`argocd-health-test.ts:281,286`), so **Loki → MinIO** is the only object-storage path this repo has exercised. Mimir's `blocks_storage` config is *unmetered* — which cuts *toward* moving, since you cannot regress a path that never passed.

## SeaweedFS already covers this

`seaweedfs/Application.yaml` is a reconciling Application with `allInOne.s3.enabled: true` and **the same five buckets** already created. Aaron built the A/B himself in **PR #8057** fourteen months ago — *"both auto-sync so we can compare backends without tearing either down"* — and **nobody has run it**. The cutover in `BLOB-STORE-CONTRACT.md:120-127` is one endpoint string per consumer, with a documented revert.

Apache-2.0 (a **licence improvement** over AGPL-3.0), chart 4.43.0 published the same day this was written, ≥100 commits in 30 days. Its S3 surface was verified against `weed/s3api/s3api_server.go` — the router that registers the routes — not the wiki: full multipart, ListObjectsV2, batch delete, CopyObject, conditional headers, versioning, lifecycle, object lock.

## Recommendation

**Adopt SeaweedFS, retire MinIO — but boot metal first.** The bring-up should debug one variable, and the metal boot produces the baseline that makes the A/B mean anything; migrating first would discard the only comparison that would have justified the migration. The CVEs make this a *clock* rather than a free wait — exposure is zero today (ClusterIP, no ingress, box not running), so steps should follow weeks-not-quarters behind the boot.

**Conditional on one check**, and it is not a formality: the A/B must use objects **>200 MB verified by checksum**, because SeaweedFS has an open unresolved silent-finalization defect on exactly that path ([#8908](https://github.com/seaweedfs/seaweedfs/issues/8908)). Multipart only engages above ~64 MB, so a small-object smoke test would pass while the real failure mode sits untouched. That plus two other honest marks against SeaweedFS are recorded rather than buried.

**Garage is eliminated on the API, not on taste:** no conditional writes, and upstream calls that *"structurally impossible … a core design choice which we cannot reconsider"* — which forecloses Loki's Thanos metastore path that Grafana says will become the default.

**Ceph/Rook is healthy upstream but wrong-shaped:** ~16 GB RAM and 3.5 cores to serve 1 TiB by upstream's own arithmetic, a monitor wanting 100 GB of SSD, defaults where *"writing to the pool will hang"* on a single host — and per `zeta-install.sh:38` it is a **block-layer** decision that must be made *at install time*, so adopting it means the largest irreversible storage commitment available on a cluster that has never booted.

If MinIO-shaped software is preferred anyway, `pgsty/silo` is the only fork that actually backported the CVEs.
