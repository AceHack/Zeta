## Description

## What

Aaron 2026-07-03: *"ephemeron integration — weak-value table, collect on strong-ref-drop."* The Shiva collector (#9354) reclaims what the **strong** heap stops referencing; this adds the **weak** layer — the interning table that holds shared reifications (`MixIr.defaultMixDef` shared across every ISA) so they live exactly as long as something strong points at them, and no longer.

A weak-value table is `{ key, value }` entries whose **own edges do not keep the key alive**: an entry survives iff its `key` is **strongly reachable** from the heap roots. So the moment the last strong reference to a key drops, its entry is collected — the interning table never leaks.

## True ephemeron semantics (Hayes 1997), not just weak refs

A value is marked **through** its key, so `reachable` is a **fixpoint**: strong-mark from the roots; any ephemeron whose key is reachable adds its value as a new root; re-mark; iterate. Two properties a plain weak table lacks:

1. an ephemeron **chain** `A→B→C` survives when `A` is rooted (the value drives the next key)
2. an ephemeron **cycle** with no external strong root collects **entirely** — ephemerons cannot keep *each other* alive (strong refs would leak it)

That cycle-collapse is the whole point of ephemerons over weak references.

Collection is still a **Z-set retraction (−1)**: `prune` returns survivors + dropped keys (exactly the entries whose key left the strong-reachable set).
