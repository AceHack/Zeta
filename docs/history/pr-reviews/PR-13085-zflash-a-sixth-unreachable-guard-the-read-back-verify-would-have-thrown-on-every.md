## Description

Closes the two known unreachable guards — and finds a third on the way in that is worse than either.

## The one found before the tasks started

`flash-usb.ts` step 7 opened the raw device with the **unprivileged** reader — only `dd` was under
`sudo`. So the read-back verify, whose own docstring says *"fail-loud by contract … there is no flag that
skips it"*, **would have thrown `EACCES` on every real flash, after a `dd` that had already succeeded.**
Present, tested, unreachable.

**I verified the refusal myself:** `/dev/rdisk6` is `crw-r----- root:operator` and an unprivileged
`openSync` returns `EACCES`. **One correction to the agent's report** — it attributed this to group
membership, and I *am* in `operator`, so the cause is something else (most likely sandboxing). **The
refusal is measured; the stated reason is not**, and is recorded as unconfirmed rather than repeated.

## R1 is now reachable

It detects *"labelled `ZETA_INSTALL` but the head digest disagrees"* — the stick that **looks**
provisioned and holds the wrong bytes — and its digest inputs were supplied only by the test file, **so a
wrong-bytes stick classified as `provisioned`**, the exact misread R1 exists to prevent.

The sample is **1 MiB, not 512 bytes**, for a stated reason: **512 bytes would agree between two
*different* Zeta ISOs, and a check that cannot tell candidates apart is not a check.** A short read on
either side is a **failure**, never a shorter comparison.

**And absent digests were their own small vacuity:** *"the bytes match"* and *"nobody looked"* produced the
same evidence object. The verdict now carries `headDigestChecked` and **says so** — *"this verdict is
LABEL-ONLY and cannot distinguish correct bytes from wrong ones."*

## The target is stated, never discovered

The fallback that made the first identity check **compare observed to itself** is **deleted** — unpinned is
now a refusal that prints the exact re-run line. The two comparisons are now genuinely different: **stated
pin vs enumeration** (wrong-disk guard) and **enumeration snapshot vs a fresh pre-write read** (TOCTOU
guard, because `/dev/diskN` is recycled across a replug). **Nothing is compared to itself anywhere.**

**Honest limit, not overclaimed:** with no `--expect-*`, `cli.ts` *derives* the pin from its own
enumeration. That is **derived-and-shown, not stated**. What it buys is still real — the pin is fixed
**before** the operator is shown it, so a swap must happen before the display rather than after — and the
fully non-vacuous form, the operator naming the target, exists and is checked.

## Policy for `half-provisioned`: acknowledge, never refuse

`unrecognized` still **refuses** — being wrong there destroys someone else's data, and re-running cannot
undo it.

But a hard refusal on `half-provisioned` would block **the most common legitimate re-flash** — a stick
whose previous write was interrupted — **and would train operators to reach for an override by reflex,
which is how an override stops meaning anything.** An extra typed line **cannot be satisfied without
reading the verdict**, and leaves in the transcript a record of *what* was destroyed rather than only that
consent was given.

**Two costs named:** one extra line on the ordinary repair path, and in `--agent` mode the acknowledgement
is auto-typed — **so there it is a record, not a gate**; the gate remains the Touch ID prompt. Written in
the code, not left to be discovered.

## The falsifier for the class — the point of the round

Two rules: **a guard whose declared inputs no *non-test* caller supplies** (with *"no production caller at
all"* also a finding — **a guard only its own test can reach is the purest case**), and **an expectation
that falls back to an observation.**

Both run over **comment-stripped text in both directions**, so a call in a comment cannot count as a
supplier **and a worked example of the defect cannot report itself.**

Replayed against the pre-fix sources it **catches both of tonight's defects by name.** On the fixed tree:
**1973 files scanned, zero findings** — so it can land with `--enforce` and **no baseline**, which is the
strongest form.

**Anchor, checked:** mutation testing's premise moved one level out — Lipton/DeMillo/Sayward (1978) ask
whether a *test* can fail when the *code* is wrong; **this asks whether a *guard* can fire when the *world*
is wrong.**

## Designed-but-unrun — the honest headline

buffer sizing are unverified against a device.

> **Stage 1 gained two guards that are *reachable in principle*, which is strictly weaker than *fired*.**

still no platform parity** — all of this is macOS-only.
