## Description

Closes the GH013 breakage: four workflows have been failing every run since `gate` became required on `main`, because they commit with `[skip ci]` and push straight at a protected branch.

**Two commits, split deliberately:**

- **`4b6a7577f` — Part A**, landable without the `workflows` scope.
- **`c65813584` — Part B**, the five `.github/workflows/**` edits, isolated so it can be applied separately.

## Three premises in my brief were wrong — two would have caused damage

1. **The "delete the hygiene tools" instruction was a NAME COLLISION. Nothing was deleted.** `check-tick-history-order.ts`, `sort-tick-history-canonical.ts`, `audit-tick-history-bounded-growth.ts` and `gate.yml:801` all target **`docs/hygiene-history/loop-tick-history.md`** — a markdown loop journal — **not** `data/tick-history.json`. They enforce an append-only / reverse-chronological guard (Otto-229). Deleting them would have stripped live protection from an unrelated file.
2. **`demo/red/red-state.json` is not accumulating** — it is a regenerated single-writer snapshot. Sharding is meaningless; latest-wins is correct.
3. **`docs/observe-events/` is already ZetaId-keyed**, so society- and agent-heartbeat needed no data-shape work at all.

**Net: the keying applied to exactly one file. The route change was the whole fix.**

## What changed

**Part A** — `data/tick-history.json` becomes `data/tick-shards/YYYY/MM/DD/<HHMMSSmmm>-<sha256[0:8]>.json`, one file per write (the proven `workitems/events/` pattern). The old path stays at its shape but is demoted to a **derived, bounded rollup** — so `monitor.html` needed no code change, and a conflict resolves by regenerating from shards rather than hand-merging. All 560 frames backfilled and verified value-identical (only key order changed, now canonical).

**Part B** — all four lanes park on ungated `heartbeat/*` and land via squash-auto-merge PR. `gate` is untouched in strength; `data/**` joins its docs-only allowlist so a 15-minute JSON frame doesn't trigger the full F# matrix.

## Two silent-failure traps, encoded

- **`[skip ci]` INVERTS on a PR route.** True for a direct push, exactly backwards for a PR: it suppresses `pull_request` runs too, so `gate` never reports and the PR hangs **unmergeable forever**. `assertNoSkipCi` refuses rather than open a dead PR.
- **`GITHUB_TOKEN` cannot open the PR** — `can_approve_pull_request_reviews: false` at repo *and* org. This is exactly why the earlier PR flush was abandoned for direct push, and that reason still holds.

## The one thing needing a human

Provision **`ZETA_TELEMETRY_FLUSH_TOKEN`** — fine-grained PAT, **Pull requests: write + Metadata: read**, nothing else. No `contents: write`: the branch push uses the workflow's own `GITHUB_TOKEN`, so a leak of this token can open PRs and nothing more.

Fallback ladder is coded and degrades safely — `ZETA_TELEMETRY_FLUSH_TOKEN || ZETA_PR_ARCHIVE_TOKEN || GITHUB_TOKEN`. Without any, the frame still parks on the staging branch and the job reports why.

## New issues surfaced (pre-existing, not caused here)

- **`AUTOFIX_TOKEN` does not exist.** `lint-autofix-apply.yml` references it and **silently degrades** to `GITHUB_TOKEN`, so healed commits never re-trigger the gate.
- **`data/tick-history.json` had a second undocumented reader** — `agent-heartbeat.yml:565` → `vault-state-bridge-cli.ts`. Safe (last frame only), but it was not the sole reader as briefed.
- **`tick-metrics.yml` had no concurrency group** — push and schedule could race. Added.
- **`data/rs-blocks.jsonl` and `data/vault-state.json` are further accumulating single files.** Same class, not addressed, future work.
