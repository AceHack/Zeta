## Description

# Summary

The same gap was papered twice, two different ways: a **comment** in `.mise.toml`
instructing a human to run `rustup target add wasm32-unknown-unknown`, and a
**bespoke shell script** — `tools/setup/common/ensure-rust-components.sh`, called
from `mise.sh:196`, running `rustup component add rustfmt clippy` after
`mise install`. That script sat in `EXPECTED_RETAINED_SHELL` as an INTERIM entry
added by #10991 to unbreak a red `main`, never as an end state.

Both collapse into one declaration on the mise `core:rust` entry:

```toml
rust = { version = "1.87.0", components = ["rustfmt", "clippy"], targets = ["wasm32-unknown-unknown"] }
```

**Deleted**: the script, its call site, the stale comment, and the allowlist entry
(plus its category mapping). Bash-retirement **removes** a shell file here instead
of permanently allowlisting one — retained shell goes 32 → 31, and
`check-bash-retirement-inventory.test.ts` is untouched: the ordering, duplicate,
categorization and drift invariants all still run and still pass.

## The hole this nearly shipped with

Found by measuring, not by reading the diff: **`.mise.full.toml` re-declared
`rust = "1.87.0"` as a bare string.** On mise 2026.6.14 that file is loaded
alongside `.mise.toml` and its `tools.rust` entry **wins** — `mise config get
tools.rust` resolved back to the plain string, silently dropping the components
and targets. The declaration would have been dead on every host carrying both
files, which is every checkout, and nothing would have failed to say so.

The full-tier mirror now carries the identical table, and a test asserts the
parity so a future partial mirror fails loudly instead of disarming the base tier.

## How provisioning was actually exercised

Run against an **isolated** `MISE_DATA_DIR` + `RUSTUP_HOME` + `CARGO_HOME` under
`/tmp`, and **without `--force`** — a `--force` probe earlier today uninstalled the
maintainer's local toolchain, so that path was avoided deliberately.

| check | result |
|---|---|
| **cold** `mise install rust`, empty `RUSTUP_HOME` | installed `rustfmt-preview`, `clippy-preview`, `rust-std-wasm32-unknown-unknown` + rustc/cargo — **no shell top-up** |
| binaries present | `rustfmt 1.8.0-stable`, `clippy 0.1.87`, `wasm32-unknown-unknown/lib/*.rlib` |
| **end-to-end** | that toolchain compiled `rustc --target wasm32-unknown-unknown --crate-type cdylib` → real wasm (`0061 736d 0100 0000`) |
| **negative control** | a bogus component was rejected by rustup **by name** (`error: component 'shadow-negative-control-not-a-component' … is unavailable`) — options are honoured, so the check *can* fail |
| **warm** `mise install rust` | 0.04s no-op, zero rustup invocations → offline property is stronger than the probe-first script it replaces |
| `mise config get tools.rust` | full table, `MISE_ENV` unset **and** `MISE_ENV=full` |
| host safety | `~/.rustup/toolchains` and `~/.local/share/mise/installs/rust` byte-identical before/after |

## What stayed UNEXERCISED — do not read the above as more than it is

- **The CDN-down falsifier was NOT re-run.** Blackholing `static.rust-lang.org`
  in `/etc/hosts` needs root on the maintainer's host, so it was not attempted.
  The offline claim in `mise.sh` is now split honestly: the *warm-skip* half is
  measured, the *end-to-end CDN-down* half is inherited from the 2026-08-16
  measurement against the script that no longer exists.
- **No CI runner and no devcontainer was provisioned from scratch.** All three
  consumers are served by the same declaration and both tiers resolve it, but
  the ubuntu-slim / arm runners and the devcontainer image were exercised only
  by CI on this PR, not by me locally.
- **macOS/aarch64 only.** The cold install was measured on
  `aarch64-apple-darwin`; Linux x86_64 and the nixos no-mise path were not.
- `tools/setup/common/install-rust-wasm32.sh` is **retained deliberately**:
  `tools/setup/linux.sh:466` calls it on the no-mise cluster-bootstrap path,
  where a `.mise.toml` declaration cannot run. Its allowlist entry stays, and its
  test stays.

# Notes

- Changing `.mise.toml` rotates the `install-v2-*` / `full-verify-v2-*` cache
  keys (they hash the file) — expect one cold run per job.
- The `1.87.0-*` rustup cache globs in `gate.yml` / `installer-unit-tests.yml`
  are unchanged and still correct; a future version bump must move them, and
  `.mise.toml` now carries that warning at the declaration site.
- `smoke-13-toolchains.sh` already **fails CI** when the wasm32 target is
  missing. That is the end-to-end falsifier for this declaration on real
  runners; its remediation hint now points at `mise install` rather than a
  manual `rustup target add`.
- Stale "added via `rustup target add`" comments in the `brew`/`apt` manifests
  were corrected. The `flake.nix` and `infra/nixos/modules/common.nix` mentions
  were left alone — those are the genuine no-mise paths.
