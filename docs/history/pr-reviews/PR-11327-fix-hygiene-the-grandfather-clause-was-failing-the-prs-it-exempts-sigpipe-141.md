## Description

`agencysignature (PR body)` **exits 141 on every pre-2026-08-15 PR** — so the grandfather clause, which exists precisely so old PRs are *not* blocked, was blocking them.

## Mechanism

The validator prints `GRANDFATHERED` and `return 0` **without reading stdin**. The upstream `gh api` producer then dies of `SIGPIPE`, and under `set -o pipefail` the step reports **141**. The tool succeeded; the step failed.

**A guard that fails the thing it exempts is worse than no guard.**

Found by an agent rebasing the stale-PR backlog. It hit **#10717** and **#10741** (both created 2026-08-14) and *cannot* hit post-cutover PRs — which is exactly why it went unnoticed: the only PRs it breaks are the ones nobody expected it to touch.

## Fix

Read stdin **once**, before the early returns, and reuse the captured text — so the producer always sees its reader drain to EOF. Guarded on `body === undefined`, since `--body` callers pipe nothing.

## Verified side by side

With a producer that exits cleanly (`seq 1 200000`):

| validator | exit |
|---|---|
| `origin/main` | **141** |
| this branch | **0** |

Tests: **52 pass / 0 fail.**

## A methodology note worth keeping

My first reproduction was wrong and I nearly shipped on it. I used `yes | head -N | validator`, which produces its own 141 — because `head` SIGPIPEs `yes` — so the *fixed* validator still showed 141 and looked broken. The bug was in the test harness, not the fix.

Recorded in the commit because the same shape will fool the next person: **when testing SIGPIPE behaviour, the producer must exit 0 on its own.**
