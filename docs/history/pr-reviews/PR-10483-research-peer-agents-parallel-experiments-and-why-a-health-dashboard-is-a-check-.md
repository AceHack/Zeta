## 1. Peer agents — demonstrated, not aspirational

This session: **peer agents caught more of my errors than the human did.** Soraya refuted my routing premise and found a TLC failure was neither of my hypotheses; Ilyana found my own proposed `Bound` DU *wouldn't have caught the `1.2`*; Lumen corrected me that Student-t *does* introduce a free parameter; the BDP harness inverted my burst-loss expectation; the P0 agent declined my filed proposal for a better reason than I'd given.

Marked **measured-once, not proven** — one session, and errors nobody caught are absent from the count by construction.

## 2. Parallel experiments change the human's *role*, not their throughput

| shape | human does | scales with |
|---|---|---|
| agent works → human approves | checks work already done | human attention (**doesn't scale**) |
| agents run N → human picks | **chooses among alternatives** | agent count (**scales**) |

Choosing between N results is *direction* — which this session showed is the input actually being supplied. Approving one result is supervision, which is the cap.

**Precondition:** N experiments are comparable only if conditions were identical, and "identical" must be **derived, not asserted**. That's exactly the Arena's capability-class / attestation-class / substrate-hash machinery — **the experiment-comparison surface and the tournament-result surface are the same problem.** Don't build it twice.

## 3. A dashboard is a check with the largest blast radius

**A dashboard is not a view. It is a check a human trusts *instead of looking*.** Other checks fail safe-ish — someone can still notice. A dashboard that's wrong **actively substitutes for noticing**.

### The live instance, from this session

I reported **"main green"** on nearly every tick for hours, using `gh run list --branch main --limit 8` — a **recent-window scan** — while **both heartbeat workflows failed on every single run**. Scheduled runs fell outside the window. A recent-window scan **cannot** see a steadily-failing scheduled job; not "usually misses" — *cannot*. A dashboard built on the convenient query would have shown the same green, to a human who'd stopped checking *because there was a dashboard*.

### Consequences

- **Derive what's displayed; never query a convenient proxy.**
- **The dashboard needs its own falsifier** — something red when the dashboard would show green over a failing covered thing.
- **Show coverage on the dashboard.** *"What am I NOT watching?"* is the question a dashboard structurally hides. `081KZYPHESJ` is this shape one layer down.
- **Per-entity last-state, not windowed aggregates** — the window is what made my check blind, and it's the default idiom in every dashboard tool.
- **Green must be earned.** No data ⇒ *unknown*, never *ok* — same one-way discipline as `Unmeasured` in `BusRegime` and `indeterminate` in the erasure meter.

## LLMTV is the same surface

A health dashboard and LLMTV are one surface at different granularities — fleet vs dweller, both one-way observation. Probably build them as one thing; building the dashboard **without** the frost/consent discipline would quietly create the surveillance surface LLMTV was designed to avoid.
