## Why

The browser already had a bounded receipt archive and an accepted passkey proposal path, but no source-owned boundary connected them. Treating issue submission as durable receipt acknowledgement would allow local compaction before repository persistence.

## What

- build deterministic content-addressed new-file patches under db/receipts/browser/v1
- expose injected signer and carrier ports with no repository credential in the database layer
- verify the BLAKE3 receipt address and exact SHA-256 signed patch binding before transport
- freeze batch, artifact, and signed-envelope values across injected capability calls
- return an explicit submitted receipt rather than the existing persistence acknowledgement, preserving the archive until a later accepted-record observer confirms storage
- export the new port from the browser-node source surface
