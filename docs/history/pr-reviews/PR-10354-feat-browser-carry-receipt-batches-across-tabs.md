## Description

## Why

The browser database receipt protocol already owned the immutable request/reply bytes, but tabs had no native transport adapter that could carry those batches between live browser contexts. This leaves same-origin peers dependent on injected test transports.

## What

- add an addressed native `BroadcastChannel` sender and receiver behind the source-owned receipt transport port
- bound request bytes, response bytes, deterministic sequences, and in-flight continuations on both sides
- preserve unanswered work until a response or explicit close; add no clocks, polling, or hidden timeouts
- isolate conflicting sequences and wrong-peer traffic, and convert malformed or blocked browser behavior into typed feedback
- export the adapter from the browser-node and emitted Dark Hall runtime surfaces
- exercise the emitted module across two real Chromium tabs in the PWA smoke

## Proof

- `bun test src/Core.TypeScript/browser-node` - 164 pass, 0 fail
- `bun run test:browser-pwa` - two real Chromium tabs complete a `[1,2,3] -> [3,2,1]` exchange with zero in flight
- `bun test` - 9,564 pass, 7 explicit live-integration skips, 0 fail
- `bun run preflight:quick` - 12/12 checks pass

## Limits

- this adapter is same-origin browser transport only; cross-device Reticulum transport remains a separate port adapter
- unanswered peers intentionally remain resumable until explicit close; no timeout policy is introduced here
