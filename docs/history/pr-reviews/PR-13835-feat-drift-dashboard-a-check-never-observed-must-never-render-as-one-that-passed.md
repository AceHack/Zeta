## Description

## The occasion — a real, measured failure

`gh run list --branch main --limit 200` — the query the fleet had been reporting **"main is clean"** from — contained runs from only **22 of 81 active workflows**. Heartbeat traffic saturates the window; its oldest run was from 15:25 the same day.

A window sample is not a slow instrument. It is a **structurally blind** one, and its blindness renders as green. Scanning latest-run-per-workflow instead immediately surfaced four workflows failing unseen, one red since 08-16 — weekly, so it sat red for six days. Those four are being fixed elsewhere. **This PR is the instrument that would have caught them on day one.**

The failure class: *a check that was never observed rendered identically to a check that passed.*

## Unknown is first-class, and mechanical

> *"Unknown is a first-class verdict that can never aggregate into green yes this would be Ideal, this is what most humans and AI are not good at keeping in their head the unknowns they forgot about lol, so the more mechanical the better."* — Aaron

- **Persisted roster** (`db/drift-dashboard/roster.json`, text, diffable). A check that stops reporting keeps its slot and keeps counting. A vanished check is marked `declaredNow: false` and **does not shrink the denominator**. Retirement is written by hand with a reason; no code path sets it.
- **Five unknown reasons, non-interchangeable** — modelled as a discriminated union so an `unknown` is *unconstructible* without saying which one: `never-observed` · `not-observed-this-pass` (today's bug wears this one's clothes) · `registered-but-absent` · `expectation-unknown` · `source-error`.
- **Aged and ranked.** Unknowns sort longest-silence-first; never-observed sorts as *infinite* silence, because that is what it is. The oldest silence is in the headline. An unknown displayed but not **distinguished** has not been surfaced.
- **Coverage is in the headline**, and any shortfall is red. Unknowns never count toward coverage, so `shortfall == unknown count` holds **by construction**.

### Expected-absent vs unexpectedly-absent — derived, never assumed

| declared trigger | silence means |
|---|---|
| `periodic` (a cron) | **RED** — it should have run |
| `on-change` (push to the ref) | unknown, ranked high |
| `on-demand` (PR / dispatch / `workflow_run`) | **correct** — `not-applicable`, and deliberately *not* called green |
| `unknown` (underivable) | unknown, **loud** — never defaulted to the convenient case |

Two red conditions a last-run-only model **cannot** see:

1. **Staleness** — a periodic check whose newest verdict is *green* but ancient did not run.
2. **The declared trigger has NEVER fired.** `chart-version-refresh` declares `7 17 * * 0`; every run in its history is `event=pull_request`. The adapter asks the declared trigger **directly** (`?event=schedule`) rather than asking what ran last.

## The seven-mode taxonomy — every one measured in this repo on 2026-08-22

Each is a distinct way *a check that did not run looks like one that passed*, and **none is detectable by "read the latest run's conclusion."**

| # | mode | how it hides | state in this model |
|---|---|---|---|
| 1 | **Sampling** | a 200-run window held 22 of 81 workflows | roster + latest-per-check; a window is never sampled |
| 2 | **Frozen roster** | a cached workflow list cannot grow, so new checks are invisible | the roster is re-derived every pass and merged; the denominator **grows** |
| 3 | **In-progress masking** | `gate`'s newest run was `in_progress`, so its last concluded `failure` did not show | the last **concluded** verdict is displayed; a running run **annotates** (`recheckInFlight`), never overwrites |
| 4 | **Cancelled-as-clean** | a killed run reads as an absence of failure | `cancelled` ⇒ `unknown`; never satisfies a check, never counts toward coverage; repeated cancellation is its own red (**dark lane**) |
| 5 | **Registered-but-absent** | active on the forge host, no file in the repository — invisible to a run check *and* a file check | `unknown{registered-but-absent}` |
| 6 | **Never-fired trigger** | a declared cron that has never produced a scheduled run | the producer asks the declared trigger directly (`?event=schedule`); red **only once the trigger has had an opportunity** |
| 7 | **Green-but-never-exercised** | `lockfile-healer` / `zetadb-scheduled-node` are green because they **no-op before** the now-forbidden `git push origin HEAD:main` | **NOT MODELLED — argued below** |

### Why mode 7 is named and not modelled

Both workflows still contain `git push origin HEAD:main`, which the ruleset forbids (`gate (required)`, `bypass_actors: []`, at push time). Both are green **only because they exit before reaching it** — one prints `No new database events to checkpoint.`, the other has had no lockfile drift since 08-09. They will fail the first time they have work to land.

I am not adding a verdict case for this, and **the refusal is the point**. A model slot no producer can fill and no test can falsify is the vacuity class wearing a taxonomy entry — it would read as coverage and constrain nothing, which is the exact defect this surface exists to refuse. Detecting it needs **path coverage inside a run**, a different instrument from a verdict roster. Recorded as the strongest open, with both instances named, so it is a gap someone can pick up rather than one nobody knows about.

### Both directions of error are real, and I made one of each

- **Unknown rendered as green** hides a failure. That is the occasion for this work.
- **Unknown rendered as red** burns the alarm's credibility until someone mutes it — worse than not having the alarm. `chart-version-refresh` was reported as a never-fired weekly cron; it landed on `main` **Friday**, its cron is **Sunday**, and the report was written **Saturday**.

Hence **`not-yet-due` as its own state**, gated on the *definition's* age (`git log --diff-filter=A`) rather than the dashboard's. Honest limit stated in the code: *one full period since the definition landed*, not *a matching cron instant has occurred* — a sound over-approximation that never raises a false alarm and at worst delays a true one by under one period. An unknown definition age **declines to alarm**, deliberately.

### The dark-lane discriminator is SPAN, not count

`tlaps-proof` over its last 40 runs: **33 cancelled, 7 failure, last success 2026-07-01** — seven weeks of a gated proof lane switched off, rendering as "not failing" everywhere. The fact was already in `apt-job-timings.measured.json`, on no surface anyone looked at, which is this dashboard's whole reason to exist.

But `gate` is cancelled by its own concurrency group on ~88% of pushes (265/300 measured) and is perfectly alive. **A count threshold calls `gate` dark and gets muted within a day.** A span threshold — inconclusive attempts newer than the last verdict spanning >6h — catches only the lane that has actually stopped concluding. Both cases are pinned by falsifiers. `runsPerCheck` is **20, not 5**, for the same reason.


## Falsifiers

**4 required, all present and all failing when the behaviour regresses:**

1. **A check absent from the observation set renders `Unknown`, never green** — plus the `never-observed` vs `not-observed-this-pass` split, and a 20-check pass observing nothing that yields **zero** greens.
2. **Latest-per-check** — newest wins regardless of array order; an older green cannot mask a newer red; ties break deterministically; the roster's memory is monotone under replay.
3. **Coverage shortfall is red** — including the live 81/22 shape, and a vanished check that does not shrink the denominator.
4. **Substrate independence — written first.** The core folds observations carrying **no forge fields at all**, and the same `CheckId` under a different producer yields a byte-identical report modulo provenance.

**121 tests** across fold / roster / render / triggers / mapping. Plus **29 hand-written mutants**, each **byte-verified as applied** before its result was believed — a harness that patches nothing manufactures fake survivors. **29 killed, 0 survived.** The new ones cover every rule above, including *"dark lane triggers on COUNT (would flag `gate`)"* and *"unknown definition age ALARMS instead of declining"*. Two survived on the first run and are fixed in this branch: a vacuous host-managed test that asserted string prefixes rather than the classification (the code was refactored into a pure `expectationForWorkflow` so it could be tested at all), and `triggerClassForEvent` having no test whatsoever.

`.claude/rules/async-all-the-way-truthful-signatures.md`: parallelism goes through `FerryThrottler` with a real DoP knob that **degrades to 1**. DoP=1 and DoP=12 produce byte-identical row order against the live repo; a full 81-workflow pass takes ~5s at DoP=8.
