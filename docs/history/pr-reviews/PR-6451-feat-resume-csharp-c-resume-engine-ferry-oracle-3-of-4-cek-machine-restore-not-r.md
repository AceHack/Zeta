## Description

## What

C# resume-engine ferry — **oracle #3 of 4** (TS reference done; F# landing via #6448; Rust next) for the 081KT07NV0008QG0R003BE6MJ2 resume slice. New `Zeta.Core.CSharp.Resume` project that **reuses** the C# Bonsai oracle's types (`Expr`/`ConstValue`/`BinOp`/`Result`/`BonsaiFeedback`) + `BonsaiCodec` for embedded-expr serialize/parse — it does **not** re-implement them (own-our-interface; the Bonsai project IS the port).

- Small-step **CEK machine** over the Bonsai-subset `Expr`; `Invoke` nodes are activities (suspension points). Pure parts evaluate inline; at an activity the machine suspends, handing back a serializable `SagaState` (continuation + pending activity). `Resume` **restores** the continuation without re-invoking prior activities (vs Temporal-style replay).
- Result-over-throw; the internal mechanism is a private typed exception adapted to `Result` at the two public boundaries.

## The three correctness properties from the F# ferry (#6448), baked in

1. **Depth ceiling** — `ParseState` tokenizes with `BonsaiCodec.MaxDepth*4` headroom (default `JsonDocument` MaxDepth = 64 would reject a valid program whose inline-embedded `Expr` nests past 64).
2. **`long`-overflow guard** — `ApplyBinOp` does arithmetic in `BigInteger` first. C# `long` silently **wraps** on overflow (TS floats don't — `Number.isSafeInteger` still catches them), so `4294967296^2 = 2^64` would wrap to **exactly 0** and return a silently-wrong `Number 0`. Now declines `NonSafeInt`.
3. **Escaper** — state strings use a `JSON.stringify`-matching surrogate-aware escaper (not `JsonSerializer`, which escapes `<` etc.), so state bytes match the reference.

`kont` order matches the **TS reference** exactly (index 0 outermost, last = top-of-stack; push appends), so C# state bytes equal the TS reference by construction.

## Tests

9 tests (`tests/Tests.CSharp/Resume/ResumeTests.cs`): golden replay (restore-not-replay at every suspension) + 4 feedback cases + the 3 regression cases (silent-wrong mul, deep-embedded restore, `JSON.stringify` escaping) + malformed-state. All pass; `Zeta.Core.CSharp.Resume` builds **0 warnings / 0 errors** under `latest-recommended` + Meziantou.

## ⚠️ Finding to flag — resume-state is NOT actually cross-oracle byte-locked yet

While building this I discovered the four-oracle "byte-locked" claim does **not** hold for resume **state serialization** (it does for Bonsai expr serialization):

- The `cond_branch_on_activity` golden trace suspends at `roll()` with a **2-frame** kont (`evalRight(lt,…)` + `branch(…)`).
- **TS** represents the stack as an array (top *last*) → emits `branch, evalRight`.
- **F#** (#6448, just landed) uses a cons-list (top *first*) → emits `evalRight, branch` — **reversed**.
- The behavioral + per-oracle round-trip tests **cannot** catch this (each oracle is internally consistent). Only a cross-oracle *byte-equality* assertion would.

This is fine for the **slice-1 contract** (the golden's own description = same suspension sequence + final value + per-oracle round-trip, which all oracles meet; cross-machine byte-identity is a stated slice-2 goal in `resume.ts`'s header). But it means a TS-persisted state would not restore on F# for multi-frame konts.

**This C# ferry matches the TS reference** (top-last), so C# == TS by construction. Recommended follow-up (not in this PR — it's a cross-oracle contract decision + touches the in-CI #6448):
1. Align the F# `kont` order to the TS reference (serialize/parse reverse the cons-list).
2. Add an `expectedStateAtSuspension` field to `resume-golden.json` so every oracle asserts its `SerializeState` bytes equal the TS-authored expected — the assertion that would have caught this.
