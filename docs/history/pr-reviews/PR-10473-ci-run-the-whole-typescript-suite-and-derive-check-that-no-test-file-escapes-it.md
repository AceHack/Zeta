The checker is modelled on `lean-orphan-modules.ts`, which solved this exact shape for Lean. It **derives** what CI runs by parsing every workflow's `bun test` invocations and applying bun's own filter semantics (positional arguments are *substring* filters against the path, resolved from the step's `working-directory`; no arguments means everything under the cwd). Coverage is credited only to `pull_request`-triggered workflows: a cadence run reports drift *after* a merge and does not stop the PR that broke it. A file `bunfig` hides counts as **unexecuted**, so ignoring a test cannot become the quiet way out.

Three fatal verdicts -- undeclared, empty reason, stale entry -- and two **non-vacuity floors asserted first**, so a broken walk or a broken parse fails loudly rather than reporting a clean sheet on an empty set.

## Judgement calls, and the reasons

**Bare `bun test`, not a directory list.** Every filter list is a fresh copy of the same defect -- `forge-host/` fell outside the old globs precisely because someone had to remember to add it. A bare invocation cannot have that bug: a new directory is covered the moment it exists. Exclusions therefore live in exactly one place, and each must carry a written reason.

**A separate job, not a step in `lint (TS)`.** That job type-checks; folding behaviour into it puts two different failures behind one red X, which is the attribution problem the 2026-06-13 per-language lint split already solved once here. It also carries a 12-minute cap sized for `tsc`.

**One job, not a parallel split.** Per-job fixed cost is the `install.sh` bootstrap plus `bun install` -- 1-2 minutes even on a cache hit -- against about 5 minutes of test time. N jobs multiply the fixed cost for a wall-clock saving that does not pay. Revisit past ~10 minutes.

**`tests/` is swept in, and that is deliberate.** It was measured separately: 259 tests across 30 files in 38s, with the only failures in `cross-verify-ir.test.ts`, which needs all seven toolchains. The new job runs `install.sh`, which provides them, so it should pass there; `full-verify` keeps its own named steps for that tree and keeps its floor status, so nothing about the treaty byte-lock lane changes.

**RUN, DO NOT BLOCK.** The new job is deliberately **absent** from `gate-required`'s `needs` list. The 2026-08-01 drift-and-heal ADR narrowed the blocking floor to `registry/uncompensatable-floor.yaml` after a priority-inversion incident; making 755 long-unrun files blocking on day one would be that inversion again. Running them *is* the drift signal. Promotion to the floor is a separate treaty amendment, once this job has a track record. **Nothing currently blocking is weakened.**

## Cost

About **9 minutes per run** (setup plus tests) on `ubuntu-24.04` at the 1x multiplier; at roughly 250 gate runs per month that is on the order of **2,250 runner-minutes added**. It buys execution of ~755 files and ~9,000 assertions that today execute nowhere.

## Where the measurement contradicts the work-item

The item recorded `7339 pass / 0 fail / 210.39s` for `src/Core.TypeScript/` and concluded that "nothing needs quarantine." **Three runs on the same machine give 298s, 257s and 346s, with 4 failures on the first and 1 on each of the others.** The repeat offender is `health/factory-health-monitor.test.ts`, whose `runHealthCheck` probes the live repository and **times out after 60s**, carrying the file to 93s; the first run additionally **created a real `kind` cluster** from `cluster/dev-cluster/use-cases.test.ts`. The item's zero-failure figure was a lucky run, not the state of the suite. Both files are now excluded with measured reasons rather than left to make the lane flaky -- and losing 50 genuine assertions in `factory-health-monitor` is a real cost, recorded in the allow-list rather than hidden.

## A finding this change already bought

`no-agent-gate-bypass.test.ts` **passes in isolation and fails in the whole-suite run.** That is a genuine test-isolation defect, invisible until the suite ran as a whole, and it is exactly the class this PR exists to surface. It is reported, not papered over. The job being non-blocking is what lets it be triaged without holding unrelated lanes.
