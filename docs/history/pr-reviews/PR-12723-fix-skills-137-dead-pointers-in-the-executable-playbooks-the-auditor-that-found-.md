## Description

`audit-rule-cross-refs.ts` has checked `.claude/rules/*.md` for stale pointers since #3202. **Skills were never in scope.** But rules hold carved sentences while `.claude/skills/` holds the procedures agents *execute* — so a dead pointer there is strictly worse: an agent following step 0 of a blueprint silently no-ops and continues as though the step ran. The vacuity class in executable form.

## How it was found

Following one filed instance (`081M0DXM725087G0R002YDM382`): the formal-verification-expert blueprint's step 0 cites `tools/alignment/concept_registry.ts`.

I first recorded that as *"the file does not exist."* **That was wrong.** The registry is real, its `KNOWN_ANCHORS` map is exactly what the step describes, and it lives at `src/Core.TypeScript/alignment/concept_registry.ts`. A stale path, not a missing artifact — which is a much more fixable problem, and suggested a class.

**The class: 218 unresolved of 2,325 repo-root-anchored refs across 291 skill files (9.4%).**

## What was actually wrong — three mechanical causes

| cause | refs |

**137 fixed here. Residual 81 filed as `081M0FDDTJ9087G0R00081B737`** — those resolve nowhere at all and need a per-item call between *create the artifact* and *delete the false claim*. Bulk-editing them to silence the auditor would be manufacturing resolution, which is the failure this tool exists to catch.

## The frame is the finding

A naive first pass reported **447** stale. Most were bare filenames and prose placeholders — `docs/FOO.md`, `src/Core.CSharp/X.cs`, `roundN.json` — shapes being *illustrated*, not artifacts being *cited*.

Reporting 447 would have been a numerator against an invented denominator. Those are **excluded from the frame, never counted as passing**, and the exclusions are what the tests pin hardest.

Three states, because `archived` and `stale` want different remedies:
- **live** — resolves as written
- **archived** — basename found under an archive dir. *Misleading, not missing.*
- **stale** — resolves nowhere. The real finding.

## Why a separate auditor, not a flag on the rules one

The rules auditor's resolution model is rules-specific: sibling-rule lookup for bare names, rules-relative joins, archive fallback. Skills cite repo-root paths. Folding them would either import false positives from the sibling heuristics or dilute them. Two honest models beat one tangled one.

## Mutation-checked — and it caught my own vacuous guard

| mutant | result |
|---|---|
| drop `PLACEHOLDER_SEGMENTS` | 10 pass / **1 fail** |
| archive-match by suffix not basename | 9 pass / **2 fail** |
| drop glob/template guard | 10 pass / **1 fail** |
| drop bare-filename guard | **11 pass / 0 fail — SURVIVED** |

That last mutant survived because the guard was **unreachable**: every ref carries a file extension, so a bare filename's first segment can never equal a real top-level directory, and the dir check already rejected it. A check whose removal no test can detect is a check that cannot fail — the exact class this auditor exists to find. Removed it rather than keep a passing-looking guard, and said why at the site.
