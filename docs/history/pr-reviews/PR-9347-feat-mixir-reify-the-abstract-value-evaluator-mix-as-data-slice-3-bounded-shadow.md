## Description

## What

Aaron 2026-07-03: *"bounded reify — make abstract-eval data, leave the universal driver native … this is basically our Shiva Garbage Collector."*

Slice 1 reified the mix's **parameters**; slice 2 its **decision procedure**; slice 3 its **abstract-value evaluation**. `tryStatic`'s per-Val-kind static-ness logic (fld reads the instruction, reg looks up known registers, add/sub combine, …) is now a data **`evalDef`** rule table read by a fixed engine (`IsaSpec.tryStaticReified`): five abstract primitives (`field`/`const`/`lookup-reg`/`lookup-mem`/`combine`); which one each Val-kind uses is the value.

`specializeFullyReified` runs the mix with `mixDef` + `evalDef` + `loadDesc` **all data** — so the **only** native part left is the universal step-driver (the fold-over-instructions loop + materialization), the same for every ISA and every algorithm. That's the honest bounded endpoint: everything ISA- or algorithm-specific is a value; the driver is the fixed step machine.

## The Shiva-GC seed (Aaron)

These reified tables are **weak-reference-shaped data** — because the mix's rules are values, not baked code, the parts of the substrate nothing references can be **collected**. Reify → collectible; the generator emits the tables, the collector (Shiva) reclaims the unreferenced ones. Slice 3 is what makes a GC over the mix *possible*. (Seeded here; the collector itself is the next ferry.)
