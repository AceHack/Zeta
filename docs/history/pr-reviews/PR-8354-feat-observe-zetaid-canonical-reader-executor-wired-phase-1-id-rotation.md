## What

Phase 1 of the zero-downtime id-rotation pattern (overlap-window dual-key):

- **autonomous-pickup.ts**: reads `zetaid` as canonical id; dual-lookup resolves both ZetaId and legacy B-xxxx during overlap window
- **kiro-executor.ts**: real `just-bash` CommandExecutor for the observe loop (creates claim branch + runs bounded work)
- **run-loop-real.ts**: wired executor + doItemOpts so `do_item` is executable end-to-end
- **b-to-zetaid-map.json**: persistent mapping table (1,131 entries) for Phase 2 batched migration
- **ADR**: documents the reusable pattern with formal properties (safety/liveness/retraction-algebra reading)

## Why

B-xxxx is a sequential counter — agents collide on 'next number.' ZetaId is 128-bit, locally mintable, zero-coordination. This kills the operational B-xxxx dependency immediately (Phase 1), with batched depends_on migration to follow (Phase 2).
