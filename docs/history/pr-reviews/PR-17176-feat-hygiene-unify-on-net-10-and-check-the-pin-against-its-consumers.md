| surface | was |

Nothing in the tree could notice.

`audit-dotnet-pin-parity.ts` holds `.mise.toml` and `global.json` equal and is correct about those two files. It says nothing about the places that **spend** the pin. The holdout is not in `Zeta.sln`, is not built by CI, and carries a deliberately empty `Directory.Build.props` so it escapes the strict profile — which is exactly why the drift was silent: **the only surface that would have caught it is one nothing compiles.** A pin nobody checks against the things it pins is a declaration, not a constraint.

## Is `auth-backend` live? Dormant, not dead.

Checked before spending effort, per the ask:

- no workflow builds it (`grep -rln genesis .github/workflows/` → nothing)
- absent from `Zeta.sln`
- no k8s manifest or `image:` anywhere references it
- `genesis/auth-config.js` ships `base: ""` — **nothing is deployed**

But it is a documented, self-contained OAuth broker the static Genesis site is written against, and retiring it deletes the only answer to a problem that site still has (a static page cannot hold a client secret). Three lines to keep it in band; the audit is what stops it drifting again while nobody is compiling it. **Proposing keep, not retire** — happy to be overruled.

## What moved

- `GenesisAuth.csproj`: `net8.0` → `net10.0`
- its Dockerfile: `sdk:10.0-noble` + `aspnet:10.0-noble`, digest-pinned

Both digests were **resolved from the MCR registry**, not copied. The `sdk:10.0-noble` digest came back byte-identical to the one `orleans-silo/Dockerfile` already carries — a free cross-check that the existing pin is current.

`dotnet build -c Release` on the upgraded project: **0 warnings, 0 errors.**

`netstandard2.0` stays on `Zeta.Generators` and `Core.CSharp.TypeProvider` — not drift; both are loaded *by* the compiler, so the analyzer contract fixes that target independently of the SDK. Each is named with its reason, and a **stale exemption is itself a failure**: "any netstandard is fine" would be a hole wide enough to drive real drift through.

## The falsifier

`src/Core.TypeScript/hygiene/audit-dotnet-runtime-band-unity.ts` derives the band from the canonical `.mise.toml` pin and refuses any `TargetFramework` or `mcr.microsoft.com/dotnet/*` tag outside it.

It also **refuses an empty scan in either category**. A regex that stops matching after a format change would otherwise report success — that refusal is what makes the other two checks mean anything.

Wired into the `cross-verify` floor through `CROSS_VERIFY_AUDITS`, so `gate.yml` is regenerated (`--derive --write`) rather than hand-edited.

## A defect the repo caught in my own code

`lint-check-then-use-file-races` flagged a `readdir-then-stat` race in this audit's tree walk on its first run. **Fixed at the root rather than baselined**: `readdirSync(..., { withFileTypes: true })` means the listing already carries the kind, so nothing asks the filesystem twice.
