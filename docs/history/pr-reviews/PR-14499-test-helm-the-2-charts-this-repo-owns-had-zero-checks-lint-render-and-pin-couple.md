The two charts are `examples/helm-dependency-graph/charts/{my-app,postgres}`.

`helm-validate.yml` already existed and does render charts — but it validates
ArgoCD **Application** manifests that pin **third-party** charts, filtered on
`infra/k8s/**`, `full-ai-cluster/**` and `infra/nixos/**`. The charts we author
sat outside every filter. `Chart.yaml` was not read by a single line of code in
the tree: `ace/deps.ts` accepts `--charts-dir` and opens only
`zeta-chart-outputs.yaml` under it.

## After

Both charts are checked, by `src/Core.TypeScript/hygiene/audit-local-helm-charts.ts`, which
**discovers** charts by walking for `Chart.yaml` rather than hardcoding two
paths — a chart added anywhere is covered with no edit to this file.

| Check | Catches |
|---|---|
| `Chart.yaml` parses | tabs, unterminated quotes, unclosed sequences |
| `apiVersion` is `v1`/`v2` | a chart Helm refuses to load |
| `name` present **and matches its directory** | **`helm lint` does not catch this** |
| `version` present, string, valid SemVer 2 | `version: 1.0` (a YAML float), `version: notasemver` |
| `zeta-deps.yaml` pin agrees with `Chart.yaml`, both directions | a chart bump that leaves the graph behind |
| `helm lint` | Helm's own metadata rules |
| `helm template` | a chart that cannot render |
| `kubeconform` over the render | manifests violating the k8s API schema |

## The part that matters most — what this refuses to claim

Both charts are **metadata-only**: no `templates/`, no `values.yaml`.
`helm template` renders **zero** documents and exits 0, so kubeconform
schema-checks **nothing**. Wiring that up and printing a green tick is exactly
the vacuous check this repo exists to refuse.

So the tool counts rendered documents and says so on every run:

```
Schema-validated manifests: 0
NOT SCHEMA-VALIDATED (stated, not silent): 2 chart(s) rendered no manifests, so kubeconform checked nothing for them:
  - examples/helm-dependency-graph/charts/my-app -- rendered 0 manifests (metadata-only chart: no templates/ directory)
  - examples/helm-dependency-graph/charts/postgres -- rendered 0 manifests (metadata-only chart: no templates/ directory)
```

The README carries the same disclosure plus the other three gaps: **no
values-overlay matrix** (no `values-*.yaml` variants exist to exercise), **no
cluster behaviour** (that is `OPERATOR-VERIFY.md` and needs a live cluster), and
third-party pins belonging to another lane. An empty discovery result **fails**
rather than reporting "0 failed" — an empty run is not zero failures.

## Three defects CI and I found in this PR's own work

Recorded because a PR that only reports its successes is not evidence.

1. **I put the validator in a tree scheduled for deletion.** `lint (yaml/k8s)`
   went red: `audit-cluster-tree-consumers.ts` refuses new coupling to
   `infra/k8s/`, and that roster's own `helm-validate.yml` entry already said
   *"move the validator out of `infra/k8s/tests/`"*. Moved to
   `src/Core.TypeScript/hygiene/`. The remaining prose mentions are rostered as
   `prose`, so `blocking+derived` stays at **16** — this makes the tree no
   harder to delete.
2. **A TOCTOU race, which reddened both failing jobs.**
   `lint-check-then-use-file-races.ts` found two `[readdir-then-stat]` findings:
   both walkers listed names then `statSync`'d each entry for a kind the listing
   already knew. Fixed with `withFileTypes: true`; `statSync` is gone from the
   file. It got there because my first draft hit a typecheck error on
   `ReturnType<typeof readdirSync>` and I reached for `{ encoding: "utf8" }` —
   which silenced the type error and locked in the extra syscall.
3. **Two vacuities in my own validator**, found by breaking the real charts (see
   above), both now carrying regression cases.

An ace-suite failure I saw locally (2 fail, 143s) was **not** a regression:
re-measured, both were timeouts under contention from a concurrent 233s hygiene
run. Clean re-runs — this branch 680 pass / 23.1s, a pristine `origin/main`
worktree 680 pass / 27.2s. CI's `cross-verify` never reached the ace step. Noted
rather than dropped, because "it passed the second time" is also what a real
