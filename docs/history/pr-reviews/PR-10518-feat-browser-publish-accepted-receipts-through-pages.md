## Description

## Why

The browser can submit signed receipt proposals without repository credentials, but it still needs public, immutable evidence that an accepted record reached `main` before compacting local receipt history. The existing Pages deployment is the repository-owned read surface for this evidence.

## What

- export accepted receipt records into a deterministic Pages index bound to the checked-out commit SHA
- copy record bytes exactly and fail the build on malformed entries or finite-budget exhaustion instead of truncating history
- add a browser-safe, same-origin HTTPS accepted-record source with no credentials and bounded streamed reads
- keep final identity, revision, path, size, and byte equality checks in the existing acceptance observer
- integrate the projection into `pages:build` without pulling Node APIs into the browser module graph
- ignore generated `dist/` Markdown during source lint and repair two stale workitem source paths found by the repository gate

## Proof

- `bun run pages:build`
- 64 focused tests across passkey verification, gated planning, receipt proposal, acceptance, handoff, outbox, Pages build/read, and PWA build
- `bun run preflight:quick` after rebase: all 12 checks passed
- clone pre-push hook: all 12 checks passed again
- browser bundle inspection: Pages source contains no `node:fs`, `node:path`, or `Bun.spawn`

## Limits

This lands the public delivery/read adapter. The active Dark Hall page still needs to instantiate the signer, proposal carrier, Pages source, and acceptance observer on its bounded retry cadence.
