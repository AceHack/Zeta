## Why it matters beyond one job

**A cancelled job reports as a red check indistinguishable from a real failure.** It cost four spurious reds today across unrelated PRs (#9893 ×2, #9903, #9908) plus rerun cycles — and each one needed diagnosing *"is this mine or infrastructure?"* before it could be dismissed.

That's exactly the false-signal class this repo spent the day removing everywhere else.

## The deeper issue — deliberately not fixed here

`audit-tick-shard-relative-paths.ts` imports **only node built-ins** (`node:fs`, `node:path`, `node:child_process`). It needs a JS runtime and nothing else, yet installs an entire toolchain to get one.

**gate.yml runs `install.sh` in 64 jobs and `setup-bun` in 2.**

Caching install.sh's output, or using setup-bun for runtime-only jobs, would eliminate this class across all 64. Both need a deliberate decision:

- the Actions cache is **already at 10.05GB of a 10GB ceiling** — a toolchain cache would evict existing entries
- **§24** makes install.sh the single install path consumed three ways; bypassing it in CI weakens the parity guarantee it exists to provide
