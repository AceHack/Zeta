## Description

Discharges §11g of `docs/research/2026-08-18-an-unmetered-channel-is-a-maxwells-demon-…-landauer.md`, whose §4 placement claim was refuted the same day it was written:

> **Meter by injectivity, not by lifecycle stage.** The declaration lives beside the operation, the measurement is an exhaustive sweep, and the two must agree in **both** directions. Extend that existing machinery to the spine/log/eviction sites, which currently declare nothing; do not build a second list.

`src/Core/ErasureClass.fs` moves the `WSetHeat` vocabulary down the compile order so representation-owning types can declare against it. `WSetHeat` is **rebased onto it**, not left as a parallel taxonomy. Eleven representations declare via `IErasureDeclaring`; three law packs (F# core, F# git, TypeScript) measure by sweep and check both directions. §12 of the doc records what landed.

## The design question, and the answer taken

§11i's sharpening was that **erasure is a property of the representation**. `IDeltaLog.TruncateAsync` is one method with one call site (`RecoverableSpine.fs:74`) and four classes across the shipped backends:

| representation | class (read surface) | why |
|---|---|---|
| `InMemoryDeltaLog` | **Erasing** (13, 3.700 b) | `list.RemoveAll` |
| `DiskDeltaLog` | **Erasing** (9, 3.170 b) | files unlinked |
| `ZetaFsDeltaLog` | **Erasing** (13, 3.700 b) | ref moved, old tree orphaned |
| `GroupCommitDiskDeltaLog` | **Reversible** (1, 0 b) | a no-op; compaction unimplemented |
| `GitDeltaLog` | **Erasing** here; **Reversible** through the commit DAG | truncated tree committed **with the old commit as parent** |

So the interface is the level at which the class is *undecidable*. `IDeltaLog` is left alone and each concrete backend answers for itself. A reflection drift guard fails when a type implements a preimage-bearing interface without declaring — silence is not a passing state.

**The composite is the sharp case.** `RecoverableSpine` **derives** its class by reading the injected backend rather than asserting one: `Erasing` over the in-memory log, `Reversible` over a preserving one, and `Unmeasured` — never free — over a backend that declares nothing. That last case is the drift guard at runtime, where a reflection test over our own assembly cannot reach a caller-supplied type.

**And the observation is load-bearing too.** `ZetaFsDeltaLog.TruncateAsync` is `Erasing` through its read surface and `Reversible` through the object store, because the superseded tree is an orphan nothing traverses to. Two honest rows beat one dishonest average, so the key is `(Representation, Operation, Observation)`.

## Two measurements that contradict the doc that asked for this

1. **Quota eviction erases nothing.** `Reversible`, zero bits — the spill writes the payload out and `Load` returns it byte-identical. §4 listed eviction; §11b demoted it; it is not a candidate at all. Stated as a commuting square: the content function under a quota that spills on every save is byte-identical to one that never spills.
2. **The bits are elsewhere, again.** `Save` is `Erasing` because a content-addressed upsert is idempotent, not because of eviction. In the DHT, k-bucket eviction accounts for 0.585 of `observeNode`'s 2.585 bits and the **idempotent refresh accounts for the other 2.000** — a separately declared, separately swept row.

## `Unmeasured` is a class, and it is not zero

`bitsErasedPpm` returns `None`, never `0L`. Five rows use it, each with a written reason: the storage medium after an unlink; `WitnessDurableBackingStore.Release`, whose only domain is one point (**a sweep that cannot fail is not evidence**); and **`GiftOfErasure.forget` with respect to the process heap** — the row that matters most, since the module's whole purpose is unrecoverability and an immutable value the caller may retain has not been forgotten at all.

## Not in this PR

**No entropy charge.** `entropy-tracker.ts` is untouched — this classifies; metering is a separate decision with its own review. Findings 1 and 2 above are the argument for keeping them apart: a meter wired to the pre-measurement intuition would have been charging for months. §11f's `Heat.fs` demon is likewise left alone; it is a charging decision.
