## Description

## What

The **first git-native persistence backend** behind the durability ports we own
(`IDeltaLog<'K>` / `ISnapshotStore<'K>`), LibGit2Sharp-backed. This is the
maintainer's sequenced next step: *"get the DB running end-to-end with git as its
persistence layer"* before the yin/yang layer and (much later) observe.ts wiring.

- **`GitDeltaLog<'K>`** — the log **IS git**. Each `AppendAsync` is a commit on
  `refs/zeta/deltalog`; the commit tree accumulates one blob per entry under
  `deltas/{seq:020}` (length-framed `[capLen:int32-LE][capturedJson][deltaBytes]`,
  delta bytes via the byte-verified `IDeltaCodec`). History = the commit DAG = the
  log for free. **Z-set retraction = appending the inverse delta as a new commit**
  (git never rewrites history — Landauer-honest, Memory-Preservation §5).
  `TruncateAsync` rewrites the tip tree without the GC'd blobs but preserves
  highwater in the commit message (never rewinds across restart).
- **`GitSnapshotStore<'K>`** — consolidated folds as blobs on `refs/zeta/snapshots`
  with a committed `LATEST.json` manifest, so `LatestAsync` survives restart (the
  cross-restart snapshot+tail recovery `RecoverableSpine` relies on).

## Proven end-to-end

`tests/Tests.FSharp.Git` (14 tests, all green) wires `RecoverableSpine` over the
**git backends**: commit input deltas → auto-snapshot+GC at cadence → "crash"
(drop the in-memory spine) → `RecoverAsync` from the git repo alone → **exact**
consolidated state. Covers retraction-to-zero, restart-after-truncate highwater
preservation, and snapshot+surviving-tail recovery.

## Design notes

- **Hexagonal** — LibGit2Sharp is the v1 adapter; a pure-managed loose-object
  backend can replace it later without touching any caller (the maintainer's
  explicit choice: *"hexagonal interfaces we own and our first version is
  implemented with libgit2sharp we can phase it out later"*).
- **Honest async (FoundationDB north-star)** — libgit2 has no async surface, so
  the adapters do their work inline and return completed `ValueTask`/`Task` —
  truthful (cf. `InMemoryDeltaLog`), **not** `Task.Run`-over-sync fakery.
- **Native-dep isolation** — LibGit2Sharp lives only in `src/Core.Git` and the
  separate `tests/Tests.FSharp.Git` project, kept out of the main F# suite to bound
  the native-binary platform surface.

## Why a PR (not direct-to-main)

LibGit2Sharp is a **native** dependency. Opened as a PR so CI validates the native
binaries on **every platform leg (esp. windows-11-arm)** before this can red main.
Verified locally on macos-arm64 (restore + `Repository.Init` + 14 tests green).
