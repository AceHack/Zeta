## Description

fix(hygiene): record the deliberate workflow disabling — the drift check was red-by-default

Aaron asked whether there are drift checks needing cleanup. There is one, and it
is the most useful kind of stale: a check that WORKS, reports correctly, and has
been red for so long that its red stopped meaning anything.

`check-github-settings-drift` compares live repo settings against
`github-settings.expected.json`. Measured 2026-09-07: 25 workflow-state drifts.
The expectation still said `active` for 14 lanes that were deliberately
disabled — the size-and-cost reduction Aaron described ("that's why we
disabled") — and did not know about 11 lanes added since.

So the check has been failing continuously on a KNOWN cause. That is worse than
it sounds: a red that is always red is not a signal, and a genuinely unexpected
change — a lane silently re-enabling, a ruleset weakening — would have arrived
into that noise and been indistinguishable from the backlog.

EVERY TRANSITION WAS REVIEWED BEFORE ACCEPTING IT, because re-snapshotting an
expectation file is exactly how a real change gets blessed by accident:

  14 disabled   agent-heartbeat, society-heartbeat, tick-metrics, drift-sweep,
                drift-dashboard-cadence, proof-closure-drift, search-index-cadence,
                budget-snapshot-cadence, context-cost-trend-cadence,
                manifesto-citation-snapshot-cadence, lockfile-healer,
                mirror-to-fork, pr-manifest-integrity, zetadb-scheduled-node
  11 new        root-flake-check, first-boot-manifest-check, ci-runtime-image,
                feldera-compare, feldera-native, seal-emulator-{bao,install},
                archive-strand-alarm, artifact-freshness, pr-categorization-cadence,
                dynamic/github-code-quality/codeql
   0 OTHER      nothing became ACTIVE that was expected disabled, and nothing
                vanished. That negative is the one that mattered.

MERGED ONLY THE `workflows` SECTION rather than writing the snapshot wholesale.
The other 13 sections — rulesets, branch protection, actions permissions,
security — already matched exactly, and a wholesale write risks dropping a
section the snapshot could not read. Diffing first showed `workflows` was the
only section that differed at all, which is also the assurance that this change
cannot smuggle a settings weakening.

FLAGGED FOR AARON, not decided here: three of the disabled lanes are
`agent-heartbeat`, `society-heartbeat` and `tick-metrics`. CLAUDE.md treats
heartbeat and liveness telemetry as load-bearing — "a check that did not run
looking like one that passed" is the failure the liveness ledger exists to
catch, and it is now catching less. Recording the state does not endorse it;
whether those three should come back is a separate call.

Verified: `check-github-settings-drift` exits 0 — "no drift across the 451
compared leaf value(s)" — and its own 22 falsifiers still pass.
