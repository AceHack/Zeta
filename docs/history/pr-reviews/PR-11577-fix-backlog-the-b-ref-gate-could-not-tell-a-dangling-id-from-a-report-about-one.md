## Description

## The symptom

`check frozen legacy backlog drift` → `legacy B-NNNN refs must resolve` is red, blocking #11546. Four refs in one file:

```
FAIL: 4 legacy B-NNNN reference(s) do not hold up
  docs/research/2026-08-15-the-archive-tag-corpus-characterized-…md: B-9999 — DANGLING — maps to 081KED9T0X008QG0R003SZN0FB, which names no row in tree and has no archive artifact
  … B-0282 — DANGLING — maps to 081KR2E4K0008QG0R000J2CKKW, …
  … B-0080 — DANGLING — no alias-map entry and no archive artifact; this id names nothing
  … B-0094 — DANGLING — maps to 081KQB8J40008QG0R000X0QSAK, …
```

That file is **an audit of ids that resolve to nothing**. Its table's content *is* the dispositions. The gate's remedy — *"cite the ZetaId of the row that carries the work, or drop the id"* — is unreachable there: there is no row to cite (that is the finding), and dropping the ids deletes the audit's subject matter to turn a linter green.

**Every fact the gate reported was true. Only its verdict was wrong.**

## Real breakage, or a false-positive class? — determined, not assumed

**The ZetaIds never existed.** `legacyZetaIdFromBId` *derives* them by hashing the B-id string. Re-running the derivation reproduces the map's entropy tails exactly:

| B-id | in `b-to-zetaid-map.json` | re-derived from the string |
|---|---|---|
| B-9999 | `081KED9T0X008QG0R003SZN0FB` | `081KED9T0X0087G0R003SZN0FB` |
| B-0282 | `081KR2E4K0008QG0R000J2CKKW` | `081KDVXSNE0087G0R000J2CKKW` |
| B-0094 | `081KQB8J40008QG0R000X0QSAK` | `081KDVK1DT0087G0R000X0QSAK` |

Same entropy tail, different timestamp field. They are backfill synthetics; `git log --all -- "*<zetaid>*"` returns nothing for all three. There is no deleted row bearing those names to restore.

**The B-ids are a more interesting story, and it does not change the answer.** Three of them *were* real rows:

| id | what history says | ancestor of `main`? |
|---|---|---|
| B-0094 | row landed, then **deliberately moved** to `docs/research/escrowed/` (a7ae8f66aa, 32476926ac) | **yes** — a real, intentional retirement |
| B-0282 | row added in a9e938cae1 | **no** — branch-only, never landed |
| B-0080 | row added in 6918dabce3 | **no** — branch-only, never landed |
| B-9999 | never a file | — |

So: nothing was wrongly deleted, and the audit's three verdicts are independently corroborated by git. **Diagnosis: false-positive class in the check** — it has no vocabulary for *"this id is dangling, and that is what I am reporting."*

## The fix — a fourth rung, not an exclusion

A mention may carry its own disposition, and the disposition is **checked, not trusted**:

```
<!-- b-ref-adjudicated: B-0282 landed-as-code src/Core.TypeScript/backlog/autonomous-pickup.ts -->
```

`checkAdjudication` accepts one only when **all five** hold:

1. **Same line** — on a line that mentions the id *outside* the comment. A reader meets the disposition where they meet the id; a blanket footer cannot cover a file.
2. **Closed vocabulary** — `landed-as-code` · `superseded` · `abandoned` · `never-a-row`. Free prose would "explain" anything.
3. **Evidence exists on disk** — the cited path is read from the filesystem.
4. **No self-citation** — a document may not be its own proof.
5. **STALE fails** — if the id ever *does* resolve, the annotation is now a false claim sitting in a document, and goes red. This is what stops the escape rotting into a permanent allowlist.

Derived, not listed: the exempt set is computed from what each document declares, each declaration independently verified — the same shape as `hygiene/audit-proof-lineage-binaries.ts` deriving its exempt binaries from the byte-lock runner's own roster rather than a hand-written list.

## What I deliberately did NOT do

- **No exclusion of `docs/research/`.** That is the vacuity class this gate's own docstring exists to condemn.
- **No allowlist.** Constraint from `no-binary-in-proof-lineage`: a hand-maintained exempt set drifts.
- **No weakening of the dangling check** — it is strictly stronger now (a false disposition is a new red).
- **Did not narrow the gate to the PR diff.** It is defensible, and I think it is wrong here: diff-scope would delete the check's headline capability — *catching a reference whose target another PR deleted*, which by definition lives outside the deleting PR's diff.
- **Did not touch the document's prose.** Four invisible HTML comments; not one word says anything different.

## Two findings worth naming regardless

**1. The trigger, and it is not what it looked like.** `backlog-index-integrity.yml` fires on `docs/backlog/**`, `docs/BACKLOG.md`, `src/Core.TypeScript/backlog/**`. **`workitems/**` is NOT in that list** — #11546 tripped it via `src/Core.TypeScript/backlog/rebuild-legacy-b-id-aliases.args.test.ts`. The structural point stands: the job judges the **whole tree**, so any PR touching one of three paths inherits responsibility for pre-existing breakage anywhere. That is the right design for a drift check and a real cost; it is why this sat red across a whole session of merges that never touched those paths.

**2. Runtime is wall-clock wait, not algorithmic cost.** Four timed runs: `1:49`, `1:21`, `58s`, `40s` — with **0.32–0.54 s user CPU** every time (2–4 % utilisation). `buildIndex` is 146 ms; a full `find` of the 35,050-file tree is 115 ms. The tool does ~2 s of work and spends the rest blocked on a loaded machine. Not a pathology in the linter — but a >2-minute red herring for anyone timing it.
