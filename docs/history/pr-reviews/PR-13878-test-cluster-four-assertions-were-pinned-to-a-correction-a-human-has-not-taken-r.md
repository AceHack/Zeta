## Description


`main` is red on `test (TS hermetic)` with four failures, and they are one cause:
the tree asserts `runnerEnvelope.freeDiskGib` is 70 while the tree records 14.

WHAT COLLIDED. #13830 (6f250f96b, 18:04Z) put `freeDiskGib` back to 14 and wrote
the correction down beside it instead of taking it:

    "PROPOSED CORRECTION, for a human to take or refuse: freeDiskGib 14 -> 70 ...
     MEASURED CONSEQUENCE of taking it, so the trade is visible: three assertions
     in lane-partition.test.ts flip ... Those are conclusions about the tree, not
     test bugs, which is exactly why the field did not move on its own."

#13805 (8cec12d05, 18:32Z) was cut before that and says so in its own message:
"Inherit #13784's freeDiskGib 70", then "rewrite lane-partition expects for the
70-world ... papering them green by restoring 14 would make 70 look like 14."

Both merged. Git saw no conflict because they touch different hunks. The MEANING
collided: #13805 landed the three assertions that #13830 had just named as the
ones that flip IF the correction is taken — and the correction was not taken. A
fourth, `rendered-resource-requests.test.ts` mutation 6, pins the same 70.

WHY THIS PR RESTORES 14 RATHER THAN SETTING 70. There are only two resolutions
and only one of them is mine:

  * set freeDiskGib to 70  — TAKES a decision the tree explicitly reserves for a
    human, and re-prices the whole partition as a side effect. Not mine to take.
  * restore the assertions  — asserts nothing new. It makes the tests true of the
    tree as the human left it, and is trivially reversible if the human takes the
    correction, which is precisely the flip the reserved note already describes.

Read plainly: with 14 live, asserting the 70-world IS the papering. #13805's
argument was right about the world it was written in and is inverted by #13830.

EVERY NUMBER IS MEASURED off the current tree, not reverted blind — #13805 also
changed `catalogueKey` and the roster, so a hunk revert would have been wrong:

    freeDiskGib 14   budget disk 10   budget cpu 2500
    all.diskGib 74.5377   all.cpuMillis 6166
    diskRatio 7.4538   cpuRatio 2.4664   -> disk is the binding axis again
    pack budget 8.5 GiB   oversize ["hindsight","vllm"]
    hindsight 22.4944   vllm 22.6549
    dropping intent edges: lane membership IDENTICAL, covered 39 both ways
    closure with intent 24.0640 > without 23.1854  (holds in BOTH worlds)

THE PINS STAY PINS. `expect(freeDiskGib).toBe(14)` is kept deliberately: the
value is contested, and the pin is what makes taking the correction show up as
red tests rather than a quiet re-pricing. Each of the four now carries the
measured 70-world value in its comment, so taking it is a re-pin and not a
re-measurement.

HONEST COST, stated rather than hidden: mutation 6 in
rendered-resource-requests.test.ts pins this value incidentally — what proves
that mutation is `envelopeOverstatements` convicting an inflated envelope, and
that reads the value symbolically. So taking the correction reddens a FOURTH test
beyond the three the reserved note names. Dropping that incidental pin would fix
the coupling, but removing an assertion from a mutation proof is a separate call
and is not folded in here.
