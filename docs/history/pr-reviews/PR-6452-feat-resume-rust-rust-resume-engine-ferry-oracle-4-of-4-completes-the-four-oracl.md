## Description

## What

Rust resume-engine ferry — **oracle #4 of 4**, completing the 081KT07NV0008QG0R003BE6MJ2 resume slice: TS reference + F# (#6448, merged) + C# (#6451) + this. New `zeta-core-resume` crate that **reuses** `zeta-core-bonsai` for `Expr`/`ConstValue`/`BinOp`/`serialize`/`parse` (own-our-interface; the bonsai crate IS the port).

- Small-step **CEK machine** over the Bonsai-subset `Expr`; `Call` nodes are activities (suspension points). Pure parts evaluate inline; at an activity the machine suspends → serializable `SagaState` (continuation + pending activity). `resume` **restores** without re-invoking prior activities.
- Result-over-throw throughout (idiomatic Rust; no panics on the wire path).

## The correctness properties from the F#/C# ferries, baked in

1. **Depth ceiling** — `parse_state` tokenizes with `4*MAX_DEPTH` headroom (state embeds bonsai exprs inline up to 1024 deep).
2. **i128 overflow guard** — `apply_binop` does arithmetic in `i128` first. i64 mul of two safe-ints overflows (**Rust debug-PANICS**, release wraps to a wrong in-range value) — `4294967296^2 = 2^64` is caught, declined `NonSafeInt`.
3. **Escaper** — `jstr` matches JS `JSON.stringify` (mirrors the bonsai escaper).

`kont` matches the **TS reference** exactly: a `Vec` where push appends / top = last (== TS array semantics), so state bytes are byte-identical to the reference by construction.

## Zero-dep JSON (the Rust-specific bit)

The C#/F# ferries got JSON parsing free from the BCL. Rust is zero-prod-dep by doctrine, so this hand-rolls a minimal **order-preserving** JSON reader (`Obj = Vec<(String,Json)>`, mirroring the reviewed bonsai reader: strict RFC-8259 number grammar, rejects raw control chars + lone surrogates + trailing input) + a `json_to_canonical` re-serializer. Embedded exprs re-parse via `bonsai_parse(&json_to_canonical(subtree))` — key order is preserved from the canonical source, so re-emitted bytes are canonical and bonsai's NonCanonical check passes (**no byte-span tracking needed** — the key-order preservation makes round-trip canonical-ness free). `serde_json` is dev-only (reads the shared `resume-golden.json`).
