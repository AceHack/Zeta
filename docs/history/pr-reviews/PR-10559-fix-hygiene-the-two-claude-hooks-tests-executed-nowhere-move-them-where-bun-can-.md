## Description

Closes `081KZZ1RK6A087G0R003C773WC`.

`.claude/hooks/harness.test.ts` and `.claude/hooks/stop-detect-response-rut.test.ts` were tracked in git and run by nothing from 2026-06-21 until now — 13 assertions on the hooks that fire at every agent session start and stop, including the `Stop` hook that watches what agents emit. A guard whose tests never run is a guard nobody is checking.

## What the measurement says (bun 1.3.14, all CHECKED)

A test file under a dot-prefixed directory is not discovered by a bare `bun test`; no positional filter reaches it either (bun answers *"the following filters did not match any test files"*); only an explicit `./`-prefixed path argument does. So the whole-suite job in `gate.yml` could not see them **by construction**, through a mechanism nobody chose.

**They pass** — 13 pass, 0 fail, 21 `expect()` calls, on the first run, before any edit. Nothing had rotted.

## Is `.claude/hooks/` a required path? No — verified, not assumed

`.claude/settings.json` names every hook by an explicit `bun "$CLAUDE_PROJECT_DIR"/.claude/hooks/<file>.ts` command. The harness resolves by **configured path**, not by directory convention, so moving the hooks was *possible*. It is rejected on **cost**, not impossibility: 51 tracked files reference `.claude/hooks`, and a user-scope `~/.claude/settings.json` in another clone would break silently.

So the **test** moves and the subject stays, to `src/Core.TypeScript/claude-hooks/`, importing back across the boundary.

## Why not the explicit-`./`-path option

It needs a dot-slash special case in the checker's `executes` model — a filter is a *substring* of the path, and `./.claude/hooks/x.test.ts` is not a substring of `.claude/hooks/x.test.ts`, so the model does not degrade to it. And it is a filter list; `gate.yml`'s own header says why that is not a fix: `forge-host/` fell outside the previous globs precisely because someone had to remember to add it. A moved file is reached by the bare `bun test` forever, with no list to maintain.

## The count was a mute — that is the half that matters

Hidden files now fold into `unexecuted`: allow-listed with a written reason, or red. They join it **directly**, never through `executes`, because the bare filter-less `bun test` would otherwise be credited with running them — inventing the coverage the checker exists to deny.

Before the teeth, that same mutation stayed **green** — so the move on its own would have been a fix nothing could verify.

## Second finding, not looked for: the same blindness in `tsc` and `eslint`

`.claude/hooks/*.ts` was in the tsconfig program **0** times before this change and **2** after (`harness.ts`, `stop-detect-response-rut.ts`) — TypeScript's wildcard `include` skips dot-prefixed segments, so the hooks were never type-checked either. They typecheck clean: 26 errors before, the same 26 after, all pre-existing missing-devDep `TS2307`s in unrelated files.

`eslint` skips dot directories the same way, which is why `sonarjs/publicly-writable-directories` fired on `harness.test.ts` the moment it arrived. Both sites are assertion targets rather than write paths — one of them **is** the path-traversal check the rule asks for — and each carries a written disable rather than a weakened assertion. Linting `.claude/hooks/*.ts` itself is **PROPOSED**, not done here.
