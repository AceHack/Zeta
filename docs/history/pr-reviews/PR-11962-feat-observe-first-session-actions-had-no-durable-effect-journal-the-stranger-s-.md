## Description

`simulateFirstSession` is pure, and that was the whole problem: five of the six
action kinds had no real-world effect anywhere in the loop. `skip_credential`,
`skip_optional_credentials`, `offer_cloud_helpers`, `use_local_llm_only` and
`complete_first_session` were state transitions over a record discarded at
process exit. The one durable artifact, `writeMarker`, is an ISO timestamp: it
records THAT first login finished and nothing about what happened in it. A
person who deliberately skipped GitHub and a person who never reached the
question left byte-identical evidence behind.

You cannot put strangers in front of that.

The before/after effect map now lives above `simulateFirstSession`, where the
next reader hits it before assuming a green test means an action landed.

What is new
-----------
`first-session-journal.ts` — an append-only JSONL fact log beside the marker.
Each APPLIED action becomes one durable, readable-back line.

- Facts, not commands: replay folds through `simulateFirstSession`, it never
  re-invokes `gh auth login`. Entries are written only after the effect lands.
- The APPLIED action is recorded, never the chosen one. A `setup_credential`
  the provider downgrades to `skipped` is journalled as the `skip_credential`
  it became, and a refused setup is journalled as nothing at all. Recording the
  chosen action would put a durable lie on disk.
- Ordered by `seq`, never by `at`. The wall clock is local proper time, carried
  for humans only — sorting a fold by it is what
  .claude/rules/local-time-never-enters-the-shared-fold.md exists to prevent.
- Result-over-exception: a failed append returns `{ok:false}` and the conductor
  logs `journal-failed`. Finishing first login on a fresh machine outranks
  keeping the record of it; losing the record is never silent.
- `--dry-run` writes no journal. Dry-run means no durable effects.

A fabrication fixed
-------------------
The already-complete short-circuit returned `defaultNodeSession()` — an
all-credentials-missing set asserted about a machine nobody had looked at. The
previous author pinned it as a KNOWN GAP and wrote that the assertion "will turn
red when someone [fixes it], on purpose." It did; this is that fix.

`reconcileSessionRecord` splits the two halves by change rate (DV2.0) and takes
each from the source that knows it: credential readiness is OBSERVABLE, so
re-probe it (a remembered "ready" is worse than a fresh one — tokens expire); a
deliberate skip is NOT observable, since `probe = missing` looks identical for
"chose to skip" and "never asked", so the record supplies that alone. Precedence:
probe `ready` > recorded `skipped` > `missing`. With no journal at all the old
default remains, now announced as unknown rather than presented as observation.

Left stubbed, deliberately
--------------------------
- Credential acquisition stays delegated to external vendor CLIs we do not own.
- The journal is local, unsigned, unreplicated. Promoting "this person chose
  local-only" to a claim peers should trust is an identity/attestation surface
  and belongs to the distributed-IdP work (ADR 2026-07-08), not to a JSONL fold.

Both are labelled in the code. A stub that is labelled is honest; a stub that
looks live is the vacuity class.
