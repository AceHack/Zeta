## Description

TWO DEFECTS, both measured against the as-merged code from #15388.

1. A CONSTANT SCORES 100%. Of six scenarios, THREE accept every option —
   `acceptableIndices` covers the whole option list, so they cannot fail. The
   other three all accept index 0. So a model emitting the constant "0" scores
   **6/6** on the full suite.

   That is what the published run measured. qwen2.5:0.5b and gemma2:2b were
   reported at "100% correct" and both answered "0" to every prompt:

     qwen2.5:0.5b   answers=['0','0','0']   correct=[T,T,T]
     gemma2:2b      answers=['0','0','0']   correct=[T,T,T]
     llama3.2:1b    answers=['2','3','1']   correct=[T,F,F]

   llama3.2 is the only model that VARIED its answer and it scored worst. The
   benchmark cannot distinguish following the priority rules from emitting a
   constant, which is the one thing it exists to distinguish.

   The accept-everything scenarios are DELIBERATE and are kept — "sovereign
   choice — all valid" is a real property of the observe loop, and a model that
   refuses to answer should still be visible. The defect is folding them into a
   correctness RATE. Scoring now runs over the discriminating subset, states how
   many were excluded rather than dropping them silently, and prints the
   best-constant baseline a real model must beat.

   Excluding them is NECESSARY AND NOT SUFFICIENT, and the tests say so: with
   all three discriminating scenarios accepting 0, constant-"0" still scores
   100% on the subset. The suite needs a scenario whose answer is not 0. Pinned
   by a test that will go green the moment one is added.

2. IT RUNS ON IMPORT. `main()` was invoked at module scope with no
   `import.meta.main` guard, so importing the module executes a full benchmark
   and REWRITES `data/model-benchmark.json` and the history JSONL. It did that
   to me while I was merely reading its exports; I reverted the write. A module
   that mutates measurement data as a side effect of being imported cannot be
   unit-tested, and its data files cannot be trusted to reflect a deliberate run.

ALSO: `decisions/joule` is a PROXY and now says so in its own output.
`correctRate / (seconds * 12)` assumes 12W — no wattmeter, no RAPL, no
powermetrics. The source comment always said "proxy"; the summary line did not,
and a derived number compared against an unmeasured model's imagined value is
not a comparison. The label now travels with the number.

8 tests, 0 fail. Control: importing the module no longer touches `data/`.
