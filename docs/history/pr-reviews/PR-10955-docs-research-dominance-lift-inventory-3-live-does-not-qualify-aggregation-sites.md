## Worst offender — `review-board.ts:115` + `review-gate.ts:81`

A code-review finding needs **≥ 3 distinct agreeing reviewers** or it is `Withheld`. The caller then does this:

```ts
if (adopted.length === 0) {
  recommendedGateOutcome = QualityGateOutcome.Approved;
  reason = "no finding reached quorum agreement; gate approved";
}
```

Three things compound: finding a bug is a **recall** task whose dominant rule is union; this is `AND`-of-3, its exact complement; and the loss lands on **approve**. The single most competent reviewer spotting a real defect alone is structurally guaranteed to be overruled by two who did not spot it — and the change ships. It is live (non-test callers via `metrics/src/index.ts`, `mcp-tools.ts`).

Tension with `every-bug-has-economic-value`: a quorum gate that discards a solitary true finding destroys ΔU by construction. A deliberate precision-over-recall trade would be a defensible defence — **the module does not name one**; it imports its rationale from the constitution gate, i.e. from *legitimacy*, which is the wrong objective for defect detection.

## Explicitly NOT findings

BFT quorums (`SybilBft.fs`, `Consensus.cs`) are **safety** mechanisms; `nway-diff.ts` majority is an **integrity detector** over units meant to be byte-identical. Neither aggregates heterogeneous competences. The constitution gate and the security stage are **veto-shaped** — deferential toward *reject*, which is the correct direction for their objective.

## The refinement the sweep forced

The theorem is stated for a two-sided accuracy objective; most of this repo is one-sided. That gives a triangle, and it is what separates the findings from the non-findings:

| shape | defers toward | dominates on | fails on |
|---|---|---|---|
| OR / union | accept | recall | precision |
| AND / unanimity / veto | reject | safety | recall |
| **unweighted k-of-n** | **neither** | **neither** | both |

## Recommendation: union, not weights

Log-odds weights need per-agent competence, which nobody has measured. I checked `calibration-ledger.ts:320` — it has exactly the right **Beta posterior** construction, but it scores **deadline-interval coverage**, and its own design contract says *"CALIBRATION ≠ COMPETENCE."* So the ledger is the right *shape* and the wrong *quantity*; a domain-specific twin scoring findings-upheld would be the path (theorem doc L4, unassigned). Until then, prefer union for recall tasks and veto for safety tasks — both are free and need no estimates.

**No aggregation logic was changed.** Changing how the society reaches verdicts is architectural and Aaron's call. Filed and recommended only. Doc is `unmetered`: no test currently fails when a rule is non-deferential.
