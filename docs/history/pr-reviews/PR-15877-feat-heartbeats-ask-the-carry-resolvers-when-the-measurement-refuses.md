## Description

#15837 landed the decision layer and nothing called it. The rules existed; the
carry never asked them. So today's wedge — six files, two lanes, hours stuck,
cleared by hand — would have recurred identically tomorrow.

TWO MECHANISMS, TRIED IN ORDER, and the order is the point.

`isLosslessLineExtension` asks "can these be carried without DECIDING anything?"
It is a per-tick measurement against the actual bytes, it is the narrowest thing
that can be true, and it stays first: a path it accepts needs no rule, no
declaration and no judgement. Nothing about that path changes — the healthy
carry is byte-identical to before.

What is new is the second question, asked ONLY of paths the measurement refuses:
is there a declared rule that decides this one? Before, the answer was always no.

ALL-OR-NOTHING IS PRESERVED EXACTLY, and that is what makes automatic resolution
admissible at all: every path is classified before a single byte is written, so a
run that cannot settle one path mutates nothing and the caller reports git's own
message unchanged. Widening the mechanism must not weaken that, and it does not.

`resolved` is reported SEPARATELY from `healed` rather than merged into it. A
healed path needed no judgement — the bytes said the lane's copy contains main's
verbatim. A resolved path DID need one: a rule read both documents and picked.
Collapsing them would hide exactly which paths a human should re-examine if a
rule later turns out to be wrong, and automatic resolution is only defensible
while it stays legible afterwards.

A PINNED REFUSAL BECAME A PINNED INVARIANT, deliberately, and this is the part
worth reading twice. `REFUSES when main published an entry the lane never saw`
asserted a refusal, and its own comment said why: *"Taking the lane's copy would
DELETE a published event from discovery."* That was true of the only mechanism
available then — `checkout --theirs` literally takes the lane's copy and drops
main's entry. The keyed-set resolver does not take a side: it merges on
`eventId`, honours deletions, and refuses when one id carries two different
payloads. The base in that fixture is EMPTY, so both sides are pure additions and
the union is the only lossless answer.

So the refusal was guarding against a clobber that can no longer happen on that
path. The test now asserts the INVARIANT instead of the mechanism — main's
published entry must survive the carry, whatever carries it — which is strictly
stronger: a future resolution that clobbers fails it even if it never refuses.
Rewriting a deliberate refusal is not something to do quietly, so it is argued
here rather than adjusted silently.

Refusal remains the common case and stays reachable. An unregistered path has no
rule and `resolveCarryConflict` refuses by default rather than guessing one.
`data/ci-runs.jsonl` — three lanes appending to one file — is the standing
example: the measurement refuses it because main holds rows this lane never saw,
no resolver claims it, and it goes to its declared driver exactly as before.
