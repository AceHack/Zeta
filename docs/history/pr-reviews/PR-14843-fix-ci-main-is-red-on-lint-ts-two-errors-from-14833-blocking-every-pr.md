fix(ci): main is red on lint (TS) — two errors from #14833 blocking every PR

`lint (TS)` fails on `origin/main` at 01245a633, so it is red on EVERY open PR
in the repo. Reproduced locally before changing anything: rc=1, 2 errors, both
in `src/Core.TypeScript/observe/run-loop-real.ts`, both introduced by #14833
(tick-reasoning log) an hour ago.

TS6133 at line 44 -- `observeWithParticipant` is imported but never used. Its
only other appearance is in a DOCSTRING at line 7, which is what made it look
used. Removed from the import.

TS2339 at line 180 -- `observeWorld.mode`. Line 158 builds `observeWorld` as a
union whose codegen arm DELIBERATELY strips `mode`
(`const { mode: _, ...rest } = enrichedWorld`), so one arm has no such property
and the new logging line reads exactly the field that was intentionally removed.

The fix is a property guard, and it is not a workaround for the typechecker: it
reports what the participant ACTUALLY SAW. When `mode` was stripped the chooser
was shown a world without one, so "unset" is the true record of that tick.
Reaching back to `enrichedWorld.mode` would typecheck and would log a value the
participant was never given -- a reasoning log that misdescribes the reasoning,
which is worse than the error it silences.
