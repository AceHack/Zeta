## Description

bun tools/setup/defender-exclusions.ts --apply    # your call, not mine

## Why a script and not a command in chat

Adding an AV exclusion is a privileged, **security-reducing** host change. Privileged operations
here are committed, tested, reviewable code — never ad-hoc `sudo` pasted into a terminal. A
one-liner in a transcript is not readable before it runs, diffable when it changes, or auditable
after.

**Dry-run by default.** `--apply` is required and is the operator's call. The cost is stated first,
because an exclusion list that advertises only its speed benefit is a security change wearing a
performance costume: an excluded path is **not scanned**, and these trees are exactly where
third-party code arrives.

## Measured, not assumed

- **Platform:** `mdatp` is present at `/usr/local/bin/mdatp`, so this targets Microsoft Defender for
  Endpoint on macOS. The Windows product is unrelated and deliberately **not stubbed** — an empty
  PowerShell branch printing `TODO` is a step that cannot fail, which looks like coverage and
  provides none.
- **Worktrees:** collapsed from **99 literal paths to one wildcard**. The first version enumerated
  them and was wrong twice — 99 entries aren't reviewable, and the set churns daily. The script does
  not *trust* glob support either: the read-back reports `NOT PRESENT` if the pattern doesn't land,
  rather than claiming success from `mdatp`'s own exit code.

## Two tests caught defects in my own work

1. The **control** test (`--apply` *does* call it) failed first, revealing the sandbox `HOME`
   contained none of the target directories — so the apply path was skipped entirely and the two
   "never calls mdatp" assertions were passing **vacuously**. A guard proven by a system that could
   not act at all.
2. The **idempotency** test then failed because each run gets its own sandbox, so it compared
   temp-directory names rather than behaviour. Normalised to compare shape, plus a non-empty
   assertion so it cannot compare two blanks.

9 pass · shellcheck clean · dry run verified to issue **zero** `mdatp` calls against a fake that
records every invocation.

## Converted to TypeScript after CI (2nd commit)

`lint (bash retirement inventory)` failed: **33 non-Lean shell files against an expected 32**, the
one unexpected entry being the file I'd just added. The guard was right, and the fix is not to widen
its allowlist — `tools/setup/` already has three privileged setup tools in TypeScript, and
`touchid-sudo.ts` states the reason in its own header: *"Written in TypeScript because that is the
repo's one interface."*

The conversion is also better tested. The shell version needed a fake `mdatp` on a sandboxed `PATH`;
the TypeScript version injects a `Host`, so tests drive real cases with no fake `PATH` and no way to
touch the real endpoint config. Two cases that reached cleanly only after the change:

- **The managed-host case** — `mdatp` reports success on the add and the exclusion is silently not
  held because policy overrode it. The read-back catches it and the run exits 1.
- **The glob is conditional** — with no worktrees present the wildcard isn't proposed at all.
