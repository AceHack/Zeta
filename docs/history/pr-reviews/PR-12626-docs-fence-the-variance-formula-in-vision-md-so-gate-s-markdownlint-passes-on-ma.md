## Description

docs: fence the variance formula in VISION.md so gate's markdownlint passes on main

`gate` has failed on every push to main for at least the last five runs
(01:58, 22:33, 22:20, 22:10, 21:52 UTC) on a single finding:

    docs/VISION.md:707 MD046/code-block-style [Expected: fenced; Actual: indented]

WHY IT PERSISTED, which is the part worth recording. The markdownlint step is
deliberately asymmetric (gate.yml:1653): on `pull_request` it fails only on
findings in files the PR itself touches, and prints everything else as
out-of-scope drift; on push it lints the whole tree, and "that run IS the
detector." The design is right -- it stops one PR being blocked by another's
mess -- but the consequence is that a violation in a file nobody is editing is
invisible to every contributor and red forever on main. Nobody's PR ever saw
this line, so nobody ever fixed it.

The fix is the minimum that satisfies the rule: the single indented display
formula becomes a fenced block. Content is byte-identical; only the two fence
lines and the leading indentation change. MD040 (fenced-blocks-need-language)
is off in `.markdownlint-cli2.jsonc`, so an anonymous fence is correct here --
the line is a formula, not code in any language.

VERIFIED, not assumed: `markdownlint-cli2 "**/*.md"` -- the exact command the
push branch of that step runs -- exits 0 on this branch. The whole tree is
clean, so this was the only violation standing between main and a green gate.
