## Description

## What

Turns the portal from a **viewer** into a real **management plane**. Clicking a resource opens a full console with a left sub-nav and rich tabs. The BFF gains a `ResourceOps` layer (rich demo impl now; the k8s impl is the in-cluster follow-up — the console renders from any `ResourceOps`).

This delivers the asks: **analytics, entering each server, control-panel access, lifecycle management, FTP/SFTP, config per deploy, and memory management.**

## The console (tabs)

| Tab | What |
|---|---|
| **Overview** | status + a **pods table** (phase, restarts, node, IP, age) + the rendered k8s objects |
| **Metrics** | dependency-free **SVG charts** (CPU, memory, 30-pt series) + a **storage usage bar** vs the Longhorn volume |
| **Logs** | terminal-styled, level-coloured log view |
| **Console** | the **"enter the server"** channel — RCON for game servers, shell for pods (command + queued exec; live PTY is the WebSocket follow-up) |
| **Files** | an **FTP/SFTP browser** — navigate dirs, sizes, modified (the game data root via the sidecar) |
| **Config** | an **editable form** — replicas, cpu/mem/storage, blueprint variables, env → **Apply** patches the Deployable |
| **Events** | the k8s event timeline (incl. the OOMKilling/BackOff chain) |
| **Room** | the collaboration timeline |
| **Danger zone** | stop + a **type-to-confirm delete** (gated, names the volume loss) |

Header **lifecycle buttons** (Restart / Stop / Start) with toasts. A new top-level **Memory** view lists every durable room log + on-disk size — the persistent agent-memory footprint (#5).

## Backend

- `ops.ts` — the `ResourceOps` interface; `ops-demo.ts` — rich, deterministic data (seeded from the resource name; lifecycle/config writes mutate an overlay so the UI reacts).
