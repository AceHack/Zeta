fix(heartbeat): declare data/rs-blocks.jsonl, the fifth append-only lane path

otto's and soraya's ticks wedged at 16:43Z on 2026-08-17 (run 32046921903):

    prepare-heartbeat-branch: carry unflushed heartbeat state failed:
    CONFLICT (content): Merge conflict in data/rs-blocks.jsonl

Fifth member of the class the 2026-08-16 fix addresses, surfaced the same way it was
designed to be: the preparer's typed backpressure refuses an UNDECLARED conflicting path
rather than guessing. That is the design working. It surfaced now because the flush outage
left the lanes many ticks ahead of main, widening exactly the partial-flush window these
attributes exist for.

MEASURED ON THIS TIP, not assumed:
  - append-only — the last 12 commits touching the file are each `+1 -0`, no line modified
  - 13 rows, 13 distinct `(agent, seq)`
  - written by otto, alexa AND soraya, so not single-writer by file; single-writer PER ROW,
    since the `agent` field names the lane that emitted it and a lane appends only its own

The duplication fear is the partial-flush case, where main and the lane both hold the same
row. Git resolves an identical addition on both sides as ONE change and emits a single
copy — the mechanism already verified in production for the four existing paths. Union
duplicates only when the sides add DIFFERENT lines, which is the case we want.

STATED LIMIT, because the manifest entry gets to make a stronger claim and this one does
not: `(agent, seq)` uniqueness is NOT enforced anywhere. `verify-rs-blocks.ts` does run in
this workflow, but it checks each block's Reed-Solomon syndrome — corruption of a row's
contents — which would not notice a duplicated row. Union is safe here on the append-only
plus per-row-single-writer argument alone; if rows ever become editable, the line must go.

The test asserts the interleaved three-row result AND that the row present on both sides
appears exactly once, so the no-duplication claim is pinned rather than asserted in prose.
Mutation-checked: deleting the `.gitattributes` line fails it with the production error
verbatim.
