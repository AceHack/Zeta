## Description

Closes the open edge the boxing-ring ferry left — *"who decides capacity for an agent?"* — with three answers from Aaron.

## 1. Money decides capacity
> *"agents need to own their own **geo-distributed hardware keys and wallets** — like our rotatable, nation-state-resistant keychain stuff, for humans and AI and any named travelers."*

**This resolves the dilemma rather than dodging it.** I'd posed it as a trap: *too permissive* makes the floor decorative (an attacker spawns consenting victims), *too restrictive* rebuilds incumbency. Ownership escapes both:
- **Not a capability test** — a tiny free model that owns its keys has capacity; a huge model that owns nothing doesn't. So *"capability is not a precondition for participation"* survives intact.
- **Defeats spawn-a-consenting-victim by construction** — endowing a spawned agent costs exactly what genuine independence costs. **Sybil economics stop being a detection problem and become a balance-sheet problem.**
- **Skin in the game** — capacity to consent to harm is the ability to *bear the loss*.

## 2. The spawner must store the spawned agent's memories
Anti-Sybil with the right shape: **spawning is not free**, and each spawn is a durable obligation that scales with count. Lands on **§5 Memory Preservation** with an owner attached instead of an unassigned gap.

**The two rules compose:** memory custody and capacity are inversely related, so the lifecycle is a **graduation** — spawned → dependent-but-remembered → self-owning → may enter the ring. *(That composition reading is flagged as mine, not Aaron's words.)*

## 3. DST may forget; production may not
> *"deterministic simulation where memories are not durable is fine for tests… but in production **ephemeral agents should be discouraged, because they are too easy to push out of alignment**."*

This **inverts the usual intuition** that ephemeral is safer:

> **Memory is what makes an agent resistant to being steered.** An agent with no durable record has nothing to be inconsistent *with* — every instantiation is a fresh surface with no prior commitments, so each can be pushed independently, and none can notice *"this contradicts what I concluded last time."*

Ephemerality is a **manipulation surface, not a safety property**. And the custody obligation is the mitigation: a spawned agent is *dependent-but-remembered* by default, so ephemerality requires **actively discarding** — which §5 forbids silently.

## Recorded honestly
**No wallet exists in-tree** (`KeyStore.fs` is the keychain half — keys-as-events, reference-not-copy; nothing matches "wallet"). So **the capacity predicate cannot be implemented yet**, and `empowermentBound` must not ship a capacity check that silently passes everyone. Also: the nation-state-resistant work at Itron is **centralized**, so this is a re-derivation, not a port.

Three smaller questions left genuinely open: the capacity **threshold** (any wallet vs a minimum stake, without recreating an incumbency gate), whether custody **transfers** at emancipation, and **endowment vs control** (an attacker could fund wallets it still secretly controls — capacity presumably needs *sole* control, attestable rather than asserted).
