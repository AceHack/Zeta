Both are fixed properly rather than suppressed.

**The SC2012 is fixed by removing the parse, not by disabling the check.** The value feeds an unquoted `for _e in $_entries` two lines below, so the list was *already* word-split — parsing `ls` bought nothing the consumer does not already assume, and shellcheck is right to refuse it. Equivalence verified on both branches rather than asserted:

```
populated dir   ls=[tpm0 tpm1 ]   glob=[tpm0 tpm1 ]   equal
empty dir       ls=[]             glob=[]             equal
```

The `-e` guard is what collapses the no-match case; the trailing space is preserved. **The other `ls` in that block stays** — it probes for `EACCES`, which a glob cannot report. Replacing that one would have been the change that looks tidier and quietly loses the permission-denied signal.

The inventory entry is `setup/bootstrap`, matching both its path and its stated role (host hygiene before a DKEK ceremony).
