## Description

The gate job `live kind included Synced+Healthy proof` has failed on `cdi` and `kubevirt` and only
those two. **I called it a flake three times. It is not.**

## My error, because the reasoning is the lesson

I saw `SUCCESS, SUCCESS, FAILURE` among the kind checks and read it as two passing runs of one job.
Verified against the head SHA's check-runs:

```
success       live kind ArgoCD health (ubuntu-24.04-arm)      <- weaker job
success       live kind ArgoCD health (ubuntu-24.04)          <- weaker job
in_progress   live kind included Synced+Healthy proof         <- the only one asserting the roster
```

**I compared three different jobs and treated it as three runs of one.** Same tree-identity error I have
spent the night catching in other people's code.

**The mechanism, confirmed:** `cdi`/`kubevirt` landed 2026-08-16, and nothing in the kind lane ever syncs
a child app with no `automated:` block — **so the failure is deterministic from the moment both
Applications appear.**

## And it corrected my brief on a load-bearing point

I told it to reuse the ratchet round's manual-sync convention. **That convention does not exist in this
tree** — the ratchet PR has not merged, and `rg` for the annotation returned **zero hits**. It verified
before building rather than importing a convention it had been told was there.

What exists is the *argument*, in the baseline doc: *"the manifest is correct and the **validator** is
what needs to learn the convention."* So it defined the convention **once**, in one module, so the render
validator can adopt the same module rather than growing a parallel one.

## Weaker assertion, not exclusion — the trap the brief named

`cdi`/`kubevirt` are still asserted on three observable things: **existence**; **a completed comparison**
(`syncStatus ∈ {Synced, OutOfSync}`, so `Unknown` or empty is a ComparisonError); and **health not
Degraded/Progressing/Suspended/empty**.

The middle one is load-bearing and **evidence-backed rather than hoped-for**: `OutOfSync` is ArgoCD saying
it *did* render and diff, and simply was not permitted to act. **For two apps that vendor a large upstream
operator manifest verbatim, a typo in `directory.include` or a malformed vendored byte surfaces there and
nowhere else in CI.**

**Fail-closed twice.** Only a *well-formed* declaration earns the weaker contract — a malformed one keeps
the full requirement, **so a broken declaration is never cheaper than a correct one.** And the weaker
contract is **unreachable by editing TypeScript**: the app must say why, in its own manifest, with a
non-empty reason and `automated:` absent so annotation and manifest cannot disagree. **No app list
anywhere.**

## What it can no longer catch — stated, not hidden

Anything that appears only once manifests are *applied*: API-server rejection, a denying webhook, an image
that won't pull, a CR the operator never reconciles, drift from the operator actually running on
`node-5b2dfa`.

> **The honest framing: the old assertion didn't catch those either — it failed unconditionally, and
> failing always is not detecting.** What is lost versus the assertion that was there is nothing.

## Verified

**Cluster suite 171 pass / 0 fail** (was 149). **`validate-applications` reports `226 passed, 13 failed`
before *and* after — identical**, so the ratchet's count is untouched.

**Six mutations bite:** widening acceptable health → 2 fail · accepting `Unknown` as completed → 2 ·
inferring manual from a bare omission → 4 · dropping the reason requirement → 2 · allowing annotation
*and* `automated:` → 2 · giving every app the weaker assertion → 3.

**End-to-end against the real 19-app roster:** the measured CI state goes **GREEN**, while a non-rendering
source, a Degraded app, a vanished Application and an ordinary regression all still go **RED**.

**Zero added CI minutes** — 22 offline tests inside the existing run.

**Flagged, not done:** `validate-applications` still counts these ten as contract failures. Teaching it the
same module would drop the ratchet **23 → 13** and requires editing the baseline in the same change — the
prescribed workflow. Left for the next round because `ratchet-*` was off-limits and the full loop could not
be verified from here.
