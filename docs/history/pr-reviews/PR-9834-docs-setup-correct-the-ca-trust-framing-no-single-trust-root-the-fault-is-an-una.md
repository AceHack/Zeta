## Description

Aaron's correction to a mis-framing I introduced in #9831. **The mechanism was right and is unchanged** (`resolveCaDisposition` untouched); the **reasoning in the code comments was wrong** — worse than in a PR body, since comments are what the next reader acts on.

- **Wrong:** "minting a second CA would SPLIT the trust root."
- **Right:** there is **no single trust root**. Every node being its own CA *is* the design, so a second CA isn't itself a fault. A CA becomes usable when its **public key is bootstrapped through an external authority** — a GitHub-controlled maintainer identity committing `maintainers/<ca>/ssh-ca.pub`. The real fault is minting an **UNATTESTED** CA: a key nobody bootstrapped, whose certs no peer can verify — an orphan identity, silently so.

Also records the mirrored conventions (git `allowed_signers`, k8s/cert-manager trust bundles, SSH CAs), a naming caveat (`committedTrustRoots` are **bootstrap anchors**, not PKI roots), and prior art for bootstrapping decentralized identity off a centralized IdP: **Sigstore/Fulcio**, **SPIFFE/SPIRE**, TOFU/web-of-trust, Zooko's triangle.
