## Description

## Why

The mise-pinned OpenJDK 26 runtime intermittently aborted on macOS arm64 in `Compile::remove_speculative_types` after TLC had completed a valid model check. That native exit made the .NET test report a false failure even though TLC found no model violation.

OpenJDK 26 source guards the crashing compiler body with `UseTypeSpeculation`. Disabling that one C2 optimization on the affected platform avoids the observed path without forcing every TLC run through the much slower C1-only or interpreter modes.

## What changed

- apply a pure, shared TLC JVM policy in the F# and TypeScript runners
- retain the existing 1 GiB heap bound and SerialGC on every platform
- add `-XX:-UseTypeSpeculation` only for macOS arm64
- test the policy directly in both language surfaces
- correct stale post-relocation TLC paths and mise-managed tool versions in `docs/INSTALLED.md`

No TLA+ model, application runtime, or non-macOS JVM behavior changes.

## Proof

- largest model benchmark (`BftConsensus`): C1-only 4m41s; targeted flag 2m58s; both produced 44,070,202 generated and 4,665,495 distinct states
- full TLC F# module: 33/33 passed in 3m13s
- previously failing `SpineMergeInvariants`: 20/20 repeated direct runs passed with the new JVM policy
- both real TypeScript and F# `SmokeCheck` entry points passed
- policy unit tests: TypeScript 2/2; focused F# 2/2
- full preflight before final rebase: all 14 checks passed, including release build and full .NET tests
- post-rebase pre-push gate: all 12 quick checks passed

## Limits

This excludes the exact native compiler body observed in the OpenJDK crash, but cannot prove that no other JVM-native crash is possible. An unrelated intermittent F# `FS0229` end-of-stream read from `obj/Release` did not recur in isolated or later full builds and is not claimed fixed here.
