## Description

**CHECKED** against `origin/main` today.

`gate.yml`'s `bun test` invocations cover exactly two directory globs (`hygiene/`, `ace/` — 86 files) plus 9 individually-named files. Everything else is **never executed by CI**: all of `discovery/` (**32 test files**), `planning/`, `browser-node/`, `ferry-throttler/`, `model-backend/`, `observe/`, `oracle/`.

This is the repo's own named defect class. `zflash-harness-lint.yml` says it outright: *"a green check that implies more than it tested is worse than no check."* A PR touching `discovery/` goes green today having run **zero** of that directory's tests.

## Two live instances, both from today

1. **The UDP chaos harness (#10417)** — 32 assertions including **four tests that deliberately pin currently-broken behaviour** so it can't silently regress. Those pins are inert; nothing runs them, so nothing will catch the regression they exist to catch. Filed with full awareness that I shipped it.
2. **`planning/orbital-independent-check.test.ts`** — the independent check that *falsified* the first proposed remedy for the light-time defect. It never re-runs, so the falsification isn't regression-protected.

**The light-time theorem itself is fine**, stated precisely rather than alarmingly: `Lean4/LightTimeAsymmetry.lean` **is** imported by `Lean4.lean:17` and `src/Core.Lean4/` **is** gated, so the proof runs. What's missing is the second oracle — `tools/Z3Verify/*.smt2` (9 files) is referenced by no workflow. Redundancy loss, not property loss.

## Why this isn't just "add a glob"

- **Runtime unmeasured.** 612 files is a different budget than 95; `lint (TS)` is capped at 12 minutes.
- **Pass rate unknown.** Tests un-run for months may already be red. Enabling all at once turns the gate red on unrelated PRs — the exact priority inversion the 2026-08-01 gate flip was designed to avoid.

Staged adoption (measure → fix or quarantine with a reason → enable) respects that history.

**Proposed shape:** exactly `lean-orphan-modules.ts`, which already solved this for Lean — derive the executed set, fail on drift, and require a **non-empty reason** for every exclusion so deliberate omission is cheap and accidental omission is loud.

Note: the fix needs a `.github/workflows/**` edit, and those PRs don't get `gate` scheduled. The measurement + checker can land as ordinary code first; the workflow edit is a separate gated step.
