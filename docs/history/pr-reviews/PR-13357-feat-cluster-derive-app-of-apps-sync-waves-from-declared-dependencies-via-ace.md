## Description

feat(cluster): derive App-of-Apps sync waves from declared dependencies via ace

SYNC-WAVES.md named 34 components while 46 `kind: Application` manifests ship.
Twelve -- agent-memory, arc-controller, arc-runner-set, cdi, cilium-lb-ipam,
gmod, headlamp, headscale, kubevirt, minio, platform, seaweedfs -- appeared in
its graph nowhere at all.

That was read as stale documentation. It was not. A hand-maintained artifact was
standing where a derived one was intended (Aaron: "for our sync waves, we are
supposed to use our ace package manager to calculate the sync waves so the order
of the helm charts can be derived where there are dependencies"). Correcting the
twelve would have made the file accurate until the next Application landed;
deriving the order makes the omission impossible.

WHAT ace CAN ALREADY DO. `src/Core.TypeScript/ace/deps.ts` carries the whole
calculation and says so in its header -- `resolveGraph()` does a DFS topological
sort with cycle detection and assigns DAG heights, and `generateArgoCD()` emits
`argocd.argoproj.io/sync-wave` from them. Nothing was missing but the
declaration. (`ace-cli.ts`'s STUB_REGISTRY is a different, flat thing: its
PackageEntry has no dependency edges at all. It is not the engine here.)

SHIPPED
  - full-ai-cluster/k8s/sync-wave-dependency-graph.yaml -- one node per shipped
    Application, every dependsOn edge carrying a citation to the artifact that
    grounds it. Placed outside the applications tree so no root glob applies it.
  - src/Core.TypeScript/cluster/derive-sync-waves.ts -- calls ace's resolveGraph
    and refuses on six findings: UNDECLARED, PHANTOM, UNANNOTATED, UNCITED-EDGE,
    ORDER, CNI-FLOOR. Roster comes from app-of-apps-discovery's
    listApplicationManifests(), not a second walk.
  - derive-sync-waves.test.ts -- 27 tests: live-tree regression guards plus
    synthetic falsifiers that drive every finding to fire.
  - Wired into the offline dry-run job of k8s-argocd-health-test.yml.
  - SYNC-WAVES.md reframed: the hand-written per-app table is deleted rather
    than corrected, the rationale prose kept.

EIGHT DISAGREEMENTS, REPORTED NOT REPAIRED. Wave order sequences bring-up on a
real cluster and a wrong reorder is a broken bootstrap, so each is registered in
ORDER_ADJUDICATION_PENDING with a reason and PRINTED on every run:
  platform(-20) -> longhorn(-15)         Longhorn-backed portal PVC pends. This
                                         is fact #6 of vault/TOPOLOGY.md, which
                                         MEASURED the identical inversion for
                                         vault, repeating on a second app.
  platform(-20) -> cilium-lb-ipam(-10)   Gateway has no external address until
                                         the pool arrives.
  alloy(0) -> loki/tempo/mimir(0)        shipper reconciles with its sinks.
  weaviate(0) -> ollama(50)              both vectorizer modules enabled while
                                         ollama is later AND manual-sync-only.
  deepseek-coder(50), qwen-coder(50) -> ollama(50)

A NEW disagreement is unregistered and FAILS; a registration whose disagreement
disappears is STALE and FAILS too, so the registry cannot rot into an allowlist.

The derived NUMBERS are deliberately not compared to the hand-written ones --
ace's heights are 0..N, the annotations run -90..50, and requiring equality
would be a coincidence of counts. What is checked is that the hand-written
assignment is a linear extension of the derived partial order.

Also corrected, in the other direction: SYNC-WAVES.md asserted "orleans needs
CockroachDB + NATS up". The tree does not carry it -- orleans/configmap.yaml
configures `"clustering": { "provider": "kubernetes" }` and no NATS endpoint
appears anywhere in the app. That edge is NOT declared, and the doc now says why.
