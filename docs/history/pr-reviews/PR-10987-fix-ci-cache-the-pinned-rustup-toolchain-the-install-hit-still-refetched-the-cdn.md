## Description

## The defect

`~/.rustup` appears in **zero** cache path lists across all 68 workflows; `~/.cargo` in exactly one (`full-verify`). mise's rust backend wraps rustup, and its install dir `~/.local/share/mise/installs/rust/1.87.0` is a **symlink to `~/.cargo/bin` holding 0 bytes** — the real 656 MB toolchain lives in `~/.rustup/toolchains/`.

So a **successful** `install-*` cache hit restored a dangling pointer into an uncached directory, and every job re-synced the channel manifest from `static.rust-lang.org`. Measured on green runs, not inferred (run 31960624373, `lint (Python)`):

```
17:08:47  ✓ mise runtimes installed        <- 45 ms, "all tools are installed"
17:08:47  info: syncing channel updates for 1.87.0-x86_64-unknown-linux-gnu
17:08:54  info: downloading component rustfmt
17:09:36  info: downloading component rust-std
17:09:38  Rust 1.87.0 + wasm32-unknown-unknown ready     <- ~51 s, every job, every run
```

And when the CDN blips, that is the whole job — three PRs on 2026-08-16 (#10903, #10930, #10963), each reported under the name of a lint **that never executed** (run 31959740624, verbatim):

```
error: could not download file from
'https://static.rust-lang.org/dist/channel-rust-1.87.0.toml.sha256' …
Connection reset by peer (os error 104)
```

## The change

Added to the `install-v2-*` path list (gate.yml ×17, installer-unit-tests.yml ×1) and to `full-verify-v2-*` (×1):

```
~/.rustup/toolchains/1.87.0-*
~/.rustup/settings.toml
~/.rustup/update-hashes
~/.cargo
```

Key prefixes bumped `install-` → `install-v2-`, `full-verify-` → `full-verify-v2-`, once.

### Why only the pinned toolchain

The ubuntu-24.04 image already ships `~/.rustup/toolchains/stable-*` (624 MB, rustc 1.97.1) that `RUSTUP_TOOLCHAIN` never selects. Caching all of `~/.rustup/toolchains` pays for it on every restore. Measured against the 1270 MB baseline entry:

| variant | cache size | delta |
|---|---|---|
| current (no rust paths) | 1270 MB | — |
| whole `toolchains` dir + `~/.cargo` | 1681 MB | +411 MB |
| **pinned `1.87.0-*` + `~/.cargo`** | **1486 MB** | **+216 MB** |

`!`-exclusion was tried and measured **inert**: `~/.rustup/toolchains` plus `!~/.rustup/toolchains/stable-*` stored the full 1681 MB. The explicit glob is load-bearing, which is why `1.87.0` is written out and must stay in sync with `rust` in `.mise.toml`. A stale glob degrades to the pre-change behaviour (CDN fetch) — never to a wrong toolchain.

## The falsifier — run, not asserted

Probe branch `shadow/rustup-cache-probe`, runs **31962065113** and **31962487520**. The warm leg restores the cache, blackholes `static.rust-lang.org` in `/etc/hosts`, **verifies the block by curling the exact failing URL first** (so the test cannot pass vacuously), then runs `install.sh`:

```
✓ static.rust-lang.org is unreachable from this runner
✓ rustup exact toolchain selected: 1.87.0
info: component rustfmt is up to date          <- no "syncing channel updates"
info: component clippy is up to date
  1.87.0-x86_64-unknown-linux-gnu unchanged - rustc 1.87.0
rustc 1.87.0 / cargo 1.87.0 / wasm32-unknown-unknown
✓ compiled to wasm32 with static.rust-lang.org unreachable
```

The same job without those paths is the failure this PR fixes.

## The `RUSTUP_TOOLCHAIN` guard

`tools/setup/common/mise.sh` claimed the selection kept "exact installed toolchains usable while the CDN is down". True, but there was no offline cache for it to protect — half a guard. This PR supplies the missing half; the comment now names the cache paths it depends on, so removing them breaks a stated, measured claim rather than silently re-vacuating the guard.

## Cost, and what was deliberately left out

The key bump forces **one cold run per job** — unavoidable, `actions/cache` only saves on a miss.

The repo cache budget is **already evicting**: measured 13,505,456,398 B / 25 entries at 17:28 UTC and 12,595,795,186 B / 24 at 17:40, with `install-Linux-X64` dropping from 3 branch-scoped copies to 1 in that window. Steady-state addition here is ~216 MB on `install-v2-Linux-X64` + ~216 MB on `full-verify-v2-Linux-X64` ≈ **+3%**.

To keep that number small, **not** included:

- the `mise-*` cache used by `build-and-test` (3 os/arch entries, ~650 MB) — still CDN-exposed, and it is in the required floor;
- `install-*-base-` / `-full-` in `helm-validate.yml` and `k8s-argocd-health-test.yml` — separate keyspaces, not the required gate.

Those are a follow-up to be paid for with a measured budget, not an assumed one.
