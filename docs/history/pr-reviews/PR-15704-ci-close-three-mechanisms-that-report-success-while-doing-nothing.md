## Description

Three mechanisms that reported **success or silence while doing nothing** — an actuator that cannot act, a green that inspected nothing, an assertion that cannot hold. Each was measured before acting; one of the three reports handed to me turned out to be partly wrong and is corrected below.

Hole 3 is fixed on its own branch and is **not** in this PR — see the last section.

## 1. The retraction actuator is live and cannot fire

`drift-sweep.yml:269` runs it with no dry-run guard. Verified on fresh `main`:

- The job's `permissions:` block grants **only** `contents: write` and `actions: read`. No `pull-requests: write` — and **no `issues: write` either**, which rules out "raise a tracking issue" as the remedy; that call would 403 for the same reason.
- The actuator's terminal act is `POST /repos/{repo}/pulls`. The 403 is caught, logged as one truncated line, then `process.exit(0)`.
- `retraction-episodes.json` does not exist anywhere in the tree. It has not fired once since 2026-08-22.

Separately, and worse: **every guard in it is about uniqueness or at-most-once; none is about attribution.** During the 2026-08-26 `www.gnupg.org` outage its isolation predicate was *satisfied*, so it would have retracted #15683 — a causally unrelated hygiene lint — with a correctly formatted letter to its author.

### What this does, and deliberately does not do

It does **not** grant a token and does **not** make the actuator able to act. Both stay operator decisions (#15698 §5.1, §5.3). The change is strictly *subtractive* of capability:

| added | effect |
|---|---|
| `isAttributable(subjectPaths, candidatePaths)` | Semantics identical to #15698's predicate — exact repo-relative equality, empty ⇒ **not** attributable. Kept byte-comparable on purpose so two copies of one rule cannot drift into two rules. |
| `redRunSubjectPaths()` | Returns the honest empty set. No deriver is wired — the actuator never fetches job, step or annotation data for the red run — so **every candidate is unattributable and the machine refuses every retraction.** |
| `break_detected.attributable` | **Required**, not optional. An optional field would default to absent at every construction site and the guard would silently not apply. |
| capability preflight | Static read of the workflow's own `permissions:` block → `::error` on **every run**, naming the missing scope. |
| push-failure branch | `::error` instead of a bare log. |

Annotations rather than a non-zero exit, on purpose: failing the step would take the whole drift sweep red for a standing design state, and an always-red lane gets muted — which would recreate the exact silence this fixes.

`redRunSubjectPaths()` returning `[]` is the one thing here that looks like the vacuity class and isn't: it is not a stub standing in for absent work, it is the accurate report that no evidence exists. Its docstring says so, and its test pins that changing it is a reviewable event.

### Falsifiers, mutated

- Disable the attribution guard → **4 tests red**, while the CONTROL (identical event, `attributable: true`, still retracts) stays **green**. That control is what proves the guard is load-bearing rather than a blanket refusal.
- Silence either loudness path → **2 more red**.
- 84 pass / 0 fail across the four affected suites; full `tsc --noEmit` clean.

**Correction to the brief I was given: #15585 has already merged** (23:11Z). So the vacuous green is not pending — it landed. 79 green checks, none of which looked at the file it changed.

`root-flake-check.yml` evaluates it. **Non-blocking drift tier** — not added to `gate (required)`'s `needs:`; nothing touched in `required_status_checks`.

`--all-systems` is load-bearing, not thoroughness theatre. Without it nix omits outputs incompatible with the runner and prints `warning: The check omitted these incompatible systems: ...`. On a Linux runner that silently drops `darwinConfigurations.zeta-mac` and its nix-darwin/nixpkgs branch-match assertion — **exactly the defect class #15585 changed.** A lane that skipped it would be a narrower vacuous green replacing a wider one.

The lane cannot be vacuous itself: `nix flake check` exits 0 on a flake whose outputs it skipped, so a following step reads the check's own output and refuses a run that validated zero outputs, or that lost a named output from the expected roster.

## UPDATE — the lane answered its own question, and corrected me twice

Run `33023664270` came back red on the anti-vacuity step. **The guard was right to be loud and wrong about the reason, and the reason was my bug.**

It counted `^✅` lines. That is **Determinate Nix 3.x** presentation — my laptop. This job installs **upstream nix** (`determinate: false`), which prints `checking flake output '...'` and never emits an emoji. Nix checked **twenty** outputs; the guard reported zero. (The two `✅` hits in that job log are my own echoed script text, quoted back by the runner.)

**Two readings of that run were proposed to me, and the log refutes both.** Verbatim from run `33023664270`:

```
checking flake output 'darwinConfigurations'...
checking derivation devShells.aarch64-darwin.default...
checking derivation formatter.aarch64-darwin...
```

- *"`--all-systems` does not reach `darwinConfigurations` on ubuntu"* — **no**, it does; the line is right there.
- *"it checked NOTHING and returned success"* — **no**, it checked twenty things. That message was my guard misreporting.

Eval is not build: nix evaluates a darwin derivation graph on Linux fine and simply cannot realise it; `--no-build` only evaluates. So **no macOS runner is warranted**, and the platform boundary was never the cause.

This is the lane's own defect class turned on itself — a check bound to an incidental artifact of one implementation's output formatting rather than to the property it meant to measure. Here it produced a false **red**; the same mistake in the other direction is a false **green**.

**Fixed:** pattern is now `^(✅|checking |evaluating )` and the roster uses substrings present under both formats. Re-validated against four cases — the real CI log (was a false red) now passes at 21 outputs; the real darwin log passes at 51; an empty log is still refused; a darwin-stripped log is still refused by name.

**Added, because naming the roster is not measuring it.** The roster proves `darwinConfigurations` was *mentioned*, not that nix *descended into* it — upstream nix prints a per-config line for every `nixosConfigurations.<name>` but only one flat line for `darwinConfigurations`, which is consistent with both deep evaluation and a shallow skip of a non-standard output type. Since the nix-darwin branch-match assert is the whole reason this lane exists, that ambiguity is not acceptable, and I would rather measure it than argue it.

So the lane now injects an undefined variable into the darwin config on the actual runner and requires nix to notice. The failure must **name the probe token**, so it cannot be satisfied by an unrelated incidental error — the same trap fixed in #15592 on this task. If darwin turns out shallow there, the step fails loudly and names the remedy in its own message: `checks.aarch64-darwin.zeta-mac = self.darwinConfigurations.zeta-mac.system`. Measurement, not hypothesis, and no macOS runner either way.

**Worth stating for whoever adds the next nix lane:** `nix flake check` returning **0 while checking nothing** is a general nix trap, not a quirk of this repo. The guard is the part that generalises — copy it. And make its pattern match the property, not one implementation's formatting.

Also fixed in passing: backticks inside a double-quoted `echo` in the new step would have been command substitution.

### The eval/build gap, now stated rather than implied

Correct and taken: `--no-build` establishes every output is **well-formed**, not that any **produces** anything. A major-version bump changes what *exists*, not merely what *parses* — and #15585 is exactly that shape. **This lane would have evaluated #15585. It would not have built it.**

That limit is now written into the lane's header: a green here means *"the root flake parses and its module system is consistent"*, never *"the root flake works"*. The PR is **not** widened.

### The follow-up, costed with real numbers

All measured on `aarch64-darwin`, 2026-08-26:

| quantity | measured |
|---|---|
| `nix build .#darwinConfigurations.zeta-mac.system`, cold | **62 s wall, rc=0** |
| derivations actually built | **55** |
| paths fetched from `cache.nixos.org` | **671** (463.9 MiB down, 1.7 GiB unpacked) |
| eval-only lane, for contrast | 4–5 s |
| existing `build-and-test (macos-26)` gate jobs | 1.5–8 min, already provisioned |

**Two premises in the framing need correcting, and both make the follow-up cheaper than assumed:**

1. **The repo is public.** GitHub Actions is free on standard runners for public repos, macOS included. The constraint is macOS *concurrency*, not minutes — so "runner minutes" is not the axis to optimise.
2. **The merge rate is not the firing rate.** Merges run ~**372/day** (higher than the 212 cited). But the lane is paths-filtered, and `flake.nix` / `flake.lock` / `infra/nix-darwin/` / `infra/nixos/` took **21 commits in 6 months ≈ 3.5/month**.

### Which inverts the scheduled-vs-per-PR recommendation

| shape | firings/month | detection latency |
|---|---|---|
| **per-PR, paths-filtered** | **~3.5** | at the PR |
| nightly scheduled | ~30 | up to 24 h |

A nightly is **~9× more expensive** *and* detects later. The paths filter already does everything the schedule was meant to do, because the root flake genuinely changes about three times a month.

**Recommendation: a per-PR, paths-filtered, drift-tier macOS lane that builds `darwinConfigurations.zeta-mac.system`.** At 62 s of build on top of a nix install, it is comparable to the eval lane and cheaper than one existing `macos-26` gate job. **A cache is not needed for viability** — `cache.nixos.org` already serves all 671 paths and only 55 derivations build. Cachix or magic-nix-cache would be optimisation, not a precondition.

Not opened as a PR here, per your call to keep this one narrow. The numbers above are what it should be judged on.
