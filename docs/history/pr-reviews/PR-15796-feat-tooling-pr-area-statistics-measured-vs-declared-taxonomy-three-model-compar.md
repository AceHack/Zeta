## Description

## Summary

PR categorisation with statistics by area, over the existing 13,185-row PR archive.
No scraper: this joins `docs/github/prs/manifest.jsonl`, the git history, and the
archived review files that are already in the repo.

**The design decision that makes this a measurement rather than a chart.** "Area" is
largely derivable from a conventional-commit title, so predicting a declared area
from title features would restate the input. Two independent sources are used:

- **label** = *measured* area, from the file paths the PR's squash-merge actually
  touched — recovered from `git log --name-only` joined on the trailing `(#NNNN)`.
  98.1% of merged PRs resolve this way.
- **features** = *declared* side only — title prose with the scope prefix stripped,
  branch, author, timing. Diff-derived features are a separate, off-by-default group.

`areas.test.ts` asserts that separation directly. Without it every accuracy below is
an identity, not a result.

## Models — temporal split (train on older PRs, predict newer)

| model | accuracy | Δ vs baseline | where baseline abstains |
|---|---:|---:|---:|
| closed-form baseline | 59.0% | — | 0.0% (by construction) |
| majority class | 4.0% | −55.0pp | 2.3% |
| random forest | 65.1% | +6.1pp | 24.2% |
| **BNN (ADF probit, one-vs-rest)** | **72.4%** | **+13.4pp** | 20.9% |
| _NULL random forest (labels shuffled)_ | _4.9%_ | | |
| _NULL BNN (labels shuffled)_ | _3.1%_ | | |

The last column is the point: the closed form scores 0% there because it has nothing
to say about a quarter of all PRs.

**The label-shuffle null is clean.** Under a random split both nulls land at
20.4%/20.5% against a 20.2% majority-class floor — they degenerate to guessing the
biggest class, which is exactly what a non-leaking pipeline does. `cli.ts` exits
non-zero if the null ever rises above that floor, because a leak voids every other
number rather than deserving a warning.

## The honest verdict on the BNN

Its advantage is **entirely a distribution-shift effect**, and that is worth more
than a bare win would have been:

- **random (i.i.d.) split** — BNN and forest are **statistically indistinguishable**
  (McNemar p ≈ 0.07–0.40 across five seeds). Both beat the baseline by ~9–10pp.
- **temporal split** — **BNN beats the forest by 5.8–8.5pp on every seed tried**
  (p < 1e-20).

So the BNN earns its place only in the regime a scheduled dashboard actually runs in.
Comparisons use McNemar's exact test, not overlapping confidence intervals: both
models are scored on the same PRs, so only the discordant pairs carry the comparison.

## k-means: clusters are not categories

ARI **0.039** (random) to **0.144** (temporal) against a null of ~0.000. Real but weak
structure, and it is **not** the taxonomy. Only chance-corrected agreement is
reported; the `majorityMap` number is labelled a supervised ceiling wherever it
appears, per `numerology-vs-number-theory`.

## The product: where the declared area disagrees with the diff

**3,037 PRs (31.9% of those with a parseable area).** The closed form cannot produce
this set at all. Dominant patterns are conventions disagreeing with directory layout
rather than anyone being wrong — `society:` ticks writing telemetry, `ferry:` notes
landing in `docs/research`, `deps:` bumps touching workflows rather than a lockfile.

## Incidental finding

In the eleven days to 2026-08-27 the merged-PR mix went to **46.5% telemetry and
23.4% archive**, with **`memory` at 0.0%** — against 11.6% / 6.1% / 11.2% before. That
shift is why the temporal split is the default and why a hand-refreshed statistics
file would describe a repo that no longer exists.

## Built around how lanes actually die

Three lanes went quiet in the week before this, and none of them died in its
algorithm. Each of those failure modes gets a check here rather than a comment:

| how a lane dies | the guard |
|---|---|
| writes N artifacts, flushes fewer (drift-dashboard: 4 written, 2 flushed, markdown frozen 3 days) | the test asserts the workflow's `--paths` list **equals** the generator's exported `ARTIFACTS`, in both directions |
| pipes a checker through `tee` and reports tee's status | the generator step sets `set -uo pipefail` and reads `PIPESTATUS[0]`; the test asserts all three are present |
| publishes with `\|\| echo` so a refusal is non-fatal | the test scans the flush step for every swallow form |
| pushes at `main`, which ruleset "CI Gate" refuses at push time | parks on `heartbeat/pr-categorization` and flushes via PR; the test asserts nothing targets `main` |
| assumes a credential works | a real `git push --dry-run` preflight, re-probed after the fallback is installed |
| nobody notices it stopped | registered in `FRESHNESS_ROSTER` against its own declared cron |

The cron minute is also checked: `:34` is a minute no other workflow uses, and the
test enforces that against **all** cron forms. Restricting the scan to `*/N` is how a
real overlap gets missed — `mirror-to-fork.yml` runs `13 8 * * *`, which a `*/N`-only
pattern does not match at all, so minute 13 read as free when it was not. That is
exactly what happened on the first draft of this lane.

## `fetch-depth: 0` is load-bearing here, not hygiene

The ground-truth label for every PR comes from the files its squash-merge touched,
recovered by walking `git log --name-only`. A shallow clone yields almost no join
hits, so the generator **refuses** (exit 3, with the cause named) rather than
publishing a study of 50 PRs as though it were a study of 13,000.

## Freshness registration

The roster's docstring predicted a third subject would be "a five-line edit, not a
design", and it was. One pre-existing test needed a fixture fix: it handed every
non-`red-state` subject an `{ at: ... }` document, which suited a two-entry roster and
reported `no-field` the moment a third subject named a different key — a fixture
failure that would have read as a subject failure.

The roster entry's declared cadence is asserted against the workflow's actual cron by
the new test, so the two cannot drift into a threshold nobody chose.

## Note on scope

`lint-drift-publication-lands.ts` only matches lanes publishing paths containing
`drift`, so it does not cover this one. Rather than widen a shared guard from here,
the three rules it enforces (no push at `main`, no swallow on the publish step,
capability probed with a real dry-run) are asserted locally for this lane. Widening
that lint to all publication lanes looks worthwhile and is left as its own change.
