# A. `SoftMessage` — no one can be silenced, and no one can be cloned into a majority

`FactorGraph.Factor<'M>` is already generic over its message family; `Zeta.Bayesian`'s only family is `Gaussian` (continuous) and `SoftValue` is categorical. This is the categorical message.

## Why it is not `SoftValue` itself

`SoftValue` is **normalized by construction** — its private repr enforces weights summing to 1. A message must be **unnormalized**: natural parameters form a group under addition, and the product of two normalized densities is not normalized. **A normalized type cannot be a message without breaking the algebra it is joining.**

## Integer log-weights, and why exactness is not fussiness

For a categorical family the natural parameters *are* log-weights, so `Product` is pointwise addition and `Divide` (the EP cavity, Minka 2001) is subtraction. Stored as integers in millinats, which buys three things floats would not:

- **Group laws hold exactly.** Float associativity drift means two agents given the same evidence in different orders can reach different argmaxes — a divergence bug wearing a rounding error.
- **Byte-lockability**, which the existing TS SoftValue oracle explicitly cannot do and says so in its own header.
- **An exact integer influence bound**, so "no one can be silenced" is checkable arithmetic rather than an approximation.

## The veto, and the one line that closes it

In log-space `Product` is addition. A message asserting log-weight −∞ **vetoes a candidate permanently** — −∞ plus anything is −∞. One participant, one message, and a candidate is gone for good.

It is also the ordinary failure with **no adversary at all**: a sensor that has never seen `c` reports zero rather than *"I have no information"*, and downstream the two are indistinguishable.

Bounded influence closes it (Huber 1964; Hampel's influence function): log-weights clamp to ±`MAX_INFLUENCE`. **The same clamp closes the EP cavity blow-up** — `Divide` subtracts, so an unbounded operand gives +∞ and poisons the graph. One mechanism, two problems.

## The correction: bounded influence was a Sybil hole

**Aaron's objection, and it is correct.** Bounding one message does nothing about an attacker who sends N of them, because `product` adds and `N × BOUND` grows without limit. *"Enough others will outvote it"* quietly assumes the others are **distinct**. Per-message bounds without identity are worthless against a Sybil (Douceur 2002) — and the first commit's *"k attackers need k defenders"* test **demonstrated the vulnerability rather than mitigating it**, since k is unbounded when identities are free.

**The fix is not an identity registry bolted on.** It is that **adding log-weights is only correct for independent evidence**, and clones are not independent. Same sentence as `numerology-vs-number-theory.md`'s *"N correlated observations are not N observations"*; same sentence as `SocietyUsefulWork.fs:95` — which states it and then warns that it has **two** correct quantifications and that picking the wrong one is itself the error the rule warns about.

Picked deliberately, as that file demands: **Kish effective sample size** (`nEff = n/(1+(n−1)ρ)`, Kish 1965 ch. 5), **not** `unionEquivalentAgentCount`. The question is how much independent *information* n correlated voices carry when their log-evidence is summed — an effective-sample-size question, not *"what fraction of facts would this many independent agents have discovered"*. The two agree only at the endpoints, and `effectiveCount` is pinned to the F# peer at both so they cannot drift.

`product` now **states** its independence precondition, which was the actual defect: it was unstated, so nothing flagged that the whole module rested on it.

## The sensor: distinctness, not an asserted ρ

`productAll` took ρ as **given** — a caller passing `0` for a colluding fleet got no protection at all. `productByDistinctSource` consumes `AntiSybil.DistinctnessReadout.SourceOf` instead, so the discount is **measured**.

**Why not estimate correlation from the messages themselves.** It is the obvious move and it is wrong. Message content cannot distinguish collusion from genuine agreement, so an in-band estimator **penalises honest consensus** — the ρ→1 collapse `anti-babel` warns about, arrived at by trying to prevent it. `AntiSybil.fs` measures an **unforgeable external trace** (clock-drift entropy, non-fungible across identities): two honest sensors that agree have uncorrelated drift, two puppets of one clock do not. A test pins that **distinct sources agreeing are not discounted**, because that is the property an in-band estimator would destroy.

This composes with the anti-Sybil substrate rather than duplicating it: forging k identities from s < k entropy sources forces, by pigeonhole, two **correlated** bit-streams — a Sybil is detectable *as* correlation, and that correlation is exactly the ρ this combine consumes. **Detection and pricing meet at one number.**

**Two decisions, each pinned by a test that fails when reversed:**

- **Within a group it averages, not sums.** Summing would let one source amplify itself by splitting its conviction across puppets and reassembling full weight.
- **An unmeasured participant fails OPEN** — counted as its own source. Default regard for someone the probe never saw, matching `TravelerRankLedger`'s honest `0.5` prior. The cost is **stated rather than hidden**: probe coverage is load-bearing.

**Honouring a trap the repo already documents.** `SourceOf` numbers components `0..DistinctCount−1` **per invocation over one batch** — not a durable identity. `dual-use-detection-is-neutral-oracle-decides.md` records this from a live incident where following the docstring would have produced silently-merged evidence under a colliding key. Using it here is the legitimate case: **combining a batch IS one batch**.

## Outliers are members, not errors

Robust inference **down-weights rather than rejects** — a Student-t weight `(ν+1)/(ν+z²)` shrinks with distance and never reaches zero. A floored candidate keeps **non-zero probability**: quiet, never deleted, because the minority candidate is the one carrying information when the majority is wrong.

And the discount **stays dual-use neutral**: high ρ might be a Sybil, or two honest cameras pointed at the same thing. It discounts both, **correctly**, because correlated evidence really is worth less either way. `atInfluenceFloor` and `distinctSourceCount` report facts and say nothing about why — **an adversary suppressing a candidate and an honest sensor with no data produce byte-identical messages**, and a test asserts exactly that.

# B. The hosted ARC roster — an agent that reads its own action space

Task #22 was blocked on a question I had answered wrong. The plan said *start with the four keyboard-only environments, extend to clicking later.* **There is no such classification available.** `EnvironmentInfo` (`arc_agi/models.py:17`) carries `game_id`, `title`, `tags`, `level_tags`, `baseline_actions` — and **no action-space field**. What an environment accepts is knowable only from `available_actions` on a live frame.

So any pre-play keyboard/click split is inferred from **tags, and tags are not an action space** — planning a curriculum on that ordering is planning on a coincidence.

The agent therefore reads its offered set **every frame** instead of being told it. That is also the answer to Aaron's layer-graph observation: different games have different input layers, and *the environment decides which are wired up*.

## Three layers, and the chooser uses the same rule as everything else here

**`click.py` — the coordinate prior.** `ACTION6` spans 4096 points against 4 for a d-pad, so uniform sampling is not a weak policy but *no policy*: one sweep exceeds a level's whole budget. The prior is that **things that are OBJECTS are things that are CLICKABLE** — component centroids first, then a coarse-to-fine lattice that covers the board rather than a raster that never leaves row 0. It forgets what did nothing whenever the world moves, because a click that did nothing *here* may do something *there* (the level-transition failure, restated for clicking).

Aaron 2026-08-25 asked for a generic learner that can look at UI quickly. **Clicking the parts that look like parts is how you probe any unfamiliar interface** — ARC is the falsifier that happens to be available.

**`layered.py` — the chooser.** Picks between click and keyboard by **which one moves the world**, with unexplored-first and a Schmitt latch. Same contingency logic as the pixel agent finding its body by acting rather than being told.

**`hosted.py` — the loop.** Level clearance is read from the frame's own `levels_completed` — the counter the scoring is *defined against* — rather than a proxy, which `play.py` had to learn twice. And `h` is not invented: hosted environments publish `baseline_actions`, so their scores use their own reference.

## A bug the new tests found in shipped code

`PixelAgent` computed *"everything that is not me"* with `_key` (`colour*100003 + area`). **Two identical sprites share one key by construction** — so `targets` came back empty and the greedy fallback called `min()` on nothing and raised. An ordinary ARC frame, not a contrived one.

Fixed to object identity, which is exact since `me` comes out of `now`. The related `_key` collision in `_update_evidence` is **left standing and named**: it degrades evidence rather than ending the episode, and it wants position-aware identity (the slot-binding research), not a wider hash.

## Honesty structure

`ARC_API_KEY` is absent from this container, so **no hosted environment could be played while writing this.** The code is split by what can be checked:

- everything that **decides** anything sits above the wrapper and is tested — including end-to-end against real `ZetaChase` and `ZetaDiscovery` through the same protocol;
- the unreachable part is **one delegating call**, guarded by a signature-conformance test against the real installed `EnvironmentWrapper`. It cannot prove hosted play works; it *does* catch the drift that would otherwise surface as a red CI run with no local reproduction.

`ZetaDiscovery` earns a test of its own for the case a scoring loop is most likely to get quietly wrong. The pixel agent does not clear it (recorded in `test_discovery.py`), so it is the available proof that **an unsolved level is a recorded ZERO with actions visible, not invented progress**. The first version asserted `levels_cleared >= 1` there and failed; weakening it to `>= 0` would have been vacuous.

# Notes

**A was authored in TypeScript because this container has no `dotnet`.** F# could not be compiled or falsified here, and an unfalsified primitive in the inference kernel is the exact failure this repo exists to refuse. F# conformance to `IMessage<'M>` (`Message.fs:55`) is the follow-up on a machine that can build it.

**Two honest limits on A, asserted rather than glossed:**

1. **It is a ratio, not an immunity.** 50 clones at ρ=1 carry exactly one clone's worth, so the honest side needs **three** voices instead of fifty-one. A majority can still bury a minority; what it cannot do is bury it with one voice, or irreversibly, or cheaply. There is a test named for that.
2. **The readout comes from F#.** `AntiSybil.antiSybil` produces `SourceOf`, and this container cannot run it. What is proven here is that **the TS side consumes a readout correctly**. An end-to-end run needs a machine with dotnet.

**`MAX_INFLUENCE` is a values parameter wearing a number**, named rather than buried: it fixes how much authority one participant may hold over one candidate. Raising it toward infinity restores the veto by degrees.

Anchors: Kschischang–Frey–Loeliger 2001 (factor graphs, sum-product); Minka 2001 (EP, the cavity); Huber 1964 / Hampel 1974 (bounded influence); Kish 1965 ch. 5 (effective sample size); Douceur 2002 (Sybil); and the robust-EP line — relaxed moment matching under outliers, plus the [2025 heavy-tailed robustness result](https://arxiv.org/pdf/2501.06349) showing a single large outlier has vanishing influence under Student-t errors.
