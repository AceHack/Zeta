## Description

The hole I built and named in #10321 and left open: findings accrue every tick, but resolutions only ever landed as PRs, never as `--choose` cells. So `resolutionCoverage` would have read near-zero forever and the false-alarm rate stayed permanently — and correctly — withheld.

**A metric that can never report is a metric nobody will keep paying for.**

## The fix is not a new discipline to remember

The moment a kill is **proven** is exactly the moment the resolution is known — so the tool that proves it records it.

`verify-kill --record --declarer X` appends a `write-test` resolution, and **only on `killed`**. A still-alive mutant has resolved nothing, and recording it would assert a judgement the run did not earn. Recording is opt-in: a read-only verification stays read-only unless the caller asks for the write.

## Idempotency is load-bearing, not tidiness

The transcript is the **numerator** of `resolutionCoverage`, so a decision appended twice silently inflates `resolved` and *deflates* the false-alarm rate computed from it. Re-running verification over the same fix is a normal thing to do — a retry, a second look — so `appendTranscriptOnce` keys on the content address and a repeat append writes nothing. `appendTranscript` is left alone for callers that genuinely want an unconditional append.

## Measured end to end, on a real proven fix

Today's `mutation-false-alarm-rate.ts` read-path gap (soraya, tick 11240):

```
first run   -> KILLED, "recorded write-test resolution 72ee8967f06bd296…"
second run  -> KILLED, "already recorded — idempotent, nothing appended"
transcript  -> unchanged at 4 lines
```

And the metric now reads a genuine resolution instead of only false alarms:

| | before | after |
|---|---|---|
| real gap (write-test) | 0 | **1** |
| alarms reported | 0 | 1 |
| resolution coverage | n/a | **100.0%** |
| false-alarm rate | withheld (nothing recorded) | withheld (**3 resolved, need 20**) |

That last row is the point: coverage is now computable, and the rate stays withheld for the *right* reason — sample size — rather than because nothing was ever recorded.
