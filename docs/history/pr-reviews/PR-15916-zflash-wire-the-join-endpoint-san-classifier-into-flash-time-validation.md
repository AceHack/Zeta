## Description

`join-endpoint-san-coverage.ts` landed in #15847 with tests and **zero production callers** —
verified with a control query, since two bad greps today taught me not to trust a bare one.

**What it catches:** shape validation (here, and `zeta-install.sh`'s single regex) accepts any https
host. A DNS name outside the founder's SAN set passes, gets staged, and fails at the TLS handshake
**after the disk is partitioned** — the live case for joining a second machine, costing a re-flash.
This runs on the operator's workstation at flash time, before hardware is touched.

## It advises; it does not refuse — and I was forced into that

The first version **refused** `not-covered`, reasoning that `k3s-server.nix:83` hardcodes exactly
`--tls-san=control-plane`, so any other DNS name structurally cannot be covered.

Sound about the certificate, wrong as a gate: **ten existing tests went red.** `control-plane.local`
appears **14 times** in this module's own tests — as often as `control-plane` — and in
`cluster-address.ts` and the zflash harness. It's a path the repo actually uses, so refusing would
have blocked real flashes on a string check.

The suite was the falsifier and I took its answer over my reasoning.

Whether `control-plane.local` genuinely survives the handshake is a **real open question** the
classifier raises and this deliberately does not answer. Surfacing it is useful; deciding it by
refusing a flash is not.

The advisory is loudest exactly where validation is now silent — a structurally-uncovered endpoint
gets the full remediation text, because nothing else says anything about it.
