## Description

## What

Closes CodeQL **`js/prototype-pollution-utility` alert 207** (`src/Core.TypeScript/ace/deps.ts:217`).

## What the alert was hiding — the existing mitigation did not close it

This alert has stayed open across an earlier mitigation that refused the segment names `__proto__` / `constructor` / `prototype`. **Measured 2026-09-09, that guard does not close the hole it was added for:**

```js
setNestedProperty(o, "a", Object.prototype);   // an ordinary value write
setNestedProperty(o, "a.polluted", "yes");     // no forbidden segment ANYWHERE
({}).polluted === "yes"                        // every object in the process
```

Refusing the **names** stops a path *spelling* its way to the prototype chain. It does nothing about a path that *walks* there, because traversal follows **values**, and a value can be a prototype object under any name at all. The guard has to sit on **what the cursor lands on**, not only on what the path says.

Four more defects, found by reading the code around the alert:

| input | before |
| --- | --- |
| `"a..b"` | `{"a":{"":{"b":1}}}` — a key named `""` no spec asked for |
| `"a."` | `{"a":{"":1}}` |
| set `a=1`, then `"a.b"` | `TypeError: Attempted to assign to readonly property.` — naming neither path nor field |
| `obj = null` | raw `TypeError` from inside the write |

## Fix

- **`isPrototypeObject()`** — an object is somebody`s `.prototype` exactly when its own-or-inherited `constructor` is a function whose `.prototype` is that object. Catches `Object.prototype`, `Array.prototype`, and any user class`s prototype; passes `{}` and `Object.create(null)`. A plain object that merely *sets* `constructor` reads as a prototype and is refused — fail-closed, the direction to be wrong in.
- Empty segments, non-container traversal, and a non-object target are refused **by name**.
- **Every refusal is atomic** — three passes (validate the path as written; walk the containers that already exist; then write), so a refused path leaves `obj` exactly as it arrived. A half-applied refusal leaves a shape neither the caller nor the spec asked for.
- Writes go through **`Object.defineProperty`**, not assignment. Assignment *runs* the `__proto__` setter; `defineProperty` defines an own property, so a forbidden key that somehow reached the sink becomes inert data instead of a prototype mutation.

## One mutation survived the first draft — recorded, not quietly repaired

Swapping `defineOwn` back to `container[key] = value` **changed nothing any test could see**, because `setNestedProperty` refuses the only keys on which the two differ. A safety property no test can distinguish is decoration. `defineOwn` is therefore exported and exercised directly against exactly that key, with a **control** test asserting plain assignment on the same key *does* move the prototype. That mutation now kills a test.

## Recorded, deliberately not changed

Two `consumes` targets where one path is a **prefix** of the other are order-dependent: `"db"` then `"db.url"` merges; `"db.url"` then `"db"` **silently discards** the url. Pinned as a measured fact in a test that says so. Which order is correct is a manifest-semantics question for the graph owner, not a security one, so this PR leaves it alone.
