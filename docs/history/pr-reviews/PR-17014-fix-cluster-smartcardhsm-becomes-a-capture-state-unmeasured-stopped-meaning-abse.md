## Description

`smartcardHsm` was a bare `boolean` while its siblings `Tpm2CaptureState` (six states) and `YubiHsm2CaptureState` (four) each carry an explicit `not-asked`. That asymmetry made the defect **unavoidable rather than careless**: a mapper that doesn't measure had two options and *both were lies* — `true` claims presence, `false` claims absence.

## The field was already read two ways in one file

| site | reading of `false` |
|---|---|
| `pickSealOracleFromCapture` — `if (capture.smartcardHsm)` | **absent** |
| `automaticOracleUnprobed` — `!capture.smartcardHsm` | **"we did not look"** |

One field, two incompatible meanings, decided by whichever function consulted it — inside `automaticCheckDidNotRun`, whose whole job is telling a check that didn't run from one that ran and found nothing.

## Measured wrong on real hardware

The frost→named mapper hardcoded `false` while correctly **refusing** to infer an HSM from a CCID reader. The refusal was right; the value it wrote was not. The capture in #17011 found a SmartCard-HSM v4.1 attached, initialised, and already provisioned.

## The change

`SmartcardHsmCaptureState = "present" | "absent" | "indeterminate" | "not-asked"`, mirroring its sibling. The mapper now writes `not-asked` — what it actually knows. The two readings become distinct expressions, a `smartcardLooked` predicate joins its two siblings, and the card gets the same stuck/silent legs the TPM and YubiHSM already had.

**Three fixtures now say what they meant.** Tests asserting `drift` for a prod box with only FIDO relied on `false` being silently read as *"looked, and absent"*. They now state `smartcardHsm: "absent"` explicitly — expectation unchanged. The type surfaced an implicit assumption rather than breaking a real one.
