## Description

## Summary

- add `.codex/bin/codex-loop-tick.ts`, a host-level Bun/TypeScript launchd runner for Codex
- keep a cheap per-minute heartbeat that records claim, trajectory, backlog, PR, and dirty-state surfaces
- enable a bounded read-only Codex gate on a separate cooldown when `ZETA_CODEX_LOOP_RUN_CODEX=1`
- add `.codex/bin/codex-loop-health.ts`, a host health probe that distinguishes healthy cooldown from a stuck loop
- document the local LaunchAgent, status/stop commands, logs, state files, health probe, and internal prior-art anchors in `docs/CODEX-HARNESS-NOTES.md`
- run the LaunchAgent from a non-protected control clone at `~/.local/share/zeta-codex-loop/Zeta`, avoiding macOS privacy failures under `~/Documents`

## Why

Codex does not expose Claude Code's native `CronCreate` / `CronList` surface. This harness does not have a native in-chat cron callback; the host loop therefore uses macOS `launchd` as the continuation mechanism.

The runner is intentionally TypeScript/Bun, not shell. It heartbeats every minute and, when enabled in the host plist, invokes `codex exec` read-only on a 900-second cooldown. The model gate writes to `ticks.log` / `ticks.err`; it does not appear in the currently open chat transcript.

Heartbeat alone is not enough to prove useful liveness. The health probe exits `0` for healthy, `1` for attention, and `2` for stuck. Stuck means launchd missing, stale runner log, over-time Codex gate, dead lock PID, or over-time lock. `codex=wait due_in=...` is explicitly healthy cooldown, not stuck.

## Root Cause Fixed During Host Verification

The first plist shape failed from `~/Documents` with macOS `Operation not permitted`, so the loaded LaunchAgent now runs from the non-protected control clone. A later forced `kickstart -k` exposed stale-lock behavior; the TypeScript runner now releases locks through normal return paths and recovers immediately when the recorded lock PID is already dead.

The first shipped version was still heartbeat-only. The loaded plist now sets `ZETA_CODEX_LOOP_RUN_CODEX=1`, `ZETA_CODEX_LOOP_CODEX_INTERVAL_SECONDS=900`, and `ZETA_CODEX_LOOP_CODEX_TIMEOUT_SECONDS=180`.
