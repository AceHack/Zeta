## Description

## The finding

`.github/workflows/agent-reviewer.yml` approved heartbeat flush PRs with:

> 'I attest that $PRODUCER produced genuine heartbeat events in this batch.'

Nothing in the mechanism supported that sentence.

- **Line ~144 was `REVIEWER="peer"` — a string literal.** No second agent, no
  second identity, no second key. The repository's own `GITHUB_TOKEN` would
  approve every producer's flush PR.
- **The independence was asserted in the artifact and absent in the machinery.**
  The one place that admitted it was a code comment; the claim went out on the PR
  and into a durable event in `docs/observe-events/`.
- **The binding was missing and was trivially available.** `$PRODUCER` is parsed
  from the branch name at the extract step; the event files carrying `by` are
  opened two steps later. They were never compared. A `flush/heartbeat-alexa-*`
  branch could carry events authored `by: otto` and be approved with a sentence
  naming alexa.

## What changed

**1. The binding (the actual fix).** Every event's `by` must equal the
branch-derived producer or the job fails. An underivable producer is now a hard
failure too: the extract step emits `agent=unknown` on an unparseable branch, and
everything downstream then approved the batch and wrote a receipt naming
"unknown" as the party whose work was verified. There is no batch for which that
is a true sentence.

One exemption, narrow and labelled: this same workflow appends its own receipt to
the flush branch, so on a later `synchronize` that receipt is inside `base..head`
and a flat rule would fail the job on its own output. The exemption accepts
exactly the shape this workflow writes and only when it names *this* branch's
producer. It is a shape match, not an authenticity check, and the comment says so.

**2. The claim.** The approval no longer uses the word "attest". It names the
verifier (this workflow, this token, **not** a peer), lists what was checked, and
states what was *not*:

> `by` and the branch name are written by the same producer, so their agreement is
> a consistency property, not proof of authorship.

No second identity was invented to make the original sentence true — the false
claim was removed instead. The durable receipt's `attestor` is renamed off
`peer-reviewer` for the same reason. Its `claim` field is left alone and
annotated: `AttestationEvent.claim` is typed to the single literal
`"heartbeat-genuine"` in `attestation-event.ts`, so widening it is
consumer-visible (`self-claims.ts` folds these into trust) and is the architect's
call, not this fix's.

**3. LOW #7, the interpolation.** `python3 -c "...open('$f')..."` spliced an
attacker-authored path into python source, and the ZetaId regex validated the
*basename* only, so directory components reached the interpreter unfiltered. Now
`python3 - "$f" "$PRODUCER" <<'PY'` with `sys.argv`, plus a full-path check that
the file is a direct child of `docs/observe-events/`.

## What this PR deliberately does NOT do

**This workflow has never run.** Measured, not inferred:

```
gh run list --workflow agent-reviewer.yml --limit 300 --json conclusion ...
=> [{"c":"skipped","n":300}]
```

Its trigger is `startsWith(github.head_ref, 'flush/')`; the fleet produces
`heartbeat/<agent>-flush-<sha>`. 300 of the last 300 runs are skips, and no event
in `docs/observe-events/` carries either attestor name. That is why the false
sentence never actually shipped to a PR — and it means this fix hardens an armed
but dormant approver rather than stopping live damage.

Re-pointing the trigger **arms an auto-approver** on the merge path. That is a
consequential, consumer-visible decision for the architect and the human
maintainer, so it is filed rather than done:
`workitems/081M0BTTM85087G0R003X6TWCD-*` — which also records an adjacent
data-quality finding (six live attestation events carry an `attestor` of
`/tmp/attest-<random>`, and `self-claims.ts` counts those as distinct witnesses).

## Blast radius

- **Who is affected:** nobody today (dormant). On the day the trigger is
  re-pointed: every heartbeat flush PR.
- **What they observe:** approval comments that state what was mechanically
  checked instead of claiming a peer attestation that never happened.
- **Action required:** none for this PR. The open decision is item
  `081M0BTTM85087G0R003X6TWCD` — arm it, or delete it; a dormant auto-approver
  in the tree is a loaded claim generator waiting for a branch rename.
- **SLA:** none breached. Independence remains unimplemented until a receipt is
  signed by a key the producer does not hold.
