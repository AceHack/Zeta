## Description

The four flash safety-rail bounds were defined **twelve times across four files** (`verify.ts`, `flash-usb.ts`, `flash-usb-linux.ts`, `flash-usb-windows.ts`). All twelve agreed, so **nothing was broken — this is a drift hazard, not a live bug.**

What makes it worth removing is that three of those files carried a *comment asserting the copies agreed*:

| file | the claim |
|---|---|
| `verify.ts` | "Exported from here so [they] cannot drift apart" |
| `flash-usb-linux.ts` | "identical to the macOS and Windows arms — one contract, three hosts" |
| `flash-usb-windows.ts` | "mirror flash-usb.ts exactly" |

Nothing checked any of it, and `verify.ts`'s claim to be the single home **was already false when written** — the Linux and Windows arms each defined their own. The way this eventually fails is silent: one arm's floor raised, the other two left behind, and a device one host refuses while another writes it.

`./size-bounds.ts` is now the single definition; the three modules import and re-export it, so their public surface is unchanged. **This adds no drift check on purpose** — divergence is no longer untested, it is no longer expressible.

### Second finding, fixed here

The test named **"rails match the macOS tool's size bounds"** imported no macOS module. It compared `flash-usb-windows.ts`'s own copy against hardcoded literals, so **it could not have caught the drift its name promised** — the same failure class as the comments, wearing a test's clothes. It still earns its place as a value pin, so it is renamed to what it does rather than deleted.

### Checked, not assumed

Mutating `MIN_ISO_BYTES` in the single definition to 999 GiB **fails 5 tests across all three arms** — including `contract with flash-usb-linux.ts` and the Windows bounds pin — so the shared definition is genuinely reached by the macOS, Linux and Windows paths rather than only typechecking against them.

Unmutated: **521 pass / 0 fail** across 23 files; `tsc --noEmit` clean.
