## Description

A passing test proves nothing until you know it can fail.

On 2026-08-01 that gap produced, in one day: six unfalsifiable "discharges" promoted into the frozen core, and a cache whose test was named *"reclaims unreachable cache entries"* while its only assertion was `expect(remaining).toBeGreaterThanOrEqual(0)` — a **count**, non-negative by construction, true for every possible value. Disabling the retraction entirely left it **3 pass / 0 fail**.

All caught by hand. Hand-catching is the most expensive tier there is and it does not scale.

## Why the free-tier fleet is the right runner

Not a capability argument:

- **Zero judgement** — flip `>=` to `>`, run the suite, compare exit codes. No model has to be *right* about anything.
- **Embarrassingly parallel** — one mutant per agent per tick. No consensus, no shared state, no ordering. Members add throughput at zero coordination cost.
- **Self-verifying** — the output is a fact, not an opinion. It survives the question every agent-produced claim must survive (*could this agent be wrong?*). No: the exit code **is** the finding.

Selection is **deterministic** from `(agent, tick)` via FNV-1a — no RNG, no clock. Ambient randomness would make findings unreproducible and breach DST (#7) and noninterference (#13). It's also what removes coordination: two agents pick different work without exchanging a message.

## Drift report, not a gate

Trunk-based at thousands of pushes a day doesn't want another blocker; it wants detection latency near zero. **Two distinct levers, not to be conflated:**

| lever | bounds | where |
|---|---|---|
| blast radius | how much one bad push can touch | `run-tier0.ts --max-files` |
| **detection latency** | how long broken sits on main looking green | **this** |

The vacuous sweep test had a *tiny* blast radius and *unbounded* detection latency — and scored perfectly on every check we had.

### A false positive found by that validation, and fixed

The first ` >= ` in `ephemeral-task-hierarchy.ts` is on **line 8, inside the docstring**. Mutating a comment changes nothing, so the suite passes and the runner reports a surviving mutant on a well-covered file. False positives are how a drift report becomes noise nobody reads.

`applyMutation` is now comment-aware; `pickMutation` filters on *behavioural* applicability. The re-run flipped that file to **KILLED as predicted**, while the Shiva finding held.

## 17 tests, including the load-bearing pair

A runner that reported "killed" unconditionally would look exactly like a healthy codebase — the same could-not-fail shape this tool exists to find, turned on the tool itself. Both directions are proven: **strong suite kills, vacuous suite survives.**

Plus always-restore *including when the suite cannot run at all* — this writes to a live repo's working tree, and in a trunk-based repo a leftover mutant is one careless `git add -A` from being pushed.

## Known limit, stated not hidden

**Equivalent mutants** — mutations that genuinely don't change behaviour — are undecidable in general. The comment case was one instance; others will produce false findings. This reports facts for a human to triage, and never blocks.
