## Description

feat(dep-update): Tier 0 export-surface diff — the free-runner escalation ladder

Aaron: "only deps that break things get routed for more intelligence off the
free runners." Measured against the actual lane, that rule is right and
incomplete, and both halves are here.

MEASURED (check-runs API, 27 Dependabot PRs, 2026-08-24 -> 2026-08-26; the
author: and label: searches return the identical set, so the denominator is not
a partial read):

  11 / 27 had a real dependency problem. By root cause:
    EXPORT_SURFACE 7 | PEER_DEP 1 | VERSION_ORDER 1 | TOOLCHAIN_COUPLING 1
    | cross-PR conflict 1

  10 of the 11 are reachable by a mechanical check; 7 by a single one. So most
  of what looked like "needs intelligence" was mechanical and unimplemented.

  The sharper number: of the 10 version-break PRs, CI caught 5 and MISSED 4 —
  and all 4 of the misses are mechanically detectable. #14583 had ZERO failures
  across 45 checks and still needed a hand-written migration, because
  src/Renderers/website has no gate job: its 45 green checks are 45 checks that
  do not look at it.

THE INVERSION, implemented rather than asserted: escalate on break OR
unexplained surface change. `routeUpdate` refuses to terminate at Tier 0 when a
removed export is unreferenced and the build is green, and ranks `TestsNotRun`
strictly worse than `TestsPassed`. The combinator is a JOIN — the max over
(outcome, surface facts, consumer facts) — so a green run can never buy down a
surface change, which is exactly the case where the tests do not cover what
moved.

SHIPPED: `toy-surface.ts` (pure: read, diff, classify, route), 16 falsifiers
over four REAL captured registry surfaces carrying their tarball integrity
strings, and `capture-package-surface.ts` (the only file touching the network).
It reproduces both real breaks — `XWing` removed from @noble/post-quantum's
./hybrid.js, and 30 removals from react-resizable-panels including PanelGroup
and PanelResizeHandle.

Eleven mutations, each killing >= 1 test. TWO SURVIVED THE FIRST RUN and were
real defects in the tests: the comment fixture never exercised `stripComments`
(the regexes are line-anchored, so the indented comment lines never matched),
and no captured fixture contains a MOVED name, so the real data could not
distinguish per-subpath keying from a flat union. Both fixed; the second by an
explicitly synthetic test labelled as synthetic.

Two design corrections the data forced, both found by running against real
packages rather than by reasoning: the surface is a map keyed by (subpath,
name), not a flat list — @noble/post-quantum's root .d.ts is literally
`export {};` and the first reader reported a clean diff of an empty surface;
and `sonarjs/super-linear-regex` found a correctness bug while complaining
about backtracking — `\s` matches a newline, so the line-anchored patterns
could span lines.

STATED, because it is load-bearing: Tier 0 cannot see a dead CSS selector.
react-resizable-panels v4 emits no direction attribute, so every
`data-[panel-group-direction=vertical]:*` utility became a selector that can
never match. That is a runtime observation of a component nobody renders, and
no amount of mechanical checking finds it.

NOT wired into .github/dependabot.yml, not wired into CI, nothing auto-merges,
nothing calls the capture tool on a schedule. Marked `toy`: the set difference
is metered against real bytes; the routing policy has no falsifier until there
are observed escalation outcomes.

Builds on #15583's typed transition core as a THIRD signal joined the same way,
not a replacement.

fix(dep-update): escape EVERY separator in the packument URL, not jus…

…t the first

CodeQL, on the previous push: "Incomplete string escaping or encoding — this
replaces only the first occurrence of '/'."

It is right, and the bug is instructive rather than embarrassing.
`pkg.replace("/", "%2f")` with a STRING pattern is single-shot. The code happened
to be correct, because an npm package name carries at most one `/` separating
scope from name — so it was right BY ACCIDENT rather than by construction, which
is precisely the class this repo refuses everywhere else. A name that said
"escape the slashes" escaped one.

Fixed to `replaceAll`, and `packumentUrl` extracted and exported so the property
now has a FALSIFIER rather than only a scanner. FALSIFIER 9 pins the two-separator
forcing case and carries a control (an unscoped name is untouched, so it cannot
pass by escaping everything). Mutating `replaceAll` back to `replace` kills it.

Worth recording why the mutation battery missed this: all twelve mutations were
applied to the PURE core, and this was in the I/O shell that was deliberately
kept impure and untested. Two mechanisms, two defect classes, neither
substituting for the other.

Local gate re-verified: prettier rc=0, eslint rc=0, tsc rc=0, 17 tests / 61
assertions rc=0, capture reproduces the XWing removal end-to-end.
