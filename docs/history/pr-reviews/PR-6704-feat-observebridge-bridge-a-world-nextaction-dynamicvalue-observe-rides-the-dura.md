## Description

## What

**Bridge A** toward wiring observe.ts into the DB (per
`docs/research/2026-06-07-observe-ts-integration-architecture-*`). The observe controller
(`World → NextAction → World`) and the durable substrate (`GitDeltaLog`/`DurableSaga`, which
carry `DynamicValue`) are the same shape; this codec lets the controller's snapshot + actions
ride that substrate — a `NextAction` becomes a delta-log event, `World` becomes the persisted
`Remains`, `Observe.Algebra.fold` over the log = recovery.

## Design

New project **`Zeta.Core.FSharp.ObserveBridge`** (refs `Core` + `Core.FSharp.Observe`) so the
**parity-pure Observe oracle stays zero-dep** (it mirrors observe.ts byte-for-byte across the 4
languages — coupling it to `DynamicValue` would break that). The coupling lives only in the
bridge. Wire tags mirror observe.ts (`work`, `self_reflect`, `preserve_ferry`, …). Encoders
total; decoders `Result`. `encodeAction`/`decodeAction` = canonical-CBOR hex (the
comparison-able log event).

## Proven (5 tests)

- All 9 `NextAction` kinds round-trip through `DynamicValue`.
- `World` round-trips (operator+mode present; and background-agent none/none).
- CBOR-hex round-trip.
- **The encoded event path folds to the SAME World as `Observe.Algebra` directly** — substrate
  composition is semantics-preserving.

Decision-free first rung. Remaining gaps (need your calls / later work): **B** (cell step =
`Observe.Algebra.simulate` vs Bonsai `Acts`), **C** (`NextAction` ↔ 4×4 `ActionGrid`), **D**
(the execution layer — actions as substrate ops, no raw git/gh).
