## The structural fact the type carries

**k-of-n is the generator and the dominating rules are its endpoints** — `Union` is `k = 1`, `Veto` is `k = n`, unweighted majority is `k = ⌈n/2⌉`. So `ofKOfN` ships and **normalises**. But the family is smooth in `k` and the dominance property is **not**: it holds at both endpoints and fails everywhere strictly between. A `KOfN of int` would have been a faithful parameterisation that hides the one fact a caller needs, so the strict middle is a separate case carrying a mandatory `Justification` — and `Unstated` is a legal, and damning, answer.

That field is what keeps **BFT honest**: `k = 2f+1` is correct there, justified by fault tolerance, not accuracy. Same for integrity detectors. Both are expressible **without being mislabelled** — and a bare quorum still cannot borrow the label: the verdict is `JustificationDisagreesWithPurpose`.

On a totally ordered codomain the same family is the **order statistics** (`max` = k=1, `min` = k=n, median = the strict middle). That reading predicts #10955's independent recommendation to replace `rmo.ts`'s median with the **max** — which is exactly `ofKOfN 1 n`.

## The mirror sweep — the quadrant nobody had examined

It falls out of the normalisation, and it found one.

**`review-board.ts:146` refuses to convene below `quorum` reviewers**, and `DEFAULT_REVIEW_QUORUM = 3`. So at the minimum convening size the quorum **is** every reviewer: `k = n`, **unanimity**, on a task whose dominant rule is union. `MirrorMismatch(needed recall, offered safety)`. That is sharper than #10955's "dominates on nothing" — in that regime it *does* dominate, on the opposite axis to the one the task needs. Honest scope: a statement about the rule at a configuration, read off the code, **not** a measurement of how often boards convene at exactly `quorum`.

The gate's fail-open other half (`review-gate.ts:81`) is the same shape inverted; **a sibling agent is fixing it, so neither file was edited here.**

Two more, weaker: `consensus.ts`'s `unanimous` and `first-n-agree(1)` mechanisms dominate on axes their site's own objective does not ask for (`WrongAxis`).

## What did not fit — findings, not forced rows

- **`Plurality` had to be added.** `Diversity.coerciveStep` and `nway-diff`'s reference fallback select by **argmax with no floor**. A threshold *refuses* when unmet; plurality never refuses. Rendering it as `Threshold` would have credited it with a floor it does not have. Naming note (not a defect): the `nway-diff` helper is **named** `majority` and is plurality.
- **`IndependenceCheck` had to be added.** `Veridicality.fs:200` counts *independent root authorities*, not votes — it checks the theorem's own independence hypothesis rather than aggregating under it. None of #10955's four buckets had a home for that.
- **"One site, one DU case" holds only at a fixed configuration.** Three sites compute their rule from runtime config, which is why the regime table is kept separate — and it is exactly where the mirror defect lives.
- **`rmo.ts`'s median fits only through the order-statistic reading**, which is an identification I am making, stated as such.

Cases that ship **unpopulated**, each forced to be declared with a reason by the exhaustiveness tests: `LogOddsCompetence` (**the finding — no site weights by a measured competence**, #10955's recommendation restated as a type), `PricedPrecisionTrade` (the defence a quorum is *entitled* to make; without it every threshold is a finding and the finding is worthless), `AnyOf` (dual of the `AllOf` earned by `constitution-gate`), `JustificationDisagreesWithPurpose` (a guard; unreached is the good outcome).
