## Description

**Windows was verified green on this branch and then never landed.** I ran the dispatch, saw both legs pass, reported it, and never opened the PR — so `main` has stayed red and the drift job has kept firing about a defect that was already fixed. That is the whole reason `drift (loud)` keeps going off.

## The fix

The previous change (`detached: true`) solved the job-object problem and **uncovered the next one**: with the grandchild finally surviving its launcher on Windows, `File.ReadAllText` could no longer open the capture file — a writer still held it.

```
System.IO.IOException : IO_SharingViolation_File ... at File.ReadAllText(...)
```

This bug **could not have existed before**: while the grandchild died with its launcher there was no surviving writer, so the read was always legal. Fixing the first bug is what made the second reachable.

`FileShare.ReadWrite` on an explicit `FileStream` is the right instrument rather than a retry, because the writer is not transient — the entire point of the fixture is that a process is *still holding* the pipe open at that moment. A retry would wait for a condition the test exists to create.
