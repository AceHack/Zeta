## Description

## The gap, measured

The ISO manifest integrity check existed in the macOS arm and **nowhere else**.
Measured on `main` 2026-08-21:

```
grep -nE 'checkIsoAgainstManifest|manifest|sha256|SHA256' flash-usb.ts          -> 5 hits
grep -nE 'checkIsoAgainstManifest|manifest|sha256|SHA256' flash-usb-linux.ts    -> 0
grep -nE 'checkIsoAgainstManifest|manifest|sha256|SHA256' flash-usb-windows.ts  -> 0
```

On Linux and Windows, `zflash` wrote an image to a block device with no integrity
verification of any kind. A live gap, not a drift hazard.

## What changed

**One definition, three call sites.** `src/Core.TypeScript/zflash/iso-integrity.ts`
holds `establishIsoIntegrity` — manifest candidate search, read, ISO hash, and the
refusal message — over an injected `IsoIntegrityIo`. The verdict logic stays where
it already was (`verify.ts`'s `checkIsoAgainstManifest`, unchanged). The macOS
arm's inline block was **replaced by a call**, not copied into the other two: a
third and fourth copy is the exact failure class `size-bounds.ts` was extracted to
end (four numbers defined twelve times, under comments asserting they agreed).

**Fail closed, no opt-out.** Six refusal reasons — `manifest-missing`,
`manifest-unparseable`, `iso-not-in-manifest`, `digest-mismatch`, plus the two I/O
failures only this layer can see: `manifest-unreadable` (deliberately *not*
reported as missing — telling an operator who has the manifest to go and download
one is how a permission error becomes an hour) and `iso-unreadable`. "No manifest
found" is never "verified". Refusals name the files expected and the directory to
put them in, and print the computed digest.

**The wiring is checked, not asserted.**
`src/Core.TypeScript/hygiene/audit-flash-entrypoint-parity.ts` derives the arm
roster from the zflash directory listing (a fourth arm is audited the day it
appears) and requires each arm's `main()` to call the gate, bind its verdict,
`bail()` on **its own** failure branch, and do all of that before the first
destructive operation. An arm whose `main()` contains no destructive operation is
a finding, not a vacuous pass; so is an empty roster.

**Placement.** Wired into `gate.yml`'s cross-verify floor beside
`audit-proof-lineage-binaries.ts` — the placement `build-ai-cluster-iso.yml`'s own
note asked for. It is deliberately **not** restored to the ISO lane: there it
gates ISO upload, the digest sidecar and cosign signing, which is how a missing
script silently killed ISO production in #13102. The stale note in that workflow
is updated to say where the audit went.

**M8 initially SURVIVED, and that is the most useful result here.** The refusal
rule's first version looked for `bail(` anywhere in the 400 characters after the
gate call — and the next unrelated guard's `bail(` sat inside that window, so the
rule passed for a reason that had nothing to do with what it claimed to establish.
That is this repo's own defect class, produced by the check written to catch it.
The rule now reads the gate's own failure branch with a balanced scan (statement
or braced block), and M8 fails as it should. The surviving-mutant shape is pinned
as a test.

**The audit run against `HEAD~`'s arm sources reports three `gate-absent`
findings** — including macOS, honestly: on `main` that arm had an equivalent
*inline* check, not the shared gate the audit names.

## Measured vs designed-but-unrun

**Measured:** everything above, on source. 554 tests green. `bunx tsc --noEmit -p
tsconfig.json` reports **46 errors, identical on pristine `HEAD`** and all
environmental (`Cannot find module 'yaml'` / `'playwright'` in this checkout's
`node_modules`, plus their `any`-typed cascades). **Zero** are in any file this PR
touches.

**Designed but UNRUN:** no ISO was written to a real block device on any of the
three hosts — this tree cannot do that, and two of the arms only run on operating
systems CI does not flash from. The gate's branches are exercised through injected
I/O; the syscall edge (`existsSync` / `readFileSync` / `sha256FileHex` against a
real ISO) and the Linux and Windows arms end-to-end remain unexercised. The audit
is source-level: it would not catch a gate reached only under a condition that is
never true. What it does catch is the entire observed defect class — an arm with
no gate, and a gate placed after the write.
