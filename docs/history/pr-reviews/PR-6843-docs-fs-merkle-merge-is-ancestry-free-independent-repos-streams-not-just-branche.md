## Description

## What — Aaron 2026-06-07
> "you can merge two independent streams/git-repos AND within a branch on the same git repo."

Both scopes use the **same `DagFs.merge`** because content addresses are **global + history-independent**:

- **within one repo** — merge two branches (shared history);
- **across independent repos/streams** — merge two roots with **no common ancestor**.

Content union dedups across *strangers* (identical content in never-connected repos → one node); only path→content bindings resolve.

**Contrast with git:** git's merge is **3-way, requiring a merge-base** — it can't cleanly merge unrelated histories. Content-addressed merge needs **no merge-base**; any two trees merge. Same reason **CRDT** merge is coordination/ancestry-free and **DBSP** merges independent streams by Z-set union — the substrate for the **geo-replicated / anygit edge-replica** vision. *"git-compatible but better": merge is ancestry-free.*
