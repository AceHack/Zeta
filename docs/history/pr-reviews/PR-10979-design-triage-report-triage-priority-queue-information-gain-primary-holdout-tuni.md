## Description

## Triage, not judgement

Nobody — no person, no agent — is labelled defective by anything here. This is an **ordering**, and:

- **It only bites under scarcity.** With capacity to examine every report, every report is examined and the order is irrelevant. The queue is a response to a resource constraint and has no meaning without one.
- **A low position is about the queue's current information, never about the reporter.** No per-reporter ranking is emitted as a product.

The frame is carried in the doc's §0, in the module's header docstring, and in a test (`the queue orders and never rejects`) — not just asserted here.

## The structural choice: information gain as the primary dimension

The naive design is track-record-primary with a severity override. It **buries a newcomer's critical find by construction**: no record → sorts last → never examined → still no record.

Ordering by **expected belief change** fixes this at the root. A severe report from an unknown reporter sorts high *on its own merits*, and track record enters only as a discount on the claimed likelihood — which produces Aaron's tiebreak ("who has been right in this area") automatically, exactly when two reports would teach us about equally much.

`lambda` is floored above zero, so **track record can scale a newcomer's report but never silence it.**

## The honest part: KL is not computable for the reports we actually get

Verified by reading `AttentionRouter.fs` and `InformationValue.fs` in full:

- `InformationValue.compute` / `valueOfMessage` already compute Lindley information gain, FsCheck-proven (IV-1..IV-7). `AttentionRouter` is already `KL × alignment × Condorcet bonus` — a multidimensional routing weight, one level over (it routes attention *between agents*, not *reports*).
- **But nothing produces claim-typed reports.** KL needs a prior over the claim's subject plus the report as a likelihood; real inbound reports are free text.

**So for today's reports the queue collapses to severity + track record — the materially weaker design.** Stated plainly rather than left to be inferred. The gap closes with a **report format** carrying `{variable, estimate, uncertainty}`, not with more scoring machinery — the scorer is already built and proven. `proxyFraction` reports what share of an ordering rests on the stand-in; today it is 1.0.

## Self-confirmation: the holdout is the escape

Aaron's mechanism, and it is better than the randomised floor I first reached for. Tuning is evaluated against a **withheld expert-labelled set the queue's ordering never selected**, so evaluation cannot self-confirm. He calls it a heuristic hack; it is the train/holdout split. Automatic feedback is safe *provided* it is evaluated that way.

Also shipped: randomised exploration (now serving mainly to keep successive holdouts unbiased — otherwise "refresh the holdout" means resampling from what the queue already surfaces), `Unexamined` kept distinct from examined-and-found-nothing, and a cap on weight movement.

**No auto-tuner ships.** No labelled set exists, so a tuner built now would necessarily train on the queue's own selections — the exact circularity. The guards ship; the tuner waits for the data.

## Cry-wolf is separate from track record, and is blocked

Severity is gameable, so severity-claim calibration gets **its own ledger**. Merging it with validity corrupts both directions: it deranks a good finder for a labelling habit, or launders an inflater because they are usually right. This is calibration in the strict sense — the quantity `calibration-ledger.ts` already computes (Beta/Brier, Gneiting–Raftery), applied to severity claims. Reuse it; **that file is not edited here.**

**It is blocked on a prerequisite Zeta does not have.** Searched by behaviour: `P0..P3` labels exist (schema-enforced), with one-line glosses that mostly describe *urgency*, plus a `**Severity:**` field in `BUGS.md`. Nothing states the observable conditions under which a report *is* P0 rather than P1 — so **no severity claim in this repo is currently falsifiable**, and a cry-wolf meter built now would measure disagreement and call it miscalibration.

Shipped as a **typed hole naming the blocker**, not a stub returning zero. The rubric is small, tractable work that belongs outside a queue implementation (§7).
