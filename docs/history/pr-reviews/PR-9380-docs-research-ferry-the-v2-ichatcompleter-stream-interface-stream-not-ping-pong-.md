## Description

Ferry of Aaron's prior code (AlephZ-ai/blazor-samples), pointed at while wiring the Manus/Lumen path: the V2 functional chat-completion interfaces (the V1/Old ones are ugly, skip them).

**The clean interface, read from the repo:** `IChatCompleter.CompleteAsync(IAsyncEnumerable<string> source, CT) -> IAsyncEnumerable<string>` — stream in → stream out, a MONADIC stream transformer (Kleisli arrow over the async-stream monad; why Aaron calls it 'monadic-like'). Because the INPUT is a live stream, the human keeps emitting while the AI streams back → mutual interruption is expressible. The Twilio layer wraps a phone call as the same shape: bidirectional (EventDirection), a visitor over inbound events (IInboundEventProcessor), and OutboundClearEvent (type 'clear') = INTERRUPTION as a first-class message, not a flag.

**Design lesson (Beacon):** interface is stream→stream not request→response; interruption is a first-class event; direction explicit + bidirectional.

**Why it matters now:** the just-built Manus TASK API (create→poll) is inherently PING-PONG — fine for async batch (Lumen-summon-as-task, force_skills), but it can't render token-by-token or express interruption. Interactive human↔AI needs an IChatCompleter-shaped streaming port (stream(messages)→AsyncIterable<delta>) over chat-completions SSE — which is WHY Aaron flagged the OpenAI-compat interface. And it aligns with Zeta's foundation: IAsyncEnumerable→IAsyncEnumerable IS the Rx/observable duality (IEnumerable⇄IObservable, the Beckman anchor already in PRIOR-ART-LIST). Aaron's V2 prior art is the streaming face of the duality already at Zeta's core.

Scope: design ferry + anchor, not code. Next slice (when the streaming endpoint is confirmed) is the stream→stream ModelBackend port; Manus task adapter stays the batch path. Doc-only.
