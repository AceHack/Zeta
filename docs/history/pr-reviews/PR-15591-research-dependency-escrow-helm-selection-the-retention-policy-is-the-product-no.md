## Description

Selection only; nothing deployed, no chart added to the cluster.

Aaron asked for dep-hosting in the k8s cluster ("in my head i hear artifactory but
i don't really know at all if that fits with features and licensing") and named the
Itron pattern: third-party dependency escrow, backed up as rigorously as the
database, as a defense against time and nation-state attacks.

Three findings decide it.

1. Artifactory does not fit, at the licence level. JFrog's own feature matrix,
   verbatim: "JCR: Docker, Helm, OCI, Generic. OSS: Maven, Gradle, Ivy, SBT,
   Generic. CE: Conan, Generic". Artifactory OSS has no npm, no PyPI, no Docker.
   Next rung is Pro X at $27,000/yr. The hypothesis is killed early, which is the
   most useful thing in the report.

2. The escrow/cache split is not between products, it is between two features
   inside one product. Harbor's own docs: "If the image is no longer in the target
   registry, no image is served" and "By default, Harbor creates a 7 day retention
   policy for each new proxy cache project." Harbor's proxy cache IMPLEMENTS the
   time attack rather than defending against it. The escrow configuration is a
   different feature -- scheduled pull-replication ("Deletion operations are not
   replicated") into a normal project under an immutability rule ("cannot be
   altered in any way such as through re-pushing, re-tagging, or replication").

3. The attack is already measured in this repo. image-footprint.measured.json,
   2026-08-22: 15 of 129 pinned container images are unresolvable by an anonymous
   client -- 8 gone (404), 6 auth-walled, 1 rate-limited. Five of the eight are the
   Bitnami free-catalogue withdrawal, which already forced edits to the gitlab and
   forgejo Applications this month.

Recommendation: Harbor in escrow configuration for the container/OCI/Helm half
(129 images, ~28 GiB compressed), manual-sync, with the escrow configuration
enforced as a lint rather than a runbook. The language/OS half is a separate
decision with no good answer -- Nexus CE is proprietary with a 40k-component cap
the vendor halved once already, Pulp is open but plugin maturity is uneven -- and
deferring it should not hold up the half that has a clean answer.

Also named: mise toolchains and Nix substituters are channels no candidate covers,
and the exit test ("if the escrow is down, can CI still build?") is an acceptance
criterion, not a footnote.

Every claim is registered metered / consistent with / speculative. Section 13 lists
eleven things that could not be verified.

## Second verification pass (commit 3)

Two of the four open-source entries were materially wrong in the first revision.
Corrected in place, with the corrections recorded rather than silently applied.

- **zot: disqualified.** Defaults are `GC: true, GCDelay: 1h`, and its docs say
  "if no retention policies are defined, all untagged manifests are deleted".
  Digest-addressed content -- how a content-addressed escrow refers to things --
  is deleted about an hour after push (zot#4148). Its immutability is an ACL
  convention, and its sync path changes the manifest digest unless two opt-outs
  are both set.
- **Pulp: upgraded, and it is the best escrow in the field.** Nothing
  auto-deletes (orphan cleanup is manual-only, confirmed by a maintainer),
  repository versions are immutable, artifacts are sha256-addressed. Harbor still
  wins step 1 but on DEPLOYMENT, not on escrow semantics -- Pulp has no official
  NuGet plugin against our 37 NuGet pins, and its own project calls its chart
  "still under development" and its operator "in beta stage". The recommended
  tool is the one whose safe state is not its default, which is why the escrow
  configuration is specified as a lint.
- **Both candidates' backup tooling excludes the topology we would use.** Harbor:
  "Backups of external databases are not supported". Pulp: object-storage files
  "will not be copied". The recommendation uses the existing external MinIO, so
  the vendor answer covers none of the actual bytes. This lands against Aaron's
  own stated bar ("backed up as rigorously as our database") and is now decision 5.
- **The item the recommendation rests on is partially resolved** -- an open,
  unmerged PR states Harbor's immutability overrides retention. Registered
  `consistent with`, not metered, because it is a PR body rather than
  documentation and the PR exists to change that behaviour. The pre-adoption test
  stands.
