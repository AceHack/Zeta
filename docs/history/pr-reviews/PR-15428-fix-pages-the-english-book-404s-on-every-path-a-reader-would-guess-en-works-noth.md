## Description

Reported: "some people are getting 404 at my English version of Born at the Hinge."

MEASURED LIVE against the published site, 2026-08-25, rather than reasoned about:

  200  /books/you-born-at-the-hinge/          <- but serves lang="zh-Hans"
  200  /books/you-born-at-the-hinge/en/
  200  /books/you-born-at-the-hinge/en
  404  /books/you-born-at-the-hinge/index.en.html
  404  /books/you-born-at-the-hinge/en.html
  404  /books/you-born-at-the-hinge/english/

The English page is FINE. The build is fine — the deploy's mkdir list and cp list match
exactly across all eleven languages plus root, and pages-deploy is succeeding. What fails
is every path a reader plausibly types.

THE SHARPEST ONE IS `/index.en.html`, because that is the REPO FILENAME. Anyone who found
the book by reading the repository sees `docs/books/you-born-at-the-hinge/site/index.en.html`
and tries the matching URL. It 404s. The publish step renames it to `en/index.html`, so the
path that exists in the source and the path that exists on the web are different, with no
bridge between them.

Compounding it: the ROOT of that directory serves CHINESE (index.zh.html). So an English
speaker handed the base link lands on a Chinese page, goes looking for English, and every
natural guess fails.

FIX: meta-refresh redirect stubs for the guessable paths — `index.<lang>.html` for all
eleven languages (mirroring the repo filenames exactly), `en.html`, and `/english/`. Each
stub carries a real anchor and a canonical link, so it works with JS disabled and for
crawlers. PURELY ADDITIVE: no existing path changes, nothing is moved or renamed.

NOT CHANGED, because it is a content decision and not mine: the root serving Chinese. If
most readers arrive in English that is surprising behaviour, but which language owns the
root is an audience call.

Controls: `actionlint` clean; the stub loop dry-run locally, emitting valid files with the
expected content.
