## Description

Updates P1 081M05G8D36087G0R0034D3QPA rather than filing a new item — same
token, same operator-gated class, and the file already carries the history.

Measured on heartbeat run 2026-08-25T14:30:17Z. The two halves fail
differently, which is what makes this conclusive rather than a guess:

  git push the snapshot ref  -> WORKING. origin/heartbeat/alexa ==
      origin/heartbeat/alexa-flush == 7eba3a909; soraya likewise at
      9562cb42d. Contents: read and write is present and doing its job.

  gh pr create the flush PR  -> 403. "Resource not accessible by personal
      access token". Pull requests: read and write is absent.

A token that can push a branch and cannot open a PR produces exactly this
pair of outcomes, which answers the operator's direct question about whether
Contents R/W + Metadata R was sufficient. It is not.

GITHUB_TOKEN cannot substitute: an org policy forbids Actions from creating
pull requests — the failure agent-heartbeat.yml already documents as the
reason a PAT exists here at all.

WHY IT SURFACED ONLY NOW, six hours after the rotation: it was masked by a
different fault. Every lane had been backpressured behind stale flush PRs
since 08:21, so no tick ever REACHED `gh pr create` — the job died earlier,
at a guard reading an output the backpressure path never wrote (#15348).
Clearing those blockers made this the first PR-create attempt in six hours
and it 403'd immediately. One defect hiding behind another is why the last
successfully created flush PR is #15326 at 08:21:52.

Nothing is lost, by construction rather than luck: the lane holds unlanded
work, not the ref — 3 commits unflushed on alexa, 5 on soraya, both parked on
immutable snapshots, and the flush is idempotent (G-Set union) so re-merging
an already-landed event set is a no-op whenever the scope is granted.

Operator action, which no repo change can substitute for: grant
`Pull requests: Read and write` to ZETA_TELEMETRY_FLUSH_TOKEN.
