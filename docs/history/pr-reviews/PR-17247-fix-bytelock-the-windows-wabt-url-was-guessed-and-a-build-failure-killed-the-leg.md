## Description

## What

Repairs both Windows byte-lock legs, which went red on run [34497580746](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/34497580746) after #17243. Two defects; the second is the one worth having.

## 1. The asset name was a guess, and the guess was wrong

The step fetched `wabt-1.0.36-windows.tar.gz`. The real roster — **queried** this time rather than assumed — is `wabt-<ver>-windows-x64.tar.gz`, and there is **no windows-arm64 asset at all**, so `windows-11-arm` runs the x64 binary under emulation. Pinned to 1.0.41, the version measured to rebuild `dla-canonical-wat.wasm` byte-identically.

The download and the extracted layout are both checked now, and both say so when they fail. A `curl` that 404s previously left `wat2wasm: ABSENT` with no clue why — the install step reporting a healthy-looking absence, which is the exact shape that change went in to remove from Chocolatey's `wabt`.

I wrote a URL I had not measured, inside a change whose entire premise was measuring first. The Linux and macOS routes came from the probe; this one was typed.

## 2. A build failure took the whole leg down, which is wrong for *this* workflow

WAT failed first, `set -e` ended the step, and **Rust, Zig, AssemblyScript and Emscripten were never attempted** — so one missing toolchain destroyed the report the cross-processor comparison reads, rather than reducing a count.

That inverts `bytelock.yml`'s stated design:

> a MISSING TOOLCHAIN is environmental and must not block; a substrate computing DIFFERENT BYTES on two machines is the fault class this workflow exists to catch

The floors already enforce the second, and better than a build step can: `BYTELOCK_REQUIRED_SUBSTRATES` **names** the substrate that did not run, and `BYTELOCK_MIN_SUBSTRATES` is per-route by exhaustion.

So the action gains `fail-on-build-error`, **default true** — the Pages and gate lanes *consume* these artefacts and nothing downstream would notice one missing — and `bytelock.yml` sets it **false** and lets its own floors judge. Either way every substrate is attempted and the failures are named in the log.

## Unchanged, and verified post-merge on that same run

`ubuntu-24.04`, `ubuntu-24.04-arm` and `macos-26` each built all six substrates from source and agreed with the **unchanged** golden vectors; the blocking `cross-processor byte-lock` passed; and `Deploy to GitHub Pages` built and published all seven oracle modules. This PR touches only the Windows path and the failure policy.
