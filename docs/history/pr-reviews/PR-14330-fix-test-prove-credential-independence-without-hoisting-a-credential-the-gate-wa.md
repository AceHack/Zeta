## Description

The `lint (bash retirement inventory + hygiene unit tests)` job went red on this PR, and
the finding is correct, not noise:

  measure-lane-footprints.test.ts:147  process.env.GITHUB_TOKEN = "ghp_..."
  measure-lane-footprints.test.ts:148  process.env.GH_TOKEN = "ghp_..."
  [process-env-assign-of-credential: assigns into process.env, which every child inherits]

I had written a test that demonstrates "this tool ignores an ambient credential" BY
SETTING AN AMBIENT CREDENTIAL. An environment variable crosses `exec` regardless of the
child's identity, so that is the one exposure no keychain ACL or signature can gate —
which is precisely why `lint-no-ambient-credential-hoist.ts` exists. A test that proves a
safety property by performing the unsafe act is not a proof of it; it is the act, inside
a process that spawns children.

It also passed locally before the commit and failed after, which is its own lesson: the
lint scans TRACKED files, and I ran it while the new file was still untracked. A check
run against a working tree that does not yet contain the subject is a check that did not
run.

NOT WIDENED, NOT DISABLED, NOT ALLOWLISTED. The claim is split into the two halves that
can each be checked without doing the unsafe thing, and both are stronger than what they
replace:

  ON THE WIRE   the stub's request log shows the first request goes out BARE and the only
                Authorization header in the whole exchange is the token the registry
                itself just issued.
  IN THE SOURCE the module names no credential environment variable and reads
                `process.env` / `Bun.env` nowhere. Comments are stripped before the scan,
                because the header NAMES those variables in order to say it ignores them
                — scanning prose would fail on the documentation of the property and,
                worse, would go green the moment someone deleted that paragraph.

The mutant it exists for is unchanged and still dies: re-adding
`headers.Authorization = process.env.GITHUB_TOKEN` to the fetch path fails the source
half. Re-verified by applying it and reverting it — 9 pass / 1 fail with, 10 / 0 without.

VERIFIED: every step of the failing job, locally — `hygiene:check-bash-retirement-inventory`,
`hygiene:no-ambient-credential-hoist`, `hygiene:no-decide-by-grep`,
`hygiene:scan-floor-routes` all exit 0, and `bun test src/Core.TypeScript/hygiene/` is
2256 pass / 0 fail. Cluster tests unchanged at 891 pass / 0 fail.
