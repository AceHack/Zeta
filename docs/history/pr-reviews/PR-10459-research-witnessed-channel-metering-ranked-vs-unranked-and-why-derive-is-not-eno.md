## Description

Two clarifications from Aaron that fix a real gap in the Arena capability-label design (#10447).

## "Derive, don't declare" was necessary and not sufficient

That doc argued the Arena should **derive** a participant's capability class from observed channel access rather than accept a self-declaration, because *"the emulator knows what was read."*

**But if the participant runs the emulator, deriving is self-attestation with extra steps.** The derivation is only as trustworthy as the deriver, and the deriver sat inside the participant's trust boundary the whole time. Aaron's fix: the meter is **cryptographically witnessed**, not merely derived.

The architectural constraint that follows: **the meter is a producer on a transport, not a logger.** Anything between the access and the signature is editable by the participant, so the record must cross the trust boundary *at the moment of observation*, while the run is still happening. "Even if it's in memory" means the in-process case uses the same code path — the DoP=1 case, no special-casing the local run.

## The name: ranked vs unranked

Aaron: *"this is like ranked vs non ranked matches."* Adopted as the vocabulary — it carries the properties without a glossary. Ranked affects standing; unranked doesn't; nobody reads unranked as lesser play; ranked costs more infrastructure, which is exactly the witness requirement.

The technical anchor is unusually good: **competitive games are server-authoritative because client-attested state is forgeable.** Client-side anti-cheat is self-attestation, and it lost. Same conclusion, reached independently.

## Unranked mislabeling is a training signal, not an offence

*"we don't scold for that we teach and get better at detection … let them refute it and mutual learning occurs, teach, play after tit for lessor tat. Ranked needs stronger guardrails."*

This applies **tit-for-lesser-tat → teach → play** to the Arena's *governance*, not just to play inside it — self-similar across levels. A detected cheat in unranked is free red-team labour; punishing it drives the behaviour out of instrumentation range, the same black-market argument made for wagering. So the regimes are a **pipeline**: unranked trains the detector, ranked deploys it.

### The coincidence worth naming

**Disputed detections are boundary cases** — nobody argues with an obvious catch. In active learning, boundary cases are the **most informative per label** (uncertainty sampling). So the refutation queue *is* the high-value training set, and **the procedure fairest to the accused is also the one that improves the detector fastest.** Due process buys efficiency here rather than costing it, which is worth saying because designs usually assume the opposite.

### The risk it creates

If unranked is the training set, **the training set is poisonable** — generate refutable near-misses to push the detector toward false positives in ranked, or flood easy cases so it never learns the technique you intend to use. That's the adversarial-teaching regime at a different layer: same geometry, same defence.

## Fifth independent arrival at one answer

The homoclinic tangle, the orbital independent check, the empowerment/decorrelation coupling, the adversarial-teaching regime, and now the Arena meter. **A loop cannot certify itself.** That recurrence is itself evidence the principle is load-bearing.

Eight open items, including: name `f` per tournament class (`quorumSize(faultModel)`, never a bare count), mutual signature so neither side can unilaterally forge a record, and whether capability class must be **pre-declared** in ranked so it can't be chosen after seeing the score.
