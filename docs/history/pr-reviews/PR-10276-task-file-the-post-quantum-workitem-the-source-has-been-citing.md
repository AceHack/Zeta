## The measurement (by execution, not assumption)

.NET 10 **does** ship the FIPS 203/204/205 types:

```
MLDsa / MLKem / SlhDsa / CompositeMLDsa   all present in the BCL
MLDsa.IsSupported = false                 ← on this macOS host
```

**The types exist and the platform doesn't back them here** — .NET's PQC is platform-provided, not managed. A check that only asked *"does the type exist?"* would have concluded we have post-quantum signatures. We don't, on this machine.

**Unverified:** whether `IsSupported` is true on the Linux cluster nodes. That's the first thing to measure — it decides whether this is buildable today or blocked.

## The N=3 work already built the shape

- **R6** — the scheme is a **port**; adding ML-DSA is one adapter, not a refactor
- **R7 + B9** — bounded **half-open** migration window on the verifier, **no coordinator**
- **B4** — an **unbounded** window is legal, so permanent hybrid classical+PQ is supported. `CompositeMLDsa` is exactly that shape
- **B7** — adapters must be pure and total, so a PQ adapter returns a fault rather than throwing when unsupported
