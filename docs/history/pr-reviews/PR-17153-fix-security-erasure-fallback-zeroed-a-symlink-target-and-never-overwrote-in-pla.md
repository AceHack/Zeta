## Description

## The finding

`tools/setup/persona-keys/teardown.ts` erases private key material. When `shred` is
absent or fails it falls back to overwrite-then-unlink. That fallback was:

```ts
const size = statSync(path).size;
if (size > 0) writeFileSync(path, Buffer.alloc(size, 0));
```

Four defects, on the path holding a **private key**.

### 1. It followed symlinks — demonstrated, not argued

Both calls resolve links, so a symlink swapped in for the key **zeroed the link's
target** while the bytes it replaced survived untouched. The new regression test
writes an unrelated file, points a link at it, erases the *link*, and asserts the
target's contents. Against the old implementation:

```
Expected: "DO NOT ZERO ME"
Received: "              "
```

### 2. It could not overwrite anything

`writeFileSync` opens **O_TRUNC**, which releases the file's blocks *before* writing.
The zeros land on freshly-allocated blocks and the private bytes are never touched.
The step could not perform the one act it exists for — an erasure byte-identical in
effect to a plain unlink, wearing a shredder's name.

### 3. Check-then-use — the `js/file-system-race` finding

Size read from the **path**, write issued to the **path**. Anything replacing the
path between the two calls redirected the overwrite (CWE-367).

### 4. No fsync

Even a correct overwrite can still be in page cache when `unlink` frees the blocks,
leaving the original bytes on the medium.

## The fix

One file descriptor, `O_RDWR | O_NOFOLLOW`, **neither O_CREAT nor O_TRUNC**. Stat and
write both go through that fd, so there is no second path resolution to race; a
vanished path throws instead of being re-created; a symlink is refused instead of
followed; `fsyncSync` forces the zeros to the device before unlink. Success is decided
by `lstatSync` rather than `existsSync`, because a **dangling symlink still occupies
the name** while `existsSync` reports false for it — which would have let a failed
unlink report success.

Separately, ENOENT on unlink now reports **success**. Teardown is re-run to prove clean
re-onboarding, and reporting failure for an already-absent path teaches an operator to
stop reading a destructive tool's output. **That gap was found by the new tests, not by
inspection.**

## Why there were no tests before

The fallback is **unreachable on any host that has `shred`** — which this repo's dev
machines do, via homebrew — so nothing had ever executed it. It is extracted as an
exported `overwriteAndUnlink` precisely so that it can be run.

## Mutation-tested, reported honestly

Restoring the old body kills **2 of the 5** new tests (the symlink test and the
idempotence test). The other three pin contract that both versions satisfy — they are
regression guards, not falsifiers of this fix, and I am not claiming otherwise.

**Defects 2 and 4 are not covered by any test.** Neither the O_TRUNC no-op nor the
missing fsync is observable from userspace; both are argued from the open flags, not
measured. Saying so is the point — a test suite that appeared to cover them would be
the same vacuity class as the shredder that could not shred.
