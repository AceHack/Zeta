## Description

Files the root cause behind three ticks of manual archive-queue draining.

`archive-pr-reviews.ts` writes `docs/github/prs/manifest.jsonl` by **read-modify-write of one shared file**. Every archive PR rewrites the whole manifest and touches the same trailing region — so **N in-flight archive PRs conflict pairwise**, merging any one invalidates the rest, and the queue drains only serially with a rebase per merge.

**Observed live today (CHECKED):** eight archive PRs simultaneously open and mutually conflicting (#10391, #10392, #10399, #10400, #10403, #10404, #10405, #10407). Draining consumed three autonomous ticks and produced one self-inflicted bug — a stray `=======` pushed into two branches by an automated union resolution, caught on verification and repaired. The queue then re-grew immediately, because each merge generates a new archive PR that conflicts with whatever is still open.

That is the designed behaviour of the data structure, not a busy day — which is why this is filed instead of drained a fourth time.

## Disciplines violated

- **§2 lock-free** — an archive PR can't progress without the prior merge of every other. The shared mutable file *is* the lock.
- **§8 DV2.0** — a fast-changing satellite stored in a single-file hub shape.
- **§12 idempotency** — re-archiving is a read-modify-write, not an upsert on a natural key.

## Fix, using patterns already in-tree

**A (recommended): shard by ZetaId** — one file per archived PR, the pattern already used by `data/tick-shards/YYYY/MM/DD/<zetaid>.json` and `workitems/events/`. Concurrent writers stop touching the same file, so the conflict class *disappears* rather than being mitigated. This is Aaron's own instruction (*"many of our folder are absgtracted with zetaids for collizion resistance"*) applied to a system that predates it.

**B: derive the manifest, don't store it** — regenerate from a scan at merge time so no PR carries the mutation. Exactly the `derive` + drift-gate pattern shipped in `build-graph.ts` (#10395).

They compose: A removes the conflict, B keeps the single-file index for readers without any writer mutating it — the same hub/satellite split DV2.0 prescribes.
