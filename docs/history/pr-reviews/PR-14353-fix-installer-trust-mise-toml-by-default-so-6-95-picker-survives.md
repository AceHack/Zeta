## Description

# Summary

QEMU picker bind (run 32647553460) captured the passphrase then died on `mise activate`: "Config files in ~/Zeta/.mise.toml are not trusted." Wifi / iSerial / keyfile `sudo -u` lines already pass `MISE_TRUSTED_CONFIG_PATHS` (PR #10226); 6.95-picker is a separate sudo and did not inherit `install.sh`'s export. A HOME-local `mise trust` store also does not survive `/mnt/home/zeta` → post-reboot `$HOME`.

This PR makes `.mise.toml` trusted by default on our setup (picker sudo + shellenv + NixOS login profile + first-session), and runs restore QEMU immediately after scenario 2 so ISO + wifi/write/picker cannot starve it.

# Spec alignment

Installer / USB-zflash QEMU path. No OpenSpec behaviour change; the picker already runs, it just failed `mise activate` on an untrusted config.
