## Description

GitHub Pages serves `main` at `/` with no build step, so `docs/design/root-site-iris/*.dc.html` are being served **right now** — and every one of their asset references was **404**.

Found while verifying the 949-file `.js` sweep (#9912) hadn't broken Pages. **It hadn't** — 0 broken by the sweep, and all 48 refs were *already* dangling. Pre-existing, invisible, on a public surface.

## Cause

The Claude-Design handoff has two directories: `sources/` (the `.dc.html` exports) and `site/` (the built page **plus its assets**). Only `sources/` was pulled into the repo. The `.dc.html` files reference three siblings that live in `site/`:

```
./support.js
_ds/design-system-f52fe130-.../\_ds_bundle.js
_ds/design-system-f52fe130-.../styles.css
```

Two zips were supplied; **z2 is a strict superset of z1** (97 vs 92 files) with byte-identical shared assets, so z2 is the source. The repo's existing `.dc.html` are **byte-identical** to the zip's `sources/`, confirming the pairing.

## Verified

Every local `.js`/`.css` reference in `docs/design/root-site-iris/` now resolves on disk: **36 resolving, 0 missing.** (36 not 48 — the earlier count included duplicate `src`/`href` pairs.)

## Deliberately not restored

The zip's built pages (`concepts.html`, `dora.html`, `gitpull.html`, `mesh.html`, `portal.html`) and `edge/zeta-mesh.js`. Those are a **different surface** from the `.dc.html` sources the repo serves today — adding them is a decision about which surface is canonical, not a bug fix. Left for Iris/Aaron.

## Guardrail gap

**Nothing verifies that a served page's assets exist.** Same class as everything else found today: fails silently, on a public surface, and only surfaced because someone went looking for an unrelated reason. A link-existence check over served HTML would be cheap and isn't in the gate.
