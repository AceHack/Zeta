## The measurement that makes this a class

`poll-pr-gate-batch.test.ts` holds 14 tests that are pure in-memory — injected fakes,
`Promise.resolve`, no I/O — and they ran in **1366ms idle** and **5.46s under load on the same
machine class**. A 4x spread on identical code is the finding. Six open PRs were red at exactly
the 5000ms per-test cap, and every one of those reds was false.

In this repo's own vocabulary a real timer in a test is an **undeclared ambient time channel** —
`dv2-data-split-discipline-activated.md` #4 (DST) and #7 (noninterference), and the test-suite
form of `local-time-never-enters-the-shared-fold.md`. That rule lets local wall-clock steer local
behaviour and forbids it from deciding a shared verdict. **A test verdict is a shared verdict.**

**Scope:** `poll-pr-gate-batch.test.ts` is **not touched here** — a separate lane owns it. This is
the rest of the class plus the enforcement.

## Honest negative: the F# suite is essentially clean

Stated because a padded sweep is worth less than an accurate one. F# `Thread.Sleep` is
overwhelmingly filesystem-retry backoff against a real OS lock (`ZetaShell`,
`DeterministicTestPath`), starting-gun jitter before a `TaskCompletionSource` release
(`Concurrency.Tests`, `ConcurrencyHarness` — it cannot flip a verdict, only reduce how much of the
race gets exercised), or `Stopwatch` perf instrumentation. `RxAdapter.Tests.fs` carries two 150ms
sleeps and **both tests are `Skip`-annotated and inert**. Exactly one genuine case, fixed.

Likewise the `setInterval: (ms, fn) => ...` sites across `discovery/*` are **injected fake
schedulers** — the model answer, not the defect — and were left alone.

## The three primitives that replaced the sleeps

`src/Core.TypeScript/testing/deterministic-async.ts`:

- **`deferred()`** — a barrier. The code under test *signals*; the test *awaits*. Zero timers.
  This is what "give the ferry time to pick up work" always meant: the ferry says so.
- **`yieldTurns(n)`** — n macrotask turns, each a **zero-delay** timer. A turn is a turn on an idle
  laptop and on a contended runner. **Measured:** every `settle()` site in `udp-lossy-transport`
  needs *one* turn; the code uses eight, so headroom is 8x in a unit that does not shrink.
- **`waitUntil(predicate)`** — poll with a deadline, for genuine external I/O only. The deadline
  is an **upper bound on patience**, not a synchronization step. A loaded machine waits longer and
  still passes, where a sleep makes a loaded machine fail.

## One production change, and it makes a test stronger

`scheduleGossipRebroadcast` took its timer and jitter from ambient globals, so ULT-14 could only
sleep 50ms and assert "it fired". `GossipJitterSources` is now injectable (defaulted; there are no
production callers at all). The test now asserts the delay lands in `[10, 30)` at both ends —
which the test's **own name claimed and it never checked**. A bug firing at 30 seconds would have
been caught before; a bug firing at 1ms would not.

## Assertions that got STRONGER

- `priority-ferry-throttler` dispose asserted `expect(processCount).toBeGreaterThanOrEqual(0)`.
  A count is a non-negative integer — that held for *every possible execution*, including one
  where the ferry never ran. Its own adjacent comment said "processCount can be >= 1" while the
  code checked >= 0. The barrier is what makes `>= 1` safe to assert. **Now `>= 1`.**
- `ferry-throttler` "bounded queue applies backpressure" asserted only that 30 items came out —
  which an **unbounded** queue satisfies just as well. The word "backpressure" in its name was
  doing work the assertions were not. Now counts enqueues that actually blocked.
- ULT-14 above; ULT-14b added (cancel-before-fire, with an anti-vacuity check that the callback
  was real and would have fired uncancelled).

## The one assertion that got WEAKER — named, not buried

`shadow-observer`'s restart test was "log shows >=2 started events **within 1200ms**" and the
1200ms was part of the assertion. It is now "the log accumulates >=2 started events", polled. The
property — the outer loop restarts — is unchanged; the wall-clock bound on how fast is gone. That
bound was never worth defending: a restart loop taking three seconds under load is not a defect,
and the test called it one. (That file executes in no CI lane today, so nothing regressed either

## My own vacuity, recorded rather than quietly replaced

The **first** anti-vacuity assertion written for the backpressure test raced the enqueue against
`Promise.resolve()` and **survived its mutation** — raising `maxQueueSize` 2 → 10000 left it green
— because an `async` enqueue always costs a microtask whether or not the queue is full. A check
that cannot fail is not a check, and it looked exactly like one that could. The replacement
measures in **turns** and does go red under that mutation; the comment in the file keeps the
history.

## The enforcement, and why NOT Semgrep

`hygiene/audit-ambient-time-in-tests.ts` walks each call's argument list with a depth counter (a
regex cannot balance parens, so it cannot tell `setTimeout(r, 0)` from `setTimeout(() => f(x, 1), 50)`).

- **Banned** — a non-zero delay. It encodes a guess about machine speed.
- **Allowed** — `setTimeout(fn, 0)`, a *yield*: one event-loop turn on a fast machine and one on a
  loaded one. Deterministic in turns. A yield is a different construct from a delay.
- **Allowed** — injected fake schedulers. Property syntax is not a call and is never matched.

Semgrep and ESLint can both match this pattern. Both were rejected for a reason that is **not
about expressiveness**: their suppression mechanism is an **inline comment**. `// nosemgrep` and
`// eslint-disable-next-line` are invisible in any roster, addable by the same edit that
introduces the violation, and reviewable only by whoever happens to read that line. For a check
whose entire purpose is that an allowlist cannot silently swallow a new violation, **the tool that
offers inline suppression defeats the check.** Semgrep's full detector set is also non-blocking
drift here, which would have made it a false green on top. TLA+/Z3 are the wrong axis outright:
the property is lexical over source text, with no transition system and no arithmetic.

So the roster is `registry/wall-clock-test-allowlist.json`, pinning **exact per-file occurrence
counts** — the mechanism `tests/Tests.FSharp/DeterminismLint.Tests.fs` already uses for `src/Core`,
adopted for the reason that file states: an allowlist saying only "this file may use timers" lets
a seventh sleep slide in behind six justified ones and reports green.

**The ratchet bites both ways.** Higher than pinned = a new violation hiding behind a justified
one. Lower = a stale row that has stopped constraining anything, which is an exemption nobody has
to argue for waiting to be reused. A row whose file vanished fails. A reason under 40 characters is
refused at load. A missing registry refuses to pass rather than defaulting to empty. And "scanned
0 files" cannot read as success — the audit exits 1 below a 100-file floor.

Four rows, and one is deliberately **not** a justification: the `poll-pr-gate-batch.test.ts` row is
a **handoff**, worded as such. Whoever lands that lane's fix will see *"stale row, no longer
constraining anything"* and must delete it. That red is the intended signal, not a defect.

`audit-ambient-time-in-tests.test.ts` pin each claim separately, including both ratchet directions,
the "second violation behind a justified one" case a path-only allowlist reports as green, and the
negative controls (zero-delay yields, injected schedulers, a regex that merely mentions the
identifier, `mySetTimeout(`). Comments are scanned **on purpose** — a commented-out wall clock is a
wall clock waiting to return — which is why prose in these files says "a `setTimeout` of 50ms" and
never spells the call.
