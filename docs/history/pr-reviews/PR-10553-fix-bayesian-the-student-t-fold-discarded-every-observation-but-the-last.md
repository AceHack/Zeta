## Description

`inferStudentT` reflected only its final element. Measured before the fix:
`[0.5, 3.0]` and `[3.0]` produced **bit-identical** posteriors, and so did 100
copies of `0.5` against one. Only `obsCount` moved. A fold that silently
discards the evidence it was given is not merely lossy, it is *confidently*
lossy — it publishes a precision the data it ignored never justified.

STB-14 was the pin left for this in #10524, and **it failing was the intended
signal**. It has been rewritten from the claim it was holding open into the
falsifier for the repair.

## Structural, not a missing loop

`StudentTState` carries **one** site message, and `updateStudentT` divided it
out of the posterior to form the cavity on every update. With a single slot
that division undoes the previous observation exactly. This is B1's story one
module over: the cell maintained an invariant that made the cavity step an
identity **by construction**, so no loop was missing and adding one would have
fixed nothing.

The repair is to **stop dividing**. Under assumed-density filtering a fresh
observation's own site message is uniform, so the cavity for it *is* the
current posterior. Full EP would revisit sites, which needs one message per
observation and is not available to a streaming fold; the module now does the
single pass and says so — including that the answer is therefore
order-dependent (STB-20).

## Two further defects found in the same read

- **factor/posterior conflation** — step 4 computed the moment-matched
  *posterior* mean and stored it as the *factor* mean; step 5 then combined the
  cavity with that "factor" again, counting the observation twice.
- **the closed form was not the Student-t projection** — graded against exact
  tilted moments it missed its own claimed Gaussian limit. Prior `N(0,1)`,
  `sigma2_obs = 0.1`, `y = 1`, `nu = 1e12`: exact posterior `N(0.909091,
  0.090909)`, shipped formula returned `N(0.474138, 0.478448)`. STB-16 is that
  falsifier.

Fixing accumulation while leaving the step wrong would have built a fold that
confidently accumulates a *wrong* likelihood, so both are repaired together.

## Why quadrature, measured before it was written

| candidate | verdict |
|---|---|
| log-partition-derivative form under `Z ~ St(y; m, v+sigma2, nu)` | returns **negative** variances for outliers (`-0.0094` at `nu=10, v=1, sigma2=0.01, y=0.5`) — that is what the old `Math.max(1e-10, ...)` was catching |
| IRLS/EM scale-mixture step (the shape `HeavyTailFold` uses) | exact in the Gaussian limit, always positive, but **one step lands between the lobes**: `7.97` where the exact tilted mean is `0.42` — 7.4 posterior sd out, at a location carrying no mass |

Both fail exactly in the heavy-tail-plus-outlier regime the module exists to
serve, so the moments are **computed**: panelled Gauss-Legendre in log space,
with panels around the cavity, the observation, their Gaussian combination,
and every real stationary point of the tilt. Those stationary points are the
roots of a **cubic** and are taken in closed form — the tilt's mode is in
general at none of the obvious candidates (for `m=0, v=0.01, y=25,
sigma2=0.001, nu=5000` the mode is `2.17` while the candidates sit at `0`, `25`
and `22.7`).

Graded over **1232 cells** (`nu` 1..5000, prior variance 0.01..10,
`sigma2_obs` 0.001..1, `y` 0..25) against an independent 400k-point reference:
worst mean error **2.0e-9** posterior standard deviations, worst relative
variance error **1.9e-8**, **zero** cells where the projection declined.

## The variance clamp fires LESS, not more

The stated risk was that accumulating more evidence would trip the clamp more
often and trade one fabrication for a worse one. Measured on one 7392-update
grid:

| | clamp fired |
|---|---|
| old closed form | **294** (3.98% of updates) |
| projected moments | **0** |

A variance computed from a positive measure cannot be negative, so the failure
mode was **removed rather than relocated** (STB-19). The floor remains as a
numerical guard and is now **reported by the producer** (`varianceOnFloor`)
instead of sniffed by the consumer comparing a value against a constant.

## What STB-14 became

The old STB-14 asserted that `tail-dependent` was structurally unreachable and
read that as a property of the model. **It was a property of the bug.** With
the projection corrected a single observation is already enough — whether you
believe a lone outlier is exactly what the tail index decides. Over the same
80-cell grid the pin swept, **43 cells now come back tail-dependent and 37
tail-independent**. STB-18 asserts both, because a check that can only ever
return one verdict is not a check.

## `nu` discipline carried forward

No bare `nu` is reintroduced: it stays first, required and validated, and
`tailSensitivity` still refuses a point interval. `createStudentTState` now
also rejects a non-positive prior variance or `obsVariance`.

**Not touched, and not silently normalised:** `createDimensionalBnn(nu = 3)` in
`error-bnn-bridge.ts` is the same defect class with a different unmeasured
value in the same call chain. This change does not reach it (it is a public
constructor default, also used by `deserializeBnn()` with no args), and
quietly aligning it to `4.0` would replace one unmeasured constant with
another. Reported, not fixed here.

## Falsifiers — five mutations of the repair, each killed

| mutation | killed by |
|---|---|
| fold discards all but the last observation | STB-7, STB-14, STB-18, STB-20 |
| wrong exponent in the t factor | STB-17 |
| drop the cubic stationary-point panels | STB-17b |
| drop the ESS peak normalisation | STB-21 |
| never report `varianceOnFloor` | STB-13 |

The first pass of this suite let the cubic-panel mutation survive; STB-17b was
added specifically to close that hole, and the mutation is now caught.

## Byte-lock

None touched. `bnn-persistence` serialises `mu`, `sigma2`, `nu`, `obsCount`
and the last robustness weight — never the site message. The
`docs/observe-events/*.json` are append-only history, not golden vectors, and
no test compares against a locked posterior. 423 tests across `planning`,
`bayesian`, `protocol` and `oracle` pass; `tsc` clean on the touched files.
