## Description

## The defect

`src/Core.TypeScript/backlog/rebuild-legacy-b-id-aliases.ts` decided whether to write by
asking whether one exact string was present:

```ts
const DRY_RUN = process.argv.includes("--dry-run");
```

So **everything that is not that string means "go."** PR #10832's agent probed the tool
with `--help`, which it does not have, and a ~1,700-file rewrite of the repository began.
They killed it before any file changed and reported it against themselves:

> *"A rewriting tool that treats an unknown flag as 'go' deserves a row."*

Authorized by Aaron 2026-08-15: *"lets fix it."*

***

## The fix — two properties, and the second is the load-bearing one

**1. Fail closed on unknown arguments.** An unrecognised flag prints `unknown arg: …` and
exits **2**. Parsed at module scope, above every `writeFileSync` in the file, so the exit
cannot be reached after a partial rewrite.

**2. Destructive mode is NAMED, not inferred from absence.** Writing requires `--write`.
Property 1 alone still leaves a tool that rewrites the repo when you **forget** a flag — the
guard would catch a typo and wave through an omission, which is the more common error.

`--dry-run` stays accepted as an explicit no-op. That is deliberate: every previously-safe
invocation keeps working unchanged, and every previously-*writing* invocation (the bare one)
becomes safe rather than silently changing meaning. `--write --dry-run` together exits 2
instead of picking one.

***

## Mutation proof — raw exit codes, no pipes, filesystem asserted

The tool is **never** run in write mode against this repository. Both runs below are against
a throwaway `mktemp -d` fixture containing one row that names a mapped legacy id.

**Mutant — the guard reverted to `argv.includes("--dry-run")`:**

```text
$ bun rebuild-legacy-b-id-aliases.mutant.ts --help-me-rhonda
EXIT=0
Alias map: 1 entries (1 unique B-ids seen in repo)
Changed: 1 files
--- row content after the run:
Supersedes 081KSE6WT0008QG0R002YBWBB1 from the closed series.   <-- REWRITTEN
```

**Guarded — same bogus flag:**

```text
$ bun rebuild-legacy-b-id-aliases.ts --help-me-rhonda
EXIT=2
unknown arg: --help-me-rhonda
--- mtime/size before: 1786825626 51   after: 1786825626 51
--- git status in fixture: (empty)
```

**Bare invocation, the load-bearing case:**

```text
$ bun rebuild-legacy-b-id-aliases.ts
EXIT=0
[DRY RUN] Would change: 1 files (nothing written — pass --write to apply)
--- git status in fixture: (empty)
```

**`--write`, fixture only — the check that the guard is not vacuous:**

```text
EXIT=0
 M docs/backlog/P2/sample-row.md
```

## The tests assert on the filesystem, not the exit code

`rebuild-legacy-b-id-aliases.args.test.ts` (6 tests). Every case snapshots the fixture tree —
**content and `mtimeMs` of every file** — before and after, and asserts on the tree. A test
that only checked the exit code would pass against a tool that rewrote everything and *then*
complained, which is exactly the failure this guard exists to stop. Including mtime means a
rewrite-to-identical-bytes still fails the test.

| test | pins |
|---|---|
| unrecognised flag | non-zero exit **and** tree unchanged |
| `--help` | exit 0, tree unchanged |
| **bare invocation** | exit 0, tree unchanged — destructive mode is not the default |
| `--dry-run` | still accepted, tree unchanged |
| `--write --dry-run` | non-zero, tree unchanged |
| **`--write`** | the row **is** rewritten |

The last row is required. Without it the whole suite could be satisfied by a tool that never
writes at all — the vacuity class this repo has hit four times in a fortnight, and the same
error PR #10832 caught in its own harness.

## Siblings — eight more, none fixed here

Scanned `src/Core.TypeScript/**` for the shape: a module-scope `… = argv.includes("--dry-run")`
guarding a destructive action. Filed as **`081M03HRHBS087G0R001HRAFQ0`** rather than swept.

| tool | what a stray flag buys |
|---|---|
| `hygiene/healers/run-tier0.ts` | rewrites markdown across the repo |
| `hygiene/mutation-runner.ts` | writes a mutant into a source file; a crash before the restore leaves it in tree |
| `migrations/b0266-review-policy-ruleset.ts` | creates/updates GitHub rulesets live |
| `migrations/b0267-safety-ruleset.ts` | same, and can **DELETE** the Default ruleset |
| `migrations/b0267-branch-safety-ruleset.ts` | same class |
| `ops/setup-dual-background-agents.ts` | writes launchd plists, calls `launchctl` |
| `zflash/flash-usb-windows.ts` | **flashes a USB device** |
| `observe/backfill-tick-shards.ts` | backfills tick shards (write path is delegated — confirm before fixing) |

**Why a row and not a sweep.** `run-tier0` and `mutation-runner` are invoked **bare, on
purpose**, by `agent-heartbeat.yml` (lines 124 and 257) — writing is what a healer and a mutator
are *for*, so property 2 does not apply to them and flipping their default would break the
heartbeat. The three ruleset migrations mutate live branch protection; `zflash` writes a block
device. Each needs its own read of what a bare invocation does for real callers. A single
sweeping change would be the un-metered blast radius the class is about.

Checked and **excluded**: `forge-host/github/create-branch-safety-ruleset.ts` — absence of
`--dry-run` reaches `ERROR: live mode not implemented` and exits non-zero. Safe, though by an
unimplemented feature rather than by a guard.

**The fix also enrols the tool in a check that already exists.**
`hygiene/audit-workflow-cli-flags.ts` (from `081M005VXY6087G0R001T04ATY`) statically refuses a
workflow that passes a flag a tool rejects — but **only for tools whose parser demonstrably
rejects unknown flags**, detected by an `unknown arg` diagnostic in the source. Every tool in
the table above is currently *skipped* by that audit: the absence of a guard also buys exemption
from the lint that would police it. Post-fix the audit reports 22 closed-flag-set tools, 60
skipped, 0 violations.
