## Description

Closes `081KZYP1X3B087G0R001EZ37PQ`. Promoted to the critical path by #10516, which measured
corruption at **0.0% attributable** and made `CorruptionEvidence` unconstructible until an
integrity check existed. This is that check.

## The defect

The transport had no checksum or MAC anywhere, and the consequence was not merely that corruption
went unnoticed — **erasure recovery amplified it.** Erase data packet 0, flip one bit in parity
packet 5 (a packet the application never sees and would not have missed) and `recoverAdinkraBlock`
returned non-null **wrong bytes** in a data packet, silently. A `[8,4,4]` code corrects 3 erasures
and 0 errors; this decoder is a pure erasure decoder, so feeding it a corrupt symbol moves
corruption out of redundancy nobody reads and into payload everybody does.

Every frame now carries a **CRC-32C trailer**; a frame that fails it is discarded before block
assembly, so **corruption degrades to erasure** — the fault class the code handles.

**The decoder is unchanged.** The check is a per-frame membrane in front of it, never inspects a
block, and therefore cannot refuse a block #10496 taught the decoder to solve. A refused frame is
one more erasure, and the Gauss–Jordan solve still runs from the 4th arrival.

## Checksum, not a MAC — and the label is the load-bearing part

A CRC detects accidental corruption and nothing an adversary does; the polynomial is public and a
forger recomputes it. A MAC needs a shared secret, and this is a **broadcast** transport with no
session, no key agreement and no group key (`myZid` is a self-asserted string for echo
suppression). `beacon-auth.ts` is Ed25519 *signatures* over an injected trust store — right for the
low-rate discovery vocabulary, wrong for every packet of an 8-packet ECC block on a LoRa-class
link. Authentication also belongs on the **control** channel, where the real lever is (#10516: a
peer can fabricate NACKs), and a per-packet data-path CRC does not move that lever an inch.

**Security, exactly.** A peer can now claim `corruption` to suppress backoff, as it can already
claim `reorder`. Same hole, not a new one — a receiver that wants to suppress a sender's backoff
can simply **stay silent** and emit no NACK, which is cheaper and strictly more effective than any
claim. The one lever this does open is bounded by `min(pendingCorruptFrames, gapSize)`: a rejection
can **re-label** a loss the receiver independently observed, never manufacture one.

## Wire format: one-way compatible, failing direction is loud

| direction | result |
|---|---|
| new sender → **old** receiver | **works** — the old decoder sliced `[16, 16+len)` and tolerated trailing bytes, so the trailer is ignored |
| **old** sender → new receiver | **rejected as `truncated`** — a *framing* error, explicitly not corruption |

There is **no fully backward-compatible option** — the format carries no version field. What was
available was *which* direction fails and *how*. A version skew reported as channel corruption
would suppress a peer's backoff for a whole rollout, so framing and corruption are kept apart in
the decode result. The trailer *position* buys the working direction: a checksum in the header's
spare padding, or a grown 20-byte header, would make an old receiver **mis-slice the payload and
deliver silently-wrong bytes** — trading a loud failure for exactly the silent one this work-item
removes. `UCH-20` pins both directions.

| 10.0% | 1593 | 1593 | 278 | **0** | 0.9653 | 0.9970 |

Silent corruptions go to zero. And **delivery goes up, not down**: rejecting a frame costs nothing
and buys a repair, because the code corrects erasures and cannot correct errors. The intuition that
an integrity check trades goodput for safety is wrong for an erasure-coded transport. Detection is
an identity, not a probability — every CRC has minimum distance ≥ 2, so no single-bit error is
undetectable. (`UCH-19`, `UCH-21`.)

## Corruption curve — BDP harness, over the axis that decides whether it can separate

|---|---|---|---|---|---|
| 0.5% | 828.6 | ×1.2 | 993.2 | **×1.0** | 48 |
| 1.0% | 605.7 | ×1.6 | 988.8 | **×1.0** | 92 |
| 2.0% | 138.7 | ×7.1 | 979.0 | **×1.0** | 190 |
| 5.0% | 23.4 | ×40.5 | 949.5 | **×1.0** | 485 |
| 10.0% | 9.6 | **×93.6** | 903.4 | **×1.0** | 945 |

`deliveredCorruptFraction` (DCF) is a new `LinkParams` knob and the honest second axis: an
application-layer check attributes exactly the corruption that **survives to the application**.

- **DCF = 1** (no lower-layer frame check, or one that missed) — the AIMD arm becomes *numerically
  identical* to the signal-blind open-loop arm at every rate. 93.6× → 1.0×, and `gapMs` never
  leaves its floor.
- **DCF = 0** (an 802.11 FCS / LoRa CRC / UDP checksum already destroyed the frame) — the curve is
  **unchanged, to the digit**. Nothing arrives, so nothing is checked, and the loss stays
  indistinguishable from a queue drop.

So the honest claim is **not** "the 90× is recovered". It is "the 90× is recovered exactly in
proportion to how much corruption reaches the receiver", and that proportion is a property of the
**link**, not of any control law. DCF defaults to 0, so every previously measured number is
preserved rather than re-baselined — `UBL-10` passes unchanged. (`UBL-13`.)

## `CorruptionEvidence` is constructible; `CongestionEvidence` is not

`mintCorruptionEvidence` is the only constructor, its only caller is the CRC comparison in
`decodePacket`, and neither is exported. **`ULT-31` flipped — as designed**, it was built to fail at
this moment — and now pins the *asymmetry* rather than relaxing: corruption brand is a real runtime
symbol with exactly 2 textual occurrences (declaration + single call site); congestion brand is
still a `declare const` with exactly 2 (declaration + interface member). There is still no
timestamp, no ECN bit and no queue estimate, so promoting both would be the pretending taxonomy
arriving by the back door.

A **wire-borne** corruption report mints nothing: the sender never held the bytes, so it never ran a
check. `retractLoss(state, seqs, "corruption")` handles it as a re-attribution — the reporter
withdrawing its own earlier congestion-suspect claim, decision recomputed not inverted — the same
shape as the reorder retraction, needing no evidence value at all.

## Mutation testing found a weak assertion

7 targeted mutations of the fix. 6 caught immediately. The 7th — **removing the bound on the only
adversarial lever this change opens** (`min(pending, missing.length)` → the bare count) — left all
**75 tests green**.

The reason is a property of the instruments, not the assertions: the clamp only bites when more
frames were rejected than the next gap is wide, and neither sweep can produce that. The chaos
harness does not drive the class, and the BDP sweep runs `meanBurstLength = 1`, whose
Gilbert–Elliott chain **forbids consecutive corruptions**
(`081KZYY6SVJ087G0R0035SW945`, filed, unfixed). The one configuration that exercises the bound is
the one the instrument cannot generate. `ULT-34` constructs it directly; all 7 mutations are now
caught. Note the NACK *contents* are identical either way — the divergence is in the **residue**,
where the unclamped counter goes negative and silently swallows a later genuine attribution.

**Instrument caveat carried, not fixed:** `meanBurstLength = 1` makes every BDP row above
optimistic in the code's favour. The chaos rows are **not** affected — genuine per-packet Bernoulli.

## Also here

- **`crc32c.ts` is now table-driven** (Sarwate 1988), with the bitwise polynomial division retained
  as `crc32cBitwise` — the *definition* the table is checked against. A wrong entry in 256 constants
  is a silently wrong checksum on a narrow slice of inputs the golden vectors are far too few to
  land on, so the new test pins the two against each other over all 256 single-byte inputs and 16
  lengths, not just against the 4-oracle seed. This is **reuse, not a second checksum**: the
  transport joins the existing byte-locked lineage rather than minting a rival free to drift from
  it.
- **The chaos harness gains a fourth fault class.** Erasure, duplication and reordering all preserve
  bytes, so every number it ever produced described a channel that never lied. Corruption draws on
  disjoint streams, applies to **survivors only** (a destroyed frame is an erasure), and is injected
  into the **encoded frame** so a corrupted `blockPos` or length is reachable — the two corruptions
  with the largest blast radius. `verifyChecksum: false` reconstructs the pre-change receiver as a
  negative control, because a suite that only runs the checked path cannot tell a working check from
  one that never fires.
- **Not touched, deliberately:** `gapMs` is not wired and the AIMD estimator window is unchanged
  (`081KZYN37T4087G0R00181THA4` stays LATENT). Ordering held: signals (#10516) → **integrity
  (here)** → estimator → pacing.
