## The named gap: (a) a missing edge, decisively

**First, a correction to the framing — these are not two factor-graph representations.** `CategoricalFactorTensor` is a **materialized** map; `FactorGenerator = (stateKey: string) => number` is a **lazy** access path wrapped in a WeakRef cache, a deterministic GC, and a Futamura specializer. Same domain, same codomain, and shiva's own comment says *"VMP factors are log-likelihood functions — exactly what FactorGenerator returns."* **Neither does the other's job, so "retire one" was never a live option.**

Second, shiva's stated purpose is *"eliminating factor graph lookup overhead during high-speed planning"* — and the planner does a raw `logProbabilities.get(nextKey)` **inside its BFS loop**. The producer names the consumer's exact hot operation.

Third, `git log -S` over all refs: the edge has **never existed** — no commit ever connected them. Born the same day (2026-08-01) in two different commits, edited together once without anyone joining them. **Parallel construction, not a removal.**

**Not overstated as "one line":** materialize → lazy is total, lazy → materialize is **not** (a generator has no enumerable domain), and **three different missing-key defaults already live in this directory** — `0.0` (combine), `-0.1` (coarse), `-0.05` (fine). Reconciling those is the real work the edge implies, which is why the recommendation is *file it*, not *write it now*.
