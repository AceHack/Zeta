## Description

I put a regression on `main` with #11002 (`39b68da9b`) and this fixes it, plus the two lessons that produced it.

## The failure: an invented namespace

The AgencySignature block was **structurally perfect** — contiguous, blank-line separated, ten lines, `Co-authored-by` last — and every key was fabricated (`Zeta-Agent`, `Zeta-Hat`, `Zeta-Blast-Radius`, …). It reads as correct to a human reviewer and parses to nothing.

That is a *distinct* failure from the `Agent-`/`Agency-` near-miss the template already warns about. A near-miss is one wrong character in a real key. This was a whole namespace that does not exist — the vacuity shape applied to attribution: a signature satisfying every structural rule while carrying no recognized field.

## Second lesson: fixing the body is not sufficient

The #11002 body was corrected **and validated** before merge. The squash commit still landed with the fabricated keys, because the message came from the commits. So `validate-agencysignature-pr-body.ts` passed while `audit-agencysignature-main-tip.ts` failed on the result — **the two checks can disagree, and the auditor is the one that decides.**

## Why the word is load-bearing

Aaron, 2026-08-16: *"an agent without agency is just an actor."*

An `Agent-Signature` would attest the executor; an `Agency-Signature` attests the thing that carries responsibility — the same source-vs-authorization split as `no-directives.md` and the persona(owner)/actor(clone) distinction in `writer-actor-routing-model.md`. Recorded because a key you can **derive from a principle** resists exactly the reconstruct-from-memory error that caused this.

This commit also re-attaches correct trailers per the auditor's prescribed remedy, since `main` history cannot be rewritten.
