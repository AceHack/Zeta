## Description

`main` fails `storage-profiles.test.ts` right now:

    the dev lane applies 33 of the 45 Applications
    Expected length: 33
    Received length: 36

Nothing is wrong with the code. `deepseek-coder`, `qwen-coder` and `orleans`
left `DEFAULT_ROOT_DEV_CATALOG.excludeGlob` (081M0JXXFV0087G0R001PGEEM4) on
measured evidence, so 12 excluded directories became 9 and 45 - 9 = 36. The test
above that assertion already says "this number moves only when that constant
does". The constant moved; the literal did not.

Measured, not assumed -- the discriminator is a checkout, not an argument:

    origin/main, clean detached worktree   ->  exit 1, 91 pass / 1 fail
    this branch                            ->  exit 0, 92 pass / 0 fail

WHY THE TWO RESOURCE-TOTAL TESTS BESIDE IT DID NOT ALSO GO RED, which is the
part worth writing down: all three departing Applications render ZERO cpu and
ZERO memory -- two are Namespace + ConfigMap, `orleans` is a StatefulSet at
`replicas: 0` -- so the lane's cpuMillis/memoryMib are arithmetically unchanged
at 36 apps. That is a coincidence of this particular glob change, not a property,
and the comment now says so.

Mutation-checked, with the mutation verified applied before its result was read:
dropping `platform/**` from the glob (9 -> 8 entries) turns the count red at
37-vs-36 AND turns both resource totals red -- which is the positive control for
the paragraph above: a departing app that DOES carry resources moves all three.
Restored, baseline green.

bun test src/Core.TypeScript/cluster/ -> 367 pass / 0 fail. tsc -> exit 0.
prettier --check -> exit 0.

Filed separately from #13329 (the Cilium kind lane) on purpose: main being red
blocks every open PR, so the unblock should not wait on an unrelated review.
