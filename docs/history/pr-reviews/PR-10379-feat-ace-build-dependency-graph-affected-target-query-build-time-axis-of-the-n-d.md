## What the graph reveals

- **35 of 36 Rust crates have no CI leg at all.** `gate.yml:1583` runs `cargo test` on `Core.Rust.Observe` only. Encoded as `legs: []` rather than pretending coverage exists — **the gap is now countable in one place.**
- **10 .NET projects are not in `Zeta.sln`**, so `dotnet build Zeta.sln` never sees them.
- .NET builds as one solution unit today, so per-project edges don't buy CI time *yet* — they're what a finer build would carve on.

## Selective builds — built to the repo's existing stance, not around it

`gate.yml`'s `path-filter` job already encodes the right answer: heavy **steps** are gated, the **job still runs** so the required check name still reports, and non-PR events fast-path to `code=true` because *"path-filter is never the mechanism that hides a code change from main-tip CI."*

Safety design:

1. **Unknown escalates.** A path matching no target and no *declared-inert* glob is `unknown`, and unknown forces `mode: "full"`. Inert is an explicit allow-list ported from gate.yml's own docs-only classifier — nothing is ignorable by default. Same stance as `Wall.Whitebox`: **forgetting to map a new tree makes CI slower, never quieter.**
2. **Coverage is declared, not implied.** `verifyCoverage` proves `affected ∪ skipped == every target`, exactly once each. A run publishes which legs ran, which were skipped, and why — so **a green always carries its coverage.** This is the direct guard against the defect class that has bitten us repeatedly today.
3. **Sometimes-full, three ways**: event escalation (anything not a `pull_request` → full); `always` globs (workflows, `Directory.Build.props`, `global.json`, `Zeta.sln`, `.mise.toml`, `tools/setup/**`, lockfiles, and the graph files themselves); and an optional 1-in-N sampler, **off by default**, `BigInt` modulo over the head sha — no RNG, no clock, no floats, so *"why did this PR run full?"* has an exact answer and DST replay is untouched. Noted honestly: the repo's ten existing "sometimes full" mechanisms are all deterministic schedule/event based, so sampling would be the first of its kind — hence off.

## The decision NOT taken — it is Aaron's

`gate (required)` is the **sole** live required check, and its rollup treats **skipped as success**. So selective building at *job* level would turn a skipped leg into a green — the exact failure mode this design exists to prevent. Two options:

- **(a)** keep gating at **step** level inside always-running jobs, as `build-and-test` does today — safe, no rollup change.
- **(b)** gate at job level and teach `gate-required` to consult the coverage declaration, so an *unexplained* skip fails.

**Neither was wired.** (a) is safe now; (b) is better but changes the required check's semantics.

## Does it belong in ace? Yes — but not in `deps.ts`

Anchored in prior work: `docs/research/2026-06-07-full-dep-graph-is-one-constructable-zeta-file-…` already says the full `dependson` graph is one constructable `.zeta`/`.ace` file, **defined not calculated**, with installs as reachability carves — and cites **Bazel** explicitly. `081KSGS9H0008QG0R0031PBNGA` (N-dimensional dependency space) is the frame holding both.

But **`deps.ts` does not generalise**: `DependencyNode.chart`, `generateFlux`, `generateArgoCD`, sync-waves — it is a Helm/Flux **deploy** graph with topo-sort welded into `resolveGraph` around charts. So: sibling module in `ace/`, same edge model, separate file.

**One correction to the framing:** the "n-dimension system" in `ace-cli.ts` is `DimensionalBnn`, a Bayesian *error-dimension* classifier — not a graph dimension. The N-D dependency space lives in the backlog item, not in that code.
