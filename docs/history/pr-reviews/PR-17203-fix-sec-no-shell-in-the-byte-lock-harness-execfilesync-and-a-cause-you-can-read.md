## Description

Alert 288, js/shell-command-injection-from-environment (medium), at
tests/cross-verification/_harness/cross-verify-ir.ts:276:

  const venvPython = join(process.cwd(), "src/Core.Python/.venv/bin/python3");
  const stdout = execSync(`${venvPython} ${file}`, { ... });

CodeQL flagged one line; the construct appears NINE times -- every oracle lane
builds a shell command string. 276 is the only one it can prove is
environment-derived, because tmpDir is a hardcoded /tmp join while venvPython
comes from process.cwd(). The alert is precise and its scope is narrower than
the defect, so all nine are converted: with no shell anywhere in the file, no
later edit can reintroduce this by interpolating a new variable.

DEMONSTRATED, both halves. Same interpreter, same script, only the containing
directory differs.

  a space in the path -- the realistic instance:
    OLD (execSync, shell)         FAILED: python3 cannot open .../cv-XXXX/my
    NEW (execFileSync, no shell)  "42"

  a semicolon -- the injection CodeQL names (payload: a marker file, nothing else):
    dir = "x; touch INJECTED; echo"
    OLD (execSync, shell)         marker created: true
    NEW (execFileSync, no shell)  marker created: false

REACHABILITY, HONESTLY. In CI the cwd is /home/runner/work/Zeta/Zeta -- no space,
no metacharacter -- so this is not a live exploit path today. The realistic
failure is the space: a clone under a path containing one silently loses the Q#
lane. The injection is a property of the construct, not an attack anyone can
currently mount here.

WHICH MAKES THE DIAGNOSIS THE INTERESTING HALF. Every lane reports its failure
as "<toolchain> not available", and expectEveryLaneExecuted quotes that string
as the CAUSE an oracle did not run:

  oracle lane "qsharp" executed 0 cases -- the byte-lock claims 7 independent
  implementations agree, and this one did not run. Cause: qdk not available: ...

So a space in a path, or a crash inside the generated program, arrives wearing a
missing-toolchain label: a WRONG DIAGNOSIS attached to the N in "N independent
implementations agree". The COUNT is already guarded -- that assertion is real
and it fires -- so nothing ever silently claimed 7 while running 6. What was
wrong was the reason given for the shortfall.

Measured before and after on this machine, where the Q# venv genuinely is absent:

  BEFORE  qdk not available: Command failed: /Users/.../sr
  AFTER   qdk not available: ENOENT: no such file or directory, posix_spawn
                             .../src/Core.Python/.venv/bin/python3

Two changes produce that. Removing the shell separates stdout and stderr, so
e.message alone degrades to "Command failed: <argv>" -- describeExecFailure puts
stderr back in front of it. And the truncation moves 100 -> 400, because a cut
that halves a path names nothing. The rust lane loses its 2>&1 in the process,
which is exactly what the helper gives back.

VERIFICATION. The harness test was run before and after on the same machine:
identical result, 1 pass / 4 fail both times, and the failing set is
diff-identical -- the qsharp lane only, because this machine has no
src/Core.Python/.venv. The six lanes that CAN run still byte-agree; no mismatch
line appears in either log. tsc --noEmit rc=0. lint-check-then-use-file-races
over src/Core.TypeScript rc=0. eslint on this file: 84 pre-existing errors
before, 64 after -- it is not on the lint:eslint roster so neither is gated, and
the change adds none. Prettier was already dirty on this file beforehand and is
left that way rather than folding a whole-file reformat into a security diff.

ALL SEVEN LANES, PROVED LOCALLY. An earlier draft of this message said the Q#
lane could only be proved by CI. That was a missing venv, not a limit, so the
venv was built (uv venv + qsharp==1.29.1 into src/Core.Python/.venv) and the
whole suite run twice on the same machine:

  CONTROL (origin/main harness, venv present)  5 pass / 0 fail
  SUBJECT (execFileSync harness, venv present) 5 pass / 0 fail

Seven oracles, byte-agreeing, before and after. That is the floor-guard
acknowledgement (ZETA_FLOOR_VECTORS_ACK): the oracles were run, and the
cross-oracle contract is unchanged.

Adjacent and not fixed: tmpDir is join("/tmp", ...) rather than os.tmpdir().
Harmless on the Linux runner this job uses, wrong on Windows. A portability
change does not belong in a security diff.
