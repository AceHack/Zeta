## Description

`lint (TS)` is red on every open PR. The cause is `src/Core.TypeScript/observe/f2-role-correlation.ts`: two unused imports plus an unused `falseNegativeRate`. The identical defect was fixed in the sibling `f1-verify-asymmetry.ts` in #15520; F2 was missed.

## The imports are dead. The metric is not.

Deleting `falseNegativeRate` would have cleared the lint and made the experiment worse.

F2 reports `catchRate` — *"when the producer is WRONG, how often does the verifier CATCH it?"* — and concludes **"if catch rate > 30%, role separation adds value beyond vote."**

A verifier that rejects **everything** scores a perfect catch rate under that test. `falseNegativeRate` — how often the verifier rejects work that was *correct* — is precisely the number that excludes the degenerate case. It was computed on the line above and thrown away before reaching output.

The existing "Rejection-rate law" line guards the always-**approve** failure. Nothing guarded always-**reject**. So the headline conclusion was being reported without the one number that could falsify it.

Logged rather than deleted.

## Not verified

That is a check that did not run, not one that passed, and it is not being reported as evidence. CI is the falsifier for the lint half.

The metric half is not falsified by CI either — no test asserts F2's output. It is an observability improvement whose correctness rests on the argument above.
