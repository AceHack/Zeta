## The change

Two optional keys, `signalSource: "reported" | "inferred"` and `signalObservations: number`, read through `heatReceiptReading` → `measured | unknown | unreported`.

**#10735's shape reused rather than re-invented** — a reading with zero observations is a third state, not the healthy one — with **one deliberate deviation, stated because it matters**: #10735 has `observations === 0 ⇒ UNKNOWN` outright. Here zero observations is UNKNOWN *only when there was no channel*. A channel that was read and reported the empty set is a **measured zero**, and the bus breaker has no analogue for that case because a peer cannot explicitly report "no envelopes". Collapsing the two would have thrown away the very distinction this PR exists to make.

**Two keys, not one folded verdict.** Neither is derivable from the other — `signalObservations = 0` occurs under both sources, `signalSource = "reported"` occurs at every observation count — so a fold would have been a fresh non-injective encoder. Asserted directly:

```
signalObservations alone: reported-empty == inferred-blind      (does not separate)
signalSource alone:       reported-empty == reported-nonempty   (does not separate)
together:                 4 cases -> 4 distinct cells           (injective)
```

**The absent-reading is conservative** and that is the load-bearing half: a receipt minted before these keys reads `"unreported"`, never `"measured"`. A **half-present** pair also reads `"unreported"` and is **rejected at the wire reader** — it would otherwise read as unreported while looking, to a human reading the JSON, like it had been reported.

**The outcome token does not move.** `HeatReceiptOutcome` gains no `unknown` member; the third state travels in a separable channel, the same shape as `temperatureBandReading.verdict` against the treaty-locked band tokens.

**Words as well as colour.** A quiet receipt already renders in the muted `--txt3`, so muteness cannot say *not measured*. `data-signal-reading` for the CSS and an auditor; `· NOT MEASURED · 0 observations — unknown, not cold` for the eye; dashed border and hatched rails so the picture agrees with the words.

## Residuals — filed on an existing work-item, not hidden

`081M01400RZ087G0R000PS3VJG` **does not exist on `main`** — it lives only on #10732's unmerged branch, exactly as the brief warned. I did **not** mint a competitor. The findings are appended to **`081M00TYT8N087G0R003MPMRX9`**, which does exist on `main` and which #10742 does not touch, so there is no file collision.

- **`DarkHallRoomTranscript.coldHeatRow` fabricates `Signals = []`.** It is synthesised for a resumable continuation with **zero measured ticks**, so on the wire it claims `reported` — a measurement it never made. F#'s `HeatRow.Signals` is `string list`, not an option, so letting the producer say *"no channel"* changes a shape F# produces and TypeScript consumes: the same published-schema decision #10742 settled for `zeta.temperature.readout.v1`, and **not one to make unilaterally in this PR**. Today's only mitigation is that the fabricated row never reaches `Transcript.HeatRows` and so never becomes a receipt — a property of one call site, not a guarantee.
- **The rails still publish no scale.** `heatReceiptScale` computes `ceilingUnits` and `protocol` and `heatReceiptFromRow` discards both, so a reader cannot invert the `log1p` and the ppm value is a ratio with an unstated denominator. Two receipts produced under different `maxUnits` are indistinguishable on the wire and mean different things.
