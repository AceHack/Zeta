feat(core)+shadow: live IRuntimeEffects (real git merge + RNS) behind the seam — SAFE, Core-pure, gate-respecting

Aaron (shadow*): "wire the real git merge + RNS daemon behind IRuntimeEffects." Wired the
disciplined way (this crosses gated-class lines — unsupervised merge-to-main + a network
daemon + crypto identity — so SAFE-by-default, with the binding parts routed, not unleashed):

- src/Core/FinalizerRuntimeLive.fs (Zeta.Core.FinalizerRuntimeLive): the LIVE
  IRuntimeEffects.
  * Core-pure: the ONLY I/O channel is an INJECTED CommandRunner (string->string);
    Core never calls Process.Start. Default = dryRun (executes nothing).
  * Gate-respecting merge, never force: MergeToMain uses `gh pr merge <pr> --auto --squash`
    semantics — auto-merge that RESPECTS branch protection + CI (merges only when gates
    pass); NEVER a force/direct push to main. DRY-RUN by default (live=false => no merge);
    even live=true does nothing unless a host injects a real runner returning MergeOk.
  * No crypto / no daemon here: the RNS daemon (rnsd) + governed ZetaId crypto identity for
    destinations are ROUTED to Dejan (devops) + Nazar (security), not minted/spun here.
  * ReadTick parses git/metrics state via the runner (culture-invariant float parse);
    parseTick lenient (empty -> cold Stop tick = safe default).
- src/Core/FinalizerRuntimeLive.test.fsx: 8/8 — dry-run never merges; live+dry-runner still
  no-merge; gate-respecting auto-merge via injected fake host => true; parseTick correct;
  end-to-end live drive ScaleUp->ReKick(merged)->Stop.
- dotnet build Zeta.sln -c Release: 0W/0E.
