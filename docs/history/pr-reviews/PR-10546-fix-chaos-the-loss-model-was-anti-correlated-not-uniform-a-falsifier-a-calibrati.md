## Description

Closes `081KZYY6SVJ087G0R0035SW945` and `081KZYP23HG087G0R000117H0K`.

`burstParams(ρ, 1)` was documented as *"i.i.d. Bernoulli — the degenerate case"*. It is the
opposite. With `r = 1` the chain leaves BAD after **exactly** one packet, always, so the channel
**forbids consecutive loss**. Measured over 400,000 packets: `P(drop | previous drop) = 0.00000`,
where i.i.d. would give ρ.

A mean loss-run length of exactly 1 is **unattainable for any lossy i.i.d. channel** — Bernoulli
sits at `1/(1−ρ)`. So `L = 1` is not the origin of the correlation axis, it is the far end of it.
Per block of 8 at ρ = 0.1, against `Binomial(8, 0.1)`: **k=4 understated 4.6×, and k ≥ 5
impossible rather than merely rare.** The tail is the only part an erasure code cares about.

### Two claims are corrected, not confirmed

**1. The bias has no fixed sign.** `081KZYY6SVJ087G0R0035SW945` claims every uniform row is
"optimistic in the code's favour". True for `[8,4,4]` delivery; **false for XOR-7/8 at high
loss**, where the old model was *pessimistic* by **9×** (0.010 vs 0.092 goodput at 40%).
Anti-correlation suppresses **variance**, and a rate-7/8 code lives on the lucky blocks variance
supplies. A model error is a **distortion**, not a bias with a direction. (`UCH-26`.)

**2. `ULT-34`'s mutation was not disarmed by `meanBurstLength = 1`.** This work was promoted on
that premise. #10541 merged while this branch was in CI, so the mutation was re-run **against the
real code**: replacing `Math.min(...)` with the bare `this.pendingCorruptFrames` leaves **all 30
tests in the corrected chaos file green** — genuine Bernoulli channel and all — and only the
hand-built `ULT-34` goes red.

There is also a proof, not just a sample:

> A refused frame does not advance `expectedSeq`, and arrivals are in sequence order, so every
> refused sequence number lies inside the **next** reported gap. Therefore
> `missing.length ≥ pendingCorruptFrames`, **always**, at every burst length and every loss rate.
> `pending > missing.length` is **unreachable in an in-order channel.**

Consecutive corruption is neither necessary nor sufficient. What *does* reach the bound is the
**desync branch**: a gap wider than `MAX_NACK_GAP = 64` reports locally and never runs the
attribution block, so `pending` survives it and the next narrow gap satisfies the condition. That
needs a loss burst > 64 — **and the sweep's burst grid stops at 8.**

So the instrument defect that hid `ULT-34` was **the grid, not the model** (`UCH-27`). Receiver
semantics were **read** from the source, not inferred — a first, inferred model was wrong and was
thrown away rather than shipped.
