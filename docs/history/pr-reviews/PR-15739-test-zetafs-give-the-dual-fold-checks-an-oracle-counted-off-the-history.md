## Description

test(zetafs): give the dual-fold checks an oracle counted off the history

`ZetaFsDualFold.Tests.fs` (#15718) shipped one assertion that cannot fail:

    let history = [ 1; 2; 1 ]
    ...
    Assert.Equal<int list>([ 1; 2; 1 ], history)

`history` is a `let`-bound literal three lines above and F# lists are
immutable, so the two sides are one expression. It is the assertion
`audit-check-arity` R2 flags, and the audit is right -- the claim it carries
("the generator never held a mutable log") is real, but parametricity already
guarantees it and no implementation could break it. Ordinary error, and the
commonest one there is: #15718 shipped a working feature and one line of its
test claimed more than it proved.

Not silenced with a census row. A census row records a judgement that an
assertion is legitimately narrower than it looks; this one was not narrow,
it was empty.

WHAT CHANGED

Both reinterpretation checks now compare against an oracle COUNTED OFF THE
HISTORY rather than one routed back through the generator:

  * the Fact pins the emitted delta to `[1, -2; 9, 2]` and the folded view to
    `[2, 1; 9, 2]` -- hand-computed from `[1; 2; 1]` with `1 -> 9`. The old
    expectation was `reread after history`, which is the same function that
    produced the value under test.
  * a new Fact pins the READ DISCIPLINE with a recording generator over a
    mutable `ResizeArray` record: exactly two reads, `before` then `after`,
    both against the same record. Those are three things a wrong `reinterpret`
    can get wrong; the immutable-list assertion it replaces was not.
  * the property pins `delta = [raw, -n; label, +n]` where `n` is counted
    directly off the history, and draws `raw` FROM the history with `label`
    from a disjoint range. Previously `raw` was generated independently, so on
    most inputs it was absent from the history, the delta was empty, and the
    property degenerated to `gen before h = gen after h`.

MUTATION EVIDENCE

Mutants of `ZetaFsDualFold.reinterpret`, each built and run:

  swap the readings   `add (neg (gen after h)) (gen before h)`   3 tests red
  drop the retraction `add (gen before h) (gen after h)`         4 tests red

And the mutant that shows the strengthening is not cosmetic -- a generator
that silently collapses duplicate history rows (`List.distinct` before the
relabel), i.e. reinterpretation that loses the retained record's multiplicity:

  BEFORE: 8 passed, 0 failed  -- the whole suite survives it, because every
          expectation routed through the same generator, so `X + (-X + Y) = Y`
          held whatever `X` and `Y` were.
  AFTER:  2 failed (the Fact on `Assert.Equal() Failure: Collections differ`,
          the property `Falsifiable, after 12 tests (5 shrinks)`).
