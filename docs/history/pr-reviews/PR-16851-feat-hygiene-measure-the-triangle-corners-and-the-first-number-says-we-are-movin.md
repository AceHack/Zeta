## Description

Aaron named a direction of travel: *"we have generator plus joins plus observability, and over time we want this triangle to move more data points to generators over observability, because observability costs more."*

A direction with no instrument is an aspiration — assertable, never checkable. This is the instrument.

## The first measurement, and it is a negative result

```
generator       57.8 MB    6379 files
joins            5.7 MB     485 files
observability  205.6 MB   42436 files
prose           97.4 MB    7181 files
excluded        29.6 MB     181 files
unclassified   655.4 KB     249 files   (0.2%)

observability per generator byte: 3.556
description length (generator + observability): 263.4 MB
```

**A month ago that ratio was 2.546.** The repo has moved **toward observability**, not toward generators.

Attribution of the observability growth: `db/search-index` **+59.7 MB**, `docs/history` **+36.5 MB**. Two qualifications I had to check before stating it, and both changed the reading:

- The search index is a **one-time landing** (first appeared 2026-08-23), not a monthly rate. Calling it "+60 MB/month" would have been wrong.
- Its cadence workflow is `disabled_manually` — **deliberate**, under the size-reduction decision, not a lane that broke. It rebuilt 7 times on 2026-08-24 and has been paused since.

The archive growth is the genuinely ongoing half, and it is what the archive-split draft already addresses.

**The search index is the sharpest instance of the triangle's own tension**: 60 MB of committed points whose generator exists, so they are regenerable — and committing them is exactly what buys `clone-at-tag-stays-sufficient`, a clone that can search without rebuilding anything. This tool does not decide that. It prices it: **24% of the observability corner.**

## What it measures — and what it does not

**Byte composition, not cost.** Aaron's claim is about storage, re-reading, staleness and re-verification; none of those are measured here, and the proxy is wrong in both directions — a tiny baseline can cost enormous attention, a large generated table can cost nothing. Stated in the header so it cannot be quoted as the cost measurement it is not.

## The classification is the arguable part, so it is published

`RULES` is an exported, first-match-wins table, each row carrying the reason it is where it is. *A meter is good when anyone can inspect it and agree to the rules before the measurement* — disagree with a row and the number changes, which is the intended way to argue with it. Two calls worth attacking:

- **Tests are generators; the baselines they compare against are observability.** An executable artifact re-derives its verdict on every run; a stored one is a point. This is the diode from the research doc, applied.
- **Prose is reported separately, never folded into observability.** The research doc argues prose is an observation *about* a generator, which would put `docs/**` in the expensive corner and swing the headline on the most contested call in the table. Counted, shown, kept out of the ratio.

## Refusals, and one that fired

- **Over 20% unclassified bytes → refuse**, naming the largest uncovered directories. **It fired on the first run at 25.8%**, and the rules were extended until it passed.
- **Excluded bytes** (vendored jars, presentation assets) are *declared* rather than silently swept into a flattering corner, and are held out of the denominator so they cannot dilute the coverage check into never firing. There is a test for exactly that.
- An undefined ratio is reported as **undefined**, never as zero.

**The reachability test found a real misclassification while being written:** `package-lock.json` does not match `package.json`, so it fell through the wiring rows into the residual-JSON sweep and was counted as observability.

## Wired into `gate` as a non-blocking drift job

Aaron: *"wire it into gate as a non-blocking drift step."* Done — `drift (triangle corners)`.

**Non-blocking by construction, not by promise.** `gate (required)` rolls up only `registry/uncompensatable-floor.yaml`, and this job is not in it. Byte composition is a direction to watch, never a bar to clear; a composition check that could block would be a bar nobody agreed to.

On a pull request it fetches the base commit at depth 1 and passes it as `--since`, so each PR reports **which way it moves the ratio**. Verified on this branch: `at origin/main: 3.555 → TOWARD generators (-0.001)`.

**What the `continue-on-error` costs, stated rather than assumed.** The meter exits non-zero on exactly one condition — over 20% unclassified, meaning its rules no longer cover the tree. Swallowing that produces a green job with a failed step and no red X, which is precisely the class `drift (loud)` exists to surface. Quiet here, loud there.

**A probe that fails is UNKNOWN.** If the base commit cannot be fetched, the step says so and reports composition without a direction. It never prints "no movement" when it could not look.

**The repo caught me on my own argument.** Registering the package script without wiring it turned `lint (bash retirement inventory + hygiene unit tests)` red on `audit-linter-coverage-vs-invocation` — *a configured linter must be an invoked one*, which is this meter's own "an artifact nobody consults stores nothing" under another name. The rule was already here.

## Why the direction has an optimum, not an endpoint

`descriptionLength` reports generator + observability, which is MDL's objective in bytes. An over-fitted generator larger than the data it replaces has made the description **longer**. Anchor: **Rissanen, minimum description length**, sitting over Shannon's rate–distortion framing — Aaron's *"compress while being accurate"* is precisely a rate objective under a fidelity constraint, and MDL is the form of it that counts both halves in the same units.
