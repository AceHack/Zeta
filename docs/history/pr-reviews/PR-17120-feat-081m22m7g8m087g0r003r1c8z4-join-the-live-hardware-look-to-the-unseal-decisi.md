## Description

## What was missing

Not the probe, and not the decision. Both were built and both are correct — nothing executed both.

Measured on a host with a YubiHSM 2 attached:

```
named-frost-look-env.ts --os darwin --effects real
  -> {"yubiHsm2":"attached","smartCardReaderAttached":true,"pkcs11ModuleOnDisk":true}
integrateAtSetup({requested:"auto"}, hostCaptureFromNamedProbe(probe))
  -> {"ok":true,"path":"pkcs11-yubihsm","mechanism":"aes-gcm","autoUnseal":true}
```

`bao-elf-capture.ts` holds the join and has no `import.meta.main`. `firstboot-bao-env.ts` is the one the installer actually runs, and it emits `probe: null` unconditionally — **correctly**, since zflash may not spawn. `zeta-install.sh` exports neither the request nor the look keys, and says so in a comment at each site.

Three rungs built, the fourth deferred at every step, and each deferral individually right. So on metal the seal path was never chosen from hardware.

## The rung

`tools/setup/persona-keys/seal-path-detect.ts` — the only place the two halves meet. It sits in the layer permitted to look at the host, so the composition travels **down** into the pure layers and `cluster/` / `zflash/` stay spawn-free and DST-replayable.

A joiner is exactly where "unmeasured" gets rounded to a value, so every distinction is kept at the join: a null look stays `probe-did-not-run`; a missing request stays unmeasured and never becomes `auto`; a driver on disk stays `driver-is-not-a-device`; `smartcardHsm` stays `not-asked`; emulators refuse as `emulator-not-declared`. A refused decision exits 0 — "no path here" is a finding, not a fault.

## CI before hardware

16 falsifiers describe hosts and assert the path each should get. The load-bearing one pins that the **same machine decides differently under a real look and a null look** — a joiner ignoring its probe passes every other test in the file and fails only that one. Five mutants, each killed:

| mutant | tests killed |
|---|---|
| ignore the probe entirely | 6 |
| null look becomes a live look | 2 |
| missing request defaults to `auto` | 2 |
| empty request becomes `auto` | 1 |
| request-parse refusal exits 0 | 1 |

The seal-emulator workflow also runs the **live** look on the runner. It deliberately asserts no path: a runner's USB topology is unmeasured from here — `/sys/bus/usb/devices` may enumerate or may be empty in a virtualised runner, which the probe honestly reports as `indeterminate` — so pinning `lucent-shamir` would assert a value nobody measured. What it asserts is the direction that can hurt: **a runner with no HSM and no TPM must never name a `pkcs11-*` path.** Verified that guard can fail by running it against a Mac with a YubiHSM attached, where it trips; it passes on shamir and on an honest indeterminate.

## Installer

Observational only. It reports which seal path the host would get, configures no seal, writes no stanza. Acting on the answer is the next rung and needs an operator decision — and for an HSM, its password.

## Not in scope

Aaron's HSM-password-at-setup prompt, and consuming the detected path to actually configure a seal. Both want the operator in the loop.
