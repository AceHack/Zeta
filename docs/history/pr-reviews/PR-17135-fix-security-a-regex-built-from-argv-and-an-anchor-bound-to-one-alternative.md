## Description

fix(security): a regex built from argv, and an anchor bound to one alternative

Four CodeQL alerts, two distinct defects, both genuine.

REGEX INJECTION (alerts 246, 450 -- js/regex-injection, medium)

`consume-pr-archives.ts:82` and `triage-orphan-branches.ts:135` both wrote:

    branch.replace(new RegExp(`^${remote}/`), "")

`remote` arrives from `--remote` on argv, so the pattern is not the pattern the
author wrote:

  * `--remote o.i` compiles `^o.i/`, where `.` is any character, so the ref
    `oXi/main` is stripped by a remote that does not name it.
  * `--remote 'a|b'` compiles `^a|b/`, and `|` binds looser than the anchor, so
    it means "starts with a, OR contains b/" -- stripping from the MIDDLE of a
    ref whose name happens to contain `b/`.
  * `--remote '('` throws SyntaxError from inside a `.map`.

ESCAPING WOULD HAVE BEEN THE WRONG FIX, and that is the point of the new module
rather than a one-line patch. `escapeRegExp(remote)` closes the injection and
leaves a regular expression compiled once per branch to answer a question
`startsWith` already answers. A prefix strip is a string operation; there is no
pattern here, only a literal. Keeping the regex keeps a machine whose behaviour
depends on how a CLI argument was spelled, and the next author to copy the line
copies the hazard back.

New `src/Core.TypeScript/git/ref-prefix.ts` -- total, no compilation, no throw.
It goes beside `changed-files.ts` and `tracked-files.ts`, which are the same
shape with the same test discipline.

ANCHOR PRECEDENCE (alerts 183, 184 -- js/regex/missing-regexp-anchor, high)

`ops-demo.ts:142,149` -- `/^\dt|information_schema|.../` anchors only the FIRST
alternative. Made explicit with a non-capturing group.

This is a CLARITY change, not a behaviour change, and that claim is measured
rather than asserted: both patterns were run against 1110 generated inputs each
(all strings of 1-3 tokens over a 10-token alphabet drawn from the alternatives)
with ZERO disagreements between the old and new spellings. The precedence the
code had is the precedence it now states.

NOT changed, and named rather than silently skipped:

  * alert 131 `js/weak-cryptographic-algorithm` -- SHA-1 in `uuidv5`. RFC 4122
    DEFINES v5 as SHA-1, the use is content-addressing for idempotency and not
    authentication, and changing the hash changes every derived ChangeSet id.
    That is a data-format decision for the maintainer, not a lint fix.

Falsifiers: 8 tests, 5 mutants, 0 survivors -- including a mutant that reverts
`stripRemotePrefix` to the injectable regex, which 4 of the 8 tests catch.
