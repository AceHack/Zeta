## Description

fix(ci): actionlint is red on main — `exit` took an unverified GH expression

`drift-dashboard-cadence.yml:102` interpolated a workflow expression directly
into `exit`:

    exit ${{ steps.pass.outputs.pass_status || 0 }}

shellcheck SC2242: the expansion is not guaranteed to be an integer in 0-255,
so a non-numeric or out-of-range value makes the shell exit with a status
nobody chose — and an exit status nobody chose is a verdict nobody made.
actionlint fails on it, which reddens `lint (actionlint)` on `main` and on
every PR that merges `main` (observed on #14206, #14243, #14251).

Reads the value through the environment and REFUSES what it cannot read,
rather than exiting on a value it did not verify. Verified locally:
`actionlint .github/workflows/drift-dashboard-cadence.yml` → rc=0.

NOT fixed here, and it wants an owner: line 98 of the same file is
`git push origin HEAD:main`. The ruleset requires `gate (required)` at push
time with no bypass actors, so that push cannot succeed — it is written with
`|| echo "::warning::"`, which means the lane degrades to "artifact stale"
without failing. Telemetry lanes park on `heartbeat/*` and flush via PR
(`.github/workflows/agent-heartbeat.yml` is the worked example, with
`ZETA_TELEMETRY_FLUSH_TOKEN` and a production falsifier for the credential).
Left alone because rerouting a publication path is a design change, not a
lint fix, and bundling it here would hide it.
