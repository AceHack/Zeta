## The near-miss

The spec'd exclude pattern `refs/heads/*-flush-*` releases **zero** refs. GitHub matches under `File::FNM_PATHNAME`, so `*` does not cross `/`: that pattern has three path segments, the refs have four.

```
exclude refs/heads/*-flush-*            -> released     0
exclude refs/heads/heartbeat/*-flush-*  -> released  1612
```

Applied naively it produces a green run, a clean PATCH round-trip, a "successfully applied" log line, and **no behavioural change** — a check that did not run, wearing the costume of a fix. The correct pattern keeps all 25 live lanes protected, including the new fixed `heartbeat/<agent>-flush` refs from #15309 (they end in `-flush`, no trailing `-`).

## Design

`read live → normalise → diff → classify → gate → snapshot rollback → PATCH → RE-READ → verify`

- **Idempotent** — normalisation drops server bookkeeping so re-runs are true no-ops. Live run verified: `NO-OP — live state already matches the committed desired state`, exit 0.
- **Verifies its own write** — re-reads after PATCH; mismatch is exit 4.
- **Verifies the *meaning*, not the bytes** — re-derives covered-ref sets from live ref names and reports `released` / `newly covered`. This is what makes the near-miss visible.
- **Never creates, never deletes** a ruleset — no code path.
- **Exit 2 = INDETERMINATE**, never silently green.

**Widening (W1–W8)** = enforcement lowered · rule removed · bypass actor added or loosened to `always` · `include` entry removed · `exclude` entry added · required check dropped · approvals lowered / thread-resolution disabled / merge method added · **any unrecognised parameter change (fail-closed)**. A widening component **poisons** an otherwise-tightening set — netting a bypass actor against an added rule is how a hole rides in on a fix.

**The gate**: a committed `approvals/<id>.approval.json` bound by **SHA-256 of the canonical desired JSON** (so editing after approval re-closes the gate — an approval that survives an edit is a licence, not an approval) **and** declaring the **exact count of refs released**, checked against what the matcher computes. There is no runtime `--allow-widening` flag on purpose: the authorisation lives in the reviewed tree, not in whoever invokes the tool.

Note W5: **the heartbeat fix is itself a widening change.** No exception is carved for the change that motivated the design.

## Privilege — stated plainly

The reconciler needs `administration: write`: it can delete every ruleset, disable every protection, and (fine-grained) delete the repo. Constrained by the committed file, the manifest allowlist (one ruleset today), the widening gate, no-create/no-delete, rollback snapshots, and trigger separation. **Not** constrained: nothing stops a compromised token doing whatever it likes — the file constrains the *reconciler*, not the *token*; and a PR editing the classifier can subvert the gate. Recommended shape is a **GitHub App scoped to this repo only**, `Administration: Read and write` and nothing else, minting a ~1h token per run.

**No token, secret, app, or ruleset was created or modified by this work.** The exact one-time bootstrap is specified in the doc §8.
