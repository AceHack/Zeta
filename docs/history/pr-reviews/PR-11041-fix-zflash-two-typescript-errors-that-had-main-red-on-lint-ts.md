## Description

`main` has been failing `bun src/Core.TypeScript/lint/lint-typescript.ts` on two zflash errors. Not in the `gate (required)` floor, so nothing was blocked — **which is why it sat**: a persistent red nobody is blocked by is one people stop reading.

**Ownership checked before touching:** last commit to either file was **2026-08-08**, eight days ago, and no open PR touches zflash. The live UEFI work is in the smoke-test workflow, not these files.

## The two errors

**1. `prepare-boot-image.ts:92` — TS2353.** The object literal passed `usbUuid` / `output` / `passphrase` to `composeBundle`, which takes only `{ persona, bakeCredArgs }` and never read them — the uuid and passphrase go separately to `buildBlob` below, and `outputPath` is the caller's. They were silently ignored.

Worth noting why `cli.ts:682` never flagged the identical call: TypeScript's excess-property check fires on object **literals** but not on **variables**, and that site passes `parsed`.

**2. `cli.ts:686` — TS2345.** `parsed.usbUuid` is `string | null` because `--usb-uuid` is optional in general. It cannot be null here — `persistArgv` always carries the flag, sourced from the `usbUuid` already guarded non-null at the top of the function. Narrowed with a **real check rather than a `!` assertion**, so that if `parsePersistArgs` ever stops round-tripping the flag it fails loudly instead of handing a null to `buildBlob`.
