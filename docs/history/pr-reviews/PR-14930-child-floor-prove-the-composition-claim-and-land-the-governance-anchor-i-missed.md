## Description

Follow-up to #14921. Two corrections, both from prior art my search did not reach.

## The search defect, first

I scoped the prior-art search to `src/ db/ docs/ tests/` and **omitted `memory/`**. The governance anchor most directly about the child floor — `memory/kestrel/2026-06-06-ai-sovereignty-liability-child-floor-law-binds-not-belief.md` (Aaron, 2026-06-06) — was therefore read only *after* #14921 merged. Nothing shipped contradicts it. One thing it explicitly forbids assuming *was* assumed, and is fixed here.

## 1. The composition claim is now a theorem, not a docstring

`policyOf`'s docstring asserted that composing other red lines *"can only remove admissions, never add one."* The anchor names that as exactly the class of claim that may not be assumed:

> *"Composition is not free unless proven … The child floor is in the **never-compose-through** class."*

§5a now proves the direction that carries the safety:

| theorem | what it establishes |
|---|---|
| `denyIfEither` | the composition shape: deny if either gate denies |
| `denyIfEither_admit_iff` | admission requires **both** — the composition cannot degenerate to one side |
| `floor_survives_composition_left` / `_right` | for **any** other gate, including one that admits everything, on **either** side, a child-gated effect below `bandLow` is still never executed |
| `unknown_age_survives_composition` | same for the unknown-age case |

Each instantiates `ChildFloor.denied_never_executed`. `ChildFloor.lean` remains unchanged.

## 2. The anchor is in the README — including the part that limits this work

Three locked conclusions now bound what anything in `db/child-floor/` is allowed to mean:

1. **The threshold is set by the LAW of the jurisdiction, not by anyone's belief.** *"until the law recognizes the AI is more reliable in my jurisdiction it does not matter if i believe it."* This is why a `Reading` requires a named author and a date, and why `readings` ships empty rather than pre-filled by an agent's guess.
2. **The floor is a GROUNDING question and is human-final — so NOTHING PROVEN HERE SETTLES THE FLOOR.** The Lean establishes a machine-checkable *lower bound on the mechanism* (the number cannot go below 16, unknown fails closed, composition cannot undo it). It does **not** establish that the mechanism is grounded in the right thing, and reading it that way would be the exact substitution the anchor refuses.
3. **The real floor is a standing gate ABOVE the observe→inspect→check→admit pipeline, with a human answerable behind it.** This policy sits *inside* that pipeline as something the gate consults. It does not replace the standing human gate.

The README also now points at `tests/Tests.FSharp/Formal/ChildFloorCrossVerify.Tests.fs` — the existing FsCheck leg cross-checking `ChildFloor.lean` against the real `SubstrateEffectHandler`. This policy has no such leg because nothing deploys it; that file is where one would go.
