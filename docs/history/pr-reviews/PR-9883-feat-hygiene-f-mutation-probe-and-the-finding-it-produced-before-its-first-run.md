## Description

Stryker covers only C# and records why it can't expand (*"Language not supported: Fsharp"*) — so the **money code, which is all F#**, had the weakest could-not-fail coverage before an audit.

**I tried the cheap thing first and measured it rather than shipping it.** Three textual signatures against the real tree: self-comparison → **0 hits**; `[<Fact>]` with no assertion → **183 hits, and both sampled were false positives** (they delegate to assertion helpers); unused `_` params → **3 files**. A detector that cries wolf 183 times is *itself* a could-not-fail tool — nobody reads it, so it can never be wrong. The property that matters is **semantic**, which is why mutation is the right instrument.

**The finding, which didn't need the probe to run:** enumerating targets gave 41 mutants in `MoneyVelocityOracle.fs` — then I checked coverage first. **It has ZERO behavioural tests.** Its only appearance under `tests/` is one row in a *determinism-lint allowlist*. No test calls `moneyRegime`, `moneyRho`, `m2VelocityToRho`, or `tsirelsonAgeDays`. All 41 mutants would survive trivially. For contrast in the same sweep: AskBidClearing **23** test call-sites, Web3Settlement **13** — so it's specific, not repo-wide.

That's the same module Soraya caught **contradicting itself** today (1184 days vs ~517 — 2.3× apart, same file) and whose `regimeTable` *asserted* a regime instead of calling the classifier. **Both are exactly what zero coverage permits.**

**Recommendation:** write behavioural tests for MoneyVelocityOracle *first*, then probe. Mutating an untested module yields 100% survival — technically true, practically useless. The coverage gap is the finding. 🤖 Generated with [Claude Code](https://claude.com/claude-code)
