## Description

`DebouncedOracle.EffectiveCorrelation` publishes `ρ = 1/(1+MinDelay)`. It is a **pure function of config** — it never touches a reading.

So the module whose stated purpose is to *guarantee* decorrelation published a decorrelation figure that **no observed behaviour could ever contradict**. Same shape as the six §A discharges demoted today — a number asserted rather than measured — sitting inside the component built to prove the property.

Verified first: `MinDelay` is never recomputed anywhere (0 references outside the file), and the accept test compares **inter-arrival time between accepted readings**, not the round-trip L the docstring describes.

## What this adds

Only quantities the oracle **already had and threw away** — it computes `elapsed` on every callback:

| field | |
|---|---|
| `Accepted` / `Suppressed` | counts |
| `MinObservedGap` / `MaxObservedGap` | observed gap range, seconds |

And two derived checks that **can fail**:

- **`isInert`** — readings arrived and *none* were suppressed. The debounce did nothing; the declared ρ rests entirely on a constant. **This is the check `EffectiveCorrelation` alone can never fail.**
- **`gateIsBinding`** — do observed gaps sit near `MinDelay`, or was the source already slower than the gate (decorative)?

## Two distinctions preserved as `option`, never `0.0`

- `suppressionRate` is `None` when nothing arrived — **"nothing was seen" ≠ "nothing was suppressed"**
- `gateIsBinding` is `None` when no gap was observed — **unmeasurable ≠ measured-false**

Same live/cold discipline the observability surfaces enforce. Conflating them is how a check goes quietly vacuous.

## Deliberately not added

**Measured autocorrelation** — the direct measurement of ρ. It needs comparable readings, and `DebouncedOracle<'T>` is generic over opaque `'T`. Reporting `0.0` for *"cannot correlate on this type"* would recreate the exact conflation above. When it lands it must be `float option`, `None` = cannot measure.

Suppression and gap range need no type constraint, so **even opaque `'T` gets a falsifier today.**

## 8 tests

Including a **negative control** (`isInert` must *not* fire when suppression really happened — otherwise an unconditionally-true `isInert` would look like a working falsifier), and one that **pins the defect**: two oracles with identical config publish identical ρ whether one suppressed 95% or nothing. That test documents why this record is needed and **will start failing the day ρ becomes measured.**
