A stale measurement in a roster is the class this repo cares most about, one layer out: not a check that did not run, but **a recorded result that stopped being true and kept deterring work**. It deterred mine — I nearly skipped this as "14 failures, real work" on the note's authority.

## What actually remained

The validators *lived inside* the tree. Moved `infra/k8s/tests/` → `full-ai-cluster/k8s/tests/` (8 files). **Same directory depth**, so every `resolve(here, "../../..")` repoRoot and the one cross-import survive unchanged — checked *before* the move, not after. Workflow references and every self-referential usage line updated.

## Two defects the move surfaced, both pre-existing

- **`validate-bootstrap.ts` mislabelled its own subject.** Its Test 2 header hardcoded `infra/k8s/bootstrap`, but `helm-validate` runs it **twice** — once plain, once with `--infra-dir full-ai-cluster` — so one run always printed a label for a tree it had not looked at. It now prints the tree it actually validated; both invocations verified separately.
- **`render-first-boot-charts.ts` hardcoded its bootstrap pair.** Now derived, and its test's coverage assertion is stated over the derived list rather than two spelled paths — strictly stronger, since it holds for however many trees the roster declares, and guarded by a length check so the loop cannot assert nothing.

## The move revealed coupling that was invisible by construction

The roster **excludes `infra/` from its scan**, so consumers living *inside* the stale tree were never counted. Moving them out made five visible at once. That is the audit working rather than a regression — but it is worth naming: **an exclusion prefix hides exactly the files most likely to be coupled.**
