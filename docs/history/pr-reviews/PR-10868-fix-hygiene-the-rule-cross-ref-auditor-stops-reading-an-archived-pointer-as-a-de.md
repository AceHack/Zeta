## What

`src/Core.TypeScript/hygiene/audit-rule-cross-refs.ts` — the auditor meant to catch stale
pointers in `.claude/rules/` — was blind in exactly the shape of the damage PR #10863
repaired. This closes both holes and makes the auditor report the three states #10863 had
to separate by hand.

**The auditor only.** No `.claude/rules/**`, no `CLAUDE.md` — those belong to #10863, which
is open and unmerged.

## The two blind spots

**1. No `.claude/rules.bak/` fallback.** A bare sibling `.md` resolved against
`.claude/rules/<basename>` and nowhere else. The #6676 archive moved 96 rules to
`.claude/rules.bak/`, so a reference to an archived rule read as simply-missing —
indistinguishable from a reference to nothing. Resolution is now three-state:

| state | meaning | reported as |
|---|---|---|
| **live** | resolves in `.claude/rules/`, or as written, or via an existing fallback | resolved |
| **archived** | resolves **only** in `.claude/rules.bak/`, and the reference does not say so | its own section, with the real location and the rewrite that fixes it |
| **dead** | resolves nowhere | stale-pointer candidate (unchanged meaning) |

A reference that already spells `.claude/rules.bak/<name>.md` is **live**. Saying where the
file actually is, is the fix — it must never be re-flagged.

**2. It read link display text, never the link target.** For ``[`foo.md`](bar.md)`` `pullRefs`
inspected `` `foo.md` `` and never saw `bar.md` — the half that has to resolve. A link is now
**one** reference carrying both halves:

- the **target** is authoritative for existence and is resolved **relative to the rule file**,
  as a markdown reader would (`../../docs/governance/MANIFESTO.md` from `.claude/rules/` is
  `docs/governance/MANIFESTO.md`) — a genuinely different rule from the repo-root-relative
  code-span convention, so the origin travels with the ref;
- the **display text** is what implies a location to a human, so where the two disagree about
  the **directory** that is reported as a mismatch.

The display half of a link is not double-counted as a code span.

## Positive control — planted, not assumed

`src/Core.TypeScript/hygiene/fixtures/rule-xrefs/` is a live/archive **pair** holding one
reference of each class, and `audit()` runs end-to-end over it. Live/archived/dead/shorthand
all classify correctly; the planted mismatch is reported.

```
refsFound 10 · resolved 5
archived: [link-target archived-rule.md -> ../rules-archive/archived-rule.md]
          [code-span  archived-rule.md -> .../rules-archive/archived-rule.md]
dead:     [link-target no-such-rule-anywhere.md] [code-span no-such-rule-anywhere.md]
          [code-span  shorthand-tool.ts]           <- exists in the ARCHIVE dir on purpose
mismatch: [display "some-other-dir/live-sibling.md" vs target dir ".../rules"]
```

`shorthand-tool.ts` is planted **inside the archive dir** so the `.md`-only guard has a
falsifier: if the guard is dropped, a shorthand reference gets mislabelled as a misleading
rule pointer, which is how an auditor teaches agents to pad the cold-start surface.

The dirs are parameters (`audit(rulesDir, archiveDir)`) rather than constants precisely so
this control can exist — a resolver whose only possible input is the real tree cannot be
positive-controlled, and the real tree is a moving target while #10863 is open.

**The control earned its keep on the first run: the planted mismatch did not fire.** The dedup
key was `(kind, origin, target)`, so a second link to the same target with a *different*
display text was silently discarded — the second claim about where the file is, dropped by the
very tool that exists to read it. Fixed; the key now includes the display half.

## Honest limits

- The **display/target mismatch is a heuristic and says so in the code** (per
  `toy-is-free-metered-must-be-earned.md`). It reports that the two halves *disagree*; it
  cannot say which half is wrong. It accepts two display conventions (repo-root-relative and
  file-relative) and stays silent on any display text with no `/`.
- The auditor **still cannot resolve legitimate unqualified shorthand** (`new-workitem.ts` and
  friends remain in the dead list). Repo-wide basename resolution was considered and rejected:
  a colliding basename would silently mark a wrong-location reference *live*, which is the
  #10863 defect class with the sign flipped. A triager's judgement stays in the loop.
- Exit code is still **0 always**. This is detect-only; nothing here turns it into a gate.
