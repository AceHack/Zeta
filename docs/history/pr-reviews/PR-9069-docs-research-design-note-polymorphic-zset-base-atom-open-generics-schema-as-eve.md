  When the schema-as-events implementation follows this design, representing a schema as `ZSetW&lt;FieldKey, FieldSpecWeight&gt;` makes the field spec part of the weight algebra, so add/drop/retype would have to combine and negate `FieldSpec` values rather than retracting a specific `(field, spec)` fact.
