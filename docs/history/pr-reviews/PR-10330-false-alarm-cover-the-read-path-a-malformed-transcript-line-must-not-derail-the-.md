## Description

**First finding from the new findings ledger**, and it landed on the metric itself: soraya, tick 11240, `false-to-true` on `mutation-false-alarm-rate.ts` — INDISTINGUISHABLE UNDER SUITE.

## The gap

`isTranscriptEntry` filters malformed lines in `readFalseAlarmReadout`. Every existing test drove the **pure core** (`falseAlarmReadout`) directly with well-formed objects, so the filter on the real read path was never exercised at all. Flipping its guard to `return true` changed nothing any test could see.

## Why it matters beyond the mutant

`null` is `typeof "object"`, so a guard that admitted it would then throw reading `.action`. One corrupt line in a JSONL file — a partial write, a truncated append — would either crash the metric or silently corrupt the counts.

This is the module whose entire job is honest measurement. It must not be derailed by its own input.

## The tests

Three, through the real path with a seeded temp transcript:

- a JSON `null` line cannot be mistaken for an entry;
- primitives, arrays, `{}`, `{action:null}` and `{action:{}}` are all rejected;
- an entirely malformed transcript yields an empty readout rather than throwing.
