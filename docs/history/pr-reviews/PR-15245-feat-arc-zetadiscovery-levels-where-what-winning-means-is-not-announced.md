## Description

# Summary

`ZetaChase` teaches **navigation**. All three levels share one win condition — reach the goal — and only the obstacles change, so an agent that learned "walk to the other blob" clears the whole ladder. ARC withholds the objective; working out what ends a level is half the task. A curriculum of ZetaChase-shaped rungs cannot teach that, however many rungs it has.

Two new levels break the rule the previous ones taught:

- **Sequence** — a goal-looking thing and a key. Stepping onto the goal does nothing until the key has been touched.
- **Surface feature** — two candidates. The one that *looks* like every previous goal (same colour, tagged `goal`) is inert; the odd-coloured one wins.

**Separate environment, not appended.** Adding these to ZetaChase would make the scored ladder unclearable and turn the lane's smoke step red. The scored episode measures navigation and should keep measuring exactly that — still 3/3 levels, 0.3375.

## My first three designs were not rungs at all

Each was caught by measurement, not review, and the sequence is the useful part:

**1. The gate was cumulative.** `win_tag in self._touched` meant touching the goal and *then* the key won without ever returning. Order didn't matter, so the "sequence" level taught nothing. Fixed: the win requires standing on the target **at the moment** the gate is satisfied.

**2. Two objects is not a puzzle.** With the gate fixed, the pixel agent still cleared it in **24 actions** — nearest-first routing oscillates between two objects, and any policy that keeps moving between them solves a two-object sequence. Rearranging so proximity pointed the *wrong* way didn't help: **27 actions**, still cleared.

**3. More objects doesn't fix it either.** "Touch everything, then the goal" is a general solution to any gate, whatever the count. So a wrong touch has to **cost** something: standing on a distractor clears what you've collected. Identifying *which* object is the gate is now the task.

## Keeping them rungs and not walls

A distractor at `(1, 3)` sat on the straight line from the agent to the key, making the level unsolvable **even by a solver holding the answer**. Moved off the direct paths — the question is which object is the gate, not how to navigate hazards, and conflating them measures the wrong thing.

# Notes

**One forgiving property recorded rather than tuned away:** walking from the key to the `(6,1)` distractor travels along row 6 and passes *over* the goal while the gate is held, winning incidentally. The visit-everything test routes via `(3,3)` so that isn't misread as evidence.

**For whatever plays a third environment:** `play.py` detects the final clear with `agent cell == goal cell` — true for ZetaChase, false in general, since ZetaDiscovery's win isn't standing on the `goal`. The general signal is `GameState.WIN`, because `next_level()` calls `win()` on the last level instead of bumping `level_index`.

**The frontier, stated plainly:** no agent we have clears these. The pixel agent has no mechanism for *I did the thing and nothing happened, so try something else* — it routes to the nearest non-self component and keeps routing. That capability is the point of the rung, and it isn't built.
