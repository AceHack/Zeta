## Description

`package.json` ran bare `markdownlint-cli2` with no glob, and `.markdownlint-cli2.jsonc` has no `globs` key. With neither supplying a file set, **the tool lints nothing and exits 0** — the local command could not fail.

CI is unaffected — `gate.yml:1200` passes the glob explicitly:

```
mise exec -- markdownlint-cli2 "**/*.md"
```

## Why it matters

A contributor runs `bun run lint:markdown`, sees it pass, pushes, and CI fails on markdown the local command never looked at. That is the exact failure class this repo has been cataloguing today — **a check that did not run, presenting as one that passed** — sitting in our own tooling.

Found the honest way: an agent was handed `bun run lint:markdown` to reproduce a red `lint (markdownlint)` check on #10700, and the command reported the file clean while CI kept failing on it.
