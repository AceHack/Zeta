## Description

Follow-on to #13476 — same defect class, different mechanism.

The apt phase on `ubuntu-slim` is fixed and measured (148s → 37–82s). The install step **still** spends 76s running `./configure && make install` for **E prover**, a first-order theorem prover, on the 1-vCPU runner whose entire job is `dotnet build` on one csproj.

**Measured**, run `32539360563` step 7:

```
13:31:31  ↓ from-autotools-tarball: eprover ← .../E-3.2.0.tar.gz
14:47:57  ✓ from-autotools-tarball eprover: installed at ~/.local/bin/eprover
          = 76s of a 353s install step, on a job capped at 840s
```

That is **9% of the whole budget**, spent on a binary this lane never invokes.

`from-dotnet-global` has honoured `tier=` since `081KTWQZY7F`; this mechanism did not — and it is the one that pays most for lacking it, since a source build is the most expensive thing per byte in the install graph and the cost lands hardest exactly where it is least affordable.

## What this does NOT fix — the bigger number

The lane's remaining budget pressure is **`dotnet build` itself**, not overhead. Across five post-fix runs it ranged **151s to 453s**, and the 453s run (`32543444813`) used **764s of 840s = 91.0%** while its install step was the *shortest* of the five at 207s. That is contention on a 1-vCPU runner doing the lane's actual payload, and no install-side lever touches it. Removing eprover would have brought that run to ≈688s = 82% — better, not solved. Named here so nobody has to re-derive it.

## Coverage unchanged

Every formal-verification lane that uses `eprover` runs on `ubuntu-24.04`, which resolves to `tier=full`. Only `ubuntu-slim` is slim, and only `low-memory.yml` uses `ubuntu-slim`.

## Falsifiers

In `from-autotools-tarball.test.ts`, reading the real manifest through the real tier predicates (`tierFromAttrs` / `tierAllows` / `resolveHostTier`) — the same two the realizer calls, so the assertion cannot drift from the behaviour:

- a slim host builds **nothing** from source
- a full host builds **everything** the manifest lists (the gate subtracts, never adds)
- **every row must carry an explicit `tier=`** — so adding a row and forgetting the token cannot silently put another source build back on the slim runner
