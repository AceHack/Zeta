## Description

## `main` is red — a defect pin fired and was left firing

`lint (bash retirement inventory + hygiene unit tests)` has been failing on `main` since PR #10860:

```
(fail) enrolment in audit-workflow-cli-flags >
       hasClosedFlagSet is fooled by prose — a tool with no parser can read as closed
Expected: true, Received: false
```

**Nothing is broken.** That test is a deliberate **DEFECT PIN** — it asserted the fooled-by-prose behaviour on purpose, and its own comment says why:

> This is NOT a fix … This test exists so the day that stops being true is visible.

PR #10860 made `hasClosedFlagSet` read `stripComments(source)`. **The day arrived and the pin fired, exactly as designed.** What was missing is the other half of the handshake: **a pin that fires must be rewritten to assert the fix, not left red.** #10860 landed the fix without closing its own pin.

## The change

The same input now pins the **fixed** behaviour, in both directions:

- a file that only *discusses* unknown arguments in a comment does not read as having a closed parser;
- the detector gives the same answer on pre-stripped text (it strips comments itself, so the caller's choice must not matter);
- plus a live diagnostic, so the tightening cannot read as simply having turned the detector off.
