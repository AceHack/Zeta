## Description

`pr-manifest-integrity` went red on main at 06:34Z (run 32107528665) with exit code 1 --
"Derived index drift outlived the repair cadence". This is the repair the workflow itself
prescribes, run verbatim:

    bun src/Core.TypeScript/forge-host/github/derive-pr-manifest.ts --write

WHY THIS IS A REPAIR AND NOT AN AUTHORING DECISION. The shards are the ledger; the manifest
is a DERIVED index of them. Regenerating it from the shards cannot invent a fact -- it can
only restate what the shards already record. Exit 1 is precisely the "index is behind"
signal, distinct from exit 2 ("a shard is unreadable, misfiled, or duplicate-keyed"), which
would be substrate loss and is NOT what fired here.

MEASURED, not assumed:
  - 6918 lines before, 8126 after; `git diff --stat` reports 1208 insertions and ZERO
    deletions. The repair is a pure APPEND of rows the index was missing. No existing row
    was reordered or edited.
  - 8126 lines, 8126 distinct `pr_number`, 8126 distinct whole lines. One row per PR, which
    is the shape `pr-manifest-integrity` enforces.
  - Re-running the checker with no `--write` now reports "in sync ... ✓" and exits 0, so
    this is a fixed point, not a step toward one.

WHY PURE-APPEND MATTERS BEYOND TIDINESS, and it is the reason this was measured before
being pushed rather than after: `.gitattributes` declares this file `merge=union`, and that
declaration's stated limit is that union is WRONG for an edit to an existing row. A repair
that REORDERED rows would meet the live heartbeat lanes' copies under union and could
duplicate them -- turning an index-drift warning into the duplicate-key failure that is
exit 2. Zero deletions is the evidence that this repair stays inside the declared contract.

WHAT THIS DOES NOT FIX, stated because main will go red again otherwise and someone should
know why. The drift is a SYMPTOM. The workflow names its own repair writer: "agent-heartbeat.yml,
soraya archive duty". That lane has been failing every tick since at least 05:11Z on
`CONFLICT (add/add)` in `docs/history/pr-reviews/PR-####-*.md` -- the seventh member of the
lane-path conflict class, and the one deliberately NOT declared in `.gitattributes` because
the two sides there are SUBSTANTIVELY divergent (main's copy of one measured file records
ZERO review threads where the lane's records a real one), so `theirs` would silently drop a
recorded review thread. That is the exact failure mode the sixth path's own comment warns
must never be assumed. Until soraya's lane can land again, the index will drift again and
this repair will need repeating. The durable fix is upstream of the merge layer and is left
for Aaron with the measurement in hand.
