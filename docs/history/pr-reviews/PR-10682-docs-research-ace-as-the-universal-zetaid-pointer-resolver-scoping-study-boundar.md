## Description

**Scoping study — design and boundaries, not a build.** Auto-merge deliberately **not** armed.

## The structural finding, first

**The resolver already exists in this repo, in two halves that do not reference each other.**

- `src/Core.TypeScript/ace/` — bytes, content hashes, Ed25519 trust, dependency solving, the capability declaration (#10675). Has **no notion of a running process**, as its own `INSTALL_TIME_VS_RUNTIME` constant states.
- `src/Core.TypeScript/service/` — `IServiceManager` + `LaunchdAdapter`/`SystemdAdapter`/`TaskSchedulerAdapter` + an OS-detecting factory. Has **no notion of content identity, trust, or capability**; it is keyed on a persona *string* against a hardcoded array.

Verified by search: neither imports the other. That reframes the work from *build a resolver* to *join two halves and repair the seam*.

## Target kinds — eight, closed by a principle

Classified by **what the resolver still owns after `resolve` returns**: Inert · Ambient · Oneshot · Periodic · Resident · Attached · Endpoint · Unresolvable-here.

**The Resident row is empty, and that is the scope win.** Every "background service" here is *Periodic* — launchd `StartInterval`, systemd `.timer` + `Type=oneshot`, Task Scheduler `<Repetition>`. Nothing is a long-lived daemon with a restart policy. Periodic genuinely abstracts across the three; **Resident is where systemd/launchd/SCM stop agreeing** and is what makes people say service management does not abstract. So Resident stays out.

`Unresolvable-here` must be a **value**, not an exception, or a caller cannot refuse a weak adapter.

## Resolver/supervisor line

The resolver owns the first transition into the target state plus the **declaration** of the invariant; it never owns maintaining it. Not invented here — `docs/writer-actor-routing-model.md` already says *"Persona = owner/supervisor of many actors, NOT an actor itself"*, and Aaron's own bound in `081KTHTPPCD…` is *"zetaids are viruses, they need a host."* The host is the supervisor.

**Falsifiable test:** `resolve` must return without ever polling a process. A retry-until-healthy loop anywhere reachable from `resolve` means the line broke.

**What the line costs, said plainly:** the resolver cannot answer "is it working?" Health belongs to whoever observes the *effect* — already the heartbeat-via-commit discipline, which deliberately does not trust a process's self-report.

## Idempotency key

A minted ZetaId spends **48 bits on `Timestamp` and 32 on `Randomness`** (`BitLayout.fs`), so minting is not a function of the thing named and **the ZetaId cannot be the key**. Only `Category.ContentAddress = 9uy` is content-derived.

Key: `ContentAddress(BLAKE3(realization spec))` over `(target-kind, content_hash, entrypoint, argv, declared env, capability list, schedule, machine-selector)` — **excluding** the requested ZetaId (or two names start two processes) and **including** the capability list (same bytes, different declaration is a different realization).

The move: write that key into the **scheduler artifact's own name** (launchd `Label`, systemd unit, task name), so apply-twice is idempotent *by the OS's namespace* rather than by our bookkeeping. A natural key, not a retry guard.

`gen(gen) == gen` **holds on the ContentAddress projection and cannot hold on minted ids** — stated rather than claimed globally.

## Distributed cron

Fires on a monotone phase counter **in the shared fold** — the `origin/main` commit DAG, already this repo's externalized counter. Local time may choose the **poll rate** and nothing else. Two nodes with different clocks *notice* at different local times and fire on the same phases in the same order.

**Honest bound, not buried:** this gives per-phase exactly-once, **not punctuality**. "Every 60 seconds" is not expressible without local time. Wall-clock schedules need a separate `Periodic-local` kind carrying a declared guarantee that it **does not join the shared fold** — do not let the two share a type, because sharing a type is how the leak returns via someone reaching for the nearest abstraction.

## Five findings, found by looking

1. **Persona-vs-occupancy is already broken in production.** `~/Library/LaunchAgents/com.lucent.zeta.otto.plist` has `Label = com.lucent.zeta.otto` but `ProgramArguments = tools/kiro/kiro-loop-wrapper.sh` with `ZETA_KIRO_LOOP_*` env. Meanwhile `persona-registry.ts` declares Otto's label as `com.lucent.zeta.otto-loop`, **which does not exist on this machine**. The live job reports `runs = 1`, `last exit code = 78: EX_CONFIG`. The name froze the persona, the contents rotated, and nothing detects it.
2. **`ServiceState` cannot distinguish healthy from broken.** `com.lucent.zeta.kiro-loop` — `runs = 1508`, `last exit code = 0` — reports `installed-stopped`, because `status()` greps for `state = running` and a periodic job is idle ~95% of the time. The crashing job above reports `not-installed`. And `SystemdAdapter.status()` asks `systemctl is-active <name>.timer` — **the timer stays active while every service invocation fails**. launchd exposes `last exit code` and the adapter does not read it.
3. **`install()` is not idempotent in effect (§12).** `LaunchdAdapter.install()` calls `uninstall()` first; `host-loop-bootstrap.sh:170-172` does `bootout` then `load -w`. Both **kill an in-flight agent tick on every re-apply**. The docstring says "Idempotent (reinstalls if exists)" — idempotent on the plist, not on the process.
4. **`cluster-cells` over-promises convergence.** It states *"re-run install, node converges"*; `install.sh:259` provisions **macOS + launchd only**, and `host-loop-bootstrap.sh:37` says *"Linux systemd: future."*
5. **No `loginctl enable-linger` anywhere** (verified by search), so the systemd adapter does not survive logout either — the same gap launchd and Task Scheduler have, undeclared in all three.

## How the proposed check fails

The adapter guarantee vector is **self-declared** — `source`, never `authorization`, exactly as `capability-manifest.ts` established. It fails whenever declaration and template drift. Mitigation is a probe per guarantee, and some probes are not CI-runnable (`survives-logout` has no CI logout). So **`declared-unprobed` must remain a distinct value from `probed-true`**; collapsing them to one boolean makes this the eleventh check that could not fail. Guarantees are declared per `(adapter × template)` pair — `bounded-run-time` is true on Windows because the XML says `PT5M`, a property of the template, not the OS. DV2.0: the vector is a satellite of the template.

## The boundary — what this does NOT do

Not a supervisor · not an enforcer · **not a runtime identity, and it makes that gap worse** (a live process people will believe is "the verified package") · not a placement engine · not wall-clock cron · no Resident kind · user scope only (root units need an escalation the shadow may inherit but not extend) · not a replacement for Nix/brew/apt · **not uninstall-complete for Ambient targets** · refuses on adapters that do not declare `converges`.

## Verdict

Service and cron **are** closeable here, and the reason is narrower than the ambition: this repo does not need a universal *daemon* abstraction — the thing that does not abstract. It needs universal *periodic-with-declared-guarantees* plus a content-derived key. Two leaks are named and confined rather than papered over: **punctuality** (→ `Periodic-local`) and **ambient reversal** (→ declared-incomplete).
