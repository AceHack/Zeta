## Description

#9910 fixed `lint (tick-shard relative-paths)` after four cancellations in one day. **That was fixing the instance I tripped over.** Measuring the class shows **seven** jobs with the same defect:

| job | budget |
|---|---|
| `lint (shellcheck)` | 5min |
| `lint (tick-history order)` | 5min |
| `lint (archive header §33)` | 5min |
| `lint (§33 migration xrefs)` | 5min |
| `lint (markdownlint)` | 5min |
| `lint (TS)` | 5min |
| `cross-verify (trust-core oracles + ace)` | 5min |

Each runs `./tools/setup/install.sh` — the full three-way-parity toolchain — before doing seconds-to-minutes of actual work. **The lint isn't the cost; the install is.**

## Why this matters more than it looks

**A cancelled job renders as a red check indistinguishable from a real failure.** Today that produced at least five spurious reds across unrelated PRs (#9893 ×2, #9903, #9908, #9912), each needing *"is this mine or infrastructure?"* triage before dismissal.

Same false-signal class this repo spent the day removing everywhere else — **a check that says FAIL when it means I RAN OUT OF TIME.**

Observed cancellations: **316s, 317s** against a **300s** budget. Systematically at the edge, not randomly flaky.

## Still not fixed, and stated rather than buried

These jobs mostly need only a JS runtime — `audit-tick-shard-relative-paths.ts` imports **only node built-ins**. `gate.yml` runs `install.sh` in **64** jobs and `setup-bun` in **2**.

Caching the install output or using `setup-bun` for runtime-only jobs would *remove* the cost rather than accommodate it. But the Actions cache is **already at 10.05GB of a 10GB ceiling**, and §24 makes `install.sh` the single install path consumed three ways. Both need a deliberate decision.

**Raising the budget buys time without pretending the underlying waste is fixed.**
