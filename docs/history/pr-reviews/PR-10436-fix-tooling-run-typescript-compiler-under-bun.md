## Description

## Why

The TypeScript gate currently invokes `bun x tsc`. TypeScript's executable has a Node shebang, so that path enters Node even though the repository runtime is Bun.

On this macOS arm64 host, Node 24.16.0 produced three native `SIGSEGV` crash reports in V8 garbage-collection workers on 2026-08-13. One occurred after Bun tests passed and before `bun x tsc` emitted any TypeScript diagnostic. The same checked-in compiler completes when Bun executes its JavaScript entry point directly.

## What changed

- Execute `node_modules/typescript/bin/tsc` directly under Bun in the lint wrapper.
- Route the public `typecheck` package script through the same Bun-owned boundary.
- Test the exact compiler command so `bun x` or Node cannot quietly return.
- Update the current TS/Bun scripting checklist.
- Keep TypeScript version, semantics, diagnostics, and retry behavior unchanged.
- Release the git-native claim in the same PR.
