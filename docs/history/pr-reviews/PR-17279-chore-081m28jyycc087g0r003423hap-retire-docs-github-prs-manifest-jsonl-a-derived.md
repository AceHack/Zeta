## Description

Retires a derived index with **no reader**, after proving containment rather than assuming it.

Aaron cleared this conditionally: "we are moving away from this, if all its
information is contained elsewhere now we can delete it." CONTAINMENT WAS
PROVEN BEFORE ANYTHING WAS DELETED, not assumed:

  manifest lines                       13,592
  with NO shard at all                      0
  identical to their shard             13,475
  differing                               117   <- and the manifest is WRONG

The 117 differ in `commit_sha`: the manifest recorded the repo HEAD at write
time instead of the PR's own merge commit. PR #16014's line says
`e7b4cba597`, which is #16030's merge commit; the shard says `c3f9b017a9`,
and the forge agrees with the shard. So this was never a second copy of the
truth -- it was a stale one that disagreed with its source.

WHY IT DECAYED, which is the part worth recording. The manifest is a DERIVED
index ("the shards are the ledger, the manifest is a DERIVED index" --
derive-pr-manifest.ts's own first line), kept current by
`agent-heartbeat.yml` running `derive-pr-manifest.ts --write`. That lane was
paused on 2026-08-29 along with a batch of cadence workflows, deliberately,
because they were causing spiraling growth pending a redesign. The index then
rotted exactly as an ungated derived file does, and `pr-manifest-integrity`
-- the gate that would have said so -- was paused in the same batch.

WHAT CHANGED

 - The file is deleted and `archive-pr-reviews.ts` no longer writes it.
   `WRITE_TARGETS` drops it too, so a workflow staging that path no longer
   stages something that never changes.
 - `derive-pr-manifest.ts` is KEPT and now distinguishes RETIRED from DRIFTED.
   An absent manifest in check mode is exit 0 with a sentence saying the shard
   store is the ledger; without that arm it reads absence as an empty file and
   reports every derived line as drift forever -- a check that cannot pass,
   landing on whoever re-enables the gate after the redesign, who is the person
   least equipped to know why.
 - `--write` is deliberately NOT short-circuited. Regenerating the view on
   demand is what makes deleting the committed copy LOSSLESS rather than merely
   tidy, and it was exercised: `--write` rebuilt all 14,378 entries from the
   shards, then the file was removed again.

THE GENERAL SMELL, MEASURED. Aaron: any single file rewritten over and over on
a cadence is a huge smell where history is forever. This file had 433 committed
versions. HONEST ABOUT THE NUMBER: their uncompressed sum is 1,594.7 MB, but
`.git` is 668 MB packed -- git delta-compresses near-identical appends, so
that figure is NOT repo growth and quoting it as such would be misleading. What
is true is the permanence, and that the cost is paid on every clone forever.

And this file is only EIGHTH by rewrite count. Measured over all history:
tick-history.json 1097, tick-latest.json 1095, BACKLOG.md 969, MEMORY.md 846,
loop-tick-history.md 696, latest.json 605, drift-mtth.json 463, then this at
439. The `*-latest` files are the clearest candidates for
overwrite-without-history, since a "latest" pointer's history is precisely the
thing that is noise -- the history IS the other file.

Nothing reads the manifest: measured, its only references were its writer and
its own deriver. The paused `pr-manifest-integrity` workflow is left alone --
retiring a governance surface belongs to the redesign, not to this change.
