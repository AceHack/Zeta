## Description

> Aaron: *"stage db/ in the heartbeat so findings get recorded."*

## The problem #10319 could only name

The false-alarm rate could be computed as false/**resolved** but not SLAM's false/**reported**, because nothing recorded the reports: the runner wrote a transcript entry only under `--choose`, and the heartbeat never staged `db/`, so a CI-tick write landed in a checkout that was thrown away.

Resolution is voluntary, so that sample is biased by construction — measurably so. The first readout showed **2 resolutions, both false alarms, zero real gaps**, in a session where four real gaps had been found and fixed by PR.

## What landed

- **`mutation-findings.ts`** — every observation appended to `db/mutation-findings/<agent>.jsonl`, all three outcomes *including* `distinguished`, because "the suite did its job" is exactly the population an alarm rate is a fraction of.
- The runner records **unconditionally**, not just on `--choose`.
- The heartbeat stages `db/mutation-findings/` — scoped exactly, never `git add -A` (the rule §159 already states for the healer). Commits land on `heartbeat/<agent>` and drain through the existing `flush-to-main`.
- The metric gains `alarmsReported` and `resolutionCoverage`.

## Idempotency is load-bearing here

Selection is deterministic in `(agent, tick)`, so a re-run — manual dispatch over the same commit, a retried job — observes the **identical** finding. Appending twice would inflate the denominator and silently *deflate* every rate divided by it. Records are keyed by content address; a matching append is a no-op. The address deliberately excludes any clock, since a timestamp would make every re-run "new" and defeat the guard entirely.

## Recording the population doesn't make the subset fair

An unresolved alarm is still an alarm nobody classified. So the rate is withheld on **two independent conditions**, reported separately because they have different fixes:

| condition | meaning | fix |
|---|---|---|
| `MIN_SAMPLE` | too few resolutions | resolve more |
| `MIN_COVERAGE` | too small a slice of the alarm population | resolve a **fairer** slice |

`slamComparable` is true only when both hold.

## A real bug caught while falsifying this

A stray edit turned the address encoding from a separated join into a bare concatenation — and **all ten existing tests still passed**. They vary one field at a time, and concatenation only collides *across* field boundaries: `("ab","c")` and `("a","bc")` become the same observation, merging two distinct dimensions into one denominator entry.

The encoding is now `JSON.stringify` — unambiguous by construction rather than by an argument about separators — with a test for the boundary case the others structurally could not reach.
