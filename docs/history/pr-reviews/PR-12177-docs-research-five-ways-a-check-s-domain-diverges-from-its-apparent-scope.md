## Description

docs(research): five ways a check's domain diverges from its apparent scope

Five separate findings today, five different lanes, five DIFFERENT mechanisms, one shared signature:
the check's EFFECTIVE domain was narrower than its APPARENT domain, and nothing in the green signal
carried the difference. Each was a real check, written in good faith, that ran and reported success
over a set not containing the thing it was believed to cover.

NOT A NEW CLASS. The vacuity class is already named — a check that cannot fail is not a check — and
toy-is-free-metered-must-be-earned plus mutation-runner exist to catch it. This is a taxonomy of
MECHANISMS, collected because five turned up in one day.

(1) STALE ROSTER ROW — the allowlist pinned 3 setTimeout sites in a file that now has 0, so the row
excluded nothing. Caught by the guard's own anti-vacuity check, and notable because the row had been
WRITTEN AS A HANDOFF predicting exactly that red. (2) EMPTY GLOB — markdownlint against a path
matching no files exits 0; a lint that scanned zero files is indistinguishable by exit code from one
that scanned many. Caught only when a commit reported a clean tree where a diff was expected. (3)
CONSTANT-TAIL ASSERTION — zflash's warning shipped with every interpolation empty, and 90 tests
stayed green because each asserted a substring of the CONSTANT tail, which cannot fail whatever the
variable part holds. (4) TRIGGER WIDER THAN VALIDATOR SCOPE — helm-validate triggered on
infra/k8s/** while its validator scanned only infra/k8s/applications, so a bootstrap change ran a
lane that structurally could not see it. (5) READING A VERDICT WITHOUT ITS PROVENANCE — the OBSERVER
version, and the one an operator commits: GitHub's rollup retains stale entries, so a superseded
FAILURE and a current one look identical; three misreads in one session, including chasing a failure
that had self-corrected two minutes earlier.

WHAT THE FIXES HAD IN COMMON, and it is the actionable part: every instance fixed WELL was fixed the
same way, independently, by different lanes — MAKE THE CHECK REPORT ITS DOMAIN, NOT JUST ITS
VERDICT. The ambient-time guard prints "1066 test files scanned"; the collation ratchet names the
file and its counts; the apt guard names the stalled mirror instead of dying silently at its
timeout; the bootstrap falsifier reports 20 passed / 1 failed against the pre-fix file. A verdict is
one bit and carries no coverage information; a reported domain makes a SHRINKING domain visible as a
falling number rather than an unchanged green. Instance 1 was caught precisely because a count was
pinned; 2-4 were invisible because nothing was counted.

Stated as an observation rather than proposed as a rule, since rule additions here are razored and
carry a cooling period: a check should emit WHAT IT COVERED, and if its output cannot distinguish
"scanned 1000, found nothing" from "scanned 0", its green is not evidence.

HONEST LIMIT: five instances in one day is not a survey, and five is exactly the sample size at
which a pattern feels more established than it is. They ARE genuinely independent — five lanes, five
mechanisms, no shared code path — which is what makes the shared signature worth recording. But the
register is "five mechanisms observed", not "the complete taxonomy", and a sixth should be expected
rather than surprising.
