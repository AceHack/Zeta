## Description

fix(observe): decorrelation-meter sorted by localeCompare — culture-SENSITIVE

`lint-no-culture-sensitive-collation` is red on `main` since #14848:
`decorrelation-meter.ts` (1 found, baseline allows 0). Line 141 sorted decisions
with `a.at.localeCompare(b.at)`.

`localeCompare` with no locale is culture-SENSITIVE and ICU-dependent, so two
machines can order the same decisions differently. For a FOLD that is the whole
problem: keys sort differently per machine, so DST replay and the N-oracle
byte-lock diverge — the exact failure 081KT07NV0008QG0R001YDB73K is on file for
(`GCounter.Merge` ordinal vs `ZSet.ofSeq` culture-sensitive, non-associative on
special keys).

Fixed with `stringCompare` from `src/Core.TypeScript/collation/collation.ts` —
the repo's TREATY collation (code point == UTF-8 byte order), not the `<`/`>`
fallback. The lint offers both and they are not equivalent: `<`/`>` is UTF-16
code-unit order, deterministic but DIVERGENT from the other oracles above the
BMP, and a decorrelation meter is a cross-oracle surface. `.at` is an ISO
timestamp so the two agree today; the treaty form is what keeps that true if the
field ever widens.

I first wrote the `<`/`>` form, on the reasoning that the only `ordinalCompare`
exports live under `ace/` and `observe/` should not depend on `ace/`. That was
an incomplete search — `collation/collation.ts` is a proper shared module and
the correct source. Corrected before commit.
