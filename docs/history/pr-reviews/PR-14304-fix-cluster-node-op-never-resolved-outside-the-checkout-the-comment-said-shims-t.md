## Description

## What Aaron hit

From his home directory:

```
(max) ➜  ~ op
zsh: command not found: op
```

Measured, before changing anything:

| probe | result |
|---|---|
| `command -v op` from `~` | **NOT FOUND** |
| `command -v op` from the repo | `…/mise/installs/1password-cli/2.34.1/op` |
| `~/.config/mise/config.toml` | does not exist |
| shims dirs in a login PATH | **0** |

Not a missing package, not missing activation. `mise activate` without `--shims` is project-scoped.

## The first read was wrong

The obvious conclusion — "pinned tools do not resolve globally, fix it everywhere" — is the one Aaron rejected:

> *"it's like local scoped dotnet or npm or other similar tools, that works great we don't need to global"* · *"i see op when i'm in zeta"*

On a **developer workstation** that behaviour is the design working: the pin travels with the project, exactly like a local `dotnet tool` manifest or `node_modules/.bin`. Making it global would let a pinned tool escape its pin.

**So `tools/setup/common/shellenv.sh` keeps pure-PATH activation and `install.ps1` is untouched.** Its only change here is comment text.

## Where it *is* a real gap

> *"well for the linux real hardware we might need it global for op"* — Aaron, 2026-08-22

Two host classes, two correct answers:

| host class | correct behaviour | why |
|---|---|---|
| developer workstation | project-scoped — **unchanged** | a checkout is always present |
| Linux cluster node | **global is legitimate** | a node bootstrapping secrets is a login shell in `$HOME` or a systemd unit — there is nothing to scope to |

## What hid it

`common.nix` asserted, twice, that *"mise activate writes shims to `~/.local/share/mise/shims/` and adds them to PATH automatically."* **That is false without `--shims`** — measured, the shims dir appears **0** times in a login PATH.

Eleven other node call sites already work around this by hardcoding the shims dir into unit PATHs (`zeta-ai-agent.nix`, `zeta-creds-restore.nix`, `zeta-first-session.nix`, `zeta-install.sh`). The `profile.d` snippet — the only surface a node's **login shell** sources — was the one place still trusting the comment.

## The obvious fix is not enough, and measuring said so

My prior was "append the shims dir to PATH". Clean env, from `~`:

```
shims on PATH only              ->  mise ERROR No version is set for shim: op
shims + MISE_GLOBAL_CONFIG_FILE ->  2.34.1
```

The shim dispatches **back** to mise, and outside a project mise has no config declaring the tool. Both halves are load-bearing.

Pointing mise's **global** config at the node's own checkout supplies one **without duplicating the pin** — the version still comes from `.mise.toml:114` (`"1password-cli" = "2.34.1"`), the single source of truth.

**Rejected:** `mise use -g`, and a nixpkgs `_1password-cli`. Either forks the version — the exact drift Aaron already caught on this same file for bun (*"we already do this we've drifted for nixos for some reason for bun"*). Note `op` is currently declared in **no** cluster nix surface at all; nodes get it from `.mise.toml` via `install.sh`.

Shims are **appended**, not prepended, so in-checkout resolution keeps the direct fast path — measured 100 × `op --version`: **1.47s direct vs 5.98s via shim (~4x)**, same direction as the ~10x the docs claim.

## The falsifier

`full-ai-cluster/nixos/modules/mise-node-path-wiring.test.ts`. Comments are stripped before every check, so the rationale block cannot satisfy it. It pins **both** directions — the node resolves globally, *and* the workstation stays project-scoped so nobody "makes it consistent" later.

Proven to discriminate — five independent breaks, each → red, restore → green:

| break | result |
|---|---|
| remove the shims PATH append | 🔴 1 fail |
| drop `MISE_GLOBAL_CONFIG_FILE` | 🔴 2 fail |
| swap in `mise use -g` (duplicate pin) | 🔴 2 fail |
| prepend shims instead of append | 🔴 1 fail |
| drop the interim label | 🔴 1 fail |
| restored | 🟢 7 pass |

A first draft of the workstation guard was **too broad** and its own test caught it: `shellenv.sh` does name the shims dir, but only inside the `$GITHUB_PATH` block — CI, where every step runs at the repo root. The assertion is now scoped to the generator block that writes `~/.config/zeta/shellenv.sh`, and the correction is recorded in the test.

`full-ai-cluster/`: **325 pass, 0 fail.** `nix-instantiate --parse` clean; the emitted `profile.d` snippet passes `bash -n` + `shellcheck`.

## Recorded, not resolved — the interim hub

Routing node secrets through one vendor means a node **has no exit**, which is an **appointed hub** under manifesto §1 and `itron-hub-patent-boundary-p2p-is-the-upgrade.md`. Aaron named it interim himself:

> *"not sure if that's how we are going to share shared secrets **until we have a decentralized way of doing it**"*

So it is labelled inline and tracked at **081M0QS0ET7087G0R000YBRKNT** rather than silently normalised — a dependency nobody marked temporary is one nobody removes. The replacement is **`proposed` only**, is not designed here, and belongs to the decentralized-identity-server lane (the row points at the `sops`/`age` machinery already in `flake.nix` as the exit-carrying starting point).
