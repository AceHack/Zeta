## Description

## What this prices

`mise` installs `bun`, so whatever installs `mise` cannot be written in `bun`.
Stage-0 shell is **essential** complexity and this change never argues with it.
What is accidental is the number of **doors**.

> An **independent stage-0 entry point** is an allowlisted shell-family file that
> no other allowlisted shell-family file invokes — a root of the stage-0 shell
> invocation graph — unless it declares itself a door with a header marker.

A file only another stage-0 script invokes sits one hop behind a door that is
already documented, already cold-tested, already on someone's map. A file
something *outside* the graph must name is what costs.

**Measured at `07aa44b3f1`: 18 independent · 12 internal · 21 invocation edges ·
453 975 bytes.** Three of the 18 (`githooks/pre-push`, `scripts/hooks/commit-msg`,
`scripts/hooks/pre-push`) carry no `.sh` suffix, so any `*.sh` glob under-reports
the surface by three — the allowlist is the denominator, reused from
`check-bash-retirement-inventory.ts` rather than re-derived.

## Why this cut and not file count

1. **It fixes the naive "is it sourced?" heuristic.** `tools/setup/macos.sh` is
   SPAWNED by `install.sh`, never sourced, and is still not an entry point.
   Sourcing is one invocation form; the graph edge is what matters. Pinned by a
   test that dies under the naive rule.
2. **Zero pressure to merge bootstrap-ordered splits.** `mise.sh` → `shellenv.sh`
   → `profile-edit.sh` are all internal, therefore free. The metric *cannot*
   reward merging them, because merging them does not move it. Structural, not a
   promise.
3. **Concatenation-resistant.** `cat a.sh b.sh > ab.sh` on two internal files moves
   the number by 0. On two doors it moves it by 1 — and the byte-guard refuses that
   trade unless the surface actually shrank.

## Ratchet, not report

`independent` may never rise; when it falls, `bytes` may not rise.

Report-only has already failed here: the retained shell allowlist has been
enforced on set-equality since #8216 and the surface still grew to 30 entries,
because nothing ever pushed the number *down*.

Wedge risk is answered by an escape hatch with a ledger — a genuinely new door is
recorded in `exceptions` with a reason and passes. The byte clause fires only on
the exact signature "fewer doors, more bytes"; ordinary work that grows a script
while the door count holds is untouched, and a test goes red if that carve-out is
removed.

## Wired into `cross-verify`, not the bash-retirement job

`lint-bash-retirement-inventory` is **not** in `gate-required.needs`, so everything
it runs blocks nothing — the existing shell allowlist has been advisory the whole
time it has been read as a guard. A ratchet that cannot fail a merge is a number,
not a ratchet, so this goes on the floor beside `audit-proof-lineage-binaries.ts`.

## The one assertion

    # zeta-stage0-entrypoint: <reason>

`install.sh` needs it — `zeta-install.sh` re-enters it on the NixOS live-USB path,
which would file the repo's primary documented door as "internal". The declaration
can only ever make the ratcheted number **worse** for whoever writes it, and an
assertion whose sole effect is to raise your own bill is self-enforcing.

## Falsifiers

- **32 tests.** Four fix live parser false positives found while building it: a URL

  *written* not run (`profile-edit.sh:31`), an `&&` inside a double-quoted error
  message (`zeta-install.sh:3286`), and heredoc bodies that print script names.
  False edges are the dangerous direction — they make a door look internal.
- **13 mutants, 13 killed.** Quote-aware splitting · single-quote stripping ·

- **Five end-to-end controls** against the real tree, each able to come out the

## Honest limits (stated in the tool's own header)

- Variable-indirected invocation is invisible (`bash "$FLOOR_HOOK"`). Direction is
  safe: the target reads as independent, which over-counts.
- No cross-language caller detection. Measured, not assumed: of the TS files
  referencing `macos.sh`, `curl-fetch.sh` and `mise.sh`, **every hit was prose**. A
  regex-built cross-language detector gives a fuzzy denominator, which is worse
  than no number. So a script whose only caller is a bun realizer counts as
  independent — over-counting creates pressure to reduce, never permission to grow.

## CI diagnosis and fix (shadow, 2026-08-26)

Seven red checks, and triage split them cleanly into **one real defect surfaced twice**,
**one determinism defect**, and **an environmental flake** that was never this PR's.

### Real — both fixed in `7829c06`

Both live in the new `src/Core.TypeScript/hygiene/measure-stage0-independence.ts`.

**1. `lint (structural hygiene)` — a privilege elevator resolved by name.**
`WRAPPER_HEADS` opens with the literal `"sudo"`, which
`lint-no-path-resolved-privilege-elevator` reads as a by-name elevator. It is not one:
the set is a **parser vocabulary**, matched with `.has(token)` against shell text so the
invocation-graph walker can step *past* a wrapper to the real command. Nothing in it is
ever spawned. That is precisely the case the lint's own message names ("a parser's
vocabulary"), and precisely the waiver
`lint-no-path-resolved-privilege-elevator.ts:49` already takes for **its** own search
vocabulary. Marker added with its reason, scoped to one line — so a future genuine
`sudo` invocation in this file still goes red.

**2. `lint (bash retirement …)` + `test (TS hermetic)` — one defect, two red jobs.**
`byPath` sorted with `localeCompare`, which is ICU- and locale-dependent: two runners
could emit the same measurement in two different orders. For a tool whose entire output
is a diffed report that is a **determinism defect**, not a style nit
(`.claude/rules/culture-invariant-by-default.md`). Now `stringCompare` from
`src/Core.TypeScript/collation/collation.ts`.

`test (TS hermetic)` was the *same* violation seen from the other side — the collation
lint's own LIVE tripwire test asserting the tracked tree stays at or under baseline,
reporting this file as `(1 > 0)`.

No lint was widened and no baseline was raised.
`stage0-independence.baseline.json` stores a **count**, not an ordered list, so (2)
cannot move the ratchet.
