## Description

fix(observe): the corpus baseline test failed precisely when the feature started working

MAIN-WIDE RED. `verify-attestation-events.test.ts` "NO record in the corpus is
bound today" fails on origin/main: 380 records, 377 refused, `Expected: 380
Received: 377`. Reproduced locally on a clean origin/main checkout before
changing anything.

THE CAUSE, and it is the interesting part. The test asserted
`expect(report.refused).toBe(records.length)` -- true when written, because every
committed record predated `attestedDigest`. But records emitted by the FIXED
`emit-attestation` DO carry a digest, so they verify as `unbound` (well-formed,
merely unsigned) rather than `refused`. Three such records have now landed.

So the assertion pinned a SPLIT that moves every time the emitter runs, which
makes a green CI depend on nobody using the feature. That is the vacuity class
inverted: not a check that cannot fail, but one that fails precisely when the
thing it guards starts working. The test's own comment predicted it -- "the
number that must MOVE for the feature to have shipped anything" -- and then
pinned the number anyway.

THE FIX keeps the invariant and drops the snapshot:
  - `report.bound === 0` STAYS. That is the real claim: no key holder has signed
    a record, nothing is cryptographically bound. Mutation-checked -- changing it
    to `toBe(1)` reddens the test.
  - `report.refused + report.unbound === records.length` replaces the pinned
    split, and a second assertion makes the accounting exhaustive across all
    three bands so a record cannot silently escape classification.
  - The reproduced counts (380 / 377 / 3) are recorded in the comment as
    observation, not as an assertion.

11 pass / 0 fail. The mutation was run and reverted; a test that survives
mutation is not a falsifier.

Found while diagnosing why six armed PRs had stalled. I had re-run this gate
repeatedly on the assumption it was the fleet-wide toolchain-cancellation flake;
it was not, and re-running a genuine failure without reading it is exactly the
laundering the ratchet discipline forbids. The log said `(fail)`, not
`cancelled`, from the first run.
