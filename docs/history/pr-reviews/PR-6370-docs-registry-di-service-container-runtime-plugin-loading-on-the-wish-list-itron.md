## Description

Maintainer-directed survey of `Source/Extensions` + `Source/Runtime/Loader` (concept-only), added to the Itron-surveyed wish-list subsection.

The ask: "we need DI and plugin stuff like not having to reference every plugin at compile time and DI on wish list."

- **DI / service-container port** — register/resolve/scope/lifetime. Framed as a port, not a mandate: natural in .NET/TS, Rust prefers explicit/compile-time wiring.
- **Plugin modules loaded at RUNTIME not compile-time** — `IModule` self-configures its own config+logging+DI (`configureServices`); a `ModuleLoader` discovers + loads them. This is the maintainer's exact ask + the cross-language-valuable core.
- **Assembly/plugin resolver** — Itron's `AssemblyResolver` uses the older `AppDomain.AssemblyResolve`; **ours should use `AssemblyLoadContext`** (collectible/unloadable isolated plugin contexts).
- keyed/named DI (now BCL since .NET 8), `Lazy<T>` auto-register, **register-only-once** (idempotent — composes with the idempotency discipline).
- DNS-sourced config provider (config from DNS records) + **ServiceInfo identity enrichment** (name/version/instance into config + every log line — the "logging context" you flagged).

`ApplicationHost`/`IApplication` + `LogHeader` were already captured earlier. Docs-only; prettier + markdownlint clean; no backlog/index change.
