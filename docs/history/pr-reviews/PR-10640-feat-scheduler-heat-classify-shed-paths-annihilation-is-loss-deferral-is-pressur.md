## The deciding test

Already carved in the repo, in `SchedulerZeta`'s weak-referenced fixed-point table:

> *"Because the fixed points are **derived**, drop-and-recompute is **lossless**."*

So a shed is classified by **what survives it**, not by how it feels:

- **derived / handed back ⇒ PRESSURE** (`isPressure = true`). Deferral. Free.
- **annihilated, nothing retains a seed ⇒ LOSS.** It pays.

Same distinction the `WSet` sweep measured this morning: `negate` costs **0.000 bits** (reversible), `consolidate` costs **3.459 bits** (annihilates, two states to one). Free negation, paid annihilation — Landauer's point that only the *irreversible* step has a cost.

## The negative result: `SoftThrottle` only ever defers

**This is the main finding, and it means most of the work here was deciding not to build.**

| shed path | recoverable? | evidence |
|---|---|---|
| `boat` closes the boat | **yes** | `rest` (the unboarded tail, including the blocking item) is **returned**. `boat @ remaining = items`, exactly — now a property test over 300 seeded inputs. |
| `boatBytes` byte budget | **yes** | same partition, different limiter. |
| `step` serves a sip | **yes** | the shortfall is `want - served`; the caller supplied `want` and still holds both halves. |
| `wrapHandler` skip (gradient) | **yes** | `Inner` carried through bit-for-bit; `Served + Skipped = Tick` every tick. |
| `wrapHandler` skip (dry tank) | **yes** | ditto. |

And the deeper reason `wrapHandler` cannot be losing anything: it **never held the arrival as data**. `SoftScheduler.Handler.Run` is `ISR<'S,'S>` — it cannot see the crossing — and `SoftScheduler.Source` is `int -> InterruptKind list`, a pure function of the tick that the scheduler retains for the whole run. Derived ⇒ drop-and-recompute is lossless.

**So `SoftThrottle` emits pressure at most, and that is what it got**: `SchedulerShedHeat.throttlePressure` (kind `backpressure`, `Units = Skipped`), plus two conservation laws locking the negative claim. No loss meter was added there. `FerryThrottler` was audited the same way and drops nothing either — `BoundedChannelFullMode.Wait`, byte-budget overshoot goes to `pending`, cancelled requests already completed their caller's task.

`Vision.predictBranches` — the Rodney's-Razor big-O branch pruning Aaron named — returns its pruned branches **in `report.Deferred`**, in full, alongside the tank that refused them. A wider tank re-boards them. So branch pruning reads as **backpressure**, exactly as he framed it, not as forgetting.

## What actually annihilates: `CellScheduler`

Three previously-silent drops in a 0-count surface:

1. **`deliver` to a cell that does not exist** — `if not (Map.containsKey target s.Cells) then s`. The state is returned **unchanged**, so the post-state is identical for every possible payload. Nothing distinguishes it, nothing will redeliver it. **LOSS** → `HeatSignal.Forgotten`.
2. **`routeOutbox` malformed entry** — dropped by a `List.choose`, *and* the whole `__outbox__` key is stripped from the returned state, so it survives in neither the state nor the emission list. **LOSS** → `HeatSignal.Invalid`.
3. **`routeOutbox` non-`Array` outbox** — the entire outbox is stripped, nothing emitted. **LOSS** → `HeatSignal.Invalid`.

Deliberately **not** classified as loss:

- **`step`'s spurious-ready drop** — `Ready` is a *derived index* over `Inbox` (`readyOf` recomputes it exactly) and the dropped entry has an empty inbox, so it carries no payload. This is the `SchedulerZeta` case: emit nothing, correctly.
- **`softStep`'s refuse-to-collapse** — the full distribution `next` **is** the returned state. The cell holds its wonder; nothing is annihilated.

## No treaty change

**No `HeatSignal` case was added.** `Forgotten` / `Invalid` / `Backpressure` already carried every distinction found. A test asserts nothing this PR emits falls through to `HeatSignal.Other`.

`src/Core/Heat.fs` is **untouched** (Vera owns it). The classifier lives in a new `src/Core/SchedulerShedHeat.fs` compiled *after* `Heat.fs` — necessary anyway, since `Heat.fs` compiles at position 256 and `CellScheduler.fs` at 203, so the scheduler physically cannot reference `HeatSignature`. `CellScheduler` therefore reports a pure, Heat-free `CellShed` / `OutboxShed`, and the mapping into treaty vocabulary happens one layer up.

`src/Core/WSet.fs` untouched.

`MassPpm` is a **bounded fraction**, never a byte count: `HeatSignature.ofMass` scales by 1e6 into an `int64`, so a byte-denominated mass would overflow on a large budget. Skip fraction and unboarded fraction are dimensionless in `[0,1]`; absolute counts live in `Units` and `Detail`.

## Deliberately unmetered, named not hidden

`CellScheduler.softStep`'s `| Error _ -> remains, []` **is** a genuine loss — the scheduler has already consumed the head message and `evolveSoft`'s error payload is discarded, so neither survives. It is unmetered because `stepFn`'s signature (`'St -> 'Msg -> 'St * emissions`) has **no shed channel to return one on**; a `stepFn` can only meter its own shed by widening `'St`. Annotated `SHED: soft-step-evolve-error class=loss metered=no` and carried in the inventory so it cannot quietly become invisible.

**M3 is the one that matters**: the conservation identity catches a drop path *that did not exist when the test was written*, without any pattern-matching heuristic. `offered = consumed + shed` over 200 seeded societies with ghost targets, self-sends, and fan-out; a new drop breaks it by exactly what it swallowed.

Anti-vacuity is asserted, not assumed: every conservation test asserts its corpus **actually shed** (`totalShed > 0`, `sawPartial`), so a run that sheds nothing cannot pass by doing nothing.

## Guard coverage boundary (stated honestly)

- **Conservation** (mechanical, catches paths that do not exist yet): the `CellScheduler` routing path and `SoftThrottle.boat` / `routeOutbox`. This is the strong guard.
- **Classification**: annihilation must land on a non-pressure signal, deferral on a pressure one; swapping them is red.
- **Annotation inventory**: catches an annotated site that was never classified, and an annotation that was removed or edited. It does **not** catch an unannotated new drop — that is conservation's job, and conservation covers the routing and boat paths mechanically. I did not write a textual "find the drops" scanner; that shape is exactly the ~70%-false-positive detector-for-detectors trap.

## Behaviour is unchanged

`init`, `step`, `runToQuiescence`, `runFerryToQuiescence`, `routeOutbox` keep their exact signatures and delegate to the `*WithShed` variants — locked by a test asserting byte-identical results across 60 seeded societies. And `shed(DoP=1) == shed(DoP=4) == shed(DoP=16)`, extending the existing scale-free law to the heat channel.
