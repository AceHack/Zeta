## The flip did NOT happen, and that is the finding

`hardware.nvidia.open` is still `lib.mkDefault false` in both `gpu.nix` files. Work item
`081M00QP33F087G0R001JKB5QM` stays open, blocked on the same thing it was blocked on yesterday:
**no host config in this repo names its GPU**, so no node's eligibility for the open kernel modules
can be established.

Re-confirmed against the audited register — `inventory/items/` holds exactly one GPU:

```yaml
name: RTX 4090 Founders Edition
device_type: gpu
status: storage
location: lab-shelf
assignment_purpose: k3s gpu node (pending rack)
assigned_machine:            # empty
sample: true
```

`assigned_machine` empty, `status: storage`, `sample: true` — a card on a shelf, bound to no node.
`inventory/items.json` (the derived projection) carries the same single GPU. Every
`--node-label=zeta.io/gpu-model=…` in every GPU host is commented out; every
`hardware-configuration.nix` is a placeholder. The blocking item
`081M00R59KS087G0R001W3837V` is still open in `workitems/`.

Generation-wise there is no known obstacle — every NVIDIA card on the (self-flagged unreliable)
house roster is Ampere or newer, and the two named in `docs/HARDWARE-CAPABILITY-MATRIX.md` are a
4090 (Ada, cc 8.9) and a 3090 (Ampere, cc 8.6), both comfortably Turing+. But "probably no
pre-Turing card exists in the house" is not "this node's card is Turing+", and breaking a node to
close a work item is the wrong trade.

## What this PR does instead: gives the gate a falsifier

The item already shipped an eval-time gate that refuses an unattested `open = true`. Its behaviour
was verified **once, by hand, and by nothing since**:

```
$ grep -rln "openModulePreflight|nvidia-open" \
    full-ai-cluster/nixos/tests/ infra/nixos/tests/ .github/workflows/
(no output)
```

No test, no workflow step, no flake check referenced it. A gate nobody re-runs can go vacuous in a
refactor and still read as enforcement — the standing-by failure shape, *a check that did not run
looking like one that passed*. It is the only thing between an unattested flip and a node that may
come back with no driver bound.

`full-ai-cluster/nixos/tests/nvidia-open-guard-gate.nix`, wired as
`checks.x86_64-linux.nvidia-open-guard-gate`. Eight expectations over the four gate states,
evaluated against the **real** `nixosConfigurations.worker-gpu` through `extendModules` — not a stub
that could drift from the shipping module set. Eval-only, no VM, so it rides the
`nix flake check --no-build` step `build-ai-cluster-iso.yml` already runs on every PR touching
`full-ai-cluster/nixos/**` (the path filter covers the guard module), at no added CI cost.

Measured against the shipping `worker-gpu` config:

| state | `hardware.nvidia.open` | preflight | failing assertions | boot-time unit |
|---|---|---|---|---|
| A — as shipped | `false` | — | 0 | absent |
| B — unattested flip | `true` | not passed | **1** (preflight gate) | present |
| C — asserted, unevidenced | `true` | passed, evidence `""` | **1** (evidence gate) | present |
| D — fully attested | `true` | passed + evidence | 0 | present |

Counts compare to state A as a **baseline** rather than to a literal 0, so an unrelated module
adding its own assertion cannot silently turn this test into a liar.

## Verified vs unverified

**Verified** (run here, real output):
- `nix-instantiate --parse` on all three `.nix` files touched — `PARSE OK` each.
- `nix flake check --no-build --all-systems` → `✅ checks.x86_64-linux.nvidia-open-guard-gate`.
- The four gate states above, against the real `worker-gpu` config.
- The mutation numbers above.

**UNVERIFIED — no GPU ran any of this.** No driver was loaded, no node booted, no CUDA context was
created, no container toolkit exercised, no pod scheduled, no node rolled. The boot-time
driver-bound systemd unit has still never executed on real hardware. This PR verifies **module
evaluation only** — that the gate refuses what it claims to refuse.

One inference flagged as inference: the check is expected to run in CI without `--all-systems`
because the runner is `ubuntu-24.04` (x86_64-linux) while this was evaluated from darwin, where
plain `flake check` reports `warning: The check omitted these incompatible systems: aarch64-linux,
x86_64-linux`. That follows from the runner label; it has not been observed on a CI run.

## Known gap, recorded rather than papered over

The falsifier covers **one** of the two module trees. `infra/nixos/modules/nvidia-open-guard.nix`
is byte-identical to its twin below the header, but its hosts hang off the **root** flake, whose
`checks` is `{ }` and whose `nix flake check` no workflow invokes — both CI invocations are
`working-directory: full-ai-cluster`:

```
$ grep -rn "flake check" .github/workflows/
.github/workflows/build-ai-cluster-iso.yml:170:        run: nix flake check --no-build --show-trace
.github/workflows/build-ai-cluster-iso.yml:687:        run: nix flake check --no-build --show-trace
```

A check was deliberately **not** added to the root flake's empty `checks`, because nothing would run
it — that is the vacuity class, and manufacturing the appearance of coverage is worse than recording
its absence. The gap is written into the `infra/` module's own header so it is legible where someone
would edit it, and into the work item.
