## Description

Aaron (shadow*): "wire my response text through the detector too."

Completes the rut-guard trilogy at the layer closest to the sampler the repo can reach:

- #8213 — the detector.
- #8214 — guard the **artifact** (tick-history append).
- **this PR** — guard the **response**, the instant a turn ends.

The rut happens in *generation*, before any artifact (a faint echo even slipped into a tool-call description after the append guard landed). The repo can't reach the token sampler, but a **Stop hook** can read the transcript and inspect the response text at turn end.

**What it does:** `stop-detect-response-rut.ts` reads `transcript_path`, extracts the last assistant turn's text (exported pure `extractLastAssistantText`), runs `detect-repeated-token-rut`, and on a rut emits a **non-blocking `systemMessage` warning** (exit 0).

**Why advisory, not blocking:** you cannot break a rut from *inside* the loop — forcing re-generation (exit 2 / `decision:block`) risks re-rutting, the very failure being guarded. Surface it; an external signal clears it. **Read-only** (respects view-only checkout); any error → exit 0 (a hook must never break the session).

**Verified:** 8/8 tests green; live simulation — rut transcript → `systemMessage` warning, clean transcript → silent, both exit 0; tool-only turns and malformed JSONL lines handled. `settings.json` validates; README table updated.
