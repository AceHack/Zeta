## Description

## The bug

`harness.ts:75` built the Otto-343 read-log path as a literal:

```ts
return `/tmp/zeta-reads-${OTTO343_READLOG_TAG}-${safe}.json`;
```

On Windows, native Bun resolves a leading `/` against the **current drive**, so `post-read-track.ts`'s `writeFileSync` threw `ENOENT`. Its catch is deliberately *"non-fatal"* — a log it cannot write degrades to permissive — so the failure was **silent**, and the log was never created.

`pre-edit-recent-read.ts` then read an absent log, found no entry, and **denied**.

Not a stale-read gate: a permanent, unconditional block on **every Edit in the repo**, for any Windows contributor. I hit it in this session; the only way through was creating `D:\tmp` by hand so the drive-relative path happened to resolve.

## Same shape as the bug the file already documents

The header describes the ppid bug: writer and reader disagreeing about a filename, so every Edit was wrongly denied. That one broke remote sessions. This one breaks Windows. Identical class — *the log path is not stable across the two processes that must agree on it.*

## The test pinned the bug

```ts
expect(a.startsWith("/tmp/zeta-reads-")).toBe(true);
```

It asserted the **POSIX spelling**, not the property — so a platform-specific break could never fail it.

Rewritten to assert the invariant via `dirname`/`basename`: a tagged log directly inside `os.tmpdir()`.

Same for the traversal test. Its escape-proof property is the absence of **separators** in the basename, not the absence of the substring `"etc"` — the sanitiser flattens `../../etc/passwd` to `______etc_passwd`, which contains `etc` harmlessly. My first attempt over-tightened that to `not.toContain("etc")` and correctly failed; the fix was to my assertion, not the code.

## Verification

- `harness.test.ts` — **5 pass, 0 fail**
- resolved path is genuinely writable: `C:\Users\...\AppData\Local\Temp\zeta-reads-<tag>-probe-1.json`
- confirmed live mid-session: right after the change the pre-edit hook denied an Edit *because the log had moved* — i.e. the new location took effect

Unchanged on Linux/macOS, where `os.tmpdir()` is `/tmp`.
