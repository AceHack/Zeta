## Description

Closes the last two links of the observability chain. **Stacked on #13040** — that PR is still open
and this genuinely *extends* its audit rather than duplicating it.

## The .NET exporter — separate assembly, on purpose

`Core` keeps a **zero-third-party instrumentation surface** (BCL `Meter`/`ActivitySource` only).
Reference `Core` → instrumentation that costs ~5 ns and goes nowhere. Reference `Core.Telemetry` →
you opted into an exporter — **and it still exports nothing until `OTEL_EXPORTER_OTLP_ENDPOINT` is
set.** Two gates, both opt-in, because **a library that phones home by default is wrong.**

The endpoint decision is **three-state**, and the middle one is the ship default:

```fsharp
| NotConfigured              // absent -> export nothing. The default.
| Configured of Uri
| Malformed of value * reason   // LOUD, never a silent disable
```

> **A typo'd endpoint that reads as "telemetry disabled" is the same failure class as a sink with no
> source** — which is exactly what this chain was full of. A mutation collapsing `Malformed` into
> `NotConfigured` fails 2 tests.

**The falsifier is the point, not the wiring.** Tests attach an in-memory exporter **through the same
compose seam the OTLP path uses** and assert arrival *with values and tags*. Two more pin the meter
and source **names** equal to what `Core` defines — **so a rename in `Core` that would silently
unhook the exporter goes red in the same PR.**

## Zeta is scraped — and the endpoint came before the annotation

The portal served no `/metrics`. **Annotating first would have been worse than leaving it bare:** the
scrape 404s, the target reads DOWN, **and the manifest reads as instrumented.** So `metrics.ts` exists
first, hand-written (portal dependency budget stays at zero), and **cardinality is a decided property
rather than a hope** — routes bucket into a closed 4-element set, bounded at 12 series, with a
falsifier proving **1000 distinct asset paths still produce one series.**

The alert worth having is **the chain watching itself**:

```
absent(zeta_portal_build_info) == 1  for 10m
```

It fires on exactly the failure modes that are otherwise invisible — bad annotation, wrong port,
ServiceMonitor not selected, portal down.

## Four new audit rules — two found while wiring, not briefed

- **Rule 5 — scrape opt-in coherence, both directions.** Annotated at a port nobody declares; *and* a
  first-party container declaring a `metrics` port with no annotation — **a sink with no source,
  inverted.**
- **Rule 6 — no vacuous alert.** Every metric in an authored PromQL expr must resolve to an emitter
  roster **derived from source, never a hand-written allowlist** — and **a missing emitter source is a
  failure rather than an empty roster, because an empty roster would make the vacuity check itself
  vacuous.**
- **Rule 7 — the ruler never selects it.** kube-prometheus-stack defaults `*SelectorNilUsesHelmValues:
  true`, so a rule without the release label **applies cleanly, appears in `kubectl get`, and is never
  evaluated.**
- **Rule 8 — Argo never applies the file.** The `platform` Application uses an explicit
  `directory.include` glob — **`monitoring.yaml` would have sat in git, reviewed and merged, and
  reached no cluster.**

## Two findings not asked for

**`hat-system` was already serving metrics nobody collected** — rule 5's reverse direction found it on
first run. And **the agent's own PromQL parser was wrong on first run**: `changes(x[1h])` reported a
metric named `h`. Both fixed with regression tests — **worth recording because the audit's whole value
is that it discriminates; a parser that invents metric names would have made rule 6 noise.**

## The finding that corrects my own brief

I told the agent the counters *"increment into nothing."* **Verified myself: `DbspTracing.StartTick` /
`StartOp` / `StartSinkTx` have ZERO call sites anywhere in `src`.** So for **tracing** the honest
statement is *stronger* than my brief — **it is not that spans go nowhere, it is that nothing starts
them.**

For **metrics** I'm correcting the agent the *other* way: **`DefaultMetricsSink` IS constructed**, at
`Injection.fs:151`, so *"nothing constructs it"* is too strong and I'm not repeating it.

> **Either way: the exporter closes the transport link, and the FIRST link — the circuit actually
> calling the instrumentation — is still open.** That's a library hot path and was deliberately not
> touched.

## Designed-but-unrun — the honest headline

> **"Telemetry arrives at a real collector" is unproven, and nothing in this change set can prove it.**

Proven: instrumentation reaches **an exporter** through the same seam OTLP uses, and the OTLP branch
attaches a live listener. **Unproven** (needs a cluster or container): bytes on the wire in OTLP
framing · Alloy accepting them · the annotations actually producing a scrape (**the relabel rules are
exercised by nothing**) · the ServiceMonitor being selected (**rule 7 checks the label the chart's
*default* selector needs — an inference from values, not an observation of the running CR**) · the
`absent()` alert resolving · Argo syncing after the glob change.

**Cheapest first probe** — deliberately **not** wired into the gate, because *a container per PR is a
cost that gets argued for, not smuggled in*: run a local otel collector with a debug exporter and read
its stdout. **That converts "an exporter" into "the wire."** The limit is written in the test file
where it belongs.
