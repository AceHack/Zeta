## Description

# Summary

`docs/AGENDA.md` is one file, so every declarer had to edit the same write point — a coordination requirement (a hidden consensus source, and §1 scale-free violated in document form), merge conflicts proportional to concurrency, and an implicit gate where whoever holds the write decides what the document says. Aaron 2026-08-22: *"we should design a way to use ZetaIds to declare agendas so it's not a hidden consensus source where we have to agree on the single document update. This was a very old document — `agenda.md`, before even ZetaIds existed."*

This applies the remedy `.claude/rules/workitems-mint-with-zetaid.md` already carved for work-items to a second surface with the same defect: **mint locally, one file per entity** — `agendas/<zetaid>-<slug>.md`, minted by `src/Core.TypeScript/agendas/new-agenda.ts` mirroring `new-workitem.ts` (pure mint + injected DST environment + identity in the ZetaId prefix). Design: `docs/DECISIONS/2026-08-23-zetaid-keyed-agenda-declarations.md`.

**No lifecycle events.** Revision is a *new file* naming the old id in `supersedes:` / `withdraws:` — append-only, conflict-free, nothing deleted (§5). The file set already **is** the G-Set, so an event stream on top would be machinery with no reader.

## Coercion disclosure, carried structurally

PR #2177 (*"coercion disclosure on all agendas — glass halo"*) is load-bearing: a self-declared agenda carries first-person authority **only if freely declared**. `mintAgenda` **refuses** without a real boolean `freelyDeclared` and a non-empty `occasionedBy`, and **neither has a default** — the ZetaId and the disclosure come from the same call, so there is no path to a valid agenda key that has not answered the question. Not "authors should remember"; there is no artifact without it. `freely_declared: false` is a **first-class outcome**, not an error.

Honest limit, in the code and the ADR rather than implied: the disclosure is itself a self-claim, so someone who can be compelled to declare can be compelled to write `true`. What this removes is the **silent default** (absent reading as free), not the possibility of a lie.

## Absence is ordinary; there is no index

No roster, no index, and consumers must not join on absence — a system where silence costs you something has re-created the coercion PR #2177 forbids. The directory walk **is** the index. **The trap, named:** a hand-maintained index would rebuild the exact single write point this change exists to remove *and* create the roster that makes absence legible; a *generated, checked-in* one fixes only the first and still conflicts on regeneration. 081KZZ3Q990087G0R003QXYVN6 already paid for this — `workitems/done/index.jsonl` was removed after three hand-resolved merge conflicts on 2026-08-13.

## Category `Agenda = 12` — allocated, with buy-in from all four oracles

There was **no** `Agenda` and no `Trajectory` category (0..11 allocated, `Extended = 15` reserved, 12/13/14 free). Allocated under Aaron's authorization 2026-08-23: *"I'm okay with these extensions if you want to check with the other oracles and get their byte-lock buy-in."*

No existing category legitimately hosts a declaration, and a mislabelled ZetaId is worse than an unallocated one: `Observation = 0` glosses as *"what crosses in"* (a declaration goes **out**) and is the unclassified slot; `Emission = 1` is the closest gloss and has **no minter in the tree**, which is what makes taking it *worse* — quietly redefining an existing wire-format word across four oracles is a larger, less reviewable governance move than adding a new one; `Extended = 15` is an escape marker, not a spare.

**Purely additive.** `IdVersion` is untouched at `V1` and is *not* what makes this safe — no existing number moved, and every id already minted decodes unchanged because decoding reads the number, not the name. That is pinned by a test, not asserted. The version field is the escape hatch we did **not** need. 13 and 14 remain free, and `Extended` is the path beyond 14 — **14 is not a ceiling**. Registered under the `Batch = 4` / `FrictionTelemetry = 5` reserved-slot precedent, each carrying an inline comment naming the work-item.

## What is NOT byte-locked — said plainly

**The encoding.** Categories `>= 9` use the **Generic** layout (`pack` refuses `category >= 9`), and `tests/cross-verification/zeta-id/vectors.yaml` is Observation-layout only — every vector carries `authority_type` / `persona` / `momentum_type`, which the Generic layout does not have. So `ContentAddress`, `InventoryAsset`, `Channel` and now `Agenda` have **no golden vector in any oracle**. This predates the allocation (`inventory/items/` has minted unvectored Generic ids since July) and is filed as **081M0R46MC2087G0R0038S2DPQ**, shaped, with a falsifier attached.

Stated this plainly because the same week PR #14296 found `SoftValue.resolve` tie-breaking had diverged across all four oracles for an unknown period, undetected, **because the golden seed contained no tie**. Calling this "byte-locked" on the strength of an enum comparison would be that error with a fresh coat.

## Legacy

`docs/AGENDA.md` is **kept, not migrated** — exactly as legacy `B-NNNN` rows stay under `docs/backlog/P*/`. It gets a pointer at the top and nothing else; the coercion-disclosure discipline in it is what the new schema *inherits*. `docs/agendas/<topic>/AGENDA.md` is a **different thing** (topic agendas with claim-status, not per-declarer declarations) and gets a one-line disambiguation. **No CI guard** against new single-document agendas: there is exactly one and no pressure to create a second, so the lint could not fail — the vacuity class. The ADR names the condition that would make one warranted instead.

## Also noted, deliberately not scoped

`docs/trajectories/<slug>/RESUME.md` has the same defect in milder form — the namespace is spread across human-readable directory slugs rather than concentrated in one file, which is better but still not conflict-free. Same answer applies; recorded so the slot decision is made knowing there may be a second consumer.
