## Description

## Summary

Add `TypeSchema.From(DynamicValue sample, string ns, string typeName)` — infer a schema from one `DynamicValue.Object` sample (sibling of `ImdbSchemas.FromTsvHeader`). Field order is the object's insertion order. Failures return `Result<TypeSchema, TypeSchemaFromError>` rather than guessing a CsType.

### Mapping
- Bool -> bool, Int -> long, Float -> double, String -> string, Bytes -> byte[]
- Uniform primitive arrays -> T[] (e.g. long[])
- Nested objects recurse as CsType `{TypeName}_{FieldName}` (root schema only this slice)

### Refusals
- Non-object top-level (`NotAnObject`)
- Empty type name / empty field names
- Null-only fields (and all-Null arrays)
- Empty arrays; mixed-shape arrays; arrays of objects (no silent `object` collapse)
- Duplicate field names (ordinal)
- Nullability is not inferred from a single sample

Tests in `TypeSchemaFromTests` pin the required cases (Int+String mapping, top-level String refuse, null-only refuse, insertion order, determinism) plus the extra refusal/mapping cases.
