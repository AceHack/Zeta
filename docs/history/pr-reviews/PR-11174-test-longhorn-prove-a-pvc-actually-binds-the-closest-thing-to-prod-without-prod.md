## Description

## What was missing

The platform-fixes check from #11079 asserts `iscsiadm` resolves on the PATH `longhorn-manager`'s nsenter uses. That is necessary — and it is **not** proof that Longhorn works. It proves one binary resolves.

Between *"iscsiadm resolves"* and *"a stateful workload has a disk"* sit: the manager staying up, registering a Node CR, the chart creating the StorageClass, CSI attaching a volume, and a pod mounting it. Every one is a place the chain can die.

On node-5b2dfa it died at the first link and nothing noticed for **62 days**:

```
longhorn-manager   CrashLoopBackOff   16508 restarts
nodes.longhorn.io  <none>
storageclass       "longhorn" not found   (x107992 over 18 days)
20 PVCs            Pending
```

…with every CI lane green, because no lane ever asked *"does a volume bind?"*.

## What this does

Boots the **real** control-plane modules in QEMU with internet, installs the **real** Longhorn chart at the **real** version (1.7.2) with the **real** prod values copied from `k8s/applications/longhorn/Application.yaml`, then asserts the chain in the order it broke — each assertion naming the prod symptom it inverts.

Link 1 requires the **readiness condition**, not just `Running`: the prod pod reached `Running` between crashes. Links 4–5 write through the mount and read back, because binding can succeed while attach fails.

## Measured — on node-5b2dfa's KVM, against these exact modules

| Link | Prod | This test |
|---|---|---|
| longhorn-manager | CrashLoopBackOff, 16508 restarts | `2/2 Running`, **0** restarts |
| `nodes.longhorn.io` | *(none)* | `server READY=True SCHEDULABLE=True` |
| StorageClass | `"longhorn" not found` | `longhorn driver.longhorn.io Retain` |
| PVC | 20 Pending | `proof Bound pvc-7821bf66… 1Gi RWO` |
| Data | never reached | pod `Completed`, read back `zeta-longhorn-proof` |

k3s logged a real `UnmountDevice` for `kubernetes.io/csi/driver.longhorn.io^pvc-7821bf66…`, so the volume was genuinely attached, written and detached — not a vacuous pass. `Retain` on the StorageClass confirms **my prod values** were applied, not chart defaults.

## What it is NOT — stated rather than implied

- **One node.** Replica placement across real nodes is not exercised.
- **A single virtual disk** on `/var/lib/longhorn` — the `/var/lib/longhorn-disk{1,2}` multi-disk wiring is out of scope, which is exactly the part still unproven on node-5b2dfa (it runs the placeholder `hardware-configuration.nix`, so both data partitions sit unmounted).
- **Not the USB installer path** — that is the zflash harness's job.
- **RWO/iSCSI only** — no RWX/NFS.
