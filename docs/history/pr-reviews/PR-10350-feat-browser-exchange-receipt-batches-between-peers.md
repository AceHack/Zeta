## Description

## Why

The browser receipt handoff could persist locally but had no source-owned boundary for moving immutable receipt generations to another peer. Discovery transports should carry bytes without owning database semantics.

## What

- add a bounded request/reply transport port and sender/receiver adapters
- bind requests and acknowledgements to both peers, the target ZetaDB node, and the complete BLAKE3-addressed receipt batch
- independently validate receipt structure, order, source identity, digest, persistence acknowledgement, and byte/receipt budgets at the receiver
- expose typed backpressure and heat readouts; transport and persistence failures do not escape as exceptions
- leave Reticulum, WebRTC, and BroadcastChannel as external adapters behind the same port

## Limits

This does not add a discovery-specific adapter or continuous replication loop. It establishes the transport-neutral, finite exchange contract that those adapters can implement.
