## Description

> *"we need to make sure new contribitors to Zeta just get this for free on Mac, Windows, Linux"*

Mac and Linux landed in #12734. **Windows was three `WINDOWS_EXCEPTIONS`** whose stated reason was that no scoop or winget id *"was verifiable from the host this was authored on."*

That was an honest exception — and it was also **a check that had not been run.** Running it falsified it. All three tools are packaged, and in **scoop Main**, which is this manifest's *primary* user-mode, no-admin resolver.

## Verified — ids copied from the manifests' own fields, not inferred

| source | package | version | binary |
|---|---|---|---|
| scoop `Main` | `yubikey-manager-cli` | **5.9.2** | `ykman.exe` |
| scoop `Main` | `yubico-piv-tool` | **2.7.3** | `yubico-piv-tool.exe` |
| winget | `Yubico.YubiKeyManagerCLI` | **5.9.2** | — |
| winget | `Yubico.PIVTool` | **2.7.3** | — |

**Three independent sources agree on both versions**, and `5.9.2` / `2.7.3` are exactly what brew reports for the same tools. So this is a cross-checked declaration rather than a plausible-looking name.

**chocolatey ids are omitted rather than guessed** — none was checked, and the resolver falls back scoop → winget without them. That's the same discipline the original exception was reaching for, applied to the part that's *still* unverified.

## The remaining exceptions are re-classed, not just trimmed

The table now says which **class** each entry belongs to, because they were two different things wearing one label:

- **Name aliases** — `yubikey-manager` (apt) and `ykman` (brew) are the same binary the Windows row declares under scoop's spelling. The matcher compares names literally and has no alias table. Same shape as `lua5.4` vs `lua`. **`yubico-piv-tool` needs no entry at all** — all four ecosystems spell it identically, so it matches on its own.
- **Genuine Windows built-ins** — `pcscd` (SCardSvr) and `libpcsclite1` (WinSCard). Nothing to install.

## The YubiHSM SDK stays undeclared — checked, and genuinely absent

`microsoft/winget-pkgs` `manifests/y/Yubico` has **no HSM entry**, and Yubico ships the SDK as a signed per-OS installer. Undeclared on all three platforms, matching the note already in `manifests/apt` — now recorded in `manifests/windows` too rather than left implicit.

This is the same distinction I got wrong this morning: a package *existing somewhere* is not the same as it being *installable from the configured sources*. Here the check was run against the sources the resolver actually uses.
