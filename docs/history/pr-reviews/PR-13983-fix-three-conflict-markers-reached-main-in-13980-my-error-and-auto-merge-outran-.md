## Description


`lint (no conflict markers)` is red on `main`. Three marker lines are sitting in
`docs/github/prs/manifest.jsonl` at 7604, 7606 and 9514.

HOW THEY GOT THERE, both halves mine:

1. `git revert 2caebefa6` in #13980 reported ONE conflict (`swarm.worker.ts`). It
   had two. I resolved the one it named and staged the rest with `git add -A`
   without reading the diff, so the markers went into the revert commit.
2. I caught it, pushed `fafd2b089` fixing it — and armed auto-merge had already
   locked the head it saw when the required checks went green. The squash captured
   the branch WITHOUT the fix. So the repair exists as a commit that never reached
   `main`, which is the worst of both: it looks handled in the branch history and
   is not handled in the tree.

The general lesson, and it is not "read the diff harder": with auto-merge armed, a
follow-up push is racing the merge. A fix for something already in an armed PR
belongs in a new PR, not a new commit on the armed one. I will not repeat that.

THE FIX, redone directly on current `main`:

1. The conflict was between one side holding only the `pr_number: 13976` row and
   the other holding the ~1,900 rows #13973 truncated away. The file is
   `merge=union` because it is append-only under a globally unique `pr_number`, so
   both sides are the answer: 9,511 rows, 9,511 distinct `pr_number`, zero
   unparseable lines, all checked before writing.
2. `derive-pr-manifest.ts` then reported `1 entr(y/ies) with no shard behind them`
   for 13976. Not a new fault — #13973 deleted the whole shard store, so when the
   archive automation wrote that row there was no store for its shard to land in.
   Repaired with the tool's own command, `--write`, which regenerates the index
   FROM the shards rather than patching it by hand: "rewritten from 9512 shards",
   then "in sync with docs/github/prs/shards (9512 entries) ✓".

The 13976 record survives its index row —
`docs/history/pr-reviews/PR-13976-chore-make-objective-text-less-scary.md` is
present, and #13976 was reverted with #13973 anyway, so its archive re-derives when
the feature re-lands.

Verified on this tree: `check-no-conflict-markers.ts` exit 0, "no git
merge-conflict markers found in committed files"; `derive-pr-manifest.ts
--min-age-minutes 180` exit 0. Net diff is 6 lines.
