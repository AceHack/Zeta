## Description

Design spec for slice 6.1 — **`ace registry publish`** (081KT07NV0008QG0R0016FVWD7), the producer-side counterpart to slice 6's consumer trust gates.

`ace registry publish --packages <dir> --base-url <url> --key <pem-path> [--out index.json]`: scan a dir of package files → derive each consumer `url` (`<base>/<name>-<version>.json`) + `package_hash` → assemble + sign the `IndexSignableContent` → auto-bump `sequence` from `--out` (anti-rollback guard) → **round-trip self-verify** the produced index through the consumer's own `parseIndex` + `verifyIndexSignature` before writing.

**Decisions locked with operator 2026-06-01:**
- **Input** — directory scan (`--packages <dir>`; non-packages skipped + warned).
- **URL** — `--base-url` + `<name>-<version>.json` convention (per-package override deferred — "1 then maybe 2").
- **Sequence** — auto-bump from the existing `--out` (+1; refuses `≤ prev`).
- **Scope** — core + **round-trip self-verify** (publish can never emit an index the consumer would reject). Deferred: per-package url, ETag sidecar, multi-dir, incremental/multi-signer publish.

New: `tools/ace/registry-publish.ts` (pure: `buildIndexDoc`/`nextSequence`/`joinUrl`) + tests; additive `publicKeyInfoFromPrivatePem` in signing.ts; `registry publish` in ace.ts; end-to-end producer→consumer test. Reuses `signIndex`/`canonicalIndexBytes`/`packageHash` + the consumer's `parseIndex`/`verifyIndexSignature` for the self-check.

Next: on approval → writing-plans → subagent-driven build.
