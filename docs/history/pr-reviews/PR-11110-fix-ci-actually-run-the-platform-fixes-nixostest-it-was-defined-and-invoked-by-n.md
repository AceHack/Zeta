## Description

## The gap

`k3s-control-plane-platform-fixes` has existed in the flake's `checks` since #6966 and is wired into **no workflow**. Measured, not assumed:

```bash
$ grep -rn "platform-fixes" .github/workflows/
(empty)
```

The `build-iso` job runs the other three nixosTests — `cluster-init`, `agent-join`, `cluster-online` — and silently skips this one.

So every regression it guards has been **ungated in CI**:

- `rpfilter` off (the pod→host black-hole)
- `open-iscsi` present + `iscsi_tcp` loadable
- k3s `--disable=local-storage`
- the loose `rp_filter` sysctl
- the iscsiadm FHS shim Longhorn's nsenter needs (#11079)

## Why this matters

This is the same shape as the bug it now catches: **a signal that reads green because nothing is actually checking.**

`longhorn-manager` crash-looped **16,495 times over 62 days** on node-5b2dfa while every CI lane was green — because the one test that would have caught it never ran. Adding the assertion in #11079 did not close that. The assertion still ran nowhere until this commit.

## Placement

Beside the other fast hermetic check (no internet, ~2 min), so it fails before the ~15-min ISO build rather than behind it.

The workflow's own path filter already includes `.github/workflows/build-ai-cluster-iso.yml`, so **this PR exercises the new step** — the green check here is the proof it runs.
