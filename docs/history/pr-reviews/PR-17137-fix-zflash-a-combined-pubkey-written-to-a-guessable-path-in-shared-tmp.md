## Description

fix(zflash): a combined pubkey written to a guessable path in shared tmp

CodeQL js/insecure-temporary-file, alert 286 (high). `zflash/cli.ts:1592` built
its scratch path as:

    join(tmpdir(), `zeta-combined-${user}.pub`)

Every component is knowable in advance by anyone with a shell on the host: the
directory is world-writable, the prefix is a constant in a public repository,
and `user` is a maintainer name. An attacker who creates a symlink at that path
before the run has the following `writeFileSync` follow it and write 0644
content wherever the link points. The file itself is public key material, so the
exposure is not disclosure -- it is the WRITE, aimed by someone else.

THE FIX IS THE DIRECTORY, NOT THE FILENAME, and that is not my reasoning: it is
already recorded in `peer-call/output-path.ts`, which met this rule first and
wrote down why a fixed name plus a later `chmod` is the weaker answer -- `mode`
on `mkdirSync` is umask-masked, is ignored outright when the directory already
exists, and CodeQL models `mkdtemp` rather than the chmod that follows it.
`mkdtempSync` is atomic, so there is no window at all rather than a window
closed a moment later. Once only the owner can traverse the directory, a
predictable name inside it is not a weakness.

Measured rather than assumed: `mkdtempSync(join(tmpdir(), "zeta-zflash-pubkey-"))`
produces mode `0700` and six random suffix characters on this platform.

AND THE CLEANUP HAD A RACE OF ITS OWN. Both teardown sites read:

    if (tempPubkeyPath && existsSync(tempPubkeyPath)) { rmSync(tempPubkeyPath, { force: true }) }

`force: true` already means "no error if absent", so the `existsSync` bought
nothing and was itself check-then-use -- the path can vanish between the two
calls. Both now remove the DIRECTORY unconditionally, which also means the
temp state actually goes away instead of leaving an empty `/tmp` entry behind.

This is the same class the companion PR makes detectable in CI; here it is two
live instances in the file being fixed for a different reason.

NOT changed, and named rather than quietly skipped -- the other four
`js/insecure-temporary-file` alerts:

  * 260, 261 `zflash/esp-inject.test.ts` -- test-local scratch paths.
  * 224 `hygiene/divergence-shard.ts:345` and 641
    `verify/z4-sle-harmonic-discharge.ts:118` -- NEITHER file calls `tmpdir()`.
    Both take the path as a parameter, so CodeQL is following a caller I cannot
    identify from the alert payload. Note 224 already carries an in-code comment
    claiming the `openSync(absPath, "wx")` form "clears the finding
    substantively" -- the alert was re-confirmed open by today's analysis at
    c524e0788a, so that claim is currently false. Editing either on a guess
    would be a fix only the scanner could see, which is the failure this batch
    is meant to avoid.
