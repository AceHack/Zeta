## Summary

Picks up pending task #269. Otto-278 named the gap: memory-only counterweights are write-once-read-never without a cadenced re-read that FORCES the inspect + drift check. Otto-276 drifted within ~30 min; Otto-277 re-tightened; Otto-278 said the pattern recurs indefinitely without a cadence.

Phase 1 = shell tool (this PR).
Phase 2 = `.claude/skills/counterweight-audit/SKILL.md` wrapping it (separate BACKLOG row).
Phase 3 = autonomous-loop tick-open hook (separate BACKLOG row).

## What the tool does

- Enumerates `memory/*otto_*.md` counterweight files (51 today).
- For each, extracts Otto-NNN identifier + \`name:\` field from frontmatter.
- Emits audit questions per counterweight:
  1. In the last N ticks, did I exhibit the drift this counter was filed for?
  2. If yes: tighten THIS counter, file a NEW tighter one (Otto-276 → Otto-277 pattern), or escalate to a skill / BP rule?
  3. Is the cadence still right or can maintenance cadence stretch?

Agent self-scores; no automatic drift detection — the point is forcing the re-read.

## Cadence modes

- \`--cadence quick\` (default): top 3 newest counterweights
- \`--cadence medium\`: top 10
- \`--cadence long\`: all (full session/round-open sweep)
- \`--count N\`: override per-cadence count

## Portability

Bash 3.2 compatible (GOVERNANCE §24 four-way-parity — macOS ships bash 3.2). No assoc arrays, no mapfile. Portable stat probe handles BSD (\`-f %m\`) vs GNU (\`-c %Y\`). \`mktemp -t\` template works cross-platform. No long-running daemon.
