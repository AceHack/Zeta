## Description

fix(archive): remove the second corrupt path from the same commit

`docs/github/prs/shazds/012/08000000000000007803000000003240.json` -- note
`shazds`, not `shards`. Same origin as #15194: commit 5223ce912 (my PR #15007)
recorded TWO R100 renames, each corrupting a single character of a path while
leaving content byte-identical. #15194 removed the first; this is the second.

Both correctly-named files were re-created by the archive tooling, so no record
was lost. These are strays under misspelled keys.

The two corruptions, as bytes:

    'r' 0x72 -> 'z' 0x7a    XOR 0x08    ONE bit      shards -> shazds
    '0' 0x30 -> '<' 0x3c    XOR 0x0c    two bits     filename

Recorded because git cannot detect this class on its own. Content addressing
protects object CONTENT; a corrupted filename is faithfully stored as tree
content, so `git fsck` passes and every hash verifies. What caught it was a
NAMING-CONVENTION check -- `derive-pr-manifest.ts` exiting 2 on a shard it
could not key -- which is the argument for having such checks at all.
