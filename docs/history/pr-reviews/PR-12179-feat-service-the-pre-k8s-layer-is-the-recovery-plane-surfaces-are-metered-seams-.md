## Description

## Summary

Aaron asked for the pre-k8s bootstrap for the agent society, then corrected the premise twice. Both corrections narrow the design rather than widen it, and both are carried here.

> *"the pre-k8s is for fixing k8s when it goes wrong on a node, and initial setup hiccups"*

The layer is **not** bootstrap scaffolding and is **not** discarded when the cluster arrives. It is the permanent **out-of-band recovery plane**, so the governing constraint inverts: **optimise for working when k8s is broken**, which makes independence from the repaired system a hard requirement rather than a preference. This is the repo's own recorded pattern -- `081KSKBP80008QG0R003Z4C0D0` ("control plane outside the control plane", **planned**, open since 2026-05-27) -- given an architecture.

> *"we have connected hive-mind-like entities, so they can exist inside and outside k8s at different access levels with different tick sources"*

So an **entity is not a service**. One entity holds several `(tick source, surface, authority)` triples at once, on both sides of the boundary, permanently.

## The design doc

`docs/research/2026-08-18-the-pre-k8s-layer-is-the-recovery-plane-surfaces-are-metered-seams-and-the-surface-count-is-measurable-not-chosen.md`

It **instantiates** the model already in `docs/writer-actor-routing-model.md` rather than deriving a new one. The mapping holds cleanly: entity = **persona** ("what remains"), actor = `persona (+) surface (+) instance` ("what acts"), surface = the **host-boundary seam**. The load-bearing consequence is that the repo already defines a surface as the hexagonal port through which section-13-metered entropy crosses -- so *"different surfaces at different access levels"* is not an access-control scheme bolted on top. **It is what a surface already is**, and the 4-10 services enumerate **seams, not processes**.

Two results worth naming:

- **The tiers are natural; equating them to services would be the imposition.** A0 observe / A1 journal / A2 propose / A3 repair-node / A4 repair-cluster / A5 custody / A6 human-gated are each read off an existing gate. "Seven tiers lands inside 4-10" is numerology. The structure that actually decides the count is `credential-reachability.ts`'s **measurement** that the live credential is `reachable-without-authentication` by any process running as that user. Hence: **two tiers co-resident in one OS user are one tier**, so the surface count is the number of distinct `(principal, credential-domain)` pairs -- **measurable, not chosen**. Today's honest count is smaller than the six drawn, and the doc says so.
- **A6 has no daemon, by construction.** Every other tier can be held by a standing process; the gated classes cannot, per `no-directives.md`. The tier list has a hole exactly where authority may not be delegated, and a service appearing in that hole is a visible violation.

Also stated: authority attaches to the **actor** and must never become a component of the routing address (the address routes, the credential authorizes -- the same refusal as *"routing uniqueness is reachability, NOT identity"*); the **portability boundary** is real rather than aspirational (supervision and observation port cleanly, package installation does not and **should not**, so the recovery plane may never install at runtime); **coherence across a boundary where one side may be down** is partition tolerance via the idempotent lane fold, with `local-time-never-enters-the-shared-fold` flagged as the highest-risk bug for a plane whose normal state is "behind"; and the **surface-choice optimisation belongs to the agent, never the platform**.

Flagged before it lands: the **forge-circularity hazard**. `origin` is GitHub today, so the journal is genuinely out-of-band. `full-ai-cluster/` already ships Forgejo and GitLab in-cluster; the moment an A0-A3 surface's `origin` resolves into the cluster it repairs, independence is lost with no code change and no diff to review.

## The small shipped thing

systemd fact-gathering for `loop-liveness`, and the removal of its platform gate.

`classify()` was already pure and OS-independent. The **fact-gatherer** was not, and the CLI answered on Linux with `launchd probing is macOS-only (systemd support: future)`, exit 2. So the one liveness check the factory has **could not run on the NixOS cluster nodes** -- the machines with the most ways to break, and the exact machines the recovery plane exists for. **Tier A0, which every other recovery capability is built on, was absent on the node type that needs it.**

It is also the same defect the module was written to kill, one layer over. On launchd the vacuous field was `state`, because a `StartInterval` loop is *supposed* to read "not running" between ticks -- the conflation that hid four dead cells for two months. `adapters/systemd.ts` installs a `Type=oneshot` service driven by a `.timer`, so `ActiveState=inactive` between ticks is likewise normal, and `SystemdAdapter.status()` keys on `is-active <unit>.timer` -- **which stays `active` while every single invocation fails**.

Both systemd discriminators are load-bearing, and both have falsifiers: a run killed by `TimeoutStartSec` reports `Result=timeout` with `ExecMainStatus=0`, so an exit-code-only check calls a timed-out loop healthy. One test strips the `Result` signal and asserts the timed-out cell then classifies as **healthy** -- that is the falsifier for carrying `lastRunFailed` at all.

`CellFacts` gains `supervisor` and `lastRunFailed`; `launchdState` becomes `supervisorState`. `parseLaunchctlPrint` keeps its launchd-specific shape. Exit-code glosses are paired: launchd `78` (EX_CONFIG) and systemd `203` (EXIT_EXEC) are the same "could not execute your program" defect under two numbers.
