## Description

## The routing call

Aaron caught a live naming defect and his instinct was right. The **fact** was not in dispute — this repo established it on 2026-07-04 and audited it on 2026-08-01. What failed is the **shape of the remediation**, and the durable fix is a check, not more prose.

Tsirelson's bound is `S ≤ 2√2 ≈ 2.828` on the CHSH correlator, implemented correctly at `src/Core/Tsirelson.fs`. `1/(3√2) ≈ 0.2357` is a different number: the image of `S = 2√2` under the **freely chosen** linear map `ρ = S/12`. It is a legitimate design threshold and every use of it is behaviourally correct. Only the **name** is wrong — and every time the physicist's name got attached to it, something broke: **Z-3 and Z-5 were DEMOTED §A→§B and the Zeta-Conjecture keystone claim was REFUTED.**

> Aaron 2026-08-23: *"i hear tsirelson and hear 2sqrt2, why do you hear 1/(3sqrt2)? this threshold and limit different thresholds, most 1/(3sqrt2) have turned out to be bugs."*

## Why a lint and not another sweep

A prose sweep is a **snapshot**: not idempotent, and it does not survive new files. Measured on 2026-08-23, the two 2026-07-16 sibling docs had drifted into **disagreeing with each other** — `austrian-economics` carried the banner, `echolocation-debounce` did not — so the repo asserted and denied the same identification in two files written the same day, and neither could know.

`src/Core.TypeScript/hygiene/lint-tsirelson-constant-caveat.ts` fails when a live surface writes the constant within 3 lines of the token `Tsirelson` without a caveat. It refuses the **NAME**, never the **NUMBER**: no value and no behaviour is in its scope.

**No hand-maintained allowlist of caveated places** — that artifact's drift is what caused the problem. The markers are **derived from the provenance doc**, which the lint **discovers by shape** rather than hardcoding, so renaming that doc reddens every stale citation instead of silently disabling the guard. Discovery resolving to ≠1 file exits **2**, never 0.

## Two of the guard's own markers were vacuous, measured, and thrown away

Each **green-lit the very file it was written for** — the vacuity class inside the guard meant to catch it:

## Also corrected

## What I deliberately left alone

- **The identifiers.** `TSIRELSON` / `tsirelsonThreshold` / `tsirelsonAgeDays` span F#, TS and TSX with tests and demos. A half-rename is worse than none, and a full one is ~10 files across 3 languages plus the .NET build for **zero behavioural gain** — churn that would bury the actual fix in review. Proposed as a follow-up; the lint pins the caveat meanwhile.
- **Frozen records** — `docs/history/**`, `docs/github/**`, `docs/letters/**`, `memory/**`, `*.void`. Editing an archived PR review or another agent's notebook to make a lint green is falsifying a record to improve a score. Excluded from the **scan**, not from the finding.
- **Bare uses with no name attached** (`OracleInferNet.tsx`, `OracleSLE.tsx`, `useDLA.ts`). A bare design parameter asserts nothing false — the defect is the **name**, and flagging every `0.2357` would make the guard noise, and noise gets a lint deleted.
- **`LiveOracleFeed.tsx`** — already says *"a simulation parameter, NOT a Tsirelson bound."* Untouched, and the lint agrees.
- **The uncompensatable floor.** This job runs on every PR but does **not** block. Adding to the floor is a **treaty-amendment consent path** (gate.yml's own rollup comment), and a naming caveat is not the **erasure** class the floor derives from. I will not widen a floor I do not hold consent for.
