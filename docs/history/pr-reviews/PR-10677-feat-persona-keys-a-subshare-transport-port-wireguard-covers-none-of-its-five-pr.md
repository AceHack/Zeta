## Description

## The blocker

`frost-reshare.ts` (#10654) says in its own header that subshare transport must be confidential, that it does not provide it, and that **a three-house ceremony must not be attempted until the confidential channel exists**. That made transport the hard blocker on geographically-distributed custody.

This lands that channel as a **hexagonal port with one working implementation**, not as a WireGuard integration — per Aaron 2026-08-14: *"this should be a hexagonal interface, we don't want to fully depend on wireguard interfaces fully, we need our own ports."*

`frost-reshare.ts` is untouched.

## The five properties, and WireGuard's coverage

| | Property | Provided by | WireGuard sufficient? |
|---|---|---|---|
| **P1** | Confidentiality **to the addressee** — not the node, not a relay | above-port | **No** — point-to-point between *nodes*; a relaying coordinator reads it in clear, a DHT has untrusted intermediaries by construction |
| **P2** | Holder authenticity bound to a **pinned key**, never a route | above-port | **No** — authenticates a *node* key; node identity is not holder identity (`writer-actor-routing-model.md`) |
| **P3** | Ceremony binding + replay resistance | above-port | **No** — its sliding window lives inside a session; a datagram replayed after reboot or into a later ceremony is a fresh valid packet |
| **P4** | Forward secrecy under later endpoint compromise | above-port | **No** — real in flight, evaporates at rest; a store-and-forward datagram spends most of its life outside any channel |
| **P5** | Eventual delivery **without** liveness, order, exactly-once | port | **No** — needs both endpoints reachable; tailscale additionally needs the control plane |

**WireGuard is sufficient for none of the five end to end, and required for none.** That is harsher than the "3 of 5" answer expected, and better: because nothing depends on the mesh, the ceremony inherits no dependency on it. What a mesh genuinely buys is metadata concealment (routing fields are cleartext by design so adapters can route without opening) plus coarse admission.

The placement rule is the whole point of the hexagonal split: **everything WireGuard does not cover lives above the port**, so every adapter inherits it — including the sneakernet "adapter", which is a person and cannot run adapter code at all. Put replay protection in a WireGuard adapter and the planned DHT adapter reimplements it and gets it subtly different.

## Why forward secrecy is required, not nice

A subshare is **secret-equivalent in transit**: `k` of them addressed to the same `j` sum to `s'_j` — that sum *is* the reconstruction — and `s'_j` stays live as long as the group key does. A recording made today is worth a break made at any later date. That also makes harvest-now-decrypt-later the literal threat model, so the KEM is post-quantum (X-Wing).

The signature is deliberately **not** post-quantum: a forged subshare must be forged *during* the ceremony, which ends in `verifyResharePreservesGroupKey`. A 2040 forgery against a 2026 ceremony has no verifier left to fool. ~1.2KB per datagram instead of ~5KB, which matters on LoRa.

## Live connectivity is not required

`reshareCombine` **sums** the subshares, so the fold commutes and the transport owes no ordering — the ceremony needs *completeness*, which `reshareCombine` already enforces. Sessionlessness costs exactly two things, both paid locally, neither by the channel. **These are the constraints on adapter 2** (TCP hole punching / websocket reverse tunnelling / DHT):

1. The **recipient** needs durable storage — replay resistance without a session is a seen-log, not a sequence window.
2. The ceremony has **two asynchronous phases** — forward secrecy without a handshake needs the recipient's per-ceremony KEM key published before holders seal (X3DH's signed prekey, minus the sessions). Both phases can be sneakernet, days apart.

No property requires a session.

## Control-plane trust

**Share custody should not depend on headscale, and the design makes that achievable rather than aspirational.** Holder keys are pinned in a `CeremonyRoster` verified at seal and open. The roster is deliberately not distributed by any code here — a roster fetched from the mesh would hand the control plane exactly the authority the pin denies it.

Two independent gates: a compromised control plane can add a **node**, whose datagrams fail P2 as `unknown-sender`; a substituted secret is still caught by `verifyResharePreservesGroupKey` from public points alone.

## Mutants — every property can fail

Nine checks that could not fail were found in this repo on 2026-08-14, including a probe that reported an empty file as attached hardware. A suite that passed against a plaintext channel would be the tenth and the worst. So the suite is proved falsifiable **before** it is used as evidence, and each mutant must kill **named** probes rather than merely fail somewhere.

| Mutant | Breaks | Named probes that die |
|---|---|---|
| M1 plaintext channel | P1 | `P1.a/secret-not-on-the-wire`, `P1.b/collector-of-all-k-cannot-open` |
| M2 trusts the routing exterior | P2 | `P2.a/unrostered-sender-rejected` |
| M3 no replay guard | P3 | `P3.a/identical-redelivery-is-idempotent`, `P3.b/conflicting-datagram-at-same-coordinate-rejected` |
| M4 long-term key, `destroy()` is theatre | P4 | `P4.a`, `P4.b`, `P4.c` |
| M5 session-bound transport | P5 | `P5.c/cold-reader-collects-everything-offered` |

All five die. The shipped implementation passes all 18 probes on both the memory and filesystem spools.

**M4 had to be rewritten, and the reason is worth recording.** Its first version wrapped the real handle with `isDestroyed: () => false` and "failed" P4 for the wrong reason — the decapsulation capability is bound to the handle *object* via a `WeakMap`, so the spread-copy simply could not decrypt. A mutant that dies of the wrong cause is not evidence either.

The end-to-end test runs a real 2-of-3 reshare over the filesystem spool with reversed delivery order and every datagram delivered twice, destroys each per-ceremony key, confirms recorded datagrams are then dead bytes, and verifies a threshold signature against the **unchanged** group public key.

## What I deliberately left

- **Roster distribution and rotation** — out of band by design; rotation belongs with the delta-rotation work live in this area (I stayed in transport).
- **Traffic-analysis resistance** — routing fields are cleartext so adapters can route without opening; a mesh carrier is the mitigation.
- **A live network adapter** — the spool plus a carrier is smaller, hermetically testable, and covers sneakernet and Reticulum for free.
- **Tier** — still L1. The scalar is in host RAM at seal and open, exactly as `frost-reshare.ts` caveat 1 says.
- **Old-share destruction** (`frost-reshare.ts` caveat 3) — still open, still not transport.
- **The operational half of forward secrecy** — the tests falsify that a destroyed handle cannot open; they cannot falsify swap files or core dumps.
