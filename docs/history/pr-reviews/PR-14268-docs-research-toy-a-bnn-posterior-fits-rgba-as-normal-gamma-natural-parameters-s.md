## Description

docs(research): TOY — a BNN posterior fits RGBA as Normal-Gamma natural parameters; Student-t does not

Aaron: *"I'm hoping somehow we can encode their information into RGB-like values.
This is the start; it is only a toy."* Register stays `toy` throughout. What this
adds is numbers, so the direction can be earned or killed cheaply.

MEASURED, not assumed — what OracleRGBA.tsx encodes today:
  - There is no texture. Display is `ctx.createImageData` (8 bits/channel); the
    WebGPU path is `array<u32>` storage buffers. Not rgba16float, not rgba32float.
  - The GPU path never renders the four-channel encoding at all: it writes a flat
    (220,100,50,255) per cluster cell, and `walkLenBuf`/`harmonicBuf` are bound and
    never read back.
  - "R = occupancy" is a constant 220 — a boolean wearing 8 bits.
  - The walker is branchy (`if (dir==0u) … else if …`), which is the exact shape
    Aaron wants colour in order to avoid.
  - Likely defect, filed not fixed: `atomicAdd(&harmonic[i], 1u)` on a plain
    `array<u32>`. WGSL wants `array<atomic<u32>>`. Not device-confirmed — LOOK,
    DON'T INFER — so it is a work-item with a falsifier, not a change.

CHOSEN: Normal-Gamma in natural coordinates, 1 weight per rgba32float texel.
  h = ( −(β + λm²/2), λm, −λ/2, α − ½ ), conjugate update = vector addition.
  The marginal on the weight is exactly a Student-t, so the heavy tail arrives
  without paying Student-t's price. Message.fs already stores Gaussians as
  (PrecisionMean, Precision) with `( * )` = componentwise add, so the repo was
  already in natural parameters; this extends that by two coordinates.

REJECTED — Student-t (μ,σ,ν), the candidate that looked like the perfect 4-fit:
  1. Not closed under fusion. The product of two t densities is not a t, so any
     implementation must project, and projection breaks associativity — measured:
     (X*Y)*Z gives ν=7, X*(Y*Z) gives ν=6.
  2. A scalar ν channel asserts what HeavyTailFold.fs already refuses to assert
     ("nu is not identifiable … noise wearing a number"; 1/ν is the coordinate).
     NG4 avoids this structurally: α counts evidence, so ν=2α is earned, not fitted.
  Also rejected with reasons: (μ,σ²) moments, mixtures, particles, and
  tri-boolean-float (v0 is unsigned+finite; η₁,η₃ are negative — and it answers
  "is this bit known", not "how coarse is this posterior").

THE FALSIFIER — round-trip, scored by KL between posteriors, not L2 on channels:
  rgba32float   max KL 4.0e-8   mean 5.4e-11   0 invalid   ← outcome 1, exact
  rgba16float   max KL 1.9      mean 3.4e-3    — and NP2 goes to INFINITY: the
                measured τ range reached 129836 against binary16's 65504 max, so
                the more evidence a weight has, the more certainly f16 destroys it
  rgba8unorm    max KL 2.7e2    mean 3.6       108/4096 decode to a NON-posterior
                (β≤0 or λ≤0). At today's precision 2.6% of weights do not exist.

  Exactness needs no multi-texture scheme. 1 fetch, 16 bytes per weight.

ASSOCIATIVITY: (η,τ) and NG4 fuse bit-identically under reassociation; naive
(μ,σ²) fails by 1.75e-1. N-parent is one reduce with no special case at 3 — the
mathematical content of 081M0QJ2Z91087G0R00061PBQF. Anchor: log-linear pooling,
the unique externally-Bayesian rule (Genest 1984; Genest & Zidek 1986).

BRANCHLESS: fold = float4 add (literally GPU additive blend); crossover = mix();
mutation = hash + fma; cone guard = min/max, which are instructions not branches.
The one real constraint, stated: clamping is not associative, so the guard belongs
only in mutation. The valid region is a convex cone, so fusion (sums) and crossover
(convex combinations) stay inside unaided. Mutate in the cone, fold anywhere.

QUANTISATION, if lossy — and the state of the art partly does NOT transfer:
  per-channel uniform (Krishnamoorthi 2018; Nagel 2021)  mean KL 3.84  ← transfers
  per-channel QUANTILE grid (NF4, Dettmers 2023)         mean KL 10.88 ← 2.8x WORSE
  quantile + 1% f32 outliers (LLM.int8(), Dettmers 2022) mean KL 4.19
  8-bit on location only 11.21 vs shape/scale only 2.19
  Diagnosis: quantile quantisation allocates by probability MASS of values; KL
  between exponential-family members is governed by the FISHER metric. Every method
  surveyed minimises an L2 on point weights or activations; none targets a
  divergence between distributions. That gap is the finding, with a number.
  Consequence, which inverts the intuition: ν=2α is EXACT even in f16 (it is a
  count), so the heavy tail is the cheapest thing in the texel — spend bits on
  location. And at 3.84 nats, 8-bit is refused: f32 is exact for 12 more bytes.

REFUTED — RGB→CMYK is not a model of `snap`. Round-trips to 1.11e-16 over 100k
colours: it is a bijection, so not lossy, not non-invertible, not directional. And
dim(RGB)=3 < dim(CMYK)=4, so the map goes UP in dimension while `snap` goes DOWN.
What survives is better: CMYK = 4 explicit trees (exact), RGB = 3 explicit + 1
inferred — the soft/solid split stated dimensionally, per the 4-tree/3-tree doc.
Also: emit/retract and additive/subtractive are the same observation twice, so the
"three agreeing framings" are two, and one of them just failed.

NUMEROLOGY BAR held per the "sharing the length 8 identifies nothing" precedent:
the 4-width match is worthless as evidence and is not what the claim rests on. 4 is
the dimension of the sufficient statistic T = (τ, τμ, τμ², log τ). The family fixes
the width; the width does not endorse the family. "Minimal such family" is recorded
as *consistent with*, not proved.

OWNED ERROR: the hand-rolled binary16 converter first routed double→f32→f16 —
double rounding — and was wrong by one ulp on 4/20012 probes. Caught only by the
self-check against the platform intrinsic that the harness runs before quoting any
f16 number. Fixed (0/300016 now), recorded in §11b, and pinned as test RT-5. A
measuring device nobody measured would have faked every f16 row.

Falsifiers: 10 tests in toy-bnn-rgba-codec.test.ts. Numbers: `bun
src/Core.TypeScript/bayesian/toy-bnn-rgba-roundtrip.ts`.
