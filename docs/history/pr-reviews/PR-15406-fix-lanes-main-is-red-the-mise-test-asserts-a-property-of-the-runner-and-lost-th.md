## Description

`test (TS hermetic)` is failing on `main` as of 6112a39205. #15402 squash-merged at
18:06:16Z carrying a `lane-allocator.test.ts` that asserts `mise --version`
succeeds and drives the real binary. No mise exists on that runner. The corrected
version was pushed to the branch minutes after the merge and never landed — my
error, and worth naming precisely: I pushed a fix and then reported the PR as
"rebuilding" without confirming the head sha the merge would actually take.

THE FIX IS NOT THE REGISTRY ESCAPE, and rejecting it is the substance here.
`registry/environment-dependent-test-files.json` exists for exactly this shape, so
it was the obvious move — but `test (TS environment-dependent)` HAS NO MISE EITHER
(measured: `grep -ci mise` over the job body returns 0). Registering would have
moved the file to a tier that also cannot run it, which is what that guard itself
calls deletion wearing a tier move. An escape hatch being available is not the same
as it being correct.

What is actually OUR contract is narrow: after `git worktree add`, invoke
`mise trust --all --yes` WITH CWD SET TO THE NEW WORKTREE, and do not let its
failure break allocation. Whether mise then honours the grant is mise's contract,
not ours. A recording stub on PATH tests our half exactly, in every environment,
with no toolchain dependency — and the cwd is the assertion carrying the weight,
since mise keys trust BY PATH and a grant made in the repo root would look
identical in any log while granting nothing.

It also buys a test that could not be written before: a stub that EXITS NON-ZERO
exercises the trust-failed branch. That branch was written as a deliberate
non-fatal choice — a lane that cannot be trusted is still a usable lane — and had
never executed once. A real mise cannot be made to fail on demand.

Net: 2 tests, no environment dependency, no registry entry, one previously-dead
branch covered, and `test (TS hermetic)` green again.
