# Summary

Redo of the dead-button defect on #11104. After device authorize, "queue harmless verification" stayed disabled because it shared the supplied-proposal `enabled` flag, which still required `payload.trim().length > 0`. Authorize never writes a payload, so the automatic path waited on the advanced textarea.

This splits the gates: generated queue is capability + registrySequence + valid baseSha only. `payload.trim()` stays on "queue supplied proposal" only.

Also drops the two leftover installer tests that still asserted dropped `isExactNonEmpty` fallthroughs (`"uuid-1 "` as "binding factor required"; dirty iserial falling through to uuid). Production `installer-binding-cli.ts` is untouched. #11125 / #11241 already pin `hasBoundaryWhitespace`; the existing "boundary whitespace is REJECTED" block covers it.

Does not merge #11104. Does not touch #10843 or consent docs.
