## Ace slice 5.2 design — semver ranges + version solver (081KR2E4K0008QG0R002YE3MMD)

Design spec for slice 5.2, building on the merged slice 5.1 (registry exact-version, #6369). Brainstormed + decided with the operator 2026-06-01.

**Locked decisions:**
- **Pragmatic semver subset** — `^ ~ >= <= > < =`, exact `x.y.z`, `* / x` wildcards, space-AND-ranges. (`||` / hyphen / pre-release / build-metadata deferred → 081KT07NV0008QG0R002WK9064.)
- **Own deterministic newest-first backtracking solver**, dependency-free on the install hot path.
- **Clean two-phase split** — `solve()` produces a `name → concrete version` map; slice-5.1's `resolve()` consumes it via one minimal `solved`-map param and runs its existing verify + atomic install unchanged. (Single-fetch cache deferred → 081KT07NV0008QG0R003659TWT.)
- **Z3 tests our TS** — `z3-solver` (WASM) for end-to-end assignment + `node-semver` for the `satisfies`/`compare` primitive, both **test-only devDeps** that always run in CI (assert, never skip — no false-green hole). Pinned via WebSearch at build time.

**New modules:** `tools/ace/semver.ts` (pure subset parser + `satisfies`/`compare`/`maxSatisfying`), `tools/ace/solver.ts` (`solve()`). New `ResolveReason`s: `unsatisfiable`, `bad-range`.

**Sliced off for further enhancement** (operator "everything we skipped lets slice off"): **081KT07NV0008QG0R002WK9064** advanced semver, **081KT07NV0008QG0R000SJ34AK** remote registry, **081KT07NV0008QG0R003659TWT** solver↔installer single-fetch cache.

Spec: `docs/agendas/ace-package-manager/2026-06-01-ace-cli-slice5.2-semver-solver-design.md`. Slice 5.3 (lockfile) remains the next slice.
