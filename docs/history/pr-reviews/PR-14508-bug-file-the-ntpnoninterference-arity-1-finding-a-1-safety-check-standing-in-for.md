bug: file the NtpNoninterference arity-1 finding — a 1-safety check standing in for a 2-safety property

Filed as 081M0RAX8AC087G0R003NQM7P9 (P2). Found by Lumen during the local-to-global
research (#14501), independently re-verified against origin/main before filing
rather than taken at face value.

tests/Tests.FSharp/Formal/NtpNoninterference.Tests.fs, the property named
"renderCard (the minted content) is a pure function of the link — no clock input",
asserts:

    MP.renderCard l = MP.renderCard l

A value compared to itself: an arity-1 (single-run) check standing in for a
2-safety property. Noninterference is a HYPERPROPERTY (Clarkson & Schneider 2008)
— a predicate over PAIRS of executions — so a single-run test is PROVABLY
INCOMPLETE for it. That is a structural limit, not a coverage gap. And the
property this test names is already guaranteed by renderCard's signature, so it
cannot fail on the bug it targets.

Scoped honestly rather than rounded up: it is NOT strictly vacuous. It could fail
if renderCard were impure or nondeterministic. What it is, is a check whose
failure probability under its target bug is approximately zero while its name
claims the stronger property. Disposition unmetered, not refuted — calling it
vacuous would be the same error in the other direction.

The useful part is why it survived: Soraya fixed this EXACT class in this EXACT
file on 2026-08-18 — the [<Fact>] ten lines below carries the rewrite comment —
and this instance came through untouched. A targeted fix of a defect class does
not clear the class, because the search that finds one instance is not the search
that finds all of them. So the acceptance criteria require sweeping the F# test
tree for self-comparisons and reporting the full count, not fixing the instance.

The fix shape is already in the file: the sibling property immediately above
correctly varies two clocks and compares stripClock page1 = stripClock page2.
Deleting the test is also a legitimate outcome and is named as one — a test that
cannot fail is what makes coverage numbers lie.
