## Description

## Why

The durable browser runtime imported its inward storage contract from the outward IndexedDB adapter. That coupled application code and persistence semantics to one browser technology and left no clean insertion point for a future native ZetaDB browser adapter.

## What

- Extract the checkpoint record, feedback, result, and port into a technology-neutral source module.
- Own monotonic save, idempotent retry, byte-conflict, identity, and bounded-removal decisions in shared policy.
- Make IndexedDB one adapter over that contract and normalize operation failures to port-level feedback.
- Rewire durable runtime and fixtures through the port while keeping native startup adapter-specific.
- Harden service-worker smoke readiness against Chromium document/controller races.
- Fix the pre-existing malformed Halsey markdown table row found by the full gate.

## Proof

- 21 focused checkpoint and durable-runtime tests pass.
- `bun run preflight` passed all 14 dimensions, including release build and full .NET tests.
- Final rebased `bun run preflight:quick` passed all 12 dimensions.
- Real Chromium multi-tab smoke passed five consecutive fresh runs and again after final rebase.
- Browser PWA smoke passed.

## Limits

This establishes the owned checkpoint boundary and shared persistence laws; it does not yet implement the future ZetaDB browser adapter. IndexedDB remains the selected native browser edge.
