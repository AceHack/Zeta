## Description

The flush step's probe read `repos/$GITHUB_REPOSITORY/commits` — a CONTENTS
read — while the step's actual work is `gh pr create`, which needs
`pull_requests: write`. Different permissions. So a credential could pass
the probe and die on the work, and the guard could not fail for the reason
the step fails.

It did exactly that, twice on 2026-08-25. The probe passed, `gh pr create`
returned HTTP 403, and because the guard reported healthy the red read as a
broken flush: three agents diagnosed it as an auto-merge fault, and I spent
two rounds telling the maintainer his token was misconfigured. It was not.
The step was calling PR-create with the BRANCH-PUSH credential; #15351's role
separation is what actually fixed it, and the flush armed PR #15361 on the
next run.

A write scope has no side-effect-free endpoint, so this probes it with a
create that CANNOT succeed — `head` names a ref that does not exist — and
reads the status code, which discriminates exactly the two cases:

    403   the credential may NOT create pull requests here
    422   the credential MAY; the request was merely invalid

VERIFIED BEFORE SHIPPING against a known-good credential:

    POST /repos/Lucent-Financial-Group/Zeta/pulls
      head=zeta-scope-probe-nonexistent-ref-do-not-create
    -> HTTP 422 {"resource":"PullRequest","field":"head","code":"invalid"}

422, not 403, and nothing was created. That is the control: a probe that
returns 422 for a permitted credential and 403 for a denied one actually
discriminates, where the old one returned success for both.

The contents probe is KEPT as a separate question rather than replaced — the
step reads the repo as well as writing PRs — so a failure now names WHICH
capability is missing instead of implying the wrong one. The run id is
interpolated into the probe head so two concurrent lanes cannot collide, and
an unexpected SUCCESS warns loudly, because that would mean the probe created
something.

Scoped to the flush step deliberately. The arming step at ~2120 carries the
same pattern and a different consequence (it degrades rather than failing),
so it gets its own change rather than riding along on this one.
