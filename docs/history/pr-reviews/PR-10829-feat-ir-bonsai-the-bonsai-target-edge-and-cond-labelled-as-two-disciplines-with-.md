## Description

## What this is

[#10827](https://github.com/Lucent-Financial-Group/Zeta/pull/10827) found that idiomatic emission needs **no new IR version and no new format**, and that the gap is a **missing edge**: `rg -l 'Bonsai' src/Core/ZetaIr*.fs src/Core/MixIr.fs src/Core/Cogen.fs src/Core/GrammarIr.fs` → empty. Bonsai has four oracles and **zero emitters**; `ZetaIrV1`–`V4` has six emitters and no expression level.

**This is the edge, working.** One generator, one target (Rust), one higher-level `fn` pair (`map` + `join`). No v5, no new format, no new node kind, no version tag moved — `map`/`join`/`row`/`loop_accum` are new **values** of `Call.fn`.

One Bonsai expression, written once. A **target descriptor** — beside the emitter, never in the IR — declares which `fn`s a target expresses natively; `arrest` lowers only until none is left.

| rung | vocabulary | Rust emitted |
|---|---|---|
| **L1** | `map`, `join` | `inputs.iter().map(…).collect::<Vec<_>>().join(",\n")` |
| **L0** | `loop_accum` | `let mut s = String::from(…)` + `for … enumerate()` + a comma branch |

The correction **strengthens** the design: the arrest ladder **is** the spec/specialization split. L1 (`map`, `join` — elementwise, associative fold) is what a program may say; L0 (`loop_accum` — sequential) is a lowering product, never authored. `assertParallelShaped` makes that a check rather than a convention.

## The finding, worth more than the edge: `Cond` has no agreed arm-evaluation semantics

All four byte-lock oracles are **serializer-only** — no evaluator in the C# or Rust oracle at all. Three evaluators exist, and they disagree:

| evaluator | arms evaluated | shape |
|---|---|---|
| `src/Core/BonsaiSoft.fs` | **BOTH**, blended by truth-confidence | **predication** — permitted under Aaron's rule |
| `src/Core/Resume.fs` | **ONE** | short-circuit — divergent |
| `src/Core.TypeScript/bonsai/resume.ts` | **ONE** | short-circuit — divergent |

**Executed, not inferred.** One expression, `Cond(true, 1, Param "nope")`, serialized once:

* `resume.ts` → `{ok: true, value: {kind: "done", value: {t: "int", v: 1}}}`
* `BonsaiSoft.evalSoft` → `Error "BonsaiSoft: unbound param 'nope'"`

Same bytes, opposite outcomes. **Not a bug in either** — short-circuit is correct for a saga interpreter whose arms may contain side-effecting activities, which is Aaron's layer split arriving on its own. The defect is that the **spec never said so**. **Not resolved here:** picking the spec reading changes what the format *is*, which is a gated call. Observation attached; authorization not.

> **Aaron, 2026-08-15:** *"yes we just need to make sure everything is labeled honestly and able to be reasoned about in the domain in which it is active. Choose the right specialization for the job and make sure you don't use one assuming it's the other. In worst case we would need two specs."*

**A correction to my own earlier framing in this PR, flagged.** I wrote that *"the spec reading of `Cond` is `BonsaiSoft`'s"* and that short-circuit *"belongs to specialization."* **Withdrawn** — that was still picking a winner, dressed as a layering argument. ### The bar was behavioural, and it is met

> Can a program authored under one discipline be silently evaluated under the other? **Before: yes. Now, through the checked path: it refuses by name.**

`bonsai-discipline.ts` names the two disciplines, registers each evaluator with the one it *actually* has, decides statically whether a program's meaning depends on the discipline, and refuses the handoff on mismatch.

**The labels are metered, not asserted** — this is the load-bearing part. `bonsai-discipline-probe.ts` runs `Cond(true, 1, Param "nope")` through all three evaluators (TS in-process; both F# ones through the real built `Zeta.Core.dll` via `dotnet fsi`, not a transcription) and fails on any registration observed behaviour refutes. **Executed, exit 0:**

```text
BonsaiSoft.evalSoft    error BonsaiSoft: unbound param 'nope'   demonstrates predicated     registered predicated     OK
Resume.run             value 1                                  demonstrates short-circuit  registered short-circuit  OK
resume.ts start        value 1                                  demonstrates short-circuit  registered short-circuit  OK

discipline-sensitive: true ($.else free-param-in-arm)
REFUSED: DISCIPLINE SUBSTITUTION: … authored under `short-circuit` … aimed at `BonsaiSoft.evalSoft` … which is `predicated` …
same program → resume.ts start: ok=true (disciplines match)
a closed/total Cond → predicated evaluator: ok=true (program is not discipline-sensitive)
```

The last two lines matter as much as the refusal: the guard is **quiet where substitution is harmless**, because a guard that cries wolf gets switched off.

**Sensitivity uses only causes that were *observed* to differ** — a `Call` in an arm, and a **free** param in an arm. Conservative: may over-report, does not under-report on those two. **Named gaps:** an ill-typed `Binary` in an arm and arithmetic overflow are real causes it cannot see, so `sensitive: false` means *"not sensitive for the two causes checked."*

### What this deliberately does not do

* **Does not move the wire format.** The program↔discipline pairing is a **sidecar**; `serialize` is byte-identical with or without it, asserted. Putting the discipline *in* the bytes may be the cleaner end state — it is a program property, so #10827's carved test does not exclude it — but **that is a gated format change.** Written up, not landed. The "two specs" outcome Aaron sanctioned remains available.
* **Does not intercept a direct call.** Nothing stops calling `BonsaiSoft.evalSoft` directly. This guards the checked path and makes the unchecked one *nameable*; calling it a sandbox would be the vacuity class.
* **Does not touch the evaluators.** Ruled out, and I agree — making them agree silently picks a reading. `BonsaiSoft.fs` / `Resume.fs` / `resume.ts` read-only; **sibling agent holds that seam** (injected scheduler) — no overlap in files touched, but they should know the probe now pins observable `Cond` behaviour on all three.
