## The four candidate architectures

Each evaluated against the four-property hodl invariant (DST-safe + lock-free + scale-free + DBSP-native, per B-0196). None is pre-selected.

1. **Two-tier**: F# DSL for hodl-required substrate; CodeAct Python for ecosystem-reach work.
2. **F#-emits-Python via codegen** using `FSharp.Compiler.Service`.
3. **Pythonnet / Python.NET interop**: CodeAct Python calls into compiled F# .NET assemblies. Lowest-friction PoC candidate.
4. **F# Type Providers wrapping Python libraries** (extends FSharpx Type Providers pattern).

## The four-property hodl gate at the boundary

Across all four candidates, the load-bearing engineering choice is **where the Python execution lives relative to substrate-modifying work**. Python is where DST is hardest (GC non-determinism + hash randomization + threading); the rule that follows is **keep DST-violating Python operations isolated to non-substrate-affecting work**.

## Where each language wins

- **F# DSL beats CodeAct** on: compile-time UoM, retraction-native semantics, DST, formal-verification composition.
- **CodeAct beats F# DSL** on: Python ecosystem reach, LLM pre-training overlap, lower adoption barrier, broad benchmark coverage. CodeAct paper: Wang et al., ICML 2024, [arXiv:2402.01030](https://arxiv.org/abs/2402.01030), verified via WebSearch per Otto-364 search-first authority.

The bridge **composes** both languages without either giving up its structural strength; CodeAct is treated as a parallel path, not "wrong" or "abandoned".
