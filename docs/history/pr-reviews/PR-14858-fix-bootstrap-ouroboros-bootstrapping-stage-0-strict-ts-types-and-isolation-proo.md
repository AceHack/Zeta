## Description

## Rescue commit (`4341bb6a8`)

The original commit wrapped the above around an **incomplete file relocation** that broke the build. Six repairs, each on the merits:

1. **`../common/deps-graph/deps.ts` → `./deps.ts`** — the relocation was never performed; no such file exists on the branch or on main. This one dangling specifier is the **root of five red checks**: `ace.ts` failed to load at all, which is why `cross-verify`'s ace suite reported failures in tests that never ran, and why tsc's two `TS7006` implicit-any reports appeared (`AppDependencyGraphSpec` was unresolvable, so `graph` degraded to `any`). Both vanish with the import.
2. **`../common/crypto/signing.ts` → `./signing.ts`**, and the three unreferenced copies under `src/Core.TypeScript/common/crypto/` are removed. They were byte-identical forks of `ace/{signing,canonical}.ts` differing only in a rewritten relative import, and `common/crypto/signing.ts` imported back into `../../ace/store.ts` — the extraction decoupled nothing. Left in place it was a live hazard: `verifySignature` is the install-time authenticity gate, and `ace.ts` would have run copy A while `resolve.ts`, `registry-publish.ts`, `capability-manifest.ts`, the other 15 importers and `signing.test.ts` all exercised copy B. The copy actually gating installs would have been the **untested** one, free to drift. No falsifier is lost — `ace/signing.test.ts` and `ace/canonical.test.ts` are untouched and still cover the surviving implementation. Relocating crypto properly means moving all 19 importers at once; that belongs in its own PR.
3. **`from "./store"` → `from "./store.ts"`** — not cosmetic. The static guard in `ace-node-runtime-parity.test.ts` refuses extensionless relative specifiers in ace's runtime closure, because node's ESM resolver requires the extension and bun's does not.
4. **`tests/cross-verification/bootstrap-stage-0.test.sh` → `src/Core.TypeScript/ace/bootstrap-stage-0.test.ts`.** The assertion is worth keeping (ace must build and run with Zeta absent — the Ouroboros base case), but **nothing invoked the script**: no workflow, no `package.json` script, no harness. It sat in a directory whose every other entry is a cross-*language* oracle suite, and it tripped `check-bash-retirement-inventory --enforce`. Allowlisting it would have widened a guard to admit a test that never ran, so it moves to where bun discovers it and runs on every PR. Verified as a **real falsifier**: against the original `ace.ts` it FAILS, against the repaired one it passes — it would have caught defect (1). It now also builds into a temp dir rather than the worktree's `scratch/`, where residue from a previous run can make it pass.
5. `await await loadRegistries(...)` → single `await`.
6. `main()`'s body re-indented to 2 spaces; its two mid-file imports hoisted into the top import block.
