## Description

Trajectory slice 2: the fingerprint constraint from local-trust-view-decentralized-identity.

A node computes its own neighbourhood WITHOUT the global graph existing anywhere. The fingerprint is a lossy projection — information is discarded by construction, not hidden by policy.

## Structural guarantees (all tested)

1. **Lossy** — subjects bucketed into phase-distance histogram (counts only, no IDs)
2. **Local** — computed from held anchors, no ambient state
3. **Pure** — deterministic given inputs
4. **Non-enumerable** — output type contains no subject identifiers
5. **Heterogeneous** — node-specific binning prevents cross-node joins (Narayanan-Shmatikov defence)
6. **Safe to exchange** — comparison reveals strictly less than either fingerprint

## Key design decisions

- Histogram over phase-distance reveals topology (dense/sparse, recent/stale) without identifying relationships
- `nodeSpecificBins(seed)` makes each node's bucketing incompatible with others — even with the same data, fingerprints from different nodes cannot be joined
- `compareFingerprints` works only between compatible bins (structural refusal, not policy)
- The separation from `local-trust-view.ts` is deliberate: holding both point-query AND summary in one object would make enumeration possible
