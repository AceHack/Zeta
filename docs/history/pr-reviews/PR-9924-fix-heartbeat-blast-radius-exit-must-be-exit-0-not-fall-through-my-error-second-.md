## Description

#9911 replaced `exit 1` with **nothing**. That was wrong in a different direction, and the 19:56 tick proved it: **otto failed again** while alexa and soraya went green — the same asymmetry, because otto holds healer duty.

## Why fall-through fails

When the bound is exceeded the healer **writes nothing** — but `--plan-out` is written **before** the bound check, so `/tmp/heal-plan.txt` still holds the full oversized plan (~1005 entries).

Without an exit, the step falls into the staging block and runs:

```
git add --pathspec-from-file=/tmp/heal-plan.txt
```

over ~1005 paths that were **never modified**. Under `set -e`, any refusal — an ignored path, a pathspec matching nothing — kills the step.

Confirmed by elimination in the run log: the last line emitted is *"Continuing the tick"*, and the step dies after it.

`exit 0` ends the **step** successfully and the job continues — which is what *"loud but not fatal"* actually requires. The `::warning::` still fires, the finding is still surfaced, the other duties still run.

## The pattern worth naming

I've now made both halves of this in one day:

> **"Do not fail" and "do nothing" are different instructions.**

#9911 removed the failure and accidentally requested the fall-through. The correct shape for a detector that must not block is **report, then stop cleanly** — never report and then continue into work predicated on the thing that didn't happen.
