## Why this rule blocks

`gha-action-mutable-tag` — a third-party action pinned by a **mutable tag**. The rule cites **CVE-2025-30066** (March 2025): a tag-rewrite on `tj-actions/changed-files` landed a malicious commit on **23,000+ repositories** through exactly this path.

A tag is a movable pointer. The upstream owner — or anyone who compromises them — can repoint it at new code that then runs with this workflow's token.

## Fix

Reused the pins **this repo already uses elsewhere**, rather than inventing SHAs:

```yaml
uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
uses: oven-sh/setup-bun@0c5077e51419868618aeaa5fe8019c62421857d6 # v2.2.0
```

Verified no mutable-tag `uses:` remains anywhere in `.github/workflows/`, and the workflow YAML parses.
