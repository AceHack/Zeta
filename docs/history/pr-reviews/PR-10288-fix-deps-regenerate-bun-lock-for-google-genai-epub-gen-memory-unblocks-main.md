## Description

`main` is red. `docker-windows-install-ps1-test` fails at `bun install --frozen-lockfile`:

```
error: lockfile had changes, but lockfile is frozen
```

## Cause — isolated to one commit

`c101a6ac9` ("feat: setup continuous translation github action and automated ebook generation") added two entries to `dependencies` in `package.json` without regenerating `bun.lock`:

- `@google/genai: ^2.16.0`
- `epub-gen-memory: ^1.1.2`

Ruled out before concluding: `package.json` / `bun.lock` were otherwise untouched since `3f16e2ee3`, and runs succeeded after that (`3a7158821`, `06649983a`, `fb37563da`). The bun build is **identical** across the last success and the failure — `bun install v1.3.14 (0d9b296a)` both times — so this is not toolchain drift.

## Fix

`bun install`, recording the resolution the declared dependencies already imply.

- **`bun.lock` only** — 166 insertions, additive
- **`package.json` byte-unchanged**
- Verified locally: `bun install --frozen-lockfile` → `Checked 413 installs across 408 packages (no changes)`
