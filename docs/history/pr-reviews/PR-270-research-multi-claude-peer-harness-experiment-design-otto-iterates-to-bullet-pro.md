## Otto-iterates-to-bullet-proof structure

1. Run iteration (lowest-fidelity first: subagent simulation / synthetic rows)
2. Measure against 5 success criteria + 8 failure-mode table
3. Identify gaps; revise design
4. Repeat until 2 consecutive iterations with no new failure modes

Then hand off to Aaron for single Windows-PC validation run when convenient.

## Mechanism candidates for Otto's solo iteration

- Subagent dispatch (Task tool) as peer-simulation
- Paired worktrees + sequential simulation
- Bash-spawned background `claude` processes
- Synthetic tick-history rows

Otto picks based on what actually works.

## Test-mode bounding (Otto-86 hard requirement)

- 30-minute wall-clock per iteration
- Process-kill target
- 10-PR async-dispatch cap
- Wall-time instrumentation

Removed in real use (stage d) only.

## 5 success criteria / 8 failure modes

Success: both complete / no resource conflicts / cross-session review happens / test-mode bounds hold / no identity-blending.
Failures: CRITICAL (cross-edit corruption, infinite-loop-bypass, prompt-injection); IMPORTANT (contradictory review, dominance, identity-blending language); WATCH (clock-approaching, name-conflict).

## Architecture

Coordinate via existing Zeta substrate (git + tick-history + memory); no new protocol. Cross-session review yes, cross-session edit no. Secondary picks its own loop-agent name per Otto-79.
