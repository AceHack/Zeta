## Description

# Summary

Follow-on to #10632. Gap 2 gated `mumps-output.json` but never ran the packer, so a weight edit in `mumps_zeta_id.m` could sit behind a stale file until someone regenerated by hand.

This slice **executes the committed `.m` file** against `vectors.yaml` via a subset interpreter (`NEW`/`SET`/`FOR`/`QUIT`/`$$label`/`$CHAR`/`$SELECT`/`$EXTRACT`). A `CAT*2` → `CAT*4` edit changes the live hex. Wired into the **existing** `cross-verify` job — no new workflow (factory: extend the trajectory).

`bun run-mumps.ts --write` regenerates the committed JSON. CI runs it without `--write` and diffs live vs committed.

# Spec alignment

No `openspec/specs/` change. The zeta-id compare gate already required the MUMPS oracle; this makes that oracle live.
