## Description

## The finding

`agencysignature-block.ts` calls `Human-Review` **"THE accountability claim"** in its own
`GOVERNANCE_KEYS` table. The only thing enforcing it was `validateReviewConsistency`, which
checks that the claim is internally consistent **with itself** — `explicit` requires evidence
`!= none`, and vice versa. Both halves are written by the commit author. Nothing queried
whether a review happened:

```console
$ git grep "pulls/.*reviews\|listReviews\|reviewDecision" -- .github/ src/Core.TypeScript/hygiene/
(empty)
```

And it was not backed anywhere else: `github-settings.expected.json` records
`required_pull_request_reviews: null` and `required_signatures: false`, and CODEOWNERS says of
itself that `required_approving_review_count: none` makes it inert. So the trailer was the
**sole** record of human accountability, **its author was its own subject**, and under
auto-merge the same actor wrote the claim, believed it, and merged it.

## What this adds

`src/Core.TypeScript/hygiene/human-review-evidence.ts` resolves the two mechanically-resolvable
evidence values against the forge — `pr-review` via `pulls/{n}/reviews`, `pr-comment` via
`issues/{n}/comments` — behind an **independence filter**: no self-review (the audited defect
one API call further out), no bots, no `PENDING`/`DISMISSED`, and no review of a commit that
history rewriting has since removed. `CHANGES_REQUESTED` and `COMMENTED` count — the claim is
that a human *reviewed*, not that a human *approved*.

The existing self-consistency check is **untouched**; this is added alongside it.

### Fail closed on the claim, not on the tooling

| outcome | meaning | exit |
|---|---|---|
| `not-claimed` | `Human-Review != explicit` — asserts nothing, **no lookup at all** | 0 |
| `verified` | an independent human artifact exists on the forge and was read | 0 |
| `unverifiable` | `chat` / `signed-policy` — **states that it did not check** | 0 |
| `absent` | looked, and the claim is **refuted** | 1 |
| `indeterminate` | **could not look** (rate limit, network, bad JSON) | 2 |

A failed API call is not evidence a review is absent — it neither convicts nor acquits the
claim, so it gets a code that is neither 0 nor 1. The workflow step checks the fetch separately
rather than letting `pipefail` flatten a `gh` failure into "the claim is refuted". That
distinction *is* the finding, applied to this fix.

**Scope kept free:** `not-implied-by-credential` + `none` performs no lookup.

## The measurement that shaped this — read before trusting a green run

Counted across all of `main`:

| evidence value | count |
|---|---|
| `chat` | **501** |
| `pr-review` | **0** |
| `pr-comment` | **0** |
| `signed-policy` | **0** |

**Every well-formed `explicit` claim in this repository's history cites `chat`** — the one
category no forge query can resolve. A verifier for `pr-review`/`pr-comment` alone therefore
binds *zero* existing commits; shipped without saying so, it would go green forever while
verifying nothing, which is the audited defect rebuilt inside its own fix.

So the gate binds the checkable values **going forward**, and reports the others as
`UNVERIFIABLE` — explicitly stating it did not check, rather than passing them silently.

## Recommended, not taken (spec §10 governance gate)

Both are **enum changes**, which the spec binds to an `Agency-Signature-Version` bump plus a
ferry round, so they are written up and proposed rather than merged unilaterally:

1. **`attested-unverifiable`** — an explicitly-unverifiable attestation class beats an
   `explicit` that nobody can falsify.
2. **Evidence as a POINTER** (`pr-review#<review-id>`) rather than a genre label. §5.3 calls the
   field an "evidence pointer"; the shipped enum is a genre label. **Migration cost: zero for
   the 501 existing v1 commits** — the version key discriminates and `validateV2` is already
   version-conditional; ~8 in-repo producers move. The honest objection (a pointer must name an
   artifact that often does not exist at commit time) is weighed in the doc.

Verification itself is **not** a schema change: §7.6 already defines `explicit` as *"requires
independent human-generated evidence"* and §5.3 already says the pointer exists to make the
claim *"auditable"*. The enum shipped; the audit never did. This is the missing half.

Full analysis: `docs/research/2026-08-18-human-review-explicit-was-self-certifying-*.md`
