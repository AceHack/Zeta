## Description

## The ask

Aaron: *"it would be nice if we have some verification for target revisions to see if they exist and are published, some test."*

## The defect it exists for, and proof it catches it

`full-ai-cluster/k8s/applications/oz/Application.yaml:21` pins `ziti-controller` at `targetRevision: 1.4.5` — a version OpenZiti **never published**. Their 1.x chart line ends at `1.3.4`; `1.4.2` exists in that repository only as an `appVersion`, which is the application's version, not a coordinate Helm can resolve. ArgoCD cannot resolve the pin, so that Application can never sync. Invisible because `oz` is one of 26 of 45 Applications no CI lane exercises — nothing ever asked the registry for the chart. (`081M0JVD5YG087G0R002QDFR9H`, #13313.)

Run against the real tree, with the acknowledgement register emptied:

```
[target-revision-unpublished] full-ai-cluster/k8s/applications/oz/Application.yaml (openziti-controller)
  targetRevision `1.4.5` for chart `ziti-controller` is NOT among the 96 versions
  `https://docs.openziti.io/helm-charts/` published as of 2026-08-21T19:35:00Z. ArgoCD cannot
  resolve this pin, so this Application can never sync. Newest published: 3.2.1, 3.2.0, 3.2.0-pre8.
```

That is pinned as a test (`§THE LIVE TREE`), and the vacuity case is pinned beside it: the snapshot is asserted to hold **more than 50** versions **and** to contain `1.3.4`, so the "unpublished" verdict is about OpenZiti and not about an empty list.

## Offline vs network — the split is the design

| | offline (default) | `--refresh` |
|---|---|---|
| where | `gate.yml` cross-verify floor, **PR-blocking** | `chart-version-refresh.yml`, weekly + dispatch, **never required** |
| does | resolves every coordinate against `published-chart-versions.json` | re-fetches all 35 coordinates and rewrites that snapshot |
| network | none, no sockets | twelve third-party registries |
| may fail the merge | yes | **no** |

A resolvability check that talks to twelve registries on every PR is worth roughly one week: the first outage reddens changes that touch nothing near the cluster tree, and the step gets deleted by whoever is on the receiving end. So the blocking lane reads a file. The snapshot is **evidence with a date on it**, not an oracle: it says *as of `fetchedAt`, this repository published these versions*.

`--refresh` exits non-zero **only when the snapshot changed** — the signal that the diff needs committing — and it does not rewrite the file when it learned nothing. It deliberately does *not* fail merely because a fetch failed: two coordinates here are permanently unreachable (below), so that rule would have made the lane red on every run from day one, and this PR's own argument applies to it — `fetchedAt` alone is not a change (`sameIgnoringTimestamps`) because a signal that is always on carries no information. Unreachable coordinates are printed there, and named as findings by the offline audit on every PR.

## Coverage — 46 sources, 46 classified, 0 silently skipped

- **35** chart coordinates. **32** resolve; **3** are findings (below).
- **11** git-path sources (`cilium-lb-ipam, platform, hat-system, vllm, qwen-coder, cdi, gmod, kubevirt, agent-memory, orleans, deepseek-coder`) — no chart version to resolve, so classified `git-path` and printed **by name** in the pass line.
- **0** skipped. Coordinates are derived by walking `full-ai-cluster/k8s/applications/**`, never hand-listed. The walk is **recursive**, so `game-hosting/gmod/Application.yaml` at depth 2 is audited — the depth-1 assumption elsewhere in the harness is exactly how that manifest stayed invisible while failing to sync on every reconcile. `spec.sources` (plural) is handled; no Application uses it today.

Shapes handled: classic Helm repos with an `index.yaml`; OCI registries (`oci://`, bare `ghcr.io/...`) which have no index and are read through the registry tag API; and git-path sources, recognised explicitly.

**Nothing is skipped silently.** Unparseable YAML, a source that is neither chart nor git path (or is *both*), a source with no `targetRevision`, a coordinate the snapshot does not cover, a snapshot entry the tree no longer references, and an acknowledgement that outlived its defect are all **findings**. An empty tree is a finding.

## Two more live defects, found by the check's own first `--refresh`

Filed as `081M0JX4M7H087G0R0029R5QG6`:

1. **`sealed-secrets`** — `https://bitnami-labs.github.io/sealed-secrets` returns GitHub Pages' *Site not found*; `index.yaml` → **404**. Upstream's README now publishes at `https://bitnami.github.io/sealed-secrets` (no `-labs`), whose index **does** carry `2.16.2`. Host wrong, version fine.
2. **`forgejo`** — `https://code.forgejo.org/forgejo-helm/` is an organisation page, not a chart repository (`index.yaml` → **404**); the chart is OCI-only (`oci://code.forgejo.org/forgejo-helm/forgejo`). **Double defect**: that registry's 169 tags contain exactly one 9.x — `9.0.0` — so `9.0.6` was never published either.

## How it lands green while reporting three real defects

Not a silent allowlist. `ACKNOWLEDGED_UNPUBLISHED` is keyed **pin-exact** (`manifest|chart|targetRevision`) and every entry carries a **workitem, a date and a reason**. Acknowledged findings are **printed on every run** — they move lists, they do not vanish — and the register is drift-checked in **both** directions: change the pin, or fix it, and the acknowledgement fails as `acknowledgement-stale`. An allowlist only ever grows quiet; this one goes red when it stops being true.

Choosing what these three Applications deploy is the maintainer's call, not the auditor's — `oz` has 1.3.4 / 2.x / 3.x lines that are not drop-in, and `forgejo` needs a pick between 9.0.0, 10.x and 11.x under a hand-written `valuesObject`. **No manifest is edited in this PR.**
