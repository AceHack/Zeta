## The verified site

`tests/Tests.FSharp/FourCornerFusion.Tests.fs:104`, in
`no ArrowApply app: SchedulerZeta predicts the VALUE-channel period; interrupts are not in that map`:

```fsharp
let _interrupt = Interrupted SentinelMissing
let r2 = SchedulerZeta.predict key step start
Assert.Equal(r.Period, r2.Period)
```

`r` on line 98 is `SchedulerZeta.predict key step start` — the **same three arguments**. The
interrupt between them is bound to `_interrupt` and discarded, so it reaches neither call.
Both sides normalise to one expression, exactly as the audit reports:

```
(SchedulerZeta.predictkeystep(FourCorner.ofIn"in"|>FourCorner.withOut"a")).Period
```

`f(x) = f(x)` over a pure function: true under every implementation of `predict`, including a
broken one. Reproduced locally before touching anything.

## The intent, preserved

The comment three lines above states the property the author was after:

> An interrupt in the ERROR channel does not change the predicted orbit.

That is a real and worthwhile claim — the file's whole thesis is that interrupts live in the
ERROR channel (sum) and corners in the VALUE channel (product). The defect is that the
interrupt was **discarded**, so it could not influence either call and the assertion
degenerated. Deleting the line would delete the claim, so instead the interrupt is made to
actually reach the second prediction: it is carried in the ticked state and advanced every
tick on a period of **three**, coprime to the corners' period of **two**.

- **CONTROL, asserted first** — keyed jointly, the orbit is `lcm(2, 3) = 6`. This proves the
  interrupt is genuinely live and genuinely on its own period. Without it the invariance below
  would pass just as happily if the interrupt never moved, which is the very defect being
  repaired.
- **THE CLAIM** — project that same interrupted run onto the VALUE channel and the corners'
  recurrence is untouched: same `Period`, same `Transient`, same `Reachable`.

Nothing is adjudicated into the census. This is a true finding and the registry is for
assertions legitimately narrower than they look.

## The mutant

In `src/Core/SchedulerZeta.fs`, `predict`:

```fsharp
- let k = key s
+ let k = hash s // key on the FULL state, ignoring the caller's projection
```

This is the precise defect the new assertion targets, and it is the one `SchedulerZeta`'s own
docstring on `runToHorizon` warns about — a projection that silently fails to project.

| | pre-fix test | post-fix test |
|---|---|---|
| against the mutant | **PASSES 5/5 — survives** | **FAILS: `Expected: 2, Actual: 6`** |

The pre-fix test survives because the interrupt-free state's *full-state* period is still 2, so
`Assert.Equal(2, r.Period)` on line 99 cannot see the mutation either. Only the new
value-channel projection over a state carrying un-projected, actively-advancing structure
distinguishes them.
