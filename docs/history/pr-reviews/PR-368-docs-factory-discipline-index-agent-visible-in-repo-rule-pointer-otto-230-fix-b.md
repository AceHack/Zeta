## Description

## Summary

Stop-gap fix (b) for the Otto-230 subagent-fresh-session
quality-gap debug. Mirrors session-captured Otto-NN disciplines
into the repo at `docs/FACTORY-DISCIPLINE.md` so dispatched
subagents can `Read` them without needing access to the
out-of-repo `~/.claude/projects/<slug>/memory/` store.

## What it covers

- Append-only audit-trail (Otto-229)
- Code comments explain code, not history (Otto-220)
- Name-attribution role references
- Verbatim-preserve vs factory-authored sections
- Glass-halo first-party vs third-party PII tiers (Otto-231)
- Auto-merge-always at PR-open-time (Otto-224)
- Drain loop has three axes — threads + CI + DIRTY (Otto-228)
- Hot-file cascade → bulk-close-as-superseded (Otto-232)
- Subagent fresh-session quality gap (Otto-230 itself)
- Serial PR open + parallel thread drain (Otto-225 + Otto-226)
- Post-drain AceHack-first routing (Otto-223)
- Branch-protection strict=false + strict-API PATCH (Otto-223)
- Cross-harness skill discovery (Otto-227)
- Three-outcome review-thread model (Otto-226 + Otto-227)

Each entry is one paragraph + pointer at the authoritative
memory file.

## Why

Subagents dispatched via the `Agent` tool have `CLAUDE.md` +
their dispatch prompt + `Read` access to the repo. They do
NOT have access to the factory-personal memory store where
recently-captured corrections live. When a subagent on
PR #364 normalised "May-01" → "2026-05-01" in a prior
tick-history row — violating the file's own append-only
discipline — the root cause was that the append-only rule
was captured in memory only, not yet in the repo. This file
closes that specific gap.

## What it's not

- Not authoritative. The memory files are. This is a
  forwarding pointer.
- Not auto-maintained. Manual updates from memory writes
  until the memory-sync mechanism (fix-a) lands.
- Not a full rule list. Stable `BP-NN` rules stay in
  `docs/AGENT-BEST-PRACTICES.md`. This is session-captured
  corrections distilled for subagent dispatch.

## Upstream

The memory-sync mechanism (fix-a) is already tracked at
elevated P1 priority in `docs/BACKLOG.md` ("Ongoing memory-
sync mechanism" row per Otto-114). When that ships,
subagents read the authoritative memory directly; this file
becomes a short-form index.
