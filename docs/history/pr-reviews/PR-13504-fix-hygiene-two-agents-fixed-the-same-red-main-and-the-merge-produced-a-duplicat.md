## Description

`main` is red on `lint (TS)`:

```
check-bash-retirement-inventory.ts(178,3): error TS1117: An object literal
cannot have multiple properties with the same name.
```

**Nobody wrote a duplicate.** #13494 (mine) and #13495 both registered `tools/setup/hsm/dkek-ceremony-preflight.sh` after #13479 left it undeclared, and they landed 3 minutes apart. Both were green. Git merged them without conflict because they inserted the **same key at different offsets** in `RETAINED_CATEGORY` — the textual merge succeeded and the semantic one did not.

Worth stating plainly rather than filing as a fluke: the **array** half of this inventory has a duplicate guard (`allowlist_duplicates`, which reported `0` throughout) and the **category-map** half does not. It did not need one — `tsc` catches TS1117 — but *the guard that exists and the guard that caught it are in different tools*, which is why the inventory report read clean while the build was broken.

The fix keeps **one** entry, in sorted position (from #13494), carrying the better comment (from #13495). Nothing is lost from either.

Verified: `tsc --noEmit` clean; inventory `duplicates 0 / order 0 / uncategorized 0 / stale 0 / unexpected 0`, `expected_retained: 32`; `check-bash-retirement-inventory.test.ts` 18 pass.
