Updates `axios` from 1.20.0 to 1.21.0
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/axios/axios/releases">axios's releases</a>.</em></p>
<blockquote>
<h2>v1.21.0 — October 21, 2026</h2>
<p>This release adds response timing and opt-in UTF-8 Basic authentication, improves request handling across runtimes, and changes how header defaults are recognized.</p>
<h2>⚠️ Breaking Changes &amp; Deprecations</h2>
<ul>
<li><strong>Header Defaults:</strong> Only plain objects, null-prototype maps, and compatible <code>AxiosHeaders</code> instances are treated as common or method-specific defaults; literal headers such as <code>Link</code> are now preserved. Applications using custom class instances as defaults must convert them to plain maps, for example <code>{ post: { ...customDefaults } }</code>, or compatible <code>AxiosHeaders</code>. Otherwise, those instances become literal header values, including on requests using other methods. (<strong><a href="https://redirect.github.com/axios/axios/pull/11156">#11156</a></strong>)</li>
</ul>
<h2>🚀 New Features</h2>
<ul>
<li><strong>Response Timing:</strong> Added <code>response.duration</code>, in milliseconds, including on <code>error.response</code> when present. Timing measures adapter execution and excludes interceptors and transforms; streamed responses stop timing when the stream becomes available. Axios replaces any existing <code>duration</code> value supplied by a custom adapter. (<strong><a href="https://redirect.github.com/axios/axios/pull/11214">#11214</a></strong>)</li>
<li><strong>UTF-8 Basic Authentication:</strong> Added <code>transitional.encodeBasicAuthUsername: true</code> to support Unicode usernames in XHR and Fetch requests. The option defaults to <code>false</code>, preserving existing authentication behavior; applications opting in should supply the original Unicode username and remove manual pre-encoding workarounds. (<strong><a href="https://redirect.github.com/axios/axios/pull/11159">#11159</a></strong>)</li>
</ul>
<h2>🐛 Bug Fixes</h2>
<ul>
<li><strong>Fetch Compatibility:</strong> Restored requests in runtimes such as Cloudflare Workers that reject the implicit <code>cache: 'default'</code>, while preserving explicit caller settings. Response-size failures now retain their original <code>ERR_BAD_RESPONSE</code> and request context when runtime wrappers replace the underlying stream error. (<strong><a href="https://redirect.github.com/axios/axios/pull/11194">#11194</a></strong>, <strong><a href="https://redirect.github.com/axios/axios/pull/11179">#11179</a></strong>)</li>
<li><strong>Runtime Consistency:</strong> Aligned encoded-byte size accounting, multipart uploads, proxy routing, same-origin resolution, parameter merging, and form serialization across adapters. Circular parameters now reject with <code>ERR_BAD_OPTION_VALUE</code>, and sparse or non-index numeric form fields serialize as keyed objects. With <code>proxy: false</code>, native <code>proxyEnv</code> agents using unsupported pool-management or TLS-session lifecycle overrides now reject with <code>ERR_BAD_OPTION_VALUE</code>; construct those agents without <code>proxyEnv</code>. (<strong><a href="https://redirect.github.com/axios/axios/pull/11242">#11242</a></strong>)</li>
<li><strong>Header Handling:</strong> Preserved headers named <code>__proto__</code> using safe casing without changing the <code>AxiosHeaders</code> instance prototype. Function matchers in <code>has()</code>, <code>delete()</code>, and <code>clear()</code> now receive the headers instance as <code>this</code>, matching their declared contract. (<strong><a href="https://redirect.github.com/axios/axios/pull/11134">#11134</a></strong>, <strong><a href="https://redirect.github.com/axios/axios/pull/11216">#11216</a></strong>)</li>
<li><strong>URL and Data URL Parsing:</strong> Accepted case-insensitive supported URL schemes and Base64 markers, and corrected decoding of percent-encoded Base64 data URLs. Node data URL allocation estimates remain aligned with decoding so configured size limits apply before allocation. (<strong><a href="https://redirect.github.com/axios/axios/pull/11138">#11138</a></strong>, <strong><a href="https://redirect.github.com/axios/axios/pull/11163">#11163</a></strong>, <strong><a href="https://redirect.github.com/axios/axios/pull/11294">#11294</a></strong>)</li>
<li><strong>Error Diagnostics:</strong> Preserved short reconstructed request stacks and appended wrapped error stacks under <code>Caused by:</code> so tooling that reads only <code>error.stack</code> retains the original failure context. (<strong><a href="https://redirect.github.com/axios/axios/pull/11132">#11132</a></strong>, <strong><a href="https://redirect.github.com/axios/axios/pull/11142">#11142</a></strong>)</li>
<li><strong>Interceptor Removal:</strong> Restored removal through canonical numeric-string interceptor IDs, including after registry compaction. (<strong><a href="https://redirect.github.com/axios/axios/pull/11139">#11139</a></strong>)</li>
<li><strong>Proxy TLS:</strong> HTTPS CONNECT tunnels now apply current origin TLS options from an explicit <code>httpsAgent</code>, or from <code>https.globalAgent</code> when no explicit agent is supplied. This preserves process-wide custom CA settings through proxy tunnels. (<strong><a href="https://redirect.github.com/axios/axios/pull/11178">#11178</a></strong>)</li>
<li><strong>XHR Lifecycle:</strong> Used asynchronous Cookie Store reads for XSRF tokens where supported, preserving cookie fallback, timeout accounting, and cancellation. Upload and download progress listeners are now removed on completion, failure, timeout, and cancellation.
