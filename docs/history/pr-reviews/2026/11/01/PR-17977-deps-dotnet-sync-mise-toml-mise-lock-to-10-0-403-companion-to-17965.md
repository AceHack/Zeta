## Description

## Why

Dependabot PR #17965 bumps `dotnet-sdk` 10.0.401 -> 10.0.403 but only edits
`global.json` — the dotnet-sdk ecosystem is the only file dependabot's updater
knows. The repo's `cross-verify (dotnet-pin-parity)` gate
(`src/Core.TypeScript/hygiene/audit-dotnet-pin-parity.ts`) requires `.mise.toml`
— the **single declared source** — to agree byte-for-byte with `global.json`,
and the pin is also carried in `mise.lock`. With only `global.json` moved,
`.mise.toml` stays at 10.0.401 and the parity gate goes red. That is the root
cause of #17965's `cross-verify (dotnet-pin-parity)` failure.

## What

Moves all three pin declarations to 10.0.403 in one commit:

- `.mise.toml` (canonical source)
- `global.json` (restatement for the no-package-manager clone-at-a-tag path)
- `mise.lock`

## Verification

- `bun src/Core.TypeScript/hygiene/audit-dotnet-pin-parity.ts` -> exit 0
  (`.NET SDK declared once: 10.0.403 ... restated identically in global.json`).
- 10.0.401 -> 10.0.403 stays inside feature band **10.0.4xx**, so no
  `Microsoft.CodeAnalysis.*` / `FSharp.Core` coupling is triggered — pure
  patch bump.

## Relationship to #17965

Landing this makes #17965 a no-op: once main carries 10.0.403, dependabot
auto-closes its bump (dependency already at target). Clears the parity-block
on the 10.0.403 uptake.
