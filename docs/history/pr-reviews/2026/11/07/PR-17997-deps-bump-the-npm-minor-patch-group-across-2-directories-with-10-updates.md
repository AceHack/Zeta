Updates `react-resizable-panels` from 4.15.0 to 4.18.0
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/bvaughn/react-resizable-panels/releases">react-resizable-panels's releases</a>.</em></p>
<blockquote>
<h2>4.18.0</h2>
<ul>
<li>Add the <code>normalizeWorkspaceModel</code> function, which checks and tidies a model the same way the <code>defaultModel</code> prop does (e.g. removing empty tabsets and fixing selections), and returns <code>null</code> if the value isn't a model (e.g. corrupt saved data). Its <code>mapTab</code> option replaces each saved tab with the app's current version (or removes it, by returning <code>null</code>), so layouts saved by older versions of an app can be restored.</li>
<li>Add the free space in each tabset's tab list (the space its tabs don't use; negative once they overflow), e.g. for a toolbar that moves items into an overflow menu when the header runs out of room. It's returned by the new <code>useTabListFreeSpace</code> hook and <code>getTabListFreeSpace</code> imperative method, reported to listeners added with the new <code>subscribeToTabListFreeSpace</code> method (e.g. from a toolbar rendered outside of the Workspace), and set as the tab list's <code>--tab-list-free-space</code> custom property. All of them are updated before the browser paints.</li>
<li>Fix <code>Workspace</code> tabsets being shown at their collapsed sizes with their content still rendered (and reported as expanded by <code>useParentTabsetState</code>) when the model's sizes don't fit the tabsets' minimum sizes, e.g. a model saved in a wider window, a workspace that's made narrower, or <code>expandTabset</code> shrinking a sibling below its minimum. Tabsets are now shown within their minimum and maximum sizes (rather than collapsed, when there's room), and tabsets that still have to be collapsed to fit are shown (and reported) as collapsed; the new <code>isCollapsedToFit</code> value (returned by <code>useParentTabsetState</code>) tells them apart from tabsets collapsed in the model (e.g. to hide an &quot;expand&quot; button, since they can't be expanded until they fit). The model isn't changed, so the tabsets are shown as the model has them again once they fit.</li>
<li>Add <code>maxWidth</code> and <code>maxHeight</code> to <code>Workspace</code> tabsets (and <code>updateTabset</code>), which limit how large a tabset's content area can be resized (e.g. a sidebar that can only grow so wide). Like minimum sizes, they must use absolute units. A maximum only applies if something else can take up the rest of its split (e.g. another tabset without a maximum); otherwise it's ignored, with a warning in development.</li>
<li>The default <code>Workspace</code> tabset drag preview now shows the number of other tabs being dragged after the selected tab's title (e.g. &quot;One (+2)&quot;). Tabsets with one tab, and workspaces with a <code>renderDragPreview</code> or <code>renderTabsetDragPreview</code> prop, show the same preview as before. - <a href="https://redirect.github.com/bvaughn/react-resizable-panels/pull/789">#789</a></li>
</ul>
<h2>4.17.0</h2>
<ul>
<li>Add dragging whole tabsets within a <code>Workspace</code>. A tabset is dragged by the empty space in its header, or by a <code>TabsetDragHandle</code> (or any element with a <code>data-tabset-drag-handle</code> attribute) when it has one. Dropping a tabset onto the edge of another tabset moves it there; dropping it onto another tabset's center or tab list moves its tabs into that tabset. Tabsets with the <code>keepWhenEmpty</code> flag can only be moved, not merged.
