## Description

## Not a flake — an unsound assertion

`MixinTests."F# WeakMap elements are garbage collected…"` failed `gate (required)` on main (`e42dcac8f6`, ubuntu-24.04-arm), and had been observed failing locally the same day on a different machine.

**MixinTests.fs:91** asserted `weakRef.IsAlive` *after* `RunGCScenario` returned — where the key is unreachable and liveness is guaranteed by nothing. That assertion was really asserting **the GC has not run yet**. A background GC collecting the key before the test's own `GC.Collect()` is legal runtime behaviour, and it is exactly what happened.

A test that passes only while the GC is idle is measuring the runner's load, not the WeakMap.

## The preconditions are moved, not deleted

They do real anti-vacuity work: without them, `Assert.False(weakRef.IsAlive)` passes trivially if the key was never stored or the weak reference never observed a live object.

They now run **inside `RunGCScenario`**, where `key` is reachable from the frame so liveness *is* guaranteed, with `GC.KeepAlive key` holding it across both. A second precondition was added — *the map actually holds the key while it is alive* — because "the weak ref saw something" is weaker than "the map stored it".

The surviving direction is the sound one: after an explicit blocking `GC.Collect()`, an unreachable object **is** collected. `GC.KeepAlive value` at the end keeps the *value* reachable throughout, so a collected value cannot make the result ambiguous about which reference was weak.
