## Description

## What

Insta360 Link Controller ships a CMIO camera system extension and has **no vendor uninstaller**. Parameterised so the next uninstaller-less vendor doesn't need a second script.

```
bun tools/setup/remove-vendor-system-extension.ts            # dry run
sudo bun tools/setup/remove-vendor-system-extension.ts --apply
# then REBOOT
```

## The thing it deliberately will not do

It never `rm`s anything under `/Library/SystemExtensions/`. That is a macOS-managed database keyed by UUID — hand-deleting a payload leaves the extension **registered but broken**, which is worse than leaving it installed. A removal that makes the system less consistent is not a removal.

The supported retirement is *remove the owning app, then reboot*. Confirmed on this machine the same day: after Defender's app was removed, `systemextensionsctl list` showed its extension as `[terminated waiting to uninstall on reboot]`.

`systemextensionsctl uninstall` is attempted first (documented direct route) but needs SIP disabled for a third-party extension. When it fails, that's **reported, not worked around**.

## Falsifiers

Seven tests, **mutation-verified in both directions** — this guard can fail dangerously either way:

| mutant | tests red |
|---|---|
| guard always `false` — would delete the macOS extension DB | 4 |
| guard always `true` — removes nothing, reports success | 3 |

The second mutant is why the control exists: without it, a guard that refuses *everything* passes every "it refuses X" assertion while silently doing nothing.
