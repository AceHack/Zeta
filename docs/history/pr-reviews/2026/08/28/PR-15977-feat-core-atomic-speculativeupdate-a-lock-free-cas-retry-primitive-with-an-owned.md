## Description

## What

`Atomic.speculativeUpdate` and `Atomic.trySpeculativeUpdate` — the optimistic
snapshot → compute → compare-exchange loop, over an owned port.

```fsharp
let landed  = Atomic.speculativeUpdate cell (fun s -> { s with N = s.N + 1 })
let didLand = Atomic.trySpeculativeUpdate cell (fun s -> s.Closed) (fun s -> ...)
```

`speculativeUpdate` returns the value that **won** the exchange, never the
snapshot it was computed from. `trySpeculativeUpdate` re-evaluates its abort
predicate against the **fresh** snapshot on every retry, and on a veto writes
nothing and never calls `update` at all.

## Three deliberate choices

**The port is ours.** `ICasCell<'T>` is the shape the algorithm depends on;
`Interlocked.CompareExchange` is one implementation of it, not the interface.
That is what makes the retry path *testable*: a lost race is otherwise only
reachable by scheduling two real threads and hoping, whereas against the port a
test can **script** a miss, so the retry is a replayable path (discipline #4)
instead of a flaky one. `CasRefCell` / `CasIntCell` are earned classes — hardware
CAS needs the address of a stable location, a location is state, and F# cannot
capture a `byref` in a closure, so the cell must own its storage.

**CE equality lives on the port**, because it genuinely differs per cell and
getting it wrong is silent. A reference cell compares by **identity** (two
equal-by-value objects are still a lost race); a primitive cell has no identity
and compares by **value**. A test pins exactly that: a CE result that is
structurally equal but a different object is a lost race, and reading it as a win
would silently drop the caller's write.

**No attempt ceiling.** A CAS loop only fails to progress when *some other*
writer succeeded, so it is lock-free by construction and the environment — not a
magic number — decides how long contention lasts. `Transaction.updateCas` caps at
1024 and throws, which converts someone else's success into our exception. That
cousin is **left untouched here**: it is a real behavioural difference and
deserves its own change with its own tests.

## Mutation results

A test that cannot fail is not a test, so each test was checked against mutants
of the implementation. **Ten mutants, nine killed**, and every one of the eleven
tests kills at least one:

| mutant | verdict |
|---|---|
| compare-exchange always succeeds | killed (4 tests) |
| no retry — settle after the first lost race | killed (4) |
| `update` hoisted out of the loop, computed once | killed (4) |
| returns the snapshot instead of the landed value | killed (6) |
| abort predicate ignored (abort still writes) | killed (3) |
| abort predicate inverted | killed (4) |
| try-variant always reports failure | killed (1) |
| ref-cell equality made structural | killed (1) |
| int-cell equality made constant-true | killed (2) |
| **`SpinWait` deleted** | **SURVIVED** |

The survivor is recorded **in the source**, not papered over. Backoff changes how
long contention *costs*, never what the loop *computes*, so the only test that
could observe it is a timing test — flaky and non-DST. That line is named
`UNMETERED` rather than left looking covered.

- **Stephen Toub** and **David Fowler** — the standing .NET concurrency lineage.
