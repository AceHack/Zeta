## Description

## Summary

- inject the owned `RevisionPolicyPort` through the native IndexedDB checkpoint boundary
- preserve monotone last-writer-wins when the option is omitted
- run one identical transaction history in two real Chromium tabs under explicit compare-and-swap and default monotone behavior
- validate shared concurrency laws plus intentional gap and recreate differences without depending on the in-memory adapter

## Measured result

Both policies serialized a concurrent revision-2 fork to exactly one accepted writer and one typed conflict. Compare-and-swap rejected revision gaps and non-1 recreation; the default monotone policy accepted revision 4 and recreation at revision 7. Both tabs read the same final durable row. The browser run passed 10 consecutive executions.
