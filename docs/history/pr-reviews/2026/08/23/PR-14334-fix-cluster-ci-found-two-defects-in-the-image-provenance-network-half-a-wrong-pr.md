## Description

fix(cluster): CI found two defects in this guard's own network half — a wrong probe, and a snapshot that changed because the measurer did

Both were found by reading run 32654405529's step output rather than its
conclusion. Both are the same class the guard exists to refuse.

1. `gh api user` IS THE WRONG PROBE IN CI
------------------------------------------
`ghUsable()` asked `gh api user`. `${{ github.token }}` is an INSTALLATION token
with no user behind it, so `/user` fails under it and the packages half reported
itself unavailable on a runner where it was merely asking the wrong endpoint:

    WARNING: `gh api user` failed, so the packages API half is unavailable.

Now `gh api rate_limit`, which answers for any valid token — user or installation
— because that is the question actually being asked ("is there a working token
here"), not "who is the human". `packages: read` added to the workflow's
`permissions` so the packages endpoint answers at all; read-only, least
privilege, nothing here writes a package.

2. THE SNAPSHOT "CHANGED" BECAUSE THE MEASURER DID
---------------------------------------------------
Consequence of (1), and the worse of the two. With packages access lost, the
refresh rewrote all 28 rows from `found`/`absent` to `unreadable` and reported
`ledger REWRITTEN` — a provenance move that did not happen. A signal manufactured
by the measurer is exactly what `chart-version-refresh.yml` already refuses in its
own `sameIgnoringTimestamps` rule, for the same stated reason: a signal that is
always on carries no information.

    AN UNAUTHENTICATED RUN MAY NOT UN-KNOW WHAT AN AUTHENTICATED ONE MEASURED.

`toLedgerEntry` now preserves `packagePresence`, `sourceRepo`, `sourceEvidence`
and `sourceVisibility` from the committed row when this run could not read the
packages API, instead of downgrading them. A BRAND-NEW row under degradation is
still `unreadable` and never `absent` — the original refusal is intact: an
unauthenticated run must not be able to invent the difference between a private
package and a missing one.

WHAT IS NEVER PRESERVED, and this is the load-bearing half
-----------------------------------------------------------
`artifact` — the anonymous pull. It is re-measured every run without exception,
because it is the half that decides REFUSAL. A package that goes private must go
red on the next refresh, and a rule that preserved it would make this ledger a
cache of a verdict rather than a record of a measurement. `packagePresence` only
chooses between two remedy TEXTS (flip visibility vs build and push), which is
why preserving it is safe and preserving the other would not be.

Three falsifiers added (38 cases now, up from 35): the degraded run preserves,
the freshly-measured half still flips `public -> denied -> ours-private` under
degradation, and a new row under degradation classifies `foreign-private` rather
than inventing "build and push it" for someone else's package.

Verified: `--refresh` now reports `ledger unchanged`, the offline check exits 0,
`tsc --noEmit` clean, eslint clean, `audit-cluster-tree-consumers.ts` clean.
