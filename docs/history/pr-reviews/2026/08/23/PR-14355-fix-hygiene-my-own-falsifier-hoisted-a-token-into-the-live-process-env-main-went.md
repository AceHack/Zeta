## Description

## Main is red on `hygiene:no-ambient-credential-hoist`, and the finding is mine

`#14336` landed the op-token-setup falsifiers and left one live finding:

```
tools/setup/op-token-setup.test.ts:177
process.env.ZETA_TEST_HOIST_PROBE = FAKE_TOKEN;
```

That line existed to prove FALSIFIER 3 **discriminates** — that "`process.env` is
byte-identical across a full run" is an assertion that *can* go red. To prove it, it
performed the exact act the file's whole argument says nothing should perform. **A test
that demonstrates a safety property by doing the unsafe thing is not a proof of the
property; it is an instance of the violation.**

## Why my local run missed it — the check ran against a different file than shipped

The line was originally `process.env[key] = FAKE_TOKEN`, which the guard's regex does not
match (it requires a quoted literal inside the brackets). I ran the guard: green. An
**eslint fix** (`@typescript-eslint/no-dynamic-delete`) then rewrote it into the dot form
the guard *does* match — after the guard had run. Same class as "verify the tree, not just
the command": the check ran, it just did not run on what shipped.

## The fix

The discrimination case runs against a **copy** of the environment. What is being shown
discriminating is the *assertion shape*, which a copy exercises exactly, and the test now
also asserts the real environment was never touched. The real-environment evidence is the
recorded **source mutation** (assign `process.env.X = capture.secret` inside `main` →
FALSIFIER 3 red), which was run, observed red, and reverted — twice.

## The near-miss, recorded because it is the lesson

When CI first went red there were **five** findings, four from `#14307`'s
`measure-lane-footprints.test.ts`, which plants `GITHUB_TOKEN` to prove the ghcr measurement
ignores it. I built a scoped `// hoist-guard-exempt: <reason>` line marker to license those
four — test-files-only, reason required, contiguous-comment-block only, with seven
falsifiers including "production code cannot claim it".

While I was doing that, **`#14328`'s author fixed the same red a better way**: they deleted
the env mutation and replaced it with a source scan asserting the module names no credential
variable at all — the same conclusion I reached about my own line, reached independently and
applied more thoroughly. That leaves my exemption mechanism with **zero call sites**, and an
exception mechanism with no consumers is a licence sitting in the tree waiting to be used.
So it is **dropped, not shipped**. One file changed here.
