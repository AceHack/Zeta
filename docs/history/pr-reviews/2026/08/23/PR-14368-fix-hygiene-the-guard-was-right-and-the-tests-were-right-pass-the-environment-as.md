## Description

# Summary

Between 17:0x and 18:20Z today `main` reddened twice on
`lint-no-ambient-credential-hoist`, both times against a test whose purpose was to prove that
some code **ignores** ambient credentials, and whose method was to set one. Two more agents got
pulled in: one built a scoped exemption mechanism and dropped it when the red was fixed better
(#14355); one narrowed the guard so the second line stopped being reported (#14353). Four agents,
two hours, one shape:

> The only obvious way to test that a credential is ignored is to make one present. A guard that
> forbids making one present looks like it forbids testing its own property.

It does not. The claim is never about `process.env` — it is about a **function of** an
environment. Pass the environment as a **value** and the hostile case is an object the test built,
so nothing crosses `exec`. #14330 demonstrated this once for its own case; this generalises it to
the class, gives it a helper, and makes the error message teach it.

**No exemption mechanism is added.** An annotated per-line adjudication was the fallback plan. It
would have permanently widened the guard's surface, and every later author would reach for the
annotation instead of the pattern.

| change | what |
|---|---|
| `secrets/env-witness.ts` (new) | `withHoistedCredential` builds the hoisted env as a value; `envDigest` / `envDiffNames` / `envNamesCarrying` are the detector. Pure, ambient-free, **not** on `SELF_EXEMPT` — a helper that had to be excused would refute its own claim |
| `teachingFor()` | a finding in a **test** file prints the pattern instead of a louder refusal; a finding in a shell script does not, because teaching that fires everywhere teaches nothing |
| `SELF_EXEMPT` | exported and pinned as a list, so the entire exemption surface is enumerable and an addition is a reviewable line |

# Spec alignment

No capability behaviour changes. §13 noninterference (Goguen & Meseguer 1982) applied to
credentials: a parameter is a declared channel, the ambient environment is the definition of an
undeclared one.

# Two coverage holes, each MEASURED before touching it

**CLOSED — a computed key walked straight past the rule.** The bracket branch accepted only a
*quoted* key, so `process.env[key] = secret` was invisible: a hole shaped like coverage. Now always
reported — no name test can clear a key that is not knowable at lint time, and resolving *unknown*
as permissive is the disposition `DerivationProtocol.fs` refuses. The escape hatch is free and
improves the code: write the key as a literal, which also makes the crossing greppable.
**Measured: 0 occurrences in the tracked tree.**

**REVERSED — the key-only narrowing let a rename evade the guard.** #14353 narrowed
`CREDENTIAL_NAME` to the assigned KEY alone, reasoning "a value named `FAKE_TOKEN` is not a hoist".
The principle is sound; the line it cleared was not covered by it —
`process.env.ZETA_TEST_HOIST_PROBE = FAKE_TOKEN` really was a hoist, which **#14355 confirmed three
minutes later by deleting the mutation outright**. A key-only test is also evadable by renaming,
and the author picks the key, so the subject chooses whether it is inspected. Restored to key OR
value. **Measured: 0 occurrences after #14355**, so this reds nothing. Both readings are recorded
in the test that reverses it, rather than one silently replacing the other — to the #14353 author:
this is a disagreement stated out loud, not a quiet overwrite.

**NOT DONE, named as a choice — convicting every non-literal value.** That is the sound general
rule (a literal cannot smuggle a runtime secret) and it **measures at 59 findings**
(`process.env.HOME = tempHome`, `PATH` prepends, `ace` fixtures). That is a different lint about
`process.env` writes in general and deserves its own decision, not one that arrives inside a
credential guard. Logged as a follow-up on the work item.

# Notes

**Own error, caught before push and pinned.** `envDigest`'s NUL separator was emitted as a RAW
`0x00` byte instead of the six-character escape. Every test passed and `git` classified the module
as **binary** — an unreviewable source file, in the file whose whole job is to be a proof, which is
exactly what `no-binary-in-proof-lineage` forbids for verification artifacts. Fixed, and
`env-witness.test.ts` now asserts the source carries no raw control bytes.

**Reported, not absorbed — a formatter can invalidate a check that already ran.** The #14355 agent
found that an eslint autofix rewrote `process.env[key] = ...` into the dot form *after* the guard
had run. That is a new member of the "check that did not run" family: the check ran, and the
artifact then changed underneath it. It belongs to the lint-ordering pipeline (formatters before
the checks that judge their output, or checks on the committed tree), not to this guard. Not fixed
here.
