## Description

## What

Retires `tools/setup/op-token-setup.sh` to `tools/setup/op-token-setup.ts`, and — the part
worth more than the conversion — turns the security model that file exists to hold from a
**comment** into **three falsifiers**.

The shell header claimed the token was never exposed. One of its claims was false:
`security add-generic-password … -U -w "$TOKEN"` put a 1Password service-account token in
`ps` output for the life of the call. `docs/SHELL-DEPRECATION-SEQUENCE.md` had already
**measured** that (`argv-secret@83`) and named it as the thing any conversion must fix
first. This carries that out rather than deferring it.

## Why — OS closure, not language preference

Aaron 2026-08-22: *"rewrite .sh files into .ts files allows the developer to have one
interface, the same interface for every operating system. One of the overarching goals of
Zeta is to completely close over the OS, like an interpreter closing over a compiler."*

A `.sh` file **is** an OS-specific interface: invoking it already commits the caller to a
POSIX shell, its word-splitting rules, and an 8-bit-exit-status result shape. The `.ts`
entry point replaces that with one command, one grammar, one result shape.

**Beacon anchor (Aaron's own, checked not merely cited):** he implemented Apple's **Carbon
API on Windows and Linux at MacVector** — a shipped instance of closing over an OS by
reimplementing one platform's interface on others. The asymmetry is recorded too: Carbon
closure targeted *source compatibility for existing apps* against a spec that could not be
negotiated; ours targets *one interface tuned for agents* against a spec that is ours.
Same technique, different consumer — do not read it as "we are doing what Carbon did".

## What the conversion genuinely buys — and what it does not

**Buys:** the token no longer reaches an argv · the security model is held by tests instead
of prose · failure paths teach · testable without a real Keychain · one fewer entry in the
retained-shell allowlist.

**Does not buy:** it does **not** remove `osascript` or `security` — it moves who spawns
them, and it is still macOS-only for those two calls. Saying otherwise would be the vacuity
this repo is built against. The new research note carries an **OS-closure ledger**: 1 of 4
seams closed, 3 named (`osascript` → secure-prompt port; `security -i` → keystore port
`081KVNRSGVR08QG0R003R3RNJX`; `pbpaste` → clipboard port). On Linux/Windows the command
**refuses and names the missing port** — it never silently no-ops.

## The falsifiers (the highest-value part)

`tools/setup/op-token-setup.test.ts`, sandbox-only — no real Keychain, no real `op`, no real
dialog:

| property | falsifier | shown red by |
|---|---|---|
| never on **stdout/stderr** | full run asserts no 12-byte window of the token appears in any emitted line | injecting a `fx.out(token)` |
| never on **argv** | the `security` argv is the constant `["security","-i"]`; `argvCarriesSecret` must be false for it and **true** for the old bash argv | restoring the `-w "$TOKEN"` shape |
| never in an **environment** | `process.env` is byte-identical across a full run | assigning `process.env.X = token` |

Each mutation was applied, confirmed red, and reverted — twice, since `main` was refactored
after the first round.

## Measured, not assumed

`security -i` **exits 0 even when the command fails** (write to a nonexistent keychain:
status 0, empty stdout, empty stderr — verified against a **throwaway keychain, never the
login keychain**). Its exit status is therefore never read; success is decided by **reading
the item back and comparing**. The sequence doc's suggested `-w`-with-no-operand prompt does
*not* fit a programmatic caller (positional-keychain arg ordering + a `/dev/tty`
`readpassphrase`); that correction is recorded in the doc.

## Not swept along, deliberately

`tools/setup/secret-clip.sh:93` carries the **identical** argv leak. It is **not** converted
here and stays allowlisted — a guarded, honest bash entry beats an unguarded rewrite, and it
is its own child of the umbrella. The generated table still ranks it row 2, which is the
point of a generated table.
