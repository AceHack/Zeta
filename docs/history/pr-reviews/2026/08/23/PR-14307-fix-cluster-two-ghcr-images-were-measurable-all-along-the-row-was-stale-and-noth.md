## Description

THE REPORTED CAUSE DID NOT EXIST

`ghcr.io/lucent-financial-group/{zeta-portal,zeta-platform-controller}` were
reported as "unmeasurable — awaiting the Danger Zone visibility flip". Both are
public. Measured 2026-08-23, anonymously, with no credential in the environment:

  gh api /orgs/Lucent-Financial-Group/packages/container/zeta-portal --jq .visibility
    -> public
  ghcr.io/token?service=ghcr.io&scope=repository:lucent-financial-group/zeta-portal:pull
    -> a token; the manifest then reads HTTP 200

A resolved blocker still being reported is the same defect class as a check that
did not run looking like one that passed, so it is fixed at the artifact AND at
the thing that let it stand.

THE HYPOTHESIS I WAS HANDED, AND WHY IT IS WRONG — CHECKED, NOT ASSUMED

The suspicion was that `measureImage` issues a bare `/v2/` request and reads the
401 as "private", never performing the anonymous-token handshake. It does not.
`fetchAuthed` reads the `WWW-Authenticate` challenge, fetches the free anonymous
pull token from the realm it names, and retries — and that code was correct the
whole time. Both files that measure images do it (`measure-lane-footprints.ts`
and `image-footprint.ts`).

Nor is the verdict credential-dependent. Nothing here reads `GITHUB_TOKEN`, `GH_TOKEN`
or a docker config; the only Authorization header ever presented is the registry's
own anonymous grant. Run against the two images with the environment stripped
(`env -u GITHUB_TOKEN -u GH_TOKEN`) they price at 43241230 and 42887187 bytes. So the
number does not change with who runs it, and I am saying that plainly because it is the
more important finding than the two images would have been.

WHAT ACTUALLY FAILED: THE ROW WAS NEVER RE-MEASURED, AND THE REASON COULD NOT SAY SO

#14250 states it outright — "No size was invented or re-measured." The two rows were
carried forward from a measurement taken before the packages were public. That is a
data-freshness failure, not a code failure.

What made it INVISIBLE is the code's, and that is the part fixed here. `manifest
HTTP 401` is equally consistent with three different findings:

  private repository        401, anonymous grant REFUSED
  repository never existed   401, anonymous grant REFUSED   <- ghcr answers 401, not
                                                               404, so as not to leak
                                                               which names exist
  this tool never asked      401, no grant attempted        <- OURS, a defect

The first two are genuinely indistinguishable from outside; the third is not, and the
artifact had no way to show which one it was looking at. `refusalReason` now names the
grant outcome, so a regression to a bare-401 read is visible in the CHECKED-IN FILE and
not only in a test run.

ANSWERING THE 401-vs-404 QUESTION HONESTLY: the status is recorded verbatim and always
was, so a genuine 404 has never been read as a 401. The conflation runs the OTHER
way, and it has two live victims. `ghcr.io/lucent-financial-group/zeta-orleans-silo`
and `.../hat-system-operator` are not private — the org publishes exactly two container
packages and neither of those is one of them. Their references DANGLE, and "unmeasurable
(401)" was hiding it. Same class as the private-repo dependency #14250 closed.

THE SEAM, AND WHY IT IS THE REAL FIX

`measure-lane-footprints.ts` had NO TEST. Its only network path reaches 129 registries,
so nothing could exercise the token dance offline, so the one thing it does that is easy
to get wrong shipped with nothing able to catch its removal. `FetchLike` is now injected
(default: global `fetch`) and `measure-lane-footprints.test.ts` drives an in-memory
ghcr.io emulator — no network, no port, no clock, so it replays deterministically.

The emulator is faithful to the two behaviours that matter, both measured live:
a public repository STILL 401s a bare read (a stub that served it unauthenticated would
pass against a tool that never learned to ask), and a denied anonymous grant comes back
HTTP **200** with an `errors` body, not a non-2xx (a stub returning 403 would let a
`tokenRes.ok`-only check through).

FALSIFIER, PROVEN TO DISCRIMINATE — four mutants applied one at a time, each reverted:

  M1  short-circuit the 401 handshake (the reported hypothesis)   killed by 4 tests
  M2  present an ambient GITHUB_TOKEN                             killed by 1
  M3  round a refusal to 0 bytes                                  killed by 3
  M4  collapse the grant outcomes back to a bare status           killed by 3

Restored: 9/9 green.

NO ALLOWLIST. Nothing here names these two images. The fix is a re-measurement plus a
seam; the next image gets the same treatment for the same reason.
