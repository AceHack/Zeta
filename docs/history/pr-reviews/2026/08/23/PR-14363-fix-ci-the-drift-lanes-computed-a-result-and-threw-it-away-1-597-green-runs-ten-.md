## Description

## The detector reported this in its own words

From `main`'s gate run 32655441086:

> **PUBLICATION NOT LANDING**: `data/platform-drift.json` is pinned at run 32232815018, older than every one of the 60 runs in this window (newest 32655872055). The tick computes and then throws the result away — the dashboard is showing stale numbers from behind a green check.

That is the vacuity class stated by the machine itself: a check that did not run wearing the face of one that passed.

## What was actually broken — measured, not guessed

`drift-sweep.yml` is the lane that writes `data/platform-drift.json`. It pushed its ledger straight at `main`, and ruleset "CI Gate" requires `gate (required)` at PUSH time with no bypass actors, so every push was refused from 2026-08-13 onward:

```text
remote: - Required status check "gate (required)" is expected.
 ! [remote rejected]     main -> main (push declined due to repository rule violations)
```

The refusal sat under `git push || echo "push race — next tick re-records (idempotent)"`. Result: **1,597 runs concluded `success`** while `docs/drift-events/` stayed frozen at tick `000247` and `data/platform-drift.json` at run `32232815018` — ten days of dashboard data served from behind a green check. Verified on this clone before touching anything: `git log -1 -- docs/drift-events/` is `2026-08-13 15:56:47`, and today's sweep runs read `success`.

**The `||` is the sharp part.** It misfiled a **permanent** rule rejection as a **transient** race. A race genuinely is re-recorded next tick; a ruleset rejection fails identically forever. So the lane kept "recovering" from something that could never resolve, and every recovery reported success.

`drift-dashboard-cadence.yml` carried the same defect in the other spelling — `git push origin HEAD:main || echo "::warning::…"` — under a comment claiming *"CAPABILITY tested, not just presence"* directly above a push whose exit code was discarded. Nothing was tested.

## The route (not invented here)

Both lanes now park on `heartbeat/*` and land via a PR with squash auto-merge armed, through `flush-via-staging.ts` — exactly as `tick-metrics`, `society` and the three `agent-heartbeat` lanes have done for months. That the route works is not a claim: #14290 (`heartbeat/tick-metrics`) and #14277 (`heartbeat/society`) merged today, and a production preflight at 18:05Z reads `[preflight] tick-metrics: push credential is authorized for this repository`.

The ruleset is untouched, no bypass actor is added, nothing uses `--admin`.

**And it fails now.** `flush-via-staging.ts` exits non-zero when the staging push or the PR call fails, and neither flush step carries `||` or `continue-on-error`. This deliberately reverses the old *"red runs here would just be noise"* comment: the noise argument is sound for a lost race and false for a broken route, and treating them alike is what cost ten days. An empty tick is still a clean no-op — idempotent without pretending.

## Two things found while doing it, that the fix itself created

- **A self-sustaining loop.** `drift-ledger sweep` mints a tick on *every* invocation — there is no "nothing happened" early return — and the flush now lands by a real actor's push to `main`, which `drift-sweep`'s own unfiltered `push:` trigger would catch. On a quiet repository that ticks forever. Bounded by a `paths-ignore` on the lane's own bookkeeping: a steady-state flush is skipped, a flush carrying an SLO filing still mints one tick whose own flush is bookkeeping-only and terminates. The file's "loop safety" paragraph is rewritten rather than deleted, because it was true and stopped being true.
- **Step ordering.** `prepare` leaves the lane's unlanded payload staged in the index, and the retraction actuator's `git revert` refuses to run against a dirty index. `prepare` therefore runs *after* the actuator, and the plain `reset --hard` sync stays.

## The falsifiers are the deliverable

`src/Core.TypeScript/hygiene/lint-drift-publication-lands.ts`, in the `gate` floor. Three rules over lanes **derived from content** — never a hand-kept allowlist, which is its own drift surface:

| rule | refuses |
|---|---|
| `route` | a publication push targeting `main` (including the bare `git push` this lane actually used) |
| `swallow` | a publish failure routed into `\|\| echo` / `\|\| true` / `\|\| exit 0`, **or** a `continue-on-error: true` publishing step |
| `capability` | a lane that publishes without a real `git push --dry-run` probe |

`capability` is the one that would have caught this **on day one instead of day ten**: a `secrets.A || secrets.B` ladder covers *absence* only, and #10850 already shipped a present-but-powerless token. Presence is not capability.

The `continue-on-error` half **cannot be caught downstream at all** — the REST jobs API reports a swallowed *step's* conclusion as `success` (`outcome` is workflow-local and absent from REST), so static text is the only channel that carries it.

Generation steps are untouched: `drift-sweep`'s platform-drift producer is `continue-on-error: true` on purpose, and a lint that forbade that would be pressure to weaken a correct design. A test pins that distinction.

And every mutant of the lint turns the tests red — no surviving mutants: swallow rule neutered `17 pass 5 fail`, capability `20/2`, bare-push detection `20/2`, comment blanking `19/3`, continuation join `20/2`, baseline `22 pass 0 fail`.

### One owned miss, pinned

The first version of the lint scanned **physical lines** and passed on a `|| echo` appended to a *continuation* line — which is the shape both shipped workflows actually use, so the one spelling it would meet in practice was the one it could not see. A guard that guarded nothing, inside the guard against guards that guard nothing. Found by running the discrimination proof, not by reading the code. Fixed, recorded in both files, and pinned by a test.
