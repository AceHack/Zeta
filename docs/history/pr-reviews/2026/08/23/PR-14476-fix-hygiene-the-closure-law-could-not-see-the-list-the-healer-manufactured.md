## Description

# Summary

The instance was fixed in #14435: `canInterruptParagraph` conforms to CommonMark's
paragraph-interruption rule, so a hard-wrapped `2007.` is prose and the healer no longer
manufactures the ordered list it thought it saw. **This PR closes the hole the instance came
through.**

The healer's write access is granted per-invocation by a certification whose closure law is
`d(heal(t)) ⊆ d(t)` — a healer may never MINT drift. The defective transform **passed that
certification** while minting `MD029/ol-prefix` on an author's paragraph. The law was right;
the detector set it quantifies over had no MD029 member, so `∀ d` held vacuously. A check that
cannot fail is not a check.

- `orderedListPrefixDetector` (MD029-shaped) joins `REFERENCE_DETECTORS`.
- The incident becomes a golden vector in the gate's own corpus, carrying both real documents'
  shapes (`2007.` from the book RAW file, `2016.` from the design brief).

The detector models CommonMark's interruption rule rather than flagging every `<digits>.`
line-start, and that is load-bearing rather than pedantic: an over-reporting detector would
report the finding on the **input** too, the minted set would be empty, and closure would pass
vacuously in a new way — the same defect wearing the opposite sign.

# Spec alignment

# Notes

**No gate can require a heal, and this PR does not pretend otherwise.** Idempotence, closure and
convergence are all satisfied by a healer that does nothing, so certification can only ever say
"this edit is not damaging" — never "this file needed editing". The easy wrong fix (stop
inserting blank lines at all) is held out by the `STILL HEALS` tests, not by the gate; confirmed
by mutation — forcing `canInterruptParagraph` to `false` turns those four red.

**The warrant is only as wide as the detector set.** It is five detectors now, not a linter. The
next prose-damaging class with no detector sits exactly where MD029 sat this morning. The general
form would be a detector derived from the linter itself; nobody has costed that.

**`docs/books/` is NOT excluded**, and that stays deliberate. The class was never books-specific —
the same defect landed in `docs/design/` and, measured during #14435, in `docs/PRIOR-ART-LIST.md`
— so an exclusion would have left the class alive everywhere else while reading as a fix. There is
also only one exclusion list on purpose (`md-heal-scope.ts` reads the linter's own `ignores`);
excluding books would either stop **checking** them too, or create the second hand-maintained list
that this defect class regenerates from. The open question — whether an auto-fixer should rewrite
authored prose at all — is `081M0R50J09087G0R000AN2QAT`, which stays open and gains the warrant
argument plus two honest limits, filed as input rather than as a decision.
