feat(ci): drift is LOUD and still blocks nothing — 124 absorbed failures in 5.5 days, 26% covered

Aaron: "we want drift to be LOUD so the red is immediately noticed, not a whisper
— just not blocking."

NOTHING HERE CHANGES WHAT BLOCKS. `gate (required)`'s `needs:` list is byte-identical,
the windows/macOS `continue-on-error` flag is untouched, and every hygiene lint keeps
exactly the status it had. What changes is that "non-blocking" stopped meaning
"unnoticed".

MEASURED FIRST. A full census of every completed `gate` push run on main across 5.5
days (2026-08-18T00:53Z..2026-08-23T16:07Z — 600 runs, 368 cancelled before any job
ran, 232 inspected) found 124 job failures sitting beside a green `gate (required)`.
Only 32 of the 124 (26%) reach any rate surface, because `platform-drift-report.ts`
folds only names starting `build-and-test (`. The largest absorber is
`test (TS hermetic)` at 47, folded by nothing. Census committed as text at
src/Core.TypeScript/ci/fixtures/absorbed-failure-census-2026-08-23.json.

THREE MECHANISMS SWALLOW THEM, and they are not equally bad:
  * job-level `continue-on-error` / a non-floor job — reports `failure`, keeps its own
    red X, and is ignored by the rollup. One surface, no rate.
  * step-level `continue-on-error` — the job reports SUCCESS with a failed step inside.
    Every surface gate.yml lists reads a JOB conclusion, so all four are blind to this
    by construction. Eight such steps exist in this repo's workflows today.
  * the surfaces themselves going quiet — the one that decided the design. drift-sweep's
    push to main has been rejected by the "CI Gate" ruleset since 2026-08-13 and is
    swallowed by `git push || echo "push race"`, which misfiles a PERMANENT rule
    rejection as a TRANSIENT race. 1,597 sweep runs concluded `success` while
    docs/drift-events/ stayed frozen at tick 000247 and data/platform-drift.json at
    run 32232815018 (2026-08-19). The dashboard was serving ten-day-old numbers from
    behind a green check.

SO LOUD LIVES IN THE RUN, not in a file that has already been shown able to stop
landing: a red X on the non-floor `drift (loud)` job, `::error::`/`::warning::`
annotations in the PR UI, and a step summary. Exit code is the loudness, never a gate.

PROPORTIONAL, because a guard that cries wolf gets switched off. Bands are computed
over a BOUNDED window of EXECUTIONS: SUSTAINED → ::error::, FLAPPING → ::warning::,
ONE_OFF → ::notice::, HEALED and UNOBSERVED → summary row and no annotation at all.
HEALED is tested before the rate bands, so a clean streak demotes a subject rather
than being averaged away — the structural fix for the unbounded window that reported
a lane RED for twelve days after it was fixed.

THE FALSIFIER IS LIVE, NOT A CLAIM. `drift-canary` fails one step on purpose under
`continue-on-error` on every run, forever — a real specimen of the class that had no
detector. `assertDetectorLive` requires it in the census, so if step-level detection
ever breaks the reporter goes red with DETECTOR WENT QUIET. Silence is what fails the
check. The census found ZERO natural step-level absorptions, which is the argument for
the canary and not against it: with no specimen, "no findings" and "detector broken"
are byte-identical output.

Also fixes the misattribution in drift-sweep.yml — a rule rejection now emits an
`::error::` naming the cause and the route, and stays non-fatal. Routing the ledger
onto the heartbeat flush lane is filed as 081M0QPZD9C087G0R002W8QC2A (P1), not done
here.

Verified against live main before landing: 13 absorbed failures over 40 runs, three
