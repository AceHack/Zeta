## Description

bug: refine the arity workitem — a partial sweep that reads as a cleared class is the failure it exists to catch

Lumen's refinement to 081M0RAX8AC087G0R003NQM7P9, accepted and folded into the
acceptance criteria.

The criteria said to sweep the F# test tree for self-comparisons (X = X,
Assert.Equal(f a, f a)). That grep finds SYNTACTIC self-comparisons and misses the
general case: two calls with identical arguments bound to different names, or a
helper invoked twice with the same input, are the same defect and are invisible to
it.

The actual class is A CHECK WHOSE ARITY IS LOWER THAN THE PROPERTY IT CLAIMS.
Self-comparison is only its most visible form.

This belongs in the criteria rather than in a footnote because a partial sweep
that reads as a cleared class is precisely the failure this workitem exists to
catch, one level up. Grep X = X, fix what it finds, close the row — and the class
survives now carrying a "swept" label, which is strictly WORSE than never having
swept, because the label suppresses the next search. That is the same mechanism as
a check that did not run looking like a check that passed, moved from an assertion
to a remediation.

So the sweep must report its own coverage limit: state that it covered syntactic
self-comparisons only, and that name-bound and helper-mediated instances were NOT
covered. Closing the row requires finding those too, or saying plainly that they
remain unsearched.

The general form is named because it is mechanically checkable in principle —
compare a check's arity to the arity of the property it claims. A 2-safety
property (noninterference, determinism, non-malleability) tested by a single run
is incomplete BY CONSTRUCTION, not by oversight. Anchored to Clarkson & Schneider
and to the in-tree result that arity is a property of a check's SIGNATURE rather
than its body, which is what makes it declarable rather than inferred.
