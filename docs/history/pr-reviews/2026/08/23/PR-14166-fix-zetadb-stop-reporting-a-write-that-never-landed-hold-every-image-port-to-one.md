## Description

Two witnessed defects in the zetadb port layer (found by Soraya during a routing review), plus the structural fix that would have caught the second one the day it was written.

## Defect 1 — the storage port reported success for a write that never landed

`zeta-db-storage-port.ts` built its tick request without `requireComplete`, then collapsed the readout with `result.ok ? succeeded(record.key) : ...`.

**Before** (on `518499177`):

```
result.ok = true   admission = backpressured   accepted = 0
feedback  = [{"severity":"backpressure","code":"database-capacity-exhausted",
              "detail":"The retained event ledger reached its 2-entry no-forget budget."}]
storage port returns = {"ok":true,"value":"a3fcad25bde5065f1a2d067e3f0587d1"}
durable rowKeys      = ["storage/1d655e83…","storage/bbd33827…"]     <- k3 absent
subsequent read(k3)  = {"ok":true,"value":null}
```

**After**:

```
storage port returns = {"ok":false,
  "reason":"database-capacity-exhausted: The retained event ledger reached its 2-entry no-forget budget.",
  "severity":"backpressure"}
```

The kernel was already correct — the adapter dropped the signal. Only the adapter changed.

**The trap worth naming:** the obvious guard, `accepted === 0 → fail`, is wrong. A re-write of an already-stored record is a *duplicate* (`duplicates: 1, accepted: 0`, admission `complete`) and must stay successful, because content-addressed writes are idempotent (§12). "Nothing was accepted" and "nothing *could* be accepted" are different facts; only the second is a failure. `requireComplete: true` separates them. Both halves have falsifiers, and the first one fails without the fix:

```
--- with the adapter fix REVERTED ---
✗ refuses a write the admission budget could not admit    Expected: false  Received: true
 5 pass  1 fail
```

## Defect 2 — deliberate, not drift. So the *type* was lying, and the type is what changed.

Witnessed divergence (two axes, one of which Soraya did not name):

```
=== stored revision 5, candidate revision 9, unrelated bytes ===
browser checkpoint port : ACCEPTED (action=write)
in-memory reference port: refused (database-revision-conflict)
Same contract?  false

=== EMPTY store, first write at revision 9 ===
browser checkpoint port : ACCEPTED (action=write)
in-memory reference port: refused (database-revision-conflict)
Same contract?  false
```

**Verdict: the browser port's laxity is DELIBERATE.** The evidence:

- `BrowserCheckpointPort` predates the ZetaDB kernel by 8 days (`98984fd59`, 2026-08-01 vs `3f16e2ee3`, 2026-08-09).
- PR #9943 specified it as *"enforce atomic **monotonic** revisions"*. Intent is on the record.
- It serves three **non-database** record kinds: `"room"`, `"causal-corrections"`, `"causal-handoffs"`.
- **The decisive one:** `browser-multitab-smoke.ts` — the real Chromium proof — saves room revision **250**, `removeCheckpoint(250)`, then saves **300** into the now-empty slot, and requires both to be admitted. Compare-and-swap refuses *both* (a leapfrog, and a first write that is not revision 1). Tightening `decideBrowserCheckpointSave` to CAS breaks a shipped proof.

So `decideBrowserCheckpointSave` is **not** touched. The drift is one layer up, at `createBrowserZetaDbImagePort`, which presented a deliberately-monotone store through an interface whose reference implementation is CAS. And `ZetaDbImagePort` carried **no written contract at all** — the adapter violated nothing, because there was nothing to violate. A port with an unwritten contract has as many contracts as it has implementations.

Per the instruction for the deliberate branch, the divergence is now **explicit in the type**: `ZetaDbRevisionDiscipline`, a *required* field on `ZetaDbImagePort`. Making it required is what found every implementation — `tsc` named exactly four, two of them test fakes. Nobody has to notice the divergence any more; they cannot construct a port without declaring it.

Which discipline the browser-backed *image* store should enforce is **not decided here** — that is the architect's call, filed as `081M0Q8TQYE087G0R001WBX1ZC` with three costed options.

**Honest limit, checked rather than inferred** — this corrects one point in the brief. Every current writer computes `loaded + 1` (kernel: `image.revision + 1`; `compactGeneration`: `archiveRevision + 1`; the two causal sites: `(baseRecord?.revision ?? 0) + 1`), and `BrowserCheckpointPort.remove` is wired **only** to `roomCheckpointNodeId`, never to a database image node. So no caller leapfrogs today. Soraya's "reachable, not theoretical" is right about the **port surface** and overstated about the **current caller graph**: this is a latent contract hole, not live data loss on `main`. The underlying finding stands unchanged — the convergence obligation really is discharged only on the reference port.

## The structural fix — the port-conformance property suite

`src/Core.TypeScript/zetadb/zeta-db-node.property.test.ts`, fast-check 4.8.0 (already pinned; no new dependency), run against a **roster** of every implementation:

| | property |
|---|---|
| CP-1/2 | save is durable and byte-exact; identical re-save is idempotent |
| **CP-3a** | obligations **both** disciplines owe — asserted with **no per-port exemption** |
| **CP-3b** | a port must behave the way it **declares** |
| **CP-3c** | the roster must contain **both** disciplines, so CP-3b cannot pass vacuously |
| CP-4/5 | a refused save never mutates the store; a closed port refuses |
| PERM-A | permutation invariance **within** a tick — falsifier for `rowPairKey` |
| PERM-B | permutation invariance **across** batches — falsifier for `canonicalEntryOrder` |
| BIND | the binding-budget divergence — captured, **not** fixed |
| PREFIX | a **new** finding (below) |

### PERM-A was caught being the vacuity class, and fixed

It is not enough to assert a property fails under a revert — you have to *run* the revert. I did, and **PERM-A passed with `rowPairKey` reverted**. The generator was too weak: the asymmetry needs a **zero crossing** (emit → retract to zero → re-emit under a different payload), and two deltas conflict *symmetrically* in both orders. Concentrated to one row key with ≥3 deltas, it goes red on exactly that shape:

```
Counterexample: [[{"rowKey":"row/a","payload":"A","weight":1},
                  {"rowKey":"row/a","payload":"A","weight":-1},
                  {"rowKey":"row/a","payload":"B","weight":1}],3,328]
```

PERM-B likewise verified red under an identity-`canonicalEntryOrder`. Both properties are proven falsifiers for the change each one names; the kernel was restored byte-identical afterwards.

### Anti-vacuity — the bar is the repo's, not fast-check's default

`fc.statistics` is a top-level sampler and cannot classify inside an async property (it throws), so the stronger form is used: **hard minimum counts on every skip class**, asserted after `fc.assert`, plus the distribution printed.

```
PERM-A generator — slack: 82  budget-binding: 38
PERM-B generator — slack: 47  budget-binding: 31  multi-payload-row (excluded, see PREFIX): 122
```

Every precondition is proved to reach *both* sides. `lean-proof.yml:312-324` — 13 names silently resolving to nothing while the lane reported green — is the receipt for why.

## A third finding, mine, filed not fixed

`081M0Q8TY2E087G0R002ES9VW5` — the **row-conflict verdict depends on batch order at tick boundaries**. #13929 made it order-independent *within* a tick; across ticks it is not, because every *persisted* image must be well-formed, so a prefix can be ill-formed when the union is fine:

```
b1 then b2: REFUSED(database-row-conflict) -> ok(accepted=1)
   final rows = [{"rowKey":"row/b","payload":"B","weight":1}]   revision 1
b2 then b1: ok(accepted=1) -> ok(accepted=2)
   final rows = [{"rowKey":"row/b","payload":"A","weight":1}]   revision 2
```

It *is* recoverable by re-submission — but nothing re-submits: `database-row-conflict` carries `severity: "heat"`, and `runConvergentZetaDbNodeTick` retries only `database-revision-conflict`.

PERM-B excludes this class by an **input-side** precondition (`singlePayloadPerRow`) with an asserted minimum count, so the excluded class is named and proved reachable rather than quietly swallowed. PREFIX carries the deterministic witness.
