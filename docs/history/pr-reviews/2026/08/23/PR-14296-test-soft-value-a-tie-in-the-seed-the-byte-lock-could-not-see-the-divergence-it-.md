## Description

# Summary

`SoftValue.resolve` picks the maximum-weight candidate. On a **tie** the four oracles are required to break by **ascending candidate key** — and the shared seed contained no tie, so for as long as that was true a tie-breaking divergence was **undetectable by construction**. The F# oracle diverged in exactly that gap (`List.maxBy` over an association list = first maximum in *arrival* order) until `5c9c60e3a` (#14266).

**A byte-lock with no tie in its vectors cannot detect a tie-breaking divergence.** The seed is the deliverable here; the F# fix was already landed.

No oracle was changed by this PR, and **no vector was weakened**.

# What the four oracles actually do (read, not assumed)

| oracle | mechanism | tie-break |
|---|---|---|
| **Rust** | `BTreeMap<String, i64>` iterates keys ascending; `argmax` keeps the incumbent on `==` (strict `>`) | **ascending** |
| **C#** | `OrderByDescending(Value).ThenBy(Key, StringComparer.Ordinal).First()` | **ascending** |
| **TS** | `Object.keys(c).sort()` then strict `>` | **ascending** |
| **F#** | `List.maxBy snd` over `Candidates` = `WeightedSet.toSeq` over a `Map` keyed by `CandidateKey`, comparison `DynamicValueOrder.compareValues` | **ascending** |

**Rust was the unverified one and it was already correct** — `BTreeMap` gives ascending iteration for free, which is why nobody had to write a tie-break there.

**The F# fix landed as described, and is genuinely ordinal.** `DynamicValueOrder.compareValues` uses `String.CompareOrdinal`, not a default or `InvariantCulture` comparison — checked by reading it, per `.claude/rules/culture-invariant-by-default.md`.

# The vectors

Six `resolve` + two `observeResolve`, all constructed so **insertion order disagrees with ordinal order** (`"b"` before `"a"`) — which is precisely what lets them fail against an arrival-order oracle.

| vector | threshold | expected | class |
|---|---|---|---|
| `{b:2, a:2}` | 1/4 | `"a"` | two-way tie |
| `{c:1, b:1, a:1}` | 1/4 | `"a"` | three-way tie, insertion fully reversed |
| `{b:3, a:3, c:1}` | 1/4 | `"a"` | leaders tie, non-tied candidate present |
| `{b:1, a:1}` | 3/4 | `null` | a tie that does **not** clear the threshold |
| `{}` | 1/2 | `null` | **empty** — previously unreached by `resolve` |
| `{a:1}` | 1/1 | `"a"` | **singleton** |

plus two `observeResolve` vectors where the tie appears only in the **posterior** — the second (`{b:2,a:1}` × `{b:1,a:2}`) ties in neither the prior nor the likelihood.

Thresholds are deliberately **off** the float-equality boundary (`den=4`, not `den=2`) so F#'s `p >= threshold` on a normalized float is not riding an exact comparison — the invariant the seed's description already claimed for its values.

# Proof that the vectors discriminate

Mutating the tie-break rule in the **real F# oracle** (negating `CandidateKey`'s comparison, so `List.maxBy` takes the ordinal-*greatest* on a tie — the same answer the pre-`5c9c60e3a` arrival-order oracle gave on this seed, since insertion order here is descending-ordinal):

| seed | mutation | result |
|---|---|---|
| **new** | applied | **FAILS** — `Expected: Some(a)  Actual: Some(b)` (exit 1) |
| **old** (`origin/main`) | applied | **PASSES** (exit 0) |

Same mutation, opposite verdicts. That is the finding stated as a measurement: the vector set that existed was blind to this exact divergence and the new one is not. The mutation was reverted — `src/Core/CandidateKey.fs` is **byte-identical to `origin/main`** in this branch.

# The hole was already registered — as `declared`

`treaty-rule-alternatives.ts` (PR #10770) already carried this treaty, with the descending-key alternative marked `expect: "not-excluded", kind: "declared"`, reasoned *"the seed's own description already says the ties are '(absent here)' … the reader is never misled."*

That was honest, and it was true. **It was still not enough** — F# was diverging the whole time and nothing could see it.

> **`declared` records that a rule is UNPINNED; it does not make the rule unnecessary.** An unpinned rule that four oracles are supposed to share is a divergence waiting to be found by something other than CI.

The row is promoted exactly as #10770 anticipated (*"if a discriminating vector is ever added, the lint promotes this row"*):

| alternative | expect | measured |
|---|---|---|
| DESCENDING-key tie-break | `excluded` | **5 of 17** change |
| **FIRST-SEEN (arrival-order) — the pre-fix F# rule** | `excluded` | **5 of 17** change |
| UTF-16 code-unit order vs UTF-8 byte order | `blocked` | 0 of 17 |

The second row names **the actual historical bug** as an alternative, so it is a regression guard rather than a story.

The third is a **residual I found while reading the oracles and deliberately did not close**: F#/C#/TS order by UTF-16 code unit, Rust's `BTreeMap` by UTF-8 bytes, and those **disagree above the BMP**. A discriminating vector there would *break* the treaty rather than tighten it, so it is `blocked` with the same reasoning as the existing `z-set-merkle` row — recorded, not silently added, and not papered over.

# Is this a one-off or a class?

**A class — and the mechanism to close it already exists.** Measured against `origin/main @ 30c0a881c`:

| | count |
|---|---|
| golden-vector seeds under `src/` | **48** |
| seeds with a `TreatyDeclaration` | **12** |
| seeds with **no declaration at all** | **36** |

A seed with no declaration is not audited as vacuous or non-vacuous — it is simply **not looked at**. That is the same defect one level up: the register pins the treaties it lists, and the prose around it reads as though it pins the class.

Filed as **`081M0QQ7984087G0R001MBVB47`** with the proposed check: **roster completeness** — derive the seed set by glob, derive the declared set from `TREATY_DECLARATIONS`, and require each seed to be either *declared* or explicitly marked *byte-agreement-only*. Same construction as `audit-proof-lineage-binaries.ts`, which derives its allowed set from the runner's own roster rather than a hand-written allowlist that drifts.

**Not implemented here on purpose**: it would go red on 36 seeds on arrival, and main's gate is green. The honest expectation from that work-item is *"36 classified"*, not *"36 repaired"* — several (`splitmix64`, `crc32c`, `fastcdc`, the `wasm-dla` seeds) are plausibly pure byte-agreement and need no vector work.

**Deliberately not proposed**: auto-generating alternatives. *"Plausible alternative rule"* is a judgement about what a competent implementer might have chosen; the existing lint says so itself and is right.
