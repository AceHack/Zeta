The killer feature — button glow as pre-snap probability mass — **is in production today**.

### Why 682 bytes looked broken and is not

682 bytes is the correct size of a built Vite `index.html`. The served body carries hashed
build outputs (`./assets/index-DLdSGO6O.js`), not `/src/main.ts`. A local build of `main` HEAD
produces **byte-identical filenames** for all three artifacts, and each returns 200 from Pages.
`pages:build` has built and copied the app since `ba965f86` (#14161, landed today 13:33Z),
with #14200 / #14239 / #14253 following.

### The `workspaces` gap is real and is not the deploy bug

Root `package.json` has no `workspaces` key — confirmed. But `pages:build` runs a **second
install inside the app directory** (`cd src/apps/twitch-ai && bun install`), so the app is built
by its own lockfile and its own `vite`. What the gap actually costs is CI **checking**: root
`tsc` reaches the app under *root* settings (`lib: esnext`, `types: bun`), never the app's own
(`lib: ES2023,DOM`, `types: vite/client`). Already filed as `081M0QF7ZVY087G0R003Q4Q18D`.

**Not fixed here.** Adding root `workspaces` is a repo-wide change on a green gate, and #14253
already added a `typecheck` script to build a CI job on. That is the workitem's call.

Two further corrections: `--base=./` is already set and is **better** than a hardcoded
`/Zeta/twitch-ai/` (survives rename and `vite preview`); and the CHIP-8 path
**deliberately bypasses the LLM** (`swarm-controller.ts:203`), so the inert endpoint never
blocked the arena.
