## Description

feat(cluster): refuse a public-tree manifest that names an image nobody outside can pull

THE INCIDENT THIS IS BUILT FROM
-------------------------------
`full-ai-cluster/k8s/applications/platform/blueprints-flowdent.yaml` sat in this
public tree for months naming two images:

  ghcr.io/flowdent/cloudservice:latest   <- Flowdent/fd-core       PRIVATE
  ghcr.io/flowdent/fd-webclient:latest   <- Flowdent/fd-webclient  INTERNAL

The `Flowdent` org reports public_repos: 0, owned_private_repos: 9 (re-measured
2026-08-23) — no public FlowDent source exists for anything. Max's account, via
Aaron: "it was a multi-repo accident — his AI checked into the wrong repo."

So an agent wrote to the wrong repository in a multi-repo setup and NOTHING
CAUGHT IT. It surfaced months later and only sideways: `lane-partition.ts` could
not MEASURE the images (401) and quarantined the whole `platform` Application as
unpriceable. A human removed it by hand in #14250. This is that accident turned
into a red check at PR time.

THE RULE
--------
Aaron 2026-08-23: "zeta should not have any private repo dependencies." The
invariant is ONE-WAY: Flowdent (closed) may depend on Zeta (open); Zeta may never
depend on Flowdent. Mechanical, not remembered — which is what the coming
multi-repo split needs.

OBTAINABILITY IS THE PREDICATE, NOT OWNERSHIP
---------------------------------------------
"No foreign images" is the tempting rule and it is wrong: this tree pulls
bitnamilegacy/*, quay.io/kubevirt/*, ghcr.io/ich777/* and a dozen more that
nobody here owns, and every one is fine because anyone who clones can pull them.
The defect is UNOBTAINABLE, not foreign — the same class as
`clone-at-tag-stays-sufficient`. So the measurement is an ANONYMOUS registry pull:
200 -> allowed; 401/403 -> refused. `org.opencontainers.image.source` is read for
a different job — WHOSE door it is, which decides which of two OPPOSITE remedies
the message prints (ours: PUBLISH IT / foreign: REMOVE IT).

WHAT LANDS
----------
- `src/Core.TypeScript/cluster/image-source-provenance.ts` — the check. OFFLINE by
  default against a committed measurement; `--refresh` is the network half.
- `full-ai-cluster/k8s/image-source-provenance.json` — 27 repositories, measured
  2026-08-23. Per-TAG statuses, because one sampled tag lies silently:
  `ghcr.io/ich777/steamcmd` is referenced at three tags, `armareforger` 404s and
  the other two are 200, and whichever the refresh picked would have set the
  repository's whole verdict. The VERDICT is not stored — it is derived on every
  run, because a stored verdict is a hand-written allowlist wearing a
  measurement's clothes.
- `.github/workflows/gate.yml` cross-verify floor — offline, every PR, 0.43s.
  HERE and not in k8s-lane-partition.yml on purpose: that workflow's path filter
  watches `full-ai-cluster/k8s` only, and a path filter is exactly the wrong shape
  for a check whose job is to notice a manifest in a directory nobody declared.
- `.github/workflows/chart-version-refresh.yml` — `--refresh` rides the existing
  weekly network lane; no new cron, non-blocking, `continue-on-error`.

NOT A FOURTH SCANNER — checked before writing
----------------------------------------------
`lane-partition.ts` asks CAN THIS LANE BE PRICED (capacity); its "unmeasurable"
bucket lumps 401 / 404 / 429 together because for SIZING they are the same answer,
and for PROVENANCE they are three verdicts with three different remedies —
that conflation is exactly why a private-source dependency read as a measurement
problem for months. `vendored-upstream-parity.ts` asks do the committed bytes match
upstream. `audit-chart-target-revisions.ts` asks does the chart pin resolve. None
answers provenance. This file REUSES `imagesInDocuments` and `parseImageReference`
from `image-footprint.ts` rather than parsing anything itself.

UNKNOWN DOES NOT PASS
---------------------
An image the ledger does not cover FAILS — the same stance `DerivationProtocol.fs`
takes for licences (`Wall.Whitebox`: unknown BLOCKS). So does a tag never measured,
a stored verdict that does not fold from its own statuses, a ledger row nothing
references, an unparseable manifest, and a scan that finds zero images.

WHAT IT FLAGS ON MAIN TODAY, and what it does not
--------------------------------------------------
30 references / 27 repositories / 209 manifests scanned. Zero classify
foreign-private. Three are OURS and refused:

  ghcr.io/lucent-financial-group/zeta-orleans-silo:latest, :bootstrap
  ghcr.io/lucent-financial-group/hat-system-operator:placeholder

All three because the PACKAGE DOES NOT EXIST — `gh api .../packages/container/...`
returns "Package not found" and no workflow builds them. Pre-existing (both
Applications are already in lane-partition's unpriced quarantine), so they are
ACKNOWLEDGED with a work-item and a LIFTS WHEN clause rather than reddening main
on day one — a check that is red from birth is learned-to-ignore within a week.
The register is drift-checked in BOTH directions and may cover only an `ours-*`
class; a foreign closed dependency is unconditionally red and cannot be
acknowledged, which is what makes this an encoding of the one-way rule rather than
a report about it. Work-item 081M0QNFBZ0087G0R000N3RXGF.

A MEASUREMENT THAT MOVED MID-SESSION, recorded because the register is only
honest if its history is: this shipped with `zeta-portal` and
`zeta-platform-controller` acknowledged as ours-private (measured 15:52 UTC, both
401, packages API `visibility: private`). Re-measured 16:14 the same afternoon:
both 200, both public — Aaron performed the two Danger Zone clicks while the check
was being written. Those acknowledgements were DELETED rather than kept, which is
what the staleness check would have forced one run later anyway.

FALSIFIERS
----------
35 cases in `image-source-provenance.test.ts`, each over a throwaway git tree.
The first reconstructs the two deleted FlowDent Blueprints and asserts they are
refused with the REMOVE remedy and never the PUBLISH one; the second asserts the
incident CANNOT be acknowledged. bitnami / weaviate / ich777 / postgres / kubevirt
must not trip it. An absent source label on a PUBLIC image is not a finding, and
that is stated as a falsifier because the opposite rule would fail most of the tree
on day one.

16 targeted mutants applied, each byte-`cmp` verified BEFORE its result was read.
15 landed and 15 were killed, 0 survivors. The 16th reported PATTERN NOT FOUND
rather than a verdict after a refactor moved the code it targeted — the
verify-the-mutant-landed discipline doing its job.

ONE LIMIT, SAID OUT LOUD
------------------------
A 404 means the repository is OPEN and the tag is missing — a broken pin, which
`lane-partition.ts` owns. Those are printed, not refused. That leaves a hole: on a
registry that 404s a live repository's missing tag, deleting a private package
would move its verdict from refused to reported. Measured: both ghcr.io and Docker
Hub answer 401, never 404, for a repository that does not exist, and the manifest
is broken either way.
