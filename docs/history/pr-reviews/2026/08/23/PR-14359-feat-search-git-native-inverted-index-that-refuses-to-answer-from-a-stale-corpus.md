## Description

## The failure this exists to make impossible

A search for `landauer` reported **0 files**. The truth at `origin/main` was **447**, one of them a rule mentioning it **32 times**.

Nothing was broken. `grep -r` searched the **working tree** of a shared checkout **336 commits behind** `origin/main`, and answered correctly about the corpus it was handed. **The defect is that a stale answer and a true answer are indistinguishable at the call site.**

Aaron:

> *"i know it's in here over and over lol… not sure why your greps are missing the information, this is why we need our own tools to close over the OS, the built-in ones are unreliable… we already started some gitnative reverse indexing around this that hopefully we can get on an update cadence."*

> *"lets send a background agent to do some sort of reverse indexing that stores the index and git and updates maybe once every 6 hours or so … we can have our own slim version of lucene like reverse indexing and yes for this index we will ignore stop words, **stop words need a completely different kind of indexing**."*

## The guard

The corpus is addressed by **rev** — `git ls-tree` / `git cat-file`, never a checkout — the rev is in `manifest.json`, and the query classifies freshness **against the rev you asked about**.

| index rev vs. queried rev | what happens |
|---|---|
| equal, or no indexable file changed | answer from the index |
| ancestor, files changed | **changed set re-read from git at the target rev** and merged **in both directions** — new hits added, superseded hits **withdrawn**. Exact, not caveated. |
| changed set over budget · diverged · rev absent | **REFUSED (3)** |
| `--no-verify` and the result would be **empty** | **REFUSED (3)** |

Exit `1` (no matches) and exit `3` (cannot answer) never collapse. That last row is the point: a non-empty stale answer is at worst incomplete and you can see what you got; an **empty** one is a confident claim of absence about files this run never read.

## Two defects that accounting found — in this PR's own code

Both are *this same bug* — a clean, confident, wrong "not here" — reproduced inside the fix for it. Neither was visible in the totals.

1. **`verifyLandauer`** — camelCase welded into one token; **20 files missing**. Fixed with Lucene's `WordDelimiterGraphFilter` shape (decompose, `preserveOriginal`).
2. **`Landauer–Bennett`** — with a **U+2013 EN DASH**. "Everything ≥ U+0080 is a word character" welded the two names together. Fixed with a pinned non-ASCII separator table.

And one design error caught by measurement: a df cap of **100**, chosen off the size table, **refused `landauer`** (447 files) — the very query this exists to answer. **A cap tuned only against the size column has no opinion about what anyone searches for.** Now 2% of the corpus.

## Doc ids: the measurement that changed the design

v0 identified documents by **position** in the sorted path list. Smaller — and adding one file shifts every subsequent id, rewriting every posting after it. Measured over one real 6-hour tick (110 commits):

| doc id | artifact | diff | pack cost |
|---|---|---|---|
| positional | 18.6 MiB | `+281,464 / −278,978` | **5,088 KiB** |
| **content-derived (shipped)** | 26.5 MiB | `+13,654 / −11,168` | **584 KiB** |

**43% bigger artifact, 8.7x cheaper tick, 20x smaller diff** — and the diff is the thing text is being paid for. A text index whose every line churns every 6 hours has forfeited the only reason it is not binary.

## Text, not binary — as a decision

`no-binary-in-proof-lineage.md` governs *verification* artifacts and this is derived data, so it does not strictly bind — but its reasons do. JSONL, `renderTermRow` pinning the exact bytes. Shipped size: **54.8 MiB raw, ~18 MiB packed**, rebuild ~30 s, **584 KiB per tick**. `.prettierignore` + `linguist-generated` follow the `docs/github/prs/` precedent so the formatter and the generator are never in a fight.

## Stop words — the distinction is kept, not flattened

Dropped, per Aaron — and **that is why a multi-word query is REFUSED with the reason** rather than silently ANDed and presented as a phrase match. A term index has **no positions**, so *"the end of error"* is unanswerable here by construction, stop words or not. The positional/biword index it needs is **filed** (`081M0QWDDDV087G0R003HM0KYX`), not half-built. Ranking, trigram regex acceleration and incremental merge likewise (`081M0QWDDF3087G0R000V7T6BV`).

## Cadence

`search-index-cadence.yml`, every 6 h. It **cannot push to `main`** (parks on the staging branch, flushes via PR — `manifesto-citation-snapshot-cadence.yml` is the pattern), and it **cannot fail silently**: it asserts the manifest's rev is the rev it asked for, asserts the artifact is non-trivial, runs the motivating query end-to-end, and always writes a run summary. That is aimed squarely at the drift-dashboard failure of publishing quietly stopping and nothing saying so.

## Prior art (Beacon) — rows added to `docs/PRIOR-ART-LIST.md`

- **Apache Lucene** — Doug Cutting, 1999–; Apache project since 2001; the engine under **Solr** and **Elasticsearch**. Not shorthand for the literature — a first-class anchor with an implementation to read. **Taken**: segment placement, dictionary/postings split, `WordDelimiterGraphFilter`. **Diverged**: binary segments + tiered merge, because we need reviewable diffs, byte-identical rebuild and no daemon — none of which Lucene optimises for. Its **tombstones-not-in-place-edit** turns out to be the Z-set retraction shape we already stand on, which is why we need none: a rebuild is a new commit and the old index is its parent.
- **Gerard Salton**, SMART (1960s–70s) — the analysis→postings pipeline.
- **Zobel & Moffat**, *Inverted Files for Text Search Engines*, ACM CSUR 38(2), 2006 — the postings/compression tradeoffs measured above.
- **Manning, Raghavan & Schütze**, *IR*, CUP 2008 — §2.2 stop lists (both the hand list and the statistical df cap), §2.4 positional/biword indexes: the index this deliberately is **not**.

## Honest limits

Non-ASCII case is not folded (`Über` indexes as `Über` — pinned by a test; `toLowerCase()` is Unicode-**version** dependent, which would break byte-identical rebuild across time). CJK indexes as one token per run. Terms in >2% of files have a **count but no postings**, and a query for one is refused **with the count** — everywhere is not nowhere.
