## Description

# Summary

#11484 let persist bind USB iSerial, but `zeta-creds-restore.nix` still always passed `--usb-uuid`. That is a lockout: the blob is bound to the stick serial, first boot decrypts with the FAT UUID, creds are gone. The same hole existed for UEFI keyfile (`uefiKeyfile restore is not wired; aborting`).

Persist writes `zeta-creds.factor` next to the blob (kind only, never KDF material). Restore reads the sidecar and uses the recorded factor:

- `usbISerial`: `/etc/zeta/usb-iserial` (recorded at install; not a live probe). Missing file fails closed. No UUID fallback.
- `uefiKeyfile`: `/boot/EFI/ZETA/keyfile` (the ESP file is the binding; bytes are not copied to `/etc`). Missing file fails closed. No UUID fallback.
- Missing sidecar stays FAT UUID (backward compatible).

`ZETA_BIND_UEFI_KEYFILE=1` writes `/mnt/boot/EFI/ZETA/keyfile` at install and forwards `--uefi-keyfile` to the picker. Mutually exclusive with `ZETA_BIND_USB_ISERIAL=1` (both set stays UUID). Default persist remains FAT UUID. QEMU phase-1 must not set the keyfile opt-in. No metal / Touch ID / TPM claim.
