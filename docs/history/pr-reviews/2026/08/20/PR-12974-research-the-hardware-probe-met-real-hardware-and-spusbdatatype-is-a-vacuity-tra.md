## Description

**METERED.** Every line is a command run against the YubiHSM 2 physically attached to the
maintainer's Mac Studio, with verbatim output. **No credential was read, printed or handled, and
no authenticated session was opened.**

Closes the metering gap on `081M0B230NW…` — *"frost-hardware-probe could not see a YubiHSM 2 at
all, and paired any module with any device"*. That bug was fixed in the same PR that filed it,
and the workitem says plainly: *"No hardware was touched: the device was never plugged in."* So
the fix was **implemented and unmetered.** It has now met the device.

## The trap found on the way in

```
$ system_profiler SPUSBDataType          # 0 bytes, exit 0
$ system_profiler SPHardwareDataType     # 514 bytes, exit 0   ← control: the tool works
```

**`SPUSBDataType` returns empty with exit 0 under an agent sandbox.** A check that *could not
run* is indistinguishable at the call site from one that ran and found nothing — **the same
sentence the closed workitem used about its own bug, now recurring one layer up in the
environment rather than in the code.** `ioreg` is unaffected and is what the fixed probe
actually uses.

> Standing consequence: on macOS, `system_profiler` is not a dependable enumerator inside an
> agent context, and any future detection route reaching for it inherits this **silently**.

The device is there — `YubiHSM`, `idVendor 4176 / idProduct 48`, serial `0039160506`, behind two
VIA Labs hubs on an Anker dock (recorded because a probe walking only the root hub would miss it).

## Both halves of the closed bug confirmed against hardware

```
  YubiHSM 2:          ATTACHED (bulk USB — invisible to the reader/ykman probes above)
  PKCS#11 module:     Not found
  PKCS#11 pair:       …/yubihsm_pkcs11.dylib drives YubiHSM 2
  Device present:     YES
  Honourable tiers:   hardware-pkcs11
```

The HSM is no longer invisible; and the module is **matched** to the device rather than merely
co-present — under the old `someModule && someDevice` logic those middle two lines **could not
coexist**. The forcing case the workitem described is exactly the state of this desk.

And the line worth keeping for its own sake:

```
  TPM 2.0: UNAVAILABLE (THE CHECK DID NOT RUN) … This is "not asked", not "no TPM".
```

The discipline is carried in the device layer's **own output string**, where a reader who never
opens the source still cannot mistake a gap for a finding.

## Connector reachability is the real perimeter — measured, not argued

```
status=OK   serial=*   version=3.0.7   pid=14449   port=12345
```

A connector **is already listening**, and **`serial=*` — it is not pinned to a device.** Live
confirmation of `081M0DJQ7BP…`: the 16-domain bitmask is enforced by the hardware **against a
session**, but the path *to* the hardware is an unpinned localhost TCP daemon. **Domain
separation is not reachability control, and only one of the two is currently constrained.** The
cheap narrowing (pin to the serial) is **named rather than performed** — it changes a running
service.

## Device facts re-measured rather than quoted

`get-device-info`, unauthenticated, **agrees** with `hsm-domain-map.ts` on firmware 2.4.1 and
serial 39160506 — the file's facts survive re-measurement. **`eck256` is secp256k1**, so the
wallet/x402 path has a real on-device curve. Brainpool and the full RSA range are present and
were not in the file's list, which **widens rather than contradicts** it (the file said "observed
subset"). **Still absent: any FROST-capable mechanism** — threshold signing remains software
FROST over HSM-sealed shares.

## What this deliberately does NOT claim

**Domain separation enforcing per-AI isolation is not metered and must not be read as such.**
`hsm-domain-map.ts` states it at the claim: the **decision** is enforced and tested, the
**separation** is not — nothing stops a caller that already holds an authenticated session from
using any key that session's domains reach, and the gate is one a caller can simply decline to
call. **A probe reporting `Honourable tiers: hardware-pkcs11` is not evidence for it.**

Also still unrun: the Linux TPM 2.0 probe (`081M00VN9P1…`) needs an x86 node; this is Apple
silicon, and the darwin path correctly declines to guess.
