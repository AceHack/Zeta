## Description

> *"for ace to be effective we need a split … different surfaces need different installs. This is related to our repo split as well."*
> *"exactly this — the list of deps is what's important, ace is just one thing that can satisfy it."*

Written **before any manifest is authored**, because this is the part that becomes unretrofittable.

## The invariant

> **A surface declares WHAT it needs, as readable data. It never declares HOW to get it.**

Any consumer — `ace`, a shell script, a human with `apt`, a Nix expression — reads the same declaration. **The moment satisfying a declaration *requires running a particular tool*, that tool is an appointed hub** and `clone-at-tag-stays-sufficient` is violated. That's what keeps `ace` an **oracle** (deference chosen, exit available) rather than a **hub** — where the discriminator is *exit*, not degree of use. `ace` may become the best way and accumulate any amount of use; never the only way.

## #12876 is the evidence, read correctly

It adds a new **150-line `.cursor/install.sh`** that hand-copies **9 apt packages out of the canonical 34** and re-declares the mise pin already at `tools/setup/linux.sh:426`, synchronised by a comment reading *"bump in lockstep."*

**That's not drift — it's a missing abstraction surfacing as duplication.** The cloud agent genuinely doesn't need the proof stack; it needed a way to declare a *subset*, there was none, so it forked. **A fork is what a missing seam looks like from outside.**

## Why "more tiers" is the wrong generalization

The split already exists in miniature — `.mise.toml` + `.mise.full.toml` at `MISE_ENV=full` (`081KTWQZY7F`) — but **a tier is a total order and surfaces are not**:

| surface | needs | doesn't need |
|---|---|---|
| cloud agent | .NET, bun | the proof stack |
| proof lane | Lean, TLA+, Alloy | k8s tooling |
| cluster node | k8s tooling | neither of the above, necessarily |

**No two contain each other.** So every non-nested surface must either over-install (the monorepo union, one level down) or fork — *and both failures are already observed*. The generalization is **named surfaces with declared sets**; tiers become a derived view.

## The load-bearing connection

> **A surface's install set IS a dependency closure. The repo split is driven by dependency closure. Same graph, queried twice.**

One query yields manifests, the other yields repo boundaries. Which means the split becomes **computable rather than argued** — and acquires a falsifier it currently lacks: **overlapping closures mean the boundary is wrong**, and a surface closure spanning two proposed repos means either the split or the surface is mis-drawn.

That's the argument for building declarations *before* finishing the split.

## Two mechanical guards, both small

1. **`.cursor` must join `BOOTSTRAP_SURFACES`** in `lint-clone-at-tag-is-sufficient.ts` — the list predates it, so the omission is an accident, and it's the one place `ace` could quietly become mandatory.
2. **The declaration must be inert.** A surface file that must be *executed* to learn what it needs has already failed the rule.

## Deliberately not done

**The surfaces are not enumerated.** That's yours to draw, and a plausible-looking invented list is exactly the failure this repo keeps catching — a confident artifact standing in for a decision nobody made. The four above illustrate non-nesting; they aren't a proposal.

Nothing here is measured: no implementation, no manifest format, and **no claim the closure is currently computable** — the increment-graph wall is precisely why externalizing it is the point and also why I won't pretend it's already done.
