## Description

> *"lets save this to vision of our dicentralized identity server, this is how we get DoP=1~infintiy on one node and keep agents decorelated and not able to touch each other"*

## The claim that makes this vision-level, not ADR-level

`async-all-the-way` asks for one code path: deterministic and replayable at `DoP=1`, fast at `DoP=N`. On a single node, `DoP=N` is only **honest** if the N workers are genuinely separable — **N agents sharing one credential are one agent wearing N hats.**

> **Identity isolation is a precondition for decorrelation metering, not a feature beside it.** A `ρ` measured across agents that share authority is measuring **one agent N times** — and the Kish `n_eff` it feeds is then not merely imprecise, it's answering a question about a population that does not exist.

That connects the identity substrate directly to today's `ρ` work, which was otherwise a separate thread.

## The chain, each layer with its register

| layer | mechanism | status |
|---|---|---|
| **node** | TPM attests the machine (SPIRE `tpm_devid`) | one identity **per node** — the point *and* the limit |
| **process** | SPIFFE/SPIRE attests the *calling process* (UDS peer creds → docker/k8s/unix plugins) → short-lived **SVID** | the workload **holds no bootstrap secret**; identity is *observed*, not presented |
| **key** | YubiHSM **domains + capabilities + delegated**, delegation monotone-decreasing | **measured** on our own device, fw 2.4.1 (#12813) |

Mapping is `SPIFFE ID → HSM domain`. **Multi-tenancy comes from the HSM, not the TPM** — a TPM binds to the *node*, and a node runs many agents, so it structurally cannot supply the per-agent split. That ordering is the opposite of the intuitive one.

It also reuses machinery we have: SVIDs are short-lived and auto-rotating — the *hats grant claims, bounded duration* model. SPIFFE trust domain ≈ node, SVID ≈ the bounded-duration claim.

## The honest limit is IN the vision text, not omitted from it

SPIRE's attestation reads properties from a **shared kernel**, and the workload-API socket is itself the trust boundary. So this is **strong operational identity, not cryptographic isolation** — a large improvement over shared credentials, and *not* the thing it imitates.

What it imitates is **Singularity** (Microsoft Research): isolation by type-safety and verification rather than the MMU, processes launched from **signed manifests**, managed code and GC in the kernel — succeeded by **Midori**. Neither shipped. **seL4** is the shipped end with a machine-checked isolation proof; SEV-SNP/TDX is the deployable-today tier.

## And the trust assumption is stated, not implied

> *"host root is special for now until we make our own kernel that can disambugate, we have to extra protect the host"*

Recorded as a **stated assumption rather than an oversight** — so the correct response is to harden and minimise the host, and to treat any design that quietly assumes container-level isolation is a security boundary as **wrong until the kernel can tell agents apart.**
