## Description

The glossary/corpus cell (#12848) sorted its output with `a[0].localeCompare(b[0])` in two places. **`localeCompare` consults a runtime locale and an ICU version that differ between machines** — so the same corpus would sort differently on two hosts and the emitted work-list would not be byte-identical. Direct violation of the culture-invariant rule, and it reached `main`.

## The lint predicted this, in its own docstring

> *"`localeCompare` and its siblings have been entirely unguarded on that side. That asymmetry, **not carelessness**, is why these keep reappearing: the same rule is a wall in one language and a suggestion in another."*

C# has `CA1310`/`CA1307` as build errors. TypeScript had nothing until this lint was written. **I walked into the exact gap it was built to close, one day after it was built** — which is the strongest possible argument that the lint was worth writing.

## The fix

An explicit `ordinalCompare` using `<`/`>` on JS strings — UTF-16 code units, machine-independent. The reason is recorded **at the function**, not in a commit message nobody re-reads.

## The test calls `localeCompare` on purpose

The paired negative asserts the two **disagree**. If they agreed, swapping one for the other would be invisible and the test would pin nothing. That requires the banned identifier, so the test file goes on the linter's `ALLOWLIST` with its reason — following the two entries that already do precisely this:

- `society.test.ts` — *"the divergence is the assertion"*
- `tracked-files.test.ts` — *"pins that order is ordinal by exhibiting the locale order it must not be"*

**The allowlist is the sanctioned path here, not an exception carved for my own convenience** — and every entry carries a reason, because as the lint says, *"an unreasoned allowlist is how a rule dies quietly."*
