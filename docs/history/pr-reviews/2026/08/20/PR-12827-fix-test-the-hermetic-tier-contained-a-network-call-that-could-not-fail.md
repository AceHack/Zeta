## Description

Caught from CI logs on #12809 — **1 failure in 13,510 tests**: `GitHubAdapter > git data API methods attempt real calls (not not-supported)`, **timed out after 5000ms**.

Two defects, and they paid for each other.

## Non-hermetic

The test called `adapter.createBlob("hello")` against a nonexistent repo, which shells out to `gh api` — **a real network call inside the tier whose job is literally named "TS hermetic."** The adapter's own spawn timeout is **30000ms inside a 5000ms test budget**, so any slow network is a guaranteed flake, on everyone's PR, forever.

## And unfalsifiable

Its only assertion was `expect(blob.error.kind).not.toBe("not-supported")`. But every error path in `createBlob` returns `classifyGhError(...)` or `forgeError("parse-failure", ...)` — **neither of which can produce `"not-supported"`.**

> It passed on auth failure, DNS failure, rate limit, and on the network being unplugged. It could not distinguish *"wired to gh"* from *"everything is broken."* **A check that cannot fail is not a check.**

## The replacement

Hermetic and falsifiable, pinning what it *meant* to pin: the classifier every git-data method routes failures through never yields `"not-supported"` — exercised across all its branches plus the `status = null` case a missing `gh` binary produces. **Paired with its own negative** (`forgeError("not-supported", …)` *does* yield it), so the assertion discriminates rather than passing vacuously.

## The limit is recorded in the file, not left implied

The replacement pins **the classifier**, *not* that `createBlob` routes through it — so a revert to a stub would stay green. Pinning that without a network call needs a **runner seam** on `GitHubAdapter`, which calls `spawnSync("gh", …)` directly with no injection point. That's a real change, **deliberately not made here**. The other half of the pair is still hermetic: `getBranchProtection` is asserted to return `not-supported` and spawns nothing.

## And the vacuity next door

`resolveThreadsBatch`'s only assertion lived inside `if (result.ok)` — so when the call fails (which it does without `gh`), the test ran **zero assertions and passed by checking nothing.** Now asserts in both branches.
