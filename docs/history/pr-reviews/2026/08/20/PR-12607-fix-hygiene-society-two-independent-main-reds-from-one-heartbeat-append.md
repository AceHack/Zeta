## 2. The ρ measurement pinned a snapshot of a corpus that grows every tick

`test (TS hermetic)` failed for a second, unrelated reason. THE FINDING asserted `effectiveCount ≈ 1.666` and `designEffect ≈ 1.8` — values I authored in #12548 against a 362-draw corpus. `db/mutation-findings/*.jsonl` is append-only and every heartbeat tick grows it, so those pins had an expiry date from the moment they landed. otto's lane appended, ρ moved 0.400 → 0.439, and the assertion failed **having never once caught a defect**.

That is the vacuity class inverted: not a check that cannot fail, but one that fails on data movement rather than on defect. Same error either way — the assertion isn't measuring what it claims to.

Bumping the number would just reset the timer. What is invariant is Kish's identity, so the test recomputes it from the **measured** ρ instead of restating a snapshot:

```
deff = 1 + (n−1)·ρ        nEff = n / deff
```

Corpus-independent, and still a falsifier. Re-ran the four arithmetic mutants the file documents:

| mutant | result |
|---|---|
| `deff = 1 + n*rho` (drop the −1) | 25 pass / **5 fail** |
| `deff = 1 + (n-1)` (drop rho) | 23 pass / **7 fail** |
| `return n` (stub) | 23 pass / **7 fail** |
| ICC denom `msb + msw` (drop k−1) | 27 pass / **3 fail** |

The first is the load-bearing case: it survives the ρ band and dies **only** on the identity — which is why the identity is the right replacement rather than deleting the pins outright. The ICC mutant dies twice over (band, and ICC/φ agreement).

Exact values stay pinned where they belong: the synthetic (n, ρ) golden vectors, frozen by construction. The band on ρ (0.35, 0.45) is kept deliberately — it is a claim about the fleet, and it *should* go red if the fleet's correlation genuinely moves.

**Measured now: ρ = 0.439, deff = 1.878, nEff = 1.598.** Three agents are worth 1.60 independent ones — down from 1.67, i.e. the fleet got slightly *more* correlated as the corpus grew.
