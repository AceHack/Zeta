## Description

Routed after Aaron said "split out some background tasks and push it forward". The
surface-closure agent traced **one surface end to end**. The result supports the framing
and **refutes the central claim as stated**, which is the useful half.

## `lint (Go)` needs **6 units** and is provisioned **~442**

Three apt packages of 34, three mise tools of 18, zero dotnet SDKs, zero of 7 dotnet
global tools, zero of 377 npm packages, zero jars. Measured work: `golangci-lint run ./...`
= **10.0s**, 0 issues, cold caches, against a 15-minute job timeout.

## It is NOT a strict subset — which falsifies the model at N=1

The **Go module graph** is a needed dependency `install.sh` does not provide and no manifest
declares. Verified both directions: `GOPROXY=off` → *"module lookup disabled"*; `GOPROXY=on`
→ 1.6 MB fetched. Nothing in `tools/` or `gate.yml` prefetches it; no `~/go/pkg/mod` in the
cache paths. **Language-native registries are a fifth dependency category** the sketch does
not cover.

## §1's fork is not the first

**Four gate jobs already forked out of `install.sh` inside `gate.yml` itself**, and they
state their reason — `lint (actionlint)`: installing the full bootstrap means *"apt
proof/QEMU/R substrate can consume the timeout before actionlint itself runs"*. A fifth
mechanism: five jobs use `setup-bun` with **no version**, so they get latest rather than the
pinned bun.

## Two costs nobody is choosing

Every gate job installs Claude Code + Codex **unguarded** while its siblings all guard; and
every gate job **compiles E prover 3.2.0 from source** — tarball cached, build not. That
already cost the fleet PR #11486: three unrelated PRs red because GitHub 429'd the eprover
tarball, killing a bun-only lint job with a first-order-logic prover.

## Derivability is about invocation shape, not language

Swept all 29 gate jobs: **`lint (Go)` is the only one with an empty `unresolved` set.** A
closure is derivable exactly when the leaf spawns literal command *heads*; the moment a tool
goes through another (`uv run X`, `dotnet X`, `npx X`) head-scanning goes blind, **and
silently**. The deriver reports those as `unresolved` rather than under-claiming, and its
tests pin the Python shortfall **as an assertion** so it cannot quietly become a claim.

## So §4 is not yet true — and the correction is the valuable part

The split being *"computable rather than argued"* is **not blocked on effort or a smarter
parser. It is blocked on a missing declaration.** `build-graph.json` + `affected-legs.ts`
already declare **files → jobs** as data, derived at run time, never hand-maintained. The
inverse edge, **jobs → tools, is declared nowhere** — and the four forked gate jobs are what
a missing edge looks like from outside.

Undecidable boundary named rather than guessed: host tier is a runtime property of the
runner's RAM; best-effort realizers change the set by succeeding or failing at exit 0;
conditional realizers key on what earlier steps installed; second-hop spawns through
imported modules are unreadable.

**Verified before landing:** 11 tests pass, 28 `expect()` calls; deriver re-run on `lint (Go)`
(empty `unresolved`) and `lint (Python)` (reports its shortfall).
