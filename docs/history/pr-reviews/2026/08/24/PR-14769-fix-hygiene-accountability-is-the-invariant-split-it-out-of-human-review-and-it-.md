## Description

## The defect

`Human-Review` does **two jobs in one field**:

- **(a)** a named party is **accountable** for this change — constant across every commit of a branch, because it follows from a standing grant;
- **(b)** a **human read this diff** — legitimately varies per commit.

**(a)** is why the field is governance-critical. **(b)** is a per-commit causal fact of exactly the kind `Action-Mode` carries. Sharing one field, they make honest per-commit records read as contradictions about authority.

Diagnosis: `docs/research/2026-08-24-liability-is-the-invariant-human-ness-is-its-current-binding-and-the-squash-carrier-already-layers.md` (#14754).

## What ships

Two **optional** keys, additive, and a reader that can use them:

```
Accountable-Party   acehack | lucent-financial-group          — WHO CARRIES BLAME
Authority-Basis     standing-grant | per-act | gated-class-approval
```

`Accountable-Party` is an **identity, not an actor class** — it accommodates a human, a company, or, if some jurisdiction ever recognises one, an AI, **with no rename**. `Human-Review` would need one. `.claude/rules/no-directives.md` already says human-only is *"for now (until legal entities can hold AI-side responsibility)"* and that what is tracked is **blame**. The rule is time-aware; the schema hardcoded the present moment.

`Authority-Basis: standing-grant` is the word the schema lacked. The same rule grants authority broadly and indefinitely, and the vocabulary has no term for **inheritance** — so every inherited act must currently be recorded as an **absence**.

**Accountability never layers and never reconciles.** A change with two accountable parties has no accountable party. Both keys are governance-critical with no resolution rule and no last-wins.

**What it buys:** when every block carries the *same rostered pair*, `Human-Review` is no longer the accountability claim, so it reconciles to the weakest review claim present — same mechanism, same direction as `Action-Mode` (#14584, unchanged). `Human-Review-Evidence` follows only as a *consequence*, never on its own.

## The part to review — the teeth are the coverage gate

The guard that makes `reconcileActionMode` safe (refuse any set whose minimum still claims a human) is **vacuous** for `Human-Review`: it has exactly one presence value and it is the maximum, so the minimum of a disagreeing set can never be a presence claim. Writing it anyway would be a line that cannot fire, dressed as safety. **It is deliberately not written.**

The relaxation instead requires a **full, agreeing, rostered** anchor on *every* block. Partial coverage buys nothing. An unrostered party buys nothing. `unknown` is deliberately **absent from the roster** — every other enum here admits an honest `unknown` floor and that is right for them, but an unknown accountable party is not a measurement, it is the absence of one wearing a value.

**Silence is recorded, never inferred.** The v1 corpus is permanently silent on accountability; `not-implied-by-credential` does not determine a party, because the information was never captured. A block omitting the pair is read as silent and is exactly as valid as today.
