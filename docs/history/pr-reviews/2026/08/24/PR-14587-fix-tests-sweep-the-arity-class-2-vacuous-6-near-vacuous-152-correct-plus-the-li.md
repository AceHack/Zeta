## Description

## The row asked for the class, not the instance

081M0RAX8AC087G0R003NQM7P9 named one check and made sweeping the **class** an acceptance
criterion, on the grounds that a targeted fix of one instance does not clear a class. The class:

> **A check whose arity is lower than the arity of the property it claims.**

Noninterference is a **hyperproperty** — 2-safety, a predicate over PAIRS of executions
(Clarkson & Schneider, *Hyperproperties*, CSF 2008 / JCS 18(6):1157, 2010). No monitor observing a
single execution can decide it; that is a theorem, not a coverage gap. Manifesto §13 **is**
noninterference, so the repo has committed to a discipline no arity-1 test can witness.

## Method — a detector, not a grep

Lumen's refinement is correct that a grep for `X = X` finds the visible form and misses the two that
matter. The detector normalizes both sides of every equality check and **transitively inlines
`let`/`const` bindings** before comparing:

| form | grep | detector |
|---|---|---|
| syntactic `f x = f x` | yes | yes |
| **name-bound** `let a = f x` … `let b = f x` … `a = b` | **no** | **yes** |
| **helper-mediated** `Assert.Equal(render (mk 1), render (mk 1))` | only if textually identical | yes |
| conjunct-embedded `c1 = c2 && c1 >= 0` | no | yes |

**755 files scanned** (F# and TypeScript).

## What is mechanical, so this does not depend on anyone re-running the sweep

`src/Core.TypeScript/hygiene/audit-check-arity.ts`, gated in `gate.yml`, falsified in both directions
by `audit-check-arity.test.ts` (19 tests).

- **R1** — a test whose **name** declares independence of a named variable may not resolve to a
  self-comparison. Arity is **declared, never inferred**: Rice (1953) makes the semantic version
  undecidable, and runtime read-set tracing is unsound in *both* directions, so the signature — here,
  the name — is the only sound over-approximation.
- **R2** — a counted per-file census (`registry/check-arity-census.json`, 107 files / 155
  comparisons) failing when a count goes **up** and equally when it goes **down**. Same mechanism,
  and same reason, as `audit-ambient-time-in-tests.ts`.
- **R3** — an F# test source no `.fsproj` compiles. The `*.test.ts` half of this check has existed
  since 2026-08-13 (`unexecuted-test-files.ts`); **the F# half did not**, which is how an uncompiled
  1000-case property sat on `main` since #2329.

## THE COVERAGE LIMIT — the class is NOT cleared

Stated plainly, because *a partial sweep that reads as a cleared class is this defect one level up*.
Four regions were not searched:

1. **Non-equality checks are entirely outside the detector.** It inspects only `=`, `Assert.Equal`,
   `expect().toBe/toEqual`, `assert.equal`. A 2-safety claim discharged with `Assert.True`,
   `Assert.Contains`, or a bespoke predicate is invisible — and sabotage 1 shows exactly that: the
   taint-style check *"the minted card content carries no clock data"* **passed** under a live clock
   leak, because the leak carried the phase as a bare integer. **Largest unsearched region, unsized.**
2. **Semantic equivalence beyond binding substitution** — cross-file helpers, shadowed rebindings,
   alias chains past the 6-level cap. Undecidable in general (Rice), so permanent rather than pending.
3. **R1's vocabulary is a whitelist.** Measured in this sweep: R1 fired on 5 of 6 bucket-2 sites and
   **missed `ActionGrid.Tests.fs:121`** (*"frame and content are separate: same geometry, different
   labels"*), and does not fire on the bucket-1 `Policy.Relocation` case. Both were found by census +
   manual reading, not by R1.
4. **Bucket-3 adjudication was not uniform.** All 34 non-determinism-named hits were read in source;
   the remaining ~126 were adjudicated **by name against the varied variable**, with targeted source
   reads of the subset carrying a differing quantifier (`different` / `independently` / `across
   independent runs` / `two nodes`).

**A complete sweep would require arity to be declared at the check** — an attribute or wrapper naming
the quantified variable and the execution count — so the lint compares two declarations instead of
parsing English. That is a change to how checks are *written*, which is the only sound
over-approximation available. Runtime read-set tracing is specifically **not** the answer and should
not be built.

**Register: `unmetered`.** The lint fires on the known instances and has falsifiers in both ratchet
directions, so it is not decoration; but nothing has been caught by it in the wild, and the four
regions above are unsearched. This PR does not claim `metered`.
