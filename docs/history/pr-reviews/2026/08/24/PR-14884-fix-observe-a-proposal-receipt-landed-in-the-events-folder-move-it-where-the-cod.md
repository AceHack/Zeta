## Description

fix(observe): a proposal RECEIPT landed in the events folder — move it where the code says

`lint (structural hygiene)` is red on `main` and therefore on every PR that runs
it -- 5 open PRs measured, including two of my own. Not a blocker
(`lint-structural-hygiene` is not in `gate (required)`'s needs), which is
exactly why it sat red: a permanently-red non-required check trains readers,
including me, to score red as noise.

CAUSE. `docs/observe-events/agent-proposal-receipts/` is a DIRECTORY inside a
folder whose invariant is that every entry is classifiable by shape --
`audit-observe-event-filenames` defends three naming schemes so a reader can
tell what a name IS without decoding it. A subdirectory is in none of them.

The content confirms the audit rather than contradicting it: the file is a
`zeta.agent-proposal-receipt.v1`, which is a receipt from the gated-commit
workflow and NOT an event. It does not belong in an events folder on the merits,
independent of the naming rule.

AND THE CODE ALREADY SAYS WHERE IT GOES.
`src/Core.TypeScript/planning/agent-proposal-runner.ts:114` resolves
`docs/automation/agent-proposal-receipts/<proposalId>.json`. That directory did
not exist -- so this receipt was written to a path nothing reads, in a folder
that forbids it. Moved to the path the writer names; no code changed, no
allowlist widened, no check loosened.

Landed in 92770a063 (#11469), which is still open and still red on this same
check.

VERIFIED, exit codes captured directly, never through a pipe:
  audit-observe-event-filenames  rc=0  ("5296 files, all names classifiable by shape")

SABOTAGE CONTROL: re-introducing a subdirectory under `docs/observe-events/`
drives it red (rc=1); removing it restores rc=0. So the green is a check that
ran, not one satisfied by absence.
