## Description

## What

`ace` is the one-liner installer's payload, and Aaron's runtime ladder puts **recompile from source** above **download a binary**: *"source you recompile is source you can verify; a prebuilt binary is bytes you must trust."* Until now the only shippable ace artifact was a **61 MiB `bun build --compile` binary**, because `node src/Core.TypeScript/ace/ace.ts list` died with `ERR_MODULE_NOT_FOUND`.

Node's ESM resolver requires explicit file extensions on relative specifiers. Bun's does not. And `tsc` does not catch the gap either — `moduleResolution: "bundler"` accepts extensionless exactly like bun — which is why nothing in the existing suite noticed. **Sixteen specifiers across ten files** now carry explicit `.ts` extensions. Nothing else is restructured.

`node ace.ts list` → **rc=0**.

## Proven, not asserted

`ace-node-runtime-parity.test.ts` runs the same commands under bun and under node in an **identical sandbox** (reset between runtimes, so any printed path is the same string for both) and compares stdout **byte-for-byte** — help, empty store, error paths, and an install/list/verify/registry transcript carrying **BLAKE3 digests and an Ed25519 signature**.

"node runs it" is worth much less than "node produces identical output". Only the second makes the source rung a *substitute* for the binary rung rather than a second, differently-behaving ace. A static guard sits beside it, so a future extensionless import fails **by name** instead of waiting for someone to try node.

## One measured divergence — `ace deps` + out-of-subset YAML is bun-only

The original parity scenarios **never exercised the YAML modules this change touches**. Closing that gap found a real divergence, and it is reported rather than trimmed away:

`ace deps validate` on a graph using flow sequences (`needs: [beta]`) or folded block scalars falls out of the hand-rolled subset reader into `yaml/vendor.ts`, whose adapter is **`Bun.YAML`** — a Bun built-in with no node equivalent.

| input | bun | node |
| --- | --- | --- |
| graph inside the YAML subset | rc=0 | rc=0, **stdout byte-identical** |
| flow style / block scalars | rc=0 (vendor adapter) | **rc=1, named refusal**: `Bun.YAML is unavailable on this runtime` |

This is the adapter behaving as designed — it *probes* for the built-in and returns a **named refusal** rather than a `TypeError` — so it is neither a regression nor a bug. It is recorded because a rung's limits must be as legible as its capabilities: "ace runs on node" would otherwise read as a promise this one command does not keep. A test pins that the refusal is **named** and that stdout stays **empty**; the failure mode worth guarding is not "node refuses" but "node answers differently and nobody notices".

Not closed here: widening the TS subset unilaterally is forbidden (081KT7YW00008QG0R002T1XNWT — the six-oracle byte-lock rests on every oracle declining the *same* inputs), so the fix is a node-side vendor adapter and deserves its own decision.

## CI caught one thing review did not

The `No check-then-use filesystem races (TOCTOU, CWE-367)` step went red on the new test: its closure walker used `existsSync` then `readFileSync`, twice. Rewritten to a single `readFileSync` inside a `catch` — "cannot be read as a file" *is* the answer the resolver wants, and it is the same answer for every reason it might hold. The sabotage control was then **re-run against the rewritten walker** (6 fail, restored to 10 pass): a guard rewritten without re-proving it can still fail is a guard you have stopped testing.

## The authenticity gate is pinned too, not just the integrity one

BLAKE3 (integrity) was covered by the install/list transcript. **Ed25519 signing (authenticity)** is a separate path and the one an attacker cares about, so it gets its own falsifier: if node and bun derived different key ids or different signature bytes for the same key and payload, a package signed on one runtime would fail verification on the other — the byte-identity claim would be false exactly where it matters most.

The comparison is legitimate rather than a comparison of two random draws because Ed25519 is deterministic by construction (RFC 8032 §5.1.6 — the nonce comes from the key and message, never an RNG). One keypair is generated **once** and both runtimes sign with it; one per runtime would compare two different keys and prove nothing.

**Sabotage control:** fold a runtime-discriminating byte into the signed payload (`Bun` present ? `"B"` : `"N"`) → rc=1, and **exactly one** test fails — this one. Restored to 11 pass.

That test's first draft also went red on a bug of its own: it gave each runtime a different `--out` path, and ace prints the out path in its success message, so stdout differed for a reason unrelated to the runtimes. Fixed. A false red that hides a real one is the same defect class as a false green.
