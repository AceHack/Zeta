## Description

# Summary

Restore QEMU sits before wifi / keyfile write / picker / scenarios 3–4. GitHub skips later steps after a failure unless `if: always()`. Measured on [run 32724820159](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/32724820159): restore hung on the picker TTY, then those siblings were skipped. This keeps the sibling **run** steps on `always() && workflow_dispatch`. Restore itself stays a hard fail (no `always()`, no `continue-on-error`) so a restore red still fails the job. Still off `gate (required)`.

Also locks the leftover P0 contract: empty bake (`--defer-all`) still writes a decryptable blob bound to the UEFI keyfile, and `wrote 0 creds` still satisfies `assertUefiKeyfileRestoreContract`.
