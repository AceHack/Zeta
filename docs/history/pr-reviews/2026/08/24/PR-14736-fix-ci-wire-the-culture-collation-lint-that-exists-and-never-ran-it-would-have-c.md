## Description

## The check existed. It ran nowhere. It would have caught a regression shipped today.

`hygiene:no-culture-sensitive-collation` is the **mechanical enforcement of a carved rule** —
`.claude/rules/culture-invariant-by-default.md`. It is configured, named in `package.json`,
has carried a baseline file since it landed, and until this PR **no workflow invoked it** —
neither by script name nor by path.

My own linter-coverage audit (#14703) found it and classified it `A GENUINE HOLE`, then
declined to close it, because that audit does not widen checks. This is the separate,
measured change it named.

### Why this is not merely the cheap one

That rule's cited live failure is **`081KT07NV0008QG0R001YDB73K`**: `ZSet.ofSeq` sorted
culture-sensitively, which made `GCounter.Merge` **non-associative** — a CRDT algebraic law
broken by a collation choice.

On **2026-08-24** an agent shipped **two `localeCompare` calls** into a PR, reintroducing
that exact class, and said so in its own words:

> *"I introduced the class I was arming a check against, twelve files away."*

It was caught **by hand, late**. The machine that exists for precisely this did not run.
That is the argument; the rest of this PR is bookkeeping.

### Why the asymmetry keeps producing this

`.editorconfig` sets CA1304 / CA1305 / CA1307 / CA1310 / CA2007 to `error`, so the **C#
compiler refuses** culture-sensitive comparison outright. **TypeScript has no equivalent
analyzer.** The same carved rule was a wall in one language and a suggestion in the other.
That asymmetry, not carelessness, is why these reappear.
