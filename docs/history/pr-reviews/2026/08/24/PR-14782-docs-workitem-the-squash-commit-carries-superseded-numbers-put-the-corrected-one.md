# Summary

`bc2d43b3` (#14768) landed with my **original commit message**, not the corrected PR body. GitHub squash-merge takes the commit messages — the exact failure `.github/PULL_REQUEST_TEMPLATE.md` warns about (*"Fixing only the body is not sufficient"*). So `git log` on main now states:

```
mean distance kept from the HUNTER    22.16 px    34.13 px
mean distance to the PREY             35.88 px    23.06 px
...picking the right label 97.5% of the time
```

Those readings are real, but they are **one deterministic trajectory** under the `desiredKeyOf` steering policy — what `train-priors.ts` and the integration tests drive — not six seeds, and not what the live page does. The tell was that running it across six seeds produced six **byte-identical** rows: that policy consumes no randomness at all, so seeding cannot vary it, and six runs were one run printed six times.

Re-measured under the **Thompson policy the arena actually runs** (`swarm-controller.ts`), across six genuinely distinct trajectories:

| | before | after |
|---|---|---|
| self is the actual player body | **0.0%** | **67.7%** |
| adversary is the actual opponent | 57.5% | 72.9% |
| distance from the **hunter** (want FAR) | 11.96 px | **23.37 px** |
| distance to the **prey** (want NEAR) | 36.74 px | 33.24 px |
| mode **label** correct | 91.0% | 79.1% |

**Flee is decisively fixed** — the agent used to sit ~12 px from the thing hunting it. **Hunt is only nudged** and still does not close. The mode *label* got worse while the *behaviour* improved, which is not a contradiction: before the fix the agent held the correct label and moved the wrong way, and that is precisely what was reported.
