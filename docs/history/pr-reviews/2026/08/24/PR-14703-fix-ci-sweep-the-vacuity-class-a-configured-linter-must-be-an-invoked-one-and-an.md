## Description

## The class, not a fourth point fix

**A linter is present, configured, believed to be checking a file, and does not examine it — while the invocation exits 0.** Every instance produces a check that did not run and looks like a check that passed.

Three instances surfaced by hand on 2026-08-24; `#10712` (`lint:markdown` linting **zero** files and exiting 0 for months) is a fourth, already paid for. The `lint (bash retirement inventory)` job that now hosts this audit already carries three separate comments saying "a check that exists and is wired to nothing reads exactly like a check that passed". Prose about the class regenerates the class. This is the machine.

**Nothing is turned on. No carve-out is removed. No ignore entry, disable, or override is added. Nothing is widened.** Every carve-out below may be deliberate — the job is to make the blindness legible and to fail when it *changes*. What to do about each instance is the maintainer's call, and each row carries the measured cost so that call has numbers under it.

## The meta-check

`src/Core.TypeScript/hygiene/audit-linter-coverage-vs-invocation.ts` — four checks, exit **3** on divergence.

1. **Script parity.** Every lint/format/hygiene/typecheck script is invoked by a workflow (by name *or* by the path it shells) or is in `DECLARED_UNINVOKED` **with its reason**. Checked **both directions**: a listed script that starts being invoked fails, and a declaration for a deleted script fails. A ledger you can only add to is a suppression list.
2. **Tool parity.** Every linter **discovered** through three independent routes — third-party binaries shelled by lint scripts, devDependency *name shape*, root config-file *name shape* — must be claimed by a `TOOLS` row whose disposition matches the workflows. `gated` with no invocation is red; `ungated` **with** one is red too (good news the ledger is lying about). An unclaimed discovery **is instance #4, caught by machine**. The routes match by shape, not by a list of the tools we happen to use, so `oxlint`/`biome`/`dprint` are recognized with no edit.
3. **Examined-corpus floors** — the sharp sub-case, below.
4. **Exclusion parity.** `tsconfig.json#exclude` vs `eslint.config.ts#ignorePatterns` — two lists of one fact, maintained separately. **11 divergent patterns covering 619 tracked `.ts` files**, every one a guaranteed typed-linting parse error the moment the roster widens over them. The eslint-only direction is empty and is required to stay empty. Shape from `audit-dotnet-pin-parity.ts`. Canonicalization collapses `bin` / `bin/**` / `**/bin/**`, without which six entries that agree read as divergences — and six false positives are how a parity check gets switched off.

**The audit carries the discipline it audits** (`audit-scan-floor-routes.ts`): each discovery route and each corpus has its own floor and fails **naming itself**, rather than reporting a shorter roster as though the class had shrunk.

### The sharp sub-case: exit 0 over zero files

Every `gated` tool asserts a floor on the corpus its invocation actually reaches. **markdownlint's is measured through markdownlint-cli2's own glob-and-ignore resolution** — a probe rule that records every file the linter opens — because reimplementing its ignore semantics here would drift from the gate within a release. Asking the linter is the only answer that stays true.

Floors are **half the corpus measured at landing**, and that choice is stated rather than tuned: the failure being detected is a *collapse* (a glob that stops matching), not a drift. Half is the largest single-step reduction ordinary churn plausibly produces. It is deliberately *not* a ratchet on the exact count — a floor that fails on every legitimate deletion gets raised by whoever is annoyed by it, and a floor nobody believes is a blind instrument again.
