# 1. fix(bnn) — the reward sensor fabricated rewards

Inverted cart, seed 23, 4000 ticks, the arena's own Thompson policy:

| | value |
|---|---|
| score changes the cart actually made | **3** |
| reward events the learner absorbed | **35** |

The OCR readout misreads **3 as 9** for exactly two ticks while a sprite brushes the top-right digit, with the true score parked at `0:3` for a thousand ticks:

```
1728   truth 0:3     OCR  0 / 9      <- misread begins
1729   truth 0:3     OCR  0 / 9      *** REWARD  (seen twice -> accepted)
1730   truth 0:3     OCR  0 / 3      <- misread ends
1731   truth 0:3     OCR  0 / 3      *** REWARD  (seen twice -> accepted back)
```

`absorbScoreboardReward` guards with **two-tick agreement**, which catches a *one*-tick flicker and is structurally blind to a *two*-tick one. The magnitude is wrong too: `r = mine − prevMine − (theirs − prevTheirs)` yields ±6 from a 3↔9 flip where a real tag is ±1, and the pair sums to zero without cancelling, because each half is credited against different eligibility-trace contents.

**The fix is the cart's own arithmetic**, not a tuned threshold: `ADD V5, 1` / `ADD V9, 1` are counters, never reset and never decremented, so a delta outside `{0, +1}` did not come from the game.

**Discrimination proof** — without the fix `Expected: <= 3, Received: 35`; with it, 3 and 3. The test must be driven by **Thompson sampling**; written first against `desiredKeyOf` it passed with the bug still in place, and that vacuity was caught only by running it against the unfixed code.

# 7. docs(research) — the mode learner was learning all along

(1) was motivated by a premise I had been carrying and never checked: *"the mode learner has learned nothing."* Re-measured on clean instruments, **that premise is false** — every bucket the agent visits has moved off its prior, on both carts.

**The actual defect is not sparsity, it is one-sidedness.** The agent scores **zero points in 4000 ticks on both carts**, so every reward it has ever seen is `−1`. Credit then lands only on the arm that was *executed*, while the untried arm keeps its prior — so `choose` comes to be decided by what was recently played rather than by what is better:

> `small/away`, normal cart: `hunt` was executed, was punished, fell `0.200 → −0.518`. `flee` was **never executed there** and sits exactly at its prior `−0.200`. So the learner now prefers **flee** — and nothing about flee was ever measured. It won by not having been tried.

Under all-negative reward it ratchets *away* from whatever it just did, regardless of merit: an anti-exploration oscillator wearing a policy's clothes. Three events is plenty to move four posteriors; the count was never the problem.

Also: on the inverted cart the `big/*` buckets have **zero visits** (its hunter is small solid, so `bigAdversary` is never true), so half the table is untrainable there by construction.

**A near-miss I kept in the write-up.** The first version of that harness printed `mine=v[5]`, saw OCR `[0,1]` against registers `1/0`, and concluded the reward *sign* was inverted — that the agent was being punished for winning. It was not: `mutual-sim.ts:34/38` says **V5 is the AI's score and V9 the player's**, and the agent plays the player. It was losing 0–3 and the `−1` rewards were correct. A dramatic finding arrived from a variable name I assigned without checking, and reading the ROM is what killed it.

`arena-reward-audit.ts` is added so the numbers can be **re-run rather than trusted**; it reproduces every figure, and carries the two provenance rules and that labelling trap in its header.
