## What

Follow-up to [#12876](https://github.com/Lucent-Financial-Group/Zeta/pull/12876) (which shipped a bespoke `.cursor/install.sh`). Per maintainer direction, dogfood the real installer instead of a fork:

- `.cursor/environment.json` now runs `ZETA_AUTO_EDIT_PROFILES=1 bash tools/setup/install.sh` — the canonical three-way-parity installer, with `profile-edit` enabled so the managed `shellenv.sh` wires into the agent's shell.
- Removes the bespoke `.cursor/install.sh` and its bash-retirement allowlist entry (it's no longer a new shell file; `install.sh` is already retained).
- **Beefs up `tools/setup/linux.sh`**: makes the apt phase non-interactive-safe.

## Why

`install.sh` already orchestrates the `ace` setup-realizers (`setup-realize --all`) on top of mise runtimes + managed `shellenv`, so using it *is* dogfooding the `ace` setup path — no duplicated logic, and runtime versions can't drift from `CONTRIBUTING.md`/CI.

## The non-interactive fix (the beef-up)

A fresh headless base image died in the apt phase on `fuse3`'s `fuse.conf` conffile prompt: `end of file on stdin at conffile prompt` (rc=100). CI doesn't hit this because its runner images ship those packages. The fix makes the apt phase headless-safe for every consumer (Cloud Agents, devcontainers, minimal-image CI):

- `DEBIAN_FRONTEND=noninteractive` on `apt-get update`, `apt-get install`, and the `dpkg --configure -a` recovery.
- `-o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold` on install, and `--force-confdef --force-confold` on the recovery loop (dpkg conffile prompts are dpkg-level, not debconf, so `DEBIAN_FRONTEND` alone isn't enough).
