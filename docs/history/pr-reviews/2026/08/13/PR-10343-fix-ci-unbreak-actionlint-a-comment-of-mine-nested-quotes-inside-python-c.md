## Description

`lint (actionlint)` — and with it **`gate (required)`** — has been failing since #10339 merged, and the cause is **a comment I wrote in that PR**:

```
agent-heartbeat.yml:337:9: shellcheck reported issue in this script:
SC2140:warning:38:61: Word is of the form "A"B"C" (B indicated).
Did you mean "ABC" or "A\"B\"C"?
```

The cadence step runs `python3 -c "..."`, so the whole script lives inside a double-quoted shell string. My explanatory comment about the malformed event file contained a literal `'{"attestor"...'` — double quotes **inside** that block, which the shell reads as the `"A"B"C"` concatenation form. The `\"` escaping in the patch script that generated the file was consumed on the way in, so what landed was bare quotes.

Reworded to say the same thing without inner quotes. The comment was explaining a hex-encoded filename; it doesn't need to quote the JSON key.

## Verified, with the caveat stated plainly

**actionlint could not run on this machine.** It aborts with *"could not make stdin pipe … too many open files in system"* and returns **rc=0 having checked nothing** — precisely the did-not-run-looking-like-passed trap, so I didn't count it.

Instead the complete cadence step was extracted and run through the same shellcheck binary and flag set CI uses:

```
SC2140 hits: 0   (was 1)
```

The other diagnostics on the extracted script are artifacts of pulling it out of YAML context — python f-strings like `{gap/60:.1f}` read as shell parameter expansions once the quoting is gone. CI reported **only** SC2140 for this file, and that's the one now gone.
