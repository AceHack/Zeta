## Description

## Why

Receipt exchange already had a deterministic tab selector and a complete fixed-peer BroadcastChannel link, but no source-owned component connected coordinator readouts to link lifecycle. Callers still had to choose, retain, replace, and close links themselves.

## What changed

- add a narrow link port and factory owned by the browser-node layer
- reconcile one active link from bounded tab-coordinator readouts
- retain a stable peer without reopening resources
- close the old link before opening a newly selected peer
- close stale links when the local tab becomes dormant, alone, or the snapshot is invalid
- expose explicit idle, linked, dormant, alone, backpressured, heat, and closed readouts
- convert injected construction, read, handoff, and teardown failures to typed feedback
- bind the generic host to the existing native BroadcastChannel peer link
- export the host through the browser-node barrel

The host introduces no clock, timer, polling loop, or receipt protocol change. Lifecycle coordinator readouts provide cadence through the existing sink port.
