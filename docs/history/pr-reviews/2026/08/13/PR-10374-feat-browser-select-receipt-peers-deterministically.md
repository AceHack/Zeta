## Description

## Why

The browser receipt link can address a peer, but callers still have to choose that peer themselves. With several active tabs, that leaves duplicate delivery work or ambient selection policy outside the source-owned database boundary.

## What

- derive one deterministic ordinal-successor ring from the converged browser-tab presence snapshot
- admit only foreground/background tabs and keep suspended/dark local tabs dormant
- fold duplicate presence through the existing sequence-aware convergence rule before selecting
- enforce a caller-declared tab capacity with no forgetting; oversized snapshots return typed backpressure
- return typed heat for invalid configuration, malformed presence, or a missing local identity
- export the pure policy from the browser-node source surface with six focused tests

## Limits

- this is pure peer-selection policy; live coordinator discovery and dynamic page-link rebinding remain separate work
- the local macOS/OpenJDK 26 TLC process crashed once after model completion during an earlier full preflight; the exact TLC test then passed 10/10 and the complete .NET suite passed in the final run. JVM hardening is being kept as a separate reliability change.
