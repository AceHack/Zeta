## Description

Two agents attacked GH013 from different angles. This reconciles them so neither re-solves the other half, and records what each verified.

**Their track** (`automation/society-protected-main-contract`): society-heartbeat, branch → PR → gate → merge per heartbeat, with tests and a design doc.
**This track**: the telemetry workflows, ZetaId-keyed writes + staging-ref flush.

## Corrections recorded

- **The workflow-file blocker is credential-specific, not a repo wall.** I claimed it generalises; testing showed a credential carrying the `workflow` scope pushes five workflow files fine. Their IDE should check which credential it authenticates with before treating it as immovable.
- Three premises in my own brief were wrong, two would have caused damage — most notably a **name collision** where the hygiene tools guard a markdown journal, not the JSON ledger.

## Verified facts they may not have

- `CI Gate` targets `~DEFAULT_BRANCH` only, one rule, **`bypass_actors` empty**.
- `heartbeat/*` is genuinely ungated (deletion rule only).
- Dropping `[skip ci]` does not help on a direct push (required checks evaluate at push time) and **actively breaks a PR route** (suppresses `pull_request` runs, so the PR hangs unmergeable forever).

## The one real conflict, framed for Aaron

Per-heartbeat PRs vs staging-ref flush. Their principle — **"the heartbeat cannot certify its own evidence"** — is the best sentence either track produced and is adopted verbatim. But it is satisfied by *any* exogenous check and does not require one PR per event.

## Ruleset direction

Path exclusion is **not** available — branch rulesets condition on `ref_name` only. Under "minimal rulesets, only no harmful actions", Branch Safety and Heartbeat Branch Protection survive unchanged (they *are* that); **CI Gate is the one that goes** — which relocates enforcement from the forge to the society, the same forge-independence direction as everything else.
