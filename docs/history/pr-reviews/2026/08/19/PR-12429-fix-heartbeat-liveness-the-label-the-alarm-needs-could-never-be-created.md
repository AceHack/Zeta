## Description

fix(heartbeat-liveness): the label the alarm needs could never be created

`heartbeat-liveness` failed at 14:57 UTC (run 32267142969). The failure is not
about liveness. The watchdog correctly detected a stale lane -- the 14:14 and
14:32 agent-heartbeat runs were both cancelled, so no success had landed for
~43 minutes -- and then died on the step that raises the alert:

  HTTP 422: Validation Failed (.../labels)
  description is too long (maximum is 100 characters)

MEASURED. The `--description` string at line 126 is 113 characters against
GitHub's documented 100-character ceiling:

  "Raised by .github/workflows/heartbeat-liveness.yml when no agent-heartbeat
   run has succeeded within the threshold"                        113 chars

Shortened to 95 by dropping the redundant `.github/workflows/` path prefix --
the label is repo-scoped and the file is named in full in the issue body, so no
information is lost:

  "Raised by heartbeat-liveness.yml when no agent-heartbeat run has succeeded
   within the threshold"                                           95 chars

WHY THIS MATTERED MORE THAN A RED CHECK. The 422 is not survivable by design,
and correctly so:

  grep -q "already exists" label_err.txt || { cat label_err.txt >&2; exit 1; }

That guard exists so permission and rate-limit failures surface instead of
becoming a silent no-op. It did its job. But it means the step has ALWAYS
exited 1 here: the label never existed, so `create` was never a benign
"already exists", so the run always died BEFORE reaching the issue it was
written to file. The escalation path -- the one surface the header says
"survives outside the Actions tab" -- has never once run to completion.

This is the same shape as the other findings in this lane: a remedy whose
applicability condition it can never satisfy. The check was right, the alarm
was right, and the thing they hand off to could not execute.

NOT FIXED HERE, and stated rather than left implied: nothing prevents this
regressing. A future edit that lengthens the description past 100 reintroduces
it, and it will again only be discovered the next time the lane actually goes
stale -- i.e. at the worst moment. A lint over workflow label descriptions
would close that, but adding one is a scope call, not a bug fix.
