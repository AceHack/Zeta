## Description

correct(research): the dark-node doc's glossary claim is wrong -- the brief was right, the check was stale

PR #12220 landed with a Vocabulary paragraph asserting that docs/GLOSSARY.md has
no `Surface` entry and that the routing brief's claim to the contrary was false.
The claim is inverted: origin/main carries `### Surface (= host-boundary seam;
the metered port)` at line 520, `### Tick source` at 563, and `### Actor / entity
/ persona` at 578, landed by PR #12173 which merged BEFORE that work was routed.

THE ERROR IS MINE, not the document's. The author checked honestly and the check
returned a false negative, because the tree it read was 754 commits behind
origin/main. My routing brief said "work in a git worktree" and never said "fetch
first" -- and a worktree cut from a stale local ref is exactly as stale as the
ref. I corrected two other agents about this today and missed this one, because I
had told it "worktree" and assumed that was sufficient.

Same root cause as the refresh-worldview fix in PR #12219: a stale view read as
current is a check that did not run looking like one that passed.

THE INVERSION IS THE PART WORTH KEEPING, and it is why the paragraph is retained
with a correction block rather than deleted: the brief's claim was TRUE and the
verification was FALSE, so the honest act of checking produced the wrong answer
and stated it more confidently than the unverified claim it replaced. A check is
only as current as its input, and nothing in the read told the reader how old the
input was. That is a sharper statement of the failure than the original doc could
make, and deleting the paragraph would delete it.

Open question 6 ("should these be promoted into the glossary?") is closed as
already-done rather than answered. No workitem needed.

Not affected: every pointer in the doc is still correct,
docs/writer-actor-routing-model.md §108-110 remains the detailed home the glossary
entries point to, and nothing in the design rests on the false claim.

Separately and also mine: this work duplicated Kenji's PR #12179 (merged
23:05:31Z, ~1h before I routed it). I did not check for existing or in-flight work
on the layer before routing. The author caught it mid-task, discarded a complete
six-service draft rather than ship a competing decomposition, and wrote a
companion instead -- which was the right call and cost real work that a
pre-routing check would have saved.
