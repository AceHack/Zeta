## Summary

Multiple stale PRs looked blocked on a premise that is **false, and was measured false**:
that a non-authoring agent cannot merge `main` into someone else's branch without asserting
trailer values it cannot witness (`Credential-Mode: dedicated-agent`, `Human-Review: explicit`).

It can, today, unchanged. `findAllSignatureBlocks` keeps paragraphs carrying all ten required
keys; `detectBlockDisagreement` returns `null` below two blocks. So **a blockless merge commit
contributes zero blocks and therefore zero disagreement**, and git's default
`Merge branch 'main' into X` message asserts nothing and passes.

| preimage | blocks | verdict |
|---|---|---|
| branch block + blockless merge | 1 | **PASS** |
| branch block + differing merge block | 2 | `block-disagreement` |
| only a blockless merge | 0 | FAIL (no trailers at all) |

**Silence is not a false claim.** The problem was that this honest path was **accidental** —
nothing asserted it. A future tightening ("every commit must be signed") would have silently
deleted the only honest maintenance route and re-created the blockage for real, leaving a
maintainer to choose between lying in a trailer and leaving PRs stuck.

**No semantic change to the validator.** Three files:

1. **`.claude/rules/maintenance-commit-on-another-agents-branch-carries-no-block.md`** — the
   carved sentence, where a maintaining agent reads it at cold start. A maintenance commit
   that *does* decide content (resolving a conflict, fixing a lint) is authored work and is
   signed **as itself** with honest values; if that honest block then disagrees on a
   governance key, **the disagreement is true** and the PR goes back to its owner — the
   mechanism working, not failing. `heartbeatMergePrBody` is the worked example: it infers
   `Credential-Mode` from the live credential and degrades to `unknown` rather than asserting
   a convenient value.

2. **`agencysignature-block.test.ts` §MAINTENANCE COMMITS** — six falsifiers. The load-bearing
   ones assert a blockless commit contributes no block and no disagreement, and that
   branch-block + blockless-merge is one block and PASSES (checked against both the CI
   reconstruction's `\n` join and GitHub's `---------` composition, in both commit orders). A
   guard on the guard asserts silence is legal **alongside** authorship and never **instead**
   of it: an all-blockless proposal is still refused. Mutation-checked — dropping the
   completeness condition in `findAllSignatureBlocks` turns the load-bearing test red.

   One test is written as an **honest admission, not a guard**: two identical blocks PASS,
   because **the parser cannot distinguish a copied attestation from an earned one** — a copy
   is byte-identical to the original. No test here can ever catch it. Only the rule stops it,
   which is exactly why the rule has to live where an agent reads it rather than in a check
   that reads bytes. The test comment says so, so nobody reads the pass as a licence.

3. **The `block-disagreement` diagnostic** in `validate-agencysignature-pr-body.ts` now tells
   a non-authoring maintainer what to do. It previously stopped at *"make the blocks agree, or
   leave ONE block"* — which, read by a maintainer, is an instruction to copy the branch's
   block or overwrite their own honest values. Both available "fixes" were the dishonest ones.

## What is deliberately NOT done

Nothing is weakened to unblock throughput. `agencysignature (PR body)` already passes on 8 of
the 9 supposedly-blocked PRs — they are stuck on ordinary red CI. The one real failure
(#12035) has `Credential-Mode: delegated` and a free-text `Task:` in its own commit, is
fixable only by its author, and **should** stay blocked.

`agencysignature-block.ts` is untouched except for nothing at all — another agent is
concurrently working on `Human-Review` verification there and in
`agencysignature-enforcement.yml`, so this PR stays in the test file, one diagnostic string,
and the new rule.
