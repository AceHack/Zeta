## Description

feat(ci): the completeness gate for build-graph job selection -- and it found the Lean and TLA+ proofs were unselectable

Option 1 taken on round-3 evidence: wire the graph first. Reversible; attacks the
94% provisioning waste and the 82% of real gate failures directly; forecloses no
later split. This ships the ACCEPTANCE GATE and the run-time selector. It does NOT
flip the `if:` guards, and it saves no provisioning yet -- saying otherwise would
be the "looks like progress and banks little" failure round 3 named.

THE COMPLETENESS-LINT RESULT, REPORTED PLAINLY: 58 FINDINGS ON FIRST RUN.
A=38 targets with no leg, B=2 dangling legs, C=18 unclaimed jobs. All live on main.

THE ONE THAT MATTERS MOST -- direction B. `lean-proof/build` and
`tlaps-proof/tlaps` named jobs THAT DO NOT EXIST; the real job ids are
`lean-proof/type-check` and `tlaps-proof/prove`. A wired graph would have skipped
the Lean proof and the TLA+ proof ENTIRELY, on every change, while direction A
counted both targets as covered. A dangling selector can never fire, and a job
that should have run and did not is indistinguishable from one that passed. This
is exactly the unsoundness the acceptance condition existed to catch, and it was
already sitting in the tree.

DIRECTION A WAS WRONG IN THE FLATTERING DIRECTION. 35 Rust crates carried
`legs: []` under a comment claiming that "states that coverage gap honestly." It
did the opposite -- it UNDER-reported real coverage: `gate/lint-rust` runs
`lint-rust.ts`, which walks `findCargoTomls(SRC_DIR)` and runs `cargo fmt --check`
plus `cargo clippy --all-targets -- -D warnings` on EVERY crate. Corrected, with
the evidence in the derivation's own comment. MEASURED CONSEQUENCE: a change to a
Rust crate previously selected NO leg at all; it now selects `gate/lint-rust`.

DIRECTION C found `gate/lint-fsharp`, `gate/lint-csharp` and `gate/lint-rust`
claimed by nobody. Both format lints run `dotnet format ... Zeta.sln` -- the whole
solution, not the language in their name -- so every dotnet target claims them.
The whole-repo hygiene legs got pseudo-targets on the pattern the graph already
used for `leg:markdown` / `leg:shell`.

AFTER THE CORRECTIONS: 0 findings, 115 targets, 32 jobs, 4 workflows. And the
audit then caught its OWN newly-added gate job as unclaimed, which is the best
evidence available that it can fail.

THREE GENUINE GAPS, ROSTERED AS GAPS RATHER THAN LAUNDERED AS COVERAGE.
`unit:agda`, `tool:alloy`, `lean:src/Core.Lean4.Cslib` have zero CI (CHECKED:
grep over .github/workflows/). The soundness obligation moves to the selector: a
change touching an uncovered target must force FULL mode, never selective. "We do
not know what checks this" resolves to "run everything" -- which is what keeps the
exemption from being the vacuity class rather than a cure for it. Both rosters
(INFRASTRUCTURE_JOBS, UNCOVERED_TARGETS) are checked for rot in BOTH directions,
so an entry cannot outlive its job, and cannot shadow coverage that later appears.

THE ANSWER TO "WHAT STOPS IT BEING UNWIRED A SECOND TIME" IS BUILT IN, NOT
PROMISED. `ci/affected-legs.ts` derives the change->job mapping FROM THE GRAPH AT
RUN TIME and emits one explicit boolean per leg. No leg name is written into
gate.yml as a condition. Twenty hand-maintained `if:` guards would be a second
copy of build-graph.json in a format nobody can diff against the first, and its
drift is silent -- that is precisely how this graph got built, tested, anchored to
Bazel and Nixpkgs, and left with zero workflow references.

The selector is FAIL-SAFE IN THE DIRECTION THAT COSTS MINUTES, NOT COVERAGE: any
error emits mode=full; full mode sets every leg true; every leg is always emitted
explicitly, because an absent output is indistinguishable from `false` to an `if:`
expression and absence is how a typo becomes a silent skip. It can only ever ADD
work relative to a full run.

OBSERVE-ONLY, DELIBERATELY. Nothing consumes the outputs. The derivation is
published and compared against what the gate actually ran, so it is checked
against reality before any `if:` depends on it. Trusting an unproven selector is
the same class of mistake as trusting an incomplete graph. Exit criteria for the
flip are in the work item, including the piece that actually captures the 94% --
per-leg toolchain subsets in tools/setup/, without which guards reduce job COUNT
and not per-job provisioning.

THE §1 GUARD, LANDED AS A FALSIFIER RATHER THAN PROSE.
`hygiene/lint-clone-at-tag-is-sufficient.ts` + `.claude/rules/
clone-at-tag-stays-sufficient.md`: `git clone` at a pinned tag must stay
SUFFICIENT forever, never "until ace ships". The ADR's word is "replaced by
`ace pull forge@<version>`", and replaced is the word that costs. The lint refuses
`ace` as a RESOLVER in any bootstrap surface while leaving using, testing and
publishing it untouched -- the discriminator is exit, not degree. Its honest limit
is stated in the file: the real falsifier is "clone at a tag with no ace on PATH
and build", which cannot run until a second repo exists; this is the reachable
proxy and the file is where the real test replaces it. 22 tests, including that it
fires on the ADR's own successor sentence and stays silent on
`bun test src/Core.TypeScript/ace/`.

THE NEW GATE JOB IS BUN-ONLY ON PURPOSE -- `setup-bun`, not `install.sh`. It needs
one 178 MB runtime; the union is 11.5 GB. It is the first job added to this repo

## FOLLOW-UP FIX (2026-08-19): a regression I introduced, and it was not the stale-test case

`cross-verify` went red. Diagnosed rather than assumed: **not** a stale
expectation -- a **real regression**, and wider than the one failing assertion.

`leg:tree-structure` was added with `sources: ["**"]` because `lint-no-empty-dirs`
and `lint-structural-hygiene` genuinely are whole-tree properties. But quorum
evidence attaches to the **finest target covering a file**, and a universal glob
makes a leg a covering target for *every* file -- so it absorbed byte-lock /
golden-vector evidence, went **T3**, and (being affected by every change) set the
quorum for every change.

**MEASURED, branch vs `origin/main`:**

| change | main | before fix | after fix |
|---|---|---|---|
| `README.md` | T1 / 2 | **T3 / 4** | T1 / 2 |
| `docs/research/*.md` | T1 / 2 | **T3 / 4** | T1 / 2 |
| `memory/*.md` | T1 / 2 | **T3 / 4** | T1 / 2 |
| `samples/CrmSample/Program.fs` | T1 / 2 | **T3 / 4** | T1 / 2 |
| `.../golden-vectors-merkle.json` | T3 / 4 | T3 / 4 | T3 / 4 |

Every change in the repo would have demanded the Byzantine quorum -- not a
stricter gate but a broken one, since over-review is ignored review and the
byte-lock tier stops meaning anything once a README edit shares it.

**Fixed at the derivation, not the expectation** (§10.1 applied to its own
author): `finestTargetsCovering` now skips `kind: "leg"` targets outright. The
doctrine was already written in that function's own comment -- *"a lint leg is not
the artifact a byte-lock protects"* -- but enforced only *indirectly*, via
`globSpecificity` losing to a path-scoped target. That holds while every leg is
extension-scoped and collapses the moment one is universal. Now total, which is
what the comment always meant. `ts:repo` is not a leg and keeps inheriting T3, so
no pre-existing tier moves.

**Given up, stated not hidden:** an evidence file covered by no non-leg target now
has its evidence dropped rather than landing on a leg. A real gap in the target
set, deserving its own report -- not a repo-wide quorum promotion. Filed open.

**Why the new completeness gate did not catch it.** It checks target/leg/job
coverage and says nothing about quorum blast radius. The catch came from a
pre-existing *single-path* assertion, and only because that path's extension
happened to fall in the new leg's glob set. So the sample is generalised into the
property it was reaching for -- `BLAST RADIUS: an ordinary change never demands
the Byzantine quorum`, five paths plus a non-vacuity check. **Mutation-checked:**
delete the one-line fix, re-derive, and both that test and the original sample
fail; restore and 84 pass.

**And it is this PR's own thesis happening to its author** -- a local graph edit
with a non-local consequence nobody held in their head, in the same session that
argued nobody can. What caught it was the externalized artifact plus a test that
reads it.

708 tests pass across 38 files. Completeness audit, clone-at-tag guard, and the
graph's `derive` drift-check all rc=0. tsc and actionlint clean.
