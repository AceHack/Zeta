## Description

Aaron, 2026-08-19: **"we are moving away from anything that blocks into drift checks instead."**

This is the macOS half of the sentence he started earlier the same day ("windows and mac are drift checks, it's fine to check per pr if we want but we don't want to block on them"). The Windows half landed in #12354; this closes work item `081M0CPEH40087G0R0016GDSB6`, which had already specified the mechanism and the one-line change.

## The change

One line of behaviour, in `.github/workflows/gate.yml`:

```yaml
continue-on-error: ${{ startsWith(matrix.os, 'windows-') || startsWith(matrix.os, 'macos-') }}
```

**No second mechanism was invented.** `gate-scope-summary.ts` (PR #12252) derives "non-blocking failure" from *(API conclusion = `failure`)* AND *(this need's rollup result = `success`)*. It knows no platform names and needed **zero edits** to cover macOS. That it was already generic is the evidence it was built as a mechanism rather than a Windows patch.

`macos-26` was never an independently required check. Verified live — `gh api repos/Lucent-Financial-Group/Zeta/rules/branches/main` returns exactly one required context, `gate (required)`. macOS blocked *transitively*, as a leg of `build-and-test` carrying no `continue-on-error`. It now does not block at all. The `needs:` list of `gate (required)` is untouched; what narrowed is the **platform coverage inside the matrix** — so `registry/uncompensatable-floor.yaml`'s `scoped-build-test-break` entry now states in data that only `ubuntu-24.04` and `ubuntu-24.04-arm` can block.

## The cost, stated rather than implied

Unlike Windows — whose legs do not run on `pull_request` at all, so the flip changed nothing about merging — **macOS runs pre-merge, so a macOS-only break can now land.**

Concretely: run `32138908732` (2026-08-18) had `macos-26` as the only failed leg and `gate (required)` concluded `failure`. Under this PR that is a green gate carrying a **named** non-blocking failure, and the break is on main.

## How a real macOS regression still surfaces (the vacuity guard)

A check that stops constraining anything in the course of being made non-blocking is the exact failure mode to avoid. Four surfaces, in the order a human meets them:

**0. The leg's own check run still concludes `failure`** — a red X in the PR's checks list, sitting beside a green `gate (required)`. **Verified against the live API rather than assumed:** `GET /commits/54492c95ec2e6e31105d698c7ef68d5884daaf38/check-runs` reports `build-and-test (windows-2025)` `conclusion=failure` for run `31978270082`, while the same commit's `gate (required)` is `success`. A `continue-on-error` job is *not* reported as `skipped` or `neutral`. **This is the surface that makes the macOS flip safe, and macOS gets it in a way Windows never did — because macOS runs where humans are already looking.**

**1. `gate (required)` names it.** A `**FAILED (non-blocking)**` row in the step-summary table, a `::warning title=non-blocking failure::` annotation on the check run, and the machine-readable `nonblocking-failures` job output.

**2. `drift-sweep.yml`'s BD001 detector** files a failed `build-and-test` leg on main into `docs/drift-events/` post-merge. (Keyed to `Zeta.sln`, so *which* leg is lost, and it reads one run, so it measures a level not a rate.)

**3. `platform-drift-report.ts`** → `data/platform-drift.json` → `data/monitor.html`: per-leg failure rate, clean streak, coverage. It will reclassify `macos-26` from `blocking` to `non-blocking` the first time it fails beside a green rollup — that classification is **observed**, never read off the flag, so the ledger will *disagree* with the workflow until evidence arrives. That is correct and deliberate; do not "fix" the ledger either.

### Why macOS stays per-PR instead of moving to push-only

Push-only was the cheaper option and it is **declined on a measurement**: surfaces 2 and 3 both query `branch=main&event=push`, and **418 of the last 500 completed push runs were cancelled by the concurrency group before a single leg executed — 16.4% coverage.** Push-only would have cut macOS observation by ~84% to save minutes the leg was already spending. Surface 0 only exists per-PR.

**Cost of this PR in runner minutes: zero.** macOS already ran on every PR; nothing was added, one flag flipped.

## Guarded against silent re-drift

Three tests in `src/Core.TypeScript/ci/gate-scope-summary.test.ts`:

1. **The classification is pinned.** Parses the `continue-on-error:` expression, asserts the drift-check prefix set is exactly `["macos-", "windows-"]`, and asserts *every* OS the `matrix-setup` job can emit is classified — so adding a leg without deciding its class fails there rather than at a merge that should not have landed. The parser refuses any expression shape it cannot read, because a parser that shrugged would report "no drift checks" and pass.
2. **A failed `macos-26` leg is NAMED**, derived from the captured Windows fixture with `macos-26`'s conclusion flipped, rather than from an invented run.
3. **The converse**, so (2) cannot pass by naming everything: if `build-and-test`'s rollup is `failure`, `macos-26` is reported as a block, not as drift.

**Mutation-checked before landing** (a test that survives mutation is not a falsifier):

| mutation | result |
| --- | --- |
| revert the flag to `windows-` only | test 1 fails — `["windows-"]` != `["macos-","windows-"]` |
| stub `nonBlockingFailure: false` | test 2 fails, plus 2 pre-existing tests |
