## Description

## A marker-gated oneshot cannot re-converge, and repair IS re-convergence

The first workitem of the pre-k8s recovery plane (`081M0BTFK85087G0R000A705AK`),
reported in [`reaching a dark node`](docs/research/2026-08-18-reaching-a-dark-node-the-recovery-planes-missing-half-rendezvous-container-seam-and-the-bootstrap-paradox.md)
§1.0 and proposed there as open question 5.

### Verified before changing anything

Measured on `origin/main` @ `8455c16337`:

| claim | verdict | evidence |
|---|---|---|
| every `zeta-*` unit is `Type=oneshot` except the agent | **confirmed** | `zeta-creds-restore`, `zeta-self-register`, `zeta-self-register-ci`, `k3s-join-observer`, `nvidia-open-driver-bound-check` oneshot; `zeta-ai-agent` `simple` |
| `zeta-self-register` is marker-gated | **confirmed** | `ConditionPathExists = [ "!${cfg.markerPath}" … ]` **and** `[ -f "$MARKER" ] && exit 0` in the script — belt *and* braces on the same defect |
| no other re-convergence path exists | **confirmed** | `systemd.timers` appears **nowhere** under `full-ai-cluster/nixos/`. `Restart=on-failure` only retries within one activation, and the script `exit 0`s (not non-zero) on its commonest failure, so even that never fires |

**Worse than reported.** The marker was written at **PR-open** time, carrying the
PR URL — so the gate closed on an *attempt*. A node whose registration PR was
closed unmerged is recorded "done" forever, having never registered at all.

**And the fix was already in the file.** The script already contained the correct
convergence check (`gh api …/contents/<node.yaml>` → "already registered on
main"). It was simply unreachable once the marker existed: a working
level-triggered test gated behind a stale assertion about the past.

### What changes

The marker becomes a **receipt**, never a gate. Each activation asks the level
question — *is the desired state present?* — and acts only on divergence, so
apply-N ≡ apply-once by construction (§12). A `zeta-self-register.timer` supplies
recurrence; the service keeps its boot activation, so **first-boot enrolment
timing is unchanged**.

`zeta-self-register-ci` keeps its marker gate deliberately: a hermetic one-shot
compose proof in a throwaway VM is allowed to be once.

### The failure mode this introduces, and its three bounds

A converger on a timer is a self-inflicted load source, and a fleet retrying hard
through an outage is a thundering herd.

1. **Read cadence** — 6h `OnUnitActiveSec`, 30min `RandomizedDelaySec`. ~4
   read-only calls/node/day, de-phased; 100 nodes ≈ 400/day against a 5000/hr limit.
2. **In-boot retry** — `RestartSec=30s` kept for "gh auth arrives a beat late",
   now capped at `startLimitBurst=5` per `startLimitIntervalSec=600`. Safe
   precisely because the 6h timer outlives the window.
3. **Write side (the sharp one)** — at most **one open registration PR per host**
   at a time, and at most one PR-creation *attempt* per 24h. A pathological
   once-a-minute run cannot open a second PR.

None is a give-up: all expire, so the node always re-converges. `Persistent` is
omitted from the timer on purpose — replaying a missed window is edge-triggered
thinking, and it is how a fleet that was dark during an outage herds on return.

Also hardened, because the timer makes it reachable: **a failed check is not a
negative result.** The probes now separate "definitely absent" (HTTP 404) from
"could not tell" (network / 5xx / auth revoked) and refuse to act on the second.

The installer-substrate audit previously asserted the marker gate as **CORRECT** —
it pinned the defect in place. It now asserts the convergence shape, and gains a
`mustNotContain` because *"this unit must not be gated on a local marker"* is only
expressible negatively.

### A second defect, found in self-review after the first push

The in-flight-PR matcher — the anti-storm invariant this design leans on — was
written against `gh --json`'s **compact** output (`"headRefName":"x"`). `gh` emits
compact only to a pipe; on a **TTY it pretty-prints** (`"headRefName": "x"`),
which is the operator-runs-it-by-hand case. There the matcher found nothing,
concluded no PR was in flight, and would have opened a **duplicate**. A bound that
silently stops binding in the one case a human is watching is worse than no bound,
because it reads as working.

Two layers were wrong, and the new test caught the second only after the first was
fixed: (1) whitespace around the colons, and (2) the per-object split is
line-based while the pretty form spans several lines per object, so the branch
name and its number landed on different lines. Both fixed; both witnessed by a
test that fails on the previous matcher. Found by reading the code, not by a
failing test — which is exactly why it now has one.

### Evaluated by NixOS, and exactly how far that goes

Corrected after watching CI — an earlier draft said `nix-instantiate --parse`,
which **understated** it. `build-ai-cluster-iso` went green on this branch and
runs `nix flake check --no-build --show-trace` over `full-ai-cluster/`, which
**evaluates** the `nixosConfigurations`; those import `common.nix`, which imports
this module. So the option types, the `systemd.timers.zeta-self-register` block,
and `startLimitIntervalSec` / `startLimitBurst` are validated by the real NixOS
module system, not merely parsed. The installer ISO also built, so the module
survives into a system closure.

### NOT checked — no node ever STARTED this unit

The correction above must not be read as more than it is. The same job runs NixOS
VM tests, and it would be easy — and wrong — to let their green tick imply this
unit was exercised. **It was not:** the tests in `full-ai-cluster/nixos/tests/`
import `k3s-server.nix`, `k3s-agent.nix` and `k3s-join-observer.nix`, and **do
not import `common.nix`**, so no VM ever brings up `zeta-self-register`. Checked
rather than assumed.

Evaluation proves the unit is well-formed; it proves nothing about behaviour.
Timer elapse, jitter, the `startLimitIntervalSec` interaction with timer-driven
starts, `StateDirectory` ownership of the receipt, and ordering against
`zeta-creds-restore` are **reviewed, not executed**. The stubs encode what we
believe `gh --json` returns; a shape change would break a node and not these
tests. First convergence on real hardware remains unobserved.
