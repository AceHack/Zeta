## The shape worth noting: this is the second instance today

markdownlint is *"scoped to the PR's own diff on `pull_request`"* but lints the **full tree** on `main`. So a violation in a file the PR didn't touch surfaces only **after** merge.

That's the same class as the build matrix:

```
PR:    macos-26 · ubuntu-24.04-arm · ubuntu-24.04
main:  …the same, plus windows-2025 and windows-11-arm
```

**In both cases the pre-merge check is narrower than the post-merge check**, so a whole class of failure is undetectable until it's already on `main`. That's how the QA-ANTI-1 Windows failure got in, and how this did.

Recording it in the commit rather than filing separately — the fix is one line and the observation is the useful part.
