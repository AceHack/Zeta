## Description

Generation 1 of the N-version protocol — the first run *designed* from the blueprint rather than improvised. Three F# derivations of one clean-room spec, isolated worktrees, none having seen the others.

## The headline: three correct implementations that cannot verify each other

All three independently found that **the spec never fixes the canonical signed bytes** — then diverged along **three independent axes**:

| | domain tag | length prefix | payload length |
|---|---|---|---|
| **A** | `"zeta.threshold-signature.v1"` | 4-byte **little**-endian | **prefixed** |
| **B** | `"zeta.threshold-sig.v1"` | **big**-endian | — |
| **C** | **none** | 4-byte **big**-endian | **trailing** |

That defect is mine — *"over the request's scope and payload"* reads as a complete requirement and isn't one.

### Two things only N=3 could surface

**C omits domain separation and is fully compliant.** It reasoned only about *injectivity* — the only property the spec's rationale argues for — and length-prefixing alone achieves it. So C is correct against the text and materially weaker in practice. **A ∥ B alone would have shown two tagged encodings differing by a string and looked settled. The absent third opinion was the informative one.**

**A prefixes the payload length; C leaves it trailing — and both are right.**

## Co-discovered, therefore real

A and C independently found: the encoding gap · the window boundary (**diverges at exactly one epoch, silently, mid-cutover**) · R9's incomplete input list · R8's bound not guaranteeing satisfiability.

## Two serious single-derivation finds

- **A: the title names a different object than the requirements.** "Threshold signature" is the Desmedt–Frankel aggregated-single-signature construction; R3/R4/AC3 only make sense for **k-of-n multi-signature**. All three built multi-signature because the requirements forced it — so the spec is internally coherent and **externally misnamed**, and a cryptographer reading only the title builds the wrong primitive.
- **C: R7's migration window is unenforceable.** The epoch is necessarily caller-supplied and **unsigned**, so a retired-scheme signature replays by asserting an in-window epoch. A saw the same gap and treated it as *completeness*; C treated it as *security*. **That severity divergence is itself a finding.**

## Nobody rounded up

A declared R8/R9/AC7 `partial`; C declared R7/R9/AC5 `partial` — **each partial exactly where the other was implemented.** Compare generation 0, where one derivation claimed twelve of twelve and four claims didn't survive execution. **The A5 amendment worked.**

## B: code survived, analysis didn't

B wedged before pushing. Its worktree was clean with 3 commits, pushed unchanged — so its implementation survived and supplied the third encoding, but its ambiguity list is lost. The incremental-report rule **half** worked: B wrote the skeleton first, which is how we know what's missing. **Generation-2: append each ambiguity when resolved — a skeleton proves intent and preserves nothing.**

Also: **worktree isolation isolates the filesystem, not the CPU.** Three concurrent Release builds pushed load past 28 and dominated wall-clock.
