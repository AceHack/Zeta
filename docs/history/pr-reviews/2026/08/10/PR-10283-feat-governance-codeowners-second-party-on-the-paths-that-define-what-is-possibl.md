## Scoped deliberately narrow

The argument isn't "important files need review." It's that **a DU or a workflow defines the set of actions that exist** — injecting an action is the attack, and widening the action space is the same attack one level up.

Covered: CI workflows · the DUs enumerating what can happen · the consent gate and its bypass · `.claude/rules/` · governance.

**Not** covered: ordinary implementation, docs, research, workitems. A second party there would grind the autonomous loop to a halt for no security gain — and a control that makes normal work painful is one people route around.

**CODEOWNERS owns itself.** A control the constrained party can edit away isn't a control.

## The limit, stated in the file

This trusts **GitHub** as the authority on who consented. GitHub can be compelled, can be wrong, and is a hub — precisely the shape the substrate refuses everywhere else. Hence: first half, not the answer.

## Needs one human step

**CODEOWNERS alone does nothing.** It takes effect only with **"Require review from Code Owners"** enabled in branch protection — `main` currently has `required_approving_review_count: none`. That's a repository-settings change and isn't mine to make.
