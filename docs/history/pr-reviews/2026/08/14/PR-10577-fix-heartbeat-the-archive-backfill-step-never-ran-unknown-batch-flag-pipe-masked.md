## Description

## The defect

soraya's **"Archive PR review history"** step in `agent-heartbeat.yml` has been a complete no-op since it shipped, while reporting **success on every tick**. Three independent defects, each sufficient on its own:

1. **`--batch` is not a flag the tool accepts.** `archive-pr-reviews.ts`'s parser falls through to `unknown arg: --batch` + `process.exit(1)` before doing any work. Live proof: run `31800609010`, soraya tick — that single line was the step's entire output.
2. **The exit code was masked twice.** A pipeline's status is the last command's, so `... 2>&1 | tail -10` turned `1` into `0` — which in turn made the trailing `|| echo "::warning::"` **unreachable**. Verified: `bash -c 'false 2>&1 | tail -10 || echo FALLBACK; echo $?'` prints no `FALLBACK` and `0`.
3. **`--since 7d` matched zero PRs anyway.** The filter is `p.mergedAt >= since`, a *lexicographic* compare against ISO timestamps, and `"2026-08-14T..." >= "7d"` is `false`. **Fixing only (1) and (2) would have produced a step that exits 0, looks healthy, and still archives nothing.** The invocation also passed neither a PR number nor `--all-merged`, which is itself a `return 1`.

### A retraction

A comment added 2026-08-11 asserted `--since 7d` on this step was *"working"* and warned readers off "fixing" it. That was wrong — it conflated this tool's `--since` with the mutation-runner's git-approxidate `--since`. Retracted in place. A comment written to prevent a bad fix ended up vouching for a broken flag.

## Honest calibration — what it actually cost

`pr-archive-on-merge.yml` archives each PR at merge time, so this step is a **backfill net**, not the primary path. Measured, not guessed:

- Archiving has a **1282-PR-number hole between PR 9058 (2026-07-01) and PR 10341 (2026-08-13)**.
- **1273 of the newest 3000 merged PRs have no shard** (1252 inside that window).
- Coverage by day is **0% for 2026-07-04..2026-08-12**, returning to **100% on 2026-08-13** when the per-merge path resumed.

**This is not data loss.** GitHub still holds those review threads. What was lost is the *git-canonical mirror* the repo keeps precisely because the host copy isn't durable — plus six weeks of a safety net reporting green while dead. The backfill would have drained the hole; it never ran once.

## The fix

- **`--limit N`** — a real bounded sweep, because none existed. `--all-merged` is a boolean, so the alternative was sweeping ~415 PRs/7d inside a 30-minute tick.
- **`--all-merged` now skips PRs that already have a shard and takes the OLDEST N of what remains.** This is the load-bearing choice: a bounded sweep without the already-archived filter re-picks the same head every tick and the backlog never drains. Oldest-first over a shrinking queue guarantees every PR's position strictly decreases. The unbounded-queue + newest-first + small-cap starvation shape is deliberately **not** recreated.
- **`normalizeSince()`** parses `Nd`/`Nh` into a real cutoff and **rejects garbage loudly** instead of degrading to a silent zero-match.
- **Workflow**: no pipe on the command, explicit `ARCHIVE_RC` check, real `::warning::` on failure. `errexit` intentionally left off — the rest of the step is written for a non-errexit shell (`|| true`), so enabling it would change behaviour well beyond this fix.

**`archive-pr-reviews.test.ts`** runs the **real parser** on the **real argv** extracted from the workflow YAML (appending `--help` so it exits before any `gh` call), pins that the historical `--batch` argv **still exits 1** (so the probe can't silently stop discriminating), and fails if the step ever pipes the exit status away again.
