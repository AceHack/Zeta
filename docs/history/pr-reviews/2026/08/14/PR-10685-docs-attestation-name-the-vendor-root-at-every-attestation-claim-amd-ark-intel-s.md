## Description

Implements work-item `081M00QP7FB087G0R00031BQ93`, from PR #10674 §5.1. The finding, previously unnamed anywhere in the repo:

> **Every attestation Zeta could ever offer terminates in a silicon vendor's self-signed key.**

**This is a cap, not a refutation.** Vendor-rooted attestation is enormously stronger than no attestation and is what every serious system in the world uses. The point is that the claim be *accurate*, not that it be abandoned. An inflated denial would be as wrong as an inflated claim.

## Verified rather than restated

Re-checking the parent's summary against vendor documentation **corrected it in one place**: NRAS / KDS / PCS are certificate **distribution and verification services**, and all four ecosystems support offline verification. The *service* is avoidable; the *root* is not. That distinction is now load-bearing in both the docs and the lint.

Roots (CHECKED 2026-08-14):

| | Trust root (irreducible) | Verification service (avoidable) |
|---|---|---|
| AMD SEV-SNP | **ARK**, self-signed; ARK→ASK→VCEK | KDS; deterministic VCEK derivation ⇒ certs cache, verify offline |
| Intel TDX | **Intel SGX Root CA**; PCK rooted in CPU fuses | PCS; PCCS caches collateral |
| NVIDIA | **device-identity CA** (per-GPU fuse key) | NRAS is *default*, local verification supported |
| TPM 2.0 | **manufacturer's EK root CA** | NV indices / manufacturer hosting |
| AWS Nitro | **`AWS_NitroEnclaves_Root-G1`** (30-yr AWS Private CA) | doc carries its own CA bundle; offline |

## Retracted — my own error

My first L3 edit said the node binding is *always* silicon-vendor-rooted. **Wrong.** SPIRE node attestation is plugin-dependent: `join_token` has no hardware root; `x509pop` roots in a CA we choose (**genuinely self-rooted**); only `tpm_devid` / `amd_sev_snp` / `aws_iid` are vendor-rooted. Corrected in the ladder and the 2026-05-31 doc. "Attested node" is a dial, not a guarantee.

## Anti-overcorrection, recorded

- **Multi-vendor diversity** is the one honest mitigation — an AMD root and an Intel root are not the same root; composes with existing decorrelation work.
- The cap is **not uniform**: Tillitis TKey *splits* integrity (self-rooted, CDI key-continuity, no vendor) from authenticity (vendor-rooted); WebAuthn's `none` conveyance is the **W3C L2 default**, making its vendor root a droppable credence booster rather than a gate.

## The lint, and proof it can fail

`src/Core.TypeScript/hygiene/audit-attestation-vendor-root.ts` flags docs naming a hardware-attestation mechanism but no trust root. Doc-scoped, because this repo uses "attest" in two senses and a line-level grep is ~90% false positives on the **social** sense (privacy budget). Excludes bare TPM / Secure Enclave mentions: **sealing is custody, not attestation**.

Generic phrases dropped; only a named root or an explicit `(root: …)` marker counts. Pinned as a regression test.
