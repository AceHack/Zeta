## Description

## What

Closes `081KZYRDMZW087G0R0012K4QA0`. **The flags a spec was MEASURED under and the flags CI CHECKED it under were silently different.** `QuorumPhaseCancellation` went red on #10452 with exit 11 not because a property broke but because the recorded runs were driven by a script passing `-deadlock` -- which *disables* deadlock checking -- while the gate passed no such flag. A hand-run green and a gated green were not the same result and nothing anywhere said so.

Adding `-config` was necessary and not sufficient; the next mismatch would have been a different flag. So the **whole invocation** is pinned.

## The shape

`registry/tlc-models.json` carries **53 model runs**, one per (module x config). Each fixes the config, the worker count, the expected exit code, the expected TLC error substring for negative runs, and -- for exhaustive runs only -- the distinct-state count. Both consumers build argv from that one file through `tlc-invocation.ts`, and neither may add a flag:

- `tests/Tests.FSharp/Formal/Tlc.Runner.Tests.fs` -- the CI gate
- `src/Core.TypeScript/formal-verification/run-tlc.ts` -- the hand-run CLI, with `--invocation <id>` printing the exact line to quote next to a result

## Did anything only pass under permissive flags

**No.** All 14 negative verdicts and every exhaustive green reproduce under the pin with the same property names. Two things moved and neither is a claim:

- Four halt-on-violation counts (234->149, 41004->41003, 54->42, 112->100) -- exploration order depends on worker count. The registry **records** these and **asserts** only exhaustive counts.
- `BftLiveness` costs **43min 02s** at the pinned `-workers 1` against the `11min 14s` its `.cfg` records from a 4-worker run. It is the one `extended`-tier model, with the reason written in. A declared gap, not a silent one.

Confirmation the exhaustive/halting split is real rather than cautious: `BftConsensus` explores **4,665,495** distinct states at one worker, byte-identical to the 4-worker figure in its `.cfg`.

**Nothing was relaxed to go green.** The one number that looked wrong -- `BftConsensus` reporting 122647 against a pinned 4665495 -- was a defect in my own parser, which matched a TLC *progress* line instead of the final summary. Fixed in both implementations with a regression test. The assertion caught it on its first real run, which is what a falsifier is for.

## Also closed

- **The related gap in the same file.** The TLA+ gate rests on one leg of the CI matrix; that leg now **fails** when java or the jar is missing instead of skipping silently.
- **Deadlock vacuity is in the artefact.** Every model records `deadlock` as `off-cfg` / `on-vacuous` / `on`. `QuorumCollateral` and `WagerSolvency` stutter, so their deadlock checks cannot fail and neither makes a deadlock-freedom claim -- that caveat now sits where the verdict sits, not only in prose. The linter cross-checks `off-cfg` against what the `.cfg` actually declares (and ignores commented mentions).
- **Drift is loud.** `src/Core.TypeScript/hygiene/lint-tlc-model-registry.ts`, gated by the existing `bun test src/Core.TypeScript/hygiene/` job, refuses a `.cfg` no model claims, a model whose files are gone, a violation-expecting model with no pinned error string, an `extended` tier with no reason, and a `tla2tools.jar` whose sha256 moved.

## Verdict on a `tlc-solver-floor` registry: no, and the cheaper answer is better

`registry/smt2-solver-floor.json` exists because z3 and cvc5 come from the runner `apt` -- their version is ambient and degrades silently, so a floor is the only lever. `tla2tools.jar` is **committed to git** (since #8053), so the toolchain is already byte-pinned by the diff. What was missing was not a floor but the assertion that the jar loaded is the pinned one. The registry carries its sha256 and version banner and the gate checks the banner on every run. One field, not a second registry.

**Found while pinning, and it is a real defect worth its own item:** `tools/setup/manifests/from-url` downloads `tla2tools.jar` into `tools/tla/tla2tools.jar` -- a path no runner reads -- with no checksum. The jar the gate loads reports `TLC2 Version 2026.05.18.174321 (rev: 8ba1027)`, which is not the `v1.8.0` that `docs/dependency-status.md` and `docs/INSTALLED.md` claim.

## The bun 5s cap

Not exposed. Reproduced the cap here (`bunfig.toml` `timeout = 20000` is ignored; a 6s test dies at 5002ms, bun 1.3.14) confirming `081KZZ3JHP1087G0R00027ARRR`. The gate runs TLC under `dotnet test` with no bun involved, and the bun-side TLC tests only invoke metadata commands. A comment in `run-tlc.test.ts` names the hazard so nobody later adds a real model check there and reads a 5s truncation as a failed proof.
