## Description

`Deploy to GitHub Pages` has been **failing on main** since #10488 landed.

```
src/lib/passkeyProposal.ts(50,43): error TS2315: Type 'Uint8Array' is not generic
src/lib/passkeyProposal.ts(94,38): error TS18046: 'byte' is of type 'unknown'
error: script "pages:build" exited with code 1
```

## Root cause: version skew, not a code error

| package | TypeScript |
|---|---|
| repo root | **6.0.3** |
| `demo/identity-dla-site` | **5.6.3** |

`Uint8Array<ArrayBuffer>` requires **TS ≥ 5.7**. So a file written and checked against the root toolchain fails in the subpackage that carries its own older one.

## The fix

Drops the three generic annotations. Bare `Uint8Array` is valid under **both** versions and runtime behaviour is identical — the type argument was documentation, not a constraint. The `'byte' is of type 'unknown'` error was **downstream** of the generic failure and resolves with it.

**Verified by running the exact failing command with the site's own toolchain:** `bun x pnpm@10.4.1 check` now exits clean.

## What this deliberately does not fix

Main is red; this unblocks it. The **skew remains**: a subpackage two minor versions behind the root will keep accepting code the root accepts and CI does not. The durable fix is either aligning the versions or type-checking the subpackage in the same lane that checks the root — not bundled here, since that's a dependency decision with wider blast radius.
