## Description

Closes `081KZZZGYBR087G0R00302Z2J6` — a §12 idempotency violation that **#10552 made more reachable**, filed honestly by the agent that introduced the reachability rather than absorbed.

## The defect

`ReceiverBlock.recovered` is the §12 duplicate guard, and it lives **on the block object**. Evicting an already-delivered block throws the guard away with it; a straggler then creates a fresh block with `recovered = false`, the [8,4,4] decoder solves it a second time, and `onData` fires again for the same four payloads. `onData` is the delivery surface, so any consumer that folds deliveries double-counts.

Pre-existing — the unbounded map hit it at reorder depth 128 too — and reachable at half that depth once #10552 bounded `recvBlocks` to 8 entries, because a bounded map necessarily evicts blocks the unbounded one remembered forever. **The same cost moved out of memory and onto the guard.** This is where it stops.

## The reproduction, before and after

The harness behind #10552's policy table lived only in a pull request, so its numbers were not re-derivable by anyone reading the file. It is committed now as `src/Core.TypeScript/discovery/udp-lossy-transport.reorder-sweep.ts`, and it reports `distinct` apart from `delivered` — because the defect hid inside a goodput total that read as a *good* number (1672 of 1600 sent).

| depth | before (delivered / distinct / dup) | after |
| --- | --- | --- |
| 32 | 1600 / 1600 / 0 | 1600 / 1600 / 0 |
| 64 | 1672 / 1560 / **112** (28 blocks) | 1600 / 1600 / **0** |

Across **144 seeded configurations** (8 seeds × 6 depths × loss {0, 5%, 15%}): zero duplicates after.

## Where the retention bound comes from — derived, and measured

`DELIVERED_BLOCK_CAP = 2 * RECV_BLOCK_WINDOW`. No fresh constant.

A retained block is eight payload references; a delivered-block identifier is one integer — so the two bounds answer different questions and must **not** be the same number. The factor of 2 is the precedent already in this file: `SUSPECT_SEQ_CAP = 2 * MAX_NACK_GAP` keeps a *wider* window of the *cheaper* item. And 2 is measured rather than chosen — over those 144 configurations:

| cap | duplicate payloads |
| --- | --- |
| `1 * RECV_BLOCK_WINDOW` (8) | **156** |
| `2 * RECV_BLOCK_WINDOW` (16) | 0 |
| `3 * RECV_BLOCK_WINDOW` (24) | 0 |

2× is where the measurement flattens, not a margin picked upward.

## Did an existing structure already answer it — checked, and no

- **`reportedMissing`** holds what is *missing*, and is emptied by the arrival that immediately precedes a delivery. It is the complement of what is wanted.
- **`expectedSeq`** can only say a packet is *older* than the retention window. That zero-new-state alternative was **implemented and measured** rather than argued away, and it does not work: it left the depth-64 column completely unchanged — 1672 / 1560 / 112, exactly the unfixed numbers — because the stragglers producing those duplicates are still *inside* `MAX_NACK_GAP`. **Age is not delivery.**

## The two hazards this file has already taught, re-answered

1. **Eviction order is where the behaviour is.** The guard evicts LEAST-RECENTLY-USED. Evicting by key would let a peer **park** it — `DELIVERED_BLOCK_CAP` deliveries at the top of the u32 range hold every slot, and every honest guard entry is evicted the instant it is created, restoring the defect for everyone but the attacker. `ULT-40` is the negative control, independent of `ULT-34`.
2. **`blockSeq` is redundant with `seq` yet trusted independently.** So the guard is keyed on the block index the encoder actually **derives** — `seq >> 3` — not on the `blockSeq` field. Keyed on `blockSeq` it would inherit a 4.29e9 peer-chosen key space bounded by nothing the receiver tracks (`081KZZZH24H087G0R002TXQA15`, open). Keyed on `seq >> 3` it lives in the key space `expectedSeq` / `reportedMissing` / `MAX_NACK_GAP` are already built on. `ULT-42` pins it.

## What is still true

The guard is a **window, not a promise**. A duplicate separated from its original by more than `DELIVERED_BLOCK_CAP` further deliveries is delivered twice — and `ULT-41` **asserts that second delivery** rather than hiding it. No bounded receiver can do better; §12 holds here over the receiver's declared memory, which is the only span it ever held over.

## Named side effect, not pocketed

Refusing a straggler for a delivered block also keeps a dead block out of the recovery window, so **distinct** delivery past the declared envelope improves (496 → 696 at depth 128). That is an eviction-policy gain, recorded on `081KZZZH7H4087G0R001HV0W40` whose cost table is updated in this PR. The cliff is **not** removed and per-peer state is still the real repair.
