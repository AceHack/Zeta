## Description


Closes 081M003VH9B087G0R002WXK2HD (PR #10564).

`audit-agencysignature-main-tip.ts` recognised an agent commit by an ALLOWLIST of
vendor co-author trailers — `Claude|Codex|Grok|Gemini|Kiro` plus five `noreply@`
domains. Anything else fell to `"no Co-authored-by signal; assuming
human-authored"`, was counted HUMAN-AUTHORED-EXEMPT, and the audit reported
success. So a commit trailed `Co-authored-by: the shadow <shadow@zeta.agents>`
was classified human-authored by the audit that exists to attribute agent work.

Measured on `origin/main`, last 300 commits, 2026-08-14:

    Claude Opus 5 / Codex / Kiro          audited
    github-actions[bot]           39      EXEMPT
    society[bot]                   9      EXEMPT (as author, no co-author)
    Dejan / Soraya / Otto / Shadow  8      EXEMPT

Extending the allowlist would have reproduced the defect: the next persona is
exempt by default, silently, until someone audits the auditor again. The default
is inverted instead.

WHAT COUNTS AS A POSITIVE HUMAN SIGNAL
--------------------------------------
A commit is exempt only on a positive identity match in the new
`agency-signature-identity-roster.json`, matched against `Co-authored-by` and
CLOSED: every co-author must be on a roster, so one unlisted identity kills the
exemption. Everything else is agent-or-unknown and must carry the trailer. Two
candidate signals were CHECKED against history and REJECTED:

- "no `Co-authored-by` at all" — this is the current fall-through, and it is
  dominated by non-humans. 7 of the last 300 commits carry none and are plainly
  agent squash-merges (#10368 "bound Ollama calls", #10410 "passkey gated-commit
  workflow", #10544, #10561), and 51 more are bot telemetry ticks.
- the git author/committer field — 155 of the last 300 commits are authored
  `Aaron Stainback <aaron_bond@yahoo.com>` and committed by `GitHub
  <noreply@github.com>`. That is GitHub's squash-merge attribution of AGENT pull
  requests to the merging human's account; trusting it would exempt the majority
  of main. The author field is never a human signal, and a test pins that.

`AceHack <578953+AceHack@users.noreply.github.com>` stays exempt, by name, in the
roster. The residual hole is stated in the file rather than papered over: a
commit an agent produced through a human's credential is attributed to that
human and will be exempted. The credential is the human-authorization boundary
here, so that is the intended reading, but it is an inference from the
credential and not evidence a human wrote the diff — which is why
HUMAN-ROSTER-EXEMPT is now its own counted bucket in every summary.

The asymmetry is the whole point: a stale roster produces a FALSE REGRESSION
(loud, one-line diff) instead of a FALSE EXEMPTION (silent, indefinite).

THE 39 BOT COMMITS — EXPLICIT, NAMED, COUNTED
----------------------------------------------
`github-actions[bot]` (both address spellings) and `society[bot]` are exempt as
MACHINE-LANE-EXEMPT, by name, with the reason recorded: their provenance is an
in-repo workflow file plus a run id, which is stronger than a self-asserted
trailer, and 4 of the cadence workflows already echo the trailer anyway. This is
an exemption BY RULE — a different thing from the accident it replaces, and it
is counted in the summary. A bot NOT on the roster (renovate, dependabot, a new
lane) is red on its first commit; there is a test for exactly that. The
exemption also cannot be bought: a `Co-authored-by: github-actions[bot]` bolted
onto an agent commit fails the closure check.

Agent-/Agency- RESOLVED
-----------------------
`Agency-Signature-Version` is CANONICAL — checked against the spec doc, the
pre-merge validator's REQUIRED_KEYS, the persona-cell ADR, `samples/`, and the
four cadence workflows that echo it. NO file in the repo emits
