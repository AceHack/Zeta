## Description

Fills the one open DoD item on **081KWPHRNFW** — with a correction to the premise. The pluggable slot was **not empty**; it held PKCS#11/TPM code whose software simulator was indistinguishable from the real adapters.

## Measured before changing anything (darwin-arm64)

| probe | result |
|---|---|
| `allowSimulatorFallback: true` + bad TPM path | returned the **TPM** adapter, not a simulator; `storeShare` threw. The try/catch could never fire — constructors were lazy. **The flag was inert.** |
| simulator vs TPM adapter | identical property sets `["kind","loadShare","storeShare"]`, identical `kind === "sealed-file"`. **No runtime discriminator.** Old FSA-7/FSA-9 asserted that sameness. |
| simulator artifact | sealed under a hardcoded source constant, wrote `alg: "AES-256-GCM"` — indistinguishable at rest from a real seal; any second instance recovered the secret. |

## What lands

**Seal tiers.** `sealTier` is the security-bearing discriminator; `kind` is demoted to storage shape and says so.

**The fake is unmistakable by four mechanisms, none of them documentation:** construction requires an explicit acknowledgement object; the tier shouts on the live object; tier + a fake-specific `alg` are written into the artifact so it stays identifiable at rest and in a git diff; and tiers must match exactly on load, so **a hardware adapter throws on a fake-sealed artifact** — silent substitution is caught at the next load even if nobody watched it being written.

**`no-silent-downgrade`:** `requireTier` is mandatory with no default; the factory returns that tier or throws. `allowSimulatorFallback` is deleted. Backends probe eagerly at construction. Labelled in-file as the *sealing-plane analogue* of the proposal invariant (which states it for the governance plane) — not quoted as the same rule.

**Two real defects fixed:** the TPM path interpolated into a shell string for `execSync` — a command-injection sink, and the route by which the old FSA-6 pointed `tpm2UnsealCmd` at `printf` and got a share labelled TPM-sealed; argv-only now. The PKCS#11 path **discarded the AAD**, and `CKM_AES_CBC_PAD` gives no integrity, so a token-sealed share's header — including `x` and the group public key — was freely editable; the header is now bound in-plaintext and verified. That is a binding **check, not a MAC**, stated as such; `CKM_AES_GCM` is filed open.

## What is NOT claimed

- **use-without-extract is not met on any tier** and cannot be behind this port — `loadShare` returns the scalar. Every adapter carries `usesWithoutExtract` typed as the **literal `false`**, so the claim cannot be made without a port change. The port change and its hardware prerequisite are filed as open items.
- **No hardware was exercised.** Mocks and the *absence* of hardware only.
- **Platform coverage:** `hardware-pkcs11` = macOS + Linux with a token. `hardware-tpm2` = **Linux only** — Apple Silicon has a Secure Enclave, not a TPM 2.0, so on Aaron's machine the only hardware tier is PKCS#11 with an external token. Secure Enclave is **not covered**, filed open.

## Tests

CI-safe lane comes **out** of the exclusion registry and into the gate: **16 tests, up from 8** — the previous registry entry itself named this separation as the fix. New hardware lane takes its place, with non-vacuity enforced *inside* it: opting in asserts hardware is attached, so opting in without it **fails rather than skips** (verified: `tpm2` → 2 failures, `pkcs11` → 2 failures, unrecognised lane → 1 failure).

Four mutations confirm the guards are falsifiers: tier-match → kills FSA-8; binding check → FSA-14; eager probe → FSA-9 + FSA-10; acknowledgement gate → FSA-6. Full persona-keys suite **279 pass / 0 fail**; `tsc` adds no errors.
