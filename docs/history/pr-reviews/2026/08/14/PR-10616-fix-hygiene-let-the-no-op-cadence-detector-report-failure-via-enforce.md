## Description

## Summary

`check-no-op-cadence-pattern.ts` already detected the standing-by / no-op-cadence failure and printed `WARNING:` lines, then returned 0 on every path. The exit code carried no information, and nothing in CI invoked it. That is work-item `081M0085XQT087G0R003W4KFS4` (#10595 filed the item; this PR implements it).

This lands option (2) from the item: opt-in `--enforce` so the check *can* fail, without promoting an uncalibrated heuristic to a required gate.

- `exitStatus(result, enforce)` is 1 only when `--enforce` AND (threshold or gap) detection. Advisory default stays 0.
- Closed parser: unknown flags exit 2. A typo of `--enforce` is not silent advisory.
- Planted-history tests: 5-of-7 short shards fail `--enforce`; a healthy 7-of-7 long-body window does not; advisory mode is 0 either way. Those tests are the falsifier — removing `enforce &&` or forcing `return 0` turns them red.
- Calibration, measured not asserted: May 2026 18:00Z sample over `docs/hygiene-history/ticks/` (the surface the heuristic actually reads). **30 windows, 23 fires, rate 0.767.** That is why `--enforce` is not added to `gate.yml` or branch protection.
- `docs/AUTONOMOUS-LOOP.md` Check 0a now points at `src/Core.TypeScript/hygiene/check-no-op-cadence-pattern.ts` (the `tools/hygiene/` path was deleted). The new test file runs in the existing hygiene unit-test job.

Work-item moved to `workitems/done/2026/08/`.
