## Description

## The question this PR exists to answer

**When one site's HSM dies, can a replacement share be provisioned WITHOUT reconstituting the secret anywhere?**

If not, a 2-of-3 across three houses has a hidden single point of failure at ceremony time and the geographic distribution is partly theatre. That had to be settled on **one** device before $1,300 more is spent on two.

**In our code, before this PR: no.** Not for lack of a construction in the literature — we had not implemented one. Evidence:

- `rg -i "reshar|share refresh|proactive secret|share renewal"` returns **zero** hits in the FROST modules.
- `frostKeygen` / `frostDkgKeygen` sample a **fresh** secret. Neither has a parameter accepting an existing one, so neither can re-split the group you already have — output is a **new `groupPublicKey`**, so every relying party re-pins (`frost-ca.pub` in every `TrustedUserCAKeys`, every cert's signing-CA fingerprint). At 20 sites that is a fleet-wide re-trust to replace one dead chip.
- `rotate.ts` / `rotate-cluster.ts` / `keyring-rotate-daemon.ts` rotate the **SSH CA keypair** under an overlap window. **None touches a FROST share.** `frost-ca-custody.ts` has no rotate path at all.
- Reassembling `f(0)` on one host — the move that creates the ceremony-time SPOF — is **not implemented anywhere**, and could not even be expressed, since no function accepts a known secret to split.

**After this PR: yes**, and the group public key is preserved byte-identically.

## How, and why nobody ever holds the secret

Each holder derives only its own additive term `u_i = λ_i·s_i`, splits **that** under a fresh polynomial, and new participants sum what they receive. `Σ u_i = secret`, but no party computes that sum.

The load-bearing check is **public**: `Σ_i C_i[0] == groupPublicKey`. An auditor holding **nothing secret** can verify a reshare targeted the original key — without the key ever being reassembled. A holder that used the wrong contributing set, substituted its own secret, or claimed two seats is caught by a verifier that holds only the public key.

## Honest limits — do not let the hardware inflate these

- **Still L1.** `reshareContribute` takes the share scalar, so it is in host RAM in the contributing process. No PKCS#11 mechanism computes `λ·s` over the ed25519 scalar field — the same reason no adapter reaches use-without-extract for signing. A $650 HSM buys **at-rest sealing between ceremonies**, not a ceremony that never exposes the scalar.
- **Subshare transport is confidential-or-bust and is NOT provided here.** Anyone collecting k subshares addressed to one recipient learns that recipient's share outright. A coordinator relaying them in the clear has re-created the SPOF while appearing to run a distributed ceremony. `runReshareInProcess` is named for the fact that it is one process; it is for tests, not for three houses.
- **Old shares must be destroyed, and code cannot do it.** Old and new shares lie on different polynomials over the same secret — a security property once the old set is gone, a liability while it exists. **RS-7 asserts the old set still signs after a reshare**, so nobody assumes resharing revokes anything.

## Human vs agent: a gate, not a type — confirmed, with a caveat

`FrostKeyShare` is `{x, secretShare}`. There is **no participant type in the crypto layer**, so that half of the framing is correct and needs no change.

The caveat is that **there was no gate binding either**: `requireBiometric` fires **once per ceremony** at the coordinator (`frost-ca-custody.ts:259`, `:357`), not once per share, and `loadShares` reads all k shares from **one local directory on one host**. Today's 2-of-3 is one machine, one fingerprint, three files. `frost-custody-contract.ts` supplies the missing half.

`CustodyGate` has exactly two members — `autonomous-hsm`, `human-touch-present` — and CG-1 enumerates the union so a third cannot be added silently. **No remote-human value, deliberately:** because a token cannot be pressed at a distance, an adversary with full remote access to every site still cannot produce a human signature. Checked and clean — the IP-KVM / "remote finger" substrate is referenced only for **power cycling and UEFI repair**; `detectBiometricPlatform` is host-local and fail-closed. There is no remote-human path to remove.

## Two quorums, two keys — amendment is structural, not policy

If an agent quorum can raise its own budget, the human signature at creation bought nothing. So this is **two FROST groups**, not one key plus a check:

| | Operating (agents, HSMs) | Creation (humans, tokens) |
|---|---|---|
| Signs | operations within a grant | grants and amendments only |
| Threshold | 2-of-3 | 2-of-3 |
| Binding constraint | survives one dead **site** | any one person may **decline** at no cost |
| Why not 3-of-3 | any site outage halts autonomous signing | one refusal becomes a veto — a coercion gate |
| Human recovery path | **none, by construction** | n/a |

The agent quorum holds no creation share, so it **cannot** mint or amend a grant — not "is not permitted to". CAP-2/3/4 test that, including the self-naming escalation where a forged grant declares its own signer to be the creation group.

**One flat t-of-n cannot express this**: it is satisfiable by *any* t members, so it cannot require two humans without also requiring nearly every agent. Two groups express it exactly, using only the FROST we already have.

Travel is **not** the outage (the token is USB+NFC portable). **Token loss** is — and that folds straight back into the reshare path above.

## Mutation testing: 18 planted, 18 killed — 3 caught my own bad tests

Three mutants initially **SURVIVED**, meaning three of my checks could not fail. All three were rewritten:

- **duplicate contribution** — passing `[c1, c1]` proves nothing (a repeated contribution misses the group key anyway). The real attack is one holder claiming two seats with commitments crafted **from public points** to sum correctly. Now tested.
- **sender binding** — two holders have different polynomials, so Feldman fails on its own. The binding actually stops **replay of a relabelled contribution**. Now tested.
- **canonical encoding** — compared values differing under any separator. Joining fields on `""` lets **one signature cover two different grants**; now tested across a field boundary.

I also found and fixed a real bug in my own first draft: `parts.join("")` was not injective across fields, and literal NUL bytes had been written into the source.
