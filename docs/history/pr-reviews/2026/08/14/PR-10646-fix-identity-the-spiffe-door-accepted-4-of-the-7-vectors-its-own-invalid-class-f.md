## Description

## The defect

`parseSpiffe` is the **peer-facing** door into `ActorRef` — a SPIFFE URI is what another
node hands us, where `parse` takes strings we generate ourselves. The strict parser was on
the inside door and the lax one on the outside.

Of the 7 strings in `INVALID_VECTORS` — the list whose own comment says *"every oracle port
(F# ActorRef.fs, future langs) MUST reject each of these"* — `parseSpiffe` **accepted 4**:

| input | `parse` | `parseSpiffe` (before) |
|---|---|---|
| `otto/COWORK` / `…/cell/COWORK` | reject | **accept** |
| `otto//fg` / `…/cell//fg` | reject | **accept** |
| `otto/cli@a@b` / `…/cell/cli@a@b` | reject | **accept** |
| `otto@machine-a` / `…/persona/otto@machine-a` | reject | **accept** |

Three of those mint an `ActorRef` that `parse(project(x))` then **throws** on. Two are worse
than a throw: `…/cell//fg` yields `{surface:"", instance:"fg"}`, which projects to bare
`"otto"` — **silently dropping the instance and colliding with a genuinely different
identity**. A peer-supplied name quietly becoming a different name is the identity-merge
failure class, arriving through the interop boundary.

## The F# oracle was right the whole time

`ActorRef.parseSpiffe` routes through `splitNode` + `assemble`, and
`tests/Tests.FSharp/ActorRef.Tests.fs` carries a test named *"Invalid SPIFFE vectors — same
rejection class through the URI port"* asserting **exactly** the cases TypeScript accepted.
Verified by execution: 6/6 pass. This was a live two-oracle byte-lock divergence on the
identity primitive.

## The fix

Mirror the F# structure — extract `splitNode` and `assembleCell`, route **both** doors
through them. The divergence existed for exactly as long as the two doors had separate
validation. Tests add the invalid-SPIFFE class plus three **closure laws** (rather than only
a case list), which fail for any input where the doors disagree, listed or not.

## Mutation testing — 10 mutants: 8 killed, 2 proven equivalent, 0 unexplained

- **M4** (drop the instance charset check) **survived the first round** — no vector exercised
  a bad *instance* segment. Added `otto/cli/FG`, `otto/cli/` and the SPIFFE forms; M4 now
  dies. Real gap, closed.
- **M1** (multiple-`@` guard) and **M5** (empty-surface guard) survive and are **equivalent
  mutants**, proven by execution not argued: with each removed the input is still rejected by
  the segment charset check, differing only in the error message. Kept for the clearer message
  and F# parity, but not independently load-bearing — and no test is added to "cover" them,
  since that test would assert a string rather than a behaviour.
- **Retracted:** my first mutation harness reported all 10 as SURVIVED. That was the harness
  failing to match bun's ANSI-wrapped result line, not a result. Rebuilt to distinguish
  KILLED / SURVIVED / **NO-SIGNAL**, and to fail loudly when a mutation does not apply or does
  not parse. The first run's output is withdrawn.

## Honest scope

`parseSpiffe`/`toSpiffe` have **no callers outside their own tests** today. This closes the
hole before the door is load-bearing — the cheap moment. It is **not** a live-exploit fix and
should not be read as one.

## Cause filed, not fixed — `081M00J1EWW087G0R000RJ6790`

The invalid-vector class is **hand-copied** into TS source and F# test source with nothing
comparing the copies, so each suite stayed green against its own copy while they drifted (the
F# side had grown four SPIFFE cases the TS side never had). ~25 other primitives already share
a `tests/cross-verification/*/vectors.json`; `ActorRef`, the identity primitive, is not one of
them. Wiring that touches `tests/Tests.FSharp/` and the `_harness` conventions — wider blast
radius than the parser fix, and worth following the existing pattern rather than improvising.
