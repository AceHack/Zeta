## Description

Closes `081KZYXRYR8087G0R003E6JZA4`.

## The defect, measured

`hygiene/unexecuted-test-files.ts` (#10473) walked the **working tree**. `bun run pages:build` copies `docs/` into the gitignored `dist/`, so the 18 archived test files under `docs/recovered-orphan-branches-2026-05/` acquire a second path and the checker reports them.

Reproduced on this branch's parent by running the real build (`llmtv-pages-static-export.ts --out-dir dist`), not by simulating it:

| | exit | summary line |
|---|---|---|
| **before**, built tree | **1** — 18 `NOT EXECUTED IN THE PR LANE: dist/...` | `files/.../unexecuted = 933 30 25 892 41` |
| **after**, same built tree | **0** | `tracked-files/hidden-from-bun/... = 915 2 30 25 892 23` |

(The work-item said four complaints; on this machine the build produces 18. The count is a function of what the build copied, which is the defect.)

CI checks out clean and has no populated `dist/`, so it stayed green throughout. **Green in CI and red on the machines of everyone who might act on a finding is the worst polarity an adoption-dependent checker can have** — it teaches its own audience to ignore it, and an ignored checker still reports green.

## The lesson was already in the repo and did not travel

`ace/build-graph.ts` (#10395) wrote it out in a docstring:

> evidence derived from the **tracked** set, so `derive` is identical on every checkout — a working-tree walk would have picked up caches and made it machine-dependent

Same defect, same fix, one subsystem over. The build-graph work found it, fixed it, and explained it — **in prose** — and the next checker built hand-rolled a walk anyway.

**So the fix is not a second `git ls-files` call.** The mechanism moves to `src/Core.TypeScript/git/tracked-files.ts` and `build-graph.trackedFiles` becomes a thin alias over it, keeping its export and its docstring. That is the externalization ladder (`docs/research/2026-08-13-lessons-belong-in-the-harness-not-in-rules-the-externalization-ladder.md`) applied to the instance that motivated it: a lesson each author must re-derive is a lesson one of them will miss.

The helper is justified rather than speculative — there were already ~16 hand-rolled `git ls-files` sites before this one. Converting them is **not** in this PR; that would be gold-plating on a bug fix.

## Two things the change surfaced, neither swallowed

**The prune list is gone, not carried forward.** By its own docstring it existed to bound *walk cost*; there is no walk. None of `node_modules`, `references`, `artifacts`, `bin`, `obj`, `TestResults` holds a tracked test file.

**Its dot-directory rule was doing something else, so that half is kept — and re-founded on evidence.** MEASURED against bun 1.3.14: a test file under a dot-prefixed directory is not run by a bare `bun test` (1 of 2 files ran), a positional filter cannot reach it ("the following filters did not match any test files"), and only an explicit `./`-prefixed path argument does. Crediting such a file to the gate's unfiltered `bun test` — which the `executes` model's no-filters rule would do — would **invent coverage**, the exact lie this checker exists to prevent. So it is excluded from the denominator and **counted out loud** in the summary line (`hidden-from-bun`), because an invisible exclusion is the defect, including in the checker's own denominator.

That count is **2**, and both are real findings the old prune was hiding: `.claude/hooks/harness.test.ts` and `.claude/hooks/stop-detect-response-rut.test.ts` are tracked and execute nowhere. That is this checker's own defect class in a shape it cannot yet express, so it is **filed as `081KZZ1RK6A087G0R003C773WC`** (with the three options and the measurement) rather than quietly absorbed by the fix that revealed it.

## The regression is a falsifier, and it was mutation-checked

`unexecuted-test-files.test.ts` plants an untracked `*.test.ts` under `dist/` — **the live defect, not an analogue** — and asserts the discovered set is unmoved. Two guards against a vacuous pass, which is the failure mode of any "it isn't there" test: the plant is asserted to **exist on disk**, and a known tracked file is asserted **present**.

Proven to be a falsifier rather than claimed: reintroducing the working-tree walk turns it **red on a clean tree as well as a built one** — i.e. in the lane where CI actually runs it, which is the only place a regression test earns its name.

`git/tracked-files.test.ts` adds a hermetic fixture-repo suite for the helper (tracked vs untracked, gitignored build dir, locally-deleted-but-tracked, ordinal order, throw-not-empty-on-failure). Hermetic on purpose: a test that read the ambient repo would inherit the machine-dependence being fixed and could not tell the two implementations apart.
