## Description

## What this is

A verification function that could not fail, in shipped code, plus the SMT lemma behind it that had the same defect. `#10476` recorded the first of these rather than fixing it, because callers depended on the behaviour and the change deserved its own PR. This is that PR, and it found two more.

A check that structurally cannot fail is worse than no check: it occupies the slot where a real one would go and reports success forever.

## CHECKED (by execution, not by reading)

**1. `verifyLandauer` compared `entropy_heat` to `entropy_heat`.** `bitsErased`, `heatPaid` and `floor` were all the same field, so `heatPaid >= floor` was `x >= x`. Known from `#10476`.

**2. `second_law_satisfied` was also vacuous — this was not previously named.** It tested `entropy_state + entropy_heat >= 0`. `measure(k)` moves `k` between the two ledgers and leaves that sum alone for every `k`, negative and oversized included, so only `branch` (+1) ever moves it. An exhaustive sweep of every operation sequence up to length 5 over the full alphabet — including `measure(-3)` and `measure(9999)` — produced `false` **zero times**. The field was the literal `true` wearing a physics name. So `holds` reduced to `entropy_heat >= 0`, the only falsifiable thing in it.

**3. `tools/Z3Verify/landauer-floor-lemma.smt2` was vacuous.** Its second-law premise `-k + heat >= 0` is algebraically the conclusion `heat >= k` that it then negated. Deleting only that premise flips the file from `unsat` to `sat`, model `k=1.0, heat=0.0` — an erasure paying no heat at all, which nothing else in the file excluded. The header advertised four lemmas F1-F4; the file contained one. **No workflow executed it**, which is why it rotted unseen.

**4. `LandauerFloor.lean` is not vacuous but was not faithful.** Its `measure` carries the precondition `k <= s.state`, which the TypeScript does not implement, and its heat-monotonicity theorems are discharged by `Nat` rather than by the model — the implementation uses signed `number`, where the same property is falsifiable and was false. A formal artefact that discharges an obligation using a type the implementation lacks has not discharged it.

## Does a non-trivial invariant exist?

Not for the Landauer bound. `measure(k)` pays exactly `k`, and the floor in normalized units is exactly `k x 1`, so heat and floor are one number and no comparison between them can fail. **The honest fix is a narrower claim, not a stricter comparison** — inventing one would produce spurious failures, which is the other half of this defect class and gets the check disabled.

So `verifyLandauer` is replaced by `auditEntropyLedger`, which reports the identities **as identities** and carries three invariants that genuinely can be false:

| invariant | falsified by |
|---|---|
| `heatMonotone` | `measure(k < 0)` — the actual arrow-of-time content |
| `heatNonNegative` | a net-negative measurement history |
| `erasuresFullyAdmitted` | erasing what was never admitted |

It deliberately exposes **no aggregate boolean**. The aggregate is where the vacuity hid, and there is a test asserting no `holds` key comes back.

## Erasing what you never held: decided, not guessed

It is legitimate, and it stays unguarded. `physics-traits.ts` `createNonAdjMap.put/delete` and `observe/event-sink-folder.ts` both call `measure(1)` with nothing admitted — three ordinary map operations drive `entropy_state` to `-3`, and `event-sink-folder` stamps the negative value into durable event envelopes. A guard would take a reporting problem and turn it into an outage.

So the deficit is named and reported (`unadmittedErasureBits`) rather than rejected, the precondition is documented with the caller list, and `key-erasure-meter.ts` remains the guarded path for callers that want admission enforced.

`measure(k < 0)` is likewise accepted rather than thrown — Result-over-exception, and this is a `void` counter — but it now falsifies heat monotonicity, so it cannot pass silently. No shipped call site passes a negative bit count, so the stricter check does not fire spuriously.

## The SMT lemma now gates itself against vacuity

Rewritten to state the ledger equations explicitly and to carry a **non-vacuity probe**: a block that drops the second-law premise and is expected to return `sat`. `tools/Z3Verify/landauer-floor-lemma.test.ts` gates it under z3 **and** cvc5 independently (BP-16 — both return `unsat sat sat sat unsat unsat`) and asserts the verdict **sequence**, not all-unsat.

An all-unsat expectation is satisfied by a tautology. That `sat` is what the old file would have failed.

Portfolio note for whoever sizes the next round: **every pre-existing `.smt2` runner in this repo asserts all-unsat**, so not one of them could have caught this. 9 lemma files, 4 with an executing runner after this PR, 5 with none.

## Lean
