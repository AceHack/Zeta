## Description


Follows #10573. That PR made the audit able to fail; this one makes it run, and
fixes a second way it was quietly not checking.

BOTH INSTRUMENTS WERE INVOKED BY NOTHING
----------------------------------------
Checked across `.github/workflows/`: zero references to
`audit-agencysignature-main-tip.ts` or `validate-agencysignature-pr-body.ts`.
That is the root cause behind #10564's numbers — 113 unsigned agent commits in
300, and three commits carrying the misspelled key `Agent-Signature-Version`.
A convention whose tooling nobody runs is a convention nobody keeps.

`agencysignature-enforcement.yml` adds two jobs at the two moments that matter:

- `validate-pr-body` (pre-merge). GitHub squash-merge uses the PR BODY as the
  commit message, so the body is the only place the block can be for it to
  survive the merge at all.
- `audit-main-tip` (post-merge), scoped `--commit HEAD`. It judges only the
  commit that just landed, so the pre-existing debt cannot hold it red — a job
  that is permanently red stops being read.

It is NOT in branch protection's required set. That is a repository-settings
change and a treaty-amendment consent path (gate.yml "THE FLIP"), so it is a
human call. Until then it gives its own red X and locks no unrelated lane.

THE CUTOVER, MEASURED FIRST
---------------------------
Before choosing the shape I measured it: of 12 open PRs, **0** carried a valid
trailer block. A retroactively-blocking validator would have red-X'd the entire
in-flight fleet for something nobody could have known. So `validate-pr-body`
grandfathers PRs created before 2026-08-15T00:00:00Z — the same instant, and
the same stated-cutover discipline, the auditor already uses. This is not a
check that cannot fail: it is blocking for every PR opened from the cutover
onward, which is all of them from now on.

The grandfather comparison lives in the TOOL (`isGrandfatheredPr`), not in the
workflow yaml. Logic in a `run:` block is logic no test can reach, and writing
untested logic into a CI gate — in this work-item of all work-items — would
have been self-defeating. It has four falsifiers, including one for the
timezone case (`2026-08-14T21:00:00-04:00` is 01:00Z on the 15th, i.e. NOT
grandfathered, which a string comparison gets wrong) and one for fail-closed on
an unparseable timestamp.

SECOND VACUITY, SAME FILE: THE SLIDING SHIP-DATE WINDOW
-------------------------------------------------------
`detectV1Ship` walked `--reverse --max-count=5000`. git applies max-count
BEFORE reversing, so it only ever saw the newest 5000 commits — and `main`
passed 5000 some time ago (6772 today).

MEASURED: the true earliest v1-signed commit is `a4bdce83da81`
(2026-05-28T20:22:11Z, PR #5928). The tool reported 2026-06-10 — **13 days
later** — so every commit in that gap was classified LEGACY and auto-passed.
And it DRIFTS: the window slides forward as history grows, so the reported ship
date advances and the auditor audits less of main every single day. A check
whose coverage erodes on a timer is the same failure class as one that cannot
fail; it just takes longer to notice.

The anchor is now PINNED (`V1_SHIP_DATE_DEFAULT` / `V1_SHIP_SHA_DEFAULT`) —
it is a historical fact and does not need re-deriving. The window scan survives
only as a fallback for repositories where the anchor commit is unreachable.

THIRD: A SHALLOW CLONE MADE THE AUDIT PASS HAVING CHECKED NOTHING
-----------------------------------------------------------------
With no reachable anchor, every commit classifies LEGACY and the audit exits 0.
Wiring the auditor into CI would have walked straight into it — `fetch-depth: 1`
is the default and it produces a green tick over zero verified commits.
`--require-shipped` turns that into exit 2. The test reproduces BOTH sides: the
same unsigned agent commit passes without the flag (the silent green, kept as
the thing the guard guards against) and errors with it.

FOURTH: THE TEMPLATE VALIDATED WITH ITS PLACEHOLDERS STILL IN
-------------------------------------------------------------
`.github/PULL_REQUEST_TEMPLATE.md` now ships the trailer block pre-filled, which
is what makes the block survive squash-merge by default rather than by every
agent remembering ten field names. That creates a new easy failure — shipping
the skeleton — and MEASURED, the validator passed the template unmodified, with
`Agent: <persona>` in it. Attribution to nobody, with a green check on top; the
same silent-green shape as the audit that exempted the whole fleet.
`checkPlaceholders` rejects any required value that is entirely `<...>`, while
leaving a value that merely contains angle brackets (`Name <email>`) alone.

The template also carries the canonical-vs-misspelled key warning inline, since
the three commits that got it wrong were composing by hand from memory.
