## Description

fix(heartbeat): scope merge duty to automation branches - my oldest-first fix aimed it at the held PRs

REGRESSION I INTRODUCED IN #10569, caught before it fired.

The merge-duty step is titled "agent-to-agent value transfer" and exists for terminal
bookkeeping - PR-review archives and telemetry flushes. It was never scoped to that in
code. While the selection was newest-first that omission LOOKED harmless: the newest
open PRs are almost always the bookkeeping ones, so an unfiltered selection happened to
land on them.

#10569 inverted the order to oldest-first to fix tail starvation. That turned a latent
hole into a live one aimed at the worst possible target, because the OLDEST unarmed PRs
are exactly the ones a human or a reviewing agent deliberately left unarmed pending
review.

Caught 2026-08-14T13:46Z, with a heartbeat run already in progress and the next three
selections being:

  10479  auth: authorize reviewed GitHub Pages passkey        (security-class, unreviewed)
  10567  feat(persona-keys): FROST signPartial + P0 CSPRNG fix (crypto, unreviewed)
  10570  feat(amplitude): exact cyclotomic carrier Z[zeta_16]  (unreviewed)

One step from arming auto-merge on security-class changes nobody had read. Mitigated
immediately by marking the seven review-held PRs draft (the `.draft` filter excludes
them), but draft is a human convention, not a guard - so this is the actual fix.

The guard is the branch name, matched against the prefixes this repo's automation
actually pushes: `automation/pr-archive-` and `heartbeat/`. A substantive change never
lives on those branches, so it can never be selected here regardless of age, review
state, or who forgot to mark something draft. Fail-closed: an unrecognised branch is not
auto-merged. A new automation lane costs a deliberate one-line diff, which is the right
place to decide whether that lane should merge without a human.

Verified against the live repo, with the draft filter REMOVED so the branch guard is
tested alone rather than shadowed:

  selected: 10592 (automation/pr-archive-10573-...), 10593 (heartbeat/society)
  excluded: 10479, 10567, 10570, 10575, 10577, 10594, 10595 - all seven held PRs

Also: YAML parses, `bash -n` clean on the extracted run block.

Worth stating plainly: the pre-existing code was also unscoped and also wrong. It failed
in a direction that looked harmless, which is why it survived. My change did not create
the hazard, it aimed it.
