## Description

## Why this was on the critical path

An unsigned announce is an **Eclipse primitive**. A peer that can announce an identity it does not hold populates a victim's routing table with identities the attacker controls, and the victim's view of the network becomes whatever the attacker chooses — no matter how good the routing geometry is. **Routing security reduces to announce authenticity.**

PR #13456's clean-room routing design independently narrowed the residual risk of a homogeneous small-world overlay to exactly this identity-side class (Sybil / Eclipse), which is what made this `docs/BUGS.md` P1 the gate on that line.

## The bug was verified live before anything was fixed

Two attacks landed on the pre-fix code:

1. **Pair-consistent impersonation.** `{dest: destinationHash(victimZid), zid: victimZid, hops: 0}` captured the victim's route. `destinationHash` hashes a **public** identifier, so anyone can mint a pair-consistent announce for any zid they have ever seen. The `dest`/`zid` pair check is *address integrity* and can never be *identity authenticity* — which is why the docstring's `SELF-CERTIFYING ADDRESS` was the bug stated in a comment. It now reads self-**describing**, with the reason recorded inline.
2. **The escape hatch.** The pair guard added 2026-08-02 read `if (a.dest.length === 32 && ...)`, so a `dest` of **any other length skipped the check entirely** — `{dest: "d1", zid: <unrelated>}` folded straight into the path table. The exemption existed only to keep older fold tests using `dest: "d1"` passing, and an attacker could take it as easily as a test could.

So the entry was **not** stale, and the earlier partial fix did not close it.

## The fix invents nothing

`reticulum-announce-auth.ts` is the direct twin of the already-shipped `beacon-auth.ts`: same persona keyring, same `ace/signing.ts` canonical bytes, same trust-entry shape (one trust store serves both wires), same dual-key overlap-window rotation ADR. Ed25519 over the canonical bytes of the identity claim `(dest, zid)`.

The transport adopts it through the same `off → dual → required` discriminated union that `llmtv-node.ts` already established for the beacon wire.

**The signature deliberately does not cover `hops`/`id`.** Every relay bumps `hops` — that is how the mesh measures distance — so a signature covering it would be invalidated by the first honest relay and would have to be disabled to ship. A check that must be disabled to ship is not a check. Relays therefore carry an announce they cannot forge; the residual is named below rather than papered over.

## Constraints held

- **Noninterference §13** — `trust` is a declared input. Verification opens no keystore, reads no clock, touches no socket; the verdict is a function of `(announce, sig, trust)` alone. The transport takes an **injected** verifier, so it holds no crypto and the dependency stays one-way (auth → transport, no cycle).
- **`local-time-never-enters-the-shared-fold`** — `nowMs` is only ever *written* onto an accepted path as a liveness stamp, never a predicate that decides acceptance. A test pins that two nodes receiving the same announce at wildly different local times fold the same evidence set. Replay protection wants the agreed phase order, not a wall-clock window; that is stated in the residual, not quietly implemented with a clock.
- **Result-over-exception** — the receive path is total; a hostile wire gets a verdict, never a throw.
- **Dual-use** — verdicts name the **fact** (`signature-invalid`, `identity-mismatch`, `dest-not-bound`), never the intent. A test asserts the verdict contains no `forger`/`attack` wording, because the same refusal must be readable as "an attack" *or* "a rotation that has not landed" by the caller's policy.

## Proof — both directions, then mutated

22 falsifiers. Both directions throughout: a forged announce is **rejected** and a genuine one is **accepted**, so a reject-everything validator fails the suite. The sharp case is that Eve is a *trusted* peer signing with her own valid key — the question is never "is this key known" but "does this key speak for **this** zid".

## Honest limit

Consumers still default to `announceAuth: {mode: "off"}`, and **an off-mode transport is exactly as forgeable as before**. This PR does not migrate `dht-discovery` / `reticulum-metered-transport` / `mux-transport-bridge` / `network-transport`. That is filed as RESIDUAL 1 in `docs/BUGS.md` and pinned by its own negative-control test, so the gap cannot rot into a false sense of coverage. Hop-count replay is RESIDUAL 2.
