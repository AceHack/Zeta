## Description

`pr-manifest-integrity` has failed 4 consecutive scheduled runs. The lead I was handed
was: either the manifest drifts every time PRs merge and nothing regenerates it, or the
recent manual regeneration (#13470) was wrong. **Neither.** The regeneration was fine and
the automatic repair has never stopped. The bug is in the check.

## Root cause: an instantaneous sample reported as a duration

The step failed on **any** drift on the 6-hourly schedule, on this reasoning in the header:

> Six hours is well past that bound, so drift seen by a scheduled run means the repair
> cadence has STOPPED.

That inference does not hold. The check samples an **instant**; the conclusion is about a
**duration**. The shard store is written by every archive PR (~135 landings/24h) and the
index is repaired by a single serialised writer on a ~50-minute flush gate, so at a random
instant the manifest is *normally* a few shards behind. That is the design.

Measured against the repair writer's own commits on `docs/github/prs/manifest.jsonl`, every
one of the four failures happened within 40 minutes of a **successful** repair:

| scheduled run | last repair landed | verdict it printed |
|---|---|---|
| 08-21T18:34 | **0.4 min earlier** | "repair writer has stopped landing" |
| 08-22T00:34 | 38.2 min earlier | same |
| 08-22T06:34 | 5.0 min earlier | same |
| 08-22T12:34 | 11.6 min earlier | same |

The first one declared the repair cadence dead **24 seconds** after it had landed. All four
are false positives. (Repair landings in the week to 08-22: 218 of them, gap p50 26.5 min.)

## The fix: measure the age

Every shard carries `fetched_at`, and the repair regenerates the **whole** index from **all**
shards — so if the writer ran at time T, every shard older than T is reconciled. Therefore
the age of the oldest **unreconciled** shard *is* "how long ago the writer must last have
run". `derive-pr-manifest.ts` now computes exactly that, and the workflow passes
`--min-age-minutes 180`.

## Why this is not "widening a tolerance until it passes"

- The tool now measures the quantity the caller was **already claiming** to have measured.
  The stated contract was always "drift that outlived the repair bound"; only the
  implementation was missing.
- **180 is drawn from the measured distribution, not from what made the run green.** Gap
  p50 26.5 min, p90 47 min. 180 is ~3.8× p90, above the entire healthy population (all four
  false positives were ≤ 38.2 min) and below the pathological one — the same week contained
  **7 gaps over 2 hours and 4 over 3 hours, and this bound still goes red on every one.**
- **Three classes stay red at any age, so the bound can never become a mute button:**
  shard-store integrity (exit 2); an **orphaned** index entry with no shard behind it
  (substrate loss, which no late repair explains); and an unreconciled shard whose
  `fetched_at` cannot be read (a check that cannot measure must not report a pass).
- A malformed `--min-age-minutes` is **refused (exit 3)**, never silently ignored — a
  silently-dropped bound would restore the old any-drift-fails behaviour invisibly.
- Omitting the flag preserves the historical contract exactly, so no other caller changes.

## Falsifiers
