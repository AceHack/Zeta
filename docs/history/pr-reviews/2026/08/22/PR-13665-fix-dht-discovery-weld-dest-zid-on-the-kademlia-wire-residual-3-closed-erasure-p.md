## Description

Closes **RESIDUAL 3** of the `docs/BUGS.md` Reticulum-announce entry: `dht-discovery` carried the same unbound `(dest, zid)` pair one layer up, on the wire that actually selects peers.

## The defect

`DhtNode` carried `dest` and `zid` as two independent fields and nothing on the receive path checked they were the same claim. `observeNode` folded whatever it was handed; `lookup` folded peer-supplied `foundNodes` straight into its shortlist. A peer answering a findNode could therefore seed a querier's routing table with **arbitrary** `(dest, zid)` pairs.

Two forms, both now refused, and the second is the one that bites in Kademlia:

| forgery | reads as |
|---|---|
| `{dest: H(alice), zid: mallory}` | *who is at alice's id* |
| `{dest: H(mallory), zid: alice}` | *where is alice* — the attacker chooses the XOR neighbourhood a victim's identity appears in |

The whole geometry rests on **node id == destination hash**, and until now nothing enforced it.

## What landed

- **`classifyDhtNode`** — total, pure, unconditional. Verdicts name the neutral fact (`malformed-node`, `dest-not-bound`), never an intent; `dest-not-bound` is deliberately the **same word the announce wire uses for the same fact**. No `length === 32` exemption — that exemption is precisely what made the announce-side guard skippable, and short dests (`"8000"`, `"d1"`, `""`) are pinned as refused.
- **Guarded at both entries.** `observeNode` refuses before folding and returns the table **byte-identically** (same object reference); `lookup` runs every peer answer through `admissibleNodes`. `answerFindNode` is deliberately **not** guarded, and the reason is in its docstring: everything in the table already passed `observeNode`, so a filter there could never fail — and a check that cannot fail is not a check.
- **`nowMs` is untouched as a predicate.** `lastSeenMs` is shape-checked and never compared against a now, so two nodes with different receive-times reach the same verdict on the same record (`local-time-never-enters-the-shared-fold`).
- **Dependency stays one-way** — `dht-discovery` imports `destinationHash` from `reticulum-transport`, never the reverse, and there is a test asserting it.

## The erasure profiles were RE-DERIVED, not adjusted

This was the filed precondition and it is the part worth reading.

The old models pinned *"id space to 2 hex characters"* over deliberately unbound ids (`{dest: "10", zid: "zid-10"}`) — records the guard now refuses, so they described a domain the code can no longer reach. Each was re-run over a **bound** pool of real `(destinationHash(zid), zid)` pairs.

**Three of the four numbers came back identical (6 / 4 / 85), and that is a result rather than an unchanged measurement.** The sweep counts how many observation *histories* collapse onto one table, and that count is fixed by the bucket/MRU combinatorics over four distinct nodes sharing one bucket at `k = 2`. Binding restricts *which* pairs exist; it does not change how a full bucket forgets or how an idempotent refresh collapses two histories. The old model was **isomorphic to the new one on exactly the structure being measured** — which is why its numbers were right about erasure while being wrong about the domain. (The 2026-08-18 Landauer research doc cites the 6 and the 4; both re-checked, both still hold.)

**A fifth profile is new**, and it is the one binding actually changed. It sweeps the domain that now *contains* refusals — the bound universe ∪ four impostors, each carrying a genuine node's `dest` under a different node's `zid` — and measures the guard itself as an erasure: **fibre 85 / 6,409,391 ppm**. `85` is derived, not fitted: it is the count of length-0..3 sequences over the 4 impostors (1+4+16+64), all landing on the empty table because a refused record leaves no trace. It is also the guard's own falsifier — **delete the guard and the same sweep measures 11**.

## What this does NOT close, carried as passing tests rather than comments

`destinationHash` hashes a **public** identifier, so a pair-consistent record is mintable by anyone for any zid they have seen. This is integrity of the **address**, never authenticity of the **identity** — the same measured limit `reticulum-announce-auth.ts` already records for its wire.

- **(a) the DHT wire has no signature layer.** The membrane shape exists (`reticulum-announce-auth.ts`); doing it here is a separate design, not a hardening pass.
- **(b) `DhtNode.route` is outside the pair entirely** — a route hint stays attacker-supplied even for a correctly-bound `(dest, zid)`. Latent rather than live only because nothing in-repo reads `DhtNode.route` today.

**RESIDUAL 2 (hop-count replay) is untouched and stays open.** It is a different design — per-link authentication or a signed monotonic sequence in agreed phase order, explicitly *not* a wall-clock freshness window.
