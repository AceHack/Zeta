## Description

Closes the `PRE_APT_RESERVE_SECONDS` half-invariant found (and deliberately left alone) by the agent that hit it, and the per-lane override the same audit could not see.

## The defect, priced

`audit-apt-budget-fits-job-timeout.ts` enforced

```
ci_budget + kill_after + PRE_APT_RESERVE_SECONDS(120) <= tightest_job_seconds
```

and its own comment defined that reserve as *"the work that PRECEDES it."* **There was no term for the work that FOLLOWS.**

| lane | old arithmetic | verdict | measured non-apt work |
|---|---|---|---|
| `low-memory.yml` | 420 + 10 + 120 = **550 ≤ 840** | **passed** | **571s p90 / 683s max** |

The guard written to stop *"a check that could not run to completion looks like one that passed"* certified the one lane already measured over budget.

## Measured across the whole governed set, not guessed

45 governed jobs, from real job wall clocks and real job logs. An apt phase is delimited by the markers `linux.sh` itself prints (`↓ installing apt packages` … `✓ apt packages up to date`); the term is

```
nonApt(run) = job wall seconds − the longest single apt phase in that run
```

The longest phase, not the sum, because the budget bounds **one** invocation — the docker legs run `install.sh` three times per job and the worst case is one of the three spending its whole budget.

The spread is why no constant could have worked:

| job | non-apt p90 |
|---|---|
| `accelerator-local-llm-validate:validate-linux` | **71s** |
| `ci-cache-paths-lint:audit` | 97s |
| `helm-validate:structural` | 143s |
| `low-memory:build-and-test-low-memory` | **571s** |
| `gate:test-typescript-hermetic` | 677s |
| `k8s-argocd-health-test:live-kind-included` | **795s** |

So the fix is **option 1 — a measured per-job term**, shipped as `apt-job-timings.measured.json` (p90 + max + sample count + **run ids** + window, per job) plus `refresh-apt-job-timings.ts` that regenerates it. The audit itself makes **no network call**: a check that passes when the API is down is strictly worse than one whose number can go stale, and the staleness is stated in the file rather than hidden.

## The invariant now

```
budget(job) + kill_after + nonApt(job) <= job_timeout_seconds
```

**44 of 45 fit.** Tightest fitting margin: `helm-validate:structural`, 420 + 10 + 143 = 573 ≤ 600.

**One does not, and it is the one that motivated this.** `low-memory` needs 1001s of an 840s cap. There is no room to find: `timeout-minutes: 14` is already one minute under the ubuntu-slim **15-minute runner-class hard cap**, and a budget small enough to fit (259s) leaves under 2× headroom over that lane's own measured 133s worst-case apt phase — the exact trade the 150s first draft of this budget got wrong on 2026-08-18. PR #13476 already took the one cut available on the apt side. What remains over budget is the lane's `dotnet restore + build + test` on one vCPU.

So it is **recorded, not widened**: a dated entry in `audit-apt-budget-fits-job-timeout.baseline.json` that

* **pins the measurement it acknowledges** — one second worse is *not* covered;
* **goes STALE and fails** the moment the job fits, or names no governed job;
* must pin **arithmetic this tree produces** (`observedTimeoutSeconds` = the job's real timeout, `observedRequiredSeconds` = budget + kill + its own term). Without that, `observedNonAptSeconds: 99999` would acknowledge anything forever.

Its `liftsWhen` names **exactly the audit's own comparison** — `420 + 10 + nonAptP90Seconds <= 840` — per the trap found in this tree on 2026-08-22: a `LIFTS WHEN` *stricter* than the gate it names keeps a deferral alive after its defect is gone.

## Second defect: the knob the guard could not see

The audit read only the **default** budget, so the per-lane `ZETA_APT_BUDGET_SECONDS` that `linux.sh` advertises was invisible — a lane could raise its budget past anything and nothing went red. Now read at workflow / job / step `env:` and inline in the `run:` block, with two refusals:

* an override the audit **cannot evaluate** (`${{ … }}`) **throws** — it must not fall back to the default, because that is the same invisibility under a nicer name;
* on a **docker leg** an `env:` override is **refused**: `env:` sets a variable in the runner and never crosses into `docker build`, so reading it would credit a job with a budget `linux.sh` never sees. There it must travel as `--build-arg`.

## Coverage cannot go quiet

A governed job the timings file has **never heard of** now fails the audit outright. The two jobs no run could measure are **named individually with reasons** and keep the old, weaker pre-apt bound:

* `scaffold-stage1-create-repos:create-repos` — `total_count: 0`; `workflow_dispatch:` only, so there is no history and no schedule that would create one.
* `tlaps-proof:prove` — last 40 runs are 33 `cancelled` + 7 `failure`; last success is run 28550177205 on **2026-07-01**. That the lane has not been green in seven weeks is a **separate finding**, recorded there so it is not lost.

## Stated limits, rather than discovered later

* The **5-attempt `install.sh` retry wrapper** (12 governed jobs carry it inline) can spend up to 5 budgets and is **not** charged. Reason: attempt 1 has already printed `linux.sh`'s own budget-exhausted error before attempt 2 begins, so a job killed later still carries a readable cause. Worst case observed: 409s of apt across retries in `gate:lint-csharp` (job 97018601440).
* The measurements are a **committed snapshot** and can go stale.
