## Description

## The class this closes

An Application's `helm.valuesObject` states an intent Helm never checks. A key the chart has no schema for is **silently discarded**, and the manifest goes on reading exactly like one that governs something. Four instances landed in one night:

| app | inert key | what it cost |
|---|---|---|
| `hindsight` | `postgresql.primary.persistence.*` | Postgres on node-local `reclaimPolicy: Delete` disk while the catalogue said `longhorn` |
| `nats` | top-level `cluster: {replicas: 3}` | **no JetStream quorum** — a stream with `replicas > 1` refuses to create |
| `oz` | `adminSecret: {name, key}` | a key ziti-controller has **never** had |
| `headscale` | `config.*` | **zero occurrences of `server_url` in the render** — CrashLoopBackOff, 12 restarts |

The first three were caught only because they happened to govern **storage**, where `rendered-storage-claims.ts` exists. The fourth governed whether the process could start, and nothing would have caught it. `inert-valuesobject-keys.test.ts` said out loud that it was **not** that guard. This builds it.

## The bar, met — and exceeded by two

Every instance is reconstructed from git history. The four pre-fix manifests are **verbatim `git show` output** in `testdata/inert-valuesobject-history/`, and the test re-verifies them against those very objects, so a fixture edited to make a test pass is caught by the repository itself.

The checker refuses all four. It also refuses **two more** that PR #13524 found later and independently — hindsight's `api.llm` and its top-level `service` — which is the closest thing available to evidence that this implements a **class** rather than four remembered cases.

**`oz` is the honest exception, and the test says which is which.** Its pre-fix pin (1.4.5) is a version no registry has ever served, so at its own pin it is refused as `chart-unavailable` — a real defect, and *not* a demonstration of the key-set comparison. The same `valuesObject` is therefore also run against 3.1.1, where `adminSecret` is named inert. Only the second demonstrates the comparison.

## The hard part was false positives

A naive comparison against the parent `values.yaml` is red on nearly every app here, and **a guard that cries wolf gets disabled**, which is strictly worse than no guard. Four legitimate sources of a key absent from the parent's values, all measured on this tree:

- **Subcharts** — resolved from `Chart.yaml` + `charts/`, **aliases included**, and a name may carry **two** value keys (spire depends on `spire-agent` twice — once unaliased, once as `upstream-spire-agent`; a `name -> key` map left that whole subtree unmeasured).
- **Library charts** — a `type: library` subchart contributes at the **parent's** prefix, because its templates run in the parent's scope. headscale's own `values.yaml` has six top-level keys; every `persistence.config.*` value it legitimately sets comes from bjw-s `common`, and folding that under its own name flags a value the chart **refuses to template without**.
- **Conditional paths** — acceptance is read from the templates' literal `.Values.a.b.c` references too. Absent from a default render is not absent from the chart.
- **Open maps** — `env`, `podAnnotations`, `persistence` (keyed by an arbitrary item name). Detected from the chart's own text — a `range`, a `toYaml` in **either** the prefix or the **pipeline** form, a variable binding, an empty-map default — never from a hardcoded list of key names, which would be a second schema free to drift.

Measured and repaired during the build, each after seeing it go wrong:

- `get .Values "edition"` is a **literal** read, not a computed one. Reading it as dynamic marked ziti-controller's whole root undecidable and turned oz's `adminSecret` from a caught defect into an unanswered question.
- A computed subscript records its dynamic reach at the **literal prefix**, not the root — gitlab writes `index .Values "global" "communityImages" .Chart.Name "repository"`, and root-level recording made every key in a 30-subchart umbrella undecidable.
- **Two `.Values` reaches on one line are both found.** A greedier pattern found only the first, and the verdict it produced was true *by accident* — which is not a verdict this module is allowed to reach.
- An **empty `valuesObject` is never a finding**, which removed 12 false positives from git-path Applications that declare nothing. It is not an escape hatch: the exemption is bought by *deleting the claims*, and a non-empty `valuesObject` against an unresolvable chart stays a finding.

## Undecidable is a finding, never a pass

A computed `.Values` reach, an unresolvable chart, and an Application the snapshot does not cover **all exit 1**. An app nobody checked must never read as an app that passed.

## What it found live

**11 pre-existing inert keys across 54 Applications**, all hand-verified against the charts. The sharpest is spire's `spire-agent.workloadAttestors.k8s.skipKubeletVerification` — the chart's **own README** says the setting was removed in 0.23.x, and the pin is 0.24.2.

Each is baselined with a reason and a `LIFTS WHEN` that names the **one manifest edit that clears that entry** — the stricter-than-the-gate trap, checked mechanically by a test that **refused two of my own first drafts**. Because each condition is exactly "this key is fixed", fixing the key makes the entry stale and the gate goes red until it is deleted, which is the ratchet working.

They are acknowledged rather than fixed because repairing them edits manifests that deploy to a live cluster; bundling eleven such changes into the change that introduces their detector would leave both unreviewable.

## Proven by mutation

**14 mutants, all killed.** Each proved *applied* by a byte-for-byte comparison against a pristine copy **before its test result was read**, and the module proved restored after; an anchor that fails to match produces `NO RESULT`, never a survival.

Four **survived the first run** — `subchart-resolution-disabled`, `library-chart-folded-under-its-own-name`, `pipeline-toYaml-form-dropped`, `uncovered-app-is-a-pass`. Every assertion up to that point read the checked-in snapshot, and **a snapshot can never falsify the extractor that wrote it**. That is what added the synthetic-chart extraction tests and the CLI exit-code tests.

A fifth, `literal-ancestor-rule-removed`, survived even after that. Measurement: across all 54 Applications and 736 declared paths, both ancestry branches fire **zero** times. They are kept as false-positive guards, the measurement is stated in the code, and they are now pinned directly rather than left unfalsifiable.

## Secondary (taken because it was cheap)

The live-kind lanes now dump `kubectl logs --previous` for any pod that is not Running/Succeeded or has restarted. A CrashLoopBackOff pod's *current* container has usually not started, so the reason the previous one died was thrown away on every restart — which is why headscale's diagnosis had to be **reasoned from a local `helm template`** instead of read from the error the process printed 12 times.

## Honest limits

- The guard answers *"does the chart have this key?"*, not *"does the key still do what you think?"* Worked case: gitlab's own `NOTES.txt` names `gitlab-runner.runners.privileged`, so the guard accepts it — while gitlab-runner 0.71.0's `runners` block accepts only `config`/`configPath`/`cache`. That is a **false negative**, verified by hand, and it is named in the code rather than papered over with parser cleverness that would make the verdict accidental again.
- The schema snapshot is ~1.0 MB. It is text, prefix-shared as a tree, chart-keyed so duplicate pins are stored once, and every byte of it is a readable path — but it is large, and a chart bump rewrites that chart's block.
