## Description

Closes work-item `081M0K36K69087G0R003BYSCF8`, whose fix landed in #13476 (`119a5e88`). This carries the *measured* result, plus the two corrections the original filing needed.

## The "420 seconds" was a budget, not a timing

Read off the step timings of a **passing** run (`32539360563`), the apt phase was **148s**. The `420s` in the failure text is the apt phase *budget*. `linux.sh` sizes that default against its own recorded measurement of **38.2s** on `ubuntu-24.04` and calls it "~11x headroom" — on a 1-vCPU runner the identical work is 148s, so the real headroom on *this* runner was **2.8x**. The budget was sized on a 4-vCPU measurement and applied to a 1-vCPU host. That is the defect, stated exactly.

Three post-fix runs, all green — apt phase **46.8s / 66.2s / 36.8s** (6.3x–11.4x budget headroom), back in line with the ubuntu-24.04 ratio the budget was designed around.

Cold path verified independently, not only warm: both package sets installed from a bare `ubuntu:24.04` image in a `--cpus 1 --memory 5g` container through the shipped filter — **271s** full (388 pkgs / 748 MB) vs **152s** slim (149 pkgs / 146 MB), slim resolving with nothing missing. CI's own `docker-ubuntu-install-sh-test` and `docker-ubuntu-jammy-install-sh-test` both passed on #13476, exercising `install.sh` end-to-end in fresh containers.

## Residual, stated rather than smoothed

`32542506735` used **683s of 840s (81.3%)** with three slim jobs running concurrently. Its apt phase was 66s; the extra went to `dotnet build` (239s vs 151s). **The lane is no longer apt-bound** — what is left is runner contention, and before this fix that same contention would have pushed the job past the cap instead of to 81% of it. If it tightens again the next levers are named in the work-item: the `eprover` autotools **source build (76s)** and the best-effort agent-CLI installs (**29s**), both inside the same install step and both irrelevant to a `dotnet build`. Option 1 (cache apt) is still available and now cheaper to size; option 3 (raise the cap) was not taken.

No behaviour change in this PR — it moves the work-item to `done/` and records the evidence.
