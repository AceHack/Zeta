## Description

Three scheduled telemetry cadences have been failing on every run for days, for one
shared reason, and nobody saw it because the run-list window is saturated by heartbeat
traffic.

## Root cause (one, shared by all three)

All three end with `git pull --rebase origin main && git push origin HEAD:main`.
Ruleset **"CI Gate" (16134995)** makes `gate (required)` a required status check on
`main` with `bypass_actors: []`, and a required check is evaluated **at push time
against the pushed tip** — so a commit that has never been through a check run is
rejected before any check could start. Every run ends:

```
remote: error: GH013: Repository rule violations found for refs/heads/main.
remote: - Required status check "gate (required)" is expected.
 ! [remote rejected]     HEAD -> main (push declined due to repository rule violations)
```

| workflow | schedule | evidence |
|---|---|---|
| `context-cost-trend-cadence` | daily `23 7 * * *` | run 32559948214 + 3 predecessors |
| `manifesto-citation-snapshot-cadence` | daily `37 6 * * *` | run 32558211949 + predecessors |
| `budget-snapshot-cadence` | weekly `23 16 * * 0` | run 31959534906 — **weekly, so each failure sat red a full week** |

The ruleset is intended and is **not** weakened here. The lanes are what was out of date:
this is the same cutover `tick-metrics`, `society-heartbeat` and the red-state lane already
made, and which `CLAUDE.md` already documents ("telemetry lanes no longer push to `main`
… they park on `heartbeat/*` and flush via PR").

## The fix

Each lane moves onto the existing, proven
`src/Core.TypeScript/forge-host/github/flush-via-staging.ts`: `prepare` (branch off
`origin/main`, union in anything still parked from an unlanded previous flush) → generate
→ `flush` (commit, push `heartbeat/<lane>`, open/reuse a PR, arm squash auto-merge).

Nothing is disabled, no tolerance is widened, no `continue-on-error` is added. The data
still has to land on `main`; it now takes the route that is legal.

Incidental simplifications that fall out of using the shared tool:
- The hand-rolled `Inspect diff` steps are gone — `flush` stages the paths and returns a
  clean no-op when nothing changed (idempotency, discipline #6). For the manifesto lane
  that also preserves the untracked-new-file case the old guard was written for (#4758),
  because `git add <dir>` picks up untracked files.
- The hand-echoed AgencySignature blocks are gone — `flush-via-staging.ts` signs at the
  shared choke point, so the three copies can no longer drift from each other, and the
  block reaches `main` on the squash body rather than being discarded with the branch
  commit.
- Two stale claims in the headers are retired: "Actions is not permitted to create pull
  requests" and "GITHUB_TOKEN-created PRs don't fire required checks" are both handled by
  the flush tool's PAT ladder, which degrades to parking-only (never data loss) when no
  PAT is present.
