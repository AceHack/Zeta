## What

Adds a Cursor Cloud Agent environment so agents boot with Zeta's core development gate ready to run:

- `.cursor/environment.json` — repo-managed environment config (`install: bash .cursor/install.sh`).
- `.cursor/install.sh` — idempotent, scoped bootstrap.
- `src/Core.TypeScript/hygiene/check-bash-retirement-inventory.ts` — allowlists `.cursor/install.sh` (setup/bootstrap shell that runs before Bun exists).

## Why

There was no `.cursor/environment.json`, so Cloud Agents started with no `.NET`, `bun`, or `mise` — nothing could build or test. This provisions the day-to-day loop:

- **.NET 10 SDK** → `dotnet build` / `dotnet test` (the `TreatWarningsAsErrors` gate).
- **Bun + Node + TypeScript tooling** → `bun test`, `tsc`, `eslint`.
- **Go, Rust, Java, Python + language linters** → what `bun run preflight` runs (`shellcheck`, `actionlint`, `golangci-lint`, `markdownlint`, `semgrep`, `yamllint`, `ruff`, `mypy`).

All runtime versions are sourced from the repo's own `.mise.toml` (single source of truth), so this environment never drifts from `CONTRIBUTING.md` and CI.

## Scope decision

`.cursor/install.sh` is a deliberately **scoped subset** of the full `tools/setup/install.sh`. It omits the heavy formal-verification proof stack (Lean / TLA+ / Alloy / TLAPS-via-opam-source-build / Agda), the local LLM (ollama), QEMU/USB-ISO, R, and the Kubernetes tool set — none of which the build + test + lint loop needs, and all of which add large/slow/flaky downloads. Contributors needing the full proof/cluster toolchain still run the canonical `tools/setup/install.sh`. Host tier is pinned to `standard` to skip the full-tier k8s mise set.
