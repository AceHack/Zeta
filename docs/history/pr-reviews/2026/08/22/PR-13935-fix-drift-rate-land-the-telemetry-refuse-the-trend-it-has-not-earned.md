## Description


The drift-rate tracker was green on every tick and produced nothing. Three
defects, all measured against the code on main before changing it, none of
them visible from the outside — which is the class.

1. THE DATA NEVER LANDED. The `Record CI drift` step ran
   `git add data/ci-runs.jsonl` and the next step ran `git push`. Git does not
   push a staged-but-uncommitted file, so every tick appended a line to a
   working-tree file that was discarded with the runner. `data/ci-runs.jsonl`
   has NEVER existed on main: `git log -- data/ci-runs.jsonl` is empty and the
   path is absent from `git ls-files`. Same silent-no-op as `lockfile-healer.yml`
   and `zetadb-scheduled-node.yml`. Now committed, with an AgencySignature, and
   flushed via the `heartbeat/*` staging path the step already used correctly.

2. CANCELLED LAUNDERED A DARK LANE INTO GREEN. `greenRatio` was
   `green / (green + red)` — cancelled dropped from the denominator. Probed on
   main: a lane with 33 cancelled runs and 2 stale successes reported
   `greenRatio: 1`. **100% green for a lane that had not concluded anything in
   weeks.** `tlaps-proof` is the live shape (33 cancelled + 7 failure in its last
   40 runs, last success 2026-07-01). Cancelled is now its own state, stays in
   the denominator, and can never move the green ratio up. Both readings are
   reported side by side, because neither alone is honest: `gate` is cancelled by
   its own concurrency group on ~88% of pushes and is perfectly alive. Darkness
   therefore keys on TIME SINCE A CONCLUSION, not on cancelled count — the same
   discriminator `drift-dashboard/fold.ts` already chose.

3. A TREND OFF ONE SAMPLE. Probed on main: one green run printed
   `"7d: 100% green (1/1) ... trend: stable"`. Every rate now carries a Wilson
   score interval (Wilson 1927 — chosen over Wald specifically because Wald
   degenerates to zero width at p-hat = 1 and would report a CERTAIN 100% off one
   run), `insufficient-data` is the DEFAULT verdict, and a trend is named only
   when both halves clear a minimum sample AND their intervals are disjoint. A
   `null` point estimate is returned for n=0 rather than `0`, so "no data" can
   never render as "0% green".

RECONCILED WITH THE DRIFT DASHBOARD (#13835) AS COMPLEMENTARY, NOT DUPLICATE.
The dashboard answers "what is true now, and what have I failed to observe"
(per-check last verdict, coverage-as-output). This answers "is it getting better
or worse" (sliding windows over recorded outcomes). Neither can produce the
other's answer: a latest-verdict-per-check has no history in it, and a log only
ever contains what someone recorded. They now SHARE A CHECK IDENTITY VOCABULARY —
this module keys on `CheckId` from `forge-host/types.ts` and takes
`db/drift-dashboard/roster.json` as its denominator. The heartbeat used to record
`--workflow "heartbeat-$AGENT"`, which is in no roster; it now records
`--check agent-heartbeat --lane $AGENT` (hub/satellite, DV2.0), so three agents
report against one rostered check instead of minting three the dashboard has
never heard of. A recorded id the roster does not know is flagged `unrostered`,
loudly.

THE ROSTER IS THE DENOMINATOR, so a lane that stops reporting cannot improve the
numbers by leaving. Probed on main: one healthy lane plus one that went silent ten
days ago summarised as "100% green". A rostered check with no sample in the window
is now a row — `went-silent` if it ever reported, `no-data` if it never did — and
unknown outranks red in the worst-first ordering, because an unmeasured lane is an
unbounded number of unknown failures and a red one is a bounded, known failure.

`--report 2>&1 || true` IS GONE, AND THE STEP IS STILL NON-FATAL. Swallowing the
status is defensible for telemetry, but `|| true` alone makes a permanently-broken
reporter and a working one byte-identical forever. The status is now captured and
announced as a `::warning::` instead of discarded. The reporter exits 0 whether the
news is good or bad — it is a measurement, not a gate (SDV) — and non-zero only
when the reporter ITSELF failed, so a warning is never noise. Same shape as the
`Verify RS block integrity` step above it; this step was the odd one out.

FALSIFIERS. `drift-rate.test.ts`, 32 tests / 84 assertions, each case reproduced
against the old implementation first and its actual output quoted in the test.
Eleven hand-applied mutants, each byte-verified with `cmp` as landed before its
result was read: 11/11 killed. The twelfth pass found a REAL survivor — flipping
the DARK band from first to last in the worst-first ordering changed nothing any
test could see, because the ordering test used a `no-data` check. A falsifier for
it was added and the sweep re-run clean. Restore byte-verified byte-identical.

WHAT IS STILL TOY, said out loud: `MIN_SAMPLES_FOR_TREND = 8` and
`DARK_AFTER_MS = 72h` are chosen, not derived, and nothing yet measures whether
they are right. The properties the tests falsify are `metered`; the thresholds
are not, and the module says so.

A FOURTH CONSUMER, CAUGHT BY CI MID-FLIGHT. `society-status.ts` gained a
drift-rate integration in #13928 while this was being written, and it read the log
with its own `loadJSONL` and passed the result in as `computeDrift(ciRuns as any)`.
That cast was the whole risk: `computeDrift` keys on `checkId`/`outcome`, a raw
legacy line carries `workflow`/`conclusion`, and `as any` let ten SUCCESSES through
as `{total:10, green:0, red:0, cancelled:10}` — measured, not inferred. It is now
routed through `loadCIRuns`, shares the roster, and both halves are pinned by tests.
The legacy shape is SUPPORTED, and only at the boundary that normalizes it.

NOT BUILT HERE: the claimed-vs-measured divergence meter. Work-item
081M0NKYZ14087G0R001DPSS8G names the seam — the claim must be recorded BESIDE the
outcome, sharing its key, in two registers that never cross — and records why it
is a governance surface rather than a telemetry one. Naming it is the whole of the
scope; no divergence meter is in this PR.
