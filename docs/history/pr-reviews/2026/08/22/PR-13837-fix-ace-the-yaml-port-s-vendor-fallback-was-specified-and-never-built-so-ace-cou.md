## Description

`ace`'s `loadDependencyGraphFromFile` failed on
`full-ai-cluster/k8s/sync-wave-dependency-graph.yaml` with
`YAML parse failed: UnsupportedConstruct`, and two tools had already routed around
it (`cluster/derive-sync-waves.ts`, `cluster/lane-partition.ts`) by importing the
`yaml` npm package. Aaron asked whether ace could tell us which Helm app groups are
independently testable; ace is the natural home for that question and it could not
read the input.

WHAT THE UNSUPPORTED CONSTRUCT ACTUALLY IS

  Prefix-bisecting the file through `tryReadEvents` puts the first decline at line
  94, `      reason: >-` — a FOLDED BLOCK SCALAR. A full scan finds two constructs,
  not one:

    - block scalars (`>-`, same class as `|`)  — 44 occurrences
    - non-empty flow sequences (`dependsOn: [cilium]`) — 28 occurrences

  Empty flow `{}` / `[]` was NOT involved: 081KT7YW00008QG0R002T1XNWT already
  tokenises those into empty container event-pairs.

WHY THE HAND-ROLLED PARSER IS NOT THE BUG

  The obvious reading — "a hand-rolled YAML parser in a package manager is a
  recurring-bug generator, replace it with the library" — is wrong here, and the
  repo says so in three places written before this defect existed.

  `src/Core.TypeScript/yaml/reader.ts` is one of SIX byte-locked oracles (TS, F#,
  C#, Rust, Go, Python) and its subset is an operator-locked decision. From
  `docs/agendas/ace-package-manager/2026-06-01-yaml-port-forward-only-one-pass-cross-language-primitive-design.md`
  Decision 2:

      "Anchors/aliases, tags, multi-document streams, flow style ({} / []), and
       block scalars (| / >) are out of scope for the hand-rolled default; THE
       WRAPPED VENDOR ADAPTER COVERS THEM WHEN A USE CASE NEEDS THEM."

  `reader.ts`'s own header says out-of-subset input declines "so a caller can fall
  back to a vendor adapter", and the LOCKED contract in the implementation plan
  repeats it verbatim. So the construct was never unsupported by oversight — it was
  delegated, and THE DELEGATE WAS NEVER BUILT. That is the defect: not a missing
  construct, a missing fallback.

  Widening the subset in TS alone would make TS accept what Rust refuses, with no
  check able to see the divergence — the byte-lock only holds because every oracle
  declines the same inputs. 081KT7YW00008QG0R002T1XNWT, the one prior subset change
  (for empty `{}` / `[]`), says it in its own body: "do NOT do unilaterally".

WHAT CHANGED

  - `src/Core.TypeScript/yaml/vendor.ts` (new) — the wrapped vendor adapter, over
    `Bun.YAML`. Decision 3 of the same design names it: "Bun.YAML is a Bun built-in
    (BCL-tier) so the TS adapter may call it directly." That means ZERO new packages
    in ace's closure, which keeps `clone-at-tag-stays-sufficient` intact, and it is
    an implementation independent of the `yaml` package the cluster tools use — so
    the agreement check below is evidence rather than a tautology.
  - `src/Core.TypeScript/ace/deps.ts` — `parseYaml` calls `parseWithFallback`: our
    subset reader FIRST, the adapter only on a typed decline. `parseYamlVia` exposes
    which reader answered.
  - `dom.parse` and `reader.ts` are UNTOUCHED. The TS cross-verify regenerates
    `ts-output.json` byte-identically (15/15 vectors, exit 0), so the six-oracle
    byte-lock is exactly where it was.

TWO HARDENINGS THE MEASUREMENT FORCED, both of which a naive fallback would have
gotten wrong:

  1. THE FALLBACK ANSWERS `UnsupportedConstruct` ONLY. Measured 2026-08-22:
     `Bun.YAML.parse("a:\n\tb: 1\n")` returns `{a: null, b: 1}` — silently accepting
     a tab in indentation that YAML forbids, that our reader declines
     (`TabIndentation`), and that the `yaml` package rejects outright ("Tabs are not
     allowed as indentation"). A blanket "decline => vendor" would have traded a
     correct refusal for a lenient misreading. The other four feedbacks describe
     MALFORMED input, not out-of-subset input, and stay refusals.

  2. MULTI-DOCUMENT INPUT IS REFUSED, NOT FLATTENED. Measured:
     `Bun.YAML.parse("a: 1\n---\nb: 2\n")` returns `[{a:1},{b:2}]` — structurally
     indistinguishable from a single document whose root is a sequence. `YamlValue`
     has no stream form, so converting that would be a parse that succeeds and is
     wrong. The adapter refuses on a column-0 document marker instead.
