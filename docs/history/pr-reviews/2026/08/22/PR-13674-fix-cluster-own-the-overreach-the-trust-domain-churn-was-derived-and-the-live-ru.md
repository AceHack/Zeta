The proof landed and it corrected me. Run 32569702770's `live kind included
Synced+Healthy proof` shows `openziti-controller  Synced  Healthy  3.1.1`, the
pod 1/1 Running, and `bundle/ziti-controller-ctrl-plane-cas ... Successfully
synced Bundle to all namespaces` — the exact object that could never be written
before. Both blockers are closed by measurement, not by argument.

The same log refutes a claim I made in passing. The note I added about
`ziti-controller-trust-domain` said the Application "sits OutOfSync and
`selfHeal: true` rewrites the SPIFFE trust domain on every reconcile". That was
DERIVED from the render being nondeterministic; it was never observed. In that
run openziti-controller reported Synced+Healthy on all four samples and never
once OutOfSync.

So the claim is narrowed to what is measured. The render IS nondeterministic
(two local `helm template` runs at these values differ in exactly that line).
The ArgoCD-level churn is NOT observed. The exposure that remains is that a
re-render — new revision, cache eviction, repo-server restart — can change the
trust domain under a controller that has already issued identities against the
old one, and nothing observed says that has or has not happened. A candidate
explanation (ArgoCD caches generated manifests per revision, so the random value
is drawn once) is written down as a candidate and explicitly not as a finding.

The correction is left visible in the manifest rather than the sentence being
quietly replaced, because the overreach is the instructive half: a consequence
reasoned from a real mechanism still has to be looked at before it is asserted.
