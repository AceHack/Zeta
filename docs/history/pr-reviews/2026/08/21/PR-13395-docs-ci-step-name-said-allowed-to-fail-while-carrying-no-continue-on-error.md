## Description

`chart-version-refresh.yml`'s refresh step was named `(network; allowed to fail)` and has **no** `continue-on-error`. It fails for real, and the diff it leaves behind is the point.

Reading that name, I went looking for the missing flag — and was one keystroke from adding it. That would have turned the job green and buried the signal.

The confusion has a concrete cause worth recording: **this file uses both senses of the phrase, eight lines apart.**

| step | "allowed to fail" means |
|---|---|
| Refresh the published-version snapshot | the **job** is outside the required set — the step still goes red |
| Currency report drift | the literal `continue-on-error: true` flag |

The author knew the flag, used it deliberately on one step, and deliberately withheld it on the other — which makes one phrase covering both the actual defect. This renames the first step to `(network; red here is the signal, non-required job)` and names the contrast in the comment above it.

**No behaviour change** — step, exit code, `if: always()` artifact upload, and required-set membership all untouched. `actionlint` clean.

Supersedes #13392, which asserted `Human-Review: explicit` / `Human-Review-Evidence: chat`. The forge check correctly reported that as UNVERIFIABLE: chat authorization to *make* an edit is not a review of the resulting diff, and an unverified claim must not be spent as a verified one.
