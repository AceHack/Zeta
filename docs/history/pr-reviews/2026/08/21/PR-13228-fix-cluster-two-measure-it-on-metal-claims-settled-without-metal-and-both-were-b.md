## 1. A pure-eval rebuild silently un-provisions a node

`injected-cluster-address.nix` and `injected-join-server.nix` both carried
`UNVERIFIED: this module has not been evaluated by a nixos-install or a
nixos-rebuild`. Part of that needs a booted guest. The part that decides whether
the module runs at all did not — `nix` is installable anywhere, so this was a
five-minute measurement.

Measured on Determinate Nix 3.21.0 / Nix 2.34.6, aarch64-darwin:

```
$ cat flake.nix
{ outputs = { self }: { p = builtins.pathExists "/etc/hosts"; }; }
$ nix eval .#p              # pure eval — the default for a flake ref
false                       # /etc/hosts EXISTS. Pure eval says it does not.
$ nix eval --impure .#p
true
```

and unguarded:

```
{ outputs = { self }: { r = builtins.readFile "/etc/hosts"; }; }
$ nix eval .#r
error: ... forbidden in pure evaluation mode
```

**The two builtins fail differently, and that difference is the bug.** `readFile`
refuses loudly; `pathExists` returns `false` quietly. Every module under
`full-ai-cluster/nixos/modules/` that reads `/etc/zeta` guards its `readFile`
behind a `pathExists` — correct defensive style, which converts the loud refusal
into a silent no-op.

`zeta-install.sh` already passes `--impure` to `nixos-install`, and its comment
explains why: *"flake pure-mode refuses non-store absolute paths"*. That is the
`readFile` half only, and it is wrong in the direction that hurts — the team
believed this failure was loud.

Meanwhile **not one `nixos-rebuild ... --flake` string in the repo carried
`--impure`** — eight sites, including the three the installer itself prints when
it finishes. Running the command the installer hands you silently:

- reverts `networking.hostName` to the flake host's hardcoded name (every node
  becomes `control-plane` again — the exact mDNS collision `injected-hostname.nix`
  exists to prevent)
- reverts `services.k3s.serverAddr` to `k3s-agent.nix`'s mkDefault and drops the
  static cluster-segment addressing, so a joiner stops reaching its founder
- contributes `[ ]` from `operator-authorized-keys.nix`, i.e. **removes the
  operator's captured pubkeys from `authorized_keys`**. On a node reachable only
  over SSH that is a lockout, produced by a routine update.

**Fix:** `--impure` at all eight sites; the measurement recorded in each of the
four affected modules and in `zeta-install.sh` (replacing the wrong claim); new
`lint-nixos-rebuild-needs-impure.ts` + suite wired into the gate. No exemption
marker, deliberately — an escape hatch here would be used by the first person who
found the flag inconvenient.

`PROVISIONING.md`'s remote form gets `--impure` **and** a caveat that eval runs on
the admin box, so the impure reads see the admin's `/etc/zeta`, not the target's.

## 2. The join token's CA hash was never checked

`firstboot-role.ts` justified requiring `https://` as *"the node-token crosses
this connection"*, implying TLS is what protects it. Read k3s
`pkg/clientaccess/token.go`:

- `parseToken` does **not** reject a token lacking the `K10` prefix — it rewrites
  it to `K10:::<password>`, so `caHash` becomes the empty string.
- `getCACerts` downloads the cluster CA from `/cacerts` using `insecureClient`,
  declared in that same file as `tls.Config{InsecureSkipVerify: true}`.
- `validateCAHash` with an empty `caHash` and a non-empty CA bundle emits
  `logrus.Warn(...)` and **returns nil**. The join proceeds.

So on a self-signed cluster `https://` protects nothing at bootstrap, and
`--join-token <path>` copied whatever file it was handed — `zeta-install.sh`
checked only that it was non-empty. A bare shared secret (`K3S_TOKEN=hunter2`,
an extremely common k3s pattern) produces a joiner that accepts whatever CA
answers first on the segment and then presents the cluster credential to it.

Refusing the shape costs a correct operator nothing: `server/token` and its
`node-token` symlink (`pkg/server/server.go` → `handlers.WriteToken` →
`clientaccess.FormatToken`) always carry `K10<sha256hex>::`.

**Fix:** `validateJoinTokenMaterial` refuses anything but
`K10<64 lowercase hex>::<creds>` — lowercase because `hex.EncodeToString` emits
lowercase and `validateCACerts` compares with `==` — called from the zflash CLI
before any command runs, and re-checked in `zeta-install.sh` (last guard, different
substrate, bytes came off a FAT filesystem).

## 3. Corrected, not fixed

`cluster-address.ts` asserted *"k3s does not set `InsecureSkipVerify` on the agent
bootstrap path"*. False — it does, for the `/cacerts` download. The conclusion
(a `.local` name is rejected) survives, by a different route: `getCACerts` makes
three requests and the third, `GetHTTPClient(cacerts, "", "")`, populates `RootCAs`
and leaves `InsecureSkipVerify` at zero. The comment now says so.

Its `UNVERIFIED` label is **narrowed, not removed**: rancher/dynamiclistener can
mint certs covering a requested host, and whether that path reaches the port a
joiner dials was not settled here. Stated rather than promoted.
