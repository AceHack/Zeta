## Description

## The gap

`audit-observability-chain` exists to refuse "a dashboard, alert, or scrape target that looks wired but is fed by nothing". It proved the ruler **selects** the monitoring object (rule 7) and that Argo **applies** the file (rule 8) — and never asked the one question that decides whether a single byte moves:

> does the ServiceMonitor's selector match a Service, and does `endpoints[].port` name a port that Service declares?

A ServiceMonitor *is* a scrape target. It was the last link in the chain with no guard.

## Proof (measured on `origin/main` @ `e5e11056d5`, before this rule existed)

Four independent ways of severing the portal scrape, each applied to a copy of the real tree:

| mutation | audit verdict |
|---|---|
| Service port renamed `metrics` → `http-metrics` | `PASS: 7 invariants hold` |
| selector label no Service carries | `PASS: 7 invariants hold` |
| `namespaceSelector` naming the wrong namespace | `PASS: 7 invariants hold` |
| port given as the **number** `8080`, not a name | `PASS: 7 invariants hold` |

`endpoints[].port` is a **Service port NAME** — not a container port name, not a number. Get it wrong and prometheus-operator emits a scrape job whose endpoint role selects zero addresses. **Zero endpoints is not a DOWN target, it is NO target**: `up{}` has no series at all rather than the value `0`, so a panel counting healthy targets stays green *because nothing reported*.

That is this repo's defining failure mode, at the one layer that had no guard. The tree's own PrometheusRule comment already named it — "ServiceMonitor not selected, wrong port, service port name" — as something only `ZetaPortalNotScraped` would catch, at 3am, in production. Rule 9 catches it at PR time.

## The rule is not vacuous

All four mutations above are now falsifiers in the suite. Disabling `checkServiceMonitorTargets` (early `return []`) turns **5 of the 8 new tests red**.

## Soundness and named limits

Candidates are matched on `selector.matchLabels` only. `matchExpressions` can merely **narrow** the matched set, so the candidate set is a *superset* of the true one — every failure reported is a real failure (no false positives).

Limits are named and asserted, never silent:
- **PodMonitor is not modelled** — the tree authors none, and an unexercised branch is exactly the vacuity this audit exists to refuse.
- An endpoint selecting by `targetPort` rather than `port` is **left unjudged** rather than guessed at.
- A `matchExpressions`-only selector is explicitly asserted to make no claim.

Scope matches the existing `checkScrapeOptIn` doctrine: a ServiceMonitor authored *here* must target a Service authored *here*. A chart-rendered workload's ServiceMonitor is that chart's job to ship, and the roster carries port **numbers** only, so it cannot answer a port-**name** question.
