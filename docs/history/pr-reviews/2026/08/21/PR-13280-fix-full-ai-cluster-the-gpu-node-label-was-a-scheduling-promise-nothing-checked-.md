## Description

`nixos/modules/gpu.nix:76-78` emitted `--node-label=zeta.io/gpu=nvidia`
UNCONDITIONALLY. Every host importing that module advertised an NVIDIA GPU to
the Kubernetes scheduler whether or not one was present — and every GPU host in
this tree carries a placeholder hardware-configuration.nix, so nothing in the
repo has ever established that any of them has a card. A pod placed there by
the label fails at runtime instead of staying honestly Pending.

WHAT SELECTS ON THE LABEL TODAY (measured, not assumed)

Three consumers, exactly one of them live:

  - nixos/modules/gpu-device-plugin.nix:85-86 — the NVIDIA device-plugin
    DaemonSet's `nodeSelector: zeta.io/gpu: nvidia`. LIVE:
    hosts/worker-gpu/configuration.nix:32-35 sets
    `zeta.gpu-device-plugin.enable = true`, so k3s applies that manifest from
    `services.k3s.manifests` at first boot. (The audit note that prompted this
    said the plugin "is never applied cluster-side"; that is FALSE — the enable
    is there and the manifest ships.)
  - k8s/applications/vllm/deployment.yaml:23-24 — masked by `replicas: 0` (:16).
  - k8s/applications/ollama/Application.yaml:54-55 — masked by
    `replicaCount: 0` (:34) plus manual-only sync.

Both workloads ALSO request `nvidia.com/gpu: 1`, an extended resource a
GPU-less node cannot advertise, so the resource request is a second and honest
gate behind the label. The DaemonSet has only the label. Net: the severity is
moderated but the label is not decorative, and it is wrong.

WHY A BOOT PROBE AND NOT A BUILD-TIME CONDITIONAL

NixOS evaluates on a build machine; whether a card is seated is a runtime fact
about the target box, and the host configs carry no second-hand claim to
condition on. A build-time `if` here would be a guess wearing a conditional's
clothes. So the shape is the one longhorn-node-preflight.nix (#13252)
established: a oneshot that probes real hardware at boot and refuses with a
named remedy.

WHAT CHANGED

  - nixos/modules/gpu-node-label-checks.nix (new, pure) — from ONE `vendor`
    value it produces both the `--node-label=` flag and the sysfs probe script.
    gpu.nix now takes the flag from here rather than restating the string, so
    the claim and the check cannot drift apart.
  - nixos/modules/gpu-node-label-preflight.nix (new) — the oneshot.
    `before = k3s.service`, `wantedBy = multi-user.target`, no Restart. Refuses
    when the claimed vendor has no display-class device on the PCI bus, and
    separately when every such device is bound to vfio-pci (a card owned by a VM
    is not available to pods). Console markers
    ZETA_GPU_NODE_LABEL_PREFLIGHT_OK / _FAILED.
  - nixos/modules/gpu.nix — imports the preflight; the label is now generated,
    not literal. The label is NOT deleted: a worker-gpu that stops advertising a
    GPU it HAS would be its own regression, and the eval test pins that it is
    still emitted.
  - nixos/tests/gpu-node-label-preflight-eval-test.nix (new) + the flake check
    `gpu-node-label-preflight` — 26 properties, evaluated by the existing
    `nix flake check --no-build` step, reading the REAL
    nixosConfigurations.worker-gpu rather than a stub.

The claim and the check share ONE switch: gpu.nix gates the label on the
preflight's own `enable`, so there is no reachable configuration that advertises
a GPU with nothing verifying it. An `enable` that silenced only the check would
have been a new way to reintroduce exactly this defect.

nvidia-open-guard.nix: A GUARD THAT HAD NEVER RUN IS NOW REACHABLE

Its boot-time driver-bound probe was `lib.mkIf useOpen` while gpu.nix ships
`open = lib.mkDefault false` and no host overrides it — so gate 2 of the "two
independent gates" the header advertised was instantiated on zero hosts and had
executed zero times. nvidia-open-guard-gate.nix:85-86 even PINNED that absence
as intended. The `mkIf` is removed: the unit now installs on every host
importing gpu.nix, because "did the nvidia driver bind" is worth an answer under
the closed module too, where nothing else asks it. `useOpen` now selects only
the remedy text. The zero-device case moved OUT of it (that is the label
preflight's question now) and is declared vacuity there rather than a second
refusal. The gate test's A/D checks are inverted to pin REACHABILITY in all four
states, with a control proving the presence test can read false.

infra/ — RECORDED, NOT FIXED, AND SAID SO IN THE FILE

infra/nixos/modules/gpu.nix carries the same unconditional label and
infra/nixos/modules/nvidia-open-guard.nix the same inert `mkIf`. Not copied
there: the ROOT flake's `checks` is empty and no workflow runs `nix flake check`
at the repo root, so a copy would be a second unrun guard rather than a fix —
the very defect class this change removes. Both files now state that precisely,
with what would settle it.

MEASURED vs DESIGNED-BUT-UNRUN

MEASURED here: `nix eval` of every x86_64-linux flake check (green);
`bunx tsc --noEmit` exit 0; `lint-guards-are-reachable` exit 0;
`nix-instantiate --parse` on all six .nix files touched. Eight mutations, each
byte-verified against a pristine copy with `cmp` before its result was read —
all eight turn a check red. One (the device-plugin selector rename) SURVIVED its
first form: the needle was a prefix, and `zeta.io/gpu: nvidia-renamed` still
contains `zeta.io/gpu: nvidia`. The needle now carries its terminating newline
and the mutant dies. Removing the preflight import does not merely fail the
test, it fails EVALUATION — gpu.nix cannot produce the label without the module
that defines the option.

NOT RUN: the probe itself. Nothing here boots a node or touches a PCI bus, and
no host in this repo records having a GPU. What settles it is one clean metal
boot on a GPU worker showing ZETA_GPU_NODE_LABEL_PREFLIGHT_OK with devices >= 1,
and — for the nvidia-open-guard unit — that same boot reaching "all N NVIDIA
display device(s) bound".

SEVERITY IS DELIBERATE: `before = k3s.service` puts the verdict on the console
before kubelet registers the node, but the unit is `requiredBy` nothing, so a
false positive on unrun code cannot cost an operator the cluster. The two
upgrades (hard-gating k3s; emitting the label FROM the probe via a
config.yaml.d drop-in so a GPU-less node carries no label at all) are named in
the module header along with the evidence that licenses each.
