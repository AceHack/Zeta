## Description

Both authorized fixes. **The deciding argument for Vault turned out to be mechanical, not stylistic.**

## Vault: ArgoCD wins — bootstrap ownership was UNWORKABLE, not merely redundant

The brief's reasoning held: **every active Vault dependency in the tree is a comment.** `spire-install.yaml`
has zero `upstreamAuthority` keys; `external-secrets` — checked specifically because it might genuinely
need Vault early — has **exactly one SecretStore-shaped hit across both trees, and it is a comment.**

**But the argument I did not have is the one that settles it:**

> **Vault's PVCs pin `storageClass: longhorn`. Longhorn is installed by the ArgoCD Application at
> sync-wave `-15`. The k3s first-boot roster installs no longhorn at all.**

**So the bootstrap Vault could never bind storage.** Independently verified before landing: `storageClass:
longhorn` at lines 26 and 30, **zero** occurrences of longhorn in `k3s-server.nix`, and
`applications/longhorn` at wave `-15`. The contrast is instructive — SPIRE uses `zeta-local-path`, which
*is* provided at boot, so **SPIRE genuinely can be a bootstrap citizen and Vault never could.**

**Rendered before/after:** the bootstrap owner produced `storage "file"`, the ArgoCD owner produces
`storage "raft"`. **After the change the `storage "file"` renderer no longer exists** — the selfHeal flap
between two storage backends is gone.

### A new blocker found while rendering — recorded, not silently fixed

The surviving config carries `podAntiAffinity: requiredDuringScheduling` on `topologyKey:
kubernetes.io/hostname` with `replicas: 3`. **On a single-node control plane exactly one of three pods can
schedule, so a 3-member raft never reaches 2/3 quorum and Vault never unseals.**

**`replicas: 3` was left deliberately** — lowering it to 1 would discard the raft design without a
decision, which is the instruction inverted. Filed as a workitem with the re-confirmed readiness-probe
defect.

### The mechanical constraint was proven, not assumed

`validate-bootstrap.ts` checks the roster **both directions**, and each was made to go red on a
half-removal *before* the real change was trusted. Full-ai-cluster: **57 → 52 passed, both exit 0**, zero
vault mentions remaining. `nix-instantiate --parse`: exit 0.

**The two false comments were deleted in the same commit as the fix**, per the audit's own recommendation.

## The ratchet — baseline is 23, not 29, for a reason that matters

**The validator-scope gap was fixed FIRST, because a ceiling that banks false reds can be "improved" by
fixing nothing.** Measured: **7 of the 29 were validator-scope, not 3** — six from OCI apps being asked for
`/index.yaml`, and one nobody spotted: Test 6 hardcoded `root-application.yaml`'s location, but this tree
keeps it in `bootstrap/` because k3s applies it at first boot.

**29 − 7 + 1 = 23** — the OCI fix **added one genuine failure it had been masking.**

**Four falsifiers, all run:** equal → exit 0 · lower baseline → **REGRESSION** · **higher baseline →
IMPROVEMENT NOT RECORDED**, printing the exact line to commit, *so the ceiling cannot rot upward-only* ·
absent validator → **`MEASUREMENT NOT TRUSTED — an empty or unparseable run is NOT zero failures`**, the
mise-trust trap encoded as a refusal.

### A hazard found by running it twice

**The measurement is not perfectly stable.** Two identical runs minutes apart returned **23 and 24** — the
extra entry being **helm itself crashing with a Go runtime panic**, a tool crash, not a manifest defect.
**An exact-match gate that reds on that becomes the muted lane, which is the failure the ratchet exists to
prevent.**

So it **confirms before accusing**: a second measurement is taken *only* when the first disagrees; two runs
that agree are believed; two that **disagree** are `MEASUREMENT NOT TRUSTED`, naming what moved. **It stops
at two, so it cannot retry until the number is convenient.**

An `--offline` flag was **removed**: offline measures 13, render measures 23, **so a green offline run
could be mistaken for the gate passing.** One mode, one number.

**Caveat carried in the baseline rather than buried:** several of the 13 contract failures are probably
**deliberate** — `root-application.yaml` documents an either/or convention where alternatives omit
`automated:`, covering 4 of the 13. **Adding those blocks to lower the number would silently switch
manual-sync alternatives to auto-syncing.** There the *validator* needs to learn the convention.

## The other six — reported, not fixed, and one is worse than expected

**The `argo-cd` twin's own comment claims *"Mirror the bootstrap values so adopting this Application is a
no-op."* It does not mirror them.** Rendered: bootstrap → 40 docs, 3 dex refs; twin → **45 docs, 24 dex
refs**. **ArgoCD selfHealing itself would enable dex — an SSO component appearing with no commit that says
so.**

Recommendation is explicitly **not** "delete an owner": make the twin genuinely mirror all nine keys, land
that alone, verify, *then* choose. **Cilium keeps bootstrap ownership** (the CNI must exist before any pod
schedules). **Spire must be split, not deleted** — `spire-crds` is bootstrap-only and dropping it makes
spire fail `no matches for kind`. cert-manager, trust-manager, external-secrets are low-risk ArgoCD-only.

## Verified

`validate-bootstrap --infra-dir full-ai-cluster` **52 passed / 0 failed, exit 0**; the existing infra lane
**unbroken at 22/0**; `infra/k8s/tests` **22 pass / 0 fail**. **helm-validate confirmed NOT a required
check** — the only required context across all four rulesets is `gate (required)` — so a red ratchet does
not block merges.

**Two gaps not papered over:** the ratchet has **no mutation suite in CI** — all four branches were proven
by hand, but nothing re-proves them, *which is exactly the discipline `validate-*.test.ts` already meets
and this file does not.* And the contract check doesn't understand the either/or convention, **so 4 of the
23 may be the validator being wrong rather than the manifests.**
