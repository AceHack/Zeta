## Description

Aaron 2026-08-20: *"i'm trying to connect machines/nodes tpm to AI identity with their own
wallets"* and *"can we simulate process injected identity, SPIFFE or SPIRE related?"*

## The gap, named precisely

**SPIRE has two attestation layers. Zeta shipped one.**

| layer | SPIRE | Zeta before this |
|---|---|---|
| **Workload** attestation (process → agent, kernel-visible selectors) | `unix`, `docker`, `k8s` | present and complete |
| **Node** attestation (agent → verifier, hardware evidence) | `tpm_devid`, `k8s_psat`, … | **absent — no port, no type, no refusal** |

The existing docstring said *"none of it is implemented"*, which was accurate. **What it did not
say is which layer was missing** — and that was the actual gap.

## A new port, not new fields — adding fields would have been a category error, twice

1. **Freshness has nowhere to live.** `attest()` is a pure function over *passively observed*
   fields, and **a TPM quote is only evidence if it answers a nonce the verifier chose.** Adding
   `tpmQuote?` to `ObservedProcess` would have made that type's own docstring false and produced an
   attestor **that cannot tell a live quote from a replayed one.**
2. **The subject differs.** A workload attestor's subject is a *process*; a hardware root's is a
   *machine*. Merging them lets a machine-scoped fact be read as per-process — precisely the error
   that makes PCR-sealing look like container isolation.

## The bug the agent's own test caught

`bindWorkloadToNodeRoot` verified the signature against `attestation.signerPublicKey` — **a key the
attestation itself carried.** Trust-on-self: any party could mint a valid attestation for `node-a`.

**And it is the SPIRE difference surfacing as a defect.** In SPIRE the node's attestation key is
vouched for by an enrolment record the *server* holds. Zeta has no server, so **the relying party
must supply the expected key from its own trust bundle.** Fixed with `expectedNodePublicKey` and a
distinct `node-signer-not-expected` refusal — kept separate from `attestation-signature-invalid`
because they diagnose **opposite** things (wrong signer vs altered bytes), and collapsing them
would make the diagnosis a guess.

## What the module encodes

`ROOT_OF_TRUST_PROFILES` scores each device class on **four independent axes** — each row carrying
its citation — **because a single "is it isolated" boolean is what made the shared connector look
like a boundary.** The claim ladder is `node-bookkeeping → machine-rooted → tenant-rooted`, and the
**only** route to `tenant-rooted` is `evidenceBindsTenant`, so **a shared TPM has no route there
regardless of configuration.**

Checks run in a deliberate order — identity, freshness, signer, signature, evidence state, *then*
the claim ladder — **so authenticity precedes policy** and a forged attestation can never reach the
interesting refusal and be mistaken for a policy decision. `coverageStatementFor` generates the
coverage sentence **from the profile table**, so prose cannot drift from data.

## The container question, answered without softening it

The YubiHSM 2 **partially** enforces per-container key restriction:

| property | enforced? |
|---|---|
| A cannot **use** B's keys | **yes — device-enforced**, domain ∩ capability, per session |
| A cannot **deny** B its keys | **no** — 16 device-wide sessions; any legitimate tenant starves every peer, reachable **by accident** from a session leak |
| B's client path is protected from A | **no** — unauthenticated connector, *"not a trusted component"* |
| audit evidence survives an adversary | **no** — 62-entry ring; ~62 operations evicts the window |

**The shared TPM cannot enforce it at all — structurally, not partially.** `--device=/dev/tpmrm0`
is all-or-nothing; non-resettable PCRs are byte-identical for every container; **there is no PCR
policy that admits A and refuses B.**

Honest alternatives, ranked, **none of them "share the TPM"**: one device per trust domain · vTPM
per microVM (solves tenancy properly, costs a VM per tick source, and **roots no trust the host did
not already have** — its state is a file the host owns) · shared HSM with disjoint domains shipping
**the confidentiality half only** · TPM as the machine's root with something else as the agent's
key store.

## Advisory finding, filed rather than acted on

`full-ai-cluster/k8s/bootstrap/spire-install.yaml` installs **upstream SPIRE** — a central
`spire-server`, no node attestor configured (so the chart default `k8s_psat` applies), rooted in
the API server's projected token rather than any hardware. That's a **single appointed issuer**,
the shape §1 and the Itron hub-boundary rule both refuse.

> **The TS module and the cluster bootstrap are two different trust architectures sharing a
> trust-domain name.** Whether that's a deliberate cluster-grade compromise or drift is not this
> PR's call to make.
