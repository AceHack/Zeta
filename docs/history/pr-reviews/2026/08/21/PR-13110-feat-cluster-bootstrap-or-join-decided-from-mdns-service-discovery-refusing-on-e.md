## Description

> *"lets push this forward and make auto join more complete"*

The join itself was already real — `k3s-agent.nix` sets `serverAddr` + `tokenFile`, and `tests/k3s-agent-join.nix` is the two-node witness. What did not exist was the **decision**: a node had no way to answer *"am I the first, or is there a cluster here already?"* without a human pressing `c` or `w` inside a 10 s prompt.

## Discovery did not exist — and its absence was silent

`rg` over `full-ai-cluster` finds **zero** DNS-SD service definitions; `common.nix`'s avahi publishes the **host** record only. A probe browsing any service type would have found silence **on a healthy cluster** — and under a naive design that silence reads as "no cluster", which is exactly how a second cluster gets founded. So this adds the publisher first.

**mDNS has failed here twice, on the record** — `k3s-server.nix` ("`control-plane.zeta.local` was a dangling name that never resolved") and `injected-cluster-address.nix` ("mDNS was TRIED and did not resolve"). This therefore **never depends on mDNS name resolution.** It uses mDNS only for *service discovery*; the endpoint is still dialled by the name in the API cert with the address used for the `/etc/hosts` entry, exactly as `injected-cluster-address.nix` already does.

## The dwell — the crux you flagged

**30 s.** RFC 6762 §5.2 mandates a doubling retransmit from 1 s, so bursts land at t = 0, 1, 3, 7, 15 s, and §6 has responders answer after 20–120 ms. **Packet loss is covered inside ~3 s.** Everything past that buys against *the path not being ready*: 802.1D spanning tree holds a port through two forward delays (2 × 15 s). A node querying before its switch port forwards hears nothing — and a short dwell turns that silence into a split brain.

The costs are asymmetric, not 60×: 30 s paid once inside a multi-minute install, against a split-brain teardown.

**Register: `unmetered`.** The number comes from protocol timers and cost asymmetry. No two nodes have run this near each other; it is not metered until they do.

Two guards make it more than a wish — a silence is **inadmissible** if the dwell is under the floor, if the probe returned before its own dwell elapsed, or if fewer than five bursts were sent. The burst count is a **measurement** (passes that actually executed), not a claim.

## Refuse on every ambiguity

Two cluster ids · one id with disagreeing trust domains · a trust domain contradicting policy · anything malformed on our service type → **refuse**, naming both sides, even when a valid answer is also present. Several answers with the *same* id is HA, not ambiguity: join, endpoint chosen by a total ordinal order so two nodes hearing the same set pick the same one.

A failed probe never reads as absence — `probe-failed` carries `browser-missing` / `responder-unavailable` / `no-carrier` / `browser-error`, all refused.

## No token over mDNS

Backlog row `081KSE6WT0008QG0R000CV98PV` lists *"ship token via mDNS TXT (acceptable since the cluster network is trusted)"* as an acceptance criterion. **Refused** — in the module header and by a test.

Discovery finds an **address**; it does not mint credentials. The token still comes from the ESP or an operator, and nothing here reads, logs or transports one. What is advertised is the **public** half: `cluster` = sha256 of the k3s server CA, already a k3s concept (its token is `K10<sha256-of-server-CA>::<credential>`). A joiner can check the answering cluster is the one its token was minted by; an attacker on the segment can answer but cannot match a hash it does not hold. A cluster answering with no token available **refuses rather than bootstrapping**.

## Checked, not assumed

**79 pass / 0 fail**, 189 expect() calls; six mutations, each killed and reverted. Verified independently rather than taken on report: **adding a token TXT record to the publisher takes 79 → 78 pass / 1 fail**, so the no-token rule is mechanically enforced.

Cost measured by A/B on the derivation: `worker-gpu`'s toplevel drvPath is **byte-identical** with and without the module — "zero cost on agents" is proven, not asserted.

## Designed-but-unrun — do not read any of this as working

- **mDNS on a real network is unproven.** No avahi on the authoring machine, no two-node boot. The 30 s dwell is unvalidated until two nodes boot near each other.
- The publisher unit has **never been built or booted**.
- **`sha256(server-ca.crt)` == k3s's own `K10` digest is ASSUMED**, stated in the module. If wrong, a joiner supplying the pin refuses every join — fail-closed and discoverable, and the first thing to check on metal.
- **Nothing calls the decider yet**, deliberately: the installer ISO ships neither an mDNS responder nor `bun`, and `usb-nixos-installer/` was another agent's this round. The package is in no host closure. Wiring it is one `systemPackages` line plus `services.avahi.enable` — and **bun's ISO-size cost is UNMEASURED**, stated as a precondition, because a discovery feature that adds an unmeasured hundred megabytes to a USB image has not earned its slot.
