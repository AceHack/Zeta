## Description

`low-memory`'s `core-smoke (ubuntu-slim)` job failed **twice on the same commit** — both attempts of run 32526035691 — with the identical mechanism:

```
E: dpkg was interrupted, you must manually run 'sudo dpkg --configure -a'
apt-get install failed rc=100
apt-get install did not succeed within the 420s apt budget
```

Two attempts, one commit, same failure. **Not a flake.** The lane's mixed history (fail / ok / fail / ok / ok) is what a *marginal* budget looks like, not a random one.

I called this environmental earlier and only half-earned it. The npm half of the same-looking symptom turned out to be a committed `node_modules` symlink; this half is real — but it is a **budget** defect, not a transient one, and that difference matters: a transient clears itself, a budget does not.

## The fix the script names is unavailable

Its refusal says to raise the apt budget, but raise `timeout-minutes` first. **That lever does not exist here.** `low-memory.yml:99` pins `timeout-minutes: 14` explicitly to stay under `ubuntu-slim`'s **hard 15-minute runner-class cap**, and says so again in the header. The job cannot grow, so the budget inside it cannot either.

## The lever nobody pulled

The lane caches **four** things — .NET SDK, mise runtimes, elan, NuGet — and does **not** cache apt. The single step that fails is the only expensive one with no cache, re-downloading the whole set (cvc5, GHC libs, llvm-18, qemu-utils, …) every run inside a budget that cannot rise.

## Why it matters beyond one red lane

The header records that `ubuntu-slim` takes ~10+ minutes against ~1.5 on a normal runner, and that it was **removed from `gate.yml`'s matrix** for that reason — so this lane exists specifically as the slim-runner canary. A canary that fails often on its own toolchain install is one people learn to skim, and a skimmed lane is how the `Synced+Healthy` job concealed a real defect for 4.5 days earlier today. The failure mode isn't "red lane", it's **"lane nobody reads"**.

## Options, none chosen here

1. **Cache the apt archives** — the missing member of a set of four. Real work; the only option that keeps the canary honest.
2. **Shrink the install** — it mirrors `gate.yml`'s sequence by design, so diverging costs the parity the lane tests.
3. **Move off `ubuntu-slim`** — deletes the subject.
4. **Mark it non-blocking** — cheapest, and produces the skimmed lane above.

Filed rather than fixed: (1) is real work and the other three each trade away something the lane exists for. Not a knob to turn.
