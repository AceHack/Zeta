## Description

My change in #13053 wrote the per-ISO digest sidecar to `${iso_path_abs}.sha256`, which resolves under
`result/iso` — **a Nix store symlink.** The store is read-only, so the step failed:

```
result/iso/nixos-minimal-25.11.20260522.b77b3de-x86_64-linux.iso.sha256: Permission denied
##[error]Process completed with exit code 1
```

Measured in run `32445604341`, job `build-iso`, step **"Locate ISO + capture metadata"** — *the exact
step I edited.* This regressed the ISO build on `main`.

**Fixed forward:** the sidecar is written to `RUNNER_TEMP`, and the upload step publishes it under the
ISO's own name, so the operator still receives `<iso>.sha256`.

## Why it got through — stated so the lesson survives the fix

**`actionlint` passed before and after**, because this is not a syntax error — it is a filesystem fact
about where a Nix build output lives. The change was landed on the strength of a **measurement
elsewhere** (the Bitcoin Knots manifest collision, which is real and still motivates the per-ISO shape)
**without any execution of the changed step.**

The commit message said so at the time — *"the digest emission is DESIGNED-BUT-UNRUN … the first ISO
build after this lands is what proves it."*

> **And that is exactly what happened: the first build after it landed is what proved it wrong.** The
> register was honest, the risk was real, and the gap between them is a workflow step nothing can
> exercise short of running it.

Nothing else is affected — the digest computation, cosign signing and ISO upload are unchanged, and the
aarch64 job never had this code.
