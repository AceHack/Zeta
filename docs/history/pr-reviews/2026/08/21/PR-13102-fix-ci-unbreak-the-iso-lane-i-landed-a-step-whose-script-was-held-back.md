## Description

**I broke this, in #13093.** That PR added a `build-iso` step invoking `src/Core.TypeScript/hygiene/audit-flash-entrypoint-parity.ts` — a script that was part of a source half I deliberately held back while #13085 was in flight. The CI half landed without it. The step has failed on a missing file on every run since.

The blast radius is bigger than one red step: **the ISO upload, the digest sidecar upload and cosign signing are all gated behind it, so the ISO artifact stopped being produced entirely** — same consequence as the read-only-Nix-store break earlier, reached by a different route.

**Why `actionlint` didn't catch it, since I ran it and called it clean:** actionlint validates workflow *syntax*. `run: bun path/to/script.ts` is syntactically perfect whether or not the file exists. A check that passed, on a property that wasn't the one that mattered.

The step is **removed, not stubbed**. A stub that always passes would report parity as CHECKED while checking nothing — worse than no step.

### The gap it guarded is real and still live

Filed as `workitems/081M0HG7X7B087G0R002A05DAP` rather than dropped. The integrity check `checkIsoAgainstManifest` exists **only in the macOS arm**:

| arm | manifest / sha256 / digest references |
|---|---|
| `flash-usb.ts` (macOS) | 5 |
| `flash-usb-linux.ts` | 0 |
| `flash-usb-windows.ts` | 0 |

On Linux and Windows, zflash writes an image to a block device with **no integrity verification whatsoever**. That is a live gap, not a drift hazard — the arms differ today, in the direction that matters.

It is also why the step **cannot simply be restored with its script**: an honest parity audit *fails* on main right now, because parity is genuinely violated. Restoring it first would force a choice between a red lane and a baseline recording the gap as acceptable. Fix the two arms, then bring the audit back — and per the note already in this workflow, into `gate.yml`'s cross-verify floor so it blocks every PR rather than only this lane.
