## Description

fix(full-ai-cluster): declare + check the WireGuard kernel prerequisite Cilium's own values demand

Cilium is the CNI here, and BOTH of its value surfaces request WireGuard
node-to-node encryption at the earliest possible moment:

  k8s/bootstrap/cilium-install.yaml:64-68   -- k3s HelmChart, `bootstrap: true`
                                               (first boot, node not yet Ready)
  k8s/applications/cilium/Application.yaml:80-83 -- ArgoCD, sync-wave "-80"

    encryption: { enabled: true, type: wireguard, nodeEncryption: true }

Before this change NOTHING under full-ai-cluster/nixos/ named WireGuard.
boot.kernelModules carried kvm-intel/kvm-amd (hardware-configuration.nix) and
iscsi_tcp (longhorn-prereqs.nix); boot.extraModulePackages was `[ ]` on both
hosts; there is no networking.wireguard anywhere; and `wireguard-tools`
appeared exactly once in the tree -- usb-nixos-installer/nixos/installer/
configuration.nix:182, the INSTALLER ISO, never an installed node.

WHAT CILIUM ACTUALLY DOES WITHOUT IT (cited, not assumed)

It fails CLOSED and LOUDLY. cilium/cilium pkg/wireguard/agent/agent.go:

    err := netlink.LinkAdd(link)
    if err != nil && !errors.Is(err, unix.EEXIST) {
        if !errors.Is(err, unix.EOPNOTSUPP) {
            return fmt.Errorf("failed to add WireGuard device: %w", err)
        }
        return fmt.Errorf("WireGuard not supported by the Linux kernel "+
            "(netlink: %w). Please upgrade your kernel, or manually install "+
            "the kernel module (https://www.wireguard.com/install/)", err)
    }

and daemon/cmd/daemon.go:608-612 turns that into a newDaemon error, so the
agent exits and CrashLoopBackOffs. No plaintext degrade. The userspace
fallback (--enable-wireguard-userspace-fallback) defaults to false, is set by
neither of our value surfaces, and was deprecated for removal in 1.17.

So the finding's severity is LOWER than filed, and this commit says so in the
files: it does not prevent a silent failure, it moves an already-loud one from
"CrashLoopBackOff on a node with no CNI" to "a named refusal on the console
before k3s starts, listing the two manifests that made the demand".

WHY IT HAS NOT BITTEN -- AND WHY THAT IS NOT A REASON TO LEAVE IT

Two mechanisms neither of which this repo owns:

  1. nixpkgs autoModules answers "m" to every tristate
     (pkgs/os-specific/linux/kernel/generate-config.pl: `$answer = "m" if
     $autoModules && ...`, generic.nix: `autoModules ? ... or true`), so
     CONFIG_WIREGUARD=m without appearing in common-config.nix at all;
  2. the kernel auto-loads it on the very call Cilium makes -- rtnetlink.c
     `request_module("rtnl-link-%s", kind)` + wireguard main.c
     `MODULE_ALIAS_RTNL_LINK`.

A hardened kernel, autoModules = false, or a stripped module tree ends that,
and nothing in the tree would notice.

WHAT LANDS (shape copied from the longhorn preflight, PR #13252)

  cilium-wireguard-sources.nix         roster of the value surfaces, read as text
  cilium-wireguard-preflight-checks.nix pure half: DERIVES the requirement from
                                        those files, emits the boot script
  cilium-wireguard-node-preflight.nix   the oneshot, before k3s.service
  cilium-wireguard-prereqs.nix          boot.kernelModules + wireguard-tools
  common.nix                            imports it -> every node, no opt-in
  tests/cilium-wireguard-preflight-eval-test.nix  34 properties, eval-only
  flake.nix                             checks.<system>.cilium-wireguard-preflight
  tests/k3s-control-plane-platform-fixes.nix  fixes 7 + 8: a real kernel

The requirement is DERIVED, so an IPsec or plaintext tree stops demanding the
module with no edit here, and the not-required path is a WHOLE separate script
that cannot emit the OK marker.

NOT `RequiredBy = k3s.service`, for two reasons

The longhorn precedent's reason applies unchanged (an unrun gate whose false
positive costs the whole cluster at first bring-up is its own 2am failure).
This one has a second and stronger reason: the failure is ALREADY loud, so
gating k3s would trade a diagnosable CrashLoopBackOff for a node that never
joins and reports nothing over the network. Unlike the longhorn note, that does
not improve after a clean metal boot -- it is not an upgrade awaiting evidence.
