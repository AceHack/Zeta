## Description

The mDNS publisher landed with an admission in its own source: *"sha256 of the CA PEM. **UNVERIFIED** that this equals the digest k3s embeds in its own K10 token prefix"*, named as the first thing to measure on real hardware. **It did not need hardware — it needed reading k3s.**

## Verified against `pkg/clientaccess/token.go` `hashCA()`

The answer is **conditional**, which is why it was worth checking rather than assuming in either direction:

| CA bundle | what k3s hashes | our `sha256sum` |
|---|---|---|
| **single** certificate (the usual self-signed cluster CA) | the **literal bytes of the file** | **matches** — the assumption held for the default case |
| **more than one** certificate | the **DER of the ROOT cert** in the chain | **diverges silently** |

So a custom CA with an intermediate would have published a cluster id **no joiner computes**, and every pinned join would refuse *while the mDNS record still looked perfectly healthy on the wire*. A wrong id is worse than no id — it is a check that did not run wearing the appearance of one that passed.

## The fix

The multi-cert case now **refuses to publish** and withdraws any stale service file, rather than advertising an id it cannot compute correctly. Fail-closed, loud about why, with the k3s source cited **in the module** so the next reader can re-check the claim instead of trusting this PR.

## Checked, not assumed — and the harness needed fixing first

Worth recording, because it nearly produced the opposite conclusion. My first mutation attempt sliced the module between `certs=` and the **first** `sha256sum` in the file — but the comment I added above the guard contains that word, so the slice was empty and the mutation **silently patched nothing**. Two mutants that had never been applied looked exactly like two vacuous tests. Searching for the digest *after* the guard's offset fixed it:

| mutation | result |
|---|---|
| M1 — refusal downgraded to a warning (`exit 1` → `exit 0`) | 12 → **11 pass / 1 fail** |
| M2 — stale advertisement no longer withdrawn | 12 → **11 pass / 1 fail** |

Restored: **12 pass / 0 fail**. The ordering assertion is deliberate — the guard must exit **before** the digest is computed, or it is decorative.

**Still true:** no metal has booted, and this changes nothing about that. What it removes is one assumption that would otherwise have cost a hardware session to discover.
