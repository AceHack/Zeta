## Description

## What this answers

Aaron, verbatim: *"what do we need to do to get all of them booting."*

The included Synced+Healthy proof asserted **19 of 45** ArgoCD Applications.
Twelve were in this agent's scope — the eight `DEV_INCLUDED_PROOF_DEFERRED_DIRS`
entries plus the four "GPU" entries of `DEV_EXCLUDED_DIRS`. **Six of the eight
carried no recorded reason at all.** All twelve now have one, established from
the manifests.

## The finding that reframes the question

There is a **fourth** exclusion rule, upstream of the two hand lists everyone
reads: `DEFAULT_ROOT_DEV_CATALOG.excludeGlob` in `ports.ts`, which decides what
the dev/CI app-of-apps root **applies at all**. **Nine of the twelve were never
applied to a CI cluster** — not asserted-and-failing, not
applied-and-unasserted, absent. Only `forgejo`, `spire` and `vault` actually
reach a cluster and go unasserted, which is exactly the three that carry
`APPLIED_BUT_UNASSERTED_REASONS` entries. The deferred set was two different
populations wearing one label.

## Landed: 3 apps, 19/45 → 22/45

All three under the **full auto-sync Synced+Healthy contract**
(`manualSync=false`), never the manual-sync one. Nothing was weakened to fit
them — the exclusion lists shrank; no assertion was relaxed.

- **`deepseek-coder`, `qwen-coder` are not GPU apps.** Their own headers call
  them "structural"; between them they render one `Namespace` and two
  `ConfigMap`s of endpoint strings. No image, no pod, no PVC, no CRD, and
  `automated: {prune: true, selfHeal: true}`. The GPU is a property of
  `ollama`/`vllm`, which *serve* those models — these two were excluded by
  association with a directory name.
- **`orleans` was deferred for a silo image it never pulls.** `statefulset.yaml`
  ships `replicas: 0`. `gitops-engine`'s `getAppsv1StatefulSetHealth` returns
  **Healthy** there: `ReadyReplicas 0 < Replicas 0` is false, and the
  API-server-defaulted `RollingUpdate.Partition` is `0` so
  `UpdatedReplicas 0 < 0-0` is false too. Precedent already in the green proof:
  `hat-system/deployment.yaml` ships `replicas: 0`.

**Not claimed:** that a silo runs, a model is served, or inference happens. What
is claimed is that these manifests parse, apply, reconcile and stay Synced —
exactly what the other 19 rows claim about themselves.
