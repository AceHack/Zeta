## Description

Closing the cheap links of the chain the earlier audit found broken at every one.

## Alloy was a DaemonSet on every node that moved zero bytes

Baseline confirmed: **three components, all sinks.** After: **fourteen** — discovery, relabels,
`loki.source.kubernetes`, two scrapes, `prometheus.exporter.self`, `otelcol.receiver.otlp`, a batch
processor, two bridges, and **the three pre-existing sinks now fed.**

**A tool the earlier audit didn't have made this a measurement rather than an opinion:** the Alloy
**v1.5.1 binary — byte-exact the version the chart ships.** `alloy run` does a full graph evaluation and
names every unknown component and unresolvable reference. **`helm template` treats the whole config as an
opaque string, so nothing in CI could have validated it.**

**23 nodes evaluated, zero semantic errors**, only two environmental (no `KUBERNETES_SERVICE_HOST`
off-cluster). **With a discriminating negative control** so that isn't a vacuous pass: `sys.env` →
`sys.envv` yields `field "envv" does not exist` at line 22:36.

### Decisions, not defaults

- **Node-filtered discovery** via `spec.nodeName`. This is a DaemonSet — **without the filter each of N
  nodes tails every pod and ingest is N× correct.** The single most expensive mistake available here.
- **`loki.source.kubernetes`, not a hostPath tail** — the chart's ClusterRole *already* grants
  `pods`/`pods/log`/`namespaces` (its own comment says so), keeping this **values-only, no RBAC change.**
- **Metrics opt-in per pod** — zero cost until a workload asks.
- **`prometheus.exporter.self` is the liveness proof:** if that series is missing in Mimir, `remote_write`
  is down — **and you learn it without instrumenting any workload first.**
- **OTLP `extraPorts` were mandatory and easy to miss.** The chart opens only `12345`, so **a receiver on
  4317/4318 that neither the DaemonSet nor the Service binds is the same zero-byte failure in a different
  costume.**

## The Loki fix had a second trap in it

Rendering loki 6.18.0 produces **ten Services, none named `loki`** — but **`loki-gateway` exposes port
80, not 3100.** So the obvious correction to `loki-gateway:3100` **would have been a second silent miss.**
Now: `loki-gateway.loki.svc.cluster.local:80`. Tempo and Mimir were cross-checked, already resolve, and
**deliberately left untouched — a minimal diff is worth more than a tidier one.**

## Alerting — no destination invented

The pre-fix Secret decoded to **one receiver named `null`**. It now reads
`unrouted-REQUIRES-CONFIGURATION`, with the always-firing Watchdog **split off** to
`watchdog-REQUIRES-DEADMANSSWITCH` — because a heartbeat belongs on a dead-man's-switch, and **naming it
separately means the maintainer cannot wire one and silently forget the other.**

**Blast radius measured, not assumed:** the two full renders are **byte-identical outside that one
Secret**; the 35 rule groups are untouched.

> **Zero alerts are delivered today. That has not changed. What changed is that the config now says so.**

The three things to supply are written into the file itself — and **the audit refuses a `REQUIRES-` name
that has an integration attached, so the rename cannot be forgotten.**

## The falsifier — the point of the round

Four rules: sink with in-degree zero · isolated component (**kind-agnostic, so it needs no roster of
component names to keep current**) · every endpoint must resolve to a Service the chart **actually
renders, at that port** · alerting must not terminate silently, where **an absent config is a failure
rather than a default.**

**The service roster is derived, not hand-written.** Each entry carries a `valuesHash` over chart, repo,
version, release name and the entire `valuesObject` — **bump a chart without refreshing and the audit
fails STALE rather than asserting a render that no longer happens.** That's what keeps the endpoint rule
hermetic **without becoming an allowlist that drifts** — the exact failure the `-skip Application,HelmChart`
finding is an instance of.

## Verified — and the strongest evidence is not a synthetic mutation

Pointing the audit at the **unfixed** tree: **exit 1, five named failures** — three orphaned sinks, the
`loki` Service the chart doesn't render, and the absent alertmanager config. **Three findings, one
command, on the state that actually shipped.** Fixed tree: **exit 0**. **22 pass / 0 fail / 40 expects.
Nine mutations, nine killed, zero survivors.**

### The suite earned its keep during the run

The first version had the sink rule nested under the isolation rule's `else`, making it **unreachable** —
a pure sink with no source is *also* isolated, so isolation always fired first. **That is the vacuity
class, in code written to catch the vacuity class.** The mutation case flushed it out; the branches are
reordered and **the reason is recorded at the site.**

Wired into `gate.yml`'s existing `lint (yaml/k8s)` job — **60 ms** audit, ~0.5 s suite, no network.
`helm-validate.yml` **not touched** (another agent holds it). **No regression:** 224 passed / 14 failed
before *and* after, stash-verified, with neither changed app in the failures.

## Designed but not measured

**Nothing here has run on a cluster.** The config is proven **valid and wired**; only a live cluster
proves it **flows** — `prometheus.exporter.self` is the cheapest first probe. The annotation relabels have
never met a real annotated pod. OTLP end-to-end is unproven; the .NET exporter is out of scope, and **the
receiver now exists before the emitter, which is the correct order.** The endpoint rule's *render* tier
runs on demand, not in CI — **what runs in CI is the hermetic tier plus the staleness key, so a chart bump
without a refresh goes red rather than green.**

The loki Application's plaintext S3 key was read for render values, **not modified**, and is not restated
anywhere; the roster contains Service names and ports only.

> **All three defects were values-only, and `helm template`, `kubeconform` and `yamllint` were green on
> every one of them. The three fixes are worth less than the check, because the check is what stops the
> fourth.**
