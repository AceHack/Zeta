## Description

## The contradiction, resolved

Two observations about `full-ai-cluster/k8s/applications/game-hosting/gmod` were on the table at once and looked incompatible:

1. it sits at depth 2, the root glob is `{*/Application.yaml,Application.yaml}`, so ArgoCD never discovers it — a manifest that looks deployed and is not;
2. the `--scope included` kind lane's own diagnostics show `gmod` in the cluster, syncing, and being **denied**:

```
admission webhook "check-ignore-label.gatekeeper.sh" denied the request:
Only exempt namespace can have the admission.gatekeeper.sh/ignore label,
namespaces "game-hosting" not found (retried 5 times)
```

**(2) is what happens. (1) is false**, and the reason is worth pinning because it is easy to re-derive wrongly.

**ArgoCD's `*` is not path-segment bounded.** `reposerver/repository/repository.go` matches the include/exclude patterns with `glob.Match(include, relPath)` — the relative path, and **no separator runes**. `util/glob/glob.go` forwards that empty separator list to `github.com/gobwas/glob`, whose `*` is documented as "any sequence of non-separator characters"; with no separators declared, `/` is not a separator. So `{*/Application.yaml,Application.yaml}` matches `game-hosting/gmod/Application.yaml`, with `*` binding the whole `game-hosting/gmod`. This is **not** `filepath.Match` and **not** doublestar — either of those would have made (1) true.

Checked, not cited: in the included lane the **only** thing that creates Applications is the `zeta-root-dev` root built by `buildRootDevCatalogManifest` with that exact glob — nothing else in the harness applies an Application manifest anywhere — and `gmod` is in that cluster.

## So where the defect actually is

The depth-1 assumption is real, but it lives in **our harness**, not in ArgoCD:

- `discoverExpectedApplications()` reads `<dir>/Application.yaml` at depth 1 only, so `gmod` is not in the roster the included lane asserts Synced+Healthy on;
- `auditAppliedButUnasserted()` is built on that same roster, so the registry that exists precisely to catch "applied but nothing asserts on it" cannot see it either;
- `auditSyncPolicyDeclarations()` in `manual-sync-policy.ts` follows the same scope.

Net: **ArgoCD deploys `gmod`, `gmod` fails to sync on every reconcile, and the lane is green.** A check that did not run, looking like a check that passed.

The underlying live defect is named, not silently patched: `game-hosting/gmod/namespace.yaml` carries `admission.gatekeeper.sh/ignore: "true"`, and `game-hosting` is absent from `exemptNamespaces` in `applications/open-policy-agent/Application.yaml` (`zeta-platform` is the worked precedent there). That fix is a policy change only a live cluster can confirm, so it is registered with its reason rather than guessed at here. What this PR removes is its **invisibility**.

## The check

`src/Core.TypeScript/cluster/app-of-apps-discovery.ts` compares **reach** against **roster**, in both directions, offline and pure:

- **NEVER-DISCOVERED** — a `kind: Application` manifest under the applications tree that no app-of-apps root's `include` glob matches. That is the class observation (1) described. Refused outright, no registry: a file nothing can ever apply is not a deferral, it is dead YAML.
- **DISCOVERED-BUT-UNASSERTED** — a manifest the dev/CI root applies (include matches, exclude does not) that is absent from the harness roster, so no lane can ever see it fail. Legitimate to defer, so this one carries a registry, and an entry without a reason is refused. Stale entries are reported too, so the two lists cannot drift apart in either direction.

Nothing is hand-listed. Roots are found by walking `full-ai-cluster/k8s` for app-of-apps Applications (the same shape `single-node-readiness.ts` already uses: a git-directory source whose path ends in `applications`) plus the dev catalog **parsed from its own generator's output**, so a change to `buildRootDevCatalogManifest` moves this check with it. A glob pattern the translator does not implement is **refused**, never approximated — a glob checker that quietly answers wrong is the exact defect above.

Live tree: **46 Application manifests, 1 registered gap, 0 drift.**
