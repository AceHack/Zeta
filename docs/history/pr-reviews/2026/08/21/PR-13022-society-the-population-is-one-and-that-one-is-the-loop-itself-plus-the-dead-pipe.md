## The society has a population of one, and that one is the loop itself

The tick is **not** a no-op — every 30 min it writes an event, a hash-chained index and a persisted posterior. **182 commits, 400 event files. The mechanism is sound; the problem is upstream of it.**

`loadAgentsFromEventLog` scans the last 200 event files and treats each distinct `by` field as an agent. **Every event this loop writes carries `by: "society"`.**

```
$ ls docs/observe-events/ | sort | tail -200 | grep -c '^society-'
200
```

**200 of 200. Zero non-society events reach the loader.** Re-verified independently before landing.

**Timeline:** population was **4** until 2026-08-16T12:48Z, then **4 → 3 → 2 → 1 within one hour** as older agents aged out of the window. **It has been 1 for four days.**

### With n=1, `evolve()` is the identity function

`k = 1` survivor, `needed = 0` offspring — **no crossover, no mutation, no replacement.** Five successive `evolve()` calls leave the genome **identical to the founder**, diversity 0.

> **Every tick's commit message advertises "score → select → crossover → mutate → replace." Only *score* and *select* execute. The last three are structurally unreachable at this population.**

`meanFitness` is **pinned, not stable** — frozen at `0.6505648066545648` since 2026-08-16 because `settledCount` saturates the window, giving `trustBound = mu − 3σ = 0.65056`. **It cannot change again while the window stays saturated.**

**And nothing would notice.** No hygiene audit references `geneticDiversity`, `meanFitness`, or population size. **A society of one and a society of forty produce identically well-formed, correctly-chained events.**

## The dead pipe guard — fixed here

```yaml
… 2>&1 | tail -10 || echo "[society] evolution tick failed (non-fatal)"
```

The only `set -uo pipefail` in the file is at **line 112 — a different step.** So the pipeline reported `tail`'s status, always 0, and **the `|| echo` guard was dead code.** **A crashing runner was indistinguishable from a healthy tick** — this repo's own *"never read exit status through a pipe"* rule, violated live on `main`.

Fixed with the reason written at the line so it cannot later be removed as noise. **Non-fatal by design; now visible.**

## USB lifecycle

**(a) provisioning EXISTS** — `zflash`, 53 files, three platform arms, Touch ID gate, hard refusals and a typed `accept-destroy` nonce. **Only the Windows arm has read-back verify.**

**(b) damage detection DOES NOT EXIST.** `flash-usb.ts` **displays** the partition table, including a `(no partitions detected — raw / freshly-erased)` branch — **but nothing classifies it and nothing branches on it.** Blank, half-written and correctly-flashed all take the same path. **`/dev/disk6` is a textbook specimen of what nothing detects.** A detector needs three inputs and **the repo already reads all three and throws them away.**

**(c) repair/reformat DOES NOT EXIST** — `reformat` means *re-flash from scratch*.

**Aaron already asked for the precursor and it was never built** — the 2026-06-09 KDF research quotes him: *"check if the partition exists every time before formatting; ask the questions BEFORE formatting."* `zeta-install.sh` still wipes unconditionally.

### The CI half is better than expected, and reshapes the problem

The ISO **is** USB media; `qemu-boot` **really boots and really asserts** a serial stage ladder (caveat: only BOOT-FAILED fails the job — TIMEOUT and STALLED are advisory by policy); and the x86 job **cosign-signs** the blob.

**But the bridge is missing entirely** — grepping `zflash` for cosign/sha256/verify-blob returns **nothing**. `cli.ts` picks the newest `~/Downloads` ISO **by mtime** and `dd`s it. **Checksum verification exists in the repo — but only for third-party upstream images, never for our own ISO.**

⇒ **"initial format" should become "verify, write, verify back."**

**Nothing that writes was run.** The destructive command is written out for a human, with the point that matters stated at it: **the target must never be discovered dynamically.** `flash-usb.ts` already reads all five identifying fields — **it just never compares them against a caller-supplied expectation.**
