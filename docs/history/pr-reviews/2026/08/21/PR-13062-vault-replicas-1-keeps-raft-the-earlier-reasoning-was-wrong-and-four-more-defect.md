## Description

Fixes the three unmet preconditions the previous round filed — and **corrects a claim I relayed and
landed.**

## The correction first, because it changes the fix

Workitem `081M0H19QD3` said lowering to `replicas: 1` *"would discard the raft design."* **It is
wrong.** `storage "raft"` comes from `ha.enabled` + `raft.enabled`, **not** the replica count.
Verified against chart 0.29.1 before landing:

```
ha.enabled=true, replicas=1, raft.enabled=true  ->  storage "raft"
ha.enabled=false                                ->  storage "file"
```

**`replicas: 1` keeps raft**, and growth to three nodes is a `vault operator raft join`, not a storage
migration. Preferred-anti-affinity at `replicas: 3` was rejected for a good reason: on one node it
schedules three raft voters onto one disk and reports 3/3 Running — **availability theatre**, and
`single-node-budget.json` already names that failure class.

## Precondition 2 had a sharper root cause than "the probe cannot pass"

**`global.tlsDisable` does not control the listener at all** — it steers the `VAULT_ADDR` scheme and
the container port *names*. The listener's TLS lives in the HCL at `server.ha.raft.config`, chart
default `tls_disable = 1`.

> **The two facts sat in two different files and nothing compared them.** That is the whole defect.

TLS-off end to end for now, listener HCL supplied explicitly. **TLS-on was rejected because it is
blocked outside this lane** — the only ClusterIssuers are ACME/HTTP-01, and ACME cannot issue for
`vault-0.vault-internal`, so shipping `tlsDisable: false` without an issuer **would recreate the exact
false claim the header already made.**

**Anchor checked, not cited:** `VAULT_CLUSTER_ADDR` staying `https` is **correct** — Vault's cluster
port always uses TLS with a self-signed certificate it mints itself. So the check **scopes to port
8200 and says so**; a naive all-schemes-must-match rule would flag 8201 wrongly and **train readers to
ignore it.**

## Precondition 3 was a layering problem, not a wave-ordering one

**Raft *is* the replication layer**, so integrated raft on a replicated network volume is replication
under replication — and longhorn here runs `defaultReplicaCount: 1`, so it **buys no durability over
node-local** and only adds the ordering hazard. Both PVCs move to `zeta-local-path`, present before
ArgoCD exists. **Wave −60 needs no change: the ordering problem is removed, not rescheduled.** Cost
stated rather than glossed — `zeta-local-path` is `reclaimPolicy: Delete` where longhorn was `Retain`.

## Two defects the workitem does not name

- **The injector carried the same hard anti-affinity** at `replicas: 2` — one of two pods Pending
  forever. Blast radius bounded by measurement: the webhook renders `failurePolicy: Ignore`, so it
  degraded ArgoCD health **without blocking pod admission cluster-wide.**
- **`replicas: 1` renders a PDB with `maxUnavailable: 0`** — which **blocks `kubectl drain` of the only
  node forever.** A NixOS host upgrade would hang. A PDB over one replica protects no availability it
  did not already lack.

## And a defect in an existing audit — reported, not fixed

**`single-node-readiness.ts` mis-classified Vault through the same blind spot this check closes.** Its
`antiAffinityOf` looks for a `podAntiAffinity` *type* key in the values; **Vault's chart expresses a
HARD anti-affinity as a raw block, invisible from the values** — so it recorded `none` and the verdict
`false-redundancy`. The truth was **needs-more-nodes: two pods Pending and Vault never starting.**

> **Two independent audits, one blind spot.**

## The falsifier

Eleven rules, offline. The sharp one compares the listener's `tls_disable` against the scheme the chart
puts in `VAULT_ADDR` — **the coherence check nothing performed, which is why the broken config
shipped.** It is backed by a rule that **refuses an Application inheriting the chart's HCL**, because
then the check is unrunnable and **a green result would mean nothing.**

**Verified independently at `origin/main`: exit 1 against the file as it shipped, exit 0 (11 rules, 0
findings) against the fix.** **29 pass / 0 fail / 45 expects.** Cluster suite **149 pass / 0 fail.**
Three mutations bite — inverting the TLS comparison **fails 8**; making inherited-affinity read as
`none` (*the exact original blind spot*) **fails 3**; flipping the storage-wave comparison **fails 4**.

**A test the agent wrote failed and was right to:** flipping the topology annotation to `three-node`
without changing the values produced **zero** findings — which would have made the manifest's own claim
false. That produced an eleventh rule. The suite also carries a **designed tripwire** asserting no
`kind: Certificate` exists, **to be deleted in the same commit that flips `tlsDisable`, so the gap
cannot close silently.**

## Blast radius, honestly

**Nobody outside the cluster.** Vault has never been initialised and holds no secrets, and the *"SPIRE
and External Secrets depend on Vault"* claim is **planned, not wired** — both reference it only inside
comment blocks. **Vault blocks the next step; it is not currently breaking either app.** Filed under
the workitem, **not** under incidents — a post-mortem here would be a category error.

## The ceremony — designed, not run

Every key-minting command is marked a **gated class needing fresh human authorization**. **Custody is
left open on purpose**: which mechanism splits the material decides who can reconstitute the barrier
key — a maintainer decision with a witness. **It survives a later move to OpenBao** (Shamir + manual
unseal is what OpenBao does before a seal is configured), and it says explicitly: **do not automate
that step against Vault CE** — automation would park unseal shares where a process can read them,
**strictly worse than a human holding them.**

## Designed-but-unrun

**Everything about scheduling, TLS and storage is read off `helm template`, not off a cluster.** Not
measured: that Vault reaches Running; that `zeta-local-path` has the free space (**an unbudgeted class,
raised 73 → 103 GiB on a `hostPath` provisioner that binds regardless of free space — over-subscription
surfaces as runtime ENOSPC, not as Pending**); that the ceremony works; that raft forms at three nodes.
The audit **encodes** two chart behaviours rather than observing them, and **pins chart 0.29.1 so a
version bump fails until someone re-measures.** It is **not yet wired into CI** — that lane belongs to
another agent this round, and the limit is stated in `TOPOLOGY.md` rather than left implicit.
