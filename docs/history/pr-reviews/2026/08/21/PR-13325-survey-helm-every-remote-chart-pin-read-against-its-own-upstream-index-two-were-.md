## Description

## What this is

The maintainer asked to update every Helm chart to its latest version, and to reach upstream to find out what "latest" is. This is the **survey half** — the accurate table you bump *from*. Nothing is bumped here; several of these are Aaron's call and one of them is a supply decision before it is a version decision.

Every "latest" claim was **MEASURED**: the chart repository's own `index.yaml` fetched at the exact `repoURL` the manifest pins, `entries.<chart>[].version` parsed and semver-sorted. OCI registries have no `index.yaml`, so those came from `/v2/<repo>/tags/list` with an anonymous pull token, and the doc says which is which per row. All fetched **2026-08-21**, and §2a lists the index URL behind every number — a version with no provenance is worthless in six weeks.

**Zero repos were UNRESOLVED.** The two fetch failures are findings, not gaps.

The parser is mine and it had a real bug before it was fixed — a naive line-based `version:` match reported cilium's latest chart as `v2`, which is a `CiliumNetworkPolicy` CRD version embedded in an *annotation*. So §1a cross-checks five rows through `helm search repo --versions`, upstream's own reader of the same indexes: the two largest indexes, the row that broke the naive parser, and both broken coordinates. All five agree, including the negative one — no `1.4.x` `ziti-controller` chart exists under either reader. Stated with its limit: two readers of the same input share that input, so this falsifies *my* failure mode, not upstream's.

## The three broken coordinates

A stale pin still resolves. These do not, and fixing them is not a bump decision.

- **`oz` / `ziti-controller 1.4.5`** — CONFIRMED against the upstream index, not re-derived. The 1.x chart line ends at `1.3.4`; `1.4.2` exists only as an *appVersion*. Already filed (`081M0JVD5YG087G0R002QDFR9H`, #13313).
- **`forgejo 9.0.6`** — NEW, and the expected repeat of the same class. The `9.x` chart line has **exactly one release, `9.0.0`**, read from an unbroken 169-tag history (`0.0.1` → `17.1.5`, nothing pruned). Unlike `oz` it is not even an appVersion: chart majors run one ahead of the app (`10.0.0`→app `9.0.0`, `10.1.2`→app `9.0.3`), so the Forgejo `9.0.x` line tops out at `9.0.3`. Its `repoURL` is dead too — the http repo returns `entries: {}` and the chart is OCI-only now. Filed `081M0JX5GQ8087G0R002TD5Z0Q`.
- **`sealed-secrets`** — the `repoURL` 404s; the chart moved `bitnami-labs` → `bitnami`. The pinned `2.16.2` **is** published at the new address, so this is a `repoURL` correction with no version decision attached — the cheapest fix in the roster, and not optional. Filed `081M0JX5KV3087G0R001DMWP1C`.

## Why majors get their own section

"Versions behind" measures **staleness, not difficulty**, and reading it alone is actively misleading. `kube-prometheus-stack` is 435 behind along a mechanical per-major CRD-apply path; `nats` is 33 behind across a `1.x`→`2.x` values-schema rewrite. §4a lists all 14 major crossings with the upstream release-notes/UPGRADING link for each (every link verified `200`). Two entries there are supply-chain reads rather than upgrade reads: `redis` sits behind the Bitnami catalog change (bitnami/charts#35164), which affects the *pinned* version too, and `external-secrets` `0.10.7`→`2.9.0` is gated on the CRD API — `v1beta1` was dropped in `v0.17.0`.

## Recommended batches

- **Batch 0** — `sealed-secrets` `repoURL` fix, keeping the version. Zero risk, independent of everything else.
- **Batch 1** — safe together, one PR: `tempo`, `weaviate`, `seaweedfs`, `ollama`.
- **Batch 2** — same major but CRD-bearing, one PR each: `cert-manager`, `gatekeeper`, `argo-rollouts`, `dapr`.
- **Batch 3** — `0.x` lines, mechanically simple but each is its own PR. Two pairs are version-coupled and must move together: `arc-controller`+`arc-runner-set`, and `spire`+`spire-crds`.
- **Batch 4** — human decision: the two fictional pins, the 12 remaining major crossings, the two sequential-only upgrades (`cilium` = 4 steps, `longhorn` = 5 steps on live storage), and `redis`.

## One more measured property worth keeping

`bootstrap/` carries a **second copy of six of these pins** (plus `spire-crds`, which has no `applications/` counterpart), and today it is in **exact lockstep** with `applications/`. That lockstep is the survey's cleanest current property. Any bump to those six must edit two files, or it silently becomes a seventh finding.
