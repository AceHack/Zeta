## Description

`fe38a2a8e` added `timestamp: Date.now()` to the history entries appended by `do_item` and `retract_time`. An ambient clock inside a pure fold is entropy entering through an undeclared channel (§13 noninterference) — and it broke the property this system is named for.

## The evidence is a one-millisecond diff

`observe.test.ts` — *"THE event-sourcing property: the loop's event log folds back to the loop's final state"*:

```
-  "timestamp": 1786506055675,
+  "timestamp": 1786506055676,
```

Folding the same log twice produced different state. **State stopped being a projection of the event log** — the founding claim of the substrate, falsified by a millisecond.

## The fix

Removal, not injection: the ledger's *order* already carries the causality the fold uses, and wall-clock time adds nothing it reads. If a timestamp is genuinely needed later, inject it the way `hygiene/mutation-readout.ts` takes `now: () => string` as a dependency, so entries still replay.

## Deliberately not fixed here

The remaining **3 golden-vector failures**. Removing the clock is necessary but *not sufficient* — I verified that by testing it.

The residual cause is that `history` is now part of the folded `World`, and the committed golden vectors contain **zero** occurrences of `history`. Those vectors are the cross-language conformance surface (`src/Core.CSharp.Observe/` and others reference them), so regenerating them would turn the tests green while silently putting the other oracles out of conformance — a treaty change wearing a bug fix's clothes.

That decision belongs to Aaron/Lior:

1. **exclude `history` from the conformance-folded state** — smallest change, keeps the four-oracle lock intact; or
2. **implement `history` in every oracle** and regenerate the vectors deliberately, as a versioned treaty change.
