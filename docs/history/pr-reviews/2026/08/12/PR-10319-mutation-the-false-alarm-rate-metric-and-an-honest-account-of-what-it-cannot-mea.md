## Description

For Alexa, from the open enhancement named in the mutants-coexist doc §6: we had no false-alarm rate.

SDV became a **required** Windows 7 gate when SLAM's false-alarm rate fell 25.7% → <4% — *not* when it became correct, since the problem stayed undecidable. That number is what bought it the right to block. Our runner stays a report until unexplained survivors are rare; this is how we'd ever know.

## What a false alarm is here

The runner reports INDISTINGUISHABLE — a fact it's entitled to. The alarm is **false** when the honest resolution was not a missing test:

| cell | reading |
|---|---|
| `write-test` | **true** alarm — a real gap |
| `declare-free` | false alarm — genuinely unconstrained |
| `note-redundant` | false alarm — masked, so no test could ever hold it |
| `defer` | **unresolved** — excluded from the ratio entirely |
| `escape` / `undefined-cell` | frontier (grammar too narrow), counted apart |
| `supersede-mine` | **revision** — an earlier classification proved wrong |

That last row is §6's *"a registry converges"* falsifier measured directly: if entries keep needing revision, the ledger is a mute button rather than accumulated knowledge.

## The denominator problem, which is the real finding

SLAM's rate is false / **all reports**. We cannot compute that, and the reason is structural:

- the runner records a transcript entry only under `--choose`, so a finding fixed by **opening a PR** — how every resolution has actually landed — leaves no entry;
- `agent-heartbeat.yml` never stages `db/`, so a write from a CI tick lands in a checkout that's thrown away.

So this computes false / **resolved**, and resolution is voluntary — a biased sample by construction. Calling that "our false-alarm rate" would be the same overclaim the runner was fixed to stop making, so `coverage` is `resolutions-only` and **`slamComparable` is a field set to `false`** — a caveat that lives only in a docstring gets separated from the number the first time someone quotes it.

Live output on real data makes the bias visible:

```
[false-alarm] resolutions recorded: 2
  real gap (write-test):        0
  false alarm (declared free):  1
  false alarm (redundant):      1
  false-alarm rate: WITHHELD — insufficient sample: 2 resolved, need 20
```

Two resolutions, **both false alarms, zero real gaps** — in a session where four real gaps were found and fixed via PR.

Making it SLAM-comparable needs findings recorded per tick, which needs the heartbeat to stage `db/` — a real decision about main-branch churn, not a change to make quietly. **Flagged, not taken.**

Below `MIN_SAMPLE` (20) the rate is withheld: `null`, never `0`, because a withheld measurement must not read as a perfect score.
