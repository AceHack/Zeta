## Description

**main is red and this unblocks it.** #11521 landed `measure-shell-key-exposure` using `localeCompare` in seven places — culture-**sensitive**, which `culture-invariant-by-default` forbids in primitives. The repo's own live tripwire caught it:

```
LIVE tripwire — the tracked tree must stay at or under baseline
  measure-shell-key-exposure.ts       found=4 allowed=0
  measure-shell-key-exposure.test.ts  found=3 allowed=0
```

`lint (bash retirement inventory + hygiene unit tests)` was failing on main and blocking the archive-automation PRs behind it. Reproduced on `origin/main` first — **30 pass / 1 fail** — rather than inferred from the PR log.

## The fix

All seven replaced with the code-unit ordinal compare **this repo already uses elsewhere**: `(a, b) => (a < b ? -1 : a > b ? 1 : 0)`. That idiom already appears in several hygiene files, so this matches the neighbours rather than introducing a second convention.

## Why it matters beyond the red X

The sort order feeds the **exposure ranking that sequences the `.sh` deprecation**. A locale-dependent comparator means two scripts could order differently on different machines — exactly the byte-lock / DST-replay divergence the rule exists to prevent. A deprecation sequence that isn't reproducible isn't a measurement.

## The tripwire stays as it is

It is a **ratchet**. The correct response to a ratchet firing is to fix the code, never to raise the baseline. Nothing here touches the baseline file.
