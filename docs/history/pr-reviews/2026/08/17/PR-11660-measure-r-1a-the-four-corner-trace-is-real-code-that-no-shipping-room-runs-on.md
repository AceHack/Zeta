## 1. Does the four-corner shape exist in code, or only in prose?

**In code — and not at a tick boundary.** `FourCorner.FourCornerOwnership` is implemented in four languages with a byte-locked `fourcorner1` treaty codec (`src/Core/FourCorner.fs`, `src/Core.CSharp/FourCornerOwnership.cs`, `src/Core.TypeScript/workflow-engine/types.ts`), and `WSet.FourCornerTrace` is the traced-monoidal-category form with laws tests and golden vectors. That is real, and more than I expected to find.

But the only place in the tree where a **scheduler state is instantiated at the four corners** is `tests/Tests.FSharp/FourCornerFusion.Tests.fs`. Zero `src/` rooms. `FourCornerTrace.toFourCorner` has test callers only.

What a tick boundary actually runs (`src/Core/SoftScheduler.fs:121-148`) is:

```fsharp
type HandlerK<'S> = { Name: string; Matches: InterruptKind -> bool; RunK: InterruptKind -> ISR<'S, 'S> }
// ISR<'A,'B> = IntrCtx -> 'A -> Task<Result<'B, InterruptFeedback>>
```

That names In, Out, and an error-position Out-Feedback. **Three corners.** The absent one is `T Feedback In` — the co-owned corner the retrocausality argument leans on hardest. The shape has been *proven instantiable* (that is exactly what `FourCornerFusion.Tests.fs` proves) and never adopted.

## 3. Confirmed gap — `ReceiptScheduler.onReceipt`

`src/Core/ReceiptScheduler.fs:87,118`:

```fsharp
(onReceipt: (ComputeReceipt.Receipt -> unit) option)
```

Fired inside the tick loop. A `-> unit` sink cannot return its effect through `'S`, the `Source`, the seed, `IntrCtx`, or `Result`. The module's own docstring says:

> **The four-corner closure:** … Feedback (backward): the `ComputeReceipt` emitted by the inner handler.

The receipt does not travel on a corner. It leaves through a hole. And this is not hypothetical usage — `ReceiptScheduler.Tests.fs` SCHED-1 already passes `Some receipts.Add` over a captured `List<>`.

`TICK-3` adds one reader handler and measures the consequence: **two runs with every declared channel byte-identical produce different outcomes.** That is the exhibit, not a theoretical hazard.

## 5. The instrument

`src/Core/TickBoundaryProbe.fs`. Pin all four declared channels, re-run in-process, compare. Because every declared channel is identical by construction, a difference is a **witness**, not a heuristic — this is Goguen & Meseguer's noninterference definition (1982) run as a test instead of asserted as a principle.

**It convicts and never acquits,** and the docstring names three blind spots rather than leaving them to be discovered: idempotent leaks, read-only ambient reads, and structural equality over `'S`. `TICK-4` exhibits blind spot #1 deliberately — the *same* `onReceipt` egress fires six times across two runs and the probe reports `DeclaredOnly`, because nothing reads the sink back. An instrument whose limits are only in prose is one nobody knows the edge of.

## 6. Own correction — the enforcement is a gradient (second commit)

I recorded the ambient-entropy sweep as clean without crediting *why* it is clean.
`tests/Tests.FSharp/DeterminismLint.Tests.fs` already bans eleven tokens across every file in
`src/Core` — comments included, on the stated ground that a commented-out wall clock is one waiting to
return — and its allowlist **pins exact occurrence counts**, so a third wall clock cannot slide in
behind two justified ones. The emptiness I measured was *maintained*, not lucky, and reporting it as
my own finding under-credited a real falsifier.

The correction sharpens the result rather than softening it:

| half of completeness | status | why |
|---|---|---|
| ambient entropy (clocks, RNG, GUIDs, `Stopwatch`) | **ENFORCED** | a token exists, so a substring lint can refuse it |
| closure-carried state | **UNENFORCED** | **no token exists to refuse** |

A `-> unit` callback and a `let mutable` field on a class handed out as a function value are ordinary
F#. They carry no lexeme. **Both confirmed gaps live in exactly that blind spot** — which is why they
survived a repo that already refuses ambient clocks, and why closing the second half needs a *type*
(the `T Feedback In` corner), not another lint.

## What in the brief proved false

The brief framed the four-corner shape as possibly "only prose". It is considerably more real than that — four languages, a treaty byte-lock, laws tests, and an explicit fusion proof. The gap is narrower and more interesting than "unimplemented": it is **implemented, proven instantiable, and unadopted**, which is a different failure and a much cheaper one to close.
