## Description

## The defect (measured)

`src/Core.TypeScript/planning/agent-proposal.ts` builds the message that
`.github/workflows/agent-proposal-gated-commit.yml` commits verbatim
(`git commit -m plan.commitMessage`, `agent-proposal-runner.ts:92`). It emitted
only a subject plus `workflow:` / `patch-digest:` — no AgencySignature block.

The required `agencysignature (PR body)` check reads **commit messages**, not the
PR description, so it failed every proposal PR this lane opened:

```
FAIL: no parseable git trailers found in the PR's COMMIT MESSAGES
```

Live instance, read from the forge rather than assumed — PR #11469, its only
commit `f8b936bf`:

```
agent-proposal: 30684619-fae9-41a6-b4b1-c6f6b4b67664

workflow: .../agent-proposal-gated-commit.yml@refs/heads/main
patch-digest: eda88449fe12...
```

A lane that can open a PR and can never merge one is a gate firing on correct
work, which is how gates get switched off.

## The fix

`AGENT_PROPOSAL_SIGNATURE_BLOCK`, appended as its own contiguous paragraph at
the bottom of the commit message. Every value is what is **true of this
producer**, not what is convenient:

| field | value | why it is truthful |
|---|---|---|
| `Credential-Identity` / `Credential-Mode` | `zeta-pages-operator[bot]` / `dedicated-agent` | **measured**: the workflow sets `git config user.name/email` to `zeta-pages-operator[bot]`, and #11469's commit carries exactly that author *and* committer |
| `Human-Review` / `-Evidence` | `not-implied-by-credential` / `none` | nobody reviews the staged commit before it is pushed; spec §7.5 forbids reading a bot credential as proof of human action |
| `Action-Mode` | `autonomous-fail-open` | after dispatch the staging runs unattended and pushes without a gate |
| `Task` | fixed slug `agent-proposal-gated-commit` | see below |

**Why `Task` is not the `proposalId`** (the one deviation worth flagging):
`validProposalId` admits a hyphen-free id such as `society`, which the canonical
`TASK_RE` rejects. Deriving `Task` from that input would trade today's
*always*-invalid block for a *sometimes*-invalid one — in the very lane whose
defect was structural unmergeability. `AAP-7` pins both id shapes.

## Falsified, not asserted

The three new tests call `validateText` from `hygiene/agencysignature-block.ts`
— **the rule the gate itself runs** — rather than restating the field list
locally. A local copy of the rule would pass while CI failed, which is precisely
the divergence that module was written to end.

Baseline **7 pass / 0 fail**. Three mutations, each restored:

| mutation | result |
|---|---|
| drop the block from `commitMessage` (the pre-fix state) | **4 pass / 3 fail** |
| `Credential-Mode: dedicated-agent` → `dedicated` | **4 pass / 3 fail** — caught by the real enum |
| blank line inserted inside the block | **4 pass / 3 fail** — contiguity break hides all ten keys |

End to end, the generated message piped through the gate binary itself:

```
$ <generated commit message> | bun src/Core.TypeScript/hygiene/validate-agencysignature-pr-body.ts
PASS: AgencySignature v1 trailer block valid
exit=0
```

and `git interpret-trailers --parse` returns all eleven lines, so git's own
parser agrees.
