## Description

fix(heartbeat): probe the scope the flush actually uses, not merely repo visibility

My own fix in #11491 was vacuous for the fault it guards, and the first run after it
landed proved it.

MEASURED, run 32044425464 at 16:07Z: the probe PASSED — neither the denial warning nor
the inconclusive warning appears anywhere in the log — and the very next call still died
on `compare failed: gh: Not Found (HTTP 404)`. A check that cannot fail under the
condition it exists to detect is not a check. That is the third instance of this class
today and the first one I authored.

The cause is a scope boundary I did not think about. `GET /repos/{owner}/{repo}` is
satisfied by Metadata alone, which this fine-grained PAT has. `GET /repos/{...}/compare/...`
is a CONTENTS-scope endpoint, which it does not. So the credential can see the repository
and cannot read its commits, and GitHub renders that second refusal as 404 rather than 403.

This SHARPENS the diagnosis rather than replacing it. The fault is not "the token sees no
repository" — it is precisely the missing **Contents** permission named in 081M010H4KE.
The narrower reading also explains the whole shape of the outage: the git preflight repairs
pushes, metadata reads succeed, and only Contents reads fail.

The probe is now `commits?per_page=1` — a Contents-scope read, one page, one request.

`compare/main...main` was tried first and REJECTED. Verified by hand against this
repository: it 404s even under a fully authorized credential, so it would have reported
denial unconditionally and demoted every lane to the lesser credential forever. That is a
worse failure than the vacuous probe it replaced — a check that cannot pass is as useless
as one that cannot fail, and it does damage on the way. Both directions were checked
against a real credential before this shipped, which is what should have happened the
first time.

Verified: actionlint clean, YAML parses, and the chosen endpoint returns a SHA under an
authorized credential while the metadata endpoint it replaces returns success regardless.
