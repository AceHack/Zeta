## Description

fix(core): SimLoop.defaultBudget's three constants — attributed, and two of the three derived

`SimLoop.fs:38-41` carried `MaxLaps = 1_000` / `MaxTicks = 1_000_000` / `MaxMillis = 300_000L`
with no provenance. Aaron 2026-08-17: "always be on the lookout where the measurement or the
limit/budget becomes the oracle silently — this is accidental hierarchy or control." The
discriminator is attribution, not existence. No value changed.

WHAT WAS DERIVABLE. The rails are tested laps -> ticks -> clock, so a secondary rail must trip at
a lap index of at most `MaxLaps - 1` or the lap rail closes first. With per-lap increment k and
limit L, a secondary rail is reachable iff `k >= ceil(L / (MaxLaps - 1))`. Measured by running the
loop at both sides of each boundary:

  ticksPerLap 1001 -> LapBudget  @1000 laps   |  1002 -> TickBudget  @999 laps
  clock 300 ms/lap -> LapBudget  @1000 laps   |   301 -> ClockBudget @997 laps

`ceil(1_000_000/999) = 1002`, not `MaxTicks/MaxLaps = 1000` — the ceiling and the `- 1` are both
load-bearing, which is exactly why this was measured rather than asserted. Every `ticksPerLap`
this repo passes is 1..25, so the tick rail is dormant under the default; `MaxLaps` is the
primary rail.

WHAT WAS NOT. `MaxLaps` is a CHOICE and no derivation exists to replace it: `run` is universally
quantified over `'S` and `cut`/`mea`/`ticksPerLap` are caller-supplied, so there is no state
machine to walk. #11539 measured a 115-state machine's diameter of 6 and set its budget to 6;
nothing of that kind exists here, and #11539 left `ARC_SWARM_TICK_BUDGET` unmoved for the same
reason. `MaxMillis` is the one field that already had a human on it: Aaron 2026-06-11, "default
timeout 5 minutes or something", carried in #7646's own signature.

DETECTOR BUG FOUND AND FIXED. `valueShape("1_000")` returned "derived": `_` starts an identifier,
so the digit separator lexed as an identifier `_000`. 32 budget-named declarations repo-wide were
invisible for this reason alone. Numeric literals are now blanked before identifier extraction.
Audit corpus 125/111/14 -> 138/123/15; the detector's own sensitivity/specificity self-test holds
at 15/15 and 123/123.

CORRECTIONS TO THE RECORD. `SimLoop.defaultBudget` was never a detector finding — its fields are
never compared directly (the clamped lowercase locals are), so the audit reported 138/123/15
identically with and without this attribution. And `DarkHallScheduler.fs:473` is not a consumer:
it takes an injected budget. The only reader of `defaultBudget` outside tests is
`SimVerb.toyBudget`, which already labelled it `ToyDefault`.
