## The measurement

`src/Core.TypeScript/hygiene/measure-shell-key-exposure.ts` — `measureScriptExposure(path, text)` is a **pure function**: no filesystem, no clock, no `git`. All I/O is in `main()`.

It is a shell **lexer** (quoting, comments, here-documents, `; && || |`, line continuations, multi-line `$( )` lifted and re-tokenized) plus a two-route taint tracker, joined into an ordinal tier over two axes:

- **material** — `root-key` > `stored-credential` > `execution-identity` > `none`
- **channel** — `broadcast` (argv/`ps`, exported env, generated env file) > `on-disk` > `confined` > `none`

**Why a lexer and not a grep.** The distinction the whole ranking turns on is `ps(1)` visibility, and no line regex has it:

```sh
printf '%s' "$SEED" | bun gen.ts          # printf is a BUILTIN — never in ps
security add-generic-password -w "$TOK"   # /usr/bin/security — in ps for its lifetime
env  TOKEN="$TOK" cmd                     # /usr/bin/env — the assignment IS argv
     TOKEN="$TOK" cmd                     # the SHELL sets it — not argv
```

Taint has two **proven** routes (`read -s NAME`, `NAME=$(<secret source>)`) and one **declared** route (spelling). Only proven taint can raise a script to `broadcast` — the first thing spelling flagged in anger was `gh secret set "$gh_secret"`, where the variable holds the secret's *name* and the value arrives on stdin.

`tierOf(material, channel)` is the **single policy seam**. Facts are reported separately from the ordering they are read under; a channel-first oracle puts rows 2–4 above row 1 and is one function swap away.

## Mutation — both directions, over all 31 real scripts

Every check is a **delta** against the unmutated measurement, so a pre-existing finding cannot be counted as a detection of the plant.

**The mutation run found two bugs the 33 unit tests did not:**

1. Dedup used `new Map(entries)`, which keeps the **last** value per key — so the flag-rule witness (`<value in argv>`) silently overwrote the proven-taint witness that names the variable. Sensitivity read 1/31 until fixed.
2. The lexer reset `quoting` at the closing quote, so `pushWord` recorded every word as unquoted and `'$PW'` scored as an expansion. Caught by a unit test written for it; the fix tracks quote style per word.

A third correction is mine: the first "stdin changes nothing" specificity test asserted the wrong thing — the stdin form *should* still record an on-disk keystore write. It now asserts what actually matters, that it never reaches `broadcast`.

## What the tool cannot see

Stated because an unstated blind spot reads as coverage. Also in the module header and in `docs/SHELL-DEPRECATION-SEQUENCE.md`.

- **Anything a child process does.** `bun gen.ts`, `mise`, `gh`, `op` are opaque. In particular `security(1)`'s **identity laundering** (research note §3.1b) is invisible here by construction — tracked as `081M00VN3FX087G0R0006ZGRWG`.
- **Indirection through a variable.** `"$TOOL" --flag "$SECRET"` → recorded as `opaque-dispatch`, not resolved.
- **`source`d files.** Taint is not propagated across a `source`; the edge is recorded as `sourced-library-edge` and each file is scored alone. A secret set in `curl-fetch.sh` and used in `macos.sh` is missed.
- **`eval`.** Recorded, never resolved.
- **Ambient authentication.** `gh auth status` uses a credential the script never names, so `zeta-self-register.sh` measures T0 while running `gh` against a live token. The claim is "no key material in the text", not "handles no credential".
- **Consequence.** Tier is exposure *shape*, not blast radius: an ephemeral CI token and a maintainer's 1Password service account both read `stored-credential`.
- **The machine.** This parses text. Per the research note §2.3 there are no FROST shares on disk yet — this is pre-positioning, not incident response.
- **False-positive cost of one relaxation:** `env` is treated as in command position when wrapped by a locally-defined function (needed to see `mise.sh:149`). A local function that does *not* forward its arguments would false-positive.
