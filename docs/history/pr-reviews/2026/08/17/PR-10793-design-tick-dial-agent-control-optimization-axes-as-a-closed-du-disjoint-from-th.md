## The correction that shapes the design

The brief's three-layer table indexes dispatch by **layer** and gives each layer one **kind**. That is the wrong shape, and the correction is safety-relevant rather than taxonomic: **kind is orthogonal to layer**, and the agent layer already ships a **gate** — `ActionGate`, `ActionClass`, `ReviewLevel`, `determineReviewLevel` in `workflow-engine/types.ts`. Those decide what may land and who must review it.

|  | **gate kind** (wrong ⇒ unsound) | **preference/optimization** (wrong ⇒ merely worse) |
|---|---|---|
| codegen | capability dispatch (v2 §0) | — (#10774: no site offers a second candidate) |
| emission | byte-lock | idiom (#10774) |
| **agent** | **`ActionGate` · `ReviewLevel` — shipped** | **the dials — this PR** |

So the defining property of the new DU is **not its variant list — it is disjointness from that gate**. An optimizer permitted to vary `ReviewLevel` improves its score by lowering the review bar: reward hacking aimed squarely at the guardrail, and the one failure mode here that is not merely "scores worse". `GATE_OWNED` encodes the boundary as data, `proposeDial` refuses rather than accepts, and TD-3…TD-6 check it — TD-6 admitting an ordinary proposal so the other three cannot be satisfied by a function that refuses everything.

**Two flagged corrections to R1 follow:** permissions and safety are *not* dials (gate-owned); and the objective function is not an axis of its own optimization (`OBJECTIVE_OWNED`, TD-5) — a scorer that tunes itself is `s = f(s)` running away rather than closing.

## Survey findings (three briefed-as-open items were already shipped, so I checked first)

- **"Harness" names four unrelated things here.** Only `docs/HARNESS-SURFACES.md` is the agent-control layer. `cluster/harness/bootstrap.ts` is k3d bring-up; `Plugin/Harness.Tests.fs` is a DBSP operator driver.
- **The eval loop has already run — and returned a negative result.** `harness-run-2026-04-20-performance-analysis-expert.md`: **−10pp** pass rate, **+37%** tokens with-skill. The eval was explicitly built so the baseline could win, and it did.
- **Our decomposition is OPLE** (Observe/Persist/Limit/Emit) and it covers **five** of the eight axes, not eight — `framing`, `hat` and scoring sit outside it. Reported as a divergence rather than forced to fit.
- **`db/sims/` is a README with no code behind it**; neither `sim` nor `measure` is a shipped binary. The sim-vs-measure split is a convention, not a mechanism.
- **Most dials have exactly one realised candidate today.** Per #10774's rule, an axis with one candidate is not an axis, so `proposeDial` refuses it.

## R3, answered honestly

Taken literally — both consumers importing `TickDial` — **the test fails, and should**: a package graph and a byte transport share no axis, and forcing the enum into both is the special case R3 forbids. What they share is the **(proposal, typed-outcome) shape**, which is OPLE's `T/TFeedback`. TD-12 opens a real `multiplexedDuplexTransport<DialProposal, DialOutcome>` over a `localDuplexPair` and round-trips it **with zero changes to any transport file**. On the ace side, revert-without-residue already exists: `applyDelta` deletes the key when the −1 retraction returns the weight to zero.

## Bug found and fixed — a locale in the proof lineage

`ace-cli.ts` `graphMerkleRoot` sorted with `localeCompare`, so the collation feeding the hash was culture-sensitive and the root machine-dependent (081KT07NV0008QG0R001YDB73K class). The sibling module `ace/build-graph.ts` already exports `ordinalCompare` with a docstring saying exactly why not to.

22 existing tests missed it because every `STUB_REGISTRY` name is lowercase ASCII, where the two collations agree. The falsifier fails against the pre-fix code (`zeta:5e2ff1f1` vs `zeta:5929e3f1`) and asserts its own premise so it cannot become vacuous. The second `localeCompare` in `list()` is **deliberately left alone** — it sorts a human-facing listing, which the rule permits at the display edge.

## "N correlated runs are not N observations" has two correct answers

Picking the wrong one is the error being warned about, so both are now in `SocietyUsefulWork.fs`: `effectiveTrialCount` (Kish 1965 design effect, for the variance of a mean) and `unionEquivalentAgentCount` (the exact inverse of the shipped `expectedSocietyIdentical`, for coverage of a union). They agree at both endpoints and **disagree in the interior** — 1.82 vs 2.83 at n=10, c=0.3, ρ=0.5. A test asserts the disagreement, without which the pair could collapse to one function and every other test would still pass.

## Toy status, stated plainly

The optimization framework has produced **no measured improvement**, and the only measurement in this family is negative. §6 of the doc names the four things that would falsify it. `ApplyDial` / `ScoreTrajectory` / `SettleDial` are **type declarations with no bodies** — there is no trajectory runner in the tree, and a stub would have looked like progress.
