## Description

gate: promote `lint (TS)` into the required floor (Aaron, treaty-amendment consent)

Aaron, 2026-08-17: "yes add lint (TS) to the required floor". gate.yml's floor list carries
the standing rule "Re-adding a job to this list = adding to the floor = treaty-amendment
consent path", so this is that path being walked, not a silent list edit.

Change: `lint-typescript` joins gate-required's `needs`, and the registry gains a
`typescript-type-break` entry. The job already ran on every PR -- this only makes its result
COUNT, so no PR gets slower.

The evidence is the job's own header, written when it was created: "Slice 9 (PR #882) shipped
a real TS2322 to main because gate.yml previously had `dotnet build` for F#/C# but no tsc
step", and "codified rules (tsconfig strict mode) without a gate aren't a control." The
drift-and-heal flip later removed it from the blocking list. On 2026-08-17 the identical class
shipped again, same error code: TS2322 in installer/usb-iserial-probe.ts plus six TS2300s in
zflash/test-harness/run.test.ts, live on main while `gate (required)` reported SUCCESS --
measured on PR #11268, merged 02:05:47Z with `lint (TS)` FAILURE beside a green gate.

TWO THINGS RECORDED RATHER THAN SMOOTHED OVER, both in the workflow comment and the registry:

1. This does NOT close the case that prompted it. Both PRs behind the breakage were
   individually green; the duplicate import existed only in the MERGED tree. A pre-merge floor
   checks each branch against main-as-it-WAS, so a two-PR semantic collision is out of reach by
   construction. What it closes is the single-PR case -- a branch carrying its own type error
   can no longer merge past a red `lint (TS)`. The collision class needs a merge queue, and is
   left open and named rather than papered over.

2. The registry derives the floor as the ERASURE class, and a type error is NOT erasure -- it
   is fully reconstructible. Admitted on the adjacent `scoped-build-test-break` rationale (a
   functional break downstream lanes consume this tick) and labelled that way in the entry, so
   the registry's own derivation stays honest instead of being quietly widened to fit.

Verified: actionlint clean on gate.yml; registry parses, 7 entries, last id typescript-type-break;
`lint-typescript` resolves to exactly one job key.
