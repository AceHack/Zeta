## Description

## The defect

The `agencysignature (PR body)` job validates the **squash preimage** — correct, and
load-bearing, since `squash_merge_commit_message = COMMIT_MESSAGES` means every commit's
block really does land. It builds that preimage with:

```
gh api --paginate "repos/$REPO/pulls/$N/commits" --jq '.[].commit.message'
```

`GET /repos/{owner}/{repo}/pulls/{number}/commits` returns **at most 250 commits**.
`--paginate` reaches that ceiling and stops. So on a longer PR the validator judged the
oldest 250 messages and reported in its ordinary voice — **a check that did not fully
run, looking like one that passed.**

## Reproduced, 2026-08-17, live forge — PR #11528

```
$ gh api repos/Lucent-Financial-Group/Zeta/pulls/11528 --jq '.commits'
475
$ gh api --paginate repos/Lucent-Financial-Group/Zeta/pulls/11528/commits --jq '.[].sha' | wc -l
     250
$ git rev-list --count 34856165584ad825987c75de21e71a413307043f..a38c1acc15a43ab11331be8424d69f57e4ed57fd
475
```

225 commits were never read. The third line matters twice: it is the independent
confirmation of the 475, and it shows **git has no cap** — which is what the workflow
diff in the work-item is for.

Also measured on the same artifact: `Agency-Signature-Version:` occurs **269** times
across those **250** messages (squashed heartbeat merges carry several blocks each), so
the stream cannot be counted from its own content. That is why the count comes from the
event payload rather than from the text.

#11555 removed the *cause* of 400-commit branches in the flush lane — post-fix flush PRs
measure 1–3 commits (#11623 = 1, #11625 = 3). It did not fix the check.

## What changed

New `src/Core.TypeScript/hygiene/agencysignature-commit-coverage.ts` — pure, injected
environment, no network — decides one thing: **can the caller show that the commit list
it piped in covers the whole proposal?** Only the PASS is guarded by the answer:

| input | before | now |
|---|---|---|
| complete list, valid blocks | PASS (0) | PASS (0) |
| complete list, disagreeing blocks | FAIL (1) | FAIL (1) |
| **truncated list, valid prefix** | **PASS (0)** | **REFUSED, UNMEASURED (3)** |
| truncated list, violation in the prefix | FAIL (1) | FAIL (1) — sound, kept |
| commit total unknown | PASS (0) | REFUSED, UNMEASURED (3) |

A FAIL over a truncated prefix is *sound* — the violating commit really is in the PR — so
it keeps its exit code and its diagnosis. A PASS over a truncated prefix is *unsound*.
Only the unsound one is replaced, and it is replaced by an honest "unmeasured", not by a
different accusation.

**No workflow edit was required.** The commit total comes from the Actions event payload
the yaml already exposes (`pull_request.commits`); the PR-body lane is exempted by DATA
(stdin byte-identical to `PR_BODY`), not by a step name. If that discrimination drifts,
the body lane starts being checked too — drift buys **more** refusal, never less.

The cross-commit consistency rule is untouched. It is correct; only its coverage was
broken.

The first push landed a **real** high-severity alert of mine: `js/insecure-temporary-file`,
alert #721, `validate-agencysignature-pr-body.test.ts:125`. The new CLI smoke test wrote
its fake Actions event payload to `join(tmpdir(), "…-<pid>.json")` — a predictable name in
a world-writable directory, no `O_EXCL`, so a pre-planted symlink is followed
(CWE-377/CWE-378). Not a false positive; fixed in the second commit with `mkdtempSync`
(atomic, mode 0700, random suffix), which is the pattern ~10 other files here already use.
