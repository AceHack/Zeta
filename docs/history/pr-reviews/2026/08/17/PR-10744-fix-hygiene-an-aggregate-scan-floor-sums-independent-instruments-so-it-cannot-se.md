## Description

## The defect

A **scan floor** — exit non-zero if the check inspected fewer items than a stated
minimum — is the guard against a check silently becoming a no-op. It has earned itself
twice here: one guard shelled `rg`, absent on the CI runner, inspected 0 files and its
floor caught it on the first CI run; `lint:markdown` linted nothing for months (#10712).

But **a floor over a total is itself a partially-blind instrument**. Where the corpus
arrives by several independent routes, an aggregate floor sums independent instruments,
so it cannot detect the failure of any one — redundancy in the numerator hides a zero.

## Two dark routes were already live on main

Both invisible to their own aggregate floor, both found by this audit rather than
assumed:

1. **`no-agent-gate-bypass.test.ts` searched a root that could never contribute.**
   Five `git ls-files` roots, union floored at 100. Measured: `.github` 69,
   `src/Core.TypeScript` **1678**, `clis` 1, `.claude` 15, and `skills` **zero** — both
   of that root's tracked files are `.md`, which the check's own `ALLOWED` list excludes
   by design. Removed rather than floored: a root that can only contribute excluded
   files is not coverage, it is the appearance of coverage. Executable skill surfaces
   live under `.claude/skills`, inside the `.claude` root.

2. **The byte-lock's Go substrate has never executed in CI.** `run-go-wasm.mjs` needs
   `dla-canonical-go.wasm`, which is not committed and not built by the workflow, so it
   reports TOOLING-ABSENT every run while `executed >= 2` stayed satisfied by the other
   eight. Now **declared** absent in `bytelock.yml` rather than silently missing.

## The refinement — measured, not assumed

The blindness belongs to **union** aggregation, not to multi-route corpora as such. Two
shapes are already sound and are deliberately **not** churned:

- **Intersection corpora.** `audit-schema-key-set-parity.ts` compares only schema ids
  bound in two oracles at once, so killing either extractor drops the compared set to 0.
  Proven both ways: F# route dark `exit 3` (compared 0), TS route dark `exit 3`
  (compared 0), both live `exit 0` (compared 6).
- **A floor whose value equals the mandatory route count.** `cross-verify-ir.test.ts`
  requires ≥ 6 languages of 7 attempted with the 7th (Q#) explicitly optional — per-route
  in effect.

## The recursion, handled

The audit shipped here is itself an enumerating check, so it carries a **per-recognizer**
floor — four independent recognizers, each required to contribute ≥ 1:

```
baseline                          exit=0  sites=56  dark=[]
dark named-min-constant           exit=3  sites=42  dark=[named-min-constant]
dark cli-min-flag                 exit=3  sites=51  dark=[cli-min-flag]
dark floor-prose                  exit=3  sites=31  dark=[floor-prose]
dark count-assertion              exit=3  sites=44  dark=[count-assertion]
restored                          exit=0  sites=56  dark=[]
CLI with one dark route           exit=3  ROUTE FLOOR BREACH names it
```

The total never falls below 31, so a floor on the total would have been blind to all
four. The floor is **one per route** — the non-vacuity boundary, and the only value that
is not a guess about how many floors the repo ought to contain.

**Self-exclusion is load-bearing, and the claim is recorded at its measured size.** The
first draft asserted the audit's own source satisfies all four recognizers; the test
written to pin that **failed** (received 1). The truth: the source contributes 13
`floor-prose` hits and the test contributes named-min-constant 2, floor-prose 1,
count-assertion 3 — three of four routes self-satisfiable, `cli-min-flag` not. Three
floors that could never go dark is still three blind instruments, so the exclusion stays
and the comment now says three.

## Not converted, and why

**Verified single-route** (an aggregate floor is correct; not touched):
`lint-no-ambient-credential-hoist.ts` (one walk, two filters) ·
`zeta-id/sort-key.test.ts` (one readdir) · `audit-skill-description-length.test.ts` (one
dir) · `eve-translation/aut-budget.ts` (set equality, stronger than a floor).

**Already per-route:** `unexecuted-test-files.ts` — two floors on two genuinely
independent routes (the file walk, the workflow parse). Its `hiddenTestFiles` is a third
*filter* over the same `trackedFiles` gather, so `MIN_TEST_FILES` already covers it.

**No floor at all**, reported rather than blanket-fixed:
`lint/doc-comment-history-audit.ts` (4 `SCAN_ROOTS`) and `hygiene/audit-research-docs.ts`
(multi-root `DEFAULT_ROOTS`). Whether either wants a floor is a judgement per check, and
an arbitrary floor that never fires is another blind instrument.

**No floor is weakened anywhere** — every aggregate floor is kept and a per-route floor is
added beside it.

## Adjacent finding, not fixed here

`src/wasm-dla/bytelock/dla-canonical-zig.wasm` is not a WebAssembly module — it is an
`ar` archive (`!<arch>`), the unlinked `zig build-lib` intermediate. Every run prints
`expected magic word 00 61 73 6d, found 21 3c 61 72`. It counts as *executed*, so it trips
neither floor. Rebuilding it needs a Zig toolchain and belongs in its own change.
