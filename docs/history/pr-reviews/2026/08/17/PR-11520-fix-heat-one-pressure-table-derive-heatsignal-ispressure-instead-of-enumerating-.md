## Description

Closes `081M07Z23EX087G0R003N676FT` — the residual PR #11476 filed off #10804, deliberately
not fixed inline.

## The defect, stated at its real size

Post-#10804 `HeatSignature.isPressureKind` and `HeatSignal.isPressure` could no longer disagree
on an **input** — both funnel through the single `classifyKind` chain. What survived is that they
named the pressure cases in **two exhaustive tables**, one per union:

```fsharp
// HeatSignature.isPressureKind — keyed on KindClass
| KindClass.Backpressure | KindClass.Denied -> true

// HeatSignal.isPressure — keyed on HeatSignal
| HeatSignal.Backpressure | HeatSignal.Denied -> true
```

The compiler forces exhaustiveness so nobody can *forget* a case, but nothing forces the two
`-> true` sets to **correspond**. Add a case and mark it pressure in one table only and the
kind-string route answers differently from the signal route again. The lint's PART B3 guarded
*"two tables that agree"* — strictly weaker than *"one table"*, and it said so in its own header.

## The fix — one table, and the split becomes unrepresentable

```fsharp
HeatSignature.isPressureClass : KindClass -> bool        // the ONE table
HeatSignature.isPressureKind  = classifyKind >> isPressureClass
HeatSignal.classOf            : HeatSignal -> KindClass  // correspondence; decides nothing
HeatSignal.isPressure         = classOf >> HeatSignature.isPressureClass
```

`HeatSignal.isPressure` keeps its `HeatSignal -> bool` signature, so `DarkHallScheduler.fs:146`,
`Heat.fs` (`dispositionOfKind`, `ofCounts`, `ofSignature` consumers) and
`SchedulerShedHeat.Tests.fs` all call it unchanged.

**The fail-safe chain direction is untouched.** Pressure is still tested first in `classifyKind`,
so a dual-token kind reads `Backpressure` and a room under genuine backpressure never reads cold.
Mutant M7 below is the guard that this stayed true.

**The direction of the derive is forced, not chosen.** F# compiles `HeatSignature` before
`HeatSignal`, so the one table cannot live on the signal side and call back into `ofKind`. Worth
recording because it is the answer to *"why not key the table on `HeatSignal` and drop `classOf`?"*

## What this trades — honest register

The membership split is gone: there is no second `-> true` to split from. What replaces it is a
**miswire** risk in `classOf` — `HeatSignal.Denied -> KindClass.Forgotten` is exhaustive, type-
checks, and would silently answer the deferral-vs-destruction question wrong. That is a strictly
smaller and more visible class than the split, and it is falsified twice rather than trusted:

- **F#** — the round-trip law `classOf (ofKind k) = classifyKind k`, one representative kind per
  class including `Other`, in `DarkHallScheduler.Tests.fs`. Stated through the real string chain
  rather than as `classOf x = <literal>`, which would only restate `classOf`'s table at itself.
- **Lint PART B3b** — parses `ofKind` and `classOf` out of `Heat.fs` and requires them to be
  **mutual inverses**.

The deeper repair (make deferral-vs-destruction a typed field, so `HeatSignal`/`KindClass` stop
being two names for one classification) remains `081M00TNWM8087G0R0027ACGKY`.

## PART B3: rewritten, not kept, not deleted

The work-item asked whether B3 should survive the unification. Decided with evidence, both ways:

- **Keeping it as written would be the vacuity class.** With one table there is nothing to
  disagree with — the comparison could no longer fail. (Confirmed mechanically: after the derive
  the old check hit its own floor, `HeatSignal-keyed=0`, rather than passing. It could not have
  been left alone even if we wanted to.)
- **Deleting it would be a regression**, because two live defect classes remain that neither the
  compiler nor the F# tests see structurally.

So its subject moved:

| | check | what it refuses |
|---|---|---|
| **B3a** | exactly one `KindClass`-keyed pressure table, **zero** `HeatSignal`-keyed ones | a second table reappearing — **even one that agrees** |
| **B3b** | the `KindClass ↔ HeatSignal` correspondence is a **bijection** | a miswired arm in either direction |

B3b **strictly subsumes** the old comparison: the old one compared pressure *sets*, so a miswire
among the non-pressure arms was invisible to it. Mutant M5 is that case, measured.
