## The problem, verified rather than assumed

`test (TS suite)` is not in `gate (required)`, so a red X on it is waved through — by humans and by agents. The brief for this work said the failures were environment-dependent noise. **Half of that is right, and the half that is wrong is the important half.**

**In CI, red already meant a real regression.** MEASURED 2026-08-16 across the 53 most recent completed `gate` runs (17 failures / 36 successes = **32% red**):

| failing test | runs | cause |
|---|---|---|
| `folderSink — entropy tracker wiring > a caller that KNOWS the menu size charges the real erasure: log2(N), not 1` | **15 of 17** | **real, deterministic code failure** |
| `the checked-in ledger keeps main green > the repo audits clean against its own ledger` + `LIVE tripwire — the tracked tree must stay at or under baseline` | 2 of 17 | real hygiene failures |
| a cluster of 18 device-binding tests (`THE FALSIFIER`, `RMA / re-provision`, `binding identity …`) | 1 of 17 | PR-local, on a branch |

Zero of those were environment-caused. `folderSink` sat red across sixteen merges and was eventually fixed by someone else — nobody was reading the check.

**On a laptop, red meant the environment.** MEASURED the same day, fresh clone of `main`, macOS, `bun install --frozen-lockfile` only — `bun test` = **11,566 pass / 8 skip / 4 fail / 1 error**:

| # | failure | real cause |
|---|---|---|
| 1 | `cross-verify-ir > Q# lane prerequisites present` | `src/Core.Python/.venv/bin/python3` absent — needs `uv sync --project src/Core.Python` |
| 2-4 | `cross-verify-ir > splitmix64` / `fmix32` / `every named oracle lane participates` | `dotnet run` cannot find SDK `10.0.302` (`global.json`) |
| 5 | `esp-inject.test.ts` — **unhandled error, module scope** | `EPERM: operation not permitted, scandir '/Users/acehack/Downloads'` (macOS TCC) |

Corrections to the brief, stated plainly:
- Not 8 failures — **5**, in **2 files**.
- **No kind/k8s cause.** `cluster/dev-cluster/use-cases.test.ts` prints `Creating kind cluster zeta-ci …` from a *fake* `LocalClusterDriver`; it is fully hexagonal and hermetic. The log line looks like a cluster call and is not one.
- **No timeout cause** in either lane.
- The file-level environment tier was **already** partitioned (5 files in `bunfig.toml` + `registry/unexecuted-test-files.json`). What remained was *test-level*, inside one file that deliberately asserts-don't-skip.

**So the real mechanism is a local/CI divergence in what red means**, not CI noise. The same command is red-for-environment where people work and red-for-regression where it matters, with nothing in either output separating the two. The prior "this suite is always red" is learned on the laptop and spent on the pull request.

## The split

| tier | job | contents | measured |
|---|---|---|---|
| hermetic | `test (TS hermetic)` | 995 files, **11,611 tests** | fresh clone, **no `uv sync`, no .NET SDK 10** → `11,611 pass / 8 skip / 0 fail`, exit 0 |
| environment-dependent | `test (TS environment-dependent)` | **2 files, 6 tests** | runs on every PR, with the `uv sync` |

**Where the line is drawn, and why.** Hermetic = reproducible from a checkout plus `./tools/setup/install.sh && bun install --frozen-lockfile`, and nothing else. That is not arbitrary: `install.sh` is the repo's three-way-parity contract (GOVERNANCE §24) — the one baseline a laptop, a devcontainer and a runner are guaranteed to share. Anything a test needs *beyond* it makes that test's verdict a fact about the host.

Measured, not assumed: with `PATH` stripped below `install.sh` (`/usr/bin:/bin:/usr/sbin:/sbin` + bun) the same suite gives **49 failures** across git-, python3-, go-, rustc-, dotnet- and solver-dependent files. Drawing the line *below* `install.sh` would move a dozen more files — including the cross-language law and Clifford byte-lock suites — out of the blocking-eligible tier, to buy a property this repo does not support. Recorded in `bunfig.hermetic.toml` so it is not re-litigated from scratch.

## Mechanism: the repo's, not a new one

`bun test` positional arguments are *include* filters; bun has no exclude form. The repo already has exactly one place where "bun must not discover this" is written down — `pathIgnorePatterns` — under exactly one discipline: every entry declared with a written reason in a registry, enforced by a checker that fails on an undeclared, unreasoned, or stale entry. This is that mechanism at one more tier.

- **`bunfig.hermetic.toml`** — invoked as `bun --config=bunfig.hermetic.toml test`. Still bare and filter-less, so the "a filter list regrows the forge-host bug" argument in the `test-typescript` header still holds.
- **`registry/environment-dependent-test-files.json`** — like its sibling, but each entry must additionally carry a **`dependency`** naming the concrete missing thing (an SDK version, a venv, a device). "environment" is rejected as a dependency name.
- **`hygiene/environment-dependent-test-files.ts`** (+ 22 unit tests) — asserts `ignores(hermetic) == ignores(base) ∪ registry`, and is red on: an undeclared exclusion, an unattributed one, one listed in **both** registries, one that is not a tracked test file, and — the load-bearing one — **one that no `pull_request`-lane invocation executes.** Excluding a file from hermetic while nothing else runs it is a deletion wearing a split's face; that condition is now unlandable.

**Skips are explicit and attributed.** `esp-inject` now prints, using the repo's existing 20-site idiom:

```
  [skip] no zeta-installer ISO — /Users/acehack/Downloads is unreadable: EPERM: operation not
  permitted, scandir '/Users/acehack/Downloads'; FAT12 ESP inject not exercised
```

`console.warn`, not only a test title, because bun's non-TTY reporter — the one CI and any piped run use — prints the *count* of skips and not their names.

`cross-verify-ir` keeps asserting-don't-skip. Its header is right that a byte-lock reporting 7-language agreement while a lane executed 0 cases is the lie the per-route floor was added to end. It moves **tier**, never verdict — and it still runs in `full-verify`, which *is* in the floor.

## Two defects surfaced on the way

1. **`esp-inject` crashed the whole suite from module scope.** `existsSync` is not permission: the directory exists and `readdirSync` still throws `EPERM` under macOS TCC, before `test.skipIf` could decide. A host privacy setting could take down a run of 11,577 otherwise-fine tests. Now fail-soft.
2. **`unexecuted-test-files`' invocation regex was `/\bbun\s+test\b/`** — it cannot see `bun --config=… test`, and `-c` must precede the subcommand (verified: `bun test -c bunfig.hermetic.toml` reads the path as a filter and matches nothing). The hermetic lane read as running **nothing**, making 817 files report unexecuted. An invocation form the parser cannot see is a lane it silently writes off — the checker's own defect class, one level up. Widened to flag-shaped tokens only, with an end-to-end fixture test.
3. `bunfig-declares-no-test-timeout.test.ts` now covers **every** `bunfig*.toml`, plus a manifest test so adding a third config without listing it fails.
