## Description

## Why

The ladder doc has said since #10685 that every attestation terminates in a named silicon-vendor root — AMD ARK, Intel SGX Root CA, NVIDIA's device-identity CA, a TPM manufacturer's EK root CA, `AWS_NitroEnclaves_Root-G1` — and that a claim which does not say what it chains to is not checkable. **The type did not hold anyone to it.**

Verified on `main` before changing anything. `AttestedEvidence.trustRoot` in `key-erasure-meter.ts` was a bare `string`:

```
trustRoot=""              -> reading=no-information
trustRoot="   "           -> reading=no-information
trustRoot="unknown"       -> reading=no-information
trustRoot="r"             -> reading=no-information
trustRoot="trust me bro"  -> reading=no-information
```

All five type-correct, all producing a byte-identical reading. The file's own tests passed `"vendor-root"` and `"r"` — placeholders naming nothing, which is the defect wearing its own test as cover.

Same class as an unanchored coinage under `anchor-to-human-prior-art`: an unnamed anchor is a debt, not a credential.

**Scope note, stated plainly:** the entire declared scope of `081M00QP7FB087G0R00031BQ93` was documentation, and all three of its items shipped in `a619ee9bd1` / #10685. That row was simply never moved out of `backlog`. This PR is the **code** half, which the item did not scope.

## What

New `src/Core.TypeScript/algebra/vendor-trust-root.ts`:

- **`VendorTrustRoot` is branded** by an unexported `unique symbol`, so no object literal written outside the module satisfies it. The roster constants and `declareVendorTrustRoot` are the only doors — illegal state is unrepresentable in the type rather than rejected by a runtime check a caller can forget.
- **`VENDOR_TRUST_ROOTS`** — the five roots transcribed from the CHECKED table in the ladder doc, each carrying the vendor, the chain leaf-to-root, and the distribution service. The doc's two-column split is preserved in the shape: the trust root is **irreducible**, the vendor's verification service is **avoidable**, and avoiding the service does not avoid the root.
- **`declareVendorTrustRoot`** — the escape hatch for a root the industry has and this repo has not checked. Deliberately *not* an escape hatch for an unnamed one: blank vendor, empty chain and blank chain element are refused, and the result is marked `onCheckedRoster: false` so "named and checked here" stays distinct from "named by the caller".
- **`parseVendorTrustRoot`** — the JSON boundary, where the brand does not exist. An unknown authority is **refused**, matching `Wall.Whitebox` / `whiteboxPermitted` in `DerivationProtocol.fs`: unknown is not permissive.

`AttestedEvidence.trustRoot` is now `VendorTrustRoot`, and `readEvidence` names the root and its chain in the reading.

**No root-key fingerprints appear anywhere.** A digest written from memory is a fabricated anchor — worse than none, because it looks checkable. They belong with the verifier that would compare against them, and a test asserts none crept in.

## Limits

**Nothing here verifies anything, and nothing here chains.** This module carries no cryptography: it does not fetch a certificate, parse a quote, check a signature, or walk a chain. `chainToRoot` is the chain's **name** — a description of what a verifier would have to walk — not evidence that one was walked. Calling it a trust chain would be the overclaim this PR exists to stop.

So `attested` still reads `no-information`, exactly as before. What changed is that the claim now **names the root it would have to chain to**; naming is a precondition for chaining and is not chaining. The reading also carries the ceiling forward: the strongest statement available even with a working verifier is *"AMD says this is genuine AMD silicon running this measurement"*, never *"this node is genuine"*.

The brand is a TypeScript brand — `x as unknown as VendorTrustRoot` defeats it, as it defeats every brand. `parseVendorTrustRoot` is the guard for where the type system is absent entirely.

Surveyed and left unchanged because already correct: `FrostDeviceAttestationV1` (`frost-ca-custody.ts`) names its root as `groupPublicKeyHex` — a Zeta-native FROST root, not a vendor one; and `src/Bayesian/Attested.fs`, a different sense of the word (evidence provenance), where `FromSource` already requires a named source and `Unattested` is the explicit un-named case that can never be deduplicated.
