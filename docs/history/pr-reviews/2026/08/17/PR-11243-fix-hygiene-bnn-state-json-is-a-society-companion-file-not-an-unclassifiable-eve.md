## Description

fix(hygiene): bnn-state.json is a society companion file, not an unclassifiable event name

main is RED and every open PR inherits it. `lint (structural hygiene)` is in the
`gate (required)` floor, and `audit-observe-event-filenames` fails on
`docs/observe-events/bnn-state.json`, which reached main via #10708 (e417aa98e3).

The file is not an event. It is the dimensional-BNN rollup written by
`planning/society-bnn.ts` (`SOCIETY_BNN_FILENAME`), so it belongs in exactly the
category `society-index.json` already occupied -- a named, non-event companion of the
society runner. `INDEX_NAME` becomes `COMPANION_NAMES`, a CLOSED set of two names, each
annotated with its producer.

What this deliberately does NOT do:
  - It does not relax `ZETA_ID_NAME` or add a `*-state.json` pattern. Widening a shape
    is how this audit would stop catching the hex-encoded-JSON class it exists for. The
    new test `the allowlist is a CLOSED list of names, not a pattern` is the falsifier:
    mutating the check to `/-state\.json$/` kills it and nothing else in the file.
  - It does not settle whether a state rollup belongs in an EVENTS folder at all.
    Relocating it changes the producer's write path and every reader -- a larger call
    than unblocking main, and one worth making deliberately rather than under a red gate.

The allowlist is held to its producer rather than commented: the test asserts
`COMPANION_NAMES.has(SOCIETY_BNN_FILENAME)` against the exported constant, so a rename
on either side fails loudly instead of leaving the audit permitting a filename nothing
writes while rejecting the one it does.

Worth recording: this was invisible for two days because the gate that would have caught
it on the society lane was itself parked (fixed in #11227). The first thing that gate did
on its first real run was find this.
