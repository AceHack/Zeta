## Description

test(installer): pin what "whitespace-only is absence" costs when a keyfile is also present

`selectCliBindingMaterial` decides that a whitespace-only value is ABSENCE rather than
malformed input. That is deliberate and documented -- "it is a typo or an empty shell
variable" -- and pinned by `still treats a whitespace-ONLY value as no factor at all`.
I started out changing that behaviour and reverted: the reasoning is sound and the
decision was already made.

What was never written down is what the rule COSTS when a SECOND factor is present.
`--usb-iserial "$SERIAL" --uefi-keyfile k` with SERIAL unset leaves `hasIserial` false,
so the mutual-exclusion guard never fires and the blob binds to the KEYFILE. Nobody is
locked out -- the factor is recorded, so restore agrees -- but the binding an operator
BELIEVES they have is not the one they have, and no diagnostic says so.

These two tests change no behaviour. They pin the consequence so the trade is visible:
if "absence" is right they pass and document it; if it is judged wrong they are the
tests that turn red and name exactly what changed.

Verified non-vacuous: mutating the presence test to `input.usbISerial !== null` (the
alternative design) kills both, and NO pre-existing test in the file catches that
mutant -- the interaction was genuinely unpinned. 16 pass / 0 fail.
