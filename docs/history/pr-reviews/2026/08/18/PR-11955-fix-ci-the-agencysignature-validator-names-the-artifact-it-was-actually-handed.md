## Description

## The defect

`.github/workflows/agencysignature-enforcement.yml` runs **one** validator over **two
opposite artifacts** — one step pipes the PR description, the next pipes the PR's commit
messages — and `emitParseFailure` hardcoded one provenance:

> this check reads COMMIT MESSAGES, not the PR description — a perfect block in the PR
> description does NOT satisfy it.

Emitted by the **PR-body** job, every sentence there is false for the text it had just
read, and it explicitly denies the fix that works. A message that cannot be right for both
inputs is evidence for neither: the vacuity class inside the tool built to enforce against
that class.

**Measured cost (2026-08-17):** PR #11707 closed and its branch rebuilt (#11710) chasing a
commit-side defect that was not the cause — the actual remedy was one `gh pr edit
--body-file`. A second agent hit the same sentence within the hour (#11712).

Work item `081M092W2E7087G0R000KDKHWS` (moved to `workitems/done/` here).

## What changed — the diagnostic only

Every verdict is byte-identical; behaviour is unchanged.

- `--source pr-body|commit-messages` on `ValidatorOptions`/`parseOptions`, passed from
  **both** workflow call sites. The failure text is derived from a per-artifact prose
  table, so no path can fall through to the other artifact's remedy.
- `emitMissingKeys` carried the same defect in the other direction ("PR body trailer block
  is incomplete" while reading commits) and is fixed with it. **That one was not in the
  filed diagnosis.**
- **Both requirements stay enforced and stay stated.** Each message says the other
  artifact is judged by a *separate job* and that **BOTH are required** — so the fix cannot
  be read as "the block is only needed here".

## Fail closed on omission — two levels, both explicit

| level | `--source` absent | why |
|---|---|---|
| **CLI** (`import.meta.main`) | **exit 2**, before stdin is judged | the level the bug lived at is the level that refuses; a step that forgets the flag goes red loudly instead of printing a guess as a diagnosis |
| **in-process `main([])`** | registers as `unspecified` — text names **neither** artifact, prescribes both | the commit-coverage suite genuinely has no artifact to declare; forcing it to invent one would manufacture the false provenance this fix removes |

An unknown value (`--source prbody`) is a usage error, never a silent fall-back to the
neutral register.

## The falsifier

`describe("the failure text names the artifact it was actually handed")` — the two
invocations must not emit the same bytes; the pr-body path must name `gh pr edit` and must
**not** say "at the very bottom of the COMMIT MESSAGE" or prescribe `git
interpret-trailers`; the commit-messages path is the mirror. Pre-fix the two outputs were
byte-identical.
