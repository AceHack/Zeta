## Description

fix(hygiene): roster the mutation-findings log as prose — third main-wide red

`lint (yaml/k8s)` is RED ON MAIN and therefore blocking every open PR. Found the same way as the
previous two: a failure appearing on unrelated PRs (an archive lane and a heartbeat flush), which is
the signature of a repo-wide red rather than a PR-specific one. Verified by running the auditor
against clean `origin/main`, not inferred from the PR.

`db/mutation-findings/soraya.jsonl` landed via #12091 and names the stale tree without a roster row.
The check is CORRECT: `infra/k8s` and `infra/nixos` are scheduled for deletion, so anything newly
naming them is new coupling unless it declares a disposition and a migration target.

WHAT THE FILE ACTUALLY IS, checked rather than assumed: an append-only mutation log, 110 records of
{source, test, mutation, outcome, address}. It names the stale tree in exactly TWO of them —
`infra/k8s/tests/validate-bootstrap.ts` and its `.test.ts` — recording that a mutation was run
against the bootstrap validator the k8s lane wrote. Nothing resolves against those paths. They are
the SUBJECT of a past run, logged.

So this is `prose`, the same disposition and the same reasoning as the ΔU ledger entry rostered
earlier tonight, and for the same structural reason: a RECORD that names a tree is not a CONSUMER of
it. Correspondingly `blocking + derived` stays at 9 — the counter gating whether deleting the tree
is provably safe is untouched, which is the right outcome. Only `prose` moves, 5 → 6.

MIGRATION TARGET IS DELIBERATELY "NONE — DO NOT REPOINT". The tempting move is to rewrite the path
to `full-ai-cluster/` so the roster shrinks. That would falsify the log: the mutation genuinely ran
against that file at that path, and a mutation record whose job is to say what was tested must stay
accurate about what was tested. Drop the row when the tree goes — the log is append-only and its
records are content-addressed, so nothing is lost.

Verified: `audit-cluster-tree-consumers.ts` reports "roster matches the tree".
