## Description

Files a CI regression found and entailment-checked tonight. **Filed, not fixed.**

## The finding

**9 of 9** cancelled jobs sampled across six recent `gate` runs died in the *same* step, and the log names it rather than my inferring it:

```
##[error]The operation was canceled
  step: Install toolchain via three-way-parity script (GOVERNANCE §24)
```

That is the **same step** `rerun-cancelled-gate.yml`'s header documents as the original root cause — *"a stalled apt mirror inside the toolchain install step, fixed at the root in `tools/setup/linux.sh` in the same commit"* (12 of 14 hung jobs, 2026-08-14). This is a regression of that fix.

## Why the second line can't save it

A job hangs in the install → runs to its `timeout-minutes` ceiling → GitHub reports the kill as **`cancelled`**, not `failure` → `gate (required)` goes red → `rerun-cancelled-gate` retries → **the hang is deterministic, so the retry reproduces it.**

PR #11735 burned ~40 minutes proving this: cancelled 00:29:20, re-enqueued, cancelled again 01:03:13. Durations match the ceilings exactly:

| job | duration | `timeout-minutes` |
|---|---|---|
| `lint (C#)` | 15m16s | 15 |
| `lint (Python)` | 15m15s | 15 |
| `cross-verify` | 12m15s | 12 |

## This is the tripwire that workflow installed

It calls itself **"THE SECOND LINE, NOT THE FIX"** and states: *"If the rerun rate rises, the root cause has returned and must be fixed there — the log line below exists to make that visible rather than quietly absorbed."*

**The recovery working is exactly what hid it.** Every affected PR eventually goes green, so each instance reads as covered infra noise — which is how I classified a dozen of them across tonight's session before checking the logs. Same shape as `081M092W2E7087G0R000KDKHWS`: a mechanism that makes a problem *invisible* rather than *absent*.

## Two corrections kept in the record

1. A cancellation-*rate* claim ("75%", then "57% vs a 37% baseline") was computed off a **bad denominator** — cancellations counted against windows including still-running runs. **Do not cite those numbers.** The job-level evidence is the finding; the rate is not established.
2. "A different place than the original apt-stall" was **wrong** — same step. Inferred from durations before the logs were read.

## Why not fixed here

The root is `tools/setup/linux.sh`, consumed three ways per GOVERNANCE §24 (dev laptops, CI runners, devcontainer images). Raising `timeout-minutes` would convert a hang into a slower hang and is the wrong lever. Neither is an appropriate blast radius for an unattended loop at 01:15Z.
