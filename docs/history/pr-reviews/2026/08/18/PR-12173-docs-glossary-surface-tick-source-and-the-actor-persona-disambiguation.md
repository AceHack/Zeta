## Description

docs(glossary): Surface, Tick source, and the actor/persona disambiguation

Aaron asked for the persona/actor/surface/tick-source mapping to land in the root glossary. Landing
it, and resolving an ambiguity rather than adding to one.

WHAT I FOUND BEFORE WRITING. The glossary ALREADY warns that "persona" is overloaded — agent
persona/expert vs user persona — and that bare use is a lint smell. And its recommended fix assigns
"actor" to the ES-native CONSUMER sense. But writer-actor-routing-model.md uses "actor" for the
RUNNING CLONE/LOOP. So the two senses of `actor` collide, and adding the routing vocabulary without
naming that would have compounded exactly the ambiguity the glossary exists to flag.

SURFACE, and the load-bearing half is not the location. Plain: WHERE something runs (cli/ide/cell/
container), the no-roles component of `persona ⊕ surface ⊕ instance ⊕ topology`. Technical: a
surface IS A HOST-BOUNDARY SEAM — the hexagonal port through which §13-metered entropy crosses, with
surface and host the same thing seen from two sides. Consequence, stated because it is easy to
re-derive badly: since a surface is by definition the metered port, "different surfaces at different
access levels" is NOT an access-control scheme layered on the topology — it is what a surface
already is. Enumerating surfaces is enumerating SEAMS, not processes.

TICK SOURCE. What drives an actor, and it CROSSES AT A SURFACE — which makes it a declared, metered
channel in the §13 sense rather than an ambient clock. That is why "different tick sources with
different access levels" restates §13 rather than introducing a concept. And a tick source is NOT an
actor; it drives one.

THE DISAMBIGUATION TABLE, with the collision named explicitly: routing-model persona = owner = what
remains (not the agent-persona/expert sense, not user persona); routing-model actor = clone/loop =
what acts = persona ⊕ surface ⊕ instance (NOT the ES-native actor used for user archetype). In
routing/topology prose `actor` means the running instance; in product/UX prose it means the user
archetype. Bare `actor` is now a lint smell for the same reason bare `persona` is.

AND THE CONSEQUENCE THAT MATTERS FOR DECOMPOSITION: an entity is NOT a service. One entity holds a
SET of (tick source, authority) pairs across several surfaces at once and may span a cluster
boundary — so a service decomposition enumerates surfaces an entity acts through, never the entities
themselves. Bus address is not identity.

Aaron settled `surface` as the standing term 2026-08-18. NOT DONE HERE: merging with the concepts
page on the LFG root-site repo — that is a different repository and the material is Addison's, so
coordinating it is hers to be part of rather than something done to her work.
