## Description

Follow-up to #11975 (081M08MVPR9087G0R000NCF8PV). Found by running the `--write` sweep
end-to-end against a sandbox checkout rather than trusting the unit tests, which inject
`runArchiver` and therefore cannot see this.

`ARCHIVER` was the repo-relative string "src/Core.TypeScript/forge-host/github/archive-pr-reviews.ts"
and the spawn used `cwd: repoRoot`, so it resolves only when the repo being reconciled is
also the repo the tool lives in. Against any other checkout:

  archiver failed for #10367: error: Module not found ".../archive-pr-reviews.ts"
  archiver-failed  PR #10367  0 -> null

Why this mattered more than a bad path usually does: the heartbeat step treats a non-zero
exit from the sweep as a non-fatal `::warning::`, so a permanently-failing archiver spawn
would have been a lane that never reconciles anything while the step keeps reporting
success. That is the silent-no-op family this same step already ate once, when `--batch 3`
was not an accepted flag and `| tail -10` swallowed the exit code for months.

The archiver is a sibling module, so it is now resolved with `import.meta.dir`. After the
fix, the same sandbox run reconciles PR #10367 from a doctored `0` back to `12` threads and
restores the full review content (12 review comments), and a second run reports "nothing to
reconcile" — idempotent, as §12 requires.

Falsifier: two tests asserting the path is absolute and points at a file that exists. They
fail against the previous relative string. 29/29 mutants still killed.
