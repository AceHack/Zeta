## Description

fix(hygiene): the ambient-time guard's own sort was culture-sensitive

Second main-wide red, found the same way as the first (#12129): `test (TS hermetic)` failed on an
unrelated branch of mine, and running it against clean `origin/main` gave 30 pass / 1 fail —
inherited, not caused there. A failure that reproduces on a docs-only branch is the signature of a
repo-wide red rather than a PR-specific one.

The failing assertion is the collation ratchet's LIVE tripwire. bun truncated the violating file out
of its output, so I replicated the scan directly rather than guessing:

    src/Core.TypeScript/hygiene/audit-ambient-time-in-tests.ts  found=1 allowed=0  kind=new-file

The guard that landed to enforce one discipline violates another. Line 221 sorted findings with
`a.callee.localeCompare(b.callee)` — culture-SENSITIVE, which `.claude/rules/culture-invariant-by-
default.md` forbids outright, and it arrived as a new file so the baseline correctly allowed zero.

FIXED, NOT BASELINED. A baseline row is for pre-existing debt; adding one for a file landed hours
ago would convert a caught violation into accepted debt, which is the ratchet running backwards and
is exactly what the row-must-carry-a-reason test exists to make expensive. Replaced with an ordinal
comparison (`<` / `>` on the strings) — codepoint order, locale-independent, the TypeScript
equivalent of `StringComparer.Ordinal`. The sort is over callee names drawn from a fixed internal
set, so the ordering is unchanged in practice; what changes is that it no longer depends on the
runner's locale, which is the property the four-language byte-lock and DST replay both require.

Verified after: collation ratchet reports zero violations; the ambient-time guard itself still
reports "OK: 1066 test files scanned; no test verdict depends on wall-clock delay. 11 elapsed-time
observation(s) named and counted"; the guard's own suite 25 pass / 0 fail.
