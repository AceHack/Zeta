## Description

Files a bug found twice in one hour today. **Filed, not patched** — see below.

## The defect

`.github/workflows/agencysignature-enforcement.yml` runs **one** validator against **two opposite inputs**: the `agencysignature (PR body)` job pipes `$PR_BODY`, the squash-preimage job pipes the commit messages. The tool reads stdin and cannot tell which it got — but its failure text hardcodes one provenance:

> `FAIL: no parseable git trailers found in the PR's COMMIT MESSAGES`
> `NOTE: this check reads COMMIT MESSAGES, not the PR description — a perfect block in the PR description does NOT satisfy it.`
> `Fix: append the 10-trailer block at the very bottom of the COMMIT MESSAGE (not the PR description).`

When the **PR body** job emits that, every sentence is false for the artifact it actually read — and it explicitly denies the fix that works.

## Measured cost

1. **#11707 → #11710.** I followed the message, found a *real but unrelated* contiguity defect, **closed the PR and rebuilt the branch**. The rebuild failed identically. The actual fix was one `gh pr edit --body-file`.
2. **#11712.** A background research agent hit it within the hour and had to be intercepted mid-flight to stop it repeating the rebuild.

That agent independently found and wrote it up as §7 of its research doc, naming it better than I did: *one validator, two opposite inputs, one shared error message — it cannot be right for both, so it is evidence for neither.* **The vacuity class in CI dress**, inside the tool built to enforce against that class.

## Why filed and not fixed

The fix is small — a `--source pr-body|commit-messages` option threaded from both call sites, so `emitParseFailure` names the artifact it was handed. But this is enforcement tooling on the **required** `gate` check, its test suite asserts on output strings, and nobody asked for it. Filing beats patching a gate at midnight.

## Kept separate on purpose

The **commit-side** contiguity rule is real and is *not* this bug: a blank line between `Task:` and `Co-authored-by:` ends the trailer paragraph, so `git interpret-trailers --parse` returns only `Co-authored-by:` and the ten fields silently degrade to prose. Both requirements are genuine — the bug is that the diagnostic for one names the other.
