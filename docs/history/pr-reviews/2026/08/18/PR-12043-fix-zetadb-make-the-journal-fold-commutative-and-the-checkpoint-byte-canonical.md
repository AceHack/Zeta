## Description

Closes the byte-canonicality half of `081KZM0FTJM` — the fold race that gates the
stated dogfooding target: GitHub runners **and** local hardware **and** browser cells
folding at once. The fix is convergence, not a lock; a cross-substrate lock would be
central coordination (§1 scale-free) and would not survive a browser tab going offline.

## The bug, and the part that was not predicted

Two cells folding the same delta set produced **different checkpoint files**, because
`entries` persisted in arrival order. Git saw a real diff, last-writer-wins clobbered,
and content-addressing could not dedup. The filing named the fix — canonically order
`entries` — and deferred it as the owner's call.

**Canonical order alone breaks the ordinary retract-then-emit update.** `score/emit`
sorts before `score/retract`, and `foldRows` summed weights per `rowKey`, rejecting the
moment an incoming payload differed from the running one. So the *conflict verdict*
itself depended on arrival order across a zero-weight crossing — admitted one way,
`database-row-conflict` the other. The same order-sensitivity sat on the admission path.
The Dark Hall `replace` command is exactly this shape, and it caught the regression.

So there are two halves:

1. **Byte-canonical entries.** `validateImage` — the single point every serialisation
   passes through, encode and decode alike — puts the ledger in ordinal `eventId` order.
   A non-canonical checkpoint is now *refused on read* rather than quietly surviving on
   whichever node's next tick happens to be a no-op.
2. **A commutative fold.** Weights are summed per `(rowKey, payload)` — a Z-set — and
   well-formedness ("a row key names one payload") is checked **once at the end of the
   batch**, as a post-condition on the admitted SET rather than as a step of the fold.
   Addition is commutative and associative with `0` as identity, so the fold is a
   commutative monoid and the verdict is order-independent. That answers the work-item's
   analytic question in the affirmative, by construction.
