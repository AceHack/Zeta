## Description

Second finding from the pre-runner coverage audit (first was #9929). Mutation sweep of the cluster module: **14 mutants, 4 survived**. Three killed here; the fourth left deliberately.

## 1. The smoke-count boundary was never exercised

`childApplicationCount >= SMOKE_MIN_APPLICATIONS` flipped to `>` left the suite green. Every existing smoke test supplies 22 children against a threshold of 20 — comfortably above, so the boundary itself was untested in both directions.

This is the check that decides whether the App-of-Apps actually produced a cluster. An unpinned threshold there reports *ready* on a node that is one Application short — exactly how a runner ends up on a half-built machine. Now pinned on both sides: exactly 20 passes, 19 fails.

## 2. `readFlagValue` had zero test references

Two surviving mutants: `argv[index + 1]` → `argv[index - 1]` (reads the argument *before* the flag) and `value === undefined` → `!==`.

It was untested because it calls `process.exit(1)`, which ends the test runner rather than failing an assertion. That's a reason to build a capture harness, not a reason to leave unproven the parser deciding which cluster gets built from which git ref. Four cases pinned — including that a value merely *containing* a dash is accepted, since the guard is `startsWith` not `includes` and cluster names are dns labels.

## Not fixed, on purpose

`while (Date.now() <= deadline)` in `waitFor`. Module-private, and the mutant is a one-millisecond boundary on a local timeout — pinning it means exporting the function or injecting a clock for zero behavioural difference. Padding a test to move the number is the failure this tool exists to find.

Worth noting for the runner work: `waitFor` takes ambient `Date.now()`. Local wall-clock gating a local timeout is explicitly allowed, but it's also the injection point if the cluster harness ever needs DST replay.

**Result:** 13 of 14 killed, 44 tests pass, tsc clean.
