## Description

Refines #9856 and the allocation work-item with the distinction that makes the loop actionable:

| signal | means | response |
|---|---|---|
| repeated **drift** in an area | the *mechanism* is illegible | **fix the design** — more intelligence papers over it |
| repeated **decline** on a class | the class exceeds the current tier | **raise the tier** — the mechanism may be fine |

Conflated, you refactor healthy code *or* throw GPUs at a design smell. **Evidence from today:** both main-reds were **drift** signals (a bot with commit rights; a tsconfig typechecking AssemblyScript) — neither wanted a bigger model.

Requirements added: a **stable `class` id** on every decline (free text can't be counted — it's the join key that turns declines into a rate); **per-attempt, not per-week** denominators; **escalation must be reversible** (record promotions so a class can be *demoted* once the pattern is learned — otherwise the system ratchets toward always-expensive, defeating the objective); and a class still declining **at the top tier** is *a design problem wearing a decline costume* — route to a human, not more compute.

And plainly: the escalation ledger and the training set are **the same artifact**. 🤖 Generated with [Claude Code](https://claude.com/claude-code)
