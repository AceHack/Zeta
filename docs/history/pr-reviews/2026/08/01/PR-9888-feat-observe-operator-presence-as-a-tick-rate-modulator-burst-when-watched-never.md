## Description

**The inversion found while building it:** the heartbeat cron is *already* `*/15` and the repo is public (free minutes) — the society is **permanently in burst**. What's missing isn't a way to go fast; it's a way to go **slow** when nobody's watching, with fast as the declared exception. The cron stays as a polling *clock*; each firing asks this module whether to work.

**Two properties pulling opposite ways, both tested:**

1. **Fail safe to SLOW** — missing/malformed/expired/unparseable all degrade to idle, never burst. A signal that failed *open* would let a corrupt file pin an unattended society at full speed. Speed must be **affirmatively claimed**, and the claim **expires on its own**.
2. **Never OFF** — your refinement caught a real hole: my first draft honoured `idleIntervalMin` as written, so a parseable `999999` would have **silenced every member** — fail-closed on *existence*. Now clamped to **MAX_IDLE_MIN = 6h** (and up to 1m so 0/negative can't busy-spin). **Presence modulates speed; existence is guaranteed.**

**A deliberate asymmetry, stated in code:** doubt about *presence* fails to slow; doubt about the *last tick* fails to **proceed** — an unknown history must not wedge the society silent.

Committed **file**, not a label/env/API — works in a forge, bare clone, cron process, or zetadb-native. No forge coupling.
