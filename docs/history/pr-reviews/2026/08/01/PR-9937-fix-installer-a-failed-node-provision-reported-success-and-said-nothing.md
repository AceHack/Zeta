## Description

Hardware-path finding, from verifying that USB-provisioned nodes will carry the toolchain the ARC runners need.

**The good news first:** they will. `zeta-install.sh:1577` runs `ZETA_HOST_TIER=full tools/setup/install.sh`, and `.mise.full.toml` carries k3d/kind/kubectl/helm (base tier carries **none**). So the runner toolchain requirement I flagged earlier is already satisfied — not a blocker.

**The bug.** That invocation read:

```bash
... tools/setup/install.sh" 2>&1 | tail -10 || echo "WARN: install.sh FAILED ..."
```

The pipe makes the pipeline's exit status `tail`'s — always 0 — so **the `||` never fired**. An `install.sh` failure printed *nothing at all*. The node finished provisioning, reported success, and could ship without k3d/kubectl/helm: unable to host a runner, and looking healthy while doing it.

Verified directly rather than reasoned about:

```
f(){ return 3; }; f | tail -10 || echo fired     -> prints nothing
f(){ return 3; }; f | tail -10; ${PIPESTATUS[0]} -> 3
```

**Non-fatal is preserved** — a node that boots without agent CLIs is recoverable, and hard-failing a first-boot install is worse. But *"do not fail"* and *"do not notice"* are different instructions, and only the first was intended. Same distinction that cost a full tick when the blast-radius guard was changed to fall through instead of exiting cleanly.

Now captures `${PIPESTATUS[0]}`, warns with the real rc, and writes a durable `~/.zeta/PARTIAL-PROVISION` marker — a first-boot console line scrolls past with nobody watching; a file on the node is discoverable by whoever finds the machine later.

**Checked the class, not the instance:** every other `| head -1 || true` in the script is a *value* extraction where empty is the intended fallback — a different, legitimate pattern. This was the only error-detection-through-a-pipe.

`bash -n` clean.
