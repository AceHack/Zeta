## Description

**Depends on #9913** — these pages reference `./support.js` and `_ds/*` which it restores. Verified: 4 refs resolving, 3 missing, and all 3 missing are #9913's files.

## I was wrong about what these are

I left them out of #9913 as *"the built pages — a canonicalization decision, not a bug fix."* Wrong. Iris was building the site as a **mini zetadb node**: runs low/medium-intelligence agents, synchronizes with other tabs, USB devices, nodes and k8s clusters, Reticulum-like addressing, some nodes more reliable than others.

**A node implementation, not a rendering variant.** `edge/zeta-mesh.js` is 219 real lines — `gateway`/`send`/`fold`/`prune`/`announce`/`snapshot`/`emit`/`goDark` and a `ZetaMeshPip` class, over **BroadcastChannel** (cross-tab), **localStorage**, **WebSocket**. The vocabulary is the repo's own: `fold` is the commutative belief fold, `announce` is the Reticulum announce.

## Security finding — landed *with* the code, not after

```js
chan.onmessage = (e) => fold(e.data, "tabs");
ws.onmessage   = (e) => fold(e.data, "ws");
```

**Unverified input folds straight into state.** No signature, no origin check — 1 crypto-ish mention in 219 lines. `announce()` emits the identity claim (`id`) unsigned.

Same defect class as the **P1 filed against `reticulum-transport.ts`** today, one layer out and on a **public** surface. Two differences, cutting opposite ways:

- **BroadcastChannel is same-origin** — cross-tab input is bounded by the browser. Real containment the mesh layer lacks.
- **The WebSocket gateway is user-supplied** (`gateway(url)`). Point it anywhere and whatever arrives gets folded, on a page served from public Pages.

The P1's fix ordering applies unchanged: **verify the claim before folding it** — not because the code is careless, but because `fold` is a commutative merge with no way to reject.

## Worth crediting

`ws.onerror` carries the comment **"honest: unreachable stays visible"**. Iris deliberately kept a failure state visible rather than silently degrading — the same instinct as the monitor's live/offline/ledger-empty split, and the opposite of the four silent no-ops found across the repo today.

## Reliability note

*"Some nodes are more reliable than others"* is the calibration-ledger problem in a second domain. Soraya's review transfers directly: reliability must be **measured from settled outcomes**, and the trust weight must not be monotone in a self-reported claim, or the loudest announcer wins. A browser tab claiming high reliability is the sybil case at a lower barrier than a machine.
