Retraction-over-prevention works because drift is **bounded and observable**. An unbounded autonomous writer breaks that premise: a tick that rewrites 4,000 files is not drift you heal later — it is an outage, and the healer that caused it runs again in 15 minutes.

Not hypothetical for this script: on 2026-08-01 the unused-import healer **shipped with an unused import** and turned main red. (This PR’s own test file did the same — caught by `tsc` before shipping.)

## All-or-nothing, not first-N

The bound is checked against the **complete plan** before a single byte is written. Writing 24 files and stopping at the 25th leaves a state no healer intended — not reproducible, not idempotent. Compute the whole plan, decide once, apply all or none.

Exceeding it is **never silently truncated** — silent truncation is how a check goes vacuous. Exit 2, print the full plan, write nothing.

## Two silent-failure bugs fixed in the workflow step

1. `|| echo "(non-fatal)"` would have **swallowed the exit-2 refusal entirely** — the bound would fire and nobody would ever see it.
2. `git add -A` staged the whole tree and attributed it to the healer. Now stages exactly the `--plan-out` paths.

## Tests — 16 new, 36/36 in the suite

Including two that exist specifically to stop this guard becoming could-not-fail:

- **Negative control** — proves the *permitted* path really heals. Without it, a guard that refused everything would pass every other test here.
- **Malformed bound ×4** — `NaN > n` is `false`, so a bad `--max-files` must not silently become unbounded. `"abc"`, `"0"`, `"-5"`, `""` all rejected, tree verified byte-identical.
