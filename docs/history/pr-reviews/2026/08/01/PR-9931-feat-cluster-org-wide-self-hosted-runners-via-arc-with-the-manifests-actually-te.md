## Description

Org-wide registration, ARC as the chart — both per your call.

## Why, measured rather than asserted

The heartbeat declares `*/15`. Actual intervals over five consecutive ticks today: **63, 71, 65, 86, 66 minutes** — roughly **20% of declared**. That's GitHub's scheduler being best-effort, not our config, so no workflow tuning reaches it. Self-hosted is the only lever. It also kills the ~16GB model pull per tick (PVC-cached, pulled once) and the 10GB/repo cache ceiling.

## What lands

Follows the documented App-of-Apps convention — one directory per workload, root picks up `*/Application.yaml` only:

| | chart | wave |
|---|---|---|
| `arc-controller/` | `gha-runner-scale-set-controller` 0.12.1 | 3 |
| `arc-runner-set/` | `gha-runner-scale-set` 0.12.1, org-scoped, + model-cache PVC | 4 |

**Contained despite being GitHub-specific:** ARC lives in the k8s deploy layer, never in Core. Nothing here is imported by the substrate — swapping forges replaces this directory rather than editing Core, so the forge stays a plugin.

**Credentials referenced, never carried.** `githubConfigSecret` is a *name* pointing at a secret this repo cannot mint, materialised by external-secrets from Vault. The GitHub App key stays operator-approved, never operator-run.

## The tests are the point

`kind: Application` is on kubeconform's skip list, so the gate validates the PVC and **skips both Applications** — measured: `3 resources found in 3 files - Valid: 1, Skipped: 2`. The two files carrying every decision about registration scope, credentials, and scaling bounds were checked by *nothing*. On GitHub-hosted runners a bad manifest is a red job; on USB-provisioned hardware it's a physical node mid-provisioning.

14 structural tests, each **proven able to fail** before shipping:

| falsifier | result |
|---|---|
| repo-scoped `githubConfigUrl` (silently undoes org-wide) | caught, 1 fail |
| `targetRevision: latest` (controller self-upgrades under its runners) | caught, 1 fail |
| PVC `claimName` typo (pods Pending forever, app reports Synced) | caught, 1 fail |

Clean state restores to 14 pass / 0 fail. tsc clean.

## Requirement recorded for the USB image

The k8s lane needs `.mise.full.toml` (k3d/kubectl/helm) at **install and run** time via `ZETA_HOST_TIER=full` / `MISE_ENV=full`. A runner image carrying only the default tier fails shim resolve on a node that looks healthy.

## Not done here

No secret is created — `arc-github-app` must exist in Vault before the runner set syncs, and minting it is operator-approved work, not mine. Adopting the runners is then a matrix entry in `k8s-argocd-health-test.yml`, which already reads `runs-on: ${{ matrix.runner }}`.
