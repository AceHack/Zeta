## Description

Corrects **my own** framing from the previous commit, which called the state "GitHub-bootstrapped" and made GitHub rung 0 of a ladder. That privileged a host Zeta refuses to privilege — and was factually wrong about this code:

- **The forge seam already exists and is host-agnostic**: `forge-host/` has a `registerAdapter` registry, a `ForgeHost` interface, and `ForgeType` spanning **github | gitlab | gitea | bitbucket | sourcehut | codeberg**, with *two* adapters shipped. GitHub is one plugin among six.
- **`resolveCaDisposition` is already git-native**: it reads `maintainers/<ca>/ssh-ca.pub` **from the working tree** — any remote, a bare repo, or a sneakernet clone works. The only borrowed authority is *push access control*, which is a forge-plugin concern.

Records the **two independent axes** so they're not conflated: *anchor attestation* (committed → Z-set fold, where **order-independence is what removes the coordinator**) and *execution substrate* (forge CI → **cron processes** → **browser tabs** → peers only).

Invariant restated (already true): this function names no forge, does no network IO, no `ForgeHost` type appears. Swapping the anchor source stays a change of **caller**.
