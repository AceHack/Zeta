## Description

## 2 of the last 40 merges landed without a passing gate. Measured, with the mechanism named.

**Files a bug; fixes nothing.** The typo that exposed this is fixed separately in #15386.

### How it surfaced

Rescuing #13909, its `gate (required)` went red on a file it does not touch. `main` had stopped type-checking, because #15384 merged **twelve seconds after it was created**:

```
16:28:45  PR created
16:28:53  lint (TS)                 -> failure     ${r.model:} — the file does not parse
16:28:53  agencysignature (PR body) -> failure
16:28:57  MERGED
16:29:19  build-and-test            -> still starting
          gate (required)           -> NEVER CREATED for this head SHA
```

`lint (TS)` is a **FLOOR** job, so that put `gate (required)` red on the merge ref of every open PR in the repo.

### The measurement

Last 40 merged PRs, via the **check-runs API**, latest run per name — `statusCheckRollup` under-reports and would have missed this:

| verdict | count |
|---|---|
| `gate (required)` completed/success on the merged head | **38** |
| `gate (required)` **never ran on the head** | **1** (#15384) |
| `gate (required)` completed/**failure** | **1** (#15363) |

### The mechanism — a repository setting, not a mistake anyone made

```console
$ gh api repos/Lucent-Financial-Group/Zeta/rulesets/16134995 -q '.bypass_actors'
[{"actor_id":5,"actor_type":"RepositoryRole","bypass_mode":"pull_request"}]
```

`CI Gate` requires exactly one check and grants the **admin repository role a `pull_request` bypass of it**. The whole fleet authenticates as the shared `AceHack` credential, which holds that role.

> **Every agent silently holds bypass on the only required check, and a plain `gh pr merge --squash` is enough to use it — `--admin` is not involved.**

So the standing "no `--admin`" instruction protects nothing here. This is the repo's own named top obstacle to human-AI trust — *an unenforced exception looks like a guarantee and carries none* — sitting on the required check itself.

### The exact gap

`forge-host/github/required-check-started.ts` already classifies "the required check never started", and does it sharply (`stalled` = no run exists vs `queued` = run exists, name unpublished). **It is scoped to OPEN PRs.** It answers *"is this PR stuck?"*, never *"did that one land without a gate?"*

Nothing audits **merged** PRs, so an escape produces no signal at all — invisible by construction, the same shape `audit-pr-archive-coverage.ts` documents for unarchived PRs.

### Proposed, in order

1. **A post-hoc coverage audit over merged PRs**, modelled on `audit-pr-archive-coverage.ts`, separating *never ran* from *ran and failed* — different defects. Ratchet baseline **2 of 40**. Makes the class visible; blocks nobody.
2. **Then** ask whether the bypass should be narrowed to named actors. That is a **maintainer decision about repository settings**, deliberately not taken here, and it must not be taken before (1) exists — narrowing an escape hatch nobody is measuring is how a fleet gets wedged.

**Falsifier stated in the item:** the audit must be shown to FAIL on today's window, not merely to pass once the window rolls past #15384 and #15363. A coverage audit that only ever reports zero is the vacuity class.
