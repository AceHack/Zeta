## What

Documents the `ZETA_WORKFLOW_DISPATCH_TOKEN` Cursor Secret so future agents notice it and know how to use it:

- New `docs/cloud-agent-workflow-dispatch-token.md` — what the secret is, why it's needed, least-privilege scope, and exactly how to dispatch from a cloud agent.
- A cross-harness surface bullet in `AGENTS.md` → "Agent operational practices", so every harness sees it at cold-boot (same pattern as the `dependency-status.md` / `COWORK-MAINTENANCE-TICK.md` bullets).

## Why

Cursor Cloud Agents authenticate `gh` as the read-only `cursor` GitHub App installation token (`ghs_…`), so they cannot `workflow_dispatch` (e.g. `build-ai-cluster-iso.yml` restore runs). An interactive `gh auth login --device` doesn't survive the ephemeral VM. The durable fix is a Cursor Secret injected into every Cloud VM — which the operator added on 2026-08-25. Without a written surface, each new cloud agent rediscovers the read-only-gh blocker.

## Usage (documented)

```bash
gh run list --workflow=build-ai-cluster-iso.yml --status in_progress --limit 5   # wait until empty
GH_TOKEN="$ZETA_WORKFLOW_DISPATCH_TOKEN" gh workflow run build-ai-cluster-iso.yml --ref main
```
