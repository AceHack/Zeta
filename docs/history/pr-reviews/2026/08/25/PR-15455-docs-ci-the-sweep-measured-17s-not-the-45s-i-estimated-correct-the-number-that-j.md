## The number that justified the design was an estimate, and it was wrong in my favour

#15440 chose a scheduled sweep over a `workflow_run` watcher on cost, and quoted **~45s per
tick / ~72 runner-min per day / ~5x cheaper**. That figure was written *before the workflow had
ever executed* — it was extrapolated from a local dry run, and it happened to flatter the
decision it was justifying.

Measured, on the first real execution — run
[32907739489](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/32907739489), dry,
45-minute window, 5 failed runs evaluated:

```
started   2026-08-25T22:46:35Z
completed 2026-08-25T22:46:52Z
          17 seconds
```

**~27 runner-min/day at 96 ticks/day, and ~13x cheaper than the watcher, not ~5x.** Corrected
in all three places that carry it — the workflow header, the CLI header, and the research doc —
each with the run id attached so the next reader can recheck it rather than inherit it.
