## Four defects, one class — a record that looks complete and is not

**1. Wrong in the permissive direction.** `enforcement: disabled` recorded against a
live `active`, with five required contexts listed that no longer exist under those
names.

**2. `bypass_actors` was never captured.** The single most safety-relevant field on
a ruleset — who may merge past it — was invisible to the detector. Live carries an
admin PR-bypass on the CI Gate.

Verified empirically rather than read off a role-ID table: `GET /rulesets/16134995`
returns `current_user_can_bypass: "pull_requests_only"` for an account whose
`permissions.admin` is `true`, and `"never"` for ruleset 16189060, which has no
bypass actors. That is what identifies `RepositoryRole 5` as repository admin.
Filed **P0-security** in `docs/BUGS.md`.

**3. List endpoints were read unpaginated.** `/actions/workflows` pages at 30; this
repo has 90. The record held one third of the inventory and gave no sign of it. Every
workflow carries a `state`, so a workflow set to `disabled_manually` outside page 1
was undetectable — the same shape as a required check that never ran reading as green
(#14914). `--jq` silently suppresses `--paginate`, and `gh` refuses `--slurp`
together with `--jq`, so the projection moved into TypeScript.

**4. Found while fixing the others: a scan that read nothing exited 0.** The checker
strips unreadable fields from both sides; strip everything and two empty objects
compare equal. New exit code **3 = INDETERMINATE**.

## Two more defects, and CI found both — in the fix itself

Recorded here rather than quietly folded in, because the second round is the
more interesting half of this PR.

**(1) Absent read as empty, inside the remedy for absent reading as empty.**
`GET /rulesets/{id}` **omits** the `bypass_actors` key for a reader without admin
rights. It does not 403 and it does not return `[]`. The first draft of
`normalizeBypassActors` coerced the missing key to `[]` — so under `GITHUB_TOKEN`
the check reported the live admin bypass as **REMOVED**, and the cheapest way to
green that would have been to record `[]` and erase the P0 this PR exists to
surface. Absence reading as the safe value: the exact class, reproduced inside its
own fix, and caught only because the detector was pointed at live.

Verified unauthenticated against ruleset 16134995 — the response carries
`[_links, conditions, created_at, enforcement, id, name, node_id, rules, source,
source_type, target, updated_at]` and no `bypass_actors`; the same call with an
admin credential returns one actor.

`null` now means unreadable and lifts to the sentinel; `[]` keeps its real meaning.
Both sentinel walks descend into **arrays**, because the one field a non-admin
credential silently cannot read lives inside an array element.

**(2) `rc=$?` was dead code — in the new step and in the sibling job.** GitHub's
default shell is `bash -e {0}` (it is in every job log's `shell:` line), and
`set -uo pipefail` does not clear a `-e` that arrived on the command line. A bare
call followed by `rc=$?` aborts the step the instant the command is non-zero, so
every line after it is unreachable — including the `case` whose whole purpose is
to tell DID-NOT-RUN from FAILED. It could never see the only case it was written
for. Job `97868684543` exited 1 with no annotation emitted.

The same shape was **already in the sibling `ruleset-plan` job**, whose reconciler
has five meaningful exit codes (1 DRIFT / 2 DID-NOT-RUN / 3 REFUSED / 4 APPLIED-
BUT-VERIFICATION-FAILED), all silently collapsed into a bare red step since it was
written. Fixed there too.

```
$ bash -e -c 'set -uo pipefail; false; rc=$?; echo "UNREACHABLE: rc=$rc"'
  (no output)                                          exit=1
$ bash -e -c 'set -uo pipefail; rc=0; false || rc=$?; echo "REACHED: rc=$rc"'
  REACHED: rc=1                                        exit=0
```

The drift step also **propagates** its exit code now, rather than the `exit 0` the
first draft had. `continue-on-error` at the job level already makes it advisory, so
`exit 0` bought nothing and cost the `drift (loud)` reporter its signal — that job
escalates absorbed continue-on-error failures, and a step that always exits 0 has
nothing to absorb. Annotations *add* the 1/2/3 distinction the step status cannot
carry; they do not replace it.
