## Description

fix(archive): remove the corrupt shard filename my own PR introduced

`docs/github/prs/shards/012/080000000000000078030000<000323e.json` carries a
literal `<` where `00` belongs. I introduced it: commit 5223ce912 (PR #15007,
an unrelated gate-absence observation) recorded an R100 rename of
`0800000000000000780300000000323e.json` to the corrupt name, and deleted
`08000000000000007803000000003240.json` in the same commit. The deleted sibling
has since been restored.

Nothing is lost by removing it. Both files hold `pr_number: 12862`, and the
correctly-named counterpart is present on main with strictly fresher data
(`fetched_at: 2026-08-24T22:44:42.624Z`). This one is a stray duplicate under a
malformed key.

It is not cosmetic: the shard store is the authoritative record and
`docs/github/prs/manifest.jsonl` is DERIVED from it, so a shard under an
unparseable key makes `derive-pr-manifest.ts` refuse -- which is the correct
behaviour for a store that cannot be read, and which was being attributed to
unrelated PRs whose only fault was running the check.
