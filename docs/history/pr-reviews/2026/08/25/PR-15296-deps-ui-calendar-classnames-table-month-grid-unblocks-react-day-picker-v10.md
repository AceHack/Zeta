## Description

## What

Renames one `classNames` key in both copies of the shadcn `Calendar` component:
`table` -> `month_grid`.

## Why

`table` is a **v8-era `DeprecatedUI` key**. react-day-picker v9 still honours it
through the DeprecatedUI shim; **v10 removes that shim entirely** (all 34 keys).
Under v10 the key becomes inert and the month grid silently loses
`w-full border-collapse`.

Nothing throws. No type error. This is a **styling regression a typecheck cannot
catch** — which is why it is fixed *ahead* of the bump rather than discovered
after it.

`month_grid` (`UI.MonthGrid`) is the canonical name in **both** v9 and v10, so
this PR is a **no-op against the currently-pinned 9.14.0** and a prerequisite for
10.0.1.

## Evidence

Verified against the published `react-day-picker@10.0.1` tarball:

- `dist/esm/UI.d.ts` contains `MonthGrid = "month_grid"`
- no `table` key survives in the v10 `UI` enum
- everything else the component imports is intact in v10: `DayPicker`,
  `DayButton`, `getDefaultClassNames`
- none of v10's removed props are used (`fromDate`/`toDate`/`fromMonth`/`toMonth`/
  `fromYear`/`toYear`/`initialFocus`, the removed `onDay*` handlers, the removed
  `format*`/`label*` aliases)
- no `react-day-picker/style.css` import, so the package rename to
  `@daypicker/react` does not bite

`table` was the **only** v8-era leftover in either file — the other 23 keys
already use v9/v10 names. It is also the only key in the object with no sibling
`defaultClassNames.<key>` reference, which is what made it visible.

## Coverage caveat, stated plainly

`demo/identity-dla-site` is typechecked by `lint (identity-dla site)`.
`src/Renderers/website` is **excluded from the root tsconfig** (lines 62–63),
referenced by no workflow, and has no lockfile — it has **no CI coverage at all**.
That copy is fixed by inspection, not by a green check.
