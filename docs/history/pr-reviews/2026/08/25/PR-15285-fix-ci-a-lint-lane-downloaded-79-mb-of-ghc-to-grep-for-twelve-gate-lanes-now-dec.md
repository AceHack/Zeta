## Description

## A `lint (no conflict markers)` job downloaded a Haskell compiler

Nine "failing checks" across seven PRs between 06:13 and 06:27 UTC on 2026-08-25 had **one** cause, and it was not the apt budget.

`tools/setup/manifests/apt` carries `agda tier=standard`. Ubuntu's `agda` transitively pulls **`ghc` (79.0 MB)** plus **63 `libghc-*-dev`** packages, `agda-bin`, `agda-stdlib`, `agda-stdlib-doc`, `elpa-agda2-mode`. On job `97707217922` — whose entire body is one `bun src/Core.TypeScript/hygiene/check-no-conflict-markers.ts` — that was **237 MB of the 556 MB** apt tried to fetch, and **95%** of everything it got a `Get:` line for before the mirror stalled:

```
Get:4 http://azure.archive.ubuntu.com/ubuntu noble/universe amd64 ghc amd64 9.4.7-3 [79.0 MB]
⚠ apt-get install exceeded its 246s slice of the 420s budget (attempt 1/3) — stalled archive mirror
⚠ ...  89s slice (attempt 2/3)
⚠ ...  45s slice (attempt 3/3)
✗ apt-get install did not succeed within the 420s apt budget (3 attempts, rc=124)
```

The other victims in that window are the same class: `lint (§33 migration xrefs)`, `lint (tick-shard relative-paths)`, `lint (semgrep)`, `lint (semgrep drift)`, `lint (archive header §33)`, `lint (shellcheck)`.

## The budget is untouched — deliberately

**Not raised. No `continue-on-error`. No extra retries.** `ZETA_APT_CI_BUDGET_DEFAULT_SECONDS=420` is a hang guard with a derivation in `tools/setup/linux.sh` and an audit keeping it inside every job's timeout. The measured distribution is bimodal — **107 successes at median 116s, 11 failures at exactly 420–421s** — so this is a hang, not slowness, and a larger budget only makes each hang cost more. The guard was right; the payload was wrong.

## The change

Twelve `gate.yml` jobs run `install.sh` purely to get a mise-provided tool — bun, shellcheck, semgrep, the five language linters — and reference **no** tier=standard package anywhere (checked: `agda`, `emscripten`, `llvm`, `pandoc`, `r-base`, `podman`, `qemu`, `mtools`, `opam`, `tlapm`). Each now declares `ZETA_HOST_TIER: slim` on its installer step, exactly as `low-memory.yml` has since 2026-08-21.

This uses the gate the repo **already built** (`081KTWQZY7F` / `081M0K36K69087G0R003BYSCF8`) rather than inventing one, and it is safe on the agda side by construction: `from-agda-cubical.ts:25` already logs `"agda not on PATH (slim tier ...); skipping"` and returns success.

**Per-lane effect:** 388 packages / 713 MiB → **149 / 139.7 MiB**. The 79 MB GHC fetch — the largest single stall surface in the file — leaves the common path for 12 of 15 installer jobs.

**Left at the auto-detected tier, deliberately:** `build-and-test` (whole F# suite), `test-typescript-environment` (zflash esp-inject), `full-verify` (smoke-7-toolchains needs emscripten). Those genuinely reach past slim; guessing otherwise would trade a slow lane for a broken one. That is where the remaining GHC exposure lives, and it is named in the test's doc comment rather than left to be rediscovered.

## The falsifier

An unenforced tier declaration is a guarantee that carries none. `apt-manifest-host-tier.test.ts` now parses `gate.yml` and checks the roster:

* **every job on `SLIM_GATE_JOBS` still declares `slim`** — kills the delete-a-line mutant (verified 11 pass / 1 fail).
* **at least one installer job is NOT on the roster, and no off-roster job declares slim** — the negative control. A roster that had quietly grown to cover everything would satisfy the first test *and* would mean the F# suite was running on a host with no emscripten. Verified red on that mutant too (11 pass / 1 fail).
