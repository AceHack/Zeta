## Description

# Summary

The key is live and the lane discovers **25 hosted environments** — run [32810964748](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/32810964748) logged `Successfully fetched 25 environment(s) from API`, `mode=NORMAL environments=25`. It still **plays** ZetaChase.

This is the cheap step between those two facts: see what the 25 actually are before designing a loop against them.

`--list-environments` reports `game_id`, `title`, `tags`, the declared `baseline_actions`, and level count. Action count is first on that list because it is the first thing that could differ from ZetaChase's four, and the first thing a generic agent needs to know.

## `private_tags` is deliberately not reported

`EnvironmentInfo` carries `tags` and `private_tags` side by side, and this output goes into CI logs anyone with read access can see. Publishing a field whose author named it *private*, purely because it was sitting in the struct, is obvious in hindsight and easy in the moment.

**A test enforces it rather than a comment.** Break-red: adding `private_tags` to the reporter fails `test_the_roster_never_reports_private_tags` while the other 32 pass. That test works **offline** — which matters, because offline is the only condition under which it can ever run in CI on a PR.

## Why a CLI flag and not a shell block

Anyone with a key can run the same reconnaissance locally instead of reading it out of CI logs. It also makes the degradation testable: no key → `OFFLINE` → empty roster → exit 0, which is what makes the step safe on the keyless `pull_request` path.
