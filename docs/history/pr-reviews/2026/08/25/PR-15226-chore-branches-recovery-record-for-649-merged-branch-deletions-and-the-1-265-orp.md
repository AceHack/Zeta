## Description

The maintainer asked for a background agent to prune already-merged branches so the important ones are visible. 3,735 remote branches; this lands the **recovery record** for the 649 being deleted, and flags what the sweep found that is not clutter.

## What made a branch deletable

The repo squash-merges, so the literal test in the brief — `git rev-list --count origin/main..<tip> == 0` — was true for only **7 of 2,113** non-heartbeat branches. Using it alone would have authorised nothing useful. Each deleted branch instead passed the equivalent-strength content check:

1. PR state **MERGED**, and its `headRefOid` equals the branch's **current** tip (nothing was pushed after the merge).
2. The PR's `mergeCommit` is an ancestor of `origin/main`.
3. `patch-id --stable` of the branch's squashed diff **equals** `patch-id --stable` of that merge commit's diff. Same patch, byte-for-byte at the patch level.
4. No OPEN PR on the name; not `main`; not under `heartbeat/*`.

All 649 passed step 3. **Zero** fell back to a weaker signal, and zero needed a judgement call.

## What was excluded, and why

- **`heartbeat/*` — 1,621 branches, excluded outright and never examined.** Live telemetry lanes; ruleset 16934633 blocks deletion anyway.
- **`main`** — ruleset 16189060 (`~DEFAULT_BRANCH`, `deletion` + `non_fast_forward`).
- **37 open PRs**, **100 closed-without-merging** (abandoned work someone may still want), **58 whose tip advanced past their merged PR** (post-merge commits that never landed).
- **6 branches whose tip *is* an ancestor of `main`** but which have no merged PR. Zero data-loss risk — the SHA is in main's history — but they fail condition (a), so they were left alone rather than deleted on inference.
- One branch merged minutes before the sweep (`claude/tender-hawking-xmcs6m`) — held back in case a session is still on it.

## The part that is not a cleanup problem

**1,265 `automation/pr-archive-*` branches have no PR at all.** `.github/workflows/pr-archive-on-merge.yml` names this in its own comments — *"this is what 1,229 orphaned `automation/pr-archive-*` branches cost"* — and the count has grown since. Each one adds a `docs/history/pr-reviews/PR-NNNN-*.md` and a `docs/github/prs/manifest.jsonl` entry that is **not on `main`**; sampled and confirmed missing for every branch checked.

They are 60% of the non-heartbeat branch clutter and they are also the PR review archive. Pruning them would destroy the history they exist to preserve. **They need landing, not deleting** — and that is a separate piece of work with a real backlog behind it.

## Recovery

`docs/history/branch-cleanup-2026-08-25.md` carries branch name + tip SHA + PR number + last-commit date for all 649. `git push origin <tip-sha>:refs/heads/<branch>` restores any of them. Text, per `.claude/rules/no-binary-in-proof-lineage.md`.
