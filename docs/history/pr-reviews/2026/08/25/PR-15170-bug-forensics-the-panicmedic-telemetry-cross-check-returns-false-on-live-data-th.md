## Description

`panicmedic.ts` says the panic instant is identified rather than guessed because
two separately-encoded NVRAM variables carry the same 64-bit microsecond value:
`panicmedic-timestamps`, and the copy embedded at offsets 8 and 16 of
`panicmedic-telemetry`. `telemetryAgreesWithTimestamps()` implements that check.

On a second real reading of the same machine it returns false.

    panicmedic-timestamps = 0:659d5fd687db9 -> 1787625474653625 us
    telemetryTimestampsUs = [1787625473653625, 1787625473653625]
    delta                 = 1000000 us = 0xF4240 = exactly 1.000000 s

Verified in exact integer arithmetic: the BigInt difference is 1000000n, both
values are safe integers that round-trip, both `/1000` divisions the function
performs are exact, and the gap is 4,096,000x the float ULP at this magnitude.
It is not a rounding or decode artifact. The two copies INSIDE the telemetry
blob still agree with each other — only the cross-variable half of the claim
fails.

Corroboration for which variable matches the event: `sysctl kern.boottime` =
1787625493 (22:38:13 EDT) and `ResetCounter-2026-08-24-223927.diag` reports
`Boot faults: wdog,reset_in1` — a watchdog reset. The machine's own panic
instant, 22:37:54, matches `panicmedic-timestamps` (22:37:54.653), not the
telemetry copies (22:37:53.653).

An existing MUTANT test proved the function CAN return false by zeroing bytes in
a fixture, so the code path was never vacuous. What was missing is that every
test built on REAL hardware data used ONE sample, and in that one sample the two
variables happen to agree. A claim about hardware checked against a single
reading of that hardware is a coincidence that had not yet been contradicted.

This commit adds the contradiction as a pinned fixture and changes NO production
logic. It is not determined whether the two variables latch at genuinely
different instants (a ~1 s stage separation in the panic path would be
unremarkable) or whether the offset-8/16 fields were misidentified from the
single matching sample. Loosening the predicate to a tolerance would manufacture
agreement without understanding the mechanism, which is the failure this module
exists to refuse.
