## The two findings that outrank the deletions

**`agent-heartbeats` would lose real telemetry.** Its PR merged 2026-05-27, then the branch kept
accumulating until 2026-06-19 and was never flushed again. **681 files exist on no other ref and are
not on `main`** — `main` has no `docs/agent-heartbeats/otto-windows/` directory at all. Flush or tag it
before it is deleted; do not batch it with the other 66 squash-landed branches.

**The legacy flush-ref emitter is still running.** Exactly one `heartbeat/<agent>-flush-<40hex>` ref
exists, and it was created *today* — after the sweep that removed 1,612 of them. One ref is not a
problem; a producer that survived the cutover is, because the population grows back.

Secondary: all 49 surviving `automation/pr-archive-*` branches are safe to delete. The sweep missed them
for a mechanical reason — one of their two paths is an append-only container (`manifest.jsonl` or a
shard `.json`) that can never be byte-identical to a months-old snapshot. A sweep comparing only
`docs/history/pr-reviews/PR-*.md` catches all 49.

## Measurement discipline

Every command is in the doc so the inventory is reproducible. `git ls-remote --heads` is the
authoritative list (not the paginated API); "merged" is `git merge-base --is-ancestor`, never a name
pattern; unique commits use the `--stdin` form; and because this repo squash-merges, "landed" is tested
as *the PR's `merge_commit_sha` is an ancestor of `main`* — only 6 of 247 branches are literal ancestors.

**Three measurement failures were caught mid-run and are written into the doc**, because the corrected
numbers are only trustworthy if the failures are visible. The sharpest: `git rev-parse "main:no/such/path"`
**echoes its own argument** and exits 128, so a presence test written as `[ -z "$(git rev-parse …)" ]`
reported **zero absent files for all 248 branches** — a check that could not fail. Caught by a surprising
count followed by a control on a known-missing path; the corrected test is what found the 681 orphans.

A fourth obstacle worth recording: `getaddrinfo` was broken on this machine (`dig` answered, `git` and
`curl` could not resolve `github.com`), so the authoritative list was obtained by pinning the transport
to the resolved address with `ssh -o HostKeyAlias=github.com`. Falling back to `gh` alone would have
meant accepting the paginated API as the source of truth.
