## Description

Every third-party action in this repo is pinned to a 40-hex SHA, which reads as
supply-chain discipline. Three things were true underneath that today, and none
of them were visible:

1. FOUR ACTIONS WERE NOT BEING AUDITED AT ALL. Any check keyed on `owner/repo@`
   misses the subpath form, so `github/codeql-action/{init,analyze,upload-sarif}`
   and `actions/cache/restore` — 10 references — sat outside every count. The
   first version of this very audit had that bug; it reported 263 references and
   12 actions where the truth is 273 and 16.

2. `actions/upload-artifact` WAS PINNED AT TWO SHAs. `ruleset-apply.yml` (landed
   today, #15349) used `ea165f8d` — dated 2025-03-19 — while ten other sites used
   `043fb46d`, dated 2026-04-10. Both SHAs are real; neither was fabricated. The
   fleet simply ran a year-old copy of one action beside a current one, and
   reviewing either site told you nothing about the other. Aligned here.

3. A FABRICATED SHA WOULD HAVE PASSED. An agent building CI earlier today reached
   for `astral-sh/setup-uv` — used nowhere in this repo — with a SHA it invented,
   and caught itself. Nothing in the tree would have. A 40-hex string is
   indistinguishable from a real one by shape, which is the only thing anything
   was checking. This is the third fabricated-identifier incident of the day after
   the two Task ZetaIds that produced AH006; it is the same failure — an agent
   reaching for a remembered value instead of the one in use — and until now it
   was the one with no guard.

The roster (`action-sha-roster.json`, 16 entries) makes each pin a value someone
committed rather than remembered. The audit refuses an action absent from it, a
SHA disagreeing with it, and — closing a hole the first draft had — a mutable
`@v4` tag, which is strictly worse than a drifted pin: the roster would read as
enforced over a reference the upstream owner can move under CI at any time.
Zero such refs exist today; nothing held them at zero.

`--write` REFUSES on a conflicted tree rather than writing whichever SHA sorted
first. An earlier draft warned and wrote anyway, which would have recorded an
arbitrary pick as an intentional pin — the vacuity class inside the tool built to
catch it.

Falsifiers: 17 tests, mutation-controlled. Stubbing `auditReferences` to return
clean kills 4; removing the `--write` refusal kills 1; restoring the narrow regex
kills 3. A fourth mutation attempt reported "17 pass" — that run was a `sed` that
errored, not a mutant that survived, and it is recorded here because reading it
as survival is exactly the error this class of tool exists to prevent.

Wired into the `gate` floor beside AH004/AH006.
