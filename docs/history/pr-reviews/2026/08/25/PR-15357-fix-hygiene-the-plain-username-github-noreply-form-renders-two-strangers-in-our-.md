## Description

## The defect

GitHub resolves a `Co-authored-by:` trailer, and a commit's author identity, by looking up the **email**. On `users.noreply.github.com` there are three shapes and exactly one is unsafe:

| form | resolves to | verdict |
|---|---|---|
| `<id>+<username>@users.noreply.github.com` | the account whose numeric id matches | SAFE |
| `<username>[bot]@users.noreply.github.com` | nobody — a GitHub username cannot contain `[` | SAFE |
| `<username>@users.noreply.github.com` | **whoever owns that username today** | **UNSAFE** |

Two personas of this fleet shipped commits under the third form — **15 commits** under one, **2** under the other. Both local-parts are live GitHub accounts belonging to **uninvolved private individuals** (registered 2008 and 2011). They are rendered in this repository's Contributors sidebar. Neither person did anything; we named them.

One of the two is `shadow`, our own persona. **This is self-inflicted.**

The usernames appear in this PR only where explaining the collision requires them (the audit's fixtures and its header), nowhere else. They are not @-mentioned anywhere, and nothing has been compiled about the people behind them.

## What this is not

- **Not a breach.** Repo collaborators are exactly AceHack, maximdolphin, Addisons820 (all admin); zero deploy keys.
- **Not a false contribution in the REST sense** — and this is the trap. `gh api repos/.../contributors` comes back clean **because it does not aggregate trailer co-authors at all**. It reports 6 where the sidebar shows 14. That endpoint under-reports this class and must not be used to check it. An earlier check of it is why the problem was first scoped as harmless.

## History is NOT rewritten

The 17 commits are on `main`. Correcting them means force-pushing the default branch, which is forbidden here. **The fix is forward-only.** Nobody should later read those commits as a missed case — they are out of reach by design, and both the audit's header and its workflow comment say so.

### A second bug found underneath the USB installer site

The old fallback could not work, and the failure reached `main`:

```sh
OP_EMAIL=$(gh api /user/emails --jq '…' 2>/dev/null | head -1 || echo "${MAINTAINER}@users.noreply.github.com")
```

Under `set -euo pipefail` (line 43 of that script), `gh api` prints its **404 body to stdout** — `2>/dev/null` hides only stderr — the `|| echo` fires anyway, and command substitution captures **both, concatenated**. Commits `bb581641` and `5144b5be` carry the result verbatim inside a trailer:

```
Co-authored-by: … <{"message":"Not Found","documentation_url":"…","status":"404"}Addisons820@users.noreply.github.com>
```

A fallback appended to a failure's output is not a fallback. Now: capture, then validate the value, instead of branching on an exit status that describes `head`.

## Two follow-up commits, both from checks this repo already runs

**1. The audit tripped two of the floor's own rules.** Found by CI, not by review, and both were real:

- *No culture-sensitive collation* — `findings.sort` used `localeCompare`, which is linguistic and ICU/locale-dependent, so two machines can order the same findings differently (`.claude/rules/culture-invariant-by-default.md`). Now ordinal.
- *No check-then-use filesystem races (TOCTOU, CWE-367)* — `walk` did `readdirSync` then `statSync` per child. The listing already knew each entry's kind. Now `withFileTypes: true`; `statSync` is gone from the file entirely, and `main`'s exit-2 condition is **derived from what was actually read** (`filesScanned === 0`) rather than from a prior stat. A check that did not run must not report clean.

**2. The self-register test stub answered a question it had not been asked.** The class-1 fix reads `gh api /user --jq .id`; the harness's `gh` stub matched on `api /user` alone and returned the **login** for both reads, so the script saw a non-numeric id, refused, and four convergence tests went red. The stub was wrong before this branch touched it — it had only ever had one caller. It now branches on `.id` vs `.login` and carries a `userId` world field, plus two falsifiers that pin the fix rather than merely unbreak it:

- the commit is made under `4242+qemu-ci@users.noreply.github.com` and **not** under `qemu-ci@users.noreply.github.com`;
