## Description

`required-check-started` splits PRs whose `gate (required)` is absent from the rollup
into **stalled** (the check can never report) and **queued** (a run exists, it's just
slow). The split was `runCount === 0` vs `runCount > 0` — pure run **existence** —
while the property it claims is that the required check **can still report**.

Those are different questions, and a live PR sat in the gap.

## The gap

**#15327** has one `gate.yml` run whose conclusion is `action_required` with **zero
jobs** — GitHub withholds workflow execution for PRs opened with `GITHUB_TOKEN`. The
run exists, is terminal, and published nothing. `runCount: 1` classified it *"queued,
not stuck"* — **for fourteen hours**.

The audit built to catch a required check that can never report could not see one.

## Fix

Measure the **live** run count (`status != "completed"`) alongside the total. Once the
check is known absent, "zero runs" and "every run already finished" are the same
verdict. `liveRunCount` is **optional**, and absent falls back to the old, more
forgiving reading — an unmeasured field must never manufacture a red.

The message changed too: *"no gate.yml run exists"* was true of the only cause the old
code could detect, and would have been a **lie** about the new one.

## Verified against live GitHub, and that mattered

All 25 tests passed while the shipped command was **broken** — `\(` inside a JS string
literal is eaten by JS escaping, so the jq interpolation never parsed. The tests
exercise the pure classifier and never cross the shell boundary. Replaced with `@tsv`.

Live run after the fix:

```
gate.yml run EXISTS but has not published gate (required) yet on #15462 — queued, not stuck
::error:: no LIVE gate.yml run for #15327, #15324 — gate (required) can never report on them
```

It catches the stuck PRs **and** leaves the genuinely in-flight one alone.
