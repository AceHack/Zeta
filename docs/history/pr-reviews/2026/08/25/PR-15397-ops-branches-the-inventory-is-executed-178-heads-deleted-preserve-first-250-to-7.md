## Nothing was deleted on the strength of the inventory's tables

The whole set was re-measured against live `origin` immediately before the delete, and the drift in those few hours is the argument for it:

- **Five listed branches no longer existed** (four had been open PRs and landed).
- **Nine branches had appeared**, four heading new open PRs.

Four gates were run at execution time rather than read off the document — tip moved (0), head vanished (0), now heads an open PR (0), matches `heartbeat/` or `main` (0). Every delete was pushed as `--force-with-lease=refs/heads/<b>:<sha>`, so a concurrent push aborts that delete *structurally*, not by my checking.

## The correction — 17 rows the inventory had at zero were not zero

Seventeen branches placed in the clear-cut classes **do** hold paths that exist nowhere on `main`: `shadow-revert-13973-mass-deletion` (32), `claude/github-project-genesis-y44lc2` (14), `claim/cross-lang-zset-isa-capstone` (6), and fourteen more at 1–5. `main` moved under the measurement — a path present when it ran can be deleted afterwards, turning a 0 into a positive count with nothing on the branch changing.

Each was **tagged on `origin` first** under `archive/2026-08-25-branch-sweep/`, verified present at the exact SHA with a two-way control, and only then deleted. A SHA written in a document is not preservation: once the ref is gone the object is unreachable and may be collected. Only the ref preserves it.

## The measure is `files absent from main`, never the unique-commit count

It misleads in both directions, and both directions occurred here: three deleted branches reported 310–315 "unique" commits and were **100% byte-identical** on `main`, while `agent-heartbeats` — classified `SQUASH-LANDED` — holds **681 files existing nowhere else** and was **not** deleted. The presence test was controlled both ways (`CLAUDE.md` → present; a fabricated `docs/agent-heartbeats/otto-windows/` path → absent) before a single result was trusted.

## A third zsh trap, found here

`"$sha:refs/tags/$t"` does not mean what it reads as — zsh applies `:r` as a history-style *modifier* and strips the extension, so the refspec pushed is `<sha>efs/tags/<tag>`. Loud only because the push refused it; a modifier that happened to produce a valid ref would have pushed to the wrong place. Use `"${sha}:refs/tags/${t}"`. This joins the two already recorded in the doc's **Method** section.
