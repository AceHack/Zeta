## Description

`docs/research/2026-08-14-agent-sovereign-keys-incremental-ladder-L0-to-L6-*` asserts
"L1 is reachable on this machine: NO — probe: zero honourable tiers." That was true
when measured on 2026-08-14 and has been false since a YubiHSM 2 was inserted.
Nothing updated it.

This is the vacuity class INVERTED, which is why it is worth a commit rather than a
quiet edit: the usual failure is a check that did not run reading as one that passed.
Here a capability we HAD was recorded as absent, so the document was more pessimistic
than reality and no alarm could ever fire. A stale row in the favourable direction is
still a stale row.

RE-MEASURED LIVE 2026-08-25, same host:

  Version number:  2.4.1        Serial number: 39160506
  Log used:        2/62         Part number:   78CLUFX5000P

  YubiHSM 2:        ATTACHED (bulk USB)
  PKCS#11 pair:     /usr/local/lib/pkcs11/yubihsm_pkcs11.dylib drives YubiHSM 2
  Device present:   YES
  Honourable tiers: hardware-pkcs11

THE OPERATIONAL CAUSE WAS NOT THE HARDWARE. `yubihsm-connector` was installed but not
running, so the device sat on the USB bus unreachable over PKCS#11. Starting it — a
USB-to-HTTP bridge needing no credential — made it visible. **A device present and
unreachable reads identically to absent** from anything probing only PKCS#11, which is
exactly what the 2026-08-14 probe did. The probe was not wrong; its row claimed more
than the probe asked.

Firmware and serial match `hsm-domain-map.ts` exactly, so that roster was never the
stale part.

WHAT IS STILL NOT TRUE, recorded so this note does not become the next stale green:

  - No FROST-capable mechanism. The full pre-auth algorithm list was read off the
    device: `eck256` (secp256k1), `ecdsa-sha256`, `ed25519`, RSA, AES, ECDH — and no
    threshold or partial-signature primitive. This is L1 (at-rest wrap), not L2
    (on-chip signing); the share still enters host RAM.
  - No session was opened. Everything measured is pre-authentication. A session needs
    an auth-key password, which is the operator's to enter, never an agent's.
  - n = 1. Unconfiscatability needs shares on distinct devices; the SmartCard-HSM is
    ordered and has not arrived. One HSM is one seizure point and no code changes that.
