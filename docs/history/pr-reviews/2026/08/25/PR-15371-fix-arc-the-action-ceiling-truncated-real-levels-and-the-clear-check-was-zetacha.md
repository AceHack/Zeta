## Description

# Summary

Two defects that only became visible once the hosted roster was readable. Both would have silently mis-scored any environment other than the one they were written against.

## The action ceiling truncated real levels

300 actions/level was sized against ZetaChase, whose levels are BFS-optimal at 7–10. The hosted environments publish their own reference counts in `baseline_actions`, and they run to **578** (DC22), **500** (M0R0), **442** (WA30) — read off run [32812742904](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/32812742904).

A 300 ceiling cuts off levels a *reference player* needs more than 300 actions for, which scores the agent as having **failed** a level nobody clears that fast. Raised to 800 — above the largest count we have actually seen, rather than above a guess.

## The clear check was a proxy that only holds for ZetaChase

`play.py` decided a level ended with `agent cell == goal cell`. That was needed because `level_index` does not advance on the final level — `base_game.py:412` calls `win()` instead — but the proxy is false in general.

**ZetaDiscovery is the counter-example and it is already in the tree:** its level 1 `goal` is a *decoy* that ends nothing, so standing on it means the level was **not** cleared. The proxy says it was. `level_cleared()` now reads `GameState.WIN`, which is what the engine actually sets.

# Spec alignment

No `openspec/specs/**` changes. ZetaChase still scores 0.3375 with 3/3 levels — these change what is measurable on *other* environments, not what this one measures.
