## Description

**Routed question:** does Zeta's DLA meter actually measure a fractal dimension, or does it report a number that was put there by hand?

## Answer

**`1.322` was typed in and never computed.** It entered as a literal with `dfa6085455` (the Oracle 10 WASM sources) and propagated as prose. Separately, the tree holds **four functions named `D_f`** computing four different quantities, two of which are not dimensions at all.

## What `get_df()` actually did — not what everyone repeated

The claim "a hardcoded ~1.322 constant in dla.wat" (`box-counting.test.ts:4`, `reference.mjs:128`) is **itself inaccurate**. There is no `1.322` in the executable path — the `* 1.322` was only ever in a **comment**. The body was always `csize / (maxr * maxr)`:

| seed | 1 | 7 | 42 | 99 | 256 | 1000 | 2718 | 31415 |
|---|---|---|---|---|---|---|---|---|
| N/R² | 0.318 | 0.374 | 0.248 | 0.270 | 0.252 | 0.419 | 0.450 | 0.264 |

A factor of 3–5 from its own comment, on every seed. `N/R² = R^(D−2)` is not scale-invariant, so it has no fixed point and **cannot** be a dimension. A mislabel, not a poor approximation. Renamed `toy_density_proxy` (zero callers).

`OracleV8Bytecode` computed `ln N / ln(√N + 1)`, which **reads no particle coordinate at all** and tends to 2 by construction — same value for a disc, a line, or a dust of equal count. Renamed `toyDfFromClusterSizeOnly`.

## The ≈1.30 is an estimator artifact, not small-cluster physics

The prior explanation — *"800 walkers is too small to reach the 1.71 asymptote"* — is refuted by the control the estimator never had. Running the **same** box-counting code on a Sierpinski gasket (exactly self-similar, true dimension log3/log2 = **1.58496**, no finite-size physics whatsoever):

```
filled square (true 2.00000)   -> 2.0000
straight line (true 1.00000)   -> 1.0000
gasket, 2360 cells             -> 1.5297
gasket, 330 pts (DLA occupancy)-> 1.0001   <- same object, same true dimension
```

Only fewer points. The 0.585 error is **pure estimator bias**. Mechanism is in the counts: at ε=2 it finds 292 boxes for 330 points, so the small-ε end has **saturated**, and the window {2,4,8,16} puts half its fit points there. Definitionally (Falconer), the box dimension of *any* finite point set is **0** — so "the box dimension of the cluster" is not well-posed; only "the slope over a stated window" is.

## The clusters *are* scaling like DLA

Witten–Sander mass-radius on the **same** byte-locked clusters: mean **1.668**, within 2.5% of the accepted **1.71** (Witten & Sander 1981, PRL **47** 1400; Halsey 2000, Physics Today **53**(11) 36). Box-counting on identical data: 1.297. Two estimators disagreeing by 0.37 was the signal.
