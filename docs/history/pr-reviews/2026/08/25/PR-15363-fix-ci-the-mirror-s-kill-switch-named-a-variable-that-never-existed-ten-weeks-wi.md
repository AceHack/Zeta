## Description

`mirror-to-fork.yml` gated its job on
`vars.ACEHACK_MIRROR_ENABLED == 'true'`. That variable has never existed —
the repo carries exactly two variables and it is not one of them. So the
condition was false on every evaluation since the file was written: the job
reported `skipped`, the run reported success, and **the mirror never ran
once.** A skipped job is not a failed one, so nothing went red while the only
off-site copy of this repository quietly stopped being a copy.

The file recorded its own symptom without anyone reading it as one. Its
timeout comment said: "no completed runs (gated on ACEHACK_MIRROR_ENABLED)".

MEASURED WHEN FOUND (2026-08-25), not inferred:

  origin ahead of mirror   8,107 commits
  mirror ahead of origin      73 commits
  merge-base               2026-06-13 — ten weeks
  fork branches carrying commits origin cannot reach   1,084 (2,191 commits)

Compounding it, the mirror had **Actions enabled** and was independently
running this repo's cadence workflows — `context-cost-trend-cadence`,
`factory-hygiene-audit`, `razor-cadence`, `soraya-formal-coverage`,
CodeQL — writing its own data into the thing whose only job is to hold a
copy. That is where the 73 divergent commits came from.

WHAT CHANGED HERE:

1. The dead gate is removed. A kill switch whose state no reader can see is
   worse than none. A missing credential now fails LOUDLY in the push step
   instead of gating the whole job into a silent skip — an unprovisioned
   side-effect should be a red run somebody sees, not a green one nobody does.

2. `push` and `delete` triggers removed; schedule-only. The maintainer's
   call: "i don't think we should mirror everytime." This repo emits hundreds
   of ref events a day, each of which was queuing a full-history mirror push
   behind a serial concurrency group. A backup is a periodic artefact, not a
   synchronous write path. 6-hourly bounds worst-case staleness at 6h.

3. The header's stale instructions are corrected — it still told operators to
   set the variable that caused this, and still described a per-push cadence.

DONE OUT OF BAND, because they are settings rather than code and the mirror
was ten weeks stale (maintainer-authorized: "we can consider anything there
not important on acehack/zeta and just make it mirror lfg/acehack"):

  * the mirror's pre-resync tip preserved on origin as
    `archive/2026-08-25-acehack/main-pre-mirror-resync`, following the
    `archive/2026-06-13-acehack/*` precedent
  * Actions DISABLED on the mirror — this is what makes the
    fork-holds-no-unique-content contract self-holding rather than asserted
  * a full force+prune resync: origin and mirror now both read 248 branches,
    325 tags, main `33a5de6a38`
