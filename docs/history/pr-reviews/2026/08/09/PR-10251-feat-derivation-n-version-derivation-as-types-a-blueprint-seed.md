## Description

Encodes today's key-custody exercise as a reusable DU and a **blueprint** rather than a one-off narrated procedure. Skill = hub, blueprint = narrow satellite; one skill points at many.

> **A divergence between two independent derivations is a defect in the SPECIFICATION until argued otherwise.** The implementations are the instrument; the amended spec is the product.

## Anchored against itself

N-version programming is **Avižienis** (1977/1985) — and its strongest refutation is **Knight & Leveson (1986)**: independently developed versions fail in *correlated* ways, so N-version **voting** doesn't buy the reliability it claims. Taking that seriously is what gives the technique its real purpose here: **we're not voting, we're reading the divergence.**

## The three failures it types

- **Rounding partial up to done** — `Implemented / Partial / Deferred / Blocked`, per requirement. `Blocked` is distinct from `Deferred`: it has a dependency, and no effort on this slice reaches it.
- **The vacuity class** — `supportsClaim` returns false for `AssertedOnly`, `MutantSurvived` and `NotConfirmed`. **A surviving mutant is a hole in the tests** and never counts toward coverage.
- **Unfalsifiable criteria** — distinct from vacuous: text fine, logic circular, because obeying the spec removes the condition being tested.

`isSpecDefect` is true for every divergence except an argued `ImplementationDefect` — the central bias made mechanical rather than remembered.

## Whitebox as a first-class wall

`Whitebox` permits sight and replaces the wall with **attribution, contributing back, and profit-sharing** — cheaper and more honest where available, since it doesn't pretend to independence it lacks. **An unknown license blocks it**: unknown is not permissive, and that's the one place the module refuses rather than reports.
