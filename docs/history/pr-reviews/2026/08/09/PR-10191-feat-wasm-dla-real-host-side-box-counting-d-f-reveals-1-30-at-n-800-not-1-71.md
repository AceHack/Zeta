## Description

Ports the D_f box-counting fix Aaron greenlit into the repo — and surfaces an honest finding that changes the story.

## What
Replaces the ad-hoc `get_df()` mass-radius proxy (a hardcoded `~1.322` constant in `dla.wat`) with a **real Minkowski-Bouligand box-counting estimator** (`boxCountingDimension` in `bytelock/reference.mjs`), computed **host-side from the byte-locked trajectory**. Because the byte-lock guarantees every substrate emits an identical trajectory, the dimension is identical across all substrates for free — and it touches **no golden vector** (the vectors lock the trajectory + clusterSize + maxRBits, not D_f; D_f is *derived* from the trajectory they already lock).

## Honest finding (the reason this isn't a "now it's 1.71" PR)
Measuring the real estimator shows that at this repo's cluster size (**`N_WALKERS = 800`**) the box-counting dimension is **≈ 1.30** (avg 1.297 over 8 seeds), **not** the frequently-quoted 2-D DLA value **≈ 1.71** (Halsey 2000; arXiv:2607.02216). The 1.71 is the **large-N asymptote**; 800 walkers is too small to reach it, and real box-counting there sits right next to the old proxy.

So "port box-counting → repo reports 1.71" **does not hold at this N** — reporting 1.71 here would be a second fabrication on top of the first. Reaching ≈ 1.71 for real requires a much larger cluster, which changes the trajectory and thus the byte-lock golden vectors — a separate, larger decision (deferred, flagged for the USB/web-app owners).

## Contents
- `boxCountingDimension`: scales 2/4/8/16px, least-squares slope of ln N(ε) vs ln(1/ε) — the same estimator the web app's OracleV8Bytecode oracle uses, so repo and web app share one algorithm.
- `box-counting.test.ts` (3 tests): locks the honest N=800 value (~1.30), determinism, and guards against anyone "correcting" it toward 1.71 without growing the cluster.
- `README`: honest note that `1.322` is a proxy constant and the real value is ~1.30 at N=800 (1.71 is asymptotic); `binary_size ⊥ D_f` still holds.
