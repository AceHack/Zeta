## Description

Ferries architecture direction Aaron streamed across three messages today that wasn't written down anywhere. Docs-only.

**The claim:** the society has four tick sources — GitHub Actions, 3–4 bare Linux services, k8s pods, browser tabs — and they are **not four systems**. *"we want to integrate and enhance this to work so our society is one thread."*

Anchored to real substrate so the exists-vs-planned line stays honest (every cited path verified):

| # | Substrate | State | Anchor |
|---|---|---|---|
| 1 | GitHub Actions | **running** | `agent-heartbeat.yml`, cron `*/15`, resets from main so *staleness is impossible by construction*. The reference implementation, not the legacy one. |
| 2 | bare Linux (3–4) | planned | tick sources now; may grow into a k8s replacement |
| 3 | k8s pods | partial | `zeta-ai-agent.nix` per-persona systemd units |
| 4 | browser tabs | partial, substantial | 32 files in `browser-node/` — service worker, tab coordinator, IndexedDB checkpoint, lifecycle host (Vera) |

Records **auto-heal by redundancy** (3 outside k8s + 3 inside) and the two carved disciplines that make redundancy resilient rather than duplicative: **idempotency** (N ticks == one tick's *effect*) and **local-time-never-enters-the-shared-fold** (four substrates, four clocks — a suspended browser tab is the sharpest case).

Also records the lesson just paid for in 081KZETP6AT as a rule the fleet inherits: **grace in the artifact, strict in the test** — an auto-heal layer with no acceptance assertion is a silent-failure generator.

Names the four things "one thread" actually requires (one identity space, one fold, one ledger, one liveness signal) as **open design questions, not settled answers**, and why the USB/nix-ld work is upstream of half the topology rather than adjacent to it.
