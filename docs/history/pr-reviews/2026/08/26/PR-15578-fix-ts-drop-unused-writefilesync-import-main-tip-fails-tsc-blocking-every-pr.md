## What

`lint (TS)` is red on `main` tip (`57b2d149f6`) and, because `tsc --noEmit` is whole-tree
scoped, it convicts **every open PR** regardless of what that PR touched.

```
src/Core.TypeScript/observe/decorrelation-harness.ts(48,10):
error TS6133: 'writeFileSync' is declared but its value is never read.
```

`appendFileSync` and `mkdirSync` from the same import are both used (L170–171).
`writeFileSync` has no reference anywhere in the file. One symbol removed, no behaviour
change.

## Evidence it is pre-existing, not introduced

`lint (TS)` on the last six concluded push-to-`main` gate runs: `success, success,`
**`failure, failure,`** `success, success`. It is intermittently red on `main` itself, and
the import is still present at `origin/main` today.

## How it was found

reach. That is a live instance of the shared-gate scoping problem — a whole-tree check
reporting under a name that says nothing about whose commit broke it, so the red lands on
whoever opened the next PR.
