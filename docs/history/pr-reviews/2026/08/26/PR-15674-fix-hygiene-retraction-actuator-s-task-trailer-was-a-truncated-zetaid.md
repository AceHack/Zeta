## Why a truncated id is worse than a wrong one

It falls **between** the two checks instead of into either:

| check | what it does with `081KZHGP45V` |
|---|---|
| `agencysignature-block.ts` `TASK_RE` | **rejects** — requires the full 26-char width, so every commit this lane writes fails the signature gate |
| AH006 `audit-task-zetaid-resolves.ts` | **cannot see it** — the extractor keeps only well-*shaped* ids, so a prefix yields zero ids and the audit reports "no Task ids in the input", rc=**0** |

Loud in the lane that runs during an incident — main red, auto-revert firing, no
human in the loop — and silent in the audit built to catch exactly this class.

## The test that passed it

The suite already had `carries all ten AgencySignature v1 keys`, and it passed
this id for as long as it was wrong: `toContain("Task: ")` cannot see what
follows the colon. Presence asserted, value unchecked — the vacuity class in a
test rather than in the code it guards.

Two tests added:

- the trailer must match the shape gate's own regex **and** equal the full id;
- the id must resolve under the same `indexWorkItems` AH006 uses — with the
  truncated form asserted **not** to resolve, so the check discriminates rather
  than accepting anything.
