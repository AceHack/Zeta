## Description

## Why

Aaron, 2026-08-26: *"many times i have to redesign over and over secure AI / human interactions. if this could be taught and reused over and over it would be great productivity enhancement to both sides."*

The repo had two thirds of the human gate. `ceremony-gate.ts` says **whether** a human is needed (a total classifier over a closed set); `ceremony-brief.ts` says **what** they are told. Nothing carried the third part: what must be true **before and after** the moment of approval. `frost-hsm-provision.ts` (#15564) derived that correctly, against real hardware, on 2026-08-26 — and the next privileged operation would have derived it again.

## What landed

**`tools/setup/persona-keys/ceremony-handoff.ts`** — the protocol as types, plus `runGatedCeremony`, the composed entry point.

`runGatedCeremony` is the load-bearing piece and it exists because of adversarial review. The parts alone would have made a consumer learn four modules to perform one act — and the evidence that this is a tax rather than a saving was already in the tree, since the two gated call sites this repo has shipped (`publish.ts`, `revoke.ts`) reach for two of the four and stop. More importantly:

> **An ordering that lives in a doc is a call-site obligation. An ordering that lives in a function body is a guarantee.**

"Approval follows authentication" was prose everywhere else — a call site could resolve credentials *after* prompting and nothing would object. Inside `runGatedCeremony` it cannot, because the sequence is the statements, and no argument reorders them. A falsifier asserts the event order rather than restating the claim.

**The six invariants**, each with the mechanism that carries it *and* what it does not deliver:

| # | invariant | mechanism | honest limit |
|---|---|---|---|
| 1 | agent never holds the secret | `Secret` renders `<redacted>` through `toString`/`toJSON`/inspect; one greppable `reveal()` | hygiene, **not a boundary** — stops accidents, stops no attacker |
| 2 | approval follows authentication | `assertFullySpecified`, and the body of `runGatedCeremony` | cannot prove no prompt appears; **prefer programs that FAIL over programs that PROMPT** |
| 3 | act fully specified before approval | `argv`/`displayArgv` are two projections of **one array** | subprocess-shaped; non-subprocess acts use `CeremonySubject` |
| 4 | **every refusal names its remedy** | `refusal()` throws on an empty remedy — the value cannot be constructed | can check a remedy *exists*, not that it *helps* |
| 5 | before/after measured | `measureAround` probes twice, carries both | runs the probe **you** supply; a constant probe measures nothing |
| 6 | **escape hatch named, never blanket** | `namedEscape` refuses `*`/`all`/`force`/`admin`; needs a reason and an authorizer | nothing stops enumerating every code by hand — but that is a visible list in a diff |

**Invariants 4 and 6 survive every generality test unchanged.** They are the portable core.

**`docs/protocols/ai-human-secure-handoff.md`** — the teachable version: an end-to-end walkthrough for a real unimplemented gated operation (`x402-authorize-exceeding-standing-budget`), the generality table, the ladder's true scope, and what you still have to think about yourself.

**The closed set is not extended.** `runGatedCeremony` is parameterised by a `FederatedIdentityOperation`, so a new capability must be classified in `ceremony-gate.ts` — with a written reason — before it can be handed off at all. That friction is the design.

## The gap this fixes, and why it is a constructor

The worked instance had **eight** `unreachable` stages that each named a remedy; two diagnosed a live operator's host well enough to repair in one step each. It also had a password refusal whose reasoning was *better* than any of them —

> *"the operator would be approving an act whose authentication had not happened yet"*

— and which named **no remedy at all**. Same file, same author, same hour.

That asymmetry is the whole argument: remedy-naming is a **discipline you fall out of**, not a thing careless people do. So it belongs in a constructor, not a review checklist. Both strings are pinned as test constants so the claim stays checkable after the code is repaired.

`keychainSecretSource` is the fix as the first consumer. The remedy names `tools/setup/secret-clip.sh set <name> --clipboard --clear-clipboard`, **verified against that script's own `usage()`** (which prints lines 11–18 of itself, so the text cannot drift from the parser). It accepts exactly `set`/`get`/`del` — a test asserts the remedy never names `put`/`store`/`add`, because *a wrong remedy is worse than none* applies hardest to this module's own output. The store's real limits travel **with** the remedy: macOS-only today, deputy fallback on existing ACLs.

## Adversarial review found four real defects in my own module

Ran two rounds with distinct lenses (cold-start cost, duplication, falsifiability, generality; then host-fit and the teaching claim). All fixed:

- **`measureAround`'s catch block was dead code.** It threw the same error down both arms of its comparison; the after-reading was computed and **discarded** while a comment claimed the caller now had it. A mutation test could have deleted the whole branch without failing anything — the vacuity class, inside the module written to abolish it, guarding the exact case invariant 5 exists for (a half-done privileged act). Now throws `MeasuredActFailure` carrying `before`/`after`/`changed`, with the cause's message preserved as a prefix so existing assertions and log greps keep matching.
- **`probe` was synchronous**, silently excluding every act whose state lives over a network — a cloud token, a remote KRL, a database. An artifact of the local-hardware instance. Now async.
- **The plaintext-in-display check used array-element equality**, so it found a credential only when it was an argument entirely by itself. `--pw=${s.reveal()}` — the ordinary spelling — reported clean while shipping the password to the operator's terminal. Now a substring scan with a stated 4-char floor.
- **`specifyPlan` overclaimed generality.** Renamed `specifySubprocessPlan`; `assertFullySpecified` added for the act-shape-agnostic case, because two of this repo's three gated ceremonies are not subprocess invocations.

## The proposed rule — reduced to three decisions, not ten

A carved sentence for `.claude/rules/` was drafted and attacked. **The verdict is: do not create a new rule file**, and the argument that decided it is that `.claude/rules.bak/desktop-admin-consent-via-biometric-plus-small-challenge-i-execute-you-fingerprint.md` (13,342 B, verified present) already covers this territory — including a section that decides invariant 1 — and **the fleet archived it out of residency**. A new file reverses that silently.

Round 1 converged on "append it all to `no-directives.md`". Round 2 rejected that, and the reason is recorded because it is the more interesting finding: three attackers agreeing was a **correlated** result — all three were optimising the same cold-start metric round 1 put in front of them, so it was one observation counted three times (`numerology-vs-number-theory.md`: *too many correlations is a warning, not a confirmation signal*). Cheapness of insertion is not fitness of host.

What survives is two small placements, and **§10 of the doc carries the full record** — including the objections that were raised and defeated, so nobody re-litigates them.

**Three residual decisions, each a genuine values call:**

1. **Is `rules.bak/` a graveyard or a lookup table?** Re-admitting archived territory sets a precedent. *For:* the archived rule covers biometric consent, not refusal hygiene, and treating "adjacent" as "covered" is how a gap hides behind a redirect. *Against:* the archive was a measured cold-start cut; reversing it per-topic re-bloats by a thousand individually-justified paragraphs.
2. **May a resident norm ship with no falsifier?** "Every refusal names its remedy" cannot be linted at broad scope — `throw new Error("nope")` is always available. *For:* it is what makes gates survivable, and the measured evidence is that good engineers fall out of it within the hour. *Against:* an unenforceable floor at maximum scope is the unenforced-guarantee shape named as *the* obstacle to human-AI trust.
3. **Is "name the remedy" a power discipline or a care discipline?** If the gate-holder *owes* the gated a path, it files near `no-directives` and authority. If it is about how one intelligence treats another when delivering bad news, it files near `never-assume-malice`. Both defensible; they file it permanently differently.

**Nothing was added to `.claude/rules/` in this PR.**
