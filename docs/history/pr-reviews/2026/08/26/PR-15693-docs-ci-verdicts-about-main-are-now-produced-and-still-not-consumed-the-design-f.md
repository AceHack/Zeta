## What remains, measured

- **104 of 235 commits in 24h (44.3%) get no gate run at all.** 41/41 sampled bot-merged commits produce none — verified by mechanism, not inferred (`actions/runs?head_sha=` returns no `event: push` run for them; 11 for a human-merged one).
- **p50 lateness at verdict: 4 commits / 16.4 min**, against a 2.77 min median merge interval. A verdict costs about six merge intervals to make.
- **Nothing reads one.** `retraction-actuator.ts` is the only designed consumer — RFC with four roster assents, twelve golden-vector laws, wired into `drift-sweep.yml` since 2026-08-22. **`docs/drift-events/retraction-episodes.json` does not exist. It has never fired.**

## The finding that decides the sequencing

Today's Windows outage is a live counterexample to retract-on-red:

| | |
|---|---|
| last green push run head | `d4e39a78` |
| first red push run head | `c3addd47` |
| `git log d4e39a78..c3addd47` | **exactly one commit** ⇒ isolation **unique** ⇒ refusal path does not engage |
| actual cause | `www.gnupg.org:443` unreachable |

It would have retracted **#15683** — a hygiene lint, causally unrelated — confidently, with a correctly-formatted letter to its author.

> Every existing guard is about **uniqueness** (one candidate) or **at-most-once** (one attempt). **None is about attribution.** Uniqueness is a property of the commit graph; attribution is a property of the failure. An infrastructure outage yields a perfectly unique isolation and a completely wrong answer.

§3.2 proposes three cheap attribution predicates, the first of which would have refused today, and recommends the write token stay unwired until one exists with a falsifier.

## Two corrections to the options as posed

- **A merge queue would not have caught today.** The pre-merge matrix is Linux + macOS only, and promoting a Windows leg to required deadlocks the queue (companion §6.5). The queue closes the semantic-conflict class and leaves platform drift exactly where it is.
- **Windows is not the slow platform.** p50 710 s — between macOS (700) and Linux x64 (742); `ubuntu-24.04-arm` at 405 s is the fastest leg. Today's 243-298 s Windows runs were short because they died early. Closing a 16.4 min verdict into a 2.77 min merge interval needs **6×**; nothing on offer is 6×. Speed is a cost lever, not an answer.

## Recommendation

Sequenced, and the first item is not on the consumption side at all — every consumption design is a no-op on the 44.3% of commits that produce no verdict.

1. Fix production first (companion §7 steps 1-2)
2. Publish coverage — a stated 55.7% beats an implied 100%
3. Attribution predicate + falsifier before the write token
4. Merge queue, if the semantic-conflict class has actually bitten (still unmeasured)
5. Bisect-on-red last, as an upgrade to the actuator's non-unique refusal
6. Speed on its own merits

§5 names five gated-class calls for Aaron. §6 lists six things I could not verify, including whether BD001 would actually have opened today — the counterfactual rests on the isolation arithmetic, which is verified, not on the trigger having fired.
