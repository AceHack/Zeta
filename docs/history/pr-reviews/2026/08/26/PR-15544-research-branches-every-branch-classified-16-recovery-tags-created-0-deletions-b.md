## The safety problem, measured twice today

A branch sweep is safe because its `archive/*` recovery tags are mirrored off-site to
`acehack/Zeta`. They are not.

| moment (UTC, 2026-08-26) | origin tags | fork tags | `archive/*` missing off-site |
|---|---|---|---|
| 08:31:56 — before this work | 343 | 325 | **18** |
| after this work created 16 | **359** | 325 | **34** |

`comm` in the other direction is empty — the fork holds nothing origin lacks, so this is one-way
loss, not divergence. **Reproduced from the run log** of `mirror-to-fork` run `32937913382`
(06:23:31Z, the last run before the fix):

```
! [remote rejected]     main (refusing to delete the current branch: refs/heads/main)
error: failed to push some refs to 'https://github.com/acehack/Zeta.git'
##[error]Process completed with exit code 1.
```

`update-ref -d refs/remotes/origin/HEAD` dereferences the symref, `--prune` then asks the fork to
delete its own default branch, the push exits 1, and `set -euo pipefail` aborts **before the tag
push on the next line**.

**#15499 fixed this and merged at 08:31:11Z.** The merged workflow is `cron "13 8 * * *"` — daily at
08:13 UTC, which today fired **18 minutes before the fix landed**. So the fix is on `main` and has
**never been observed to run**, and absent a dispatch the next proof is 2026-08-27 08:13 UTC.

**Before executing any delete list:**

```bash
gh workflow run mirror-to-fork.yml --repo Lucent-Financial-Group/Zeta
# then confirm the two counts agree:
git ls-remote --tags https://github.com/Lucent-Financial-Group/Zeta.git | wc -l
git ls-remote --tags https://github.com/acehack/Zeta.git | wc -l
```

## Method — and the trap

`git merge-base --is-ancestor <branch> origin/main` is **not** a merged-test here: `main` takes
squash merges, so an absorbed branch's commits are never ancestors and the test reports `merged=no`
for branches whose PRs are demonstrably `MERGED`. Used instead: **PR state** for merged/refused,
`compare` for ahead/behind, and **blob-identity per changed path** against `main` for redundancy —
followed by a rename search across `main`'s 50,625-path tree before calling anything missing. That
last step recovered four "missing" paths that had simply moved (e.g. a workitem promoted into
`workitems/done/2026/07/`).
