## Description

Aaron, reviewing #15666 — a change whose whole content is "remove one audit", and which therefore had to edit two lists that are parity-checked as ordered sequences:

> *"this design seems a bit flakey, are we going to be fixing this all the time, can we automate this fix in our small free github runners agent society? or redesign this so it's different and less brittle?"*

**This answers the third question, not the second.** Automating the repair of a brittle design keeps the brittleness and adds machinery to it. Two hand-maintained lists that must agree IS the defect.

## What was actually duplicated — three places, not two

| where | what it encoded | how it failed |
| --- | --- | --- |
| `gate.yml`'s `audit:` matrix | the 31 ids, in order | had to be edited in lockstep with the roster |
| `CROSS_VERIFY_AUDITS` | the 31 ids + titles | the source |
| `docs/ci/CROSS-VERIFY-CHECK-NAMES.md` | the check names + titles | a **fourth** hand-maintained table — measured, all 31 descriptions were byte-identical to the roster's `title`, so it was pure duplication |
| `cross-verify-roster.test.ts` | `toHaveLength(31)` | **went red on #15666's legitimate removal** |

## The redesign

The roster is the only place the ids live. `gate.yml`'s matrix and the doc's table are **delimited generated regions** emitted from it:

```bash
bun src/Core.TypeScript/ci/cross-verify-roster.ts --derive          # exits 1 on drift, naming it
bun src/Core.TypeScript/ci/cross-verify-roster.ts --derive --write  # rewrites every generated region
```

Copied from `ace/build-graph.ts derive [--write]` rather than invented — including its refusal to rewrite a file that is already current. **The same command is the check and the fix, so they cannot disagree with each other.** Adding or removing an audit is a roster edit plus that one command.

### Why a generated REGION and not a generated FILE

Weighed, and the workflow forces the answer. GitHub cannot read a matrix out of a file: the only way to feed one from elsewhere is `fromJSON` of a job output — the **dynamic matrix** the roster's own header already rejects, because the leg names would then not exist until a roster job succeeded, and *a required context that never reports does not fail a PR, it WEDGES it.* That argument is unchanged and still load-bearing, so the region has to live in `gate.yml`.

It also diffs better, which was the tie-breaker for the doc using the same mechanism: a reviewer sees `- an-audit` appear in the workflow they already read, not a line in a generated artifact plus a claim about what consumes it.

## Order: incidental to correctness, load-bearing for reading

`fail-fast: false` and every leg is independent, so **no leg's result depends on any other's position** — order is incidental. It is *not* sorted anyway, and the reason is stated in the generator: the roster groups related audits adjacently (`image-source-provenance` beside its `-tests`, the two heartbeat-lane audits, the two tech-radar ones), and sorting would scatter every pair for no gain. **Source order is exactly as deterministic as sorted order**, which is the property a generator actually needs. Determinism is proven below; sorting is one way to get it, not the only one.

## Could the parity check be deleted? **No — and it stays, with the hole named.**

Generation does **not** make divergence impossible. `gate.yml` is a text file; the generated region remains hand-editable. **A parity check removed while a divergence path remains is strictly worse than today**, so it stays.

What changed is what it *is*. It is no longer two hand-maintained lists compared as sequences — it is a **byte comparison against the generator's output**, which subsumes membership, duplication and order in one test that cannot hold a different opinion from the fix. `compareRosterToMatrix` survives as **diagnosis only**: after a byte mismatch it re-reads the workflow with an *independent* parser to turn "the region's bytes differ" into "leg `x` has no roster entry". Nothing passes because it returned `ok` — that is stated in its docstring so the next reader does not promote it back.

**Where the enforcement runs, precisely:**

- every one of the 31 matrix legs runs the gate.yml check *before* its own audit, so a hand-edit there survives at most one CI run;
- the leg check is deliberately **narrower** than `--derive`: it does not check the doc, because a stale table turning into 31 red legs would re-widen exactly the blast radius the 31-way split was built to shrink. The doc's region is covered by the test suite, which runs in `test (TS hermetic)` — a floor job.

## Coordination with #15666 — it merged, and the resolution is the demonstration

**Built beside it, on `origin/main`, not on top.** Three reasons:

1. The repo squash-merges. Stacking would put #15666's commits inside this PR and land the same content twice; the bounds also require base `main`, which a stacked PR would not have.
2. #15666 is a separately-argued change that also adds a 509-line guard and a new workflow. Coupling a representation change to it makes both harder to review and makes this one hostage to that review.
3. **The conflict surface was deliberately minimised**: the `- <id>` lines were left untouched by this diff — only the comment above them and two marker lines move — precisely so #15666's single-line deletion would merge into the generated region rather than fight it.

**#15666 landed as `09bd8b8507` while this was open, so that prediction got tested rather than asserted.** After resolving, `--derive` is **rc=0 on both regions with no regeneration needed**: #15666's deletion of `- orphaned-archive-refs` from the matrix, and of its row from the check-names table, merged in as *exactly the bytes the generator now emits*. That is the change working on the first case that needed it.

## Honest limits

- **The hand-edit path survives** — that is why the check stays, and it is named above rather than implied away.
- **`--check-parity` is gone**, replaced by `--derive`. `git grep` found no workflow, script, or doc invoking it; the roster's own USAGE header is updated.
- **The doc's drift is caught by the test suite, not by a matrix leg** — a floor job either way, but a different one, and the asymmetry is deliberate rather than accidental.
- **A generated region in a hand-maintained file is a compromise, not a clean separation.** The alternative was rejected on a stated mechanism (GitHub cannot read a matrix from a file without a dynamic matrix), not on taste. If that ever stops being true, the region should become a file.
