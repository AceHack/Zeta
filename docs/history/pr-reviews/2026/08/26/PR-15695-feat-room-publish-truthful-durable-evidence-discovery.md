## Description

## Durable room-evidence live feed

This PR adds a repository-visible discovery view of room-evidence audit envelopes. Publication occurs only after `DurableRoomEvidenceAuditLedger.append` succeeds. The feed reader distinguishes `ready`, `empty`, `unavailable`, and `malformed`; the initial committed manifest is intentionally empty and therefore does **not** fabricate a room episode, assertion, retraction, or witness outcome.

The GitHub Pages evidence room displays the same state while declaring its boundary: browser parsing checks manifest/envelope shape and event-ID binding only. Durable content-address verification and local roster authority remain at the persisted writer/verifier boundary.

### Fault controls

The new DREL suite demonstrates that an empty manifest remains no-data, a failed envelope write cannot create discovery, an unavailable index is not folded, and duplicate or mismatched event IDs become teaching errors. Targeted strict TypeScript compilation, 4 Bun tests / 10 assertions, Prettier, diff integrity, and both static-site builds passed locally.

### Non-claims

The manifest is discovery data, not a global identity roster, a transport guarantee, a proof of unseen-event absence, or a browser-side Merkle verifier. The emitting adapter that writes this manifest after a production room runtime append remains the next operational integration.
