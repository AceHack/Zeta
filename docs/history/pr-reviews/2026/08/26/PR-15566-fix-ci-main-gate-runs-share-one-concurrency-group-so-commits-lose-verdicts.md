## Description

`drift (loud)` reports **11 commits landed on `main` carrying no gate verdict** — neither pass nor fail — at a **56.7% cancellation rate (34/60 runs)**. An unchecked commit on main is indistinguishable from a passing one.

## The cause is the group, not `cancel-in-progress`

`cancel-in-progress` is already `false` for pushes — `${{ github.event_name == 'pull_request' }}`. Main pushes do not interrupt each other.

But every push to main shares **one** group, `gate-refs/heads/main`, so runs serialize into a single queue slot. Under a merge wave — 12 PRs merged in the 35 minutes before this commit — a third arrival displaces the pending run, and the displaced commit never gets a verdict.

Keying the group by `github.sha` for pushes gives each commit its own group: nothing queues, nothing is displaced.

## PR behavior is deliberately unchanged

`github.event.pull_request.number` still keys PR runs and `cancel-in-progress` stays `true` there, because superseding a PR's in-flight run when its tip moves is **correct** — only the tip matters, and cancelling saves capacity we are short of.

**Not all cancellation is a defect.** The metric currently conflates correct PR supersession with main-side verdict loss, and only the second is a problem. A large share of tonight's 56.7% was the fleet's own remediation: an agent pushed merge-commits to 11 PR branches, each one correctly cancelling a superseded run.

## Scope — deliberately narrow

**32 other workflows** key their concurrency group on `github.ref` and have the same displacement behavior on main. They are **not** changed here:

- `gate (required)` is the only required check, so it alone decides whether a commit is checked at all.
- An experiment that moves 32 variables at once cannot attribute its own effect.
- Actions cache is separately measured at ~69 GiB/hour of writes against a 9.31 GiB ceiling, evicting 23 GiB in 61-second sweeps. A fleet-wide parallelism increase is not free.

## Not verified

The displacement mechanism is **inferred** from GitHub's documented concurrency semantics plus the observed pattern — not reproduced. The falsifier is direct and cheap: **if verdict coverage on main does not improve after this lands, the mechanism is wrong.** Watch `drift (loud)`'s commits-without-verdict count.

A decision doc costing this against enabling the merge queue — whose `merge_group:` trigger is **already wired** in `gate.yml` and `codeql.yml`, so the workflows are queue-ready and only the branch setting is off — is in flight separately.
