## Description

## The defect

`scripts/hooks/install-git-hooks.sh` mixed two different scopes:

| | resolves to |
|---|---|
| source (`$(dirname $0)/../..`) | the **current worktree** |
| destination (`git rev-parse --git-path hooks`) | the **owning clone**, shared by all its worktrees |

Run from a throwaway worktree, it wrote a symlink into the owning clone's shared
hooks directory pointing **into a directory about to be deleted**. When the
worktree went, the link dangled — and **git silently skips a hook it cannot
execute**. No error, no warning.

Blast radius: `commit-msg` is the AgencySignature / Manus-leak guard and
`pre-push` is the uncompensatable floor. Both stopped running for *every*
worktree of that clone. It is reachable from all three `GOVERNANCE.md §24`
install paths, so any agent creating a worktree could disarm the fleet's hooks
as a side effect of ordinary setup.

## The falsifier

```
create a worktree -> run the installer from it -> delete the worktree
-> the owning clone's hooks STILL EXECUTE
```

Run end to end, for **both** the shell installer and the ACE realizer:

| install path | before | after |
|---|---|---|
| shell installer | `commit rc=0` — **silently disarmed** | `commit rc=1` — hooks execute |
| ACE realizer | `commit rc=0` — **silently disarmed** | `commit rc=1` — hooks execute |

Every assertion checks that a hook **ran** (a refused commit, a blocked push),
never that a file exists — a symlink that resolves is not proof git invoked
anything. A **control** test pins that the probe fails when nothing is
installed, so a pass cannot come from a broken probe.

Now permanent in `src/Core.TypeScript/ace/setup-realizers/from-git-hooks.test.ts`
(12 tests). Mutation-checked: restoring the old installer + old realizer turns
**5 of them red**, including both headline falsifiers.

## Why `core.hooksPath` (approach 1), measured not assumed

Against `git 2.54.0`:

- a **relative** value resolves against **each worktree's own top level**, so
  every worktree runs *its own* tracked hooks — verified from subdirectories too;
- `--local` lands in the **shared** `.git/config` even when set from a linked
  worktree, so **one install arms every present and future worktree**;
- there is **no symlink**, so nothing can dangle;
- a fresh clone's `.git/hooks` holds only `*.sample`, so **nothing is displaced
  in the common case** — the first install for a single-worktree clone is not
  made worse.

Approach 2 (absolute source from the owning clone) was rejected: it keeps a
symlink, still breaks if the owning clone moves, and makes every worktree run
*one particular worktree's checkout* of the hook rather than its own branch's.

Approach 3 (refuse from a linked worktree) was rejected **as stated** — under
`core.hooksPath` the worktree case is *correct*, so refusing it would be a false
alarm. Its discipline is kept where a real hazard remains, below.

In-repo prior art pointed at this layer already: the 2026-05-01 tick and
`docs/backlog/P2/081KQGDBJ...` both name `core.hooksPath` as the versioned
integration point and `.git/hooks/*` as the wrong (per-clone, untracked) one.

## The ACE realizer had to move too

Not only for §24 parity. With `core.hooksPath` set, `--git-path hooks` returns
`scripts/hooks`, so the realizer's `dest` collapsed onto its own `hookSrc` and
the `unlink`+`symlink` pair **deleted the tracked hook**, leaving a
self-referential symlink — measured as `Too many levels of symbolic links`, with
git reporting a typechange. Leaving it untouched would have made this PR a
regression. Covered by a test.

## Refusals name their remedy

- a **foreign** `core.hooksPath` → refuse, preserve it, print the exact adopt command;
- a **worktree-local** `core.hooksPath` that would **shadow** the shared one →
  refuse (measured: worktree config does win);
- foreign hooks in `.git/hooks` that `core.hooksPath` now bypasses → **warn**,
  rather than silently stranding them;
- only links the installer **provably created** are removed, which **heals an
  already-dangling clone** on re-run.

## Third commit — pinning the property the fix rests on

"The install worked" is also true of a shared **absolute** `core.hooksPath`, so
nothing yet tested the property the relative value is actually chosen for. Added
a test that gives the feature branch a hook which additionally refuses `BANANA`,
then asserts the feature worktree refuses it while the base clone does not:

> **each worktree runs ITS OWN branch's hook, not the installing worktree's**

Mutation-checked, so it is a falsifier and not a restatement — storing
`$top_level/$HOOKS_REL` (absolute) instead turns it red, along with the
worktree-deletion falsifier and the idempotency test. **13 pass** on the real
code.

## Second commit — three CI legs, all three mine

Control first: each is green on pristine `origin/main`. My first "pristine"
comparison was **wrong** — `git stash` drops uncommitted edits, not the commit,
so it measured my own change twice. Re-measured in a clean worktree at
`origin/main` (18 entry points, rc=0).

1. **`cross-verify (stage0-independence)`** — `HOOK_NAMES="commit-msg pre-push"`
   reads to the stage-0 parser as an assignment prefix plus a bare head token:
   `ASSIGNMENT` strips `HOOK_NAMES="commit-msg`, leaving `pre-push"`, which
   `tokenNamesTarget` un-quotes into an **`exec` edge that does not exist**.
   `scripts/hooks/pre-push` moved from entry point to internal, entry points
   fell 18 → 17, and the concatenation guard fired because stage-0 bytes had
   also risen. Fixed by naming the hooks in separate assignments. The guard was
   right on the merits even though the edge was an artifact, so the long
   rationale moved to the README (not stage-0): **6780 → 4935 bytes**.
2. **`cross-verify (check-then-use-races)`** — the realizer's `existsSync` gate
   on `chmodSync` is a **genuine** race and the lint's prescription is correct.
   Removed; a missing hook now surfaces as `ENOENT` from the one syscall that
   does the work.
3. **`lint (bash retirement inventory + hygiene unit tests)`** — named via the
   jobs API rather than guessed (the check-run id *is* the job id): the failing
   step was "Hygiene unit-test suite", sharing root cause 1. Green (3037 pass).

Also strengthened while re-verifying: the foreign-hook warning now fires on a
**dangling** symlink. `-e` alone is false for one, so the original loop skipped
precisely the failure mode this PR exists to fix.
