## Description

While digging into bug B (081KZHJPJCF — wifi-ESP markers missing), found *why it couldn't be root-caused*: the wifi-ESP contract-failure path calls `reportResult()` **without** first calling `writeArtifactSerialLog()`, so the serial log is never written — yet `reportResult` logs "Full serial log preserved at: …". The upload step then finds nothing ("No files were found with the provided path: qemu-wifi-esp-serial.log"), making the failure a black box.

The write happens on the `exitCode!=0` path (~717) and the success path (~757); the wifi-contract branch fires *before* ~757, falling through the gap. And this is precisely the branch bug B hits: install **completes** (exitCode 0) but the `[iter-5-wifi]` markers are absent → wifi-contract branch → serial not persisted.

**Fix:** `writeArtifactSerialLog(phase1Serial, "")` before `reportResult`, mirroring the exitCode!=0 path. Next dispatch uploads the phase-1 serial so the actual iter-5-wifi behavior (found vs "no…skipping", and which dirs it searched) becomes visible.

**Red herring ruled out:** the ESP offset — `prepareBootImage` already auto-detects via `resolveEspOffsetBytesForIso` (line 122) and **ignores** the passed-in `espOffsetBytes`/`DEFAULT_ESP_OFFSET_BYTES`. So the bake offset is correct; #2 is dead-field cleanup, not bug B's cause.

`tsc` clean.
