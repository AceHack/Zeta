## Description

Completes deprecated-item **#2** — now confirmed **pure dead-field cleanup**, not a behavioral change (the investigation into bug B established this).

`prepareBootImage` auto-detects the ESP offset internally (`resolveEspOffsetBytesForIso`, line 122) and **ignores** the passed-in `input.espOffsetBytes`. So `PrepareBootImageInput.espOffsetBytes` was a required-but-dead field, and `DEFAULT_ESP_OFFSET_BYTES` (its deprecated fallback) was only ever fed into that dead field.

**Removed:** the field; its 4 construction-site args (`qemu-full-install-test.ts`, `run.ts` ×2, `prepare-boot-image.ts` helper); the deprecated `DEFAULT_ESP_OFFSET_BYTES` const + 2 imports.
**Kept (the live ones):** the real `espOffsetBytes` on the zflash CLI/lib interfaces (`ports.ts`/`file-backed.ts`/`lib.ts`) — validated + fed to mtools; and `resolveEspOffsetBytesForIso` / `ISOHYBRID_ESP_OFFSET_FALLBACK_BYTES` (the auto-detect).

**Verified:** tsc + prettier + style clean; no dangling refs; zflash lib + file-backed tests **69/69** (real offset path unchanged).

Closes the last deprecated TS member from the Alexa-handoff cleanup (other two dead fields: #10160).
