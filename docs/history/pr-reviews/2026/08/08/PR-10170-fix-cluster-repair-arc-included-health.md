## Description

## What

- apply the ARC controller chart with ArgoCD server-side apply
- retain ARC pod state plus current and previous controller logs in the included kind proof
- pin both behaviors with focused workflow and manifest tests

## Why

ArgoCD client-side apply serialized each ARC CRD schema into the last-applied-configuration annotation. All four CRDs exceeded Kubernetes' 262,144-byte annotation limit, so none were created and the controller exited because EphemeralRunnerSet was unavailable. Server-side apply stores field ownership without that oversized annotation and lets the controller start normally.
