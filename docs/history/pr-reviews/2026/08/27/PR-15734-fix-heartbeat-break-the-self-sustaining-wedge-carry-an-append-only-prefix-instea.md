## Description

## The verified cause

The alexa lane failed **eight consecutive scheduled runs** (17:50Z–23:42Z, 2026-08-26). The
run-level red was misleading: in run `33024333706` five of six jobs succeeded and only
`alexa heartbeat tick` failed, at step `Accumulate unflushed heartbeat state over current main`.

Read out of that step's log rather than inferred:

```
prepare-heartbeat-branch: carry unflushed heartbeat state failed: Auto-merging data/ci-runs.jsonl
Auto-merging data/tick-reasoning.jsonl
CONFLICT (add/add): Merge conflict in data/tick-reasoning.jsonl
```

The flush lands a lane on `main` with `--squash`, so main's copy of a lane-written file carries
**no ancestry** back to the lane that wrote it. The next tick's merge base therefore predates the
flush and holds *neither* side, and git reports add/add on a file whose two sides are one
append-only stream at two lengths. Measured on the live refs at 00:54Z:

| | |
|---|---|
| merge-base | `443cdacdb5` (22:27:58Z) — `data/tick-reasoning.jsonl` **absent** |
| main | 16 rows (via the 23:11Z squash flush #15551) |
| lane | 30 rows — and main's 16 are the lane's rows 1..16 **verbatim** |

## The loop is genuinely self-sustaining — and it is dormant, not gone

A failed tick never pushes, so the lane ref stays frozen, so the merge base never advances past
the flush, so the next tick recomputes the identical add/add. It cannot clear on its own.

**#15722 cleared today's instance** by declaring `data/tick-reasoning.jsonl merge=union`, and the
lane went green in run `33028579971`. That is the declaration working — **not** the loop being
broken. This is the eighth member of the class since 2026-08-16, and each was cleared the same
way: a human diagnosing it and hand-writing one `.gitattributes` line. The loop survived every
one of those fixes, and the next undeclared append-only path re-arms it.

## The fix

The carry now **resolves** a conflicting path when main's copy is a **whole-line prefix** of the
lane's, checked against the actual bytes in the index at merge time. The tick then commits and
pushes, which re-parents the lane onto current main — the base advances and the divergence is
**gone rather than deferred**.

**Why it cannot clobber.** Under a whole-line prefix, taking the lane's copy is losslessness by
construction: every line main holds is already in the result, in place. The newline requirement
is load-bearing, not decorative — a bare byte prefix ending mid-line would let the lane *rewrite*
main's last record instead of appending after it, and that case is refused with its own test.
Binary is refused outright.

**Why it is narrower than `union`, deliberately.** `merge=union` is a per-path assertion a human
made once and nothing rechecks; this is a per-tick **measurement**. It also cannot hit union's
documented duplicate-row hazard (`.gitattributes` stated limit 3) — appending nothing duplicates
nothing.

**What it refuses**, which is what keeps the backpressure typed: if main holds one line the lane
does not, the test is false and the tick fails exactly as today with git's own message. Measured
live on the same refs — `data/ci-runs.jsonl` is main=539 lane=516 and is **not** a prefix, because
all three lanes append to it. This rule refuses it and leaves it to its declared driver. That
split is the design, not a gap.

**Fallback-only.** Every carry that succeeds today never reaches the new code, so the healthy path
is unchanged. It runs only where the tick is already dead.

## The falsifier

`prepare-heartbeat-branch.test.ts`, describe `squash-flush divergence`:

- the wedge is **reproduced first**, asserting `CONFLICT (add/add)` from the same git command the
  preparer runs — so the passing tests are provably not vacuous
- the carry is asserted **on the bytes**: flushed rows survive, the unflushed row arrives, no
  duplicates, no conflict markers
- the loop-break is asserted on the merge base **moving** and the next tick being clean
- four refusal controls: a rival line on main, a mid-line prefix, binary, and all-or-nothing
  (one refused path leaves the index untouched)

**Mutation-checked rather than assumed:** removing the fallback fails exactly the two positive
tests and leaves all refusal controls green. 29 tests pass on this branch.
