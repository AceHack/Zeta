## Description

Aaron asked whether the 78 remote branches can be reduced by **pigeonhole categorisation**, with a mandatory **UNKNOWN** bin and **forward actions** where a branch carries new information.

The answer is that they mostly cannot, and the reasons are measurable.

## The test that does not work

`git diff origin/main...<branch>` being empty is the obvious landed-test, and it is **wrong in the direction that costs work**. The three-dot form diffs from the **merge-base**; this repo squash-merges, so a squash-merged branch keeps its full diff forever and reads as unlanded every time.

Measured across 40 recently-merged refs: **40 unlanded / 0 landed**, including three branches watched merging that same night. A 100% false-positive rate.

## What is used instead

The **PR record is primary** — it is the branch's own self-claim, which is exactly what `pigeonhole-by-self-claim-never-by-assumption` asks us to read. Two corroborating content tests carry an **enforced asymmetry**: an empty touched-path diff proves landing; a non-empty one proves **nothing** (`main` may have moved past those files) and can never downgrade a branch on its own. `git cherry` patch-equivalence catches commits re-landed under another ref — **full** equivalence is landing, **partial** is reported rather than rounded up.

Both controls were run on the PR query before trusting it: a known-merged branch returns `#15696 MERGED`, a nonexistent branch returns `0`.

## What the evidence says

**Six** work refs are cleanly landed and deletable, each SHA recorded so any deletion reverses with `git push origin <sha>:refs/heads/<name>`. **Nothing is deleted here** — the bulk decision is Aaron's.

Three of those six had their PR **closed unmerged** and the content reached `main` anyway. PR state alone would have kept them; read the other way it would have deleted work that is genuinely unlanded.

**26 `heartbeat/*` refs cannot be deleted at all** — ruleset 16934633 carries a `deletion` rule with an **empty `bypass_actors` list**. Nor should they be: the `heartbeat/<lane>` + `<lane>-buffer` pairs are a reusable two-ref staging design that mints nothing per flush, which is why they hold at ~2 refs each while the lane they replaced reached **1,290**. Those refs are the *fix* for branch proliferation, not an instance of it.

## UNKNOWN = 1, and that is the success signal

`liveness/observations` has **no merge base** with `main` — ancestry and content tests are not merely inconclusive, they are *undefined*. An empty UNKNOWN would mean the classifier force-fit something, and a force-fit here is a deleted branch.

## Forward actions, not dismissal

Highest-value finding: **`derivation-{a,b,c}/threshold-sig-verify`** — a clean-room N-version experiment (N=3, independent derivations, 14–15 spec ambiguities each) with **no report doc in `main`**. Those three branches are the only copy; deleting them collapses an N-version experiment, which is what the raw-vault discipline forbids (*both branches held, each with its path recorded*).

Also named: `agent-heartbeats` at **689 unique commits**; `otto/telemetry-zetaid-shards` partially re-landed 1-of-3; and a per-day claim lane minting a ref per tick that wants the same staging fix `heartbeat/*` already uses.

## Separately: 15,602 stale remote-tracking refs

Pointers, not branches — **pruning deletes no objects**. 65 recent stale refs sampled, **zero carry unlanded content**; the two with no PR were local shorthand for work that landed under a different ref. A stale local view is itself a defect that has been producing false negatives.

## Falsifiers

`report-branch-pigeonholes.test.ts` — 19 tests, written so they fail if the classifier is made **more confident than its evidence supports**: partial patch-equivalence must not read as landed, `0/0` must not vacuously pass as full equivalence, a non-empty content diff must never downgrade on its own, and a deletion-protected ref must never be handed a delete action.
