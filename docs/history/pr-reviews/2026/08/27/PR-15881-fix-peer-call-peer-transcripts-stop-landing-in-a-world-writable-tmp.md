## Description

CodeQL `js/insecure-temporary-file`, and it is right. Four files carried an
identical copy of

    return `/tmp/peer-call-output/${ts}-${entity}.md`;

and `summon.ts` inlined a fifth. Three defects, in descending order of weight:

  1. `/tmp` IS WORLD-WRITABLE AND SHARED. `mkdirSync(..., { recursive: true })`
     creates `peer-call-output` under the process umask — typically 0755 — so any
     local user can read every transcript in it. These hold peer-model
     conversations. Worse, whoever creates the directory FIRST owns it and picks
     its mode, and a symlink planted at a predictable name redirects the write.
  2. THE NAME IS FULLY PREDICTABLE — second-resolution timestamp plus a known
     entity. Guessing it is not work.
  3. `/tmp` IS HARDCODED, which is wrong off Unix and ignores a TMPDIR the user
     deliberately set.

THE FIX IS THE DIRECTORY, NOT THE FILENAME. `mkdtemp` per call would defeat the
reason the fixed name exists — a shell contract and five callers grep for it —
and would leave a world-readable directory behind anyway. Creating it 0700
removes the exposure at the root: once only the owner can traverse it, a
predictable name inside is not a weakness and a symlink cannot be planted.

`mode` ON `mkdirSync` IS NOT ENOUGH, which is the part worth reading. It is
masked by the umask and IGNORED OUTRIGHT when the directory already exists —
which it does, from every previous run of the version that made it 0755. So the
mode is set with an explicit `chmod` and then READ BACK. A permission requested
and never verified is the vacuity class wearing a security hat, and the test that
matters is the one with a pre-existing 0755 directory, not the fresh-mkdir case.

`PEER_CALL_OUTPUT_DIR` is now honoured by all ten callers; five already did and
five did not, so the same setting meant two different things depending on which
entity you called. An operator-chosen directory is used verbatim and its mode is
LEFT ALONE — hardening a directory someone else named would be this code
exceeding its instruction.

TWO DEFECTS OF MY OWN, both caught by the tests rather than by review:

  * The function took an `env` parameter, used it for the override, and read the
    temp ROOT from ambient `process.env` via `tmpdir()` — an ambient read wearing
    an injected-dependency's clothes, and a §13 noninterference violation. The
    root now comes from the supplied env, with `tmpdir()` as the fallback.
  * The "no hardcoded /tmp" assertion matched the whole file and convicted the
    docstring that quotes the old line while explaining it. A check that fires on
    its own explanation measures the wrong thing; it matches code only now, and
    separately requires the prose to keep naming it.

10 new tests, 76 pass across peer-call, tsc clean. Remaining oxlint warnings in
this directory are pre-existing and untouched.
