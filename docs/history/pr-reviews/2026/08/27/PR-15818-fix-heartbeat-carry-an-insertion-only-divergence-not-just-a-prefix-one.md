## Description

## The measured answer: (1) — the fallback was reached and correctly refused

The task framed this as an add/add recurrence on `db/mutation-findings/alexa.jsonl`. The full
annotation says otherwise; the excerpt was truncated at the first two lines, both of which are
*successes*:

```
carry unflushed heartbeat state failed: Auto-merging data/ci-runs.jsonl
Auto-merging db/mutation-findings/alexa.jsonl
Auto-merging docs/room-evidence/index.json
CONFLICT (content): Merge conflict in docs/room-evidence/index.json
```

`Auto-merging` is git reporting a path it **resolved**. The conflicting path is
`docs/room-evidence/index.json`, and it is a three-stage **content** conflict, not add/add.

Reproduced byte-identically before changing anything, by pushing `origin/main` and
`origin/heartbeat/alexa` into a scratch bare origin and running the shipped preparer: same
annotation, same exit code.

Then measured the conflicted index directly:

| stage | bytes | content |
|---|---|---|
| 1 (base `8a39a30`) | 73 | `entries: []` |
| 2 (main) | 333 | `[59e83513…]` |
| 3 (lane) | 591 | `[11d5cf2c…, 59e83513…]` |

`#15734`'s fallback ran, listed the path, read both stages, and returned false — **correctly**.
`isWholeLinePrefix` requires main's bytes to be a prefix of the lane's; these diverge at byte 60,
inside the first `eventId`. So the fallback is working as designed and the gap is that the
prefix rule does not describe this file's shape.

**Why:** the index is not a log. `canonicalIndex` in `durable-room-evidence-live-feed.ts`
re-serialises the *whole entry set* sorted by `eventId` on every publish, so a new low-sorting
entry lands **in front of** what main holds. Nothing is lost — the diff is pure insertion — but
it is never a prefix.

## Why `ci-runs.jsonl` auto-merged while #15734 refuses it

The two mechanisms are **in series, not in competition**. `.gitattributes` declares
`data/ci-runs.jsonl merge=union`, so git's union driver resolves it during the merge and it is
never left unmerged. `healPrefixOnlyConflicts` only ever sees `--diff-filter=U` paths — the
residue after every declared driver has run. #15734's docstring is right that ci-runs is not a
prefix (main 539 rows, lane 516, all three lanes append); it simply never reaches the code that
would refuse it. No contradiction.

## The fix: widen the rule from PREFIX to INSERTION-ONLY

Take the lane's copy iff main's lines embed in the lane's as a **subsequence** — equivalently,
iff the diff between the two sides is pure `+`. This is the losslessness condition stated at the
level it actually holds:

- **prefix is the special case** where the insertions all land at the end, so nothing the old
  rule accepted is now refused;
- **it reaches the sorted-set shape** the old rule could not, without knowing anything about JSON
  or about this schema — the rule stays indifferent to serialisation;
- **the refusal is unchanged in kind**: a line main holds that is absent, rewritten, or reordered
  breaks the embedding and still kills the tick with git's own message.

Verified end to end against the live refs — the carry resolves, the index parses, both entries
survive, and after the lane pushes, the merge base advances `8a39a30 -> f9a1c35`, so the next
tick is an ordinary clean carry with no heal notice.

## There is no ninth `.gitattributes` line, and the reason is measured

Six union scenarios run against a scratch repo with `merge=union` declared on the index:

| base | main | lane | merge rc | result |
|---|---|---|---|---|
| `[]` | `[HIGH]` | `[LOW,HIGH]` | 0 | valid JSON, no duplicate — **the live case** |
| `[]` | `[LOW]` | `[LOW,HIGH]` | 0 | valid JSON, no duplicate |
| `[]` | `[a,c]` | `[a,b,c]` | 0 | valid JSON, no duplicate |
| `[]` | `[b]` | `[a,b,c]` | 0 | valid JSON, no duplicate |
| `[]` | `[a,z]` | `[a,b]` | 0 | **INVALID JSON** |
| `[a]` | `[a,c]` | `[a,b]` | 0 | **INVALID JSON** |

I had first written that union would produce invalid JSON here and then measured it; the first
four rows falsified that, and the last two are the real argument. Union does the right thing on
every **lossless** case — which is exactly why a ninth line would be written, tested, seen to
work, and landed — and corrupts the **divergent** case *silently, with exit code 0*. Nothing in
the tick re-reads the index, so the first reader would be a browser. A green tick publishing an
unparseable index is worse than the wedge it cleared.

That measurement is now three tests, one of which fails if the line is ever added.

## Two guards were unfalsifiable; both fixed rather than left standing

Mutation surfaced them:

- the `ours` ends-with-newline guard **killed no test** once `terminatedLines` carried the
  newline inside each token (an unterminated fragment can only match an unterminated fragment).
  Removed; the property it asserted is pinned at the unit level instead, where a tokeniser
  off-by-one *does* kill a test.
- the existing binary test **passed with the NUL refusal deleted** — its pair was refused by the
  line comparison alone. Strengthened with `a\0\n` vs `a\0\nb\n`, which embeds as a line
  subsequence and is refused only by the NUL check.

## Is the loop structurally closed?

**For the insertion-only class, yes** — and that class is now defined by a per-tick measurement
rather than by a serialisation. Any file where the lane's copy differs from main's by insertions
alone now carries, whatever its format, with no declaration needed. #15734's author warned the
loop would "re-arm on the next undeclared append-only path"; the widening removes the
append-only qualifier.

**What is still open, stated plainly:** files where main *legitimately* holds content this lane
never had — the genuine multi-writer case. `data/ci-runs.jsonl` is that case, and the
measurement correctly refuses it rather than dropping rows. Those still need a declared driver,
and picking one is a per-path judgement about serialisation that no measurement can make. If a
tenth path appears and it is genuinely multi-writer, a `.gitattributes` line remains the right
answer for it — but only after checking, as above, what that driver does on the divergent case.
