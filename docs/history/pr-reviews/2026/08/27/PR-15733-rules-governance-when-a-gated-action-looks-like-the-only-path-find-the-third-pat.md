## What

Carves a governance rule from the PR #15691 process miss: `gated-action-find-the-third-path.md`.

When a signature block on #15691 carried two false credential fields, the correction was right but the path was wrong in two ways Otto named:

1. **Cited a peer as authorization for a gated action.** Otto asked for the correction; force-push is a gated class only the maintainer authorizes. Source is not authorization (`no-directives.md`).
2. **Framed a false dilemma.** force-push vs. append-and-launder — when a third sanctioned path existed: close the PR and re-branch. Fix-forward doesn't clear a false block from the squash preimage; close-and-rebranch does, at the cost of a PR number and nothing else.

The rule records the mechanical move: halt at the gate, enumerate ungated alternatives before concluding there are none, and if none exist, name the need and stop. It also notes the substrate gap (`non_fast_forward` is scoped to `~DEFAULT_BRANCH` only, so feature branches have no ruleset-level force-push protection) — the agent is the guard where the substrate has none.
