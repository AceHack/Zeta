## Description

Aaron 2026-08-27: *"similar to our fixed point registry except it's an oscillation registry where you
can tell if two rules will oscillate or override each other."*

## Why a registry and not a disjointness assertion

I proposed the assertion first and it was **wrong**. Overlap isn't illegal — two healers may
legitimately write the same file, and a templated rule family shares a write-set *by construction*
(the five `*-parity` detectors are one rule five times). A disjointness check would refuse exactly
the collapse we want.

| relation | meaning | verdict |
|---|---|---|
| `disjoint` | write-sets don't intersect | commutes **structurally** |
| `commutes` | overlap, orders agree anyway | fine, but a weaker guarantee — holds for these inputs, not by construction |
| `override` | orders disagree, both settle | **legal once declared** with a reason |
| `oscillate` | composite never reaches a fixed point | **always a defect**; no declaration can launder it |

**Composability becomes a number.** Override edges induce a priority DAG; its height is the measure.
Height 1 = antichain = the roster is a *set*, not a sequence. Measured on Tier-0 today: **10 pairs,
all disjoint, height 1** — which independently reproduces the hand measurement that motivated this.

## What the harness doesn't cover

`healer-harness` certifies idempotence, closure and convergence of the **composite**, in the one
order `composeHealers` folds. That proves it reaches *a* fixed point, never *the* fixed point — so a
hardcoded order can be silently load-bearing. 120 orders exist for the five Tier-0 healers; exactly
one is certified.

## My tests caught two real bugs in my own implementation

1. **Convergence was checked only when the one-step composites disagreed.** But `advance` (x→y,
   y→z) with `reset` (z→x) gives the *same* value in both orders at step one and still cycles
   x,y,x,y forever. A pair can oscillate while looking perfectly commutative — the worst version,
   because it passes the cheap check.
2. **Cycle detection was inverted** — revisiting a seen state returned "converged". x→y→x revisits
   x, so the one relation this module exists to detect was undetectable.

My first oscillation *fixture* was wrong too, and fixing it corrected my model: wrapper/unwrapper
does **not** oscillate — the composite hits a fixed point on the first step, so order changes the
*result*, making it an `override`. A genuine cycle needs ≥3 states. Both cases are now pinned.

## Vacuity is reported, not passed

A pair that fired on nothing has a verdict that means nothing. Measured live: the three built-in
fixtures fire **none** of the Tier-0 healers, so a registry built from them alone would report
`disjoint` for every pair and constrain nothing. Reported — and deliberately not a failure, because
missing evidence is a different thing from a defect.

## Scope

Additive; `healer-harness.ts` is untouched since other agents depend on it. **Not wired into CI** —
that's a change to the certification path and is your call.
