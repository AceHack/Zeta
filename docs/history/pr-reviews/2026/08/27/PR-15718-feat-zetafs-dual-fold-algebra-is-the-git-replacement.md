## Summary

Aaron: DBSP Z-sets run dual folds — forward in time `+1` (`I`) and `-1`
folds from generator-function updates that reinterpret the past. That is
the foundation of ZetaDB/FS once we replace git (including LibGit2) with
our own storage. It ties to DagFs and Merkle trees.

This names that contract and pins it. It does not pretend LibGit2 is
already gone.

- `ZetaFsDualFold.foldForward` / `foldLog` = DBSP `I`
- `retract` = unary minus, appended later (log stays append-only)
- `reinterpret` = `-gen(before, H) + gen(after, H)` as a **new** delta
- `snapshot` = `ZSetMerkle.root` of the net Z-set (`+w` then `-w` is a no-op)
- `applyPresence` = Distinct-shaped DagFs `link`/`unlink` (`editLocal` default)

Tests pin ping-return, generator reread without rewriting history,
Seq-ordered foldLog, and a rename that keeps a shared Merkle node.

ROADMAP item 1 now states the destination is this algebra, not
LibGit2Sharp forever. `GitDeltaLog` remains the hexagonal v1 adapter.
