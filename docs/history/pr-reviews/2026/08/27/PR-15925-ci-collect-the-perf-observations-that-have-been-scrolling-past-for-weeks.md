## Description

`PerfObservation.emit` (F#) has printed a `##perf-obs` line on every perf assertion since it landed.
`perf-regression-ledger.ts` folds them into a regression-vs-flake verdict. Both halves tested, both
green — and **nothing ever read the lines.**

The denominator existed in principle and nowhere in fact. Same shape as a check that cannot fail,
which is the thing I've been naming all session while leaving this one alone. Fourth instance,
closing it.

## The dangerous part

Bash's exit status for a pipeline is the **last** command's, so `dotnet test | tee` returns tee's
`0` and **masks every test failure**. GitHub's default shell is `bash -e`, which does *not* set
pipefail. Demonstrated rather than asserted:

```
bash -e -c 'false | tee x'                  -> exit 0   failure MASKED
bash -e -c 'set -o pipefail; false | tee x' -> exit 1   propagates
bash -e -c 'set -o pipefail; true  | tee x' -> exit 0   success intact
```

That step's outcome is read by a later reporter via `steps.test.outcome`, so it had to fail exactly
when `dotnet test` fails and at no other time.

## Design

- **Never fails the build** (exit 0). The perf assertions already decide pass/fail; a measurement
  that can break a test run is worse than no measurement.
- **Never silent about silence.** `renderPerfLedger` already refuses to call an empty ledger clean —
  that refusal is what makes running it non-fatally safe.
- **`if: always()`** — a *failing* run is when the ledger is most worth reading. A perf miss is
  exactly what it exists to classify; skipping on failure would hide the observations that matter
  most.

## Tests pin the seam, not the halves

- observations buried in realistic MSBuild noise are found
- **empty output does not render clean**
- malformed sentinel lines are **counted, not dropped** — a half-broken emitter must appear as a
  number, not as quiet
- a control pair pins `clean` vs `regression`, so a collector that always reported one register fails
