## The ask

Aaron, 2026-08-26:

> *"heartbeats themselves go through a PR today because we don't have our decentralized git setup yet and rely on GitHub centralized control. For observations about liveness on top of heartbeats — the liveness observations about heartbeats never ever need PRs to get to main. We need to make this happen."*

Two layers. **Only the second is touched.**

| layer | disposition |
|---|---|
| heartbeat **ticks** | land on `heartbeat/*`, flush to `main` via PR. A centralized-GitHub concession. **Unchanged.** |
| liveness **observations** about those ticks | were durable only as a check-run annotation. **Now a direct-pushed git ledger.** |

## The defect, and why it is not aesthetic

**The observer must not depend on the observed.** An observation routed through the PR pipeline cannot report when the PR pipeline is broken. Same family as three things measured the same night: a retry loop probing over the transport it was saturating; a failure reporter that ran `bun` when the failing step was the one installing `bun`; a watchdog that went silent at the same second as its subject.

The annotation channel had a quieter version of the same defect: an annotation is written **only when the verdict is bad**, and **only inside the substrate under observation**. So it could not distinguish **"healthy"** from **"not observing"** — both look like no annotation. That is the vacuity class.

## Ground truth (verified against the live API, 2026-08-27, not re-derived from memory)

| ruleset | target | rules | bypass |
|---|---|---|---|
| `CI Gate` | `~DEFAULT_BRANCH` | `required_status_checks` | `RepositoryRole 5`, `bypass_mode: pull_request` |
| `Branch Safety` | `~DEFAULT_BRANCH` | `deletion`, `non_fast_forward` | none |
| `Heartbeat Branch Protection` | `refs/heads/heartbeat/*` | `deletion` | none |

Nothing pushes to `main` without a PR — not even an admin. `conditions` offers `ref_name` alone, so **there is no path-scoped carve-out**. Non-`main` refs carry no push rule.

## What shipped — option 1 of three

A dedicated `liveness/observations` orphan ref, direct push. **No bypass actor, no ruleset change, no new credential, no new trust.** It is the mechanism `heartbeat/*` already uses, pointed at the observation layer.

The cost is that the bytes are not literally on `main`, so the question gets answered rather than dodged: **what does `main` actually buy?** Exactly one thing — presence in the default fetch refspec, hence discoverability without a reader instruction. Everything else people mean by "on main" (durable, in git, no PR, readable from a clone, diffable, replayable) is a property of **being a git ref**. That one thing is recovered the way this repo already recovers it for `heartbeat/*`: a fetch line in `CLAUDE.md`.

Four properties, each a requirement:

- **Every run records, including the healthy one.** This is what makes *"is anyone still observing?"* answerable — the question an annotation cannot answer. `liveness-ledger.ts read` returns the age of the newest record; a gap in the stream **is** the finding.
- **A blind observer records its blindness.** Inputs unreadable ⇒ `outcome: "blind"` with the reason. It never goes quiet, because going quiet is the bug.
- **Four outcomes, not two** (`alive` / `degraded` / `not-alive` / `blind`). `assessFleetLiveness` returns `alive: true` the moment *one* source is fresh — right for the alarm, but it flattens a fleet on its last source into the same bit as a healthy one.
- **Fails loudly rather than succeeding quietly.** Empty stage ⇒ error (the recorder just wrote a fresh `observedAt`; nothing staged means the write did not land — the false-green shape this subsystem exists to stop believing). Denied credential ⇒ reported on the first attempt, never retried into a slow silence. Only a lost race retries, and only after re-syncing onto the winner's tip.

## What I did NOT do, and what needs you

**A bypass actor is the only mechanism that puts the bytes literally on `main` without a PR.** If that is what you meant, there is no third way — and the cost is real:

> GitHub's bypass is **per-actor, never per-path**. Granting one produces a credential that can push **anything** to `main`, at any time, with the "it only writes `observations/`" discipline living **in the pusher's own source code rather than in the guard**. That inverts the trust model `gate` exists to provide, and it creates a standing high-value secret in a workflow that runs unattended every 15 minutes.

Named, not granted: *a fine-grained PAT or App installation in `CI Gate`'s `bypass_actors` with `bypass_mode: always`.* **Your call, not an agent's.** My read is that the ref is the right answer — the recursion you objected to is gone either way, which suggests the ref, not `main`, was the actual requirement.

Also named, not made: **`liveness/*` has no `deletion` rule** (its `heartbeat/*` sibling does), so the ledger ref is currently deletable. That is a ruleset change.

## One permission did change, and here is exactly what it can reach

`heartbeat-liveness.yml`'s `permissions:` went `contents: read` → `contents: write`. That is the workflow's **own scoped `GITHUB_TOKEN`** — the same grant `agent-heartbeat.yml` already holds — used for one command: `git push origin HEAD:liveness/observations`. It **provably cannot reach `main`**, and that is a property of the rulesets above rather than of this workflow's good behaviour: `GITHUB_TOKEN` is not `RepositoryRole 5`, and even that actor cannot push to `main` without a PR.

## The honest limit

This writer runs inside GitHub Actions, so a run dying before `Setup bun` writes nothing, and a total Actions outage stops the writing along with the ticking. **Nothing hosted inside Actions can fix that**, and the workflow comment and decision record both say so. What the ledger changes is that such a gap becomes **readable** — because the healthy case is written too, a reader with a clone gets a straight answer with no call to the provider whose health is in question.
