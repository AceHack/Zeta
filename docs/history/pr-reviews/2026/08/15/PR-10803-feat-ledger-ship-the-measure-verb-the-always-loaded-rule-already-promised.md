## Correction to the brief: the mechanism half-exists, and that is worth stating precisely

Outcome 1 was worth checking hardest, and it returned a real but non-rescuing result:

- **ΔU as a value is genuinely shipped**, in three unrelated places: `src/Core/Finalizer.fs` (`TickResult.DeltaU`, a per-tick metric), `src/Core/ComputeReceipt.fs` (`DeltaU = IV − ΔJ`, Landauer accounting), `src/Core/SocietyUsefulWork.fs` (the ΔU aggregation theorem, workitem `081KV6B1MBM08QG0R000RZK4WY`). All real, all tested.
- **None of it is keyed to a bug-fix, and none of it touches the ledger.** `git grep` for `db/uncertainty` or `db/sims` across `src/`, `tests/`, `scripts/`, `.github/` returns **zero** hits — no writer, no reader, in any language. `grep -rlE "deltaU|DeltaU|ΔU" src/Core.TypeScript/` returns nothing at all.
- **`mea` existed only as an unwired stub.** `clis/Verbs.fs` declares `IMeaVerb.Mea : IEffects * ISim<'a> -> IMeasurement` where `IMeasurement = interface end`, under a header that says so itself: *"STUB: not yet wired into a project."*
- The ledger's single entry was **hand-authored**, not produced by anything.

So it is **outcome 2 + outcome 3**: the rule was aspirational and said so nowhere, and the honest close is to both label it and build the small thing.

## Second correction: the price is ORDINAL, not cardinal

The brief said an invented ΔU is worse than an empty ledger. Agreed, and pushed further: **the tool gives you no field in which to invent one.** An entry records a ΔU *sign* (`ΔU > 0` / `< 0` / `≈ 0`) plus a *witness*. Nothing in the repo meters a bug-fix in units, so a cardinal price would be `toy` asserted as `metered` (`toy-is-free-metered-must-be-earned.md`) — and since this ledger exists to *price* work, a fabricated price corrupts the only thing it is for. This also matches the schema the pre-existing hand-authored entry already used. A cardinal ΔU must be **earned** later.

## Idempotency, tested on real data (`dv2` §6)

Re-running the identical measure against the live ledger:

```text
measure: unchanged db/uncertainty/081KZZZH24H087G0R002TXQA15-...md
exit=0  entries: 5 -> 5  content: BYTE-IDENTICAL
```

The key is the ZetaId, not the slug, so a **retitled** re-measure upserts rather than forking a twin, and a **legacy short-form** entry (`081KWG9JQ9H-…` for `081KWG9JQ9H08QG0R0024EMETG`) is matched by prefix — both covered by tests.
