## Description

## The number first

The byte-lock is the repo's central cross-language verification mechanism — the claim that
N independent implementations agree byte-for-byte. The roster lists **nine** substrates.

**Seven were actually comparing vectors.** The last CI run before this change
([31326468275](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/31326468275),
2026-08-09, `push` to main) reported:

```
Summary: 7 PASS, 1 FAIL, 1 TOOLING-ABSENT, 0 SKIP
Byte-lock DIVERGED — 1 of 8 executed substrate(s) disagree (drift signal, not a gate).
```

Roster 9, stated denominator 8, real coverage 7. The job concluded `success` on all eight
of its historical runs. Nothing anywhere said so.

**Correction to the brief:** #10744 is **open, not merged**, so its per-substrate floor is
not on `main` — the only floor there is `executed >= 2`. Second correction: the Zig failure
is not *silent*. It prints `FAIL Zig … expected magic word …` on every run. It is
**loud and non-fatal**, because a load error arrives through the same channel as a byte
divergence and divergence is deliberately not a gate here. That distinction matters: the
defect is not that nobody could see it, it is that **the runner had no way to say
"this instrument is broken" as opposed to "these two disagree"**.

## Two more of the same shape, found while verifying the first two

**3. Every script substrate could fail in complete silence.** The run-error classifier
matched the literal string `"Command failed"` — which `execSync` prefixes onto *every*
non-zero exit — so a substrate that launched, ran, and crashed was reported as
"toolchain absent — NOT a divergence". Reproduced on `main`: `dla-canonical-source.js`
replaced with a script that writes to stderr and exits 7 gave

```
  TOOL  JS (V8)              seed=1  (toolchain absent — NOT a divergence)
Summary: 7 PASS, 0 FAIL, 2 TOOLING-ABSENT, 0 SKIP     exit=0
```

with node plainly installed, since node was running the runner. This applies to JS, Lua
and Go — including the substrates that currently pass.

**4. The negative controls had never run.** `test-fault-injection.mjs` — the suite that
proves this byte-lock can detect a fault at all — is referenced by **no workflow**
(`grep -rn "test-fault-injection"` matches only the file itself). A negative-control suite
that never executes is the identical defect one level up.

## Restore, not remove — and why that was the honest option here

Removal is a legitimate outcome and an honestly smaller N beats a padded one. It was not
the right call, because **both toolchains are already pinned in this repo's own
`.mise.toml`** (`go = "1.26.4"`, `zig = "0.13.0"`), whose comment even documents the
correct Zig command — `zig build-exe -target wasm32-freestanding`. The substrates were not
unbuildable; the build was wrong.

Both were rebuilt and both **agree with the reference at all four CI seeds**.

**Zig — restored and committed (1,314 bytes).** Built single-step with
`zig build-exe -fno-entry`; Zig ships its own linker, so no `wasm-ld` and no `ar`. The old
two-step `build-lib` route is deleted from `build-substrates.mjs`: its intermediate shared
a *name* with its output, which is how the archive got committed. `build.zig` (which used
`addSharedLibrary`, the same wrong route, and does not link on the maintainer's machine) is
removed along with the six tracked `.zig-cache/` files it produced — including an **x86-64
ELF executable** sitting inside the verification directory. Rebuild is byte-identical
(`sha256 c28210dc…` before and after).

**Go — restored, but built in CI rather than committed.** The module is ~1.9 MB: 1,500× the
Zig one and 4× the largest binary already in the directory. `src/wasm-dla/bytelock/.gitignore`
already declares that compiled substrates are "built by CI/local toolchain, not stored in
repo", and building from the committed 3.8 KB `dla-canonical.go` keeps the reviewable input
**text**. Pinned to `go-version: 1.26.4` because the committed `wasm_exec.js` is the Go
runtime's own bridge and must match — a parity requirement, noted in the workflow.

## The guard that makes the Zig failure mode impossible to repeat

A new failure class, **`MALFORMED`, exit 3**: a substrate binary whose first eight bytes are
not `00 61 73 6d 01 00 00 00` is refused at load, reported by name, **excluded from
`executed`**, and stops the run. Eight bytes rather than four, so a wrong binary-format
version is caught too.

Deliberately hard while divergence stays soft. That asymmetry is the point of this runner's
design: a divergence is a finding you want *delivered*; a broken instrument is a finding you
want *stopped*, because everything downstream of it is unearned.

This is not a novel invention — `src/Core.TypeScript/discovery/identity-dla-pages-wasm-assets.ts`
already header-checks every module on the **publishing** path. The verification path simply
lacked the check the publishing path had.

## Floor raised 2 → 9

The previous comment asked for exactly this: *"raise it as substrates become reliably
buildable in CI; never lower it silently."* Two was an aggregate over nine independent
instruments, so seven could go dark and still clear it — and two of them were dark. At
**9 the floor equals the roster**, which makes an aggregate floor per-route by exhaustion
with no list to keep in sync. Lowering it is now coupled to removing a substrate.

## Fault-injection suite: extended and, for the first time, executed

Phases 6 (malformed artefact, both directions) and 7 (a script substrate that ran and
crashed must be `FAIL`, not `TOOLING`) added, and the suite wired into `bytelock.yml`.

## On `no-binary-in-proof-lineage`

Stated honestly rather than stretched. The rule's subject is **verification artefacts** —
golden vectors, byte-locks, Merkle roots — which must be text. Here the golden vectors are
and remain `testdata/golden-seed-*.json`; the `.wasm` files are the **implementations under
test**, not the evidence, so they sit **outside** the rule as written and this change does
not claim otherwise.

The rule's *reason* landed on us anyway, and that is worth recording: an opaque committed
artefact was wrong for two weeks and **no `git diff` could ever have shown it**. That is
precisely the harm the rule exists to prevent, arriving through a door the rule does not
cover. It is the main argument for building Go rather than committing 1.9 MB, and it is why
the header check now runs at both the load and the emit end. A separate finding worth its
own decision, not made here: whether the five other committed `.wasm` substrates should
also become CI-built.

Swept the whole repo while here — all 12 tracked `.wasm` files now carry a valid header;
`dla-canonical-zig.wasm` was the only broken one.

## CI TRIGGER CONSTRAINT — a green PR is NOT evidence the byte-lock works

`bytelock.yml` fires on `push` to `main` under `src/wasm-dla/**`, so **it does not run on
this PR**. Every check that matters here runs **post-merge**. A reviewer must not read a
green PR as confirmation. What is and is not proven:

- **Proven locally, raw exit codes above:** both artefacts build and agree at seeds
  1/42/100/999; the malformed guard fires and clears in both directions; the classifier fix
  reclassifies a crashing substrate; the extended fault-injection suite passes here and
  fails against `main`.
- **Not provable before merge:** that `actions/setup-go@v7.0.0` provisions Go 1.26.4 on
  `ubuntu-24.04` and that the CI-built Go module agrees there. If it does not, the failure
  is loud by construction — the build step fails, or the floor of 9 exits 2 and names the
  substrate. That is the correct direction to fail, but it is the one claim resting on the
  first post-merge run rather than on evidence in this PR.
