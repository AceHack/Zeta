## Summary

Closes `081M010W1BP087G0R002M2BNVW`. `HeatSignature.isPressureKind` and `HeatSignal.ofKind` were two classifiers of the same bit. A kind carrying both a forgetting token and a pressure token (`forget-backpressure`, `prune-rejected`) read as pressure on one route and forgotten on the other. `TemperatureReadout.ofHeatSignature` takes the `ofKind` route, so it reported **zero pressure** — a cold room under genuine backpressure.

Both routes now read `HeatSignature.classifyKind`. Dual-token kinds are **pressure**: missing that signal is fail-dangerous. The order is the decision, not an accident of `if/elif` listing.

Live kinds (L7 corpus in `ShedDisposition.Property.Tests`) all carry one token class; none change.

- `classifyKind` is the single ordered classification
- `isPressureKind` and `ofKind` are both projections of it
- Falsifier walks the live corpus and the forget × pressure product (kinds built by concatenation so a kind-literal lint does not fire)
- `forget-backpressure` now reports `PressurePpm = MaxPpm`
