## Description

Supersedes #15996 (carries its two files unchanged, plus the design doc and the correction it prompted).

## The assumption being dropped

Spokes runs 3PC and Continuity needs an S3 compare-and-swap for the same reason: **one ref must advance atomically.** Everything expensive in those systems is downstream of it.

My Continuity analysis listed that as a requirement of *the problem*. Aaron's correction: it is a requirement of **Git having one ref**. A store whose tip is *reconstructed* by a commutative join over partitioned Z-sets is not obliged to pay for it — and that, not WAL-vs-DBSP, is the largest divergence. Corrected in that doc in this PR.

## The tip is a query result, not a stored pointer

Many partitioned Z-set tips; the logical tip is reconstructed by joining them with an Rx query that is **itself data** — Bonsai-serialized with dynamic values, so it ships and runs wherever the partitions are. A single global tip lock becomes N partition-level operations, most needing no lock because merge is commutative.

## Why order stops mattering

Two halves, defending different failures:

- **Bayesian uncertainty is stored, not adjudicated by arrival.** Conflicting evidence is *combined*, so nothing needs to be last.
- **ECC makes drift repairable** — a drifted partition is re-derived, not replayed in order.

### The precision our own code insists on

`BeliefConvergence.fs` states its own boundary, so the doc states the bounded claim rather than a blanket one:

| | |
|---|---|
| **commutes** | `observe` with *fixed* likelihoods — sharper than the usual claim; independence was merely *sufficient* |
| **does not commute** | state-dependent revision that reads the belief it updates (`sharpen` is the in-tree counterexample) |
| **not idempotent** | a commutative *monoid*, not a semilattice — commutativity buys freedom from ordering, **not** from duplicate delivery |

That survives contact with the counterexample already in the codebase, which a blanket claim would not.

## The consensus ladder — three deliberate cost tiers

| tier | mechanism | cost | when |
|---|---|---|---|
| **0** | commutative merge (Z-set/CRDT) | none | the large majority |
| **1** | CAS scoped to row/partition, **wrapped in a decentralized DU so the conditional is part of the operation's own type**, not a hidden retry loop | one conditional write | genuinely order-dependent state |
| **2** | BFT (`SybilBftProtocol`) | **slower than 3PC — adversarial, not crash, faults** | high-stakes governance / multi-oracle only |

No middle tier pays consensus cost for ordinary data: an operation either partitions, or it is important enough to be adversarially agreed.

## Names are views, not locations

The content-addressed DAG is irreducible; filesystems are *presentations* over it. No canonical folder tree; symlink-native and multi-parented, which is **tagging** with a tree as the degenerate one-tag case. This is what makes a partitioned tip coherent — if names were locations in one tree, you would need agreement on the tree.

## §2b — dissolving the non-commuting case (added; **not built**)

§2a ends at a real boundary: a state-dependent revision that *reads the belief it updates* does not commute, and `sharpen` is the in-tree counterexample. Aaron's answer doesn't make that operator commute — it can't — it **removes the read from the update path**.

A read-modify-write is non-commutative because the read is a **hidden input** taken at update time, so two updates see different worlds depending on order. Supplied instead as an explicit **amortized pre-read** (from reservoir computing, carried on the `observe.ts` snapshot DU), the update becomes a pure function of `(event, supplied belief)` — and pure functions of explicit inputs compose without ordering constraints. **An ordering problem becomes a data-dependency problem.**

`observe.ts` is already *"a pure function over a snapshot → an action DU"*, so the pre-read and its budget are one more typed field on that snapshot. No new architecture.

### Staleness becomes metered, not forbidden

Same conversion the rest of the design makes: an obligation requiring **coordination** ("read the latest") becomes one requiring **measurement** ("you may read this stale, and the repair is defined"). It extends the per-row CAP-posture result to a *per-read staleness budget carried in the type*.

**The bound is not arbitrary.** An ECC corrects up to a bounded number of errors; past its distance, divergence is not merely uncorrected but **undetectably wrong**. The budget must be *derived from* the correction capacity, not merely paired with it — one chosen for convenience reintroduces silent corruption in the one place the design promises repair.

### Why it must live in the DU, not a context window

> *"it should be in the DU that tracks this, not agent context windows — that's unreliable."*

A budget held in a context window is **unenforceable** (nothing checks it), **unobservable** (no artifact records what bound was in force), and **silently lost** (a compaction or handoff drops it and the next read proceeds as though it had been honoured). That is the vacuity class exactly — a constraint that looks like a guarantee and carries none.

The general form, worth stating on its own: **an invariant that lives in a context window is not an invariant.**

### What would make it real

- the budget *derived from* ECC correction capacity
- a falsifier that **exceeds** the budget and shows repair succeeding or failing **loudly** — a test that never exceeds it proves nothing, and a silent plausible answer over budget is the failure mode
- the pre-read wired through `observe.ts`'s snapshot, visible at the seam where actions are already chosen

## Status: designed, not built

Section 6 says so plainly. Neither the amortized pre-read (§2b) nor the partitioned-tip join exists. **No benchmark, no measured contention improvement.** The argument is from the algebra — commutative merge needs no agreement, so a tip built by commutative join needs no tip lock. Sound, and *not evidence*. The falsifier is a measured comparison against a single-tip baseline under concurrent writers.
