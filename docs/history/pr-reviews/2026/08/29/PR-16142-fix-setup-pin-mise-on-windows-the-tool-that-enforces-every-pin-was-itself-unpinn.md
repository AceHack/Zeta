## Description

## The failure

`build-and-test (windows-2025)` and `(windows-11-arm)` have been red on **every recent commit**, failing at `install.ps1:52`:

```
mise ERROR Failed to install npm:markdownlint-cli2@0.22.1: aube install failed
This is a supply-chain trust failure ... an earlier release had stronger trust evidence
mise Version: 2026.8.14 windows-x64
```

## Root cause

Only **one of three** platform installers pins mise:

| installer | mise acquisition |
|---|---|
| `tools/setup/linux.sh` | `MISE_PIN_VERSION="2026.6.12"` + **six SHA256 hashes** |
| `tools/setup/macos.sh` | `brew install mise` — **unpinned** |
| `tools/setup/install.ps1` | `scoop install mise` — **unpinned** |

`.mise.toml` declares `min_version = "2026.6.12"` and its comment says to keep it in sync for *"three-way parity"*. Reality: three platforms potentially running three different mise versions against one `.mise.toml` — and **mise 2026.8.14 enforces aube's supply-chain trust policy, which 2026.6.12 does not.** Windows was failing a check no other platform runs.

The sharp part: **the version manager is the thing that enforces every other pin.** An unpinned mise means the whole pinning story has an unpinned root.

## What this changes

Windows installs `mise@2026.6.12`, matching what the repo already declares everywhere else. **This does not weaken anything relative to the declared intent** — it makes reality match the declaration. Both installers now warn loudly on drift, because a silent mismatch is exactly what hid this.

Homebrew can't install an arbitrary old formula version, so macOS **warns** rather than claiming parity it cannot deliver.

## What this deliberately does NOT decide

Whether the fleet should move **up** to a mise that enforces the trust policy. That policy is real and was doing its job. Today it runs on exactly one platform — **the one that does not gate merges** — so the same supply-chain signal is unenforced where it would actually block.

Adopting it fleet-wide first needs the offending transitive dependency identified. **No `markdownlint-cli2` release carries npm attestations** (checked the registry — all versions are signature-only), so the regression is *below* it in the tree, and only `MISE_VERBOSE=1` will name it. Filed rather than silently resolved in either direction.
