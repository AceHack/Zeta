## Description

## What

Adds four **generated-ledger** subtrees under `db/` to the gate path-filter's docs-only allowlist:

```
db/mutation-findings/*  db/drift-dashboard/*  db/uncertainty/*  db/search-index/*
```

## Why

PR #16124 changed seven files, every one generated data (`data/ci-runs.jsonl`, `db/mutation-findings/alexa.jsonl`, `docs/observe-events/*.json`, `docs/room-evidence/**.json`) — and still ran a full .NET **Build + Test** on macOS, ubuntu-24.04 and ubuntu-24.04-arm: **6m29s + 12m32s + 5m41s ≈ 25 runner-minutes for a PR with no source code.** `Skipped (docs-only PR)` was itself skipped, so the lane looked healthy.

The allowlist covers `docs/ memory/ openspec/ .claude/ data/` but **not `db/`**, so one appended line falls through to the catch-all and sets `HAS_CODE=true`. Over the last 48h on `main`, `db/mutation-findings` was touched **32×** and `db/drift-dashboard` **8×** — nearly every heartbeat/telemetry flush.

## Correction to this PR's own first rationale

The initial commit justified the narrow list by claiming `db/` holds real source (`db/src/Core.Git/CredentialSource.fs` etc.). **That was verified by file extension, not by content, and it is wrong.** All six `db/` paths with a source extension are 3-line markdown placeholders:

```
# GitDeltaLog.fs/
**Carved sentence:** [A provisional carved sentence explaining what GitDeltaLog.fs is about]
```

They are in no `.fsproj`/`.csproj`/`.sln`/`tsconfig`, and no linter scans them. **`db/` holds 264 files and zero compiled source**, so a blanket `db/*` would in fact be safe today. Second commit records this rather than quietly amending it — checking a name instead of the thing is precisely the failure this repo's falsifier discipline exists to catch, and it turned up inside a change whose subject is a path classifier.

## Why the narrow list is kept anyway

Because that safety is an **accident of db/'s current contents**, not an invariant anyone enforces. Explicit prefixes mean a new sibling under `db/` does **not** inherit the exemption — it fails closed into a full build.

## This is a stopgap; the durable fix is structural

Per maintainer steer: `db/` should have a **clean code/data split** so this arm can be a single prefix instead of a growing list of special cases. Measurement supports it being cheap — `db/` is already 264 data files and 0 code; the only cleanup is renaming the six misnamed `.fs`/`.ts`/`.sh` stubs to `.md`. Not in this PR.
