## Description

## The defect, verified against the construction

`src/Core/AdinkraCode.fs` and `src/Core/BitAdinkra.fs` labelled the length-8 doubly-even self-dual
code **"N=4"**. That `4` is `k` — the code dimension, the 4 generator rows — read as `N`.

In the Doran–Faux–Gates–Hübsch–Iga–Landweber correspondence an adinkra with **N colours** (one edge
colour per supercharge `Q_I`) is the **N-cube quotiented by a doubly-even code of length N**. Length
is N. So this code is **N = 8, k = 4**.

**Which of the three possibilities it is:** the label is wrong and the code is right — *and* both
quantities are genuinely meaningful, so the fix is **disambiguation, not replacement**. Every
function in `AdinkraCode.fs` already used `length` and `dimension` correctly; there was simply no
name for the adinkra-side `N`, so `4` got captured by the letter. Both are now named.

**No computed value changes anywhere in the repo.**

## The invariants that force it — not the arithmetic

`numerology-vs-number-theory`: 28 and 6 are counts, and so is 16. The counts are not the argument.

***

**1. Existence.** A doubly-even self-dual binary code exists **only at length ≡ 0 (mod 8)** (Gleason;
Mallows–Sloane). Reading `N` as the dimension demands a doubly-even self-dual code of **length 4**,
and there is none — so the "N=4" reading names an empty set. It contradicts the existence theorem
the module stands on.

**2. Valence.** The quotient `GF(2)^8 / C` is **8-regular** — every node has 8 distinct neighbours,
one per colour — because `d = 4 ≥ 3` puts the eight weight-1 vectors in eight distinct cosets. The
new test **builds the quotient and measures** this rather than restating the constant.

## The repo already contradicted itself

`tests/Tests.FSharp/AdinkraIdentity.Tests.fs` searches lengths 2/4/6 exhaustively, asserts
`hasDoublyEvenSelfDual 4 = false` (*"none at N=4"*), finds the code at 8, and calls `AdinkraCode`
**"the fixed-N=8 module"** — while `AdinkraCode.fs` two directories away said "the canonical N=4
example". Both were in-tree, both green.

## Why it survived: a real coincidence, now named

This adinkra and the plain 4-cube adinkra of `AdinkraViz.fs` **both have 16 nodes** (`2^(8−4) = 2^4`).
Node count does **not** discriminate them. Valence does — 8-regular / 64 edges versus 4-regular /
32 edges. That coincidence is written into the docstring and into a test, so the two 16-node objects
cannot silently merge again.
