## Description

## The failure

`agencysignature (main tip)` is red on main at `63ebc56f7` — *"archive(pr-reviews): PR #11119 on merge -- run 31975289645"* — whose entire commit body is:

```
Archive PR. Auto-merge armed.
```

No trailer block at all.

## Root cause

`pr-archive-on-merge.yml` emits a complete, correct AgencySignature into the **PR body**, but composes the **commit message** without one.

These archive PRs carry exactly one commit and are auto-merged with squash, so GitHub builds the squash message from the commit. A block that lives only in the PR body never reaches main, and the main-tip audit fails on the merge commit.

This is verbatim the failure mode `.github/PULL_REQUEST_TEMPLATE.md` already documents from #11002:

> "Put the block in the COMMIT MESSAGE too, not only here."

The workflow's own comment even says these values are *"the same shape the red-state-flush workflow already emits on its commits"* — commits were the intent; only the body was wired.

## Fix

Append the identical block to the commit-message `printf`. Values unchanged from the PR-body block (they describe the workflow, not a human), so the two stay in step.

## Trailer-parse safety with untrusted PR_TITLE

The block must be the final paragraph, and nothing above it may **start** a line with `---` — `git interpret-trailers` reads that as the patch boundary and silently discards everything after it.

- The title is emitted as `PR title: %s`, so the line always begins with the literal label
- GitHub PR titles cannot contain newlines, so an embedded `---` line is unreachable

Verified by simulating the `printf` with a hostile title of `--- hostile ---` and piping to `git interpret-trailers --parse` — the exact parser the audit uses. **All 11 trailers parse.**

Note: this fixes the generator going forward. `63ebc56f7` itself is already on main and cannot be corrected without rewriting main history.
