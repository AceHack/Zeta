## Description

Three PRs stopped at the same missing decision, and two of them said explicitly it must be decided as one decision. This is that decision, applied to both schemas.

Decision record: `docs/research/2026-08-14-how-a-published-four-oracle-schema-acquires-a-field.md`.

## The finding that decided it — it is not only a key-set drift

`src/Core/DarkHallRoomTranscript.fs` **serialises** `zeta.temperature.readout.v1` (`[<JsonPropertyName>]` on `TranscriptTemperatureReadout`) and `src/Core.TypeScript/darkhall-ui/darkhall-room.ts` **parses it back** as `TemperatureReadout`, an unchecked cast. F# is a producer; TypeScript is a consumer. So `fidelity` was never a private field on a TypeScript type — it is a key on a wire contract with a live producer that never wrote it.

Measured against unmodified `main`, on the exact eight-key shape F# emits:

```
keys on the wire        : 8
fidelity declared type  : ChannelFidelity (required, non-optional)
fidelity at runtime     : undefined
reads as 'exact'?       : false
reads as NOT 'exact'?   : true
rendered into a string  : fidelity=undefined
```

**The type was false about its own wire format.** That is the same fault #10732 named one level down — an unwired fidelity channel *positively asserts* a faithfulness nothing measured — raised into the type system, where it is harder to see and easier to cite.

This does not refute the recorded position that "keep v1 unchanged" is weakest; it strengthens it. It was not merely *at risk* of breaking. It was already broken, silently, at the boundary.

## The decision

1. **A published `vN` acquires a new field ONLY as an optional key.** Checked anchors, not house convention: Avro *Schema Resolution* (a field with no default is an unresolvable difference) and Protocol Buffers *Updating A Message Type*. The compatible unit of schema growth is a field with a defined reading when absent.
2. **A required key, a type change, or a meaning change is `vN+1`** — all binding oracles move together, `vN`'s vectors are **kept** (they remain valid `vN` instances), `vN+1` gets its own. Versioning a compatible extension would couple the oracles' release schedules: a producer that cannot yet compute the field would *block the bump* (§1 scale-free, §2 lock-free).
3. **An optional key must declare its absent-reading, and absence must be conservative.** `reportedFidelity(x) === "exact"` **iff** `x === "exact"`; absence is `"unreported"`, a fifth token — never "fine". Without this clause, optionality is a dodge that reintroduces the original fault one level up.
4. **An optional key must be pinned by a vector**, because optionality trades key-set enforcement for value enforcement.

**Clause 4 was found by mutation, not by design, and it is the one I would have skipped.** With `fidelity` optional in TS, removing it from F# now exits `0` as *compatible* (M8). That is correct under clause 1 — but it means the key-set audit can no longer catch "this oracle quietly stopped reporting". The guard moved to the value byte-lock, which is the right place: an optional key carries no obligation to be *present* and a full obligation to be *correct when present*. Verified — M8b does not merely fail, it does not compile.

## (a) and (b) were not alternatives

They answer different questions — what the type may **assert** versus what the producer **computes**. Both were wrong, both are fixed, and no choice between them was needed.

- **TypeScript** — `fidelity?: ChannelFidelity`. The `?` is what makes the type *true*: valid `v1` instances without the key exist (every pre-today F# transcript, and the treaty's `temperatureCases`).
- **F#** — `TemperatureReadout` gains `Fidelity`, populated by new `TemperatureReadout.fidelityOfPpm`. **This is the half that was never a TypeScript encoder concern.** `max 0 |> min MaxPpm` discarded a negative and an above-ceiling input exactly as silently as the TypeScript clamp did, and nothing said so. Out-of-domain outranks saturated.
- **`v2`** — refuted under clause 2.

## `zeta.heat.receipt.v1` — the blocked fix lands

`heatReceiptFromRow` encoded through `heatReceiptPpm`, which computes the fidelity in `heatReceiptScale` and throws it away, so `heatRejected: NaN` and `heatRejected: 0` both rendered `heatPpm: 0` with no key on which they differed. It now encodes through `heatReceiptScale` and publishes **three optional keys, one per rail**.

**Three, not one folded verdict, deliberately.** A fold to the worst would be a fresh non-injective encoder — `(exact, exact, out-of-domain)` and an all-blind receipt would render identically — which is the defect class this lane exists to remove. **One fidelity per independently-encoded channel value.**
