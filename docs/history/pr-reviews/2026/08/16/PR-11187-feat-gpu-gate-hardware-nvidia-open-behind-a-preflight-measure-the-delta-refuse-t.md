## Description

# Summary

The item asked to switch GPU nodes to `hardware.nvidia.open = true`. **The flag was not flipped**, because no host in this repo has a known GPU — and the work-item's own bar says not to flip on nodes whose generation cannot be established. What ships instead is the measurement that makes the flip checkable, and the gate that makes it safe to make later.

All four GPU host configurations — `full-ai-cluster/nixos/hosts/{worker-gpu,worker-template}` and `infra/nixos/hosts/worker-gpu-0{1,2}` — carry a **PLACEHOLDER** `hardware-configuration.nix`, and every `zeta.io/gpu-model=…` node label in them is commented out. The open kernel modules require Turing or newer (they depend on the GSP, which Maxwell/Pascal/Volta lack), so flipping on unestablished silicon risks a node that cannot load its driver.

# The measured closure delta

At the pinned nixpkgs rev `b77b3de` (`nixos-25.11`), `nvidiaPackages.production` = **580.142** — step 1 of the item, confirmed `>= R560` and read out of the rev rather than asserted. The NixOS module makes exactly one substitution (`extraModulePackages = if open then [ nvidia_x11.open ] else [ nvidia_x11.bin ]`). Evaluated against this repo's own `gpu.nix`, both ways:

| `open` | package in `boot.extraModulePackages` | `meta.unfree` | license | cache.nixos.org |
|---|---|---|---|---|
| `false` (today) | `nvidia-x11-580.142-6.12.90` (`bin`) | **true** | `unfreeRedistributable` | **404** |
| `true` | `nvidia-open-6.12.90-580.142` | **false** | `GPL-2.0-or-later` + `MIT` | 200, NarSize **23,949,280 B** |

**The unfree package count in `boot.extraModulePackages` goes 1 → 0** — all of that surface — backed by **126,145,240 B** of `open-gpu-kernel-modules` source at tag `580.142`. A second gain: the closed output is not in the public cache at all, so the flip also moves the ring-0 artifact from vendor-blob-at-install to a hash-locked reproducible build.

**Bounded honestly.** The `nvidia-x11` `out` (userspace libGL/libnvidia-*) and the GSP firmware stay unfree and stay in the closure; GSP already loads today (`gsp.enable` defaults true for `>= 555`); `allowUnfreePredicate` is untouched. The binding moves, it does not disappear — as the item's "Not claimed" section says.

# The correction the roster forces

Addison's draft lists 19 NVIDIA cards, **all Ampere or newer** — nothing pre-Turing anywhere in the fleet, which is good news for this item. But it includes an **RTX 5090**, and Blackwell has **no proprietary kernel module at all**. On that node `open = false` is the broken setting, not the cautious one. The flag is wrong in both directions depending on hardware nobody recorded. The draft is also self-flagged unreliable, is being redone (`081M00R59KS087G0R001W3837V`), and maps cards to *the house*, never to *a node*.

# What shipped

- **`tools/nvidia-open-preflight.ts`** — run on a candidate node while the closed module is still loaded; gates on driver-reported CUDA compute capability **`>= 7.5`**. Capability rather than a PCI-ID table because NVIDIA device IDs are not ordered by architecture; **7.5 not 7** because Volta is 7.0/7.2 and has no GSP. `evaluateRoster` is pure and exported so the decision is testable with no GPU present.
- **`{full-ai-cluster,infra}/nixos/modules/nvidia-open-guard.nix`** — eval-time assertion refusing `open = true` without a recorded, evidenced preflight; plus a boot-time oneshot verifying every NVIDIA display-class PCI function has a driver bound (`vfio-pci` accepted as deliberate passthrough).
- Both `gpu.nix` keep `open = lib.mkDefault false`; the stale comment (silent on Blackwell) is replaced by the measured position.

# Shell retirement: rewritten, not allowlisted

First revision added `tools/nvidia-open-preflight.sh` and `lint (bash retirement inventory)` rejected it. **Rewritten in TypeScript rather than allowlisted**, decided on the fact rather than convenience: the allowlist's bar is *"runs before Bun is available"*, and this script does not qualify. `full-ai-cluster/usb-nixos-installer/zeta-install.sh` Step 6.95a runs `tools/setup/install.sh` on the pre-cloned repo, which routes NixOS to mise and provisions the `.mise.toml`-pinned bun for the `zeta` user; the preflight is an operator diagnostic run long after that. An allowlist entry would have carried a reason that is not true.

The one part that genuinely must run bun-free — the **boot-time driver-bound check** — is inline systemd shell inside `nvidia-open-guard.nix`, depends on nothing but coreutils, and is not a tracked `.sh`. That is the right side of the line.

`EXPECTED_RETAINED_SHELL` is **unmodified** and the guard's ordering test is not weakened: `retained_non_lean_shell: 32`, `expected_retained: 32`, `unexpected: 0`.
