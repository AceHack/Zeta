## Description

## What this is

Aaron's three approved changes to `agencysignature-block.ts` — the single-implementation module from #10922. All three, plus the measurement he needs to see because one of them **alters the recorded verdict on 30 landed commits**.

> Aaron 2026-08-16: *"yes this sounds good"* / *"any layout is fine with me, as long as we have the needed fields is what matters most."*

## Why now

PR bodies were failing for text **the author cannot control**: an IDE appends `Made with [Cursor](https://cursor.com)` below the body (Riven's PRs; Aaron's own #10949 hit it), and the forge re-emits `Co-authored-by:` after a blank line. This is the PR-body analogue of the forge finding — something downstream of the author mutates the payload. A gate that fires on correct work gets switched off, which is worse than no gate.

## The three changes

**1. Layout tolerance.** A complete block need not be the final paragraph; trailing text is legal. `RECOVERED-MALFORMED` is deleted — that shape is now `CORRECT`.

**Layout tolerance is not field tolerance.** The ten fields stay required, contiguity *inside* the block stays required, every value rule still applies. `missingRequiredKeys` is untouched, and a falsifier pins it.

**2. Last-block-wins.** `findSignatureBlock` returns the **last** complete block. This is the *same decision* as trailing tolerance, not a separate one: taglines append **after** the real block, quoted examples (a doc PR showing the template) appear **before** it. Once trailing text is legal, first-wins would let a quoted example outrank the signature of the PR quoting it.

**3. Disagreement is loud.** Several complete blocks making mutually exclusive **governance** claims is an explicit error, never a silent pick.

## The governance-field set, and why

The discriminator is **escalation** — `no-directives.md`'s line applied to a parser: inherit authority, never extend it.

| governance-critical | why |
|---|---|
| `Agency-Signature-Version` | schema discriminator; changes how all the rest is read |
| `Credential-Mode` | whether the credential implies a human at all |
| `Human-Review` | *the* accountability claim |
| `Human-Review-Evidence` | where that claim's evidence lives (spec §5.3) |
| `Action-Mode` | autonomous vs supervised vs human-directed |

| incidental | why |
|---|---|
| `Agent`, `Agent-Runtime`, `Agent-Model` | a multi-author squash honestly has several; misattributes, cannot escalate |
| `Task` | a squash spanning two work-items honestly has two |
| `Credential-Identity` | spec §7.5's Identity Demarcation Rule already forbids using an identity field as proof of human action, so it cannot escalate alone |

The live forcing case: **`c417b28c6357`** carries `Human-Review: none` in one block and `explicit` in another. Last-wins there would **record a human review that the other block denies**. That is why it errors instead.

## Honest limits

- **Cost of layout tolerance, stated not glossed:** `git log --pretty='%(trailers:key=...)'` is no longer a complete query over signed commits. Spec §3.5's queryable-verification property now belongs to `findSignatureBlock`, not git's trailer parser. The auditor still counts what git cannot parse so the size stays visible.
- The pre-merge validator no longer shells out to `git interpret-trailers` at all — dead once the canonical scan is the reader. Side benefit: one less forge dependency in the gate.
- This module is the single implementation behind both instruments, so a defect here breaks both at once. That is the payoff and the risk; it is why the parity test and the mutation table are the review surface I would look at hardest.
