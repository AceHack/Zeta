## Description

Survey-and-cost following PR #10675, which resolved the enforcement question in the negative as `INSTALL_TIME_VS_RUNTIME`. **No auto-merge armed** — this is a judgement call that wants a read.

## The answer: not yet, for a reason stronger than cost

Options 1–3 (macOS keychain ACL, LSM label, IMA/EVM) all fail for one shared and previously unnamed reason: **they bind to an executable, and this fleet has no per-cell executable identity to bind to.**

Measured, not argued. Every cell's launchd `ProgramArguments` is an unsigned `.sh` wrapper driving `bun`:

```
Authority=Developer ID Application: Jarred Sumner (7FRXF46ZSN)
```

One identity, four cells — plus everyone else who downloaded the same build. This is `INSTALL_TIME_VS_RUNTIME`'s *unmeasured interpreter* reason reappearing one layer down. It disqualified ace as an enforcer; it equally disqualifies the OS mechanisms proposed to replace ace. **The gap is not a missing mechanism, it is a missing identity, and buying a mechanism does not create one.**

## Four inherited claims that did not survive

| Claim | Finding |

| "No hardware isolation on this fleet" | Too broad. TDX/SEV-SNP/SGX absence **confirmed** — but those are confidential computing. **fTPM/PTT is present**, and `hardware-to-buy.md` already lists it as Tier 0 *owned*. Bounded by faulTPM (needs physical access, so does not bind our threat model) |
| `ace verify` | Still tautological on `origin/main` — no `verifySignature`, no re-hash. Left alone; `feat/ace-capability-manifest` claims to fix it |

## The measured baseline

```
$ security find-generic-password -s zeta-op-service-account -w
READ SUCCEEDED without prompt. secret length=852 (value redacted)
```

Current isolation is zero. Aaron's *"we might just have to trust agents not to read each others keys in the start"* is now a **measurement**, not an assumption. Also: no FROST shares exist on disk at all — the enforcement question currently protects one shared keychain token.

## The one "yes"

**Per-cell Unix users on Linux, scoped to cell-scoped resources only.** Needs no code identity, imports no third-party trust root, composes with SEV-SNP later instead of being replaced by it, and reaches the HSM credential better than any other option (a token is a device node; groups gate device nodes natively).

Its defect answers open question 5: `cell-id` is a **slot** that survives rotation, so uid-bound keys are inherited by the next occupant — failing the no-forced-upgrade test verbatim. Hence the blocking work-item.

VFIO is deferred on **architectural collision, not merit**: it reverses the landed *"Hypervisor: None for primary stack"* decision, and consumer IOMMU grouping is unverified.

## Threshold that changes the answer

The cheapest by far: **make a cell's unit of execution a signed artifact** (`bun build --compile`, our own key, one per cell). That single change unblocks options 1–3 simultaneously and costs less than any mechanism surveyed.
