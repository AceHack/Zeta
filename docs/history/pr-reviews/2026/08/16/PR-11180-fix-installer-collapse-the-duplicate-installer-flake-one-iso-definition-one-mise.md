## Description

## What diverged

`full-ai-cluster/usb-nixos-installer/flake.nix` built `nixosConfigurations.installer` from the **same** `usb-nixos-installer/nixos/installer/configuration.nix` as `full-ai-cluster/flake.nix`, but applied no overlays. Both `flake.lock`s pinned nixpkgs at the **same** rev `b77b3de8775677f84492abe84635f87b0e153f0f`, so the mise-pin overlay was the **only** difference between the two ISOs — not a general drift.

The work item said the resulting mise versions were *inferred*. They are now **measured** — `nix eval` on both flakes at their own committed locks:

| flake | `nixosConfigurations.installer.pkgs.mise.version` |
|---|---|
| `full-ai-cluster/flake.nix` (what CI builds) | **`2026.6.12`** |
| `full-ai-cluster/usb-nixos-installer/flake.nix` (retired; verbatim from `origin/main`) | **`2025.11.7`** |

`2025.11.7` is below `.mise.toml`'s `min_version = 2026.6.12`, which is what makes it *fatal* rather than merely stale: it fails the check in `tools/setup/linux.sh` and falls into the tarball branch that is deliberately fatal on NixOS, so the divergence surfaced only at first boot.

**And the "obvious" path was the documented one.** The root `flake.nix` (bootstrap comment + devShell hint), `infra/README.md`, `infra/nix-darwin/README.md` and `infra/nix-darwin/configuration.nix` all told operators to run `cd full-ai-cluster/usb-nixos-installer && nix build .#installer-iso` — the un-overlaid flake. This was not a trap you had to wander into.

## The fix

**Collapse** — the work item's preferred option (DV2.0: one hub, not two). `usb-nixos-installer/flake.nix` and its `flake.lock` are deleted; `full-ai-cluster/flake.nix` is the single definition, which is what CI already built. Every doc surface now says `cd full-ai-cluster`.

The alternative — re-apply the overlay inside the installer flake — was rejected: the overlay lives at `full-ai-cluster/nixos/overlays/mise-pin.nix`, above that flake's root, and Nix cannot reference paths above a flake root. It would have had to be *copied*, i.e. a second hand-maintained list.

## The check that keeps it fixed

`src/Core.TypeScript/hygiene/mise-pin-parity.ts` (+ `.test.ts`), run by the gate's `lint (bash retirement inventory + hygiene unit tests)` job. Two halves, one per way to re-diverge:

1. **Structural** — every flake found by `git ls-files '*flake.nix'` that references `nixos/installer/configuration.nix` must also reference `overlays/mise-pin.nix`. Discovery is by glob, **not** a hardcoded list, so a newly-added flake is covered the moment it exists.
2. **Value** — the four sites restating the pin (`.mise.toml`, `tools/setup/linux.sh`, `tools/setup/macos.sh`, `full-ai-cluster/nixos/overlays/mise-pin.nix`) must agree, compared against `.mise.toml` as canonical. **No expected version is written into the checker.** A renamed or missing declaration is a failure, not a skip.

Also available as `bun run hygiene:mise-pin-parity`.

## Owned error found by that second mutation

The structural check's first version keyed on the marker `usb-nixos-installer/nixos/installer/configuration.nix`. The retired flake lived *inside* that directory and referenced its config as `./nixos/installer/configuration.nix` — so the marker did not occur in the file at all, and **the check passed green on the exact bug it was written to catch.** Only the narrow hardcoded path assertion fired.

It survived because my fixture interpolated the marker under test, so it matched by construction. The marker is now the suffix `nixos/installer/configuration.nix`; the fixtures are literal flake text; and a `markers are the substrings they claim to be` test guards the vacuity directly.

## Named gap

The overlay cannot *derive* its version from `.mise.toml` — that file sits above the `full-ai-cluster/` flake root, and Nix flakes cannot reference paths above their own root. The restatement is structural to Nix; check (2) is the binding. **Derived-by-check, not derived-by-construction** — stated rather than papered over.

## Not exercised

**No ISO was built.** `nix eval` proves the package *selection* on both sides; a full `nix build .#installer-iso` (Linux, or CI's `build-ai-cluster-iso.yml`) remains the only thing that exercises the ISO itself. The first-boot behaviour of `tools/setup/linux.sh` under the old mise is still reasoned-about, not run.
