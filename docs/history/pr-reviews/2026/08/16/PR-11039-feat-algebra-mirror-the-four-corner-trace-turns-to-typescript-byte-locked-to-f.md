## Description

# Summary

`FourCornerTrace` (`TraceTurn` / `RecordedFold`, #10992, Vera, 2026-08-16) existed in exactly one
oracle: `TraceTurn` and `RecordedFold` appeared in no `.ts` file, while the surrounding `FourCorner`
concept is mirrored (`src/Core/FourCorner.fs` ↔ `src/Core.TypeScript/four-corner/`). This mirrors it
to TypeScript and adds a **cross-oracle byte-lock** so the two sides cannot drift apart silently —
the defect class that produced 081KT07NV0008QG0R001YDB73K twice (F# `ZSet.ofSeq`, then `compareTagged`
in TypeScript, verbatim).

`src/Core/WSet.fs` is untouched. F# is the source of truth; this conforms to it.

## The three load-bearing semantics, preserved and given falsifiers

- **Append-only; `Sequence` is logical order, not wall time.** `sequence` is `bigint`, not `number`
  — a double stops being an exact integer at 2^53 and would silently merge two turns. Turns are
  `Object.freeze`d, so rewriting one *throws*; `readonly` alone is erased at runtime and would have
  left the claim unfalsifiable. No clock is read anywhere.
- **The trace is returned, never retained.** The TS module keeps no log; `RecordedFold` is handed to
  the caller. Storage and forgetting stay policy decisions at the boundary (Bennett's reversibility
  boundary — keeping history is free, forgetting is where the Landauer cost lands).
- **Empty deltas are still recorded.** A no-op turn occupies a sequence number *and a golden line*
  (`…\t-`). The golden file has 7 turn lines for 7 feedbacks; a fold that skipped no-ops emits 5 and
  the byte-lock goes red on both oracles.

## Divergences reported rather than papered over

1. **`consolidateWSet` does not sort** (081M05ZZG6A087G0R001PBBKDX). F# `WSet.consolidate` ends with
   `List.sortBy fst`; the TS port returns `Map` insertion order. Not patched — it has other callers.
   The trace sorts on top (`consolidateOrdered`) so its own byte-lock holds.
2. **F# ordinal is UTF-16 code UNIT, not the canonical code POINT collation**
   (081M060AYN9087G0R0006E6FWZ). Measured: F# sorts U+1F600 before U+FFFD; `collation.ts`
   `stringCompare` sorts U+FFFD first. The mirror matches **F#**, because using the canonical
   comparator would have put the oracles silently out of order on astral keys while still calling
   itself parity. Pinned by a test on both sides; every golden key is BMP so the lock is exact today.
3. **`toFourCorner` cannot return the `four-corner/` type** — that TS module is string-quad only. It
   returns the generic `FourCornerOwnership` from `workflow-engine/types.ts`. F# `None` maps to an
   *absent* property under `exactOptionalPropertyTypes`, not `undefined`; asserted in the test.
4. **The F#-side codec lives in the test**, not in `src/`, because `WSet.fs` must not be edited. What
   the golden file locks is the fold semantics; the line format is the observation instrument. Named
   in the file header.
5. **No FsCheck in TS** — the property tests use a seeded LCG over 200 cases. Deterministic by
   construction (discipline #4), which is stronger for replay than an ambient RNG, but it is a fixed
   corpus rather than shrinking random search.

# Notes

The honest limit on the parity claim: the byte-lock covers the string-key / ℤ-weight instantiation
over five scenarios. The ℂ corner and the number-key laws are mirrored but not byte-locked — the F#
ℂ tests compare within an epsilon, so there are no exact bytes to lock there, and inventing some
would be a false lock. Naming that is cheaper than implying more coverage than exists.
