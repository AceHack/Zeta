## The short version

**The mechanism exists, under a name nobody was grepping for.** Searching by *behaviour* rather than
vocabulary lands on `SchedulerZeta.runToHorizon` — *"FAST-FORWARD through detected recurrence … the
scheduler stops re-simulating a config it has proven periodic."* That is Aaron's sentence, in the
source, with a load-bearing test that runs **one billion CHIP-8 frames** of a period-4 ROM in
O(reachable ≈ 5) work.

So this PR does **not** add a dilation policy. It adds the **measurement**, which is the falsifiable
half — and the measurement refutes the design it was given.

## What was measured

`tests/Tests.FSharp/TimeDilation.Tests.fs` wraps `step` in a call counter and divides the simulated
horizon by the work actually done. The factor is a quotient of two counted things — no constant in this
PR was chosen by taste, so nothing needed a `toy` label.

| orbit class | λ (measured) | work | achieved dilation |
|---|---|---|---|
| `Fixed` | 0.000000 | 1 | **20 003** |
| `Crystal 4` | ≈3e-8 | 4 | **5 000.75** |
| `Quasiperiodic` | −0.000000 | 20 004 | **0.99995** |
| `Chaotic` | **0.693494** | 20 004 | **0.99995** |

**The derived factor:** achieved dilation = `horizon / Recurrence.Reachable`, exactly, and
`Reachable = Transient + Period` *is* the counted work. `SchedulerZeta.predict` already returns it.

**The refutation — λ fails in both directions:**

* *Same λ, different dilation* — `Fixed` and `Crystal 4` both meter λ = 0 to within 1e-6; dilation
  differs by exactly 4×, the ratio of cycle lengths.
* *Different λ, same dilation* — `Quasiperiodic` and `Chaotic` are separated by λ ≈ ln 2, the largest
  gap in the set, and dilate identically to the last bit.

λ is the right meter for a **lossy** skip (how long until two states agree to within ε); it is the wrong
meter for the lossless one. Not implemented here — a lossy skip is a policy with an error budget.

Two costs stated rather than rounded: off the periodic classes dilation is **strictly below 1** (one
wasted step plus O(horizon) memory to prove there is no cycle), and `predict` is **unbounded** on an
aperiodic map — only `runToHorizon` is horizon-bounded.

## The correlated-set observable, carried from the start

Per #10834's closing note. Two-part system, part A a period-4 rotation, part B accumulating A's value
with coupling `c`, prime modulus so B's return is not an artifact of the horizon.

| coupling | key | work | dilation | result | correct? |
|---|---|---|---|---|---|
| **0** (control) | part A only | 4 | 5 000.75 | (3, 0) | yes |
| **0** (control) | joint | 4 | 5 000.75 | (3, 0) | yes |
| 1 | part A only | 4 | **5 000.75** | (3, **3**) | **NO** |
| 1 | joint | 3 988 | **5.016** | (3, **93**) | yes |

1. **The dilator's own view is blind to the cost** — byte-identical factor at both couplings; the ~997×
   collapse is invisible from the side doing the skipping. Exact zero-coupling control.
2. **Unilateral dilation is silently wrong** — a lossy key returns a state stale in the projected-out
   component, with no exception and no diagnostic.

### The precondition this exposed (repair, not accusation)

`runToHorizon` stated *"Equal to the naive `stepⁿ start` for every `horizon` (the guarantee)"*
**unconditionally**. It holds only when `key` is injective on the reachable set. The docstring now says
so and names the test. **No behaviour changed.** The existing CHIP-8 caller satisfies the precondition
(its ROM writes no memory, touches no display, never ticks timers) but satisfies it **by argument, not
by check** — its test compares two *projections*, so it would pass either way. Labelled `unmetered`
rather than upgraded.

## Task 2 — Aaron's structural-holes connection, triaged

Both talks are in `docs/research/ip-questionable/`: Greenberg's Hitchhiker trees (Strange Loop ~2016)
and Vokes's *The Code That Isn't There* (Strange Loop 2012, ferried 2026-08-01 with *"I found the holes
data structure in this talk"*). The holes are the **difference lists** in the Vokes talk, not anything
in the tree.

**Verdict: suggestive, unpromoted.** The disqualification uses this repo's own definition: an orbit is
**recurrence** (`s = stepⁿ s`). Buffered ops in a fractal tree **strictly descend** — depth is a monotone
potential, every op terminates at a leaf, so no recurrence and no orbit. A difference-list hole does
better (binding a hole creates a new hole of the same shape) but the structure never returns — that is a
**fixed point**, shape A, not a periodic orbit. Under `Orbit`'s taxonomy that puts the hole at `Fixed`,
which *is* the maximally-dilatable class, so "a hole carries zero information per operation" is a real
bridge — but "both are fixed points of their own step" is a shared *property*, not a shared *mechanism*,
and nearly every structure with an invariant has it. **Promotion condition named in the doc:** exhibit a
structure whose holes recur with period n > 1.

**But the sentence is literally true somewhere else, and I measured it today.** `runToHorizon`'s key
projection **is a hole** in Vokes's exact sense — `chip8Key` deliberately does not look at Mem or
Display, an absence with a name. And in the coupled probe above, projecting part B out turned a
trajectory whose true period is **3 988** into an apparent **period-4 orbit around the retained
structure**. *The hole manufactured the orbit.* This does **not** promote the tree mapping — it is an
independent instance — and the cautionary half is the same measurement: the induced orbit is an
**artifact**, and acting on it returned a wrong answer.
