# Summary

Files an **owned error** from PR #11039, shipped hours ago by me.

That PR carried a structurally correct AgencySignature block in both the commit message and the PR
body, and `validate-agencysignature-pr-body.ts` passed pre-merge. The squash commit
`163f09edfd37cd591a14315ece142685efd5f647` nonetheless ended up **invisible to git's own trailer
parser**, because GitHub appended its own co-author section after the block:

```
git log -1 --format='%(trailers:key=Agency-Signature-Version,valueonly)'
  2b705e63f -> "1"   711bab897 -> "1"   80a146304 -> "1"
  163f09edf -> ""    <-- mine
```

1 of the last 17 `main` commits carrying a block has GitHub's `---------` separator, and it is mine.

The finding worth more than the instance: **`audit-agencysignature-main-tip.ts` reports `CORRECT: 1
/ PASS` on that exact commit.** It parses the message itself rather than delegating to git, so the
post-merge audit cannot detect the failure mode its own template warns about. "The audit passes"
and "git can read the trailer" are different claims, and only the second is what downstream
`git log --format='%(trailers)'` consumers actually receive.

No fix is proposed here — changing the audit's parser or the template's last line is a governance
call on a surface I did not author, and either change has blast radius across every future commit.
The measurement and the two open decisions are recorded so someone can make that call with the
evidence in hand.

The suspected trigger (a `Co-authored-by` naming an address GitHub cannot resolve to a user) is
labelled a **hypothesis, not a conclusion** — one observation, confounders not isolated. Recorded
under the coincidence-vs-structure discipline rather than promoted to a cause.

# Notes

**A named deviation from the template, run as the experiment.** This body's AgencySignature block
omits the final `Co-authored-by:` line. The template says to copy the block exactly and I am not
doing that, deliberately: the house commits that end at `Task:` are the ones git can still read, and
this is the cheapest available test of the hypothesis. `validate-agencysignature-pr-body.ts` accepts
the block without it.

So this PR is itself the observation. If its squash commit carries no `---------` separator and git
can read `Agency-Signature-Version`, that supports the hypothesis and the item should be updated to
say so. If it splits anyway, the hypothesis is wrong and the trigger is elsewhere — #11039 had two
commits and this has one, which is the next confounder to isolate. Either result is worth having;
neither is worth asserting in advance.
