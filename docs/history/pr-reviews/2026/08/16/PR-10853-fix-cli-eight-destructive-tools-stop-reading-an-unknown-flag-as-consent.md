## Description

## The class

`rebuild-legacy-b-id-aliases.ts` decided whether to rewrite ~1,700 files by asking whether one
exact string was present:

```ts
const DRY_RUN = process.argv.includes("--dry-run");
```

**Everything else meant "go."** PR #10841 fixed that tool, and found eight siblings with the same
shape — filed as `081M03HRHBS087G0R001HRAFQ0` rather than swept, because each needed its own read
of what a bare invocation does for real callers. This is those eight.

***

## Scope — property 1 only, and the omission is deliberate

**Property 1 — an unrecognised argument is an error, exit non-zero before any filesystem write.**
Applied to all eight.

**Property 2 — destructive mode must be opted into. NOT applied, on purpose.** `run-tier0.ts` and
`mutation-runner.ts` are invoked **bare** by `agent-heartbeat.yml` (lines 124 and 257); writing is
what a healer and a mutator are *for*, and flipping their default would break the heartbeat. The
same reasoning was extended to the other six: **no bare invocation changes meaning in this PR.**

***

## The payoff — the guard buys enrolment in a lint that was silently skipping these tools

`hygiene/audit-workflow-cli-flags.ts` refuses a workflow that passes a flag its tool rejects — but
only for tools whose parser **demonstrably** rejects unknown flags, detected by an `unknown arg`
diagnostic in the source. The absence of a guard bought exemption from the check that would catch a
bad invocation. Measured before and after on this branch:

```text
BEFORE (origin/main)                       AFTER (this branch)
SKIPPED  hygiene/healers/run-tier0.ts      CHECKED  hygiene/healers/run-tier0.ts
SKIPPED  hygiene/mutation-runner.ts        CHECKED  hygiene/mutation-runner.ts
totals: checked 22  skipped 60  viol 0     totals: checked 24  skipped 58  viol 0
```

**Correction to the brief.** The brief asked me to show the auditor now *covers* each of the eight
rather than skipping it. It cannot, and the reason is structural rather than a defect in my guards:
`auditWorkflowCliFlags` is **invocation-driven** — it walks `.github/workflows/`, and a tool no
workflow invokes is never read at all. The other six appear in **neither** list, before or after;
they were never "skipped", they were never *seen*. For them the enrolment is latent: the day a
workflow invokes one, it is policed instead of waved through. Two of eight is the whole of what
"enrolment happens" can mean today, and it did happen.

## Mutation proof, per tool

Every proof asserts on the **filesystem**, never the exit code — an exit-code-only test passes
against a tool that rewrites everything and *then* complains, which is the defect itself. Raw exit
codes, no pipes. **Nothing was run for real:** `gh`, `pwsh`, `git` and `launchctl` are PATH shims
that record what was asked of them, `HOME` is a fixture, and repository targets are `mktemp -d`.

### 1. `hygiene/healers/run-tier0.ts` — rewrites markdown/TS across a repo

```text
GUARDED   bun run-tier0.ts --repo-root FX --dry-runn
EXIT=1    unknown arg: --dry-runn
          [tier-0] REFUSED — nothing was written. Accepted: --dry-run --max-files --plan-out --repo-root
          fs before: sub/sample.ts 1767243600 136  e711aaa8…
          fs after : sub/sample.ts 1767243600 136  e711aaa8…      <- mtime AND digest identical

MUTANT    guard line removed, same bogus flag
EXIT=0    [tier-0] HEALED: sub/sample.ts
          fs after : sub/sample.ts 1786834200  96  93e1c0ba…      <- REWRITTEN
```

Exit **1**, not 2. `agent-heartbeat.yml` treats rc=2 as a tolerated `::warning::` and ends the step
cleanly, because an oversized heal plan is a finding about the repo. A mistyped flag routed through
that branch would report a heal that never ran as a known-and-accepted condition — a check that
cannot fail wearing the costume of one that passed. rc=1 lands in `HEALER FAILED rc=$HEAL_RC`.

### 2. `hygiene/mutation-runner.ts` — writes a mutant into a source file, appends to `db/`

```text
GUARDED   --repo-root FX --agent shadowtest --room "…" --choose 3 --reason proof --dry-runn
EXIT=1    unknown arg: --dry-runn
          files after: []                                          <- nothing created

MUTANT    guard line removed, same argv
EXIT=0    files after: [FX/db/mutation-transcript/shadowtest.jsonl 1786834256 559]
```

Exit **1**, never 3/4/5 — those are FINDINGS the heartbeat renders into the run summary, and a
mistyped flag must not be able to publish itself as a measurement.

### 3. `observe/backfill-tick-shards.ts` — writes shards under the caller's cwd

```text
GUARDED   EXIT=2  unknown arg: --dry-runn   fs: unchanged
MUTANT    EXIT=0  fs after adds data/tick-shards/2026/08/01/080cfdd4f6c0000078030000638a1137.json
```

The write is idempotent, which is exactly why a stray run would have gone unnoticed — idempotence
makes a wrong invocation quiet, not harmless.

### 4-6. The three ruleset migrations — mutate LIVE branch protection

Never pointed at GitHub. A fake `gh` on `PATH` records every call and answers `[]`. **For a tool
whose destructive act is an API call, the recorded call IS the write.**

```text
b0266-review-policy-ruleset.ts
GUARDED   EXIT=2  unknown arg: --dry-runn / REFUSED — no ruleset was read or modified
          gh calls: (none — the canary file was never created)
MUTANT    gh api repos/Lucent-Financial-Group/Zeta/rulesets?includes_parents=false --method GET
          gh api repos/Lucent-Financial-Group/Zeta/rulesets --method POST --input -
          gh api repos/Lucent-Financial-Group/Zeta/rulesets/15256879 --method PUT --input -

b0267-branch-safety-ruleset.ts   identical: GET, POST /rulesets, PUT /rulesets/15256879
b0267-safety-ruleset.ts          GET, GET /rulesets/15256879 (its live path can DELETE Default)
```

A bogus flag on `origin/main` today reaches `POST /rulesets` and `PUT` on the Default ruleset. The
guard is above the **first** `ghApi` call, so a bad invocation makes no request at all — not even
the read.

### 8. `zflash/flash-usb-windows.ts` — writes a block device

Two containments, and the second is the interesting one. On macOS `realRunner.ps` shells out to
`pwsh`, so a shim intercepts the tool's first external command. The destructive path is also
Windows-gated, so to show the guard sits **above** that gate rather than being masked by it, a
harness substitutes exactly one expression — `process.platform !== "win32"` becomes `false` — and
nothing else.

```text
A. real tool, guarded, bogus flag     EXIT=2  unknown arg: --dry-runn      pwsh calls: none
B. real tool, mutant, bogus flag      EXIT=2  "only runs on Windows"       (the platform gate)
C. harness (gate defeated), guarded   EXIT=2  unknown arg: --dry-runn      pwsh calls: none
D. harness + mutant                   pwsh -NoProfile … IsInRole(…Administrator)   <- reached the machine
```

B and C together are the point: on macOS both the guard and the platform gate produce exit 2, so
comparing exit codes alone would have been vacuous. C proves the guard fires with the gate removed;
D proves that without the guard the tool proceeds into the PowerShell pipeline.

This tool's defect was worse than "ignored": it **filtered** every `-`-prefixed token out of its
positional list, so an unknown flag was actively discarded and `--dry-runn` meant "not a dry run".

## The one invocation whose behaviour I deliberately changed

`zeta-flash.ts usb` re-execs this flasher on Windows with the caller's arguments, and its mac
sibling `cli.ts` accepts flags the Windows backend never had (`--agent`, `--host`, `--skip-iso-pull`,
`--bake-cred`, …). I looked rather than reasoned — harness, `pwsh` shim, fixture `HOME`:

```text
BEFORE  bun flash-usb-windows.ts --skip-iso-pull
        the flag is silently discarded; the tool runs the elevation check and proceeds to ISO
        discovery (it stopped here only because the fixture HOME has no ISO)
        pwsh calls: 1  <- it reached the machine

AFTER   EXIT=2  unknown arg: --skip-iso-pull — REFUSED, no device was read or written.
        pwsh calls: 0
```

**This is a behaviour change and I am not smoothing it over.** A user who passed `--skip-iso-pull`
to the Windows flasher previously got a device-flashing run in which their flag did nothing.
Silently ignoring a flag on a tool that destroys a disk is the same defect class as reading one as
consent, so refusing is the fix and not a regression. The underlying finding — the router promises
a flag set the Windows backend does not implement — is now **named** instead of silent. Not fixed
here; that is a real divergence needing its own read.

Everything else is preserved and proven: the heartbeat's exact `--repo-root . --max-files 25
--plan-out …` and `--agent … --tick … --since "24 hours ago"` invocations, every `--dry-run`, both
`--help`/`-h` paths on the flasher, and `--ssh-key <path>`.

## The tests, and the survivor they exposed

`src/Core.TypeScript/hygiene/cli-fail-closed.test.ts` — **46 tests**. Subprocess cases snapshot the
fixture tree (path, size, `mtimeMs`) before and after and assert on the tree, and **every one
carries a positive control**: the same fixture is also run in a mode that *does* write, and that
write is asserted. Without the control, a broken fixture would produce a green suite proving
nothing.

Then I mutated each of the eight guards in place and re-ran the suite:

| guard removed from | suite result |
|---|---|
| `run-tier0.ts` | 43 pass **3 fail** |
| `mutation-runner.ts` | 45 pass **1 fail** |
| `backfill-tick-shards.ts` | 43 pass **3 fail** |
| `b0266-review-policy-ruleset.ts` | 43 pass **3 fail** |
| `b0267-safety-ruleset.ts` | 43 pass **3 fail** |
| `b0267-branch-safety-ruleset.ts` | 43 pass **3 fail** |
| `setup-dual-background-agents.ts` | 45 pass **1 fail** |
| `flash-usb-windows.ts` | 44 pass **2 fail** |

**The first run of that sweep had a survivor, and it was my own comment holding the test up.**
Removing `setup-dual-background-agents.ts`'s guard left the suite **fully green**. `hasClosedFlagSet`
runs its regex over the **raw** source — comments included, unlike `extractAcceptedFlags` which
strips them first — and the doc comment I had written above the guard, explaining why the phrase
`unknown arg` matters, still contained the phrase. The enrolment assertion passed against a tool
with no guard at all.

Fixed by asserting the diagnostic survives `stripComments` — the guard must be in **code**, not in
prose — which is what turns that test into a falsifier. Every one of the eight now fails the suite
when its guard is removed.

**That is also a finding about the auditor**, and it generalises past my mistake: any tool that
merely *discusses* unknown arguments in a comment reads as having a closed parser, and
`audit-workflow-cli-flags` will then police workflow invocations of it on the strength of a parser
that does not exist. Measured: **zero tools in the repo are currently enrolled by a comment alone**,
so tightening `hasClosedFlagSet` would be a no-op today. Pinned as a test, not fixed — changing
which tools the audit polices deserves its own change and its own reading.

## Findings recorded, not fixed

1. **All three ruleset migrations reference a script that moved.** Their final "re-snapshot
   expected.json" step shells out to `tools/hygiene/snapshot-github-settings.ts`; the file now lives
   at `src/Core.TypeScript/hygiene/snapshot-github-settings.ts`. The live path dies with
   `Module not found` *after* mutating branch protection — visible in the mutant runs above. Out of
   scope for property 1.
2. **`full-ai-cluster/tools/flash-usb-windows.ts` is a stale fork of the flasher**, 22 diff lines
   from the `zflash/` copy, and it is missing the `mkdtemp` fix that the canonical copy carries for
   the CodeQL insecure-temp-file finding. Nothing but its own README references it; the workflow
   tests only the `zflash/` copy. It has the unknown-flag defect too. Not guarded here — guarding a
   stale duplicate would entrench it, and deleting it is a judgement call, not a property-1 change.
3. **No behavioural test for `setup-dual-background-agents.ts`, on purpose.** A positive control for
   it would have to exercise the live path, which runs `launchctl bootout gui/$uid/com.zeta.claude-loop-opus`.
   With a shim that failed to intercept, a test could stop the operator's real background agents. A
   test that can do that is worse than the defect it guards. Its guard is mutation-proven by hand
   above and pinned statically.
4. **One unexplained observation.** In a single sweep run the *baseline* reported 44 pass / 2 fail;
   14 subsequent runs (10 standalone, 4 via the sweep) were 46/0 and I could not reproduce it or
   capture the names. Recorded because it happened, not because I understand it. If this file flakes
   in CI, that is the thread to pull.
