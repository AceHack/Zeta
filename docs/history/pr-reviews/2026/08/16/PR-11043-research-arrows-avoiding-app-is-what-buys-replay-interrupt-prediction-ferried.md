## Description

Ferrying architecture that existed only in Aaron's head and in the shape of the code.

> *"this is where we slip in prediction and pseudo retrocausality over iterated runs … this was really hard to accomplish — interrupt prediction of controller input and how it affects game state … it felt like magic once I got it right, and I didn't even know to avoid `app`, it was just instinctive."*

## The causal chain — an ordering, not a style preference

Rollback prediction requires the computation be **replayable against a corrected input**; that requires **structure knowable independently of the values** flowing through it; `ArrowApply`'s `app` — *run an arrow that arrived as data* — destroys exactly that, because you cannot identify the computation until you already hold the value you were trying to predict.

> **no `app` ⇒ static structure ⇒ inspectable ⇒ replayable ⇒ prediction is possible at all**

## Why the monad survives anyway

`Result`'s short-circuit is monadic **sequencing** at a **fixed branching shape** — two outcomes, statically known, at every `>=>`. Unlike `app`, where branch structure is whatever the value says. So unpredictable **content** (which interrupt fired) sits in a channel whose **control flow** is determined, and the surroundings stay replayable.

**The cut: separate unpredictable VALUE from unpredictable STRUCTURE.** Only the second breaks rollback.

## The membrane, stated so it can be metered

Aaron read this as a Markov boundary. Not literally Pearl's construct, but the property underneath is a genuine conditional independence, and the exact form is more useful:

> In the Applicative fragment, **structure ⊥ values**. `>>=` on a runtime value is where that independence breaks.

Which is why it's cheap to meter — a crossing is a **syntactic** event, not a statistical estimate.

## The same move, twice, years apart

The Itron **ferry throttler** made *degree of parallelism* independent of the work; avoiding `app` makes *structure* independent of the values. Both remove a dependency that looked essential so a dial can be turned without changing the program. One skill applied twice rather than two lucky architectures.

## Prior art — and an honest gap

Established: Hughes 2000 (`ArrowApply ≡ Monad`); McBride & Paterson 2008; **Haxl** (ICFP 2014); **Selective applicative functors** (ICFP 2019); **Build Systems à la Carte** (2018) — the closest published statement, classifying build systems by static vs dynamic dependencies.

**Not found:** the application to **speculative execution and rollback**, with the fixed-shape-error-channel carve-out.

### Registered `NotFound`, explicitly **not** `Established`

Applying the discipline that landed in #11033 to this very question: one probe, one vocabulary, one set of priors is **artifact-class**. Settling it needs **decorrelated** probes — weight-diverse, not persona-diverse, since we measured ρ̂ = 0.651 across personas vs 0.096 across weights.

**Plausibly novel, unverified, and the instrument that produced it is the wrong one to settle it.**
