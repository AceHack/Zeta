## Description

## The defect

`evaluateReviewGate` read `adopted.length === 0` as "the change is clean" and returned `Approved`.
**That one variable represented two genuinely different states:**

| state | what it means | approving is |
|---|---|---|
| no finding was ever **raised** | there is nothing to know | **correct** |
| findings were raised and **withheld** for lack of quorum | information exists | **erasure, then read as approval** |

Upstream, `packages/metrics/src/review-board.ts:115` withholds any finding that fewer than 3 distinct
reviewers agree on. So state 2 is the ordinary fate of a solitary true blocking finding from the one
reviewer who spotted it — and the gate approved on it. Aaron 2026-08-14: *"that's shipping bugs."*

The fix is not a different default constant. Flipping to reject would fail every genuinely clean
change — one wrong constant for another. The fix is to stop having one variable mean both things.

## How the two states were separated

- An explicit `ReviewGateBasis` DU **names the state**; `recommendedGateOutcome` is derived from the
  basis through a single `outcomeForBasis` mapping, never from a count that cannot discriminate.
- `NoCandidateFindings` is the **only zero that may approve**. This is the same remedy as the sibling
  `agent-reviewer.yml` fix (`sovereign=true` when zero files had been inspected): **count what you
  inspected, and do not let "nothing survived aggregation" wear the same clothes as "nothing was
  found."** Zero participation still fails closed to `feedback` upstream, and there is now a test
  pinning that.

| basis | outcome | change |
|---|---|---|
| `NoCandidateFindings` | `Approved` | unchanged — clean path preserved |
| `AdoptedBlockingOrMajor` | `Rejected` | unchanged |
| `AdoptedMinorOrInfoOnly` | `ChangesRequested` | unchanged |
| **`UnadoptedBlockingOrMajor`** | **`ChangesRequested`** | **was `Approved` — the defect** |
| `UnadoptedMinorOrInfoOnly` | `Approved` + advisories | was `Approved`, findings silently dropped |

Deliberate restraint on the fixed row: **`ChangesRequested`, not `Rejected`.** The board did not
establish that the finding is true, so rejecting would assert it. `ChangesRequested` says *someone
must look* — the weakest outcome that is not silent approval.

Contested findings (quorum agreed **and** quorum disagreed — the board's own "escalate") were also
approving. They now travel the same unadopted path; escalation is not approval.

## What happens to sub-quorum findings now

They are **carried, not deleted.** Every non-adopted finding is returned on `advisoryFindings` with
severity, comment, board state (withheld vs contested), the agree/disagree counts, and **attribution**
— the reviewer agent ids on each side. Minor/info advisories are non-blocking, so they do not gate a
change; they are simply no longer erased.

A withheld finding that is dropped is erasure; a withheld finding that is surfaced is correction.
This is `LandauerFloor.lean` theorem 3 applied to a review gate, and it restores the ΔU that
`.claude/rules/every-bug-has-economic-value.md` says a discarded finding destroys.

## Blast radius

`packages/metrics` is **untouched.** Attribution is computed in the gate from the votes the caller
already supplies, so `metrics/src/index.ts` and `mcp-tools.ts` consumers are unaffected. The
`ReviewGateResult` ok-arm gains fields (additive; structural typing). `evaluateReviewGate` has no
non-test caller in-repo today — the exported surface is the blast radius. **No caller depends on the
fail-open**, so there was nothing to stop and report.

## Recommendation, NOT implemented — the aggregation rule is Aaron's call

The deeper finding from #10955 §1.1.A stands and is **not** touched here:

> `AND`-of-3 is the **complement** of the right rule for a recall task. Bug-finding is one-sided
> discovery, where union dominates tautologically (`⋃Aᵢ ⊇ A_{i*}`); an unweighted k-of-n count defers
> toward **neither** accept nor reject, so it dominates on neither precision nor recall. The best
> reviewer spotting a real defect alone is structurally guaranteed to be overruled.

Recommended, for decision: **adopt every finding and publish the agreement count as a confidence
annotation rather than a gate.** Free, needs no competence estimates, provably not worse than the
best reviewer. **Do not add weights** — the log-odds route needs per-agent competence that nobody
here has measured, and `calibration-ledger.ts` measures *calibration*, which the module itself says
is not competence.

Why it is out of scope for this PR: changing the quorum rule alters what blocks merges repo-wide.
This PR fixes only the fail-open, and that fix is **independent of which quorum rule wins** —
whatever the rule, a withheld finding must not read as approval and must not be erased.

**Register:** the fail-open and its fix are `metered` (mutation-proven falsifier above). The
aggregation recommendation is `unmetered` — no test in this repo fails when the quorum rule is
non-deferential, and no measurement of this board's empirical error rate exists.

Not touched, per scope: constitution gate, security stage, BFT quorums, n-way diff (#10955 verified
these are veto-shaped or integrity detectors, correctly not this defect class).
