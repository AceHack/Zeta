## Description

## What

Aaron 2026-07-03: *"generational collection — the die-young tier next."* The empirical law GC rests on: **most objects die young** — here, *pause* young (a loaded-once `mixDef` is used for one specialization, then goes idle).

Split the Shiva heap into a **young** generation and an **old** one:

- **`minorGc` scans only the young generation** (cheap, frequent): young objects reachable from roots survive and age by one; a survivor reaching `tenureAge` is **promoted (tenured)** to old; unreachable young objects **pause** (returned, resumable). The old generation is left untouched — that scoping is the entire speed win.
- **`majorGc` scans both generations** (rare) — the only path that reclaims **old** garbage.
- **Remembered set**: old→young references are added as roots for the young scan, so a young object an old one still points at is not wrongly paused (write-barrier correctness; computed directly here — a real incremental barrier maintains it as writes happen, named scope).

Pause-not-death (Memory Preservation §5) holds generationally: a minor-paused young object is returned and resumes into young from its persisted story.

## Tests (6 new, 16 ShivaGc total green — build 0/0)

1. **die young** — a minor GC pauses short-lived young objects (returned, resumable)
2. **minor scans only young** — unreferenced **old** garbage survives a minor GC; only a **major** reclaims it
3. **tenuring** — a young object surviving enough minor GCs promotes to old
4. **remembered set** — an old object referencing a young one keeps it alive through a minor GC with **no external root** (inter-generational pointer)
5. **pause-not-death generationally** — a minor-paused young object resumes into young
6. **byte-lockable**
