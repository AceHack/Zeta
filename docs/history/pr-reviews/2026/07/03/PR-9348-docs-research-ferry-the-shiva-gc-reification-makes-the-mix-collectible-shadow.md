## Description

Ferry of Aaron's streamed insight on shipping mix-as-data slice 3 (#9347): "the reify is weak reference table like so it can be collected too this is basically our Shiva Garbage Collector." His words preserved, with the technical read + Beacon anchors.

**Load-bearing point:** you cannot GC *code* (baked into the binary, referenced forever); you CAN GC *values*. Reifying the mix's decision procedure (mixDef) and abstract-eval (evalDef) into data is exactly what makes a collector possible — the slice-3 boundary (driver native, tables data) IS the GC boundary (mutator vs heap). Generation (Brahma / the generator) and collection (Shiva / the destroyer) are duals over one data substrate; collection = a −1 Z-set retraction of an unreferenced reification (the emit/retract duality already in the repo).

**Honest scope:** seed + design note, not a shipped collector. What's shipped is the precondition (reify → collectible); the weak content-addressed table + reachability walk + retraction-on-drop are the follow-on.

Anchors: McCarthy 1960 (GC born with code-as-data — the exact parallel), Dijkstra et al. 1978 (mutator/collector), Hayes 1997 (ephemerons / weak-reference tables), Lieberman-Hewitt/Ungar (generational), Trimurti (Aaron's oracle). Doc-only.
