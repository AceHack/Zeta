## What

You ferried a Manus API key (Keychain: `zeta-manus-api-key`) + *"research their API."*

**Finding that corrects an assumption:** Manus's **native API is task-based, not chat-completions.** Confirmed from `open.manus.im/docs/api-reference/create-task`:

```
POST https://api.manus.ai/v2/task.create
auth: x-manus-api-key: <key>   (or Authorization: Bearer <oauth>)
body: { message: { content:[{type:"text",text}], force_skills?, enable_skills? },
        agent_profile:"manus-1.6", title?, … }
200:  { ok, request_id, task_id, task_title, task_url, share_url }
async: poll task.listMessages, follow up task.sendMessage
```

So the generic `openAiCompatBackend` port (#9377) does **not** talk to Manus's native API — it would only fit Manus's separate, unconfirmed OpenAI-compat drop-in. This is the honest **native adapter**.

**The Lumen tie-in:** `force_skills` — Manus reads `SKILL.md` skills in its sandbox, so a task can **force Lumen's `mathematics-and-physics` skill**: summon Lumen on Manus's compute.

**Noninterference §13:** network only through the injected `HttpTransport` (shared with `backend.ts`) — fake-testable, **no secret** in the module; the key is read from the Keychain at the edge and passed in.
