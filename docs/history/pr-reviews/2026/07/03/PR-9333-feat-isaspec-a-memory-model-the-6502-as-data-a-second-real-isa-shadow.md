## Description

## What

Aaron 2026-07-03 *"build whatever you like"* (+ 2026-07-02 *"sonic mario"*). The ISA-as-data generality claim was only ever dogfooded on **CHIP-8** — which `Isa.eval` *also* hard-codes, so it was never an independent witness. This adds the real one: the **6502** (Mario's NES CPU), purely as data.

## The primitive that made it possible: memory

The register-only core gained the one thing every real ISA has and it lacked — an **addressable store**:

```
Val    += { v:"mem", addr }          // memory read
Effect += { e:"setmem", addr, val }  // memory write
```

threaded through `evalVal` + a new `evalSpecFull` returning `(regs, mem)`. `evalSpec` keeps its **old signature** (memory internal) so register-only ISAs are byte-for-byte unchanged.

## `mos6502` — the 6502 register + zero-page core, as a spec

A/X/Y = regs 0/1/2, zero page = `mem`: `LDA_IMM`/`LDA_ZP`/`STA_ZP`, `TAX/TAY/TXA/TYA`, `INX/INY/DEX/DEY`, `ADC_IMM`/`ADC_ZP`, `JMP`, `SKE` (compare-skip), `NOP`, `BRK`. Runs under the **same** `evalSpecFull` — the interpreter is never touched; a new CPU is a spec value.

## Honest scope (named, not hidden)

Register + zero-page core, **not** the full 6502. No processor status flags → control flow uses the spec's compare-skip as a stand-in for the flag-based `BEQ`/`BNE` (a status-register extension is the next rung); no carry-in on `ADC`; no indexed/indirect addressing; no decimal mode; no stack; no PPU/APU. What it proves is exactly the checkbox: **the machinery is ISA-general to a real, memory-bearing CPU — CHIP-8 was not special.** The spec-driven `mix` over the 6502's memory ops is a named follow-on.
