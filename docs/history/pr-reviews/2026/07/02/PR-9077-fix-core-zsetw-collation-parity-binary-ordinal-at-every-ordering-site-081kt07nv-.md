## Description

Self-caught reviewing step 2b before the reframe: ZSetW mixed two collations — `ofSeq`/`ofSeqBy`/`lookup`/instance-`sum` used culture-sensitive defaults while `sumBy` merged ordinally. Same class as canonical 081KT07NV.

**Proven bug:** keys `a`/`B` (culture a<B, ordinal B<a) — cross-construction merge produced unsorted output with a duplicate key. 2 of 3 new regression tests **fail pre-fix**, pass post-fix.

**Fix per the DB-collation model** (Aaron + `docs/research/2026-06-07-collation-as-sql-server-…`): every ordering site → `KeyComparerCache` = `Collation.forKey` = the shipped **binary** default (`_BIN2`/Postgres-`C` shaped — fast, no linguistic pass); linguistic collations stay opt-in catalog entries at the edge. Header documents the treaty. 18 tests green; no public API change.
