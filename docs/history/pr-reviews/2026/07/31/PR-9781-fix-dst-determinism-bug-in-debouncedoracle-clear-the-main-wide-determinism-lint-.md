## Description

## The red

The determinism lint (`no ambient entropy in src/Core outside justified edges`) was **red on `main`** — 10 ambient `UtcNow` uses across three oracle files — **blocking every PR** (including the semgrep-cap #9779, which only inherited it). Diagnosing it surfaced a **real bug** behind the red.

## The bug (DebouncedOracle DST leak)

`DebouncedOracle.Subscribe` read ambient `DateTime.UtcNow` in **both** match branches — including the `SyncContext = Some` (DST) branch — despite the docstring promising *"in DST mode, time is pump ticks, not wall clock; timing enters only through the injected context (§13)."* So the debounce accept/suppress decision ran on real wall-clock even under DST (non-deterministic on replay), and the two branches were **identical for timing** (the `match` was a no-op).

**Fix:** the DST branch now advances a **monotonic pump-tick counter** (one tick per delivered callback; the injected pump drives delivery deterministically) → `elapsed` and every accept/suppress decision replay byte-for-byte. Live mode keeps the wall-clock as the fenced local-rate-control door. No `DebouncedOracle` tests existed, so no contract regressed.

## The other 9 (justified edges, allowlisted with WHYs)

Each verified before allowlisting — none feed the ρ/Condorcet math, none run on the DST/seed path:
- **DebouncedOracle.fs (1)** — the live-mode debounce door.
- **OracleTransport.fs (7)** — reading-timestamp metadata + live Git/WebSocket/Reticulum **emit-latency instrumentation** (observability, live-emit path).
- **MoneyVelocityOracle.fs (1)** — reading-timestamp display field (ρ/bonus/velocity come from UTXO age + M2).
