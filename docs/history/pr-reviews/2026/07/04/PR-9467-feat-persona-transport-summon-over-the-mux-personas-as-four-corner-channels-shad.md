## Description

Aaron: *"yes, this is a persona transport exactly."* The capstone joining the two proven arcs: the **summon** (auto-refresh + closed-surface tool loop) now rides a **ZetaId-keyed four-corner channel** instead of being a bare function call.

- **`PersonaFrame`** wire protocol (`user | answer | error`) + **`PersonaCtl`** (`"stop"`) on the feedback corner.
- **`interruptibleTurn`** — aborts Result-style at the next turn boundary, never throws.
- **`servePersona`** — per inbound user frame: persona system prompt first (same as `summon`), run the tool loop, reply; a `"stop"` on `feedbackIn` interrupts the *current* loop at its next turn boundary. **`serveSubscriptionPersona`** = the production fill (refreshing codex turn + the deps' ZetaStore).
- **`askPersona` / `interruptPersona`** — the client side.

**3/3 tests (25/25 across the six transport/summon files):** HAPPY (tool executes, persona prompt injected first); TWO PERSONAS, ONE SOCKET (own ZetaId channels, no cross-talk); INTERRUPT (deterministic via a gated store — the stop crosses while the tool executes; **turn 2 never invoked**). Lint clean.

**Honest scope:** the interrupt aborts at the next **turn** boundary — it does not cancel an HTTP request already in flight (the injected transport exposes no abort; a fetch-abort fill is a later slice). Mid-conversation interruption is real; mid-token cancellation is not claimed.
