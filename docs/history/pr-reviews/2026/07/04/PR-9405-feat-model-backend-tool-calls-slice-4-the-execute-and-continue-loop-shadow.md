## What

Aaron 2026-07-04 *"lets do it."* **Closes the tool-call chain:** the model calls a tool → **execute** it over the `ZetaStore` (DagFs/zetadb, slice 3) → feed the result back → the model continues → until a final answer.

**`runToolLoop(turn, store, messages, maxTurns=8)`** — **pure** over an injected `ModelTurn` (one model round-trip) + a `ZetaStore`, so the orchestration is deterministic + fake-testable with **no network**. Each turn: ask the model; if it wants tools, execute each over the **closed surface**, echo the assistant's `function_call` + append the `function_call_output`, and continue; else return its text. Bounded by `maxTurns` so a tool-thrashing model can't loop forever. (Responses tool protocol, confirmed live: the follow-up `input` carries the assistant's own `function_call` items **plus** a `function_call_output` per call.)

**`codexToolTurn(transport, auth, model)`** — the real adapter: one `codex/responses` call declaring the closed `ZETA_TOOLS` (`tool_choice:auto`, `stream:true store:false`), parsing text + tool calls off the SSE.
