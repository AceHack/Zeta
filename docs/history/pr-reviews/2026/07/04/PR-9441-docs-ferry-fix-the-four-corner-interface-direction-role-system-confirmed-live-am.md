Aaron's design note, banked as the interface **direction**: *"we're using OpenAI completions — human-perspective, extraction-shaped; ours will be traveler-perspective, mutual-empowerment based; the biggest interface difference is the four-corner feedback system — two in and two out channels, normal flow + feedback flow in both directions."*

- **Chat completions = 2 channels** (prompt in → completion out), extraction, one-way.
- **The four-corner interface = 4 channels** (normal-in/out + feedback-in/out, both directions), mutual empowerment; `Input<T,TFeedback>` in, dual out — **feedback rides the input channel**, not just the result. Mutually-interruptible = a feedback-channel event (the arc's first requirement).
- **Chat completions is the degenerate projection:** drop the two feedback corners → chat completions. The current `summon`/`respond` is the *extraction projection* (feedback-free instance) — same "one is a special case of the other" discipline as `respond = collect(respondStream)`.

## Honest register
OpenAI is a 2-channel API, so the four-corner interface *wraps* it (normal corners → `codex/responses`; feedback corners → Zeta's addition, fully realized over Reticulum). The shape is right, the fill is partial. Typing the interface four-corner is the next principled slice — the OpenAI `summon` becomes the feedback-free instance of it.
