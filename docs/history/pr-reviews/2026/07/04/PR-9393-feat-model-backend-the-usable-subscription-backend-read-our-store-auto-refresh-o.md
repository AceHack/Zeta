## What

Aaron 2026-07-03: *"eventually this is how you'll all talk to each other over Reticulum; push forward with your suggestions."* The store-wiring slice that makes the account-login streaming backend usable end-to-end.

`chat(deps, messages)`: reads the token from **our** store (`~/.config/zeta/auth` via `TokenStore`), calls the ChatGPT backend (`codex/responses`, streaming SSE — confirmed live), and if the access token has expired (**401**) it **refreshes** via the `AuthProvider`, **persists** the rotation, and **retries once**. The caller just sends messages — no manual token handling. Injected transport + store: fake-testable, **no secret** (token read at the edge). Non-401 failures surface as-is (not retried).

This is the per-agent **"speak to a model"** primitive the Reticulum agent-to-agent layer sits on: messages-in → answer-out, one provider today (OpenAI subscription), many later.
