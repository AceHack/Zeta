Updates `pnpm` from 12.7.0 to 12.8.1
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/pnpm/pnpm/releases">pnpm's releases</a>.</em></p>
<blockquote>
<p>pnpm 12.8.1 fixes <code>pnpm install --frozen-lockfile</code> rejecting lockfiles with injected workspace packages that have peers, restores the executable bit on files of local directory dependencies, makes <code>pnpm dedupe</code> converge, and uses less CPU on many-core machines.</p>
<h3>Patch Changes</h3>
<ul>
<li>
<p><code>pnpm install --frozen-lockfile</code> no longer rejects a freshly generated lockfile when an injected workspace package has peer dependencies <a href="https://redirect.github.com/pnpm/pnpm/issues/16332">#16332</a>.</p>
</li>
<li>
<p>Executable files in a <code>file:</code> directory dependency or an injected workspace package keep their executable bit again. Since 12.8.0, pnpm installed these files without the permissions they have in their project.</p>
</li>
<li>
<p><code>pnpm dedupe</code> now reaches a stable lockfile when a package's peer suffix is long enough to be hashed. Before, each run could switch that package's key between the hashed and the spelled-out suffix, so <code>pnpm dedupe --check</code> always failed <a href="https://redirect.github.com/pnpm/pnpm/issues/16331">#16331</a>.</p>
</li>
<li>
<p><code>pnpm install --frozen-lockfile</code>, the default in CI, now uses less CPU on machines with more than 8 cores. Warm installs on many-core Windows machines got up to 10% faster. Frozen installs now link with at most 16 worker threads.</p>
</li>
<li>
<p><code>verifyDepsBeforeRun</code> no longer reports dependencies as outdated after a filtered install just because <code>pnpm-lock.yaml</code> has a newer modification time. It checks the lockfile against the packages that install put in place. Before, <code>pnpm run</code> reinstalled the whole workspace with lifecycle scripts on, for example after a Docker <code>COPY</code> brought in a lockfile with a newer mtime <a href="https://redirect.github.com/pnpm/pnpm/issues/16322">#16322</a>.</p>
<p>After a filtered install, <code>verifyDepsBeforeRun</code> now also checks that the install put the selected projects' dependencies in place. A <code>node_modules</code> directory alone no longer counts as proof.</p>
</li>
<li>
<p><code>pnpm run</code> and <code>pnpm exec</code> no longer install a project that has never been installed and has nothing to install. Such a project declares no dependencies, no peer dependencies that <code>autoInstallPeers</code> would fetch, and no install lifecycle scripts. The command now runs without writing <code>node_modules</code> or <code>pnpm-lock.yaml</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/16313">#16313</a>.</p>
</li>
<li>
<p><code>pnpm update -g --latest</code> now upgrades globally installed packages beyond their saved version ranges <a href="https://redirect.github.com/pnpm/pnpm/issues/16320">#16320</a>.</p>
</li>
</ul>

Updates `pnpm` from 12.7.0 to 12.8.1
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/pnpm/pnpm/releases">pnpm's releases</a>.</em></p>
<blockquote>
<p>pnpm 12.8.1 fixes <code>pnpm install --frozen-lockfile</code> rejecting lockfiles with injected workspace packages that have peers, restores the executable bit on files of local directory dependencies, makes <code>pnpm dedupe</code> converge, and uses less CPU on many-core machines.</p>
<h3>Patch Changes</h3>
<ul>
<li>
<p><code>pnpm install --frozen-lockfile</code> no longer rejects a freshly generated lockfile when an injected workspace package has peer dependencies <a href="https://redirect.github.com/pnpm/pnpm/issues/16332">#16332</a>.</p>
</li>
<li>
<p>Executable files in a <code>file:</code> directory dependency or an injected workspace package keep their executable bit again. Since 12.8.0, pnpm installed these files without the permissions they have in their project.</p>
</li>
<li>
<p><code>pnpm dedupe</code> now reaches a stable lockfile when a package's peer suffix is long enough to be hashed. Before, each run could switch that package's key between the hashed and the spelled-out suffix, so <code>pnpm dedupe --check</code> always failed <a href="https://redirect.github.com/pnpm/pnpm/issues/16331">#16331</a>.</p>
</li>
<li>
<p><code>pnpm install --frozen-lockfile</code>, the default in CI, now uses less CPU on machines with more than 8 cores. Warm installs on many-core Windows machines got up to 10% faster. Frozen installs now link with at most 16 worker threads.</p>
</li>
<li>
<p><code>verifyDepsBeforeRun</code> no longer reports dependencies as outdated after a filtered install just because <code>pnpm-lock.yaml</code> has a newer modification time. It checks the lockfile against the packages that install put in place. Before, <code>pnpm run</code> reinstalled the whole workspace with lifecycle scripts on, for example after a Docker <code>COPY</code> brought in a lockfile with a newer mtime <a href="https://redirect.github.com/pnpm/pnpm/issues/16322">#16322</a>.</p>
<p>After a filtered install, <code>verifyDepsBeforeRun</code> now also checks that the install put the selected projects' dependencies in place. A <code>node_modules</code> directory alone no longer counts as proof.</p>
</li>
<li>
<p><code>pnpm run</code> and <code>pnpm exec</code> no longer install a project that has never been installed and has nothing to install. Such a project declares no dependencies, no peer dependencies that <code>autoInstallPeers</code> would fetch, and no install lifecycle scripts. The command now runs without writing <code>node_modules</code> or <code>pnpm-lock.yaml</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/16313">#16313</a>.</p>
</li>
<li>
<p><code>pnpm update -g --latest</code> now upgrades globally installed packages beyond their saved version ranges <a href="https://redirect.github.com/pnpm/pnpm/issues/16320">#16320</a>.</p>
</li>
</ul>
