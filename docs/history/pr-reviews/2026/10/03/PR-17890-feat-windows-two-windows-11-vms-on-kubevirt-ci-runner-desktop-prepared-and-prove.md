## Description

## What

Two Windows 11 VMs for the cluster's KubeVirt, **prepared and proven short of the Windows ISO**, in namespace `windows-vms`:

- **`win11-ci`** - a headless-ish GitLab runner, tags `windows` + `zeta-windows`, `run_untagged: false`, for Windows builds (the FlowDent installers).
- **`win11-desktop`** - an interactive desktop: VNC (`virtctl vnc`) and RDP **through an SSH tunnel to a ClusterIP** (never a LoadBalancer).

Both are `runStrategy: Manual`: nothing boots until the owner supplies the Windows 11 Enterprise Evaluation ISO. No Windows image and no Microsoft URL is in the repo; the owner accepts Microsoft's terms and types the Administrator password themself (`read -rs`; it exists only in a Secret).

Runbook: `docs/ops/WINDOWS-11-VMS.md` (human steps, exact commands in order, serving the ISO from the PC incl. the firewall note, GUI access for Windows/Mac, which-step-failed table, eval limits, snapshots, known issues, proven/unproven).

## The point: nothing lands on the 120 GB root disk

Every claim names Longhorn explicitly (Filesystem mode); the namespace quota **refuses any claim on the default local-path class**, so a forgotten `storageClassName` is a rejected claim, not a DiskPressure eviction storm. Verified: all PVCs on `zeta-block-replicated` (disk1/disk2, 1 replica) or `longhorn` (12Mi TPM state); none on `zeta-block-local`.

## Proven (live) vs unproven

**Proven:** both VM specs boot to OVMF with Secure Boot, SMM, `host-passthrough`, Hyper-V enlightenments, a persistent TPM 2.0 and a virtio disk (and run together, sharing one ISO claim); a Linux guest with the same firmware/TPM spec saw Secure Boot enabled and a TPM whose NV state **survived a VMI restart**; a 512 MiB stand-in imported from the PC into Longhorn and hash-matched; a masquerade guest resolved and reached GitLab and the runner download bucket; the token Job minted the runner on GitLab 19.4.1 (record id 2, tags/untagged as required); `ssh -L` through the node to a ClusterIP works; screenshots and key presses work through `kubectl` alone.

**Unproven:** the Windows install itself, the OOBE skip, the runner registering, the "Press any key to boot from CD" prompt (the key press is proven on the firmware menu). Stated plainly in the runbook.
