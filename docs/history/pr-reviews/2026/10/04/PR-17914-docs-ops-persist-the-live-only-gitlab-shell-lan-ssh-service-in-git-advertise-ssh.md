## Summary

A Service applied by hand on the live cluster (`gitlab-shell-lan`, namespace `gitlab`) is what makes `git clone git@gitlab...` work from the LAN, and it was in no repo. This puts it, and the SSH port GitLab advertises, in git, with no network addresses hard-coded.

- **Service `gitlab-shell-lan`**: kept by the existing `discover` loop of `node-lan-hosts.yaml` as a fifth relay (same mechanism as `https-relay` / `ssh-relay` / `http-relay`): `externalIPs` = every LB address not already serving :2222, selector `app: gitlab-shell, release: gitlab`, `2222 -> 2222`. Addresses are discovered from the cluster, never in git, so a rebuilt cluster or another LAN gets the right set. The gitlab-exposure hook was rejected for this: it only knows the single `global.zeta.lanAddress` (the live Service carries all four LB addresses because the router can bind to any).
- **RBAC** for that one Service is declared in the gitlab Application's `extraObjects` (Role + RoleBinding to SA `node-lan-hosts`), not in cluster-hygiene: cluster-hygiene syncs at wave 20, before namespace `gitlab` exists, and a Role in a missing namespace would hold the wave.
- **`global.shell.port: 2222`** so the UI advertises the right clone port (chart 10.4.1 has no other coordinate; `gitlab-shell.service.externalPort` does not exist). `helm template` before/after against the Application's `valuesObject`: only `ssh_port 22 -> 2222` in the webservice/sidekiq/toolbox ConfigMaps (those three pods roll once, maxSurge 0, brief blip), the `gitlab-gitlab-shell` ClusterIP Service port 22 -> 2222 (targetPort unchanged), one inert nginx tcp-services key, and the new Role/RoleBinding. The gitlab-shell Deployment is not restarted.
- **Docs**: `docs/ops/GITLAB-SSH-LAN.md` (what/why, `~/.ssh/config` recipe, limits: LAN only, port 22 is the node's sshd not GitLab, host-key note) with an index of the other live-only items (KubeVirt `vmStateStorageClass` + CDI scratch class -> cross-referenced to `WINDOWS-11-VMS.md`, not duplicated; the flowdent.net website Deployment comes from fd-webclient's `k8s/flowdent-web/deployment.yaml`). Pointers added from `WINDOWS-11-VMS.md` and `SSH-FROM-OUTSIDE.md`.
