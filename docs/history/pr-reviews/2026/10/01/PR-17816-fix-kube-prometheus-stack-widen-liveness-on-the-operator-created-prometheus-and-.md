## Description

## What

`prometheus.prometheusSpec.containers` and `alertmanager.alertmanagerSpec.containers` now patch the operator-generated `prometheus` / `alertmanager` containers' liveness timing: timeout 5s, period 10s, failureThreshold 12 (115s stall tolerance, the figure the operator and node-exporter pods of this chart already carry).

## Why (measured, not inferred)

Constrained first-boot replica, run 36831938019 (main@15bbbc3433, 4 vCPU / 12 GiB, dev rung), `kubectl describe` of the operator-created pods:

| pod | probe | stall tolerance | Restart Count |
|---|---|---|---|
| `prometheus-...-prometheus-0` | `/-/healthy` timeout 3s period 5s #failure 6 | 28s | 6 |
| `alertmanager-...-alertmanager-0` | `/-/healthy` timeout 3s period 10s #failure 10 | 93s | 6 |

Both show `Last State: Terminated / Completed / Exit Code: 0` (each exits 0 on SIGTERM, so a liveness kill reads as a clean stop) next to `Unhealthy ... Liveness probe failed ... context deadline exceeded` events.

`liveness-kill-budget.ts` could not see them: `helm template` renders the `Prometheus` / `Alertmanager` custom resources, not the StatefulSets the operator builds.

## Mechanism

The CRDs have no probe field (checked in the 88.6.3 render). `spec.containers` entries named like an operator-generated container are strategic-merge patched onto it (prometheus-operator v0.93.1 `pkg/k8s/merge.go` `MergePatchContainers`), so only the three timing fields are named and the operator's `httpGet` survives. A name that matches nothing would APPEND a second container, so the names are pinned by the test.

## Tests

`src/Core.TypeScript/cluster/kps-operator-pod-liveness.test.ts`: 7 cases, 4 red without the patch (verified by reverting `Application.yaml`), a negative control pinning the unpatched figures at 28s / 93s, and a misnamed-container case.

## Not claimed

That this is why `kube-prometheus-stack` read `Degraded` in WP11 run 36832486494. That guest requests 9122m / 21822Mi at the metal rung against ~3250m / 9228Mi allocatable; the pods may never have been scheduled. This removes one measured, independent source of restart churn.
