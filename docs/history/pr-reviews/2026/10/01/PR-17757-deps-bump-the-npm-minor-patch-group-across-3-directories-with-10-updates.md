Updates `pnpm` from 12.6.0 to 12.7.0
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/pnpm/pnpm/releases">pnpm's releases</a>.</em></p>
<blockquote>
<p>pnpm 12.7.0 ships with <code>.nvmrc</code> and <code>.node-version</code> support in the global <code>node</code> shim, <code>pnpm install --allow-build</code>, <code>pnpm publish --publish-wait-timeout</code>, and <code>pnpm-workspace.yaml</code> created from the <code>workspaces</code> field. <code>pnpm install --force</code> no longer installs optional dependencies built for other platforms. This release also carries security fixes for bin shims on Nix, for lifecycle scripts of packages in a <code>storeDir</code> inside the workspace, and for <code>userAgent</code> placeholders in <code>pnpm-workspace.yaml</code>.</p>
<h3>Minor Changes</h3>
<ul>
<li>
<p><code>pnpm install --force</code> now keeps skipping optional dependencies whose <code>os</code>, <code>cpu</code> or <code>libc</code> do not match the host. It still refetches every package and lifts <code>engineStrict</code>. The new <code>forceIgnoresPlatform</code> setting restores the previous behaviour, installing optional dependencies of every platform under <code>--force</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/6133">#6133</a>.</p>
</li>
<li>
<p>The global <code>node</code> shim created by pnpm now uses the Node.js version from the nearest <code>.nvmrc</code> or <code>.node-version</code> file when the project does not declare a Node.js runtime in <code>devEngines.runtime</code> or <code>engines.runtime</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/4471">#4471</a>. The nearest directory with a Node.js runtime declaration decides the version. Within one directory, <code>package.json</code> takes precedence over <code>.node-version</code>, which takes precedence over <code>.nvmrc</code>. An <code>.nvmrc</code> value that only nvm can act on, such as <code>system</code> or a custom alias, is ignored.</p>
</li>
<li>
<p><code>pnpm install</code> now supports the <code>--allow-build</code> option to selectively allow or deny package lifecycle scripts and record them in <code>pnpm-workspace.yaml</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/15388">#15388</a>.</p>
</li>
<li>
<p>Added <code>pnpm publish --publish-wait-timeout &lt;milliseconds&gt;</code> to wait for published versions and their tarballs to become available from the registry. Set <code>publishWaitTimeout</code> in <code>pnpm-workspace.yaml</code> to configure a default. A value of <code>0</code> disables the check.</p>
<p>Recursive publishing confirms availability before publishing dependent packages. If confirmation times out, the command fails.</p>
<p>When <code>pnpm publish -r --report-summary</code> fails after some uploads were accepted, the summary file now lists those packages.</p>
</li>
<li>
<p><code>pnpm install</code> now creates <code>pnpm-workspace.yaml</code> from the <code>workspaces</code> field of the root <code>package.json</code> when the repository has no <code>pnpm-workspace.yaml</code>. The projects the field lists are linked on that same install. An existing <code>pnpm-workspace.yaml</code> is never changed. With <code>--ignore-workspace</code>, no file is created. If the <code>workspaces</code> field later differs from <code>packages</code> in <code>pnpm-workspace.yaml</code>, pnpm prints a warning <a href="https://redirect.github.com/pnpm/pnpm/issues/2255">#2255</a>.</p>
</li>
<li>
<p>When a project pins a pnpm version or a runtime that another pnpm process is installing at that moment, pnpm now waits a few seconds and then installs and runs a private copy of its own. It used to wait up to five minutes and then use the shared install directory without the lock. The private copy is removed once the command has run. <code>pnpm store prune</code> removes any private copy that a killed process left behind <a href="https://redirect.github.com/pnpm/pnpm/issues/15413">#15413</a>.</p>
</li>
<li>
<p>pnpm now keeps the blank lines between entries of <code>package.json</code> when it updates the file, for example on <code>pnpm add</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/5602">#5602</a>.</p>
</li>
</ul>
<h3>Patch Changes</h3>
<h4>Security</h4>
<ul>
<li>
<p>pnpm no longer expands environment variables in a <code>userAgent</code> set in a project's <code>pnpm-workspace.yaml</code>. A <code>userAgent</code> with a placeholder in that file is now ignored. Before this fix, pnpm sent the variable's value to the configured registry <a href="https://redirect.github.com/pnpm/pnpm/issues/15415">#15415</a>.</p>
</li>
<li>
<p>On Nix, a dependency's bin named like a system utility such as <code>sed</code> can no longer redirect a POSIX bin shim or the <code>pnpm</code>, <code>pn</code>, <code>pnpx</code>, and <code>pnx</code> launchers. The shims and launchers now ignore <code>node_modules</code> and relative <code>PATH</code> entries while they locate their own files. Installing again replaces the shims already in <code>node_modules</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/14883">#14883</a>.</p>
</li>
<li>
<p>pnpm no longer treats manifests inside its store, cache, state, or modules directories as workspace projects. Before, a <code>storeDir</code> inside the workspace could let lifecycle scripts of packages in the store run without <code>allowBuilds</code> approval <a href="https://redirect.github.com/pnpm/pnpm/issues/15033">#15033</a>.</p>
</li>
<li>
<p>Packages that run a lifecycle script are no longer hard-linked into the virtual store, so a build script can no longer rewrite the workspace source of an injected package or the store copy it was imported from <a href="https://redirect.github.com/pnpm/pnpm/issues/15483">#15483</a>.</p>
</li>
</ul>
<h4>Installing packages</h4>
<ul>
<li>
<p>Fixed <code>pnpm install</code>, <code>pnpm add</code>, <code>pnpm remove</code>, and <code>pnpm peers check</code> running out of memory when many packages share a missing peer dependency. This mostly affected projects with <code>autoInstallPeers: false</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/15362">#15362</a>.</p>
</li>
<li>
<p>pnpm no longer hangs for up to 5 minutes after a pnpm process was killed while setting up the pnpm version pinned in <code>packageManager</code> or <code>devEngines</code> <a href="https://redirect.github.com/pnpm/pnpm/issues/15360">#15360</a>, <a href="https://redirect.github.com/pnpm/pnpm/issues/15393">#15393</a>. The killed process left behind a lock that every later pnpm command in the project waited on. pnpm now detects that the process holding a lock is gone and takes the lock over at once. The same applies to the locks pnpm takes while installing a managed runtime or writing the global bin directory. Two pnpm processes that are both still running keep waiting for each other as before.</p>
</li>
<li>
<p>Requests to a registry or tarball server whose TLS certificate fails verification now fail at once. Such requests were retried for more than a minute without any output <a href="https://redirect.github.com/pnpm/pnpm/issues/9134">#9134</a>.</p>
</li>
<li>
<p>On macOS, pnpm now falls back to its bundled CA roots when system trust evaluation is unavailable, such as in a sandbox or when macOS cannot create an SSL policy for a registry connection. Installs failed or crashed on the first registry request in that case. Custom <code>ca</code> certificates are now honored directly <a href="https://redirect.github.com/pnpm/pnpm/issues/15329">#15329</a>, <a href="https://redirect.github.com/pnpm/pnpm/issues/14461">#14461</a>.</p>
</li>
<li>
<p><code>pnpm install</code> now caps concurrent connections to a proxy at 50 sockets by default <a href="https://redirect.github.com/pnpm/pnpm/issues/15280">#15280</a>. It also immediately retries transient connection resets when downloading package archives.</p>
</li>
<li>
<p><code>pnpm install</code> now reuses a package already present in the store when an existing lockfile entry satisfies the dependency, avoiding registry requests that fail without authorization <a href="https://redirect.github.com/pnpm/pnpm/issues/2522">#2522</a>.</p>
</li>
<li>
<p>Installing or adding dependencies no longer fails when a previously installed local tarball file was deleted from disk <a href="https://redirect.github.com/pnpm/pnpm/issues/8367">#8367</a>.</p>
</li>
</ul>
