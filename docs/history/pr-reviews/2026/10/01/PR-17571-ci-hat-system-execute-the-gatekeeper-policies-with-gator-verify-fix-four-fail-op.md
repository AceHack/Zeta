## Description

## What

Nothing in CI had ever **executed** the Rego in `full-ai-cluster/k8s/applications/hat-system/policies/` (the seven ConstraintTemplates are the only Gatekeeper/Rego policies in `full-ai-cluster/` and `agentic-organization/`). The kind lane proves they compile and apply, `hat-constraint-roster.ts` proves the sync Config feeds what they read, and `hat-conflict-symmetry.test.ts` *models* one rule from its text. This PR runs them with `gator verify`, which is Gatekeeper's own offline tester.

- **Pin**: `gator = "3.23.1"` in `.mise.full.toml`, the same release as the gatekeeper chart. It is locked in `mise.full.lock` with mise 2026.6.12 (the version `linux.sh` pins), and the digests match GitHub's asset digests. Upstream ships no Windows gator, and that gap is recorded as a `PARTIAL_COVERAGE` reason.
- **Suites** (`full-ai-cluster/k8s/tests/gator/hat-system/`): 47 cases. Every policy has must-violate and must-admit cases. Conflict-of-interest covers **both binding orders** for policy-admin/executor and executor/hat-designer, with the committed seed hats as inventory.
- **Runner** (`src/Core.TypeScript/cluster/gator-verify-hat-policies.ts`):
  - Splits each two-document policy file, because gator reads only the first document.
  - Renders `{{now±Ns}}` placeholders, because three policies compare against `time.now_ns()`.
  - Refuses to run when coverage is incomplete (a policy with no must-violate or no must-admit case) or when the gator and chart versions differ. When gator is missing it exits 2, meaning nothing ran.
- **Job**: `lint (gator hat policies)` is drift tier (not in `gate (required)`'s needs). A declared build-graph leg, `leg:gator-hat-policies`, selects it for changes to the policies, seed hats, suites, chart pin and runner. `.mise.full.toml` is already in `always`.

## Found by executing the Rego (fixed here)

All four are the same shape: a comparison against a missing field is *undefined*, so the `violation` rule does not match, and the request is admitted.

| policy | defect |
|---|---|
| 02-max-bindings | `b.status.phase != "Revoked"` is undefined on a binding the operator has not reconciled yet, so those bindings were not counted. With the operator down, the per-wearer cap never fires. |
| 03-conflict-of-interest | Same defect, in both the forward and the reverse rule. Unreconciled conflicting bindings were invisible. |
| 04-quorum | `count(spec.cosignedBy)` is undefined when the optional field is left out, so a quorum-gated hat could be bound with **zero** signatures. |
| 07-no-supervisor-cycles | The bare Hat inventory lookup is undefined when no Hat is synced, so the rule failed open and even `supervises: [self]` was admitted. The fix keeps a literal path so `hat-constraint-roster.ts` still sees the read. |

## Mutation check

`gator-verify-hat-policies.test.ts` plants **17 defects**, one at a time, in a copy of the policies. Every one turns the real gator run red (exit 1). An unmutated control exits 0.
- Deleting 03's reverse-direction rule turns **5 of the 11** conflict cases red, including `holds-policy-admin-binds-executor-denied-by-reverse-rule`.
- One mutant survived the first pass: dropping 05's `oldObject.status.phase == "Warmup"` check. A case was added for it (a status refresh on an already-Active binding inside the window must be admitted).
- One candidate mutant, dropping 07's `object.union` overlay, turned out to be *equivalent*: the path from `sup` back to `name` never uses `name`'s own edges. It was left out rather than counted.

Without gator the mutation half skips in the hermetic TS lane. In the gator job, `ZETA_REQUIRE_GATOR=1` makes a missing gator fail instead.

## TS model test: kept

`hat-conflict-symmetry.test.ts` stays, as defence in depth:
1. It runs in the **blocking** hermetic lane, and the gator job is drift tier.
2. It derives conflict pairs from the catalogue, while the gator suites name fixed pairs.

Its header now names the retirement condition: the gator job is promoted to the required gate and its suite derives pairs from the catalogue.
