## Description

## What

The `web` Blueprint declared port 8080 and ran `nginx:1.27-alpine`. That image's config (registry blob, linux/amd64) says `ExposedPorts {"80/tcp"}` and has no `User`, so a Deployable rendered `containerPort`, Service `targetPort` and HTTPRoute backend all on 8080 while nothing listened there. No probe existed, so the pod read Running while serving nothing. Reported by another agent; verified here from the image config.

## Fix

- `web` now runs `docker.io/nginxinc/nginx-unprivileged:1.29-alpine` (ExposedPorts 8080/tcp, User 101): the port stays, the image moves. 1.29-alpine is already pulled for mimir's gateway, so no new image enters the lane.
- `web` gains a readiness probe on 8080 so a future image/port mismatch reads NotReady instead of Running.
- The portal's `blueprint-agent.ts` draft and `demo.ts` seed carried the same nginx:1.27 + 8080 pairing; corrected.
- Ledgers keyed on the image string moved with it: `image-source-provenance.json` (one entry, hand-applied from a measured anonymous probe -- a local `--refresh` downgraded unrelated GHCR rows from `found` to `absent` because my token lacks `read:packages`, so that run was discarded rather than committed), `lane-footprints.json`, `image-resolvability.json`.

## Test (fails without the fix)

`full-ai-cluster/platform-controller/src/blueprint.test.ts` -> "library Blueprints serve on the port they declare": a table of image listen ports from registry configs, a check that every declared TCP port is one the image listens on (an image with no row FAILS), the rendered containerPort/targetPort/probe for `web`, and a control proving the pre-fix pairing is reported. Game Blueprints are env-configured, so for them the check is env port == declared UDP port. Verified red on the parent `blueprints.yaml` (2 failures), green here. Other Blueprints checked for the same class: postgres (5432) and the three game servers are consistent.

## Not verified

Nothing was run on a cluster. Separately noted, not changed here: the `postgres` Blueprint defaults `PASSWORD` to `change-me` (same in the portal blueprint-agent draft); fixing that needs the controller to mint a Secret, which it deliberately never creates.
