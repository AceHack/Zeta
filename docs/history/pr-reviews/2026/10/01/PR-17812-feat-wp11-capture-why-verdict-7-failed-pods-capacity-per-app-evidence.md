## Description

## What

Run 36832486494 failed WP11 verdict 7 (26/48 Synced+Healthy) and named the 17 unconverged Applications, but the serial log says nothing about *why*. This adds `zeta_wp11_cluster_diag` to `zeta-first-boot-k3s-verify.nix`:

- captured **once mid-run** (API still answering) and **once at the end** on a verdict-7 failure, after a bounded wait for the API (the old per-app dump fired into a k3s restart: 4 of 10 dumps were `connection refused`);
- nodes, requests vs allocatable, `get pods -A -o wide`, a Pending-reason census, `describe` (state/requests/Events tail) + `logs --previous` for the worst non-Ready pods, `kubectl top` (soft), Warning events, ArgoCD conditions/failed tasks/non-Healthy resources per unconverged app;
- three states (`captured` / `failed` / `did-not-run`) in the verdict JSON as `clusterDiagnostics`; bounded by line budget, per-section cap, line width, wall-clock deadline; every skipped section named; read-only; returns 0 on every path; mid capture time comes out of the roster budget.
- pressure block: k3s journal tail no longer drowned in `left-over process` narration; adds a `k3s-exits` timeline.

## Tests
