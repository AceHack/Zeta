## Description

## Evidence
WP11 run 36858893664 (with the LB range staged, #17814): verdict `lbPool` PASS -- Application `cilium-lb-ipam-pool` exists and `CiliumLoadBalancerIPPool zeta-lb-pool` lists `10.0.2.240-10.0.2.250` -- yet the Application read Progressing, then Degraded. Its only workload is Job `gitlab-lan-address`, whose pod sat in `PodInitializing` for the whole run (initContainer `wait-for-gitlab-application`, `kubectl wait --for=create applications.argoproj.io/gitlab --timeout=24h`). The WP11 envelope excludes GitLab, so that Application never exists.

## Fix
Annotate the Job `argocd.argoproj.io/ignore-healthcheck: "true"` (Argo CD docs/operator-manual/health.md "Ignoring Child Resource Health Check in Applications"). It drops this one child from the Application's health; the pool object is what the Application now reports. A failed Job remains visible as a failed Job and as GitLab keeping its sentinel address.
