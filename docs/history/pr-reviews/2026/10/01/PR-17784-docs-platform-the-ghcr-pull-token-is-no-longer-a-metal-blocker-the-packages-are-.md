## Description

## What

`full-ai-cluster/INJECTION-POINTS.md` and the two platform pod specs say the platform images are PRIVATE (anonymous GET -> 401, measured 2026-08-22) and conclude that unattended metal bring-up of `platform` is not achievable. That premise no longer holds.

**Measured 2026-10-01**, token-less `ghcr.io/token` exchange then a manifest GET on `:latest`: `zeta-platform-controller`, `zeta-portal` and `zeta-orleans-silo` all return **HTTP 200**. `k8s/image-source-provenance.json` has recorded all three as `artifact: public` since 2026-09-22, so the registry-side fact predates this note. `hat-system-operator:placeholder` still answers 401 (replicas 0, nothing pulls it).

So the exit the section already named -- make the packages public, after which `imagePullSecrets` is inert -- was taken. A missing `zeta-platform/ghcr-pull` Secret is a kubelet warning, not an ImagePullBackOff.

## Change

A dated STATUS note on the INJECTION-POINTS section and on `platform/controller.yaml` / `platform/portal.yaml`; the original text is kept as the record of the 2026-08-22 measurement. **No behaviour changes.**

## Worth a follow-up (not touched)

The catalog row for `ghcr-pull` is still `**EXTERNAL**` / NOBODY, and `first-boot-replica.ts` parses those rows as operator-supplied credential gaps -- so the replica lane may still excuse a platform failure as a missing credential that nothing needs any more.

## Not verified

A metal node pulling these images: this is a registry-side measurement, not a cluster run. No test pins it because it needs the network. `bun test src/Core.TypeScript/cluster` shows no new failures versus the unchanged tree.
