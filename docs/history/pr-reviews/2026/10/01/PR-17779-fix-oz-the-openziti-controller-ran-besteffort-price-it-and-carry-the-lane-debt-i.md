## Description

## What

`ziti-controller` 3.3.1 renders `resources: {}` on its one regular container (nothing on its init container either), so the zero-trust fabric's only control-plane pod held a request of nothing: cpu weight at the kubelet floor of 2 and first in line for eviction -- the failure measured for the ArgoCD control plane in #17666. `missing-resource-requests.ts` has listed oz as ACTIONABLE since 2026-09-04.

## Fix

`resources` on the Application's valuesObject: requests 50m/128Mi, memory limit 512Mi, no CPU limit; one block, so both rungs are the same. The pinned chart accepts the key and renders it on the controller container.

## The honest pricing moves the arithmetic, so every number that quotes it moves, none rounded

| | before | after |
|---|---|---|
| dev lane | 1990m / 9868Mi | 2040m / 9996Mi (memory 780Mi over the 9216Mi budget) |
| metal over the dev cohort | 8140m / 16956Mi | 8190m / 17084Mi |
| all 50 Applications at metal | 13215m / 27659Mi | 13265m / 27787Mi |

This is what the pinned-debt register itself predicts ("pricing them will make this number worse before it gets better, and that is the point"). The debt is **carried, not absorbed by shrinking the request**, which would restore the BestEffort defect in the lane whose job is to catch it. Touched in lockstep: the `oz` row and the rendered snapshot at both rungs; the debt key `dev memory 9868>9216` -> `9996>9216` and its reason; `single-node-budget.json` rung-gap key and compute prose; the `[cite: lane-*]` anchors in `argocd-health-test.ts` that `reason-truth.ts` re-derives; and the literals in the storage-profiles / reason-truth / single-node-readiness / argocd-health-test / rendered-resource-requests tests.
