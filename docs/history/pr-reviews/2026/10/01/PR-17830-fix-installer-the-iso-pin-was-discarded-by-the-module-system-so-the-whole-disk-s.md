## What went wrong

Run 36870188468 (WP11 scoped dispatch) failed with `boot-medium=/dev/sda`: the boot medium was mounted from the WHOLE disk, which holds it O_EXCL and makes every partition (the ESP included) unopenable for the install. Not rare. WP11 USB-lane `boot-medium=` over every run since #17751 merged:

|---|---|
| 36856972760 | `/dev/sda` |
| 36865505620 | `/dev/sda` |
| 36870188468 | `/dev/sda` |
| 36858893664 | `/dev/sda1` |
| 36832486494 | `/dev/sda1` |

3 of 5 -- exactly what an unpinned by-label race predicts.

## Root cause: #17751's pin was inert

`installation-cd-base.nix:36` sets `fileSystems = lib.mkImageMediaOverride config.lib.isoFileSystems`: priority 60 on the whole option. The module system keeps or drops a *definition* of an option by its top-level priority before it looks inside it. #17751's `fileSystems."/iso".device = lib.mkForce "..."` is a default-priority (100) definition with the `mkForce` nested in the value, so it was dropped whole, and the evaluated `/iso` device stayed `/dev/disk/by-label/ZETA_INSTALL` -- the symlink that races. The udev rules were right; they created a symlink nothing mounted. Every check that "verified" the pin read source text, where the line is present and correct. (Found by the #17751 post-merge grade, which ran `nix eval`; I confirmed the priority rule by reading the pinned nixpkgs `c25784012c99` source. I could not run `nix` locally, so the merge outcome is argued, not measured here -- the new flake check is what measures it.)

## Fix

```nix
config = lib.mkIf hasIsohybridMbr {          # makeBiosBootable && makeUsbBootable
  ...
  fileSystems = lib.mkImageMediaOverride {   # same priority as the base: both definitions merge
    "/iso" = lib.mkImageMediaOverride {
      device = lib.mkForce "/dev/disk/zeta-install-medium";
    };
  };
};
```

- **Equal priority at both levels** so this merges with the base per mount point. `mkOverride 50` on the attrset would win and *delete* `/`, `/nix/.ro-store`, `/nix/.rw-store`.
- **Gated on the isohybrid MBR** (the thing that creates the LBA-0 partition). aarch64 builds without it: its GPT's only partition is the EFI image, nothing would claim the symlink, and the mount would wait out its timeout. It keeps by-label.
- **dm-/loop-/nbd- whole disks claim the symlink outright** (nothing can partition them), so a loop-presented ISO is not left with no claimant.

## Falsifiers that can see this class

- **flake check `install-medium-device-eval`**: evaluates the REAL `nixosConfigurations.installer` and `.installer-aarch64`; fails unless the evaluated `/iso` device is the symlink, `fsType`/`neededForBoot` survived, the base's other mounts are still present, both udev stages carry the claim rule, and aarch64 is untouched. Added to the named eval-only list in `build-ai-cluster-iso.yml`, so a green lane that never reached it is itself an error.
- **Model** (`install-medium-selection.ts`): now judges which `fileSystems` definitions survive the merge; a pin the base discards leaves by-label in the model, as the real eval did. With #17751's module the exact layout of the failed run (`sda` / `sda1` / `sda2`) yields `{sda, sda1}`; with this module `{sda1}`. **9 of 20 tests fail on the pre-fix module.**
- **Guest verdict** (`zeta_boot_medium_verdict`, `zeta-first-boot.sh`): prints `[..-boot-medium] verdict=` on every boot, from sysfs only (the kernel's `partition` attribute and a disk's partition children; never opens the device). `PARTITION` / `WHOLE-DISK-UNPARTITIONED` / `WHOLE-DISK-CLAIMED` / `NOT-MOUNTED` / `UNRESOLVABLE`. `WHOLE-DISK-CLAIMED` prints a loud banner and does **not** exit (the script's header forbids `exit 1`, and the ESP is still read through rung 4); `bootMediumShape` convicts on it before falling back to device names. Fake-sysfs bash parity suite pins it; a mutant that miscounts children dies.

## Source fix: evaluated, not taken

The LBA-0 partition is syslinux's `isohdpfx.bin` MBR template (`-isohybrid-mbr`); the `0xEF` ESP entry zflash's Windows flasher finds (`MBR 0xEF @ LBA 276`) is `-isohybrid-gpt-basdat` marking `boot/efi.img` inside the ISO, not an `-append_partition`. Deleting the duplicate means replacing nixpkgs' ISO builder (no hook for xorriso flags) and touching BIOS-USB, UEFI-USB and dd boot at once; no lane here measures BIOS-USB (every QEMU lane is OVMF). With the pin effective the duplicate label no longer reaches the mount. Recorded in the work item.
