## Description

## What

The weaviate chart's default `initContainers.sysctlInitContainer` renders a **privileged, root `docker.io/alpine:latest`** init container that only runs `sysctl -w vm.max_map_count=524288`. This PR disables it and makes the host provide the value instead.

## Evidence

- `helm template weaviate/weaviate 17.8.3` against this Application's own `valuesObject`: `initContainers` / `alpine` / `privileged` appear in the render before the change, **0 times after**.
- `alpine:latest` is on no bootstrap preload list and is unpinned (`image-resolvability.json`: `isLatestOrUntagged: true`). On a fresh install the pod cannot leave `Init:0/1` until an anonymous Docker Hub pull succeeds; a StatefulSet with `readyReplicas 0 != replicas 1` is `Progressing`, and an Application whose only complaint is a Progressing workload has **empty `status.conditions`** -- the signature of the open "weaviate Synced/Progressing, conditions empty" item in `usb-installer-first-boot-reliability/RESUME.md` section 4.
- **Register: candidate, not confirmed.** No live pod description exists, so this is the remaining mechanism the render shows, not a measured cause of that run.

## Change

- `weaviate/Application.yaml`: `initContainers.sysctlInitContainer.enabled: false`.
- `node-tunables.json`: host `vm.max_map_count` 262144 -> 524288 (the chart's own value; still satisfies OpenSearch's 262144 floor). Applies to the NixOS host and the CI runner through the existing single source.
- `node-tunables.test.ts`: pins both halves together. Fails on the old tree (key absent = chart default = enabled; host value below 524288).

## Not done / unverified

- No cluster run: whether weaviate then reaches Healthy on the installed disk is for the next WP11 dispatch to say.

- Generated snapshots (`lane-footprints.json`, `image-footprint.measured.json`, `image-resolvability.json`) still list `alpine:latest` for weaviate; they are dated measurements and `measure-lane-footprints --check` is documented as not a gate.
