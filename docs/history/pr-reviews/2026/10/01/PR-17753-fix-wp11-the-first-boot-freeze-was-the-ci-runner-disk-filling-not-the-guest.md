## Description

## What the "first-boot freeze" was

Run 36420588893's WP11 serial ends at `roster progress t=331s sample=5`. The **job log** says, in the same half-minute (14:17:12, phase 3 began 14:11:12):

```
##[warning]You are running out of disk space. ... Free space left: 0 MB
```

WP11's phase 1 had started with **14.3 GiB** free on the runner, against 52-55 GiB for every earlier QEMU lane in the same job. What ran in between was the two dispatch-only B0891 lanes (scenario 3 retention, scenario 4 path-fork), which leave ~38 GiB of qcow2/boot images in `b0891-*-run/`. The WP11 first boot writes ~26 GiB (k3s images plus the dev toolchain). When the host filesystem filled, QEMU's virtio default `werror=enospc` **paused the VM**. That is why nothing printed: no OOM line, no hung-task line, no pressure diagnostics. The guest was paused, not frozen.

The earlier run that did not freeze (36381850496) was an `only_wp11` dispatch. It ran no B0891 lanes and had 53.6 GiB free. That explains the "intermittent" behaviour: it depends on whether the dispatch is full or WP11-only, not on #17747/#17748/#17751.

## Changes

- **workflow**: a new `Reclaim B0891 disk images before WP11` step (dispatch/schedule, `always()`) deletes the B0891 images (their `*.log` files are already uploaded and are kept) and the unused preinstalled SDKs, and prints `df -h` before and after.
- **harness** (`qemu-full-install-test.ts`): every phase-3 progress line now carries the runner's free space. Below 256 MiB the phase fails with a named `RUNNER DISK EXHAUSTED` reason instead of a 75-minute timeout, and skips the 20-minute post-verdict toolchain wait. The phase-1 allocation warning no longer blames only mkfs.
- **zeta-dev-toolchain** (hardening for real nodes, **not** the cause of this failure): Nice/SCHED_IDLE only rank tasks inside the unit's own cgroup. `system.slice` carries k3s's `CPUWeight=1000` + `MemoryLow`, so the unit was weighted above every pod. It now runs in its own `zeta-background.slice` (`CPUWeight=idle`, `MemoryHigh=25%`, `MemoryMax=40%`).
