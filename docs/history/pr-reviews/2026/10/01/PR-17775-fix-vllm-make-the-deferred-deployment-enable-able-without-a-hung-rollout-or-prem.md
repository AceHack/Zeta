## Description

## What

`vllm` ships `replicas: 0` and manual-sync (local-models phase deferred), so its defects are latent: the day a maintainer sets `replicas: 1` on a GPU node is the first time any of them runs. Three, each provable from the manifest:

1. **No probes.** The Service routed to the pod as soon as it started, though vLLM does not listen until weights are downloaded and loaded (minutes to an hour for a 33B model on a cold cache), and a wedged engine was never restarted. Now: `startupProbe` on `/health` with a 3600s budget (360 x 10s) so a slow first pull is not liveness-killed (the slow-container failure the first-boot trajectory measured), then tight readiness and a 6 x 30s liveness tolerance.
2. **RollingUpdate on a GPU + ReadWriteOnce pod.** The surge pod asks for the same single GPU and the same RWO claim, sits Pending, and the old pod is never retired because the rollout waits for the new one -- any edit (a new `--model`) is a perpetual Progressing. Now `strategy: Recreate`, as the ollama chart already ships.
3. **`/dev/shm` at the 64Mi runtime default.** Now an 8Gi Memory emptyDir. *Standard remedy for a known PyTorch/NCCL failure, not reproduced here (no GPU node); the manifest says so.*

## Test (fails without the fix)

`src/Core.TypeScript/cluster/vllm-model-load-probes.test.ts`: all three probes exist and target a declared port; the startup budget (via `liveness-kill-budget`'s own `probeKillBudgetSeconds`) covers a >= 30 min cold load; liveness never exists without startup; `/dev/shm` is a Memory emptyDir. The Recreate rule is general -- any git-path Deployment mounting a ReadWriteOnce claim -- so the next workload of this shape is caught (today it inspects vllm alone). Verified red on the parent manifest (4 failures), green here. `bun test src/Core.TypeScript/cluster`: no new failures vs. the same tree without the change; the AMD rung override (`containers[0]`, docIndex 1) is index-stable and its live test passes.

## Deliberately not changed

- Image stays `vllm/vllm-openai:latest`: pinning needs a tag measured and re-priced in lane-footprints/provenance (a ~22 GiB image), a decision for whoever enables the phase.
- The default 33B fp16 model does not fit a single consumer GPU; a model choice left to the maintainer.
- No node toleration: `rung-overrides.test.ts` requires the AMD tree to contain no `nvidia` string, and no node is tainted by the repo's nixos modules.
