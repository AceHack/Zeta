## Question asked

Does a real operator-managed Postgres cluster with replicas exist for applications (CNPG? cockroach? hindsight pgvector?), with sane PVC sizing, backups, credentials and securityContext?

## What this PR does -- and deliberately does not do

It does **not** add a shared always-on cluster. CloudNativePG's model is one cluster per application, a shared one would be an appointed hub (manifesto section 1), and it would cost 750m / 1.5 GiB of requests on every install whether or not anything used it. Instead it ships the **template** a consumer copies (`k8s/examples/cnpg-postgres-ha.yaml`):

- 3 instances, `primaryUpdateMethod: switchover`, **preferred** pod anti-affinity (required would leave 2 of 3 Pending on one node)
- operator-minted credentials -- no password, no superuser access, no pre-supplied secret
- explicit requests + memory limit, no CPU limit; node-local storage per CNPG's shared-nothing guidance
- the same pinned PostgreSQL image as temporal-postgres (test requires equality)

The header states where HA stops: on one node it survives a crashed pod, a rolling update or a corrupted instance, **not** the node or its disk; replication is async by default; and **there is no backup** (replication is not one). Backup is the largest open gap: it needs an object store, a minted credential Secret and CNPG's barman-cloud plugin, none of which the tree provisions yet.

Kept under `k8s/examples/`, not `k8s/applications/`: inside the applications tree the cluster-pricing audits read a Cluster as 30Gi + 750m of demand no sync provisions (measured on the sibling KubeVirt template: three ledger tests failed).
