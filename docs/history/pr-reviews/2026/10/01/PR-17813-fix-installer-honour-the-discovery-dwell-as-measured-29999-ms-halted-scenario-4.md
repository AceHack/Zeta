## Description

Run 36832486494 scenario 4 (path-fork) timed out at 1800 s. Serial log: `discovery heard nothing in 29999 ms` -> `dwell-too-short` -> `[zeta-discovery] HALTED`, waiting for a keypress. WP11 in the same run heard nothing in exactly 30000 ms and bootstrapped.

- **Defect**: `probe.ts` slept once then re-read `elapsed()`; a timer can wake 1 ms early against `Date.now()`, so `decideClusterBoot` (correctly strict) refused. Fix is in the probe (bounded dwell top-up), not the admissibility check. Real operators on a silent segment hit the same halt.
- **Harness**: the zflash retention/path-fork lane lacked the `[zeta-discovery] HALTED` failure marker that `ci/qemu-full-install-test.ts` already had; a determined stop was served out as a 30-minute timeout.

Tests: `probe.test.ts` (fails with the top-up disabled), `installer-bail-marker.test.ts`. Locally 2 pre-existing `cli.test.ts` failures (`/bin/sleep`, `/bin/echo` on Windows).
