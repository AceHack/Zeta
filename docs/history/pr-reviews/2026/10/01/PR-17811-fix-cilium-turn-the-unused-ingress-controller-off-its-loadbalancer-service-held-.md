## Description

## What
`ingressController.enabled: true` rendered Service `kube-system/cilium-ingress` as `type: LoadBalancer`. ArgoCD reports a LoadBalancer Service with no `status.loadBalancer.ingress` as Progressing, and the Cilium LB-IPAM pool is install-time configuration that is legitimately absent when no range was supplied. So the CNI's own Application read Synced+Progressing with every pod Running.

Measured three times: k3d run 35924216557 (42 min at `<pending>`), first-boot replica run 36831938019, WP11 run 36832486494 (cilium at t=3221s). The earlier EndpointSlice-exclusion hypothesis (081M3BF6P31) did not cure it: in run 36831938019 the warning is gone (`conditions: []`) and cilium is still Progressing.

Nothing uses the Ingress surface (exposure is Gateway API, no Ingress of class `cilium` exists), so the Service only spent one of the installer's LoadBalancer addresses. Disabled in the Application and in the first-boot HelmChart that shares its release.
