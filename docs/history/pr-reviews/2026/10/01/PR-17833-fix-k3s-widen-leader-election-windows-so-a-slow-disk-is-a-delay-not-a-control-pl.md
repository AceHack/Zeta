## Description

Implements the first recommendation of `docs/ops/WP11-UNCONVERGED-CENSUS-2026-10-01.md` (#17832).

**Defect (measured, WP11 run 36875247887):** k3s.service restarted 19 times and every exit is a lost lease (`controllermanager.go:368/265 "leaderelection lost"`). Upstream treats a lost lease as fatal and k3s runs those components in one process, so one slow etcd renewal under a CPU/IO burst (CPU PSI 84%, IO PSI 96%, etcd apply 3-5 s) took the whole control plane down onto the same starved disk, repeatedly. Any first boot under a burst is exposed, not just the CI guest.

**Fix:** `k3s-server.nix` sets `leader-elect-lease-duration=90s`, `renew-deadline=60s`, `retry-period=10s` on kube-controller-manager, kube-scheduler and kube-cloud-controller-manager (upstream 15/10/2). `lease > renew > retry * 1.2` holds (client-go refuses to start otherwise).

**Cost (also in the module):** on a multi-server cluster a crashed leader is replaced after up to 90 s instead of 15 s; running pods are unaffected, reconciling and scheduling new pods pause for that long. A single server has no failover to delay.

**Not claimed fixed:** k3s's own election (`leaderelection lost for k3s` / `k3s-etcd`) is compiled in with no flag; etcd's own timeouts are untouched. The next WP11 `k3s-exits` timeline says whether these three were the ones that mattered.

**Test:** `k3s-leader-elect.test.ts`: all three components carry exactly one of each flag, equal windows, strictly wider than upstream, the ordering invariant unit-tested including failure cases, agents untouched; 11 cases fail with the renew flags deleted. It is a source-level assertion, not a Nix eval: `k3s-server.nix` cannot be evaluated standalone and no Nix is available where this was written. Does not touch the roster or `wp11-ci-envelope.json`.
