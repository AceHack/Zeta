## Description

## Summary
Audit of root/ownership/mode defects on the installed system after #17723. Work item 081M3TRMTXW087G0R003E10WDE.

- **First-session marker dir root-owned.** `zeta-first-session.nix` created `/var/lib/zeta-first-session` as `root:root 0755` under a comment claiming the hook writes the marker with sudo; it does not. The conductor writes the marker + journal as the logged-in user, so both were EACCES and the credential adventure re-ran on every interactive login. tmpfiles now creates (`d`) and repairs (`Z`) it owned by the conductor's user.
- **Restored credentials written 0644.** `applyPlan` runs as root under umask 022: tokens world-readable, a persisted ssh private host key that sshd refuses, a NetworkManager keyfile NM ignores. A named secret set is written 0600; an old 0644 copy is rewritten, not skipped as already-present.
- **Wifi restore threw EISDIR** (manifest path is the `system-connections` directory). That killed the unit under `set -e` and skipped the ownership pass, leaving earlier writes root-owned in `~`. The blob is now filed as a keyfile inside the directory; the unit holds the restore exit status until after the ownership pass, which drops `-maxdepth 4` and uses `chown -h`.
- **`sudo HOME=... -u uid cmd`** in the installer's `claude login`/`codex login`: sudo stops option parsing at the first non-option word. Options first.

## Tests (each fails without its fix)
- `cluster/first-session-state-dir-nix.test.ts` (verified red on the old module)
- `cluster/zeta-creds-restore-ownership-nix.test.ts`
- `installer/zeta-creds-restore-modes.test.ts` (wifi/path/mode-table assertions run everywhere; POSIX mode-bit assertions are skipped on win32 and run on the Linux CI leg)
- `installer/sudo-option-order.test.ts`

## Not verified
POSIX mode assertions were not executed locally (Windows author machine); no nix evaluation or booted ISO. The sudo option-parse claim is from sudo's documented synopsis, not from running sudo.
