## Description

## Why (follow-up to #17846 and #17851)

#17851's stale-render gate was measured NOT to work (lane run 36955944272): ArgoCD re-renders a retried/running operation from the source it STARTED with, so a gate that fails the operation fails on every retry (eight in a row), each time rendering the sentinel. Wave 20 (#17835) was also not a fix (run 36951220893). The install-time Job can only patch the Application after ArgoCD's first sync has begun, so **nothing the operation renders or waits on may depend on the pin**.

## Fix

The release no longer renders the Gateway/HTTPRoutes and the `gitlab-pin-fresh` gate is removed. A **PostSync hook Job `gitlab-exposure`** reads the address from the LIVE Application (`global.zeta.lanAddress`) and applies the Gateway + routes from the template in ConfigMap `gitlab-exposure`. A hook completes when its own Job does, not when the Gateway is Programmed, so a stale operation finishes, the pin makes the Application OutOfSync, the next operation rolls GitLab onto the real hosts, and the hook re-applies the same objects (idempotent).

- No resolved LB range (empty or 192.0.2.x): creates nothing, exits 0 (GitLab stays reachable in-cluster).
- Application unreadable: exit 1 (ArgoCD retries) -- exposure that silently did not happen is the failure this removes.
- The objects are not ArgoCD-tracked (nothing to prune, nothing to read OutOfSync). A node that has them from the previous release: the hook strips their tracking annotation (ArgoCD 3.5.2 tracks by annotation).
- RBAC: Gateway/HTTPRoute verbs in `gitlab`; `get` on `applications/gitlab` in `argocd`; nothing wider.

## Tests

`gitlab-exposure.test.ts` (a)(c)(f): the release renders no Gateway/HTTPRoute; the hook's script is **executed** under bash against a stub `kubectl` -- sentinel/empty creates nothing, a real address creates `gitlab-lan` at exactly that address with web + registry routes, three legacy objects untracked, unreadable Application exits 1. (c) now asserts the Gateway the hook creates is the address GitLab advertises, inside the pool, on several LANs. `lb-ipam-pool.test.ts` (e) and the rendered-placeholder baseline updated. The `gitlab-live-proof` lane runs on this PR; blocking a-f, a6 and a7 must pass before auto-merge is armed.
