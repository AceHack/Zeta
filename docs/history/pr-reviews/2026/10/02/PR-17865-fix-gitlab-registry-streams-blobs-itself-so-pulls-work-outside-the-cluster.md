## Description

## Why
MEASURED on the live cluster: image pulls from `registry.flowdent.net` fail for every client outside the cluster (containerd `ErrImagePull DeadlineExceeded`; Docker `unexpected status from GET ... http://blob-store-seaweedfs-all-in-one.object-store.svc:8333/gitlab-...`). The registry's S3 driver answers blob GETs with a 307 to a presigned URL on the in-cluster SeaweedFS name, which no outside client (the node included) can resolve.

## What
- `registry.storage.redirect.disable: true` (verified by rendering chart 8.7.0 with `helm template`: renders `storage.redirect.disable: true` in the registry config; the only diff vs. before is that block plus the ConfigMap checksum).
- `global.appConfig.object_store.proxy_download: true`, pinned. The chart default was already `true` for the consolidated block and every typed store (artifacts, lfs, uploads, packages), so this is a guard against a chart bump, not a behaviour change.
- `gitlab-exposure.test.ts` test (i): both new tests fail on the previous Application, pass now.
- `docs/ops/GITLAB-REGISTRY-PULLS.md`: symptom, cause, cost (registry pod now carries blob bytes).

## Not proven
No cluster access: that an outside client can now pull is unverified until ArgoCD syncs this to the live node.
