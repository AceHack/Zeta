## GitLab datastores M1: a dedicated PostgreSQL 17 and Valkey 7.2, created beside the bundled ones

Why: GitLab 18.0 dropped PostgreSQL 14/15, 19.0 dropped PostgreSQL 16 and Redis 6, and chart 10.0 removes the bundled
PostgreSQL/Redis/MinIO "with no replacement" (see `docs/ops/GITLAB-UPGRADE.md`). This instance runs bundled PostgreSQL
14.8 and Redis 6.2.16 (archived `bitnamilegacy` images). One move to PostgreSQL 17 (tested from GitLab 17.10, required
by 19.x) before the 18.2 stop covers both majors.

This PR only CREATES the replacements. GitLab keeps using the bundled instances; nothing it reads changes.
The cut-over (quiesce, dump, restore, repoint `global.psql` / `global.redis`) is the next change, opened only after the
17.11 stop is live and its migrations are finished.

- `gitlab-runner.extraObjects` (the release's object list, wave -2): CNPG `Cluster gitlab-rails-db` (PostgreSQL 17.11
  `minimal` image already on the node, C.UTF-8, `pg_trgm`/`btree_gist`/`amcheck` created at initdb as superuser) and
  `StatefulSet`/`Service` `gitlab-valkey` (valkey 7.2.14, `volatile-lru`, AOF, the password GitLab's chart already
  minted in `gitlab-redis-secret`).
- Dedicated rather than shared (`postgres-shared`, `redis`): a GitLab migration cannot contend with
  flowdent_prod/staging, and Sidekiq queues cannot meet another tenant's eviction policy.

**Tried on the live cluster before this PR** (same objects, `kubectl apply`): both reach Ready, and it found two defects the
render cannot show, both fixed here: `en_US.UTF-8` does not exist in the minimal image (initdb: `invalid locale name`;
now `C.UTF-8`, the repo's own collation rule) and `gitlab-redis-secret`'s key is `secret`, not `redis-password`.
Restore rehearsal: the verified pg_dump of the 17.7 database restores into the new database in ~20 s (798 tables owned by
`gitlab`, 3179 schema migrations, 9 projects / 3 users / 101 pipelines, equal to the source).

Ledgers touched, each because a test named it: `image-source-provenance.json` (+ the valkey image), `METAL_NOT_SEEDED` and
the secret baseline (`gitlab-redis-secret` is minted by the chart's shared-secrets hook), `single-node-budget.json` prose
(node-local claims 110 -> 122 GiB), and the `gitlab-live-proof` lane now applies the `cloudnativepg` operator so its
Application sync can reconcile the Cluster.

Not covered: WAL archiving / barman backup of this database (needs a per-namespace S3 credential this release does not
have; GitLab's own backup is the backup, see the doc).
