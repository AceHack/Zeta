## What

The 2026-10-02 runtime fixes on `node-5b2dfa` (no reinstall) now have installer / NixOS equivalents, so the next ISO carries them and a fresh node needs no hand-applied workaround. Work item `081M3YY6TWX087G0R003HZTVWQ`.

| # | Runtime fix | Installer-level equivalent in this PR |
| --- | --- | --- |
| 1 | `iptables -I nixos-fw ... --dport 443` from the DaemonSet | `nixos/modules/node-public-https.nix`: TCP 443 open on every node (server + agent). **80 stays closed** (nothing on the host listens; HTTP-01 :80 goes through Cilium eBPF on the LB address). Unconditional on purpose |
| 2 | bind-mounted `/etc/hosts` pinning gitlab./registry. | `nixos/lib/public-hosts.nix` + `modules/injected-public-hosts.nix`: those two names resolve to the node's own loopback relay, from the same `/etc/zeta/public-domain` the TLS module reads. **Loopback, not the Gateway's LB IP**: that address is cluster state a static line cannot know and would shadow (first-match). The GitOps relay stays the right home for the address-following part |
| 3 | router binds the forward to the wrong one of the node's addresses | ADR + docs: the router forwards to the **node**; `https-relay` + host relay are base GitOps (already merged). Options not taken (announce-only, sharing-key, DMZ, open 80, pin the Gateway IP) are recorded with reasons. zeta-install.sh completion banner, DOMAIN-SETUP.md, INJECTION-POINTS.md no longer say "forward to the gateway's LoadBalancer IP" |
| 4 | disk pressure | `k3s-process-protection.nix` (both roles): kubelet image GC 75/65 (default 85/80 sat ON the imagefs eviction line), `container-log-max-files=3`. Eviction-hard map untouched. Dedicated containerd partition / larger root stay the owner's reinstall-time decision |
| 5 | no sudo | already: console-password policy (`default` is the repo default). New: opt-in `zeta.operatorSudo.sshAgentAuth` (**OFF**), `NOPASSWD` rejected, `docs/ops/OPERATOR-SUDO-BREAK-GLASS.md` (no-wipe recovery) |
| 6 | registry redirect off | verified: committed GitLab Application carries `redirect.disable` + `proxy_download`; the install-time render patches hostnames only (test pins both). No change needed |
