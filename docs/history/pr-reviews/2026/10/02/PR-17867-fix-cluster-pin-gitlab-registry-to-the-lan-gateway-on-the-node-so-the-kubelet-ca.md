## Description

## Why
MEASURED on the live node: containerd could not pull `registry.flowdent.net/flowdent/fd-core:<sha>` (`dial tcp 66.10.240.234:443: i/o timeout`, then `failed to fetch oauth token: Post https://gitlab.flowdent.net/jwt/auth`). The node resolves those names to the public IP and the router has no TCP 443 forward. Pods use CoreDNS and are fine; the kubelet uses the host resolver, and on NixOS `/etc/hosts` is a read-only symlink (OS layer, needs a rebuild + sudo).

## What
`cluster-hygiene/node-lan-hosts.yaml`: a DaemonSet (own `privileged` namespace) that bind-mounts a hosts file pinning **only** `gitlab.*` / `registry.*` to the Gateway's LB address. Both come from the live Gateway, nothing is hardcoded. `api.*` is deliberately not pinned (still Azure until cutover). GitOps only, no ISO or OS change; re-asserted every 30s, so it survives a rebuild or reboot.

## Proven
Applied live: staging `fd-core` pod went `ImagePullBackOff` -> `Running`, `/health` returns `Healthy`. `node-lan-hosts.test.ts` runs the apply script against a fake host (7 pass). Mutation-checked: removing the guard fails the incident test.

## Added: the node's :443 relay + firewall rule
The AT&T router can only port-forward to a device (the node, .79), never to the Gateway's LB IP (.240). MEASURED: nothing listened on node:443, and once a relay did, `nixos-fw` still dropped it. A `forward` container (socat, `NET_BIND_SERVICE` only, TLS passthrough, target discovered from the Gateway) relays :443 to the gateway, and `apply` asserts `-I nixos-fw 1 -p tcp --dport 443 -j nixos-fw-accept` every tick. Proven live: node:443 -> 401 on the LAN; external HTTPS to gitlab./registry.flowdent.net returns 302/200 from 7 regions. Cost: client source IPs at the gateway become the node's. OS-layer fix for the next ISO: `networking.firewall.allowedTCPPorts = [ 443 ]`.

## Incident worth knowing
My first live version mounted a hosts file holding only the block (no `localhost`/`control-plane`) because it read `/etc/hosts` through `/proc/1/root`, where the absolute NixOS symlink resolves against the container's root. I unmounted it within minutes and restored the node. Fix: read via `nsenter` in the host mount namespace, plus a guard that refuses to mount a base lacking `localhost`.

## Not proven
Survival across a real `nixos-rebuild`/reboot. The NixOS-module equivalent (`networking.hosts`) is the durable fix for the next ISO.
