## Description

## What
Both Let's Encrypt ClusterIssuers get a second solver: `dns01.cloudflare` (Secret `cloudflare-api-token`, ns `cert-manager`, key `api-token`), selected **only** by label `zeta.io/acme-solver: dns01`. The existing `http01.gatewayHTTPRoute` solver is unchanged and has no selector, so it stays the default. The Secret is operator-created on the node and never committed.

## Premise correction (measured in cert-manager v1.21.1 source)
The Certificates are not owned by ArgoCD: cert-manager's gateway-shim creates them from the Gateway annotation, and the shim resets labels set on them (`certNeedsUpdate` / `updateCrt.Labels = crt.Labels`). So the opt-in label goes on the **Gateway** `zeta-public-gateway`, which the shim copies to its Certificates (all four names move together). Deleting a stuck Certificate to bypass the ~1h backoff is recreated by the shim, not ArgoCD. No `ignoreDifferences` added (not needed by the reasoning in the doc; unobserved live).
