## Description

## What

The shared CNPG cluster `postgres-shared` has 97 usable connection slots; every flowdent role was unlimited and fd-core used Npgsql's default pool of 100 per pod. A staging burst at 256 clients drew 120 `remaining connection slots are reserved` and 66 `too many clients` (53300) errors, and could have starved production.

- `full-ai-cluster/k8s/flowdent/database-budget.yaml`: one budget ConfigMap (prod role limit 60 / pool 15, staging 20 / pool 8, 15 slots of headroom) and an idempotent ArgoCD PostSync-hook Job `flowdent-db-tune` that appends the Npgsql pool options to each `flowdent-db` connection string and sets `connectionLimit` on each managed role (CNPG would revert a bare `ALTER ROLE`). The Job refuses a budget that violates the inequalities.
- `flowdent-platform.test.ts` section F pins `(replicas + surge) x pool + health-reserve <= role limit`, `sum(limits) <= max_connections - 3 - headroom`, `max_connections == cluster.yaml`, least-privilege RBAC, and the no-secret-in-argv/env posture. Verified the first two fail when the numbers are broken.
- `docs/ops/POSTGRES-CONNECTION-BUDGET.md`: measurements, formula, before/after proof, why `max_connections` is not raised, why no Pooler, rollback.

## Measured finding worth reviewing

fd-core `/health` (`AddDbContextCheck` -> `CanConnectAsync`) opens a new physical connection per call and bypasses the pool (30 calls = +30 sessions in `pg_stat_database`). `Maximum Pool Size` therefore does not bound it; the role limit does, and `health-reserve` leaves room for it. The fix belongs in fd-core (pooled `SELECT 1`), documented as an open item.

## Live state (applied 2026-10-02 with this exact manifest, before merge)

`rolconnlimit`: flowdent_prod 60, flowdent_staging 20. Both `flowdent-db` Secrets carry the pool options. Staging restarted, prod rolled one pod at a time (`maxUnavailable: 0`, `/health` 200 on every probe). Load test to 1024 clients on staging: 0 server-wide 53300, staging peak 13 connections (limit 20), prod peak 4, prod `/health` 200 on all ~215 samples. The staging rate-limit override used for the test was removed.

## Not proven

The hook's first run through ArgoCD (applied by hand live); prod scaled past `max-replicas` (a declared ceiling, not an enforced one); real metal under a real prod burst. `local-checks.ts` failures on this Windows host are in files this diff does not touch (agentic-org manifests path handling, cross-verify, graphql-transport lint, twitch-ai, mathjs); the one that was mine (R5 absence-assertion census) is fixed.
