## Description

## Why
MEASURED on the live cluster: the node's :443 relay (socat) re-originated every connection from the node, so the app's **per-IP** rate limiter saw ONE address for every outside client. After one client sent 100 requests, probes from 7 countries all got 429; the login/refresh budgets are per IP too. Azure's ingress passed the real address, so this was a regression of the cutover. (Real traffic was light, so nobody was throttled yet.)

## What
`node-lan-hosts` replaces the relay with an **HAProxy SNI router** (`edge`):
- the **API hostnames** (`api.<domain>`, `api-staging.<domain>`) are TLS-terminated at the edge and forwarded as HTTP with the **real client address** in `X-Forwarded-For` (a client-supplied one is discarded; the real address crosses the internal hop via PROXY protocol);
- every **other hostname** is passed through to the public Gateway, byte for byte;
- `discover` writes the two API certificates (memory-backed volume; RBAC reads exactly those two Secrets) and the listener->namespace upstreams; **a failed read keeps the previous set**; reloads run only after `haproxy -c`, an invalid config is refused.

## Two live bugs in the first draft, both pinned by tests
1. The internal hop was an abstract unix socket; a reload cannot re-bind it, so **every reload failed and the old passthrough-only config silently kept serving** (the shared bucket came back). It is loopback TCP now.
2. `fe_edge` logged every connection; now `no log`.

## Proven
Live on production through :443: client A limited at its own 100 requests (with a spoofed `X-Forwarded-For`), client B on a different source address untouched 6/6, outside probes 200 (`server: Kestrel`, i.e. terminated at the edge). `node-lan-hosts-edge.test.ts` runs both scripts against stubs; mutation-checked (re-introducing the unix socket, or dropping the XFF discard, each fail a test). 108 related tests pass. Provenance ledger refreshed for `docker.io/library/haproxy:3.0-alpine`.

## Not proven
A real haproxy parse in CI (the live node ran `haproxy -c` on the generated config; a broken config exits 1), a reload under load, and that the router keeps forwarding to an address this edge serves (the `https-relay` Service from #17867 covers every node address).

Accepted risk: the PROXY-protocol hop listens on 127.0.0.1:18443; pods cannot reach host loopback, only host-local processes can, and on this single-tenant node that is accepted and documented in the manifest.
