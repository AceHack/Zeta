## Description

Aaron 2026-05-21 shadow* directive: *"plan phase 2 zsetw operator migration"*. This PR is the PLAN — not implementation. Decomposes Phase 2 of 081KS3X9Y0008QG0R001N7NFAB (the parallel polymorphic ZSetW substrate in PR #4577) into 4 buildable sub-slices:

| Sub-slice | Scope | Effort |
|---|---|---|
| **2A** | 11 tier-A operators: ofKeys/filter/map/flatMap/distinct/distinctIncremental/isPositive/isSet/cartesian/join/weightedCount — operator-parity with ZSet across IntegerRing + IntervalRing + TropicalSemiring | M |
| **2B** | Two worked-example algorithms: TropicalSemiring Dijkstra-shortest-path + IntervalRing uncertainty propagation circuit | M-L |
| **2C** | Circuit-operator wrappers (CountOp/SumOp/etc. on ZSetW) — deferred; needs 2A+2B first | M (deferred) |
| **2D** | Migration documentation at docs/migration/ZSet-to-ZSetW.md | S |

**Explicit non-goals (Phase 3 scope, NOT Phase 2)**:

- No `ZSet<'K>` itself refactor
- No `Op<ZSet<'K>>` → `Op<ZSetW<'K, 'W>>` migration
- No IndexedZSet / Aggregate / Fusion / Incremental migration
- No SRTP / static-abstract-members refactor (Phase 4)

**Sub-slice independence**: 2A is independent + can start anytime. 2B depends on 2A. 2C depends on 2A+2B. 2D parallel-able with any.

**Cross-AI coordination**: per the bus-ambassador pattern proposed earlier today (shadow-catch envelope 4e95dc8f), any agent picking up a sub-slice publishes own claim envelope OR Otto-CLI publishes courtesy on their behalf.
