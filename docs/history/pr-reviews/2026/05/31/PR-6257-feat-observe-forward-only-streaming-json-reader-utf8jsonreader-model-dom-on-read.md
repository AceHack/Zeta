## Description

## What

A **forward-only, pull-based, zero-copy JSON reader** for the Rust observe crate — the .NET `Utf8JsonReader` model — acting on operator observations 2026-05-31 (the JSON parser must be "one pass forward only ... never needs the whole object at once ... deserialize infinite json streams" at "aspnet json speed"; DOM is DoS-susceptible → "trusted situations only"; "the dom one can be built on the forward pass only one"). Grounded in the operator's SOAP/XML-era DOM lessons (the `XmlReader` → `Utf8JsonReader` lineage).

> **Stacked on #6255** (the Rust oracle crate). Merge #6255 first; this rebases clean onto main after.

## The reader (`json_reader.rs`)

- **Forward-only, single pass.** `read()` yields one `JsonToken` per call, `None` at EOF. Never materializes the whole document.
- **Constant memory.** State is bounded by nesting **depth** (a small container stack), not document size. Proven: a 50k-element array streams with `depth()` pinned at 2.
- **Zero-copy.** Strings are `Cow<'a, str>` — `Borrowed` (zero-copy) unless escapes force `Owned`; numbers are raw `&'a str` slices (lossless; `number_as_f64()` parses on demand).

## DOM built on the reader, trusted-only

- `ZetaJsonParser` (DOM) is **rebuilt on `JsonReader`** — one tokenizer; the reader is the primitive, the DOM a consumer (the standalone recursive `Cursor` is gone).
- **SECURITY note:** the DOM materializes the whole tree + recurses on depth → a DoS vector → **trusted input only**. Use the forward-only `JsonReader` for untrusted/unbounded input. The serde adapter (also a DOM) carries the same caveat.

## Hexagonal preserved

`JsonReader` / `JsonToken` / `Json` / `JsonParser` are our ports; serde is the adapter; nothing outside the adapter names a serde type.
