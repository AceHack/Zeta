## Summary

Phase 1 (read-only audit baseline) of B-0171 OpenSpec catch-up. Aaron
2026-05-03 verbatim: *"openspec which we are way behind on, that's
suppsed to be our source of truth lol, if we were to delete everying
other than it"*.

The "if we deleted everything but OpenSpec, the project would be lost"
test fails today. This PR lands the research baseline showing where
the gaps are and the recommended Phase 2 catch-up sequence.

- Inventory: 6 capability specs (`circuit-recursion`, `durability-modes`,
  `lsm-spine-family`, `operator-algebra`, `repo-automation`,
  `retraction-safe-recursion`) totaling 1953 lines, 56 requirements,
  136 scenarios. `openspec/README.md` line 84 is stale (says "Three"
  — actual is 6).
- Spec-vs-code alignment check on 4 sampled specs: existing specs
  DO describe shipped behaviour at the surfaces sampled. Problem is
  not drift, it's absent specs for everything else.
- Gap table covering 17 untyped F# code surfaces (~12k LOC), 11
  CLAUDE.md disciplines, 13 GOVERNANCE.md rules, and 9
  ALIGNMENT.md clauses with no spec coverage.
- Coverage estimate today: ~15-20% of load-bearing substrate is
  reconstructable from OpenSpec alone.
- Recommended Phase 2 sequence (10 capabilities, P0 batch first).
  **Top-5 to ship first:** `alignment-floor`,
  `substrate-durability-classification`, `circuit-runtime`,
  `graph-substrate`, `agent-loop-refresh-discipline`.

## Out of scope

- Authoring or modifying any spec file. Phase 2 work, separate PRs
  per capability per `openspec-expert` workflow.
- Exhaustive drift-scan of existing capability specs. That is
  `spec-zealot`'s job per GOVERNANCE.md §28 drift-detection clause.
- Updating `openspec/README.md` capability count. Should land with
  the first Phase 2 PR.
