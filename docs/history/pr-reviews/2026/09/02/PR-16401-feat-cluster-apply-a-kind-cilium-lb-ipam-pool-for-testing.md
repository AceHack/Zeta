# Summary

We need a LoadBalancer implementation for testing. This is not MetalLB: `PLATFORM-ARCHITECTURE.md` §4.1 gives that slot to Cilium LB-IPAM, and `servicelb` is disabled so a second LB would fight it.

The metal Application (`cilium-lb-ipam`) stays **excluded**. Its pool is pinned to `192.168.1.240-250`. Applying it on kind would assign IPs ArgoCD calls Healthy that nothing can route, and `selfHeal` would overwrite a kind-local pool. Kind `--cni cilium` instead applies a bring-up alias — the same two CRs, on `172.18.255.200-220` (high end of kind's typical docker-bridge `/16`). Assignment is the goal (`status.loadBalancer.ingress`); L2 ARP on `eth0` is extra and is not claimed as "routable from the runner".

weaviate is **not** lifted. Its LIFTS WHEN now names a live kind `--cni cilium` run that shows both LoadBalancer Services receive an address from this alias. The file existing is not that measurement. k3d is a follow-up: it helm-installs Cilium too, and this range is not its network.
