## Summary

Aaron 2026-09-02: lead with ReFS-like resilience so crash recovery is a category we can win; update metadata pointers instead of copying bits; DB and FS must understand each other's cache; policies exist so CoW cannot 10× the volume. FoundationDB-style chaos must cover the **filesystem**, not only the database.

- **D9 pointer-not-copy** — ReFS block cloning / allocate-on-write is the Beacon, not a port. Jumprope 1-byte edit reuses most chunk ContentIds.
- **D10 one cache authority** — do not double-buffer (OS page cache + mutbuf + DB pool). `Buffered` is one class.
- **D11 CoW amplification bound** — `rolling(2)` of 5 versions leaves 3 reclaim-eligible. This is why the policies exist.
- **D12 crash DST for FS *and* DB** on the same `IFileSystem` door. Still `toy` until first-product PR12.

Honesty: not a v0.9 FS ship, not crash-safe, not ReFS-class repair on one disk.
