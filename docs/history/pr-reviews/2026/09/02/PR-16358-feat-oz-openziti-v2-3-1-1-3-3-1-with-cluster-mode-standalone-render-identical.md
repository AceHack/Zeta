## Description

## The decision you asked about

`ziti-controller` **3.2.0** took appVersion **1.7.2 → 2.0.0** (a *server* major) and
made `cluster.mode` **mandatory** — the chart refuses to render without it. That
refusal is why the pin sat still. (The earlier note put the boundary at 3.2.1; it's
**3.2.0**.)

The four modes: `standalone` · `cluster-init` · `cluster-join` · `cluster-migrate`.

**`standalone` is not the lesser branch — it's the faithful one.** appVersion 1.7.2
had no cluster concept at all, so one controller is exactly what this Application
has always deployed. Choosing it changes no behaviour; it says out loud what was
previously implicit.

## Measured, not argued

Rendering **3.1.1** and **3.3.1** against this Application's own `valuesObject` at
`--kube-version 1.35.6` gives **byte-identical object sets**:

> Secret 1 · ConfigMap 1 · PersistentVolumeClaim 1 (`oz-controller`, 3Gi, longhorn)
> · Service 1 · Deployment 1 · Bundle 1 · Certificate 8 · Issuer 5

with the image the only difference: `openziti/ziti-controller 1.7.2 → 2.0.2`.
**No storage row, resource row, or lane total moves.**

`cluster-init` also renders clean (checked) — it additionally wants
`cluster.trustDomain` and `cluster.nodeName` for the SPIFFE ID. A `cluster-migrate`
mode exists, so **standalone is not a one-way door** if clustered Raft is wanted later.

Behind-upstream **6 → 5**.

## Six fixtures moved with the pin, and two are worth reading

- **`an acknowledgement whose pin has moved stops applying`** had to change from
  `oz@3.1.1` to `oz@3.3.1` — which is that test's own thesis working on itself.
- **`THE BAR`**'s historical `adminSecret` proof **refused to run rather than skip**,
  because the schema snapshot no longer carried 3.1.1: *"the proof could not run"*
  fails there, correctly. Re-pointed at 3.3.1 rather than answered by retaining a
  schema for a version nothing deploys — the claim (`adminSecret` is a key
  ziti-controller has **never** had in any published version) was never about one
  version, so re-pointing preserves it exactly.
