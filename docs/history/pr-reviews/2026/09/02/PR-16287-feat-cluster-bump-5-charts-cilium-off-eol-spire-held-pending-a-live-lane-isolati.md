## Two false positives in my own checker

Both found by reading the diffs instead of acting on them:

- **Quoting.** cert-manager appeared to drop **six CRDs**. It does not — the newer chart quotes `metadata.name` and the older does not, so an unstripped compare read every quoted resource as removed-and-re-added. Counted CRDs directly in each render: **6 and 6**.
- **Base64.** kube-prometheus-stack appeared to lose `repeat_interval: 12h`. It does not — the alertmanager config moved into a base64 Secret, which a substring check cannot see through. Decoded it; the value is there.

Corrected, every removal is benign and named at its own pin: cilium loses one `Endpoints`; cert-manager a legacy tokenrequest `Role`/`RoleBinding`; longhorn a consolidated webhook `Service`; kube-prometheus-stack five grafana **Helm test** fixtures; mimir the bundled nginx gateway, which nothing in the tree references; spire a `ConfigMap` the server now writes at runtime while still creating the Role and mounting it by the same name.

## argo-workflows is REFUSED — the find of the batch

`0.42.5` renders **8 CRDs**. `2.0.3` renders **zero** — with `--include-crds`, and with `crds.install: true` as the chart's own default. Bumping it would leave the cluster **with no Workflow CRDs at all**. Left at 0.42.5 until how v2 expects CRDs to be installed is understood.

## The inert-key tool caught mimir — correctly by its rule, wrongly in fact

It refused three storage keys (`compactor`/`ingester`/`store_gateway` `.persistentVolume.storageClass`) because mimir-distributed 6.2.0 ships them **commented out** in `values.yaml`, and a commented line is in neither the values nor a template's `.Values` reference.

Rendering 6.2.0 with our own `valuesObject` emits **`storageClassName: longhorn`** on the PVCs — the keys work. Acknowledged **with that render as counter-evidence** rather than silenced. (At 5.5.1 the same render emitted both `longhorn` *and* an empty `storageClassName`, so 6.2.0 is the cleaner of the two.)

## Update — spire held, pending a live-lane isolation

**The first failure this exercise could not have predicted from a render.** Batch 1's thirteen charts passed `live kind included Synced+Healthy`. Batch 2's five went **red** on it, with 93 other checks green.

The job's log was not retrievable through the API (no annotations; the run id 404s), so this is an **isolation run, not a diagnosis**. Four charts go on; **spire is held at 0.24.2**; the live lane adjudicates.

**Why spire is the one held** — a hypothesis stated as one: this pin's own `WATCH` note, written when it was bumped, predicted exactly this shape. `0.30.x` flips a webhook `failurePolicy` default toward **fail-CLOSED**, and a fail-closed admission webhook whose backing service isn't ready **blocks admission** — precisely how unrelated Applications fail to reach Synced+Healthy while every static check stays green.

**The control is clean:** reverting to 0.24.2 restores exactly batch 1's spire state, which passed this proof with `spire-crds` already at 0.6.1. One variable moves.

Landing here: **cilium 1.20.1** (off EOL), **cert-manager v1.21.1**, **longhorn 1.12.1**, **kube-prometheus-stack 88.6.2**.
