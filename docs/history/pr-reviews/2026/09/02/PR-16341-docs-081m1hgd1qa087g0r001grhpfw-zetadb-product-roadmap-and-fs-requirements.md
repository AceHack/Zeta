## Summary

ZetaDB product map, combined with the existing ROADMAP / ZetaFS first-product spec, plus the filesystem requirements the database actually needs.

- **ZetaDB is the whole database**, not Feldera sitting on Postgres. Feldera's Postgres usage is **connectors** (input query + experimental output). Their compute storage is their own posix/memory backend. We wire the log, the views, SQL, and the wire.
- **Feel is Flink + Reaqtor** (unified batch/stream, durable standing Rx queries). Feldera is the **DBSP competitor**.
- **WAL is truth; tables are views.** Event sourcing as the source of truth, same as treating the WAL as truth.
- **SQL is a ZetaDB package**, not a compiler inside `Zeta.Core`. Opens the 2026-04-17 WONT-DO revisit without reversing the *why*.
- **Protocol adapters** (Postgres/MySQL/own wire) so teams migrate without a flag day. Compatibility at the wire, not the storage.
- **ZetaFS is optional as a product** until it beats host FS + `GroupCommitDiskDeltaLog` on small writes. Auto-batch already exists on a host directory. The FS must win on fork, CAS, `Regen`, erasure coding, per-entity policy, typed durability.
- **Honesty:** this is not a v0.9 FS ship. Crash recovery stays `toy` until PR12. Freeze still does not use the ferry (D4, named).
