## The move exposed a false-INERT bug in our own guard

`inert-valuesobject-keys` reported `loki.storage.bucketNames` as governing
**nothing**. It does not — the chart marks it `required` (it *refuses to render*
without it) and the rendered ConfigMap carries `bucketnames: loki-chunks` from
exactly that value. **Deleting it on the guard's word would have silently removed
the log store's object-storage configuration.**

Cause: sprig **`dig` puts the dict LAST**.

```
dig "storage" "bucketNames" "chunks" "" .Values.loki
```

`index`/`get`/`pluck` take the collection *first*, which the existing branch
matches. `dig`'s path segments come *before* `.Values`, so every `dig` reach in
every chart read as unreferenced. A false **INERT** is the direction that gets a
live setting deleted — worse than a missed defect.

Fixed with a named control; the control kills the mutation that removes the branch
(**57/1** mutant, **58/0** restored).
