## Description

## What

Turns your policy into a check.

> "we never want to stay on projects who don't push updates, this is a security hazard." — Aaron, 2026-09-02

A chart whose **publisher has stopped shipping** now fails a check, separately
from ordinary "behind".

## Why a check and not a column

`ace/currency.ts` has carried `isSuspicious()` — *"true when a verdict warrants
attention beyond ordinary staleness"*, matching exactly `dormant` /
`behind-dormant` / `unpublished` — since it was written. **Measured 2026-09-02:
its only consumer in the entire tree was its own unit test.** A predicate that
names the dangerous class while nothing acts on it is the vacuity class with the
safety label already printed on it.

## The worked instance, where every existing check was green

`headscale`, pinned to `charts.gabe565.com` (a third-party *personal* chart repo,
still alive — it publishes adguard-home — that stopped updating its headscale
chart 559 days ago):

- the pin **resolves** → `audit-chart-target-revisions` green
- the chart **renders** → nothing in the cluster tree complains
- it is at the **newest chart version** → currency report says **0 behind**
- and it freezes us at appVersion **v0.25.0** while the project shipped **v0.29.3**

Four server releases of unshipped fixes behind an all-green tree. The report even
labels the row `DORMANT` and then prints it beside the healthy ones, because
*behind* is what it gates on. The label was right; nothing consumed it.

## A real bug found in the checker, and the test kept

The first implementation matched `"UNPUBLISHED"` — **not a member of `Verdict`**
(the value is `PIN-UNPUBLISHED`), so that branch could never fire. A check unable
to detect a class it claims to cover, written inside the checker for exactly that
defect. Fixed, with the regression test that catches it.

## What it deliberately does NOT do

| | |
|---|---|
| judge "behind" | **no** — stays a report; a gate on it would be red from birth and learned-to-ignore |
| pass on `unreachable` | **no** — exit 2, never 0. A dormancy detector reporting "none found" when it could not read the registry is the defect it exists to catch |
| pin the silent-day count | **no** — it would go stale daily and teach re-stamping. The acknowledgement pins the **repoURL**, so it dies the moment we relocate — which is when it should be re-argued |

## headscale is carried, not fixed, and why

**Measured: headscale ships no official Helm chart** — the project repo has
`packaging/` and `nix/`, and its README never mentions Helm. So every option is a
third-party packager and "relocate to the official chart" is not available. That
makes it a real migration decision (best-maintained community chart vs. in-repo
manifests over the project's own image), tracked by `081M1HH1ERN087G0R00309EG9D`
with a lift condition — debt with a deadline, not a settled answer.
