## Description

## What

An Application that **names a Secret nothing creates** now fails a check instead
of a cluster.

## The break this is written from was mine

The redis → valkey migration (#16292) declared:

```yaml
auth:
  usersExistingSecret: redis-auth   # create via Sealed Secret / Vault
```

That comment is true of metal and **false of the dev lane**, and nothing checked
the difference. `applyDevBootstrapSecrets` mints the credentials Applications
expect to find already present — grafana's admin Secret, ziti's — and redis was
never added to it. redis then sat **OutOfSync/Progressing** in the included proof
on main, found by Riven reading a schedule run, not by a check.

Same shape the observability roster taught (change an Application, re-derive what
is keyed to it) but for a **runtime** dependency, which is worse: a stale
generated file fails in CI in seconds; a missing Secret fails after a cluster has
been built and an Application has tried to sync.

## I got the first version wrong in the acquitting direction

It matched `existingSecret` only — so it missed `oz`'s
`customAdminSecretName: ziti-admin-credentials`, a Secret the roster **does**
mint. I noticed because the minted count came back **1** when the roster mints
**2**.

A guard that recognises one spelling doesn't prevent a class of defect; it
prevents that defect written one way, and the next arrives spelled differently.
The rule is now the **shape** of the key — anything ending in `existingSecret` or
`secretName`. Mutation **M1** restores the narrow pattern and is killed.

## What it deliberately does not do

It does **not** decide whether an Application is applied in the dev lane. Three
sources of truth already exist for that (`DEV_EXCLUDED_REASONS`, the root
catalogue's `excludeGlob`, `isExcludedFromIncludedProof`) and a fourth
reimplementation would be a copy that drifts. So an excluded Application's Secret
is carried in the baseline **with its exclusion named**, and the entry goes stale
the day the exclusion lifts.

## The four carried references

| key | why | lifts when |

| `redis\|redis-auth` | Riven's **#16362** mints it on the same roster | that PR lands — this entry is **designed to fail as stale** immediately |
