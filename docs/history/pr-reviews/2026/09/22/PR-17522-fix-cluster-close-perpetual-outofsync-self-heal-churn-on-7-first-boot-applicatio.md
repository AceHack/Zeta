## Summary

Live run 35713533700 ("live kind included Synced+Healthy proof") failed the post-Healthy soak on `argo-workflows left Healthy/Synced (OutOfSync/Progressing)`. The same run (and 35628762464 for openziti) showed every app below stuck perpetually `OutOfSync` on one resource, and with `selfHeal: true` that is a real re-sync loop on a real cluster, not a display artifact.

Two distinct root causes, both matching the same upstream ArgoCD mechanism family (`argo-cd#11143` / `#18568`), plus one unrelated render-randomness defect:

| App | Drifting field | Cause | Fix | Citation |

| cockroachdb | `StatefulSet/cockroachdb` `.spec.volumeClaimTemplates[0].{apiVersion,kind,status,metadata.creationTimestamp}` | ServerSideApply-emulated diff introduces apiserver-conversion-defaulted fields | Dropped `ServerSideApply=true` (StatefulSet 4690B, 55x under the 262144B last-applied-configuration cap) | [argo-cd#11143](https://github.com/argoproj/argo-cd/issues/11143), this repo's own `spire/Application.yaml` 2x2 |

| argo-workflows | `CustomResourceDefinition/{workfloweventbindings,workflowtasksets}.argoproj.io` — server-defaulted `spec.conversion`/`spec.preserveUnknownFields` | same conversion-as-default mechanism, CRD-level | `argocd.argoproj.io/compare-options: ServerSideDiff=true` — dropping SSA is NOT viable (largest CRD is 227552B, already most of the 262144B cap before the last-applied-configuration annotation doubles it) | [argo-cd#11143 comment thread](https://github.com/argoproj/argo-cd/issues/11143) — multiple independent reporters confirm `ServerSideDiff=true` closes this; stable since ArgoCD 3.1.0 (cluster runs chart 10.8.0) |
| openziti-controller (oz) | `Secret/ziti-controller-trust-domain` | chart's `getTrustDomain` helper falls through to `randAlphaNum 32` on every render when `cluster.trustDomain` is unset (ArgoCD's repo-server has no cluster for `lookup`) | Set `cluster.trustDomain: openziti.zeta.local` — the exact fix this file's own prior note named as `LIFTS WHEN` | Measured: two `helm template` runs now byte-identical (were different every time before) |

Every StatefulSet fix was verified by rendering the app's own committed `valuesObject` against its pinned chart and inspecting the JSON-encoded object — none declare `apiVersion`/`kind`/`status`/`metadata.creationTimestamp` in `volumeClaimTemplates[]`, confirming ArgoCD (not the chart) introduces them. The `ServerSideApply`-drop fix mirrors a MEASURED precedent already in this repo (`spire/Application.yaml`'s own 2x2: an `ignoreDifferences` rule cannot reach `creationTimestamp: null` because ArgoCD introduces it downstream of the normalizer the rule runs against; dropping SSA does).

Also extends `runSoakPhase`'s failure message (`src/Core.TypeScript/cluster/argocd-health-test.ts`) to name the OutOfSync **resource**, not only the Application: `status.resources[]` → `ArgoApplicationSnapshot.outOfSyncResources` → `ApplicationVerdict.outOfSyncResources` → appended in brackets by `soakRegressionFailure`. Run 35713533700's `##[error]` line named only the Application; the drifting CRD was legible only several thousand log lines later in a separate diagnostics dump.
