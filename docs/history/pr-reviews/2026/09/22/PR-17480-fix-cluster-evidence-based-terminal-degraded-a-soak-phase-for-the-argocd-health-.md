## Summary

`src/Core.TypeScript/cluster/argocd-health-test.ts`'s live-kind-included lane (081KSXN940008QG0R000SCP2H1) has been red on the daily schedule since 2026-09-19 (runs 35456502519, 35524259964, 35628762464). Run 35628762464 aborted at ~T+10min of a 2400s budget on `asserted Application is Degraded (kube-prometheus-stack=Synced/Degraded)` while its pods were simply `PodInitializing` -- still pulling images / provisioning a Longhorn PVC. The existing abort rule (`confirmedDegradedTerminalFailure`) trusted two consecutive Degraded polls (~15s) as terminal, which cannot distinguish an ordinary first-rollout Degraded blip from a genuinely dead workload.

**Task A -- evidence-based terminal Degraded**, replacing the sample-count rule:
- `podsFromPodsJson` / `PodSnapshot` -- full live pod status parsing.
- `podsBelongingToApplication` -- attributes pods to an Application via `spec.destination.namespace` (ArgoCD-declared ground truth, no extra API call), with `app.kubernetes.io/instance` disambiguating the four namespaces this catalogue's Applications actually share. An unmatched pod in a shared namespace is attributed to **neither** Application -- fail-closed.
- `podBlockingReason` -- hard evidence waiting cannot fix: CrashLoopBackOff at/above a restart threshold, ImagePullBackOff/ErrImagePull, CreateContainerConfigError, FailedScheduling on insufficient resources.
- `podStillProvisioning` -- the task's explicit NOT-terminal roster: Pending/ContainerCreating/PodInitializing/Init:N/M, or Running-but-not-Ready inside a startup grace window.
- `degradedApplicationTerminalEvidence` / `evidenceBasedDegradedTerminalFailure` -- terminal only on hard evidence (fires on the FIRST poll -- more fail-fast than the old rule for a genuinely dead workload) or a 600s ceiling with no pod still provisioning.
- Wired into `waitForApplications`, replacing the two-poll call; the extra pod-list `kubectl` call only fires when an Application is actually Degraded.

**Task B -- a soak phase** ("does it crash-loop?"):
- `runSoakPhase` (new `--soak-sec` flag, default `0`/disabled) polls after the all-Healthy verdict and fails on any container `restartCount` increase or an Application leaving Healthy/Synced for more than one poll, naming the pod/container/last termination reason+exit code.
- STARTUP-RESTARTS report (`startupRestartEntries`): containers with `restartCount>0` at the all-Healthy moment (ordering smells that self-healed).
- A ratchet (`ratchetStartupRestarts`, same discipline as `full-ai-cluster/k8s/tests/ratchet-app-failures.ts`, keyed by `(app, container)` never by pod name/hash) against `src/Core.TypeScript/cluster/startup-restart-baseline.json`, committed **unseeded** -- the first live run with `--soak-sec` names the real entries.
- Wired into the `live-kind-included` job's `--run` invocation (`--soak-sec 300`).

40 new unit tests, including fixtures reconstructed from the measured false positives (kube-prometheus-stack PodInitializing, openziti Init:0/1), every required terminal case, and mutation-sanity pairs (each terminal assertion paired with the same input just under its threshold).
