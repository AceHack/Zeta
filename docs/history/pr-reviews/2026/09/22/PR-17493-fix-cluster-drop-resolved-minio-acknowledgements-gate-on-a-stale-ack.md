## Summary

Follow-up to #17475 now that #17486 landed (GitLab's bundled `minio` subchart disabled, object storage repointed at seaweedfs) — `minio/minio` and `minio/mc` no longer render anywhere in this tree.

- Removed both entries from `ACKNOWLEDGED_MISSING` in `image-resolvability.ts`. The register is now empty — its own header records that emptiness as the mechanism working, not an omission.
- `staleAcknowledgements()` now **gates** rather than merely reporting. An acknowledgement whose target is no longer even a current `missing`/`arch-missing` finding is dead weight either way (a fix landed without the entry being removed — exactly this register's own history — or a reference that never matched anything), and it's cheap to check and cheap to fix, so it no longer sits quietly in a report section forever. Wired into `main()`'s exit code for both offline and `--refresh` modes.
- Threaded an injectable `register` parameter through `isGatingRow` / `gatingRows` / `counts` / `formatReport` (previously hardcoded to the production `ACKNOWLEDGED_MISSING`). This was needed, not just tidy: the existing "acknowledged does not gate" tests were pinned to the exact minio references the production register happened to carry at the time — the same fragility this cleanup is itself evidence of. Tests now inject their own fixture registers.
- Kept the "real register" test block meaningful now that it's empty: one test asserts the register's current (empty) state explicitly rather than the describe block silently vanishing, and a separate test proves the shape-invariant checks would actually catch a malformed entry (against a fixture) rather than leaving two now-vacuous for-loops as the only coverage. Added dedicated tests for `staleAcknowledgements()` itself (matches a current finding / target resolved ok / never referenced / empty register).
