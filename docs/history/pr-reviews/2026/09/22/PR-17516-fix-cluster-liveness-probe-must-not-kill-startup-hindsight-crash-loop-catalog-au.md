## Summary

- Fixed the measured defect: hindsight's `api` container was killed by its own liveness
  probe mid-migration on PR #17505's "live kind included" soak phase
  (`soak phase detected instability after the all-Healthy verdict:
  hindsight/hindsight-api-... [api] restartCount 1 -> 2`, `Liveness probe failed: ...
  connection refused` while alembic migrations were still running). `api.livenessProbe.failureThreshold`
  30 (kill budget 50s -> 320s; chart 0.9.2 has no `startupProbe` key at all -- verified by
  extracting it). Also set `api.env.HINDSIGHT_API_WORKER_ID` to a stable literal, silencing
  a real recovery-hazard warning the vectorize-io/hindsight image logs at boot (worker id
  defaults to the container hostname, stable across container restarts but not across Pod
  recreation).
- Audited the whole catalog with a new tool, `src/Core.TypeScript/cluster/liveness-kill-budget.ts`
  (+ `.test.ts`, wired into `.github/workflows/helm-validate.yml`): renders every Application,
  flags any container with a `livenessProbe`, no `startupProbe`, and a kill budget
  (`initialDelaySeconds + (failureThreshold-1)*periodSeconds`) under 120s. Found
  `controlPlane` on the same hindsight chart (fixed here too, 50s -> 170s) plus 44 more
  (app, container) pairs across the rest of the catalog -- grandfathered into
  `KILL_BUDGET_ALLOWLIST` with reasons and tracked in a follow-up work item
  (081M348H97G087G0R0020EA0NY) rather than fixed blind in this PR.
