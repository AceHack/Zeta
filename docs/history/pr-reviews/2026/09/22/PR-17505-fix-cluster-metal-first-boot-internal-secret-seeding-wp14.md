## Summary

- `first-boot-replica.ts` run 35700790207 (real NixOS k3s roster in Docker, ArgoCD syncing the dev rung) found `CreateContainerConfigError` for hindsight, loki, mimir and opensearch — all a missing Secret. Tracing every `existingSecret`/`secretKeyRef`/`envFrom`/`imagePullSecrets` the catalog references (table below), six credentials are **INTERNAL** (random values used only between in-cluster components) and nothing on a real USB/metal install ever minted them.
- Adds `full-ai-cluster/k8s/bootstrap/internal-secret-seeding.yaml`, a k3s first-boot manifest (same roster mechanism as the other `*-install.yaml`/`*-namespace.yaml` bootstrap files, applied before ArgoCD exists) that mints each of the six credentials **only if absent**, per-namespace RBAC scoped to `create` on `secrets` alone, using `kubectl create` (never `apply`/`replace`, so an existing Secret is never overwritten). Randomness is drawn from each seeding Job's own pod UID via the Kubernetes Downward API + native `$(VAR)` command/arg expansion — no shell needed, so the already-pinned `registry.k8s.io/kubectl:v1.32.3` (distroless, no shell) suffices and no new image-resolvability/image-source-provenance ledger entries are required.
- `hindsight-llm-api-key` and the GHCR pull token stay **EXTERNAL** (operator-supplied) gaps — not seeded with random values, since that would clear the crash loop while guaranteeing no real LLM call or image pull ever succeeds. Both are non-gating (`zeta.io/gates-later-waves` not set) and documented in a new `INJECTION-POINTS.md` table.
- Key shapes are cross-checked against `dev-cluster/lib.ts`'s `DEV_BOOTSTRAP_SECRETS`/`DEV_SHARED_SECRETS` (the same source dev/CI already mints from) by a new `internal-secret-seeding.test.ts` so the two cannot silently drift.
- Updates the k3s-server.nix roster comment, the pinned apply-order golden vectors (`k3s-first-boot-apply-order-eval-test.nix` and `first-boot-replica.test.ts`), and marks workitem `081M343EEP8087G0R000BAF6QF` in-progress.
