## Summary

Audited every generated credential in the repo against its consumer's documented charset/complexity rule (grep for `randomBytes`, `base64url`, `/dev/urandom`, `randAlphaNum`, `openssl rand`, `tr -dc`), following on from PR #17534 (WP19c), which fixed the same defect class on the metal side for OpenSearch only.

### Audit table

| credential | consumer | rule | verdict |
|---|---|---|---|
| `opensearch-admin-credentials` (**dev/CI**) | OpenSearch Security `install_demo_configuration.sh` | `(?=.*[A-Z])(?=.*[^a-zA-Z\d])(?=.*[0-9])(?=.*[a-z]).{8,}` | **FIXED here** — was `randomBytes(24).toString("base64url")`, ~38% chance per draw of missing the required special character (base64url's only non-alphanumerics are `-`/`_`) |
| `opensearch-admin-credentials` (metal) | same | same regex | already fixed, WP19c (#17534) — no change |

`gitlab-initial-root-password` is a known, separately-tracked gap (never minted at all yet — see `crd-provider-consumer-order.ts`); out of scope here since it isn't a *generated* credential violating a charset rule.

### The fix

`DEV_OPENSEARCH_ADMIN_SECRET` in `dev-cluster/lib.ts` now carries `passwordPolicy: "opensearch-strength"`. `composeOpenSearchAdminPassword` (new, pure, in `lib.ts`) maps two extra CSPRNG bytes through the **same 16-symbol hex-nibble alphabets** WP19c's metal shell pipeline uses, guaranteeing one uppercase letter and one special character **by construction** rather than by chance, prepended to a 31-byte hex body — same shape, same rule, same guarantee as the metal fix, just in TypeScript. `use-cases.ts`'s `mintDevAdminPassword` dispatches on the new field so every other credential's draw is untouched.

### Tests

`lib.test.ts` adds: the exported `OPENSEARCH_ADMIN_PASSWORD_REGEX` pinned verbatim against the cited OpenSearch source; 1000 deterministic draws from a seeded PRNG (never wall-clock randomness) all satisfying the regex; a plain-hex draw (the pre-fix shape) asserted to **fail** the regex, proving the test isn't vacuous; mapped characters asserted to come from their declared alphabets regardless of input; and `DEV_OPENSEARCH_ADMIN_SECRET` asserted to be the only `DEV_BOOTSTRAP_SECRETS` entry carrying the policy.
