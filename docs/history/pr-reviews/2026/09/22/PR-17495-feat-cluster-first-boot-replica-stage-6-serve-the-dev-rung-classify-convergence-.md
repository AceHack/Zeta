## Summary

WP1b (081M340NKP9087G0R000F8YHXQ), continuing WP1 (#17481). Stage 6 of
`first-boot-replica.ts` (the harness that boots the REAL k3s control-plane
manifest roster in Docker) previously slept a fixed window and took one
pod/Application snapshot — it counted a Succeeded helm-install Job pod's
already-reported retries as a "crash loop", and treated every Pending pod
the same whether it was CAPACITY-starved by design (a 4-vCPU runner against
metal-sized resource requests) or genuinely broken. No verdict this stage
produced actually meant anything.

- **Serve the dev resource rung in-cluster.** Reuses `argocd-health-test.ts`'s
  own `buildLaneTreeForProfile` (now exported) — the same rung + rung-overrides
  + in-cluster-git-server pipeline the live-kind/live-k3d included lanes
  already proved — rather than re-deriving it. `applyServeTreeOverride`
  re-patches `root-application.yaml`'s repoURL/targetRevision to the served
  tree and injects a `directory.exclude` importing `ports.ts`'s
  `DEFAULT_ROOT_DEV_CATALOG` glob via `rootDevCatalogExcludeGlobFor`. Each
  override lands as its own named Divergence.
- **Excludes Succeeded pods** from crash-loop counting.
- **`classifyPod`** names why a non-converged pod is stuck, from container
  waiting reasons and `FailedScheduling` events: `CrashLoopBackOff`→CRASHLOOP,
  `ImagePullBackOff`/`ErrImagePull`→IMAGE, `CreateContainerConfigError`→SECRET
  (all FAIL), `Insufficient cpu/memory`→CAPACITY, unbound PVC→STORAGE (both
  DIVERGENCE, not FAIL).
- **Bounded convergence wait** (up to `--stage567-timeout-sec`, 1800s in CI)
  polling until every Application leaves `Progressing`, then a **soak**
  (`--soak-sec`, 300s in CI) that FAILs if any container's restartCount
  increases. PR #17480 (evidence-based terminal Degraded + soak in
  `argocd-health-test.ts`) is still open — this stays a separate, minimal,
  independently-unit-tested implementation pending consolidation.
- **Per-app verdict table** (Healthy/DIVERGENCE(reason)/FAIL(reason)) in the
  JSON report and `$GITHUB_STEP_SUMMARY`.

39 new unit tests (66 total in the file) for the classifier, verdict, settle
and soak-regression logic — each rule has a test that fails if the rule is
inverted.

CI workflow bumped to `--serve-tree dev --soak-sec 300 --stage567-timeout-sec
1800`; job `timeout-minutes` raised 75→150 for the new worst-case budget.
