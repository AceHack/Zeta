## Description

## Summary

The USB installer's default metal target is a single-node control plane, but nothing ever budgeted the kubelet's `--max-pods` pod-COUNT ceiling — only CPU/memory were checked. This closes that gap.

## The arithmetic

Rendered metal-profile totals (`src/Core.TypeScript/cluster/rendered-resource-requests.snapshot.json`, 49 Applications the bootstrap root applies):

```
  147  rendered pods
-  23  Job/CronJob pods (terminal — kubelet max-pods admission only counts
                          non-terminal Running/Pending pods)
-   3  manual-sync Applications' pods (cdi 1, kubevirt 2 — never auto-applied
                          per manual-sync-policy.ts; ollama/vllm already render 0)
+   3  kube-system baseline (coredns + metrics-server — bundled by k3s, not
                          disabled by any `--disable=` flag in k3s-server.nix —
                          + local-path-provisioner, read directly off its own
                          committed Deployment in local-storage.nix)
= 124  steady-state pods on a fresh single-node boot
```

Against the kubelet default of 110, that is already over — the tail of ArgoCD's sync waves would sit `Pending` with `0/1 nodes are available: 1 Too many pods` forever, and nothing existing catches it (the static checks in `single-node-readiness.ts` only ever summed CPU/memory).

CPU/memory are unaffected and already fit with headroom (`findComputeProvenance`, unchanged): the metal rung's 12365m/25867Mi against the smallest registered node's 16000m/62942Mi (16 logical CPUs, 66G RAM decimal).

## What was set, and why

- `full-ai-cluster/nixos/modules/k3s-server.nix` / `k3s-agent.nix`: `--kubelet-arg=max-pods=220` on **both** roles (`--kubelet-arg` is per-kubelet, not server-only).
  - 220 clears the kubelet default (110) by 2x and the measured 124-pod floor by ~77% headroom.
  - Chose 220 over a rounder 250 because of a second, independent bound: Cilium's cluster-pool IPAM hands each node a `/24` at the chart's default `clusterPoolIPv4MaskSize: 24` (confirmed against `install/kubernetes/cilium/values.yaml` at the pinned 1.20.1) — 254 usable addresses. 250 would leave only 4 addresses of slack against that block (the node's own `cilium_host` router IP and any hostNetwork pod already eat into it); 220 leaves 34.
- `full-ai-cluster/k8s/bootstrap/cilium-install.yaml` and `full-ai-cluster/k8s/applications/cilium/Application.yaml`: added `clusterPoolIPv4MaskSize: 24` explicitly, in lockstep on both (same release, adopted from bootstrap by the Argo Application), since the pod-count budget now depends on that number rather than an inherited chart default.

## The static guard (so this can't regress)

`findPodBudget` in `src/Core.TypeScript/cluster/single-node-readiness.ts`:
- derives the steady-state floor from the same render `findComputeProvenance` already prices (Job/CronJob subtraction, manual-sync subtraction via `manual-sync-policy.ts`'s own `classifySyncPolicy` — never a hardcoded roster — plus the named kube-system baseline);
- reads `--kubelet-arg=max-pods=N` off both nix modules;
- refuses (blocker) when either role has no flag set, or the two roles disagree, or the floor exceeds the configured budget — same "convict, never acquit" / acknowledgeable-debt discipline as every other check in this file;
- wired into `auditAll`, gated on `resources !== null` the same way `findComputeProvenance`/`findRungCoverage` are, so synthetic-tree unit tests that don't wire a resource catalogue skip it cleanly.

Already covered by CI: `.github/workflows/k8s-argocd-health-test.yml` runs both `single-node-readiness.test.ts` and the live `single-node-readiness.ts` auditor on every PR touching this file — no new workflow wiring needed.

`full-ai-cluster/k8s/single-node-budget.json` gets a new `acknowledgedPodBudgetShortfall` list (empty) with the arithmetic recorded in its `$comment_*` block, same shape as every other acknowledgement list in that ledger.

Live run against this branch: `bun src/Core.TypeScript/cluster/single-node-readiness.ts` prints the arithmetic above and exits 0 (`no blockers.`).
