## Description

#17477 made Argo CD child-Application health gate later sync waves for the
opted-in providers. The first-boot replica (the real k3s bootstrap roster in
Docker) shows two of those gates are unproven on the real bootstrap path:

- cilium (wave -80): Synced/Progressing for 15+ minutes with every cilium pod
  Running, in main's ungated replica run 35696323545. With the gate on, the
  replica on #17477 saw only 3 Applications after 480s, against ~50 ungated.
  A stuck gate at -80 stalls the entire catalog on a real first boot.
- arc-controller (wave 3): never observed reaching Healthy on that path. A
  stuck gate there would stall waves 4-50.

Removing a gate restores exactly the pre-#17477 behaviour for that app: its
consumers still order by wave and rely on automated retry. The remaining
gates are cert-manager, open-policy-agent, spire-crds and trust-manager, all
observed Healthy in the replica. The live-tree test pins the new set, and
crd-provider-consumer-order.ts reports zero violations. Re-add a gate once the
replica shows the app reaching Healthy.
