## Description

## Summary

Two verified defects in the app-of-apps bootstrap, plus one extended audit. **Reworked per architect review** (see "The rework" section below) — health gating is now **opt-in, providers only**, not global.

### 1. Application health gating was missing (most important part)

`resource.customizations.health.argoproj.io_Application` — removed from ArgoCD's built-in health checks in 1.8 — was absent from `argocd-cm` in **both** bootstrap HelmCharts and the self-managed `argocd` Application. Without it, sync-wave ordering among the ~50 child Applications under `zeta-root` only orders the **apply** of each Application resource, never waits for the workload underneath to actually converge before starting the next wave.

Restored (verbatim upstream lua, cited to ArgoCD's 1.7→1.8 upgrade notes) in all three sites, with a parity check (`audit-argocd-pin-parity.ts`) so the three copies can't drift.

### The rework — opt-in gating, providers only

**The risk trade-off, spelled out:**

| Design | Risk |
|---|---|
| Gate on EVERY Application (upstream default, the first cut of this PR) | One never-Healthy app anywhere in the ~50-Application roster stalls the **entire cluster** — and there are real ones: `platform`'s unminted `ghcr-pull`, `openbao`'s sealed-by-design state, four declared manual-sync apps |
| Gate on NOTHING | A genuine CRD/webhook consumer can race its provider with no ordering guarantee stronger than the wave *number* — the exact `platform`/`kube-prometheus-stack` bootstrap-noise class this PR's analyzer exists to catch |
| **Opt-in, providers only (shipped)** | Only apps a later wave genuinely depends on, and only when *verified* safe (no operator ceremony, no unminted secret, not manual-sync) |

**Mechanism:** the lua now returns the child's real health **only** when it carries `zeta.io/gates-later-waves: "true"`. Every other child reports synthetic Healthy — wave ordering never waits on it — while its real health stays fully visible everywhere else (ArgoCD UI, `kubectl get application`, the lua's own input). Upstream's snippet is kept byte-identical inside the annotation guard.

**Gating set (6), each verified metal-safe:**

| App | Provides | Consumed by | Verified |
|---|---|---|---|
| `cilium` | `cilium.io` CRDs | `cilium-lb-ipam` | zero secrets, not manual-sync, bootstrap-installed |
| `cert-manager` | `cert-manager.io`/`acme.cert-manager.io` | `openziti-controller`, `platform`, `trust-manager` | zero secrets, self-issues webhook CA |
| `trust-manager` | `trust.cert-manager.io` Bundle | `openziti-controller` | zero secrets |
| `open-policy-agent` | `templates.gatekeeper.sh` | `hat-system` | zero secrets, cold-boot webhook-failOpen already mitigated |
| `spire-crds` | `spire.spiffe.io` | `spire` | CRDs only, zero secrets |
| `arc-controller` | `actions.github.com` | `arc-runner-set` | zero secrets ("registers nothing itself") |

**Excluded, with reasons:**

| App | Why excluded |
|---|---|
| `kube-prometheus-stack` | Real CRD provider (`monitoring.coreos.com` → `platform`) but `admin.existingSecret: grafana-admin-credentials` is unminted **anywhere in the committed tree** (measured: `collectTreeMintedSecretNames()` returns **zero** Secrets, tree-wide). `platform`'s consumption stays protected by `SkipDryRunOnMissingResource=true` instead. |
| `openbao` | Not a CRD provider at all. Also independently barred by a new `CEREMONY_GATED_APPS` table: sealed by design, PKCS#11 auto-unseal not wired for metal (`openbao-unseal-sidecar.ts`: "HONEST SCOPE -- SHAMIR / KIND ONLY... blocked on a same-libc OpenBao image"). |
| `longhorn`, `cockroachdb` | Not CRD providers — `StorageClass` is a builtin kind, cockroachdb is consumed via network connection string, neither is a K8s API extension. (cockroachdb's historical `cockroach init` deadlock is already fixed via an Argo-hook trick; noted for completeness, not because it mattered here.) |
| `cdi`, `kubevirt`, `ollama`, `vllm` | Declared manual-sync — barred categorically. |

**Three new machine checks** in `crd-provider-consumer-order.ts`, run on every PR, **not acknowledgeable** (a finding means the design needs to change, not be documented away):
- **(a) NEEDLESS-GATE** — a gating app must provide something a *different* Application consumes.
- **(b) UNSAFE-GATE-{SECRET,MANUAL-SYNC,CEREMONY}** — a gating app may not depend on an unminted secret, be manual-sync, or appear in the ceremony table.
- **(c) UNPROTECTED-NON-GATING-PROVIDER** — a consumer of a non-gating provider must carry `SkipDryRunOnMissingResource=true` or the consumer must have `selfHeal: true` (confirmed: every automated Application in the roster already does, except the four manual-sync apps).

Stall analysis that drove the manual-sync-floor fix (kept from the first cut): `cdi`/`kubevirt` moved from wave `-5` to wave `50` (matching `ollama`/`vllm`'s existing convention) so a manual-sync app can never sit before an automated wave; `derive-sync-waves.ts` gained a machine-checked floor invariant.

### 2. CRD provider/consumer ordering analyzer (new)

`src/Core.TypeScript/cluster/crd-provider-consumer-order.ts`: renders every Application (`helm template --include-crds`, or reads directory sources) and checks every consumed non-core kind has a provider that reconciles first, is bootstrap-installed, or carries `SkipDryRunOnMissingResource=true`.

**One real violation found and fixed:** `platform/monitoring.yaml`'s `ServiceMonitor`/`PrometheusRule` (wave `-20`) consume `monitoring.coreos.com` CRDs `kube-prometheus-stack` installs at wave `0`. Fixed with `SkipDryRunOnMissingResource=true` — the smallest correct fix named in the pre-existing `ORDER_ADJUDICATION_PENDING` registry entry, and now the thing that keeps `kube-prometheus-stack`'s exclusion from gating safe.

Wired into `.github/workflows/helm-validate.yml` as a failing step.

### 3. Secret audit extended for raw pod-spec references

`audit-existing-secret-is-minted.ts` extended with a raw-manifest scan (`imagePullSecrets`/`envFrom.secretRef`/`env[].valueFrom.secretKeyRef`/`volumes[].secret.secretName`), checked against what the **tree itself** mints rather than the dev/CI roster. This is what surfaced `ghcr-pull`, `orleans`'s `redis-auth` (already self-documented, optional, replicas=0), and `kubevirt-operator-certs` (self-minted by the operator at runtime, confirmed via its own RBAC).

**Filed workitem 081M33TN49G087G0R000X5ZJ75** for the metal `ghcr-pull` gap — a human decision (real secret material): make the GHCR packages public, or project the credential via `zeta-creds-to-k8s.nix` + the `INJECTION-POINTS.md` rail.
