## Description

## Summary

WP19's new stage 8 (`--power-cycle` in `first-boot-replica.ts`) reproduced a genuine, consistent finding on 3+ CI runs: `opensearch-cluster-master-0` crash-loops after a hard `docker kill -s KILL` + restart. Filed as workitem `081M34QTS06087G0R0015D7X5W`.

## Root cause

Run 35744676325's `kubectl logs --previous` (captured by this PR's first commit, `collectCrashLoopDiagnostics`) named the exact cause:

```
Password <64 lowercase hex chars> failed validation: "Password does not match validation
regex" ... must contain at least one uppercase letter, one lowercase letter, one digit, and
one special character.
```

`opensearch-cluster-master-0`'s admin password is minted by `full-ai-cluster/k8s/bootstrap/internal-secret-seeding.yaml`'s `seed-opensearch-admin` Job via:

```
head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' > /work/admin-password
```

`od -An -tx1` hex-encodes — output alphabet is exactly `0-9a-f`, so the drawn password can **never** contain an uppercase letter or a non-alphanumeric character. OpenSearch Security's `install_demo_configuration.sh` (`org.opensearch.security.tools.democonfig.Installer`) validates the admin password against `(?=.*[A-Z])(?=.*[^a-zA-Z\d])(?=.*[0-9])(?=.*[a-z]).{8,}` before letting `opensearch` start ([docs](https://docs.opensearch.org/latest/security/configuration/demo-configuration/); this demo-installer check is separate from the runtime `plugins.security.restapi.password_validation_regex` setting — [opensearch-project/security#4081](https://github.com/opensearch-project/security/issues/4081)). So validation fails **deterministically, on every boot** — first boot included, not specific to the power cycle. `describe pod` on the same run shows the container already crash-looping (6 restarts) well before stage 8's hard kill; the power-cycle soak window is simply the first check in this harness sensitive enough to catch it (it compares the soak-window restart delta rather than relying on Argo Application health, which apparently reports this StatefulSet loosely).

**Ruled out by this same evidence:** stale `node.lock`, translog/cluster-state corruption, JVM heap OOM, and the WP18 liveness-kill-budget probes (the opensearch chart ships **no** `livenessProbe` by default — only `startupProbe`/`readinessProbe` — so kubelet is restarting a process that exited on its own, not one a probe killed).

## Fix

`seed-opensearch-admin`'s `draw-entropy` script now draws two extra CSPRNG bytes, hex-maps each through a 16-symbol `tr` table into a guaranteed uppercase letter and a guaranteed special character (bijective, no entropy lost vs. the existing hex draw), and prepends them to the same 248-bit hex body every other credential in this file uses. The password satisfies OpenSearch's strength regex **by construction** on every draw, not by chance — verified with real `/dev/urandom` draws through the exact shell pipeline, each checked against the literal regex in Python (100% pass). Fixed by minting a compliant credential, not by weakening OpenSearch's security posture — same discipline this file's own `Application.yaml` precedent already used for the missing-password issue that preceded this one.
