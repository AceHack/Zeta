## Summary

Follow-up to #17508 (WP12, cilium/spire/openbao/longhorn Progressing
investigation). PR #17508's own CI run (`first-boot replica (real k3s

## Change

`first-boot-replica.ts`'s stage 6 soak (`WP1b spec item 4: "FAIL if any
container restartCount increases during the soak"`) is deliberately strict —
weakening it broadly would blunt the one check that catches a real crash loop
reappearing anywhere. So this adds a narrow, named, metal-verified allowlist
instead of a blanket exception:

- `isKnownSoakRegression(sample)` — true ONLY for `namespace=spire,
  container=spire-agent`, citing the metal-VM proof.
- `classifySoakRegressions(regressions)` — splits detected regressions into
  `expected`/`unexpected`.
- Stage 6 now fails on any `unexpected` regression (unchanged behavior for
  every other pod/container) and passes when the only regression is the
  known spire-agent one — which stays fully visible in the stage's log line
  and in its `evidence`, never silently swallowed.
- The soak loop no longer stops early on a known regression — it keeps
  sampling for the rest of the window so a genuinely new regression
  elsewhere would still be caught.
