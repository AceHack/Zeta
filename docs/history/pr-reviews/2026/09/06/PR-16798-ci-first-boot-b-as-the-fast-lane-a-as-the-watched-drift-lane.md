## Description

Both, as asked — and **A is non-blocking by construction rather than by a flag.**

## B — `first-boot-manifest-check.yml`, the fast lane

Evaluates the full-ai-cluster flake when either `k8s/bootstrap/` tree changes.
`k3s-first-boot-apply-order`'s assertions fire during **evaluation** — the flake says so
itself, *"so `nix flake check --no-build` already runs it"* — so the fast lane needs no VM
and builds no derivation.

## A — the two bootstrap globs on `build-ai-cluster-iso.yml`, the watched drift lane

It runs, it is visible, and **it cannot block.** Measured against the live rulesets:
**`gate (required)` is the only required status check on `main`**, so every job in that
workflow is already watched rather than gating.

**No `continue-on-error` was needed and none was added** — claiming non-blocking with a flag
when the ruleset already says so would be a second, weaker statement of the same fact.

## The trigger covers both halves of one fact

A manifest and its `services.k3s.manifests` entry are two halves of one thing, and the
eval-test reads **both** — so the lane also triggers on `k3s-server.nix` and the two test
files. A lane watching only one half would be checking a pair it could see only when the
other side moved.

## The anti-vacuity step is copied on instruction, not by habit

`root-flake-check.yml`'s own comment: *"anyone adding a nix lane anywhere should copy this
step, because the default failure mode of a nix eval lane is a confident green over an empty
check."* `nix flake check` exits 0 over outputs it skipped entirely. The guard is
format-independent for the reason that file records — a version counting `^✅` was reading
Determinate 3.x presentation and reported **zero** outputs while upstream nix had checked
twenty.

**And it adds one assertion that file does not have:** the log must *mention*
`k3s-first-boot-apply-order`. A green that never reached the check this lane exists for is
green about some other flake output.

## Verified locally — the guard run verbatim against a real flake check

```
exit 0
outputs checked                175
k3s-first-boot-apply-order       6 mentions  (aarch64-linux, aarch64-darwin, x86_64-linux)
k3s-first-boot-roster            2
both guard conditions         PASS
```

`--all-systems` is load-bearing and now **measured rather than asserted**: the check exists
on three systems, and without the flag nix omits the incompatible ones and still exits 0.

## What the green means — written into the file so it is read correctly

`--no-build` realises nothing, so `k3s-first-boot-roster` — a `nixosTest` whose own header
says it *"REQUIRES INTERNET (five Helm charts and roughly 2-3 GB of images)"* — is
**evaluated** by the fast lane and **run** only by the drift lane.

**B says the roster and its order are still well-formed. It does not say the cluster boots.**
A is what says that, at 32 minutes, when someone looks.
