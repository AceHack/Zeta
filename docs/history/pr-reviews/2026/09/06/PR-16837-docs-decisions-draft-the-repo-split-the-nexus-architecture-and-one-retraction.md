## Two measurements reorder the ask

**1. "docs into its own repo" is not the easy one.** **728 files** under `src/`, `tests/`,
`tools/`, `clis/`, `.github/`, `infra/` and `full-ai-cluster/` reference a `docs/` path:

| subtree | files | readers |

| `docs/backlog` | 1,140 | **101** |
| `docs/observe-events` | 5,993 | 50 |
| `docs/history` + `docs/github` | 28,061 | 83 |

Of 77 subdirectories, ~26 have **zero** readers — and every one of those is 1–10 files. **The
cut is prose vs machine-read substrate, not `docs`**, and the prose half is both easy and
low-value.

**2. The languages are already partitioned** — every one has its own top-level directory by
existing convention. `git subtree split` per language needs no re-organisation first.

## The blocker, and it is one step not eight

Golden vectors **live** in `src/Core.TypeScript` (71 files) and are **read** from ten
directories — F# tests 54, C# tests 36, F# src 22, C# src 19, four Rust crates,
`tests/cross-verification`.

**I first wrote that this makes TypeScript an appointed hub. That is retracted in the doc, and
it was wrong twice** — it contradicted the standing 2026-09-04 decision (*canonical-by-choice
is not appointed*, and that doc already applies the same exit-not-degree test), and the
language-level exit is real and measured: **6.3%** of TS files touch the `Bun.` global, and
`node` already runs as a second runtime in `bytelock.yml`.

What survives is narrower and **independent of language** — it would be identical for
`zeta-fs`:

> **The split converts a file every oracle HAS into a repo every oracle must REACH.**

The fix that dissolves it: **vendor the treaty, don't fetch it.** A pinned subtree means a
clone at a tag still has the bytes and builds offline — satisfying
`clone-at-tag-stays-sufficient.md` and removing the required remote in one move.

## The nexus architecture

Aaron: *"zeta is the nexus for now but it's an **accidental** nexus."* That renames the
problem — **an undeclared junction has no rules, so everything crosses**, which is one cause
behind all three measurements above. Two tiers: **a nexus repo per language** (one clone is a
whole world — code, tests, its own charts, stubs for the rest) and **one intentional common
nexus, `zeta-treaty`**.

**Helm charts: nearly free today.** 37 cluster charts are third-party pins; this repo owns
**two**, both fixtures. So the rule can be carved before the first service chart exists — *a
chart that deploys **code** lives in that code's repo; a chart that deploys **someone else's
software** lives with the cluster.* The second half stops it becoming licence to scatter 37
upstream pins and undo the pin-parity work.

**Stubs have a falsifier and a limit:** a language repo's tests must pass with **no other
language present** — but a stub that drifts is a lie with a green tick, so stubs are checked
against the real thing by golden vector. *Stubs are how a repo stands alone; the treaty is
what stops them drifting.*

## Naming — the memory constraint

`zeta-rs`, `zeta-py`, `zeta-go`, `zeta-lean`, `zeta-qs`, plus `zeta-specs`, `zeta-formal`,
`zeta-archive`, `zeta-treaty`.

## Order — and step 4 is the gate

specs (34 files) → formal (197) → archive (28k) → **`zeta-treaty` (~120)** → smallest language
first (`zeta-qs`, 9) → the rest.

**If the four-oracle byte-lock cannot pass from a pinned treaty checkout with no package
manager, steps 5–6 do not start.** Better to learn that on 120 files than on 3,717.

Each shot ends by **deleting from Zeta** — but only after: split → verify independently →
repoint consumers → **watch one real CI run go green** → then delete, leaving a pointer.
