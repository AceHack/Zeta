## Description

Found while reading the QEMU boot logs.

## The measurement

`configuration.nix:404` writes

```nix
isoName = lib.mkForce "zeta-installer-${config.system.nixos.release}.iso";
```

and nixpkgs **renamed `isoImage.isoName` to `image.fileName`.** CI prints the warning **three
times per x86_64 run**:

```
evaluation warning: The option `isoImage.isoName' ... has been renamed to `image.fileName'
```

So both arches ship under the nixpkgs default name:

```
nixos-minimal-25.11.20260522.b77b3de-x86_64-linux.iso
nixos-minimal-25.11.20260522.b77b3de-aarch64-linux.iso
```

**A `lib.mkForce` that forces nothing.** `mkForce` is the strongest statement the module
system offers — it exists to win arguments — and here it wins an argument about an option
nothing reads.

## What is not wrong, checked before filing

**The image is correct.** `networking.hostName = "zeta-installer"` *is* live, and the x86_64
boot proves it end to end: `Outcome: BOOTED`, furthest stage `login`, **24s** against a 300s
budget, reaching the exact `zeta-installer login:` prompt the harness waits for. **Only the
filename is inert.**

## Why nothing caught it

`qemu-boot-test`'s ISO discovery accepts either name:

```sh
-name 'zeta-installer-*.iso' -o -name 'nixos-minimal-*.iso'
```

That fallback keeps the lane green — and is also what makes the defect invisible. The second
arm was presumably added *because* the ISO was already arriving under that name, which is the
fix-the-symptom move: **the finder learned to accept the wrong name instead of anyone asking
why the right one wasn't applied.**

## Why it matters beyond tidiness

- Every artifact published from these runs — ISO, digest manifest, `.sha256` — is named
  `nixos-minimal-*`. A downloader cannot tell a Zeta installer from a stock NixOS image by
  its name, and the digest manifests are keyed on it.
- It is a live instance of the class this repo audits hardest: **configuration that is
  present, well-formed, passes every check, and is not in effect.** The seaweedfs auth bug
  (`081M1FG1RCW`) is the same sentence about a different option.
- **The warning has been printed on every run and read by nobody.** It isn't hidden — three
  lines of `evaluation warning:` in a 3,500-line log.

## Filed, not fixed — and the reason is the `Done when`

The one-line rename is the easy half. The half worth insisting on is the **falsifier**: assert
the built ISO's filename starts with `zeta-installer-`, so the next nixpkgs option move cannot
rot it silently again — and *then* delete the `nixos-minimal-*` fallback so the finder stops
accepting the wrong answer.

**Doing the rename without that would restore the name and leave the mechanism that lost it.**
