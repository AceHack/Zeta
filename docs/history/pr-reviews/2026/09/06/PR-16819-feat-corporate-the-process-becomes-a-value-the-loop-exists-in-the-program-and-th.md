## Description

## What was wrong

Three defects, each one hiding the next.

**1. Thirteen gates reviewed nothing.** The runtime evaluated all gates, *then* opened a change and executed the work. `implementation_review`, `qa_uat` and `adversarial_review` approved an implementation that did not exist; `runtime_validation` was decided by tests that ran before the code was written.

**2. The agent loop was joined to the pipeline in one direction.** `run-org.ts` supplied a constant for every `PickWork` an agent chose:

```ts
resultFor: (o) => o.tag === "PickWork"
  ? { workId: o.work.id, lane: o.work.lane, success: true, doraContribution: 0.5 }
  : undefined
```

Every cycle reported work nobody did. `run-agent.ts` supplied nothing, so there the choice vanished. That is not shadow mode — a shadow lane's whole value is recording what *would* have happened while everyone knows nothing did, and a lane that fabricates `success: true` is indistinguishable in the record from one that worked.

**3. The gate that fixed (2) could not open.** Nothing recorded a tick, so `shadowTicks` was always 0; nothing compared anything, so `divergenceMeasured` was always false. Every refusal test passed, and none of them could tell a working gate from a disconnected one. A check that cannot fail proves nothing; a gate that cannot open measures nothing.

## What this does

**A phase pairs a producer with the gate that judges it**, and a pipeline is a list of phases: produce → show the reviewer what was just made → evaluate → next. The artifact's refs become the gate's `evidenceRefs`, so evidence is a by-product of doing the work rather than a field somebody fills in. A `Pipeline` is **data** — reorder, drop, add, swap a producer, without touching the runtime.

**`autonomy.ts`** runs cycles until the organization settles, with four stop reasons and only one of them success: `delivered` / `halted` / `no_progress` / `bound_reached`. `maxCycles` has no default — a defaulted bound is a bound nobody chose.

**`slot-dispatch.ts`** gives the three modes the design names and a dispatch seam that is a port with `meta`, so it shows up in a run's fidelity report. Shadow performs nothing and **invents nothing**: it returns no `WorkResult`, because in shadow `success: true` is a lie and `success: false` is also a lie — the work did not fail, it was not attempted. `dispatcherFor` takes a *verdict*, not a mode, so "run this in primary" is not a sentence a caller can say.

**`observe-act-window.ts`** makes the gate reachable. The tick is a fact on the append-only log; the window is a fold — the same shape used for fidelity, queues, QA and pace. Soak is the **span**, not the count. Divergence is *defined* rather than assumed: the observe-act selection compared against the legacy priority lane, a genuinely different selector, because a measurement between one selector and itself reads 0% by construction. Both halves of a selection count. A partial comparison stays **unmeasured**, and an unmeasured divergence blocks — a rate of zero from a comparison nobody ran is not a clean rate, and this is the gate that unlocks real side effects.

The clock enters through a **declared channel** (`--now`), defaulting to the frozen epoch. `Date.now()` would make every run unreplayable and leak wall time into the shared window.
