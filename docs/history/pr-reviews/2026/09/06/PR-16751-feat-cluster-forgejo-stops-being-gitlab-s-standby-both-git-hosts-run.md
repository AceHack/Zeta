## Three things measured before anything was touched

| question | measured answer |
|---|---|
| **do they actually conflict?** | **No.** Different namespaces (`forgejo`, `gitlab`), no shared object, no name collision. *"Only one at a time"* was a convention, never a mechanism |
| **what does running both cost?** | **forgejo 100m / 128Mi / 1 pod** against **gitlab 2525m / 5733Mi / 17 pods** (`rendered-resource-requests.snapshot.json`, dev **and** metal) — 4% of the CPU, 2% of the memory. The cheap half of an either/or is not worth an either/or |
| **what actually blocked it?** | **One unminted credential** — and the repo had already written the lift condition: *"forgejo is synced in any lane … the honest fix is to add it to `DEV_BOOTSTRAP_SECRETS` rather than to re-acknowledge it"* |

So this is the fix that acknowledgement asked for, not a new one. **The entry is deleted
rather than re-worded**, because its condition is met.

## What changed

- **`DEV_FORGEJO_ADMIN_SECRET`** — key names **measured, not guessed**: `helm template` at
  the pinned chart 17.1.5 renders the init container reading `secretKeyRef.key: username`
  and `key: password`. `gitea_admin` is the chart's own default username, kept rather than
  invented because Forgejo reserves some names. Drawn from `randomBytes(24)` per cluster,
  logged nowhere, committed nowhere.
- **`automated: { prune: false, selfHeal: true }`** — `prune: false` matching gitlab and
  deliberately: a Git host holds the only copy of whatever has been pushed to it, so an
  Application-level prune is the one reconciliation this workload must never perform
  automatically.
- **forgejo leaves `DEV_INCLUDED_PROOF_DEFERRED_DIRS`** — the half with teeth. The live
  lane will now go **red** if forgejo does not reach Synced/Healthy. *"Both up"* that
  nothing checks is the same claim the standby posture was making, and asserting a
  manual-sync app's exists-but-never-synced contract is the cdi/kubevirt vacuity #13084
  had to fix. gitlab **stays** deferred — its reasons are ~40 subcharts and a multi-GB
  image stack, about chart size rather than about the pair.

## Six tests went red, and every one of them was right

The standby posture was pinned in six places. That is the suite doing its job:

- two `argocd-health-test` assertions — **flipped, with `gitlab` kept beside each as the
  control.** A `forgejo` that is now included proves the mechanism *discriminates* rather
  than that it stopped excluding anything.
- a stale `APPLIED_BUT_UNASSERTED_REASONS` row reading *"deferred until dev wiring
  exists"* — caught by `auditAppliedButUnasserted().stale`, which is **how it was found
  rather than remembered**.
- *"the five manual-sync apps"* → four, asserted **whole** so an app arriving or leaving
  unannounced still fails.
- `DEV_BOOTSTRAP_SECRETS.length` 4 → 5.

Every prose site describing forgejo as standby is **rewritten rather than deleted** — the
class each defines is defined by which apps are in it, and an app *leaving* is the outcome
those classes exist to make possible.

## One thing stays open, and is now louder

**The database.** forgejo runs `sqlite3` on its PVC (chart 14+ removed the postgresql
subcharts; Bitnami's image 404s below that). Whether it gets an external PostgreSQL or the
CockroachDB already in the cluster is a maintainer decision. What changed is that this is
now what **runs** rather than what would run if anyone ever synced it — one writer, no
replication, on a 20Gi local-path volume, being exercised instead of described.
