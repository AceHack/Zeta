## Description

`infra/k8s/bootstrap/argocd-install.yaml` — **the HelmChart K3S auto-applies on NixOS
first boot, i.e. the metal bring-up path** — pinned argo-cd **7.7.10 (ArgoCD v2.13.2)**
while the other four sites moved to **10.8.0 (v3.5.2)** across three bumps on 2026-09-01,
09-03 and 09-04. Its own header still claimed *"It is also the pin `full-ai-cluster`
uses"*: true when written 2026-08-18, false from 2026-09-01.

## This exact defect already fired once

2026-09-03, run 33736439359, written up at length in `dev-cluster/use-cases.ts`: the k3s
bootstrap moved and *"this kind-lane pin was the one left behind."* v2.13.2 ships Helm 3
only; seaweedfs ≥ 4.33.0 uses the Helm-4-only `fromToml`; the repo-server failed manifest
generation and **cached the error per revision**, so the wave −90 self-upgrade arrived
after the failure was cached and could not clear it. seaweedfs then read `health=Healthy`
**vacuously** with zero applied resources, kube-dns answered `no such host` 700 times, and
every mimir module died on its sanity-check.

**On metal it would be the same failure, one major version wider:** K3S installs v2.13.2,
then the root Application it applies carries 10.8.0 — so ArgoCD attempts to upgrade itself
across v2 → v3 (Helm 3 → Helm 4) in the earliest sync wave, on real hardware.

## The response to the first incident was prose

Four file headers now carry a paragraph saying *"All FOUR pin sites move together."* Prose
was already in place when the pin was left behind — **three times** — so prose is not what
stops the next one. And the prose was **wrong when written**: there were five.

## Measured before bumping, with this file's own values at both versions

- **40 → 44 resources, nothing removed**
- the four additions are all `NetworkPolicy` (application-controller, redis, repo-server,
  server) — four rather than the five `full-ai-cluster` measured, because dex is off here
  so there is no dex NetworkPolicy
- every value this file sets still lands: `argocd-server` Service is ClusterIP,
  `server.insecure: true` reaches `argocd-cmd-params-cm`, notifications render zero
  resources, and **dex renders zero resources at 10.8.0**

## The falsifier is the point

`audit-argocd-pin-parity.ts`, wired into `cross-verify` as two legs. **It went red on
`main` the day it was written**, naming this exact file and both versions.

- it **refuses** when the dev-cluster install-site count changes, rather than auditing
  whatever it found. The *roster* is what drifted both times, so "audit the sites I
  happened to see" is the failure mode, not the fallback.
- the dev-cluster scan is anchored on `chart: "argo/argo-cd"`, never a bare `version:`
  line — that file installs several charts, and a bare scan would compare cilium's pin to
  ArgoCD's and fail loudly on a **correct** tree, which is the kind of check that gets
  deleted rather than fixed.
- a missing or non-string pin is reported and does **not** also emit an agreement line: a
  partial audit reporting success is how a broken parser reads as a green tree.
- one falsifier reads all five **real** files, so a rename cannot leave the seven
  fixture-driven cases green over an audit that reads nothing.
