# Summary

Aaron: continue after the SoftHSM2 / swtpm install job (#16767). SoftHSM can witness `openbao-inits-without-shamir` only when HSM-enabled `bao` inits without Shamir unseal keys.

This PR adds a loud, path-filtered workflow that downloads the SHA-pinned glibc `openbao-hsm` 2.6.2 tarball (Otto's chart appVersion), apt-installs `softhsm2` + `opensc`, mints the AES wrap key with `pkcs11-tool` (OpenBao will not mint wrap keys), and runs `bao operator init` with `BAO_HSM_PIN`. PIN is never in HCL. Init JSON with Shamir `unseal_keys_b64` fails the claim. Recovery keys + health 200 without `bao operator unseal` is the pass.

Workitem: `081M1TV43F6087G0R0008QFTKM`.

This does **not** put `seal "pkcs11"` in Application.yaml. SoftHSM green is not YubiHSM / CardContact / this-board TPM green. The Alpine musl image is not this job's proof. extraContainer sidecar stays a later hop.

Live on this VM: `seal-emulator-bao: pkcs11-init ok recovery_keys=1 health=200`. Init JSON mode 0600. Run log does not contain the root token or recovery keys.
