## Description

## The problem

`src/Core.TypeScript/corporate/` could staff a work item through 117 hats, cross seven quality gates, catch regressions, escalate, bring in an architect, and print `goal DELIVERED` — **without doing any work at all**. Four boundaries made that possible, and none of them was visible in the output:

| boundary | what it meant |
|---|---|
| no work performed | no shell, no network, no file the run could point at |
| the inbound event was a hardcoded fixture | no Jira, no portal, no connector |
| a resumed surface had an empty queue and no QA history | resuming forgot what it was resuming |
| the model chose but did not work | a decision recorded as an implementation |

The failure they share is not that a simulation exists — simulations are the point of a deterministic register. It is that **a simulated run and a real one were indistinguishable to every reader**, live and afterwards.

## The change

**Five ports** (`Intake`, `WorkExecution`, `TestExecution`, `Review`, `ChangeControl`) behind a registry that **refuses rather than falls back**. An unresolvable port is an error, never a silent simulation — the one design decision the rest of this PR rests on.

**Adapters that reach real things**, all with the same safety shape (`shell: false`, argv arrays never interpolated with work-item text, exit code decides, captured output truncated visibly at 4 000 bytes):

- `httpIntake` — a Jira/portal ticket fetched over HTTP and field-mapped
- `agentWorkExecutor` / `commandProposal` / `modelProposal` — work performed by a command or a model
- `gitWorktreeChangeControl` — isolated worktrees and real `--no-ff` merges
- `directoryReview` / `commandReview` / `agentReview` / `modelReview` — gates decided outside the process
- and the simulated counterpart of each, which **says what it is** rather than impersonating the real one

**Both CLIs reach the same adapters.** `run-org.ts` and `run-agent.ts` share one `parseArgs` and one `providersFromArgs` — two mappings would be two sets of defaults to drift, and the default is the answer that decides whether a run touched anything.

**Fidelity is derived, never declared, and it survives persistence.** `fidelityOf(set)` computes `replayable` from the ProviderSet; nothing may assert it. It is recorded (`run_fidelity`), folded (`foldRunFidelity`), and printed. A run reports three things, all derived:

- `reached` — real **and** called; the only set "reached something" can honestly name
- `configuredNotCalled` — real and never called; its own answer, folded into neither of the others
- `replayable` — configuration-derived and deliberately conservative: a set holding a real adapter cannot be promised to replay whether or not this run got that far

**UNKNOWN is a third answer.** Runs predating the fact carry no fidelity, and reading that silence as "nothing was real" would invent a fact nobody observed. `deliveryRate` reports three buckets — real, simulated, unknown — and writes no field for a run that has none.

End to end against a real repository, a model choosing real work off a real cascade and doing it:

## Eight defects, none visible in review, all found by running it

1. **The review port was decorative.** `deps.gateChooser` could override the reviewer. Measured: 12 reviewer calls, **all REJECT**, `delivered: true`, no refusal recorded. The seam was removed rather than guarded.
2. **The store was losing events.** `identifyEvent` deduped by the writer's `event.id` rather than by content, so two different events sharing an id were **both written and one dropped on read** — 78 event files on disk, 58 readable. Now content-addressed: 78/78.
3. **`commandProposal` ignored `ctx.workdir`.** The agent wrote to the shared repo while the verifier looked in the worktree, so every item failed with the agent confidently reporting success.
4. **A performer with no verifier silently simulated.** `--work-agent claude` with no `--work-verify` fell past every branch to `simulatedWorkExecutor(true)` — an executor that reports success without doing anything.
5. **A merge that moved nothing reported success.** `git merge --no-ff` of a branch at the same commit as HEAD prints "Already up to date." and **exits 0**. Both git adapters read that as a merge, so a run that produced no commit reported real delivery over an untouched repository.
6. **A refused merge did not contradict `DELIVERED`.** The runtime's own comment said a refusal contradicts the claim; `delivered` was computed from the cascade alone.
7. **The `run_fidelity` fact was missing on three early-return paths**, so a store's run record and its event log could disagree about the same run — the record knew, the log did not.
8. **Nine docstrings documented the wrong symbol.** Inserting a function by anchoring on `export function X(` lands the new code *between X's doc comment and X*. Caught by none of tsc, eslint, the suites, or review — so it now has a lint (below).

Three stale stated-limits were also corrected. In this register `"stated rather than hidden"` makes a limit a promise about the code, so a stale one sends the next reader to build what already exists — one file asserted `queue` and `qa` are EMPTY three lines above its own code comment saying the opposite.
