## Description

CLAUDE.md told every agent to run `liveness-ledger.ts read --dir <checkout>`. The tool's own
usage says `--dir <ledger-worktree>`. Following the carved surface gives:

```
[liveness-ledger] the liveness ledger holds NO records at all — nothing has observed
the fleet, or the channel is broken
```

and exit 1.

**That is a false alarm in the one check whose job is telling real silence from apparent
silence** — produced by the instruction rather than by the fleet, and it is the worst
possible false alarm, because the message it prints is the exact wording of the condition
the ledger exists to detect.

## Measured both ways — it is the invocation, not the tool

| `--dir` | result |
|---|---|
| ledger worktree | **rc=0**, *"fleet last OBSERVED 6min ago"*, records: **290** |
| repo checkout | rc=1, *"holds NO records at all"*, records: 0 |
| empty dir | rc=1, same |

So the tool **fails closed correctly and needs no change.** It was the doc.

## And I read that wrong once first

The first run reported **rc=0 alongside the NO-records message** — which would have been a
genuine vacuity, the alarm condition exiting success, and I was about to write it up as
one. It was not: I had piped the output to `tail` and read `$?` from the pipe.
*Exit-code-through-a-pipe* is a mistake I have a memory file about. The correction cost one
command; the write-up would have cost a reviewer their afternoon.

## The fleet is fine, and the ledger's verdict is the useful part

Outcome **`paused`**, because `.github/workflows/agent-heartbeat.yml` is
`disabled_manually` — **verified independently against the Actions API**, not taken from
the ledger's word. Its 8-day silence is expected and correctly **not** reported as an
outage.
