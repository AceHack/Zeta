## Description

`generateArgoCD` wrote `path: infra/k8s/applications/${chart}` into every Application it emits, against `repoURL` Lucent-Financial-Group/Zeta at `main`. Wrong in two independent ways, and **the second is the defect**:

1. `infra/k8s` is the older cluster declaration, scheduled for deletion, and carries `prune`+`selfHeal` — ArgoCD would prune whatever it found there.
2. **`infra/k8s/applications` holds no per-chart directories.** It contains exactly one file, `root-application.yaml`. So the emitted path resolved to nothing for *any* chart, in either tree state. **The manifest looked correct and would have deployed nothing.**

Repointed to `full-ai-cluster/k8s/applications/${chart}` — the live tree, which does carry per-chart directories (50 of them).

## And the path is now asserted, because it was not

`deps.test.ts` exercised `generateArgoCD` for sync waves and `valuesObject` and **never looked at `spec.source.path`** — which is exactly why a path pointing at nothing could sit there under a green suite. Two assertions now:

- the exact emitted path, per chart;
- a negative: **no emitted path may sit under a tree the roster declares stale.** The stale set is *read* from `cluster-tree-consumers.json` rather than spelled in the test, so the guard covers whatever is scheduled for deletion when it runs — and the test does not itself become a consumer of a tree that is going away. Guarded by `expect(stale.length).toBeGreaterThan(0)`, since an empty stale list would make the loop assert nothing.

**Mutation-checked, not assumed.** Reverting the source line to the old path turns the suite red (17 pass, 1 fail). The assertion is live.
