## Summary

Two grow-only Bloom filters (I over ever-inserted keys, D over ever-deleted keys) belong on **ZetaDB / Core query membership**, not ZetaFS. Volume identity is ContentId (exact). Join-probe and negative lookup already sit on counting/blocked Bloom.

This targets the *reason* WONT-DO refuses deletable Bloom (silent false negatives), not Rothenberg's construction. Bits are never deleted. Unknown is named. `fp(I)×fp(D)` is the bound.

**Analysis, not a result.** Counting Bloom stays shipped. CQF stays radar Trial. ZD10 is the two measurements: product FPR vs counting space at equal guarantees, and unknown-region size under retraction churn **including insert-delete-insert resurrection** (grow-only D cannot return `present` after a key has ever been deleted).

Does not reopen WONT-DO deletable Bloom.
