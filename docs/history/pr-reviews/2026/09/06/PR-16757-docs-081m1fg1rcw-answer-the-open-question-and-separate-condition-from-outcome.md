## The open question is answered

That work-item asked whether the chart-generated `anvReadOnly` identity is *"deterministic
per-chart or regenerated per-render"*, and said **that decides whether it is a static
credential in a rendered manifest**. Two `helm template` runs of 4.45.0 against this
Application's own `valuesObject`, same inputs, back to back:

```
read_access_key_id: TfyV3sgj7l7wdsMzP3Mf
read_access_key_id: 97iPWEs9okjBlwK8XdRT
```

**Regenerated.** Not a static credential, and nothing in this tree declares it.

## What it surfaces instead is the same shape one layer over

A Secret whose content is non-deterministic per render *should* churn on every sync —
rotating an S3 identity under the running gateway — and it doesn't, because the chart puts
`helm.sh/resource-policy: keep` and `helm.sh/hook: "pre-install,pre-upgrade"` on that
object. **Nothing in this tree asserts those annotations exist.** If either changed
upstream, every sync would rotate a credential and no check would say so.
