**Two-thirds of everything Zeta accretes is one mechanism** — `docs/history/pr-reviews` +

## They are not duplicates of each other — my first read said they were

Identical file counts (13,983 each) invite that conclusion, and it is wrong:

- `docs/history/pr-reviews/PR-N-*.md` is the **content** — every review comment and thread.
  Its README calls it *"the project's most valuable data"* (maintainer, 2026-06-07) and
  **fuel** for the GitOps fine-tuning signal.
- `docs/github/prs/` is the **index** — ~10 JSON fields per PR pointing at that archive.

Both earn their place. Recorded rather than quietly corrected, because the next reader will
reach for the same wrong answer.

## The internal redundancy is real, and the stale side is the surprise

Measured across all of them:

```
manifest records             13,592
shard files                  13,982
shard identical to its line  13,475   (96.4%)
shard differs                   117   (fetched_at / commit_sha — the SHARD is newer)
shard absent from manifest      390
```

**`manifest.jsonl` is the stale copy, not the shards.** It is 390 records behind and
disagrees with 117 more — so anything reading it gets an incomplete, partly wrong index.
That is a correctness issue independent of size, inside a directory the README marks
protected. Dropping it and deriving on demand saves **one file, not fourteen thousand**.

## What it says about the ask

1. **The growth is the archive, and the archive is deliberate.** *Reduce size* and *keep the
   most valuable data* point in opposite directions on the same object — a maintainer
   decision, not a cleanup.
2. **The strategy already named fits it exactly.** Moving the pair to a dedicated archive
   repo with a pointer left behind removes **64% of the file growth and ~44 MB/month**
   without deleting anything. It is the one lever that changes the trajectory rather than
   the snapshot.
3. **Stopping growth and shrinking the past are different asks with different costs.**
   Moving the archive stops future accretion and is ordinary work. It does **not** shrink
   the existing 285.8 MiB pack — that needs a history rewrite, which is gated and only the
   maintainer authorises.

## Not proposed here, deliberately

No deletion, no move, no rewrite. The archive is marked *read-not-refactor* and its value
was asserted by the maintainer.
