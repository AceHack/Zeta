## Description

**The verdict sampled the thing it was named for (Applications) and not the thing that would discriminate between causes when it went red.**

## What the gap cost

Verdict 7's first live run (`36097310492`) measured Applications regressing — **25/35 Synced+Healthy at t=1214s → 13/35 at t=3007s**, then flat for 723s. Two mechanisms predict that fall, and they call for **different repairs**:

| mechanism | prediction |
|---|---|
| **eviction** — node under memory pressure, kubelet evicts BestEffort pods | the **pod** count falls with the Application count |
| **render failure** — repo-server cannot re-render inside its timeout | Applications flip to `sync=Unknown` while pods **keep running** |

They *were* separated — but **only by inference**:

- ArgoCD's health field: **47 of 102** unconverged rows read `health=Healthy`, and the eviction signature `sync=Synced health=Missing` occurred **zero** times (`sync=Synced health=Degraded` once).
- `grep -icE "evicted|OOMKilled|MemoryPressure|out of memory|oom-kill"` over the whole 2857-line serial: **0**. Kernel-side OOM: **0**. The one apparent hit on a wider pattern was `PREEMPT_DYNAMIC` in the kernel version banner.

That is good evidence. **It is not a measurement** — and it should not have had to be one. Verdict 6 counted pods exactly **once**, at t=152s, and nothing looked again for the next hour.

## What lands

Per sample, beside the Application counts, on serial and in the verdict JSON:

```
pods <running>/<total> Running/total
```

**Two numbers, because they answer different halves.** Eviction takes pods *away* (total falls); a pod can also persist in a terminal phase while being gone as far as a workload is concerned (running falls, total does not).

**A failed probe reports `-`, never `0`** — and both ride as strings for that reason. Same discipline as `081M3BP768B087G0R0010C6GPR`, which was this very verdict being bitten at this very layer: a probe that did not answer must never read as a cluster with no pods.

The summary line also states the discriminator in the output itself, so the next reader does not have to rederive it.

## The general lesson (why it is filed, not just fixed)

> When a verdict is designed, ask what the **two competing explanations of a red** would be, and sample enough to tell them apart.

A check that can say *what* failed but not *why* forces the next reader into inference — and inference is what the falsifier discipline exists to replace.
