## Description

`081M3BVERK0087G0R001GVH1QP`, **direction (2)** — the one worth doing *first* and *regardless* of the pre-staging fix, because it converts a mystery into a diagnosis even if that one slips.

## What the operator got

**MEASURED, run `36110246885`**: the first-boot install failed after all three attempts, and everything printed was

```
WARN: install.sh FAILED rc=1 after 3 attempts
Location: src/toolset/toolset_install.rs:244
```

— a Rust source location in a tool they did not know they were running, followed by 40 lines of everything matching `/error|fail|cannot/`. The actual cause was GitHub's **unauthenticated API rate limit (60/hour per source IP)** refusing the artifact-attestation verification `.mise.toml`'s trust policy requires. **Nothing about the machine was wrong, and nothing readable said so.**

## What they get now

```
CAUSE: GitHub's UNAUTHENTICATED API rate limit (60 requests/hour PER SOURCE IP)
       refused the artifact-attestation verification ...
CAUSE: NOTHING IS WRONG WITH THIS MACHINE. The limit is shared by every device
       on your public IP -- an office NAT, a CGNAT ISP or a campus network may
       have spent it before you started.
CAUSE: blocked tool(s): github:yannh/kubeconform@0.7.0
CAUSE: the limit resets at <UTC from x-ratelimit-reset>.
REMEDY: wait / different network / GITHUB_TOKEN (5000/hour).
REMEDY: do NOT disable attestation verification. The policy catches real
        supply-chain regressions; verify EARLIER, not LESS.
```

The **machine is not the problem** line is the most valuable sentence here: an operator's first hypothesis on a failed install is their hardware or their USB, and they are wrong — this is a budget shared with strangers on their public IP.

The last line is deliberate too. The next person under time pressure will look for a disable flag, and the argument against it belongs **at the point of failure**, not only in a work item.

DNS, connection-refused/timeout and disk-full are classified as well. The cause prints **above** the existing generic grep — one actionable sentence must not be buried in forty lines of everything.

## Silence is the floor, and it stays reachable

Anything unrecognised prints **nothing** and falls through to the existing diag. A classifier that always has an opinion would replace evidence with a guess, and **a guess printed in the same voice as a measurement is worse than the bare `rc=1` it replaces.** Four tests pin the silence, including a log that merely *mentions* attestations and rate limits.

## Two defects this found in itself

1. **Found by its own test, not in the field:** mise prints the same tool on two lines — `mise ERROR Failed to install X` and `0: Failed to install X:` — and the trailing colon defeated `sort -u`, so the first draft told the operator **two** tools were blocked when one was.
2. **My first mutation check was itself a check that could not fail.** The `sed` pattern did not match, so it reported 15/15 green against an *unmutated* file. Redone with an asserted replacement: **8 of 15 go red.** Likewise the `date -u` conversion is asserted against an **independent JS derivation** rather than the shell's own output — my hand-computed constant was wrong, and only the independent derivation caught it.
