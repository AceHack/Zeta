## Description

Work items only, no code change.

> **A first boot that depends on an external API is an install that fails for reasons the operator cannot see or influence.**

So for **every** external dependency of a first boot: **what does an operator get when it is unavailable?**

| verdict | meaning |
|---|---|
| **named refusal** | it stops, says which dependency, says what to do. **Fine.** |
| **partial install** | it continues half-provisioned and the error is a stack location. **What we measured.** |
| **silent skip** | it continues and nothing records that a step did not happen. **The defect class this whole effort is about.** |

## Ten dependencies enumerated — four measured, six honestly marked unverified

| dependency | when unavailable | status |
|---|---|---|
| `git ls-remote` preflight | **NAMED REFUSAL — and the model for the rest.** Runs **before any disk is wiped**, bails with reason, remedy (`nmtui`) and the reassurance that nothing was destroyed. | reviewed |
| pinned-commit `git fetch` | **NAMED REFUSAL** with an escape hatch that *records* that it was used | reviewed |
| `mise` attestation API | **PARTIAL INSTALL** — `rc=1` + `toolset_install.rs:244` | **MEASURED** `081M3BVERK0087G0R001GVH1QP` |
| ArgoCD repo-server | **PARTIAL, and it does not self-announce** — apps sit at `sync=Unknown`; the node looks up and the apps never arrive | **MEASURED** `081M3BPJNRS087G0R0008WFXBZ` |
| discovery probe | **SILENT SKIP — the worst class, and it has NEVER RUN** (`--no-db-lookup`, a flag this `avahi-browse` does not have) | **MEASURED** `081M39K8ND1087G0R000G4EN4N` |
| Nix substituters · 5 Helm chart repos · DNS/NTP · image pulls | **UNKNOWN** — read off source, not observed | **unverified** |

The six `unverified` rows are stated as unverified on purpose. Each is answerable by making the dependency unreachable and watching — which is what a lane is for.

## A new measurement the inventory produced

The 134 first-boot images span **eight** registries. The pull-through cache covers **one**.

```
48  registry-1.docker.io   <- MIRRORED via mirror.gcr.io
34  quay.io                <- no mirror
31  ghcr.io                <- no mirror
14  registry.gitlab.com    <- no mirror
 4  registry.k8s.io        <- no mirror
 3  cgr.dev / code.forgejo.org / ecr-public.aws.com
```

**36 % covered.** WP9 added `mirror.gcr.io` for exactly the right reason — Docker Hub's anonymous limit is 100 pulls / 6h / source IP and a first boot pulls 50+ distinct docker.io images from behind one NAT. The other **64 % have no cache at all**, and `registry.gitlab.com` at 14 images is the next one to look at.

Same shape as the attestation finding: **a per-source-IP budget on a shared address, spent by strangers, failing an install for a reason the operator cannot see.**

## The ranked call on `081M3BVERK0087G0R001GVH1QP`

- **(4) Pre-stage the verified binary in the ISO — THIS IS THE FIX.** Already a pinned version; the ISO is already built in CI where a token exists. Verification at **build** time happens **once**, on a machine we control, with the policy **fully enforced**, instead of once per operator on a network we do not control. It **removes** the dependency rather than making it more reliable.
- **(2) Name the rate limit — first, regardless of (4).** Small, and it converts a mystery into a diagnosis if (4) slips.
- **(3) Back off on a 403 — a palliative, and the item says so.** A rate-limit window can be an hour; no in-install backoff waits that out.
- **(1) Token where one exists — CI only,** and it must not look like an operator fix. Fixing the lane while leaving the product broken is how a check stops representing what it claims to.

And for the next person under time pressure reaching for the disable flag:

> **The answer is to verify EARLIER, not to verify LESS.**
