## Description

The pod-count instrument landed in #17665 with a guard that **cannot fire**, and its first live run proved it.

```sh
ROSTER_POD_TOTAL="$(kc get pods -A --no-headers | $WC -l | $TR -d ' ')"
if [ -z "$ROSTER_POD_TOTAL" ]; then ROSTER_POD_TOTAL="-"; fi
```

A kubectl that fails prints **nothing**, `wc -l` counts nothing and prints `0`, and `0` is not empty — so the emptiness test is never true and a failed probe was reported as *a cluster with zero pods*.

**MEASURED, run `36114004943`: two samples printed `pods 0/0` and not one ever printed `pods -/-`**, on a cluster carrying ~148 pods.

A check that cannot fail, guarding against checks that cannot fail, written in the same commit whose message explained why that class is dangerous. The mechanism is the one this repo keeps meeting: **a failed probe and a genuine zero produce the same output, so only the exit status distinguishes them — and I tested the output.**

## The fix is also a falsifier

The logic moved into `zeta_wp11_count_or_unknown` **inside** the `ZETA-WP11-ROSTER` parity block, so the extracted-verbatim test executes it under a real bash+awk. Five cases, and the first two are the pair the old version could not tell apart:

| probe status | output | result | |
|---|---|---|---|
| **failed** | empty | `-` | **old version said `0`** |
| succeeded | empty | `0` | a real, measured zero |
| **failed** | some rows | `-` | the status wins |
| succeeded | 3 rows, no trailing newline | `3` | awk, not `wc -l` — command substitution strips the trailing newline and `wc -l` undercounts the last row |
| succeeded | blank lines present | not counted | |

Parity tests **26 → 31**. `bash -n` clean, typecheck clean.

## The instrument still did its job on that run

Which is why the bug was visible rather than fatal. The series that answered the eviction-vs-render-failure question **directly**, rather than by inference:

```
t=1104   apps 16/43   pods  90/152
t=1334   apps 12/43   pods  96/148
```

**Applications fell while pods held** — running pods went *up*. Eviction predicts the pod count falling with the Application count; it did not. Zero `evicted` / `OOMKilled` / `MemoryPressure` lines on the whole serial, for the second run running.
