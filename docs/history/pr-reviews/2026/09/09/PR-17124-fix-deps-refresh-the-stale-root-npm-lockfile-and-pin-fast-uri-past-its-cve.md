## Description

fix(deps): refresh the stale root npm lockfile and pin fast-uri past its CVE

Fourteen open Dependabot alerts sit on npm lockfiles. Ten are on the root
package-lock.json; this closes nine of them, and the reason most of them
existed is worth stating plainly.

package-lock.json was STALE against bun.lock. The repo declares
packageManager bun@1.3.13 and CI installs with bun, so bun.lock is what is
actually installed -- but package-lock.json is what Dependabot reads, and the
two had drifted to different transitive resolutions of the same declared
dependencies:

  package                      package-lock.json    bun.lock
  markdownlint-cli2 js-yaml    4.1.1 (vulnerable)   5.2.2 (patched)
  markdown-it                  14.1.1 (vulnerable)  14.3.0 (patched)

So four alerts (16, 18, 19, 31) described versions the repository has not
installed for some time. They were true statements about a file, and false
statements about the build. Regenerating package-lock.json from package.json
makes the file describe reality, which is the honest way to close them --
the alternative was dismissing four alerts on a claim no check re-runs.

Two were real in BOTH lockfiles and are genuinely fixed:

- fast-uri 3.1.2/3.1.5 -> 3.1.7 (patched at 3.1.6). ajv asks for ^3.0.1, so
  the patched version is in range; pinned via a flat `overrides` entry
  alongside the existing smol-toml one, which both npm and bun honour.
  Closes alerts 23, 24, 25, 26.
- cosmiconfig js-yaml 4.1.1 -> 4.3.2, within its own ^4.1.0 range. bun
  re-resolved this on its own during the lockfile regeneration; no override
  was needed, and markdownlint-cli2 keeps its separate js-yaml 5.2.2.
  Closes alerts 17, 18, 19, 31.

A wrong turn worth recording, because the wrong version looked like a fix.
The first attempt used a global `"js-yaml": "4.3.2"` override. That resolves
the alert and silently DOWNGRADES markdownlint-cli2 from js-yaml 5.2.2 to
4.3.2 -- a major downgrade of a tool the gate depends on. The second attempt
scoped it as a nested override under cosmiconfig; bun warns
"Bun currently does not support nested overrides" and ignores it, so npm's
lockfile would have shown the fix while bun -- the installer CI uses --
carried on installing 4.1.1. That is a fix visible only to the scanner. Both
were dropped; the regeneration turned out to fix it correctly with no
override at all.

Deferred, tracked, not dismissed: alert 15, mathjs 6.6.5 (high). The patched
version is 7.5.1, quantum-circuit@0.9.250 requires ^6.0.3, so this is a major
bump of a numerical library underneath a package the cross-verification
roster loads (src/Core.QSharp.ReferenceOracle, src/Core.TypeScript/ci/
cross-verify-roster.ts). It needs the byte-lock re-run, not a drive-by
lockfile edit. Filed as 081M22RGXDA087G0R0009FB070.

Also out of scope here: the four qs alerts (21, 22, 27, 28) are in pnpm
lockfiles under src/Renderers/website and demo/identity-dla-site, a
different ecosystem and a separate change.

Verification: bun install resolves; bunx markdownlint-cli2 README.md exits 0;
bunx tsc --noEmit -p tsconfig.json exits 0; bun test on
hygiene/agencysignature-block.test.ts passes 82/82. The bun.lock diff is
three lines -- the override entry and the two version bumps -- so what
changed for the actual build is reviewable by eye.
