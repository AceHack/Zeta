## Description

Aaron asked for **one kind cluster bring-up per enabled chart-set, one job each, in parallel**. This ships the prerequisite that is worth having whether or not the split happens, and puts the split itself up for sign-off rather than landing a CI decision unreviewed.

## The falsifier

`lane-partition.ts` **prints** `covered by a lane: 47/49`. Nothing failed when that ratio dropped, and `k8s-lane-partition.yml` fails only on a **zero-lane** matrix — so a single Application quietly leaving every lane (a new chart, a changed dependency edge, a footprint that grew past the budget) was invisible. A report is not an assertion, and a split built on an unchecked coverage claim would be a quiet way to stop testing something.

The rule now checked: every Application the **included proof** asserts is either assigned to **exactly one** lane, or quarantined with a **named artifact**. Duplicate assignment fails too — an app asserted in two lanes hides which lane proved it.

| mutant | tests failed |
|---|---|
| an unpriced app vanishes instead of being quarantined | 3 |
| a quarantine reason is emptied | 2 |

Plus a non-vacuity test: the asserted roster must be ≥ 30 apps and at least one lane must hold at least one app, so neither an empty roster nor a zero-lane partition can read as coverage. Live instances exercising the quarantine branch today: `hat-system` (unpriced — a dangling ghcr reference) and `gitlab` (oversize).

`argocd-health-test.ts` joins the workflow path filters, since the covered set now comes from `discoverExpectedApplications`.

## The design doc

`docs/research/2026-09-09-one-kind-cluster-per-chart-set-...md` — **DRAFT, five numbered questions awaiting sign-off.** It records where the measurement contradicts the reason the split was proposed:

- **The lane is not starved.** Run `34338106811` reached 37/37 in **513 s** against a 2400 s cap — 4.7x headroom. Run `34323056405` reached 35/37 in 497 s and then sat 1900 s on exactly two genuinely-broken apps (`headscale`, `orleans`).
- `cdi`/`kubevirt` read `Missing` because they are declared **`manualSync`**, not because a sync wave was never reached. `weaviate`/`hindsight` are `excludedFromDev`. Four more "drifting" apps were counted **ok** by the proof own final poll 18 seconds before the dump that showed them `OutOfSync` — the green run dump lists **more** `OutOfSync` apps (20) than the red one.
- **Parallelism is real at the current width**: six concurrent jobs started within a 4–5 second spread in two measured runs. That is evidence for 6, not for 30, and the doc says so.
- **The ask survives the refutation on attribution**, which headroom does not buy: 37 apps in one cluster scope a failure to "something in this cluster".
- **Most of the machinery is already Aaron own**, from his 2026-08-22 observation: dependency closures, pricing, a per-lane matrix job, and `laneRootExclude`, which already computes the glob that would bring up only one lane Applications. The gap is three named items.
- **The scarce resource is registry pulls, not minutes** — `k8s-lane-partition.yml` already retries pulls because "registry throttles are transient", so throttling has been met at the current width.
