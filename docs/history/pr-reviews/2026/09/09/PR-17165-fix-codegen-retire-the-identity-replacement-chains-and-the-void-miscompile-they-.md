## Description

Fourth-tranche code-scanning cleanup. Closes the whole `js/identity-replacement`
class (10 alerts, 537-546) **by fixing, not dismissing** — holding the
zero-dismissal bar of the three prior tranches.

## The alerts

All ten are in `tests/cross-verification/_harness/codegen-interface.ts`, and all
ten are links in a chained `String.prototype.replace` that map a token to
ITSELF: `.replace(/\bint\b/g, "int")`, `.replace(/\bbool\b/g, "bool")`, and so
on.

## The dead links were hiding a real defect

Seven functions mapped IR type names to a target language by CHAINING `.replace`
calls. A chain is order-dependent — every later pattern re-scans the OUTPUT of
every earlier one, so mapping `int64 -> int` and then `int -> long` silently
yields `long` for `int64`. Nothing here tripped that, but nothing prevented it.

More to the point, **the identity links made each chain LOOK exhaustive.**
`goType` enumerated four tokens, all four mapping to themselves — it reads as a
complete mapping and is in fact the identity function. Under that appearance:

| language | `void` row | emitted for a void-returning member | valid? |
|---|---|---|---|
| C# | absent | `public void Accept(T value);` | yes — `void` IS the C# spelling |
| TypeScript | absent | `Accept(value: T): void;` | yes — same |
| Python | present | `-> None` | yes |
| Q# | present | `: Unit` | yes |
| **Rust** | **absent** | `fn accept(&self, value: T) -> void;` | **no — `void` is not a Rust type** |
| **Go** | **absent** | `Accept(value T) void` | **no — a Go method returning nothing omits the result type** |

Twelve members across four committed IR fixtures (`database`, `port`, `zset`,
`zset-isa`) emitted code that does not compile in either language.

## What changed

1. **The seven chains become seven declared `TypeMap` tables**, applied by a
   single `applyTypeMap` pass. One pass cannot cascade, so order-independence is
   **structural** rather than a fact about the current ordering. The mapping is
   now DATA and its gaps are visible.
2. **`RUST_TYPES` gains `void -> ()`.** **`GO_TYPES` gains `void -> ""`** and the
   Go emitter appends the result type only when it is non-empty.
3. **`codegen-interface-golden.json`** byte-locks all 7 emitters over all 17
   committed IR fixtures — text in JSON, per
   `.claude/rules/no-binary-in-proof-lineage.md`, so drift is a readable diff.

**The refactor is proved behaviour-preserving, not asserted.** The golden vectors
were generated from the ORIGINAL code before any chain was touched, regenerated
after the refactor, and diffed: **byte-identical across all 119 emissions**. Only
then was the void fix applied, which makes it the sole behavioural delta in this
PR — 8 vectors wide, all of them `void` becoming valid syntax.

## Falsifiers, and what mutation testing found

New in `codegen-interface.test.ts` (42 pass, 0 fail):

- **`applyTypeMap does not cascade, and a chain would`** — asserts the correct
  result AND that the chain it replaced disagrees, so it cannot go vacuous.
- `key declaration order cannot change the result` — reverses every static map.
- `longer keys win over their own prefixes`.
- `a key a word boundary cannot anchor is REFUSED` — an entry that can never fire
  is the vacuity class, so a non-bare-word key throws rather than being escaped
  into something that matches nothing.
- `which IR primitives each language leaves unmapped is PINNED` — a primitive
  absent from a map passes through unchanged, which is correct only when the
  language spells it the way the IR does. No test can check that, so the set is
  pinned and any change is loud.
- the per-language void-spelling block, and the golden byte-lock plus a
  non-vacuity check on the lock itself.

Four mutations were run:

| mutation | outcome |
|---|---|
| drop both `\b` anchors from the pattern | **killed** by 3 tests |
| remove `void` from `RUST_TYPES` | **killed** by 3 tests |
| Go emitter always appends the return type | **killed** by 2 tests |
| longest-first key sort reversed to shortest-first | **SURVIVED** |

**The surviving mutation changed the code.** A longest-first sort had been
written into `applyTypeMap` to make `int64` win over `int`; reversing it changed
no result, because the `\b` anchors had already decided every prefix case by
backtracking (`(?:int|int64)` tries `int` inside `int64`, fails the trailing
boundary against the `6`, backtracks, takes `int64`). The sort was dead code — of
exactly the class this PR is about — so it was **deleted rather than kept as
decoration**, and the comment now credits the boundaries.

The Go mutation initially escaped the unit test and was caught only by the
byte-lock, because the mutant left a trailing space. That assertion is now
anchored to the exact emitted line.
