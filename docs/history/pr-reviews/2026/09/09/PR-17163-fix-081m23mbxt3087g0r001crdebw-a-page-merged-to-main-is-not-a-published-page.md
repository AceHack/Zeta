## Description

fix(081M23MBXT3087G0R001CRDEBW): a page merged to main is not a published page

`demo/clifford-e8/` landed on `main` in #17155 and 404s at
https://lucent-financial-group.github.io/Zeta/demo/clifford-e8/

Measured after the merge:

  GET /Zeta/                      -> 200
  GET /Zeta/demo/clifford-e8/     -> 404
  GET .../clifford-e8-substrate.js -> 404

The cause is that this site is `build_type=workflow`: `pages-deploy.yml`
assembles `./dist` and uploads THAT, not the repo root. Nothing copied the demo
in, so committing the page to `main` published nothing. The merge looked like
the last step and there was no signal that it wasn't.

Copies rather than rebuilds. The bundle is a build artifact of the rung 1-7
modules that is committed beside its page, and a falsifier already executes the
COMMITTED bundle and asserts its positions, levels, histogram and a ray-traced
frame equal the TypeScript modules'. Rebuilding it in this workflow would create
a second producer of the same bytes — the duplicated-implementation shape that
mutation testing caught one rung earlier, where `lambertCosine` could be forced
to a constant and survive 670k assertions because a copy was what the tests
actually exercised.

The step fails closed: absent or empty inputs and outputs are `test`-ed on both
sides of the copy, so a missing file fails the build instead of publishing a 404
— which is the defect being fixed, and it would be poor to reintroduce it as the
fix's own failure mode.

A NOTE ON WHY #17155 SAT BLOCKED, because the record currently says otherwise.
It was reported as GitHub evaluation lag that cleared on its own. It was not.
`main` carries `required_conversation_resolution=true`, and the PR held seven
unresolved bot threads. Verified before resolving them, not assumed stale:

  - the two CodeQL threads named alerts 922/925; the PR ref returns ZERO alerts
    and the head has zero `.innerHTML =` assignments, so both were already fixed
  - the two "guard always evaluates to true" threads flag `if (stats !== undefined)`
    in the GENERATED bundle, where the page's single call path always passes
    stats; in the source `stats` is optional and four call sites in
    clifford-e8-raytrace.test.ts omit it, so the guard is exercised as false
  - the five "unused variable" threads name library constants a bundle carries
    and the page does not consume

The merge fired within seconds of the seventh resolve. The distinction matters
operationally: "lag" means wait, and waiting would not have worked.
