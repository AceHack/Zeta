## Description

docs(security): file the research-record dependabot class for a maintainer decision

38 of the 44 remaining Dependabot alerts -- including the only open critical
and 10 of the 13 highs -- sit on two files:
docs/research/2026-09-08-character-evolution/*/requirements*-resolved.txt.txt

Those are byte-preserved provenance records of an EXTERNAL project's resolved
dependency set, captured for a rejected character-reconstruction experiment.
The archive README states the convention: snapshots preserve original bytes
with a trailing .txt appended. Nothing in the repo installs them; searching
for the filenames returns only the two inventory JSONs and an archived
.py.txt record. The dependency graph matched them because the doubled suffix
still ends in .txt and the basename starts with "requirements".

not_used is very likely the correct disposition. It is not being applied here
because it would be 38 dismissals on a public repository resting on a
grep-shaped proxy for "nothing installs this" rather than on a check that
re-runs -- and a mass-dismissal nothing can later falsify is the shape of
failure this repo is built to refuse. The alerts stay open; the decision goes
to the maintainer with the evidence and three options written out, one of
which (renaming the preserved files) would quiet the scanner by editing a
byte-preservation archive, which is exactly the trade someone other than me
should make.

Also recorded, so they are not lost in the noise: the qs alerts in the two
pnpm lockfiles are RUNTIME scope and real, and src/Interp.Python/uv.lock has
a real accelerate advisory. Both are separate changes from this one.
