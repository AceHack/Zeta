## Description

Routed by the maintainer: pull the **rolling** v1.8.0 `tla2tools`, not the old immutable v1.7.4, and not a jar checked into git — *"the updates may find new cases"* — and build it so that *"we might need an exception like this in the future again"* is cheap. So `rolling=` is a **general `from-url` regime**, not a TLA special case.

## The regime

An upstream that **replaces the asset behind a URL**. The digest stays mandatory and still **fails closed** on every rebuild — a pin under a mutable tag is DETECTION, never permission. A future rolling dependency is one row.

| surface | what it adds |
|---|---|
| `manifests/from-url` | `rolling=` · `identity=` · `remeasure=` · `pinsurfaces=` on one row |
| `setup-realizers/from-url.ts` | names the rebuild, prints both digests, prints the remedy |
| `manifests/from-url-rolling-receipts` | the pinned digest must NAME the run that judged it |
| `tools/setup/repin-rolling.ts` | one command: fetch → rewrite every pin surface → re-measure → receipt |
| `lint-verifier-jar-provenance.ts` | a third regime, `fetched-rolling`, with the receipt + pin-surface checks |

**Bumping a digest by hand to make a red tree green is the failure this exists to stop.** It swaps the model checker under every claim the checker established, in a one-line diff that reads as housekeeping. The tool refuses to write a digest whose `remeasure=` run did not pass; the lint refuses a rolling pin with no matching passing receipt.

## Measured — and it is worse than "monthly"

| time (UTC) | rev | sha256 | gate models |
|---|---|---|---|
| 12:48:04 | `65fbace` | (not measured) | — |
| 15:25:40 | `4ad12e8` | `82cc5759…` | **52/52** |
| 16:25:36 | `4ad12e8` | `bb82311b…` | **52/52** ← pinned |

Three rebuilds in four hours. The last two **share a rev** — same source, different bytes, no `master` commit between them — so a rebuild is often not a new checker at all, and the digest cannot tell the difference. Over the prior 180 days `master` had commits on 24 distinct days.

**The open question this cost buys, left to the maintainer rather than decided here:** mirror the measured bytes to one immutable asset under our own org and pin that. It keeps every property asked for (no jar in git, newest checker, `git clone` at a tag still sufficient) and removes the fleet-wide breakage window, at the price of becoming a redistributor of an MIT-licensed third-party binary. Written up in the work item.

## Re-measured, both builds, 52/52, no expectation edited

`82cc5759` by hand and `bb82311b` by `repin-rolling.ts` itself — its end-to-end dogfood. Transcripts under `docs/cross-verify/`. `QuorumCollateralDeterrenceR2` still prints the discriminating `Temporal property Deterrence was violated`, the diagnostic the immutable v1.7.4 loses — which is why v1.7.4 (51/52) was declined.

## The follow-up bugs

- **The wedge.** An on-disk file whose digest no longer matched made the `from-url` realizer **throw**, and `from-url` is not best-effort, so `install.sh` aborted fleet-wide with no remedy printed and no way out but a hand `rm`. Every provisioned machine hits that the moment a pin moves. It now discards the stale bytes and re-fetches; fail-closed is untouched because the replacement is verified before it lands. **That fix is what makes caching the jars safe.**
- **The cache name was false.** 25 `actions/cache` steps said "verifier jars" and cached neither — the TLA jar came from git, the Alloy jar was re-downloaded every job. Both jars are now in the path list of all 27 `install.sh` cache blocks (path lists stay byte-identical, per `installer-unit-tests.yml`), and two blocks caching the same outputs under a narrower name were renamed.
- **`install.ps1` drove no Bun realizer at all**, so a Windows box never got `alloy.jar` — masked because Alloy's gate leg only asserts the jar on Linux-x64 CI. It now runs `setup-realize.ts from-url`, that one platform-neutral mechanism, gracefully. Scope is deliberately one mechanism, not `--all`.
- **`doctor.sh`** told a user to `git checkout --` a file git no longer tracks.

## Not done, deliberately

`nci-witness-receipt.ts` stays pinned to TLC2 `2026.05.18.174321`. That receipt is a **dated claim about which checker produced a witness**, so advancing it would have republished a 2026-09-06 research artefact to match a newer build. Its test now reads those exact bytes back out of git **by blob id** (`2fb671d8be5a1e137f001965d0246509e882aed3`) — content-addressed, permanent, and no binary re-committed.
