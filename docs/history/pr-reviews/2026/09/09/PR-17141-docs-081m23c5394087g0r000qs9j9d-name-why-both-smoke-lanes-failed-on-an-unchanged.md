## Description

Run `34367032579`, a dispatch on **unchanged** `main` (`28527c40`): **both** `live kind ArgoCD health` jobs failed — amd64 and arm64 — while the `live kind included Synced+Healthy proof` **in the same run passed**.

## The cause

The root Application carried:

```
ComparisonError: Failed to load target state: failed to generate manifest for
source 1 of 1: rpc error: code = DeadlineExceeded desc = context deadline exceeded

  repoURL:           https://github.com/Lucent-Financial-Group/Zeta
  targetRevision:    28527c40c7a7cf7816dcd535a39c218d166846ba
  directory.recurse: true
```

`git count-objects -vH`: **size-pack 649.45 MiB**. ArgoCD's repo-server has to clone that inside a kind node and finish manifest generation within `ARGOCD_EXEC_TIMEOUT` (default 90 s). Nothing overrides it — the install in `dev-cluster/use-cases.ts` sets exactly one value, `server.service.type=ClusterIP`.

## The asymmetry inside one run is the proof

The included proof runs the same ArgoCD, on the same runner image, against the same commit, and never touches that path — `--serve-tree dev` packs the tree and serves it in-cluster:

```
[serve-tree] rung=dev files=149 repoURL-rewrites=13 packed=497927B
```

**497,927 bytes against 649 MiB — about 1,300x less to fetch.** That is why one passed and two failed on the same commit in the same run.

## Register: ONE occurrence

The smoke lane was green in the three preceding runs (`34254081213`, `34323056405`, `34338106811`) on the same code path. So this is a **margin that repository growth has been eating**, not a break. Both architectures failing at once on an unchanged tree points at a shared external variable — clone throughput — against that thin margin. A second dispatch is running to settle the register.

## Filed, not fixed — and the reason is stated

Two candidate remedies, and choosing between them is a CI decision rather than a bug fix:

1. Raise `ARGOCD_EXEC_TIMEOUT` on the repo-server. Cheap; buys time, does not fix the trend.
2. Stop cloning the whole history. Large, and it narrows what the lane proves.

And what must **not** happen, written down so a later agent under time pressure does not reach for it: pointing the smoke lane at `--serve-tree` to make it green would delete the only place the GitHub-backed App-of-Apps path is exercised at all, which is the entire reason this lane is separate from the included proof.
