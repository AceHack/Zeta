## Description

fix(cluster): capture WHY a pod keeps dying, not just that it is not running

Measured on the live lane 2026-09-08. `headscale` and `orleans` were the two
Applications holding the whole `included Synced+Healthy` proof open for its full
2400s budget, and NEITHER appeared in the `not-running-pods` dump.

The reason is structural: a CrashLoopBackOff pod is in phase **Running** between
restarts, so a selector keyed on phase cannot see it. Only `warning-events`
caught them, with "BackOff restarting failed container" -- which names the
SYMPTOM. The container's own last words were nowhere in the bundle.

That is the same gap the roster's own comment already describes for Pending pods
("a diagnostic bundle that cannot distinguish Pending from CrashLoopBackOff is
not a diagnosis, it is a prompt to speculate"), one case further along: the
earlier fix reached "which pod", this reaches "why it died".

Adds `collectCrashLoopLogs`: one `kubectl get pods -A -o json`, select containers
that are restarting, and capture `logs --previous` for each. `--previous` is the
point -- the CURRENT attempt is usually still starting or already dead, and the
useful output is the exit of the attempt before it.

THE SELECTOR TAKES EITHER SIGNAL, and that is deliberate: a container can sit in
`CrashLoopBackOff` with restartCount still 0, and one mid-restart can have an
empty waiting state. Keying on only one misses a real case, which is exactly how
these two pods stayed invisible.

Bounded on purpose -- one pod scan, only restarting containers, at most 8 of
them, tail-limited, each call timeout-bounded. A diagnostic bundle that can
itself hang or explode is a second failure stacked on the first.

Falsifiers over the pure parser (5 tests), mutation-checked:

  * dropping the CrashLoopBackOff arm of the selector fails exactly the
    "zero recorded restarts" test (102 pass / 1 fail);
  * removing the JSON try/catch fails the malformed-output test AND two
    PRE-EXISTING failure-shaping tests -- the guard is load-bearing beyond my
    own coverage. A parser that throws here would replace one diagnosis with two
    failures, while the bundle runs precisely when something is already broken.

Restored: 103 pass / 0 fail. tsc 0 errors.

WHAT THIS DOES NOT DO: it does not fix headscale or orleans. It makes the next
red run name their cause instead of describing their state, which is the
precondition for fixing them on metal rather than guessing.
