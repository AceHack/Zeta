## What

Fourteen `TokenPermissionsID` alerts across thirteen workflows granted `GITHUB_TOKEN`
`contents`, `actions` or `issues` **write at workflow level**. Every job in each file
held that write whether or not it wrote anything, and every job added later would
inherit it silently.

Twelve files: **the effective grant per job is unchanged, only its scope narrowed.**
Top level becomes `contents: read`; the write is declared on the job that performs it.
One file loses a grant outright.

## The one real over-grant

`agent-proposal-gated-commit` held `pull-requests: write` that `GITHUB_TOKEN`
**could not reach**. The only PR call is `createGatedReviewPullRequest`
(`proposal-gated-commit-runner.ts:127`), which sets `GH_TOKEN` to
`ZETA_PR_ARCHIVE_TOKEN` explicitly and **throws on an empty token**, so it never
falls back to the workflow credential. `flush-via-staging.ts:47` records why no
lane can use it:

> THE PR CANNOT BE OPENED BY `GITHUB_TOKEN`. The enterprise forbids the Actions
> identity from creating pull requests.

The grant conferred close, merge, comment and label on every PR in the repository
and bought the lane nothing.

## Why a YAML-only reading was not enough

`agent-proposal-gated-commit` and `passkey-proposal-gated-commit` look write-free
in their YAML — no `push`, no `gh api`. Both genuinely need `contents: write`
because their **runners** push the review branch with the checkout's persisted
credential. Every grant here was followed into the script it calls before being judged.

## Honest limit — read this before scoring it by alert count

This closes the fourteen **topLevel** findings and Scorecard will open **jobLevel**
findings in their place, because it flags a job-level write too. **The count is not
the point; the blast radius is.** A workflow-level grant is held by every job in the
file, including ones not yet written. The seven workflows already flagged at job level
(784, 780, 779, 778, 777, 693, 564) are in that already-correct shape and can only be
*justified*, not fixed — Scorecard's `TokenPermissions` cannot reach zero on this repo
without removing writes the lanes genuinely perform.
