## Description

fix(081M24DNGYK087G0R0002C26Z9): wrap the code-scanning alert read, because the ad-hoc one was wrong

Aaron, after the fourth confidently-wrong reading of the session: "not [to] rely
on adhoc commands ever, write a ts script that's reproducable and rate limit
friendly ... ad hoc commands are never safe really, you get them wrong 1000s of
times a day and make tons of mistakes."

He is right, and this is the specific instance. **Nothing in this repository read
`code-scanning/alerts` from committed code.** Five tranches of security work —
roughly eighty alerts closed today — ran entirely on `gh api ... --jq`
incantations typed fresh each time. One of mine was wrong:

  ?ref=refs/pull/17177/head   -> []
  ?ref=refs/pull/17177/merge  -> 1 OPEN  (929 js/prototype-pollution-utility)

`refs/pull/N/head` returns an empty list for EVERY pull request, always, because
code scanning analyses the merge commit. The emptiness is structural, not
observational — and it reads exactly like "no findings". On that basis I resolved
two review threads that sat on live alerts. Corrected and re-opened; this is the
mechanism so nobody types it again.

THE REF IS NOT A PARAMETER. `alertRefForPr` is the only way to name it and it
cannot spell `/head` — a caller that could pass a ref could pass the wrong one,
which is the defect. It refuses a non-positive or non-integer number rather than
building a malformed ref.

AND AN EMPTY LIST IS `unknown` UNTIL THE ANALYSIS IS KNOWN TO HAVE RUN. The
outage earlier the same day made that concrete: CodeQL jobs died at their
toolchain-install step, so `Analyze (csharp)` was `failure` while the alert list
was empty. Reading that emptiness would have declared clean an analysis that
never happened.

Both halves are checked TOGETHER, and the reason is the sharper half of the
lesson: on 2026-09-10 I applied the analysis-ran guard CORRECTLY, over the wrong
ref. A sound guard over a wrong query is still a wrong answer, because no amount
of confirming that CodeQL ran can surface an emptiness that is structural.
Neither half is sufficient alone, so neither is offered alone.

Composes rather than duplicates. I first wrote a parallel PR-inspection tool and
deleted it on finding `check-observations.ts`, which already does roster-first
latest-run-per-workflow, already treats `cancelled` as establishing no verdict
(265 of 300 gate push runs, measured), and already runs through the
FerryThrottler. This adds only the piece that was genuinely absent and follows
that file's shape: pure functions, no IO, the measurement in the docstring.

Falsifiers: 11 tests, each pinning a wrong reading that actually occurred rather
than a hypothetical one. Six mutants, five killed — /head (2), trust-empty (3),
count-closed-as-open (2), always-none (1), accept-bad-number (1) — and a
comment-only CONTROL that survived, so the suite discriminates.

Not claimed: this does not fetch. The IO seam belongs with the caller, and
wiring it into the alert-triage path is follow-up rather than smuggled in here.
