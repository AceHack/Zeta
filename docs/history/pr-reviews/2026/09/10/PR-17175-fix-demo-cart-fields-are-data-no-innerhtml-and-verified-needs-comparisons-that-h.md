## Description

## What

Closes CodeQL **`js/xss-through-dom` alert 466** (`demo/chip9-cart-viewer.html:105`), and gives a page that had **no test at all** a falsifier.

## What the alert was hiding

The viewer takes a JSON cart from a textarea — untrusted input — and put fields of it straight into `innerHTML`. CodeQL named **one** flow. Measured 2026-09-09 with a stub DOM, there were **five** defects, and the two worst were not the XSS:

| cart | behaviour before |
| --- | --- |
| `name` carrying markup | rendered as **live markup** (the named alert) |
| `steps` carrying markup | rendered as **live markup** — a **second flow on the same line** |
| `height: 0`, `goldenRows: []` | displayed **VERIFIED** after **zero comparisons** |
| `goldenRows` longer than `height` | displayed **VERIFIED**, the extra rows never compared |
| `romHex` / `goldenRows` absent | uncaught `TypeError`; the page froze on the **previous** render, so a refused cart looked like an accepted one |

`VERIFIED` is an integrity claim shown to a person, and the loop that produces it could run zero times while the flag stayed `true`. That is the vacuity class wearing a verification result, and no taint analysis could have seen it.

## Fix

- `meta` and `screen` are built from **DOM nodes**. `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `document.write` appear nowhere in the page any more; the 3-bit gamut moved from a concatenated `style=""` into CSS classes `.c0`..`.c7`, so no attribute is assembled from data either.
- `cartProblem()` validates every field the render reads **before** it is read, and refuses **by name** (which field, which index) instead of throwing.
- `VERIFIED` now rests on a **comparison count**, not on a flag nothing decremented — two independent guards (`goldenRows.length === height`, and `compared === height && compared !== 0`).
- A refusal **clears** the previous render, so it can no longer be mistaken for an acceptance.

## Falsifier

`demo/chip9-cart-viewer.test.ts` — 26 tests. The page stays buildless, so the test **parses** it with `HTMLRewriter` (not a regex — the sibling lesson from #17173), evaluates its scripts against a stub DOM, and asserts on what a user would see. It separates `markup()` from `shown()`, so *injected as HTML* and *displayed as text* are distinguishable rather than both merely present in a string.

The source-level assertion that no HTML sink is named reads a **comment-stripped** copy, and carries a **control** asserting the raw source *does* contain the word — a negative source assertion satisfied by its own explanatory comment is not a check.

**Mutation-tested:**

| mutation | tests killed (of 26) |
| --- | --- |
| `el()` text routed back through `innerHTML` | 16 |
| `cartProblem` always accepts | 15 |
| both VERIFIED guards deleted | 2 |
