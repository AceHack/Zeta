## Four defects surfaced

1. **`triage-orphan-branches.ts` classes OPEN-PR branches as prunable.** It gates
   on content only. Its SAFE set contained `agent/face-lattice-flake-…` (#17184)
   and `agent/unrun-flake-eval-checks-…` (#17187), both open at the time;
   `--prune` would have deleted two live PR head refs. Excluded here by
   intersecting with an open-PR list read over REST before any delete.
2. **Its basename gate produces false SAFEs.** On the 2026-09-07/08 custody-log
   corpus, `claim/task-compiled-capture-five-publication-20260907` was **SAFE**
   while carrying **2566 files absent from `main`**. Nothing was deleted on that
   signal alone.
3. **The 2026-09-03 sweep tagged 15 branches and never deleted them.**
   Preservation ran, the delete did not — and a delete that silently fails reads
   as success. Every row here was confirmed absent by re-listing the remote.
4. **`scripts/hooks/pre-push` cannot tell an archive tag from a contract change.**
   For a new ref it scopes to `merge-base(tip, origin/main)..tip`, though its own
   comment says "commits not already on any origin ref". Each tag target was
   verified already-published with `git branch -r --contains` (zero objects
   transferred) and pushed with `ZETA_FLOOR_VECTORS_ACK=1` on that stated basis.
