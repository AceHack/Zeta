## Description

## What

Deletes the six committed `.wasm` byte-lock substrates and builds them in CI instead — closing six OpenSSF Scorecard `BinaryArtifactsID` alerts **by deletion, not by dismissal**.

## Aaron's question, and the correction to the brief

> "is this cause we are serving it? can it be built and published or something so it can be served from our github pages."

**Yes, they are served.** All six are staged into the Pages artifact by `identity-dla-pages-wasm-assets.ts` as `wasm/dla-{wat,zig,emcc,llvm,rust,asc}.wasm` and driven by six live oracle panels. The measurement I was handed said they were not, having grepped `demo/`, `site/` and `dist/`; the staging lives in `src/Core.TypeScript/discovery/`. An empty grep is `unknown`, never a negative result.

**Yes, they can be built and published** — and the rule's own condition 3 asked for it: *"where the toolchain also exists in CI, prefer BUILDING over COMMITTING"*. `src/wasm-dla/bytelock/.gitignore` recorded the trade the six were accepted under: tracked *because* no leg could rebuild them, and *"add a toolchain to the workflow and the corresponding file should stop being tracked, not start being trusted."*

Every rebuilt substrate reproduces the **unchanged** `testdata/golden-seed-*.json` vectors. **No vector was touched.** WAT and Zig rebuild byte-identical on three platforms; LLVM, Rust and Emscripten differ in bytes and agree in trajectory — which is the reproduction the byte-lock needs.

## Two upstream gaps, recorded rather than smoothed over

- **Chocolatey's `wabt` installs successfully and ships no `wat2wasm`** on both Windows legs. Windows now fetches wabt's own release archive. An install step that reports success while providing nothing is the check-that-cannot-fail shape; it hid behind a committed `.wasm` that meant nobody needed the tool.
- **emsdk publishes no Windows-arm64 SDK** — `error: tool or SDK not found: sdk-releases-<sha>-64bit`. Emscripten is honestly `TOOLING-ABSENT` on `windows-11-arm`; that leg's required list drops it and its floor drops 8 → 7. The floor still equals what the leg can supply, so it stays per-route by exhaustion. `windows-2025` installs emsdk in 46s and builds it fine, so this is an arm64-Windows fact, not a Windows one.

## The audit gained a half rather than losing one

A roster substrate with no committed file used to be a flat failure. It must now be **built**, and `audit-proof-lineage-binaries.ts` reads two things out of `bytelock.yml` itself: the job runs the shared build action, **and** the substrate is named in a `BYTELOCK_REQUIRED_SUBSTRATES` list. The second is load-bearing — it turns *"the file is gone"* from an absence nobody sees into a named, red per-route floor, which is the guarantee the committed file used to give by simply existing. Both halves are falsified in the test file.

**It does not go vacuous.** After the deletion it still inspects 1 committed binary (SCOPE), 6 roster substrates (BUILDABLE + BUILT-IN-CI), and 4 golden vectors — and it now prints the committed/built split, so a reader can see which checks had no subject instead of inferring health from a silent OK.

## Three defects found while measuring, each fixed here

- **`npx asc` could never work.** With no assemblyscript present it exits *"could not determine executable to run"*; installed from the bytelock directory, npm hoists to the repo root and `./node_modules/.bin/asc` is not there. It failed on **all five legs**. `assemblyscript` is now a root devDependency, resolved by path.
- **`-C debuginfo=0` is a no-op** — the fix named in the audit's own header and in the README for the 478 KB Rust module. Measured on rustc 1.99.0: 624,772 bytes with it, 624,772 without. The DWARF is already-compiled upstream libcore. `-C strip=debuginfo` lands it at 8,058 bytes and passes the unchanged vectors at all four seeds.
- **The zig↔artifact provenance coupling could only check committed bytes.** It now runs in `bytelock.yml` on the rebuilt module, which is strictly stronger: it asks whether zig 0.13.0 *still produces* those exact bytes. On the toolchain-free `cross-verify` lane it says so out loud instead of printing a match it never computed.

## Blast radius

Four lanes need these artefacts, so the install lives in one composite action (`.github/actions/build-wasm-substrates`): `bytelock.yml` (5 legs), `pages-deploy.yml`, gate's `lint (identity-dla site)`, and gate's whole-tree `bun test`. Six copies of an install list is the include-list defect `gate.yml` already names.

**Cost, stated plainly:** `pages-deploy.yml` runs on a `*/15` schedule tick as well as on push, so it pays ~61s of toolchain install 96×/day against a 10-minute cap and observed med 1.1m / max 3.9m. That is the honest price of not committing the binaries.
