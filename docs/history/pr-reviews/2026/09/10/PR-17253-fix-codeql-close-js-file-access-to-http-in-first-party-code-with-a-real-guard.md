## Description

The maintainer asked why CodeQL findings are not required. They are not a
required CHECK, but they do block: `required_conversation_resolution: true`
means every `github-advanced-security` thread must be resolved, so findings are
enforced per-finding — and a thread can be resolved without the alert being
fixed. This round fixes rather than resolves.

The reserved `packs:` slot in `.github/codeql/codeql-config.yml` was the obvious
place to start, and it turned out to be a dead end. Measured with CodeQL CLI
2.27.0, each with its own control:

  * a `barrierModel` data extension is honoured by a byte-identical clone of a
    shipped query compiled inside a local pack (1 -> 0) and IGNORED by the
    shipped query itself (1 -> 1), in the same invocation over the same
    database. Not a resolution failure (`codeql resolve extensions` lists the
    row against `codeql/javascript-queries`), not a `.qlx` cache (deleting the
    precompiled query changed nothing), not specific to barriers (a `sinkModel`
    control failed to ADD an alert the same way), and identical across all
    three delivery routes including `database create --codescanning-config`,
    which is what `github/codeql-action` actually does;
  * subclassing a query's `abstract class Sanitizer` from another pack drove
    that pack's own copy of the flow to 0 while the built-in stayed at 6 —
    QL abstract classes resolve per compilation closure;
  * `js/file-access-to-http` and `js/http-to-file-access` carry no
    models-as-data hook at all, so even a working extension could not reach
    them.

What does work is a guard in the code that CodeQL's DEFAULT taint barriers
already recognise. `full-ai-cluster/portal/src/data-k8s.ts` now refuses a
mounted ServiceAccount token that is not a JWT before presenting it as a bearer
credential — a real failure mode (misconfigured projection, wrong volume,
replaced file), not a formality. Measured on that file: 3 alerts before
(#180, #192, #262), 0 after. No suppression, no dismissal, no rule disabled.

The over-suppression falsifier is committed and runnable:
`codeql test run .github/codeql/custom-queries/zeta-security/test`. Its
`.expected` files pin the alerts that must SURVIVE as tightly as the one that
must disappear — an unguarded sibling still reports both flows, a half-guarded
one still reports the flow its guard does not cover.

The `js/log-injection` alert on `realtime-client.ts` is left open on purpose,
with its diagnosis committed. The file's comment predicted that if the alert
survived, the shape hypothesis was wrong. It is wrong, and the discriminator is
narrower than "shape": `StringReplaceSanitizer` requires the REPLACEMENT to be
the empty string. `.replace(/[\r\n]/gu, "")` is silent, `.replace(/\n/gu, " ")`
is loud — the character range was never the issue. The shipping function
replaces with a space to stay length-preserving, a property that file argues
from and its tests assert, so the behaviour call belongs to its author.
