## Description

## The flake, and why it was diagnosed rather than re-run

`test (TS hermetic)` failed once on 2026-09-09 at **5126 ms** on `research/clifford-e8-face-lattice.test.ts` — *"every face is contained in exactly 26 derived facets, split 16 + 10"* — and passed on re-run. That is exactly the shape in which a real red gets clicked away, so it got a cause instead of a retry.

## It is not nondeterminism

The module reaches for no clock, no RNG and no env — its own FALSIFIER 10 asserts that over a **comment-stripped** copy of the source, with a control (`Math.hypot(` must survive). The test is pure combinatorics over 240 roots and 60,480 faces.

**The number is the diagnosis.** bun's default per-test timeout is 5000 ms, and the failure landed **126 ms past it**. A deterministic test does not fail at 5126 ms for any reason other than the clock.

## Slow by accident, not by nature

`bunfig.toml` already draws the distinction this repo cares about:

> "A test that is slow BY NATURE carries its own explicit timeout. A test that is slow BY ACCIDENT gets made fast."

This one was slow by accident. The loop built `new Set(facetsOfVertex[a])` and `new Set(facetsOfVertex[b])` **per face** — 2 × 60,480 = **120,960 Set constructions over the same 240 distinct lists**. The membership sets are per *vertex*, so 240 of them suffice. Hoisted.

| | before | after |
| --- | --- | --- |
| the 26-facets test | 2.636 s | **0.825 s** |
| the whole file | 5.71 s | **3.62 s** |
| headroom vs the 5 s default | ~1.9× | **~6×** |

## No assertion was widened, and no timeout was raised

The expected value is still exactly `[["16+10", 60480]]`; the 240-roots-used check is untouched. Same sets, constructed once. Raising the bound instead would have bought green by **moving the line rather than removing the cause** — and would have left the next slower runner to trip it again.
