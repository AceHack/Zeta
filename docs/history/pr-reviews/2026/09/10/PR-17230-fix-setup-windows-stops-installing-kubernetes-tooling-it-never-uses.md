## Description

## What

`tools/setup/install.ps1` assigned `ZETA_HOST_TIER = 'full'` to every Windows host that did
not declare one. Windows now defaults to `standard`.

## Why

On Windows, `ZETA_HOST_TIER` changes exactly one thing: `MISE_ENV=full`, which merges
`.mise.full.toml`. Diffed against `.mise.toml`, that file adds exactly five tools —

| added by `full` | used by any Windows surface? |
|---|---|
| `k3d` | no — `k8s-argocd-health-test.yml` is `ubuntu-24.04` |
| `kind` | no — same |
| `kubectl` | no — same |
| `helm` | no — `helm-validate.yml` is `ubuntu-24.04` |
| `github:yannh/kubeconform` | no — gate.yml's `lint (yaml/k8s)` is `ubuntu-24.04` and `go install`s its own copy |

`rust` and `zig` also appear in `.mise.full.toml`, but as deliberate byte-identical mirrors of
`.mise.toml` (the file says so, and says why), so they install the same versions at either
tier. `install.ps1` reads no manifest carrying a `tier=` token (`manifests/windows`,
`manifests/from-bun-global`, `manifests/local-llm`) and drives no dotnet-global manifest. So
those five WERE the tier's entire Windows payload.

The Windows leg of `build-and-test` runs `dotnet build` + `dotnet test` over `Zeta.sln`. It
invokes none of the five.

**And it was not free.** `build-and-test (windows-11-arm)` failed on `main` at
`Install toolchain via three-way-parity script` because `github:yannh/kubeconform@0.7.0` could
not be installed — GitHub's attestation service returned 503. An outage in a Kubernetes tool
took down a Windows build-and-test leg that has no Kubernetes in it. This is the same shape as
the `qemu` row in `manifests/windows`, demoted to `optional` on 2026-09-01 for the identical
measured reason: a package nothing on Windows invokes is still a way for Windows to go red.

**Honest limit on that number:** 17 of the 20 fall inside one 50-minute window

step, and every tool it fetches is another upstream that can take Windows red. This PR removes
five of them, all of which Windows never used. It does not claim to remove the burst.

inside k8s, eventually we may support windows non control nodes but today we don't."*

## The capability is kept, not deleted

A declaration still wins, exactly as `tools/setup/common/host-tier.sh` specifies.
`ZETA_HOST_TIER=full` on a Windows host still installs the k8s set. The "eventually" above
stays one environment variable away; it just stops being the unasked-for default. The skip is
printed by name with both tiers, per the loud-skip discipline at the top of `host-tier.sh`:

```
-> k3d/kind/kubectl/helm/kubeconform skipped: require tier=full, host is standard
host tier: standard (MISE_ENV=<none: base .mise.toml only>)
```

## Why `standard` and not `slim`

This is a **workload** statement, not a capacity one. The ranks are read as host SIZE elsewhere
— `host-tier.sh` detects `slim` below 8 GB — and a Windows dev box, or a 16 GB GitHub runner,
is not a small host. Both tiers drop precisely the same five tools on Windows today, so `slim`
would buy nothing extra and would claim something false. `standard` additionally keeps every
standard-tier entry (`manifests/from-dotnet-global`: the dotnet diagnostics suite, stryker,
fsharp-analyzers) available for the day Windows wires that manifest up.

## Three-way parity (GOVERNANCE §24)

§24's rule is *"asymmetries between dev and CI are bugs"*, and no such asymmetry is introduced:
dev laptops, CI runners and devcontainer images all run this same script and all get the
identical Windows behaviour.

The divergence introduced is against the **Unix** installers, which auto-detect from RAM and so
resolve `full` on any 16 GB host — and that divergence is the point of the change. Detection
answers *"how big is this host"*; the question here is *"can this host run the workload"*, and
on Windows the answer is no regardless of RAM.

## Falsifier

`src/Core.TypeScript/ci/windows-install-ps1-smoke.test.ts` parses the policy out of
`install.ps1` itself — `parseWindowsHostTierPolicy`, with whole-line comments stripped so the
guard matches the CALL and not the prose beside it — and asserts both halves:

- the default is `standard` (and explicitly *not* `full`);
- `$env:MISE_ENV = 'full'` is still guarded by `ZETA_HOST_TIER -eq 'full'`, i.e. declaring the
  tier still reaches the full graph.

**Mutation-checked, locally, before this was pushed:** reverting the default in `install.ps1`
to `'full'` turns the first assertion red (`Expected: "standard" / Received: "full"`);
restoring it returns 17/17 green. The parser also has its own negative controls — it reports
`full` for a `full` assignment, and `null` when the same text appears only inside a comment.

A third test pins the fact the other two rest on: the only entries `.mise.full.toml` adds over
`.mise.toml` are exactly `["github:yannh/kubeconform", "helm", "k3d", "kind", "kubectl"]`, with
`rust` and `zig` present in both. If someone adds a Windows-relevant tool to the full tier, that
test goes red rather than the Windows lane silently losing it.
