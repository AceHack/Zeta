## Description

## The defect

A Gatekeeper policy is **two objects**, and only one of them was ever asserted.

1. a `ConstraintTemplate` — Rego. Gatekeeper compiles it and, only if it compiles, generates a CRD for the Constraint kind it declares.
2. a `Constraint` — an instance of that generated CRD. **The policy.** A compiled template with no Constraint enforces exactly nothing.

The lane grew a real check for (1) earlier today ("Gatekeeper compiled every ConstraintTemplate"), after runs `34323056405` (red) and `34338106811` (GREEN) in which `hatconflict` and `hatnocycle` never compiled. Nothing asserts (2).

(2) is the harder half because **ArgoCD assigns Constraints no health**, and `isApplicationSynced` admits `OutOfSync + Healthy` for git-directory apps like `hat-system`. So an Application holding zero installed policies reads exactly like one holding seven.

## Re-measured, not inherited

Run `34390707656` — the **GREEN 37/37 `main` run**, taken *after* the template check landed:

```
=== hat-system: sync=OutOfSync health=Progressing
    ConstraintTemplate/hatconflict:     sync=OutOfSync health=-
    ConstraintTemplate/hatcooldown:     sync=OutOfSync health=-
    ... all seven, OutOfSync ...
```

and **not one of the seven Constraints appears in the resource list at all** — ArgoCD cannot render a Constraint whose CRD does not yet exist. The template step then passed 31 s later ("all 7 ConstraintTemplates compiled and created") because it waits. The half that is checked recovers on retry and says so. The half that is not checked has never been observed either way.

## What lands

`src/Core.TypeScript/cluster/hat-constraint-roster.ts` — the roster, **derived** from `full-ai-cluster/k8s/applications/hat-system/policies/*.yaml`, never restated. A hardcoded list of seven names is the drift shape an eighth policy file walks straight past.

Three refusals, each because its absence makes the check vacuous:

- an **empty roster** is a failure, never a skip — a loop over nothing passes trivially;
- a **Constraint whose kind no template declares** — gatekeeper never generates that CRD, so the policy can never apply on any cluster, and that is knowable from the text alone;
- a **template no Constraint instantiates** — compiles, enforces nothing, reads as coverage.

A new lane step waits (bounded, 300 s) for every Constraint in the roster to exist, and fails when the bound expires.

## What it deliberately does NOT gate on

`status.byPod[].enforced`. Existence is what was **false** in the measured runs, so it falsifies something today. Enforcement is printed as diagnostics because nothing has measured how long gatekeeper takes to load a fresh constraint on a cold kind node, and a timeout nobody measured is a flake dressed as a check. Promoting it is a follow-up with a measurement attached.
