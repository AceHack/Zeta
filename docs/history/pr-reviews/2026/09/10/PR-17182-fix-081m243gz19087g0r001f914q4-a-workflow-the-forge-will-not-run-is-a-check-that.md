## Description

## The finding

**16 of 105 workflows on this repo are `disabled_manually`, and no surface in the repository names that fact.**

A disabled workflow sits at its correct path, is valid YAML, is referenced by prose and by rosters, and emits **zero runs** — so it can never be red. It does not fail; it stops existing. That is the cardinal failure class of this repo in its purest administrative form: *a check that did not run looking like one that passed.*

Every workflow guard here reads **text**, so none of them can see it:

| guard | what it reads | why it misses this |
| --- | --- | --- |
| `lint-no-nested-workflow-dirs` | paths | the nearest sibling — "a workflow file GitHub will never read is not a check". A disabled workflow is at a path GitHub reads perfectly well |
| `lint-linter-coverage-vs-ci-invocation` | the YAML | it finds the invocation. The YAML is correct |
| `lint-workflow-job-timeouts`, `lint-drift-publication-lands` | the committed file | the file is fine |

The state lives **only in the forge**, so only a live query reaches it.

## The sharpest instance is inside the job this PR edits

`drift-sweep.yml` is the **second host** of `verdict-drought.ts`, and it has been `disabled_manually` since **2026-08-29**.

`verdict-drought.ts` chose two hosts for one stated reason:

> "a drought detector that lives only inside `gate` is cancelled by exactly the condition it exists to report — it would be silent precisely when it matters"

and then named the failure it could not self-report:

> "If BOTH go quiet the condition is invisible again — that limit is real and is not papered over here."

Half of that has been true for eleven days, and **the surviving host is the cancellable one.**

Also disabled: `agent-heartbeat`, `society-heartbeat`, `tick-metrics` — the lanes `CLAUDE.md` instructs every agent to read for liveness — plus four named alarms (`pr-manifest-integrity`, `proof-closure-drift`, `artifact-freshness`, `archive-strand-alarm`).

## What this does NOT do

It does **not** re-enable anything and does **not** judge whether any given lane should run. That is a maintainer call. It refuses only that the answer be **unrecorded**.

## The mechanism

`registry/workflow-enablement.json` records each non-active workflow with a `reason` and a `classification`. The audit goes **red** on four conditions:

- `undeclared-disabled` — non-active in the forge, absent from the registry. **The next silent disablement lands here.**
- `stale-baseline-now-active` — the registry names a workflow that is running again. A row claiming a closed gap teaches readers to skip the row that names an open one.
- `baseline-path-absent` — an entry naming a path the forge does not list.
- `malformed-entry` — no reason, or an unknown classification. A roster row with no reason records nothing.

The 16 measured today are seeded `unreviewed` — recorded as **fact, explicitly not as approval** — and print as warnings on every run rather than as a permanent red, because `gate.yml` already says why: *"a red X nobody must clear is a red X nobody reads."* The check is armed from its first run regardless: against the seventeenth disablement, against any of the sixteen coming back, and against its own roster going stale.
