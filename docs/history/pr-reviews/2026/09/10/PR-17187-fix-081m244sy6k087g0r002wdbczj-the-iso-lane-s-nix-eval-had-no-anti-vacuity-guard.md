## Description

## What I first concluded, and why it was wrong

Nine eval-only checks in `full-ai-cluster/flake.nix` are named individually by **no workflow step anywhere**:

`zeta-creds-to-k8s-model` (the T5 kubeconfig-retry properties) · `tpm2-seal-prereqs-model` · `host-seal-profile-model` · `secure-boot-desired-state-model` · `longhorn-node-preflight` · `longhorn-disk-registration` · `longhorn-common-default-disk-eval` · `cilium-wireguard-preflight` · `gpu-node-label-preflight`

I concluded they were **unrun**. That was wrong, and falsifying it is what produced this diff.

`Check flake evaluates` in this same job runs `nix flake check --no-build`, and an eval-only check's assertions fire **during evaluation**. Measured: mutating `zeta-creds-to-k8s-eval-test.nix` so every property fails makes `nix flake check --no-build --all-systems` **exit 1 in 61 s**, naming `missing kubeconfig retries (exit 1)` among the failures.

**The coverage is real. The defect is the opposite shape, and it is worse.**

## The actual defect

That coverage had **no anti-vacuity guard**, so it could have stopped covering anything without a red X. `nix flake check` exits 0 on a flake whose outputs it skipped entirely.

`root-flake-check.yml` and `first-boot-manifest-check.yml` both carry a guard for exactly this. root-flake-check's own comment says:

> "anyone adding a nix lane anywhere should copy this step, because the default failure mode of a nix eval lane is a confident green over an empty check."

Of the four nix eval lanes in this repo, **the two in this file — the oldest and by far the most expensive — carried neither that guard nor `--all-systems`.**

## Three changes

**1. `--all-systems` on both `Check flake evaluates` steps.**

| | outputs (guard's own pattern) | wall clock |
| --- | --- | --- |
| without the flag | 94 | 7 s |
| with the flag | **189** | 54 s |

47 s inside a job that measures ~32 min.

**2. The guard**, on both steps, plus a **named roster** of the nine on the x86_64 one — this step is their only coverage, so a green that never reached them is a green about some other output. Format-independent, per the lesson of run 33023664270 (counting `^✅` read Determinate Nix presentation while upstream prints `checking flake output`, and the guard reported ZERO while nix had checked twenty).

**3. The false comment corrected.** It said:

> "No lane runs `nix flake check` on this flake (the steps here name each check individually), so both were checks that could not fail because nothing invoked them."

Line ~212 of the same file did exactly that. A reader auditing coverage was told it did not exist when it did — which is how I got it wrong in the first place.

## `--all-systems` is load-bearing, not cosmetic

Replaying the new assertion against the two real logs:

| log | result |
| --- | --- |
| `--all-systems` | **PASS** — 189 lines, all nine present |
| no flag | **FIRES** — `gpu-node-label-preflight` missing |
| empty | **FIRES** — zero outputs |

`gpu-node-label-preflight` hangs off `nixosConfigurations.worker-gpu` and is omitted outright when nix restricts itself to the current system. **One of the nine was not evaluated, and nix still exited 0.** That is the whole class, caught in its own lane.

## Cost

+47 s per run on a ~32 min job, on a lane that is not in `gate (required)`'s `needs:` and blocks nothing. Verified after the change: the floor is still 9 jobs and none of them reach this.
