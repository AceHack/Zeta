## The measurement

`main`, 2026-09-09: **78 open code-scanning alerts, 51 of them four rules** —
`js/file-system-race` (21), `js/http-to-file-access` (13),
`js/indirect-command-line-injection` (9), `js/file-access-to-http` (8).

**Those 51 sit in ~40 distinct files, none carrying more than four.** That
distribution is the whole finding. It is not a few bad files; it is ~40 authors
independently hand-rolling the same three operations — fetch-then-write,
stat-then-open, spawn-with-argv-from-outside — and each getting the same detail
wrong.

**Instance-patching demonstrably does not close it.** On #17182, alert #930
(`js/http-to-file-access`, `ci/workflow-enablement.ts:525`) was fixed; alert
**#931 — same rule, same file, 37 lines down** — was raised the next day. The
fix relocated the pattern, because the pattern is what the author had to write.

### The finding that decided the design

**The correct shape already existed in this tree. Twice.**
`peer-call/claude.ts` and `peer-call/kiro.ts` split the command line, refuse
shell metacharacters, look the executable up in a fixed roster, and spawn with
a **literal** `argv[0]`. Both are clean in code scanning today. The **eight**
other copies of the same `runContextCmd` function reach for
`spawnSync("/bin/sh", ["-c", ...])` and **all eight carry the alert**.

So the fix was found, reviewed and merged, and then stayed inside the two files
that found it. A primitive nobody can import is a primitive that gets
rewritten — which is why this PR is a module **and** a lint, and the lint is the
half that makes it stick.

## The primitive — `src/Core.TypeScript/io/safe-io.ts`

`Result<T, IoError>` throughout; no exceptions on these paths.

| function | what it eliminates |
|---|---|
| `readFileBounded(path, {maxBytes, headBytes})` | TOCTOU. One `openSync`; **every** later decision comes from `fstatSync(fd)`, never from a second path lookup. `not-found` is ENOENT interpreted, not `existsSync` asked. |
| `writeFileOwned(path, data, {exclusive, mode})` | check-then-create. `exclusive: true` is `O_CREAT|O_EXCL`, so a concurrent creator loses with `already-exists` rather than one writer silently winning. |
| `splitCommandLine(input)` | shell syntax. Quote-aware split that **refuses** `\| & ; < > \` $` and NUL — there is no argument vector that means a pipe. |
| `spawnArgv(cmd, args, opts)` | shell interpretation. No `shell` option exists to pass; a shell basename with `-c`/`/c`/`-Command` is refused. |
| `spawnFromRoster(roster, requested, args)` | **external input in `argv[0]`**. Spawns the **roster's own string**; `requested` selects an index and never supplies the value. |
| `runCommandLineFromRoster(roster, line)` | the peer-call composition: split → roster → argv, no shell on the path. |
| `spawnShellDeclared(shell, line, {reason})` | nothing — and it says so. The **one** sanctioned shell, for the documented `--context-cmd` contract. Requires a written `reason` as a **value** (a comment gets copied along with the code it excuses — that is how nine of these appeared), bounds output in-process, takes the shell as a two-value enum so `argv[0]` is a literal. |
| `fetchBounded(url, opts)` | an unbounded `res.text()`/`res.json()`. |
| `fetchToFile(url, dest, opts)` | unbounded download. Scheme checked before anything opens; mandatory cap and deadline; streamed straight to one owned descriptor; **a failed transfer removes the partial file** — a half-written artifact is worse than none, because the next reader finds a file and believes the download happened. |
| `truncateUtf8Bytes(text, n)` | the `\| head -c N` pipeline. `String.slice` counts UTF-16 code units, so every "20000-byte" bound in the peer-call family **was not a byte bound**. |

### What is only bounded, not eliminated — stated in the header, not implied

Remote-bytes-to-disk and file-bytes-to-network are **data flows this tree is
supposed to perform** (a package manager downloads; `--file` sends context to an
LLM). No primitive makes them stop existing, and one claiming to would be
lying. Routing them through one bounded function is a **consolidation**: code
scanning will still see the flow, at `fetchToFile`'s own write. That is the
honest claim and it is the one made here.

## The lint — `src/Core.TypeScript/hygiene/lint-hand-rolled-io.ts`

**Refuses**, with the replacement printed in every message:

- `shell-string-spawn` — `execSync(`; a call whose first argument is a shell
  path literal and whose second begins `-c`/`/c`/`-Command` (matched on the
  **shape**, not the callee name, so a local `runSpawn("/bin/sh", ["-c", …])`
  wrapper is caught); `shell: true`.
- `unbounded-fetch-to-disk` — a response body reaching a file sink, through
  `const res = await fetch` → `const b = await res.text()` → a write naming `b`,
  through the one-expression spelling, or through `res.body.pipeTo(createWriteStream(…))`.

**Does not** report check-then-use races — `lint-check-then-use-file-races.ts`
already owns that class with a 510-signature baseline, and a second lint
double-counting it would teach everyone to ignore both. What this PR adds there
is a **destination** for the fix that lint has always demanded.

**Comments are masked and the match is the CALL form.** This file names
`execSync` and `spawnSync("/bin/sh", ["-c"` in prose repeatedly; without masking
it would report its own documentation, be disbelieved, and be deleted along
with the explanations. Both properties are pinned by tests **with controls** —
the control fails if the masking is removed, so the "does not fire" tests cannot
pass vacuously.

Suppression is `safe-io-ok: <reason>`, reason mandatory; an empty one is itself
a finding.

**Measured on landing: 2957 files, 50 pre-existing sites over 33 keys**, all
grandfathered. The baseline stores **counts** per (rule, file, signature), so a
new site in an already-listed file still goes red — a set-shaped baseline would
have grandfathered the file's whole shape. Named limit: delete one baselined
site and add another of the same shape in the same file and the count is
unchanged.

Wired as cross-verify leg `hand-rolled-io` (`gate.yml` regenerated with
`--derive --write`) and as `hygiene:no-hand-rolled-io`.

**Two first-run false positives are pinned as regression tests rather than
tuned away**: a path segment spelled `"data"` matching a body variable, and a
test fixture whose written *content* calls `fetch`. Both were string literals
read as code; `stripStringLiterals` now runs before every match.

**M10 survived the first round** and that is why the download was restructured.
The original buffered the whole bounded body and only then opened the
destination, so no partial file could exist and the removal was unreachable —
the test asserting "leaves no file behind" was passing on a code path that could
not fail. `fetchToFile` now streams straight to the descriptor, which makes a
partial file genuinely possible, the removal load-bearing, and the assertion a
falsifier.

Two properties are asserted **structurally** rather than behaviourally, and the
tests say why: "TOCTOU-free" is the *absence* of a second path lookup (a race is
not deterministically reproducible, and a flaky test here fails in the direction
that reads as a pass), so the subject's own source is asserted to contain no
`existsSync(` / `statSync(` / `readFileSync(` **call** — with a control proving
the comment-stripper is not a no-op.
