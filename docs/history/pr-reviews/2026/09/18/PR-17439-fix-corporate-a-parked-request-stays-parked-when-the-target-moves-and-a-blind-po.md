## Description

## What this is

Three bugs the live watcher's own logs showed after #17385 merged. All found by reading what the running organization actually did, not by reasoning about the code.

## 1. A request handed to a person was restarted by the target moving

Every reason loop in `watchReasons` skips a request the watcher has given up on — except `targetMoved`.

MEASURED on dev-portal task-012, 2026-09-14, from `watch.log`:

```
[watch dev-portal] STILL RED after 3 tries, and a person is needed: task-012: 3 follow-ups in a row could not complete …
[watch dev-portal] started a run (pid 16516): master moved under task-012
[watch dev-portal] the run ended (exit 0) after 562s
[watch dev-portal] STILL RED after 3 tries, and a person is needed: task-012: 4 follow-ups in a row could not complete …
```

It announced that a person was needed, then started another run anyway, which died on the same thrashing context 562 seconds later. **The target moving is exactly what keeps happening while a person is away**, so this single gap would re-open every parked request indefinitely.

## 2. A watcher that could not look said it saw nothing

From late on 2026-09-12 `tgcsgitlab.rtptgcs.com` stopped resolving. The poller read **no merge request at all**, and every tick logged:

```
[watch agentic-tpm] nothing new (the poll said: … dial tcp: lookup tgcsgitlab.rtptgcs.com: no such host …)
```

"Unreachable" and "quiet" are the two sentences that must never be confused — the repository already says so in `git-data-source.test.ts`, and the watcher was confusing them. `idleReport` now says **"could not look"** when the poll failed *and* read nothing. A partial failure keeps its verdict with the failure beside it, and a successful poll is unchanged.

## 3. Tests that start processes had no timeout

On a cold checkout the full suite failed **7 tests, every one at ~5000 ms** — bun's default limit, not an assertion. With a 60-second limit all passed, and the same failures reproduce on clean `main`, so this is a pre-existing flake and not a regression.

The convention already existed and was applied unevenly: in `claude-agent.test.ts` the tests that start the agent script mostly pass `30_000` — **28 did not**. The four tests in `git-worktree.test.ts`'s feature/trunk group run dozens of git commands with no limit at all.
