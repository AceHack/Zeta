## Description

`claimGeneration`'s fix had no test that failed without it, and I said so when I shipped it:
reverting the fix left the whole suite at 21 pass / 0 fail. It now has one.

  create-then-write (defective)   empty=2293   FAIL
  stage-then-link   (fixed)       empty=0      PASS, 5/5 consecutive runs

A second process spins on ONE FIXED PATH -- no readdir -- while the test claims the same
generation 20,000 times. `empty` counts the generation existing with NO CONTENT, which is the
defect observed directly rather than argued from the mechanism.

I PREVIOUSLY CLAIMED THIS COULD NOT BE DONE, and the claim was half wrong. The work item said
a falsifier would need "a test-only seam in the claim path, or a concurrent observer that can
only ever produce false GREENS". A concurrent observer can produce a true RED -- provided it
watches one path instead of a directory. Three approaches failed before that one worked, and
each is recorded in the test because each is a plausible thing to reach for next:

  fs.watch on the lock directory   macOS coalesces; 10/10 trials saw only `0.lock`, never the
                                   staging file. Not an observer.
  spin-reader doing readdir        scanning a growing directory is microseconds while the
                                   window is nanoseconds: 0 hits in 28,018 claims against the
                                   DEFECTIVE build. A clean false green.
  plant a zero-byte generation     tests the tolerated case (corrupt => supersede), which the
                                   fix does not change. Passes either way.

THE `full > 0` ASSERTION IS THE CONTROL AND IS NOT OPTIONAL. A reader that never managed to
open the file reports `empty = 0` and the test passes having observed nothing -- which is
exactly how the readdir attempt looked like a working detector for one run. It is asserted
separately so that failure mode is loud.

BOUNDED BY A CLAIM COUNT, NOT A CLOCK. The reader stops when the test drops a sentinel file,
and startup is a `ready` handshake rather than a sleep. Nothing here asserts on elapsed time,
so `audit-ambient-time-in-tests` has nothing to allowlist -- it reports 1756 files clean.

Verified rather than assumed: mutant `empty=2293` vs control `empty=0`; 5/5 stable; the
existing lock suite still 21 pass / 0 fail; `tsc --noEmit` rc=0 on an empty log; the
check-then-use auditor finds no races over 3052 files.
