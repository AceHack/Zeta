## Description

Ilyana's measured answer to Aaron's question, plus an addendum after his "no generator
is root" correction. Landed verbatim; advisory, non-binding.

THE ANSWER: yes technically, no you should not. A type with 1024 type parameters
COMPILES (measured; 4096 timed out at 120s and is reported as a timeout, not a failure).
But it is usable at exactly one n, so every operation is written n times. What gives
arity-polymorphism is ONE type parameter applied recursively.

And for `WSet` the answer is ZERO new type parameters -- an n-degree weight is a choice
of 'W, not a new degree of freedom. The repo answered this twice already: `Doubled<'A>`
(one parameter, arity 2^n by nesting) and `ITensor<TCoord,TWeight>` (rank moved into the
coordinate).

MEASURED, not argued. SRTP cannot do recursive instance resolution -- four formulations,
four compiler transcripts, the tail monomorphised at the first recursive call so the
recursion collapses at arity 2. `CayleyDickson.fs` already has a comment rejecting SRTP
for this; the measurement is that comment's falsifier. C# is WORSE, not a fallback:
`InlineArray` takes an attribute constant, not a type parameter, and exposes no `Length`.

The phantom-nat `Vec<'N,'T>` works -- flat compile time to n=256, arity-polymorphic
`sum`/`map`/`inner` written once -- and stays INTERNAL, because
`Vec<S<S<S<Z>>>,float>` can hold one element. The index is a claim, not a proof: the
vacuity class in type-system form, and worse than no parameter because it manufactures
the belief the arity was checked.

Ilyana also caught and RETRACTED one of her own measurements: a "constant 393 chars"
error-size figure was an FS0058 indentation artifact, not a type error. Her note: "a
constant where linear growth was expected should have been the tell ... a measurement
that cannot vary is the vacuity class, and I nearly shipped one into a document about
falsifiers."

THE ADDENDUM CONTAINS THE MORE SERIOUS FINDING, and it is not about arity.

`IRing<Sedenion>` compiles with zero compiler objection and is not a ring. Measured
exhaustively over the basis: 42 of 49 octonion basis pairs refute Mul commutativity,
168 of 343 triples refute associativity, and 84 sedenion pairs are zero divisors with
both factors nonzero. `IStarRing.cs` discloses this in its own words -- "law profile
carried as documentation, not types ... the caller's responsibility" -- which is an
honest disclosure AND a guarantee with no falsifier: the vacuity class relocated from
the code into the prose. By Hurwitz (1898) the loss is FORCED; the algebra is not wrong,
the INTERFACE claims more than it delivers. Filed as 081M29N1AX9087G0R001GSJD6G.

The diagnosis is directional: `ISemiring` ⊂ `IRing` ⊂ `IStarRing` adds capability going
up while ℝ→ℂ→ℍ→𝕆→𝕊 loses laws going up. Those run in OPPOSITE directions, so no
subtyping and no encoding repairs it -- capability and law are on one inheritance chain
and are not the same axis. It is also the root cause of Lumen's problem from the other
side: a belief weight needs a star WITHOUT an additive inverse, and `IStarRing : IRing`
makes `Conj` reachable only through `Negate` -- one consumer's constraint promoted into
the interface for all consumers.

AARON'S "NO GENERATOR IS ROOT" CORRECTION CHANGED THE ANSWER, and Ilyana retracts her
own phrasing: she wrote "you need one generator", and notes the repo disagreed before
Aaron did -- CayleyDickson, ProbabilitySemiring, IntervalRing and BooleanKleene are four
roots with no root-of-roots.

But many-roots makes the case against type-level arity STRONGER, not weaker: the moment
towers join, every type parameter in either signature must survive the join, and two
phantom arities meeting need type-level arithmetic F# does not have. Arity in the type is
quadratically worse under joins; arity in the KEY joins for free.

AND THE BEST RESULT WAS ALREADY IN THE BUILDING. `tensor`/`join` compose in the KEY, so
the n-fold join result IS the n-degree tuple. Mac Lane's coherence theorem (1963) says a
monoidal category whose associator satisfies the pentagon has every bracketing at every n
canonically isomorphic -- and `Meno.associator` is shipped with pentagon and triangle
proven at MENO-8/MENO-9. So binary tensor + pentagon IS the n-ary type, and building an
n-ary join type would be new public commitment for a theorem already held.

compiler today, so a Z tower and a probability tower cannot be joined at all -- which is
fine under one root and is the central missing operation under many. A hom-mediated join
