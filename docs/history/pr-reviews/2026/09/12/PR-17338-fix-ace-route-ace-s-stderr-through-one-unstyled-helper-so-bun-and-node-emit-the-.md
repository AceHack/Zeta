## Description

## The failure

`cross-verify (ace-suite)` is red on clean `origin/main` — two of the eleven
`ace-node-runtime-parity` cases fail, and every PR inherits it. Verified in a control
worktree at `origin/main` before any edit: **9 pass / 2 fail**.

## Measured cause

Bun's `console.error` wraps its output in ANSI red; Node's does not — and Bun does it
even when stderr is a **pipe**, not a TTY. Same source, same message text, different
bytes:

```
NODE  "ace: Unknown command: frobnicate\n"
BUN   "^[[0m^[[31mace: Unknown command: frobnicate^[[0m\n"
```

Both failing scenarios are this one mechanism (`error paths`, and the two
`ace: WARNING: ... UNSIGNED ...` lines).

## The fix is at the producer

`src/Core.TypeScript/ace/stderr.ts` exports one helper — `aceErr(message)` — writing
`message + "\n"` straight to `process.stderr`, the path neither runtime decorates, and
already the house idiom elsewhere under `src/Core.TypeScript/`. All **156**
`console.error` call sites in ace's non-test sources are converted:

| file | sites |
|---|---|
| `ace.ts` | 133 |
| `refresh-pins.ts` | 8 |
| `refresh-ollama-pin.ts` | 6 |
| `build-graph.ts` | 5 |
| `helm-change-detector.ts` | 2 |
| `runtime-plan.ts` | 1 |
| `install-pinned-artifact.ts` | 1 |

**The conversion is faithful, and that was measured rather than assumed.** A parser over
the 156 call spans (tracking strings, template interpolation and nesting) found every one
passes a **single string argument** — so `console.error`'s multi-argument space-joining is
behaviour no caller depends on, and none had to be left behind. Message text is
byte-identical apart from the colour codes.

## What was deliberately NOT done

Stripping ANSI inside the test. That file's own comment says stdout is compared **RAW** —
no normalisation, no filtering — and relaxing the comparison would hide the next, *real*
divergence along with this cosmetic one. A check weakened until it passes is the vacuity
class.
