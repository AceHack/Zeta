## Description

Aaron 2026-09-11: "we should add to claude.md and agents.md ... to refresh / merge main
to their branch often like before testing and pushing everytime, this seems like it
would solve our PRs overwriting each other often."

The measured instance that makes this a rule rather than tidiness, from the same day:

A fix to `src/Core.TypeScript/corporate/claude-agent.test.ts` -- two tests that assert a
session's child processes are reaped -- merged in #17271. A later PR from the same
author, cut BEFORE that merge, rewrote the whole file and restored the defect. It merged
in #17296. Nothing conflicted. Nothing was loud. The two tests simply went red again, on
main and on every branch cut from it, and surfaced hours later as the blocking failure on
an unrelated dependency PR.

That is what `git merge origin/main` buys: it turns a silent revert into a CONFLICT
somebody has to look at. A branch cut a few hours ago is not current in this repo.

The second failure the ORDER prevents is mine, and it is why "before testing" is in the
sentence rather than "before pushing". CI builds the MERGE REF. A local green on a stale
base predicts nothing about it -- so `local-checks.ts` run before the merge is a check
that did not run, which is the class this repo cares most about.

Both surfaces get the same two bullets, because both are read on load and neither reader
sees the other: CLAUDE.md section 4 (the build gate) and AGENTS.md beside the pre-push
hook section, which is the nearest existing thing about what to do before pushing.

Also points at `local-checks.ts` as the local form of the gate, including the exit-code
distinction added today: an unresolvable check name exits 2 (nothing ran, not a finding)
rather than 1, because `bun <missing-file>` exits 1 and is otherwise indistinguishable
from a check that ran and found something.
