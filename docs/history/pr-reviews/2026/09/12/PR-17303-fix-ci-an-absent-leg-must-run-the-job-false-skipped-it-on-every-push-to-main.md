## Description

**Live defect on `main`, shipped by me in #17293.** Every push to `main` since it landed has
reported a green gate while skipping most of the tree — including three jobs in the
uncompensatable floor.

## What broke

```yaml
if: fromJSON(needs.path-filter.outputs.legs).gate_lint_typescript != false
```

I described this as fail-closed: a leg the selector never emitted reads as `null`,
`null != false` is true, so an unknown job **runs**. That reasoning is wrong about GitHub
Actions.

Actions compares operands of **different types by casting both to number**. `null` → 0 and
`false` → 0, so an absent leg evaluates `0 != 0` → **false** and the job **skips**. The exact
inverse — and silent: nothing fails, nothing is loud, the gate stops covering the tree while
still reporting success.

## Measured

`legs` is `{}` on non-PR events **by design** — that is the run-everything value of the fast
path. So on every push to `main`:

| commit | `test (TS hermetic)` |
|---|---|
| `92e7ca9b` | **skipped** |
| `0e33715a` | **skipped** |

And with it `build-and-test` (all matrix legs), `lint (semgrep)`, `lint (TS)`, every language
lint — 20+ jobs, three of them floor.

PR runs were **unaffected**: on a PR, `detect` emits a real verdict for every leg, and
boolean-vs-boolean needs no cast. Which is exactly why it survived review — the PR that
introduced it was green for the right reasons.

## The fix is the type, not the operator

`affected-legs.ts` now emits the **strings** `"true"`/`"false"`, and every selector compares
`!= 'false'`. The cast then works *for* us:

| leg | expression | result |
|---|---|---|
| absent | `null` vs `'false'` → `0` vs `NaN` | not equal → **runs** |
| `"false"` | same type, string compare | equal → skips |
| `"true"` | same type, string compare | not equal → **runs** |

28 selectors rewritten. The prose that documented the broken reasoning is **corrected, not
deleted** — 23 mentions of `!= false` remain on purpose, each explaining why the quotes are
load-bearing.

## The audit now refuses the boolean form

`ci/gate-leg-wiring.ts` gains a `boolean-comparison` finding, scanning the `if:` **lines**
(not comments — refusing prose would make the file unwritable alongside its own explanation).
Falsifiers: a mutant reintroducing `!= false` caught by job name; a check that the emitted
values really are strings; and one asserting a comment mentioning the form is *not* a finding.

## Why nothing caught it

Everything was checked except the thing that mattered. `actionlint` accepts both forms. The
tests pinned the selector **string**, not its **semantics**. No local tool evaluates a GitHub
expression. The only surface that could have shown it was a live run — and the live run
existed, green, with `skipped` on the floor, for four pushes before anyone read the
*conclusions* rather than the *colour*.

**Checking which jobs ran, not just that the gate was green, is the lesson**, and it is the
same lesson as "a required check that never ran contributes nothing to a failure count".
