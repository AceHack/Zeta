## Measured first — and the deletion half is already done

The committed tree was deleted on 2026-09-07 in **PR #16919**, and the ~6h cadence workflow has been `disabled_manually` since 2026-08-29. So there is nothing at the tip left to delete, and this PR says that rather than performing a deletion that removes nothing.

```bash
for c in $(git log --format=%H -- 'db/search-index'); do
  git ls-tree -r "$c" --name-only | grep '^db/search-index/' |

done | sort -u | git cat-file --batch-check='%(objectsize) %(objectsize:disk)'
```

The **on-disk** figure is the honest one; quoting the raw sum as the cost is a known error in this repo. Those objects stay reachable from the commits that introduced them, so **this PR does not shrink the repo** — reclaiming them needs a history rewrite, a gated class, not proposed here.

## The toy marking is split, because one label would be false

Per `.claude/rules/toy-is-free-metered-must-be-earned.md`:

| claim | register | evidence |
|---|---|---|
| **retrieval correctness** — tokenizer, corpus policy, freshness classification, `1` vs `3` | **metered, unchanged** | 81 tests; byte-identical rebuild at a rev; measured accounting vs `git grep -il landauer` at `6426eacf` (447 vs 421, all 26 attributed to a declared corpus rule, **0 unexplained**); four defects found by checking output |
| **git-native storage** — commit the index, rebuild every ~6h | **toy** | it had a meter and **failed** it — the numbers above are its result |

I did not downgrade the retrieval half. Marking 2,900 lines of measured retrieval code `toy` because its storage design failed would be exactly the silent mislabelling the rule exists to prevent, in the other direction.

`INDEX_DIR` → **`TOY_GIT_NATIVE_INDEX_DIR`** so every call site carries the label (the prefix is the guard). It is the only identifier carrying the storage claim, so it is the only one renamed — 3 call sites.

`format.ts` gains a header stating **what is not established**: that git is a viable store for a pure function of its own tree (the one measurement says otherwise); that any retention bound exists (there is none — nothing prunes or caps, and `git gc` reclaims nothing a commit still reaches); that any cadence is right (never falsified, just switched off); that the ~2 GB in-RAM rebuild holds past ~4x this corpus.

**What earns the promotion:** a store with a **bound** — a history-not-preserved repo (`zeta-index` in the repo-split draft), a retention rule, or an artifact host — plus a measurement over at least one cadence period showing total cost stays bounded as rebuild count grows. That is the falsifier the design never had: nothing in it could ever have reported *"this is too expensive."*
