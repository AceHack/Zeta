## Description

The local pre-push runner derived its roster by scanning `gate.yml` for `bun <path>.ts` — one of three invocation forms the gate actually uses.

**Measured 2026-09-12 across the whole workflow:**

| form | count | derived before |
|---|---|---|
| `bun src/…​.ts` | 46 | yes |
| `bun run <script>` | 26 | **no** |
| `bun test <path>` | 18 | **no** |
| `bun install` | 12 | no (correctly — setup) |

So **44 of 90 real check invocations were invisible** to the tool that exists to predict CI.

**Why `--audit` stayed green.** It asks whether a *job* is classified, never whether that job's *steps* are reachable. `lint (bash retirement inventory + hygiene unit tests)` runs 29 checks and contributed 2 — chart currency, the GraphQL-transport guard, ambient-time-in-tests, mise pin parity, decide-by-grep. All routine post-push failures; none runnable locally. A coverage tool that cannot see two thirds of what it claims to mirror is the vacuity class pointed at itself.

**Fix.** `matchInvocation()` recognises all three forms and still refuses `bun install`. Uncovered CI run-steps fall **96 → 47**; the 31-step job leaves the offenders list entirely. The remainder are non-bun commands (semgrep, shellcheck, npm) that `--audit` already reports and continues to report.

**Falsifiers.** Three tests, all killed by a mutant restoring the narrowing (12 pass / 3 fail). The fixture asserts each form derives and that `bun install` does not; the real `gate.yml` is asserted non-zero per form rather than an exact count, so a new gate step is not a test failure.

**What it immediately surfaced.** The first run after the fix reported 3 local failures previously invisible (`twitch-ai` `build` script missing, one hermetic TS test, one `cross-verify-ir` test). Reported, not fixed here, and not caused by this change — seeing them is what the change is for.
