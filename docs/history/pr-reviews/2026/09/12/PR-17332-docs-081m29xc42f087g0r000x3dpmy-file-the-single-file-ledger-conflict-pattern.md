## Description

Reconciling eight concurrent PRs today produced **seven merge conflicts**, and six were the same three single-file ledgers:

| file | conflicts | what they were |
|---|---|---|
| `registry/unbounded-growth-register.json` | 3 | twice "both sides added a **different** new row in the same array slot"; once two independent re-measurements of one row |
| `docs/UNHASHED-DEPENDENCIES.md` | 3 | a **derived** file — both sides were measurements taken at different times |
| `src/Core.TypeScript/hygiene/apt-job-timings.measured.json` | 1 | both sides added a different new entry in the same slot |

Not one was a real disagreement. Every one was two parties **appending independently to a single file**, which git can only present as a conflict because the additions land on adjacent lines.

This is the shape the repo already rejected. Aaron, 2026-09-11, on the refutation ledger:

> *"any ledger that's stored in git should not be a single file, it should use partitioning and date based folders like we already described and can also take advantage of our zetaid if needed."*

`db/refutations` was built that way and two appends to it **cannot** conflict, because they are different files. These three predate the principle and are exactly the case it was written for.

### Why this is filed rather than tolerated

A hand-resolved append can **silently drop an entry**. One register conflict today was two different new rows in the same array slot — resolving it by picking a side, which is the obvious move, would have deleted a measured row with nothing to notice. A conflict in `claude-agent.test.ts` the same day *did* truncate a test, and failed loudly only because of where the boundary happened to fall.

### Falsifier

Two branches each adding a new entry, merged in either order, **no conflict and both entries present**. Fails today for the register and the timings file; `db/refutations` passes it, which is the control.

### A caution for whoever re-measures

Sequential commits on `main` (register 5, timings 4, UNHASHED 6 over 7 days, all single-author) make this look harmless. The cost is entirely in **concurrent branches**, which that count cannot see — that number was 6-of-7 today.

This PR files the work item only; it changes no storage shape.
