<blockquote>
<h2>2.4.0</h2>
<ul>
<li>Harden FROST distributed key generation against round-one transcript substitution.
<ul>
<li>This is not a vulnerability; it's protection against those who don't follow the FROST spec. Spec wants user to preserve rounds.</li>
</ul>
</li>
<li>FROST: Enforced RFC 9591 point validation for BLS and BN</li>
<li>POPRF: replace inversion with const-time version</li>
<li>Weierstrass: harden public-key boundaries &amp; infinity handling
<ul>
<li>ECDH and ECDSA now reject the identity even for point types whose generic codec permits it</li>
<li>Curves that disallow infinity cannot encode it, while opted-in curves use the canonical SEC 1 <code>0x00</code> encoding.</li>
</ul>
</li>
<li>DER: Bounded ECDSA signature and INTEGER sizes before bigint conversion, preventing malformed inputs from causing disproportionate parsing and allocation work</li>
<li>Snapshot all security-sensitive state (passed arguments) to ensure it can't be mutated</li>
</ul>
<p>Special thanks to Red Team (Rob Hamilton, CalleBTC, Omer Talip) and 1Password's Off-by-1 Labs.</p>

<h2>2.4.0</h2>
<h3>Security and correctness</h3>
<ul>
<li>Protect passed options against mutation / pollution</li>
<li>keccakprg: fail until entropy is added</li>
<li>webcrypto: reject output sizes which crashed engine</li>
<li>blake3: fix tree merging for multi-terabyte streams</li>
<li>Improve zeroization</li>
</ul>
<h3>Misc</h3>
<ul>
<li>Speed-up Argon2 by 20%</li>
<li>Argon2 cost options are now optional. The defaults are <code>t: 3</code>, <code>m: 1024 ** 2</code> KiB (1 GiB), <code>p: 1</code>, <code>dkLen: 32</code>, and a 1 GiB <code>maxmem</code> limit; larger-memory calls must set <code>maxmem</code> explicitly.</li>
<li>Corrected scrypt's default <code>maxmem</code> to work for <code>N: 2 ** 20</code>, <code>r: 8</code>, and <code>p: 1</code></li>
<li><code>nextTick</code> and <code>asyncLoop</code> now yield through <code>scheduler.yield()</code> when available or <code>setTimeout</code> otherwise, allowing timers, I/O, and rendering to progress. They also accept optional rejection cleanup; async Argon2, PBKDF2, and scrypt use it to wipe work state if scheduling is aborted.</li>
</ul>

<h2>plugin-react@6.1.1</h2>
<h3>Add <code>compiler.logDiagnostics</code> option</h3>
<p>Recoverable React Compiler diagnostics are no longer logged by default. Set <code>compiler.logDiagnostics</code> to <code>true</code> to log them through Vite. Fatal diagnostics are always logged and fail the transform.</p>

<p>The React Compiler transform was using the top-level sourcemap option instead of the environment sourcemap option. This caused a problem when the experimental <code>builder.sharedPlugins</code> was enabled.</p>
</blockquote>
