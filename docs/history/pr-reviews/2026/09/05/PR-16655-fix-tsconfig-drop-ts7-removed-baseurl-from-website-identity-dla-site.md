## Description

## What

Remove the `"baseUrl": "."` compiler option from two tsconfigs:
- `src/Renderers/website/tsconfig.json`
- `demo/identity-dla-site/tsconfig.json`

## Why

TypeScript 7.0.2 — pulled in by the vite 8 bump merged as #16648 — removed the `baseUrl` option entirely (`error TS5102`). After #16648 landed on main, the `gate / lint (Renderers/website)` and `gate / lint (identity-dla site)` lanes went red on **every** open PR (#16640, #16641, #16651, #16654), because those lanes run `tsc --noEmit` against the merged tsconfig.

These are drift-tier (non-required) lanes, so they were not blocking merges — but they painted a persistent, misleading red X on unrelated dependabot/heartbeat PRs. This clears the noise at the root.

## Safety

Both tsconfigs already express path aliases with explicit `./`-relative values (`@/* -> ./client/src/*`, `@shared/* -> ./shared/*`, `@/* -> ./src/*`). Under TS7, path values resolve relative to the tsconfig location by default, so removing `baseUrl` is behavior-preserving under both TS6 and TS7.

## Verification

Ran `tsc 7.0.2` against the fixed `identity-dla-site` config: `TS5102` count drops from 1 to 0 and `-p tsconfig.json` loads cleanly.
