## Description

## Why

`macos-install-sh-test` has failed on **every commit to main** for 6+ consecutive runs (over a day). Root cause is a manifest name-drift, not flakiness.

The failing step ("Did install.sh satisfy its own manifest?") runs `tools/setup/manifest-realized.ts`, which verifies each `manifests/brew` row against `brew list --formula`. Two rows added 2026-09-01 (`f5ce8a2cf`) declare Homebrew **aliases** that `brew list --formula` never reports:

- `pkg-config` — Homebrew renamed this formula to `pkgconf`; `brew list --formula` reports `pkgconf`.
- `openssl` — bare `openssl` is an alias for the keg-only `openssl@3`; `brew list --formula` reports `openssl@3`.

`install.sh`'s `brew install pkg-config openssl` still succeeds (the aliases resolve), but the installed keg names differ from the declared row names, so the verifier reports both as `DECLARED AND ABSENT` and exits 1 forever.

## What changed

- `manifests/brew`: `pkg-config` → `pkgconf`, `openssl` → `openssl@3` (the canonical names `brew list --formula` reports; both remain valid `brew install` targets).
- `manifests/apt` is left untouched: `pkg-config` is the correct Debian package name — only Homebrew renamed.

## Tested

- `bun test tools/setup/manifest-realized.test.ts` → 21 pass / 0 fail, incl. "every real manifest parses with zero errors".
- Verifier parse over the edited manifest: 0 errors; rows now carry candidates `[pkgconf]` / `[openssl@3]`.

Refs: [Homebrew Formulae — pkgconf](https://formulae.brew.sh/formula/pkgconf), [Homebrew/brew#18788](https://github.com/Homebrew/brew/issues/18788) (pkg-config→pkgconf), [Homebrew/homebrew-core#119967](https://github.com/Homebrew/homebrew-core/pull/119967) (openssl aliases openssl@3).
