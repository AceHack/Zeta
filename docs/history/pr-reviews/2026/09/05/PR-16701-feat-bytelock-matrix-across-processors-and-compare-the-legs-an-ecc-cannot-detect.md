## Description

## The gap

The byte-lock proves nine independent implementations agree with a committed trajectory. It ran on **one runner** (`runs-on: ubuntu-24.04`, no matrix), and that cannot say anything about the **machine** — for a structural reason rather than a matter of code strength:

> **An error-correcting code cannot detect a wrong processor.** A code over data detects corruption *of the data*. If the CPU miscomputes, it computes the **check** wrong too — consistently, and in agreement with itself — so recomputing or lengthening the code does not help. The check and the thing checked share the fault.

Not hypothetical: mercurial cores miscompute specific inputs while passing every self-test (Hochschild et al., *Cores That Don't Count*, HotOS 2021; Dixit et al. 2021). The only mechanism that catches it is redundant computation on **independent hardware**.

Both ingredients already existed and were never connected — `bytelock` had four-plus implementations on one runner; `build-and-test` had five machines with no cross-leg comparison (`upload-artifact` appeared **0 times** in `gate.yml`).

## What lands

- `bytelock` gains a **three-leg matrix** — `ubuntu-24.04`, `ubuntu-24.04-arm`, `macos-26` (two architectures, three OSes) — with per-OS toolchain install, per-leg artifact names, and `fail-fast: false` (cancelling siblings would destroy exactly the evidence the comparison needs, and the interesting case is a leg that fails while others pass).
- A new **`cross-processor`** job downloads every leg and compares them, running `if: always()` on purpose.
- `src/wasm-dla/bytelock/compare-across-legs.mjs` — the comparator.
- A research note recording the fault taxonomy (power loss / disk / memory / CPU), what each corrupts, and which mechanism catches which.

**Why comparing verdicts is enough:** each leg records a per-(substrate, seed) verdict against a *committed* golden vector, so source, input and expectation are all held fixed and the only free variable across legs is the machine. Two legs disagreeing on the same pair is a hardware-or-toolchain fact by construction.

## Proven able to fail before being trusted

- **9 self-tests run in CI *before* the verdict is believed** — agreement, divergence, both vacuity guards, the toolchain-difference case, an unreadable leg, and substrate names containing spaces.
- **End-to-end against a real locally-produced report:** two identical legs compare **28 shared pairs** and AGREE; flipping one verdict yields a named divergence (substrate, seed, which legs) at exit 1; a single leg REFUSES at exit 2.

**The vacuity guard is the point, and it is the likely failure mode here.** A cross-leg comparison finding no disagreement is indistinguishable *in an exit code* from one that compared nothing — an artifact that did not upload, a leg that died before emitting, a toolchain absent everywhere. So it **refuses** (exit 2) rather than passing when fewer than two legs report, or when no pair executed on more than one. Silence is never reported as agreement.

Toolchain differences are **excluded, not compared**: `SKIP` / `TOOLING-ABSENT` / `MALFORMED` never counts as a divergence — the same conflation `run-bytelock-ci.mjs` already refuses internally.

## Reviewer notes — two things deliberately not fudged

- **The new legs' floors are `1` and marked UNCALIBRATED in the file.** Nobody has measured which substrates those runners execute, and inventing a number would be asserting instead of reading. A floor of 1 still refuses a leg that ran *nothing*. **They must be raised once the first runs report** — the same discipline as the ubuntu leg's own `2 -> 9` history, and a permanently-1 floor would be the check-that-cannot-fail this matrix exists to defeat. **The ubuntu leg's measured floors are untouched.**
- **Windows is not in this matrix.** `windows-2025` and `windows-11-arm` are already in `build-and-test`, so the runners exist; what is unmeasured is whether `wabt` and `lua5.4` install there, and a leg that reports nothing would pad the count without adding a processor. Named as follow-up rather than guessed at.

**Honest limit, inherited not solved:** this does not catch a fault common to every leg — an implementation wrong everywhere, or a specification bug. Knight & Leveson (1986) measured that independently developed versions fail in correlated ways.
