<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/pnpm/pnpm/releases">pnpm's releases</a>.</em></p>
<blockquote>
<h2>pnpm 11.25</h2>
<h2>Minor Changes</h2>
<ul>
<li>
<p>Added an opt-in proof of concept that lets installs reuse a dependency's build output across machines, by publishing and restoring signed, organization-scoped artifacts through pnpr instead of running the lifecycle scripts locally.</p>
<p>Configure it with the new <code>remoteSideEffectsCache</code> setting. A workspace names the eligible <code>organization</code> and <code>packages</code>; everything describing the act of signing — <code>publish</code>, <code>keyId</code>, <code>builderId</code>, <code>trustedKeys</code>, <code>privateKey</code> and the provenance fields — is refused in <code>pnpm-workspace.yaml</code> and read from the global config file or the environment instead.</p>
</li>
<li>
<p>Added macOS and Windows x64 and arm64 support to remote shared build artifacts <a href="https://redirect.github.com/pnpm/pnpm/issues/13771">pnpm/pnpm#13771</a>.</p>
</li>
<li>
<p>Added the <code>audit.ignorePrune</code> setting. When set to <code>true</code>, <code>pnpm audit --fix</code> removes ignored GHSA entries that no longer appear in the audit report.</p>
</li>
<li>
<p>Generalized the experimental shared-artifact protocol so candidates and signed payloads identify a discriminated subject. Dependency side effects use package and source-integrity subjects, while workspace tasks use project and task subjects.</p>
<p>This changes shared-artifact request bodies and signed payloads. A pnpr server and its clients have to be on matching versions.</p>
</li>
<li>
<p><code>pnpm init</code> now pins the latest pnpm version, instead of the version of pnpm that ran the command. A project scaffolded by an outdated pnpm therefore no longer inherits that staleness through its own <code>devEngines.packageManager</code> / <code>packageManager</code> pin <a href="https://redirect.github.com/pnpm/pnpm/issues/7490">#7490</a>.</p>
<p>The version is read from the <code>latest</code> tag on the package-manager registries. When that lookup cannot answer — no network, an unreachable or slow registry, <code>offline</code>, or a <code>latest</code> that the <code>minimumReleaseAge</code> / <code>trustPolicy</code> settings reject — <code>pnpm init</code> pins the running version as before, and never fails or hangs on the lookup. A <code>latest</code> that is older than the running pnpm is never pinned either.</p>
</li>
<li>
<p>A <code>scope</code> set in a project's <code>pnpm-workspace.yaml</code> is now ignored, with a warning naming where to set it instead. <code>pnpm login</code> records the scope as a <code>@scope:registry</code> route in the machine-global <code>auth.ini</code>, which outranks <code>~/.npmrc</code> in every project — so a repository-committed file could redirect a scope such as <code>@acme</code> for all of a user's other projects after one routine login. Use <code>--scope</code>, the <code>PNPM_CONFIG_SCOPE</code> environment variable, or the global config file instead <a href="https://redirect.github.com/pnpm/pnpm/issues/13557">#13557</a>.</p>
</li>
<li>
<p>Verified remote build artifacts are persisted in the shared store with their signed origin metadata. Later installs reverify the artifact against current trust, policy, platform, and source before reuse, while invalid remote variants are quarantined per channel (<a href="https://redirect.github.com/pnpm/pnpm/issues/13771">pnpm/pnpm#13771</a>).</p>
</li>
<li>
<p>Persist completed recursive tasks so <code>--resume-from</code> skips exactly the work that passed during a matching interrupted or failed <code>pnpm -r run</code> / <code>pnpm -r exec</code> invocation. When no compatible state exists, pnpm retains its graph-based resume behavior.</p>
</li>
<li>
<p>Allowed <code>pnpm update --patches</code> to refresh registry revisions through a configured pnpr server while retaining locked package versions.</p>
</li>
<li>
<p>Added explicit registry revision selection with <code>&lt;version&gt;+rN</code> and <code>pnpm update --patches</code> for refreshing revision artifacts without changing package versions. Registry-backed lockfile policy checks recognize historical revisions, and pnpr now preserves safe revision histories from upstream registries.</p>
</li>
<li>
<p>Workspace install, rebuild, pack, publish, stage, and lifecycle work now starts as soon as its dependencies finish instead of waiting for an unrelated topological group.</p>
</li>
<li>
<p><code>pnpm stage approve</code> now approves several staged packages at once. Run it without a stage id to pick from the staged versions interactively, or pass a list of stage ids. The whole batch is approved with a single one-time password, and pnpm asks for a new one only once the registry stops accepting it. Inside a workspace, the selected packages are approved in dependency order, and a package whose workspace dependency could not be approved is skipped instead of being published against a dependency that never reached the registry.</p>
</li>
<li>
<p>Added per-task concurrency limits to workspace task orchestration. Set <code>tasks.&lt;name&gt;.concurrency</code> in <code>pnpm-workspace.yaml</code> to limit how many instances of that task may run across workspace projects at once:</p>
<pre lang="yaml"><code>tasks:
  build:
    concurrency: 2
</code></pre>
</li>
<li>
<p>Added support for registry replacement tarballs using standard integrity values, explicit revision fields, registry routing from the <code>registries</code> setting, non-redirecting integrity-addressed URLs, canonical safe-integer revision numbers, and pnpr proxying for immutable upstream revision artifacts.</p>
</li>
<li>
<p><code>sideEffectsCache</code> now declares the whole of how a package's build output is reused — whether one is restored, whether one is saved, and the remote tier that shares it between machines:</p>
<pre lang="yaml"><code>sideEffectsCache:
  read: true
  write: true
  remote:
</code></pre>
</li>
</ul>
