# Summary

Aaron asked to make the emulator-vs-metal distinction follow **detected hardware**, using NixOS (not just Kubernetes labels); to support FIDO and biometrics on developer boxes; and to keep prod key rotation automatic.

Kubernetes cannot see a USB YubiHSM or a fingerprint reader. Nix eval cannot either (`hardware-configuration.nix` in this tree is still `not-detected.nix`). The host **declares** `zeta.hostSeal.boxRole`. Presence is still a probe (`ID=nixos`, `frost-hardware-probe.ts`, `tpm2-linux-probe.ts`). SoftHSM2 / swtpm stay a **job** declaration — never inferred from `/dev/tpmrm0` on a runner.

| Role | Rotation |
|---|---|
| `developer` | FIDO and biometric supported. Attached YubiHSM / smartcard HSM / TPM still wins. |
| `prod-metal` | Rotation **must** be automatic (HSM or TPM PKCS#11). FIDO / biometric may exist as break-glass; they are refused as the rotator. |
| `ci-emulator` | TypeScript-only. Not a NixOS host role. |

Default NixOS `undeclared` is a no-op (same as `zeta.tpm2Seal.mode = "off"`). This import does not flip control-plane to `prod-metal`. Init stays gated on every role. `security.pam.u2f` / sudo fingerprint are **not** enabled (lockout).

Classifier: `src/Core.TypeScript/cluster/host-seal-profile.ts`. Nix model: `full-ai-cluster/nixos/modules/host-seal-model.nix`. Workitem: `081M1SD6GZ8087G0R001TNHN19` (continues #16689, now on `main`).
