## Description

Three of your corrections, all measured.

## 1. My drift step was skipping sixteen other checks

`chart-currency` had **no `continue-on-error`**. Steps run in sequence and a failing one aborts the rest — and chart currency fails every run by design, so the job died at **19s** and sixteen downstream checks never ran: graphql, scan-floor, ambient-time, arity-equality, arity-nonequality, hook-script-paths, linter-coverage, consent-signoff, collation, mise-parity, hygiene-tests, audit-tests, hw-inventory, inventory-readmodel, book-index, inventory-tests.

All read `skipped`, indistinguishable from `passed` at a glance. I introduced the exact failure class this repo refuses, inside a change meant to make a silent condition loud. **The 19 seconds was the signal.**

## 2. "Don't just ignore drift" — now it goes green

**Cleared:** argocd 10.7.2 → **10.8.0** (all four pin sites), argo-workflows 2.0.3 → **2.0.4**.

**Carried with reason + exit** in `chart-currency.baseline.json`: gitlab, temporal, kube-prometheus-stack, spire. `--drift` exits **0** — *"no NEW drift, 4 carried with a reason and a lift condition."* A chart not in the baseline going behind turns it red, which is the signal worth having.

The baseline isn't a parking space: a **stale acknowledgement is an error**, since an entry for a chart that stopped drifting silently grants it a pass next time. That predicate caught its own author — v1 keyed on `behind > 0` and convicted headscale's entry, because a dormant chart has nothing to be behind *of*.

## 3. headscale moves home — and DORMANT is an error now

You were right that the plan existed; I hadn't read it before writing "nothing to bump to." The work item's title says it: **headscale is NOT dormant, the chart moved home.**

| | chart | appVersion |
|---|---|---|
| was | `charts.gabe565.com` 0.16.0 | v0.25.0 |
| now | `codeberg.org/wrenix/helm-charts` **1.0.19** | **0.29.3** |

That repo's **whole index is dead** — `max(created)` across all 39 charts is 2025-02-19. So this repoint is worth **four minor server releases** no chart bump could deliver. *Chart currency is not app currency.*

**DORMANT is now an error**, per your call. Being unable to move is worse than being behind — no security fixes, no upgrade path — and headscale wore that label 563 days while its project shipped four releases. A warning invites waiting for a bump that cannot arrive.

Values **rewritten, not carried** (different chart): flat `persistence.*`, `headscale.config.server_url` (real config, your "headscale with config"), and `certmanager.enabled: false` since the default points at a `letsencrypt-prod` ClusterIssuer the dev lane doesn't have.
