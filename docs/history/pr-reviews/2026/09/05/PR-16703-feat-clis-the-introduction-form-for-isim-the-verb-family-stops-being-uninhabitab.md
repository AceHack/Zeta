## Description

## The gap

`Verbs.Tests.fs` already stated it at its sharpest, by reflection rather than prose:

> *"An interface family with eliminators and no introduction form is uninhabitable as a pipeline by construction — no amount of implementation effort produces the first value."*

Six members **consumed** an `ISim<'a>`; none returned one. That was BREAK A, and it made the whole surface un-startable.

## What lands

`IGenVerb.Gen<'a> : 'a -> ISim<'a>`, inherited by `ICli`.

## Why this is safe to land on a question reserved for the maintainer

`Verbs.Tests.fs` lists three readings of *"what does `sim` return"* and picks none, because choosing decides the semantics of the universal interface everything conforms to.

**This change needs none of them.** All three readings require *some* way to produce the first value — and reading 2 says so outright: the value comes from *"a builder, the room, or `SimVerb`"*. Under that reading the form already exists and was merely never declared here. Declaring it takes nothing off the table.

### I nearly did the wrong thing, and it is worth a reviewer's attention

My first plan was to fix BREAK B by making `IMeasurement<'a>` so that `sim |> mea |> cut` would chain. **The file's own analysis stopped it.** Aaron stated a preference (2026-08-17) for the reading under which `ISim<'a>` is the **free object** and `mea`/`cut` are two *interpretations of one term* — and under that reading **BREAK B is not a defect at all; the documented pipe is what is wrong.** Bending the types to match the doc would have silently picked the reading that contradicts his stated preference, on the exact question the file reserves for him.

## What is and is not settled

| | |
|---|---|
| **Settled** | the family is now **inhabitable** as a pipeline |
| **Answered, narrowly** | reading 1's objection — that `Sim: ISeed * TimeSpan -> ISim<'a>` makes `'a` a return-position-only parameter chosen out of nothing. `Gen<'a>: 'a -> ISim<'a>` determines `'a` from the **argument**. That answers an objection to a *mechanism*; it does not choose reading 1. |
| **NOT settled** | what `sim` *means*, which reading is right, and **BREAK B**. `Sim` still returns `unit` deliberately (reading 2's point stands — it is the CLI invocation, and a command returns nothing). `mea` and `cut` still both consume the sim; `documentedLoop` still executes the fan-out. The free-object reading remains a **shape correspondence** this does not promote: an introduction form is *necessary* for it and nowhere near sufficient. |

## The test was revisited, not flipped

It carried a standing instruction:

> *"the day an introduction form is added, `producers` stops being empty and this test fails — which is exactly the moment the gap closes and this file must be revisited."*

It did fail, and it is rewritten rather than deleted:

- the assertion is **inverted**, so it cannot pass vacuously — remove the form and it fails again
- **both halves** are asserted now, because a family with only introduction forms is as uninhabitable as one with only eliminators
- the producer is **named**, so a future reader sees *which* member closed the gap rather than only that a count is non-zero

Its sibling prediction was exact too — *"if `Sim` ever returns that value, this parameter disappears and the change is a one-line diff at this call site"*. The `produceSim` parameter is gone, and that is the diff.
