## Description

The `live kind included Synced+Healthy proof` job has been red with prometheus unschedulable. It was recorded — by me among others — as a **capacity** problem. The scheduler says otherwise:

```
0/1 nodes are available: 1 Too many pods.
```

## That is a COUNT ceiling, not a resource one

kubelet's `maxPods` defaults to **110 per node** and is reached by the *number* of pods regardless of how small their requests are. **None of the millicore/MiB budget work touches it** — halving every request in the tree would not schedule one more pod once the count is hit. Reading "Too many pods" as capacity sends you to the wrong lever entirely, which is why the reason is written into the config beside the number.

Raised to **250** in both CI kind profiles, labelled as **headroom, not a measurement**: the exact steady-state pod count is UNMEASURED — the failing run's event log names 43 distinct pods, but that counts only pods that *emitted an event*, so it's a floor and not a total.

**Why the raise is safe:** `maxPods` bounds pod *count*, not resource consumption. The scheduler still enforces every CPU and memory request against the node's allocatable, so this cannot oversubscribe the runner — it only stops the count from binding before capacity does.

## The second half is the more interesting defect

This fix **could not have been verified**, because `full-ai-cluster/dev-cluster/profiles/**` was **not in this workflow's `paths:` filter** — on either `pull_request` or `push`.

The files passed to `kind create --config` decide what the cluster *is* — node count, CNI, and now the pod ceiling the scheduler enforces. They could not re-run the only job that proves the cluster comes up. **A bootstrap change landed unverified by construction.**

That's the same shape as a check that cannot run looking like one that passed, one layer further out: here the check exists and is green — on a cluster built from a config it never saw.

Both trigger sites now include the profiles directory, **so this PR verifies its own fix.**
