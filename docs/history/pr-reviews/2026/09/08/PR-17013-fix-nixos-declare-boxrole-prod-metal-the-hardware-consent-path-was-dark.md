## Description

`host-seal-profile.nix` defaults every host to `boxRole = "undeclared"` — a deliberate no-op: no pcscd, no YubiHSM udev, no packages, no assertions. **No host set it.** So the entire hardware-consent path has been off on every real host — not unwired to the ceremonies, switched off one level beneath them.

That's why *"no biometric gate on Linux"* read as the blocker. It isn't. The eleven key-custody CLIs failing closed on Linux are refusing the **wrong question**. The intended mechanism is TPM or HSM, with biometrics *"few and far between"*, because the goal is hardware **completely controlled by the AI and the code after bootup**, with human intervention only through declared remote interfaces. A fingerprint prompt on an unattended node is the opposite of that.

## `prod-metal` encodes exactly that posture

```
automaticRotationRequired = true    rotation must be machine-driven
fidoRotationAllowed       = false   a forgotten YubiKey cannot become rotator
biometricRotationAllowed  = false   no fingerprint, no console presence
enablePcscd               = true    the smartcard reader stack comes up
enableYubiHsmUdev         = true    the HSM is addressable
```

The two `false`s matter as much as the two `true`s — `developer` would enable FIDO and biometric userspace, which is the console presence this cluster is designed not to need.

## Measured before and after, not asserted

`nix eval` of `config.services.pcscd.enable`:

| | value |
|---|---|
| main (undeclared) | **`false`** — reader stack dark |
| this change | **`true`** — on control-plane *and* worker-gpu |

`config.zeta.hostSeal.boxRole` evaluates to `prod-metal`. Both hosts parse and evaluate. Declaring the role asserts nothing about hardware at build time — it brings up the stack that can *see* it. With `undeclared`, a device sitting in the reader could not be reached no matter what any probe reported.

## The module asked for a measurement first

*"Flip the role on a real host after measuring hardware"* — and one now exists (#17011): two readers on this box, both with cards present, including a **SmartCard-HSM v4.1 already provisioned** with a `zeta-test-token`.

**Honest limit, written into both host files:** that capture is macOS, taken on the box about to be reformatted into this host. It establishes the *devices* exist and are provisioned; it does **not** establish that NixOS enumerates them, since nothing has ever booted this configuration. The capture also found two OS surfaces disagreeing — `opensc-tool` saw both readers while `security list-smartcards` reported none — so a probe on this side must not read one silent surface as absence.
