## Description

feat(core): StateSpace counts what it PRUNES — the first erasure meter

Aaron 2026-09-08: "our heat mostly comes from future pruning from our zeta
scheduler and rodneys razor." That names the dominant erasure source, so this
makes it countable at the one site where the pruning is explicit.

WHAT THE SITE ACTUALLY DOES. In exploreKeyed and exploreGuarded:

    let child = Chip8Cow.frameStep cyclesPerFrame { parent with Keys = a }
    if invariant child then ... // kept
                                // else: dropped, with no record whatsoever

frameStep runs BEFORE the invariant is checked, so a pruned child is a fully
materialised frame that is then discarded. The erasure is real computed work, not
an unexplored option -- which is exactly the quantity Landauer prices.

And it was the ONE ending that left no trace. Revisits, SelfLoops and Truncated
were all already counted; pruning alone was invisible. That is the asymmetry
Chip8ConsultCensus warns about in this same subsystem -- "a bucket with count
zero is a measurement, not an absence" -- applied to itself.

Adds `Pruned: int` to StateSpace.Graph. `explore` takes no invariant and reports
0 rather than an unknown. Graph is constructed in exactly three places, all
inside StateSpace.fs, so the blast radius is the file itself.

WHY A FIELD AND NOT A DERIVATION. Aaron, on the degenerate case being
field-for-field identical to a no-op: "yes but they cost more heat than no-op."
That is the argument for a third axis in one line -- two runs can produce
IDENTICAL observable results at DIFFERENT cost, so heat is not recoverable from
the output and must be counted separately.

FALSIFIERS, and mutation testing earned its keep here in an embarrassing and
useful way. Three tests; each mutation kills exactly its own:

  * exploreGuarded COUNTS the children it computed and dropped
  * exploreKeyed also counts what it drops -- THIS TEST EXISTS BECAUSE A MUTANT
    SURVIVED. My first mutation run disabled the KEYED counter and all seven
    tests still passed: the counter was real and its test was not. Every existing
    test exercised exploreGuarded. Mutation found a vacuous falsifier, not a
    broken implementation, which is what it is for.
  * explore reports zero pruning, not an unknown

DEGENERATE CASE RECORDED, NOT BLESSED. Aaron: "nothing is safe is a degenerate
case and belongs to our antibable to resist." An all-refusing invariant is the
rho -> 0 cliff in invariant space. exploreGuarded handles it by refusing the ROOT
before the loop, so every counter reads zero and the returned Graph is
field-for-field identical to a no-op -- nothing distinguishes "your invariant
excluded the entire space" from "there was nothing to explore". That is a check
that did not run looking like one that passed.

NOT FIXED HERE, and the test says so: fixing it needs a distinguishable outcome
for a degenerate guard (a refusal, or a verdict constructor in the OpenAtBound
spirit), which is a type change with its own callers. The test asserts the
INDISTINGUISHABILITY explicitly, comparing against an empty-action no-op, so a
future fix BREAKS that line rather than silently passing it.
