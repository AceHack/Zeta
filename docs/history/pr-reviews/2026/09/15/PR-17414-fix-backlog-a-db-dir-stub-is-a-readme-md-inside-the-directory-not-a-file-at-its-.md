## Description

411 open code-scanning alerts appeared — all CodeQL QUALITY rules, which is a different
stream from the security alerts this repo had been tracking at zero. 41 of them came from
THREE 3-line files.

THE DEFECT. `getStubContent`'s last branch is commented `// db-dir (README.md)` and emits an
H1 with a TRAILING SLASH (`# name/`) — the directory form. The write ignored that and put the
content at `path` itself. Combined with the type rule (anything not ending `.md` is
`db-dir`), a reference to `dora-metrics.ts` produced a MARKDOWN FILE NAMED `.ts`, and CodeQL
duly parsed it as JavaScript.

ELEVEN files were in that state, not three: 3 `.ts`, 2 `.sh`, 2 `.yaml`, 2 `.fs`, and 2
extensionless. Only the `.ts` ones raise `js/syntax-error`; the rest were silently wrong.
All eleven are now `<path>/README.md`, which is the tree's own convention — `db/` holds 92
of them.

IT IS A REPEAT, WHICH IS WHY THE GENERATOR IS FIXED AND NOT JUST THE OUTPUT. PR #8814
(2026-06-21) fixed the same shape once already. And Vera's record of #16336 names the cause
exactly — "Type bug instantiated: db-dir stub on file paths ... Bug lives in parent
auto-vivify.ts" — reached independently before I looked at it, which is the cross-check
working rather than duplicated effort.

THE FIX HAD NO FALSIFIER AND NOW IT DOES. Reverting the write left all 8 existing tests
green. That is the same gap I shipped with the exclusive-lock fix earlier this week, and I
am not repeating it: the decision is extracted as a pure `stubTargetPath(path, type)` —
necessary because `processAll` writes into the real repository root and could not otherwise
be tested without creating files under `db/` — and pinned by three tests.

Mutation-verified in BOTH directions:
  db-dir writes at the path (the original bug)        9 pass  2 fail
  db-file ALSO gets a README (the over-correction)   10 pass  1 fail
  control                                            11 pass  0 fail

`tsc --noEmit` rc=0 on an empty log. `auto-vivify --check` scans 1221 files, vivifies 0, and
reports the same 50 dangling references as before — the repair changed no resolution.

REMAINING, NOT CLAIMED AS FIXED: 370 alerts. 109 are in `docs/`, `db/` or `demo/`; 41 in test
files; the largest classes are `js/implicit-operand-conversion` (81) and
`js/useless-expression` (69). Triaged but untouched here, because a 370-alert sweep is a
disposition decision — fix, dismiss-with-premise, or narrow the query pack — and not one to
take unilaterally.
