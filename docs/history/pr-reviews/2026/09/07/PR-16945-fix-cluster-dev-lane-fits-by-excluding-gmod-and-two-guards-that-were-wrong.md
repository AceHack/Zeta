## Description

The dev/CI lane's memory axis was **11148Mi against a 9216Mi budget**. It is now **9100Mi and FITS**.

**NO REQUEST CHANGED.** The `metal` rung the committed tree ships is byte-identical and the 16-core box deploys exactly what it deployed before — only the lane's *denominator* is one Application smaller. This is the option the ledger had not considered: it had already weighed and declined *cutting gmod's dev memory* ("its own claim argues against it in writing") and *squeezing keda* ("a size chosen to pass rather than to be right").

> Aaron 2026-09-07: *"we can remove gmod and test it in its own lane with some minimal install … gmod is not critical"*

## Scoped to `game-hosting/gmod/**`, not `game-hosting/**`

The narrowing was **forced by a test, not chosen**: `app-of-apps-discovery.test.ts` keeps a `game-hosting/quake` fixture it expects to be reported as UNASSERTED, and the directory-level glob swallowed it silently. Excluding one Application must not quietly exclude its unwritten siblings.

## Two guards were wrong, both surfaced by the cascade

**1. `auditDevExclusionReasons` built `present` with a non-recursive `readdirSync`.** A reason keyed on a depth-2 directory was reported STALE — *"a reason for a directory that no longer exists"* — about a directory that exists and that ArgoCD applies. This is the **same depth-1 blindness the resource ladder was already widened for** after it hid a literal 1000m; this audit was never updated with it.

**2. `"every registered reason is non-empty"` asserted `size > 0` — a check that fails when the thing it monitors gets FIXED.** It required at least one discovered-but-unasserted Application to *exist*, so a clean tree read as a regression, pricing "fix the defect" above "leave it". Now pinned to the exact size, with the vacuity admitted in the file: while the map is empty the loop below it *is* vacuous, and the pin is what stays falsifiable.

## No defect was laundered out

The retiring entry recorded a **live defect** — gatekeeper's check-ignore-label webhook denies gmod's ignore label because `game-hosting` is absent from `exemptNamespaces`. That finding was **carried to the exclusion comment in `ports.ts`**, not deleted, and it sharpens the LIFTS WHEN: restoring gmod restores the sync failure too, so memory headroom is **necessary and not sufficient**.

Prose in `single-node-budget.json` updated to the current reading; superseded figures stay in the test sequences, where that ledger's own checker says they live.

## Correction (in-branch): a lane-glob "fix" of mine was reverted

Mid-branch I changed `laneRootExclude` so a lane would not defer its own members, on the stated grounds that the function **had no test**. **That claim was false** — `src/Core.TypeScript/cluster/lane-root-exclude.test.ts` is a dedicated file naming it seven times. I had grepped only `lane-partition.test.ts`. CI caught it; the revert is in this branch.

**The union is deliberate and correct.** Those directories are deferred from *every* CI cluster for named reasons that are not lane-scoped. The measured case is `platform`, a lane-1 member whose images sit behind a GHCR token CI may not hold — without the union, a lane-1 bring-up fails for a reason unrelated to the lane, inside a job whose whole purpose is attributing failures to lanes.

**The tension I noticed is real and is recorded, not patched.** Deferrals have two kinds of reason and the design treats them as one:

| kind | example | global? |
|---|---|---|
| **blocker**-scoped | `platform` — a token CI may not hold | yes; every lane must defer it |
| **budget**-scoped | `gmod` — the dev lane's memory | **no**; a purpose-built lane with room could stand it up |

So "test gmod in its own lane" needs the two kinds *distinguished in the deferral data* — a deliberate change with its own falsifiers — not a one-line filter weakening a guard that protects a different case. Filed as the next step; the lane bring-up it would serve isn't wired yet either (`k8s-lane-partition.yml` says so itself).
