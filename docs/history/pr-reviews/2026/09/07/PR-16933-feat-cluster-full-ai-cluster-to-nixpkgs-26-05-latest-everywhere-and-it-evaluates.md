## Description

feat(cluster): full-ai-cluster to nixpkgs 26.05 — latest everywhere, and it evaluates clean

Aaron 2026-09-07: "we want to be on the latest everywhere too."

THE GAP RAN THE OPPOSITE WAY FROM THE RECORD. The stale-tree roster said
full-ai-cluster was on 25.11 "against the root flake's 24.11" — implying the
cluster was ahead and repointing would cost a downgrade. Measured: the ROOT was
already on nixos-26.05, and this flake — the one that actually installs machines
(`nixos-install --flake .#<host>`) — was the half a release behind. The version
argument that made this look expensive was backwards.

Both inputs move in ONE commit, which is not a style choice: nix-darwin asserts
at eval time that "nix-darwin and Nixpkgs branches in use must match".

  nixpkgs     b77b3de (2026-05-22)  ->  c257840 (2026-09-06)
  nix-darwin  ebec37a (2026-02-26)  ->  c3e90c8 (2026-07-11)

stateVersion 25.11 -> 26.05, and this is the edit that would have been wrong on
any other day. It is legal here because the file already records the condition —
"fresh-install scope ... no persistent K8s workloads yet, safe to bump for new
hosts" — and Aaron restated exactly that today: "there are no machines out there
tracking anything yet, I'm waiting to reformat the machine once we get
everything working." Left at 25.11 it would record a first-install release that
never happened. With a live machine it would be a migration, not an edit.

VERIFIED, and this is the part a major bump usually fails:
`nix flake check --no-build --all-systems --show-trace` exits 0 with 76 outputs
green. Renamed packages and removed options are what break a nixpkgs jump, and
none surfaced — every host, check and package evaluates on 26.05 as written. No
compatibility fixes were needed, so none are claimed.
