## Description

Aaron offered to make packages public and asked which ones needed clicking.

**None.** All four `Lucent-Financial-Group` container packages — `zeta-ci-runtime`, `zeta-orleans-silo`, `zeta-platform-controller`, `zeta-portal` — are **already public**.

## Verified by exercise, not by API report

The API report is precisely what went stale last time, so this was checked by doing it: an **anonymous** ghcr.io pull token, carrying no credential of any kind, returns **HTTP 200** on `tags/list` for both `zeta-platform-controller` and `zeta-portal`.

No `GITHUB_TOKEN`, no package-level grant, and no `ZETA_GHCR_PULL_TOKEN` is required. That last secret does not exist in the repo today — and now never needs to.

## What this corrects

The workflow asserted:

> both packages are private AND both report `repository.full_name = Lucent-Financial-Group/Zeta` … a well-founded expectation … if the token is refused, the exit is a package-level grant or a PAT in `ZETA_GHCR_PULL_TOKEN`

That reasoning was careful and correctly hedged. It became **false** when the packages were made public, and nothing re-measured it.

**The repo already held the correction, in another file.** `lane-partition.ts` says in its own comment that these two *"had been made public, the anonymous read prices them, and nothing had re-measured."* So the stale claim and its refutation sat in the tree simultaneously, in two files, for over two weeks.

A resolved blocker still being reported is the same defect class as a check that did not run looking like one that passed — and the cost here was not hypothetical: **the standing plan was to mint a PAT for a wall that is not there.**

The superseded text is kept inline rather than deleted, because the shape of the error is the lesson.

## Scope

`packages: read` is **retained** — additive, least-privilege, no write scope, and the next image added here may well be private. It is simply no longer load-bearing for these two. The GHCR half of `platform`'s deferral is closed; whatever still defers `platform` is not a credential.

YAML parses; actionlint clean.
