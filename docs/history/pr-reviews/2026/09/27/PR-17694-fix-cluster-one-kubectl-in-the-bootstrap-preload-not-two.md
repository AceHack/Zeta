## Description

Closes work item `081M3C10FFX087G0R0033DYXG0`: the bootstrap preload archive held two kubectl images at two versions (36.5 MB spent on one tool).

## Change

- `full-ai-cluster/k8s/bootstrap/internal-secret-seeding.yaml`: the 11 kubectl containers move from `registry.k8s.io/kubectl:v1.32.3` to `docker.io/rancher/kubectl:v1.35.6`. That is the exact image string the spire chart's hooks already pull in the same roster. The spire chart is **not** touched (no values override).
- `full-ai-cluster/k8s/bootstrap-preload-images.json`: regenerated. 26 → 25 images, 1,022,787,139 → 1,004,034,155 compressed bytes. That is **18,752,984 B (18.8 MB) saved**, exactly the size of the removed image. Every other digest is unchanged.
- `full-ai-cluster/k8s/image-source-provenance.json`: adds the measured `registry-1.docker.io/rancher/kubectl` row, which the offline provenance gate needs now that our own manifest names that image.
- `internal-secret-seeding.test.ts`: the image is now tied to spire-install.yaml's pinned `tools.kubectl.image.tag`, not to gatekeeper's image. The test also asserts the generated preload roster carries exactly **one** kubectl, and that every Job sets numeric `runAsUser` alongside `runAsNonRoot`.
- `INJECTION-POINTS.md` and the manifest header prose are updated to match. The work item is completed with a resolution section.

## Why it is safe (measured, not assumed)

I read the anonymous Docker Hub manifest and config blob for the amd64 manifest `sha256:da5097fc…`:
- The image is built FROM scratch.
- It has three layers: `/bin/kubectl`, `/etc/passwd`, `/etc/group`.
- `Entrypoint ["/bin/kubectl"]`, and there is no shell. That is the same shell-less shape and binary path that the Jobs' explicit `command: ["/bin/kubectl"]` uses. The Jobs only run `kubectl create secret generic`.
- It is multi-arch: amd64 + arm64.
- One difference: the image's `USER kubectl` is non-numeric. `runAsNonRoot` would reject that unless the pod names a numeric user. Every seeding Job already sets `runAsUser: 1001`, and the test now pins that.
- The server is 1.35.7, so kubectl is now one minor behind instead of three.
- The tag exists: `bootstrap-image-preload.ts --verify` resolves all 25 images to their pinned digests.

## Not verified

- No real cluster or VM run of the seeding Jobs on the new image. The first-boot roster VM workflow would cover that.
- I did not run the `--refresh` CLI itself, because Docker was not running on the Windows host and it needs Docker to derive the sandbox image. I called `buildSnapshot` with the sandbox image passed in, using the value already in the snapshot (`docker.io/rancher/mirrored-pause:3.10.2`). Helm rendering and registry sizing were real.
- `gatekeeper-crd-wait.yaml` (ArgoCD lane, not in the preload) still uses `registry.k8s.io/kubectl:v1.32.3`, so the cluster still pulls both images at runtime. Moving it is a separate, optional change.
