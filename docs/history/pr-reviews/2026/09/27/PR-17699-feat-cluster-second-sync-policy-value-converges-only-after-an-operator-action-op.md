## Description

Work item `081M3BKQFNC087G0R003MDGSAX` (closed here).

**Gap.** `zeta.io/sync-policy: manual` means *nothing will ever sync this*. `openbao` and `hindsight` are synced automatically and then wait on a **human**:

- openbao stays sealed until someone runs the gated init ceremony.
- hindsight needs an external LLM API key.

There was no word for that state, so WP11 verdict 7 reported both as `unconverged`, alongside real failures. Widening `manual` would erase the difference, so this adds a second value instead.

**The value:** `zeta.io/sync-policy: converges-only-after-an-operator-action` (`OPERATOR_ACTION_SYNC_POLICY_VALUE`).

| where | change |
|---|---|
| `manual-sync-policy.ts` | `classifySyncPolicy` → `kind: "operator-action"`. A reason is required. An `automated:` block is **required**, the inverse of `manual`, because "synced, then waiting" is false of an app nothing syncs. `operatorActionAssertion` is **stronger** than the manual contract: sync must be exactly `Synced`, and health must have been evaluated (not `Unknown` or empty). Only health may lag. `operatorActionDeclarations` reads the tree. |
| other consumers (`derive-sync-waves`, `crd-provider-consumer-order`, `single-node-readiness`, `validate-applications`, `argocd-health-test`) | They key on `kind === "manual"`, so the new kind gets the full automated treatment. That is correct: these apps *are* automated. |
| WP11 verdict 7 awk (`zeta-first-boot-k3s-verify.nix`) | New `excluded-operator-action` bucket that prints the declared action. It counts toward `excluded`. `OutOfSync` or unevaluated health stays `unconverged`. `Synced+Healthy` → `converged`. A malformed declaration (no automated block, or no reason) gets the full contract plus the MALFORMED note. The reason field width goes 180 → 400 so the doc pointer is not truncated. The header's "who owns the red" list is updated. |
| `first-boot-replica.ts` stage 6 | Reads `operatorActionApps` from the declaration, ahead of the name-based `isKnownSealedByDesign` fallback. |
| `openbao`, `hindsight` Application.yaml | Annotated. Each reason names the action and where it is documented (`openbao/TOPOLOGY.md` §5, `INJECTION-POINTS.md`). |
| **operator-facing:** `zeta-install.sh` completion banner | New **OPERATOR ACTIONS** section. It prints a `k3s kubectl … -o custom-columns=… \| grep …` command that lists these apps and their actions **off the live cluster**, so the banner cannot drift from the declarations. |

**Tests**
- `wp11-roster-shell-parity.test.ts` runs the real awk extracted from the `.nix` (40 pass). It checks the bucket, the `OutOfSync`/`Unknown` reds, both malformed forms, the counts, and that the awk literal equals the exported TS constant.
- `manual-sync-policy.test.ts` checks the classifier's refusals, that the assertion is stricter than manual on `OutOfSync`, that the real tree contains exactly openbao and hindsight, and that the banner contains the value.
- `first-boot-replica.test.ts` checks DIVERGENCE when the app is Synced but sealed, and FAIL when it is `OutOfSync`.

**Risk worth watching.** The replica lane's stage 6 now **FAILs** openbao or hindsight if either is not `Synced`. The item specifies this stronger contract. Earlier measurements say both were Synced, but a synthetic test fixture shows hindsight `OutOfSync`. If the replica goes red on that, it is the new contract reporting a real sync issue, not this diff breaking something.
