## Description

## What

`probe.ts` `browseArgs()` passed `--no-db-lookup` to `avahi-browse`. Every pass exited 1 (`avahi-browse: unrecognized option '--no-db-lookup'`, run 35985197702), so bootstrap-or-join discovery has **never run** on a shipped image. It has only ever taken the fallback. Work item `081M39K8ND1087G0R000G4EN4N`.

## Why the flag is gone, not replaced (checked against source)

- avahi 0.8 `avahi-utils/avahi-browse.c` only puts `no-db-lookup` (`-k`) and `dump-db` (`-b`) in `long_options[]` under `#if defined(HAVE_GDBM) || defined(HAVE_DBM)`.
- nixpkgs at the flake-locked rev `c25784012c99` (`pkgs/by-name/av/avahi/package.nix`) sets `version = "0.8"` and configures with `--disable-gdbm`.
- Dropping the flag does not change the output. Without a service-type database there is no lookup to suppress. On a build that has one, `_zeta-k3s._tcp` is not in it, so the type column is the raw type either way. The new args are `--parsable --resolve --terminate _zeta-k3s._tcp`.

## Found / found-nothing / could-not-run

Three states were already kept apart: `responded`, `silence` and `probe-failed`, through probe → decide → `zeta-first-boot.sh`. This PR pins the measured failure: that exact stderr becomes `probe-failed(browser-error)`, and the decider answers `refuse` for it with or without a token. It never answers `bootstrap`.

**Gap that remains (not fixed here, filed as `081M3HP7KKH087G0R0011NQAKF`):** in `zeta-first-boot.sh`, when the role is undeclared and `ZETA_DISCOVERY_REQUIRED` is left at its default `0`, a `probe-failed` is reported loudly but then **falls back to the ISO default role, control-plane**. That founds a cluster. On real hardware the safe default is to halt: a halt can be undone (press `c`/`w`), a second cluster cannot. I did not flip the default here because no lane has seen the probe *run* yet. Scenario 2 runs on `push`, and flipping blind could halt installs on `main` over some probe failure we haven't found yet. The follow-up flips it once a QEMU serial log shows the fixed probe reaching `silence` → `bootstrap`.

## Falsifier

`probe.test.ts` adds five tests:
- Every long option in `browseArgs()` must be in `AVAHI_BROWSE_UNCONDITIONAL_LONG_OPTIONS`, which is avahi 0.8's table minus the gdbm-gated pair.
- The probe runs against a getopt-faithful stand-in and returns `silence` with all five bursts, and `responded` when there is an answer.
- The measured rejection gives `probe-failed`, and the decider answers `refuse`.

With the old flag, 3 of them fail. They all pass now (15/15 in `probe.test.ts`).

## Not verified

- **Not run against the real binary.** The option table comes from the source. Nothing runs the real `zeta-cluster-discover` against the real `avahi-browse`, and there is no local `nix`.
- **No NixOS VM test exercises discovery.** `control-plane-host-boots-k3s.nix` runs avahi only as the publisher. The QEMU scenarios run the installer, but on a single node with no peers. No two machines have ever run the probe on one segment.
- `cli.test.ts` has 2 failures on Windows only (`/bin/echo`, `/bin/sleep`). They were there before this PR, and this PR does not touch `cli.ts`.
- `local-checks.ts` shows 8 failures, all in areas this diff does not touch: chart currency, the GraphQL-transport lint over other scripts, the twitch-ai build, a light-time test, and 3 cross-verify tests that need `go`.
