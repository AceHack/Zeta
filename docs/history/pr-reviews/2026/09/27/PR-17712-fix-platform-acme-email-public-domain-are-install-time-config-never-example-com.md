## Description

## Defect (live, bare-metal node, read-only kubectl)

ArgoCD `platform` never finishes syncing: both ClusterIssuers fail `Failed to register ACME account: 400 ... invalidContact ... forbidden domain "example.com"`, the sync waits on `ClusterIssuer/letsencrypt-prod` health and retries forever (`OutOfSync Degraded ... Retrying attempt #11`), so platform-controller, the portal StatefulSet, zeta-gateway, HTTPRoute, PrometheusRule, ServiceMonitor and Blueprints are never applied. Cause: `you@example.com # ← CHANGE` / `portal.example.com` / `portal.zeta.example.com` placeholders that a generic installer never changes.

## Fix: install-time configuration, never a repo default

- **UNSET is a clean, healthy state.** `platform` no longer applies `clusterissuer.yaml`; `zeta-gateway` is LAN-only (`:80`, no hostname, no cert-manager annotation); the `portal` HTTPRoute matches any Host.
- **Resolution at the START of the install** (`zeta-install.sh`, new `ZETA-PUBLIC-TLS` block, before disk enumeration): ESP `/zeta-firstboot.conf` → prompt (direct when interactive; behind a single `p` keypress, 15 s, on the zero-typing first-boot path) → UNSET. Enter / EOF / no TTY = UNSET. RFC 2606 names (+ `.local`) and shell-unsafe input refused; an invalid ESP value is refused loudly and falls through; half a pair is never applied. Joiners don't ask.
- **zflash**: `--acme-email` / `--public-domain` on both the device CLI and file-backed path, both-or-neither, validated before anything is flashed, appended to the one `/zeta-firstboot.conf`; `zeta-first-boot.sh` exports them.
- **Mechanism (existing path):** installer writes `/mnt/etc/zeta/{acme-email,public-domain}` (symlinked for `--impure` eval, like `cluster-node-id`) → new `nixos/modules/injected-public-tls.nix` → k3s auto-deploy roster (the door `root-application.yaml` uses) → a **separate** ArgoCD Application `platform-public-tls` whose kustomize base `k8s/public-tls/` carries no email/hostname; values arrive only as inline JSON6902 patches (issuer emails, public Gateway HTTPS listener `portal.<domain>`, `portal-public` route). Separate Application, no sync waves inside: ACME cannot gate platform again.
- `sync-wave-dependency-graph.yaml`: platform's `cert-manager` edge removed (no cert-manager kind left in platform).
- Operator step (DNS A `portal.<domain>` → public IP; forward 80/443 to `zeta-public-gateway`'s LB IP) in `INJECTION-POINTS.md` §10 and the completion banner.
