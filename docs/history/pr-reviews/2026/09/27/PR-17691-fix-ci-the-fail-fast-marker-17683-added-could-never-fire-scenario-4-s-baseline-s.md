## Description

Work item `081M3CAJD7J087G0R0021H6WRS` (closed here).

Run **36140151239** ran #17683's own head commit (`02c93a887c`) and scenarios 3 and 4 still took **30m10s** and **30m19s**. The serial-log artifacts show one defect per lane.

**1. The wait loop could never stop on `[zeta-first-boot] Install failed (rc=`.** `waitForManagedProcessStop` took the *first* matching terminal marker and only then asked whether it was suppressed. `nixos@zeta-installer:~` is first in `RETENTION_ABSENT_TERMINAL_MARKERS`, is present on every failed first boot (the drop-to-shell prompt), and is suppressed while first boot is in progress — so the loop picked it, discarded it, and never looked further. #17683's replay test asked the list via `.filter`, not the loop, so it passed while the loop hung. `terminalFailureMarkerToStopOn` (exported from `qemu-state.ts`) now applies suppression per marker; the loop and the test call the same function. A negative control rebuilds the old two-step and shows it returns "keep waiting" on the measured log.

**2. Scenario 4's baseline bootstrap booted the bare ISO**, which carries no ESP override, so it printed the byte-identical `BOOT disk /dev/vda is 20 GiB` refusal. Scenario 3, which boots a prepared image, got past the floor. `planPathForkBaselineBootstrap` now takes an optional `bootImagePath`, and `runPathForkRuntime` passes the fresh (no credential blob) prepared image.

**Not verified by a dispatch.** Both fixes are pinned by unit tests on the functions the lanes call; no `workflow_dispatch` has been run. In 36140151239, scenario 3 got past the floor and then stopped at `ZETA_ISO_COMMIT='unknown' is not a 40-hex git commit`. That repo-pin refusal is owned by other work and is not touched here. With fix 1 it now costs about 3 minutes instead of 30.

Local: `bun test src/Core.TypeScript/zflash/test-harness/` passes apart from 3 pre-existing Windows-path failures in `run.test.ts` and the scenario-5 contract test. They are Windows path/line-ending artefacts in code this diff does not touch; CI (Linux) is the authority.
