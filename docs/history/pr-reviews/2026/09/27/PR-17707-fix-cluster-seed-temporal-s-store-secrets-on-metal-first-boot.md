## Description

## Defect (live, read-only evidence)

Fresh USB install `node-5b2dfa`, 2026-09-27: ArgoCD `temporal` Synced/Degraded; frontend/history/matching/worker and `temporal-schema-1`'s init all `CreateContainerConfigError: secret "temporal-default-store" not found`. `kubectl get externalsecret,sealedsecret -A` → none. The other first-boot seeded Secrets (grafana, opensearch, redis-auth, zeta-blob-store, forgejo) exist. CockroachDB is up and initialised.

## Root cause

`temporal/Application.yaml` names `existingSecret: temporal-default-store` and `temporal-visibility-store`. The chart reads each via `secretKeyRef {key: password}`. Nothing on metal produced either one. `k8s/bootstrap/internal-secret-seeding.yaml` had no temporal step. Both existing audits were green: the valuesObject scan checks the **dev** roster and acknowledges temporal as dev-excluded, and the raw-manifest scan never reads the seeding Jobs.

## Fix

- **`src/Core.TypeScript/cluster/metal-secret-production.ts` (+ test).** Every Secret named in the catalogue (valuesObject and raw pod specs) must be produced on metal in one of three ways:
  - seeded by a first-boot Job in the Application's **own namespace**
  - committed as a Secret, SealedSecret or ExternalSecret
  - listed in `METAL_NOT_SEEDED` with a reason. Five entries: `hindsight-llm-api-key`, `arc-github-app` and `ghcr-pull` are external; `openbao-unseal-shares` is optional; `kubevirt-operator-certs` is operator-generated. An entry that stops matching fails as stale.
- **`seed-temporal-store` Job.** Same pattern as `redis-auth`: one `/dev/urandom` draw into tmpfs, then two create-only `kubectl create secret generic` steps with key `password`. Both Secrets get the **same** value because both stores log in as SQL user `temporal`. No credential goes into git.

## Not verified / still open

- Not applied to a cluster. The live node was only read.
- After this change temporal pods will **start** and then be **refused by the store**. CockroachDB still has no `temporal` SQL user with this password, the TLS-only store's client CA isn't in the `temporal` namespace, and the visibility schema is CockroachDB-incompatible. These are the Application's existing BLOCKED notes.
- `first-boot-replica.ts`'s `seededInternalSecretTargets` derives its targets from the dev roster, so the power-cycle stage does not cover the temporal Secrets.
