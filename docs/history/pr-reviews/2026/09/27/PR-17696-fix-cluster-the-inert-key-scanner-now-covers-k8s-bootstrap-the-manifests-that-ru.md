## Description

Work item `081M3BTKNNB087G0R000EPCNJ1` (closed here).

**Gap.** `inert-valuesobject-keys.ts` scanned Application `valuesObject`s only. A bootstrap `HelmChart` keeps its values in `spec.valuesContent`, a YAML document embedded as a string, in a file that is not an Application. So the manifests K3s applies at first boot, before ArgoCD exists to correct anything, were not scanned at all. `applicationSet.enabled: true` sat inert in `argocd-install.yaml` from the 7.7.10 -> 10.x bump until a parity change exposed it by accident.

**Change.**
- `discoverBootstrapHelmCharts` walks each declared tree's `k8s/bootstrap/`, using `bootstrapDirs` from `declared-cluster-trees.ts`. It keeps every `helm.cattle.io/*` HelmChart and parses `valuesContent` per YAML *document*. This is the same parse as `parseHelmChartValues`, but that one reads only the first document, and `spire-install.yaml` carries two HelmCharts.
- `appId` is `<tree>/bootstrap/<name>`, so a baseline key never collides with the Application of the same name.
- The offline audit, the live audit and `--write-snapshot` all go through `discoverAuditSources` (Applications + bootstrap charts). There are 57 sources, 8 of them bootstrap charts.
- Schema snapshot: `cilium@1.20.1` was measured live with helm and added. The other bootstrap pins, argo-cd 10.8.0 (both trees), cert-manager, external-secrets, spire, spire-crds and trust-manager, were already in the snapshot and are reused by chart key. This was an incremental add, not a full `--write-snapshot` re-measure.

**First-run finding (1):** `full-ai-cluster/bootstrap/spire spire-agent.workloadAttestors.k8s.skipKubeletVerification`. This is the same removed-in-spire-0.23.x key the spire Application already has in the baseline, and the same consequence: the declared intent, *verify the kubelet*, is not in force. It is **baselined beside the Application entry, not fixed**. Turning verification on changes whether the agent attests workloads at first boot, and it has to land in both places together because bootstrap/Application parity is asserted elsewhere.

**Falsifier + negative control** (new tests in `inert-valuesobject-keys.test.ts`):
- The test re-plants `applicationSet.enabled: true`, the exact historical key, into a copy of `argocd-install.yaml` in a throwaway repo root. The audit refuses `full-ai-cluster/bootstrap/argocd applicationSet.enabled` and exits 1.
- The unmodified file in the same harness produces no refusals.
- The multi-document file yields both `spire-crds` and `spire`. Every declared root is scanned, and the list of roots is read from the roster rather than hard-coded, so the test does not couple to the stale tree (`audit-cluster-tree-consumers` stays clean).
- The CLI count with an empty baseline goes from `REFUSED (15)` to `REFUSED (16)`.

Local: `bun test src/Core.TypeScript/cluster/inert-valuesobject-keys.test.ts` passes 65/65. `--offline` exits 0. `bun run typecheck` is clean. `local-checks.ts` shows 8 failures, and each one is either a missing toolchain on this Windows host (go, python3) or a check this diff does not touch (chart currency, graphql lint, twitch-ai, light-time).

**Not verified:** the full live `--check-snapshot` re-derivation was not run. Only cilium was measured live.
