## Description

## Why

Constrained replica lane, dispatch 36119931377 (job 108022790117), pulled from the job log:

- 61 kubelet `failed liveness probe, will be restarted` events over 28 containers, zero `OOMKilled`, zero `Evicted`.
- Of the 122 `Liveness probe failed` lines, **89 are the client-timeout shape** (`context deadline exceeded` / `Client.Timeout exceeded`) and 22 are `connection refused`. The containers were alive and slow, and a 1-second probe killed them.
- `coredns` (`Get "http://…:8080/health": context deadline exceeded`) and `metrics-server` were both killed. Every other pod depends on them, so they get fixed first (RESUME §4).

## What changes

**1. The node's floor: CoreDNS and metrics-server**
- k3s v1.35.7+k3s1's own `manifests/coredns.yaml` and `metrics-server/metrics-server-deployment.yaml` are vendored as `k8s/bootstrap/k3s-coredns.yaml` / `k3s-metrics-server.yaml`. They are byte-identical to k3s's copies except for the resolved `%{…}%` template variables and the liveness probe.
- Liveness goes from `timeoutSeconds: 1, failureThreshold: 3` (about 21s of stall before a kill) to **5 / 5** (about 45s). These are **upstream Kubernetes' own CoreDNS values** (kubeadm, `cluster/addons/dns/coredns`); k3s had tightened them.
- QoS and priority were already correct in k3s's copies and are kept: Burstable with requests, `system-cluster-critical` / `system-node-critical`. Node reservations and `eviction-hard` were already added by #17666; this PR does not change them.
- k3s's own copies are kept out with **`.skip` markers**, not `--disable=coredns`. `--disable` also sets `Skips["coredns"]`, and that turns off k3s's node controller, which writes `NodeHosts` into the CoreDNS ConfigMap (`pkg/server/server.go`). A `.skip` is matched by basename (`pkg/deploy/controller.go listFilesIn`), so `metrics-server-deployment.yaml.skip` removes only that one file. The RBAC, Service and APIService stay with k3s.
- `k3s-packaged-manifests.test.ts` checks four things: the vendored version matches the k3s pin in `kubernetes-version.json`, the kube-dns `clusterIP` equals the derived service CIDR + 10, no template variable is left unresolved, and the probe, priority and requests values are as intended. Negative controls: a wrong clusterIP fails test 2, and a reverted timeout fails test 4.

**2. Roster plumbing**
- `first-boot-replica.ts` now parses `<attr>.target = "…";`, so the replica writes the same skip markers the node links. A `.skip` file is written but never counted in the apply order.
- `k3s-first-boot-apply-order-eval-test.nix`: P0 still refuses a `target` override, except on the two declared skip markers. A new property pins exactly those two markers, and the expected apply order gains `k3s-coredns.yaml` and `k3s-metrics-server.yaml`.
- `bootstrap-preload-images.json` was refreshed. The only additions are the two images that now come from the roster: coredns 1.14.6 (23.8 MB) and metrics-server v0.9.0 (23.3 MB). No other digest moved.

**3. The instrument: `liveness-kill-budget.ts` now reports steady-state stall tolerance**
- The existing kill budget (`initialDelay + (threshold-1)*period`) only covers startup, so it could not see this failure. New columns: `timeout` and `stall tolerance = (failureThreshold-1)*period + timeout`. They are report-only; no new gate.

**4. One app widened, following the keda precedent: cockroachdb `db`**
- It had the tightest stall tolerance in the catalog at **11s** (chart hardcode: period 5, timeout 1, threshold 3).
- On 36119931377 all three members were killed: `x7`, `x8` and `x7 over 22m`. Every failure was the timeout shape, and cockroach itself logged `slow range RPC: have been waiting 118.13s`.
- The chart takes `statefulset.customLivenessProbe` (checked with `helm pull cockroachdb 22.0.3`). New values: timeout 5, period 10, threshold 13, for **125s** of stall tolerance, chosen to clear the measured 118s stall.

The remaining killed containers and their stall tolerances are listed in work item `081M3HPXKAJ087G0R001SQEXWY`. They were **deliberately not widened** in this PR, per RESUME's plan (floor first, re-measure, then the rest). Some of them, e.g. grafana at 120s, were killed despite already-generous probes.
