## Description

## Defect

On a fresh bare-metal install, ArgoCD app `gitlab` stays OutOfSync/Missing. The chart's hook Job `gitlab-gitlab-upgrade-check` fails on every retry with one log line: `Please follow the upgrade documentation at https://docs.gitlab.com/ee/update/#upgrade-paths`. CI run 36221053730 showed the same stall: "waiting for completion of hook batch/Job/gitlab-gitlab-upgrade-check".

## Root cause (gitlab chart 8.7.0, `helm pull --untar`)

- `templates/upgrade_check_hook.yaml` is a `helm.sh/hook: pre-upgrade` Job. It mounts ConfigMap `gitlab-gitlab-chart-info` with `optional: true`.
- `templates/_runcheck.tpl` exits 1 when `/chart-info/gitlabVersion` is missing. That is the exact line we saw live.
- `templates/chart-info.yaml` is an ordinary resource, not a hook.
- Under Helm this works, because `helm install` never runs a pre-upgrade hook. ArgoCD maps both pre-install and pre-upgrade onto PreSync, and PreSync also runs on the first sync, before the Sync phase has created chart-info. The failed hook blocks Sync, so chart-info is never created and every retry fails the same way. The result is a deadlock, and it will not clear on its own.
- This is not a version mismatch. The live Job env is `GITLAB_VERSION=17.7.0` and `CHART_VERSION=8.7.0`, and the same script exits 0 once chart-info exists (reproduced offline, see below). Live read-only check: the `gitlab` namespace contains no chart-info ConfigMap.

## Fix

Set `upgradeCheck.enabled: false` in `full-ai-cluster/k8s/applications/gitlab/Application.yaml`. The chart has no values setting for the Job's hook annotation, so the check cannot be moved to a phase where it would work. **Honest limit:** this also removes the guard for future `targetRevision` bumps. The Application now says that any bump must follow GitLab's documented upgrade path by hand.

## Falsifier

`src/Core.TypeScript/cluster/upgrade-only-hook-first-sync.{ts,test.ts}`:
- A pure check, `firstSyncDependencies`, finds every upgrade-only Helm hook (`*-upgrade`, no `*-install`, no explicit `argocd.argoproj.io/hook`) that reads a ConfigMap or Secret the same render produces as a non-hook object. It has synthetic tests.
- It renders the gitlab Application the way ArgoCD does. **RED on main:** `+ { hook: "Job/gitlab-gitlab-upgrade-check", dependsOn: "ConfigMap/gitlab-gitlab-chart-info", optional: true }`. GREEN after the fix.
- With `upgradeCheck.enabled` forced back on, it runs the chart's own rendered `runcheck` offline. With chart-info absent it exits 1 and prints the live log line; with chart-info present it exits 0. If a future chart version stops failing in this case, the test goes red, and that is the signal to turn the check back on.
