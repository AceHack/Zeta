## Description

## What failed

Run 36333822934 (job 108660735337): scenario 3 (reformat-with-retention) and scenario 4 (path-fork) both failed at `initial-install-from-iso-with-disk` after ~4.5 min with:

```
failure marker observed in serial log: panic
```

Both serial logs end mid-`nixos-install`, still copying from cache.nixos.org. The only `panic` in either log is line 619, inside nixos-install's `these 358 derivations will be built:` list:

```
  /nix/store/n3kppcrfdxaap9gwrhymfjhmkc147si5-unit-panic-on-fail.service.drv
```

That is a stock nixpkgs 26.05 systemd unit. The guest was healthy.

## Root cause

`RETENTION_FAILURE_SERIAL_MARKERS` in `zflash/test-harness/serial-markers.ts` is substring-scanned over the whole serial log, and it contained bare `"panic"`. The hypothesis that #17691's per-marker terminal suppression was the cause is **refuted**. The stop came from the plain `failureMarkers` scan, which runs before `terminalFailureMarkerToStopOn` is called.

`ci/qemu-full-install-test.ts` had already narrowed the same marker to `"Kernel panic"` for this same false positive (see its FAILURE_MARKERS comment). The zflash harness never got that change.

## Fix

`"panic"` -> `"Kernel panic"`. That is the only production change.

## Red -> green

The new test block in `qemu-state.test.ts` uses the real serial lines as a fixture and drives the actual wait loop (`createSpawnSyncQcow2RetentionExecutor().runCommandUntilSerialMarkers`):
- On origin/main: 4 fail. The healthy-install test reproduces the exact CI stderr, `failure marker observed in serial log: panic`.
- After the fix: 44/44 pass.
- Negative controls still stop fast: a `Kernel panic - not syncing` line, and `[zeta-first-boot] Install failed (rc=`.
- The existing "failure marker appears" test now feeds a real kernel-panic line instead of `panic: installer crashed`.

## Not done / not verified

- `"bail"` is still suspect, here and in the sibling lane. It was left alone.
- Scenarios 3 and 4 have not re-run past `nixos-install` since this fix. The retention restart phase and the path-fork fork phase may still hide failures of their own.
