## Description

Work item `081M3HSAP54087G0R002B846XC` (minted and closed here).

**The failure.** build-iso on PR #17695 (job 108649139794) failed at "Verify the bootstrap image pins still resolve" with this output:

```
UNRESOLVABLE  ecr-public.aws.com/docker/library/redis:8.6.4-alpine — manifest HTTP 429
1 of 26 images no longer resolve to the pinned digest ... a supply-chain event, not a chore.
```

A 429 means the registry declined to answer; it says nothing about whether the digest changed. Reporting it as a supply-chain event teaches readers to dismiss the one message this check must never have dismissed.

**The fix** (`src/Core.TypeScript/cluster/bootstrap-image-preload.ts`)
- `withTransientRetry` retries 429, 5xx and network errors up to **5 attempts**, backing off 5/10/20/40 s. It **honours `Retry-After`** (delta-seconds or HTTP-date), and total waiting is capped at **180 s**. A `Retry-After` longer than the remaining budget ends the retries instead of hanging the job.
- `resolveAmd64Digest` now returns `couldNotCheck: true` when the retry budget is spent. `--verify` goes through a new `verifySnapshot`, which counts three outcomes separately:
  - **ok**
  - **MOVED / UNRESOLVABLE**: the supply-chain-event message, unchanged. This covers a 404 (which is not retried) and a digest that resolves to a different value.
  - **COULD-NOT-CHECK**: its own message, which says "not a moved digest, not a supply-chain event … Rerun the job; if it persists, the registry's anonymous budget for this runner IP is exhausted."
- COULD-NOT-CHECK **still exits 1**. A verification that did not run is not a pass, and the ISO should not ship on an unverified pin. Only the wording changes.
- `--build-archive` pulls the same images from the same registries and would hit the same limit, so its manifest, amd64-child and blob fetches retry too. If the budget runs out there, the error reads `COULD NOT FETCH … rerun, this is not a moved digest`.
- To keep the CodeQL taint barriers intact, each URL is built right after its inline guards and outside the retry closure. The guard-count tests pass unchanged.

**Tests** (`bootstrap-image-preload.test.ts`, 68 pass)
- 429 → retry → ok, and `Retry-After: 7` produces exactly one 7 s sleep.
- A persistent 429 becomes COULD-NOT-CHECK after exactly 5 attempts, with sleeps of 5/10/20/40 s.
- A network error becomes COULD-NOT-CHECK.
- A 404 is not retried and is not COULD-NOT-CHECK.
- A `Retry-After` of 3600 stops after one attempt.
- The `verifySnapshot` output for COULD-NOT-CHECK contains no "supply-chain event" or "no longer resolve" text.
- **Negative control:** a different digest is still a supply-chain event.
- A blob 429 is retried through, and a persistent blob 503 reports COULD NOT FETCH.

**Not verified:** no live registry was rate-limited on purpose. Whether 5 attempts over about 75 s outlast public ECR's actual 429 window is unmeasured. If it does not, the job now fails with the "rerun" message rather than the supply-chain message.
