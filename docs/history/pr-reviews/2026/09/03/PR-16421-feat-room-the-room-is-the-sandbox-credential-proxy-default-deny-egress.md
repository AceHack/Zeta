## Description

Item 4 of the agentic-organization port list: **a proper credential proxy that goes inside the room where an agent executes, with the room acting as the sandbox carrying the policy.**

`ROOMS_AS_DETERMINISTIC_SIMULATIONS.md` §1 says the room *is* the agent's isolation boundary — a sandbox plus a credential proxy bound to the agent's identity — and §8 says `observe.ts` is *"the only path from 'who + where' to 'may run this tool'"*. The org side declares the shape (`CredentialProxyPort`, `ToolGrant`, `SandboxSpec` on `agentic-organization/packages/application/src/room.ts`) as a record **nothing consumes**, so nothing can fail. This puts it on the one seam a room's work actually goes through: `CommandExecutor`.

## What it does

`tickRooms` no longer hands a room a bare executor. It wraps the base executor in **that room's own** egress + credential policy first, so a room cannot run a command that skipped them.

| property | mutant that kills its removal |
|---|---|
| The agent never holds the secret — it gets a scope NAME, the proxy attaches the credential | M5 proxy returns credential material |
| A script inlining its own credential is **refused** (that is bypassing the proxy) | M3 inlined credential passes through |
| **Default-deny** egress — an empty allowlist permits nothing | M1 fails open on empty allowlist / M2 policy never blocks |
| The gate **refuses**, it does not observe-then-report | M4 runs it, then refuses |
| A room with **no declared sandbox gets NO executor**, not an unguarded one | M9 sandbox-less room still gets one |
| The wrapping is real, per-room, and the raw executor never leaks through | M8 room receives the raw executor |
| The decorator keeps the wrapped `tier` (the glass-halo audit must not be misinformed about where work ran) | M6 misreports tier |

## Honest ceiling

Stated in the module header, because this is easy to oversell: `RunSpec` is a bash script, so host extraction is a **text scan**. A script that builds a URL from variables, uses a bare IP, or shells out to a helper that fetches on its behalf is **not seen**. This bounds **declared** egress, not actual network access — real containment is the `oci`/bwrap network namespace and this does not replace it. Calling it a sandbox in the containment sense would be a stronger claim than the mechanism supports.
