## The defect

`agent-heartbeat.yml` has been `disabled_manually` since 2026-08-29 for the storage-efficiency redesign. `heartbeat-liveness.yml` was re-enabled on 2026-09-03 **without asking whether its subject was still switched on**, and then answered the only question it knew how to ask — *"how old is the newest success?"* — correctly, loudly and uselessly.

Every statement was true. None of it was news.

This is the failure the workflow's own header already warns about — *"an alarm that cries wolf gets muted, which is a slower way of having no alarm at all"* — reached from an angle the header did not anticipate. The 60-minute threshold was sized against GitHub's measured scheduling jitter. Nothing was sized against the subject being turned off.

## The missing distinction

A source that is **expected** to tick and has not is **stale**. A source nobody expects to tick is **unenrolled** — and reporting the second as an outage manufactures a finding out of a decision. The repo already had this vocabulary: a loop participant carrying a `deregister` event is not a faulty participant, it is not a participant.

## The fix

The subject workflow's live `.state` is now an input to the verdict. Three outcomes where there were two:

| state | exit | surface |
|---|---|---|
| `alive` | 0 | as before |
| `paused` | 0 | `::warning::` on **every** run + a fifth `outcome` value on the liveness ledger |
| `stale` | 1 | **unchanged** — this is still the alarm |

### Why the pause branch is not the vacuity class

A pause branch is a silence branch, and a silence branch in a monitor is one refactor from being decoration. Three properties bound it, each pinned by a falsifier and each **mutation-checked**:

1. **Derived from the live API**, never a repo-side flag — nobody can mute the alarm by editing a file, and re-enabling the workflow re-arms it with no code change at all.
2. **Freshness wins** — a fresh source is `alive` whatever the subject's state, so `paused` is reachable *only* when nothing ticked anyway. It changes how silence is **reported**, never whether a tick was **seen**.
3. **Unrecognised state fails closed** — a state string the module does not know is treated as `active`. `subjectIsUnenrolled(s) => s !== "active"` is the tempting simplification and it is a back door: a typo, a truncated response or a state GitHub invents next year would all read as "disabled".

A **watchdog fault** (evidence present, timestamps unparseable) stays `stale` even under a disabled subject — the one state in which nobody is checking the parser must not also be the state in which its failure is silent.

### What it still cannot tell apart, said out loud

With the subject off and every other source silent, nothing here can separate *"that source was paused too"* from *"that source died"*. So the stale sources are **named** under a `paused` outcome instead of being folded into either reading. A reader gets "nobody is currently watching for these" — true — rather than "all well" or "they are dead", each of which would be a guess wearing a verdict's clothes.

## Two things the comment storm exposed

- **A 6-hour re-notify floor** on the tracking issue. A level-triggered alarm needs a floor for the same reason it needs a threshold: its job is to be noticed once and stay findable, not repeated until it is filtered. A suppressed reminder prints why (`::notice::`), so it is never a silent skip; the run stays red and the verdict stays on the run summary.
- **The issue lookup moved off `gh issue list` (GraphQL) to REST.** This call runs every fifteen minutes, unattended, forever — exactly the case `rest-is-the-default-transport-graphql-is-the-contested-budget` governs.

## Ledger consistency

The recorder threads the same state through `verdictFromInputs`, so the ledger and the run annotation cannot disagree about a single run. A ledger saying `not-alive` where the run summary says `paused` would be worse than no ledger.

The schema tag stays `zeta.liveness.observation/1` on a **measured** basis rather than a convention: the only consumer of `outcome` validates it as a string and prints it verbatim, so there is no exhaustive switch a fifth value could fall through. The shape did not change; a label gained a member. Bumping to `/2` would have told every reader to expect a different record and handed them the same one.
