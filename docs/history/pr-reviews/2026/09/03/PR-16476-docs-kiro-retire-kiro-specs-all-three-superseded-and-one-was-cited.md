## The default answer was "delete all three" — and it was wrong for one

**`ferry-throttler-priority-lanes/design.md` is cited by two research docs** as the design a math handoff was performed against (`…math-handoff.md` in 3 places, `…math-team-REPORT.md`). Deleting it dangles a citation to the very document a review was run on.

**That isn't hypothetical.** `docs/DECISIONS/2026-06-15-zero-downtime-id-rotation…:108` already points at `.kiro/specs/zero-downtime-id-rotation/`, **which does not exist** — a previous `.kiro` removal left exactly this defect, and it's still there.

## Three dispositions, not one

- **MERGED** — `ferry-throttler-priority-lanes` → `docs/design/2026-06-11-ferry-throttler-priority-lanes/`, both citing docs repointed. This is the *"merging them"* half: content leaves the tool-specific dir and lands where its citations can reach it.
- **REMOVED** — `unified-loop-service`: fully shipped, cited by nothing.
- **DROP** — `forge-host-adapter`: fully shipped, cited by nothing, and **untracked**, so there is nothing in the repo to remove. It exists only as loose files in the shared checkout; `rm -rf` there retires it and this commit records why.

**Supersedes #16472**, which committed the two untracked specs *into* `.kiro/` — the wrong shape once the question is "get rid of .kiro", and wrong regardless for documents whose subject shipped months ago. Closed rather than merged.
