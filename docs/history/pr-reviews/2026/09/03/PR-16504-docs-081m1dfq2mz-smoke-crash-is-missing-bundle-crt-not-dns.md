# Summary

#16501's dump worked on live-k3d [33751425785](https://github.com/Lucent-Financial-Group/Zeta/actions/runs/33751425785) job `100636645454`. The agent CrashLoop is **not** the included-class DNS timeout.

```
could not parse trust bundle: open /run/spire/bundle/bundle.crt: no such file or directory
```

`spire-server-0` was 0/2 Pending. PVC `spire-data-spire-server-0` was still `ExternalProvisioning` on `rancher.io/local-path`. The server writes `bundle.crt` at runtime. No server → empty mount → agent CrashLoop. Selector is `app.kubernetes.io/name=agent` (DaemonSet name is still `spire-agent`).

The included dump (33429761222) had server + CSI already Running and then `lookup spire-server.spire on 10.43.0.10:53: i/o timeout`. Smoke cannot see that class while the PVC is still provisioning. Do not collapse the two. Do not re-lift `--scope included`. Do not invent Cilium helm values.

This PR records that measurement and makes the dump print PVC + ConfigMaps, and `cilium-dbg service list` without swallowing exec failure (the grepped dump printed nothing and looked like KPR had no kube-dns; kube-dns ClusterIP was `10.43.0.10` with endpoints `10.143.0.41`).
