## Description

**The one laggard keeping `live kind included` red since #16279, read from the dump instead of guessed.**

`seaweedfs`: `ComparisonError … parse error at seaweedfs/templates/shared/security-configmap.yaml:21: function "fromToml" not defined`. `fromToml` is a **Helm 4** function. The kind lane bootstraps argo-cd **7.7.10 = v2.13.2 = Helm 3**, renders seaweedfs, and **caches** the failure (`Manifest generation error (cached)`). The self-managed Application upgrades to 10.7.0 = v3.5.2 (**Helm 4 only** — `helm4_version=4.2.1`, `cmd.go`: *"We now support v4 only"*), but a cached render error isn't cleared by swapping the binary.

**The chain, every link measured** (runs 33713945771 / 33736439359): seaweedfs `sync=Unknown health=Healthy` **vacuously** (zero applied resources) → no `blob-store-seaweedfs-all-in-one` Service → kube-dns `no such host` ×700 → mimir's startup `sanity-check` fails → every mimir module *"depends on module sanity-check"* → 9–12 restarts each. Loki logged **zero** S3 lines — it never tried — so its Healthy was as vacuous as seaweedfs's.

**Why 2026-09-01:** #16279 bumped seaweedfs 4.33→4.45 for a HIGH CVE. The k3s bootstrap moved to 10.6.0 that day; the kind lane's bootstrap in `use-cases.ts` (two profiles) was left on 7.7.10. Both now **10.7.0**, and the k3s manifest 10.6.0→10.7.0 for parity so bootstrap == self-management and no mid-run self-upgrade happens at all.

**Not an engine question.** Flux supports Helm 4 (helm-controller on `helm/v4 v4.2.2`; flux2 ≥ v2.9.4) — and so does ArgoCD as of v3.5.x, which is what's already pinned. The defect was one bootstrap pin.

**Second, independent blocker — recorded, not fixed here:** `mimir-kafka-0` Pending, `0/1 nodes are available: 1 Insufficient cpu` (kafka requests `cpu: 1` at the metal rung; over the runner budget — the acknowledged rung gap). mimir-distributed 6.2.0 has ingest-storage on by default, so no Kafka = no write path even once seaweedfs renders. That's a rung/capacity decision, next on this lane.

Also noted: 17× `.status.terminatingReplicas: field not declared in schema` — ArgoCD's SSA differ vs a k8s-1.33+ status field; it's what flips sync to `Unknown` broadly late in the run.

Work item `081M1FG1RCW` updated: the **auth finding stands** (4.33 rendered zero identities, fail-open; 4.45 fail-closed) and its exit condition still holds; what's retracted is *auth becoming real is why mimir went Degraded*. The store was never applied.
