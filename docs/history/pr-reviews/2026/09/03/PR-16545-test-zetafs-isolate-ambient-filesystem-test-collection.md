## Description

## Summary

This is a **test-isolation hypothesis**, not a production ZetaFs repair. It
places all six F# test modules that call `FileSystem.register` in one
non-parallel xUnit collection. Production `Journaled.freeze`, content-ID, and
durability code are unchanged.

The change responds to a Windows 2025 and Windows 11 ARM failure of:

> `Journaled freeze ContentId matches the mutbuf snapshot, not a later pwrite`

The reported behavior could reflect interference among tests sharing the
ambient `AsyncLocal` provider. The failure was not reproduced locally, so the
collection is explicitly a bounded isolation control. It must not be treated as
proof of the snapshot bug’s root cause.
