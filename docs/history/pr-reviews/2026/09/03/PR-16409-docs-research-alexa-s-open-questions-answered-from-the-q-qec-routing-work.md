## Q1 — coded vs uncoded: answered, and stronger than asked

Not a yes/no. The N=8 adinkra category was **exhaustively enumerated**, so the trade is a
**monotone curve**:

| `dim C` | CSS code | `k` | `d` |
|---|---|---|---|
| **0 — UNCODED, full 8-cube** | **[[8,8,1]]** | 8 | **1 — corrects nothing** |
| 1–3 | [[8,6,2]], [[8,4,2]], [[8,2,2]] | 6→2 | 2 |
| **4 — self-dual, Construction A → E8** | **[[8,0,4]]** | **0** | 4 |

Adding code drops `k` and raises `d`. The uncoded end has every degree of freedom and **no
protection**; the fully-coded end has maximal protection and **encodes nothing**.

> **"Homoiconicity is bought by declining the quotient, and the quotient is where the protection
> lives."**

That's Aaron's coded-breaks-homoiconic claim **confirmed in-tree with the price named: `d = 1`.**

**Honest gap:** it was run against `[[n,k,d]]`, **not** against a co-ownership criterion — because
co-ownership has no operational definition in-tree. Alexa's version is still open, blocked on her
own point: define the term first.

## Q2 — graph topology: family-relative, which dissolves the question

**Coded:** not free — doubly-even code ↔ adinkra (Doran–Faux–Gates–Hübsch–Iga–Landweber) determines
it. **Uncoded:** primitive by construction, since the quotient is declined so there's nothing to
derive from. **Parity alone does not generate the graph; the code does.**

## Q3 — the Meno bridge: formal one way, and the two routes land elsewhere

Construction A is one line: `L_A(C) = {x ∈ ℤ⁸ : x mod 2 ∈ C}`. What reframes it is that the routes
**do not produce the same object** — coded → E8 **lattice** (240 minimal vectors, proven in
`E8Lattice.fs`); uncoded bivector/spinor tower → E8 **Lie algebra** (`120 + 128 = 248`).
`CliffordPeriodicity.fs` says the bivector route *"quotients nothing"* outright. Carries the
on-record correction that the coded route yields the **lattice**, not the group.

## Q4 — the ISA binary primitive: this is where the chain is wrong

`ZSetISA.qs` answers directly — **the ISA does not have *a* binary primitive, it has two groups:**

| operator | Q# | group |
|---|---|---|
| `EMIT(k,θ)` / `RETRACT` | `Ry(θ)` / `Adjoint Emit` | **U(1)** — continuous |
| `BRANCH` / `JOIN` | `H` / `CNOT` | **ℤ/2ℤ** — order 2 |

So *"ISA bit = adinkra edge parity = qubit basis"* holds for BRANCH/JOIN and **fails for
EMIT/RETRACT**. The vertical-coherence claim isn't supported as stated.

**The better half is supported:** `EMIT ∘ RETRACT = I` *by construction*, since `Retract` is
literally `Adjoint Emit`. **The DBSP retraction and the quantum adjoint are the same operation
here** — structural, not asserted, and it needs no ℤ/2ℤ story.

## The correction the chain most needs

It closes with *"the physics and the architecture agree."* The tree refuses that **in its own
source** — `CssStabilizerCodes.qs`: *"the simulator is a program, not a device. **Nothing in Zeta
holds an encoded qubit**, and no golden vector in this directory should ever be read as evidence
that one does."*

Measured execution status, since "an ISA that supports both" deserves precision:
`generate-qsharp-golden.py` **does** run the Q# through Microsoft QDK for unitaries — but it's an
**offline generator rerun by hand**. **CI runs neither compiler nor simulator**:
`qsharp-golden.test.ts` checks committed JSON, and `zset-isa.test.ts` / `css-stabilizer.test.ts`
**read the `.qs` files as text and parse them with string/regex matching.**

Written, simulator-checked once per surface change, text-checked in CI. A real artifact and a real
byte-lock — **not a physical result**, and that gap is exactly where a chain of confident review
steps can quietly promote one into the other.
