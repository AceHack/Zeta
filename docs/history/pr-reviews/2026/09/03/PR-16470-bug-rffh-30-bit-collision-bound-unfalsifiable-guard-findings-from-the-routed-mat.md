## Description

Aaron routed Lumen's CRDT/Bayesian work to the math team. Soraya's adversarial review returned two findings carrying P0-shaped language; both are filed as work items here. I re-checked the two load-bearing facts myself rather than relaying them on trust.

## S1 — RFFH factor IDs (P1)

Two corrections **in opposite directions** to the "nice-to-have" framing:

**Better than claimed:** not silent corruption. `ReferenceFrameFactorHeterarchy.fs:595-601` detects the collision and **refuses** the evidence. Availability defect, not a wrong posterior — hence P1, not P0.

**Worse than claimed:** one message consumes **one** 30-bit `baseId` (the `<<<1`/`|||1` split is derived, not entropy), so the population is 2^30. **1% collision at 4,646 messages**, 0.1% at 1,466 — roughly **8x tighter** than the 32k framing, and an ordinary workload.

**And the primary defect is neither:** `RFFH-FACTOR-ID-COLLISION` occurs **exactly once in the tree — the line that raises it.** I re-counted: 1. No test, no caller, no doc, and reaching it needs a 30-bit SHA-256 near-collision no unit test can brute-force. A guard that cannot be shown to fire, with nothing checking the refusal *preserves* the evidence.

**Route:** widen to 64 bits, parameterize the width, FsCheck property at 8–12 bits asserting refuse-**and**-preserve. Explicitly **not** Z3/TLA+ — the bound is closed-form; a model checker costs human-weeks and buys nothing.

## S2 — witness independence, refuted as stated

Of 14 "witness groups": **5 cross-oracle, 8 F#-only self-reports** against string literals, 1 mutant check. The Python oracle *is* genuinely independent (joint precision matrix + Gauss-Jordan — a different algorithm). But the coupling-sign mutant's 4 disagreements are **all in means, none in variances**, `|d| = 0` exactly — and that zero is **structural**: a sign flip is a similarity transform by `diag(1,-1,1,-1)`, which leaves the covariance diagonal invariant. **1 of 14 groups carries the detection load.** The count is printed, never pinned (`> 0`).

## Recorded, not filed

**The review also corrected my own prompt:** I asked for a double-apply idempotency test on "absorbed exactly once" — that would have **pinned a bug**, since two observations of the same value *are* two observations. MLBNN-41 already tests the real (cross-layer) claim correctly.
