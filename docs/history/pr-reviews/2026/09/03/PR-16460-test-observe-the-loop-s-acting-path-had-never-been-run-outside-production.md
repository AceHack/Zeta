## Description

# The loop's acting path had never been run outside production

## The gap

`loop-resilience-probe.ts` drives the real loop under injected failure, and all ten of its scenarios
pass `--dry-run`. That is the **right** contract for a chaos harness — a probe that could push or
merge would become the incident it is testing for — but it leaves the half of the loop that actually
does something entirely unexercised:

```
observe → choose → EXECUTE → sink → commit → PUSH
```

Nothing had ever run that. The unit tests inject a fake sink; the resilience probe declines to act;
and the only thing that had ever exercised a real acting tick was **production**.

## The inverse contract, and how it is enforced

`loop-acting-probe.ts` is the resilience probe's opposite: it **executes**, deliberately, with no
`--dry-run`. The safety property is not _"does nothing"_ but _"does it somewhere that cannot
matter"_ — it builds its own bare repository in a temp directory, clones it, and points the loop's
`cwd` and `--repo-root` at that clone.

And `assertDisposable` **refuses** to run against a checkout whose `origin` is not under the temp
root this process created. _"Don't point this at the real repo"_ is a comment; a refusal that reads
the remote and compares it to a path minted this run is a check.

## What it asserts, and why that is stronger than the logs

Not what the loop _said_ — what reached **another repository**. A tick can print every expected line
and push nothing, so each scenario declares `expectEventOnOrigin` and the probe inspects the bare
origin's `main` afterwards.

| scenario           | outcome                                                                              |
| ------------------ | ------------------------------------------------------------------------------------ |
| promoted lane acts | the event is on `origin/main`, not merely committed locally                          |
| unsoaked lane      | stays in **shadow** and still **records** — dispatch is withheld, observation is not |
| e-stop raised      | **nothing** executed, **nothing** pushed                                             |

That third one is the reason the probe exists. The resilience probe can only show the e-stop
stopping a _dry_ tick — where nothing would have been pushed anyway. This shows it stopping a tick
that otherwise **would have pushed**, which is the claim an operator actually cares about.

**3/3 with the oracle, and 3/3 again with `local-llm:qwen2.5:0.5b` choosing every tick.**

## The falsifier

With the halt guard defeated (`if (false && halt.halted && …)`), the probe **exits 1** and reports:

```
FAIL  the e-stop stops an ACTING tick, not just a dry one
      !! must not print: [execute] OK
      !! an event reached origin/main despite the gate: events/080d0331b78f3010a0130008a6a8f148.json
```

Note _how_ it caught it — by finding an event on the remote, not by a missing log line.

## A defect in my own guard, found by its own test

The first `assertDisposable` compared paths with

```ts
resolve(origin).toLowerCase().startsWith(resolve(root).toLowerCase());
```

which accepts `/tmp/zeta-acting-XYZ-evil` for the root `/tmp/zeta-acting-XYZ` — the classic
path-prefix hole. Here it would mean **pushing into a repository the probe did not create**.

It was caught by the test written for exactly that case, in the guard whose entire job is to be the
last line of defence. Now a containment check: `relative(root, origin)` must neither start with `..`
nor be absolute.

The accepting case is asserted too — a guard that refused everything would pass the refusal test and
render the probe useless.
