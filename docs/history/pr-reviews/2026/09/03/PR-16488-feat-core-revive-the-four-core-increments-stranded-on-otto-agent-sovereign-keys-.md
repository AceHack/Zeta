## What had to change to fit current main

**Increment 3 (delta log):**
- Main had since bound the filesystem door at construction (`fsDoor`), moved to `ConfigureAwait(false)` on the pooled `ValueTask` writes, and disposed the boat stream in `try/finally` so a crash-mid-write faults the boat. The rollover is written on top of all three rather than the branch's older shape.
- Segment discovery uses a `*.segment` **suffix** glob and checks the `delta-` prefix itself — the in-memory test filesystem's `GetFiles` matches suffixes only, so the branch's `delta-*.segment` glob would have found nothing under the crash-mid-write tests.
- `Int64.TryParse` on the segment name is explicit `NumberStyles.None` / `InvariantCulture`.
- A segment leaves the in-memory list only after its unlink **succeeds**; a failed unlink is retried on the next call and rediscovered by a fresh instance (not swallowed into "gone", not rethrown into a commit that already durably succeeded — the reasoning is in the code).
- **The load-bearing one:** the erasure-classification apparatus (`ErasureClass` / `IErasureDeclaring`, PR-era after the branch) had declared this method *"Reversible because unimplemented … this declaration is what will fail when [compaction] lands."* It did. Three measured rows replace it: read surface under the default cap = **Reversible IN THE MODEL** (fibre 1 — two records never roll, and the active segment is never unlinked; the `RecoveryChannel` text says this is reversible by model size, not by design); read surface with the cap forced to one byte = **Erasing** (fibre 3, 1,584,963 ppm ≈ 1.585 bits, measured by a **new sweep row** in `Erasure.Representation.Laws.Tests.fs`); the storage medium = **Unmeasured**. `Erasure.Charge.Laws.Tests` (spine posts a *measured* zero over the default-config backend) still passes for the honest reason: that configuration never rolls in the model.
- Tests referencing the fixed `delta.segment` name were updated; six new rollover/truncation tests added (segment roster by name, boundary-exact truncation, snapshot+truncate recovery, legacy upgrade, sealed-segment corruption stays loud **and untruncated**, non-positive cap rejected).

**Increment 4 (WSet):**
- `FourCornerTrace` has grown since the branch (`appendCorrection`, `foldRecorded`, `foldWitnessed`, `inverseDelta`, internal `deltaUnconsolidated`); all **nine** ring parameters now take `#IRing<'W>`, not just the four the branch touched. Zero consumer ripple: `WSetHeat`, `BipartiteMachZehnder`, `MachZehnderWSet` and the law packs all pass `IStarRing`, which subsumes both rungs.
- **Deliberate deviation:** the branch added a new `BoolOrSemiring` type in `Semiring.fs`. Current main already ships the one `(∨,∧)` `ISemiring<bool>` in Core — `BooleanKleene` (`KleeneClosure.fs`). A second copy would be a duplicate, not a corner (`only-the-irreducible-is-primitive`), so the Rel corner instantiates over `BooleanKleene`; its docstring now names that role and keeps the GF(2)/XOR distinction apart. **No new type.**
- `WSet.Comonoid.Laws.Tests.fs` on main is a different (shorter) file than the branch's base; the Rel block (§2c) is appended to main's version, plus a ℤ-corner positive control that the split removed no capability.
- Lean: `ZSetCopyComonoid.lean` compiles unchanged against main's pinned Mathlib (`0c154d67…`, `leanprover/lean4:v4.30.0-rc1`): `lake build Lean4.ZSetCopyComonoid` → `Built … (7.3s)`, no `sorry`, nothing axiomatized. The three theorems are stated against Mathlib's `Finsupp.instCoalgebra`; coassociativity/counitality/cocommutativity are instance fields, not re-proved.
