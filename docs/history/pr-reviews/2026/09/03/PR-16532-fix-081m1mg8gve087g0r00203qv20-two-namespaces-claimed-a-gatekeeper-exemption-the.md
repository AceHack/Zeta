## Description

Half of what fails the included Synced+Healthy proof is not resources at all.

## The defect

Gatekeeper ships its own validating webhook, `check-ignore-label.gatekeeper.sh`, which refuses the label `admission.gatekeeper.sh/ignore` on any namespace outside the controller's `exemptNamespaces` set. It is not one of our ConstraintTemplates and no Constraint can switch it off — it guards the exemption mechanism itself, so a workload cannot exempt itself from policy merely by labelling its own namespace.

Three namespace manifests carried that label. One was exempt.

| namespace | manifest | in `exemptNamespaces`? |
| --- | --- | --- |
| `zeta-platform` | `applications/platform/namespace.yaml` | yes |
| `agent-memory` | `applications/agent-memory/namespace.yaml` | **no** |
| `game-hosting` | `applications/game-hosting/gmod/namespace.yaml` | **no** |

MEASURED on run 33790413535 (`main`, 2026-09-03), both non-exempt namespaces were denied on **every** sync attempt:

```
application/agent-memory  Sync operation ... failed: the namespace failed to apply, reason:
  admission webhook "check-ignore-label.gatekeeper.sh" denied the request: Only exempt
  namespace can have the admission.gatekeeper.sh/ignore label (retried 5 times).
application/gmod          ... identical ...
```

The Namespace never applies → the Application never syncs → it reads `OutOfSync`/`Missing` indefinitely. **Two Applications were permanently undeployable**, and `agent-memory is OutOfSync/Missing` is one of the two findings that failed the proof.

## Why it survived

The correspondence was asserted in a YAML **comment** — `agent-memory/namespace.yaml` said *"(matches open-policy-agent exemptions)"* — and never read from the other side. It was false when it was written. Nothing in the repo compared the two files, so the claim could stay wrong until someone deployed it, and the failure then arrived as an ArgoCD sync error a long way from the label that caused it.

## Drop the label, don't widen the exemption

Measured, not preferred:

1. **The stated reason was already covered.** Both comments said the label was so "a policy outage can't block" the workload. The Gatekeeper Application already sets `validatingWebhookFailurePolicy: Ignore` — it fails **open**, admitting cluster-wide when the engine is unreachable. Nothing about outage resilience was lost.
2. **No Constraint targets these namespaces' kinds.** All seven ConstraintTemplates in the tree (`applications/hat-system/policies/*.yaml`) match `apiGroups: ["society.zeta.io"]`, kinds `Hat` / `HatBinding`. None matches a Pod, Deployment, StatefulSet or Namespace — so the label exempted these namespaces from nothing they were subject to.
3. Adding a namespace to `exemptNamespaces` exempts it from **every** Constraint, present and future. That's a maintainer's policy call, and it isn't needed to fix this.

## The comment becomes a check

`src/Core.TypeScript/cluster/gatekeeper-ignore-label.ts` compares every `kind: Namespace` manifest against the Gatekeeper Application's exempt list. It reproduces the whole CI failure **offline, in about a second**:

```
[gatekeeper-ignore-label] 9 Namespace manifest(s); 3 carry admission.gatekeeper.sh/ignore; exemptNamespaces: 9
[gatekeeper-ignore-label]   EXEMPT      zeta-platform
[gatekeeper-ignore-label]   NOT EXEMPT  game-hosting
[gatekeeper-ignore-label]   NOT EXEMPT  agent-memory
[gatekeeper-ignore-label] 2 namespace(s) claim an exemption they do not have.   rc=1
```

Wired into `k8s-argocd-health-test.yml` as **two explicitly named steps**, because that workflow runs named test files only — its own comment warns that a new test file there is *"orphaned by default: green, passing locally, and never once executed by CI."*

### Its own vacuity guards, each with a falsifier

| guard | why |
| --- | --- |
| zero-namespace walk → **alarm** | zero findings over zero inputs is a check that did not run |
| unreadable exempt list → **reported** | `[]` would manufacture false findings; "assume exempt" would manufacture silence. Neither is a measurement |
| empty list ≠ unreadable list | tested in both directions so neither can be silently substituted |
| exempt namespace with no label → **not** a finding | the list names infra namespaces this tree never creates; refusing those would be a check about nothing |
| at least one namespace still carries the label | otherwise deleting the last one makes the tree assertion pass over an empty set forever |

**Mutation-verified 2026-09-03:** reinstating the label on `agent-memory` turns the tree assertion red (12 pass / 1 fail).

## Not fixed here

The other half of the proof's failure is CPU. `mimir-kafka-0`, `hindsight-api`, `hindsight-control-plane` and `hindsight-postgresql` are `Pending` on `Insufficient cpu` because **CI applies the committed tree and the committed tree is the `metal` rung**:

| rung | dev lane (39 apps) | budget | |
| --- | --- | --- | --- |
| `dev` | 1165m / 9164Mi | 2500m / 9216Mi | fits |
| `metal` | **6390m** / 14352Mi | 2500m / 9216Mi | does not |

Trimming individual apps cannot close a 2.5× gap. `argocd-health-test.ts:973` already names the real blocker — *"one committed tree, two substrates, no override point"* — and `--resource-profile dev --apply` rewrites the working tree while ArgoCD syncs the committed tree at `--git-ref`. That override point is the next change.
