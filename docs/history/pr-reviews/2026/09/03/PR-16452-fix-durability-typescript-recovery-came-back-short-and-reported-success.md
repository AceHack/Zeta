## Description

F# ships **four** durable `IDeltaLog` backends. TypeScript shipped one, and it was in-memory. So with the durable snapshot store in place, `RecoverableSpine.recover` restored the snapshot and then replayed a tail that had **died with the process**.

It did not throw. It did not warn. It returned a spine missing every commit made since the last snapshot. At a cadence of 64, a crash costs up to 63 committed deltas and **reports success** — which is why *"durability is missing"* understates it. A missing feature announces itself; a recovery path that comes back short does not. There is a test named for exactly that, asserting the old behaviour, so the defect is on the record and not only in a commit message.

## The format is F#'s, deliberately

`%020d.delta`, one file per entry, the whole entry as canonical CBOR through the four-language-locked `DeltaLogEntry` codec, temp+rename appends, high-water recovered from the filenames, truncate as an unlink. A TypeScript-shaped format would have been easier and would have left the two runtimes unable to read each other.

## The byte-lock was green over a function nothing shipped

`entryToTagged` — the encoder those vectors lock — **lived inside the test file**. So the lock proved TypeScript *can* produce the canonical frame while nothing in `durability/` *could*.

It is now `entry-codec.ts`, imported by the test. And it gained the half it never had: a **decoder**. Every prior assertion went encode → hex, or hex → decode → **re-encode** → hex — both directions through the *encoder* — so a decoder could have been absent or wrong and the vectors stayed green.

## The crossing the vectors do not cover

Frame parity is a codec treaty. It says nothing about the **directory**: filename, padding, the exclusive replay boundary, high-water recovery. Two implementations can agree on every byte of every frame and still be unable to read each other's log.

The fixture records what the real TypeScript writer wrote, verbatim, as hex-in-JSON — the frames are CBOR, `no-binary-in-proof-lineage` keeps binary out, and that rule's enforcer is scoped to `src/wasm-dla/bytelock/`, so a binary fixture here would be **unaudited as well as forbidden**. The F# test materialises it and replays with the real F# `DiskDeltaLog`.

## Mutation matrix — mutate the TypeScript *writer*, ask whether F# notices

| mutant | F# crossing |
|---|---|
| weights written as magnitudes (sign dropped) | **killed** |
| captured metadata dropped | **killed** |
| framed seq off by one from the filename | **killed** |
| entry files use a different extension | **killed** |
| filename padded to 19 digits | survived |
| delta keys sorted case-insensitively | survived |

Both survivors were predicted, and both are **owned by the check that should own them** — verified by running that check under the mutant, not asserted:

- **19-digit padding** — F# recovers the sequence with `Int64.TryParse`, so any width parses. Padding buys *lexical* ordering and both sides sort numerically, so it genuinely is not part of the crossing contract. Killed by the TypeScript test that owns it.
- **case-insensitive collation** — the frame's key order changes, but a decoded ZSet is order-independent, so the crossing cannot see it. Killed by the byte-lock (`captured_ordinal`), which is where a canonical-order violation belongs.

**A survivor at one boundary is a gap unless another boundary owns it.**

## A test that passed for the wrong reason

The first version of *"the disk log does not lose it"* paired a snapshot store whose manifest said seq 1 with a brand-new log, and the commit vanished — `recover` replays the log **past** the snapshot's sequence, so a snapshot ahead of the log masks the whole log. F#'s `RecoverAsync` does the same. Pinned as its own test rather than guarded: quietly diverging from F# would break the parity these two implementations exist to hold.
