## Description

`codegen-executor.ts` merged a `merge-pr-N` item with `gh pr merge --squash --auto --delete-branch` — the safe path, because `gh` goes through the forge, so branch protection, required checks and required reviews all apply.

**When `gh` was absent from PATH** (`errCode === "ENOENT"`) it fell back to `mergeViaGit`:

```
git fetch origin pull/N/head:pr-N
git checkout main && git pull --ff-only
git merge --no-ff pr-N -m "..."
git push origin main
```

That bypasses the pull request entirely — no required checks, no required reviews, no unresolved-thread check, no merge queue. **Its trigger was the tool being missing**, so the loop merged precisely when it had lost the ability to ask whether merging was allowed.

That is the exact inverse of the discipline the control-plane halt and the promotion gate are built on: *"could not tell" is not permission.* Branch protection on `main` would very likely have rejected the push — but that is a constraint enforced somewhere else that this code does not check, which is the shape this repo names as the main obstacle to human–AI trust. And `gh` is not on the Bash PATH on the machine this was found on, so the trigger is not exotic.

## Two dead capabilities this also connects

| capability | callers before |
|---|---|
| `ForgeHost.getPrGateState(n)` — the forge's own answer: gate, checks, required checks, **unresolved review threads** | **zero** outside `forge-host/` |
| `applyTransition` — the `Backlog → … → Approved → Merged` machine, verified against `src/Core/WorkflowEngine.fs` by a **264-vector treaty** | **three**: its own test, the transcript generator, the treaty test |

The loop's merge condition came from `listOpenPullRequests`' `mergeStateStatus === "clean"`, which speaks to **mergeability** and says nothing about whether reviewers' threads were ever answered. **A PR can be perfectly clean with an unanswered review thread.** This PR gives the verified lifecycle machine its first production caller.

## The fix

`observe/merge-receipt.ts`:

- `lifecycleFromGateState` **walks the real machine** — `PrOpen` →`RequestReview`→ `InReview`, then either `ReceiveRevisionRequest` (threads outstanding) or `ResolveAllThreads` (→ `Approved`). It does not encode "you may merge when X"; the rule stays where the F# oracle checks it.
- `mergePermitted` **asks** `applyTransition` whether `Merge` is legal, rather than testing `state.tag === "Approved"` locally.
- `authorizeMerge` treats **no reader** and **a failed read** as refusals, and takes the receipt *before* the dry-run report — so a dry run says whether the merge would be **authorised**, not merely attempted.

`codegen-executor.ts`: the `ENOENT` branch refuses with the reason. **`mergeViaGit` is deleted, not merely disconnected** — leaving a working gate-bypass unreachable is one edit away from being re-wired, which is the dead-control shape this repo keeps finding.

`run-loop-real.ts` builds the reader from the `ForgeHost` it already resolved and leaves it **undefined when no forge resolved**, which `authorizeMerge` refuses.
