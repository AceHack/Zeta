## Description

Review of Lumen's #16499. **The adapter is correct and the canonical order is real** — this is a gap in what the control can *falsify*, not a defect in the code.

## What the six-permutation control does and does not pin

It is not vacuous: reduce `canonicalState` to the identity and it produces six distinct receipts and goes red. But every bit of that discriminating power comes from `orderedFingerprints`, which is metadata about the arrival list.

Measured 2026-09-03 on that control's own catalogue, with canonicalisation removed:

| quantity | distinct across the 6 permutations |
| --- | --- |
| receipts | 6 — the control fails, correctly |
| **posteriors** | **1 — byte-identical** |

The declared precisions (1, 0.25, 2/3) sum to the same float64 in every order. So the control pins canonical **reporting** and is silent about canonical **numerics** — and the second is the property this substrate actually needs: *two agents that saw the same evidence in different orders must reach the same conclusion, not merely print the same provenance list.*

## The added control

A catalogue where the fold genuinely is order-sensitive — precisions `1e16, 1, 1`, where the unit terms vanish into the huge one unless summed with each other first:

| canonicalisation | distinct posteriors |
| --- | --- |
| removed | **2** — `9.999999999999997e-17` and `1e-16` |
| present | 1 |

Two nodes, one evidence set, different conclusions.

**Mutation-verified:** the new test is independently red under the identity-`canonicalState` mutant, on the posterior alone (`3 pass / 2 fail`; both the original control and the new one go red, and the new one's failure is a posterior mismatch).

## What is *not* doing the work

Kahan compensation was **on** in the divergent run. It buys accuracy; it does not buy associativity, because compensated summation is still a left fold. The load-bearing mechanism is the **canonical order** — the same content-addressed union that serves as the state merge — and the new control is what says so.

Crediting Kahan for order-independence would be the same defect shape the `MinimalBnn.update` finding already surfaced one layer down: an order-dependent fold hidden by a catalogue that could not expose it. (The contract doc itself was careful here — it says "in that exact vector order" and names the union canonicalizer; the mis-attribution was in the summary, not the spec.)

Posteriors are compared as **bit patterns**, not with a tolerance. A tolerance would accept exactly the divergence being tested — the two values differ in the last three bits — and approximate agreement between replicas is not agreement, it is a disagreement nobody has measured yet.
