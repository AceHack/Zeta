## Summary

SPEC, not code. Answers Aaron's question on the Fable 5.1 math team: *converged loopy graphs are labeled means-only — can research make this more accurate?* The answer is exact, not "more accurate": for the declared linear-Gaussian multilayer model, conditioning on a **feedback vertex set** of size `k` recovers exact means **and variances** with `k + 1` runs of the tree solver `FactorGraph.runToFixpoint` already has plus a `k × k` dense solve (Liu, Chandrasekaran, Anandkumar, Willsky 2012, Theorem 1 — page-checked, quoted). Cost `O(k² n)`. Every graph the suite runs has `k ≤ 2`.

Files:

- `docs/research/2026-09-03-loopy-variance-correction-spec-feedback-message-passing-over-the-factor-graph-fvs.md` — the spec: the gap with MLBNN-42/46's numbers, 12 candidate methods ranked, the chosen method stated in the repo's own functions, the `ExactLoopyViaFvs of k` DU extension, eight falsifiers each with its pinned mutation, the order-independence test, cost, coordination with Lumen's lanes.
- `docs/PRIOR-ART-LIST.md` — new section indexing the cutset / FVS lineage (Pearl 1986 → Weiss–Freeman → Malioutov–Johnson–Willsky → Sudderth–Wainwright–Willsky → Welling–Teh → Liu et al. 2012 → Giscard et al. 2016 → Li–Su–Wu 2019 → 2021/2023/2026 frontier), each row marked page- or abstract-checked. The list had no Weiss–Freeman or Willsky rows before.

## Two findings worth reading even if the spec is rejected

1. **The evidence fold is arrival-ordered today** (`MinimalBnn.update` multiplies likelihoods in receive order; floating-point addition is not associative). MLBNN-42 uses four identical observations, so no test can see it. The invariant requires the shared query to run on a canonically-ordered fold of the evidence set (§7.2); F5 is the falsifier and carries its own negative control. Ordinary omission, reported as a defect.
2. **A cancellation-induced zero in `J`** for the MLBNN-42 model (`J₀₂ = J₁₂ = 0` because `1/v₂ = 1/v₃`) would make the moral-graph FVS 1 instead of 2. The spec computes the FVS from the declared topology and refuses to exploit a floating-point zero (numerology rule).
