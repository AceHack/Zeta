## Description

`lint (actionlint)` has been red on `main`. It's mine, from #16527.

## The defect

The tracking-issue body gained the sentence *"a switched-off subject reports `paused` and never reaches this step"* — with markdown code spans, inside the `printf` **format string**, which is single-quoted.

A backtick in single quotes is command-substitution syntax, so shellcheck raises SC2016 and actionlint turns that info-level finding into a failed job:

```
.github/workflows/heartbeat-liveness.yml:346:9: shellcheck reported issue in this script:
  SC2016:info:26:172: Expressions don't expand in single quotes, use double quotes for that [shellcheck]
```

Reproduced locally against the same shellcheck 0.11.0 the lane installs. One backtick pair, one failing lint job.

## The fix, and how it was verified

Removed the backticks — escaping is not available inside single quotes, so the prose says the word plainly.

**Verified by extracting every `run:` block in the file and shellchecking each — 6 blocks, clean — rather than only the one that was reported.** A fix confirmed on the single failing block would not have told me whether the file had others; that is the difference between "the reported error is gone" and "the file is clean".

A comment records why the obvious markdown spelling is not used. Without it the next person writes the backticks back, since the body *is* markdown and rendering it as code is the natural thing to want.
