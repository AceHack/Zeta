## Summary

`SimulatedBlockIo` had crash-mid-write. The file door also has corrupt-last-write and reorder. Same intercepts on the LBA door, no POSIX path.

- `ArmCorruptLastWrite(n)` XORs the last n bytes with 0xA5, commits, acks.
- `ArmReorderNextTwo` holds the first Write (Read sees zeros); the second Write commits itself then the held write. `CommitOrder` is `[second; first]`.
- Crash-mid-write still wins if both arms match.
