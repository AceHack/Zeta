## Description

## Why

Dependabot #17459 (xunit.v3 3.2.2 → 4.0.1) fails every `build-and-test` leg before a single test runs. All 7 test projects stop at:

```
microsoft.testing.platform.msbuild/2.4.0/.../Microsoft.Testing.Platform.MSBuild.targets(355,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later.
```

xunit.v3 4.x ships Microsoft.Testing.Platform (MTP) v2, and MTP v2 refuses the VSTest mode of `dotnet test` on the .NET 10 SDK ([docs](https://learn.microsoft.com/dotnet/core/testing/unit-testing-with-dotnet-test#mtp-mode-of-dotnet-test)).

## What

- `global.json` opts `dotnet test` into MTP mode (`"test": { "runner": "Microsoft.Testing.Platform" }`). **This works on xunit.v3 3.2.2 too**: 3.2.2 ships MTP v1 1.9.1, and the mode needs 1.7 or later ([xunit docs](https://xunit.net/docs/getting-started/v3/microsoft-testing-platform)). So this lands on main first, and #17459 then needs only its version change. `sdk` is unchanged; `audit-dotnet-pin-parity` passes.
- Every `dotnet test` call site now uses the MTP argument form:
  - `gate.yml`: `dotnet test --solution Zeta.sln -c Release --no-build --verbosity normal -- --long-running 300 --timeout 20m`
  - `low-memory.yml`: `--project tests/Core.CSharp.Tests/...`
  - `preflight.ts`, `build-receipt-checks.json`, `runner-disk.ts`, and the onboarding docs (CLAUDE/AGENTS/CODEX/CURSOR/KIRO/CONTRIBUTING, PR template, `docs/FORMAL-VERIFICATION.md`, `tests/Tests.FSharp/README.md`).
- **Replacing `--blame-*`:** the hang half becomes xUnit `--long-running 300`, which reports each test still running after 300 s by name, plus MTP `--timeout 20m`, which kills the run. The slowest leg's whole Test step took about 8 minutes on run 33998492679. The crash half is **not** carried over:
  - Nothing ever uploaded the crash dump.
  - MTP mode reports each test app's exit code by name, so the `MSB4181 VSTestTask returned false` mystery that motivated `--blame-crash` cannot happen any more.
  - `print-blame-sequences.ts` is removed. Under MTP it would find no `Sequence_*.xml` and print "the host did not crash" on every crash.
  - Crash naming (CrashDump) and coverage (`profile.ts coverage` used coverlet.msbuild, which hooks the VSTest target) come back in **081M380V792087G0R001PR993V**. Their MTP extensions have to match xunit's MTP major. Adding them now would also change the test lock files, which would conflict with #17459.
- `fsharp-mutation-probe.ts`:
  - It now runs a **baseline** on the unmutated file first. Under MTP a filter that matches no tests exits 8, and without the baseline every mutant would count as KILLED.
  - VSTest `--filter` becomes xUnit `--filter-method`. The legacy `FullyQualifiedName~X` still works and means `*X*`. Any other VSTest expression is refused. The new test file pins this translation.
  - Build and test are now separate steps. MTP-mode `dotnet test` passes `-m:1` through to the test app, which exits 5 (measured).
- Side effect: the Windows-only `Catastrophic failure ... Test process did not return valid JSON` flake came from xunit.runner.visualstudio parsing the stdout of sibling test processes. MTP runs each test app directly over a pipe, so that code path is no longer used.
