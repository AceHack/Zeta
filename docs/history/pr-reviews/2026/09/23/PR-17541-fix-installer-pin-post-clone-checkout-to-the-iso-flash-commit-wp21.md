## Description

## Summary

`zeta-install.sh` cloned `$REPO_URL` with **no ref**, so the installed system was always built from the remote's default-branch HEAD at *install* time — never the commit the ISO (or a zflash-prepared medium) was actually built from and tested against.

Measured consequences:
- A PR's NixOS-module changes were unprovable on the real install path before merge (run 35738858328 built `claude/wp11-k3s-diagnostics` but the installed disk ran `main`'s copy of `zeta-first-boot-k3s-verify.nix`).
- In the field, a USB flashed on day X installs whatever `main` is on day Y.

## What changed

1. **Embed the commit at ISO build time.** `full-ai-cluster/flake.nix` passes `self` into `mkSystem`'s `specialArgs`; the installer `configuration.nix` writes `/etc/zeta-iso-provenance` (`ZETA_ISO_COMMIT=${self.rev or "unknown"}`) — a standard flake attribute, no impure env lookup. `"unknown"` (dirty tree / hand-built ISO) is treated exactly like no pin.
2. **ESP override, same shape as the role conf.** `zeta-first-boot.sh` sources the ISO-baked file, then an ESP-written `/zeta-repo-pin` overrides it (new `repoPinCommit` field on `planFileBackedZflashImage`, `src/Core.TypeScript/zflash/lib.ts`).
3. **Checkout + fail-closed.** `zeta-install.sh`'s new `ZETA-REPO-PIN` block validates the pin (40-hex or refuse) and, after the clone, `git fetch --depth=1 origin <sha> && git checkout --detach <sha>`. A present-but-unhonourable pin (junk format or checkout failure) **aborts the install** unless `ZETA_ALLOW_REPO_DRIFT=1` is set, which proceeds on the default branch and says so loudly. Outcome is logged (`[repo-pin] outcome=...`) next to the install log and folded into the ClusterNode self-registration annotations beside the existing `flake-commit` provenance.
4. **QEMU proof.** `src/Core.TypeScript/ci/qemu-full-install-test.ts` sets the ESP pin to the workflow's own commit (`GITHUB_SHA`, falling back to `git rev-parse HEAD` locally) whenever the WP11 k3s-first-boot-verify lane runs, and asserts the installed disk's own `[repo-pin] honoured: HEAD is now <sha>` serial line matches it.

Pure decision logic (40-hex validation; fail-closed vs override) lives in `src/Core.TypeScript/installer/repo-pin.ts`, checked for shell/TS parity by `repo-pin-shell-parity.test.ts` (same extract-block-and-run-under-bash harness as `force-reformat-shell-parity.test.ts`). `injection-rail.ts` classifies the new ESP write (a commit sha is not a secret) so the constitutional-rail exhaustiveness check stays green.
