## Description

Since the quality pack began running on every PR (#17437), one rule has been
blocking correct merges. CodeQL's JavaScript extractor cannot follow this
repo's `.ts`-extension imports, so it types each imported function as
`undefined` and flags the call. Measured: `stripRemotePrefix` (2026-09-17) and
`isFullGitCommitSha` x5 on #17541 -- real exports, correct calls, all flagged.
Each finding opens review threads, `main` requires conversation resolution, and
the PR sits blocked until someone resolves them by hand. That is how #17541
waited, and it is a regression introduced by my own change.

Why this is not a suppression: on a file tsc checks, strict tsc already refuses
calling a non-callable, and tsc gates every PR. The property this rule looks for
is enforced there by a checker that resolves the imports this one cannot.

Why it is scoped so narrowly -- and this is the part that changed my plan. The
premise holds ONLY where tsc looks. `tsconfig.json` includes `**/*.ts` with no
`allowJs`, and excludes whole trees (src/wasm-dla is AssemblyScript, checked by
`asc`). About 51 plain JS files are checked by nothing but CodeQL. A repo-wide
query exclusion would have silently removed the rule from all of them, so I did
not do that.

Instead the JavaScript leg analyzes without uploading, a small filter drops that
ONE rule's results on files in tsc's own `--listFilesOnly` output -- the
compiler's answer, not a re-reading of tsconfig's globs -- and uploads the rest.
Every other rule, and this rule on every file tsc does not check, is untouched.
Other languages keep their existing upload path.

Witnessed. 8 tests. Three mutations, each caught: drop on ANY file (2 red); drop
ANY rule (1 red); decide by `.ts` extension instead of tsc membership (1 red --
that shortcut would wrongly silence the AssemblyScript tree). End-to-end against
a real tsc listing: the tsc-checked result is dropped, while the plain-JS file
and the AssemblyScript `.ts` file keep theirs.

Not covered: GitHub's separate `github-code-quality` reviewer also posted these
threads on #17541. It is not fed by this workflow's SARIF, so this change may
not silence it; if it keeps posting, that is a repository Code Quality setting.
