## Description

INVESTIGATION FIRST, because the obvious suspect was wrong.

`live kind included Synced+Healthy proof` went red on main at cb5c8f9f1 (the
rung-overrides JSON -> YAML conversion, #17567) after a green run at b4ed2800a,
and again on the next push. It was not that commit. The old JSON and the new
YAML parse to structurally identical data -- one override, `ollama/cpu-only-dev`
-- the loader change is sound, and none of the failing charts is ollama.

Measured instead: since the soak phase landed (c89c3abea, 2026-09-22) this job
has FAILED 18 times and passed 30 (5 cancelled), interleaved on PRs and main
alike -- about one run in three. Classified from each run's own verdict:

  12  soak phase: a chart left Healthy/Synced after the all-Healthy verdict --
      argo-rollouts x6, argo-workflows x2, keda, dapr, node-feature-discovery,
      forgejo; almost all CRD-owning charts
   2  startup restart count over the crash-loop threshold (spire, hindsight/mimir)
   2  soak restarts in hindsight-api
   1  mimir distributor CrashLoopBackOff
   1  lane tree over the ConfigMap budget (a since-fixed bootstrap failure)

So "main broke" was this flake landing twice in a row. Every chart involved
already runs Server-Side Apply, so it is not the classic client-side CRD drift.

WHAT THIS CHANGES. The soak verdict names which resources went OUT OF SYNC, but
for the `Synced/Progressing` flips -- argo-rollouts, the most frequent -- it named
nothing, because nothing was out of sync. The code's own comment recorded the
gap: the resource is absent "whenever the Application went unstable for a reason
`status.resources` cannot carry -- health regressed with no OutOfSync resource."
But `status.resources[]` DOES carry each resource's `health.status` and
`health.message`; it just wasn't read. `parseUnhealthyResources` reads it, the
snapshot and verdict carry it, and the soak message now appends
`{unhealthy: Deployment/x Progressing: <ArgoCD's message>}`. The next flip names
its resource and reason in the primary failure line, which is what is needed to
fix the flap rather than guess at it.

Resources ArgoCD assigns no health (CRDs, ConfigMaps, most RBAC) are skipped:
absence of a health verdict is not an unhealthy one.

Witnessed: 8 new tests; four mutations caught -- carry dropped at the verdict (1
red; that step was untested until this change), message omits the block (1),
parser reports Healthy resources (1), parser drops the message (3). Harness 187
pass, tsc 0.

NOT DONE: fixing the flap itself. This makes the flake explain itself; the fix
per chart (ignoreDifferences for controller-owned fields, a readiness or probe
change, or treating a self-healing re-sync inside the soak window differently)
waits on what the named resources turn out to be.

This replaces #17586, closed and rebuilt: running prettier over the whole
file re-wrapped hundreds of unrelated lines (main does not keep this file
prettier-clean), burying a ~160-line change in a ~530-line diff and colliding
with concurrent edits. This version carries only the change.
