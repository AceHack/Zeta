## Description

## Why

Agents kept improvising `waitjob.sh` / `watch.sh` and raw `gh api` loops for three jobs no
homemade CLI covered. These are the homemade answers, REST-first per
`.claude/rules/rest-is-the-default-transport-graphql-is-the-contested-budget.md`.

## What

All in `src/Core.TypeScript/forge-host/github/`:

| CLI | does | transport | outcomes / exit |
|---|---|---|---|
| `wait-run.ts` | wait for one run (run id, PR + workflow, or SHA + workflow), then report the conclusion plus each job's name, conclusion and failing steps | REST only; 60 s default poll, 20 s floor; back-off on 429 and 403 secondary limits | `completed` 0/1 · `timed-out` 3 · `unknown` 4 · usage 2 |
| `arm-auto-merge.ts` | arm auto-merge, then verify by reading `auto_merge` back; optional `--update-branch` | one GraphQL mutation (no REST form); pre-read, readback and update-branch are REST | `armed` 0 · `not-armed` 1 · `already-merged` 3 · `unknown` 4 · usage 2 |
| `explain-failures.ts` | why a PR / SHA / run is red: failing check, its job id (the check-run id IS the job id), failing steps, failure annotations, optional log tail (a 0-byte log is `unknown`) | REST only, bounded retries with back-off | clean 0 · failing 1 · pending-only 3 · `unknown` 4 · usage 2 |
| `github-rest-transport.ts` | token → `fetch`; no token → `gh api` argv through `io/safe-io.ts` `spawnArgv` | — | — |

A failed probe is always `unknown`, never a pass or a fail. `arm-auto-merge` never takes its
verdict from the mutation's answer: `gh pr merge --auto` exits 0 whether it armed, merged
at once, or silently failed.
