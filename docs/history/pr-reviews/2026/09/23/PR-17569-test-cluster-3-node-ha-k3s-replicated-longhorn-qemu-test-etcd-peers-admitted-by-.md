## What

**The first QEMU test of a real cluster**, plus the fix for the P1 false green in the two-server join test.

### `k3s-ha-longhorn-cluster` (new nixosTest, 3 VMs)

- **3 role=server nodes with embedded-etcd HA.** server1 founds the cluster. server2 and server3 join one at a time through the shipped `injected-server-join.nix`. The test asserts three etcd members and **one** cluster CA.
- **All three nodes Ready** on the real Cilium install from `k8s/bootstrap/cilium-install.yaml`.
- **Longhorn** at the prod chart version (1.12.1) and prod values, with **one** test-only override: `defaultReplicaCount: 3` / `defaultClassReplicaCount: 3`. Each node has its own `emptyDiskImages` block device mounted at `/var/lib/longhorn-disk1`.
- **Placement is exercised.** A PVC binds. A pod pinned to server3 writes 32 MiB plus its sha256. The volume must be `healthy` with **3 replicas on 3 distinct nodes**, read from Longhorn's Replica CRs.
- **Failover.** server3 holds a replica and is where the data was written. It gets a **hard power-cut** (`crash()`). Then the test checks:
  - `/readyz` answers on both survivors.
  - A ConfigMap **write** commits through the 2/3 etcd quorum.
  - server3 goes NotReady.
  - A pod pinned to server1 passes `sha256sum -c` while the volume reports `degraded`.

### P1 false green 081M10ZG61D087G0R001A70F0P: fixed in the product, not the harness

`k3s-server-join.nix` opened etcd 2379/2380 itself, while `k3s-server.nix` keeps them closed. CI was therefore green on a join that a real second control plane could not complete.

**Decision: server HA is supported.** `injected-server-join.nix` and `zflash --role joiner` already ship it, so the product has to be able to express it. It does that through an **explicit, default-off, source-scoped option**:

- `modules/k3s-etcd-peers.nix` (imported by `k3s-server.nix`) adds `zeta.k3sServer.etcdPeers`.
  - Default `[ ]` keeps both ports closed, so every existing host is byte-identical on this point. The eval check below asserts this for the real `nixosConfigurations.control-plane`.
  - When set, 2379/2380 are admitted **from the named peers only**: iptables `-s` ACCEPTs, or an nftables input rule on that backend. It is never a flat `allowedTCPPorts` entry.
- Evaluation now refuses a JOINING server (`serverAddr` set) when nothing admits etcd peer traffic. "Admits" means any of: the option, both ports flat, both ports on one interface, or a non-CNI trusted interface.
  - **The first draft of this refusal was vacuous.** NixOS adds `lo` to every host's `trustedInterfaces`, and the check counted it as an admitting interface. Evaluating that mutation caught it, and it is now pinned.
- `k3s-server-join.nix` uses the option instead of its own ports. It now also asserts that the rule is source-scoped and that 2379/2380 are not open as flat ports.
- `k3s-etcd-peers-model` is a new eval-only check with 13 properties. It is added to the flake-check anti-vacuity list.

### Wiring

- New `cluster-ha` job in `build-ai-cluster-iso.yml`, at the same tier as `longhorn-volume-binds`: push, schedule and workflow_dispatch. Like the rest of this workflow it is advisory, not required.
- It is a separate job so that three 4 GiB guests get a whole 16 GiB runner. It runs in parallel with `build`.
- It samples host memory every 10 s and writes the peak to the step summary.
- A new `only_cluster_ha` dispatch input runs this job alone. `build` and `build-aarch64` skip only when that input is true, so PR, push, schedule and plain dispatch runs are unchanged.
