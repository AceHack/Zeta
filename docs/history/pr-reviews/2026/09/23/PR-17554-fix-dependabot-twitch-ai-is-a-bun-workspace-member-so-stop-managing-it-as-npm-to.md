## Description

Dependabot's npm group #17456 turned 50 checks red, and every one failed at the
same step: dependency install. Not 50 regressions -- one lockfile.

`src/apps/twitch-ai` is listed under BOTH ecosystems. It is a member of the root
bun workspace (`package.json` "workspaces"), so the `bun` entry already owns it
through "/", and its versions live in the root `bun.lock`. It was ALSO listed
explicitly under `npm`. #17456 therefore bumped `twitch-ai/package.json` while
touching only a stale `twitch-ai/package-lock.json` and never `bun.lock`, and
`bun install --frozen-lockfile` refused the mismatch in every job that installs.

This recurs every week, not once: any npm-group bump that touches twitch-ai
reproduces it. And the bun group (#17454) bumps the same package.json at the
same time, so the two ecosystems also race on one file.

The npm entry's own comment defines its scope -- directories whose lockfile is
npm's or pnpm's, or that carry none. twitch-ai carries a bun.lock and is locked
by the root one, so by that rule it never belonged there. Removed, with the
reason recorded inline so it is not re-added. Checked: nothing in .github/,
tools/ or src/Core.TypeScript/ reads twitch-ai's package-lock.json or runs npm
against it.

Left alone, deliberately: the stale `twitch-ai/package-lock.json` itself.
Deleting it is probably right, but it is a separate claim from "dependabot
should not manage this directory twice", and this change should not have to
defend both.
