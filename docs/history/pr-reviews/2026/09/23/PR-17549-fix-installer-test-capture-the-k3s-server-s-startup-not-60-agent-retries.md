## Description

Run 35780287818 gave the first real diagnostics from the installed disk and
they refute the network-online theory: network-online.target is ACTIVE,
k3s.service is `activating` with its start job running, NRestarts=0. The
agent is looping on

  server is not ready: /var/lib/rancher/k3s/agent/serving-kubelet.crt:
  error loading key from /var/lib/rancher/k3s/agent/serving-kubelet.key: <nil>

which says the SERVER never finished starting and nothing about why -- the
tail of the journal is 60 copies of that one retry.

So capture what actually carries the cause: the HEAD of k3s's journal (the
server's startup), every level=fatal/error line in it, the TLS material the
agent is waiting for (present? empty?), and disk/memory, which is the other
way a k3s server stalls on a QEMU disk.
