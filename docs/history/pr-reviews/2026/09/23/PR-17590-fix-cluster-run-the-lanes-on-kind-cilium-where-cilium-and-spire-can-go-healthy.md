## Description

Second live run of the six deploying lanes (35924216557), with vault init now in
place. OpenBao went Healthy in all six -- that fix worked. Every lane-specific
chart went Healthy too. And the same two BASE charts stalled in all six for the
full 40 minutes: cilium and spire. Both are now diagnosed from the harness's own
dump rather than guessed.

cilium. Every workload was healthy -- agent DaemonSet 1/1 rolled out, operator,
relay and UI 1/1 -- yet the Application sat at Progressing. Its health message
named `cilium-ingress`, a LoadBalancer Service at `EXTERNAL-IP <pending>` for 42
minutes, beside `cilium-lb-pool: No resources found`. ArgoCD holds a
LoadBalancer with no address at Progressing forever. The k3d bring-up applies no
LB pool; the kind + Cilium bring-up applies `applyDevCiliumLbKindAlias`.

spire. spire-agent in CrashLoopBackOff, 11 restarts, identically in two lanes:
"could not open attestation stream to SPIRE server ... lookup spire-server.spire
on 10.43.0.10:53: dial udp 10.43.0.10:53: i/o timeout". The agent runs with host
networking and cannot reach a ClusterIP. That exact path was already MEASURED
broken on k3d -- ci.k3d-config.yaml records "live-k3d 33800779819: ... hostNetwork
ClusterIP TCP FAIL" -- while kind + Cilium runs spire Healthy on the SAME Cilium
values. The leading explanation is Cilium's socket load balancer not attaching
inside k3d's nested node containers: a substrate artifact, not something bare
metal (bare hosts) would have.

One hypothesis was checked and REFUTED before this change rather than shipped:
that CI k3d not passing metal's --cluster-cidr / --service-cidr (metal derives
10.143.0.0/17 and 10.99.192.0/19; k3d uses its defaults) breaks the host-to-
service path. The passing kind + Cilium profile does not use metal's CIDRs
either, so the mismatch cannot be what separates pass from fail.

So the lanes move to kind + Cilium: same shipped Cilium values, same kube-proxy
replacement, the LB-pool alias present, and a WireGuard kernel preflight (the
shipped values encrypt with WireGuard), matching live-kind-cilium-included. The
trade is the k3s distribution, stated on the workflow step. The maintainer:
"the tool used to test it matters much less as long as all the charts are
tested."

The apply-equals-assert lockstep test now covers kind/cilium too -- the pairing
that lifts `cilium` out of the exclude glob. 14 pass, tsc 0, actionlint clean.
This PR's own CI is the first kind + Cilium run of the lanes.
