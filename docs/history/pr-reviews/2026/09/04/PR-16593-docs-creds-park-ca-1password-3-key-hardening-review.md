# Summary

Park the CA / unseal / Lucent 1Password / 3-key inventory so the next pickup is git-native, not chat weather.

Aaron asked to production-harden the CA, name the unseal startup, use Lucent 1Password (maybe for unseal), inventory checked-in pubkeys, verify GPG/SSH/wallets, keep three keys per agent/human, and fold rolling into Z-sets / 0-downtime schema evolution. Follow-up: can we login to 1Password the way we login to GitHub, save it in the harness, pass it through to Kubernetes to break the injector chicken-egg, and refresh / notify before expiry?

This PR is **findings only**. It does not unseal Vault, persist a Lucent token, install a 1Password injector, mint keys, or flash USB.

Host→Secret projector **landed** as PR #16587. This branch is merged with current `main`. The 1Password-like-GitHub answer is in the design doc: yes for a Lucent **service-account** token (`ops_…`); no for `op signin` / `OP_SESSION` (official: 30 minutes of inactivity). Relogin product is an in-cluster Consent service plus a portal lease panel; SSH is break-glass. Vault unseal stays gated.
