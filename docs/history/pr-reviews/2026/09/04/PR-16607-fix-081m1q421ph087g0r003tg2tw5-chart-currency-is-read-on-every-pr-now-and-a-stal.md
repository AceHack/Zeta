## Description

Aaron 2026-09-04: *"i'd love a read check on CI for any chart that is out of date even if it's not blocking it can be in the drift checks, for any deps actually, i've asking you to update to the latest version of all our charts at least 20 times now and somehow we still have out of dates charts."*

## Why it kept happening — mechanical, not memory

1. `chart-version-refresh.yml` measures upstream **correctly**. It is not broken.
2. It runs **weekly** (Sun 17:07 UTC) + `workflow_dispatch` + a self-test limited to changes to its own files. It does **not** run on an ordinary PR, so a chart going stale produced no signal where anyone was working.
3. It is outside the required set and goes red **by design** — its own step name says *"red here is the signal"*. Its last **six** runs are all `failure`, the 2026-08-30 schedule included. That's the mechanism working, and it's indistinguishable from the mechanism being broken to anyone not opening it.
4. **Its output never lands.** `git commit`, `git push` and `create-pull-request` appear **zero** times in that workflow — the refreshed snapshot is uploaded as a 90-day *artifact* and discarded. So `published-chart-versions.json` moves only when a human or agent runs `--refresh` by hand. Which is what happened today, and is why one sweep found six charts behind at once.

Charts are also the **one dependency class with no automatic landing path**: `dependabot.yml` covers eight ecosystems (nuget, github-actions, bun, npm, cargo, gomod, uv, dotnet-sdk) and opens PRs for each. Dependabot has no Helm ecosystem that reads an ArgoCD `targetRevision`.

## What this adds

`report-chart-currency.ts --drift` — **offline** (every input is a committed snapshot), so it runs on every PR at zero network cost in `lint (bash retirement inventory + hygiene unit tests)`, a job **not** in `gate (required)`'s needs. A finding paints a red X and blocks nobody; being behind is a standing condition, not an error.

## The loudest finding isn't about any chart

Being offline means this reports what the **snapshot** knows. A clean currency report over a snapshot nobody refreshed is exactly a check that did not run wearing the shape of one that passed — which *is* finding (4). So `snapshot-stale` is an **error** at 8 days (one missed weekly cadence + a day), and its message says every number under it is a **FLOOR**.

That falsifier is mutation-checked: *"clean rows over a STALE snapshot is still an error"* goes red when the staleness branch is disabled (verified — 2 tests fail under `} else if (false) {`). A drift check a stale snapshot could satisfy would reproduce the bug it was written for.

Also registered in the job's `which step failed` aggregate — an unregistered step still goes red, but the one line a reader opens wouldn't name it.

`report-chart-currency.test.ts`: **42 pass / 0 fail**.

## Not fixed here

**Nothing lands the refreshed snapshot.** This makes staleness *visible* on every PR; it refreshes nothing. The landing path — a PR-opening step on the weekly job, same shape as the heartbeat flush — is filed as follow-up rather than smuggled into a change about reading.
