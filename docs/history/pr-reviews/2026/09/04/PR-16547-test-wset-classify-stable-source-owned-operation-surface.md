## Description

## Summary

This repair restores the WSet erasure-classification drift guard on current main without treating a compiler helper as a new thermodynamic operation. The reproducing failure was the public CLR method `<sumBy>__debug@69`; direct metadata inspection shows that it carries `System.Runtime.CompilerServices.CompilerGeneratedAttribute` and is generated for the local `bornProb` lambda rather than declared as a source-owned WSet transformation.

The law pack now defines a stable WSet surface as methods declared on `Zeta.Core.WSet` that are public, static, and not metadata-marked compiler-generated. It retains the separate `WSetHeat` profile-coverage comparison and adds an independent fixed receipt for the nine current source-owned operations: `apply`, `bornProb`, `consolidate`, `copy`, `discard`, `mapKeys`, `negate`, `plus`, and `tensor`.

## Evidence

The original focused test fails on clean current main with the unclassified generated name. The repaired focused WSet law pack passes 7/7. A deliberate temporary source mutation adding an unclassified public WSet function causes the fixed stable-surface receipt to fail; the mutation was removed before commit. The full F# suite passes on the repaired tree: 6,278 passed, 6 skipped, 0 failed. `ace/build-graph.ts derive --check` and `git diff --check` also pass.

## Scope and non-claims

The change filters only CLR methods carrying `CompilerGeneratedAttribute`; it does not use a generated-name pattern and does not classify compiler helpers as WSet operations. The finite receipt remains a drift detector for source-owned public operations, not a general physical heat claim or a universal classification theorem for arbitrary WSet specializations.
