# Summary

Aaron is going for Google's 1Password unseal automation, very close to the extraContainer loop. This is the adversarial review of that sketch, parked as findings. Init stays gated. Standing human-every-reboot is the smell. Post-init unseal on pod restart is a Helm `extraContainers` sidecar that fetches Shamir shares from Lucent **at unseal time**.

Keep: extraContainer on the existing Vault `valuesObject` (Otto/Dejan chart seam), Lucent as share store, single-node first.

Reject / rewrite: ESO copying unseal keys into etcd, rekey to threshold 1, `alpine:latest` + runtime `apk` (and the script calls `vault` which alpine does not ship), read-keys-once, 1Password Connect as first hop, health URL `http://127.0.0`, calling it HashiCorp auto-unseal.

HA Raft secondaries: out of scope. Current topology is `single-node`, raft `replicas: 1`. Joiner unseal waits on the three-node delta in `TOPOLOGY.md`.

`TOPOLOGY.md` §5 still says "Do not automate step 5 against Vault CE". The unsealer implementation slice amends that sentence in the same commit as the sidecar. This PR does not add `extraContainers`.

Metal first-boot hops (USB `tty1` login, then Lucent fetch) are named in the same review: the laptop is not the production hop.
