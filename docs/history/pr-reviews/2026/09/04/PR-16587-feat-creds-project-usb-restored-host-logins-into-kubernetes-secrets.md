# Summary

GitHub and AI logins the harness already stores (and restores from the USB encrypted blob) now also land as Kubernetes Secrets on the control plane, so future agent pods can mount what the host already has after setup.

This is **not** a Helm chart bump. Restore still writes host files; a control-plane oneshot then applies Opaque Secrets into namespace `zeta-host-creds`. External Secrets / Vault stay the later hop (Vault may be sealed at first boot; ESO's ClusterSecretStore is still commented).

Follow-up on this PR: `collectRestoredFiles` now reads each restored file in **one syscall** and classifies `ENOENT` / `EISDIR` / other from the errno. The previous `existsSync` + `lstatSync` then `readFileSync` pair was a CWE-367 check-then-use race. That is what turned `gate (required)` red (`lint (bash retirement inventory + hygiene unit tests)`, `cross-verify (check-then-use-races)`, CodeQL `js/file-system-race`).

# Spec alignment

No OpenSpec behaviour change. Worker specs already say credentials come through Kubernetes Secret or ExternalSecret later; this is the host→Secret projector those pods can consume.

Workitem: `081M1PWSF56087G0R000FDS3NY`. Design: `docs/design/2026-09-04-host-creds-as-k8s-secrets.md`.
