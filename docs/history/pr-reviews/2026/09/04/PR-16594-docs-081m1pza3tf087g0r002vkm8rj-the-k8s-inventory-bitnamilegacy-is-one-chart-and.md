## 1. `bitnamilegacy` is a gitlab problem, and only a gitlab problem

Four frozen images — `postgresql:14.8.0`, `redis:6.2.16`, `postgres-exporter`, `redis-exporter` — and **all four are pulled by one chart**. Nothing else in the tree pulls a legacy image; the single remaining `bitnami/*` image (sealed-secrets-controller) is in the **live** namespace, not the frozen one.

**The fix is structural, not incidental.** Verified by unpacking both versions and listing their vendored subcharts:

| | vendored subcharts |
| --- | --- |
| `gitlab` **8.7.0** (our pin) | includes `postgresql`, `redis`, `minio` |
| `gitlab` **10.3.1** (newest) | **none of the three** |

`helm template` at 10.3.1 refuses outright: *"external Redis became required"*, *"external PostgreSQL became required"*, *"The chart provides no longer bundled object storage solution"*. The images aren't upgraded away — the subcharts that pulled them are gone.

So it's a **wiring job**, and all three prerequisites already have candidates in the tree: `cloudnativepg` (operator installed, no `Cluster` CR yet), `redis`/valkey, `seaweedfs`. Not a coincidence — the sync-wave graph already records cloudnativepg as *"the shared prerequisite of the gitlab and temporal bumps"*.

**Temporal is the same shape and lower risk:** 0.59.0 ships `cassandra`, `elasticsearch`, `grafana`, `prometheus`; 1.6.0 ships none. We **already refuse** the bundled datastore — the Application's header calls the bundled cassandra *"0.14.3 from the ARCHIVED helm/incubator repo … a durable-execution engine on a store that loses its data on restart"*. The bump deletes a subchart the manifest already declines.

**Headscale has no upgrade path:** newest published version, upstream silent **560 days**. `DORMANT`, not behind — exactly the trap `CHART-CURRENCY.md` names. Replace or retire, not maintain.

## 2. The plan understates itself

Every one of `PLATFORM-ARCHITECTURE.md` §7's "immediate next steps" is **built** — headlamp, the Cilium LB-IPAM pool *and* L2 policy, kubevirt, cdi, the GameServer CRD, the GMod instance.

§6 still lists a `Tenant` CRD as a phase-1 *draft*, while `platform/` already ships **seven CRDs** — App, Blueprint, Deployable, GameServer, Policy, Tenant, WebApp — plus a controller, portal, gateway and default policy. **The roadmap is behind the repository**, which is the opposite of the usual failure and worth knowing before anyone plans from it.

Genuinely missing, both named in the plan: `nixos/modules/kubevirt-node.nix` (KubeVirt and CDI are installed; the host-side enablement isn't in the tree) and OpenCost (phase 3, document-only).

**A correction to my own first pass**, recorded because the method matters: I reported the GameServer CRD as NOT FOUND after grepping `game-hosting/`. It exists, under `platform/`. The grep was right and the question was wrong.

## 3. The gap that matters before hardware

The dev lane excludes **eight** Applications:

```text
cilium, cilium-lb-ipam, longhorn, ollama, vllm, gitlab, temporal, platform
```

| excluded | what it carries |
| --- | --- |
| **`platform`** | **the entire product surface** — seven CRDs, controller, portal, gateway, default policy |
| `cilium`, `cilium-lb-ipam` | the networking game/VM external ports depend on |
| `longhorn` | the storage every stateful workload binds against |
| `gitlab`, `temporal` | the two charts with pending major bumps |

Each exclusion has a recorded reason and most are plainly right — a kind node can't run Longhorn's provisioner, a `type: LoadBalancer` can't get an address. **The point isn't that they're wrong.**

The point is that *"the included proof is green"* means **the 40 Applications that can run on a runner are green**. The eight that carry the product are verified on hardware or not at all — which is what makes the hardware run worth scoping from *this* list rather than from the CI lane's. For eight Applications it is the only test that has ever run.
