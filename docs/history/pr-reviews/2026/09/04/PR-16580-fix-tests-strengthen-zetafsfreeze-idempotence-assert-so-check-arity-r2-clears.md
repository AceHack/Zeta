## Description

## What

Strengthen the idempotence assertion in
`tests/Tests.FSharp/ZetaFsFreeze.Tests.fs` (test: *POSIX freeze of the same
ContentId does not rewrite object bits*) so the `check-arity` equality audit
stops flagging line 1458 as an R2 self-comparison.

Before: `Assert.Equal(afterFirst, objectWrites().Length)` — both sides
normalize to `objectWrites().Length`, so the audit cannot see the mutation
(second freeze) that runs between the two evaluations.

After: capture `afterSecond = objectWrites().Length` and assert
`Assert.Equal(0, afterSecond - afterFirst)`. The claim — re-freezing the same
ContentId writes zero new object bits — now rides a check that can fail, and
the two operands are distinct expressions.

## Why

The defect landed on `main` via PR #16575 (which added this test file). Every
currently-open PR branch forks from that `main` and therefore inherits the
failure, turning the bundled `lint (bash retirement + hygiene)` gate red across
all of them (`arity-equality=failure`). Fixing it on `main` clears the shared
blocker for the whole open-PR queue.
