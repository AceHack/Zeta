## Description

Stacked on #16535 (the mechanism). This is the wiring — the part only CI can judge.

Aaron 2026-09-03: *"we don't have to test metal on our CI, metal is for our real hardware, dev is for testing on our github runners."* This is that, wired.

`--serve-tree <rung>` builds a copy of `full-ai-cluster/k8s` with that rung applied, serves it from an in-cluster read-only git server, and points the root Application there instead of at GitHub. The committed tree is untouched, so the hardware box keeps `metal`; nothing is pushed, so the repo doesn't grow and a fork PR works. Both `--scope included` jobs now pass `--serve-tree dev`.

## Fails closed

If the server never becomes Available the bring-up **throws**. A fallback to the committed tree would sync `metal` onto a runner-sized node, reproduce `Insufficient cpu` on `mimir-kafka-0` and three hindsight pods, and look exactly like the failure this removes — with nothing in the log saying the override had been skipped. A test asserts the throw **and** that no root Application is applied on that path.

## Ordered, asserted by index

The server is applied and waited on **before** the root Application: a root app pointed at a server that isn't yet answering fails its first sync and retries on ArgoCD's backoff, so the lane pays minutes for a race a readiness wait removes. *"Both happened"* is a weaker claim than *"in this order"*, and only the second is the property.

The wait is `condition=Available`, which the readiness probe gates on `GET /tree.git/info/refs` — so it waits for the **repository** to be servable, not for a pod to be running. A container up with an empty volume satisfies the weaker condition and hands ArgoCD a 404 that reads like a bad repoURL.

## The URL guard is widened by a literal, not a pattern

`assertGitHubRepoUrl` refuses anything that isn't `https://github.com/<owner>/<repo>`, and that refusal is load-bearing: ArgoCD clones what it's handed, so a lane that could be pointed anywhere is a lane that could be pointed at anything.

Serving in-cluster needs exactly one exception, so it gets exactly one — `LANE_TREE_REPO_URL`, compared by **equality**. A pattern like *"any http:// on .svc.cluster.local"* would have accepted every service in the cluster, including one an Application could stand up. The GitHub predicate is unchanged and still applied to the fallback URL.

**And the literal has a drift guard**, because it's two constants in two files that never read each other: `dev-cluster/lib.ts` decides what the bootstrap *accepts*, `lane-tree-source.ts` decides what it *produces*. A test pins that they're the same string; a second pins that the rendered Service name, namespace, port and path are the ones that URL resolves. **Mutation-verified:** changing the port on one side turns both red. Without it the bootstrap could end up refusing the only URL anything generates — an exception with no subject.

`--serve-tree` absent is byte-identical to before, and a test says so rather than leaving it assumed.
