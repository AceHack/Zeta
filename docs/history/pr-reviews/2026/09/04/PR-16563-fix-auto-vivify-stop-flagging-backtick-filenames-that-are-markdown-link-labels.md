## Description

## Why

The auto-vivify \`--check\` preflight reported 4 dangling references on \`main\` that were all false positives, from two distinct causes. Left unfixed, this preflight noise erodes trust in the dangling-reference gate and risks masking a real dangling ref among the phantoms.

## What changed

1. **Resolver bug (3 refs).** A design-doc citation written as `` [`foo.md`](../docs/research/foo.md) `` was double-counted: the markdown-link rule captured the authoritative (existing) target, but the backtick rule *also* captured the bare label filename `foo.md`, which resolves to a different, nonexistent directory and registered as a phantom dangling reference. `extractPointers` now skips a backtick match whose position falls inside a markdown-link label span on the same line — the link target is authoritative.

2. **Imprecise workitem prose (1 ref).** Workitem `081M1N9KE2N` referred to the healer as `healers/zetafs-virtual-path.ts`; the real file is `src/Core.TypeScript/hygiene/healers/zetafs-virtual-path.ts`. Corrected to the true repo-relative path.

## Tests

Adds two regression tests: the label-vs-target double-count case, and a control asserting standalone backtick paths (outside any link label) are still captured.
