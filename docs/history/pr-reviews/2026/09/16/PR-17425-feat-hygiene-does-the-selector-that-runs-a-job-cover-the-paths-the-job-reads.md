## Description

`audit-build-graph-completeness` already checks that every job is CLAIMED by some target.
Nothing checked whether the claiming target's SOURCES cover the paths the job's own commands
actually read. A job can be fully claimed and still be unselectable by the changes it exists
to judge.

WHAT THAT COST, measured (081M2F88XEA087G0R00056SE0V). `gate/lint-bash-retirement-inventory`
is claimed by one target, `ts:hygiene` (`src/Core.TypeScript/hygiene/**`). One of its steps
runs `lint-orphaned-doc-comments.ts src/Core.TypeScript/corporate`. The job SCANS corporate;
nothing that SELECTS it covers corporate. PR #17403 changed 17 files, all under corporate,
stranded a docstring, and that lint SKIPPED. The defect reached main and surfaced only when an
unrelated PR happened to touch `hygiene/**`.

This audit finds that gap from the workflow and the graph alone, plus four more:

  lint-yaml-k8s                   reads kubernetes-version.json; selected by **/*.yaml only
  lint-bash-retirement-inventory  reads corporate, audit, inventory; selected by hygiene only
  lint-tick-shard-relative-paths  reads its baseline .json; selected by data/** only
  build-graph-completeness        runs 12 .test.ts files none of its 4 sources name
  test-typescript-environment     reads src/Core.Python; selected by **/*.ts only

TWO CLASSES, AND ONLY ONE IS THE DEFECT. A first pass reported 11 "gaps", most of them a job
reading the `.ts` that IMPLEMENTS it -- `lint-go` reads `lint/lint-go.ts`. That is a different
question and folding it in buries the real finding. Reads are split: the first path after
`bun`/`node` is EXECUTED (tool), everything else is an ARGUMENT (subject). 17 of 28 jobs turn
out to read only their own tool and are reported as such, never as gaps.

INDIRECTION THROUGH package.json IS FOLLOWED, because that is where the real gap hid. 30 gate
steps invoke `bun run <script>`, and `hygiene:no-orphaned-doc-comments` expands to
`... src/Core.TypeScript/corporate`. A reader that stops at `bun run` sees no paths and reports
the tree clean -- this tool's own false negative, reproduced inside this tool.

ONE FALSE POSITIVE FOUND AND FIXED BEFORE SHIPPING. Judging a scanned DIRECTORY against an
extension glob said `agentic-organization/deploy` was uncovered by `**/*.yaml`, when every
yaml inside it selects the job perfectly well. Coverage is now directory-aware and bounded
(depth 3, because that tree holds its manifests one level down). 11 reported gaps became 5.

HONEST LIMITS, stated rather than discovered later: literal paths only, so a runtime-computed
path is invisible and the output is a LOWER BOUND on the gaps rather than a proof of absence;
one level of `bun run`; and a path is counted only if it exists, so a typo reads as no-path
rather than as a gap -- conservative in the under-reporting direction.

Mutation-verified in five directions:
  sibling subtree counted as covered      12 pass  2 fail
  tool/subject collapsed                  13 pass  1 fail
  bun run indirection not followed        13 pass  1 fail
  directory/extension coverage dropped    13 pass  1 fail
  leg slug mapping broken                 13 pass  1 fail
  control                                 14 pass  0 fail

DRIFT TIER and deliberately NOT in `gate-required`'s needs: it reports a number nobody has,
and promoting it to a blocker is a separate decision with a threshold nobody has calibrated.
`tsc --noEmit` rc=0 on an empty log; the four sibling hygiene checkers stay green.
