## Description

Task: `081M3B7Z38Q087G0R003F9X7HM` (follows #17695).

## The defect that remained
#17695 gave the whole disk `link_priority=-100` so `/dev/disk/by-label/ZETA_INSTALL` would go to the LBA-0 partition. Full dispatch run 36406378420 (main@88b688444e) still failed three USB lanes (UEFI keyfile restore decrypt, UEFI keyfile install-time write, WP11 phase 1) with `boot-medium=/dev/sda`, while other lanes of the same ISO reported `/dev/sda1`. So the outcome still depended on timing.

## Root cause (pinned sources: nixpkgs `c25784012c99`, systemd 260.2)
1. **Stage 1 is the systemd initrd.** `boot.initrd.systemd.enable` defaults to `true` (`nixos/modules/system/boot/systemd/initrd.nix`), and the installer does not override it. The `root=LABEL=` → `/dev/root` path, which runs `udevadm settle` before mounting, belongs to the scripted initrd only.
2. **Under the systemd initrd, iso-image.nix mounts the symlink directly**: `fileSystems."/iso".device = "/dev/disk/by-label/${volumeID}"`.
3. **The mount starts as soon as the symlink resolves to something.** `sysroot-iso.mount` is bound to that path's `.device` unit. systemd marks a devlink unit ready while it handles the uevent, if the symlink resolves to that device (`src/core/device.c`, `device_setup_devlink_unit_one` → `sd_device_new_from_devname(devlink)`). Nothing settles udev first.
4. **udevd never runs a partition's event while its disk's event is still running**, so `sda` is always processed before `sda1`. At that point `sda` is the only device claiming the label, so the symlink points at it, and the mount can start before `sda1` exists to outrank it. `link_priority` ranks devices that are already claimants. It cannot rank one udev has not processed yet. Stage 2 agrees with this reading: in the failing lanes, `by-label/ZETA_INSTALL -> /dev/sda1` resolved correctly *after* boot, while `/iso` had already been mounted from `/dev/sda`.

## Fix
- `fileSystems."/iso".device = lib.mkForce "/dev/disk/zeta-install-medium"`, a udev symlink (in both the initrd's and stage 2's rules) that only three kinds of device can claim:
  - an **iso9660 partition** carrying the ISO label (`sda1` / `nvme0n1p1` / `vda1`);
  - an **optical drive** `sr*`. The kernel never partitions it, although blkid may still report the isohybrid MBR;
  - a **whole disk with no partition table** (plain iso9660 written to a stick).
- A partitioned whole disk never claims the symlink. The `.device` unit therefore cannot become ready until `sda1`'s event is processed, and the mount source is `sda1` for every event order. Nothing is left to race.
- The `link_priority` rule stays, so stage 2's `by-label` (which the first-boot ESP scan walks) keeps pointing at the same partition.
- `bootMediumShape` is unchanged and still strict. Its failure message now names the new mechanism.

## Red → green
`src/Core.TypeScript/installer/install-medium-selection.ts` is a model: it reads the module's udev rules and `/iso` device, prepends the upstream `60-persistent-storage.rules` by-label rule verbatim, and replays every legal uevent order, keeping each parent before its partitions. For each order it records every device the `/iso` path can resolve to, from the moment the path first exists until coldplug ends.

## Not verified locally
- The module has not been evaluated by `nix` (no nix is installed locally). CI builds it.
- The model has not been tested against real udev. It assumes blkid sets `ID_PART_TABLE_TYPE` on the isohybrid **whole disk**, which is what libblkid reports for isohybrid images (`PTTYPE="dos"` alongside `TYPE="iso9660"`). If that assumption is wrong, the whole disk would claim the symlink again, and `bootMediumShape` would fail that lane loudly.
