## Description

## What a fresh install measured (2026-09-27, read-only kubectl on a reinstalled bare-metal node)

- The chart rendered three Ingresses of class `gitlab-nginx`. The only IngressClass on the cluster is `cilium`, so nothing served them. They never got an address, and ArgoCD held the gitlab sync at Progressing ("waiting for healthy state of networking.k8s.io/Ingress/gitlab-kas and 2 more resources").
- GitLab advertised `https://gitlab.gitlab.zeta.local`. Nothing on the LAN resolves that name, and nothing terminates TLS for it. The bundled runner registered against it, failed, and PANICked. It was also using the registration-token flow, which GitLab 17 disables by default.
- **StatefulSet `gitlab-gitaly` was never created.** SSA refused it: `.spec.template.spec.containers[name="gitaly"].env: duplicate entries for key [name="TZ"]`. Chart 8.7.0 includes `gitlab.timeZone.env` twice, and no values setting removes it. That is the gitaly row among the OutOfSync resources. The other two rows, `gitlab-postgresql` and `gitlab-redis-master`, are the known SSA volumeClaimTemplates drift (argo-cd#11143).

## Fix

| | |
|---|---|
| LAN (no public domain) | Ingress is off. Web and registry are HTTPRoutes on a dedicated hostname-less Cilium Gateway `gitlab-lan`, pinned to **192.168.1.250**, the last address of `cilium-lb-ipam/ip-pool.yaml`. External URL: **`http://192.168.1.250/`**. The registry uses the same address (`/v2/`, plain HTTP, so it has to be listed in `insecure-registries`). The route is not on `zeta-gateway` because that gateway's hostname-less `:80` listener is the portal's catch-all. |
| Public domain set | `platform-public-tls` adds `gitlab.<domain>` and `registry.<domain>` to `zeta-public-gateway`, each with its own listener and certificate, so a name that fails to issue blocks only itself and never GitLab. It also adds the `gitlab-public` and `gitlab-registry-public` routes. Job `gitlab-public-hosts` merge-patches the gitlab Application's `spec.source.helm.parameters`, which makes the external URL **`https://gitlab.<domain>`**. `zeta-root` ignores exactly that field (`ignoreDifferences` + `RespectIgnoreDifferences=true`). |
| Runner | `gitlabUrl: http://gitlab-webservice-default.gitlab.svc:8181` with an in-cluster `clone_url`. Uses the authentication-token flow (`runnerRegistrationToken: ""` switches the chart's register script to its glrt- branch). A wave-5 Sync-hook Job execs `gitlab-rails runner` in the toolbox and calls `Ci::Runners::CreateRunnerService` (idempotent: it reuses the `zeta-cluster` runner and never overwrites an existing token). It writes the `glrt-` token into `gitlab-gitlab-runner-secret`. No PAT is minted and the token is never printed. The runner Deployment is at wave 10. If the Job fails, it prints the operator step and exits 0, so it never blocks the sync. |
| OutOfSync | The gitlab Application now uses client-side apply. That lets gitaly be created and closes the vct drift. KAS is off: its only exposure was the unserved Ingress. |
| Collateral | Removed the stale `NO-PROVIDER|gitlab|extensions|Ingress` acknowledgement. The image-provenance scan now skips Helm template expressions (`{{ ... }}`); the rendered image is already measured in `image-resolvability.json`. |
