## Description

## What

The `gmod` and `unturned` Blueprints in `full-ai-cluster/k8s/applications/platform/blueprints.yaml` ran an install initContainer calling `/opt/steamcmd/steamcmd.sh`, and they overrode the main container's `command`. Neither works with `ghcr.io/ich777/steamcmd:*`:

- **No image ships `/opt/steamcmd`.** Steamcmd is downloaded at runtime by the image's own entrypoint. `/opt/scripts/start.sh` runs as root, sets up the `steam` user, chowns `/serverdata`, then `su steam` into `start-server.sh`. That script fetches steamcmd into `$STEAMCMD_DIR`, runs `app_update $GAME_ID` into `$SERVER_DIR`, and starts the server.
- **The `command:` override skipped the entrypoint,** so steamcmd was never fetched and the game was never installed. The install failed with "not found" whatever UID it ran as.

This change drops `install:`, `command:` and `args:`, so the image's entrypoint runs, and drives the image through its env contract instead:

| | gmod | unturned |
|---|---|---|
| `GAME_ID` | 4020 | 1110390 |
| `GAME_NAME` | garrysmod | (unused by its script) |
| `GAME_PARAMS` | `+maxplayers … +gamemode … +map …` | same three tokens the old `args:` passed |
| `GAME_PORT` | `${PORT}` | 27015 |
| `VALIDATE` | `${VALIDATE}` (default `true`; the old install line always validated) | same |

**The PVC now mounts at `SERVER_DIR` (`/serverdata/serverfiles`), not at `/serverdata`.** `start-server.sh` wgets into `$STEAMCMD_DIR` without creating it first. A volume over `/serverdata` would hide the image's empty `steamcmd/` directory, so a fresh install would fail. The cost: steamcmd is downloaded again on every pod start. The game files persist on the volume.

The PR #17721 invariant is unchanged: the pod `securityContext` is exactly `{ fsGroup: 1000 }` with no `runAsUser`, because the entrypoint has to start as root to drop privileges. `k8s/applications/game-hosting/gmod` (cm2network) is not touched.

## Image contract evidence (read from the registry, 2026-09-28)

I read the linux/amd64 config and all six layers of `garrysmod` (index `sha256:8b7aa732…`) and `unturned` (index `sha256:7aad7004…`):
- Entrypoint `["/opt/scripts/start.sh"]`, no Cmd, no User.
- Env: `DATA_DIR=/serverdata`, `STEAMCMD_DIR=/serverdata/steamcmd`, `SERVER_DIR=/serverdata/serverfiles`, `GAME_ID/GAME_NAME/GAME_PARAMS=template`, `GAME_PORT=27015`, `UID=99`, `GID=100`.
- The only steamcmd-shaped path in any layer is the empty directory `serverdata/steamcmd/`. Under `opt/` there are only `opt/scripts/start.sh` and `opt/scripts/start-server.sh`.
- The extracted scripts are byte-identical (apart from CRLF) to the `garrysmod` and `unturned` branches of `ich777/docker-steamcmd-server`.

The full record is in the test comment in `full-ai-cluster/platform-controller/src/blueprint.test.ts`.

## Red, then green

For each ich777 Blueprint, the rewritten describe block in `blueprint.test.ts` asserts:
- no `command` or `args`, and no initContainer
- no `/opt/steamcmd` anywhere in the pod spec
- `GAME_ID` is the appid, and `GAME_PORT` and `GAME_PARAMS` are set
- the volume mounts at `/serverdata/serverfiles`
- `fsGroup`-only, with no container `securityContext`

It also checks that `gmod`'s `GAME_NAME` is `garrysmod`. The Blueprint filter is now keyed on the image prefix rather than on `install`, so the tests do not become vacuous once `install` is removed.

- On origin/main: **9 fail**. The fsGroup assertions pass.
- After the fix: platform-controller 89/89 pass. `tools/k8s-manifests.test.ts`, the portal `blueprint-agent` tests and the `cluster/` Blueprint tests are also green.
