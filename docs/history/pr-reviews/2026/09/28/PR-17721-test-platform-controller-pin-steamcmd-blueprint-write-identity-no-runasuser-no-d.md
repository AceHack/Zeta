## Description

## Suspected defect: NOT present — invariant pinned instead

PR #17708 fixed `ERROR! Failed to install app '4020' (Missing file permissions)` in the hand-written gmod StatefulSet by forcing `runAsUser/runAsGroup: 1000` (cm2network/steamcmd owns its tree as uid 1000). The platform controller's `renderDeployable` sets only `fsGroup: 1000` for SteamCMD Blueprints. Was that the same defect? **No.**

### Evidence
- Both SteamCMD install Blueprints in `full-ai-cluster/k8s/applications/platform/blueprints.yaml` (gmod, unturned) use `ghcr.io/ich777/steamcmd:{garrysmod,unturned}`.
- Registry image configs (amd64, read 2026-09-27): **no `User`** → the process starts as root. `Entrypoint: /opt/scripts/start.sh`, env `UID=99 GID=100 UMASK=000 DATA_PERM=770`.
- Upstream `ich777/docker-steamcmd-server` (branch `garrysmod`) `start.sh` does `usermod -u $UID`, `groupmod`, `chown -R $UID:$GID $DATA_DIR`, then `su steam`. That privilege drop **requires** starting as root; forcing `runAsUser` would break it.
- The rendered pod overrides `command` for both the install init and main, so the entrypoint never runs, nothing drops, and both run as root, which can write the fsGroup-1000 PVC. The PR #17708 failure has no path here.
- UID/GID env matching fsGroup is **not** the right invariant: only the bypassed entrypoint reads that env.

### Change
A test only. `blueprint.test.ts` loads the shipped `blueprints.yaml`, renders every `ich777/steamcmd` install Blueprint and asserts:
- the pod `securityContext` is exactly `{ fsGroup: 1000 }`, with no runAsUser/runAsGroup/runAsNonRoot;
- the install init uses the Blueprint image, has no `securityContext`, and mounts the data PVC;
- the set is exactly `[gmod, unturned]`, so the test cannot pass vacuously.

Mutation check: adding `runAsUser: 1000, runAsGroup: 1000` to `blueprint.ts` turns 2 tests red, and reverting turns them green. Platform-controller suite: 82 pass. `tsc --noEmit` is clean.

### Not verified / still open
- That future image tags keep having no `User`. That needs the network, and the test comment says to re-read the image config on a tag bump.
- **A separate, real defect stays open (already tracked in workitem 081M0QB1ZCV087G0R001P9YCPX):** the gmod/unturned `install:` runs `/opt/steamcmd/steamcmd.sh`, which exists in no ich777 image. They fetch steamcmd at runtime into `/serverdata/steamcmd`. The install init would fail with "not found" whatever the UID. This PR does not change that.
- Not exercised on a live cluster.
