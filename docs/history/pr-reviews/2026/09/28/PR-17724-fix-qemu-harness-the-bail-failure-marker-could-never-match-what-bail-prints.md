## Description

## What

Both QEMU harnesses carried the literal failure marker `"bail"`. The installer's `bail()` prints `ERROR: <reason>` and exits 1 (`zeta-install.sh:94`), and it never prints the word "bail". That left the marker with no true positive. All it could do was false-positive on a healthy line that happened to contain the substring. Work item 081M3JG8ZRN087G0R00001RG0J noted this, and `qemu-full-install-test.ts` had it filed as STILL SUSPECT.

Both lists now use one shared marker instead: `INSTALLER_BAIL_SERIAL_MARKER = "\nERROR: "` (exported from `zflash/test-harness/serial-markers.ts`).

- **Why it is line-anchored.** The installer also prints non-fatal `ERROR:` text in the middle of a line (`      PROBE ERROR: …` and `[iter-5.4.1]   ERROR: …`). `bail()` is the only thing that starts a line with it. The `\n` also matches a CRLF serial stream.
- Every `bail` is fatal (`exit 1`), so stopping the harness on this line cannot hide a run that would otherwise have passed.

## Red → green

`installer-bail-marker.test.ts` reads the prefix from `bail()`'s own definition. If `bail()` ever changes what it prints, the test goes red instead of the marker quietly going blind again.

- RED: exports added, lists unchanged. 6 of 9 failed: in both lists a real bail line was not caught, a CRLF bail line was not caught, and the literal `"bail"` was still present.
- GREEN: all 9 pass. The existing `qemu-state.test.ts` healthy-install fixture also still passes against the new list.

## Not verified

This was not exercised in a live QEMU run. The real bail text shape comes from run 36097366591's serial output (`ERROR: BOOT disk /dev/vda is 20 GiB …`).
