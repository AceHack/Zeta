## Description

## What

`full-ai-cluster/portal/src/blueprint-agent.ts` is the AI draft generator. It still produced the contract that #17729 and #17736 fixed in the shipped library:

- The **gmod, unturned, valheim and rust** drafts have three problems:
  - an `install:` line calling `/opt/steamcmd/steamcmd.sh`, a path no ich777 image ships;
  - a `command:` override, which skips the image's `/opt/scripts/start.sh`, the script that actually installs the game;
  - a PVC mounted at `/data`.
- The gmod draft named `ghcr.io/ich777/steamcmd:gmod`, which is **not a tag**: the manifest fetch fails. The publisher's tag is `garrysmod`.
- **Every** game draft carried a bare `atmoz/sftp` sidecar, which crash-loops. The "add sftp" follow-up added the same bare sidecar.

## Fix

**ich777 drafts** configure the image by env and set no install, command or args. The PVC mounts at `/serverdata/serverfiles`.

| draft | image tag | env |
|---|---|---|
| gmod | `garrysmod` | `GAME_ID=4020`, `GAME_NAME=garrysmod`, `GAME_PARAMS` (maxplayers/gamemode/map), `GAME_PORT=${PORT}`, `VALIDATE` |
| unturned | `unturned` | `GAME_ID=1110390`, `GAME_PARAMS` (the same three tokens as before), `GAME_PORT=27015`, `VALIDATE` |
| valheim | `valheim` | `GAME_ID=896660`, `SRV_NAME`, `WORLD_NAME`, `SRV_PWD`, `GAME_PARAMS=""`, `GAME_PORT=2456`, `VALIDATE` |
| rust | `rust` | `GAME_ID=258550` and `GAME_PARAMS` (maxplayers/worldsize), both required because the image defaults them to `template`; plus `SERVER_NAME`, `GAME_PORT=28015`, `VALIDATE` |

**SFTP** uses the opt-in gate from #17736 everywhere. The sidecar mounts the optional `${RESOURCE_NAME}-sftp-keys` ConfigMap, idles until that ConfigMap holds a key file, then runs `exec /entrypoint zeta::<uid>:<gid>` as the owner of the data:
- ich777 images: **99:100**.
- **itzg/minecraft-server: 1000:1000, verified**, not assumed. The registry config of `:latest` (index `sha256:83c076bb24c8…`) has `Env UID=1000 GID=1000` and no `User`.
- **arma-reforger: 1000:1000**, the pod fsGroup. That image runs as root and I did not want to serve SFTP as root. Write access to files the game created is not guaranteed.
- "add sftp" on a draft without a sidecar now adds the same gate: 99:100 on an ich777 image, 1000:1000 otherwise.

## Anti-drift: one shared helper for the library and the generator

New file `full-ai-cluster/platform-controller/src/steamcmd-contract.ts`. It holds pure checks that return a list of violations, and is imported only by tests:
- `ich777ContractViolations(podSpec, {appId, gamePort})` checks that the pod:
  - overrides no command or args and has no initContainers;
  - never names `/opt/steamcmd`;
  - sets `GAME_ID` and `GAME_PORT` to the expected values, and sets `GAME_PARAMS` to something other than `template`;
  - mounts the PVC only at `/serverdata/serverfiles`;
  - has a securityContext of exactly `{ fsGroup: 1000 }`, with none on any container.
- `sftpGateViolations(podSpec, resource, userSpec, root)` checks the optional read-only keys ConfigMap and the data mount. It then **runs** the rendered script against an atmoz stub in three cases:
  - empty keys directory: the sidecar must idle;
  - only `..data` present: it must still idle;
  - a key present: atmoz must start as `userSpec`.

Both callers now use it. `blueprint.test.ts` checks the shipped library with it; I refactored the two library blocks from #17729 and #17736 to call it, and added control tests showing it reports the pre-#17729 gmod shape and the pre-#17736 bare sidecar as violations. `portal/src/blueprint-agent.test.ts` renders **every game draft through `renderDeployable()`** and applies the same checks. The portal Docker image copies only `portal/src`, so the portal imports the helper in tests only, never at runtime.

## Red, then green

- The final `blueprint-agent.test.ts` run against origin/main's `blueprint-agent.ts`: **14 fail** (16 pass). The failures:
  - the gmod image tag;
  - 4 ich777 contract checks;
  - 6 sftp gate checks;
  - the "add sftp" gate;
  - 2 updated app-id assertions.
- After the fix: portal 127/127, platform-controller 87/87. `tsc --noEmit` is clean for both packages.
- local-checks: 8 failures, all on the known pre-existing Windows list.

## Not verified

- No live pod was run, so nothing confirms these drafts actually install and serve.
- For valheim and rust I read the upstream `start-server.sh` and the registry config only. Unlike garrysmod and unturned, I did not diff their image layers against upstream.
- It is not checked that Unturned and Rust honour the `GAME_PARAMS` tokens when launched this way.
- `itzg/minecraft-server:latest` floats, so its UID/GID default could change. The draft does not pin it.
