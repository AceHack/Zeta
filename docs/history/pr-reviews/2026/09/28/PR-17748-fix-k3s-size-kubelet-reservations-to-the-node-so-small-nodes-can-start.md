## Description

## Regression

#17728 raised the server's static kubelet reservation to kube-reserved 2Gi + system-reserved 512Mi + eviction-hard 500Mi = **3060Mi**. The kubelet refuses to start when that exceeds node memory capacity:

```
kubelet.go:1750] "Failed to start ContainerManager" err="invalid Node Allocatable configuration. Resource \"memory\" has a reservation of {{3208642...
k3s.service: Main process exited, code=exited, status=1/FAILURE
```

Every k3s NixOS VM test (2560 MB guests: cluster-init, platform-fixes, agent-join, second control plane, datastore-bootstrap-sentinel) fails this way on main (build-ai-cluster-iso run 36379743833), and so would any real node under ~3 GiB.

## Fix

`k3s-kubelet-reservations.sh` runs as a oneshot **before** `k3s.service` (`wantedBy`, never `requiredBy` — a failure leaves kubelet defaults, never a refused start). It reads MemTotal / nproc and writes `kube-reserved`, `system-reserved`, `eviction-hard`, `eviction-soft` (+ grace) into `/run/zeta/k3s-kubelet-reservations.yaml`, which k3s reads via `K3S_CONFIG_FILE` (checked in k3s `pkg/configfilearg/parser.go`: env var honoured, file values inserted before CLI flags so `--kubelet-arg` appends, missing file = args unchanged; nixpkgs 26.05's k3s module passes no `--config`).

Rule: role targets unchanged when kube+system fit in 25% of the node (GKE's first-tier rate), scaled proportionally otherwise; hard eviction 5% (100Mi floor, 500Mi cap); soft 10% (≥2x hard, 1Gi cap); CPU clamped to 25% of cores. `MemoryLow` on k3s.service/system.slice is re-set at runtime (`systemctl set-property --runtime`) to the kube-reserved actually granted, so #17728's "accounting = enforcement" invariant holds on small nodes too. No `--kube-reserved-cgroup` (#17666's decision kept).

| node | server kube / system / hard / soft | total | agent kube / system |
|---|---|---|---|
| 2 GiB, 2 cpu | 333m/409Mi · 167m/103Mi · 102Mi · 204Mi | 614Mi (30%) | 256Mi / 256Mi |
| 2.5 GiB (test VMs) | 333m/512Mi · 167m/128Mi · 128Mi · 256Mi | 768Mi (30%) | 320Mi / 320Mi |
| 4 GiB, 4 cpu | 500m/819Mi · 250m/205Mi · 204Mi · 409Mi | 1228Mi (30%) | 512Mi / 512Mi |
| 12 GiB (WP11 guest) | 500m/2048Mi · 250m/512Mi · 500Mi · 1Gi | 3060Mi | unchanged |
| 62 GiB / 256 GiB | 500m/2048Mi · 250m/512Mi · 500Mi · 1Gi | 3060Mi | unchanged |

On every node ≥ ~12 GiB the values are exactly #17728's.
