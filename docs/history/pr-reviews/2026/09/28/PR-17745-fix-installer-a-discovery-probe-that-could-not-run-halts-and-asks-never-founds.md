## Description

## What

On a box whose role was not declared, a cluster-discovery probe that **could not run** now halts and asks the operator. It no longer founds a new cluster by default.

## Root cause (work item 081M3HP7KKH087G0R0011NQAKF)

When the role is undeclared and `ZETA_DISCOVERY_REQUIRED` is at its old default of `0`, these non-results fell back to the ISO default role, `control-plane` (`first-control-plane`), which founds a cluster:

- `probe-failed`
- `dwell-too-short`
- a missing `zeta-cluster-discover` binary
- an unexpected exit

On a second machine where discovery errors, that produces a second cluster. That is split-brain, and it has to be undone by hand.

## Precondition check (the work item's gate)

The item asked for a lane showing the fixed probe actually running before the default flips. **Met.** Main's push run **36364582344** (2026-09-28) has this in its `qemu-full-install-serial-log` artifact:

```
[zeta-discovery] probing for 30000ms (token-present=false) ...
[zeta-discovery] BOOTSTRAP — nothing answered, and the silence passed
```

## Change

- `ZETA_DISCOVERY_REQUIRED` now defaults to `1`.
- Two pure decisions sit in a marked block, `ZETA-DISCOVERY-NONRESULT`:
  - `zeta_discovery_nonresult_decision <required> <kind>` returns `fallback` or `ask`. `kind=off` always falls back, because the operator chose `ZETA_DISCOVERY=off`, and halting would override that choice.
  - `zeta_discovery_key_decision <key>` returns `control-plane`, `worker` or `shell`.
- When the decision is `ask`, the script prints `[zeta-discovery] HALTED — …` and reads one key with **no timeout**. A timeout would amount to a default, and the default is the split-brain.
  - `c` or `w` records `ZETA_ROLE_SOURCE=keystroke:c|w` (declared), exactly like the role prompt.
  - Any other key, or EOF, drops to a shell.
- Setting `ZETA_DISCOVERY_REQUIRED=0` restores the old fallback.
- The QEMU harness treats `[zeta-discovery] HALTED` as a hard-fail marker, so a lane never burns its phase-1 budget waiting for a keypress.
- `installer-unit-tests.yml` now also triggers on `zeta-first-boot.sh`.

## Red → green

`src/Core.TypeScript/installer/discovery-nonresult-shell-parity.test.ts` has 8 tests. It runs the extracted decisions in real bash (required=1 asks, required=0 falls back, off falls back, c/C/w/W, anything else or no key → shell) and pins the wiring: the default is `1`, the off arm passes `off`, and the prompt reads one key with no `-t` and sets the keystroke sources. On `origin/main` 0/8 pass; on this branch 8/8. The existing `installer-wiring.test.ts` (routing of refusal reasons) still passes.

## Not verified

- Nobody has pressed a key at the new prompt on metal or in QEMU; the halt path is exercised only through the extracted functions.
- If some QEMU lane's probe does fail on a future ISO, that lane will now go red on `HALTED` rather than silently founding. That is intended, but it has not been observed yet.
