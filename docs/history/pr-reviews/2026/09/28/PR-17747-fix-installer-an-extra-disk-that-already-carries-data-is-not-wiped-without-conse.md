## Description

## What
The installer wiped **every** non-boot disk as Longhorn storage without asking. On a real reinstall of node-5b2dfa it reformatted the entire second NVMe (`nvme1n1` → `/var/lib/longhorn-disk2`) with no confirmation.

A new step runs after the disk probe and **before** the wipe scope and Longhorn capacity preflight are decided. For each extra disk it prints size, model, serial and what the probe saw, then decides:

| extra disk | decision |
|---|---|
| USB boot medium | never selected |
| blank (no partitions/filesystems/labels) | adopted — the documented intent (docs + capacity-preflight remedy) |
| listed in `ZETA_LONGHORN_EXTRA_DISKS` (device paths or serials, or `all` / `none`; env or ESP `zeta-firstboot.conf`, passed through by `zeta-first-boot.sh`) | adopted |
| carries data, or unreadable | asks for `y` within 30 s on a real TTY; otherwise **left untouched** and removed from both the data-disk list and the wipe scope |

**Consequence to know:** re-paving a node whose second disk holds a previous install's Longhorn data now needs consent (press `y`, or set `ZETA_LONGHORN_EXTRA_DISKS`). Without it, the Longhorn capacity preflight may refuse — before anything is wiped.
