## Description

## What failed

k8s-lane-partition run 36364582440 (jobs 108748845153 lane-3, 108748845232 lane-4, 108748845261 lane-6) and the live kind/k3d ArgoCD health jobs failed pulling the argo-cd 10.8.0 chart's default redis image, `ecr-public.aws.com/docker/library/redis:8.6.4-alpine`. The error was `toomanyrequests: Data limit exceeded`. That is a data quota on anonymous ecr-public, not a burst limit, so retrying does not clear it. kind nodes also pull the image themselves, so pre-pulling it on the runner does not help either.

## Fix: change where the image comes from

`docker.io/library/redis:8.6.4-alpine` is the same image, re-measured today:
- The index digest is `sha256:2cc044fc5a07c9b701f8f1255a309ae9ad7856e694ac03513bf3648c01e40763`.
- Its linux/amd64 manifest is `sha256:c64af41b8fc06a2d9b8fde812dd781aa157bed6fcf8ae1656ad4e79f3f9fc9b1`, the same digest the preload snapshot had pinned for the ecr-public ref.

docker.io is also the one bootstrap registry the metal pull-through cache (mirror.gcr.io) covers.

`redis.image.repository=docker.io/library/redis` is now set in all three places that install ArgoCD. The tag stays the chart's, so a chart bump still moves redis.
- `k8s/bootstrap/argocd-install.yaml`, the k3s HelmChart.
- `k8s/applications/argocd/Application.yaml`, the self-managed Application. Without it, the wave -90 self-sync would switch redis back to ecr-public. `audit-argocd-pin-parity` passes: the values are identical.
- The kind/k3d `--set` list in `dev-cluster/use-cases.ts`. Both lanes now use one `ARGOCD_HELM_SET_VALUES` constant.

`helm template` against argo-cd 10.8.0 renders `docker.io/library/redis:8.6.4-alpine` for all three value sets.

## Derived snapshots

- `bootstrap-preload-images.json`: the ref is renamed and the digest and size are unchanged. `--refresh` could not run locally because it needs docker for the sandbox-image derivation. The ISO lane's `--verify` re-resolves it.
- `lane-footprints.json`: the size comes from `measureImage`.
- `image-resolvability.json`: the entry comes from `resolveImage`, status ok.

`ecr-public` is now left only in history comments and in one rate-limit unit-test fixture.

## Red to green

A new `describe` in `bootstrap-image-preload.test.ts` checks four things: the snapshot, the bootstrap values, the Application values, and the kind/k3d set-values. All 4 fail on origin/main and pass here. The "mostly UNMIRRORED" floor drops from 0.9 to 0.85 (the measured share went from 0.916 to 0.883), because redis moved to a mirrored registry, which is the intended effect.
