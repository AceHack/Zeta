## Description

## What

After the wipe, the repo clone and `nixos-install` now have an overall time bound. A hang ends as a named failure instead of an endless wait on a machine whose disks are already wiped.

## Root cause (work item 081M3HPNSY5087G0R002QAVCEJ, read from source)

- `sudo git clone "$REPO_URL" /mnt/etc/zeta` had no `timeout` and no `GIT_TERMINAL_PROMPT=0`. The `git ls-remote` preflight a few seconds earlier catches "no network" but not a stall partway through the transfer.
- `nixos-install` limited each **download** (`connect-timeout`, `stalled-download-timeout`, `download-attempts`) but not the **run** as a whole. A `github:` flake-input fetch (flake inputs are not baked into the ISO) or a from-source fallback build could still stall the install with nothing on screen.

## Change

- New `zeta_bounded_step <name> <secs> <cmd...>` (marked block `ZETA-BOUNDED-STEP`). It wraps the command in `timeout --kill-after=30`, so a child that ignores SIGTERM is killed 30 s later. On timeout (124 or 137) it prints `TIMEOUT: <name> did not finish within <secs>s` and returns 124. Any other failure keeps its own return code.
- The clone runs as `sudo env GIT_TERMINAL_PROMPT=0 git clone …`. It is bounded by `ZETA_CLONE_TIMEOUT_SECS` (default 900).
- `nixos-install` is bounded by `ZETA_NIXOS_INSTALL_TIMEOUT_SECS` (default 10800). That is generous because `fallback true` can mean a from-source build.
- Each step gets separate `bail` messages for a timeout and for an ordinary failure. Both say the disks are already wiped, name the likely cause, and give the override variable.

## Red → green

`src/Core.TypeScript/installer/bounded-step-shell-parity.test.ts` (8 tests) runs the extracted function in real bash:
- `sleep 20` under a 1 s bound gives rc 124 and a message naming the step and the bound.
- A command that succeeds keeps its output and rc 0.
- `false` keeps its own rc and is not reported as a timeout.
- It does not trip the caller's `set -e`.

It also pins the call sites: the clone and `nixos-install` go through the wrapper with `GIT_TERMINAL_PROMPT=0`, the named bail messages exist, and both bounds are defined before use.

On `origin/main` 0/8 pass; on this branch 8/8.

## Not verified

- No real install was run, so neither bound has been seen to fire on metal or in QEMU.
- The defaults (15 min clone, 3 h `nixos-install`) are judgement calls, not measurements.
- The work item's second direction (baking flake inputs into the ISO so `nixos-install` needs only the binary cache) is **not** done here.
