## Description

fix(security): enforce the two unchecked premises under Scorecard alert #254

Scorecard reports "score is 7: 3 existing vulnerabilities". Measured 2026-09-13
against api.osv.dev and this tree, all three are either accepted-and-checked or not
applicable -- but only ONE of them had anything enforcing that:

  GHSA-x2fc-mxcx-w4mf  mathjs prototype pollution
      REAL, ACCEPTED, ALREADY CHECKED. Rides on `quantum-circuit`, a declared
      role=second-oracle the maintainer ruled stays. Premise enforced by
      lint-mathjs-dismissal-premise.ts. Untouched here -- one premise, one checker.

  PYSEC-2026-3804      accelerate path traversal via sharded-checkpoint weight_map
      NOT VULNERABLE. The advisory's own range is {introduced: 0,
      last_affected: "1.14.0"}; src/Interp.Python/uv.lock pins 1.15.0. There is no
      `fixed` event, so a matcher asking "has a fix?" rather than "is it in range?"
      reports it outstanding forever.

  GO-2026-5932         golang.org/x/crypto/openpgp unmaintained and unsafe by design
      NOT REACHABLE. x/crypto is an `// indirect` requirement of one module (the
      hat-system operator); the advisory is scoped to the `openpgp` SUBPACKAGE,
      which no .go file in this tree imports. A module-level matcher cannot see
      subpackage reachability.

THE POINT IS NOT THAT THE ALERT IS NOISE. It is that "this is noise" was true,
undocumented, and unchecked -- and both remaining premises are one dependency bump
from becoming false with nothing to say so. That is the vacuity class pointed at a
security disposition, and this repo already has the answer pattern for it.

The new checker goes red when: accelerate is pinned <= 1.14.0 or its pin becomes
unreadable, or any .go file imports x/crypto/openpgp. It reports UNKNOWN -- never a
pass -- when it scans zero files, cannot read a file, or meets a version it cannot
order.

FALSIFIER, NOT DECORATION. 17 tests; three mutants killed:
  numeric ordering -> string compare      17 pass/0 fail -> 15/2
     (the forcing case: "1.9.0" > "1.15.0" under string compare, so a vulnerable
      pin would have passed)
  openpgp subpackage -> whole x/crypto    17 pass/0 fail -> 15/2
     (would fail a healthy tree: the module is legitimately an indirect dep)
  last_affected exclusive -> inclusive    17 pass/0 fail -> 16/1

The first mutation harness written for this reported four blank results, because
`"$F".test.ts` expanded to `...premises.ts.test.ts` and bun matched no files. Four
mutants "survived" by never being tested. Rerun against the real path, they die.

Wired as a drift-tier step beside the mathjs checker, plus its unit tests in the
existing audit-unit-test list. Not added to `gate (required)`'s needs -- that is a
treaty amendment and this is not one.
