## Description

Four changes land together, and the last two only make sense because of the first two.

## Work arrives without being polled for

`webhook-intake` verifies a delivery against a secret read from a **file** at call time, maps it through the organization's own `field=path` configuration, and files an intake item where `directoryIntake` already looks. `serve-hooks` runs as a separate process on a separate port from the read-only dashboard. **Arrival is not execution** — a delivery is filed immediately and picked up on the next cycle, so no stranger and no retry storm decides how often the company works. Linear joins as a read-only `DataSourcePort`, and `org configure` grew a `receive_events` step so an agent can walk a person through setup from nothing.

## The history answers questions

Every read of the store was a full walk — open every shard, parse every shard, then filter. Measured on real stores, and **the filter is free**, so all of it was opening files that could not match:

| events | full read (before) |
|---|---|
| 1,000 | 99 ms |
| 5,000 | 777 ms |
| 20,000 | 2,873 ms |
| 60,000 | 9,994 ms |

One work item, one run, writes ~219 shards — so 60k events is a small organization's first month or two. `readShards` now prunes whole `YYYY/MM/DD` directories (the partition was already on disk and nothing used it), and `org-index` keeps a derived, rebuildable `bun:sqlite` index beside the shards.

| query, 60k events | before | after |
|---|---|---|
| `eventsFor` | 5,732 ms | **86 ms** |
| `decidedUnder` | 5,678 ms | **104 ms** |
| time-ranged read | 5,679 ms | **292 ms** |

There is deliberately **no fold checkpoint**. It was planned, then measured: the fold is 9 ms of a 186 ms resume. It would have bought 5% of a fifth of a second and cost a second record of the same facts, which `org-store` refuses in its own header. The numbers are recorded at `foldOrganization` so nobody re-derives the case.

## DELIVERED implies a commit

`merge` returns the merge commit and its tree, a `change_merged` fact records them, and `foldLandedChanges` makes *"has this ever landed"* answerable across processes.

The first attempt asked **this run's** projection instead, and was reverted after measuring it: on a resume every already-merged item comes back `Done` with a projection at `Claimed`.

```
RUN 1  delivered: true    merge commits in git: 1
RUN 2  delivered: false   done_with_nothing_merged   merge commits in git: 1  ← it IS there
```

## A gate can be answered by running checks

`check-roster` runs a roster in the change's own checkout and records each verdict against the git **tree** it judged, so an unchanged tree reuses it and a changed one cannot. Bound checks are **strictly additive** — a roster that is not clean rejects the gate before the reviewer is asked; a clean one changes nothing. A check with no falsifier reports `UNPROVEN`, never `Passed`.

`org check bind|list` reads the same `cross-verify` roster CI does, so adding an audit there adds it here. Measured against this repo: **32 bindable checks, 4 of which can prove they are able to fail.**

## Defects found by testing, not by reading

- **`recordingProviders` dropped the change port's optional methods.** `changed` had been gone since the wrapper was written, so no run through `runOrgRuntime` had ever emitted `change_files`. Found only by adding a *second* optional method and watching it arrive `undefined`.
- **`hooksOf` mapped an unrecognised scheme to `"none"`** — the scheme that verifies *nothing* — under a comment claiming it refused. One transposed character turned a verified endpoint into an open one.
- **A multi-byte character split across TCP chunks** corrupted the bytes a signature was taken over: correct in every ASCII test, wrong a few times a day in production.
- **`trackerMapper` refuses by throwing and nothing caught it.** Inside an `end` handler that is a process-level throw, so one oddly-shaped delivery killed the receiver and every other integration with it.
- **Pruning the shard walk on the way down** could not tell a prefix like `2020/01/01` from the date triple, and pruned every in-range shard beneath it.
- **Unfinalized sqlite statements** hold the file handle past `close()` on Windows, so `dropIndex` failed with `EBUSY`.
- `checkKey` collided across its halves — the defect `externalRefOf` already solved here. And one of my own guards survived a mutation that deleted it outright, so it was removed rather than left as decoration.
