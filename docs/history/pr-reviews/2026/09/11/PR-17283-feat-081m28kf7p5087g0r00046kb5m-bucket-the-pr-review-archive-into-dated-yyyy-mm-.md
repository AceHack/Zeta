## Description

feat(pr-archive): bucket the PR-review archive into dated YYYY/MM/DD folders

`docs/history/pr-reviews/` is ONE FLAT DIRECTORY holding 14,378 archive bodies
(93 MB), growing ~25/day. Its sibling index `docs/github/prs/shards/` indexes the
same 14,378 PRs and has been bucketed at ~660-820 files per directory since
2026-08-13. Same corpus, one bucketed and one not.

Aaron 2026-09-06: "one per pr would be best, and they can be in dated folders so
we don't end up with too many files in one folder" and "we rarely want to add
more than one directory per day on a cadence too."

One file per PR is UNCHANGED. Only the directory changes.

DAILY, NOT MONTHLY - measured, not extrapolated
-----------------------------------------------
Monthly looks right from the current ~25 merges/day (750/dir, matching the shard
convention). That extrapolation is wrong for this corpus. Over all 14,378
`merged_at` values:

  layout              dirs  median/dir  p90/dir  max/dir
  monthly YYYY/MM        6       2,703        -    4,871
  weekly                22         573    1,231    2,077
  daily   YYYY/MM/DD   119          93      265      522

The repo's busiest day saw 522 merges (2026-08-17), so monthly would have put
4,871 files in `2026/08/` - six times the sibling store's fan-out, and worse than
the flat directory is at its own busiest month. Daily is the only one of the
three whose worst directory stays under the shard store's bucket ceiling.

Daily also satisfies the cadence constraint BY CONSTRUCTION rather than by
argument: a day-keyed path creates exactly one new directory per day and cannot
create two. And the buckets nest, so no level fans out far.

The bucket comes from the PR's own `merged_at`, never the archive-run date: the
archive is backfillable, so bucketing by when we happened to write the file would
scatter one PR's neighbours and make a re-run a move rather than a no-op.

THE FOUR SILENT-PASS DEFECTS THIS WOULD HAVE CAUSED
---------------------------------------------------
`reconcile-review-archive.ts`, `audit-archive-pr-lane.ts`,
`audit-review-archive-capture-window.ts` and `audit-review-archive-thread-capture.ts`
each did a FLAT `readdirSync` over the archive root. Against a bucketed tree that
matches zero `.md` files, and every one of them reports "no archives found" as a
clean pass - a check that cannot fail, arrived at by leaving a directory read
unchanged. All four now use the shared `walkArchiveDocs`, which tolerates both
layouts, so they are correct before, during and after the move.

`consume-pr-archives.ts` wrote `${REVIEW_DIR}/${basename(added)}`, which FLATTENS:
it would have drained bucketed orphan branches back into the flat root, one at a
time. It now writes the path the branch used.

THE READ BOUNDARY, NOT A HISTORY EDIT
-------------------------------------
Append-only ledgers under `db/` and prose citations name the old flat paths and
are NOT rewritten. `resolveArchivePath()` translates at the read boundary: any
cited path, flat or bucketed, current or stale, resolves in ONE shard read (the
shard path is a pure function of the PR number), because the PR NUMBER is the key
and the slug is not. A missing shard fails loudly with the PR number rather than
falling back to the cited path.

Measured while enumerating: the `db/mutation-findings/*.jsonl` ledgers cite
`src/.../archive-pr-reviews.ts` - the SOURCE file - and no archive record paths at
all. The only two legacy record citations under `db/` are prose, in
`db/child-floor/README.md` and one ip-questionable research doc. Both resolve
through the resolver; neither is touched.

WHAT IS HERE AND WHAT IS NOT
----------------------------
This is the writer, the resolver, the shared walker, the migration tool and their
tests. The 14,378 renames land separately (081M28KFAGV087G0R000BKEAZK) so this
half stays reviewable. No record moves in this commit; new records start landing
in buckets immediately, and the resolver and walker already handle the mixed tree.

FALSIFIERS
----------
34 tests. Four mutants run and killed: monthly instead of daily (5 fail), undated
falling back to today's date (1), the resolver echoing the cited path (2), and a
non-recursive walk (2). A record with no `merged_at` - PR #1702, archived while
OPEN - lands in a NAMED `undated/` bucket carrying its reason, never a guessed
date, and that is pinned by its own test rather than left to the summary line.
