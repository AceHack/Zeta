## Description

Wires `affected-legs.ts` into the gate, per Aaron's "all of it, including the floor legs".

> **Depends on #17291.** That PR re-arms the unclaimed-path fail-safe, which this one is
> not safe without: today an unclaimed path returns `mode=selective` with the whole floor
> off. Merge order matters.

## What changed

28 jobs now run only when `ace/build-graph.json` says the diff can reach them.
`path-filter` publishes **one** output — `legs`, a JSON object keyed by job slug — and
each job carries one expression:

```yaml
if: fromJSON(needs.path-filter.outputs.legs).gate_lint_fsharp != false
```

The **keys** come from the graph at run time, so no roster of them lives in the workflow.
A roster there would be a second copy of the change→job map and would drift the moment a
target is added — the thing `affected-legs.ts`'s own header refuses.

## Why this is the answer to "archive-only PRs should go through less checks"

Measured, post-fix:

| diff | mode | legs on | floor |
|---|---|---|---|
| archive-only | `selective` | 6 cheap lints | **off** |
| docs-only | `selective` | 4 | **off** |
| `src/Core/ZSet.fs` | `selective` | build-and-test, lint-fsharp, lint-csharp, semgrep-drift, … | on |
| unclaimed path | `full` | **all** | on |

**#17290 was open while this was written** — an archive-only PR running the full hermetic
TypeScript suite.

## Fail-closed, twice, and neither is a convention to remember

- `|| '{}'` on the output — a `detect` that did not run, could not run, or emitted nothing
  yields an empty object.
- `!= false` at each consumer — a leg absent from the object reads as `null`, and
  `null != false` is **true**, so the job **runs**. A new job, a typo, a graph that lost a
  target: each does the work rather than skipping it.

Note the polarity flip on the five language lints: `== 'true'` failed **open** on an
unknown value (skip); `!= false` fails **closed** (run).

## Two legs are deliberately NOT gated

This is a graph-modelling rule, not a one-off (`081M28X3E5P087G0R0004S8JJY`):

> **A verification leg cannot be derived from "which targets produce this artifact". It
> must be claimed by everything it VERIFIES.**

`gate/cross-verify` is claimed by **3** targets and `gate/full-verify` by **4**, while
both run the cross-oracle treaty byte-lock over F#/C#/TS/Rust. An F#-only change that
*breaks* the byte-lock turns neither leg on — so gating on them would skip the check that
exists to catch it. A verifier's job is catching changes that do not declare themselves;
deriving its trigger from declarations is circular. Both sit on a roster with the measured
reason and a `LIFTS WHEN`, and the roster is checked in both directions so an entry cannot
outlive its reason.

Contrast the legs that *are* sound: `gate/build-and-test`, `gate/lint-fsharp` and
`gate/lint-csharp` are claimed by **59** targets each; the TypeScript legs by `**/*.ts`.

## `build-and-test` is decided by two predicates, so the implication is checked

Its **job** runs on its leg; its **steps** still run on `code`. If the leg were ever on
while `code` was false, the job would start, skip every step, and report success — a
vacuous green on the largest job in the floor. `leg ⇒ code` holds today, but that is an
argument and arguments rot, so `detect` now **refuses** when the two disagree. Both values
already exist in that step; the check costs one `grep`.

## A relaxed safety property, moved rather than deleted

`build-and-test` had no job-level `if:`, so `gate-skip-verdict.ts` treated any skip of it
as **blocking**, and four tests pinned that. It has one now — a real relaxation. The tests
assert its new condition explicitly rather than dropping the old expectation, and
`cross-verify` (no `if:` at all) takes over the "no licence to skip" role so that refusal
class stays covered. Without that, MUTANT 3 and MUTANT 5 would have stopped being killed
for the reason they name — they would still have passed, which is the failure mode.

## New falsifier

`ci/gate-leg-wiring.ts`, run in `lint (build-graph completeness)`. Three failures are
silent without it:

| kind | what it costs |
|---|---|
| `unknown-slug` | `fromJSON(...).typo` is `null` → job never skips. Safe, and the selection is **permanently gone with nothing saying so** |
| `ungated` | graph grew a leg, `gate.yml` never learned. Same silence |
| `wrong-slug` | gated on another job's leg — **this one is not safe**: skips a job whose own leg said run |

Each finding class is produced by a mutant in the test, plus two roster-hygiene classes
(`stale-exemption`, `legless-exemption`).
