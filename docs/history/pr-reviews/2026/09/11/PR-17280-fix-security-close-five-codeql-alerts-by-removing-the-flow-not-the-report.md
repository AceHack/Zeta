929 js/prototype-pollution-utility - src/Core.TypeScript/ace/deps.ts
  `setNestedProperty`'s walk read `current[part]`, which RUNS a getter.
  An own property may be an accessor, so `hasOwnProperty` is true, the
  walk descends, caller-influenced code executes inside a pass the
  comments call read-only, and a getter returning a different object
  each call lets the guards judge one object while PASS 3 writes through
  another. Now `Object.getOwnPropertyDescriptor(current, part)?.value` -
  the exact mirror of why `defineOwn` uses `defineProperty` instead of
  assignment. Two falsifiers added; both die under the old expression.

932 js/log-injection - src/Core.TypeScript/observe/realtime-client.ts
  `sanitizeForLog` mapped control characters to a space, which stops a
  forged line and DESTROYS the evidence. Now JSON-escaped: lossless,
  one line, quotes delimiting the untrusted region, and a round-trip
  test proves an operator can recover what the peer sent. It is also the
  shape the shipped model recognises - `StringReplaceSanitizer` matches
  `.replace(x, "")`, never `.replace(x, " ")`, which is why two
  widenings of the character class only moved the alert (#653 -> #932).

182 js/http-to-file-access - full-ai-cluster/portal/src/data-file.ts
  Found a real path traversal next to the reported flow. `decodeResource`
  runs `decodeURIComponent`, so `%2F` arrives as a real `/` past the
  `[^/]+` route pattern, and `fileFor` used `resource.replace("/", "~")`
  - first occurrence only - so `../../etc/...` stayed live and
  `appendFileSync` could create or grow a file outside the volume.
  Now an allow-list on `<namespace>/<name>` DNS-1123 labels. Actor ids
  reaching the append-only log are validated the same way, which is what
  closes the reported flow (k8s API -> `spec.ai.admin` -> `proposedBy.id`).

131 js/weak-cryptographic-algorithm - change-control-id.ts
  UUIDv5 is DEFINED as SHA-1 (RFC 4122 4.3), so "content-addressed UUID"
  and "no weak hash" cannot both hold under that version. RFC 9562 5.8
  version 8 exists for exactly this. Now SHA-256 tagged v8. It was never
  RFC-compliant v5 anyway (it hashed the namespace's ASCII spelling, not
  its 16 raw bytes). No golden vectors pinned the old ids - checked.

224 js/insecure-temporary-file - src/Core.TypeScript/hygiene/divergence-shard.ts
  The "caller nobody could find" was the string literal `"/tmp/unused"`
  in the test that proves a byte-identical pair is refused: CodeQL models
  a `/tmp/...` literal as the OS temp dir. Two previous identifications
  in that comment were wrong, including one that concluded FALSE POSITIVE
  from `mkdtempSync`'s properties - a flow the query was not following.
  The test now uses a real 0700 root and asserts it stayed EMPTY, which
  proves the property the name "unused" only asked the reader to assume.
