## Description

The brief: cilium / cilium-lb-ipam are covered by the Cilium lanes -- make that
coverage COUNT rather than excluded. The lane that asserts them,
`live-kind-cilium-included`, was dispatch-only and had not been green since
2026-09-09.

MEASURED: dispatch run 35934909707 (main + #17599) is GREEN -- 39 Applications
in the roster, 37 auto-sync Applications Synced+Healthy on kind with Cilium as
the CNI, `cilium` and `weaviate` among them: the two this lane adds over
kindnetd's 35. What made it green was #17595 + #17599 (kind's control-plane
parity with k3d and metal); run 35929570637 before them had Cilium's agent in
Init:CrashLoopBackOff and 30 Applications Degraded behind it.

A lane that only runs when someone dispatches it is coverage nobody measures, so
it now runs on push to main (for the paths this workflow already filters on) and
on the daily schedule, and stays dispatchable. NOT on pull_request, on purpose:
one green is not a track record, it costs ~60 runner-minutes, and a flaky
non-required red on every PR teaches people to ignore it. The job's comment says
when to promote it further. The job name keeps "PROBE" so nothing keyed on it
moves. The apt-job-timings row that said "refresh this if it is ever promoted to
a cadence" now records the promotion (the budget audit is green).

`cilium-lb-ipam` STAYS excluded, unchanged: its pool pins a home-LAN range;
kind uses the bring-up alias pool instead, and lifting the Application would
selfHeal the metal range over it (reason in DEV_EXCLUDED_REASONS).
