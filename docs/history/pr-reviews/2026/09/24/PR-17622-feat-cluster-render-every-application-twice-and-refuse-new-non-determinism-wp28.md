## Why

A chart whose render differs from **itself** is non-deterministic by construction. ArgoCD diffs a fresh render against live state on every sync, sees a difference that is not a drift, re-applies, and under `selfHeal: true` the workload churns forever — on any cluster, including the one that boots off the USB installer. Nothing in this repo could see that class.

**Measured over 49 Applications, helm v4.2.0: 45 stable, 4 unstable, 0 unmeasured.**

|---|---|---|

| cilium | `Secret/kube-system/hubble-relay-client-certs` | regenerated-secret |
| cilium | `Secret/kube-system/hubble-server-certs` | regenerated-secret |
| seaweedfs | `Secret/object-store/blob-store-seaweedfs-sftp-secret` | regenerated-secret |
| weaviate | `Secret//weaviate-cluster-api-basic-auth` | regenerated-secret |
| gitlab | `Pod/gitlab/gitlab-webservice-test-runner-*` | fresh-identity |

**Two shapes, deliberately not conflated**, because the remedies differ. A regenerated **secret** means the chart mints a password or certificate at template time — supply the value so it stops inventing one. A fresh **identity** is a hook Pod with a random name — exclude the hook or accept it via `ignoreDifferences`; nothing about its contents is wrong. A third bucket, `contents-differ`, has no instance today and exists so a *new* shape is reported rather than filed under one of the two.

**Documents, not apps.** "cilium is unstable" sends the next reader nowhere.

**Both directions are findings.** A new unstable document is the obvious one. A baseline row that is *no longer* unstable is also red — a baseline still carrying a fixed row has stopped constraining it, so the next regression there passes.

## The six "unrenderable" charts were ours

This is most of the change. The first census reported `arc-controller`, `argo-rollouts`, `argocd`, `cloudnativepg`, `external-secrets` and `kube-prometheus-stack` as `helm-template-failed` with an **empty detail string**. Running `helm template` by hand on cloudnativepg exited 0 and produced **1,272,266 bytes**.

`defaultRunHelm` called `spawnSync` with no `maxBuffer`, so Node's 1 MiB default killed the **six biggest charts** with `ENOBUFS`. The reason was lost because `spawnSync` leaves `stderr` as the *empty string* rather than `undefined` on that path, so `result.stderr ?? error.message` never reached the message.

Both halves are fixed: the cap is **raised** to the repo's own `DEFAULT_MAX_BYTES` (64 MiB — raised, not removed, since an unbounded child can hang the process), and `error.message` is used whenever stderr is blank.

**Every consumer of that renderer was affected**, not just this census — `image-footprint`, `image-resolvability`, `inert-valuesobject-keys` and the storage-claims snapshot all quietly stopped seeing those six. Six charts that "could not be rendered" were six charts nobody had rendered.

The unmeasured set is therefore empty — but it is **named** and **never counted as stable**, because an app nobody can render has not been shown to be deterministic. An unmeasured entry with an empty detail is itself the finding, and that is asserted.

## The baseline had to be made deterministic too — and my first attempt was not

A `fresh-identity` row cannot carry a literal name, so the suffix is wildcarded. The first version **guessed** it from a single key with `/-[a-z0-9]{5,}$/`, narrowed to require a digit so it would not eat real names. It wildcarded `…-test-runner-9pl2t`, then failed to match `…-test-runner-jjcvk` on the very next render — helm's `randAlphaNum` emits five alphanumerics and is not required to include a digit. **The baseline it wrote went red against the next run**, which is precisely the failure the wildcard exists to prevent.

Replaced with a rule derived from the **pair**: whatever the two names share is the name, whatever they do not is the suffix. It cannot wildcard a real name, because a real name has no counterpart to differ from, and it refuses to wildcard across a `-` separator — that is two objects, not one.

Documents are matched by **identity, not position**: a chart may emit its documents in a different order without being non-deterministic, ArgoCD matches by identity too, and a positional comparison would report every such chart as churn.

`--measure` now **carries the prose forward**. The `$comment` block is the only part of the baseline a reader can act on, and the first regenerator dropped it — the next `--measure` deleted the explanation silently. Same defect `image-footprint.measured.json` records about its own regenerator, caught here before it reached main.
