## Description

`Human-Review: none` is already permitted end to end: the enforcement job short-circuits a
`none` claim with no forge lookup, so nothing mechanical requires a person on a PR. What a
person was still SUPPLYING is the judgement that a green suite means something.

Two PRs measured 2026-09-13 show the system cannot make that judgement today:

  #17402 premise checkers    32 new tests   every mutant died        genuinely self-verifying
  the exclusive-lock fix      4 new tests   ALL survive the defect   needed a reviewer

Restoring the lock defect leaves that file at 21 pass / 0 fail. Both reached CI looking
identical -- green, with new tests -- and only one had tests that could fail.

WHAT THIS ADDS. A drift-tier job that mutates a line THIS PR CHANGED and asks whether THIS
PR's tests notice. `mutation-runner.ts` already mutates recently-changed files by
`git log --since=<when>`, which answers "is the codebase covered" over a window; the per-PR
question is the one review actually asks, and a file-scoped mutant can land on a line the
author never touched.

The baseline-first protocol, the three-valued outcome and the always-restore are NOT
reimplemented. `runMutant` is refactored into `runVariant`, which takes the choice of variant
as a callback; both selectors now share one copy of the honesty about what a run established,
so they cannot drift apart. `runVariant` also now reports `unresolved` when the mutation had
no site, instead of crediting the tests for a change that was never made.

THE FAILURE IT MUST NOT HAVE, taken from its own sibling: `mutation-runner.ts` shipped with
`--since=24h`, invalid git approxidate, which matches zero commits without erroring -- it
would have reported "nothing to do" forever while looking healthy. So every empty outcome here
is classified and none is spelled "clean": NO-MERGE-BASE and NO-CHANGED-FILES print as CANNOT
SEE, NO-TARGETS and no-sites print as NOTHING TO ASK, and all four end in "NOT MEASURED --
nothing is claimed". Verified live: run on a tree whose HEAD equals the base, it reports
NO-CHANGED-FILES rather than a clean pass.

MEASURED LIMITATION, AND IT IS THE HONEST HEADLINE. Pointed at the exclusive-lock fix -- the
very PR that motivated this -- the tool reports KILLED and "every mutant killed". A clean bill
on the case that proves the gap. The catalogue is eight OPERATOR swaps; `claimGeneration` has
exactly two operator sites, both errno comparisons; and the real defect is an ORDERING change
(create-then-write vs stage-then-link) that no operator swap can express.

So this measures a LOWER BOUND on coverage and nothing more. It finds changed lines whose
operators and branches no test constrains at all. It cannot see a missing await, a wrong call
order, an unchecked return or an atomicity gap. That limitation is written into the tool's
header and into its own success verdict, which now says "every CATALOGUED OPERATOR mutant"
rather than implying the tests are sufficient. It is the first reason this ships at drift tier
and is deliberately NOT in `gate-required`'s needs.

Falsifiers: 16 tests, and the tool was mutated against them. Six mutants -- hunk length
defaulting to 0, 0-based line numbers, dropping the changed-line filter, mutable comments,
pure deletions counted as changed, and collapsing NO-MERGE-BASE into NO-CHANGED-FILES -- and
FIVE died on the first pass. The comment mutant SURVIVED: my `//` test passed because an
EARLIER guard fired (a `//` line is also caught by the trailing-comment check), so the guard
under test was doing nothing. Replaced with a block-comment case, which only `isCommentLine`
catches; all six now die. That is the same defect class this whole tool is for, found in the
tool itself by the technique the tool applies.
