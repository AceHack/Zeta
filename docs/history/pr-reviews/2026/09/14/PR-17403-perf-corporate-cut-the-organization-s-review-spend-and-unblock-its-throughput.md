## Description

Six FlowDent tickets took **15.3 hours** and reached design approval. This is what the event store said was happening, and what it cost.

**13.71 of the 15.3 hours — 90% — was the organization idle between store writes.** All figures below are counted the way `foldGateEvaluations` counts: the raw event stream carries every verdict twice (once as its own event, once inside the governance roll-up that summarises it), so reading the events directly doubles every number.

## What was actually wrong

Most of these are the same defect wearing different clothes: **information the organization already held, withheld from the agent that needed it**. Each time, the agent then behaved *correctly* and produced something that looked like a quality problem.

| | Measured |
|---|---|
| Reviewer never saw the title or brief | `business_context_grooming` rejected goal-024 **81 times, approved 0** — while a 1,215-char description sat on the node |
| Producer never saw the AI reviewer's objection | `architecture_design` rejected proj-050 **51 times** on a byte-identical file |
| Implementer had no feedback channel at all | rework re-ran from a prompt identical to the one that was rejected |
| `briefOf` used `else if` | reproduction steps dropped for **4 of 6 tickets**; `reproduction` rejected task-036 **12 times** |
| Ceremony ran for already-passed gates | **24,209 of 31,977 events (76%)** — and it filled reviewers' calendars, causing "no common slot" |
| Change-control livelock | **452 of 688 refusals (66%)** were one derivative shape |
| Parked work held a contributor seat | proj-042 parked **44 times**, holding 1 of only 2 implementation seats |
| Store re-read on every append | cold read ~176 s; `ocli task` ran twice inside every review |

## Effect

- Store reads: **4,000 ms → 0.25 ms** warm; **125,652 ms → 295 ms** via snapshot, byte-identical content.
- Review context handoff: **176 s → 75 ms**.
- Replayed against the real verdicts: the rejection ceiling alone removes **192 of 349 calls (55%)**; `--pipeline diagnosed_design` reaches **81%** while keeping the `approach` human checkpoint.

## Two things that fail *open*, now refused or warned

- A `--checkpoint` naming a gate its `--pipeline` never walks was accepted in full and **could never fire**, while the run reported it as configured. Now refused.
- With no `--test-cmd` the test port answers `passed` without running anything, so `qa_uat` and `runtime_validation` **cannot fail**. The run now says so at startup. (`--test-timeout-ms` is new so a real suite's budget doesn't become every review's patience — one shared `--port-timeout-ms` was why a timed-out review, recorded as a *refusal*, cost 4.44 h of the run.)

## Deliberately not changed

`progressOf.gatesPassed` counts rejections despite its name, which is why 78 cycles never declared NO_PROGRESS. Counting only passes would halt a legitimate rework round after one cycle; the rejection ceiling bounds the spin correctly instead. Documented in place.
