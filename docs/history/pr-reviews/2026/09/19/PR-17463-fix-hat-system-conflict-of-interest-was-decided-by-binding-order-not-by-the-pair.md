## Description

`03-conflict-of-interest.yaml` read only the **incoming** hat's `conflictsWith`, while its own header has claimed *"(or vice-versa)"* since it was written. The code never implemented the second half.

## Measured on the committed seed hats

`executor` and `hat-designer` name each other, so that pair was symmetric by luck. **`policy-admin` declares `conflictsWith: [executor, hat-designer]` and neither names it back:**

| order | policy's lookup | outcome |
|---|---|---|
| bind `executor`, then `policy-admin` | policy-admin's list holds executor | **DENIED** |
| bind `policy-admin`, then `executor` | executor's list is `[hat-designer]` | **ALLOWED** |

Same pair, opposite outcome, decided by arrival order. An anti-collusion control a wearer defeats by choosing which hat to take first is not a control — and the bypass needs no privilege, only patience about ordering.

## The fix

Ask the **existing** hat's declaration as well, so the pair is refused whichever hat arrives second. Both rules are kept rather than merged: Rego violations are a union, a symmetric pair is simply caught twice, and deleting either one silently restores half the hole.

## On the test, honestly

There is **no OPA or conftest runner in this repository** — these seven Gatekeeper policies have never been executed by anything in CI. So the falsifier does *not* run the Rego. It reads which directions the policy implements out of the policy text and simulates the admission decision over the committed catalogue in both orders.

That is a **model** of the rule, not a test of it: it would not catch a syntax error or a typo'd field path. It does catch the defect that was actually present, and it carries a control asserting the pairs are genuinely *refused* rather than merely *agreeing* — without that, "both orders permitted" would pass too.

**Witnessed:** reverting the reverse lookup turns **3 tests red**, including the `policy-admin` case by name. 5 pass restored, tsc 0.

## Provenance

Found by a routed agent building a PoC for the placeholder `hat-system-operator` image. It reported the asymmetry as a **fact** about the catalogue rather than as a verdict, which is what made it checkable — I verified the declarations and the Rego independently before acting on it.

**Not fixed here:** the seed catalogue's one-sided declaration is left as it is. With both directions implemented an asymmetric declaration is now harmless, and making `executor` and `hat-designer` name `policy-admin` back is a statement about what those roles *mean* — a maintainer's call, not a drive-by edit.
