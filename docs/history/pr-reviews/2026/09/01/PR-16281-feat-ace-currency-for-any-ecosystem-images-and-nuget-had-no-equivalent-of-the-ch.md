## Description

## Why in `ace`

Aaron: *"we should get the images version going and any other package manager, we should wire this into our ace package manager to be able to report on this, it's supposed to be able to handle any kind of package."*

`report-chart-currency.ts` answers "is this pin current" for Helm charts. **Nothing answered it for container images, NuGet, or npm** — which is how `bitnamilegacy` (frozen 2025-08) and `ankane/pgvector:latest` (no push since **2023-10-11**) sat in the tree while the chart versions above them looked fine.

## Built around the chart report's own lesson

> A pure versions-behind metric reports the **most dangerous** dependency as the **healthiest** — which is exactly what happened with minio.

So **gap** and **upstream silence** are two independent axes, both reported. `dormant` exists as a class precisely because being at the newest version can mean upstream *stopped*. A test demonstrates the one-number collapse producing the wrong answer on an archived package.

### It refuses rather than reassures

| condition | verdict | why not "current" |
|---|---|---|
| probe failed | `unreachable` | a failed probe is **UNKNOWN**, never a pass |
| pin not published | `unpublished` | it can never resolve |
| registry carries no dates | silence = **unknown** | inferring "not dormant" from an absent date invents a measurement |

`nowIso` is **injected**, not read from the clock — so verdicts replay deterministically. A test changes only `now` and shows the verdict move, proving the parameter is load-bearing rather than decorative.

## Proven against the real registries — the cases that bit us

```
bitnamilegacy/redis  7.4.1-debian-12-r2  -> UNPUBLISHED  silentDays=375
ankane/pgvector      latest              -> DORMANT      silentDays=1056
valkey/valkey        9.0.6-alpine3.24    -> BEHIND gap=35 silentDays=0
Microsoft.Orleans.Server      10.3.1     -> CURRENT
Microsoft.Extensions.Hosting  10.0.0     -> BEHIND gap=27
```

**That last row is the tool catching my own error from earlier today** — I wrote `10.0.0` from memory and NuGet rejected it as a downgrade. This is the mechanical answer to *"how do we keep ending up on older versions"*: query the registry, don't recall.

## Two bugs found by probing, not by reading

- **Docker Hub detection** keyed off the first dot *anywhere* in the coordinate, so `bitnamilegacy/redis` went down the registry path with `bitnamilegacy` as a hostname — every Docker Hub image returned `UNREACHABLE`, the answer that hides a frozen repo.
- **Only the first 100 tags are read**, so an old pin can report `unpublished` when the truth is "not on the first page". That errs toward *alarm* rather than reassurance, which is the safe direction — but it is a false reason for a true verdict, and it is recorded as a limit at the call site rather than smoothed over.
