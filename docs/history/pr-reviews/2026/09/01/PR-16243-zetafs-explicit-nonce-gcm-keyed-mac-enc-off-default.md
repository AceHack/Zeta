## Description

## Summary

PR9 of the ZetaFS first-product sequence (E8 / E12 / C2). Volume crypto does **not** call `RandomNumberGenerator.Fill`. That remains `AesGcmCryptoProvider` for the spine DiskBackingStore.

Nonce is `pack(epoch, LSN, disc)` (96 bits). ContentId is prefixed into the AEAD plaintext. Cleartext is HMAC-SHA256 of the ciphertext. FORMAT default stays `enc=off` until numbers are metered.

Aaron accepted ghost text `start PR9 once freeze lands (shadow*)` after freeze #16232 and CLI #16233 landed.

## What this is not

- Not XTS (not an object format; parse refuses `enc=xts`)
- `vault-dedup` and `convergent-opt-in` named and refused (default off)
- Passphrase KDF is toy HMAC, not R8 TPM/USB wrap
- Hardware AES is `AesGcm.IsSupported` at process start, not a FORMAT key
- No marketing numbers. OpenZFS / LUKS are named baselines, not hooked
