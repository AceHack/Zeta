## Description

## Three literals, two answers, neither the cluster's

| where | said |
|---|---|
| `audit-observability-chain.ts` | **1.31.0** |
| the legacy tree's manifest validator | 1.33.0 |
| `gate.yml` (kubeconform) | 1.33.0 |
| **k3s, from this repo's own flake lock** | **1.35.6** |

The kubeconform pin's own comment names that exact drift — *"Two lanes validating the same kinds against two different Kubernetes versions is the drift this closes"* — and it closed two lanes and left a third at a different number. That is the argument for a **file** rather than a shared constant: a hand-applied fix reaches the places its author happened to grep for.

## Derived, not asserted

k3s comes from `pkgs.k3s`, so the version follows this repo's flake lock, and the declaration records the command that reads it back.

**One trap is written down because I hit it:** evaluating `<nixpkgs>` with `--impure` and no flake resolves the **machine's channel**, not the lock — it said `1.35.7` while the lock said `1.35.6`. Close enough to look right, and wrong.

## A stale version fails in BOTH directions

- **Too low rejects charts that would install** — not hypothetical: `mimir-distributed` 6.x needs ≥1.32, could not render at 1.31.0, and **its bump was reverted earlier today on a constraint that never applied to us.** Verified here: **mimir 6.2.0 renders cleanly at 1.35.6.**
- **Too low also clears charts** using APIs removed after the declared version — they validate here and fail on the real cluster. Silent, and the dangerous one.

## The linter, and the vacuity it started as

`lint-kubernetes-version-agrees` refuses any literal that disagrees. Its **first clean run reported `0 literal(s) scanned, all agree`** — a pass that *cannot fail*, because wiring the consumers had removed everything its matcher could see.

Writing the falsifiers found two real gaps: it missed a **quoted JSON key** (`"kubernetesVersion": "..."` — the spelling the declaration file itself uses) and a **value not adjacent to its key** (`"kube-version": { default: "..." }` — the shape the legacy validator carried). It now scans **13**, and a mutant is caught then restored.

## Two of my own defects, both found by this repo's guards

- The declaration **named a path in the tree scheduled for deletion**, adding an entry to a list whose purpose is to shrink. Reworded — the fact reads the same without it.
- The linter's directory walk did **readdir-then-stat**, a check-then-use race (CWE-367), *in a tool written to prevent drift*. Now `withFileTypes`, so the kind arrives with the listing.

## What this does NOT check

That the declaration still matches the flake. That needs `nix` and a flake evaluation, unavailable in every lane this runs in. **Moving the lock without moving the declaration is a gap this cannot see** — named in the file rather than implied.
