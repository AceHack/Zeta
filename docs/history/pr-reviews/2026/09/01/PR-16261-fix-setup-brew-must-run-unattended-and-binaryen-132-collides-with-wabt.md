## Description

Two defects hit while running `install.sh` on the maintainer's machine today. **Neither is reachable by the CI lane that covers it.**

## 1. `brew install` prompted and stopped the installer dead

```
==> Would upgrade 1 dependency for tectonic: pcre2
==> Do you want to proceed with the installation? [y/n]
```

No `NONINTERACTIVE` was set anywhere in `macos.sh`.

**Why CI never saw it:** Homebrew only prompts on an interactive terminal, and a runner has no TTY. So `macos-install-sh-test` is **structurally incapable of failing** for this class — its green means *"no terminal was attached"*, not *"the installer is unattended"*.

## 2. `brew install binaryen` failed at the link step

```
Could not symlink bin/wasm2c
Target /opt/homebrew/bin/wasm2c is a symlink belonging to wabt
```

**An upstream bump, not a local mess — and this is the part worth keeping.** The CI run at 06:10 *that same day* poured **binaryen 131 and passed**. **132 published after it**, and 132 is the version that added `wasm2c`, which wabt 1.0.41 already ships. Both formulae are in `manifests/brew`.

**The next CI run would have hit this.** The lane was green because it ran a few hours early, not because the tree was sound.

Resolved by a **declared allowlist**, not a blanket `--overwrite` — forcing every link would let a future collision resolve silently in whichever order brew happened to run, which is the same shape as the bug.

`binaryen` wins because we install it for `wasm-opt`/`wasm-as`/`wasm-dis` (AssemblyScript's optimizer, checked by `smoke-10-toolchains.sh`), and `wabt` for `wat2wasm`/`wasm2wat`/`wasm-validate`/`wasm-strip`. **`wasm2c` is in neither reason and is referenced nowhere in this repo** — the collision is over a binary nothing here uses. An *undeclared* collision still fails loudly.

Verified after relinking on the maintainer's machine: all seven binaries this repo actually uses resolve. Nothing lost.

`bash -n` clean; `shellcheck` rc=0.
