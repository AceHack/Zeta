## Description

Main went red on `build-and-test (windows-2025)` (gate `33474539115`) with `install-windows=failure` — and `roslyn-guard`, `build` and `test` **all skipped behind it**:

```
- Qemu (exited 404) - Error while running '...\Qemu\tools\chocolateyInstall.ps1'
warn: choco install qemu failed (exit 404); falling through to the next package source
qemu failed on every available package source
```

The 404 is upstream — a chocolatey package whose vendor URL moved — and not ours to fix. **Requiring a tool we never invoke is.**

## Measured, not assumed: nothing on Windows runs QEMU

Every lane that invokes it — `build-ai-cluster-iso`, `multiboot-qemu-uefi-smoke`, `installer-unit-tests`, and the rest — is `runs-on: ubuntu-24.04`. No `runs-on: windows-*` workflow references qemu, and no `.ps1` in the tree invokes it. The acceptance substrate the row exists for is a **Linux** substrate.

So an unused dependency's upstream outage was blinding the entire Windows build and test leg.

## Why `optional` rather than deleting the row

A Windows dev box that wants qemu still gets it, `manifest-symmetry` still sees a Windows disposition, and `install.ps1` warns and continues — exactly what `ollama` already does for the same best-effort reason. `manifest-realized.ts` already understands it: `absent-optional` is a distinct verdict and does not fail the lane.

## The justification is now machine-checked

*"Nothing on Windows uses it"* was about to be just a comment. `qemu-optional-on-windows-premise.test.ts` holds the **premise**, not the token — it fails the moment a windows-runs-on workflow starts referencing qemu, which is the only condition that makes this exemption wrong.

**And its first version was vacuous.** The controls had their *own* inline regex, so mutating the scanner's regex to `false` left all four tests green — a premise "verified" by a scan that could no longer see anything, in a test written to prevent precisely that. The mutation run caught it. Both controls now call the same scanner the assertion does.
