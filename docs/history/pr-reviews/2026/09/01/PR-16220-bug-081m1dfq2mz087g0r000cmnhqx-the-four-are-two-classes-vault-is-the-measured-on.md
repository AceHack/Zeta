## Description

Ran the item's own distinguishing test against an existing **green** `live-kind-included` job (kindnetd, same 33-app roster). No new CI needed.

## `vault` diverges by substrate

```
kind (kindnetd)     vault   sync=OutOfSync   health=Healthy
k3d  (k3s+Cilium)   vault   sync=Unknown     health=Progressing
```

Same Application, same roster — **Healthy on one substrate, never converging on the other.** That's a substrate difference, not an Application defect, and since **k3s+Cilium is what metal runs**, it's the one of the four most likely to matter for hardware. It's now the lead.

## The other three are UNMEASURED, not exonerated

`openziti-controller`, `trust-manager` and `spire` produce **no verdict line at all** in the kind run — they aren't in its asserted set, so there's no baseline. Calling them regressions or artifacts would be inventing a comparison nobody made.

Incidental confirmation: `cilium` is likewise absent from the kind run, which is exactly what the provider-conditional lift specifies — included on k3d only. The mechanism does what it claims.

## Method caution, recorded in the item
