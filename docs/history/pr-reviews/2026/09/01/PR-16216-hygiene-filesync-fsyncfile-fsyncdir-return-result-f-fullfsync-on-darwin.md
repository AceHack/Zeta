## Description

## Summary

PR2 of the ZetaFS first-product sequence. FileSync no longer swallows directory-fsync failure on the API Durable will call.

## Changes

- `fsyncFile` / `fsyncDir` return `Result<unit, FileSyncError>`
- Darwin: `fcntl(F_FULLFSYNC)` (ordinary `fsync` is not a power-loss barrier)
- Windows directory: documented no-op `Ok ()` — no Durable claim
- `fsyncDirBestEffort` keeps print-and-continue for DiskDeltaLog / DiskSpine
- Durable Freeze (PR7) must use the Result API, never the best-effort helper

`DbspError` is not a type in-tree yet; this PR uses `FileSyncError` so Durable can map later without inventing a global error DU here.
