## Description

## Summary

Adversarial perf finding: Nexmark Q1–Q8 sent **N singleton Z-sets then one Step**. `ZSetInputOp` pairwise-added the queue (**O(n²) allocs**). Feldera batches. The harness also rebuilt the circuit inside every BenchmarkDotNet iteration (measured `Circuit.create`, not the tick). `docs/BENCHMARKS.md` compared Z-set micro-ops to Feldera events/s — those are different experiments.

This lands the engine path Feldera already has: one batch, one tick, k-way coalesce.

## Changes

- `ZSet.ofArray` — one pool workspace, sort+consolidate; `ofKeys` on an array takes it.
- `ZSetInputOp` / `ChannelZSetInputOp` drain: 0/1-item identity; k>1 is `ZSet.sum` (O(n log k)).
- `bench/Feldera.Bench` Q1/Q2: circuit + `ZSet.ofArray` batch in `GlobalSetup`; tick is Send+Step.
- Nexmark Q1–Q8: `Send(ofArray)` + sync `Circuit.Step` (not `task { StepAsync }`).
- Tests: `ofArray` equals `ofKeys`; N singleton Sends coalesce to one ofArray Send; `ofArray` allocates less than pairwise singleton add at N=256.
- Honesty peel in `docs/BENCHMARKS.md`. We still have **no measured events/s vs Feldera** until a Release run is pasted there.

`map` is still O(n log n) even when `f` is monotone (Feldera Q1 `p * 100` on int64). Next measured cut.
