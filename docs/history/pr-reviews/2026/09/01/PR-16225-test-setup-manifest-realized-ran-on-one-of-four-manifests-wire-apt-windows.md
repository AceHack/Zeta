## Description

`manifest-realized.ts` shipped 2026-08-31 supporting **four** OS-native manifests — `brew`, `brew-cask`, `apt`, `windows` — and was wired into exactly **one** lane: macOS. The tool was complete; its deployment was not, and nothing said so.

So the check that exists to catch *"declared but not installed"* had never once been asked about `manifests/apt` (35 rows) or `manifests/windows` (14 rows).

**This is the tool's own defect, one level up.** Its header says *"A declaration that nothing checks is not a declaration."* A **check that nothing runs is not a check.**

## Why this matters for the hardware lane specifically

The row that motivated the tool was `opensc`: a week of smartcard work proceeded on the belief that the SmartCard-HSM was invisible to the OS — a belief formed from an empty `security list-smartcards`, never controlled against `opensc-tool --list-readers`, **because opensc was declared and not installed.**

`manifests/apt` declares `opensc`, `pcscd` and `libpcsclite1` **for exactly the same hardware**, and nothing had ever verified that `linux.sh` lands them.

## What the new steps measure — not host drift

Both containers are built minutes earlier from the very manifests under test, so *"is this host in sync"* could not fail and its green would be a claim about nothing. What they measure is the **installer**, by cross-checking two independent implementations of "this row is satisfied":

| | realizer | verifier |
|---|---|---|
| ubuntu | `linux.sh` shell parse + `apt-get install` | TS parse + `dpkg-query -W` |
| windows | `install.ps1` scoop→winget→chocolatey | TS parse + the same three indexes |

A row an install loop silently skips, a `tier=` token the two parsers disagree about, a package whose install name differs from its query name, or an install whose failure the loop swallowed — all fail **here** and are invisible to every other check in the repo.

## Both are hard asserts, and each earns it

- **ubuntu** — the runs above force `ZETA_INSTALL_FULL=1` while `detectTier` can only ask for `full` or less, so the required set is a **subset** of what was installed. A tier mismatch can hide rows; it cannot manufacture a failure.
- **windows** — `absent-optional` is a distinct verdict and only **non-optional** absences set exit 1, so this asserts exactly what `install.ps1` itself promises (it warns-and-continues on `optional`) — no more.

Neither lane is `gate (required)`, so neither blocks a merge either way.

## Guard against recurrence

`manifest-realized-runs-on-every-os-lane.test.ts` holds the coverage matrix, and its last test **derives the expected set from `MANIFESTS` in the tool itself** — so a fifth manifest with no lane fails rather than passing unnoticed.
