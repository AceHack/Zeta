## Description

## The gap

`full-ai-cluster/k8s/applications/orleans/statefulset.yaml`, `infra/k8s/applications/orleans/deployment.yaml` and `infra/k8s/bootstrap/initial-orleans.yaml` have all pinned `ghcr.io/lucent-financial-group/zeta-orleans-silo` since they were written. **Nothing built it** (081M0QB1Q6Z087G0R00091JH3Q).

It stayed invisible because GHCR answers `manifest HTTP 401` for a package that **does not exist** — identically to one that is private. The status code cannot tell them apart, so a missing image read as a permissions problem. The packages API settled it: `404 Package not found`. **Making a package public would not have fixed it, because there was no package.**

## What ships

A real Orleans 10.3.1 silo, not a placeholder — Redis clustering read from the mounted ConfigMap, `POD_IP` advertised to peers, and `IHeartbeatGrain`, the smallest grain that proves activation, state and placement. A silo with no grain registered starts, reports healthy, and can demonstrate none of that.

### It refuses rather than defaults

Three places, each because the quiet version produces **a silo that reports healthy while being wrong**:

| condition | behaviour | why not a default |
|---|---|---|
| config missing/malformed | exit 2 | defaulting joins whatever cluster the defaults name — a silent membership split |
| `clustering.provider` unimplemented | refuse | the ConfigMap carried `kubernetes` until 2026-09-01; a defaulting silo forms a cluster of one and **passes its TCP readiness probe** |
| empty Redis password | passed as empty | never as "no auth" — a wrong secret fails loudly instead of connecting to an unauthenticated Redis |

## Two real gaps found while wiring it

1. **The pod projected no credential.** The ConfigMap names `clustering.passwordSecret`, but `statefulset.yaml` passed no secret at all — the silo would have read an endpoint it had no password for. `REDIS_PASSWORD` is now projected (`optional: true`, so an unauthenticated Redis still starts).
2. **`redis-auth` does not exist in the tree.** The redis Application says `create via Sealed Secret / Vault`. So `replicas: 0` stays — but the header now names *that* as the reason, instead of the missing image it used to blame.

## The contract is checked, and the check was mutated

`src/Core.TypeScript/cluster/orleans-silo-contract.test.ts` reads **both halves** — manifests and source — and every assertion touches both. A test reading only the manifests would pass against a silo that ignores them.

Four mutants, each confirmed to fail it:

| mutant | caught |
|---|---|
| `REDIS_PASSWORD` projection removed | ✅ |
| ConfigMap grows a key the silo never reads | ✅ |
| provider refusal deleted | ✅ |
| gateway port drifts between ConfigMap and pod | ✅ |

The first one is the drift that was **already present** when I started.

## Build discipline

`Directory.Build.props` **and** `Directory.Packages.props` both stop inheritance in `full-ai-cluster/orleans-silo/`. Both are needed: NuGet discovers `Directory.Packages.props` on a search entirely separate from the `Directory.Build.props` chain, so `ManagePackageVersionsCentrally=false` in the latter is not sufficient — measured, the build failed `NU1008` on exactly that. Without both, the project would compile one way locally and another in the image, where the repo root is not in the build context.

`dotnet build -c Release` → **0 warnings, 0 errors**, with analyzers live. They caught `IDE0040`, `CA1848` and `CA1873`. `CA1873` is fixed by caching the grain key at activation rather than by an `IsEnabled` guard — the analyzer does not credit the guard, and the per-beat call was waste anyway.
