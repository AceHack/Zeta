## Description

Attempt 2 (run `33478106365`) failed on a different — and better — refusal:

```
{"kind":"UsageError","message":"--ephemeral-vault-init cannot be combined with
 --existing: the ceremony is authorised only for a cluster this process creates
 and destroys."}
```

**This is a design flaw in my experiment, not a flag typo.**

The job *must* pass `--existing`: the Cilium bring-up has to happen before the proof, because the no-CNI profile cannot schedule ArgoCD until a CNI is installed. So the ceremony is unavailable here **by construction**. I had copied `--ephemeral-vault-init` from `live-kind-included` along with the rest of the command line without noticing the two flags cannot coexist — the same copy-without-context that produced the empty git ref one attempt earlier.

## The consequence bounds what this job may conclude

The green baseline **does** run the ceremony. An uninitialised vault can fail to reach Healthy for reasons that have nothing to do with the CNI, so **`vault` in this lane is not comparable to the baseline.** Reporting its state here as evidence about Cilium would be comparing two different experiments and calling the difference a finding.

The table now prints vault under an explicit **CONFOUNDED** heading: the observed line, then in words that it is not comparable, not evidence, and that vault's standing evidence remains the kind-vs-k3d divergence in `081M1DFQ2MZ087G0R000CMNHQX`.

## The probe still answers what it was built for

`openziti-controller`, `trust-manager` and `spire` **do not depend on the ceremony** — and those three are the ones with *no baseline at all*, since kind never asserted them. That is exactly why step 2 of the work-item's own test existed.
