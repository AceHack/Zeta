## Description

Rendered at the **pinned** seaweedfs version against our own values:

| | 4.33.0 (pinned) | 4.45.0 |
|---|---|---|
| `identities` rendered | **0** | 1 |
| our access key rendered | **0 mentions** | 4 |
| `config-s3-users` volume | **absent** | present |
| bucket declarations | 12 | 12 |

`enableAuth: true` is declared with credentials beside it, and **no identity file is produced**. Combined with the loader's fail-**open** behaviour at that version:

> **Anything able to reach `blob-store-seaweedfs-all-in-one.object-store.svc:8333` can read and write the blob store, with or without credentials.**

That endpoint holds loki chunks, loki ruler state, mimir TSDB blocks, mimir ruler state, and `zeta-backups`.

## Why it went unnoticed

The Application *looks* correct and every static guard passes. The keys are not "inert" in the `inert-valuesobject-keys` sense — the chart **has** those keys; they simply never reach a rendered identity file at this version.

**This is the vacuity class one level up: a configuration that is present, well-formed, checked by every guard we own, and not in effect.** Nothing in the tree asserts auth is *enforced*, only that it is *configured*.

## How it surfaced

Sideways. #16279 bumps seaweedfs to close CVE-2026-77611; its `live kind` proof went red with `mimir is Unknown/Degraded`. Investigating **that** showed the bump turns on authentication that was previously doing nothing — so the Degraded mimir is a **consequence of auth beginning to work**, not of the CVE patch.

## What is NOT the cause (checked, so nobody re-checks it)

- Credentials match — mimir presents exactly what seaweedfs declares
- Permissions are sufficient — the identity is `anvAdmin` with `["Admin","Read","Write"]`
- Buckets are declared identically at both versions

## Open, and needing a live cluster

Why mimir is Degraded once auth is enforced. A render cannot answer it. **This must not be fixed by guessing at a security bump.**

## Also noticed

The 4.45.0 render carries a second chart-generated read-only identity (`anvReadOnly`) with a fixed access/secret pair — worth knowing whether that is deterministic per-chart or regenerated per-render.

## Done when

An unauthenticated request to the blob store is **refused, demonstrated by a test** rather than by reading the values — and mimir and loki reach Synced/Healthy against the authenticated store.
