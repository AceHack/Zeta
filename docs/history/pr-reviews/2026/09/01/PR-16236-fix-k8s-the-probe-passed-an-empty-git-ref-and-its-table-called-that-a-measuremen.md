## Description

The dispatched probe (run `33474432508`) failed, and **it measured nothing about Cilium**. Two defects, both mine.

## 1. The step had no `ZETA_ARGOCD_GIT_REF`

I copied the command line from `live-kind-included` — including `--git-ref "$ZETA_ARGOCD_GIT_REF"` — but not the `env:` block that defines it. It expanded to empty and the harness refused:

```
{"kind":"UsageError","message":"git ref must match [A-Za-z0-9._/-]+ ..."}
Process completed with exit code 2
```

**Exit 2 is a usage error: the proof never ran.** Every other lane in this file (735, 823, 1007, 1415) sets that env exactly as this now does. The harness's refusal is the only reason it didn't run against a garbage ref — it refused rather than proceeding, which is the design working.

## 2. The verdict table turned "never ran" into "not asserted"

With zero verdict lines in the log, it printed four tidy rows:

```
=== vault: NOT ASSERTED IN THIS SCOPE
=== openziti-controller: NOT ASSERTED IN THIS SCOPE
```

That reads exactly like a measurement of the roster and is nothing of the kind. **The only reason it was caught is that the all-apps section above it was also empty — an accident.**

That accident is now the explicit check: zero parsed verdicts prints *"the proof did not complete"*, refuses to list the four at all, and says in words that the job measured nothing.

## The falsifier took two attempts, and that's the part worth recording

`workflow-step-env-vars-are-defined.test.ts` cross-references each step's shell text against the env in **its own scope** (step → job → workflow). `actionlint` cannot catch this: the YAML is valid and `"$VAR"` is a legal expansion.

**Version 1 of that test could not fail for the bug it was written for.** It asked whether the variable was defined anywhere in the *workflow* — and `ZETA_ARGOCD_GIT_REF` is defined in four other steps of the same file, so deleting it from the offending step still passed. Its control also carried its own inline regex, so blinding the scanner left every test green.

Both are the vacuity class, committed inside the file written to name it — one hour after making the identical control mistake in the qemu premise test. **Mutation caught both; review would not have.**
