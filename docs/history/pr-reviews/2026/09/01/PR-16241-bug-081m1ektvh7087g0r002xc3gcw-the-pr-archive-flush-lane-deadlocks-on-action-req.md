## Description

`pr-gate-presence` refused on main with the sentence that matters:

> `required-check-started: no LIVE gate.yml run for #16228` … `gate (required)` can never report on it. **Note that a bare `gh pr checks` reads this as green; `--required` does not.**

## Root cause

The gate run for #16228's head is **`completed/action_required` with zero jobs**. It was created and never executed, so nothing published `gate (required)` — and auto-merge is armed against a check that cannot arrive.

## Systemic, not a one-off

Of the last 60 `gate.yml` runs, **7 are `action_required` and every one is `heartbeat/pr-archive`** with `actor=github-actions[bot]`:

```
09-01T08:50 · 08:00 · 07:16 · 06:33 · 05:51 · 05:06   heartbeat/pr-archive
```

Roughly every 45 minutes the lane retries and deadlocks identically. Same-repo branch (`from_fork=false`), author `AceHack`, and no other branch in the window is affected — so this is specific to runs a `github-actions[bot]` credential triggers.

## Why it matters more than a stuck PR

This is the lane that lands **PR archive data** — named on 2026-09-01 as the high-quality corpus: *"the pr responses and fixes are the high quality data."* Nothing is lost today (the content sits on the branch), but it is not landing, and the failure reads as **green** to `gh pr checks`.

## Three options recorded, none taken

1. **Approve each run** — unblocks one PR, not the next one 45 minutes later; workflow approval is a security gate whose purpose is that a human decides.
2. **Change the workflow-approval setting** — relaxes a security control.
3. **Give the lane a credential whose runs execute** (app token / PAT rather than `GITHUB_TOKEN`) — most durable, largest change, interacts with `credential-role-separation`.

Every option either relaxes a security gate or spends a credential decision, and both are maintainer-scoped. What an agent can do is name it, measure it, and stop.

It is also the **root cause** of a symptom already on file — *"a flush PR with an all-green head and `gate (required)` ABSENT never supersedes and must be closed by hand."* That note describes the deadlock; this row explains why it happens.
