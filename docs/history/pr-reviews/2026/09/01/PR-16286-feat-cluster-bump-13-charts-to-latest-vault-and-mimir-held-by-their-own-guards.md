## Description

Charts to latest before the next USB test. This is the batch whose upgrade path **a fresh install does not have to walk**.

## Method, not eyeballing

Every chart in the tree was rendered at **both** its pinned and its newest published version, using that Application's **own** `valuesObject`, and compared on two axes: did any value stop taking effect, and was any resource removed. Fourteen came back clean on both.

## One false positive, found and disproved

The checker reported kube-prometheus-stack losing `repeat_interval: 12h`. **It had not** — the alertmanager config moved into a base64 Secret, and a substring check cannot see through base64. Decoded it; the value is there.

## And a real defect in the snapshot mechanism — most of this diff

Bumping nats, headscale and node-feature-discovery turned **eight of this module's own tests red** — not because the charts broke, but because the schema snapshot was derived from the **live tree only**.

The fixtures in `testdata/inert-valuesobject-history/` are the four real Applications that motivated the guard, each judged against the chart version it was pinned at. The moment anyone bumps one of those charts, the pin falls out of the snapshot and the proof cannot run. The test **refuses to skip** in that case — correctly, since a proof that could not run must not read as one that passed. So a routine bump turns the module's own falsifiers red, and the cheap way out is to delete them.

`measureSchemaSnapshot` now measures the **fixture pins alongside the live ones**, into `charts` and deliberately *not* into `entries` (entries is what coverage is judged against, and a fixture is not an Application the cluster deploys). The proofs now survive every future bump.

**Without this, "get all charts to latest" and "keep the guard's falsifiers" were in direct conflict.**

Ten baseline acknowledgements embedded the chart version in their text and were carried forward — but only after the same run **re-confirmed each key still inert** at the new version. Two `infra/` entries were reverted: that tree was not bumped, and I had over-replaced them.
