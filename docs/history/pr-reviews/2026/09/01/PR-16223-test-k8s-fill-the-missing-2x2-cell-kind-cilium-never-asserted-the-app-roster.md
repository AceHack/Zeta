## Description

Four Applications never reach Healthy on the k3d lane (`vault`, `openziti-controller`, `trust-manager`, `spire`). `081M1DFQ2MZ087G0R000CMNHQX` asks whether that's the **CNI** or the **orchestrator** — and it turns out that question could not be answered from what exists, because of a hole in the coverage:

| CNI | orchestrator | app roster asserted | result |
|---|---|---|---|
| kindnetd | kind | ✅ `included` | green, 25 apps |
| Cilium | **k3s** (k3d) | ✅ `included` | 4 never reach Healthy |
| **Cilium** | **kind** | ❌ **never asserted** | ← this job |

`live-kind-cilium` proves Cilium comes **up** on kind and stops there — it runs `cilium-kind-up.ts` and never touches `argocd-health-test.ts`. So it was never able to settle this, and reading its green as evidence about the four would have been reading a check that never asked the question.

Running the **same `included` proof that is green on kindnetd** against a kind cluster whose CNI is Cilium changes exactly one variable against that baseline:

- **red ⇒ convicts Cilium**
- **green ⇒ convicts k3s**

Since metal runs k3s+Cilium, this is the answer that matters before hardware.

## Dispatch-gated on purpose — the part worth arguing

**Its expected first result is RED.** Wiring a known-red assertion into the PR/cron path would build a check that is red on every run — a check nobody reads. That is *precisely* the defect repaired hours ago in #16222, where a publisher disabled by decision had been reported as silent breakage on every `gate` run since 2026-08-29.

Rebuilding that defect deliberately, in the same session that fixed it, isn't a trade worth making. This runs by hand, answers its question, and gets switched off again.

## Design notes

- **Separate job**, not a step on `live-kind-cilium`: that lane's 30-minute ceiling is a real guard on a bring-up that should take ~15. Widening it to 90 to fit a 40-minute proof would weaken the guard on every ordinary run to serve an experiment that runs by hand.
- **`--existing` is load-bearing**: the cluster is already up *with Cilium*, and the harness's own kind path would bring up kindnetd and destroy the single variable this job exists to isolate.
- **Verdict table prints under `if: always()`** — on this job the red run is the informative one, and its output is the whole deliverable. Apps absent from scope render as `NOT ASSERTED IN THIS SCOPE` rather than as silence: three of the four produced no verdict line at all on kind, and **an absent verdict reading as a passing one is how this investigation nearly went wrong in the first place.**

## Blast radius

No existing lane's triggers, scope, or timeout is touched, and the new job cannot run without an explicit dispatch. `gate (required)` is the only required check, so this blocks nothing either way.
