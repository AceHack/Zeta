## Description

`drift (loud)` has been red on **every `gate` run on main since 2026-08-29** — 5/7 of the last runs — with one annotation:

> PUBLICATION NOT LANDING: `data/platform-drift.json` is pinned at run 33238368515 … **The tick computes and then throws the result away.**

**That sentence is false.** Nothing is being thrown away: `drift-sweep` is `state=disabled_manually` and was turned off on purpose.

## Re-enabling the publisher is NOT the fix — I measured before assuming

| | |
|---|---|
| ledger size | **238 KB**, rewritten in place |
| commits | **20 in two days** (11 on 08-28, 9 on 08-29) |
| all-history churn | **+33,497 / −26,435 lines** |
| trigger | every push to `main` **plus** a twice-hourly cron |
| ⇒ | **~4.7 MB of blobs in 48h** |

That is precisely the unbounded growth being held off until the repo split, and it's a cron-driven *writer*. **The publisher is correctly off.**

## So the defect is in the CHECK

A loud signal that is **always on** is a loud signal nobody reads — and it was crying wolf in the exact way that eats a real alarm later.

`drift-loud` had three ledger states (`absent` / `stale` / `fresh`) and no way to say *"the publisher isn't supposed to be running."* This adds that as a separate axis, probed from the workflow's own `state`, and makes the verdict a pure function of (what the file says, how old the window is, whether the publisher is on):

```
disabled + stale -> WARNING  "PUBLICATION OFF BY DECISION ... FROZEN at that run, not current"
active   + stale -> ERROR    (unchanged)
unknown  + stale -> ERROR    (unchanged)
```

## `unknown` is not permissive — that's the whole safety of this change

A probe that failed says nothing about the publisher. Treating *"could not look"* as *"off by decision"* would turn this repair into a **silencer for real breakage**. Same refusal as `Wall.Whitebox` (an unheld licence blocks rather than permits), and the same discipline as a failed API probe being `unknown` rather than a negative result.

The downgrade also never downgrades the **honesty of the surface**: the warning still says the dashboard is FROZEN, because a stale dashboard that looks live is the failure this job exists to catch. It reports the fact and lets the reader decide — it does not smuggle "broken" into a state that is merely "off".

## Falsifiers — the interesting ones are not the disabled case

- **ACTIVE + stale still errors** ← the anti-silencer branch
- **UNKNOWN + stale still errors** ← unknown is not permissive
- absent ledger errors under **all three** publisher states
- every `readPublisherState` failure path returns `unknown`, never a guess
- missing repo/token doesn't even look, and never reads as active
