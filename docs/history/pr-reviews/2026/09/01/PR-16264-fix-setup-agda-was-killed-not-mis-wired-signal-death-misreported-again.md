## Description

Running `install.sh` on the maintainer's machine today:

```
agda-cubical.sh: line 199: 65011 Killed: 9   agda ProvidedView/Hello.agda
error: cubical verify typecheck FAILED — lane is mis-wired (agda 2.8.0, cubical v0.9).
```

**The second sentence is false.** `Killed: 9` is SIGKILL — rc 137 — and the lane was wired correctly. The script treated *every* non-zero exit as a typecheck verdict, so a killed process was reported as a claim about agda and cubical **versions**, sending a reader to check pins that are fine.

## This is the same defect #16200 fixed for mise

There, a SIGSEGV surfaced as an empty version string and the lane was red for **38 hours** while every message pointed away from the cause. `linux.sh` already draws the line at `rc >= 128`; this puts that line where the second instance showed up.

## Three outcomes instead of two

| rc | meaning |
|---|---|
| `0` | the lane verified |
| `>= 128` | **KILLED by signal N** — says so, and says explicitly it is *not* a typecheck result and nothing about the wiring |
| otherwise | a real typecheck failure, message unchanged |

For signal 9 it names the likely cause instead of leaving you to guess: building the `Cubical.Foundations.Prelude` interface cache is the **memory high-water mark of the whole install**, SIGKILL there is the kernel reclaiming memory, and the cache persists so a retry starts further in.

## What this does not do

It does not make the lane pass and it does not retry. The run still fails — **it fails with a true sentence.**
