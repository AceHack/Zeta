## Summary

PR6 of the ZetaFS first-product sequence. File body is a Jumprope (Vokes 2012 / Pugh 1990) over FastCDC v1 chunks. ContentId is the trunk digest.

Successor of #16215 (close-and-rebranch: restack onto main + seek alloc cut. No force-push).

## Alloc (hot path)

Seek/pread is POSIX `read` of a frozen body:

- **In memory:** binary search on a prefix array built at freeze, then `ReadOnlyMemory` over the stored FastCDC payload.
- **Not on seek:** `ToArray` of the chunk, `ToHex` of ContentId, re-parse of trunk CBOR.
- CAS is keyed by `ContentHash256`, not 64-char hex strings.
- CBOR skiplist remains the durable encoding / ContentId. `seekEncoded` walks it so tests prove the two agree.
- Freeze/build may allocate (CAS objects, leaf index; FastCDC already copied each chunk).
