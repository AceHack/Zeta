## Description

## What

`install.sh` provisioned four launchd cells **by default** on macOS. The escape was `ZETA_SKIP_CELLS=1`, and `grep` finds **no setter for it anywhere in the tree** — so the default was the only path anyone took.

Running the *toolchain* installer therefore also installed background agents, writing to four roots outside the repo you cloned:

| root | what |
|---|---|
| `~/.zeta/clones/<cell>/` | an isolated git clone per cell |
| `~/Library/LaunchAgents/com.lucent.zeta.*` | the launchd jobs |
| `~/Library/Logs/zeta-<cell>-loop/` | runner logs |
| `~/Library/Application Support/Zeta*Loop/` | per-cell state |

Installing background agents is a separate decision from installing a toolchain. It now takes `ZETA_PROVISION_CELLS=1`, the skip path prints how to opt in, and the block lists the roots inline — because the surprise being removed is *not knowing where the files went*.

## The falsifier, and the bug it caught in itself

`install-cells-are-opt-in.test.ts` — 6 tests, and the scanner is **shared** between the assertion and its three mutants (old opt-out default restored · guard deleted · bootstrap call gone).

The first draft classified by if-nesting position — *"the second-to-last `if` before the call"* — a guess about nesting depth. The opt-out mutant read as `unconditional`, so **the mutant caught a real defect in the control before the control ever guarded anything.** It now classifies by the env comparison itself, which also means the `ZETA_PROVISION_CELLS=1` text in the comment and the echo cannot satisfy it.

## Not in this PR

Measured while answering the question, filed rather than fixed here:

- Zeta state is spread across **`~/.zeta`, `~/.config/zeta`, and three `~/Library` roots**. Consolidating them moves **CA private keys** (`~/.config/zeta/ca/`) and wants a tested migration with a fallback, not a `sed`.
- **Two launchd naming conventions are live at once** — `com.zeta.*-loop` and `com.lucent.zeta.*-loop` — with both spellings on disk for `lior`.
- Of the loops with plists on disk, **four are alive** (alexa, lior, otto, vera — logs written today); the rest last wrote in **May/June**.
- `~/.zeta` is **126 GB**, 118 GB of it harness installs under `~/.zeta/agents` (codex 63G, otto-cli 18G, gemini 12G). Nothing prunes it. Not touched here — deleting 118 GB is not a side effect of a PR about an install flag.
