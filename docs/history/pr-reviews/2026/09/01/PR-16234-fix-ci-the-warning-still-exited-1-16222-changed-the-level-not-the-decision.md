## Description

#16222 taught `stalenessVerdict` to return a **warning** when the drift publisher is off by decision, and the annotation duly changed from `::error` to `::warning`. Measured on main at `d1b67ea6`, **with that fix present**:

```
[warning] drift publication is off by decision: PUBLICATION OFF BY DECISION...
Process completed with exit code 1.
```

The message was right and the job was still red, because the exit decision read:

```ts
const red = ... || stale !== null;     // `stale` is verdict?.message
```

**A warning has a message.** So half the fix landed and looked whole, and `drift (loud)` went on being red on every gate run — the exact condition #16222 was written to end.

## My own falsifiers went straight through it

#16222 shipped **five mutation-tested falsifiers** on `stalenessVerdict`, and every one of them passes against this bug — because all five tested the **function** and none tested its **consumer**.

> A verdict's severity is decorative until something that acts on it reads it *as* severity.

So the decision is now a named, pure function — `runIsRed(sustainedCount, livenessStatus, verdict)` — specifically so it can be falsified. Being untestable in place is *why* it was wrong.

## Verified — and the limit stated

Live against this repo, the publication line is now `::warning` and the drift table reports **`0 at ::error::`**.

I could **not** reproduce a green exit locally. The one remaining `::error` is `detector went quiet`, which fires because the liveness canary can only be exercised by the run observing *itself*, and a local invocation isn't that run. That's a local artifact, not this change — but it means the green exit is verified **by unit test and mutation, not by a local end-to-end run**. CI is what confirms it.
