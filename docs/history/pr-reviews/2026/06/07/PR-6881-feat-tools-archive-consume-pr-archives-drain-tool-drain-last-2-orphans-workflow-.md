## Description

Aaron 2026-06-07 (picked 'build a batch-consume tool'). The pr-archive-on-merge workflow orphans archives
because GitHub Actions cannot open PRs — and the block is ENTERPRISE-level ('the enterprise does not allow
GitHub Actions to approve pull requests', 409), not org. Rather than relax an enterprise-wide security
control (Actions self-approving PRs — plausibly a liability increase, excluded from my authority), this tool
is the drain: a human/agent (who CAN open PRs) runs it to consolidate pending automation/pr-archive-*
branches into main, then opens a normal PR. Extracts ONLY each branch's archive .md + manifest line (never
the stale branch diff), dedups by pr_number, verifies, optional --delete after preservation. Idempotent;
bun/TS (matches tools/archive/, aligns bash-retirement); tsc-clean.

Also drains the last 2 orphans (PR #6879/#6880 — this rescue's own archives): manifest 4208->4210.
Bulk-deletion of the prior 4029 (all verified on main) already done out-of-band.
