## Description

Aaron 2026-06-07: 'single-core CPU + parallel-optimized algebras for the same algebra, combinations in
between, all relevant'; 'avoid ifs everywhere so it's easy to switch parallel-soft <-> serial-sharp'; 'our
DUs would be the algebras in between'; 'consensus or crdt like flows.' Principle: ONE algebra interface,
many target-optimized impls ({sharp,soft}x{serial,parallel,hybrid}), selected by PASSING a different
instance, never by if/match at the call site -> branch-free (shader-friendly) + scale-free (manifesto §1,
the DoP knob). This is why instance-passing ISemiring beats .NET static-abstract (which bakes one impl per
type, can't swap). The DUs encode the in-between: a DU whose cases merge by a join-semilattice = CRDT-like
(parallel, AP); one needing total order = consensus-like (serial, CP) — the CommutativeView/SerializedSaga
lanes, chosen by structure not ad-hoc ifs. Honest gap: Result vs Sat have different return shapes -> one
interface per return-shape family (build pending that fork). Anchors: typeclass-as-dictionary, GraphBLAS,
BLAS/MKL/cuBLAS, confluence theorem.
