## Description

## Symptom

A Windows-flashed node (`node-09485d`) ran self-registration during install on 2026-06-07, **pushed a `register-node-09485d-*` branch**, but the branch had **0 commits**, **no PR** was opened, and the operator got **no error**. Meanwhile the *same code* registered cleanly for other nodes the same week.

## Root cause (installer-side, not the flasher)

Step 6.9 staged the manifest, committed an **empty tree** (nothing was staged), then ran `git push -u origin "$REG_BRANCH"` **unconditionally** — pushing an orphaned branch at the clone's HEAD. Only the downstream `gh pr create` failed (*"no commits between main and …"*), and that was swallowed as a `WARN` by `set +e` + the subshell `|| true`.

Confirmed **not** a Mac-vs-Windows flasher difference: both flashers inject only the SSH pubkey for this path (and normalise CRLF→LF); Step 6.9 resolves the maintainer fresh via `gh api /user` on the node regardless of how the USB was flashed. Nothing the Mac flow optionally bakes (creds/hostname) feeds registration. The empty-staging was a transient/edge glitch on that one install — but the installer turned it into a **silent, branch-orphaning, no-signal** failure.

## Fix (hardening, all in Step 6.9)

- **Verify `node.yaml` exists + is non-empty** before staging (`test -s`); abort if not.
- After `git add`, **confirm something is actually staged** (`git diff --cached --quiet`) before commit/push; if empty, emit diagnostics (maintainer, node, dir, `ls -la`, `git status --porcelain`) and **abort — push nothing**.
- Defense-in-depth: **only push when a real commit exists** ahead of the clone base (`git rev-list --count HEAD ^origin/main >= 1`).
- If `gh pr create` fails after a push, **delete the just-pushed branch** so it's never orphaned.
- Replace the vague trailing `WARN` with a **loud, boxed "this node is NOT registered"** message + post-boot remediation.

**Net:** registration either succeeds, or it **fails loudly with the trigger visible and no orphaned branch** — instead of silently stranding the node. `bash -n` clean.

## Note

This does not change the *success* path (which already works — see other nodes registered the same week), so on reinstall the node will most likely register normally; if it hits the edge again, you now get a clear error + diagnostics instead of silence.
