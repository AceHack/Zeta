## Description

Aaron: "we can do password management via S=4 coincidence — the auth-app rolling code."

The staged-coincidence generator (`BellTest`/`CoincidenceClock`) reused as a **rolling-code authenticator** (TOTP-like): shared secret = the common-cause ZetaId seed; time step = `ZetaDateTime`; the **rolling code = the staged coincidence value at time t** (both sides stage the same from the shared seed); verify = the coincidence matches. **No secret transmitted** (shared-cause → same value; attacker without the seed sees the random floor). Reuses the coincidence generator + composes with the keyring + privacy gate.

**Honest peel (crypto is governed — not claimed):** this is the idea, not a security claim. Soundness depends on seed secrecy + the staging being an unpredictable PRF of seed+time + replay/clock windows. **Routed to the security team (Mateo/Nazar) + governed crypto** to evaluate vs TOTP/HOTP (RFC 6238/4226); do NOT ship as "secure."
