## Description

## What

The complete WorkspacePort interface covering every git operation found in the codebase, plus multi-home (link) and merge-base (LCA). Parameterized conformance tests prove both backends implement the same contract.

### Interface surface

| Category | Operations |
|----------|-----------|
| Content | readFile, writeFile, exists, readDir |
| Multi-home | link (symlink on os-fs, DAG edge on zeta-fs-native) |
| VCS | currentBranch, branch, stage, commit, push, pull |
| History | readFileAt(path, ref), history(path?, n?), blame(path), diff(from?, to?), mergeBase(a, b) |
| Escape | git(args) — legacy, exec(cmd, args) |

### Key design decisions

- **mergeBase** = LCA in the commit DAG. On polyfill: `git merge-base`. On zeta-fs-native: Merkle ancestor lookup.
- **link** = multi-home primitive. On os-fs: symlink. On zeta-fs-native: DAG edge (content hash gets another parent).
- **Schema is a Z-set.** Filesystem metadata (permissions, paths, hashes, timestamps) is itself a Z-set entry. Schema evolution = a delta on the schema Z-set. The conformance suite proves backward-compat.
- **1 file ≠ 1 Z-set.** A file is a container; the db = fold(all containers) via Rx joins.

### Conformance suite

30 tests × 2 backends (simulated + real os-fs with git). Adding a backend = one factory entry → all 15 assertions run automatically.
