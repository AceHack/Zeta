## Description

## Diagnosis (run #403)

- Phase 1: **green** (iter-5.3/WIPE fix works; hostname generated e.g. node-e207b2)
- Phase 2: **timeout** waiting for login; **serial artifact was 0 bytes**

Root cause: installed nodes use **systemd-boot (UEFI)** per common.nix, but phase 2 QEMU used legacy `-boot c` without OVMF — the disk never booted, so no serial output and no login prompt.

## Vera #8324 (already on main)

Adds `detectUnexpectedControlPlaneLogin` — **detection only** for B-0835 Bug 1 (fail fast if `control-plane login:` appears when a generated hostname was expected). Does **not** fix the empty-serial boot failure; complements this change once UEFI boot works.

## Fix

- Phase 2: attach OVMF_CODE/OVMF_VARS pflash drives on q35
- CI: apt install `ovmf`
- Clearer timeout hint when phase-2 serial is empty
