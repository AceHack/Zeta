## Description

Re-lands the BCL-interface corrections the maintainer flagged on the pool/lock entries (2026-06-01: *"IObjectPool — is dotnet not having a good object pool like this yet? … RAII lock-scope guards prob can be improved since dotnet moved away from locks on objects to a real lock type and i think it does not use Monitor anymore"*).

These corrections raced the auto-merge on #6398 (it merged on the original capture commit before the follow-up landed), so this PR carries the delta onto current main. **Verified via Microsoft Learn (search-first):**

- **Object pool → mostly BCL.** `Microsoft.Extensions.ObjectPool` (platform-tier) already gives `Get`/`Return` + factory (`PooledObjectPolicy.Create`) + reset (`IResettable`) + **validate-on-return** (`IPooledObjectPolicy<T>.Return(T) : bool` → `false` discards instead of pooling — the "is this still alive?" knob I'd mis-called net-new) + retain-cap + DI; `System.Buffers.ArrayPool<T>` for arrays → **depend, don't re-mint**. Net-new = the **bounded-blocking** variant: the docs say it *"caps retention, not allocation"* and `Get` never blocks (creates-on-empty), so the wait-when-exhausted / connection-pool semantics are the only genuine gap.
- **RAII locks → sync scope is BCL now.** .NET 9 `System.Threading.Lock`: `lock(Lock)` lowers to `using (x.EnterScope())` returning a `Lock.Scope` `ref struct` (`Dispose()` exits), **not `Monitor`** → depend, don't re-mint. Wrapper value narrows to **reader/writer** (`ReaderWriterLockSlim` has no built-in RAII scope) + **async** (`Lock` can't cross `await`, CS9217 → `AsyncLock` over `SemaphoreSlim(1)`).

Both remain `⬜` wish-list markers; concept-not-code; lineage preserved.
