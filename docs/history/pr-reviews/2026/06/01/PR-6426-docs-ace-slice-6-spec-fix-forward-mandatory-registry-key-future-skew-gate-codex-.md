## Description

Fix-forward for two Codex findings on the slice-6 spec (#6424, merged), folded in **before** the build (the #6414 precedent):

- **P1 (mandatory registry key):** dropped the any-trusted-key fallback. The trust store is the *global package-signing* keyring with no registry role separation, so any package author's key could sign a catalog and steer this registry's version selection. `--key` is now **required** (`key_id` required in `RemoteRegistryConfig`; `add` without `--key` is a parse error); the index `signature.key_id` must equal the pin **and** be trusted. Full trust-store role separation stays deferred to the TUF-roles row.
- **P2 (future-skew gate):** added a max-future-skew bound (default 5 min) to freshness. A far-future `issued_at` makes `now − issued_at` negative so the past max-staleness check passes trivially — a skewed/compromised signer could publish a future-dated high-sequence index accepted for years. Future-skew is **always** enforced (incl. `--offline`); only the past-staleness gate is skipped offline on cache.

Spec sections updated: Decision 1 + 4, index components (`RemoteRegistryConfig`, `verifyIndex` gates), error-handling table, testing. markdownlint clean.
