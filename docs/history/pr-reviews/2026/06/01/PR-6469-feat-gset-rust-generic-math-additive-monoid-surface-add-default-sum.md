## Description

## What

Rust slice of the **numerics-ladder → generic-math** retrofit (after F# #6467, C# #6468). G-Set is an additive, commutative + idempotent monoid, so per the rule it surfaces the **native Rust idiom** — `Add` (the `+` operator) + `Default` (the `Zero`/identity analog) + `Sum` (fold a collection) — never `Sub`/`Neg`/`Mul`. **Zero-dep** (std/core only; no `num_traits`, per the zero-prod-dep doctrine).

## Key design call: ref-operator, not by-value

`Add` is implemented for **`&GSet<T>`** (`&a + &b`), **not** `GSet<T>` by value. The type already has an inherent `add(&self, x: T)` (add ONE element); a by-value `Add for GSet` makes `Add::add(self, Self)` win method resolution over that inherent method for owned receivers — which **silently broke the existing `s.add(element)` test** (confirmed E0308 before the switch). The ref-operator is the idiomatic Rust form for non-`Copy` collections and keeps **both** the union-`+` and the element-`add`.

- `impl Add for &GSet<T>` → `&a + &b` = union
- `impl Default for GSet<T>` → `default()` = empty (additive identity)
- `impl Sum for GSet<T>` → `iter.sum()` folds via the monoid
