## Description

Your observation (2026-06-01): _"reticulum and zetaids are both 128 bit"_ + agreement on the name-address split. Captured on the **Discovery/transport** line:

- Both are **16 bytes** → a ZetaId fits a Reticulum destination slot exactly (same `<hex32>` display).
- But derivations differ: ZetaId is **structured / decodable**; a Reticulum destination is a **truncated SHA-256 of the node's public key** (self-authenticating routing).
- So bridge as **name ↔ address**: ZetaId = stable readable **name**; Reticulum destination = key-bound **address**; announce the `ZetaId → destination` mapping over the discovery layer (Nostr/DHT). Keeps ZetaId's structure **and** Reticulum's self-auth — vs. fusing a pubkey-commitment into the ZetaId, which would eat the whole 128-bit budget.
- Composes the **Identity** + **Comms/Bus** lines — a ZetaId-keyed bus routing over Reticulum mesh.

Docs-only; prettier + markdownlint clean; BACKLOG.md untouched. Edits the Discovery line (region 41) — non-overlapping with #6379 (47-49+EOF).
