## Description

Third decode oracle — **Rust `DynamicValue::from_canonical_cbor(&[u8]) -> Result<DynamicValue, DecodeError>`**, inverse of `to_canonical_cbor`, all 8 shapes. New `DecodeError` enum + `Display` + `std::error::Error` (public API), mirrors C#/F#. float16 decodes by reusing the encode side `f16_to_f32`.

**Strictly canonical** via the same fixed-point check as the C#/F# oracles (#6512/#6514): after a structurally-valid decode it asserts `to_canonical_cbor() == bytes` → `DecodeError::NonCanonical` otherwise. One check rejects non-shortest int/length widths, non-shortest floats / non-canonical NaN, and invalid UTF-8 repaired to U+FFFD. Per-form readers stay lenient; the wrapper is the enforcement point.

**Cargo test/clippy/fmt green:** `cbor_decode_cross_verify` round-trips all 42 seed vectors (decode → re-encode == seed; structural == expected, skipping the NaN vector since Rust `f64` NaN != NaN) + a decode-rejection unit test (incl non-shortest int/width, invalid UTF-8, non-canonical NaN, 1.0-as-f32, 1.0-as-f64).

Sequencing: C# (#6512) + F# (#6514) + **Rust here** → TS CBOR decode → JSON decode ×4 → 081KT07NV0008QG0R0032MCYER multi-format seeds.
