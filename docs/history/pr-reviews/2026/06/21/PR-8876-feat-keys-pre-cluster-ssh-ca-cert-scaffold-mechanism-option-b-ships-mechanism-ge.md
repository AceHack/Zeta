## Description

## What

Option B of the unified key-onboarding workitem (`081KVM1TK3Z08QG0R0002959G6` §"Trust distribution" + §"Pre-cluster bootstrap"): a **real-but-minimal SSH Certificate Authority**, git-distributed, that replaces the `operator-ssh-keys.nix` authorizedKeys **LIST** (the N×M trap) with **one CA pubkey** fed to `TrustedUserCAKeys` + **per-machine signed certs** (`principal=<user>` + machine id + validity window). Forward-compatible: same trust *model*, custody upgrades to Vault + cert-manager later. **git is the distribution channel, never the secret store.**

**This PR ships the MECHANISM only — it generates NO real CA and commits NO real CA key. CA-keypair generation stays operator-run.**

## The 5 parts (reuse the machine.ts injected-effects seam — no reimplementation)

1. **`ca.ts ensureCa`** — generate/recognise the SSH-CA keypair via the injected `CaEffects.genCa` door (CA private written **local** under umask 077 by the runner; **only the PUBLIC key** returned/printed). `--commit-pub` writes ONLY the CA pubkey to `maintainers/<ca>/ssh-ca.pub` (no git commit). `--dry-run` generates/writes NOTHING. Idempotent.
2. **`ca.ts signMachineCert`** — sign a per-machine device **PUBLIC** key into a cert (`ssh-keygen -s -I -n -V`) via the injected `signCert` door; reads the machine pubkey from machine.ts's `publishPubPath` seam. Fail-closed: `no-ca` / `no-device-key` are typed no-ops. `--dry-run` signs NOTHING.
3. **`ca-cli.ts`** — thin shell (`ca` / `cert` modes); CA private + seed never to argv/stdout/git; only the CA pubkey + certs (public) printed.
4. **`full-ai-cluster/nixos/modules/ssh-ca.nix`** — NEW, **additive + inert**: sets `TrustedUserCAKeys` to the committed CA pubkey ONLY when present (`pathExists` guard). `operator-ssh-keys.nix` **unchanged**; module **NOT wired** into any node config (activation = operator step).
5. **`onboard.ts` tie-in** — OPTIONAL flash-time cert-sign (`--sign-with-ca`); delegates to ca.ts; **reuse-only**; skips cleanly when no CA is configured (`fx.ca` absent → no step) or no CA private key (`no-ca` → recorded skip). onboard's existing reuse-only / no-secret property preserved.
