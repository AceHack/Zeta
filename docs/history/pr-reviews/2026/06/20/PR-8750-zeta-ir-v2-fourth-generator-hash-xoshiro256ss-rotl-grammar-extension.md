## Description

## What

The **fourth** generated-from-IR oracle: `hash.xoshiro256ss` — the xoshiro256\*\* output scrambler `rotl(x*5, 7) * 9`. It is the **first** generator that needs an op **outside the frozen v1 `mul`/`xorshr` vocabulary**: `rotl` (rotate-left by a constant) wraps the top bits back to the bottom, which neither `mul` (carries propagate only upward) nor `xorshr` (bits move only downward) can express. Because it **breaks the v1 grammar**, it ships under a **new frozen schema tag, `zeta-ir-v2`**.

## How

- **`src/Core/ZetaIrV2.fs`** — new `ZetaIrV2` module: extends the grammar with `Rotl`, owns the frozen `zeta-ir-v2` tag, validator, canonical-JSON emitter, the `xoshiro256ss` row, and a `v1 → v2` widening (`ofV1`). Firewall: the **v1 validator rejects v2** artifacts; the **v2 validator accepts both v1 and v2** ops.
- **`src/Core/GeneratorIrRegistry.fs`** — `xoshiro256ss` (v2) row registered in `known` alongside splitmix64 / fmix32 / fmix64.
- **`tests/cross-verification/xoshiro256ss/`** — a 6-language **N-way** oracle (TS, F#, C#, Go, Python, Rust — independent hand-ports, no shared proof logic), `vectors.yaml` with 10 goldens, `compare.ts`, and an **IR-driven `gen-ir.test.ts` fidelity self-test** in which a corrupted constant, a corrupted **rotate amount** (`rotl 7 → 8`), a **dropped `rotl`**, or a wrong width each turns the green red (Sybil guard).
- **F#** `ZetaIrV2.Tests` (conformance, golden byte-lock, v1↔v2 firewall both directions, `rotl` necessity, widening) + a `GeneratorIrRegistry` byte-lock row.

## External anchoring

Constants and the scrambler form are from the **Blackman & Vigna** public-domain reference (`prng.di.unimi.it/xoshiro256starstar.c`): `result = rotl(s * 5, 7) * 9`, all wrapping `uint64`. Goldens were independently recomputed and matched the committed vectors exactly.
