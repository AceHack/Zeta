## Description

## Diagnosed live on node-09485d

A "fresh" single-node cluster (nothing user-deployed) was sitting with **cert-manager crash-looping 869×/3d** and **~20 Pending pods**. Two gaps in the bootstrap code — neither caused by any user action; the GitOps root-app just deploys the catalog onto a substrate missing two prerequisites.

## Fixes

1. **Gateway API CRDs were never installed.** Cilium (`gatewayAPI.enabled: true`) does **not** ship them, and cert-manager runs with `ExperimentalGatewayAPISupport` → fatal crash `"the Gateway API CRDs do not seem to be present"` → no TLS → cascade. Vendored the pinned **v1.2.1 standard** CRDs into `k8s/bootstrap/gateway-api-crds.yaml` and wired them as the **first** k3s auto-manifest (`aa-` prefix), before Cilium + cert-manager.
2. **local-path-provisioner v0.0.30 crashed** `"invalid empty flag helper-pod-file and it also does not exist at ConfigMap"` — the ConfigMap was missing the `helperPod.yaml` key the helper-pod model requires. Added the minimal busybox helper pod so the default StorageClass provisions.

## Live result

Applied the CRDs out-of-band on node-09485d → **cert-manager recovered to `Running`, 0 restarts** immediately. This PR makes both durable for fresh installs.

## Notes

- The duplicate-default StorageClass seen live is pre-existing drift from before `--disable=local-storage` landed; the repo is already correct (k3s-server.nix:72).
- Separate, still-open: the platform images are **private** on GHCR (401) — that needs a one-time visibility flip (no REST API for it); the repo has zero `imagePullSecrets` by design, so public is the design-consistent answer.
