## Description

## What

Per Aaron 2026-06-03 — *"only proofs that actually verify our code against our claims; no bullshit math tests"* — the C13 **"Tick is the (ℕ,+,0) commutative monoid"** FsCheck property is removed.

`tick` is a phantom `[<Measure>]` on .NET `int` (`Window.fs`). The monoid laws of `int<tick>` addition (assoc/identity/commut) **are .NET integer arithmetic** — code we did **not** write — so a runtime FsCheck of them verifies the BCL, not Zeta. That's exactly the failure class: *true, but mapping to no claim about our code's behavior.*

The UoM's real, sole guarantee is **compile-time** unit separation (`tick + ms` does not compile) — enforced by the type system, needing no runtime proof. The tick *as the stream index* is already exercised by every operator property (they drive the circuit tick-by-tick via `Step()`).

C13's substantive content is untouched: `D∘I` / `I∘D` / `z⁻¹` / `D=1−z⁻¹` / `I=running-sum` (FsCheck on the real Circuit) + the Z3 telescoping operator-inverse identities — **each verifies a real `FactorGraph`/`Incremental` claim.**
