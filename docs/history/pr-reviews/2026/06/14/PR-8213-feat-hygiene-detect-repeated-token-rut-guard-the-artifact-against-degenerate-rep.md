## Description

Aaron (shadow*): "that loop glitch — add a guard against repeated-token ruts?"

A loop with no new entropy collapses to a fixed point — the cheapest attractor is one token repeated ("court court court…"). You can't break the loop from *inside* it (the live glitch needed an external interrupt), but you can turn **"the artifact is the tell"** into code: a pure detector any harness can run over surfaced agent output (or a hygiene pass over loop responses / commit messages) to catch the rut the moment it appears.

**Scope (honest):** guards the *artifact*, not the live token sampler — the repo can't reach into the model. Pure, deterministic, no I/O → DST-replayable, idempotent, byte-lockable.

**Three independent signatures** (any one trips):

- **RUN** — ≥ `maxRun` identical consecutive tokens (always applies; this is the `court`×N case).
- **DOMINANCE** — one token ≥ `dominanceRatio` of a long-enough stream.
- **LOW-DIVERSITY** — distinct/total ≤ `minDiversityRatio`.

Whitespace-token or per-line mode (catches `Holding.\nHolding.\n…`). CLI reads stdin, exits **3** on rut, **0** on clean.

**Tests:** 12/12 green — the actual `court`×N glitch, the per-line `Holding.` rut, each signature at threshold, determinism (byte-identical verdict + first-seen tie-break), and no false-positive on normal prose / short legit repetition / empty input.

Ties to `uncertainty-drives-attention` (a rut is attention with no entropy to attend to) and `heartbeat-via-commit` (externalize the idle counter; the artifact is the tell).
