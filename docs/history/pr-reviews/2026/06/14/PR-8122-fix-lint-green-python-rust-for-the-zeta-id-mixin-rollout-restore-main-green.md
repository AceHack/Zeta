## Why

Final languages in the multi-language lint cleanup (after #8113 markdownlint, #8117 Go, #8120 C#). The lint job **short-circuits at the first failing language**, so Python + Rust were masked behind Go/C#; fixing those unmasked these.

## Rust — `Core.Rust.ZetaId` failed to **compile** (39 errors, same root cause as Go #8117)

- `bit_layout.rs` (hand-written consumer): generated `*_OFFSET`/`*_WIDTH` constants are the `Bits` newtype (over u32); `BitField.offset/width` are `u32`, and Rust has no implicit conversion. Appended `.0` at the consumer (incl. the `o += *_WIDTH` add-assign). Durable — not the regenerated `.gen.rs`.
- `zeta-id-generator.ts`: emit a doc comment on `pub struct Bits` so clippy's `-D missing-docs` (previously masked by the compile errors) passes; regenerated `bit_layout.gen.rs` (clean diff — just the one doc line).
- `TriBoolean/float.rs`: `cargo fmt`.

## Python — `mixin.py` (from #8115)

- `ruff format` on the three rollout files.
- `mypy`: annotate `WeakMap._dict` and the two test `map_instance` bindings.

## Verified with the CI toolchains

`cargo build` + `clippy` + `fmt` clean (strict `-D warnings`), `ruff check` + `format` + `mypy` clean, `tsc` clean.

## Root cause (worth addressing)

The #8087 6-language zeta-id codegen + #8115 mixin landings were merged **without running the per-language formatters/compilers locally**, and the gate's lint job stops at the first failing language so each red hid the next (this is the 4th PR to clear them one by one). **Recommend a pre-merge local lint pass for multi-language rollouts** so this stops reddening main.
