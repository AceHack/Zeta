## Description

## Summary
Stack-independent DB scaffold for the factory-demo. Standard Postgres + one-command docker-compose + dockerized smoke test.

### What lands
- `schema.sql` — Postgres 14+ DDL: customers / opportunities / activities. Money as BIGINT cents, TIMESTAMPTZ throughout, `updated_at` trigger on customers + opportunities for last-modified bookkeeping.
- `seed-data.sql` — 20 trades-contractor customers, 30 opportunities (5 stages), 33 activities, 2 intentional email collisions. Row counts / keys / amounts are deterministic; activity timestamps use `NOW() - INTERVAL 'N days'` so the data looks recent on every load (not a determinism bug — documented in README).
- `docker-compose.yml` — one-command Postgres startup with schema + seed auto-applied via docker-entrypoint-initdb.d. Named volume for persistence. Healthcheck via `pg_isready`.
- `smoke-test.sh` — verifies seed shape after docker-compose up (row counts, duplicate pairs, per-stage counts). Uses `docker-compose exec` so no host psql needed. Includes pg_isready readiness-wait loop (30s budget) before running checks.
- `README.md` — framing (software-factory demo, not DB pitch), endpoint table, design notes, open questions for Aaron.

### What this does NOT do
- No Zeta / DBSP / retraction-native language exposed to the factory-demo audience (per the positioning directive)
- No wiring to the API layer (in-memory APIs are separate PRs #146/#147)
- No app-behavior triggers beyond `touch_updated_at` last-modified bookkeeping
