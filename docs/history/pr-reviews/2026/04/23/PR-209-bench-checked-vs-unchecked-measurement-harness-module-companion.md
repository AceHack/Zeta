## Summary

Companion benchmark harness for the production-tier Craft module at `docs/craft/subjects/production-dotnet/checked-vs-unchecked/module.md` (PR #208). Proves the module's ≥5% throughput-delta gate claim with runnable measurements; seeds the per-site audit BACKLOG row (PR #207) with concrete numbers instead of vibes-perf.

## What landed

- `bench/Benchmarks/CheckedVsUncheckedBench.fs` (~100 lines, 0 warnings)

## Three scenarios

| Scenario | Models | Class |
|---|---|---|
| `SumScalar{Checked,Unchecked}` | NovelMath.fs:87 + CountMin.fs:77 counter increments | bounded-by-workload |
| `SumUnrolled{Checked,Unchecked}` | ZSet.fs:289-295 4×-unroll partial sums | SIMD-candidate |
| `MergeLike{Checked,Unchecked}` | ZSet.fs:227-230 merge-inner predicated add | unbounded stream sum (keep Checked) |

`[<MemoryDiagnoser>]` + `[<Params(1M, 10M, 100M)>]` sizes. Baseline-tagged on `SumScalarChecked` so BenchmarkDotNet emits per-scenario ratios directly.

## Why include the keep-Checked site

Measuring the cost we're paying for correctness is honest. The numbers settle per-site demotion debates — instead of "the comment says keep Checked", reviewers see exactly how many ns/op the correctness guarantee costs. Prevents future pressure to demote the canonical unbounded-stream-sum site based on fuzzy-feel arguments.
