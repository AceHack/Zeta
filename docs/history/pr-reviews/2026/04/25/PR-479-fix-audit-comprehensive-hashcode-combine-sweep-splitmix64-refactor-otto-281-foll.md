## Description

## Summary

Per Aaron 2026-04-25 pushback on PR #478's *"out of scope: 4 other \`HashCode.Combine\` sites... separate audit can sweep them if/when they become a problem"* framing — that's exactly the deferred-bug pattern Otto-281 just memorialized. This PR addresses the full sweep + a related refactor.

## Triage outcomes

**Bug fixed:**
- \`Shard.OfFixed\` — name said "stable across restarts" but used process-randomized \`HashCode.Combine\`. Now uses \`XxHash3.HashToUInt64\` on key's hash bytes. **Caveat**: for value types fully deterministic; for string keys still relies on \`string.GetHashCode()\` (which is process-randomized in .NET Core+). New \`OfFixedBytes(bytes, shards)\` overload added for callers needing string-key cross-process determinism (pass UTF-8 bytes).

**Documented as intentional non-determinism:**
- \`Shard.OfKey\` — HashDoS defence requires per-process random salt. Trade-off doc-comment added.
- \`Sketch.fs::HyperLogLog.Add\` — perf trade-off (avoid 1M Gen-0 allocs). Process-randomization caveat added; points to \`AddBytes\` for deterministic variant.
- \`NovelMathExt.fs::InfoTheoreticSharder.Pick\` — load-distribution flexibility on cold start. Cold-start vs post-warmup determinism contract documented.

**Test-side fix:**
- \`CountMin.Tests.fs\` — \`HashCode.Combine("x")\` → \`detStringHash\` helper using \`XxHash3\` on UTF-8 bytes (same pattern as Otto-281's \`detHash\` in \`Sharder.InfoTheoretic.Tests.fs\`).

## SplitMix64 refactor (Aaron 2026-04-25 directive)

Aaron: *"we are using the same constants over and over we should refactor them into a common place for reuse."*

Three sites repeated the same SplitMix64 finaliser constants (\`Sketch.fs\`, \`FastCdc.fs\`, \`ConsistentHash.fs\`). Plus a fourth use in \`CountMin.Tests.fs\`. Extracted to \`src/Core/SplitMix64.fs\` — one module with three documented \`[<Literal>]\` constants + one \`mix\` function. Each constant has its provenance:

- \`GoldenRatio = 0x9E3779B97F4A7C15\` = \`floor(2^64 / phi)\` — Knuth TAOCP §6.4 multiplicative hashing.
- \`VignaA = 0xBF58476D1CE4E5B9\` + \`VignaB = 0x94D049BB133111EB\` — Vigna's SplitMix64 finaliser-pair multipliers from [arxiv 1410.0530 §3](https://arxiv.org/abs/1410.0530), validated against BigCrush.

All 4 call sites updated to use \`SplitMix64.mix\`. 57 affected tests pass.
