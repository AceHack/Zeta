## Description

## What this is

`frost-reshare.ts` (#10654) **cannot revoke**, and not by omission: preserving `groupPublicKey` byte-identically is exactly what keeps old shares able to sign. Its own RS-7 asserts this and its only remedy is *"the holder destroys the old share"* — a request, not a security property.

> Aaron 2026-08-14: *"we can assume if they use our software it will be destroyed but not if they fork."*

**You cannot revoke a share and keep the group key. Revocation is a key change.** The only open question is whether it costs a cold re-pin at every relying party — and at 20 sites that cost is what makes rotation too slow to do promptly, which is the actual vulnerability.

## The three pieces, composed

**1. Delta rotation** (`frost-delta-rotation.ts`). Contributing holder `i` uses `g_i(0) = u_i + δ_i`, so `H(0) = secret + δ` and `A' = A + [δ]B`, with `δ` a joint random secret no party knows. One extra published point per contributor, `Δ_i = [δ_i]B`, makes it checkable by a party holding nothing but the **old** key:

```
Σ ( C_i[0] − Δ_i )  ==  A      the rotation targeted THIS key
A'  :=  Σ C_i[0]               the new key is DERIVED, never asserted
```

Set every `δ_i = 0` and it degenerates term for term into `frost-reshare` — reshare is the `δ = 0` point of the family, **asserted as DR-2**, not claimed in prose.

**2. Revocation as a G-set** (`key-epoch-ledger.ts`). CRL/OCSP/CT share a shape they rarely name: you only ever *add* a revocation. `src/Core.TypeScript/g-set` is used **verbatim** — no list format was invented. It converges under exactly the partition that breaks OCSP, which needs an online responder. `BoundedGSet` is deliberately not used: evicting a revocation is a re-exposure.

**3. The 20-site protocol** — stages, budget, and measured crypto in the research doc.

Belt and braces, not competitors: **delta rotation makes old shares mathematically dead; the G-set makes verifiers learn about it under partition.**

## The security argument

Adversary with `t−1` old shares + the whole public transition **can** verify it and compute `[δ]B` (obtainable from `A` and `A'` anyway). It **cannot** sign under `A` (needs `t`), sign under `A'` (its shares are points of `F`; it never receives `D` at its indices — **DR-7** plants the mixing attack), or forge a competing transition.

Stronger, and why `δ ≠ 0` is the whole point: **an adversary holding `t` old shares — the entire old signing scalar — still cannot sign under `A'`**, because it knows `secret` and `[δ]B` and recovering `δ` is discrete log. That is recovery from *total* compromise, which HJKY proactive refresh cannot give (refresh preserves the secret). Delta rotation is HJKY with the constant term left nonzero and jointly generated.

**Three limits, in the code rather than the changelog:**

- **The arithmetic check is not authentication.** A party with no shares can fabricate a passing transcript. **DR-16 plants that forgery and lets it pass**, so nobody reads the check as more than it is; authorization is the quorum signature (**KL-4** asserts the other side).
- **An adversary at `t` old shares can equivocate.** `foldChain` returns `forked` and never picks a winner (**KL-9**).
- **Immediate in the key, eventually consistent in the knowledge.** **KL-11** asserts the exposure rather than hiding it.

Tier is unchanged — still **L1**. Nothing here implies otherwise.

## No permanent human privilege

Authorization is the wallet's own quorum, whoever holds it. No human-only key exists in this path and none may be added — manifesto §3 weight-free, and `no-directives.md` records human-only authorization as explicitly provisional. It is also wrong operationally: if rotation needs a human, incident response runs at human latency and the attacker wins. **Symmetry and speed are the same property.**

## A bug found while writing it

The first draft of `foldChain` asked whether two distinct **elements** extended the same epoch. FROST signing is randomised, so a quorum re-signing one statement produces two elements — **the fold would have cried compromise at its own retries.** Equivocation is two distinct **statements**. `statementKey` is the canonical identity, mutant **M15** re-plants the bug, and the distinction buys a sound compaction (one element per statement is a lattice homomorphism, not an eviction).

## Falsifiability — 22 mutants planted, 22 killed

Three survived first, and those are the findings:

| Mutant | What it exposed |
|---|---|
| **M02** delete the duplicate-contribution guard | `[c, c]` misses the group key on the arithmetic anyway, so the guard was never exercised. The real attack is one holder taking two seats with the second built from **public points** to close the equation. New **DR-15b**. |
| **M10** drop `fromX` from the transcript digest | The relabel test moved `1 → 9`, which also moves the sort position — *ordering* was giving the test its answer. My first repair (swap the labels) failed the same way and was **retracted**. |
| **M18** advance on any higher epoch instead of exactly `current+1` | No fixture had an element that both chained to the current key **and** skipped ahead. It is a takeover: sign epoch `n+5` off the epoch-`n` key and a verifier that accepts the jump lands where the honest `n+1` is unreachable — silently, **with no fork ever reported**. New **KL-12b**. |
