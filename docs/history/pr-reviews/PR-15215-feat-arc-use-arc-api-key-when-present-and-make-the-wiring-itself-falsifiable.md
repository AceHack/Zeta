## Description

# Summary

`ARC_API_KEY` is now in repo settings, so the lane can reach the hosted environments. Three parts, and the third matters most.

## 1. The mode is chosen, not hardcoded

`play()` constructed `Arcade(operation_mode=OFFLINE)` unconditionally and then reported `"mode": "OFFLINE"` as a **string literal** — a claim no test could falsify, and one that would have been false the moment a key existed. `operation_mode_for` is now a pure policy function (testable without a network) and `open_arcade` reports the mode it *actually obtained*.

**The line is network access, not features.** Measured in `arc_agi/base.py`: every mode except `OFFLINE` reaches the network during construction — `_fetch_from_api()`, preceded by `_get_anonymous_api_key()` when the key is empty. `OFFLINE` is the only mode that provably makes no request, which is what keeps this lane runnable on a laptop, in CI without secrets, and with egress blocked.

Whitespace counts as blank, deliberately: an unset GitHub secret expands to `""`, and treating that as a key would turn a *missing secret* into a *network call*.

Degrade-never-fail is measured rather than asserted — with a key and an unreachable API, `Arcade` constructs in 0.09s, logs the `ConnectionError`, returns zero environments, and the episode still scores 0.3375 with 3/3 levels.

## 2. The key is withheld from `pull_request`, and that is a security boundary

GitHub withholds secrets only from **fork** pull requests. This repo's PRs come from its own branches, so a `pull_request` run **would** receive the real secret — and every agent here pushes branches and opens PRs. Any PR touching `src/Arc.Python/**` could then add a step that prints it.

```yaml
ARC_API_KEY: ${{ github.event_name != 'pull_request' && secrets.ARC_API_KEY || '' }}
```

PRs run the OFFLINE path; only `push: main` and `workflow_dispatch` get the key. **The cost is real and accepted:** no hosted-environment feedback at PR time.

## 3. The wiring has a falsifier, because without one the secret is invisible

This is the part I'd want reviewed hardest. Rename the secret, unset it, or typo it, and the lane simply degrades to OFFLINE and **the job stays green** — "verifying nothing" wearing a success, the same shape as the byte-lock's `verified 0 of 10`.

So the smoke step now asserts the mode **both ways**: a run that should have the key and reports anything but `NORMAL` fails with *"check the repository secret is named exactly ARC_API_KEY"*, and a `pull_request` run that somehow obtained `NORMAL` fails as a credential leak.
