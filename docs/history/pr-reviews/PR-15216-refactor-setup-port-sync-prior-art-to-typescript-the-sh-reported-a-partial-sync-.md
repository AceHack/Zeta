## 3. Ignore-path verdict: CLEAN — and now true by construction

Proven, not asserted. Real content was cloned and checked:

```
git check-ignore -v references/prior-art/chip8-roms/README
  -> references/prior-art/.gitignore:1:*
git status --porcelain -- references/prior-art/   # 0 addable entries
```

All 103 manifest rows resolve under `references/prior-art/`, covered by `references/prior-art/.gitignore` (`*`) and root `.gitignore:66-68`.

But that was true **by inspection**. The `.sh` trusted `.path` verbatim and wrote `$REPO_ROOT/$rel_path`, so a row with `path: "src/foo"`, `"../../etc"`, or an absolute path would have written outside the ignored tree and made multi-gigabyte third-party checkouts committable, silently. `resolveDestination` now refuses all three:

- on the **resolved** path, because a prefix match is not enough — `references/prior-art-evil` has the right prefix and the wrong destination (`CONTAIN-4`);
- absolute manifest paths (`CONTAIN-5`);
- the prior-art root itself, which would make `--prune` delete every mirror (`CONTAIN-6`);
- as a **configuration error** failing the whole run, checked over the whole manifest rather than the filtered subset — a row that can address `src/` is a defect whether or not this invocation would have written it (`CONTAIN-8`).

`CONTAIN-9` runs the check against the **shipped** manifest, so a bad row reddens CI before the mirror can be created.

## 4. Honest partial failure

One unreachable source out of 103 must not look like a clean sync. Every source lands in exactly one bucket, failures are named, and any failure exits 1. Three zero-source states the `.sh` printed identically now read differently: empty manifest, fully filtered out, everything failed.
