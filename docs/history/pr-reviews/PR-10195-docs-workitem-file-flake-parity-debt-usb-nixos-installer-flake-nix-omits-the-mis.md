## Description

Files the parity DEBT Dejan found while analysing 081KZETP6AT, so it isn't lost. **Verified by reading both flakes.**

- `full-ai-cluster/flake.nix:81` applies the mise-pin overlay to every configuration including `installer-iso` — **this is what CI builds**.
- `full-ai-cluster/usb-nixos-installer/flake.nix` builds `nixosConfigurations.installer` from the **same** `configuration.nix` (l.28) but applies **no overlay**.

So two flakes claim to describe "the installer ISO" and produce different ISOs: a local `nix build` from the installer directory yields an **unpinned** mise, which then fails the `MISE_PIN_VERSION` check (`linux.sh:191`) and falls into the deliberately-**fatal** tarball branch (`linux.sh:209-215`) on NixOS. A developer building the obvious way gets an ISO that behaves differently from every ISO CI has validated — and it only surfaces at first boot.

Parity/DEBT issue **independent of** the nix-ld vs nix-native decision: whichever way that goes, one artifact with two divergent definitions is wrong on its own.
