## Description

## The real error

The `alexa` lane failed every tick from **2026-08-26T23:42Z** (run `33024333706`, job `98362009835`) at *"Accumulate unflushed heartbeat state over current main"*. The annotation carried only `Process completed with exit code 1`. The cause was 1250 log lines down:

```
prepare-heartbeat-branch: carry unflushed heartbeat state failed: Auto-merging data/ci-runs.jsonl
Auto-merging data/tick-reasoning.jsonl
CONFLICT (add/add): Merge conflict in data/tick-reasoning.jsonl
Automatic merge failed; fix conflicts and then commit the result.
```

## Is this the 2026-08-16 outage? No — and the prior fix is intact

2026-08-16 was `fatal: empty ident name`: the preparer's carry step ran before any committer identity was set. That fix moved `git config user.name/email` ahead of the preparer, and it **held** — the identity lines are visibly still in the step, and no ident error appears in tonight's log.

This is the **eighth** member of the *undeclared append-only path* class the `.gitattributes` heartbeat block tracks (`mutation-findings`, `manifest.jsonl`, `rs-blocks.jsonl`, `ci-runs.jsonl`, the `theirs` snapshots, PR shards, PR reviews). The preparer's typed backpressure refusing an undeclared conflicting path is the design **working**, not regressing.

## Was it caused by tonight's main→lane merge? Yes, but not as fallout — as the ordinary flush

`data/tick-reasoning.jsonl` first reached `main` at **23:11:11Z** in `18e00976d2`, *the alexa flush itself* (#15551). Measured per lane on that tip:

| lane | merge-base | base has file | outcome |
|---|---|---|---|
| **alexa** | `443cdacdb5` | **NO** | **ADD/ADD — wedged** |
| otto | `64005b76ac` | YES | 3-way content merge, green |
| soraya | `64005b76ac` | YES | 3-way content merge, green |

otto and soraya were rebuilt over a main that already carried the file. alexa's base predates its own flush, so the base has neither side. That is the whole reason one lane wedged while two siblings ticked green on the same run — the cause is the **merge base**, not anything shared.

It is **self-sustaining**: a failed tick never advances the lane, so the base never moves past the flush, so the next tick reproduces the same add/add. Two hours of red is the empirical proof it cannot clear on its own.

The alexa *tick* job succeeded at 22:28 and 21:22 — those runs went red on the **flush** job, a different failure.

## Why `union` is sound here

- Sole writer is `appendFileSync(path, JSON.stringify(reasoning) + "\n")` in `observe/tick-reasoning.ts` `recordReasoning`; no path rewrites a line.
- Every row carries an `agent` field ⇒ single-writer **per row**, as `ci-runs.jsonl` and `rs-blocks.jsonl` are.
- Live: 16 rows on main, 30 on the lane, main a strict subset (`comm -23` = 0 only-main).
- Verified against the **live refs**: clean merge, 30 rows, 0 duplicates, 0 markers, nothing lost from either side.

### Measured limit that is NOT covered

`union` can **duplicate** a shared row when main holds a foreign row *before* the shared ones. Three orderings measured:

| main | lane | result |
|---|---|---|
| `[A1]` | `[A1,A2]` | 2 rows, 0 dupes — **the live shape** |
| `[A1,O]` | `[A1,A2]` | 3 rows, 0 dupes — pinned by the new test |
| `[O,A1]` | `[A1,A2]` | 4 rows, **1 dupe** |

Never data loss, but one row counted twice. This is a property of the driver, so it applies equally to the four union paths already declared; recorded in `.gitattributes` where it was first measured.

## Legibility (item 4)

`prepare-heartbeat-branch` now emits a `::error::` annotation naming the conflicting path, newline-encoded so the CONFLICT line — the *third* line of the message — is not truncated at the first newline. This class is designed to recur and the remedy is always "declare the path"; the only thing between the alarm and the remedy is knowing which path.
