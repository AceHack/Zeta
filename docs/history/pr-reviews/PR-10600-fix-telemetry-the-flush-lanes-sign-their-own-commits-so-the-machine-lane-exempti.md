## Description


Follows #10573 and #10594. #10573 gave `github-actions[bot]` an explicit,
named MACHINE-LANE-EXEMPT entry so the fail-closed audit would not redden 39
mechanically-generated commits. That was the right call at the time and it is
still the wrong long-term answer: an exemption is a PROMISE that provenance is
established some other way, while a signature establishes it directly. These
commits now classify CORRECT rather than exempt.

SIGNED AT THE CHOKE POINT, NOT PER LANE
---------------------------------------
Three lanes flush through `flush-via-staging.ts` — tick-metrics, society,
red-state — so `agencySignatureBlock(lane)` lives there and signs all three at
once. Four cadence workflows already `echo` this block by hand in yaml; three
more hand-written copies would have been three things to drift apart, and a
trailer block that drifts is the failure this whole thread has been about.

BOTH COPIES, AND THE BODY IS THE LOAD-BEARING ONE
--------------------------------------------------
The block goes on the branch commit AND in the flush PR body. The body is the
one that matters: these land by SQUASH-MERGE, which uses the PR body as the
commit message and discards the branch commit's trailers entirely. Signing only
the commit would have produced a signed commit that arrives on `main` UNSIGNED —
the Squash-Merge Invariant, and the mechanism behind most of the 113 unsigned
commits #10564 measured. Getting this half wrong would have looked like a fix
and changed nothing observable on main, which is why it is called out here.

TESTS — THE PARSER IS THE WITNESS
----------------------------------
16 tests. The load-bearing ones do not assert "the string contains the keys";
they run the message through `git interpret-trailers --parse` and assert git
itself recovers all ten required keys plus `Co-authored-by`. A block that reads
correctly to a human and does not parse is precisely the Trailer Contiguity
Survival Failure, and only the parser can tell the two apart.

Paired with a MUTATION that proves the contiguity test is testing something: a
block with one blank line inserted mid-way is parsed, and git is shown to
recover `Task:` while silently dropping `Agency-Signature-Version:` above the
break. That is the failure mode, constructed rather than described.

Also pinned: the canonical key spelling (a negative assertion that
`Agent-Signature-Version` does NOT appear), that signing does not displace the
subject line the PR title is built from, and that it does not smuggle in a
CI-skip token — which would stop `gate (required)` reporting and hang the flush
PR unmergeable forever.

VERIFIED END TO END, not just in unit tests: a generated flush body piped into
`validate-agencysignature-pr-body.ts` returns PASS and prints all ten fields.

SCOPE, STATED HONESTLY
----------------------
This does NOT remove the machine-lane roster entries, and the PR does not claim
to. They are still needed for (a) all existing history and (b) the lanes that do
not flush through this tool — drift-sweep, lockfile-healer, lint-autofix-apply,
pr-archive-on-merge, which still commit unsigned. What changes is that the
exemption stops being LOAD-BEARING for the three highest-volume lanes. Removing
it entirely is a later step, once the remaining lanes sign too and the roster
can be shown empty of live users rather than asserted to be.

`agent-heartbeat.yml` is deliberately untouched — #10577 is in that file.
