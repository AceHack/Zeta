## Description

# Summary

**`src/Core/Rx.fs` had no operator set at all.** Before this PR it was 115 lines exposing exactly two functions — `asObservable` and `asObservableForCount` — both channel-to-observable bridges. There were zero combinators. So this is not "the join operators were missing from Rx's combinator library"; this **is** the combinator library, and it starts with joins because that is what was asked for.

Adds `RxJoin` to `src/Core/Rx.fs`: `zip`, `zipBounded`, `combineLatest`, `withLatestFrom`, `groupJoin`, `join`, and `durationAfter`.

## Why exactly these, and what stage two still needs

Aaron 2026-08-24, verbatim: *"for rx we need the join operators lets start with the simple ones that don't requrie query planners, query planner joins come second but should not be discounted against, just many required ongoing statistics capture about the two streams."*

Read as a **staging, not an exclusion**. A join needs a planner exactly when its cost depends on statistics it would have to *infer from the data*. Every operator here has its window/key fixed by the **caller** up front, so there is nothing to infer:

| operator | what fixes the cost | statistic needed |
|---|---|---|
| `zip` | arrival index (pairwise) | none |
| `combineLatest` | one slot per side | none |
| `withLatestFrom` | one slot on the right | none |
| `groupJoin` / `join` | the caller's duration selectors | none |

**Planner joins are deferred, not discounted.** So that stage two is a build and not a redesign, the module docstring names the statistics a planner would need and where they would have to come from:

* **arrival rate per side** (items/phase) — buffer sizing, ferry DoP
* **key cardinality + skew per side** — hash vs index-nested-loop
* **join selectivity** (matched / offered) — multi-way join ordering
* **window occupancy over phase** (open windows, live rights) — pricing memory
* **retraction ratio** for Z-set inputs — DBSP joins pay differently on `−1`s

**Where they must come from:** the metered-crossing channel of §13 noninterference, i.e. a statistics *satellite* fed at the membrane — **not** an ambient counter read off a wall clock. That keeps the statistics phase-indexed and therefore DST-replayable, which a planner built on wall-clock rates could never be. Getting that wrong is how the planner would smuggle back in exactly the leak stage one avoids.

# The load-bearing constraint: no clock lives in this module

Per Soraya's finding on #14800 and `.claude/rules/local-time-never-enters-the-shared-fold.md` — a join duration window is a **choice context**, and resolving it from a wall clock puts local time inside a shared conclusion.

* `zip` / `combineLatest` / `withLatestFrom` are **arrival-index driven**. Time is not a term in their definitions. This is the concrete reason they ship first.
* `groupJoin` / `join` take the window as an `IObservable` the **caller** supplies. The operator never reads a clock to decide when a window closes; it only observes the caller's duration stream.
* `durationAfter` is the sanctioned way to build a time-shaped window and takes the scheduler as a **required parameter**. There is deliberately no overload that defaults it, because `Observable.Timer(ts)` resolves against `Scheduler.Default`, which **is** a wall clock.

**Measured, repo-wide:** `git grep -E 'Scheduler\.Default|Observable\.Timer|Observable\.Interval|TaskPoolScheduler|DefaultScheduler|ThreadPoolScheduler' origin/main -- 'src/**/*.fs' 'src/**/*.cs' 'tests/**/*.fs' 'tests/**/*.cs'` returns **0 hits**. That door is currently unopened — which is precisely why the guard belongs here, at the first operator that makes it reachable.

(After this PR the same grep returns 6, and all six are inside `RxJoin.Tests.fs`: four are the negative control's forbidden-token list and two are prose explaining the substitution it catches. None is a call. Stated because the grep is the evidence, and a reader running it should not be surprised by the delta.)

# FINDING — the constraint cannot be enforced by a signature, only by a lint

This is the finding worth more than any single operator, and it is stated here rather than buried.

`join` and `groupJoin` **can** be made planner-free and clock-free — no hidden statistic, no hidden clock, and the four operators all shipped without one. But **the operator cannot refuse a wall-clock-derived window.** A duration selector has type `'L -> IObservable<'LD>`, and *every* observable inhabits that type, including `Observable.Timer(ts)` on the default scheduler. There is no type-level way to say "this observable was not produced by a wall clock."

So `durationAfter` is a **mitigation, not an enforcement**: it makes the right thing easy and the wrong thing explicit, and that is all a signature can do here. The only real enforcement available is a lint, and the repo does not have one — `src/Core.TypeScript/hygiene/audit-ambient-time-in-tests.ts` covers ambient time in **TypeScript tests** and says nothing about F# Rx scheduler usage.

**Follow-up worth filing:** a hygiene lint refusing `Observable.Timer` / `Interval` / `Delay` / `Throttle` / `Sample` / `Buffer(TimeSpan)` without an explicit scheduler argument anywhere in `.fs`/`.cs`. The `NEGATIVE CONTROL the RxJoin implementation names no wall-clock API` test in this PR is that lint at file scope; generalising it to the repo is the real fix. I did not build it here — it is out of scope for the operators and deserves its own review.

## Second finding: `zip` is planner-free in COST but not in MEMORY

`zip` needs no statistics to decide *what* to do, but the buffer on whichever side runs faster grows without bound. Bounding it needs the **arrival-rate statistic** listed for stage two — which is exactly why, in stage one, the number has to be the caller's. `zipBounded capacity` makes the ceiling an explicit caller choice and **fails loudly** at it (`OnError` with a message naming the capacity), rather than growing silently or dropping silently. `zip` is `zipBounded Int32.MaxValue` — one code path, honest about the cost in its docstring.

`join` / `groupJoin` have the same shape: occupancy is data-dependent and bounding it needs the window-occupancy statistic. Named in the docstring, not solved here.

## DETERMINISM (DST, DoP = 1)

`driveSeeded` pushes both sides from **one thread** using a seeded interleaving (S = 4, the common seed) and compares both the interleaving and the rendered output across two runs, for `zip`, `combineLatest`, `withLatestFrom`, and `join`. The operators are a pure fold over the arrival sequence, so replaying the sequence replays the output exactly.

Non-vacuity is built into the test itself: a **different** seed must produce a **different** interleaving, so the equality assertion cannot pass over a no-op. M7 confirms it mechanically.

## NEGATIVE CONTROLS (two, independent)

1. **Behavioural.** A one-hour join window on an injected `HistoricalScheduler` the test advances by hand. Virtual time moves two hours; real time moves microseconds (asserted). The test names the leak directly: `1b` and `2a` are the pairs that exist **only** if the windows survived the advance — i.e. only if a wall clock, not the injected scheduler, decided when they closed. Substituting `Scheduler.Default` yields `1a|1b|2a|2b` and both assertions fail (verified — M8).
2. **Source scan.** Reads the shipped `RxJoin` section of `src/Core/Rx.fs` and refuses `Scheduler.Default`, `DefaultScheduler`, `TaskPoolScheduler`, `ThreadPoolScheduler`, `CurrentThreadScheduler`, `DateTime[Offset].[Utc]Now`, `Stopwatch`, `Thread.Sleep`, `Task.Delay`, `Task.Run`. Comment and docstring lines are excluded, because the doc deliberately *names* the APIs it forbids — and the test asserts it scanned >200 code lines, so it cannot pass by scanning nothing.

This control **found a real error during development**: my first version asserted that after advancing virtual time no further pairs could exist. Wrong — elements arriving *after* the advance get *fresh* windows, so `2b` is correct. The operator was right and my expectation was the bug. Corrected, and the assertion now names the two impossible pairs explicitly rather than pinning a total.

## The docstring claim was NOT falsified

The file header claims: *"NOT claimed: 'Rx can't leak.' Claimed: our lifetimes are bounded above every subscription."* These operators open inner subscriptions — both sources, plus one duration subscription per live element in `join`/`groupJoin` — so that sentence had to be re-earned rather than assumed.

Every inner subscription is registered in a `CompositeDisposable` owned by the handle the operator returned, and `groupJoin` additionally completes **and** disposes every open window on teardown. The header now carries a clause (c) saying so and pointing at the §TEARDOWN falsifiers, which prove a disposed combinator stops feeding, closes its windows, and releases both source subscriptions. M6 proves that clause is not decoration.

**Discipline notes.**
* #2 lock/wait-free: each operator holds a `Sink` gate that is a monitor owned by **one subscription** and reachable from nowhere else. It is the Rx grammar's serialization requirement for an operator with two independent sources, not shared substrate. At DoP = 1 it is uncontended and the operator reduces to a pure fold.
* `async-all-the-way`: no `Task.Run`, no `async void`, no sync-over-async, no `.Result`/`.Wait()` anywhere in the new code — the source scan refuses `Task.Run` and `Task.Delay` mechanically.
