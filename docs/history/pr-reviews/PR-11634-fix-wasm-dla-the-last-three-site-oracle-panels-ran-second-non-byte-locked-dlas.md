## Per-panel diagnosis

**All three were divergent second implementations, not the canonical substrate with a bug.** The
question the brief asked me to answer separately per panel has the same answer three times, and the
evidence is different in each case.

### C / emcc — `src/wasm-dla/c/dla.c` — DEGENERATE, and it is the Zig defect exactly

Not seed-4 specific, measured rather than assumed:

```
      seed 1 -> 1
      seed 4 -> 1
      seed 42 -> 1
      seed 100 -> 1
      seed 999 -> 1
      LCG mod 4: a=1664525%4=1, c=1013904223%4=3
      first 12 directions after spawn: 1,0,3,2,1,0,3,2,1,0,3,2  (period 4, MAX_STEPS 10000 % 4 = 0)
```

`prng_next() % 4` off an LCG whose multiplier is ≡1 and increment ≡3 mod 4: the state advances by a
constant 3 mod 4, so the direction sequence has period 4 and covers all four directions once per
cycle — `+x`, `−x`, `+y`, `−y` cancel. `MAX_STEPS = 10000` is divisible by 4, so every walker ends
on its spawn cell. Also divergent from the spec independently of the PRNG: uniform spawn over the
whole grid, no kill radius, boundary clamping instead of escape.

### LLVM — `src/wasm-dla/c/dla-llvm.c` — diffuses, ran a different experiment

`N_WALKERS` is a **compile-time constant 3000**, and the export is `run_dla(seed)` — it takes no
walker count, so the panel's `N_WALKERS = 800` never reached it:

```
      run_dla(4) = 1642   run_dla(4) again = 1642
      (source hardcodes N_WALKERS 3000; the panel's 800 is never passed)
```

Plus: seed offset by `+42`, spawn on a triangle-wave approximation of a circle rather than cos/sin,
kill radius `spawn_r + 10`, 5000 steps.

### Rust — `src/wasm-dla/rust/dla.rs` — diffuses, on a torus

`GRID_SIZE = 100` (spec says 128) and every access goes through
`idx(x,y) = (y.rem_euclid(100)) * 100 + x.rem_euclid(100)` — **wraparound**, so a walker leaving one
edge re-enters the other and the kill radius can never fire. Also in-module f32 `cos`/`sin` instead
of the spec's host trig, and 20000 steps.

## The fix: staged, not repaired

The canonical substrates **already existed** and were **already in the byte-lock roster** —
`WASM_SUBSTRATES` in `run-bytelock-ci.mjs` lists `dla-canonical-{emcc,llvm,rust}.wasm`, and they
already agreed with the committed vectors:

```
      seed 1: golden cluster_size=332  emcc=332 llvm=332 rust=332
      seed 42: golden cluster_size=339  emcc=339 llvm=339 rust=339
```

So all three panels now stage those, exactly as #11530 did for Zig and #11489 for Go. Patching the
divergent modules would have produced three more plausible wrong numbers that nothing in the tree
could contradict — the 516 lesson.

**Verified end-to-end against the real staged artifact** (`stagePagesWasmAssets` into a temp dir,
then each published module driven with the panel's own import object and call sequence — the new
code paths verbatim, not a paraphrase):

```
staged: wasm/dla-wat.wasm, wasm/dla-zig.wasm, wasm/dla-emcc.wasm, wasm/dla-llvm.wasm, wasm/dla-rust.wasm, wasm/dla-asc.wasm
absent: wasm/dla-go.wasm: src/wasm-dla/bytelock/dla-canonical-go.wasm is missing (the Pages Go build did not run)

  WAT   cluster = 345
  Zig   cluster = 345
  C     cluster = 345
  LLVM  cluster = 345
  Rust  cluster = 345
  ASC   cluster = 345
```

**Which panels still disagree: none.** All six committed panels return 345, and
`identity-dla-pages-wasm-behavior.test.ts` now covers all six (was three) against the committed
golden vectors at seeds 1 and 42 — 13 tests, up from 7.

`env.memset` turned out to be load-bearing for the LLVM substrate and is the one thing that did not
work first try: the behavior test's shared import object had no `memset`, so bringing LLVM into
scope produced `LinkError: import function env:memset must be callable`. The freestanding link
leaves `memset` undefined and clang emits a call to it for the grid clear in `init`. Both the test
and the panel now bind it lazily, as `run-wasm.mjs` does.

Ten files deleted (~1.86 MB of binary, including the `dla-llvm.o` / `dla-llvm.bc` build
intermediates the rule names explicitly). Exactly one DLA per language remains, except `go/main.go`
— it survives from #11489, is loaded by nothing, and is now the last of the class.

## Two things found on the way that were not in the brief

**1. The emcc build recipe did not reproduce its own committed artifact.** Rebuilding
`dla-canonical-emcc.wasm` with the recorded `-s SIDE_MODULE=1 -s EXPORTED_FUNCTIONS=['_run']`
produces a *relocatable* module that the byte-lock harness cannot even instantiate:

```
LinkError: imported global env:__memory_base must be a number
```

That is condition 3 of `.claude/rules/no-binary-in-proof-lineage.md` — "reproducible from committed
source" — failing quietly, because the artifact is committed and the build is only run by hand. The
recipe is corrected to the standalone flags, found by bisecting against the committed artifact's own
import/export shape and confirmed by measurement (332 / 345 / 339 at seeds 1 / 4 / 42, identical to
the committed module). **Honest limit: behavioural reproduction, not bitwise** — emcc 5.0.7-git here
gives different bytes, and which emscripten built the committed module is recorded nowhere. Pinning
it is separate work.

**2. `src/wasm-dla/README.md` claimed a CI step that does not exist.** It stated that `full-verify`
in `gate.yml` runs a "WASM Oracle 10 build-verify" step rebuilding all four compiler outputs.
`grep` finds no such step; the only trace is an unapplied `docs/research/gate-wasm-build-verify.patch`.
Same defect class as the panels — a check that never ran, reading as one that passed. Corrected.

## The unfalsifiable banner, named rather than left

Worth flagging because it is the direct consequence of this fix and it cuts against the result:

> **Now that all seven panels agree, the page's "Spread: 0.0000 — Z-7 CONFIRMED" banner has become
> unfalsifiable.**

`computeDf` is a pure function of cluster size; the byte-lock guarantees every substrate computes
the same cluster size; therefore the D_f readouts are equal *by arithmetic*. A number that cannot
come out any other way measures nothing. I did not want to make the page look *more* confirmed
while making its confirmation vacuous, so the banner now says what is true — that a zero spread is
expected here and is not evidence — while a **nonzero** spread is kept and labelled `DIVERGENCE`,
because that would be real news: it would mean a panel is off the canonical substrate again, which
is exactly how this page read for months.

The Z-7 evidence is that seven independently compiled binaries spanning ~1,870× in size produce the
same trajectory, and it is carried by the byte-lock and its golden vectors, not by arithmetic on
the page.

Three adjacent presentation defects were corrected while making these numbers uniform, since
leaving them would have been papering over:

- **Every dot was drawn outside the plot area.** The scatter's Y axis ran 1.0–1.8 around a reference
  line at 1.322 — but 1.322 is the substrates' hardcoded `get_df()` *proxy constant*, which this
  panel does not use. What it computes is `computeDf(345) = 1.9647`. The axis now brackets the value
  actually shown, and the reference is derived rather than typed in.
- **The binary sizes were stale**, and they are the scatter's X axis. WAT was listed at 697 B and is
  1,018; Rust at 7,428 B and is 478,353. Now `stat` of the staged files. *Named residual: nothing
  checks these against the files.*
- **The "convergence speed" chart is fabricated data** — `r.df + noise` with an invented 1/√N
  wobble — captioned with a causal claim ("smaller binaries converge faster") that nothing on the
  page tests. No convergence history is recorded anywhere. It is now titled **ILLUSTRATION ONLY,
  NOT MEASURED DATA** with the fabrication described. I think it should probably be deleted; that
  felt beyond what this change should decide unilaterally.

Also note the Rust panel now ships **478 KB instead of 7.4 KB**. That is a real cost to the page, and
per `src/wasm-dla/README.md` 98.8% of it is DWARF from a missing `-C debuginfo=0` — already tracked
with a named, ceilinged audit exemption, not introduced here.

## Verified vs unverified

- **Verified:** the three reproductions; the arithmetic behind the C defect (evaluated, not asserted,
  and across five seeds); that all three are divergent implementations rather than the canonical
  substrate; that the canonical substrates agree with the committed vectors; that all six panels
  return 345 through the new code paths against the real staged artifact; the falsifier (both
  mutation runs go red on the literal `1`); the emcc recipe defect and its correction.
- **Unverified — and this one matters:** `OracleWASM.tsx` is **not type-checked**. The site has its
  own tsconfig and its `node_modules` could not be installed here (`pnpm` absent; `npm install`
  fails on a peer-dependency conflict), and per #11530 it is **covered by no CI workflow either**.
  It transpiles cleanly (`bun build`, JSX and syntax valid) and every runtime path in it was
  executed directly in Node, but no compiler has checked its types. Browser behaviour is likewise
  untested — the modules and imports were exercised in Node with the same shim `run-wasm.mjs` uses.
- **Not attempted:** rebuilding the canonical LLVM and Rust substrates. `llc`/`wasm-ld` are absent
  here, so the mutation was done on the emcc substrate — which is the panel this change is named
  for, and the one that was degenerate.
