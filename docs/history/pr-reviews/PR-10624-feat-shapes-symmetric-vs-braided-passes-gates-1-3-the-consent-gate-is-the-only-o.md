## Description

feat(shapes): symmetric-vs-braided passes gates 1-3 -- the consent gate is the only one left

The Meno drawing work: `db/shapes/cartridges/pending/symmetric-vs-braided.lines`
advanced three gates of the pending README's promotion ladder. Nothing was
promoted. The catalog count stays 19.

WHAT LANDED

Gate 1: `shape.symmetric-vs-braided` registered, with the ComplexityRegistry
row the shelf lint requires. The cartridge's `meta shape-zetaid` already WAS
`idOf "shape.symmetric-vs-braided" 1`, so registration could not silently
disagree with the file -- and ShapePending.Tests now checks that for all three
pending cartridges, which nothing did before.

Gate 2: `ShapeRender.strokesOf` draws both panels. `word` is bound ONCE and
handed to two calls of one panel function that differ in exactly one argument,
`gapped` -- so "a panel with its own word" is not merely discouraged, it is
unrepresentable. Columns derive from the declared `panels`/`strands`, so there
are no bare positions to go stale (shape-braid's stale-gen-args lesson).

Gate 3: `ShapeAcceptance.geometryLaw` has a known-answer case the file PASSES.

WHAT DID NOT LAND, AND WHY

Gate 5 is the treaty block and it is nobody else's to write. No treaty row was
written, stubbed, placeholdered, or TODO'd; the three pending cartridges still
carry zero. Consent-first is a manifesto spec, not a convention.

Gate 4 (goldens) is blocked BY gate 5, not before it -- found by trying it.
`zeta shape render` calls `ShapeAcceptance.accepted`, which is
`bytes AND geometry AND honest-labels`, and refuses at exit 3. `bytes` is a
treaty row. So the README's steps 4 and 5 are listed in the wrong order; a
dated correction is in that README. Hand-writing the SVG is forbidden and
loosening the CLI gate would be weakening a consent-linked check to make my own
work look finished, so no golden is committed -- and a new test enforces that
absence, because a golden for a pending cartridge is locked by nothing.

TWO MUTANTS SURVIVED MY FIRST LAW; BOTH ARE FIXED

Planted against the renderer, run, observed:

  M1 gap the symmetric panel .................. died
  M2 un-gap the braided panel ................. died
  M3 draw the symmetric panel as STRAIGHT LINES  SURVIVED -> law strengthened
  M4 invert Artin's sign (who goes under) ..... SURVIVED -> law strengthened
  M5 gap only the first crossing .............. died

M3 is the plausible one -- sigma^2 IS the identity in a symmetric category, so
"draw the collapsed form" sounds right -- and it passed every count (2 runs, 0
gaps, ends home) while quietly making the cartridge a much weaker claim. The
law now projects each panel's strands onto their COLUMN ITINERARY and requires
the two panels to agree strand for strand. M4 kept the gap count, the
itinerary, and the per-strand run totals identical while drawing sigma-inverse
squared; the law now replays the permutation and checks WHICH strand breaks,
not merely how many breaks there are. Six more mutants live in the suite as
falsifiers, including the do-undo word sigma*sigma^-1, which satisfies every
integer line in the file while teaching nothing.

FOUND ON THE WAY: THE GENERATOR HAD LOST FIVE ROWS

generated file and never added to the source: shape.refraction:draw,
shape.sybil-verdict:draw, rng.lcg64_mmix:mix, hash.murmur3_32_tail:mix,
rng.lcg32_glibc:mix. Running the documented regeneration command deleted all
five (verified by running it, not by reading). All five artifacts are in
GeneratorRegistry.known, so the next person to regenerate would have reddened
`ComplexityRegistry.unstated()`. Restored to the YAML; the generator is
idempotent against the committed file again.
