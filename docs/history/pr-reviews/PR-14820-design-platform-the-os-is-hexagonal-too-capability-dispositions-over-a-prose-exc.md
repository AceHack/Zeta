## Description

## What this is

A design decision, not an implementation. `pam-reattach` turned `main` red on every PR because it had no Windows twin and no English sentence in `WINDOWS_EXCEPTIONS`. Aaron's reading is that the sentence is the symptom: *"we need a hexagonal port interface from us that abstracts the different os/platforms behind one zeta interface that is connoncal and safe for human ai interaction without coreorsion either way."*

This is the **second instance** of `docs/DECISIONS/2026-06-21-hexagonal-pki-and-secret-vault-ports-swappable-adapters.md` and reuses its vocabulary. It does not compete with it.

**`manifest-symmetry.test.ts` is untouched and PR #14807 should still land as the unblock.** `main` is red for an unrelated reason to this branch; that is #14807's job, not this one's.

## The design in one line

Key rows by **capability**, not by package; give each (capability, OS) cell a **modelled disposition** from POSIX.1-2024 §2.1.6's `-1`/`0`/`>0` tri-state — with POSIX's *"undefined means -1"* deliberately **inverted**, because silence is exactly what a symmetry check exists to refuse. Under a capability-keyed model, `pam-reattach` never reaches the symmetry layer and the trigger does not occur.

Seven ports, not one — `HostOs` (a value), `CapabilityRegistry`, `ProvisionPort`, `ConsentPort`, `SupervisorPort`, `SecretStorePort`, `ExecConventionPort` — split along the measured category boundaries.

## Non-coercion, stated operationally

Four properties (N1–N4) with falsifiers, in §6. The sharpest: **N1 has already failed in-repo and the map records it against itself** — three YubiKey entries asserted no Windows id "was verifiable from the host this was authored on", and when the check was finally run "all three resolve". The check asked for something unverifiable and got a plausible sentence. §6.1 keeps *"nothing operator-run, only operator-approved via biometric"* structural: the port exposes `requestApproval`, never `runAsRoot`, so an adapter cannot report an elevation it did not get approved.

## Proof of concept (in scope; the 53 sites are NOT converted)

`src/Core.TypeScript/platform/` — `host-os.ts`, `disposition.ts`, and 8 tests. Nothing imports them, so nothing breaks. Interfaces and pure functions only; zero classes, zero instance state (`interfaces-free-classes-earned-under-rules.md`).

## Findings filed in §11 (not fixed here)

1. **`loop-liveness.ts` reports a live Windows loop as `not-installed`** — `gather()` falls through to `systemctl` on Windows, `unitFound: false`, verdict `not-installed`. `type Supervisor = "launchd" | "systemd"` has no arm for "no adapter here". A check that did not run, wearing the face of a check that failed.
2. Absence is expressed at every absence site in **six mutually-incompatible encodings**; exactly one is modelled (`BiometricPlatform`'s `"unsupported"`). This design is that one shape generalised.
3. `hostKey()` collapses "wrong OS" and "unsupported arch" into one `null`.
4. `tailscale` is in `manifests/windows` **and** in the exception map — its 107-character reason is unreachable.
5. `headscale-cli`'s reason is a **role** distinction, not a platform one.
6. Conformance note against the first decision: `credential.ts` imports `keychain-macos.ts` directly, so **SecretStore is not a port at the call site**.
