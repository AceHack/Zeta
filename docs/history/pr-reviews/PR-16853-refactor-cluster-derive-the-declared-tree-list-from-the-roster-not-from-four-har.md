## Description

The repo carries **two declarations of one cluster**: `full-ai-cluster/` (live) and the older `infra/k8s` + `infra/nixos`, scheduled for deletion under `081M00QCHWA087G0R000GKKRXD`. Three guards exist *because* there are two — argocd pin parity, bootstrap/Application pin parity, and the committed-credential scan. Their job is to prove the two declarations agree.

Each hardcoded the pair, and that cost two things. The second is the interesting one:

1. The deletion — **gated on maintainer sign-off, not performed or authorised here** — becomes a four-file edit instead of a one-line one.
2. `git grep infra/k8s` reported those guards as consumers of the stale tree. True, and unhelpful: **they are not surfaces that need migrating, they are the surfaces that make the migration safe.** The roster's own criterion — *deletion is provably safe when every `blocking` entry is gone* — is unreachable for a guard whose subject **is** the two-tree divergence, because it must keep naming the tree until the tree is gone.

`declared-cluster-trees.ts` gives the tree list one home, read from the roster that already declares `survivingTree` and `stalePatterns`. **Coverage is unchanged** — the guards still scan both trees, and all three audits pass with the same results.

## What replaces the hardcoded list's safety

A literal list cannot silently shrink. A derived one can, and **a guard that quietly scans one fewer tree is the vacuity class.** So the derivation **refuses when a declared root is absent from disk** — strictly louder than the count check it replaces, because it *names the tree that vanished* instead of reporting that a number moved. Both branches are exercised, so the assertion cannot go green by the refusal never being reachable.

The real-roster test checks the derivation against the **filesystem**, not against a copy of the roster: asserting the derived list equals the roster's own contents is `f(x) = f(x)`, which passes for any implementation reading the same file — including a broken one. Fixture tree names are synthetic on purpose, since a fixture spelling the real stale path would make the test file a consumer of a tree scheduled for deletion, which is precisely what the roster audit catches. (It did catch it, twice, while this was being written.)

## Measured effect

`blocking + derived`: **18 → 15.** Two entries dropped because the files no longer name the stale tree; `audit-argocd-pin-parity.ts` moves `blocking → prose` because its only remaining mention is the header paragraph explaining why there are five sites and not four.

**This does not delete anything, and does not ask to.** It makes the eventual gated deletion a roster edit rather than a scavenger hunt.
