## Description

**Supersedes #10183's approach** and fixes the resulting red build-iso.

#10183 deferred the iter-4.2 `$PROBE_MOUNT` umount past the iter-5 probes — but that moved the umount **out of the iter-4.2 block**, breaking the `test-iter-54` structural invariant *"iter-4.2 copies the zflash-baked blob to target ESP BEFORE USB unmount"* (`indexOf('umount "$PROBE_MOUNT"', copyIdx)` within the iter-4.2 block → -1), turning build-iso red on that test.

**Cleaner fix (respects the tested invariant):** keep iter-4.2 self-contained (mount → copy cred-blob → **umount, restored**), and **re-mount** the same ESP partition (read-only) before the iter-5.2 hostname + iter-5-wifi probes, then unmount once after. Captures `BOOT_ESP_PART` when the pubkey is found so iter-5 re-mounts the exact partition.

**Root cause recap:** the bake writes all three ESP files correctly (the #10180 verification passing proved it); iter-4.2 mounted the ESP, found the pubkey, then unmounted — so iter-5.2 (hostname) and iter-5-wifi checked an empty `$PROBE_MOUNT` and silently no-op'd. Re-mounting restores their read. **Also fixes hostname injection.**

Verified: `bash -n` clean; `test-iter-54-install-flow` **29/29** (the invariant #10183 broke is green again). Validated end-to-end by the next `build-ai-cluster-iso` dispatch.
