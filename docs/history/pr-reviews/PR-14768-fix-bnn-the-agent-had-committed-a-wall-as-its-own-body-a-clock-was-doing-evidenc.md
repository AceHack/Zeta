## Description

# Summary

The second live-arena report was *"still had issues with the flee and hunt not really noticing"*. The mode latch was never the problem — it was picking the right *label* most of the time and then moving in the wrong direction, because the steering vector was computed from the position of **a wall**.

Ground truth below is the emulator's own `V0/V1` (player) and `V3/V4` (AI), read **in the harness only**. The agent still sees nothing but 64×32 pixels.

Every row is 6 seeds × 3000 ticks under the **Thompson policy — the one the live arena actually runs** (`swarm-controller.ts`). Where a number comes from a different policy it says so; see "provenance" below, because the two policies disagree and picking the flattering one would be the whole trick.

| | before | after |
|---|---|---|
| self **is** the actual player body | **0.0%** (0 of 2999, every seed) | **67.7%** |
| adversary **is** the actual opponent | 57.5% | 72.9% |
| distance from the **hunter** (want FAR) | 11.96 px | **23.37 px** |
| distance to the **prey** (want NEAR) | 36.74 px | 33.24 px |
| mode **label** correct | 91.0% | 79.1% |

Read honestly, that is **one half of the report fixed and the other half only nudged**:

- **Flee is decisively fixed.** The agent used to sit ~12 px from the thing hunting it — it was *hugging its own hunter*. It now keeps nearly double the standoff.
- **Hunt is barely better** (36.74 → 33.24 px). It still does not close on the prey.
- **The mode label got worse** (91.0% → 79.1%), and that is not a contradiction: the label is internal state, the distance is what the agent *does*. Before this change the agent held the correct label and moved the wrong way, which is precisely the failure being reported. A label is not a behaviour, and only one of the two is visible on the page.

## Root cause — a clock doing evidence's job

Same class as the `maxProb > 0.4` gate removed in #14738.

1. `pickSelf()` committed the body on a **clock**: `exploreTicksDone >= EXPLORE_TICKS`.
2. `mutual-sim.priors.ts` bakes `"exploreTicksDone": 240` into its snapshot, so that clock had **already expired before tick 0**.
3. The cart draws its two walls one frame before the movers exist. Measured: tick 0 has no tracks, tick 1 has **only the two walls**, the player and AI first appear on tick 2.
4. So the election was final on tick 1 over a screen containing nothing but walls — `committedSelfId = 1`, `committedSelfColor = 1`.
5. And that second field sealed it: `elect(committedSelfColor) ?? elect(null)` only falls through when the colour-filtered election finds **nothing**, and a wall is always on screen. The unfiltered election was unreachable for the rest of the run.

At t239 the real player carried empowerment evidence **15.06** and was labelled the *adversary*, while a wall with evidence **0.00** stayed "self".

A second, independent defect surfaced the moment the first was fixed: the empowerment probe read only the **commanded** branch. The AI in this cart *chases* the player, so when the player goes right the AI goes right too and scores just as well on agreement — and the agent duly committed to its **opponent** as its body. What separates a body from a follower is **contingency, not correlation**: my body moves when I command it *and holds still when I do not*. Motion under the null action is now full disagreement.

Anchors: Klyubin, Polani & Nehaniv, *Empowerment: A Universal Agent-Centric Measure of Control* (IEEE CEC 2005) — empowerment is the channel capacity from actuators to sensors, and a channel is defined across **all** inputs including the null one; Watson (1966, 1994) on contingency detection.

## The fix

Four changes, all the same correction — the probe, not a clock or a costume, says which body is mine:

- commit only once `selfEvidence` is actually **positive**;
- colour is a tie-break **bonus**, never a filter, so a wrong commitment can be escaped;
- the latch is **revisable** — a challenger that out-scores the held body by `SELF_LATCH_MARGIN` takes it, and since the accumulator leaks (×0.95) a wrong self decays out on its own;
- `updateSelfEvidence` reads **both** branches of the probe.

## Provenance of the numbers, and a correlation trap I walked into

The repo has a rule about a pile of agreeing measurements being a warning rather than a confirmation. It caught this PR.

I first measured the behavioural rows under the **`desiredKeyOf` steering policy** (what `train-priors.ts` and the integration tests drive) and got a much prettier result — distance from hunter 22.16 → **34.13**, distance to prey 35.88 → **23.06**, i.e. *both* the right way round. I then ran it over "six seeds" and got six byte-identical rows, which is the tell: **that policy consumes no randomness at all**, so seeding cannot vary it and six runs were one trajectory printed six times.

Re-measured under Thompson sampling — which does consume the seed, and is what the live page runs — the six trajectories genuinely differ and hunting is **not** fixed. The table above is the Thompson one. The steering-policy numbers are recorded here as what they are: a single deterministic trajectory, and not the thing the page does.

# Notes

**What this exposed, and did not cause.** The game score went **down**: mean final player:ai 1.00:0.50 → 0.17:0.83. Retraining did not recover it, so it is not prior staleness. The distance rows are the explanation — the agent is now genuinely good at the half of the game that *avoids* contact, and you score by *touching*. The retired behaviour scored better precisely because a body pinned to a wall produced a steering vector that swept the arena at random, and a random walk in a tag game blunders into the opponent more often than a competent escape does.

Two integration tests in `mode-value-learner.test.ts` failed on that; they assert the OCR reward channel fires at all. On `main` the 2000-tick window held **exactly one** event, at t1633 — one lucky tag from red either way, and far too thin to carry a sentence about what the learner "survived". The window is raised to 4000, where the same run now carries **three** events (t2906, t3058, t3137). The assertions are untouched, and a broken reward channel still fires zero at any window length.

**Follow-ups, named not fixed.**

1. **Hunting does not close.** 33.24 px mean standoff from prey it is supposed to catch. This PR makes the agent see correctly; it does not make it a good pursuer.
2. **The learner has learned nothing.** The mode split is ~50/50 hunt/flee before *and* after, because it sees roughly **one reward per 3000 ticks**. Reward sparsity, not perception.
