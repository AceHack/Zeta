## Description

## What

`longhorn-manager` does not exec `iscsiadm` from its own image. It nsenters into the host PID-1 mount+net namespace and execs `iscsiadm` there, resolving it through the **container's** PATH:

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

NixOS populates none of those (only `/usr/bin/env` and `/bin/sh`), so `services.openiscsi.enable` is necessary but **not sufficient**.

## Impact found on node-5b2dfa

```
nsenter: failed to execute iscsiadm: No such file or directory
```

- `longhorn-manager`: **16495 restarts over 62 days**
- zero `nodes.longhorn.io` CRs -> the `longhorn` StorageClass was never created
- **10 PVCs Pending since install** (cockroachdb x3, mimir x7) with `storageclass "longhorn" not found`

The whole stateful layer has been dead since first boot. The workaround was to put everything on `zeta-local-path` instead.

## Why the existing test did not catch it

`k3s-control-plane-platform-fixes.nix` asserted `command -v iscsiadm`, which resolves via `/run/current-system/sw/bin` — a path on a login shell's PATH and on nothing else. Longhorn never sees it. The test was green the entire time Longhorn was dead.

This PR asserts the path Longhorn *actually* uses, reproducing its exact resolution:

```
env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin iscsiadm --version
```

## Approach

Declarative `systemd.tmpfiles` `L+` symlinks, so the bridge belongs to the generation — recreated each boot, replaced on rebuild — rather than lingering as imperative `ln -s` state from an activation script. Store paths are used directly so the shim does not depend on the packages also being in `environment.systemPackages`.

RWX volumes cross the same nsenter boundary over NFSv4, so `mount.nfs` / `mount.nfs4` / `umount.nfs` / `umount.nfs4` get the same treatment.

## Verification

Built both directions on real KVM (x86_64-linux `nixosTest`):

| | outcome |
|---|---|
| with shim | build succeeds, all assertions pass |
| without shim (negative control) | fails at `test -x /usr/local/bin/iscsiadm` (exit 1) |

Scope: the nixosTest checks are gated to x86_64-linux (flake.nix `optionalAttrs (system == "x86_64-linux")`), so this assertion runs on x86_64 only. The aarch64 installer lane builds + boot-smoke-tests the ISO but runs no k3s/platform checks, so it is unaffected either way.

Distinct derivation hashes confirm these were genuinely separate builds, not a cache hit.
