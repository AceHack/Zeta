## Description

The lane proved something real and called it something else.

WHAT IT ACTUALLY PROVES: OVMF boots a GRUB EFI built by real `grub-mkimage` from a real
FAT/ESP image, and the menu is reached over serial. That is worth having and is unchanged.

WHAT IT DOES NOT PROVE: anything about our installer. The GRUB menu entry only `echo`s a
string -- it never `loopback`s or boots -- and the file it points at is a placeholder of a
few bytes written by `writeFileSync(isoPath, "zeta-uefi-smoke-iso\n")`.

The placeholder was named `zeta-installer.iso` and its menu entry `zeta-installer`, which
BORROWS THE NAME OF THE REAL PRODUCT: the installer ships as `zeta-installer-<version>.iso`,
is built by `nix build .#installer-iso`, and is boot-tested in a different lane entirely
(`build-ai-cluster-iso`, which does boot what it built, in-run).

No assertion here was ever false. The NAMES did the misleading, and they did it in the one
place naming is load-bearing -- a checks list, where a reader sees a green tick and a
familiar word and reads it as installer coverage.

Renamed:

  check name   "multiboot QEMU UEFI menu smoke"
            -> "ESP+GRUB menu reached under OVMF (no installer ISO)"
  placeholder  zeta-installer.iso -> not-an-installer-placeholder.bin
  menu entry   "zeta-installer"   -> "placeholder-not-the-installer"
  plan item    "zeta-installer"   -> "placeholder-not-the-installer"   (SMOKE PATHS ONLY)

DELIBERATELY NOT RENAMED: the real planner's `zeta-installer` plan-item name, and
`multiboot.test.ts` which asserts it. A genuine multiboot USB really does carry an item by
that name -- that is the feature, not the confusion. Only the two smoke files' placeholders
moved, and the real planner's test is untouched and still asserting the real name.

FALSIFIER, because a placeholder drifting back toward the product's name is exactly the kind
of change that looks harmless in a diff: a test refuses the string `zeta-installer` in either
smoke source. Comments are stripped FIRST -- the test's own explanation says
`zeta-installer.iso`, and a guard its own prose can satisfy is not a guard -- and a CONTROL
test proves the stripper is not a no-op, since stripping everything would make the refusal
pass vacuously.

Mutation-tested: reclaiming the product name in a plan item is killed by 1; making the
comment stripper a no-op kills the control, as it must. 74 tests, 292 assertions, 0 failures.

One process note, since it nearly cost the falsifier: reverting a mutation with
`git checkout -- <file>` wiped that file's LEGITIMATE changes too, because it held both.
Restored and redone from an explicit backup. `git checkout --` is not an undo for one edit.

Reported by the hardware/USB review agent, which flagged it rather than changing it
unilaterally -- correctly, since which way to resolve it was a decision. Aaron chose rename
over loopback-the-real-ISO.
