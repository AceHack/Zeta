## Description

Aaron: *"sorting with localeCompare — culture-sensitive, yeah we need to get these culture sensitive things out of here."*

## The structural cause (two halves, both now closed)

`.claude/rules/culture-invariant-by-default.md` was enforced at **compiler-error level for C#** — CA1304/1305/1307/1310/2007 are `error` in `.editorconfig` — and **not at all for TypeScript**. That asymmetry is why these keep reappearing.

Verifying it turned up a second half the brief did not have, and it is worse:

> **The repo's own ESLint config was recommending the banned API.** `sonarjs/no-alphabetical-sort` arrives via `sonarjs.configs.recommended`, and its message is: *"Provide a compare function that depends on `String.localeCompare`, to reliably sort elements alphabetically."*

It had already bitten — `src/Core.TypeScript/hygiene/unexecuted-test-files.ts:79` carries the comment *"NOT localeCompare, which the lint rule suggests"*. So one lint was telling every agent to introduce exactly what the rule bans. It is now `off` in `eslint.config.ts` with the reasoning inline.

**Correction to the routing brief:** it said there is no `eslint.config.*` at the repo root and to treat ESLint as unwired. There *is* one — `eslint.config.ts`, 120 lines, with the sonarjs stack. Looked rather than inferred. (It is installed in `gate.yml` but the orchestrator `lint-typescript.ts` runs `tsc` only, so ESLint does not currently gate CI either way.)

## The durable half — the lint

`src/Core.TypeScript/hygiene/lint-no-culture-sensitive-collation.ts`, modelled on `lint-no-ambient-credential-hoist.ts` (house style, no new dependency). Bans a **closed list of named APIs** at call sites: `localeCompare`, `Intl.Collator`, `Intl.DateTimeFormat`, `Intl.NumberFormat`, `toLocale{LowerCase,UpperCase,String,DateString,TimeString}`.

- **Comment/string stripper** — the repo has ~10 files whose doc comments explain *why not* to use `localeCompare`. All 10 are correctly not findings; a live call one line below a comment about it still is, with the right line number.
- **Bare `.sort()` is deliberately NOT a target.** Confirmed rather than assumed: ECMA-262 SortCompare with `comparefn` undefined uses ToString + the abstract relational comparison, i.e. UTF-16 code-unit order. Measured byte-identical under `LC_ALL=C` and `LC_ALL=sv_SE.UTF-8`. Flagging it would have been noise that gets the lint disabled.
- **Anti-vacuity floor** — exits 2 if fewer than 1200 files are scanned (2650 today).
- **Allowlist** = the permitted display edge, 10 entries, **every one carrying its reason**, each verified by reading the call sites (JSX text nodes and console output; no ordering, no key, nothing written to a tracked file). Its file-granularity limitation is stated in the source rather than hidden.
- **Baseline** = a **debt ledger, not permission**: counts may fall, never rise; a file absent from it may hold none. Every row carries a category and a reason, and a test fails if any row is `UNCATEGORIZED` or `TODO`.

## The sharpest find

`compareTagged` (`file-type-plugin/types.ts`) is **the canonical DynamicValue comparator** — the ordering key for every `Tagged` Z-set (`ofEntries`, `union` in `cell.ts`), the codecs' canonical field order for YAML frontmatter and TOML, and the query language's `<`. It was `localeCompare` in seven places.

That is the 081KT07NV0008QG0R001YDB73K defect class — the F# `ZSet.ofSeq` culture-sensitive sort — reappearing verbatim in TypeScript. Now routed through the collation treaty comparator. The behaviour change is real and contained to `file-type-plugin`; no checked-in artifact binds it (traced every caller).

`ace/graphMerkleRoot` had its **input ordering** fixed. Its docstring now says what the function is: `h = h*31 + c`, Java's `String.hashCode` — non-cryptographic, 32 bits, **not a tree**, so it proves no inclusion. Reported, not silently redesigned; replacing it changes every emitted root.
