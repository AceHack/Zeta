## Description

fix(heartbeat): declare the PR shards, a sixth lane path — and the first add/add

soraya's tick wedged on a run of `CONFLICT (add/add)` across many
`docs/github/prs/shards/**/*.json` at once. Sixth member of the class the 2026-08-16 fix
addresses, and the first that is ADD/ADD rather than a content conflict: two branches each
CREATED the same shard, so the merge base has neither side.

WHY TAKING ONE SIDE IS LOSSLESS, and it is the repo's own rule rather than one invented for
the merge driver. Measured on the wedging pair (PR 9180, shard .../009/…23dc.json): both
files are 545 bytes and differ in EXACTLY TWO keys —

    fetched_at:  main 2026-07-02T18:35:46.863Z   lane 2026-08-17T13:47:37.443Z
    commit_sha:  main 764d57a2…                  lane 8ca0ad39…

`pr_number`, `archive_path`, `title`, `source_ids` and `schema_version` are byte-identical.
Those are exactly the two fields `pr-manifest-shards.ts` already excludes from equality in
`equalModuloWallClockNoise` — "the two fields that drift between runs WITHOUT indicating any
substrate change." The codebase already declares these two files the same record; picking
either is picking between two spellings of one fact.

WHY THE WRITER'S GUARD COULD NOT PREVENT IT, so nobody reads this as a writer bug.
`writeShard` preserves existing bytes on a wall-clock-only match — and it can only preserve
bytes it can SEE, via `existsSync(path)` in ONE checkout. Two branches that each create the
shard from a tree where it is absent never observe each other, so the guard cannot engage.
That is inherent to concurrent creation on divergent branches, which is why the resolution
belongs at the merge layer rather than in the writer.

THE FAILURE MODE THIS DOES NOT COVER, stated because it is the real risk: if two sides ever
differ SUBSTANTIVELY — a different `archive_path` or `title` for one `pr_number` — `theirs`
takes the lane's and drops main's silently. Nothing detects that. It is unreachable by the
wall-clock drift above, and `pr-manifest-integrity` catches duplicate keys rather than
divergent values, so if shards ever become editable in place this line must be revisited.

The test reproduces the ADD/ADD shape specifically — it does not reuse the `partialFlush`
helper, which seeds main first and would produce the content-conflict shape this is not. It
asserts the merged file still `JSON.parse`s to one record, which is what makes `union` fail
loudly here instead of silently concatenating two objects. Mutation-checked: deleting the
`.gitattributes` line fails it with the production error.
