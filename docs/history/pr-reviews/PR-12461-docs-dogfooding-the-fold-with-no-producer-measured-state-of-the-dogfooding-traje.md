## The finding

**Both surfaces named as dogfooding's centre ship an eliminator with no introduction form,
so the loops around them run on schedule and cannot change state.**

`data/zetadb/journal.json` has been written **exactly once, ever** (2026-08-09, #10206) and
holds one delta. `zetadb-scheduled-node.yml:9` folds it **48x/day**. `scheduled-node.ts`
(241 lines) exports a reader and a fold and **no append** — there is no writer for this
journal anywhere in the tree. ~480 folds have each printed the workflow's own
*"No new database events to checkpoint."* Meanwhile **#12043 landed yesterday** making that
fold commutative and its checkpoint byte-canonical — the right properties, on an instrument
whose one row was placed by hand ten days ago.

`081M08VM385087G0R001DTM0K6` found the identical shape in `clis/Verbs.fs` two days earlier:
*"eliminators for `ISim<'a>` and no introduction form."* Two surfaces, two agents, same
defect. Anchored to Gentzen 1935 harmony — an elimination rule with no introduction rule is
not wrong, it is **inert**, which is exactly why neither produces a failure.

## The proposal (advisory only — nothing executed here)

Adds **no** workflow, **no** lane, **no** new surface: give
`data/zetadb/journal.json` **one real producer** — the society lane already emits 340
hash-chained events on a live 30-min cron — **or retire its cron.** Either closes the row.

**Cost named rather than minimised:** a producer is what **arms** `081KZM0FTJM`'s unguarded
race. That is the cost, and it is also the point — an unfired race is unmetered, and that
item is already the trajectory's own #1 leverage row. Second cost: it touches a live cron
lane, so degrade-don't-halt applies.
