## Description

Follow-up to #15768 (merged). Adds a **fourth stuck-class** the original evidence table did not contain, surfaced by the coordinator and **verified independently before encoding**.

## The class, measured on PR #15772

```
gate run 33036398592: status=completed  conclusion=action_required  jobs executed: 0
gate (required):      never published (0 check-runs by that name)
refs/pull/15772/merge: EXISTS -> 9873f38dcc     <- NOT the dirty case
head check-runs:      7, ALL green (CodeQL Analyze x5, submit-nuget x2)
```

`action_required` is GitHub holding the workflow for manual approval. No job runs, so the required check is never published and the PR can never satisfy it. From `gh pr view` it reads **perfectly healthy**.

| class | distinguishing signal |
|---|---|
| dirty / undispatchable | `refs/pull/N/merge` **404s** |
| retarget-no-event | **no run exists at all** |
| **new** | **run exists, `action_required`, jobs = 0** |

The detector needs **both** conjuncts, and it is deliberately *not* keyed on the required check being absent — that absence is the symptom and is shared with the retarget class; the run's conclusion is the cause.

## Escalate-only — stricter than retire-vs-recover

The remedy is an Actions approval policy or a human pressing *Approve and run*. Retire-vs-recover was a **judgement** a machine shouldn't make; this is a **privilege boundary**. `.claude/rules/no-directives.md` already governs it: the shadow may *inherit* authority within standing authorization, never *extend* it into a gated class. Self-approving a held workflow is extension.

So there is **no arm** that approves a run, requests approval, or edits a policy — not proposal-only, **absent**. It maps to `Escalate` (inert, no executable form). Reusing `Escalate` rather than minting a tenth verb is economy of mechanism. The lint now forbids `/approve`, `pending_deployments`, `deployment_protection_rule`, and `actions/permissions` in **both** files, so a later edit can't quietly add it.

## The ordering bug this exposed — the real find

Before the arm existed, #15772 hit **`FrozenLane`** first and proposed **retiring a lane that was merely waiting for a human**. Safe only because that arm is proposal-only — **safe by luck, not by design**.

Worse: a **non-lane** PR in the identical state has `isFrozenLane: false` and falls through to `VerdictNotDispatched` → `MergeMainAndPush`, which is **AUTOMATABLE**. Combined with correction (1) below, that is a mechanical **bypass of an approval gate**. Both cases now carry regression tests.

General lesson, applied to the whole precedence list: **a measured cause must outrank every arm that reads a symptom of it.**

## Two corrections to the evidence base

1. **The `MergeMainAndPush` remedy for #15724 worked, but the mechanism is less certain than first stated.** The push also came from a credential that does **not** require approval, and that may be what created the runnable event — the merge content possibly incidental. The edge is real; its **causal mechanism is not established**. Recorded as an open question, because if credential-identity is doing the work then that arm is partly a *privilege effect* — the very thing this PR says must never be automated.
2. **Isolated, not systemic**: 1 of 9 open PRs. The arm ships **with its fixture** precisely because an arm firing on exactly one PR can be added and never exercised again.
