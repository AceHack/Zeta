## Description

## What this is

Two work-items, **no code change**. Investigated whether an adapter is warranted
between the two Bayesian factor representations in `src/Core.TypeScript/bayesian/`:

- `CategoricalFactorTensor { factorId, logProbabilities: ReadonlyMap<string, number> }` — eager, finite, **partial**
- `FactorGenerator = (stateKey: string) => number` — lazy, unbounded, **total**

## Verified vs inferred

**Verified — the gap is real.** Searched by *behaviour*, not by name: no function
anywhere maps a `ReadonlyMap<string, number>` to a function or the reverse; the
string `logProbabilities` occurs in exactly one file; neither type has any consumer
outside its own module. No adapter exists under any name.

**Verified — they are NOT demonstrably "the same object."** They share a signature
shape. The invariant that would make them the same — *"denotes one total function
from state key to log-potential"* — holds for `FactorGenerator` and **fails** for
`CategoricalFactorTensor`: it is partial, and its own module gives it three
different total extensions under two different key namespaces. Same shape,
different domains, different totality. Sameness is a resemblance here, not a result.

## `081M05DPGKR087G0R0017GX310` — bug, P2 (the upstream defect)

**Defect 1 — three absent-key semantics in one file.** `?? 0.0` (fusion) is the
log-space **monoid identity** and is not tunable; `?? -0.05` (fine) and `?? -0.1`
(coarse) are search heuristics and are. Two different *kinds* behind the same bare
`??` literal.

Demonstrated by mutation — changing the fusion default `0.0` → `-0.05`:

| test | result under mutant |
|---|---|
| `STRICT BYTE-LOCK COMMUTATIVE INVARIANT` (pairwise) | **green** — cannot pin the identity; `(a+d)+(b+d)` commutes for any `d` |
| `PROPERTY TEST: 100 random frame arrival permutations` | **red** — `[["3,3",-1.04]]` vs `[["3,3",-1.09]]` |

So the property test is the real falsifier, and what it pins is **associativity of
the left fold**, which holds iff `d = 0` — not commutativity as its name suggests.

**Defect 2 — one keyspace, two distributions.** The docstring declares coarse
`P(B_next | B_curr)` and fine `log P(S_next | S_curr, A)`; both are read from the
same map with the same `` `${r},${c}` `` format and no namespace tag. Instrumented
the search on the existing fixture:

```
same string used as both block and cell coords : 0,0 0,1 1,0 1,1 2,0 2,1 3,0 3,1  (8)
tensor entries consumed at BOTH levels          : 0,0 0,1 1,1                      (3 of 3)
```

Structural for any `blockSize > 1`, not an artifact of the fixture.

## `081M05DPKQA087G0R0036HE8CE` — task, P3 (recorded negative)

**No adapter should be written today**, and the negative is filed rather than left
as silence. Reasons: no caller exists; the specification is unsettled upstream; and
no honest falsifier is available — a test pinning an arbitrary default checks *my
guess*, not the requirement, and a check that cannot fail in the way that matters
is not a check.

Direction analysis, stated precisely:

- **`CategoricalFactorTensor → FactorGenerator`** — trivial to write, **not
  currently well-defined**. Becomes sound once the default is carried **in the
  type** rather than chosen per call site.
- **`FactorGenerator → CategoricalFactorTensor`** — **not total**; it is a
  *restriction* and the key set is a **required parameter**. Measured with
  `studentTFactorGenerator()`: entropy **1.776 / 2.616 / 2.598** over key sets
  `0..3` / `0..7` / `-3..3`. `computeFactorEntropy` is therefore a property of
  **(factor, domain)**, not of the factor — materialisation is choice-bearing and
  its output must never be reported as "the entropy of the factor".

## Registered honestly, not rounded up

- **Coincidence, not intent:** `-0.1 === 2 × -0.05` and the test uses `blockSize = 2`.
  Both are bare literals; nothing scales by `blockSize`. Logged as a coincidence per
  `numerology-vs-number-theory.md`, not as a derivation.
- **Minor, separate:** the property test shuffles via `sort(() => Math.random() - 0.5)`
  — unseeded ambient randomness in a determinism test, and biased (measured
  25/25/12.5×4 over the 6 permutations of 3 elements). Flaky-pass ≈ `6e-61`, so the
  falsifier stands; recorded so it is not later mistaken for a seeded property test.
