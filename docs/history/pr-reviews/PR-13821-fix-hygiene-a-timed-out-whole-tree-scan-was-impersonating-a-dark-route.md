## The report, and what the measurement says instead

`gate` was red on `main` with five hygiene tripwire failures, and the reasonable next
step — a bulk baseline refresh, plus possibly retiring two scan-floor recognizers —
would have been wrong for four of them.

| # | test | verdict |
|---|---|---|
| 1 | `no file exceeds its baselined count` | **real defect** — `localeCompare` newly introduced in `rho-series.test.ts` against a baseline of 0. Fixed correctly in #13777: the code changed, the baseline did not. Nothing left to do. |
| 2 | `matches the current tracked repo shell inventory` | **timeout**, not a count |
| 3 | `main is clean: every wall-clock in a test file is named and counted` | **timeout**, not a count |
| 4 | `route named-min-constant contributes at least one site by itself` | **timeout**, not a dark route |
| 5 | `route cli-min-flag contributes at least one site by itself` | **timeout**, not a dark route |

bun reports a timed-out test **by its name**, so the bare fail lines read as substantive
findings. The line underneath says `this test timed out after 5000ms`. In the same hour,
CI passed all five on the same commit in **89–222 ms**. Nothing drifted, no route went
dark, no baseline is stale. #13777's own commit message records the same observation
independently.

## Why the misreading is itself the defect

`audit-scan-floor-routes.ts` exists to catch a recognizer that stopped recognizing, and
its failure text instructs the reader: **"Fix the recognizer, never the floor."** A
timeout wearing test #4's name is a false accusation that asks for a *live* instrument to
be retired — the exact inverse of the correct repair. Same shape at #3, whose name
asserts the tree is clean, so a breach reads as "the tree is dirty".

**The cost is the host, not the tree.** Measured 2026-08-22: one bun process reading the
2,896 tracked sources costs **~17.5 s on its first pass and ~350 ms on every pass after**,
reproduced identically in a months-old checkout and a minutes-old clone — so it is neither
tree's property. `mdatp health` reports `real_time_protection_enabled: true`; Microsoft
Defender's EndpointSecurity client authorises each open per *(process, file)*, which is
precisely a large first pass and a free second. Under load (`wdavdaemon_unprivileged`
~500% CPU) the same read measured **132 s**. CI has no such scanner.

## What changed

- **`audit-scan-floor-routes.ts` memoises the corpus per root.** The audit is already
  documented as a pure function of the tracked tree, and the test file called `runAudit`
  **eleven** times, re-reading all 29 MB each time. Eleven reads become one — on every
  host, including CI. This is the host-independent half.
- The one remaining read moves into `beforeAll(…, 120_000)`; the two-scan live-tree block
  in `audit-ambient-time-in-tests.test.ts` becomes one scan in the same shape;
  `lint-nixos-rebuild-needs-impure.test.ts` — a **third** instance of the class, surfaced
  in a full-suite run while this was being written — gets an explicit budget at the call site.
- **No baseline, allowlist, floor, or assertion was weakened.** The scan-floor audit's
  output is byte-identical before and after (`cmp` exit 0, 156 lines).

`120_000` is **inherited, not tuned** — it is what `lint-no-culture-sensitive-collation.test.ts`
already carries for the same whole-tree class. A number picked to outrun an antivirus
would be the same move as a baseline picked to outrun a regression, and `60_000` was
already outrun once while this was being written. A host slow enough to breach 120,000
still fails, and now says so *as a slow hook* rather than as a dead recognizer.

## Measured, not assumed

`bunfig.toml` documents at length that its `[test] timeout` key is inert and the real cap
is 5,000 ms. **The same silent cap applies to hooks**, which was not written down
anywhere: a 6.5 s `beforeAll` fails at **5000.55 ms** bare, fails at **2000.18 ms** under
`beforeAll(fn, 2000)`, and passes under `beforeAll(fn, 20000)`.
