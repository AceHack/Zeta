## Description

Bootstrap the load-state file at \`docs/active-trajectory.md\`.

**The failure mode this addresses:** on wake/branch-switch/tick I reflexively re-derive 0/0/0 state from \`git rev-list\` / \`git diff\` rather than loading the prior trajectory state. Three confirmed instances in this session's 09:00-09:40Z window. The prior state exists (commit \`37bbca9\` + forward-sync proposal + calibration doc) but doesn't get loaded before new state gets generated.

**The fix:** a known-path file (\`docs/active-trajectory.md\`) that any 0/0/0 work session reads first, with the verified state + canonical artifact pointers + next concrete action + do-not list + stop conditions + resume protocol.

**Multi-AI feedback acknowledgment:** the structural shape (RESUME.md / active-trajectory.md / etc.) was the convergent answer from external review (Amara / Gemini / Ani / Claude.ai / Alexa / Deepseek). The maintainer correctly noted their consensus is correlated (all read the same raw logs without peer cross-talk) — signal not proof. The structural diagnosis still lands because the failure mode is verifiable; the content of this file is my own honest read, not a copy of any peer's text.

**What this PR does NOT do:**

- Does NOT execute forward-sync (those are per-file PRs after this lands).
- Does NOT execute hard-reset (explicitly requires maintainer sign-off per the existing path-to-0/0/0 plan).
- Does NOT promote the trajectory-protocol pattern to doctrine (B-0105 consolidation gate active; the meta-note at the bottom of the file names it as candidate substrate only).
- Does NOT add new memory files or new substrate islands.

**After this lands:** every 0/0/0 work session reads \`docs/active-trajectory.md\` first, then proceeds from "next action." The file gets updated as part of any tick that changes trajectory state.
