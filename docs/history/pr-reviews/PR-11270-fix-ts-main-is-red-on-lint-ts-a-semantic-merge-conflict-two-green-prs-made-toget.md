## Description

fix(ts): real type errors rode onto main because the shard that catches them is not gating

Two TS errors are live on `main`. Neither PR that produced them was wrong and both passed
`lint (TS)` on their own branch. Merged, they collide -- the failure class branch CI
structurally cannot catch, because each side is checked against main-as-it-was, never against
main-as-it-will-be.

1. `zflash/test-harness/run.test.ts` -- lines 5 and 7 were BYTE-IDENTICAL imports of
   `Qcow2RetentionExecutionStep`, `QemuCommand`, `QemuCommandExecution` from `./qemu-state`.
   I added one in #11209 to fix this same shard; the Linux zflash work (#11259) added the other
   independently. TS2300 duplicate identifier, six times. Removed the second.

2. `installer/usb-iserial-probe.ts:140` -- `let sysfsDir = USB_SYSFS_DEVICES_DIR`, where that
   const is declared `as const`. Inference narrows the binding to the literal type
   `"/sys/bus/usb/devices"`, so the `--sysfs-dir` assignment below cannot type (TS2322). The
   flag is new; the `as const` predates it. Annotated `: string`, with a comment saying why the
   annotation is load-bearing rather than noise -- deleting it silently breaks `--sysfs-dir`.

CORRECTION to this commit's first draft, which claimed `lint` is in the `gate (required)` floor
and that this blocked every open PR. It does not and it did not. Measured: PR #11268 merged at
02:05:47Z with `lint (TS)` FAILURE and `gate (required)` SUCCESS on the same PR. The shard is
not inside the required gate.

That makes this worse, not better, and it is the reason to land it rather than shrug. A real
type error reached `main` and can keep reaching it, because the check that catches it cannot
block anything. Same shape as `test (TS suite)` -- a check nobody can be stopped by is a check
nobody reads -- one layer down, and now with a concrete instance instead of a worry.

Whether `lint (TS)` belongs in the required floor is Aaron's call, not mine; this commit only
fixes the errors and records the measurement.

Verified: `bunx tsc --noEmit -p tsconfig.json` clean (was 7 errors); usb-iserial-probe suite
11 pass / 0 fail.
