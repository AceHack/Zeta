## Summary

Follow-up to #10778 (`081KZZZH24H087G0R002TXQA15`). The receiver now derives `blockSeq`/`blockPos` from `seq`. ULT-32..34 still sent `seq = i` with a claimed `blockSeq`, which now **completes** blocks and empties the retention window. The full TS suite went red on the bound those tests were written to protect — seen on #10778 itself and again on #10800.

They now spend `seq = 8k` (position 0 of each derived block). That is the drain that remains after the wire-field attack closed: many *incomplete* blocks, never a completed one.

- **ULT-32**: property over peer-chosen seqs, aligned to pos 0; unique key is `floor(seq/8)`
- **ULT-33**: 20,000 pos-0 packets still retain 8, still deliver nothing
- **ULT-34**: squatters are high derived blocks (`0xffffffff - i*8`), not a lying `blockSeq`
