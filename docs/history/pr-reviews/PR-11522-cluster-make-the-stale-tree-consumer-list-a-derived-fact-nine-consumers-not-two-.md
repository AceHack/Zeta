## What ships

`audit-cluster-tree-consumers.ts` derives the consumer set with `git grep` and
checks it against `cluster-tree-consumers.json`. **One source of truth (the
grep) with the roster derived from it** — not two copies checked for agreement.
Two directions, both load-bearing:

- `unrostered-consumer` — a **new** file couples to the stale tree → RED. The re-divergence guard.
- `stale-roster-entry` — a rostered file no longer couples, or is gone → RED. The roster must **shrink** as the migration lands, so it can never over-claim safety.
