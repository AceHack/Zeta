## Description

Step 1 defined the tokens; this makes them **load-bearing**. `Settlement.dc.html` computed a hex in its component script (`const C = {dim, teal, amber, red, violet}`) and interpolated it into inline styles — a second source of truth for *"what live looks like"*, which is exactly what contract change 3 removed `color` from the JSON to prevent.

```
{{ room.color }} · {{ room.lightBg }} · {{ dw.color }} · {{ room.pulse }}   →   var(--state)
```

**The legacy vocabulary is now translated at the boundary** instead of leaking into markup: `active→live`, `working→stale`, `attention→heat`, `idle→cold`, with `?? "cold"` as the fail-safe so an unmapped name reads cold, never live. Sealed rooms get the **withheld register** (`data-observed="false"`, `data-withheld="sealed"`) rather than a status — *"may not be seen"* is a different claim from *"nothing is happening"*, and the cascade makes withheld outrank state.

Also: **dweller colour is gone** (it was `i%2 ? blue : orange` — index parity wearing the appearance of meaning); the emoji lock became **◍**, since emoji render at platform-dependent size, weight and *colour*, defeating a DU whose point is that colour lives in one place; and the status dot gained `class="zx-pulse"` so the CSS motion rule has something to bite on — without it `[data-state="live"] .zx-pulse` matches nothing and motion silently never happens.

## A gap in my own tests, found by sabotage

The first six migration tests check the **bindings** are gone and the attributes present. Hardcoding `#5EC8C2` in a room **passed all fourteen** — the exact drift the DU exists to prevent, sailing through the suite written to prevent it.

The fix can't be "ban these hexes": brand chrome legitimately uses them (the ζ logo is amber). So the ban is **scoped to the room-rendering block**, where a state hex is always wrong. That sabotage now fails, and the same test asserts `var(--state)` *is* used — so "no hexes" can't be satisfied by rendering nothing.
