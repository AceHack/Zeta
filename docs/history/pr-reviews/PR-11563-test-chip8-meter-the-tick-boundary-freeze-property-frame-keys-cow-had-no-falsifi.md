## Description

## The question

Can an **unfrozen** reference cross a tick/continuation boundary at a site where a **frozen** one is assumed?

## The boundary

- `src/Core/SoftScheduler.fs:121-148` — `driveK`: `state <- s` is the tick boundary; `'S` is the whole carried state.
- `src/Core/SimLoop.fs:91` — the lap boundary; `SimLoop.Continuation` (line 119) carries a *pointer*, never a payload.
- `src/Core/SimFramework.fs:112` — `runK`, whose docstring (line 20) states the contract: *"same room, same seed ⇒ same report."*
- `src/Core/PredictionScheduler.fs:22-27` — `Planned.LastPrediction` is the speculative frame carried tick→tick.

## Enforced or merely available? — **AVAILABLE**

Nothing refuses an unfrozen reference. F# structural immutability does most of the work, and the discipline is genuinely well held, but the escape hatches are open: `Chip8Cow.Frame` (`src/Core/Chip8Cow.fs:32,39`) carries `V: byte[]` and `Keys: bool[]`, and `{ f with Keys = a }` installs a caller-owned array at ~20 sites.

## What was measured

The COW discipline for the two array fields of the **same record** had opposite metering status. Whole Tests.FSharp suite, Release:

| COW site | mutation | result |
|---|---|---|
| `Chip8Cow.setV` (`Chip8Cow.fs:60`) | `Array.copy f.V` → `f.V` | **12 failed / 5260 passed** — metered |
| `SoftChip8Flux.applyKey` (`SoftChip8Flux.fs:75`) | `Array.copy f.Keys` → `f.Keys` | **0 failed / 5272 passed** — unmetered |

`applyKey` is the one place an input crossing enters the `driveK` loop (`SoftChip8Flux.inputHandler`), and `Chip8Cow.step`/`tick` carry the `Keys` reference forward unchanged. So an aliasing `applyKey` writes through into every frame retained from an **earlier** tick — the antecedent a continuation carries forward acquires a key state the original tick never saw, and DST replay diverges from the run it claims to reproduce. Its own docstring already read as a claim: *"COW — fresh Keys array; parent untouched."*

## The change

Two tests, **no production change** — the code was already correct; the falsifier was missing.

- `applyKey is COW: the input crossing never writes through into the parent frame`
- `a key crossing at a LATER tick cannot reach back into a frame retained from an EARLIER tick` — driven through `SoftScheduler.driveK` with crossings arriving at tick ≥ 1 and the tick-0 frame retained. It asserts the crossings **did** land downstream *before* asserting they did not reach back, so it cannot pass vacuously.

Mutation numbers for the new checks: **2 failed / 11 passed** under the alias (and only those two); **5274 passed / 0 failed / 6 skipped** on this branch.

## No live bug found — what was checked

A mechanical sweep of all 144 array-typed parameters in `src/Core` found **zero** functions that write through a parameter array (the two `LatticeVoa.fs` hits are false positives — locally allocated). So the "someone mutates the buffer they handed in" crossing does not occur today.

**UNPROVEN hazards, named rather than fixed** (nothing refuses them; no in-repo mutator exists):

1. Caller-owned `bool[]` retained inside frames: `StateSpace.fs:81,133,182` (also retained in `Graph.Edges`), `SoftDrive.fs`, `SoftController.fs:59,69,84`, `MemoryLens.fs:52`, `ControlMerge.fs:29`, `HierarchicalPlanning.fs:242,251`, `Chip8Cow.fork`, `SoftChip8.resolve`. `SoftController.none` / `allButtons` are module-level singletons that become the `Keys` of many retained frames.
2. `Cart.Rom: byte[]` (`Cart.fs:73`) and `TwoTimescaleFold.SharedEvidence.Likelihood: int64[]` are caller arrays retained in long-lived values.

## Reference case, confirmed

`Chip8Cow` COW is genuinely correct: `Mem`/`Display`/`Extra` are persistent `Map`s, `setV` copies, `step` is pure. The `Chip8` mutable oracle is the declared exception and `clone` deep-copies.
