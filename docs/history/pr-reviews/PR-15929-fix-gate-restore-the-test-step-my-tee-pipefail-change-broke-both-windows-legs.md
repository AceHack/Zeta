## Description

**Mine, and main is red for it.** #15925 changed the Test step to `shell: bash` + `set -o pipefail`
+ `tee` to capture output for the perf collector.

| main commit | windows-2025 / windows-11-arm |
|---|---|
| `4779f542` (before) | success, success |
| `35ab8cc4` (**landed my change**) | success, **FAILURE** |
| `499fa5c6` (next) | **FAILURE, FAILURE** |

The step died in **~2 minutes** — far too fast for real test failures — so it was the *invocation*,
not the tests. Build succeeded and Test failed on both arms, which is the signature of a broken
command line. Windows runners resolve `shell: bash` to Git Bash, and forcing it changed
interpretation on legs that had been using the default shell.

## The fix

Test step **restored exactly as it was** — verified by parsing both YAML versions and comparing the
step objects, not by eyeballing a diff.

The collector step **stays and is now inert.** Its missing-log branch is honest: it reports that
nothing was captured rather than printing an empty ledger. The collector is tested and correct; what
was wrong was how the bytes were captured. A Windows-safe capture (`RUNNER_TEMP`, or a Linux-only
duplicate step with its own id — `steps.test.outcome` is read downstream so two steps can't share
one) is the follow-up.

## What I should have done

I proved the pipefail semantics carefully on Linux and **never asked what `shell: bash` does to a
Windows leg.** I verified the half I was thinking about and shipped the half I wasn't. The matrix
was in the same file.
