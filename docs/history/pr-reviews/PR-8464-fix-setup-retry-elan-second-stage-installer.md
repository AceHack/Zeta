## Description

fix(setup): retry elan second-stage installer

Wrap the pinned elan-init.sh execution in a bounded retry loop. The script download itself already uses curl_fetch with retries and SHA256 verification; the observed CI flake happened one layer deeper when upstream elan-init.sh fetched the GitHub release tarball and received HTTP 500.

Retrying the installer invocation keeps the pin and hash verification intact, absorbs transient release-CDN failures, and still fails loudly after four attempts if the upstream outage is persistent.
