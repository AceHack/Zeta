## Description

## The finding, verified

`full-ai-cluster/usb-nixos-installer/zeta-install.sh:1094-1099` (at `ff11e15a`):

```bash
HW_SRC="/mnt/etc/nixos/hardware-configuration.nix"
HW_DST="/mnt/etc/zeta/full-ai-cluster/nixos/hosts/${HOST}/hardware-configuration.nix"
if [ -f "$HW_SRC" ] && [ -e "$HW_DST" ]; then
  sudo cp "$HW_SRC" "$HW_DST"
else
  echo "[iter-5.1] WARN: hardware-configuration not copied (src=... dst=...)" >&2
fi
```

A failed capture printed one stderr line and the install continued. The script
has by that point created, formatted and mounted `longhorn{1..N}`
(`:907-909`, `:943-951`, `:1053-1066`), so continuing bakes the committed
placeholder — `/` and `/boot` only — and those partitions never mount again on
the node.

**When it can fire.** `[ -e "$HW_DST" ]` is false whenever the selected host
carries no `hardware-configuration.nix`. That is true today for
`hosts/worker-template` (menu choice 3 — the storage-heavy suggestion) and for
any custom host from menu choice 4. `[ -f "$HW_SRC" ]` is false whenever
`nixos-generate-config` exits 0 without producing the file.

**What the operator saw.** One `>&2` line, inside a run that is `tee`'d to a log
and scrolls past — the failure mode `:46-49` of the same file already documents
as faster than human read speed.

## How it compounds with #13252

`nixos/modules/longhorn-preflight-checks.nix` derives `requiredMounts` from the
host's own `fileSystems`. On a placeholder node that set is **empty**, so check
1 passes with nothing to check. The module says so honestly in its `HONEST
VACUITY` section — but it reads the empty set as a host that *chose* to declare
nothing, when it is equally the signature of an install that failed quietly. A
silent install-time fallback turned a brand-new guard into a check that cannot
fail.

## Is the placeholder ever legitimate? Yes — and that is not what changed

`hosts/control-plane/hardware-configuration.nix` and
`hosts/worker-gpu/hardware-configuration.nix` are `/`+`/boot` stubs on purpose:
they exist so `nix flake check` can evaluate an unprovisioned host in CI, and
both say so in their own header. Blanket-refusing a placeholder **in git** would
break that. Nothing here objects to the committed files; the defect is the
install-time capture failing quietly.

There is also one legitimate **non-copy**: `hosts/worker-template` imports no
`hardware-configuration.nix` at all — it is disko-shaped and declares its
filesystems from `zeta.disko.*`. Refusing there would be wrong.

## Refuse vs loud — chosen deliberately, per branch

| branch | behaviour | why |
|---|---|---|
| probe output absent | **bail** | there is no capture of the hardware at all |
| host dir absent | **bail** | `nixos-install --flake #HOST` has no such attribute either |
| host imports the file but does not carry it | **bail** | the flake cannot evaluate |
| copied, but the result omits a mounted Longhorn path | **bail** | the check is on the CONTENT, not on `cp`'s exit code |
| host carries no file **and imports none** (disko) | **loud stdout NOTICE** | nothing at install time can prove a disko host declares those disks — disko derives them from `zeta.disko.extraDisks`. Handed to the boot-time check, which has the node in front of it. |
| unrecognised verdict | **bail** | an unhandled arm is the same silent-fallback class |

**What a correct operator loses.** A refusal costs a re-run of an installer
whose disks are already wiped either way, and it lands *before* `nixos-install`.
The old behaviour cost them a node that looked healthy and had no storage. On
the disko branch a correct operator loses nothing but gains a console line they
must read; the enforcement moved to boot, where it can actually be decided.

## The boot-time half — extending #13252, not rewriting it

New **check 1b** in `longhorn-preflight-checks.nix` asks the *disks* instead of
the config. Any device carrying a `longhorn*` filesystem label — written by this
installer's `mkfs.ext4 -L longhornN`, so it is positive evidence the installer
prepared it as Longhorn storage — that is not mounted under `/var/lib/longhorn`
is refused, with the failed-capture cause named in the remedy. It routes through
the existing `fail()`, so the single exit path and the single `/dev/console`
writer are untouched. A node that genuinely runs no Longhorn storage has no such
label and stays quiet, so no per-host opt-out is needed.

The verdict now reports `longhorn_devices` beside `mounts_checked`:
`mounts_checked=0` alone was never "nothing to check", and now the pair says so.

The `HONEST VACUITY` section is rewritten rather than left standing — a stale
note saying the case passes trivially would itself be the drift.
