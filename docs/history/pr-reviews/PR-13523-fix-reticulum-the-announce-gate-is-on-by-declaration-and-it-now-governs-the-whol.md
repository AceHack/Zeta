## Description

## What this closes

`docs/BUGS.md` **RESIDUAL 1** — the announce-auth membrane #13466 built was correct and switched off.

## The residual as filed was mis-scoped, and that is the first finding

RESIDUAL 1 named four consumers that "still default to `announceAuth: {mode:"off"}`" and asked for
`off → dual → required` per consumer. Looked, rather than inherited:

| file | what it actually does |
|---|---|
| `mux-transport-bridge.ts` | mentions `reticulum-transport.ts` in a "composes with" docstring. No import. |
| `network-transport.ts` | same — names `ReticulumTransport` as one possible backend of an interface. No import. |
| `dht-discovery.ts` | header mentions announce as the layer below; shares the *concept* of a destination hash without importing it. |
| `reticulum-metered-transport.ts` | imports `destinationHash`, and nothing else. No announce, no path table, no frame. |

Repo-wide (`src/`, `tools/`, `clis/`), the only `createReticulumTransport` call sites are this
module's own tests. **The migration as filed had an empty domain.** What was actually wrong was the
*default*, and a second thing that was not filed at all.

## What changed

- **`announceAuth` is REQUIRED on `ReticulumConfig`.** `{mode:"off"}` still typechecks and is still
  exactly as forgeable as the pre-fix wire — what is gone is *inheriting* it without writing it
  down. Every construction site now declares its mode, so an unmigrated consumer is visibly
  unmigrated rather than merely looking fine. Done now because it costs three test files now and is
  unretrofittable once a fleet depends on the default.
- **The gate now governs the WHOLE FRAME, not just the path fold.** This was a live hole, not a
  tidy-up. The gate guarded `observeAnnounce`; the other two exits ran regardless. So a node in
  `"required"` that **refused** a forged announce still (a) delivered the frame's payload upward
  attributed to `frame.announce.zid` — an unverified identity handed to the upper layer as the
  sender — and (b) relayed the frame onward, amplifying to every peer it bridges the forgery it had
  just detected. The relay step's own comment claimed the opposite; that claim was false when
  written and is true now, by an early return rather than by assertion.
- **Fail-closed at the JS boundary**, mirroring `llmtv-node`'s signer backstop: an omitted
  `announceAuth`, or a non-`off` mode with no `verify`, is refused at construction. Previously the
  missing `verify` surfaced as a `TypeError` thrown from inside the packet handler on the first
  inbound frame — a security surface failing by exception on a hostile wire.

## Both directions, everywhere

- Convergence suites (two-node, three-node relay through a transport node, and the `llmtv-node`
  integration) now run over **both modes** and assert identical outcomes. That makes the migration's
  central claim falsifiable: **authentication changes nothing for honest traffic.** A gate that
  broke multi-hop relay would pass every forgery test and still be undeployable.
- The `"off"` negative control is **extended, not weakened** — `off` must still capture the route,
  still deliver the payload, and still relay the forgery, at all three exits. A partial control
  stops measuring what "on" buys.
- `"dual"` had no transport-level coverage at all. It now has the window's sharp case: an unsigned
  announce is admitted and flagged; a signed-but-**invalid** one is refused and never downgraded to
  the unsigned path, at all three exits.

## The invariants that were held

- **`trust` stays a declared input.** `sign`/`verify` are injected; the transport holds no key
  material, no trust store, no crypto. Dependency stays one-way (auth → transport); no import cycle.
- **`nowMs` is written, never predicated.** No wall clock filters what enters the fold
  (`.claude/rules/local-time-never-enters-the-shared-fold.md`). The two-nodes-at-different-times
  test is untouched and still passes.
- **Neutral verdicts.** `signature-invalid` / `identity-mismatch`; the wording test is untouched.

## Migration order and default — the deliberate decision

**Globally, at the type, not per-consumer** — because there are no consumers. Per-consumer routing
would have been three no-ops and one file that imports a hash function. The `off → dual → required`
window is preserved and now actually exercised at the transport level, so the *next* consumer walks
it with coverage in place. No lane is left silently off: there are no production lanes, and the
tripwire below fails the moment one appears off-mode.

## Standing guard against re-rot

`reticulum-announce-auth.adoption.test.ts` refuses any **production** call site declaring
`{mode:"off"}`. Its quantified claim ranges over ∅ today — the vacuity class — so two companion
tests make it mean something: one falsifies the predicate against a fixture it must catch, one
proves the scanner sees the call sites that *do* exist (so empty means empty, not "scanner broken").
A `@ts-expect-error` covers the type-level half: if `announceAuth` ever goes optional again,
`tsc --noEmit` fails, and nothing else in the suite could catch that, because every existing site
passes the field explicitly.

## Left filed, deliberately

- **RESIDUAL 2 (hop-count replay)** — untouched. Needs per-link auth or a signed monotonic sequence
  in **agreed phase order**, explicitly not a wall-clock window. Separate design.
- **RESIDUAL 3 (NEW)** — `dht-discovery` carries the same unbound `(dest, zid)` pair on the layer
  above: `DhtNode` has both as independent fields, `observeNode` never checks the binding, and
  `lookup` folds nodes returned by queried peers straight into its shortlist. Filed with a
  **`LIFTS WHEN:`** rather than half-fixed — the guard is not free there, because
  `dht-discovery`'s four `dhtErasureProfiles` are measured over deliberately *unbound* short ids
  (`{dest:"8000", zid:"a"}`) and `dht-discovery.erasure.test.ts` re-checks their
  `largestFibre`/`bitsErasedPpm` against the code. Binding `dest` to `zid` changes the reachable
  state space, so the four profiles must be re-derived in the same change — and a profile whose
  numbers no longer match its operation is a discharge certificate that has stopped being true.
