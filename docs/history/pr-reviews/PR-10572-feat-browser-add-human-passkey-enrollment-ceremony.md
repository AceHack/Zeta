## What

- add a source-owned WebAuthn registration ceremony to the active Dark Hall browser page
- emit a public-only ES256 enrollment package from an explicit user activation
- independently verify the package's challenge, origin, RP-ID hash, flags, credential ID, and P-256 public key before registry review
- align the existing identity demo with the same enrollment treaty

## Authority boundary

Enrollment requires a person to confirm the browser authenticator prompt. It creates no repository authority and stores only the public credential ID in browser-local storage. A separate protected PR must add the independently verified public author entry to `docs/security/proposal-author-registry.json` before the passkey can sign accepted proposals.

Startup, visibility changes, and page-show events remain polling-only. They cannot trigger enrollment or signed submission.
