## Description

Four agent results from the hardware round.

## R12 — a web page the operator merely opens can execute HSM commands blind

Read from upstream `yubihsm-connector` master @ `76b26eb8` (3.0.7). `apiHandler` performs **exactly two** admission checks before proxying to the device: method must be POST (`api.go:175`) and `ContentLength` in [3, 3139] (`api.go:182`). **`Content-Type` appears exactly once as a request-side value in the whole repository** — `api.go:81`, as a logrus field. **It is printed and discarded, never compared.**

So a CORS-simple `text/plain` POST triggers no preflight, passes both checks, and executes. The page cannot read the reply and **does not need to** — blind writes buy session-slot exhaustion, denial of the root of trust, and the response-parser position.

**The one mitigation does not apply:** host-header allowlisting defaults to `false`, and the measured connector runs with no config file. Even enabled, its default list contains `127.0.0.1` — which is exactly the `Host` a browser sends. **It defeats DNS rebinding, not this.** UNKNOWN → **REACHABLE**.

## The delegated-capability lint is built — 43 tests, 4 mutations proven

Yubico's claim holds only if *their own* means **delegated**: the minter chooses the new key's password and can open a session with it. **It is a closure, not a one-hop check** — a pinned case needs two fixpoint rounds.

**Three corrections to my own brief, each primary-sourced:** `delete-object` is a *command*, not a capability (the lint **refuses** a roster naming it); `change-authentication-key` is not an escalation; and **the device does enforce domain subsetting on create**, which *narrows* my central claim — the real defects relocate to declared-domain-trespass and the **import-wrapped** path, run as a separately-named pessimistic model registered `doc-silent-unverified`, **explicitly not claimed as demonstrated**.

## The drainer, with its limit at the claim

`(f+1)(rT+c) ≤ R` ⇒ **T = 9.33 s** at 1 payment/s. Two conclusions pinned as tests: **the drainer consumes what it protects**, and a **rate ceiling** exists above which no schedule is lossless. The hash chain proves a *drained window* was unaltered — **it does not prove nothing was evicted before you drained, and it stays valid across a wrap.**

**The tick trap is enforced by a test:** host wall-clock lives in one field named `hostObservedAtUntrusted` and **decides nothing** — proven by re-running with a 1999 timestamp and asserting identical findings. **You get order, never wall-clock time.**

**A finding that outranks the drainer:** Yubico's documented `command-audit` default parses to **every command disabled, including SIGN ECDSA**. A perfect drainer over that config exports session-open noise and **never sees a signature.**

## Seal tier — no new string; the *difference* was what was missing

`hardware-tpm2` already **is** sealed-to-PCR-unsealed-to-RAM. What was missing: both tiers answered `true` to `isHardwareSealTier` and the gap lived only in a comment. Now an exhaustive `Record` over the tier union means **a new tier does not compile until someone says where its wrapping key lives.**

**A real hole found while extending no-silent-downgrade:** `createSealedFileShareAdapter` took the tier as a **caller-supplied label nothing derived from the backend** — one wrong argument produced an adapter that *reported* `hardware-pkcs11` while unsealing into host RAM, **and the artifact carries the false claim for its whole life.**

## The curve probe has four states, and the fourth is the crux

`tpm2-tools` `dump_ecc_curves` recognises exactly eight identifiers, none secp256k1, and prints `unknown<HEX>` otherwise. **So the tool's vocabulary is the registry's vocabulary** — which corroborates the registry claim *and* means a vendor secp256k1 **could not print its name**. Hence **`indeterminate`**: the curve is *not excluded*.

**Mutation B is reported as a finding, not a pass.** Deleting one throw left everything green because that call site is unreachable-as-a-difference. **Not deleted, not pretended otherwise** — the limit is written at the call site with the measurement that established it.

## KSP verdict: mostly already decided, Microsoft is not in the way

*"Starting with Windows 8, it is no longer a requirement that CSPs must be signed"*, and the PPL gate never loads a third-party KSP. **Not an appointed hub.** It's blocked by having **no consumer**.

And the structural fact: **a KSP is loaded into every calling process while a USB HSM is exclusively claimed** — so any KSP over USB is **necessarily a thin client of a device-owning broker.** They are not two products.

**The highest-value finding deletes work:** `libyubihsm` speaks **`yhusb://`** — direct USB, no daemon, no listener. **Every connector finding is a property of a listening socket.** Not exercised here: it claims the device exclusively and would take it from the running connector.
