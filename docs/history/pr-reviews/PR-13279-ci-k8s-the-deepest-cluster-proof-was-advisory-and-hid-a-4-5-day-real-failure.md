## Description

ci(k8s): the deepest cluster proof was advisory — and hid a 4.5-day real failure

`live kind included Synced+Healthy proof` is the strongest end-to-end evidence
this repo has that the cluster comes up: it asserts every non-excluded dev ArgoCD
Application reaches its required state on a real kind cluster. It carried
`continue-on-error: true`, so it could not fail a run.

THE RECORDED REASON, and why it expired. Added 2026-06-20 in #8789, a five-part
`chore(setup)` PR. Its only justification is one clause of one bullet: "live kind
job advisory until stable". Explicitly temporary, with an exit condition nobody
came back to. The job had shipped BLOCKING seven days earlier (#7911), and the
flag carried no inline comment in the 62 days it stood.

THE MEASUREMENT, over all 195 runs of this job 2026-06-21..2026-08-21:

  * 157 decisive conclusions — 104 pass / 53 fail (66%).
  * ZERO failures in cluster creation, install.sh, cache restore or teardown.
    All 53 were the assertion step itself. It does not fail for environmental
    reasons — which is the one thing that would have justified advisory status,
    and the thing the data refuses.
  * Failures cluster into outages traceable to real, later-fixed defects. Only
    4 isolated failures in two months (~2.5%).
  * 91% pass before the 2026-08-16 regression (main 90%, PRs 92%); 100% (10/10)
    after it was fixed on 2026-08-21.
  * A green run is ~10 min median. Only failures run long (~45 min to timeout).

AND WHAT IT COST. 52 of those 53 failures reported run-level `success`. The
2026-08-16..2026-08-21 window was 44 consecutive failures, 18 of them on `main`,
and all of them one real defect: `cdi` and `kubevirt` asserted under the
auto-sync contract when both are declared manual-sync (fixed in #13084). The job
caught it on the very first run. It went unseen for four and a half days because
every surface that aggregates runs said green.

The job was never the problem. The reporting was: a check that ran and failed
looked exactly like a check that passed.

WHAT CHANGES. `continue-on-error` is removed, so the run conclusion is honest,
and the reason is now legible without opening an 11,000-line log:
`included-proof-summary.ts` reads the harness's trailing JSON and emits a job
summary plus one `::error::` annotation per unhealthy Application. A run that
printed no verdict at all (timeout, crash, lost runner) renders UNREADABLE —
never green, never a specific failure it cannot support.

WHAT DOES NOT CHANGE. This does not block merges. `gate (required)` is the only
required status check on this repository and this job is not in its floor.
Making it required is a policy call for the maintainer, not a cleanup, and is
deliberately not done here.
