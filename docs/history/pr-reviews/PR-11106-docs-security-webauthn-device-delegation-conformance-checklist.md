## Description

Aaron: *"is this a valid path for humans to grant permission to AIs to use their hardware through PWAs securely … we have wasm and webgpu that can run AIs and commit changes to github for Zeta."*

**Architecturally yes — with one gap the standard does not close.**

WebAuthn proves **a human was present at a device at a moment**. It does **not** bind the assertion to *what* was authorized. For login that's sufficient: the human authenticates *themselves*. For delegation it isn't — the human authorizes **an agent to act later, unattended**, and the assertion carries no statement of what was granted.

The substitute for the deprecated `txAuthSimple` extension is cheap and is the most important decision in this shape: **make the challenge `SHA-256(capability descriptor)` and display that descriptor** (§0). Then the signature binds to what was granted, not merely to someone touching a sensor.

## What the checklist is

One line per property, each with a test that **can fail** — because "18/18" without them counts runs, not guarantees (`AssertedOnly`).

**Highest-value additions beyond a stock verifier:**

- **§1.3 high-S rejection.** ECDSA malleability means `(r,s)` and `(r, n−s)` both verify. A verifier that normalises or ignores S accepts **two encodings of one authorization**, defeating any exactly-once accounting above it.
- **§2.1** the signature must be over `authenticatorData ‖ SHA-256(clientDataJSON)`, **not** the challenge. Signing over the challenge passes hand-written tests and fails against every real authenticator — or appears to work while checking nothing.
- **§4.3** UV must be **required**, not merely observed. "Present" is not "required."
- **§6 — matters more than the crypto:** scope, TTL, revocation, binding, audit, and a fine-grained **App installation token rather than a PAT**. A flawless verifier in front of an unbounded bearer token is the weaker half doing all the work.
- **§7:** compute consent (WebGPU/WASM) and act-on-GitHub consent are **separate grants**. Conflating "may use my GPU" with "may commit as me" is the likeliest design error here and is invisible until exploited.

Fixtures are specified **hex-in-JSON** per `no-binary-in-proof-lineage`, and §9 requires reporting *which lines pass plus the mutation that makes each fail* — a line with no failing mutant is not covered.
