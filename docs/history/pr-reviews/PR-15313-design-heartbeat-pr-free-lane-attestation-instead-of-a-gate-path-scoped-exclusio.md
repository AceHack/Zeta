## Description

Design + falsifier for the PR-free heartbeat lane, per Aaron's brief: *"heartbeats should not need a PR to go to main… any new design that has PRs as part of the design should be treated as a smell."*

**No ruleset or branch protection is changed here.** The exact change is written out as a reviewable command for the maintainer's own hand, gated behind three steps that need no ruleset change at all.

## The straight answer to "maybe we can exclude the heartbeat folder"

**No — not expressible on GitHub.** Rulesets scope by **ref**, never by path; `required_status_checks` is all-of-the-branch or none. `file_path_restriction` exists and is available on this plan (org is `enterprise`), and it is the wrong polarity (deny-list, not allow-list) *and* the wrong axis (no actor scoping). What we want is *(actor × path × operation)*; the forge's language is *(ref × rule)*. That gap is the sharpest concrete argument for sovereign mode in the whole document — a remote we control takes a `pre-receive` hook that says it in ten lines.

## The surface is smaller than the record claims

Measured live, and the brief I worked from listed two rulesets — there are five:

| Ruleset | Rules | Bypass |
|---|---|---|
| `Branch Safety` 16189060 | `deletion`, `non_fast_forward` | **none** |
| `CI Gate` 16134995 | `required_status_checks: ["gate (required)"]` | `RepositoryRole 5`, `pull_request` |
| `Default` 15256879 | **`[]`** | none |
| `Heartbeat Branch Protection` 16934633 | `deletion` on `heartbeat/*` | none |

Plus classic protection: `enforce_admins`, `required_linear_history`, no force-push, no deletions — and **no required status checks, no required PR reviews**.

So **nothing on `main` requires a pull request.** Exactly one mechanism forces every lane through one: a required status check is evaluated at push time against the pushed tip, and a commit that has never been through a check run is *missing* it. **One ruleset, one rule, one field.**

## What replaces the gate

A **content-bound** attestation. `Verification-Subject` is the commit's *own tree sha*, so a **copied** attestation is mechanically detectable — closing half of the limit `agencysignature-block.ts` records as unfixable. A **forged** fresh one is not closable by any parser; that half is priced (§5c), not claimed away. Evaluated and rejected extending AgencySignature v1: absence there honestly asserts nothing, absence here must be loud, and a key with inverted absence-semantics would corrupt both.

## Containment is structural, not procedural

Bypass actors are **per-ruleset**. A `CI Gate` bypass grants nothing in `Branch Safety` and nothing against classic protection. The lane can **append and can never erase, rewrite, or merge** — the compensatable class in `uncompensatable-floor.yaml`'s own sense of the word.

## The falsifier, and what it found

`audit-heartbeat-lane-attestations.ts` + `registry/heartbeat-lane-allowlist.json`, 38 tests, one per violation class, **wired into `cross-verify`**.

- **As shipped on `main`: clean over 300 commits — and vacuous**, because the lane identity does not exist yet so all 300 are `NOT-LANE`. Reported as such, not quoted as a pass.
- **Counterfactual (current flush identity, cutover moved back): 290 violations of 300.** It fires at scale on real history.
- **Allowlist fit:** 40/40 real `[heartbeat-batch-merge]` commits clean, 0 path escapes. `archive(pr-reviews)` 20/20. Society, drift and metrics escape only on telemetry-shaped paths — the mechanism generalises.

Two real defects found while building it, plus three more from making it actually run:

1. **`docs/github/prs/manifest.jsonl` is not append-only.** Rows are inserted in **sorted order**, so 13 of 40 flushes show *zero deletions* while the pre-image is *not a byte prefix*. The cheap check (`--numstat`, deletions == 0) would have passed all 13. This is why the implementation reads both blobs.
2. The byte budget was measuring **blob size** rather than added bytes — every flush would have gone red.
3. Collection is two-phase: at `fetch-depth: 1` the tip has no parent, so the naive form enumerates all 45,823 files and `<sha>^` does not resolve. It now **refuses (exit 2)** rather than reading a missing object as a violation.
4. The parent probe used `<sha>^@`, which expands to all parents while `--verify` demands one ref — it failed on every commit. Caught by the counterfactual, not the unit tests.
5. Per-check millisecond costs in the doc were **estimates presented as measurements**. Replaced with observed numbers and an explicit note that the breakdown was not measured.

## Two side-findings worth the maintainer's eye

- **The PR route forces the lane to wear a human's identity.** Actions may not open PRs on this enterprise, so a person-owned PAT does it — all 59 daily flush commits are authored by `aaron_bond@yahoo.com`. Removing the PR **removes** a shared-human-credential dependency. A direct push is also strictly *more* forge-agnostic: zero forge API calls versus six plus a GraphQL mutation.
- **`docs/operations/branch-protection-lfg-main.json` is stale**: it describes ruleset 15256879 as carrying squash-only merges and thread resolution. Live, that ruleset has `rules: []`. Independent second confirmation of the forge-agnostic doc's §4d. Material and Aaron's call.

## Recommendation

**Yes, with sequencing.** Steps 1–3 (land the audit; teach the *existing* PR lane to write the attestation, where the gate still catches it if wrong; prove the App identity on a throwaway branch) need no ruleset change. Step 4 is then one field. **The one thing I would not do is open the bypass while step 2 is unproven** — an attestation nobody has ever seen fail is indistinguishable from one that cannot fail.
