## What this does

`Human-Review` and `Human-Review-Evidence` now reconcile the same way and in the same
direction as `Action-Mode` — **to the weakest claim present** — with **no
`accountabilityAnchor` required**.

## Why under-claiming is the safe direction

The check's own error text names the hazard: *"Silently taking either end can record a
human review that the other block denies — manufacturing authorization nobody gave."*

**The manufacture is a strengthening.** Taking the weakest claim cannot strengthen
anything — structurally, not by convention: `explicit` is the *maximum* of
`HUMAN_REVIEW_BY_HUMAN_AUTHORITY`, so the minimum of a disagreeing set can never be it.
The loud failure is warranted in the *strengthening* direction only. Under-claiming is
always safe; over-claiming is the sin.

**What is given up is real**, and it is the same loss the `Action-Mode` reconciliation
already accepted: #13909's genuinely-reviewed security fix lands under an authoritative
reading that says no human reviewed the change, with no per-commit attribution left to
recover it from. The record may understate human backing. It may never overstate it.
That asymmetry is the entire warrant.

## The rostered-pair path was already implemented — this generalises it

`CANONICAL_SHAPE` documented it *and* `reconcileHumanReview` / `reconcileReviewEvidence` /
`accountabilityAnchor` implemented it, wired into both `detectReconciliations` and
`detectBlockDisagreement`. So this is a **generalisation, not a new mechanism**: the same
weakest-claim reconciliation, with the gate removed.

The gate never guarded the property that makes the reconciliation safe — the **direction**.
It guarded **coverage**, and it charged for a relaxation that was already sound. Because it
required a key no block on `main` carries, the relief it was written to deliver **reached
zero real PRs**. `accountabilityAnchor` is retained (it is still what the falsifiers use to
show a partial or unrostered pair is not an anchor) but no longer gates.

## What still has teeth

A gate removed is exactly how a check becomes one that cannot fail, so four refusals, each
with a falsifier:

1. **Out-of-enum values have no rank** and are not ordered. `main` carries 25 out-of-enum
   `Human-Review` spellings over 273 blocks; a set containing one stays loud. Now enforced
   for `Human-Review-Evidence` too, which it was not before.
2. **Resolutions only discard, never invent** — always a value some constituent wrote.
3. **`Human-Review-Evidence` never reconciles on its own**, and its four pointer values
   (`chat` · `pr-review` · `pr-comment` · `signed-policy`) are a **partial** order with no
   minimum — they name different *places* a review is recorded, not different *amounts*.
   Only `none` is tier 0, so a set reconciles iff `none` is in it.
4. **NEW — the cross-field guard.** The resolved *pair* must satisfy
   `validateReviewConsistency`. Removing the anchor makes its failure shape reachable:
   blocks disagreeing on review while all citing `chat` would resolve key-by-key to
   (`not-implied-by-credential`, `chat`) — a pair the schema itself refuses — and report
   green. That set now stays loud. `reconcileReviewPair` resolves both keys together so the
   gate and the report cannot drift.

**Scope is unchanged elsewhere.** `Credential-Mode`, `Agency-Signature-Version`,
`Accountable-Party` and `Authority-Basis` are untouched and as loud as ever.
