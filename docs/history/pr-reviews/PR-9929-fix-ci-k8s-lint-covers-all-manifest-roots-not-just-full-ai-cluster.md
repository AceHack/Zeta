## Description

Found while auditing test coverage ahead of self-hosted runners.

**19% of the k8s manifests were validated by nothing.** `yamllint` and `kubeconform` both pointed only at `full-ai-cluster/k8s/`:

| root | manifests | validated before |
|---|---|---|
| `full-ai-cluster/k8s` | 105 | yes |
| `infra/k8s` | 12 | **no** |
| `agentic-organization/deploy` | 12 | **no** |

The unvalidated set includes the ArgoCD bootstrap and the Orleans deployment/service/rbac/configmap. These still reach a cluster via ArgoCD sync, so a malformed manifest failed at *apply* time against a live cluster rather than in CI. Once runners live on USB-provisioned k8s nodes, that means finding a bad manifest on physical hardware mid-provisioning.

**Verified before shipping** so the gate doesn't go red on arrival:

```
yamllint -d relaxed infra/k8s/ agentic-organization/deploy/   rc=0 (warnings only)
kubeconform -strict over the 24 newly-covered files           48 resources
                                                              42 valid, 0 invalid, 0 errors, 6 skipped
```

The job stays advisory (`continue-on-error`) exactly as before — this widens what it looks at, it does not change its blocking status.
