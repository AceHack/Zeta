## What — Aaron 2026-06-07
> "the merge request could be your fs metadata, and their response is a streaming response of missing content."

The network form of the ancestry-free merge — content-addressing makes it trivial:

1. requester → responder: **fs metadata** (manifest: path→hash links + content-hash set/closure, or root + reachability summary) — compact, **hashes not content**;
2. responder **set-diffs** against its store → the nodes the requester lacks;
3. responder **streams** just the missing content (pipelined/seekable — Jumprope);
4. requester content-unions received + resolves path collisions → merged branch.

"What's missing" = a **set-difference of content hashes** (no 3-way diff / merge-base / ancestor); transfer **only what the other side lacks** (globally deduped). The standard CAS-sync shape we adopt: **rsync · git smart protocol (want/have) · IPFS Bitswap · Dat/hypercore · BitTorrent**. Transport rides the bus/CloudEvents; big blobs stream as Jumprope chunks. The sync mechanism for the geo-replicated/anygit edge-replica vision + cross-cell AP reconcile.
