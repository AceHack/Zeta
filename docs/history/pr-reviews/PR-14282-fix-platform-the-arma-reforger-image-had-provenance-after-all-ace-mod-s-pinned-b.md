## First: ich777 really has nothing, and that was re-checked rather than assumed

The sibling `gmod` defect had a fix **at the same publisher** (`:gmod` is a 404, the real tag
is `:garrysmod`), so a 404 here proves nothing about whether the image exists under another
name. The tag list was enumerated instead:

```text
GET ghcr.io/v2/ich777/steamcmd/tags/list?n=1000     -> 94 tags
    arma-family entries: arma3, arma3exilemod        (nothing reforger-shaped)

gh api /users/ich777/packages?package_type=container -> 98 packages, none Arma Reforger
hub.docker.com/v2/repositories/ich777/               -> the same set, none Arma Reforger
```

For contrast, on the same token: `garrysmod`, `unturned` and `arma3` all return 200 with a
digest. The publisher genuinely ships no Arma Reforger image under any naming.

**Substituting a nearby ich777 tag stays refused.** The workitem already measured that the
game tags share only their first two layers, so they are different images, not one base with
four entrypoints — picking one would be a guess wearing a pin's clothes.

## The replacement, and every bar it had to clear

`ghcr.io/acemod/arma-reforger`, pinned:

```text
ghcr.io/acemod/arma-reforger:sha-cd226c0@sha256:90883ce2f3d8b3b5b132ae7f4b3377afdc9e6be7e7c8cb1a290f8bd7b39d079c
```

| question | answer, measured 2026-08-23 |
| --- | --- |
| does it resolve, without auth | yes — manifest HTTP 200, single manifest, `linux/amd64` |
| is it measurable | **55,712,029** compressed bytes, via this repo's own `measureImage` |
| where does it come from | the image's OWN label: `org.opencontainers.image.source = https://github.com/acemod/docker-reforger` |
| is that credible | ACE Mod (the ACE3 org), MIT, 117 stars, tip commit `cd226c0` of 2026-07-30 |
| **is it "the latest version"** | `latest` and `sha-cd226c0` resolve to the **same digest**, and `cd226c0` is the tip of that repo's default branch. So yes — and the pin says so checkably instead of asserting it |
| does the image agree it is this game | its config sets `STEAM_APPID=1874900` — the identical appid this Blueprint used to hand to steamcmd |
| is the game real on Linux at all | Steam app-info for 1874900: name "Arma Reforger Server", type `Tool`, `oslist windows,linux`, depot **1874902** declaring `oslist: linux` |

That second-to-last row is the same check that validated the `gmod` fix (`garrysmod` agreeing
with `+app_update 4020`): **the image and the Blueprint agree about which game this is,
independently.** Neither was derived from the other.

The digest is the pin because `:latest` is unmeasurable in principle — it was one of the
original blockers. The tag is carried beside it only so a reader can see which commit built
it; `parseImageReference` handles the tag+digest form and has its own falsifiers for it.

## The second defect went with it — otherwise this would be a measurable image that cannot run

`081M0QB1ZCV087G0R001P9YCPX` records that every steamcmd Blueprint calls
`/opt/steamcmd/steamcmd.sh` while the ich777 image declares `STEAMCMD_DIR=/serverdata/steamcmd`.
Reading the layers says something stronger than the declaration did:

```text
ghcr.io/ich777/steamcmd:unturned — every path matching `steamcmd` or `opt/`, all six layers:
  serverdata/steamcmd          <- an EMPTY directory
  opt/scripts/start.sh
  opt/scripts/start-server.sh
```

**`/opt/steamcmd` does not exist, and neither does any steamcmd binary.** `start-server.sh`
wget's `steamcmd_linux.tar.gz` at runtime into `${STEAMCMD_DIR}` and then runs the
`+app_update ${GAME_ID}` itself.

So `install:`, `command:` and `args:` are **gone** from this Blueprint, deliberately. The ACE
Mod image installs and launches itself: its Cmd `python3 /app/launch.py` (read out of the
layer, not from a README) runs

```text
/steamcmd/steamcmd.sh +force_install_dir /reforger +login anonymous +app_update $STEAM_APPID validate +quit
```

then writes `/reforger/Configs/docker_generated.json` from the environment and execs
`./ArmaReforgerServer` in `/reforger`. **Overriding the Cmd would skip both the install and
the config generation**, so the correct fix for the path mismatch here is to issue no command
at all and configure by env. Storage moves to `/reforger` (the image's WorkingDir and its
`+force_install_dir`; `Configs/` and `workshop/` both live under it). Two variable defaults
were wrong on their own terms and are corrected to the image's documented values: `SCENARIO`
was `Conflict-Everon`, which is not a scenario id, and `CONFIG` was `server.json`, a file that
does not exist in a fresh volume.

**`gmod` and `unturned` are NOT fixed here, and the workitem says why.** They are wrong twice
— the dead install path *and* a `command:` that replaces the entrypoint which would have
installed the game — so correcting the path alone leaves a pod running a binary nobody
fetched. That is its own diff, with its own review. `unturned` remains the tell: it measures
fine, so no pricing signal will ever point at it.
