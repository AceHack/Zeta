## Description

## What changed

- add database revision invalidation messages to the browser tab coordinator and lifecycle host
- add a source-owned browser ZetaDB tab runtime that serializes finite local writes and peer-triggered rereads
- compose the runtime into the real Chromium multi-tab fixture and prove a surviving tab reads the committed rows without replaying writes
- fix the current main TypeScript regression in the regional book rewrite script by refusing a missing HTML block

## Why

Browser tabs should cooperate as finite database executors without assigning continuous ownership to a service worker or broadcasting database bytes. Persisted storage remains authoritative; peer messages carry only bounded revision evidence.
