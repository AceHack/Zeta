## Description

## Why

The browser receipt proposal port had owned interfaces but no source-owned native WebAuthn signer or credential-free carrier. The verifier already uses Ace canonical bytes and an anti-rollback author registry, while the open Pages work in #10512 keeps its browser implementation in a demo and exchanges an assertion for a server capability. This adds the local-signing alternative without merging those trust models.

## What

- move proposal constants and wire types into a browser-safe shared contract used by the Node verifier/generator and browser signer;
- validate exact patch digest, origin, RP ID, credential ID, nonce, lifetime, and current time before invoking WebAuthn;
- serialize the native assertion with required user verification and typed cancellation/backpressure;
- present the exact gated-commit issue envelope without a repository credential in the page;
- report issue-composer `presented` separately from durable `submitted`;
- fix the newly landed timeout workitem's incomplete source path so auto-vivify remains green.

## Proof

- 77 receipt, transport, proposal, verifier, and gated-commit tests pass;
- `bun run preflight:quick`: all 12 checks pass, including the pre-push rerun;
- browser-target bundles contain no `node:`, `Bun.`, or `require(` references;
- the signer challenge is byte-compared with the existing Node verifier challenge;
- the carrier body round-trips through the existing gated-commit parser.

## Boundaries

- Passkey signing remains an explicit caller action; background acceptance polling never invokes it.
- Opening a prefilled GitHub issue is presentation, not proof of submission or acceptance.
- No live hardware-passkey ceremony is automated in CI; the native boundary is exercised through an injected browser host.
- This is a token-free alternative behind owned ports, not a replacement for #10512's separately hosted operator-service path.
