## Description

## Why

PR #14371 reproduced a publication liveness failure: a later cadence tick force-pushed the active telemetry branch while its final required check was still running. That replaced the tested head and restarted the complete gate. On a busy main, the generated ledger could remain stale indefinitely.

## What changed

- Keep the active telemetry PR head immutable while it is open.
- Mirror each publishable aggregate to a second `heartbeat/<lane>-buffer` ref.
- Route later observations only to that buffer until the active PR disappears.
- Promote the complete buffer on the next publish cycle.
- Resolve overlapping generated snapshots toward the newer buffered aggregate.
- Fail closed when the remote buffer cannot be inspected.
- Qualify four newly landed workitem references so auto-vivify resolves their existing `.claude/rules` sources.
