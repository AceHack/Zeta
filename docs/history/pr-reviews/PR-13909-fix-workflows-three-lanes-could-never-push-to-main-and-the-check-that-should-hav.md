## Description

Three automated lanes ended in a push at `main` that ruleset "CI Gate" (16134995) refuses at push time — `gate (required)` is evaluated against the pushed tip, so a commit that has never been through a check run is rejected before any check can start. All three were **GREEN**, because each no-ops before reaching the push. A lane green for never doing its work is the vacuity class, and it is worse than a red one: the failure looks new when the defect is months old, and it arrives exactly when the lane was finally needed.

**Rescued and rescoped 2026-08-25** after 416 commits of `main`. What changed is recorded below, because two of the four original pieces did not survive contact with what landed in the meantime.

## The 416-line lint is withdrawn — this is a doctrine collision, not a scope quibble

`lint-no-direct-push-to-main.ts` (PM001) and its `gate.yml` wiring are **removed**.

The overlap with AH001 (`audit-push-without-rebase`) and AH002 (`audit-skip-token-cannot-land`), both merged into the `cross-verify` floor tonight, was the smaller reason. The deciding one:

> The lint's own text says **"NO EXEMPTIONS … the only way to satisfy this check for new code is to stop pushing at `main`."**

**#15313 (merged) designs the opposite**, on the maintainer's brief — *"heartbeats should not need a PR to go to main… any new design that has PRs as part of the design should be treated as a smell."* It replaces the gate with a **content-bound attestation** plus `audit-heartbeat-lane-attestations.ts` (verified present, `cross-verify` job, `gate.yml:2486`).

Landing a floor check literally named `no-direct-push-to-main` would have enshrined the position the repo had just decided against. **The rule that survives both is "no UNATTESTED direct push"** — attested direct push is the sanctioned route; an unattested one is caught post-hoc by the attestation audit. The three fixes here are unaffected: none of those lanes writes an attestation, so their pushes are refused today and would be refused under the new design too.

## What the lint found that AH002 genuinely could not — folded into AH002 instead

AH002 exempted any line containing `echo`, so a workflow could DOCUMENT the ban without tripping the check enforcing it. That exemption also covered the standard idiom for **building** a message:

```sh
{ echo "subject [skip ci]"; echo; echo "body"; } | git commit --file=-
```

**Measured, not argued.** `zetadb-scheduled-node.yml` on `main` commits `db(zetadb): fold scheduled journal [skip ci]` exactly that way. AH002 reported OK on it. Rewriting that one `echo` as `printf` — no other edit — made AH002 fire on the push line. **One character of spelling decided whether the check could see the only lane on `main` it was built to catch**, so its green was entirely vacuous.

What it was masking is not hypothetical: five identical **permanent** ruleset refusals would have been reported as *"sustained contention"* (081KZM0FTJM), aiming the diagnosis at a race that does not exist.

Writing the regression tests surfaced a **second** instance of the same class one token to the left: `COMMITS` did not match `git -c k=v commit`, so a lane using only that spelling was invisible. Also fixed.

The fix **narrows** rather than removes — `echo` stops being exempt only inside a block that demonstrably pipes into a commit message, so `lockfile-healer` and `drift-sweep` still document the ban freely. Seven new falsifiers pin both walls; one of them states the limits (`<<EOF` heredocs, `-m "$(…)"`) rather than implying coverage that is not there.

## The merge conflict that was authored work, not maintenance

`retraction-actuator.ts` conflicted because **two independent hardenings landed on the two sides**, and they are orthogonal:

- `main` replaced `sh(...)` (a concatenated shell command line) with `git(...argv)` over `execFileSync` — closing **command** injection on a function that consumes GitHub API responses.
- this branch replaced the unlandable `push origin HEAD:main` with a park on `heartbeat/retraction-<sha>` plus a PR, and added `normalizeFullCommitSha` — closing **argument** injection, which removing the shell does **not** (`git revert --no-edit --upload-pack=…` is still a git option).

Taking either side alone drops a real defence. The resolution keeps both: the staging route spelled entirely in the no-shell form, with `safeSha` reconstructed from a literal `HEX_DIGITS` before it reaches any argument or path. That decided content, so the merge commit is **signed** rather than silent.
