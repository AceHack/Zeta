## Description

## The race

The step added in #17136 asks Gatekeeper whether every ConstraintTemplate compiled. It asserted that **instantaneously**, right after the proof verdict, on an eventually-consistent cluster.

| run | verdict from the same step |
|---|---|
| `34370409538` (the merge commit that introduced it) | `all 7 ConstraintTemplates compiled and created` |
| `34373356539` | `no ConstraintTemplate exists` |

Same code, same tree, opposite verdict. That is my own step going red on a defect it did not find.

## Why the proof can finish first

At T+512 s in `34373356539`, `hat-system` still had `ServiceAccount/gatekeeper-crd-wait` `OutOfSync` and Gatekeeper own `constrainttemplates.templates.gatekeeper.sh` CRD had only just been created.

`isApplicationSynced` admits `OutOfSync + Healthy`, which cannot tell an app whose resources are **not applied yet** from one whose sync **failed** — the same blindness #17138 closed for the failed case. The in-progress case is still open, and it is what lets `hat-system` pass the proof with **zero policies applied**.

## Fixed without weakening the check

- up to **300 s** for any ConstraintTemplate to appear;
- then up to **180 s** for every one to reach `status.created: true`.

A bound that **expires is still a failure**, never a skip — *"gatekeeper compiled nothing"* is the finding this step exists for, and waiting must not become a way of never saying it.

A non-empty `status.byPod[].errors` is decided **immediately** rather than waited on: a template that failed to compile keeps its errors, so waiting could only delay a verdict that is already final.

Both jq filters checked against fixtures in both directions — a compiled template is not selected; an errored one and a status-less one are. Step body passes `shellcheck`; workflow passes `actionlint`.

## Named, not fixed here

The underlying reason the proof can declare victory while `hat-system` is mid-sync is the `OutOfSync + Healthy` allowance itself. Narrowing that further changes what the lane asserts and belongs with a maintainer, not inside a race fix.

## Cost

Adds at most 300 s to a job only when Gatekeeper is genuinely slow; zero when templates are already present. No new job, no new tool.
