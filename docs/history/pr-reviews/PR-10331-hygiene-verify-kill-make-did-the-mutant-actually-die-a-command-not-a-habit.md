## Description

Today the re-run-and-confirm step caught a **wrong answer five times**:

- **twice** a test written specifically to kill a mutant *passed against that mutant unchanged* (`grammar-16-render.ts`, `mutation-readout.ts`) — in both cases the survivor was masked/redundant code and a test was the wrong response entirely;
- **once** a hand-rolled falsifier loop applied a mutation that *silently did not match*, so every mutant "survived" and the run read as a clean bill;
- **twice** the surrounding shell reported success from a command that had produced no output at all.

Every one was caught by *remembering* to check, and I hand-rolled the same throwaway probe script **seven times** to ask one fixed question. A discipline that lives in someone's head dies with their context window.

## The guard that matters most

Applicability, checked **before** spending a suite run. A mutation whose pattern is absent is a no-op, and a no-op mutant always "survives" — indistinguishable from a real finding *and* from a test that failed to bite.

That's the runner's own `unresolved` lesson one level up: **a check that did not run must never look like a check that passed.** So `not-applicable` is its own outcome with its own exit code, never folded into either verdict. Comment-only matches aren't applicable either.

```
0 killed · 3 still-alive · 4 not-applicable · 5 unresolved · 2 usage
```

**STILL ALIVE does not say "write a better test."** It points at the *redundant* reading, because a masked guard cannot be held by any test — sending the reader to look for one wastes the tick, which is the exact mistake I made twice.

## It found one in itself

`gte-to-gt` on `verify-kill.ts` is **STILL ALIVE**, and that's recorded rather than papered over. `argValue` does `process.argv.indexOf(flag)`, and `argv[0]` is always the runtime path, so a flag can never sit at index 0 — `>= 0` and `> 0` are equivalent in practice.

That's the **redundant** reading, the third case this tool exists to point at. No test is written for it, because no test could hold it.
