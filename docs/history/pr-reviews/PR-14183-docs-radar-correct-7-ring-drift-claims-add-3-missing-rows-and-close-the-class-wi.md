## Part 1 — the two Soraya found

### `fast-check` was in use with no ring at all

Pinned `4.8.0`, imported by 5 tracked test files, absent from a 102-row radar. The only property-testing row was *"FsCheck 3 | Adopt"* — which is **.NET**.

But the missing row was **hiding** something, and it changed the ring:

| | FsCheck 3 (.NET) | fast-check (TypeScript) |
|---|---|---|
| files using it | 156 under `tests/` | 5 under `src/Core.TypeScript/` |
| **runs in CI** | **yes** — `dotnet test Zeta.sln -c Release`, blocking | **no** |
| honest ring | Adopt | **Trial** |

Every `bun test` invocation across `.github/workflows/` is path-targeted (`hygiene/`, `ace/`, `inventory/`, `cluster/`, named files); none of the five directories appears in any of them; there is no bare `bun test`. So it lands at **Trial** — the same "live code path, no CI wiring" condition that already holds Alloy at Trial. **One row standing in for two languages had let one tool's Adopt ring launder another tool's ungated status.**

### TLA+/TLC — ring stays `Adopt`, lane state recorded beside it

Last `tlaps-proof` **success 2026-07-01**. Last 100 runs: **16 success / 22 failure / 62 cancelled**. Last 12: **zero successes**.

The two failure modes are different, and separating them meant reading **step** conclusions, not run conclusions:

- **`cancelled` = the 60-minute job timeout, firing in the wrong step.** Five runs at 60m14s±20s, every one cut inside **`Install toolchain`** (the opam source-build of `tlapm`). `Prove all TLAPS obligations` is **`skipped`** — the prover never runs.
- **`failure` = `exit 127`**, i.e. *command not found* — `tlapm` was not invocable, **not** an unproved obligation.

> This answers half of Soraya's first prerequisite with evidence rather than inference: it is **not** "a model that grew". It is the build. Whether it slowed or the `~/.opam` cache stopped hitting is still open — and there is a coupling to check first: the cache key hashes `tools/setup/manifests/**`, which is *also* a trigger path, so a manifest edit both fires the lane and busts its cache in one commit.

**And a vacuity underneath it:** in both failure runs the preceding `Verify TLAPS toolchain` step concluded **`success`**. `checkToolchain()` returns non-null on the mere presence of `opam`:

```ts
const opam = which("opam");
if (opam !== null) {
  return { cmd: opam, preArgs: ["exec", `--switch=${TLAPS_SWITCH}`, "--", "tlapm"], specsPath };
}
```

`opam` existing does not imply the switch holds a built `tlapm`. A green square for a check that did not check.

**Not downgraded, on purpose.** A ring is a claim about what we would start new work with, and TLA+/TLC still is. A silent `Hold` would replace a *visible* discrepancy with an *invisible* one. Soraya's read — *"Hold in practice despite an Adopt ring"* — and her three restoration prerequisites are now on the row. The old note *"6 specs validated; 7 more with `.cfg` pending"* is retired as unsupportable: 36 `.tla` and 53 `.cfg` files now, and no artifact records which 6 it meant.

## The falsifier — yes, I wrote it

`src/Core.TypeScript/hygiene/audit-tech-radar-claims.ts`, on the **`cross-verify` floor**, offline, ~1s, plus 22 unit tests.

- **Check A** — every backticked repo path the radar cites must exist. Zero allowlist; a *proposed* artifact is marked `` `path` (planned) ``.
- **Check B** — every root-`package.json` **devDependency** statically imported by a tracked `*.test.ts` must be named in the radar. The scope is **derived**: `devDependencies` is the manifest's own declaration of "tooling not product", and "imported by a test" is the proxy for "part of how we verify".

**What I deliberately did not check, and why:** runtime `dependencies`. A radar is an evaluation register, not an SBOM; demanding a row for `pg` and `@scure/bip39` produces ~25 findings nobody intends to act on, and a check people route around is worse than none.

**Stated limits, in the file and pinned by tests:** static imports only (`solver.z3.test.ts`'s `require()` inside a spawned process is invisible — it **under-reports, never invents**); root manifest only; a row that merely *mentions* a tool satisfies check B. And the big one: **neither check can tell you a ring is wrong.** TLA+ sat at Adopt with a dark lane for seven weeks and this audit would have stayed green throughout.

**Went red on `main` when written — 7 findings** (4 dead paths, 3 unringed devDeps). Green here, so no baseline file: `AUDIT-LIFECYCLE.md`'s cleanup-to-zero path.

## Three things found on the way

### The check reported *itself* — and the fix is the better half of this PR

It went red on this very PR (cross-verify job `97201065831`), reporting `playwright` as an in-use tool with no ring. **True of the audit's own test file, false of the repo**: no tracked test statically imports playwright, but `audit-tech-radar-claims.test.ts` used `import { chromium } from "playwright"` as a **parser fixture**, and that file is itself a tracked `*.test.ts` inside the scanned corpus.

It passed locally and failed in CI because the two runs used different regexes — the simplification that satisfied `sonarjs/slow-regex` during review also stopped anchoring to a line start, which was what had been hiding the fixture. **The fix that made the regex safe made the corpus self-referential.**

Repaired twice, because the first repair added a header comment *explaining* the false positive and the comment quoted the specifier verbatim, re-creating it. Now: `stripComments` — a character scanner, not a regex, because `"https://…"` carries `//` inside a string — blanks comments before the import scan; and **fixtures may not name real devDependencies**, written at the top of the test file with the reason. Comments can be stripped; **string literals cannot**, and that limit is stated in the docstring rather than discovered a third time. Six new tests pin the class (29 total).

Exempting the audit's own test file was the alternative and was rejected: an allowlist of one, and an audit that skips a file can be silenced by moving code into it.

### `lint (TS)` announces three checks and runs one

`src/Core.TypeScript/lint/lint-typescript.ts` **is** the `lint (TS)` gate job, in full:

```ts
const STEPS: readonly Step[] = [
  { label: "TypeScript type check: tsc", cmd: TYPESCRIPT_COMPILER_COMMAND },
];

function main(): number {
  for (const step of STEPS) { if (!run(step)) return 1; }
  console.log("✓ TypeScript, Prettier, and style checks passed successfully!");
  return 0;
}
```

**One step; three checks claimed.** Nothing else runs them either — no workflow invokes prettier or stylelint, and `gate.yml:1665` installs *"the eslint stack"* and never calls eslint. Not a regression: `git log -S"STEPS: readonly Step[]"` returns exactly one commit (`4f3d20a25`, the file's first, 2026-06-13) and the message has claimed Prettier and style checks since then with `STEPS` tsc-only from the start. **It was never true.**

Found because `docs/TECH-RADAR.md` is not prettier-clean on `main` and nothing ever said so — running `--write` over it turned a 12-line content diff into a 211-line one. Reverted; edits re-applied to the pristine file. **A drift-fix PR whose point is legibility must not bury its own changes in whitespace.**

Same shape as §1.2's `--check-toolchain` reporting success for a `tlapm` that then exits 127. Not fixed here — three repo-wide linters need a baseline. → `081M0QDHQQQ087G0R002JE1JMA`, with the cheap half split out on purpose: *make the message stop lying today, enforce later.*
