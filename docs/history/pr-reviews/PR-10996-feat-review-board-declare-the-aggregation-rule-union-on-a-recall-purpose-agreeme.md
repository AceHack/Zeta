## Description

## What

The review board now **declares** its aggregation rule as an `AggregationRule` value and sets it to **`union` (k=1)** against **`Purpose = recall`**. Every finding any reviewer raises is adopted; the agreement count is published as a **confidence annotation** rather than spent as a gate.

Closes the mirror defect #10974 found at `review-board.ts:146`: the board refused to convene below `quorum`, and `DEFAULT_REVIEW_QUORUM = 3` was **also** the agreement threshold — so at the minimum convening size `k = n`, which `ofKOfN` normalises to `veto`, and a veto on a discovery task is `mirror-mismatch(recall, safety)`.

Keeping #10974's honest scope: that is a statement about the rule *at a configuration*, read off the code. It is not a claim about how often boards convene at exactly `quorum`, and this PR does not make one.

## How the rule is declared

```ts
// packages/metrics/src/review-board.ts
export const REVIEW_BOARD_PURPOSE: Purpose = { kind: "recall" };
export const DEFAULT_REVIEW_RULE: Rule = union;      // k = 1
```

Both are imported from the canonical algebra (`src/Core.TypeScript/society/aggregation-rule.ts`), not restated. Three consequences follow mechanically:

1. **Adoption is the rule applied, not a count.** `toBooleanRule(rule)` is handed a vote vector with one slot per convened reviewer, in ordinal id order — so `union` is "any reviewer agreed", `veto` is "every convened reviewer agreed", and a reviewer who never voted on a finding contributes `false` (silence is not agreement). There is **no counting logic left in the file** to drift from the declaration.
2. **The declaration is checked, not trusted.** `classify(purpose, rule)` runs before anything is decided; a `mirror-mismatch` pairing is **refused** (`aggregation_rule_mirror_mismatch`). Setting the rule back to `veto`, or writing `ofKOfN(n, n, ...)`, now fails mechanically. The board also asserts `verdictKey === "dominates:recall"` in test.
3. **No weights, structurally.** `toBooleanRule` returns `undefined` for a `weighted` rule, so the board returns `aggregation_rule_not_applicable`. Weighted aggregation is unavailable rather than merely discouraged, until a measured-competence ledger exists. `calibration-ledger.ts` is untouched.

### Two numbers that were one number

| | before | after |
|---|---|---|
| `quorum` | minimum board size **and** agreement threshold | **attendance floor only** — a `liveness-precondition`. Still 3, still fails closed below it. |
| aggregation | implicit, hardcoded `>= quorum` | declared `AggregationRule`, defaults to `union`, caller-overridable |

Separating them is what removes the mismatch: the board can still refuse to sit with two reviewers while adopting on one reviewer's finding.

## What the confidence annotation looks like

```ts
export type FindingConfidence = {
  distinctAgree: number;      // one agent voting three times counts ONCE
  distinctDisagree: number;
  distinctAbstain: number;
  reviewerCount: number;      // the denominator: everyone who convened
  agreementRatio: number;     // distinctAgree / reviewerCount
  contested: boolean;         // the dissent would also have satisfied the rule
};
```

Carried on every `FindingDecision`, and surfaced at the gate on a new `adoptedFindings: ReportedFinding[]` alongside the existing `advisoryFindings` — both with #10957's `agreedBy` / `disagreedBy` attribution.

**Nothing branches on it.** Not in the board, not in the gate. A 1-of-3 and a 3-of-3 blocking finding reach the same basis and the same outcome, and are never indistinguishable — that pair is pinned by a test. Branching on the count would be a k-of-n threshold one layer up, i.e. the same defect moved.

**Dissent annotates, it does not suppress**, under a recall-dominant rule. Letting one disagreeing reviewer withhold a discovery would have reinstated the mirror defect through the back door. `Contested` stays an escalation under every other rule, derived from `dominanceAxes(rule)` rather than special-cased.

## #10957 is not weakened — it is pinned to its own rule

Every assertion #10957 wrote survives, **verbatim**, by passing the rule it was written for:

```ts
rule: threshold(3, { kind: "unstated", note: "the pre-#10974 quorum gate, pinned so its assertions stay under test" })
```

So `UnadoptedBlockingOrMajor`, `UnadoptedMinorOrInfoOnly`, the contested-advisory attribution test, and the "clean vs advisory approvals must not share a basis" test all remain live. The `basis -> QualityGateOutcome` mapping is **unchanged**; only which basis a given input reaches has moved.

**The one place this supersedes a deliberate #10957 choice, stated plainly:** #10957 returned `ChangesRequested` rather than `Rejected` for a sub-quorum blocking finding, reasoning that "the board did not establish that the finding is true — rejecting would assert it." Under `union` that input is now *adopted*, so it maps to `Rejected`. That is a real strengthening and I am not hiding it. Its warrant is #10957's own header, which named this exact change as the open question it deferred: *"Changing it alters what blocks merges repo-wide, so it is not this module's call."* The guard #10957 actually asserted — `recommendedGateOutcome !== Approved` — is untouched and still passes.

### Expected volume change: I cannot estimate it from existing data, and here is why

There is **no stored review-board run data anywhere in the repo** — no recorded findings, votes, or outcomes to fold. Worse for the estimate and better for the risk: `evaluateReviewGate` is exported from `packages/application/src/index.ts` and **has no caller** in any app or worker, and `evaluateReviewBoard` is reachable only through the `run_review_board` MCP tool. Nothing under `.github/workflows/**` invokes either. So:

- **Live volume change today: zero.** This changes no merge outcome now. It changes what happens when the gate is wired up.
- **Future rate: not estimable.** Any number I gave would be invented.

What can be stated honestly is the **structural** set of inputs that changes class — findings with `1 <= distinctAgree < quorum` move from withheld-advisory to adopted — plus a combinatorial count, which is **a count over a uniform prior, not a measurement of reviewer behaviour**:

- 3-reviewer board, one finding, each reviewer agrees or not (2³ = 8 patterns): `threshold(3)` adopts **1**, `union` adopts **7** — **6 of 8 patterns flip**.
- With the full stance set `{agree, disagree, abstain}` (3³ = 27): `threshold(3)` adopts **1**, `union` adopts **19** — **18 of 27 flip**.

Real reviewers do not vote uniformly at random, so these bound the shape of the change, not its rate. Flagging them as coincidence-class counts rather than predictions is the point.

**More findings will surface and some will be noise.** That is the priced consequence of choosing recall, and the confidence annotation is what makes the noise legible rather than silent: a `1 of 3, contested by 2` blocking finding reads differently from a `3 of 3` one even though both now block.
