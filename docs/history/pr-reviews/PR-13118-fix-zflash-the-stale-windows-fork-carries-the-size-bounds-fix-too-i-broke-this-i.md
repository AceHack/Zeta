## Description

**`test (TS hermetic)` has been red on main since #13099 — my change.** It gave the four flash safety-rail bounds a single home and rewrote the canonical Windows arm to import them. But `full-ai-cluster/tools/flash-usb-windows.ts`, a stale fork of that file, still declared all four inline, and `flash-usb-windows.security.test.ts` asserts the fork's only divergence from the canonical copy is self-referential path prose. Four freshly-orphaned `export const` lines failed it.

Worth naming, because it is the same shape as the bug being fixed: **#13099 removed a duplicated-constant hazard, and what broke was another duplicate — a whole forked *file* — whose drift this repo already checks with a test.** The mechanism for exactly that class existed, pointed at a different pair, and I did not look for it before landing.

## The fix

The fork now imports from the same one home, so it *"carries the fix too"* — which is what the failing test is named for. That leaves exactly one differing line: the import specifier, because the fork lives two directories away and the identical import cannot be spelled identically.

The test is widened to permit that one line and nothing more, and **the allowance is derived from the canonical line rather than written out**, so it cannot drift — if the canonical import changes shape, the allowance stops matching and the divergence is reported again.

## What I did not do, and why it's yours

**I did not delete the fork.** The test's own comment says a failure means *"the delete/dedupe question has to be reopened rather than assumed"*, and #10853 recorded the standing position that *"deleting it is a judgement call, not a property-1 change."*

The case for deletion is strong — nothing in the tree imports it, and its tests are `skipIf(!present)`, so deletion would be clean and would end this class outright. But it is a judgement call about an operator-facing tool, so it goes to you rather than into an autonomous tick.

## Checked, not assumed

The relaxed test **still catches real drift**: appending one unrelated `export const` to the fork reds it (8 pass → 7 pass / 1 fail), so the exemption is not a hole. A sibling test pins the allowance at exactly one line and asserts it is the import — **an allowance nobody can fail would be the vacuity class**, reporting parity as CHECKED while a fork drifted freely underneath.

Restored: 8 pass / 0 fail on that file, **521 pass / 0 fail** across zflash, `tsc --noEmit` clean.
