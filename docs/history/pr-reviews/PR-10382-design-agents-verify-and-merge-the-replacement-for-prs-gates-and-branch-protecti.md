## Description

Aaron answered four open design calls at once, and one sentence carries the rest:

> **"The review can be the mutual observation too."**

## Why that is a strengthening, not a relaxation

Today's vocabulary makes it precise:

- A **PR approval is a witness** — one external observer, tolerating **zero faults**. If the single reviewer is wrong, captured, or inattentive, the rescue fails silently *and looks like success*.
- **Mutual observation among N agents is a quorum** — sized for fault tolerance.

So *"each change can go through multiple reviews and correctors, it does not have to be one"* is literally the move from **witness to quorum**. Dropping PRs **raises** the bar — provided the quorum is real, which is the whole engineering problem.

It also satisfies a constraint the rest of the day established independently. `FigureEightEnsemble.fs:22-27` proves a closed loop cannot escape its own fixed point from inside, and the society-delivery track reached the same place from the other side: *"the heartbeat cannot certify its own evidence."* Mutual observation among distinct agents is exogenous correction; self-merge is not.

## The four answers

| Question | Answer |
|---|---|
| Step vs job gating | **Neither long-run** — the gate itself shrinks. Keep step-level short-run; do not invest in job-level, it is on the path being replaced. |
| Per-heartbeat PR vs staging flush | **Neither is the destination.** Heartbeats should be *close to free*; batch only for corporate mode or a genuinely wanted human review. |
| hex vs base32 | **Base32, and pluggable.** 128 bits = **32 hex chars vs 26 base32 chars**, so base32 wins on the stated criterion, and `encoding.ts` already calls it *"the CANONICAL filename form"*. |
| `observe-events` category drift | Still open — and it interacts: if agents route work by category, a mis-categorised ledger mis-routes. |

## What replaces the gate

1. An agent checks work in on a **cheap ungated branch**.
2. **The build graph decides what must be verified** — `build-graph.json` (landed today, #10379; 106 targets, edges derived from the manifests) and `build-graph.ts affected`.
3. **Other agents run those checks and merge** — the verifier is never the author. That is the quorum.
4. Only affected targets rebuild, fanning out in parallel because the graph says which are independent — *"incremental builds on steroids."*

## Guards this must not lose

All learned the hard way in the last day:

- **A skipped check and a passed check must never be indistinguishable.** `verifyCoverage` already proves `affected ∪ skipped == every target`. That property becomes **more** important without a monolithic gate, not less.
- **Unknown escalates** — forgetting to map a new tree makes verification slower, never quieter.
- **Not every leg is content-addressable.** Local .NET assemblies embed absolute source paths, Lean `.olean` bytes are unverified, TLC/Q# logs carry timing. Hash **(sources ‖ toolchain ‖ recipe)** and the **claim**, not artifact bytes.
- **The verifier must not be the author.**

## Sequencing

Build agent-verified-merge → prove it on a real lane → **then** minimise the ruleset. `Branch Safety` and `Heartbeat Branch Protection` *are* "no harmful actions" and survive; `CI Gate` is the quality gate that goes — but removing it before the replacement exists leaves **neither**.

## The gap worth naming

*"Multiple reviews and correctors"* has **no number yet**. Until it does, the design is a witness wearing a plural noun — and `vocab/words/quorum.md` says a quorum is a witness set **sized** for fault tolerance.
