## Description

## What this is

A prioritized, line-cited inventory of the gap Aaron named: Zeta builds substrate — a package
manager (`ace`), transports, schedulers, formal oracles — and then, in its own operation,
frequently uses someone else's tooling. **Inventory only. Nothing migrated, nothing switched.**

The triggering instance (`agent-heartbeat.yml`'s `curl | sh` of ollama) is treated as the worked
example, not the target — another agent is in that file and I did not touch it.

## Top three, ranked by (§13 exposure) × (requirements-and-test value) × (readiness) ÷ (blast radius)

**1. `~/.rustup` is in ZERO cache paths across all 64 workflows.** Verified: `~/.cargo` appears in
exactly one (`gate.yml:1716`, `full-verify` only); the `install-*` cache used by the lint jobs lists
no Rust path at all. Direct observation on this machine shows why caching `~/.local/share/mise`
does not help — `installs/rust/1.87.0` is a **0-byte symlink into `~/.cargo/bin`** while the actual
1.2 GB toolchain lives in `~/.rustup`. So a "comprehensive" install cache restores a dangling
symlink. And the existing mitigation at `tools/setup/common/mise.sh:170-179` states it keeps "exact
installed toolchains usable while the CDN is down" — a guard whose precondition (an offline cache of
`~/.rustup`) never holds, i.e. a check that cannot fail. Measured cost, not hypothetical: #10903 and
#10930, two unrelated PRs in one working day, and #10930 reported the failure **under the name of a
check that never executed**. Verdict: **not a dogfooding row — keep rustup, fix the cache.**

**2. A second `curl -fsSL https://ollama.com/install.sh | sh` at `mux-swarm-tick.yml:41`**, hourly,
separate from the heartbeat instance. Substrate `setup-realizers/from-ollama.ts` is **READY** —
verified end to end (NixOS `nix build` path, Linux tarball path, brew deferral, daemon polling,
dry-run) and it already degrades rather than halts. Two named gaps: no digest pin (a recorded
operator decision in the manifest, not an oversight — so the honest gain is
*no-arbitrary-shell-execution*, not byte-pinning), and the lane that validates it,
`accelerator-local-llm-validate.yml`, does not set `ZETA_INSTALL_FULL=1` which the realizer's
non-interactive guard requires — and that lane last executed **2026-05-30**. One `workflow_dispatch`
settles whether that free test is still free.

**3. `tools/setup/linux.sh:461` installs `wabt lua5.4 golang-go` with a hardcoded apt call** that
bypasses `manifests/apt`. `wabt` is declared there too (installed twice); `lua5.4` and `golang-go`
are declared nowhere. `golang-go` additionally conflicts with the `.mise.toml` `go = "1.26.4"` pin
that `bytelock.yml` states is a hard parity requirement — a live diamond-resolution instance sitting
in the repo.

## Feature requests, not switches

Named as such deliberately, since filing a stub as a switch is how a stub gets promoted silently:

- `OracleTransport.fs` — `GitTransport.EmitAsync` writes a local file ("In production, this calls
  the GitHub REST git-data API"); `ReticulumTransport.EmitAsync` is `Task.Delay`. **Two of three
  named transports move no bytes.**
- `gossip-mesh-transport.ts` — nine exports, **one** (`udpMeshTransport`) contains real I/O
  (`node:dgram`); the rest are inversion-of-control shells (correct design under §13, but "six
  adapters" ≠ "six working transports"). **No test file.**
- `ace-cli.ts` — `graphMerkleRoot` is a hand-rolled 32-bit rolling string hash labelled STUB.
  Routing a real install through it would produce an integrity claim that only *looks* like one.

## Rows where the answer is "keep the external tool"

`yamllint`, `kubeconform`, `mise`, GitHub Actions — with the reason stated per row, including one
that is **merely aesthetic** (yamllint) and one that would be **speculative building** (a Go
mechanism for a single tool). `mise` is the cautionary anchor: replacing it with an immature
internal PM is the exact way dogfooding reduces reliability.

## What I switched: nothing

Both candidates sit on the required gate. Adding `~/.rustup` to the cache needs a key bump (one cold
run per job) and deserves its own reviewed PR; declaring `lua5.4` flips a swallowed failure into a
hard gate failure. Each is **routed to a destination** — experimental arm, or its own PR — rather
than done here. The brief said shipping the inventory alone is the correct outcome; I took that at
face value rather than manufacturing a change.

## Framing recorded (from Aaron, via Otto)

Dogfooding as a **requirements source** (one real dependent specifies which of `ace-cli.ts`'s five
unbuilt pieces we actually need) and as a **free test supplying the non-deterministic tail DST
abstracts away by design** — the two are complementary, and each row says which it supplies. Plus
the **failure-isolation** correction: experimental arms are containment (bulkhead/blue-green), not
decorrelation, so arms need not be diverse — and the sharp consequence is that **shared unpinned
egress silently defeats failure isolation**, because one upstream outage removes every arm *and* the
stable fallback at the same instant. That makes the egress rows a prerequisite for the arm
architecture rather than hygiene.
