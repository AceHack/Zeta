## Description

## The failure

`docker-windows-install-ps1-test` has been red on **every PR that triggers it** since #14303 merged, ~435 seconds into the Windows container build:

```
error: Workspace not found "src/apps/twitch-ai"
bun install --frozen-lockfile failed (exit 1)
```

## Nobody wrote a bad line

Three correct changes composed into a break:

1. #14200 / #14253 / #14292 added the `src/apps/twitch-ai` workspace.
2. #14303 regenerated `bun.lock` for it — **necessary**; `main` had been red for every PR on `--frozen-lockfile`.
3. This lane inherited the breakage, because the Windows Dockerfile's hand-maintained *"COPY only the install-relevant subset"* set had **silently stopped being sufficient**.

`tools/setup/install.ps1:351` runs `bun install --frozen-lockfile` inside the image, and bun resolves the **root** manifest's `workspaces` array against the build context. The context had `package.json` and `bun.lock` but no workspace manifest, so bun failed closed.

**Only the Windows lane is affected** — the Unix installers do not run a frozen install in the image:

| lane | status |
|---|---|
| `docker-windows-install-ps1-test` | 🔴 was failing |
| `docker-nixos-install-sh-test` | 🟢 |
| `docker-ubuntu-install-sh-test` | 🟢 |
| `docker-ubuntu-jammy-install-sh-test` | 🟢 |

## The fix, and the check that should have existed

The COPY list is **coupled** to `package.json`'s `workspaces`, and nothing checked that coupling. So this is one `COPY` plus the falsifier that would have caught it.

`windows-dockerfile-workspaces.test.ts` **derives** the expected set from `package.json` rather than restating it — a hand-written second list would drift from the first and reproduce this exact bug one level up. It also guards its own precondition, so it cannot pass vacuously if `workspaces` is ever removed.

**Proven to discriminate:**

| state | result |
|---|---|
| remove the new `COPY` | 🔴 1 fail — *"package.json declares workspace(s) that the Windows Dockerfile never COPYs: src/apps/twitch-ai … Add: COPY &lt;workspace&gt;/package.json …"* |
| restored | 🟢 3 pass |

The next workspace is now caught in seconds, at lint time, with the line to add — instead of after a multi-minute Windows container build.
