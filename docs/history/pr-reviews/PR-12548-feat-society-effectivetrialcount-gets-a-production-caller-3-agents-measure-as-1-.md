## Description

feat(society): effectiveTrialCount gets a production caller — 3 agents measure as 1.67

`SocietyUsefulWork.effectiveTrialCount` (Kish 1965) shipped proven and
mutation-verified on 2026-08-16 with ZERO call sites. One comment in `tick-dial.ts`
pointed at it; nothing invoked it. So every witness count and match count in this repo
was a HEAD COUNT. This wires it to a real corpus and reports what the heads are worth.

THE FINDING, stated plainly because it is unflattering: over
`db/mutation-findings/{alexa,otto,soraya}.jsonl`, inter-agent rho = 0.4002 (ICC(1,1)),
design effect 1.800, so THREE AGENTS ARE WORTH 1.67 INDEPENDENT ONES. 44% of the
apparent independence is not there. Pairwise overlaps run 2.8x-3.0x what independence
predicts (72 vs 24.0, 53 vs 19.0, 57 vs 18.7).

THE UNIVERSE MUST COME FROM OUTSIDE THE AGENTS' OWN BEHAVIOUR, and that is the
load-bearing part. A Lincoln-Petersen estimate off the observed overlaps gives ~230-250
and would be CIRCULAR: L-P assumes the samples are independent, so estimating N from
the samples and then testing independence against it is a check that cannot fail — the
vacuity class. The frame is instead enumerated from the COMMITTED TREE at a named
commit: every git-tracked `.ts` with a sibling `.test.ts`. N = 703.

TWO CORRECTIONS TO THIS EVENING'S FIRST PASS.
(1) The frame was wrong at N = 616. Restricting it to `src/Core.TypeScript` left 30 of
the 362 observed draws — in `tools/setup` and `tests/cross-verification` — OUTSIDE the
frame. A frame that does not contain the draws is not the population that was sampled.
Repo-wide it contains 100% of them, and `assertFrameContainsDraws` now FAILS rather
than filtering, because dropping out-of-frame draws lets a wrong universe produce a
confident number.
(2) `git ls-files` rather than a directory walk, so the frame is a pure function of a
commit and replays deterministically from the recorded sha.

THE ESTIMATOR IS NAMED, WITH ITS ASSUMPTIONS — a rho from an unnamed method is not a
measurement. Primary: one-way ANOVA ICC(1,1) (Fisher 1925; Shrout & Fleiss 1979), which
is Kish's rho by definition. Corroborating: mean pairwise phi (Yule 1912), 0.4016 —
these coincide under exchangeability, so their agreement is a real check. Independent,
touching no pairwise statistic: inverting the SHIPPED union formula against observed
coverage, 0.4729. It disagrees by 0.07 because it assumes identical agents and these
three have unequal draw rates; the gap is reported rather than averaged away.

PHI, NOT TETRACHORIC, AND THE REASON MATTERS. `costume-rho/tetrachoric.ts` argues at
length that phi is wrong THERE, and it is right: that target is the latent parameter of
an explicit Gaussian copula. But Kish's deff is derived from Var(sum) = sum Var +
2 sum Cov, so the rho appearing in it is the PRODUCT-MOMENT correlation of the observed
variables. Substituting a tetrachoric coefficient inflates deff and answers a question
nobody asked. Both estimators are correct for their own target; picking by habit is the
error.

CROSS-LANGUAGE PARITY. `golden-vectors-effective-agent-count.json` is hex-in-JSON per
no-binary-in-proof-lineage and is replayed by BOTH oracles (the TS test and the new
`SocietyUsefulWork.CrossVerify.Tests.fs`). Two comparison strengths, and the split is
principled: `effectiveTrialCount` is pinned by EXACT IEEE-754 BIT EQUALITY because it
uses only the four correctly-rounded operations, so bit equality is a guarantee the
arithmetic already provides; the union functions use pow/log, which IEEE-754 does not
require to be correctly rounded, so they are pinned at 1e-12 — byte-locking them would
be a check that fails on some machines for reasons unrelated to the model. Both
endpoints (rho = 0 and rho = 1) are in the seed and both oracles assert they are
present, because a vector set that never touches an endpoint cannot detect an endpoint
regression.

FALSIFIERS, RUN NOT CLAIMED. 30 TS tests; 7 mutants applied and all 7 killed (deff
drops the -1 / drops rho / stub returns n / clamp removed / phi numerator sign / ICC
drops the k-1 / frame check filters instead of throwing), logged in the test file. The
F# side was mutated too — `1 + n*rho` — and 2 of its 3 tests went red, so the parity
test is a falsifier and not decoration.

not claimed: that it describes the fleet's FUTURE behaviour. The measurement is entirely
backward-looking — it records which files these three agents DID sample. That limit is
