## Description

## What

Closes the **adoption half** of BUGS.md P1 #9304. The signing membrane shipped in #9311 was used *nowhere*; now `llmtv-node` actually runs it, as a **windowed migration** (Aaron 2026-07-03: *"greenfield, public API changes are fine, route to the team"*).

| `beacon.mode` | behavior |
|---|---|
| `off` (default) | legacy: send/accept unsigned — exact prior behavior |
| `dual` | overlap window: sign outbound, accept **both** signed and legacy-unsigned (legacy fires `onUnsigned`); a signed-but-**invalid** message is rejected, never downgraded |
| `required` | signed-only, fail-closed |

## Public-API review (Ilyana) — BLOCKED first shape, adopted

- **Opaque signer.** `BeaconSigner = (msg) => string` replaces a raw `signingKey: string` PEM — the node never holds private-key material, so signing can sit behind a **biometric prompt / Keychain / HSM** (your *"nothing operator-run, only operator-approved"* invariant). 
- **Discriminated union `BeaconConfig`** — illegal states unrepresentable (`required` structurally requires signer+trust; `off` carries no auth cruft; `onUnsigned` only where it can fire). The runtime throw is now a JS-boundary backstop, not the contract.
- **`onUnsigned`** hands back the **decoded** message (which peer is still unsigned), not raw bytes.

`beacon-auth.ts`: `observeSigned` now returns the accepted inner message (additive) so a verified probe can be answered without re-decoding; exports `BeaconSigner`.

## Tests — 20 discovery, all green (lint + tsc clean)

5 new migration proofs: `required↔required` discovery · required-**rejects**-unsigned (the flag-day breakage the window avoids) · dual-accepts-**both** · dual-**rejects**-untrusted (no silent downgrade) · fail-closed. Plus full regression — the `off` default preserves old behavior exactly.
