## Description

**The instance is not the class.** #17249 added a Playwright acceptance spec; `bun test` collects `*.spec.ts` exactly as readily as `*.test.ts`, so one file silently enrolled itself in the hermetic bun suite and threw at module load:

> `APP_DIR is not set: acceptance has no service to run against, which is not a pass`

That refusal was *correct*. What was wrong is that bun collected it at all — and the cost was a **24-minute** hermetic run reporting `1 error` for a reason unrelated to anything it checks, with `gate (required)` red behind it.

That instance was fixed by excluding `uat/**`. The class wasn't: the next Playwright spec anyone adds, anywhere, is enrolled the same way, and nothing says so until a 24-minute job goes red.

## The check

Offline and tree-only, deliberately — a file importing a Playwright entry point whose path isn't covered by `pathIgnorePatterns` in **both** bun configs will be collected. No network, no bun invocation, no runner state. That's the property the hermetic tier is named for, and a check *about* hermeticity had better have it itself.

Both configs, because the hermetic-only list is for tests some *other* bun lane still runs, and `environment-dependent-test-files.ts` is red on an entry no PR-lane `bun test` executes. A Playwright spec is a **wrong-runner** exclusion, not a tier split.

## Two parser defects it shipped with

Both found by running it against a tree whose answer I already knew, both now pinned:

- It matched `pathIgnorePatterns` **inside a prose comment** sixty lines above the real key, took the next `[`/`]`, and returned **zero patterns**. That's the dangerous shape — zero doesn't look like a parse failure, it looks like a file that excludes nothing, so the audit reported a confident **false positive against a correctly-configured repo**.
- It captured quoted prose from a comment *inside* the array: `bunfig.toml` yielded `"a deletion wearing a split's face"`.

Comments are now stripped and the key must match at line start. Measured after: **19 and 23** patterns, `uat/**` present in both, no prose leaked, tree clean.

Coverage matching is **conservative on purpose** — only the pattern shapes this repo writes are understood, and an unrecognised shape counts as *not* covering. A cleverer glob matcher that guessed wrong would make the check quietly permissive, which is the exact failure it exists to prevent. A test pins that direction.

**13 falsifiers**, including the mutation in three positions (excluded from neither config, one config, both) plus a negative control that a `.spec.ts` *not* importing Playwright is silent.
