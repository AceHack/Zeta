## Description

Folds Aaron's rule into the capability-deferment doc (*"fold 'no re-roll for business/safety' into the determinism notes"*).

- **A check has teeth only if you can't re-roll it.** Stochastic (temp>0) → re-roll until validation = the con; **temp-0/deterministic → same verdict every time = un-shoppable.** Determinism is the teeth (DST on the critic).
- **The rule:** *"no re-roll — rerolls are for games and the game of life, not business and safety."* Re-roll = the **generative engine** (reversible play / evolution); **forbidden where the verdict commits** (business: no re-rolling to a favorable indemnity price; safety: no re-rolling until the critic spares you). Generation-vs-grounding as a determinism rule.
- **Stack:** temp-0 LLM (reproducible, can be *deterministically wrong*) → deterministic Pareto → **formal verification** (deterministic *and* correct). *Determinism = un-shoppable, not correct*; **determinism + decorrelation + binding = the full critic-quorum.** Self-ref: a stochastic chat AI is re-rollable → weaker builder-check than the deterministic stack.
- **Seams:** game-vs-business line can be gamed (same legible gate); handoff must fire (re-rolled candidate passes the no-re-roll gate before commit); **even life re-rolls the variation, never the selection.**
