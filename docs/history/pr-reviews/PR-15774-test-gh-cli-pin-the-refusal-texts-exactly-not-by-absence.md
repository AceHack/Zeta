## Description

Follow-up to #15763, which merged while its `check-arity (non-equality)` job was red.
That job was right and this is the fix.

It refused:

```ts
expect(tokenRefusalMessage("rejected-by-charset-filter")).not.toContain("no GitHub token");
```

> An absence assertion under a taint claim witnesses **one rendering** of a leak, never
> its absence.

`not.toContain(X)` passes for every message that happens not to contain `X` — including
one that leaks something else entirely. It is the vacuity class wearing a security
check.

**Strengthened rather than adjudicated** — remedy 1, which the audit itself says is
usually right. Both refusal texts are now pinned by exact equality, so what the function
returns *is* the assertion: it visibly does not claim absence, and it visibly has no
interpolation site a credential could be rendered into. Two positive assertions carry
what the absence one gestured at.

Mutation re-checked after the change: collapsing the two messages back into one now
fails **3** tests rather than 2.
