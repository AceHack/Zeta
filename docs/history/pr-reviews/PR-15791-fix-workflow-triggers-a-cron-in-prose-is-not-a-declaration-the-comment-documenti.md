## Description

## The defect

`lint (markdownlint)` was red on `main` at `docs/DRIFT-DASHBOARD.md:23` with two MD037
(spaces inside emphasis markers), and the offending line was **generated**:

```text
schedule: '`', '11 3 * * *' — period not fully derivable, using the derivable minimum for staleness
```

One of the extracted "crons" was a **literal backtick**. That is a parser defect, not a
formatting one — a bogus value reached the dashboard and then broke the markdown it was
written into.

## The mechanism — which line matched, and why

`expectationFromWorkflow` extracted crons with an **unanchored** regex:

```ts
onBlock.matchAll(/cron\s*:\s*["']?([^"'\n#]+)["']?/g)
```

Nothing tied it to a declaration, so it matched `cron:` anywhere in the `on:` block —
including inside a comment. `.github/workflows/docker-ubuntu-install-sh-test.yml:64`,
inside its `on:` block, reads:

```yaml
  # (src/Core.TypeScript/forge-host/github/workflow-triggers.ts) turns a `cron:`
```

`["']?` is optional and `[^"'\n#]+` happily accepts a backtick, so the match consumed
`` cron: `` and carried off the trailing backtick as a cron expression. `cronPeriodSeconds`
could not price it, so the row also fell into the "not fully derivable" branch and said so
about a value that was never a cron.

**The irony is worth keeping**: the workflows whose comments *document this parser* are the
workflows that break it. Six install shields carry that sentence; all six were affected.

**#15779 was right and could not help here.** Wrapping crons in code spans instead of quotes
is correct, but the value *itself* was a backtick, so the span put around it closed on it —
post-#15779 the detail rendered ```` schedule: ```, `11 3 * * *` ```` with an **odd** number
of backticks. Building on it, not reverting it.

## The fix

Three properties, in `extractCrons`:

1. **Comment-blind key matching.** `^[ \t]*-[ \t]*cron[ \t]*:` anchored at line start — the
   only shape GitHub accepts, and one no `#` comment line can satisfy.
2. **Validate the extracted value.** `isCronShaped` requires five fields over
   `[0-9A-Za-z*,/-]` (letters because GitHub accepts `MON`/`JAN`). A value that is not a cron
   is **refused loudly**: named in the detail, backslash-escaped rather than code-spanned —
   because the value that forced this clause into existence was a backtick — never dropped
   and never rendered as if it were a cron.
3. **A `schedule:` with nothing readable under it is `unknown`**, not a fall-through to the
   `push` arm. Falling through would silently downgrade a cadence claim to `on-change`, and
   the dashboard would stop asking why the clock went quiet.

And one the rewrite would otherwise have **broken**: `low-memory.yml` puts its cron scalar on
the line *after* `- cron:`, which the old newline-greedy `\s*` read by accident.
`continuationScalar` preserves that, so an anchored match does not swap one silent defect for
another. Found by sweeping the real workflow corpus before trusting the change.
