## Description

Derives `requiredQuorum` for all 106 build targets in `src/Core.TypeScript/ace/build-graph.json` from path evidence over `git ls-files` — answering Aaron's framing that *"the quorum size will be path dependent like golden vectors and byte locked treaties will require more reviews and likly we want different reviewers per language."*

## Tiers

| tier | evidence | fault model | members | targets |
|---|---|---|---|---|
| T0 | change reaches no target | `none` — a **witness**, named as such | 1 | — |
| T1 | floor | omission, f=1 | 2 | 33 |
| T2 | golden vectors, one oracle | omission, f=2 | 3 | 21 |
| T3 | cross-oracle byte-lock / treaty transcript | **byzantine, f=1** | 4 | 52 |

**Fault model, not a count.** `RequiredQuorum` has no size field; the only route to a number is `quorumSize(faultModel)`. 3f+1 is claimed only for T3, whose verdict genuinely is an agreement claim across independent oracles (Pease/Shostak/Lamport 1980; PBFT 1999). T1/T2 are omission faults and say so. **CHECKED**: the tier assignment. **PROPOSED**: the `f` per tier — one table, marked.

Evidence is derived from the **tracked** file set, not a working-tree walk, so `derive` is identical on every checkout rather than picking up local caches.

## Aggregation is max, and that is not a style choice

Sum is nonsense — reviewers are not consumed per target. Average is a live **dilution attack**: bundle one treaty edit with ninety trivial files and the mean falls exactly as the change broadens. Max is the only monotone choice; pinned by a regression test.

## Guards

Each elevated target records the rule that fired, the witnessing file, and which target holds it. Tests assert every recorded witness still exists, and fail if any single tier swallows >80% of the graph. The drift gate recomputes every row including declared ones, so a hand-edited tier or invented reviewer class fails exactly as a hand-edited `dependsOn` does — two tests tamper and assert red. 77 tests pass (was 46).

## Findings worth acting on

1. **Named prerequisite: the churn heatmap does not exist.** CHECKED — no hotspot tooling in-tree. `change frequency × quorum size` is a path's ongoing verification cost; this PR supplies the second factor and the first is absent, so the identity is half-computable and split decisions stay judgement calls.
2. **`ts:repo` is one target over every `.ts` file**, so every TypeScript change costs a T3 quorum. Not a derivation bug — the arithmetic saying "split this target".
3. **`ts:cross-verification` declares `dependsOn: []`** while genuinely consuming every oracle, so a Rust-only edit yields a Rust-only reviewer set though it can break a treaty with C#/F#/TS. Missing **edge**, not a missing rule.
4. **Known coarseness, stated in code**: one .NET test target holds 30 cross-verify files, so projects it references inherit T3 including some no byte-lock touches. Over-approximation, safe direction.

Two bugs found in the work itself and pinned: evidence must propagate from **consumers** not dependencies (same direction as dirt), and evidence must attribute to the finest covering target — one README under `tests/cross-verification/` had put *every markdown edit in the repo* into the Byzantine tier.

Not wired into CI, per the design doc's sequencing.
