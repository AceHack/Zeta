## Description

Re-does the capture I broke Windows with — **without going near a shell.**

## What went wrong the first time

#15925 tee'd the Test step's stdout, requiring `shell: bash` + `set -o pipefail` on **every** matrix
leg. Windows resolves `shell: bash` to Git Bash, the command line was interpreted differently on
legs that had been using the default shell, and both Windows arms went red on main — build green,
Test dead in ~2 minutes, which is a broken *invocation*, not broken tests. #15929 reverted it.

## The fix moves the write into the emitter

`PerfObservation.emit` already knows it's emitting. It now appends to `ZETA_PERF_OBS_FILE` when set,
in addition to stdout. .NET's `File.AppendAllText` handles Windows and POSIX natively, so the
workflow needs **no `shell:`, no pipe, and no exit-status surgery** on a step whose outcome is read
downstream via `steps.test.outcome`.

Verified by parsing the YAML: the Test step keeps its default shell, contains no pipe, and its
invocation is byte-identical to the one that's been passing.

The env var is unset locally, so `dotnet test` on a laptop still writes no files — opt-in by CI, not
a surprise for a developer.

## Two deliberate choices

**A failed write is swallowed.** A telemetry sink that can fail a test run is worse than no
telemetry, and stdout still carries every line — an observation is never lost even when the file is.

**CRLF is pinned.** `Environment.NewLine` is `\r\n` on Windows and the parser splits on `\n`,
leaving a trailing `\r`. `JSON.parse` tolerates trailing whitespace so it works — **by accident**
until something pins it, and the failure mode is a silent zero-observation ledger on exactly the
Windows legs, which reads as a quiet build rather than a broken sink.

The collector's missing-file branch now says outright that absence is **not** a clean bill of
health, so the inert state can't be mistaken for a green one.
