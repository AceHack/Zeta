## Description

**Good news buried in a red test: the society is healed.** Against the live corpus on `main`:

```
pop=3 div=5.610 fit=0.432 gen=5 flat=1t OK
```

Population **3** (was 1), diversity **5.61** (was exactly 0), **generation persisting at 5** (was pinned
at 1 across all 400 events), flatline reset to a single tick, **and no alarms.** The
lexicographic-outranking fix worked and the runner has been ticking on it since.

## The red test is how we found out

It asserted `r.latest!.population === 1` and that the **current** alarms contain
`POPULATION-COLLAPSE`. True when written; **the fix made it false**, so `test (TS hermetic)` went red on
an unrelated PR.

> **It fired correctly** — a tripwire that goes red when the thing it describes is repaired is the
> mechanism working, and this repo builds those deliberately.

**But asserting a transient live value was the defect in the test, not in the fix.** It would have gone
red again on any future recovery — and **a test that must be edited every time the system gets better
trains its reader to edit it without looking**, which is eventually how a real regression gets edited
away too.

## What it asserts now

What stays true forever: **the historical collapse is still in the corpus** (max population 4, min
population 1, both permanently on file), and **the readout reproduces it when shown the collapsed
window.**

That is the property worth pinning — **it dies if `computeReadout` stops detecting a real collapse** —
**without pinning today's health to a literal.** The reasoning is written at the site so the next reader
does not have to reconstruct it.
