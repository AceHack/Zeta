## The finding

**The drift ledger has been dead for five days, and the cause is that the required status check rejects the ledger's own writes.**

`drift-sweep.yml` commits its tick with `[skip ci]` and pushes to `main`. The `CI Gate` ruleset declines it -- `Required status check "gate (required)" is expected` -- and the rejection is swallowed by `|| echo "push race -- next tick re-records (idempotent)"`, which describes a transient failure that is not the one occurring.

The hub disabled the oracle, and the disabling was invisible for five days. The repair is one lane adopting the route already shipped in `flush-via-staging.ts`, exactly as `proof-closure-drift.yml` did -- named in the doc, deliberately **not** performed here.

Two further live instances of the same class, both measured:

- **`github-settings-drift.yml`** -- job conclusion `failure`, run conclusion `success`, on every sampled run since **2026-06-21**. It is finding real drift, including that the expected snapshot believes `CI Gate` is `disabled` with five contexts while live it is `active` with one.
- **`lockfile-healer.yml`** -- its summary prints `**Healed.** ... and pushed` from the *detector's* output, never from the push result. Unfired but armed, and subject to the identical rejection.

## What the doc adds

- **The honesty contract** -- `DriftReceipt` with four obligations (it ran / what it found / what fired / whether that worked), `inconclusive` as a first-class outcome, and the coverage invariant borrowed from `build-graph`'s `verifyCoverage`. Measured gap: 68 of 69 workflows are non-blocking; **6** drift classes carry receipts; **0** detectors are in a coverage-checkable roster.
- **The irreducible blocking set, in the right unit.** Push-time *predicate* vs *rendezvous* check. Every measured pathology -- the livelock, the five-day outage, the frozen heartbeat lanes, the `[skip ci]` trap -- belongs to the rendezvous class, and only that class can livelock. Live surface enumerated; `Default` ruleset found `active` with **zero rules**.
- **The corrective-action loop's three gaps**, in severity order, with bounds on what an actuator may change.
- **Forge exit measured, not asserted** -- GitLab implements **1 of 23** methods; **62** TS files and **29** workflows bypass the port. Proposes `audit-forge-exit.ts` as the mechanical version of the exit test, extending the existing `audit-hidden-oracles.ts` precedent.
- **Corporate/sovereign as one code path** -- and sovereign mode identified as DoP=1, i.e. the reference implementation rather than a fallback.
- **Eleven items listed as Aaron's decision**, not the architect's.

## On the livelock

A minimal gate does dissolve it. The doc declines to claim that as the mechanism: shrinking duration is contingent on a cadence we do not control and are deliberately increasing, whereas a push-time predicate has no duration at all, so the livelock condition cannot be formed. That distinction is also the strongest concrete argument for sovereign mode in the doc, because GitHub does not sell us the predicate (`pre-receive` hooks are Enterprise Server only).
