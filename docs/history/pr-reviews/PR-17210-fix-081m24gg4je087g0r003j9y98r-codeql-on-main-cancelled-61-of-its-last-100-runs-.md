## The cause is one line

`concurrency.group` is scoped on `github.ref` with an unconditional `cancel-in-progress: true`. On `main`, a **push**, a **cron** and a **merge_group** all resolve `github.ref` to `refs/heads/main` — so they shared a single group and killed each other. At ~84 commits/day on `main`, most analyses never finish.

The workflow's own comment asserted the opposite — *"schedule runs carry a distinct ref (`refs/heads/main` on cron) so they don't cancel each other."* That is backwards, and it stood unchallenged because **prose cannot be run**.

## Why this is the worst class, not a slow-CI annoyance

An alert count read from a cancelled scan is **a check that did not run looking like one that passed**. Every open/closed code-scanning number quoted today rested on this.

**The defect demonstrated itself.** Of the last four runs on `main`, the two cancelled ones were exactly the two that would have verified this session's own security fixes (#17201, #17203) — so those alerts staying `open` carried zero information about whether the fixes worked.

## The fix

```yaml
cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

PR force-push still supersedes the previous run — the case cancellation was *for*. Runs on `main` now queue and complete. Queuing is the accepted cost and it is the right trade: **a delayed analysis that finishes is worth more than a prompt one that is cancelled, because only the first produces data.**

## The falsifier

A one-line YAML change rots silently, so `hygiene/audit-scanner-cancels-itself-on-main.ts` is wired into the `cross-verify` floor. It refuses any **evidence-producing** workflow that runs on a default-branch trigger, groups on `github.ref`, and cancels unconditionally — and its refusal **prints the replacement**.

**Scoped deliberately.** Cancelling a redundant *build* costs latency; cancelling an *analysis* costs the truth of every number downstream of it. Only the second is refused, and a test pins that a build workflow is left alone.

**Proven to FAIL on the pre-fix workflow, not merely to pass on the fixed one:**

```
pre-fix  → rc=1, REFUSED, remedy printed
fixed    → rc=0, 2 evidence workflows audited
```

A check only ever shown to pass is the vacuity class — which is the very thing this one exists to catch.
