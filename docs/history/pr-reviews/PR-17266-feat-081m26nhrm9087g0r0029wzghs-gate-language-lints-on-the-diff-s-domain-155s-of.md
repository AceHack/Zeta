## What changed

`path-filter` already emitted one scalar (`code`). It now also emits a **per-domain vector**, computed by `src/Core.TypeScript/ci/path-domains.ts`, and five non-floor language lints gate on their own domain.

**Four safety properties, each verified rather than asserted:**

1. **The diff is the authority, never the label.** Nothing reads the PR title — `[skip-review]` does nothing. A test pins it by feeding those literal strings in and asserting every domain comes back **on**.
2. **Fail closed.** Outputs carry a `|| 'true'` tail, so an absent or failed verdict runs everything. An unrecognised extension returns `null` (deliberately distinct from `ALL_DOMAINS`, so a caller can't confuse *"feeds everything"* with *"nobody classified this"*). Non-PR events force every domain on.
3. **The required floor is untouched** — verified by parsing the workflow: `gate-required` needs `[matrix-setup, path-filter, build-and-test, lint, lint-typescript, cross-verify, full-verify, test-typescript-hermetic]`, and **none of the five gated jobs appears in it**. Narrowing a floor job is a treaty amendment on your consent path; not done here.
4. **Whole-tree coverage survives** — the workflow also runs on `push: branches: [main]`, where every domain is forced on. A drift lint skipped on a docs-only PR would have been reporting on *main's* state, not the PR's.

**Cost stated, not hidden:** `needs: path-filter` puts these behind a job with p50=23s but a heavy tail (p95=70s, p99=201s, max=262s) — in the tail this can *delay* a lint that would have started immediately.

## The falsifier caught my own bug, and it was the worst available one

The first draft consulted an inert-prefix list **before** the extension, so anything under `docs/`, `.claude/` or `data/` classified as feeding nothing. The whole-tree test refused it and named the reason: **158 tracked source files live under those prefixes** — 7 TypeScript hooks in `.claude/hooks/`, 20 scripts in `docs/research/scripts/`, a long tail in recovered branches. Prefix-first would have silently exempted every one from its own lint, **including `lint-typescript`, which *is* a floor job.** Extension now beats prefix: a directory name states intent, a `.ts` extension states what a linter will open. 19 falsifiers, green.

**Deliberately not gated:** shellcheck (shell reaches it through workflow `run:` blocks and shebang files with no extension — a domain I couldn't establish by reading the lint is one I leave running) and markdownlint (nearly every PR touches `.md`).

## The taxonomy

Your three axes are the **confusion matrix**, plus — on the third — **the oracle problem** (Weyuker 1982; Barr et al. 2015): you can't place a verdict in the matrix without ground truth, and most of ours have none.

**One structural correction:** the verdict is **ternary** — fired / did-not-fire / **could-not-run**. Collapsing the third into the second *is* the vacuity class. And a **fourth** value is needed, **not-applicable**, which is exactly what this PR emits — and which GitHub renders identically to a killed job.

**Five missing dimensions, each with a worked instance from today:**

- **Locus** — subject (`release()` was an empty function), test (`/store` hardcoded), environment (no `node_modules`). One red X, three owners, three opposite responses.
- **Determinancy** — what the verdict is a *function* of. `/store` is 100% deterministic given the OS and perfectly inverted between two. Not flake: an undeclared channel, §13 stated as a property of a verdict.
- **Freshness** — the 24,954 GraphQL count was correct and its interpretation stale; splitting by date reversed the conclusion.
- **Independence** — `rhoIcc` 0.549/0.628, `effectiveCount` **1.43 from N=3**.
- **Blocking vs drift** — the one dimension already implemented.

**And the answer to "minimal multi-check over each change":** not one check per cell — enough checks to *resolve each axis*. **Does it run · does it fail when it should · does it depend only on the change · is it fresh for this tip · is there a decorrelated second witness.** The finding is that this repo **already has all five and applies none of them to a single change as one gate**. A wiring problem, not a missing capability.
