## Description

Work-item 081KYWE8Q3508 — with schema-on-ZSets, *"our entire db stored-proc architecture long term."*

**Finding that shaped it:** the design doc carries **two** open generics and one was already landed — the *weight* axis lives in `ZSetW.fs`'s `*By` ops, so re-landing it would have been duplicate work. The un-landed axis (and the one the work-item names) is the **element/row** type, where §4's **path 1, dictionary-passing (Wadler–Blott 1989)** is the *correct* mechanism, not the demoted fallback.

- **Type-tagged key** `(TypeId, Canon)` — heterogeneous `ZSet<ZAtom>`, no boxed `obj`, and **no registry lookup in the compare path** (a mutable global there would make sort order depend on *registration order* — capture + a DST hazard). Comparison is `Collation.binary`, not F#'s structural default (UTF-16 code units diverge on astral planes).
- **Two genuinely different impls**: int64's canon is **order-preserving** (codepoint order *is* numeric order — the collation treaty discharged by the encoding); string's `double` is concatenation — *the same abstract x⊕x in a different monoid*. `succ` is absent from string so operator-not-supported has a real instance.
- **`mapValues` is all-or-nothing** — a partial result would be a silent drop wearing an `Ok`, the same landmine class as the `Meno.Bind` bug.

**29 tests** incl. a regression guard that *an unregistered row hidden among succeeding rows still fails the call* — the exact shape a `choose` would swallow. Z-linearity (incl. w<0 and emit-then-retract), determinism/DST, canon injectivity. Composes with `SchemaLog` via a **fold**-tracked coverage check.
