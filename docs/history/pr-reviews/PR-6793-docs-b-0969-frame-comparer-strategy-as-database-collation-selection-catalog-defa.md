## What
Maintainer 2026-06-07 refinement on 081KT07NV0008QG0R001YDB73K's comparer strategy: **don't treat it as a CS comparer parameter — treat it like database collation selection.**

- **A catalog of named, selectable collations** (like SQL/Postgres `COLLATE`, ICU locales) — part of a value's identity, not raw `IComparer` plumbing.
- **Ship one default**, chosen for (i) easiest identical support across all 4 langs + (ii) familiarity to DB people → both point to **binary/ordinal collation** (codepoint ≡ UTF-8 byte order; DB "binary collation" `*_bin`/`BINARY`/Postgres `C`), which is also the culture-invariant canonical collation.
- **Other collations** (case-insensitive, ICU/locale-aware) are **opt-in** catalog entries, never the silent default.

So strategy (a)'s "explicit comparer param" is really **"select a collation (default = binary/ordinal)"** — name + model the API in DB-collation terms.
