## Description

fix(agent-proposal): terminate the delivered patch, and make git apply refuse out loud

The first live Pages operator delivery (proposal 60b7c599, 12:28Z 2026-08-17, runs
32030034784 and 32030041970) failed with `corrupt patch at line 12`. Decoding the run's
own ZETA_AGENT_PATCH_B64 shows the patch was otherwise exactly right -- correct headers,
`@@ -0,0 +1,7 @@` matching its seven `+` lines, a bounded `docs/` path. Its final line
simply carried no terminating newline, and `git apply` reads a unified diff as a
line-oriented format in which every line, the last one included, is terminated.

Every designed bound held. `planAgentProposal` passed, so the schema, the proposal ID,
the protected-main workflow source, the base-SHA binding and the path bound all did
their jobs; the delivery died one byte later, on the raw format.

Two changes:

1. `normalizeUnifiedPatch` terminates the final line. This is not laxity. A target file
   that genuinely lacks a trailing newline is stated by an explicit `\ No newline at end
   of file` LINE inside the patch, itself terminated, so the patch text's own final byte
   carries no information about the result. And it is digest-invariant by construction:
   the binding is over `sha256(payload.trim())`, and `.trim()` already removes that
   newline -- so normalization cannot carry a patch past a check the delivered bytes
   would have failed. A test pins that invariance, because it is the whole safety
   argument.

2. `git apply --check` now refuses with a teaching error naming a generator, like every
   other rejection in this runner. It previously escaped as a raw execFileSync stack --
   `status: 128`, a pid, and Bun echoing this file's own source around the throw site --
   which reads like the runner crashed rather than like the patch was refused. git's
   stderr is kept verbatim because its line number is the only part that localises the
   defect for the producer.

The load-bearing test runs `git apply` against a temp repo and asserts the delivered
patch is refused and the normalized one accepted. The string assertions alongside it
would all pass against a normalizer that did nothing; this one asks the actual authority.
Mutation-checked: replacing the normalizer with `return patch` fails 2 of 5, including
that one.
