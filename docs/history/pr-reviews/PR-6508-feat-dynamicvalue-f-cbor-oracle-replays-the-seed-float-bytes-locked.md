    Real observation, addressed by scoping the contract in e209233a5 rather than changing behavior. A lone UTF-16 surrogate is malformed String content (not a valid Unicode scalar). CBOR text strings are UTF-8 by format (RFC 8949 3.1), so unlike JSON text there is no `\u`-escape that preserves it -- it is simply unrepresentable as a CBOR text string.
