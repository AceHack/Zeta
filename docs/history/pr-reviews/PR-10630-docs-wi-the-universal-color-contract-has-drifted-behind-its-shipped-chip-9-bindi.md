## Description

## 1. `universal/color.md` describes a binding that shipped as unbuilt

The doc still lists CHIP-8 as `Mono1` — **"not yet"** — with colour opcode extensions as the *upgrade path*. That upgrade landed 2026-06-11/13: plane mask + `Fn01` + per-plane `DRW` + selective `CLS` in `src/Core/Chip8Cow.fs`, conformed by the TypeScript / C# / Rust oracles against `src/Core.TypeScript/chip9/golden-vectors.lines`, with `src/Core/ZetaMax.fs` binding `Indexed8` off the frame's own state.

The doc's `Capability` (`Mono1 | Grey<n> | Indexed<palette> | TrueColor`) also disagrees with its only implementation (`ZetaMax.Capability = Mono1 | Indexed8`).

## 2. One 3-bit gamut, three tables, two of them different bytes

`ZetaMax` (names + ANSI SGR), `ShapeRender.colorHex` (hex), and `demo/chip9-cart-viewer.html` `PALETTE` (hex) each define mask→colour independently. The **semantics** agree (same hue per mask; R=1 G=2 B=4 is ANSI's own bit order, which is why the ZetaMax binding is nearly free). The **hex tables differ**. `ShapeRender.colorHex`'s comment calls itself "the ZetaMax Spectrum palette" while `ZetaMax.fs` carries no hex to check that against.

Not claimed: that either table is wrong. Display edges may legitimately differ. What is missing is a declared source and a golden vector.

## Guardrails written into the item

- `db/shapes/golden/*.svg|html` are byte-locked to the **current** `ShapeRender` hexes, so a reflexive "unify the palette" edit churns 19 cartridges. The item says so up front.
- `db/shapes/` cartridge promotion (`pending/`, `ShapeRender.strokesOf`, `ShapeAcceptance.geometryLaw`) is **explicitly out of scope** — another agent is live there as of 2026-08-13/14.
- The shape-cartridge → CHIP-9-ROM bridge is named as a separate, larger piece and deliberately **not** filed here.
