## Description

## The half that was unbuilt

`SoftChip8.lookAhead` already answers *"where is this machine `n` steps from now"* **within one run**
(`Chip8SelfSim.Tests` T1: byte-equal to the real timeline). Nothing carried a result **across** runs —
`db/emus/chip8/` held exactly one file, a capability ledger. Run 1's computation could not reach run 2.

Aaron 2026-08-17, verbatim:

> "we do this in our chip8 rooms where we can do superdeterministic calculations based on one run and
> then save the results for future runs, we have been able to compute over all chip8 4k memory space
> cause it's tractable, but other calculations may not be tractable, it's a calculation-by-calculation
> basis. this is how we can let the 'future' affect the past in a 2nd retrocausal way because the 1st
> run of the game all the way up until the end can affect the start of the 2nd run of the game through
> superdeterministic calculations in chip8 memory space"

**Mirror register:** his words, preserved (note his own scare quotes on "future"). **Beacon register:**
memoization of a deterministic transition function over a finite state space. Nothing propagates
backward in time; a previous run's *computed* results are *stored* and later *read*. Anchors, checked
rather than gestured at:

- Michie, *"Memo functions and machine learning"*, **Nature 218, 19–22 (1968)** — coined "memo function".
- Eventual periodicity: any `f : S → S` on finite `S` has `f^(μ+λ)(s₀) = f^μ(s₀)`, `μ+λ ≤ |S|`
  (pigeonhole + determinism) — the "rho".
- Brent, *"An improved Monte Carlo factorization algorithm"*, **BIT 20, 176–184 (1980) §7** — the
  `(μ, λ)` detector.
- Harris (1960), random-mapping statistics — cited as the reason **not** to extrapolate, since CHIP-8's
  step map is not a random map.

No identifier or comment in the shipped code claims physical retrocausality.

## Two measurements that corrected the plan

**1. Some orbits provably do not close — Aaron's scope limit is literally true here.**
`Chip8Cow`'s `Rng` is a 2^64 additive counter carried *inside* the frame, so a ROM executing `CXNN` in
a loop cannot revisit a state until it wraps.

| `C0FF 1200` (RND then jump) | result |
|---|---|
| bound 1 000 | OPEN — no cycle |
| bound 100 000 | OPEN — no cycle |
| bound 1 000 000 | OPEN — no cycle (6.4 s) |

100 000 steps → **100 000 distinct full states, zero repeats**.

So the artifact records a **verdict**, and `OpenAtBound` is a *distinct constructor* from `Closed`.
That is the hidden-oracle guard in its exact local form: a precompute that stopped at its bound and
wrote `lambda = 1` would have promoted **its own budget** into a **claim about the machine**, and run 2
would then reduce modulo a cycle that does not exist and return a confident wrong state. The type makes
that unrepresentable.

**2. Three of the five "fixed points" are not halts.** Two are `FX0A` waiting for a key, which
`Chip8Cow` models as a no-advance stall — a literal fixed point of the *pure, no-input* step map. The
orbit did not end; the **deterministic segment ended at an input branch**, the seam
`SoftChip8.branchesOnInput` already names. Recording those as "cycle of length 1" would be a store that
lies by omission, so `terminalKind` distinguishes `halt` / `awaiting-input` / `cycle`.

## The bound, and how it is attributed

There is **no default step bound anywhere in the module**. `PrecomputeBudget = { MaxSteps; Attribution }`;
an empty attribution is refused **before any work runs**; and the budget is written into the artifact so
a later reader can judge whether an `OpenAtBound` is a fact about the ROM or a stingy caller. The bound
used for the committed artifacts reads, in full:

> "Otto 2026-08-17 (work item 081M087DVKF087G0R002DDHMPR): 4096 steps, chosen to exceed the largest
> measured orbit among the committed fixtures (513) with headroom; NOT a claim about any ROM"

## The Dark Hall seam — the guess was wrong, and DV2.0 says why

Measured split: **F#** owns the engine (`DarkHall*.fs`, 2 854 lines); **TypeScript** owns the browser
surface (`darkhall-ui/`, 32 files). The natural guess for the TS persistence seam was
`darkhall-browser-durable-runtime.ts` — **that is the wrong seam.** It manages *mutable per-session*
IndexedDB checkpoints with an invalidation/replay ledger; an orbit artifact is *immutable,
content-addressed, committed, shared, read-only*. Different change rates ⇒ different storage shapes, and
routing an immutable artifact through checkpoint-invalidation machinery would hand it a mutable-cache
failure mode it does not have.

**The right seam is the one F# already uses, in both languages: injection.** The room *receives* a
reader; both modules perform zero IO — no filesystem, no `fetch`, no IndexedDB. That is §13.

### Honest notes on the mutation numbers

- **My first mutation harness had the defect it hunts.** M1's patch text did not match the source, so
  the mutation silently never applied and the run reported "20 passed" — a *false survivor* that reads
  exactly like a killed claim. Every patch now asserts its search text was found, and M1 was re-run
  properly (5 failed). This is worth stating because an unapplied mutation is the vacuity class inside
  the tool meant to detect the vacuity class.
- **T4 and T4b are genuine equivalent mutants.** Removing *either* hex guard alone leaves the claim
  defended by the other, so the suite stays green — correctly. Only removing **both together** goes red.
  Reported as redundancy, not as a gap.

## What is deferred — 081M089ZPAY087G0R001MYXM7N

Room-loop auto-consult, the IO adapter, Dark Hall browser injection, a TS *writer*, and branch
memoization. Auto-consult is deliberately not slipped in: a memo hit is nearly free, so it changes what
the metered tank pays for — a *metering* change that deserves its own ΔU story rather than arriving as
a silent subsidy.

TypeScript can read and verify these artifacts but cannot write them: `chip9.ts` is a treaty conformer
for the DRAW subset whose `Frame` has no `delay`, `sound`, `keys`, or `rng`. A second implementation
that independently recomputes the same digest and refuses the same corrupt bytes is the cross-oracle
check that matters; a second emulator is its own byte-lock exercise.
