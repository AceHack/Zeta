## Description

Red-on-main fix-forward: tick-codec vectors (302f30500) stored versions as
bare JSON numbers; max-int63 9223372036854775807 parses to ...776000 in any
float64 JSON reader (JS), so the TS oracle failed 3 tests and tsc failed on
the un-imported bun:test globals + an unchecked index. Fixes: (1) versions
are now decimal strings — lossless in every reader, encoding note added to
the vector file; (2) Rust reader as_i64 -> as_str().parse::<i64>; (3) F#
reader GetInt64 -> GetString + Int64.Parse(InvariantCulture) (CA1305
discipline); (4) TS test imports bun:test; (5) tick-codec.ts unchecked
buf[i] -> buf[i]!. TS oracle: 64/64 green, tsc clean. Rust/F# lanes verify
in CI (no cargo/dotnet in this sandbox). C# tests hardcode their vectors —
unaffected.

The bug had economic value: it surfaced the int64-in-JSON-number hazard the
no-binary-in-proof-lineage rule implies but never spelled out — golden
vectors must string-encode anything a float64 reader can corrupt.
