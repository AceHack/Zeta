## Description

Builds the verify half that was missing on every axis: nothing checked the ISO, nothing checked device identity, nothing classified device state, and **only the Windows arm read back what it wrote.**

## Verify before write — reuse, not rewrite

Reuses `parseSha256Sums` and `sha256FileHex`. **Deliberately NOT reused: `resolveLatestFromSha256Sums`**, which picks the highest-*version* entry matching a glob — right for "fetch the newest upstream image", **wrong here, because it would happily attest a *different filename* than the one about to be written.** Lookup is by exact basename, with a test pinning that distinction.

Four hard refusals, **all before any device enumeration**: `manifest-missing`, `manifest-unparseable`, `iso-not-in-manifest`, `digest-mismatch`.

### The honest limit, stated at the claim

**Verification alone does NOT fix the newest-in-`~/Downloads`-by-mtime picker.** It converts *arbitrary code execution on the operator's boot media* into *denial of service* — a real improvement, and not the fix. The residual hole is exact: an attacker who can drop files there drops `evil.iso` **and** a matching `SHA256SUMS`, and **self-consistent forgery passes.**

> **A digest proves integrity, never provenance.**

Closing it needs the source pinned — `cosign verify-blob` against a published signature with the identity pinned to the workflow ref, and the ISO resolved **by run-id rather than by mtime.**

## Device identity — checked, not discovered

`flash-usb.ts` already read all five identifying fields and **only printed them.** They're now compared against a caller-supplied expectation. **Checked twice** — before the consent prompt *and* immediately before `dd` — because the operator may sit on that prompt for minutes and **`/dev/diskN` is recycled across a replug.**

## The classifier returns a FACT, not a permission

Closed union `blank | half-provisioned | provisioned | unrecognized`, each verdict carrying which rule fired, and **`unrecognized` is the default** — so a novel shape never reads as safe. **Somebody's photo drive classifies `unrecognized`, never `blank`.**

**Verdict on the real specimen, read-only from the live device: `/dev/disk6` is `half-provisioned` (R4)** — FDisk scheme, one 3,145,728-byte partition, no filesystem, 123,976,286,208 bytes unallocated.

The separator is **principled rather than tuned**: `allocated < MIN_ISO_BYTES`. A complete write allocates at least the smallest ISO we'd ever write, so **"something allocated, but less than any ISO" *is* the signature of a write that started and stopped.** Two orders of magnitude of margin.

## Read-back verify ported to macOS/Linux

A pure comparison over an injected reader, wired in after `dd` and before eject, **with no opt-out flag.**

## Measured vs designed-but-unrun

**Measured:** all four functions including every refusal branch, the `/dev/disk6` pinning test, closed-union exhaustiveness, and **three live read-only end-to-end runs** against the real device.

**Designed but unrun: exactly one thing** — the chunk reader pointed at `/dev/rdiskN`, an `openSync`/`readSync` shim **deliberately held free of logic so the untested surface is as small as a syscall wrapper gets**; pointed at a regular file it *is* covered. **The logic is measured; the call site is not.**

**Verified in a trusted clone at `origin/main`: 494 pass / 0 fail** — 468 baseline + 26 new, **nothing broken.** Three mutations bite: R4 comparator flipped → **2 fail**; byte comparison neutered → **3 fail**; manifest-missing turned into a pass → **1 fail**.

## Five findings — and the second is a foot-gun this change creates

- **F1 (P1): the target is still discoverable by default.** `cli.ts` spawns with only an ISO path, so the common path takes the unpinned branch. **This is what keeps "one plugged-in phone away" partly true.**
- **F2 (P2): CI publishes no `SHA256SUMS`, so the new gate has nothing to check and REFUSES THE NORMAL PATH** until a one-line workflow change lands. That file is held by another agent this round, so **the exact line is written into the finding instead.** A P3 row reportedly exists; **this raises it to P2 precisely because a refusal-by-default gate now depends on it.**
- **F3 (P2):** digest is not provenance. **F4 (P3):** `/dev/disk6` left half-provisioned, destructive command written out for a human and **not run.** **F5 (P3):** the aarch64 arm emits no digest at all, so the gate can never be satisfied there.

**No write, format, partition, erase, mount or unmount of any physical device.** Only `diskutil list`/`info`, read-only; **`/dev/disk6` verified byte-for-byte identical in partition layout before and after.**
