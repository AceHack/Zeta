## Description

The sharding migration (#10427) snapshotted `manifest.jsonl` before #10414's archive entry landed, so `origin/main` carries **6340 manifest entries against 6339 shards** and the derive drift gate fails on the tip.

Fixed by re-running `migrate-pr-manifest-to-shards.ts`, which is re-runnable by design:

```
parseable:  6340   unparseable: 0
shards:     added=1 replaced=0 noop=6339
round trip: input=6340 derived=6340
round trip: BYTE-IDENTICAL modulo ordering (pr_number ascending, integer compare) ✓
```

**Worth knowing before someone follows the hint:** the failing check prints `repair: derive-pr-manifest.ts --write`, which would have been the **wrong direction** here. `derive` regenerates the manifest *from* the shards — so `--write` would have **deleted PR 10414's entry** rather than creating its shard. The migration is the correct tool whenever the manifest leads the shards; `--write` is correct only when the shards lead.

Also: the run independently confirms **6340 parseable, 0 unparseable** — the same result that corrected the false "3 malformed lines" premise in #10434.
