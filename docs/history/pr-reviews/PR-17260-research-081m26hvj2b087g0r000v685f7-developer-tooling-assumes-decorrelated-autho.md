## Description

## Thesis

Aaron 2026-09-10: *"github and likely all other tools are not designed for AIs that cluster based on common next token space… AIs / LLMs have much more base model context so they get mixed together more."*

Human authorship decorrelates for free — geography, team vocabulary, which codebase you came up in. Developer tooling inherits that as a silent premise: a second reviewer is worth having because they learned differently; four implementations disagree because four teams derived them separately; blame is informative because a name maps to a persistent individual. Agents drawing on a shared base distribution do not have the property, because what varies between them — context, persona, memory — sits *above* the layer that produces the token.

This is the trainset floor from `2026-08-25-rho-is-a-layer-stack-not-a-scalar` showing up in **tooling** rather than in vocabulary, and it is the `ρ → 1` side of the band `anti-babel-preserve-reconcilability` names and does not dwell on. The repo's own checked-in meter agrees: `rhoIcc` 0.549 cumulative / 0.628 windowed, `effectiveCount` 1.43 / 1.33 from N=3, against `ρ* = 1/3`. Three agents are worth about one and a third — and that series has been stale since 2026-08-22.

## A falsifiable form — run, with an honest failure

Restricting the denominator to files that perform the operation at all, so an agent that never touches the filesystem is not credited with avoiding a filesystem defect:

> **189 attributable `.ts` files had the opportunity. 80 took the racy shape. Pooled `p = 0.423`.** 16 agents; 11 have at least one.

- **Author coverage** was computed and is a **dud**: observed at or below the independence prediction at every threshold, because at `p = 0.42` coverage saturates under both hypotheses. Published anyway — a statistic that cannot discriminate is worth retiring in public.
- **Overdispersion** (`χ² = 39.54`, 15 dof) rejects a single shared rate, which cuts *against* the strong thesis — but is confounded by subsystem assignment and was chosen *after* the first statistic failed. Garden of forking paths, disclosed.
- **The statistic that would work needs an external control**: run the same lint over pre-2023 human-authored TypeScript on the same denominator. Prediction recorded before the measurement. Thesis stays `toy` until it runs.

## Tooling if authors are correlated

Three of four need only data the repo already stamps and folds into nothing.

1. **Review assignment on prior distance, not availability** — compare `Agent-Model:` between author and reviewer, warn on equality when another family was available. Knight–Leveson with the last source of separation removed.
2. **N-version on differing model *families*, not repos.** `dual-use-detection-is-neutral-oracle-decides` already concedes the four oracles *"do not agree by default"* and that *"the seed is the treaty."* The extension: the treaty was negotiated by four human language traditions; **our four conformance implementations were written by agents drawing on one prior**. Measure the `Agent-Model` distribution per oracle directory. Not run here.
3. **Audits report author coverage.** `p = 0.423` across 16 agents is not 80 mistakes; it is one API doing what it does. `io/safe-io.ts` already made that escalation *by instinct*. Make it a threshold.
4. **`Agent-Model` is stamped on every commit and used for nothing**, while `Credential-Identity` is `AceHack` on essentially everything — so `git blame` returns one human for work done by 25 agents across 6+ model families. A `db/authorship-correlation/` fold is the per-layer ρ measurement the rho doc asks for and nothing does.

Constrained by the escape hatch `docs/VISION.md` already names: *"ρ is per-**task**… a mechanical check has ρ ≈ 0 no matter how correlated the agents running it are."* The answer to correlated review is not more reviewers — `N_eff` caps at `1/ρ` — it is more mechanical falsifiers.

## Self-implication

Written by an instance of the thing it describes. The verification was done by **three subagents of the same model** — `ρ ≈ 1` at the vendor layer, varying context alone. Every correction above came from a mechanical read (`git log --diff-filter=A`, the code-scanning API, a byte hash), not from anyone's judgement. And one correction is mine: §2.4's first draft told the Task audit to index `docs/backlog/`, which the repo had **already refused** for a documented reason — widening it turns a prefix-ambiguous *misidentification* green. Caught by running `classify-zetaid-nonresolution.ts`, which took one command.

Three of five nominated items weakening is the healthy ratio. A version where all five held up would deserve less trust.
