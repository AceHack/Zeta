## Description

## `lane lane-2` went red on #14174, for a true reason

#14174 made `redis`, `weaviate` and `gitlab` measurable (39/47 → 41/47). The packer then did its job and filled the lanes, and `lane lane-2` reported:

```
MEASURED on-disk for lane-2: 8999 MiB against a budget of 8.500 GiB
lane-2 does NOT fit: 8999 MiB measured > 8704 MiB budgeted. The x2.67 ratio under-estimates this lane.
```

All three lanes in that run (32641344919):

| lane | estimated | measured | measured / estimated |
|---|---|---|---|
| lane-1 | 8704 MiB | 7721 MiB | **0.887** |
| lane-2 | 8704 MiB | 8999 MiB | **1.034** |
| lane-3 | 1587 MiB | 1427 MiB | **0.899** |

The `x2.67` ratio is **not biased low — it is ±10% per lane**, exactly as `measure-lane-footprints.ts` already says of itself ("the four samples span x2.49-x3.39 and 2.67 is the low end of that spread applied uniformly").

## The tempting fix was tried and does not work

`packLanes` fills each lane until the next closure would overflow, so a packed lane always sits at ~100% of budget — and the workflow asserts the *measurement* against that *same* budget. Slack is ~0 by construction:

```
--margin 0.85   budget 8.50Gi   lane-1 8.50Gi   lane-2 8.50Gi   lane-3 1.55Gi
--margin 0.80   budget 8.00Gi   lane-1 7.98Gi   lane-2 7.97Gi   lane-3 1.49Gi
```

Budget and fill move together, so **no value of `--margin` changes the measured-to-budget ratio.** The gate has been green only because the lanes were not full — lane-2 sat at 8.05 GiB against 8.50 GiB, slack it had not earned.

## Nothing was tuned to go green

Redefining "fits" to land my own PR is the move this repo is built to refuse, so the workitem records both candidate fixes and takes neither:

1. pack below the assertion threshold (a second, named fraction), or
2. assert fit against real capacity (`freeDiskGib − reservedDiskGib` = 10 GiB, which lane-2's 8999 MiB is *under*) and report `measured / estimated` per lane as the standing evidence about the ratio — which is what that check was built to convict in the first place.

**Both live in `lane-partition.ts` / `k8s-lane-partition.yml`, and #14163 is in flight on both**, moving `freeDiskGib` 14 → 70. Whoever lands the 70 should land this with it: at a 56.1 GiB budget the same ±10% is ±5.6 GiB of unbudgeted disk.
