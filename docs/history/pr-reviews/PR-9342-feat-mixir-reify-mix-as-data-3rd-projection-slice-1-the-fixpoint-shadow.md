## Description

## What

Aaron 2026-07-03: *"yes, start reifying mix-as-data."* The apex of the Futamura thread — the **real** 3rd projection, not the trivial currying reading (which holds for free by referential transparency and says nothing).

The native `specializeMem` had one non-data parameter left: the `loadImm` builder (a native closure emitting "set register r to constant v" when a static read is materialized). This slice turns it into **data** — a `loadImm` *descriptor* the runner reads:

- **single-op** form `{ op, regInto, immInto }` → CHIP-8's `SET`
- **per-register** form `{ perReg:[{r,op}], immInto }` → the 6502's `LDA`/`LDX`/`LDY`

With that, **every** input to `mix` is a `DynamicValue`: spec, program, static state, *and* the materialization strategy. So a whole mix invocation is one serializable `MixCall` value, and `runMixCall` is a pure **data → data** transformation.

## The fixpoint (the real `gen(gen) == gen`)

A residual is a **fixed point of `mix(·, ∅)`**: mixing it again with nothing static reproduces it byte-for-byte.

```
mix(mix(p, s), ∅) == mix(p, s)     // machine-checked
```

This is the ISA-side analogue of the parser-side `Cogen`'s `regenerate == direct`.

## Tests (4, all green — build 0/0)

1. **faithful (CHIP-8)** — the data loadImm reproduces the native closure byte-for-byte
2. **faithful (6502)** — same, over the memory-bearing ISA with its per-register descriptor
3. **the `gen(gen)==gen` fixpoint** on both ISAs
4. a `MixCall` is **byte-lockable** data

## Honest scope

This makes the mix **data-parameterized + self-idempotent**; it does **not** yet reify the mix *algorithm* into the IR (the decision procedure is still native F#). Expressing the partial evaluator itself as an IR program that `mix` can specialize — **true self-application** — is the next slice. This slice removes the last native *value* from the interface and lands the fixpoint law.
