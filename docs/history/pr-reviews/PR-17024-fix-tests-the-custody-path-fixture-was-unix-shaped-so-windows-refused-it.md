## Description

## What was red

`build-and-test (windows-2025)` and `(windows-11-arm)` have been failing on `main`
at **62.7% / 67.2%** with clean streak 0 — the two loudest rows in `drift (loud)`.

Both failing tests were in `HiddenSwitchMetadataTests`, and both failed at their
**first** assertion (the baseline `Assert.True(Result.isOk (Admission.parse ...))`).
The fixture was being refused before any assertion under test could run.

## Root cause — one platform-dependent predicate

`Admission.filePin` requires a fully-qualified custody path:

```fsharp
IO.Path.IsPathFullyQualified value.File     // Admission.fs:30
```

The fixture built every path as `"/owned/" + file`. On Unix that is fully
qualified. **On Windows a leading `/` is drive-relative** — rooted, but not fully
qualified — so the predicate returns false and the fixture is refused.

## What moved, and what deliberately did not

The **production rule is unchanged**. An unambiguous absolute custody path is
exactly what that check exists to enforce; weakening it to `IsPathRooted` would
admit drive-relative paths on Windows, which is the opposite of the intent.

Only the fixture moved: one `owned` root (`C:\owned\` on Windows, `/owned/`
elsewhere) applied to all 11 path literals in the file, so every equality and
inequality relation between them is preserved.

## Verification, stated honestly

- **macOS: 13/13 `HiddenSwitchMetadataTests` pass** — the Unix branch is intact.
- **Windows is NOT verified by this PR.** Windows never runs on a `pull_request`
  (the matrix gates it to push/dispatch), so a green PR here proves nothing about
  the platform being fixed. Proof comes from `workflow_dispatch` run
  **34182552704** on this branch, and **that run should gate the merge**.

## Blast radius

`IsPathFullyQualified` has exactly one caller; `/owned/` appears in exactly one
file. That is the whole surface.

**Not addressed here:** a separate intermittent `install-windows=failure`
(seen on `4d69d7a8`) which skips build and test entirely. Different defect.
