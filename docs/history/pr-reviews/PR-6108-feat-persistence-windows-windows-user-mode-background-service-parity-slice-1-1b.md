## Description

## Windows pre-install-surface parity — slice 1 + 1b

Brings Zeta's macOS/Linux-only pre-install surface to Windows, **user-mode** (client
workstation, not server — no admin, no UAC), per Aaron's direction on the ServiceTitan
laptop 2026-05-30. Closes the `install.sh:159` "Windows backlogged" loop (slice 1).

### Slice 1 — user-mode background-service installer (`tools/persistence/windows/`)
- `install-scheduled-task.ts` — TS installer (mirrors `install-launchagent.ts`): renders a
  UTF-16 Task Scheduler XML + `schtasks /Create`. `--ref` selects the dedicated clone's branch.
- `scheduled-task.xml` — `LogonType=InteractiveToken` + **omitted `<RunLevel>` => Limited**
  (no UAC/admin), at-logon trigger + `PT1M` repetition, `IgnoreNew`. Schema verified vs this
  machine's OneDrive task.
- `otto-loop-wrapper.ps1` — per-tick wrapper; runs the tick against a **dedicated clone**
  (`%LOCALAPPDATA%\zeta-otto-loop\Zeta`), never the operator checkout (the tick's
  `git reset --hard origin/<ref>` would wipe it). macOS dual-agent parity.
- `README.md` — install/verify/uninstall + parity table.

### `.claude/bin/claude-loop-tick.ts` changes (additive, zero macOS impact)
- **OS-conditional subprocess PATH** (`tools/persistence/loop-subprocess-path.ts`, unit-tested):
  the tick replaced `process.env.PATH` with a POSIX list, erasing PATH on Windows. Now inherits
  on win32; `posix.join` keeps the macOS/Linux PATH host-independent.
- **`ZETA_CLAUDE_LOOP_REF`** (default `main`): configurable reset-ref so a dedicated clone can
  track any branch (lets a freshly-registered loop run the fixed tick before this merges).

### Slice 1b — cross-machine heartbeat-push
- Wrapper publishes a ZetaID-keyed heartbeat to the shared `agent-heartbeats` branch via the
  existing `tools/agent-heartbeats/write-heartbeat.ts` (REST git-data, PR-free, race-safe),
  gated ~10 min. `otto-windows` heartbeats now visible cross-machine (answers the git-native
  PR-free comms question; the `/tmp` bus is machine-local).

### Verified on real hardware

- Tick heartbeat: `fetch=ok claims=27 open_prs=2` (PATH fix works; git+gh resolve).

  <pre>
  PowerShell's `try/catch` does **not** trap non-zero exit codes from native executables (`bun.exe` here), regardless of `$ErrorActionPreference = 'Stop'` — that only applies to cmdlets. As written, if the heartbeat push fails (`bun ... write-heartbeat.ts` exits non-zero), the `catch` block never runs: the `WARN heartbeat-push failed` line is never logged, and `$hbStamp` is still written, which then suppresses retries for ~10 minutes. Either check `$LASTEXITCODE` after the call and only stamp on success, or (PS 7.3+) set `$PSNativeCommandUseErrorActionPreference = $true` so non-zero native exits throw.
  </pre>

**Replies:**

  - **`AceHack` (human)** at 2026-05-30T13:45:58Z on `tools/persistence/windows/otto-loop-wrapper.ps1`:72 (association: MEMBER)

    <pre>
    Fixed in 9e6175477. Used the `$LASTEXITCODE` path (not `$PSNativeCommandUseErrorActionPreference`, which is PS 7.3+ and would break the `#Requires -Version 5.1` floor). Now: run the native `bun ... write-heartbeat.ts`, then stamp `$hbStamp` only when `$LASTEXITCODE -eq 0`, else log `WARN heartbeat-push failed (exit $LASTEXITCODE)`. The ~10-min retry-suppression no longer triggers on a silent push failure. Verified via `pwsh` parse-check.
