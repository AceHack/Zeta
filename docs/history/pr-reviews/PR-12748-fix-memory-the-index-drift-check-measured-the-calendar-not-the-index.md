## Description

`081M0DY68KN087G0R002MQ1BDR`.

`renderIndex` read the wall clock for its "Last reindex" stamp, and `--check` compared the **whole** rendered output against the file on disk. So on any calendar day after the last reindex the two differed by exactly one field — the date — and the check reported **INDEX DRIFT** against an index that had not drifted.

The workflow triggers on `memory/**`, so that was a red on **any** memory-touching PR, every day, forever.

Observed on #12537 against an edit to `memory/soraya/NOTEBOOK.md` — a file the index doesn't even contain (`grep` returns 0 of 1631 entries), so it could not have caused index drift *by construction*. Regenerating produced a one-line diff: the date.

## Why fix it rather than tolerate it

The remediation commit bumps a date string and verifies nothing. **A check that cries wolf daily is a check nobody reads** — and that's the actual damage. It trains contributors to regenerate reflexively on a red they've learned is meaningless, which is exactly the condition under which a *real* index drift gets waved through. The failure signal did not track the property the check names.

## The fix was already in the file, one variable away

The AutoDream marker is read off the existing `MEMORY.md` and passed back into the render — specifically so the reindexer doesn't reset a date someone else wrote more recently. The "Last reindex" stamp needed exactly that treatment.

It's now a parameter carried forward from the existing file, so the render is a **pure function of (heap content, existing stamp)**: an unchanged heap reproduces the file byte-for-byte on *any* day, and the stamp advances only when a write actually changes the index — which is what "Last reindex" always claimed to mean.

That's `local-time-never-enters-the-shared-fold` fixed **at the root** rather than worked around: the ambient clock is local, the generated index is the shared conclusion, the two no longer cross.

The work-item's alternative candidate — diff only between the AUTO-INDEX markers — would have carved the header *out* of the comparison, leaving a region where real drift could hide. Removing the clock beats excluding the field it corrupts.

## Falsifiers — including one against fixing-by-silencing

Four tests added. The load-bearing pair, confirmed by mutation:

| mutant | result |
|---|---|
| restore the wall-clock read (the original bug) | 24 pass / **1 fail** |
| empty the entries so all indexes render alike | 20 pass / **5 fail** |

**The second matters as much as the first.** Holding the stamp fixed must not make two *different* indexes compare equal — a fix that silenced the check would satisfy the bug report and destroy the check. `a DIFFERENT heap still differs under the same stamp` is the assertion that refuses that.
