## Description

All three fire before or instead of the wipe. Found by the adversarial review run against `main` ahead of the first reformat.

## 1. The ABORT default exited 0, so a refusal announced success

`zeta-first-boot.sh` reads 0 as success and prints *"Install complete. Rebooting in 10s"* — then reboots into the same USB, hits the same gate, **loops forever**. The R9 ledger append happens *after* the gate, so the breaker never counted the attempts and never tripped.

The identical defect was already fixed on the **keypress** branch of the same `if`, with a comment explaining exactly this. The ABORT branch never got it. And it isn't the rare path — the default flips to ABORT when any in-scope disk classifies `foreign-data`, and **a machine being reformatted has an OS on it**. Now exits 10, matching its sibling.

## 2. Nothing checked for UEFI

`common.nix` sets systemd-boot with `canTouchEfiVariables`, so `bootctl install` needs `/sys/firmware/efi/efivars`. The ISO is **hybrid**, so it boots happily in legacy/CSM — and most firmware menus offer `USB HDD` and `UEFI: USB HDD` one keystroke apart.

Without a check the mistake surfaces at bootloader install: **after** wipe, partition, format and the full closure download. Previous OS gone, most of an hour gone, nothing bootable. Added before Step 3 — the cost of catching it is re-entering the boot menu.

## 3. An external NVMe could be chosen as the BOOT disk

The filter excluded only what is *known* to be USB (`$5!="usb"`) — "not proven external" rather than "proven internal". A Thunderbolt/USB4 enclosure reports `TRAN=nvme, RM=0` and passed as internal; `disk_class` sorts NVMe first and `DEFAULT_BOOT` takes the head, so an external SSD could be selected on enumeration order, with every other in-scope disk becoming a whole-disk Longhorn target.

`HOTPLUG` is the discriminator that actually separates a hot-pluggable bay from a soldered controller. **Verified against representative rows:**

```
old filter selects:  nvme0n1, nvme1n1(TB), sda   ← the defect
new filter selects:  nvme0n1, sda
new filter withholds: nvme1n1(TB)
```

**This keeps external drives attached** rather than requiring they be unplugged — not a usable instruction when the installer stick itself lives in one of those hubs. Withheld devices are **named on stdout**, so an operator whose internal bay reports `HOTPLUG=1` sees why the set is short instead of meeting a bare "no internal disks found". Fail-closed either way: an empty set hits the existing `bail` and nothing is wiped.
