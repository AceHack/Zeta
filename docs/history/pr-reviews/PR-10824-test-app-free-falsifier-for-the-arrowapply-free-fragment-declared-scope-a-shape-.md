## Description

Implements the falsifier that PR #10821 specified but deliberately did not build. That PR
established the finding; this one is the enforcement. Aaron: *"we want this in repo somewhere and
make sure it progresses."*

`app` here is Hughes's **`ArrowApply`** operator (*Generalising Monads to Arrows*, SCP 37, 2000) —
not `App<'F,'T>`, not applicative `ap`, not the CCC evaluation morphism.

***

## The design constraint, taken from the sibling's own diagnosis

> **The allowlist *is* the content — the grep's real defect was undeclared scope.**

So `registry/app-free-fragment.json` is the artefact and the test is its executor. Five modules
claim `app`-freedom **with a stated reason each**; four are declared explicitly **outside**; one
in-fragment **unchecked caveat** is recorded. Adding or removing a module is a visible diff.

## Three layers

| | reads | scope | for |
|---|---|---|---|
| **C1 totality** | source text, comments stripped | all `src/**/*.fs` | every `ISR<`-using file must be classified — scope cannot drift in silently |
| **C2 structural** | reflection over `Zeta.Core` | assembly-wide, exemptions by type name (empty) | no member has `app`'s **type shape**, under any name |
| **C3 syntactic** | source text, comments stripped | declared `fragment` only | no `app`/`bind` binding, `.Bind`, `>>=`, or CE builder |

**The structural discriminator.** `ISR` is a type abbreviation and F# **eta-expands**, so the arrow
is flattened into trailing method parameters (measured by reflection on the Release build, not
inferred). Everything before the last `IntrCtx` parameter is supplied at *construction*; everything
after it is the *value channel*. `app` is exactly "an arrow arriving through the value channel":

```text
ISR.(>=>)        params (ISR<A,B>, ISR<B,C>, IntrCtx, A)   arrows at construction  -> OK
IsrLift.ofPure   params (FSharpFunc<a,b>, IntrCtx, a)      value channel is `a`    -> OK
app              params (IntrCtx, ISR<a,b>, a)             arrow IS value channel  -> VIOLATION
```

No name appears in that rule.

## It does not fire outside the declared scope — proved both ways

`Meno.fs` and `SagaBuilder.fs` **do** contain constructs C3 bans (`MenoBuilder.Bind` selects its
continuation arrow from a runtime value; `SagaBuilder` ingests `ISR` via `liftISR`). The test asserts
both that they are declared `outside` **and** that scanning them produces hits — so the exclusion is
a decision, not luck. A lint that flagged legitimate monadic code would be switched off in a week.

## Lane choice — a correction to the brief

The brief asked for a **hygiene lint** in `src/Core.TypeScript/hygiene/`. That directory **does not
block**: since the drift-and-heal flip, `gate (required)` rolls up only `build-and-test`,
`lint (semgrep)`, `cross-verify`, `full-verify`, and `gate.yml` says re-adding a job is *"= adding to
the floor = treaty-amendment consent path"* — a gated class. For an artefact whose whole subject is
*a check that did not run looking like one that passed*, that placement would be self-refuting.

So it is a **test**, and `dotnet test Zeta.sln -c Release` runs inside `build-and-test`. I also did
**not** write a second TypeScript implementation: two checkers over one manifest drift, and the one
that drifts is the one nobody runs. Cost stated plainly — `scoped-lint.ts` will not surface this
locally.

## Register — partial promotion, and I am not claiming the whole sentence

**Now metered:** no ArrowApply **type shape** anywhere in `Zeta.Core` under any name; no monadic
construct in the five declared modules; every `ISR<`-using file is **classified**.

**Still prose:** the link from fragment membership to *predictor accuracy* (this measures the
antecedent, never the consequent); full dataflow; and **"by construction", which remains false** —
`app` is still definable in one line and still compiles. The property is `app`-free **by absence**,
now maintained by a falsifier instead of by nobody having written it.

**Declared unchecked, in the manifest and pinned by a test:**
`SoftScheduler.HandlerK.RunK : InterruptKind -> ISR<'S,'S>` selects an arrow from a runtime value —
the closest thing to `app` inside the fragment. Neither layer flags it and neither *can* by type: it
is indistinguishable from `SoftChip8Scheduler.timerIsr : int -> ISR<Frame,Frame>`, which is
legitimate. Separating them needs dataflow. The original grep never reached this module.

Other stated limits: boxing/`obj`, `containsIsr` depth bound 8, block comments unstripped, C1 keys on
textual `ISR<`, C2 scans `Zeta.Core` only.

## An error of mine, recorded

C1's first run reported two unclassified files (`SchedulerShedHeat.fs`, `SoftThrottle.fs`). Both
mention `ISR<'S,'S>` **only in docstrings**, so both layers now strip comments. My own first
inventory came from an `rg` against a clone whose `main` was stale and missed them — the same lesson
the artefact is about, happening to the person writing it.
