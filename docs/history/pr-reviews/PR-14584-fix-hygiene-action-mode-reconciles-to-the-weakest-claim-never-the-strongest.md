## Description

## What

`Action-Mode` stays a governance key and is now **reconciled to the weakest claim present, never the strongest**, instead of erroring.

## Why the split was wrong

`detectBlockDisagreement` treated `Action-Mode` exactly like `Human-Review`. The rationale written in the module is entirely about the latter, and the two are different in kind:

- **`Human-Review`** is a claim about **the change** — who is accountable for what lands. One change cannot have been both reviewed and not reviewed, so two values are a genuine contradiction and no parser may pick.
- **`Action-Mode`** is a claim about **how one commit was made**. Six commits a human asked for plus one autonomous maintenance fix is not a contradiction — each value is *true of its own commit*, in exactly the sense that makes `Agent:` and `Task:` incidental.

Measured on the live artifacts, not inferred:

| PR | blocks | Action-Mode | other governance fields |
|---|---|---|---|
| #14251 | 7 | 6 x `human-directed` (shadow) + 1 x `autonomous-fail-open` (dejan) | **all agree** |
| #14430 | 3 | 2 x `human-directed` + 1 x `autonomous-fail-closed` | `Human-Review` and `Human-Review-Evidence` **disagree** |

#14251 is a .NET SDK roll closing 10 CVEs, red on `Action-Mode` alone. The `autonomous-fail-open` commit is an agent's later maintenance fix of a check-then-use race the PR itself introduced — the exact shape `.claude/rules/maintenance-commit-on-another-agents-branch-carries-no-block.md` tells a maintainer to sign honestly as itself.

## Why NOT just drop the key

Dropping `Action-Mode` from `GOVERNANCE_KEYS` is the easy change and the wrong one: it would make `human-directed` vs `autonomous-*` resolve by **last-wins**, so a squash whose final commit happened to be the human-directed one would RECORD human direction on autonomous work. That is the escalation shape, reintroduced through the back door. Ordering the vocabulary by claimed human authority and taking the **minimum** inverts the failure mode instead: mixing can lose a claim of human direction and can never acquire one.

```
0  autonomous-fail-open      no human; PROCEEDS past error — widest machine reach, so the floor
1  autonomous-fail-closed    no human; HALTS at error
2  supervised                a human was PRESENT
3  human-directed            a human ASKED for this change
```

## The four properties that make this a reconciliation and not a waiver

Each has a falsifier in `agencysignature-block.test.ts` §ACTION-MODE RECONCILIATION:

1. **Never invents.** The resolved value is always one a constituent commit actually wrote; the rule only discards.
2. **Never strengthens.** Always the minimum rank present — asserted **exhaustively** over all 11 multi-member subsets of the enum, not on a sample.
3. **Never manufactures a claim of presence.** `supervised` and `human-directed` are both claims that a human was involved and neither implies the other, so a set holding only those two **stays loud**. Only the `autonomous-*` values are claims of *absence*, and a claim of absence is the one thing a parser may assert on an author's behalf — the same move as the house rule that a block degrades to `unknown` rather than assert a convenient value.
4. **Never orders unknown vocabulary.** 58 commits on `main` carry the retired `autonomous` / `agent-chosen` spellings; a value outside the enum has no rank and fails closed.

No waiver, no allowlist, no per-PR flag, no "accepted" marker. The scope is derived from the vocabulary itself.

## Nothing else got more permissive

`Human-Review`, `Human-Review-Evidence`, `Credential-Mode` and `Agency-Signature-Version` are untouched. A falsifier iterates `GOVERNANCE_KEYS` minus `Action-Mode` and asserts each still raises `block-disagreement`, so generalising this into a table goes red for whichever key was added. The reconciliation is keyed on the literal string `"Action-Mode"` rather than a lookup table for that reason — a table is an invitation to inherit the exemption without the argument.

## The report cannot leak the stronger value either

`TextVerdict` now carries `reconciliations` and `emitPass` prints the resolved value. The authoritative block still literally contains whatever the **last** commit wrote, so an instrument reading it directly would print `human-directed` for a squash resolved as autonomous — the manufacture re-entering through the report.

## What is GIVEN UP

Real, and not small. A squash mixing human-directed work with one autonomous maintenance commit is now **read as `autonomous-*` for the whole**. Aaron's six human-directed commits in #14251 land under an authoritative reading that says no human directed them, and there is no per-commit attribution left to recover it from — the squash discards the constituents' authority the same way incidental last-wins already discards the other authors' `Agent:` values.

It is accepted for the reason the incidental case was already accepted, one line up in the same file: the alternative is a check that fires on correct work. The two exits available to an author facing that red are force-pushing to re-sign (a separately gated class) or writing a value nobody earned — and a check whose only exits are "rewrite history" or "lie" does not protect the invariant, it prices it. Dejan, holding this exact red: *"I'd rather leave this red and visible than have a green build that records a human direction nobody gave."* That instinct is what is preserved; what changes is that the honest reading is now reachable without a force-push.

**The direction of the loss is the whole justification.** The record may understate human backing. It may never overstate it.
