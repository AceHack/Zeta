## 4. Which strategy the data chose: **the path strategy**

1. **Clean paths exist — 28 of them.** Not a compromise: available today at zero remediation cost,
   and it locks the **full** strict profile in, every rule, no subsetting.
2. **The two security-shaped rules are the wrong first move, on their own evidence.**
   `sonarjs/no-os-command-from-path` = **442**, `sonarjs/publicly-writable-directories` = **342**.
   Enabling them repo-wide either reddens `main` by 784 or demands 784 triage decisions first. Both
   are heuristics with real false-positive rates; the honest claim is **"these 784 sites deserve
   review"**, never *"784 vulnerabilities"* — and triaging a security-shaped finding is
   **@Mateo's call, not a DevOps CI change**. Deferred with the counts attached, not rejected.
3. **The rule strategy is also weaker enforcement** — it says nothing about the 3,922 non-null
   assertions. The path strategy says everything about 102 files and is honest about the rest.
