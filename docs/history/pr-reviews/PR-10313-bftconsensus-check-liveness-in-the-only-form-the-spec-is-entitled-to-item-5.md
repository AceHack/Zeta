## Description

Closes the last open item of the 2026-08-10 audit repair. Item 3 (the network model) was its blocker and landed in #10311.

The audit's §2c defect was liveness **claimed in prose and present nowhere**. The fix isn't to assert a stronger property — it's to state the weakest *true* one together with the assumption it needs, and check both.

## The assumption, stated rather than smuggled

`Fairness` is this spec's stand-in for partial synchrony: every sent honest vote is *eventually* delivered, and a node that can decide eventually does. Deliberately weak — no bound on delay is claimed, only eventual delivery, which is what FLP (1985) requires you to assume to get termination at all. `DeliverByzantine` gets **no** fairness: an adversary is never obliged to send.

## What is checked

`ConditionalTermination` — once the honest nodes have all cast the same value, every honest node commits. **HOLDS**, exhaustive: 4,665,495 distinct states, 0 left on queue, 11m11s against the shipped `BftLiveness.cfg`. The antecedent is stable (honest votes are write-once), so it isn't vacuous by evaporation of its own hypothesis.

## Where a plausible claim nearly shipped

Unconditional termination is **false** here. TLC's first counterexample was the *trivial* one — no honest node ever votes, since `CastVote` carries no fairness. That refutes the property but isn't an interesting reason. Re-running with fairness added to `CastVote` still violated it, and *that* trace is the real mechanism:

```
votes = [otto |-> "merge", vera |-> "reject", riven |-> "merge", lior |-> "none"]
```

A 2-1 honest split. The minority value can be carried by at most its one honest voter plus the `F` Byzantine nodes — 2 senders, never the quorum of 3 — so vera can never decide, and there's no view change to move it. Meanwhile **`merge` does reach quorum at riven, which commits**. So the shape isn't "nobody decides"; it's *some honest nodes decide and one never can* — exactly the partial-decision shape safety permits and liveness forbids.

A first draft of the spec comment asserted "neither value reaches quorum 3". Reasoned rather than measured, and the trace refutes it: the Byzantine node cannot lift *both* values, but it can and does lift one. Corrected against the counterexample before shipping — the same claim-not-matched-to-check class this audit exists to catch.

Liveness runs separately (`BftLiveness.cfg`) because temporal checking costs ~14x the safety pass. Safety re-verified green on the edited spec: 4,665,495 distinct states, 0 left on queue.
