## Description

## What this is

The rank-1 measurement from `docs/research/2026-08-24-the-accurate-meter-is-four-measurements-*.md`: re-run the existing `costume-rho` harness at the **production** model sizes so `N_eff` stops being an instrument with no reading. Zero model spend — 2,800 local ollama calls, ~29 min.

## The headline, stated against the flattering reading

**`N_eff` for the live fleet is not small. It is NOT DEFINED — and the reason matters more than any ρ̂: at these sizes the lanes are not doing the task.**

Base rate is 0.580, so *"always answer killed"* scores **0.580 for free**. The best of twelve agents scores **0.640 (z = +1.77, not significant)**. Eight of twelve are *significantly worse* than that constant (z −2.83 → −6.15). Seven of twelve are at or below chance, and the harness says so itself: `!! 7/12 agents are at or below chance. Condorcet runs BACKWARDS here; the rho question is secondary.`

`N_eff = N/(1+(N−1)ρ)` is only meaningful as an input to `P(majority correct | N_eff, c)`, which assumes `c > 0.5`. Below that the majority is worse than one lane and more lanes make it worse. **So `N_eff` is REFUSED, not estimated.**

### The trap, and the bug I found in my own code

Cross-family ρ̂ came out **negative**: **X = −0.2722 [−0.2992, −0.2395]**. The flattering reading — *"negative correlation, better than independent, the fleet is worth more than three!"* — is wrong. My first `production-panel.ts` printed exactly that (`N_eff = 3.000`). **I fixed the script, not the sentence.**

It is opposing **response bias**, not complementary judgment:

| model | says KILLED on | ĉ range |
|---|---|---|
| `llama3.2:1b` | **73.2%** | 0.615–0.640 |
| `qwen2.5:0.5b` | 42.9% | 0.370–0.595 |
| `gemma2:2b` | **28.9%** | 0.370–0.480 |

One lane mostly says *killed*, another mostly says *survived*. They disagree **by construction on every item regardless of the answer**. Two biased coins pointed opposite ways are not a decorrelated jury.

Production panel (N=3, one lane per family, persona fixed — the shape the live roster has): pooled ρ̂ = **−0.2835**, range [−0.3719, −0.1841], **N_eff refused** on the precondition.

**ρ\*(3) = 0 is the sharpest line here** and it is algebra: `(n−3)/(3(n−1))`. At three lanes the benefit threshold is *exactly zero*, so any positive error correlation loses to one lane.

Robust: `--exclude-fallback` (9/200 dropped, fallback rate 0.46%) moves W by +0.0013, X by −0.0008.

## Two further findings, neither repaired here

**1. The constant-responder guard does not fire where it matters.** It triggers above **95%** modal raw index. Measured: `llama3.2:1b|soraya` 93.5%, `qwen2.5:0.5b|otto` 90.0%, `qwen2.5:0.5b|soraya` 90.0%, `gemma2:2b|soraya` 89.5% — **all four walked through.** It was calibrated on `llama3.1:8b` at a flat 100.0%, an easy case. At 90–93.5% an agent emits just enough variation to look like a judge. The right test is *"does it beat the best constant strategy"* (z against the base rate), which convicts all twelve where the percentage threshold acquits all twelve. Named, not silently applied.

**2. The DST determinism claim is falsified.** `local-llm.ts:22-23` says temperature 0 + fixed seed + pinned model ⇒ deterministic. Same model, same seed, same prompts, two invocations over 200 items: **199/200 identical**, one item flipped `raw='1'` → `raw='0'`. Matters because DST replay and byte-lock both assume the chooser is a function. Recorded as measured, not repaired.

## Method / failure modes, each checked

- **wrong estimand** — avoided by construction: `error = predictedKilled !== truth` vs the recorded `killed` key; agreement/κ never computed.
- **wrong null** — not inherited: `tetrachoric()` conditions on each agent's own marginal error rates; `decorrelation-meter.ts` is not on this path.
- **φ attenuation** — φ shown only as a labelled lower bound (0.4960 vs tetrachoric 0.6069); `validate.ts` re-measures attenuation live at 20.7–65.8%, c-dependent.
- **non-shared item set — the one that bit:** 32/200 items no longer match their recorded `before` line on current `main`. Arm A is pinned to **`89bb4fb9`**, the exact commit that produced the 7b/8b/9b responses, so **only the model sizes changed**.
- **cluster dependence** — cluster bootstrap over 93 strata; HAC n_eff min 151.5 / median 186.4 of 200.
- **estimator falsifier** — `validate.ts` rc=0, ALL CHECKS PASSED (tetrachoric worst |bias| 0.0192; `findRhoStar` under-reports 2.78× at N=8, hence `rhoStarAlgebraic` everywhere).
- **Arm B replicates** the 2026-08-16 panels bit-exact (N=8 → 0.6508 / 0.0961 / 0.5547 vs published 0.651 / 0.096 / 0.555).

## Bottom line

The fleet-value claim is **not "priced low" — it is still unpriced**, and now the reason is specific and fixable: raise model size or lower task difficulty until the lanes clear the base-rate baseline, *then* ρ̂ means something. Power is not the obstacle (SE(D) = 0.0302 at n=200; n≥70 resolves a 0.10 contrast). **Competence is.**
