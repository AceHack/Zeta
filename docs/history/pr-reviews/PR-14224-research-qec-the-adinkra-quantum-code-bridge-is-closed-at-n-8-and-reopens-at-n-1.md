## Description

research(qec): the adinkra->quantum-code bridge is CLOSED at N=8 and reopens at N=16

Aaron asked for a QEC stack under the multi-oracle byte-lock discipline, on the
premise that "we have some adinkra ecc that can run in q#."

PREMISE REFUTED, by grep not inference. There is no adinkra code, no ECC, and no
QEC of any kind in the Q# tree. The eight .qs files declare DBSP operators, a Z-set
ISA, heat-signal labels, a Grover oracle and Pauli wrappers. All five hits for
`adinkra|hamming|error.correct|stabiliz|syndrome|steane|css` are comments -- and
the README's "CSS" is Cascading Style Sheets. src/Core.QSharp.ReferenceOracle/ is a
byte-lock parity oracle for the finite-resolution qubit model, which is what its own
README says it is.

THE BLOCKING FACT IS A THEOREM, NOT AN ACCIDENT. k_q = 2*dim(C) - n, and a self-dual
code has dim = n/2, so k_q = 0 identically -- for every self-dual code at every
length, not just ours. Verified on the committed generator: C = C^perp, so
CSS(C,C) = [[8,0,4]]. REPORT #6 derived the same object as a MAXIMAL commuting family
in the extraspecial group; "the Bell-inert half" and "k=0" are one fact in two
vocabularies. We do not currently have a quantum code at all.

TWO NEW RESULTS, both computed:

1. The N=8 adinkra category is EXHAUSTIVELY CLOSED. Every doubly-even self-orthogonal
   binary code of length 8: dim 1 -> [[8,6,2]], dim 2 -> [[8,4,2]], dim 3 -> [[8,2,2]],
   dim 4 -> [[8,0,4]]. You get d=4 with k=0, or k>0 with d=2. There is no third option
   because there is no fifth row. A negative that permanently retires a direction, found
   in seconds, before anyone wrote a spec.

2. The bridge REOPENS at N=16. RM(1,4) is dim 5, weights {0,8,16} -- doubly-even and
   self-orthogonal, hence a genuine adinkra code at N=16 -- and RM(1,4)^perp = RM(2,4)
   exactly, giving CSS = [[16,6,4]]. Six logical qubits, distance 4, corrects any single
   error, nothing punctured, nothing outside the category. The code is known
   (Calderbank-Shor / Steane 1996); what is ours is that it sits INSIDE the adinkra
   category where [[8,0,4]] and [[7,1,3]] do not.

CORRECTION TO THE PROPOSED ROUTE. Puncturing [8,4,4] does give [7,4,3] -> Steane
[[7,1,3]] at any of the 8 coordinates (Aut(C) = AGL(3,2) is transitive, so the puncture
is canonical). But the punctured code's weights are {0,3,4,7}: odd, so NOT doubly-even
and NOT self-orthogonal. The puncture EXITS the adinkra category. Provenance, not
inheritance.

ROUTING. L1-L4 (code construction, distance, decoder correctness) are finite and
exhaustible -- direct enumeration, NOT Lean, NOT Z3, NOT FsCheck. Property testing here
would SAMPLE a space we can EXHAUST, which is strictly weaker than the trivial loop.
L6 (syndrome-extraction circuit) is the one genuinely quantum layer and the one place Q#
earns its keep -- and it is the BP-16 second instrument, since L1-L4 are one tool wearing
four hats.
