## Description

# Summary

Persist can bind a UEFI keyfile, but live QEMU never asserted the install-time write. Host cannot set guest env, so this bakes `/zeta-bind-uefi-keyfile` onto the installer USB ESP (same pattern as wifi JSON). The guest synthesizes `ZETA_BIND_UEFI_KEYFILE=1` and writes `/mnt/boot/EFI/ZETA/keyfile`. Dedicated `QEMU_UEFI_KEYFILE_PHASE1=1` — not implied by wifi/iSerial. Default wifi/iSerial phase-1 still stays UUID and fails if that marker appears. This slice asserts the **write**, not restore decrypt: non-interactive QEMU skips the passphrase, so the picker never binds the blob. `workflow_dispatch` only; not on `gate (required)`. No TPM / Touch ID claim.

# Spec alignment

USB-IDENTITY-THREAT-MODEL §8 item 3. No OpenSpec capability change. Default persist remains FAT UUID.
