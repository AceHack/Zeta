## Description

## The finding

`helm-validate` was the only gate over `infra/k8s/` — the GitOps tree ArgoCD syncs onto real hardware. **Three of its checks could not go red.** Measured against the pre-change validator, not inferred:

| Mutation | Expected | Actual |
|---|---|---|
| Tab indent + unterminated quote + unclosed flow sequence | red | `PASS: orleans/Application.yaml: valid YAML` |
| Duplicate `destination.namespace` key (API server rejects it) | red | `37 passed, 0 failed`, exit 0 |
| `targetRevision: 999.999.999` on the cockroachdb chart | red | `44 passed, 0 failed`, exit 0 |

Two causes. A ~120-line hand-rolled YAML parser that **never threw** — it skipped any line it did not understand, so the "YAML syntax validation" test could only fail via a code path that did not exist. And a chart check that was literally `index.yaml.includes("name: " + chart)`: a substring match that never looked at the pinned version, and that would also match any chart merely prefixed by ours.

Compounding it: that chart check ran only on push-to-main and a **weekly** Monday cron, never on a pull request. Total run count of this workflow before today: **one**, on 2026-08-10.

## Cadence and the "too heavyweight for a PR" question

Aaron asked why a real cluster is considered too heavyweight for a PR, naming `kind`. Measured from run history rather than assumed: `k8s-argocd-health-test` **already** stands up live kind clusters on pull requests — `live kind ArgoCD health` takes **5–6 min**, the fuller `included` scope 12 min, at **zero billable minutes** (public repo; `/timing` reports `billable.UBUNTU.total_ms = 0`). The belief is inherited, not measured. The real gap was never cluster cost — it was that `infra/k8s/` was outside every lane that mattered.

And the cheap checks are genuinely cheap:

| Check | Wall clock (local, warm) |
|---|---|
| Offline structural validation, 7 apps | 0.4 s |
| Mutation suite, 12 cases, subprocess each | 1.7 s |
| Online exact-version check, 6 charts, ~5 MB | 1.4 s |
| `helm template` of all 6 charts | 5.1 s |
| End-to-end `--render` | **7.6 s** |

Seconds. Job wall clock is dominated by toolchain install, and the `charts` job reuses a **byte-identical cache key** to `k8s-argocd-health-test.yml` so it restores artefacts that workflow's daily run already paid for. There was never a cost case for keeping chart validation off pull requests.

Cron moved weekly -> daily (`29 15 * * *`, an unused minute). The drift it catches is entirely external — a yanked version, a repo that moves or goes dark — since `paths` already covers every in-repo input. Weekly gave ~3.5 days MTTD against a ~1-day drift period; daily gives ~12 h. Sub-daily would re-measure unchanged upstream.

## What changed

- **Validator rewritten** on the `yaml` package (already a direct dependency) with `uniqueKeys: true` — invalid syntax and duplicate keys are now parse errors.
- **Exact version resolution**: resolves the parsed repo index and requires an exact `version` match, reporting published-version count and newest on failure.
- **New `--render` lane**: `helm template` each chart with its real `valuesObject`, then `kubeconform -strict` over the rendered manifests. This is the check that actually exercises the chart against the values we ship.
- **New mutation suite** (`validate-applications.test.ts`, 12 cases) — copies the real tree, breaks one thing, asserts exit 1 **and the specific expected reason**. Exit code alone is not enough; a script can exit 1 for the wrong reason and still look like a working check.
- `parseArgs` `strict: false` -> `strict: true`. A typo'd flag was silently ignored and the run went green having checked nothing the caller asked for.
- A missing `helm`/`kubeconform` under `--render` is a **hard failure**, not a skip.

## Proof it can go red

Stubbing out the validator's non-zero exit (`if (failures.length > 0)` -> `if (false)`) failed **9 of 12** mutation cases immediately; restoring it passed all 12. The suite is load-bearing, not decorative.

The bogus-version mutation now fails in both lanes:

```
FAIL: cockroachdb: chart 'cockroachdb' has no version '999.999.999' in
      https://charts.cockroachdb.com (110 published versions; newest 21.0.4)
FAIL: cockroachdb: helm template failed: Error: chart "cockroachdb"
      version "999.999.999" not found in https://charts.cockroachdb.com repository
```

Both exit 1. Same mutation gave `44 passed, 0 failed` before.

The `control` case runs the **unmutated** copy and asserts exit 0 — without it, a validator that failed unconditionally would satisfy every other case.

## On the pipe trap

The retry in the `charts` job deliberately uses **no pipeline**. A `| tail` there would take the pipeline's status from the last stage and discard the validator's exit code, making the following `||` unreachable — the exact pattern that cost this repo months of silent failure. Retry semantics verified by simulation: persistent failure -> rc=1, transient (fails twice) -> rc=0, success -> rc=0.

## Deliberately left

- **`helm template` + `kubeconform` check structure and schema, not semantics.** Measured: `statefulset.replicas: "not-a-number"` renders `replicas: 0` — schema-valid, silently wrong, and neither tool objects. Only a live cluster notices no pod ever appears. Stated in the workflow header rather than hidden, because that gap is the kind lane's job.
- **`gate.yml`'s `lint (yaml/k8s)` job is still `continue-on-error: true`** and so cannot fail the gate. Its own comment says to flip it once clean for a few rounds; it has been clean since 2026-08-01 and the last four gate runs are green. That is a one-line change, left out here only to avoid colliding with concurrent work in `gate.yml`.
- **`infra/k8s/` still never reaches a live cluster in CI.** `argocd-health-test.ts` hardcodes `full-ai-cluster/k8s/applications` in three places. Wiring the second tree in is a real change to a 1318-line file under an existing work-item, not a drive-by.
- **Parity drift noted, not fixed:** `gate.yml` installs kubeconform via `go install ...@v0.7.0` while `.mise.full.toml` pins `github:yannh/kubeconform = "0.7.0"`. Same version today, two sources of truth.
