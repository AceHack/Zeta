## The call: route (a), and the evidence is executed

#10735's own falsifier was red:

```
[part B] no binding in src/Core/Heat.fs named 'ofKind' consumes isBackpressureKind/isDeniedKind
[part B] 'classifyKind' ... decides pressure from the raw substring probes ... That is the SECOND classifier
```

**The lint was wrong, not `Heat.fs`.** PR **#10804** (Grok, 2026-08-15) had already closed
081M010W1BP by a different — and better — route than the branch assumed:

| | the branch assumed | what #10804 landed |
|---|---|---|
| `HeatSignature.isPressureKind` | deleted | **kept**, derived from the chain |
| the single classifier | `HeatSignal.ofKind` | **`HeatSignature.classifyKind`** (a third binding) |
| chain order | forgetting first | **pressure first** |
| a dual-token kind | *not* pressure | **pressure** |

Both routes on `main` read `classifyKind`, which is the only consumer of the raw probes. There
is one classifier. The lint's suggested repair — `classifyKind kind = kind |> ofKind |> isPressure`
— is circular against that shape and would not typecheck; it is a templated message with the
wrong binding name substituted in.

**The order inversion is the sharper finding, and it is not cosmetic.** Pressure-first is the
*fail-safe* direction: missing a pressure signal is exactly what makes `TemperatureReadout` read
cold for a room under genuine backpressure. #10735's F# assertions
(`Assert.False(HeatSignal.isPressureKind "prune-backpressure")`) encode the pre-#10804 semantics
and would have re-inverted that choice. Verified rather than argued — applying the pre-#10804
order to `classifyKind` and running the suite:

```
Failed Zeta.Tests.DarkHallSchedulerTests.heat pressure classifiers agree on live kinds and on dual-token kinds
Failed!  - Failed: 1, Passed: 53, Skipped: 0, Total: 54
```

Exactly one test fails, and it is the one named for this work-item. So `main`'s guard is live and
the branch's assertions are refuted by it. **No F# is changed here.** The stale lint was loud and
cost a red PR; the stale *test* was quiet and would have cost the behaviour.

## What changed, and why it is not a weakening

The classifier is now **discovered, never named**. A name-pin catches *renames*; the defect is
**arity** — how many bindings decide the bit. The pin produced exactly one signal in its life and
that signal was a false positive against correct code. It is replaced, and paid for with three
checks it could never have made:

| | first draft | this PR |
|---|---|---|
| finds the classifier | by the name `ofKind` | **discovers** the unique probe consumer |
| second classifier via the named probes | caught | caught (B1) |
| second classifier that **inlines** `kindContains` | **missed** | caught (B2) |
| the same, **named like a probe** (`is*Kind`) | **missed** | caught (B2b) |
| the two pressure tables split on **membership** | **missed** | caught (B3) |
| a **miswired** `ofKind` arm (`Denied -> Forgotten`) | **missed** | caught (B3) |
| the classifier renamed | **false positive** | green, new name printed |

B2b was found by *planting the mutant*, not by reading B2: name your inline classifier
`isSomethingKind` and `tokenPredicates` parses it as a legitimate probe, so B2 waves it through.
Same meta-lesson as the scan floor in §1 of the lesson log — second time in the same file.

## Honest register — what this does NOT close

B3 guards **two agreeing tables**, not **one table**. `isPressureKind` (over `KindClass`) and
`isPressure` (over `HeatSignal`) still enumerate the pressure bit separately. Post-#10804 they
cannot disagree on an *input* — both funnel through `classifyKind` — only on *membership*, and B3
is what makes membership drift fail loudly. Collapsing them is filed as **081M07Z23EX**, with the
shape of the fix, rather than done here: it is an F# change to a load-bearing file and this branch
is a lint correction. The lint's own header says so.

Also fixed by omission: #10735 deleted the `hygiene:scan-floor-routes` gate step (an artifact of
its stale base). This branch only **adds** a step.
