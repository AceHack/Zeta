## Summary

Files \`B-0176\` capturing the v0.7 substrate-claim-checker context-aware-suppression architectural intent as durable backlog substrate.

**Empirically motivated**: v0.6 retroactive eval (PR #1329) found 7 drift items across 65 session shards, mostly from a recurring false-positive class. Same-day 0603Z drift exploration confirmed 4 sub-classes of false-positives.

## The 4 false-positive sub-classes

| Class | Example | Why intentionally absent |
|---|---|---|
| Hypothetical | *\"still HYPOTHETICAL — not currently in the repo\"* | Prose explicitly marks path as not-real |
| Contrastive | *\"as `docs/research/` ... rather than `docs/skills/`\"* | Rhetorical contrast |
| Partial-path | *\"`docs/DECISIONS/...router-coherence-claims-vs-complexity.md`\"* | Ellipsis indicates pattern, not literal path |
| Branch-name | *\"PR opened on `research/` branch\"* | Git-branch-prefix, not directory |

## What v0.7 builds

Context-aware suppression atop v0.6's severity-tier model:

1. ±N-line context scan for HYPOTHETICAL markers / \"not currently\" / \"would be ... if added\" / etc.
2. Contrastive-context detection (\"rather than\" / \"NOT placed in\" / \"instead of\")
3. Partial-path detection (paths containing literal `...`)
4. Branch-name detection (`branch:` keyword OR known-branch-prefix list)

Output: drift findings retain their position; false-positives marked \`severity=warning-suppressed-context-aware\` or omitted entirely.

## Composes with

- **B-0170** (parent substrate-claim-checker tool)
- **B-0175** (substrate-retrieval-index — similar architecture pattern: in-flight context analysis closing gaps)
- **0603Z tick shard** (empirical drift sweep that motivated this row)

## Why this matters

False positives erode trust in the tool. If reviewers see noise (hypothetical paths flagged as drift), they learn to ignore drift findings — the tool's signal degrades. Context-aware suppression keeps the signal-to-noise ratio high enough that drift findings remain actionable.
