## Description

Four defects in the branch-sweep triage, all measured 2026-09-09, all the same family: a gate that answered a **proxy** question and read as if it had answered the real one.

## 1 — It never asked whether a PR was open

The gate was content-only, so a live PR's head ref classified `SAFE`. At measurement time the SAFE set held PR #17184's and PR #17187's heads while both were **open**; `--prune` would have deleted them. Both have since merged, so this was a near-miss and not damage — nothing stopped it recurring.

`OPEN_PR` is now the first bucket and it is terminal. An open PR's **base** is protected too: deleting it breaks the stacked PR just as surely as deleting its head.

PR state is read over **REST** — `gh api --paginate "repos/{owner}/{repo}/pulls?state=open&per_page=100"`, one call for the repository — never over `gh pr list`. GraphQL is the contested budget here. **A failed query is `unknown`, not "no open PRs"**: it refuses the whole run.

## 2 — Comparing basenames is not comparing content

`claim/task-compiled-capture-five-publication-20260907` read `SAFE` while carrying 2,566 files and 23,286 insertions absent from `main`, because its generated custody logs collided on basename with unrelated files.

Reproduced today against the live branch:

| gate | verdict |
| --- | --- |
| old (basename) | 0 absent across 2,566 files → **SAFE** |
| new (blob OID) | **UNLANDED**, all 2,566 named |

Containment is now decided on the git **blob OID** — a hash of the exact bytes — so two files match only when they are the same file. Same bytes at a different path still counts: a landed file that was later moved has not become unlanded.

## 3 — There was no containment predicate

The 2026-09-09 sweep worked around its absence by hand-running four positive tests, one per row. **Ancestry cannot substitute**: a squash merge writes a new commit onto `main` whose parent is `main`, so branch commits never become ancestors of it. Measured today: `git branch -r --merged origin/main` reports **2 of 131**.

Two sound proofs replace it, either sufficient:

- **patch-id equivalence** (`git cherry`) — compares patch ids, so it sees cherry-picks and rebases. Sound but incomplete for multi-commit squashes; the incompleteness costs a false `UNLANDED`, which errs toward keeping.
- **blob presence** — survives a squash, because a squash keeps the bytes even though it destroys the commits.

A probe that **errors** yields `UNCHECKABLE`, never `SAFE`. The inherited code swallowed a failed `git diff` with `allowFail` and returned `""` — an errored gate producing an empty absent-list, which reads exactly like a branch with nothing absent.

## 4 — Preservation ran and deletion did not

The 2026-09-03 sweep tagged its branches and never deleted them. Two halves, one ran, success reported — a check that did not run looking like one that passed.

Preserve and delete are now **one transaction per branch**: tag → **verify the tag on the remote** → delete, with an explicit furthest-step-reached record. Tagged-but-not-deleted is a `PARTIAL`, partials print under their own heading, and the run **exits 3**. "Tagged" is no longer expressible as success.

`--audit-archive-tags` reports every archive tag whose branch still exists — the residue that sweep left — and refuses to report a verdict when the remote returns zero tags, because an empty lookup is broken, not clean.

**Status of that residue, measured 2026-09-09:** 49 tags under `archive/2026-09-03-branch-sweep/`, and across all **464** archive tags on `origin`, **zero** name a branch that still exists. Some later pass reconciled it. What this change removes is that *nothing detected it*.
