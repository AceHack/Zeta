## Description

GitHub credentials wired into the agent harness the same way the OpenAI token is (Aaron 2026-07-08): a second implementation of the hexagonal `AuthProvider` port — same `login-runner`, same per-provider `TokenStore` (`~/.config/zeta/auth/github.json`).

RFC 8628 device flow with shapes **confirmed live today** — this exact flow minted the token that pushed #9549–#9551. Key GitHub quirk encoded: 200 for pending AND success, body is the discriminator (`authorization_pending`/`slow_down` = keep polling).

Honest asymmetries: classic OAuth-app tokens (gh CLI id, default) never rotate → `refresh()` reports re-login instead of pretending; GitHub-App ids with expiration refresh normally; browser/PKCE degrades cleanly (GitHub has no secretless PKCE exchange — no client_secret enters the harness). `makeGithubProvider(clientId, scope)` for least-privilege app ids later.

Verified with fake transports under node (tsc --strict, 15 assertions). Please run `bun test src/Core.TypeScript/model-backend/github-auth.test.ts` (no bun on the cowork cell).
