## Description

## The bug

`appNameFor` did `relPath.split("/")`. On Windows `relative()` returns backslashes, so the split produced **one** part, the `applications`/`bootstrap` anchor was never found, and app identity degenerated to `<wholepath>/<wholepath>`:

```
full-ai-cluster\k8s\applications\cockroachdb\Application.yaml/full-ai-cluster\k8s\applications\cockroachdb\Application.yaml
```

That matches no ledger key, so **every long-acknowledged app** — `cockroachdb`, `vault`, `nats`, `redis`, `platform` — read as a fresh false-redundancy violation. The suite failed 5 tests on Windows for a reason with nothing to do with the cluster: **the ledger was correct, the parser was not.**

It also made the auditor unusable as a local check. I hit this while verifying the kubevirt ledger entry in #11173 and had to ship that fix on CI evidence alone, because the local run couldn't distinguish a real finding from this noise.

## Two-layer fix

- `loadManifests` POSIX-normalises `rel` once at the source, so **both** `app` and `path` are platform-independent. `path` matters too — `acknowledgedRootAppDuplicates` keys are built from source paths.
- `appNameFor` splits on either separator. It's exported and called directly by tests and other callers, so it shouldn't depend on its caller having normalised.

## Regression test

Nothing asserted that a Windows-shaped path yields the same identity as its POSIX twin — which is why this survived. Added backslash cases plus an explicit *"both spellings agree"* assertion.

Same defect shape as the `"/tmp"` literal in `harness.test.ts` (#11213): **an assertion written in one platform's spelling cannot catch that platform's absence.**
