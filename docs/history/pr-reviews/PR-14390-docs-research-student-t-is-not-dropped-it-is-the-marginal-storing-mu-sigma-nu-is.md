## Description

# Summary

Aaron asked directly: *"did we decide with the RGB(A)/CMYK stuff that if we want to encode into GPU texture we don't need Student — it's actually a degrade? can you do a writeup?"* — with a live consumer mid-rewrite of the BNN key predictor who needs to know what to preserve.

**The answer is yes, but it needs one distinction or it is read backwards.** The Student-t *distribution* is not dropped: the Normal-Gamma marginal on the weight **is** a Student-t with `ν = 2α`. What degrades is storing `(μ, σ, ν)` as the texel parameterisation. Same distribution, worse carrier — `ngStudentT` is a 4→3 projection with **no inverse** (three different `λ` reproduce one identical t triple).

This doc is the **decision + the API bridge**, cross-referencing the existing codec doc rather than copying its measurements.

# Notes

**Three things here are new work, not restatement:**

**1. A correction to the sibling doc.** Its §3.1 says *"under **any** projection rule, blend-three-parents stops meaning one thing."* **That is false** — measured, four of eight ν-closure rules (`min`, `max`, `sum`, `sum−1`) are perfectly associative, because `(μ,v)` never depended on the ν-rule. The real defect is **stronger**: against a 2,000,001-point grid of the true product of three t densities, *every* rule is wrong by the same **6.2e-2** in the mean and **10.6%** in the variance, and the **best possible** Student-t misfits by **6.52% of peak**. Associativity is a symptom you can paper over by picking a nicer ν-rule; **non-closure has no rule**. The conclusion survives and is better supported; the sentence as written hands a reviewer a real objection to a correct decision.

**2. The GPU claim, promoted from `read` to `metered`.** Nobody in this thread had a GPU; Aaron pointed out it is testable here. Executed via WebGPU under headless Chrome 151 on Apple `metal-3`:

| path | vs CPU f32 fold |
|---|---|
| compute shader `acc += inp[i]` | **bit-exact**, max abs diff `0.000e+0` |
| **fixed-function additive blend** → `rgba32float` | **bit-exact**, max abs diff `0.000e+0` |

Fusing N Bayesian posteriors took **zero shader instructions** — it ran in the blend unit. The same blend on `(μ,σ,ν)` gives `μ=1.5` against a true `−0.8236` (**off by 2.324**), and a correct t fusion needs a custom kernel with 6 divides and a `sqrt` to compute the answer that is 10.6% wrong anyway. Format verified not silently downgraded (`70000` survived; binary16 would have clamped it to `Infinity` and faked the τ-overflow finding).

**3. The API bridge — the section the codec doc lacks entirely** (zero mentions of `createStudentTState`, `updateStudentT`, `StudentTState`, `bnn-key-predictor`, `ngStudentT`, `obsVariance`).

**The most consequential finding for the person mid-rewrite:** `createStudentTState`'s four arguments do **not** map onto NG4's four parameters.

> `StudentTState.nu` is the tail index of the observation-noise **likelihood** — caller-supplied, and `updateStudentT` never moves it. `ngStudentT(p).nu = 2α` is the dof of the **posterior marginal**, and it grows with the evidence count. **Same letter, different object.**

`obsVariance` likewise has no NG4 home, and NG4's `λ` has no source — so the `4 → 4` arity match is a *coincidence*, not a correspondence, and is called out as the live instance of `numerology-vs-number-theory`. **Routing `StudentTState.nu` into `α` type-checks, runs, and silently asserts a posterior tail that no evidence counted** — the likeliest bug in this rewrite.

Also measured: the predictor reads `posterior.mu` **and nothing else** (line 121), so the consumed surface is one scalar; the adapter round-trips `mu` exactly, `sigma2` to one ulp (`6.939e-18`), and **loses `factorMu`/`factorSigma2`** — reported rather than faked.

**Registers.** Everything stays `toy` except §3, which earned `metered`. The synthetic-posterior weak point (`081M0QMDMC7087G0R000W6QRCV`) is named rather than glossed — this is explicitly **not settled work**. No performance number is claimed anywhere; §3 measures correctness and hardware-path availability only, on one adapter and one browser (`float32-blendable` is an optional WebGPU feature).

**Follow-ups:** `081M0QMDMD3087G0R000ZTVT1Q` (GPU kernel for fold + crossover + cone-guarded mutation) is now better grounded — its fold row is measured. The §7 correction is flagged in this doc rather than edited into the sibling, so it carries its own evidence.
