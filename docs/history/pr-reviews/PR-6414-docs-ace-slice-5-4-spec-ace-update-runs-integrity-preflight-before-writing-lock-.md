## Description

Fix-forward on the slice-5.4 spec (#6412, merged) per Codex P2 review.

**Finding:** `ace update` was specced as solve→resolve→buildLockfile→write with "no preflight" — but `resolve()` can succeed for a graph containing an unsafe file path or a store-key collision (those checks live in the install **preflight**, before lock writing). So `ace update` could write a lock for a graph that a later `ace install` would refuse.

**Fix:** `ace update` now runs the same integrity preflight (`content_hash` + `validatePackagePaths` + store-collision over `res.order`) before writing the lock, skipping only the extract (`installPackage`) step. Added an error-table row (preflight failure → hard refusal, no lock written) and updated the data-flow line.

Docs-only; markdownlint clean; canary 67.
