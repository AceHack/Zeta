## Description

## Owning an error in #10904

#10904 renamed `genomeToAdinkraByte` → `genomeToParityByte` because its bytes are the single-parity-check **[8,7,2]**, not the doubly-even self-dual **[8,4,4]**. **That rename stands and is unchanged here.**

But in writing it I over-generalised a scoped fact. My no-consumer check covered `genomeToAdinkraByte` *only*; I then wrote **"No production path uses it yet"** about `[8,4,4]` itself in `docs/ZETA-ARCHITECTURE-UNIFIED.md`. That is **false**. Aaron flagged it: *"we have a few places Adinkra's ecc are used for ecc with real consumers already... we use it in our udp transport protocol or did... we also use it to handle missed observations over time."*

## Verified consumers (looked, did not infer)

| surface | how it uses [8,4,4] |
|---|---|
| `src/Core/AdinkraCode.fs` | the pinned generator: `encode` / `syndrome` / `isCodeword` / `correct` |
| `src/Core/PrivacyPreservingIdentity.fs:83,84,132` | key roots must be codewords |
| `src/Bayesian/YinYangCell.fs:153` | cell-state validity gate |
| `src/Core/BitAdinkra.fs:41,50` | bit-level encode |

| `src/Bayesian/BusDelayTick.fs:145,146` | codeword-indexed reseed |

| `src/Core.TypeScript/discovery/udp-lossy-transport.ts` | **erasure code on the wire** — 4 data + 4 parity packets per block, `ADINKRA_G`/`ADINKRA_H`, `recoverAdinkraBlock` |
| `src/Core.Lean4/ImaginaryStack/ErasureDistance.lean` | distance ⇒ erasure correction — the missed-observations-over-time property |

Both of Aaron's named uses check out concretely: the UDP transport is `udp-lossy-transport.ts`, and the missed-observation/erasure property is `ErasureDistance.lean` plus that transport's block recovery. His hedge — *"maybe just this spot or language is not doing it yet"* — is exactly right: this was a local naming gap against a real, live capability.

## Why this makes the rename more right, not less

A function named "adinkra" that emits a **distance-2, detection-only, non-self-dual** byte is a live hazard *precisely because* paths exist that rely on the genuine guarantees. One name, two referents, with real users of the true referent — that is the failure the rename prevents.

## Changes (documentation only — no code, no test values touched)

- `ZETA-ARCHITECTURE-UNIFIED.md`: the false "no production path uses it yet" is replaced with the verified consumer list, keeping the warning that the parity byte must not be wired into a path expecting [8,4,4] guarantees.

- `genomeToParityByte` docstring: routes a reader who wants a real adinkra code to `AdinkraCode.fs` and `udp-lossy-transport.ts` **first**, and re-scopes "no consumer" so it can only read as a statement about this function.
