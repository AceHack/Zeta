## Description

The enterprise forbids the **Actions identity** from creating pull requests — reproduced against the repo API today:

```
409: The enterprise does not allow GitHub Actions to create or approve pull requests
```

It can't be lifted from the repo or the org; that setting sits at the enterprise tier. So `pr-archive-on-merge` has been pushing its archive branch, failing `gh pr create`, catching the policy denial, and **exiting green** with a notice deferring to *"the next agent pass"* — which, for 1,229 consecutive merges, never came.

## The restriction is on the identity, not the operation

A fine-grained PAT authenticates as its owner and isn't subject to that policy. One step now runs as `ZETA_PR_ARCHIVE_TOKEN`, the archive PR opens, and branches stop orphaning.

## What it cost before

Four accumulations of the same backlog — ~4,049 drained in #6879, 1,132 in #8043, 16 in #9059, and **1,229 now in #10346**: ~3.5 MB of PR-review substrate stranded off main, which the repo calls its most valuable data and which is rate-limited (older PRs effectively unregenerable).

Every prior round drained the symptom. **This is the first change to the generator** — what the 2026-06-30 orphan-triage retro asked for in as many words.

## Scope, deliberately minimal

`ZETA_PR_ARCHIVE_TOKEN` carries `pull_requests: write` + `metadata: read` and nothing else:

- **not `contents: write`** — the branch push is authenticated by `actions/checkout`'s persisted `GITHUB_TOKEN` credentials and already works
- **not `actions`** — that authority belongs to `ZETA_SOCIETY_DISPATCH_TOKEN`

Two secrets, two authorities: neither can do the other's job if either leaks. `pull_requests` also covers the archival tool's own reads against `/pulls/N/comments` and the GraphQL `reviewThreads`, per this workflow's existing comment.

The other two `GH_TOKEN` sites are untouched and still `GITHUB_TOKEN`.

## Fallback

```yaml
GH_TOKEN: ${{ secrets.ZETA_PR_ARCHIVE_TOKEN || secrets.GITHUB_TOKEN }}
```

If the secret is ever removed, the expression yields `GITHUB_TOKEN`, `gh pr create` fails exactly as it does today, and `is-pr-create-policy-denial.ts` catches it and exits green with the branch pushed. **Losing the secret degrades to the old behaviour rather than turning the job red.**
