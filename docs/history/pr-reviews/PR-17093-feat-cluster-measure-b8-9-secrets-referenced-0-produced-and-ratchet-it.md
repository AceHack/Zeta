## Description

feat(cluster): measure B8 — 9 Secrets referenced, 0 produced, and ratchet it

B8 said "twelve Secrets are named by automated: true Applications and nothing on
metal creates any of them ... against 22 references". The finding is real. Its
arithmetic had aged: measured 2026-09-08 the catalogue references NINE distinct
Secrets across TEN sites, with ZERO producer files. That is the same staleness
class as the register reading all-24-OPEN while three had landed -- a number in a
roster ages, a number a check recomputes does not.

Adds `secret-reference-audit.ts`, which enumerates what the metal catalogue
CONSUMES (existingSecret / secretName / secretKeyRef / secretRef / imagePullSecrets)
against what it CREATES (Secret / SealedSecret / ExternalSecret /
ClusterSecretStore), and reports the difference.

WHY MEASURE BEFORE FIXING. A referenced-but-absent Secret does not fail loudly:
the pod waits, ArgoCD reports Progressing, and the wave stalls. That is exactly
the headscale/orleans shape found earlier today -- an Application that never
becomes Healthy and burns the whole health timeout reporting a symptom rather
than a cause. Turning the finding into a recomputed number is what makes the
eventual fix verifiable rather than asserted.

THE SHAPE IS SHARPER THAN "WE LACK A MECHANISM". external-secrets and
sealed-secrets are DEPLOYED as Applications, and there is not one ExternalSecret
or SealedSecret anywhere. The machinery is running and nothing feeds it.

The split is actionable rather than a flat list: 3 of the 9 have no producer on
ANY path (kubevirt-operator-certs, temporal-default-store,
temporal-visibility-store); the other 6 have a dev-path producer, so metal simply
does not run one. Those are different jobs -- the first three need a producer
authored, the other six need the dev pattern carried to metal.

RATCHET, NOT A BLESSING. The known unproduced set is recorded in the test so the
check ships TODAY rather than being red on arrival and disabled. A NEW unproduced
reference fails it; removing a name from the list is how the gap closes.

Mutation-checked in both directions, which matters because half of this check's
job is to not be vacuous:

  * adding a new unproduced reference -> fails the ratchet and the count (2 pass
    / 2 fail);
  * making the reference regex match nothing -> fails the "finds references at
    all" guard and the count (2 pass / 2 fail). Without that guard a broken
    regex would report a perfect zero-gap catalogue, which is the exact failure
    mode this repo names as its worst.

Restored: 4 pass / 0 fail. tsc 0 errors.

Also corrects the B8 row in FIRST-METAL-BRINGUP-FINDINGS to carry the measured
numbers, the three-vs-six split, and a pointer to the check that now recomputes
them.

NOT FIXED: nothing here creates a Secret. This is the measurement and the guard.
