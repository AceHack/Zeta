## Description

fix(forge-host): refresh-worldview's queriedAt timestamped the wrong clock

CLAUDE.md §2 makes `refresh-worldview.ts` the fleet's standing wake-time
orientation step. It computes `behind` from `rev-list --count origin/main...HEAD`
where `origin/main` is the LOCAL remote-tracking ref -- as fresh as whenever
someone last happened to fetch -- and then stamps the snapshot
`queriedAt: new Date().toISOString()`.

That is the wrong clock. `queriedAt` measures when the TOOL RAN, not when the REF
WAS REFRESHED, so a snapshot dated to the second can report `behind: 0` off a
week-old ref. The freshness field does not merely omit the staleness -- it
manufactures the appearance of currency, which is a check that did not run
looking like one that passed.

FIRED TWICE TODAY, both times against the shared checkout, which was 754 commits
behind origin/main. One agent returned three confident "corrections" about
AgencySignature enum values that exist on main; another found a research doc
absent from the tree it was auditing. Neither had any signal that the tree was
stale, because the canonical orientation tool does not carry one. CLAUDE.md
already states the fetch-first requirement in PROSE for the heartbeat lane -- the
discipline is known and simply was not in the tool.

THE FIX is additive and changes no existing field:

- `BranchState` gains `trackingRefFetchedAt` and `trackingRefAgeSeconds`, read
  from FETCH_HEAD's mtime, which git rewrites on every fetch.
- Both are `null` on every failure path, and `null` means UNKNOWN, never "fresh".
  Substituting 0 would reintroduce exactly the false-currency bug the function
  exists to expose, so the code says so at the site.
- The summary line ALWAYS emits a freshness note, because an omitted note reads
  as "fine" -- that is the failure mode. Three states: fetched Xm ago; STALE past
  900s with `behind` marked unverified; or UNKNOWN (never fetched here) with
  `behind` marked unverified.

Deliberately NOT done: making the tool fetch. That would add a network call to
every wake and change behaviour under a name change alone; surfacing the age lets
the reader decide, and a consumer that cannot establish the age now knows to
treat `behind` as unverified rather than as zero.

Verified by running it: summary now reads "... 1 dirty file, ref fetched 3m ago",
and `branchState` carries `trackingRefFetchedAt` + `trackingRefAgeSeconds: 198`.

Found by the verdict-vs-evidence audit applying the Xbox 360 class-2 finding
(a component returning a verdict the consumer cannot recompute) to our own code.
Here the reporting component is your own past self: a verdict ("you are current")
whose one falsifying input was never gathered.
