## OCI syntax

`repoURL: code.forgejo.org/forgejo-helm` — **scheme-less on purpose**. ArgoCD's declarative Helm source takes the registry host+path bare and supplies `oci://` itself: *"note: the `oci://` syntax is not included"* (<https://argo-cd.readthedocs.io/en/stable/user-guide/helm/>). This matches the three OCI Applications already in the tree (`arc-controller`, `arc-runner-set`, `hindsight`) and both in-repo classifiers (`classifyRepoUrl` in the audit, `isOciRepo` in `validate-applications.ts`). The equivalent helm CLI coordinate, `oci://code.forgejo.org/forgejo-helm/forgejo`, is recorded in the comment.

## The THIRD register keyed to the old pin — measured, not re-keyed

`full-ai-cluster/k8s/storage-profiles.json` carried `acknowledgedUnmeasuredRequests: ["forgejo@9.0.6", "oz@1.4.5"]`. PR #13348 sized every Application by `helm pull`ing its pin, and forgejo could not be pulled **because the pin never existed**. That key carries the pin so a bump invalidates it — and this bump did. **The register worked.**

Re-keying to `forgejo@17.1.5` would have preserved a *"we cannot measure this"* claim that had stopped being true — an acknowledgement outliving its own defect, which is the failure this apparatus exists to catch. So it is **measured**:

`helm template` at 17.1.5 with this Application's own `valuesObject` — one Deployment, `replicas: 1`; the sole app container declares **no** requests; three init containers (`init-directories`, `init-app-ini`, `configure-gitea`) each declare `100m` / `128Mi`. Init containers run **sequentially**, so the pod's effective request is `max(highest init request, sum of app-container requests)` = **100m / 128Mi** — *not* the `300m / 384Mi` a naive sum over all four containers gives (Kubernetes, "Init Containers" → resource sharing within containers). The chart's `forgejo-test-connection` Pod is a `helm.sh/hook: test` ArgoCD never applies on sync and declares no requests either way, so it is 0 under either convention. Both numbers and the rule are in the row's `evidence` — no convention a reader has to guess at.

Totals move by exactly that, at both rungs, in the catalogue prose and the tests:

| cohort | before | after |
| --- | --- | --- |
| dev, applied | 1806m / 6079Mi | **1906m / 6207Mi** (budget 2500m / 9216Mi — still green) |
| metal, applied | 4131m / 11299Mi | **4231m / 11427Mi** |
| metal, all 45 | 9756m / 23400Mi | **9856m / 23528Mi** |

`oz@1.4.5` untouched — still fictional, still `081M0JVD5YG087G0R002QDFR9H`'s.

**The tests follow the fact rather than being relaxed to fit it.** The unmeasured-set test drops to `["oz"]`; the moved-pin test re-keys onto `oz`, which is still unmeasured, so it goes on testing the same property. Two are **added**: forgejo left the acknowledged set *by being measured* (asserting the 100m/128Mi and the absent key), and **the other direction of the register** — an acknowledgement for an app that *is* measured is reported stale. That second one is the branch forgejo just took, and nothing covered it before.

One hardening fell out: `pinnedChartVersion` probes at most three lines either side of `chart:` and returns `""` rather than failing, so a comment wedged between `chart:` and `targetRevision:` would silently unpin an app from its acknowledgement key. The manifest now keeps those three lines adjacent, and says why.
