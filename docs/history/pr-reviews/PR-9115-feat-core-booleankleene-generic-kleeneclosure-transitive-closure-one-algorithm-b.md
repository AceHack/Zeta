  When the pivot has a non-trivial `Star`, skipping `i = p` leaves the pivot row unscaled, so closures for paths that start at the pivot are wrong. With the existing `TropicalSemiring.Kleene`, edges `A -&gt; A` with `-1` and `A -&gt; C` with `5` make `dpp` the `-∞` marker, but `A -&gt; C` remains finite because the row update is skipped; similarly a language/regex instance would return `b` instead of `a* b` for `A -&gt; A = a, A -&gt; C = b`. Lehmann matrix star needs to account for the pivot row as well, or explicitly reject divergent/non-trivial pivot stars before advertising this as generic.
