## Description

`references/prior-art/` mirrors third-party projects Zeta READS. Calling
them "upstream" asserts a DERIVATION relationship — that Zeta's tree
descends from theirs. It does not, and it must not be implied: per
`.claude/rules/cleanroom-two-team-separation.md`, whoever LOOKED may not
BUILD, and a spec crossing the wall carries requirements never
expression. The naming was quietly asserting the exact lineage that rule
exists to prevent. The register is "reference source" / "prior art".

Two senses of "upstream" live in this repo and only one is wrong:

  [A] third-party source mirrored for reference  -> renamed here.
  [B] contributing patches BACK to a real dependency, and ordinary
      technical usage (upstream package / installer / dataflow) -> LEFT
      ALONE. GOVERNANCE.md §23 and §25 are correct as written.

10,791 tracked files contain the string, so nothing here was a blanket
replace. Every occurrence was read in its sentence and classified before
being touched. 46 removed across 11 files; 17 remain in those files
deliberately (5 are new "not upstream, and here is why" notes; 12 are
sense-[B]).

## P0 check requested first: CLEAN, but a real doc bug was behind it

`references/README.md:28` documented the sync-managed tree as
`references/upstreams/`. That directory does not exist. Evidence on
6cec0e272:

  (a) the script writes `$REPO_ROOT/$rel_path` from the manifest, and
      all 103 `.path` values are under `references/prior-art/`
      (`jq -r '.[].path' | sed 's|/[^/]*$||' | sort | uniq -c` -> 103).
      `UPSTREAMS_DIR` (the mkdir + --prune root) is likewise
      `references/prior-art`.
  (b) git check-ignore -v:
        references/prior-art/sqlite/src/main.c
          -> references/prior-art/.gitignore:1:*
        references/upstreams/sqlite/src/main.c
          -> NOT IGNORED
      Two independent rules cover the real path: `.gitignore:66`
      (`references/prior-art/*` + sentinel carve-outs) and a nested
      `references/prior-art/.gitignore` of `*`.
  (c) So the script never writes anywhere `.gitignore` misses. No live
      defect — mirrored source is not committable today.

The stale string was a bug waiting for someone to believe it: a
contributor who followed that README and created `references/upstreams/`
would have had gigabytes of third-party source fully committable, which
is precisely what must not happen. Fixed by correcting the path rather
than by adding a speculative ignore for a directory nothing writes to.

`references/reference-sources.json` needs no change: zero occurrences of
"upstream" anywhere in it, and its keys are `name/url/branch/path/
categories/notes` — no `upstream_url`-style field to break. Its only
consumer is the sync script.

## Follow-up for the TypeScript port (not fixed here)

The script trusts the manifest's `.path` verbatim. A row with
`path: "src/foo"` would write outside the ignored tree and be
committable. All 103 rows are fine today, so this is latent, not live —
but the port should validate that every resolved destination stays under
`references/prior-art/` and refuse otherwise. That turns the P0 answer
from "true by inspection" into "true by construction".
