## Description

Fixes the apt-stall regression filed as `081M096T3AN087G0R0008JZQ7B` (PR #11744). Aaron authorised the fix.

## The gap

The hang guard added 2026-08-14 bounds a stalled mirror with `timeout --signal=TERM --kill-after=30s`, which correctly converts a stall into a **retryable** non-zero exit. What it misses is what the kill does to **dpkg**: apt-get is terminated **mid-dpkg**, leaving the package database interrupted, so attempts 2 and 3 fail **instantly** with `rc=100`:

```
E: dpkg was interrupted, you must manually run 'sudo dpkg --configure -a'
```

They never reach the mirror at all. **One stall costs all three attempts** — the retry loop is decorative on precisely the failure it was written for.

## The fix

One line plus its reason: `$SUDO dpkg --configure -a || true` before the retry sleep. That is verbatim what apt's own error message instructs, it is a **no-op on a clean database** so it is safe on the ordinary-error paths, and it lives in `linux.sh` so laptop / runner / devcontainer recover identically (GOVERNANCE §24 three-way parity).

## Evidence

Measured 2026-08-18 from a **surviving** log on PR #11746 — the stall normally *hangs* rather than failing, so its log is usually lost with the killed job, which is why this went unseen for so long. Across six recent cancelled `gate` runs, **9 of 9** cancelled jobs died in this same step (`Install toolchain via three-way-parity script (GOVERNANCE §24)`), with durations matching their `timeout-minutes` ceilings exactly.

## Deliberately not changed

- **`timeout-minutes` ceilings** — raising them converts a hang into a slower hang.
- **`ZETA_APT_TIMEOUT_SECONDS`** — the 600s wall-clock bound is doing its job; the bug is what happens *after* it fires.
- **The mirror itself** — a separate call, not proposed here.

## Verification

`bash -n tools/setup/linux.sh` → OK. `shellcheck -S warning` → clean. The real proof is behavioural and arrives with the next stall: attempts 2 and 3 should now reach the mirror instead of dying on `rc=100`.
