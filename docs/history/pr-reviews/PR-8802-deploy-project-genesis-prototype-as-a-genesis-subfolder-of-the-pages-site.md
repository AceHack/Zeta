## Description

## What

Stands up the interactive **"Project Genesis"** React prototype as a built Vite static site, served as a **subfolder of the existing Jekyll GitHub Pages deployment** rather than replacing it.

**Live URL (once merged to `main`):** https://lucent-financial-group.github.io/Zeta/genesis/

## Why this shape (important)

The task this came from literally asked for a new Pages-deploy workflow + switching Pages Source to "GitHub Actions". That would have **destroyed the existing Pages site** — `_config.yml` records it as "our only real DORA signal and my daughter edited it a lot", and a repo gets only **one** Pages deployment. So instead this rides on top of the existing classic-Jekyll deploy (root `index.html` + `demo/`) with **zero changes to the Pages source or workflow**. The maintainer chose this subfolder approach.

Jekyll serves the built `genesis/index.html` + `genesis/assets/*` verbatim (static files with no YAML front matter are copied as-is). The Vite build emits with `base=/Zeta/genesis/`, so assets resolve under the project-Pages path. It goes live automatically when this lands on `main` (Jekyll deploys from `main`).

## Contents

- `genesis/` — built static site (served).
- `genesis/_src/` — reproducible Vite source. The leading underscore makes Jekyll skip it, so it's committed for auditability but never served. **`Genesis.jsx` is byte-identical to the original upload — unchanged.** Only the wrapper (`main.jsx`, `index.css`, `index.html`, `vite.config.js`) is project config.
- `.gitattributes` — mark `genesis/assets/**` `linguist-generated` + `-diff` (keeps 250KB minified JS out of review walls and out of the repo's language stats).
- `.github/codeql/codeql-config.yml`, `.semgrepignore` — exclude the minified bundle / prototype from scanners, mirroring the existing `bench/` and `references/prior-art/` exclusions.
