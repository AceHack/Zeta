## Description

fix(audit): dep-currency saw one flake of two — discover them, don't list them

`audit-dep-currency.ts` hardcoded `full-ai-cluster/flake.nix` as its only
Nix input source. The root `flake.nix` — 239 lines, four inputs — was
invisible to the entire dep-currency apparatus. Same divergence that left
the root flake unlocked for months (#15573), showing up on a second surface.

Adding a second hardcoded path would have been the same defect with a
longer list. So the roster is DERIVED from `git ls-files -- '*flake.nix'`,
the same mechanism `hygiene/mise-pin-parity.ts:trackedFlakes` already uses
for the same class of question: a newly added flake is covered the moment
it is tracked.

Measured, before -> after:

  nix-input pins    3 -> 9
  total pins      119 -> 125
  flake files       1 -> 2

The +6 is not only the root flake's four. The `name.url = "..."` regex
also missed the ATTRSET form entirely —

    nix-darwin = {
      url = "github:nix-darwin/nix-darwin/nix-darwin-25.11";
      inputs.nixpkgs.follows = "nixpkgs";
    };

— which has no `nix-darwin.url` line anywhere. So `nix-darwin` and `disko`
were dropped even in the one file the audit DID read. Both forms now parse,
scoped to the `inputs` block so an `outputs`-side `url = ...` is not
reported as a dep pin.

THE FALSIFIER, AND WHERE IT RUNS.

A scan that reads the new source and extracts nothing looks identical to a
pass, so the test asserts the root flake's inputs BY NAME with their pin
VALUES, and cross-checks each reported value against the line of
`flake.nix` the audit itself names. Value assertions are structural
(`github:NixOS/nixpkgs/nixos-` prefix, not `nixos-24.11`) so the pending
EOL upgrade does not have to fight its own falsifier.

Two mutations, both killed:

  A. roster re-hardcoded to `full-ai-cluster/flake.nix`   6 pass / 6 fail
  B. attrset-form `url` regex made unmatchable            7 pass / 5 fail

Unmutated: 12 pass / 0 fail.

`src/Core.TypeScript/audit/` ran in NO workflow — `grep -rn
"Core.TypeScript/audit" .github/workflows/` returned nothing — so a test
written next to the tool would have been a test that never ran, which is
the vacuity class exactly. A `bun test src/Core.TypeScript/audit/` step
goes on beside the existing hygiene one. Its cost comment is labelled a
LAPTOP figure (0.49-0.55 s warm over three runs, 1.54 s cold), not a
runner figure, because this step has never run on a runner.

One line leaves `lint-check-then-use-file-races.baseline.json`: the
`existsSync(flakePath)->readFileSync(flakePath)` race is gone with the
hardcoded path (grandfathered count 295 -> 294). A suppression should not
outlive its cause.

Verified locally: `bun test src/Core.TypeScript/audit/` rc=0 (12/12);
`hygiene:no-check-then-use-file-races` rc=0; `hygiene:no-culture-sensitive-collation`
rc=0; `audit-ambient-time-in-tests`, `audit-check-arity`,
`audit-check-arity-nonequality`, `audit-linter-coverage-vs-invocation`,
`audit-scan-floor-routes` all rc=0. `bun run typecheck` reports exactly one
error and it is NOT from this change — `observe/decorrelation-harness.ts(48,10)`
unused `writeFileSync`, already red on main tip and already fixed by #15578
/ #15580.
