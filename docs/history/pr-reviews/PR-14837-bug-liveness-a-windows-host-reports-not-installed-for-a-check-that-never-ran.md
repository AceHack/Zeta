## Description

bug(liveness): a Windows host reports "not-installed" for a check that never ran

`loop-liveness.ts:358` dispatches `platform === "darwin" ? gatherLaunchd :
gatherSystemd`, so every non-darwin host gets `systemctl` -- Windows included.
There `systemctl` does not exist, `unitFound` is false, and line 149 renders
that as `verdict: "not-installed"`.

A check that COULD NOT RUN is reported as a check that found nothing installed,
in the liveness monitor, whose whole job is noticing when something is not
running. The union is the bug, not the dispatch: `type Supervisor = "launchd" |
"systemd"` has no arm for "no adapter on this host", so the docstring's claim
that the classification "stays one total function over both" is true over the
union it DECLARES and false over the platforms it RUNS on.

The repo already ships the correct three-state shape elsewhere -- `secp256k1:
present, absent, and THE CHECK DID NOT RUN are three answers` -- so this is a
missing application of an established local pattern, not a new idea.

Found by the architect persona while measuring platform-branch sprawl for the
hexagonal OS port (#14820). Verified independently before filing rather than
taken on report: `Supervisor` at line 98 has exactly two arms, and line 149 maps
`!unitFound` to "not-installed". Filed with a falsifier that must fail against
today's code.

No fix in this commit -- the disposition belongs with the `host-os.ts` /
`disposition.ts` port that just landed (`081M0T694EG087G0R002SJST5K`).
