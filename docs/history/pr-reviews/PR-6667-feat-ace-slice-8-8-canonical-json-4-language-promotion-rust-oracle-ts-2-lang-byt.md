## Slice 8.8 — canonical-JSON depth promotion: Rust oracle

**First depth step** (after breadth slices 8.4–8.7). Per the canonical-primitive gate (proof **and** 4-language byte-lock), the breadth slices left the Ace seam primitives *TS-only + proof-owed → not canonical*. This converts the foundational one — the canonical-JSON seam (`canonicalBytes`/`toTagged`, slice 8.1/8.5) — from a TS-only golden-vector into a **multi-language byte-lock**, adding the **second oracle (Rust)** alongside TS. canonical-json is the foundation every `package_hash` + signature is computed over, and has no crypto deps — the right first promotion.

Spec: `docs/agendas/ace-package-manager/2026-06-03-ace-slice8.8-canonical-json-4lang-rust-oracle-design.md` (in this PR).

fix(ace): slice 8.8 — Rust sorts object keys by UTF-16 code units to …

…match JS (Codex P2)

Codex P2 on #6667: ace_canonical_json sorted object keys with `&str` Ord (UTF-8 byte = code-POINT
order), which diverges from the TS oracle's `Object.keys().sort()` (UTF-16 code-unit order) for an
astral key alongside a BMP key >= U+E000 — an astral char's high surrogate 0xD800..=0xDBFF sorts
BELOW 0xE000 in UTF-16 but its code point 0x1F600 sorts ABOVE it. Both keys pass the lone-surrogate
check, so well-formed input could produce different canonical bytes / package hashes across Rust
and TS.

Fix: sort keys by `encode_utf16().cmp(...)` (UTF-16 code-unit lexicographic = JS String order), so
the Rust oracle matches TS for ALL keys, not just the BMP keys the vectors carry. This case cannot
be a cross-verification vector — Python's json.dumps sort_keys is code-POINT too, so it would
diverge identically (the reason the 8.5 vectors keep keys BMP) — so a crate unit test
(astral_key_sorts_by_utf16_like_js) locks it instead. F#/C# get this free (their strings are UTF-16).

Behavior-preserving for the BMP vectors: rust-output.json is unchanged (UTF-16 order == byte order
on BMP); cargo test idempotent-passes against the committed golden; compare.ts TS+Rust agree on 14;
cross-verify-all 9/9. cargo build warning-clean.
