## Summary

Archive coverage is **77.4%** (10,337 archive docs against 13,347 merged PRs). Nothing measured it, so nobody knew.

**The lane is not broken. Its trigger stopped being reachable.**

## The gap is three populations, not one failure

| # | population | count | what it is |
|---|---|---:|---|
| A | `automation/pr-archive-*` / `claim/archive-pr-*` | 578 | the workflow's `if:` **deliberately** skips these — archiving an archive PR is a recursive chain. Not a gap. |
| B | merged before 2026-05-06 | 1,506 | the event lane did not exist yet. Real category, **no fix to the lane can ever move it** — only a backfill. |
| C | eligible, and the lane should have archived them | **926** | the defect. 765 of them since 2026-08-21, i.e. **still happening**. |

## Root cause of (C) — it terminates in an already-open P1

**`ZETA_TELEMETRY_FLUSH_TOKEN` is refused by the API on every heartbeat run**, so `agent-heartbeat.yml` falls back to `GITHUB_TOKEN` and every flush PR merges as `github-actions[bot]`. All six most recent heartbeat runs emit `::warning title=Heartbeat API credential denied` (32823324598, 32821142228, 32818569388, 32816194481, 32814829813, 32813161986) — not an edge case, **every run**.

```
PAT lacks contents:write  (081M05G8D36087G0R0034D3QPA — P1, OPEN, "NEEDS THE OPERATOR")
   -> fallback to GITHUB_TOKEN
   -> flush PRs merge as github-actions[bot]
   -> `pull_request: closed` event SUPPRESSED
   -> pr-archive-on-merge.yml never runs
   -> the PR is never archived, silently
```

**Nobody had connected that open credential bug to archive coverage.** Its measured cost is **910 unarchived PRs, accruing ~150/day** — recorded on the work item so the operator can see what the grant buys. The grant is a gated class an agent cannot make, which is exactly why this PR is the right deliverable: it holds the line while the credential waits on a human, and goes red again if it regresses.

## The mechanism, measured

**GitHub does not deliver a `pull_request` event for an action taken with `GITHUB_TOKEN`.** A PR merged by `github-actions[bot]` never triggers `pr-archive-on-merge.yml`. No run is created, nothing fails, nothing is red — the archive simply does not happen.

Checked, not assumed. Two samples over the same 5-day window:

| population | merged by github-actions | merged by a user |
|---|---:|---:|
| unarchived + eligible (n=765) | **747 (97.6%)** | 18 (2.4%) |
| archived, same window (n=539) | 9 (1.7%) | **530 (98.3%)** |

And directly, by asking the API whether a run exists for each merge SHA:

```
PR #15280  heartbeat/society      merged by github-actions[bot] -> 0 runs
PR #15267  soraya-flush           merged by github-actions[bot] -> 0 runs
PR #15272  heartbeat/tick-metrics merged by AceHack             -> 1 run, success
PR #15264  heartbeat/society      merged by AceHack             -> 1 run, success
```

The bot-merge share of all merges crossed over on **2026-08-20** (9/40 on 08-18, 11/40 on 08-19, 29/40 on 08-20). Coverage collapsed on **08-21**. The population that cannot trigger the lane grew; the lane did not change.

### The reported diagnosis was the wrong half

The 1,298 orphaned `automation/pr-archive-*` branches were expected to be the gap. They are not: **1,280 of the 1,298 are for PRs that already have a record.** Only 18 gap PRs have a branch at all. The other 1,271 have neither a branch nor a run — the workflow never fired for them.

## What is fixed

The sweep in `agent-heartbeat.yml` is no longer the safety net under the event lane; for bot-merged PRs it is **the only path**. It was not sized like one.

1. **`listMergedPRs` now applies the same eligibility predicate the workflow does.** It applied none, so it archived exactly what the event lane refuses to — 774 such records already written. `selectBatch` is oldest-first, so the 524 archive-of-archive PRs in its window sat at the **head** of the queue and consumed **41% of the budget**. (The 774 existing records are not deleted — §5.)

2. **`--limit 3` → `15`.** At 3 the ceiling was 288/day; after the 41% waste, ~170/day against ~150/day of accrual — break-even, which is exactly the flat ~1,289 backlog observed. 15 × 96 ticks = 1,440/day. At the measured ~6s/PR that is ~90s, against the worst measured tick of 293s in a 600s budget. The comment saying `RAISE IT once this lane has produced a few clean ticks` is now discharged, with the arithmetic recorded.

3. **One shared eligibility predicate** (`archive-eligibility.ts`) so the event lane, the sweep and the audit stop disagreeing about the denominator. A coverage number over an ambiguous denominator is a coin flip between two defensible answers.

## The durable deliverable: the coverage audit

`src/Core.TypeScript/hygiene/audit-pr-archive-coverage.ts`, running 4×/day in `pr-manifest-integrity.yml`.

That workflow already asked two questions — is the derived index behind the shards, and does a doc under-report its threads. **Both presuppose a record exists.** An unarchived PR has no shard to be unreconciled and no doc to under-report, so it was absent from every surface that reports. That is how 77.4% survived four days of green watchdog runs and was found by counting files by hand.

Two numbers, two floors, because they answer different questions:

- **window** (7d, minus a 90-min in-flight grace) — *is the lane working now*. Floor 95%. Catches a new break within a day.
- **lifetime** over eligible PRs — *how much of the corpus do we own*. A ratchet only a backfill moves. Floor starts at 75% so the audit lands green-on-truth rather than red-on-history it cannot fix.

**Against main right now: exit 1, window coverage 65.24%** (1,398/2,143; excluded=524, in-flight=22, missing=745). It goes red on the real condition.

### The threshold is backtested, not asserted

Replaying the audit's exact computation over the fifteen days around the break:

| day | window coverage | verdict |
|---|---:|---|
| 2026-08-11 .. 08-20 | 100.00% every day | **green** — 10 healthy days, no flap |
| 2026-08-21 | 94.62% | **RED** — day *one* of the break |

| 2026-08-23 | 73.04% | RED |
| 2026-08-24 | 64.50% | RED |

Both properties a threshold needs, and which are usually only claimed: it does not flap on ten consecutive healthy days, and it fires on the first day of the real incident rather than after it accumulates. 0.99 would also have caught 08-21; 0.90 would have missed it for a day.
