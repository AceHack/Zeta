## Description

The 21:50 scheduled run failed with *"the feature pipeline is leaking the label and every reported
number is void"*. Reproduced locally:

| null model (labels shuffled) | accuracy |
|---|---|
| NULL random forest | **5.3%** |
| NULL BNN | **22.9%** |
| majority-class floor | 3.9% |

**Both nulls train on the same `Xtrain`/`Xtest` and the same shuffled labels.** A feature carrying
the label would be visible to both — and the forest sat at the floor. The guard's own output
exonerated the feature pipeline while its message accused it, and voided the forest's 74.5%, which
no evidence implicated.

## The distinction the guard collapsed

It took `max` over the nulls. Now:

- **every null leaks** → the *features* carry the label. Shared cause, every number void.
- **some nulls leak** → that *model's* inductive bias. The clean null is positive evidence **for**
  the features; only the affected model's numbers are void.

Both still **exit 4** — an unexplained null above the floor blocks publication either way. What
changes is that the message names what the evidence supports.

## Why 22.9% needs no leak — and the codebase already knew

Under the temporal split the **test-majority oracle is 47.3%, area `telemetry`**. A model whose
shuffled-label predictions collapse onto one frequent class scores near that with nothing leaking.

`study.ts` documents this in its own docstring — *"under a temporal split with heavy distribution
shift it is far above the train-majority floor"* — and added `testMajorityOracleAccuracy` for
exactly this reading. The guard never consulted it. It does now, in the refusal text.

## Cause of the timing

**No code changed in the pipeline.** 57 PR shards landed in the window and tonight's telemetry flood
moved the test distribution. The guard was always going to fire; the data reached it this evening.

## What this does NOT do

It does not diagnose the BNN. The shuffled-label collapse is real and still owed an explanation —
one-vs-rest with a diagonal Gaussian posterior under heavy class imbalance is where I'd look, and
**I did not verify that.** This change stops the wrong component being blamed and points at the
right one.
