## Description

## What

Otto's guard on H3: the +3.2pp confidence-gated lift (merged in #15743) was measured in-sample, and a fitted-threshold selector will almost always beat best-single in-sample because the threshold absorbs the noise it saw. This adds 5-fold cross-validation over the existing raw log (no new model calls).

## Result — it survives with zero optimism

| | accuracy | lift over best-single |
|---|---|---|
| zero-threshold rule (H3 as reported) | 93.8% | +3.2pp |
| fitted threshold, in-sample | 93.8% | +3.2pp |
| **fitted threshold, out-of-sample (5-fold)** | **93.8%** | **+3.2pp** |
| optimism removed (in-sample − OOS) | — | **0.0pp** |

OOS McNemar vs best-single: +3.2pp, CI [1.8, 4.6], resolved.

**Why zero optimism:** the confidence gap is bimodal with a clean gap straddling zero (clause-wins +0.04..+0.66, canon-wins −0.31..−0.04), so the fitted threshold lands at the natural τ=0 on every fold. There is no noisy boundary region to overfit — the selector has no free parameter to exploit, which is exactly why CV does not shrink it.

`kFoldThresholdSelector` ships with a pure-noise control test that correctly collapses to ~0 OOS lift, proving the guard can catch optimism when it exists.

Also folds in Otto's two smaller points on the H3 doc: the logprob **portability scope limit** (a model-internal signal not every provider exposes), and **why "resolved" is justified for H3** (CI [1.8, 4.6], clears zero with margin and survives CV) in a way it was borderline for H2 (CI [0.05, 5.28]).
