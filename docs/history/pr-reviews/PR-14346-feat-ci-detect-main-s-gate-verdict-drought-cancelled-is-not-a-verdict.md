## Description

# Summary

Builds a detector for a condition that was **invisible** on this repo: `main` going a long
time with no *completed* gate verdict.

`gate.yml` cancels its in-flight run on every merge to `main` (per-ref concurrency,
`cancel-in-progress`). That setting is correct. What it produces, when merges arrive faster
than the gate finishes, is a `main` whose recent commits carry **no verdict at all** — not a
pass, not a fail, just `cancelled`.

Measured on this repo, 2026-08-23T17:35Z:

```
last SUCCESS on main:  10fbd9a4   16:29:06Z → 16:43:22Z
now:                   17:33:54Z          (≈50 min later, ~20 commits)
last 8 runs:           6 cancelled, 2 running, 0 success
gate duration:         ~14 min when allowed to finish
merge interval:        17:30:13, 17:30:29, 17:30:37   ← three merges in 24 seconds
```

Merges outran the gate by roughly an order of magnitude, and **`cancelled` reads as neither
pass nor fail** — so every surface that folds gate outcomes (`platform-drift-report.ts`,
`gate-scope-summary.ts`, `drift-loud.ts`) finds nothing, and nothing renders as green.
`drift-loud.ts` has the hole today: hand it 60 cancelled runs and `subjects` is empty and it
prints `EXIT 0 — no sustained drift`. It is not wrong about drift; it is silent about the
fact that nothing was measured. **A check that did not run must never look like a check that
passed.**

**Owned error.** Earlier the same day I looked at this exact cancellation pattern, reasoned
that a later successful run covers the earlier commits, and called it benign. That reasoning
has a premise — that there eventually *is* a later success — and the premise is what the
condition removes. At 50 minutes and ~20 commits with no success the conclusion had already
failed. I found it by counting conclusions by hand, and a detector that has to be asked is
not a detector.

## Extended, not added

One reporter, `src/Core.TypeScript/ci/verdict-drought.ts`, running in **two existing
surfaces** — deliberately not a fourth parallel mechanism.

| host | why | loudness |
|---|---|---|
| `drift (loud)` job in `gate.yml` (#14283) | already built to go red beside a green required check | `::error::` + step summary + **non-zero exit** (red X, blocks nothing) |
| `drift-sweep` job | own concurrency group with `cancel-in-progress: false` — **survives** the storm that cancels every gate run | `::error::` + step summary, `--report-only` so it never goes red |

The second host is load-bearing, not redundancy. A drought detector living only inside
`gate` is cancelled by exactly the condition it exists to report — silent precisely when it
matters. Measured during the storm above, `drift-sweep` concluded `success` at
17:30:37 → 17:34:32 while four consecutive gate runs were being cancelled.

`--report-only` on that host because `drift-dashboard`'s roster folds the latest run per
workflow and fails when any is red; failing `drift-sweep` would cascade into a lane this
change may not alter.

## What it reports

- **Time since `main` last had a COMPLETED gate verdict** — `success` **or** `failure`.
  `cancelled`, `skipped`, `timed_out` and an in-flight run are **not** verdicts and can
  never satisfy the check.
- **Commits landed on `main` since that verdict** — because "50 minutes quiet" and
  "50 minutes and 20 unverified commits" are very different facts. `null` when unmeasured,
  **never coerced to `0`**.
- **Cancellation rate** over a bounded window.
- The last **SUCCESS** as a separate fact, and the **median gate duration** the time
  threshold is derived from, so the constant stays checkable.

**The cancellation rate is annotated independently of the register**, at `::warning::`.
This gap was found by the detector's **own first CI run**, not by a test: `drift (loud)`
run 32657724476 reported register `ok` — a `failure` verdict 1 minute old — alongside a
60% cancellation rate and a 112-minute success drought, and emitted **no annotation at
all**. That is the leading indicator of the very condition this exists for, sitting silent
behind an `ok`. Merges outrunning the gate is the *mechanism* that produces a drought, so
it is now said before the drought arrives. Warning rather than error is deliberate: the
register says whether main is **checked** (error when it is not), the rate says the gate is
being **outrun** (a forecast, not yet a fault). It is suppressed when the register is
already loud, because every other register carries the rate inside its own reason list.

Three registers, and **`unknown` never aggregates into green**: `ok` · `drought` · `unknown`
(no completed verdict in the window at all, or the window could not be observed —
deliberately the loudest, since an unmeasurable drought is strictly worse than a long one).
`isVerdict` is a strict allow-list of exactly two conclusions rather than a deny-list: the
failure that matters is a non-verdict counted as one, and that direction turns a drought
green every time GitHub invents a new conclusion string.

## CodeQL `js/http-to-file-access` — investigated, fixed at the source, not suppressed

Two medium alerts landed on the first push: *"Write to file system depends on Untrusted
data"* at `verdict-drought.ts:667` and `:668`, rule `js/http-to-file-access` (*"Network data
written to file"*).

**1. Is a path component API-derived?** **No.** Both sink paths are constants —
`$GITHUB_STEP_SUMMARY` from the runner environment, `--out` from `argv`. No part of either
path comes from a response body, so there is no traversal to defend against. The finding is
about **content**, not location.

**2. The content finding is real, and I did not argue it away.** API-derived fields
(`head_sha`, `conclusion`, `created_at`, `updated_at`) reached two **structured** formats by
string concatenation:

- the step-summary **markdown table** — a `|` splits a cell; a newline ends the row and the
  table, and everything after it renders as fresh document structure;
- the **`::error title=…::message` workflow command** — a newline forges a second command in
  the runner's log stream, the well-known Actions command-injection surface.

The tempting defence was that the values are well-formed *in fact*: the listing is filtered
to `?branch=main&event=push`, so `head_sha` is git-computed and `conclusion` is a GitHub
enum. But that is a claim about the server, **checked nowhere**, that would have to be
restated every time the query changes. This PR exists because a check that did not run must
not look like one that passed — shipping it behind an unchecked assumption would be that
defect committed inside the detector built for it.

**3. Fixed structurally, not by blocklist.** Every network-derived value is matched against
an anchored shape at the single API→model boundary (`toObservation`) and **replaced** by a
fixed, self-describing constant on failure — not escaped, not repaired:

| field | shape | on failure |
|---|---|---|
| `id` | `Number.isSafeInteger` | `UNRECOGNISED_ID` (`-1`) |
| `head_sha` | `/^[0-9a-f]{7,64}$/` | `UNRECOGNISED_SHA` |
| `created_at` / `updated_at` | strict ISO-8601 UTC, then **re-emitted from parsed epoch ms** | `UNRECOGNISED_INSTANT` |
| `conclusion` | GitHub's documented set + `RUNNING`, returned as **our own literal** | `UNRECOGNISED_CONCLUSION` |

No value reaching the renderer can carry a `|`, a newline, a backtick or a `::`, because no
value reaching the renderer came from the network unchecked. The injection is
**unexpressible rather than filtered**. Two properties are pinned by tests: replacement is
**loud** rather than silent normalisation, and **an unrecognised conclusion is never a
verdict** — `isVerdict` stays an allow-list of exactly two strings, so an unknown value
cannot become one by being replaced. That is the direction that would turn a drought green.

**On the JSON sink specifically:** it was already structurally safe — `JSON.stringify`
escapes a newline to `\n`, so no field could break out of the document — but it carried
unvalidated *content*. The test now asserts those two properties **separately** instead of
conflating them. Nothing is built by concatenation.

**A second hole this exposed, same class as the bug this PR is about.** Once a timestamp can
be replaced by a sentinel, `minutesBetween` returns `null`, and the fold's
`overTime = minutesSinceVerdict !== null && …` fell through to `false` and returned `ok`. An
**unmeasurable drought read as a healthy one**. There is now an explicit branch: a verdict
whose age cannot be computed is `unknown`, loudly, never `ok`.

### The alert itself will NOT clear, and that is stated rather than worked around

After the fix, `js/http-to-file-access` **still reports at the two sinks**. I am not
suppressing it, dismissing it, or contorting the code to launder the dataflow, because the
honest reading is that **the query flags a category, not a vulnerability**. *"Network data
written to file"* is inherent to a detector whose whole job is to write a report derived
from the Actions API into `$GITHUB_STEP_SUMMARY`. There is no version of this feature that
does not write remote-derived text to a file — that text **is** the report. The same shape
already exists in `drift-loud.ts`, and the class already carries **three open instances on
`main`**: `src/Core.TypeScript/hygiene/retraction-actuator.ts:201`,
`docs/books/you-born-at-the-hinge/scripts/translate_book.ts:192`,
`src/Core.TypeScript/peer-call/summon.ts:369`.

Precisely, for a reviewer to check rather than trust:

- **What CodeQL believes is tainted:** the `fetch` response body from
  `GET /actions/workflows/gate.yml/runs`, flowing through `head_sha`, `conclusion`,
  `created_at`, `updated_at` into `appendFileSync` / `writeFileSync`.
- **What constrains it in fact:** the table above — anchored shape, fixed-constant
  replacement, `conclusion` returned as our own literal, instants rebuilt by the runtime
  from a number.
- **What remains true, and is accepted:** remote-*derived* text still reaches a file. That
  is the feature. The exploitable part — breaking out of a markdown table or forging a
  workflow command — is now unexpressible, and a test goes red if the constraint is removed.
- **Both sink paths are constants**, so nothing can be written outside the intended location
  under any input.

If the repo wants this class closed rather than accepted, that is a decision about four
files and one query, not about this PR, and it should be made once for all of them.

**No CodeQL suppression was added, no alert was dismissed, and no existing check was
weakened.** The two follow-up constraint changes (canonical instants, own-literal
conclusions) were made because they are better engineering — format stability in a diffed
table, and a result guaranteed by construction — not because they were expected to move the
scanner. They did not, and the commit says so.

## The falsifiers, and the discrimination proofs

Proved by inverting the implementation locally, confirming red, and restoring — not by
asserting.

**FALSIFIER 1 — a window of only `cancelled` runs is `unknown`, never ok/green.** Widening
`isVerdict` to accept `cancelled`:

```
✗ FALSIFIER 1 > the register is `unknown` and is NOT `ok`
    Expected: "unknown"   Received: "drought"

✗ FALSIFIER 1 > the rendered summary says UNKNOWN and never claims the lane is ok
✗ FALSIFIER 1 > the DETECTOR is live even though the LANE is silent
```

**FALSIFIER 2 — a `failure` still counts as a *verdict*.** Narrowing `isVerdict` to
`success` alone:

```
✗ FALSIFIER 2 > the newest failure satisfies the check — register `ok`, no drought
    Expected: "ok"        Received: "drought"
✗ FALSIFIER 2 > a red main is a KNOWN main — success drought reported SEPARATELY
✗ FALSIFIER 2 > the ok register emits no annotation
✗ the two drought axes are independent > COMMITS: a fresh verdict with a large pile
    Expected: "drought"   Received: "unknown"
27 pass, 5 fail
```

**FALSIFIER 3 — the boundary constraint.** Removing the four `constrain*` calls from
`toObservation` turns five tests red, and the failure output contains a literal forged
command inside both the rendered step summary and the annotation line:

```
| last COMPLETED verdict | run 4242 `success` deadbee  (2026-08-23T16:43:22Z
::error title=forged::injected workflow command) |
```

The injection demonstrated, not asserted. All three inversions were reverted; the tree is
green.

One lesson kept in the test file rather than deleted: **the first hostile fixture proved
nothing**, because its `conclusion` was not a verdict so the fold discarded it before the
renderer ever saw it. A hostile input the code never looks at is not a falsifier. The
fixture that discriminates is an ordinary `success` whose sha and timestamp are hostile.

## `CodeQL` fix — `compare.ahead_by`, the one API value the boundary missed (otto, c471ac9)

The failing `CodeQL` check was two `js/http-to-file-access` alerts on the file writes at the
bottom of `verdict-drought.ts`. The SARIF taint path (analysis `1659768752`) does **not** run
through `toObservation` — it runs through the *second* API call: `commitsSince` →
`compare.ahead_by` → `foldDrought` → the summary table → `$GITHUB_STEP_SUMMARY` and `--out`.
Three commits of boundary hardening never touched it, which is why the alert did not move.

It is a real defect, in this file's own defect direction. `typeof NaN === "number"`, and every
comparison the fold makes against the count is `>=` or `>` — both `false` for `NaN`. So an
`ahead_by` of `NaN`, `Infinity` or a negative reported itself as MEASURED (`=== null` is false,
so `COMMIT COUNT NOT MEASURED` never printed), rendered as `NaN` in the table, and then declined
to fire: a commit count that failed looking exactly like one that found nothing wrong.

`constrainCount` joins the `constrain*` family — anchored shape, loud degradation into the
report's existing NOT-MEASURED register (`null`, never `0`), and the value re-emitted here
(`Math.trunc` on an already-safe integer is a copy, not a repair) so no part of the response
body survives into the report, exactly as `constrainInstant` re-emits from parsed epoch ms.

Discrimination proved by inversion, not by assertion: reverted to
`typeof value === "number" ? value : null`, two of the four new tests go red. Both restored.

`bun install --frozen-lockfile` — without it `tsc` exits on `TS2688` and never typechecks),
