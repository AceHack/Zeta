## Tests are green — and the cross-check is what proves it

`dotnet build` **0/0**. `dotnet test` **6335 passed, 0 failed**. `bun test` 13,746 with **22 failures**.

**CI gate run 32434946163 is at the exact worktree HEAD and all 33/33 jobs are green** — including `test (TS hermetic)`, which runs the same bare filter-less suite. **So zero of the 22 is a genuine regression.** 12 are contention timeouts (another agent held **load average 28**; 3.7 s CPU vs 77 s wall). **4 are pre-documented to the letter** in `registry/environment-dependent-test-files.json`, which predicts exactly which four fail and why. **That is the mechanism working.**

**Two worth acting on anyway:** `concept-index.test.ts` collapses a whole file's coverage into one `beforeAll` scanning **30,309 files** against a fixed 30 s budget on a set that grows daily — when it trips, **~20 real assertions never run**. And three whole-tree scans exceed the 5 s cap in isolation, one by **58 ms**, while `bunfig.toml`'s own doctrine says slow-by-nature tests carry their own timeout.

**The TPM tripwire is armed and green, not firing** — compliance, correctly reported. But of the 6 .NET skips, three `RxAdapterTests` are **the falsifiers for a shipped race fix**, so **that fix ships unverified in CI**.

## Dual ownership is SEVEN charts, and four diverge

**8 bootstrap `HelmChart` CRs, 7 also owned by an ArgoCD Application with `selfHeal: true`.** Same chart, same version, same release name, same namespace, **two reconcilers**.

**The worst is Vault, and it is not latent:**

| | k3s helm-controller | ArgoCD |
|---|---|---|
| `server.ha` | `enabled: false`, `replicas: 1` | `enabled: true`, `replicas: 3`, `raft: true` |
| **rendered backend** | **`storage "file"`** | **`storage "raft"`** |

> **Different storage backends on the same release name, and `selfHeal` will keep converting Vault between them. That is data loss on the cluster's secrets backend, on a loop.**

**Verified independently before landing:** `k3s-server.nix:118` declares `vault-install.source`; `root-application.yaml` recurses with `recurse: true`/`selfHeal: true`; `vault/Application.yaml:50` carries `selfHeal: true`.

Also **`argo-cd` is dual-owned** and the ArgoCD values drop to 4 top-level keys vs 9 — **selfHeal would strip its own controller config.** And **`cilium` is the CNI**, where one side adds `l2announcements` another app depends on — **so that capability toggles on and off.**

**The Vault comment is worse than lying:** it claims cert-manager TLS with **zero `kind: Certificate` resources**, and the render is **internally contradictory** — `tls_disable = 1` plaintext listener while `VAULT_ADDR` is `https` and readiness runs `vault status -tls-skip-verify`, **which skips *verification*, not the handshake.** **Vault never goes Ready** — and SPIRE and External Secrets both depend on it.

**Pinning:** CI supply chain is **clean** (every `uses:` a full 40-char SHA). Images are not — **zero digest pins, six `:latest` in a GitOps path, four first-party.** **With `selfHeal: true`, a `:latest` is a silent capability change arriving with no commit.**

## Observability — broken at every link

**Real:** the full stack renders; **13 ServiceMonitors, 35 rule groups**; `Metrics.fs`/`Tracing.fs` are first-class; **tick telemetry works end to end**; and the portal **degrades honestly**, enumerating each degraded capability rather than faking it.

**But:**

1. **Alloy is a DaemonSet on every node that moves zero bytes** — three components, **all sinks**, **zero** receivers/scrapes/sources repo-wide. **Three pipelines with an output and no input** — while its header claims it ships logs, metrics and traces.
2. **Its Loki sink names a Service that does not exist** (`loki` vs the rendered `loki-gateway`).
3. **Alerting fires into `/dev/null`** — **one receiver, named `null`**, default route sends everything to it. **35 rule groups fire and every alert terminates there. No push path to any human.**
4. **The DORA page's data source has no writer** — it says *"every frame here is a JSON file committed by CI"* and fetches a file **that does not exist**. It has an honest fallback and **does not fabricate** — **the "committed by CI" claim is the false part.**
5. **`Zeta.Core.Circuit` metrics reach nobody** — zero OTel packages, so **`StartActivity` returns null and the counters increment into nothing.**

**Missing:** no in-repo ServiceMonitor or PrometheusRule — **all 35 are chart defaults** — and **no Zeta workload is scraped at all.**

> **The chain: F# emits with no exporter → Alloy has no receiver → no source → its sink names a nonexistent Service → alerts route to `null` → the DORA writer was never built. Any single fix leaves it broken.**

**Order that buys signal:** Alloy sources (**values-only**) → `loki-gateway` → an Alertmanager receiver → then the OTel exporter.
