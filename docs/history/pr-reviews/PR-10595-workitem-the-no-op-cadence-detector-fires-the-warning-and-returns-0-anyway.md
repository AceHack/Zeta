`src/Core.TypeScript/hygiene/check-no-op-cadence-pattern.ts` is the mechanical
detector for the standing-by / no-op-cadence failure — the one CLAUDE.md's
heartbeat-via-commit section calls THE failure mode. It computes the answer
correctly and throws it away.

CHECKED by reading, not inferred: `main()` is 360 lines and contains exactly
three `return` statements. Line 259 `return 0` (no shards, nothing to check).
Line 355 `return 0` — every other path, INCLUDING both detections. Line 266
prints `WARNING: no-op-cadence pattern detected`, line 307 prints
`WARNING: missing-shard-cadence detected`, and both fall through to line 355.
The entrypoint is `process.exit(main())`, so the process exits 0 when the
pattern is detected and 0 when it is not. The exit code carries no information.

And it is invoked by no workflow — checked across `.github/workflows/` — so the
warnings are not merely unread by a caller, they are not produced in CI at all.

This is the fifth vacuity found today, after verifyLandauer (`x >= x`), the
all-`unsat` SMT runners, 12-of-15 unopened TLC configs, and the AgencySignature
audit that exempted the fleet's own personas (#10564 / #10573). Those verify
properties and provenance. This one is aimed at the shadow's own conduct — an
instrument for detecting "you did nothing" that itself does nothing — which
means every clean run of it to date was uninformative rather than reassuring.

WHY FILED RATHER THAN FIXED IN PLACE. Unlike the other four, "make it exit 1" is
not obviously right. Both detections are HEURISTICS with env-tunable thresholds
(NO_OP_CHECK_THRESHOLD default 5-of-7, NO_OP_CHECK_GAP_MINUTES default 15), and
the script's own text says the warning is meant to fire "at decision-time",
which reads as an advisory rather than a gate. Promoting an uncalibrated
heuristic to a blocking gate is a different act from repairing a tautology, and
it is a routing call rather than mine to make unilaterally.

The item lays out the three options and recommends the reversible one: add
`--enforce` so the exit code CAN carry the detection, wire it non-blocking, and
measure the false-positive rate against real heartbeat shard history before any
blocking mode is armed. Per toy-is-free-metered-must-be-earned the detector is
currently UNMETERED — implemented, used, never falsified — and the acceptance
criteria say so, including that the falsifier must go red under mutation.
