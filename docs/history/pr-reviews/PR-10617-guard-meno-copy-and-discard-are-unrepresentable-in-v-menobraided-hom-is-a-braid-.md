## Description

## What

`⟨V⟩` is genuinely braided **only because it excludes copy `Δ` and discard `ε`**, and nothing enforced that. This lands the guard at **rung 1** of the externalization ladder: `MenoBraided.Hom` makes copy and discard *unrepresentable*, not merely absent.

Work-item `081KZZVC6SE087G0R001SXE8BV`.

## Why it is load-bearing, not hygiene

A **cartesian** monoidal category has a unique *braiding* — stronger than Mathlib's `Subsingleton (SymmetricCategory C)`, which only pins the *symmetric* structure. `I` is terminal, so naturality of `c` against `!_A : A → I` forces `π₁∘c = π_B` and `π₂∘c = π_A`; the product's universal property then pins `c = swap`. `Meno.fs:38` records that the **deterministic** subcategory (the `arr f` arrows) IS cartesian (Fox 1976), and `braidR` is built with `Meno.arr`. So if `Δ`/`ε` ever entered `⟨V⟩`, `braidR` would be forced to the swap and the machine-checked `braidR_not_symmetric_perm3` would be false.

Note the scope: the **ambient** `⊗_Kronecker` is not cartesian, so `braidR` is a legitimate braiding of `⟨V⟩` today. The risk is forward-looking, and it is silent.

## Rung 1 — the type

`MenoBraided.Hom` is a `private` union over braid words with a **total** `inverse`. Every letter's interpretation `crossingOnList c` is invertible by `crossingOnList (-c)` — in range because `R`/`R⁻¹` are mutually inverse, out of range because both are the identity — so `Hom` is a *group* and every inhabitant interprets to a basis bijection. `Δ : V → V⊗V` is not surjective on basis and `ε : V → I` is not injective, so neither can be named.

Checked in the **emitted IL** rather than assumed: `Hom` is `NestedPublic`, but `NewBraidHom` / `.ctor` / `get_Item` / `get_Tag` are all `Assembly`-scoped, so the guard binds C# and every other consumer of `Zeta.Core.dll`, not only F#. An external `MenoBraided.BraidHom [1]` is `error FS1093` — probed, then reverted.

*"Ask which operation the defect required, and remove it; don't add a field beside it."* The defect required **building a `⟨V⟩` hom from an arbitrary function**. That operation no longer exists.

## Shipped API

**Unchanged.** `rep : int list -> Meno.Arrow<V list, V list>` keeps its exact signature; it is now `Hom.ofWord >> Hom.toArrow`, so the arrow form has no second construction path. `repHom` is added for `⟨V⟩`-typed callers. `braidR` / `braidRinv` / the §A-24 conformance gate / `src/Core.Lean4/` are untouched.

## Rung 3 backstop — the hole no F# type closes

`Hom.toArrow` is a **one-way door** into `Meno.Arrow`, where `Δ` and `ε` legitimately exist (Meno is a CD category). A future edit could still hand-write one *beside* `rep` and call it `⟨V⟩`. Seventeen exact-integer tests — exhaustive over 343 basis tuples and all 85 braid words of length ≤ 3 — catch that.

## S₃ witness — exact, independent of `Braid.fs`

Built from permutations, sharing no code with the free-group implementation. `R` is a bijection on **36/36** pairs, and `π₁∘R ≠ π₂` on exactly **18/36** — the non-commuting pairs, `36 − Σ_x|C(x)| = 36 − (6 + 3·2 + 2·3)`. The swap differs on **0/36**, so the 18 is discriminating rather than decorative. No floats, no tolerances.
