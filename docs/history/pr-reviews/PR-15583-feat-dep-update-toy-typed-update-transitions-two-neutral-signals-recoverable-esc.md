## Description

## What

A **semver range is a CLAIM, not a guarantee.** `^1.2.3` is the publisher asserting minors won't break you, and every tool in the ecosystem treats that assertion as binding. This adds the typed core that measures whether each publisher's assertions have historically held, holds that signal strictly separate from provenance/continuity, and escalates in a way that can be **recovered from**.

**Nothing calls it yet, and that is the design.** A decision function nobody calls is honest; a half-wired auto-updater is not. No CI wiring, no `.github/dependabot.yml` change, no auto-merge, no persistence layer, no registry queries.

Marked **`toy`** throughout per `.claude/rules/toy-is-free-metered-must-be-earned.md` — there is no measured adherence data anywhere, so every number it produces is a number about a fixture.

## Three findings worth the reviewer's time

**1. `TravelerRankLedger.fs` has no dynamics factor.** The brief said to reuse it because "TrueSkill's dynamics factor inflates σ with time since last observation". It does not — the file's own docstring states `"σ² is strictly decreasing with each observation"`, which **is** the swallowing Aaron asked to avoid: after 50 clean releases the 51st breaking one barely moves μ, so the score would be *rising* through the window where the evidence turned. The reuse is therefore honest but partial: the ADF update is transcribed, and τ is **added** (Herbrich, Minka & Graepel 2006 — TrueSkill's own dynamics factor, not an invented decay constant).

**2. Nothing in this repo verifies provenance of an *incoming* dependency.** Eight workflows mention `attestation` / `provenance` / `cosign` / `sigstore`; every one is about artifacts **we produce** (our images, our ISO, our agents' peer attestations). Not one of the 8 dependabot ecosystems checks npm provenance, a sigstore bundle, or reproducibility on a package it pulls in. The second signal is a surface that does not exist yet — and this change does not build it either.

**3. Uncapped σ² inflation diverges on a long clean run.** Found while building it. Once μ is large the probit likelihood saturates (`w(t) → 0`), so a further success carries almost no information while inflation keeps adding τ² per step — the estimator reports its *most consistent* publishers as its *least certain* ones. Measured: 60 clean observations gave σ² = 0.91 and rising against σ₀² = 1.0. Fixed by capping at the prior: **no amount of staleness can leave you knowing less than you knew before any evidence existed.**

## Two neutral signals — never one trust score, never an intent

| signal | asks | source |
|---|---|---|
| semver adherence | did this publisher's PAST CLAIMS hold? | the registry |
| provenance / continuity | is this artifact WHAT IT SAYS IT IS? | sigstore / in-toto / npm provenance, reproducible builds |

Fact rows name **facts**: `MaintainerChanged`, `ProvenanceMissing`, `ProvenanceIdentityChanged`, `BuildNotReproducible`, `SuddenReleaseCadenceShift`, `NewPublisher`, `AdherenceBelowFloor`, `AdherenceStale`. There is no `Compromised`, no `Malicious`, no `Attacker` — a test asserts their absence in the shape a DU row would take.

**The combinator is a JOIN, not a weighted sum.** Under any sum a maximal adherence score *buys down* a provenance discontinuity, and the better the record the more it buys — backwards precisely in the xz-utils case. `toyProvenanceReading` is **not passed** the adherence record, so independence is enforced by parameter list rather than by discipline.

## The two falsifiers, mutation-checked

A test that cannot fail is decoration, so each was run against the mutant it claims to catch:

| mutant | what it changes | result |
|---|---|---|
| **A** | join → weighted sum | **5 fail** — all three FALSIFIER 1 tests |
| **B** | dynamics factor removed | **3 fail** — incl. the swallowing test |
| **C** | escalation made sticky (a blocklist) | **5 fail** — both FALSIFIER 2 tests |

Restored: **21 pass, 0 fail**. Mutant B is not a strawman — it is literally the current F# estimator, and it fails the property that was asked for.

- **FALSIFIER 1 (adherence is never sufficient):** xz-utils / CVE-2024-3094 had a spotless record. A publisher with a *maximal* score (pinned > 0.95, and shown `AutoEligible` with clean provenance so the test can't pass by everything escalating) still escalates on a provenance discontinuity. Each of the five facts is checked alone; the patch-bump case separately.
- **FALSIFIER 2 (escalation is recoverable):** *"we never assume betrayal unless it's self declared by the betrayer and even then the game continues we don't end playing."* No permanent blocklist, no confiscation. `Transition` has no terminal row; `toyClassify` has no memory and never returns a modified belief. Recovery is tested on **both** axes — a resolved discontinuity returns byte-identically to `AutoEligible`, and a publisher whose *adherence* was the problem recovers by accumulating new observations.
