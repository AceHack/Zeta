## Description

Follow-up to #13472, correcting one of its own four reasons.

## What happened

#13472's `temporal` reason said its chart *"has no persistence store configured, so it does not render"*, citing the `helm-template-failed` acknowledgement in `rendered-storage-claims.baseline.json`.

**That was true when measured and false when it merged.** #13469 landed in the interval, wired temporal's datastore to the CockroachDB already in the cluster, re-measured the render as **OK** (6 Deployments, 8 Services, 2 ConfigMaps, 1 Job, **zero** PVCs), and **deleted the acknowledgement the reason cited**. The two merged 40 minutes apart; my rebase carried the stale sentence onto `main`.

## The real blockers — both from #13469, both already in `temporal/Application.yaml`

1. **The visibility schema does not apply to CockroachDB.** temporal v1.27.2's `advanced_visibility.sql` opens with `CREATE EXTENSION IF NOT EXISTS btree_gin` and uses a plpgsql function inside `GENERATED ALWAYS AS (...) STORED` columns. CockroachDB implements neither (`cockroachdb/cockroach#51992` open; computed columns may not reference UDFs, `#122945`). The **default** store is unaffected — which is why this is a split, not "temporal does not work on CockroachDB".
2. **No TLS material, and this CockroachDB is TLS-only.** The CA is a Secret in the `cockroachdb` namespace, this app runs in `temporal`, and no `temporal` SQL user exists. Declaring `sql.tls` today would point a values block at a Secret nothing creates.

## The part that matters more than the fix

**Both audit directions stayed green through this — including the two #13472 added.**

All four directions check that a reason is **present** and names a lift condition. **None checks that it is true**, and nothing there can. A false sentence with a `LIFTS WHEN:` clause satisfies every mechanical property the registry has.

That limit is now written into the function's own doc-comment instead of left for the next reader to discover the way I did:

> What the registry buys is that a reason is **written down and therefore refutable by a reader**; what it cannot buy is the reading. Reasons citing a render, a run id or an HTTP status are cheap to re-check on purpose — that is the mitigation, and it is a **convention, not an enforcement**.

## The error is kept, not erased

The corrected reason opens by naming that it was corrected within the hour by its own author, and a test refuses the refuted claim **by name**. A reason quietly overwritten teaches nobody — and #13472's whole argument was that a stale reason is a defect. It took ten minutes to become the next instance of it.
