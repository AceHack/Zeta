## Description

Routes the container-based job runtime Aaron asked for, with the toolchain-portability tiering rule that decides which jobs get to use it — and proves it on **one** job rather than migrating the fleet.

## The layering (Aaron: *"there is only one ace and pre ace bootstrap"*)

The image is **not** a fourth consumer sitting beside `tools/setup/`. It is a **materialization** of two layers at a pin — the minimal seed that gets a bare machine to the installer, then `tools/setup/install.sh`. So the Dockerfile carries **four package names** (`ca-certificates curl git xz-utils`, the seed `linux.sh` needs before its own apt phase) and no other package list. There is no second definition to drift.

The prior art was already here: `src/Core.TypeScript/ci/dockerfiles/ubuntu-install-sh-test/Dockerfile` has done exactly this since 2026-05-30 and then thrown the image away. This is one change to that — keep it, and let jobs run in it.

## Drift detection is manifest comparison, not bit-reproducibility

Aaron: *"manifest comparison is fine, don't chase bit-reproducibility"*. Text expectation = `.mise.toml` (already the single declared source for tool versions); artifact under test = what `mise ls --json` reports inside the image. Same discipline as the golden vectors.

Recorded precisely because it is easy to mis-attribute: **reproducibility is a property of the package manager, not the container runtime.** `apt` resolves version ranges against a mutable mirror; Podman and Buildah run the same non-deterministic build. "Try a different container toolchain" buys nothing.

Both controls run locally before commit:

| control | result |
|---|---|
| positive — `--check --tier slim` against a real mise host | `EXIT 0 — every one of the 18 mise-managed pins is satisfied` |
| negative — same, with `bun = "1.3"` mutated to `"9.9"` | `EXIT 1 … bun declares 9.9 but the runtime has 1.3.12, 1.3.13, 1.3.14` |

Plus 16 unit falsifiers, three aimed at this check's specific ways of going vacuous (absent tool silently skipped; substring match accepting `1.30` for `1.3`; `mise ls` failing to run read as "nothing wrong"). Blind spots — apt, elan, dotnet global tools, the zig/rust realizers — are enumerated by `unmanagedSurfaces()`, printed on every run, and pinned non-empty by a test.

## The proof — one job, executing on this PR

1. **Negative control, run before the image exists**, and guarded against being vacuous: asserts `bun` is absent from the bare runner (loud `vacuous control` failure if that ever stops being true), then requires `memory-reference-existence-lint`'s payload to **fail** there.
2. **The same payload, verbatim**, green inside the image with the install step **deleted rather than replaced**.
3. Toolchain drift check + its own falsifiers, both run inside the image.

`docker run` with the workspace mounted rather than job-level `container:`, because `container:` needs a registry-resolvable image before the job starts and none is published until this lands. Operationally identical (image carries the toolchain, job carries the source), so the cutover transfers without changing shape. The exact cutover diff is in the doc.

## A correction to a premise, recorded rather than buried

On GitHub-hosted runners there is **no layer cache between jobs** — each job is a fresh VM, so every containerized job pays a **full pull**. Net time saving is therefore `install_seconds − pull_seconds`, and `pull_seconds` is **unmeasured** until a digest publishes. The case rests on what is structural: no Actions-cache writes, and one sequential registry pull replacing ~149 apt fetches plus the whole mise graph — the exit-124 class is a mirror-stall class and does not exist on the pull path. If the measured pull turns out worse, the proposal should shrink to the lanes where reliability alone justifies it.

## Scope — what this does NOT do

No fleet migration. **No demotions** (they are proposed with their costs named; none implemented). `gate.yml` untouched. `required_status_checks` unchanged. No cache key expressions touched. Publish is main-only, cosign-signed over the **digest**, and consumers pin the digest, never a tag.

## Second deliverable — Nix scoping read (§7 of the doc)

`flake.nix` present (239 lines, referenced by `gate.yml`); **`flake.lock` ABSENT**; no `dockerTools`/`streamLayeredImage` anywhere. The missing lock is the highest-leverage reproducibility gap in the repo and is **independent of containers entirely** — without it the flake resolves nixpkgs at evaluation time. Could Nix emit the CI image? Not today; the gap is large and I did not evaluate the flake (no Nix on this host), so no fraction is claimed. Finding, not direction; nothing migrated.
