## Description

## Summary

`agencysignature-enforcement.yml` requires an AgencySignature v1 trailer block in the PR **body** for every PR created after `FAIL_CLOSED_CUTOVER` (2026-08-15T00:00:00Z). `pr-archive-on-merge.yml` predates the cutover and emits no trailer, so **every archive PR it opens fails the gate on creation.** #10763 was the first; without this it would have been every one after it.

A workflow that cannot pass a gate it is subject to is not a flaky check — it is a check nothing can ever satisfy.

## The values, and why they are these

They describe the **workflow**, not a person. The credential is the Actions bot, nobody reviewed the PR, and it runs unattended — so `Human-Review: not-implied-by-credential` with `Human-Review-Evidence: none`, and `Action-Mode: autonomous-fail-open`. This is the same shape `red-state-flush-workflow` already emits on its commits, so it adopts an existing in-repo precedent rather than inventing an attribution.

## Two shape constraints, recorded in-file

Both are invisible until they bite, and the second cost real time today:

* The block must be the **last contiguous trailer group** — exactly one blank line before it, zero inside it, and `Co-authored-by` inside the same group, since it is itself a trailer.
* **Nothing above it may begin a line with `---`.** `git interpret-trailers` reads a leading `---` as the diff/patch boundary and discards everything after it, so an ordinary markdown horizontal rule silently makes a correct block unparseable — while the validator's error text points at blank-line discipline instead. Nine open PR bodies currently contain one, including all five dependabot PRs, whose template footer carries it.

## Verification — simulated, not inspected

The generated body was reconstructed from the workflow's own `echo` sequence and run through the real validator:

```
full simulated body                       exit 0
trailer block removed                     exit 1
a bare `---` inserted above the block     exit 1   <- the hazard, reproduced
```

`actionlint` exit 0.

One honest note on method: the first attempt at the removal case used `head -n -11`, which BSD `head` rejects, producing an empty file and a misleading exit 2. Redone with `sed` over a computed line count. A falsifier that fails for the wrong reason is not a falsifier.

## Not addressed here

The five dependabot PRs still fail this gate for two independent reasons — a bot cannot emit the trailer, **and** its template footer contains a bare `---`. Scoping the gate for third-party bots is a policy call, not this PR's.
