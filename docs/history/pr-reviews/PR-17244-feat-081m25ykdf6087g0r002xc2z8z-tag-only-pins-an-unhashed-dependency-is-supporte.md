## Description

Aaron 2026-09-10, twice:

  "for some things we don't need a pin at all, or we can pin a tag instead of a SHA,
   we can't be perfect with security here if it keeps blocking us over and over and
   over and over, security on a product that never ships never matters."

  "we need to support non hashed dependencies they are just not the preferred and need
   to be handled separately, we need to wire these everywhere though, not all
   dependencies have a stable sha."

THE DEADLOCK THAT FORCED IT, measured today rather than argued. `repin-rolling.ts`
advances a digest only after the row's declared `remeasure=` passes. For tla2tools that
sweep judges the jar against `registry/tlc-models.json`'s versionBanner -- a COMMITTED
RESTATEMENT OF THE PIN that only a successful re-pin updates. So the sweep reports
"banner is 2026.09.10.133702, registry pins 2026.09.09.213036" for all 52 models, the
re-measure fails, the tool restores the tree, and refuses:

  RE-MEASURE FAILED (exit 1). Nothing was re-pinned and the tree was restored.

THE PIN CAN NEVER ADVANCE. Three hand re-pins in one day were people stepping around a
tool that cannot succeed, and one of those left the tree half-applied -- pins moved, no
receipt -- which is exactly the verifier-swap state the receipts ledger exists to stop.

THE MECHANISM. `sha256=tag-only`, and it is bounded on purpose:

  * PER ROW, OPT-IN. Matches that literal string and nothing else. Every other row still
    requires 64 hex and still fails closed. There is no global switch and none may be
    added.
  * A REASON AS A VALUE, not a comment: `tagonly=<why>`. A comment gets copied along with
    the line it excuses; a required field does not.
  * THE URL MUST CARRY A VERSION-SHAPED TAG. A row pointing at `latest` or `main` is
    REFUSED -- "pin the tag instead of the digest" is only meaningful when there is a tag.
  * The bytes are still hashed and the digest LOGGED at accept time, as a report rather
    than a verdict. An unpinned install nobody can see is worse than the pin it replaced.

WHAT IS GIVEN UP, plainly: whoever can publish to that tag chooses the bytes we install,
and nothing here will notice. That is not new -- the auto-accept exception row already
granted exactly that for this dest. This removes the ceremony around the exposure, not a
protection.

WHAT IS NOT GIVEN UP: the four TLC model verdicts -- completion marker, expected-violation
substring, exit code, and the pinned exhaustive distinct-state count -- run on every gated
run. A substituted jar that changes any RESULT still fails. The digest was never the only
guard, which is what makes the trade takeable.

THE OBLIGATION CHANGES RATHER THAN DISAPPEARS, and this is the "handled separately" half.
`lint-verifier-jar-provenance` does not exempt tag-only rows; it asserts the OTHER duty:
a digest row must prove its digest was measured, a tag-only row must prove it said why it
has none. Silently exempting would have narrowed the check without saying so. Proven both
ways: with the reason rc=0, with the reason deleted rc=1 naming the row.

The receipt requirement is dropped for tag-only rows because a receipt BINDS A DIGEST to
the run that judged those bytes -- with no digest there is nothing it could say, and
demanding one would be demanding a signature on a blank cheque.

RETIRED: the auto-accept exception row for this dest, its 90-day expiry, and its
re-measure coupling. With no digest, that row could never fire again -- and an exception
that cannot fire is a check that cannot fail.

7 unit falsifiers on the gate itself (digest accepted, missing pin refused, tag-only
without a reason refused, tag-only on a moving alias refused, tag-only with tag and reason
accepted, malformed digest refused, isTagOnly false for a digest). 117 realizer tests pass.
lint-rolling-exceptions, lint-verifier-jar-provenance and lint-tla2tools-rolling-premise
all rc=0.

STILL TO DO, named because the instruction was "wire these everywhere": `from-elan` and
`from-autotools-tarball` carry the same mandatory-digest refusal, and `mise.lock` already
has 8 of 22 rows with no digest on a separate roster. Those want the same declared class
rather than three dialects of the same exception. Routed separately.
