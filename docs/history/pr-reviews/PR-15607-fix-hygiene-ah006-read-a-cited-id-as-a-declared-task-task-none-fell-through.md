## Description

fix(hygiene): AH006 read a CITED id as a declared Task — `Task: none` fell through

`cross-verify` is a REQUIRED floor, and it goes red on any PR whose body
says `Task: none` and mentions a ZetaId in prose. That is most autonomous
PR bodies, and citing prior work by id is exactly what
`anchor-to-human-prior-art` asks for.

THE MECHANISM, IN ONE LINE

`extractTaskIds` collects ids from `Task:` lines, then falls back to
scanning the WHOLE text for any ZetaId — a fallback that exists so a bare
list of ids can be piped in on stdin. The fallback was guarded by
`out.size === 0`, which cannot distinguish

  * no task declared anywhere        (bare list — fallback is correct), from
  * a task declared as `none`        (an explicit declaration of no task)

`none` is not a ZetaId, so it contributes no id, so `out.size === 0`, so
the fallback fired and the entire PR body was read as a list of Task
declarations. Every id CITED in prose was promoted to a Task id and had to
resolve to a `workitems/` file.

The audit was collapsing MENTION into DECLARATION —
`workitems-mint-with-zetaid` already draws exactly this line: "Naming an
existing legacy id in prose is not minting."

THE FIX

Guard the fallback on `sawTaskLine` — whether a `Task:` line EXISTS —
rather than on whether one produced an id. Four lines of logic.

A `Task:` line whose value is not a well-formed id (`none`, a placeholder,
a typo) now yields zero ids and no fallback. That is deliberate and
matches this file's own division of labour, stated in its header: SHAPE of
the Task value is the AgencySignature check's job; RESOLUTION of ids that
are present is this one's.

THE LIVE INSTANCE

PR #15573's body says `Task: none` and mentions
`081KSGS9H0008QG0R001EKTS5A` in a sentence about an existing backlog row.
`cross-verify` failed on ALL THREE of that branch's revisions, and the id
it named is real — `docs/backlog/P1/081KSGS9H0008QG0R001EKTS5A-iter-6-0-bump-nixpkgs-24-11-to-25-11-warbler-xantusia-eol-re.md`.
It is a legacy `docs/backlog/` row rather than a `workitems/` entry, so
even the resolution half was answering a question nobody asked.

Reproduced locally against that exact body: rc=1 before, rc=0 after.

FALSIFIERS (4 added, 26 pass total)

  * `Task: none` + an id in prose declares NO task
  * an unresolvable prose id under `Task: none` produces NO finding
    (the end-to-end form — this is what reddened #15573)
  * `Task: none` does NOT suppress a real Task id elsewhere in the text
  * the bare-list fallback STILL fires when there is genuinely no `Task:` line

The last two guard the fix from over-reaching into "a Task line silences
everything", which would have traded one vacuity for another.

Mutation: restoring the `out.size === 0` guard fails 2 of the 4. The other
two pass under both, by design — they pin behaviour the fix must PRESERVE,
not behaviour it introduces, and saying so is more honest than implying
all four discriminate.
