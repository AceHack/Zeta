## Description

## The gap, named by the repo itself

`docs/research/2026-08-20-hsm-tpm-into-vault-and-cert-manager-yes-for-tpm-but-not-through-vault-openbao-is-the-answer.md`
§5 recorded:

> a `seal` stanza or a `tpmDirect: true` flip breaks **zero** existing tests on a hardware-free machine.

That was still true. The seal half stops being true here; the `tpmDirect` half is
untouched and still unguarded, and the doc now says so.

## What it refuses, and what it deliberately does not

`audit-vault-topology-coherence.ts` gains a twelfth rule,
**`seal-stanza-requires-vault-enterprise`**. An **active** `seal "pkcs11"` stanza
in HCL rendered by **HashiCorp's** chart is a finding, and the message carries the
citation — *"Auto-unseal and seal wrapping for PKCS11 require Vault Enterprise"*
([`vault/docs/configuration/seal/pkcs11`](https://developer.hashicorp.com/vault/docs/configuration/seal/pkcs11))
— plus where the capability actually lives (OpenBao, MPL-2.0).

It refuses **one specific impossibility, not auto-unseal in general.** `transit`,
`awskms`, `gcpckms`, `azurekeyvault` and `ocikms` are Community Edition and are
absent from `VAULT_ENTERPRISE_ONLY_SEALS`, with a test pinning that the list is
exactly `["pkcs11"]` so the rule cannot quietly widen into refusing a seal that
works.

## Why this is the mistake worth a check

Once the OpenBao thread in §6 of that doc is live, the tempting move is to copy
its hardware seal stanza back onto the Vault chart. It reads like progress toward
the TPM, and it is a server that does not boot: the Enterprise seal does not
degrade to Shamir, it refuses to start. A check that says so at review time costs
nothing; finding out on a cluster costs an unseal ceremony.

## Both directions of the gate are exercised

`rendersHashiCorpVault(source)`:

- **stands down** for a source that positively identifies a different chart, so
  the OpenBao migration is not obstructed — and the stand-down has its **own
  test**, because a gate nothing ever takes the other way is indistinguishable
  from a gate that is always open;
- treats an **unnamed** chart as Vault. Unknown is not permissive: a rule that
  stands down where it has the least information is the vacuity class, and that
  branch is tested too.

The detector ignores commented-out stanzas — the chart's own default HCL ships a
commented `seal "gcpckms"` example, and counting it would make the rule *always*
fire, which is the same defect as one that never can. Both halves are tested.
