## Description

## What this is

A **sequencing note**, not a proposal. Aaron 2026-08-14: *"we are trying to deprecate all .sh files eventually into our own clis"* — that direction is already set. This gives it a **security-driven order**, because PR #10683 established the fleet has no per-cell code identity to bind a key to, and right now the ordering is by convenience.

Docs + `workitems/` only. No build or CI config touched.

## Three corrections to the premise I was handed — all measured on this box

**1. The cells do not run a `.sh` wrapper. They do not run at all.** All four plists name `tools/kiro/kiro-loop-wrapper.sh`, deleted from `main` on 2026-06-13 by PR #8088; every cell `git reset --hard`'d it away. `launchctl list` → exit **78 (`EX_CONFIG`)**, no PID, stderr logs zero-length since 2026-06-11. `host-loop-bootstrap.sh:142` still emits the dead path. **This is a live availability finding**, not only a security one.

**2. Removing the `.sh` created no code identity — which is the whole point.** The current templates emit `{{BUN_PATH}} loop-tick.ts --persona X`, no shell anywhere, and the executing identity is still `Developer ID: Jarred Sumner (7FRXF46ZSN)`.

> The `.sh` was never the identity gap. The **interpreter** is. Shell → TypeScript-run-by-bun is a legibility win and is **security-neutral by construction**. A programme that stops at "no more `.sh`" will report success having moved the needle not at all.

**3. The cells do not share *one* identity.** The launcher touches no credentials; `loop-tick.ts` spawns the persona's harness. Those carry **five distinct third-party Developer IDs** (Anthropic, Google, AMZN, AgileBits, Jarred Sumner) plus **two unsigned scripts** — `cursor-agent` is bash, `codex` is a node script. Per-cell binding is unreachable at that layer no matter what we compile.

## Feasibility — run, not reasoned

`bun build --compile` → Mach-O arm64, re-signs cleanly with a chosen identifier + hardened runtime, `--verify --strict` passes, runs. **Byte-reproducible** given the same source *and* the same `--outfile` basename (the filename is compiled in). A keychain ACL accepts it and records `requirement: cdhash H"…"`. `spctl` rejects ad-hoc — irrelevant for build-on-node, gating for ship-a-binary.

**Two negative results are the valuable half:**
- macOS denies by **prompt**, which on a 60s unattended cell is a wedge, not a denial.
- **`security(1)` launders the caller's identity** — the ACL-trusted binary is itself DENIED, because `/usr/bin/security` is the caller. 9 sites, including one already ported to TypeScript with the defect intact (`manus-smoke-test.ts:16`). Without fixing those, L2 on macOS buys nothing.

## The highest-exposure surface is not a repo `.sh` at all

`~/.config/zeta/secrets-env.sh` hoists the 852-byte OP service-account token into **every shell environment**. An env var crosses `exec` regardless of the child's code identity — no signature, ACL or IMA policy can gate it. §13 noninterference, and the cheapest fix on the list.

## Honest caveat, kept load-bearing

**No FROST shares exist on disk**, and there are **no code-signing identities** on this machine. This is **pre-positioning ahead of the risk, not incident response.** What is exposed today is one 1Password service account, a gh token, thirteen Claude credential blobs and an ssh key — all shared, all legitimately needed by the cells as designed.

## Boundaries held

- **code identity ≠ custody ≠ attestation.** A signed binary creates an *identity*; binding a key to it is *custody* (the L1/L2/L3 ladder, unbuilt); proving that binding to a third party is *attestation* and needs a vendor root. Only the first is delivered here. A signed binary is **necessary, not sufficient** — proven by re-running the reachability probe *from* a compiled, signed binary and getting byte-identical access.
- **Signing keys are Aaron's.** No key generated or proposed; every signature here is ad-hoc (no certificate, no key material). Developer-ID signing stays a biometric-gated operator action. Every measurement reports a **length** — no key material printed or logged.

## Owned error (doc §0.4)

Provoking the ACL denial **put a macOS keychain password dialog on Aaron's screen** for a password he never set. The finding was already available from the ACL dump without provoking it. An autonomous agent must never park an interactive credential prompt in front of the human; "this path requires interactive auth" is the finding to record. Test keychain was in a temp path with a self-generated password, never touched `login.keychain-db`, and is **confirmed deleted** — `list-keychains` shows login + System only, no stray `security(1)`/`SecurityAgent` process, probe directory and its compiled binaries removed.

## Prior art I should have found first (doc §1.0)

I hand-rolled an enumeration before checking whether one existed. **It does, and it is CI-enforced** — `src/Core.TypeScript/hygiene/check-bash-retirement-inventory.ts`, run by `gate.yml`, reports **31 retained shell entrypoints, zero drift**, with a categorized allowlist.

- My `*.sh` glob **undercounted by three** (the extensionless git hooks). The allowlist is the correct denominator.
- More important: its categories answer *"why is this still shell?"* and never *"what can it reach?"* — so `setup/bootstrap` holds **22 of 31**, with `keyring.sh`, `op-token-setup.sh` and `secret-clip.sh` in the same bucket as `install-zig.sh` and the toolchain smoke tests.

**That artifact is the convenience ordering, in the open.** So the deliverable is narrower and more actionable than a new inventory: **add an exposure dimension to the allowlist that already exists** (`081M00VVBAN087G0R000XC5MN7`).
