## Description

The module landed in #15890 with tests and **no entry point**. Nothing could invoke it, which made
every property it proves true and *unreachable* — a tested module nobody can run is the same shape
as a check that cannot fail, and it was the third instance of "built but not wired" in one day.

```bash
bun src/Core.TypeScript/installer/hardware-only-facts.ts            # prints the artifact
bun src/Core.TypeScript/installer/hardware-only-facts.ts --out p.json
```

## Two design calls worth reviewing

**stdout is the primary sink, deliberately.** On a first boot the console is mirrored to the serial
UART, so printing means the facts reach a durable place even when the disk write fails or the target
filesystem isn't mounted yet. A capture that exists only as a file is one a failed mount silently
deletes.

**Exit 0 even when everything is `unknown`.** This records; it does not judge. A host with no sysfs
produces an artifact full of `unknown` and a populated `unmeasured` list, and that is a *successful*
run — "this machine tells us very little" is an answer, and failing on it would make callers treat
an honest result as an error. The one thing that *does* fail is a requested `--out` that couldn't be
written, because then the caller asked for a file and hasn't got one.

`realProbe` collapses every failure to `null` — "could not look" — which the pure code renders as
`unknown`. A probe returning `""` or `[]` on error would convert *we could not look* into *we looked
and found nothing*, which is the one thing this module exists to prevent.

## Run for real

On this darwin host every row comes back `unknown` or absent, with each gap named in `unmeasured`.
That's the module behaving correctly on a machine it can't read, not a defect.

The tests include the **control** that `realProbe` can actually read something — without it, a probe
returning `null` unconditionally satisfies every "unreadable yields null" assertion.

26 pass · tsc clean.

## Not done, and deliberately not guessed

The systemd/NixOS wiring that runs this at first boot. It needs `bun` present on the node, which I
could not verify: there's no `bun` reference in `full-ai-cluster/nixos/modules/`, and
`full-ai-cluster/usb-nixos-installer/` contains no `.nix` files at all. Shipping a unit ordered after
an install that may not provide bun would be a service that silently never runs — the exact failure
class this PR is fixing. The entry point is the unambiguous half and lands first.

**Open question for you:** is `bun` on the installed cluster nodes after `zeta-install`, or should
the capture run from the installer ISO instead?
