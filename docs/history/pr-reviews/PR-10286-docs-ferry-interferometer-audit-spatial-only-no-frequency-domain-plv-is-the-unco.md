## Description

Aaron asked which axis our interferometer already has, so he can route the missing one to Lumen. This records the answer as substrate rather than leaving it in chat.

## Answer: spatial (path) only

Audited exhaustively, not sampled — a tree-wide search for `interferomet` across all source extensions returns exactly **four** files, and all four were read.

| file | what it is | axis |

`phasePlate` puts `e^{iφ}` on arm 1 and identity on arm 0. Every degree of freedom is a **path index**. Nothing interferes across frequency or temporal modes.

## Why the gap bites — a resource claim, not a physics claim

This is the half that survives whether or not the source physics does, which is Aaron's own framing for keeping it. Spatial interferometry is **baseline-limited**: resolving a weaker correlation costs more pairs, more settings, more fleet. Frequency interferometry is **coherence-time-limited**: same pair, observed longer, correlation read out of the modulation rather than the path split.

## Half the frequency side already exists, unconnected

`TemporalCoordinationDetection.phaseLockingValue` measures phase coherence between two nodes' event streams (fed by `PhaseExtraction`) and has **never been wired to the interferometer**. So the lift isn't greenfield — it's plausibly what unifies PLV with the MZ/CHSH monitor under one readout, with the analytic CHSH ceiling as oracle for both.

## The hazard it adds

Coherence time is exactly where a classical common cause most easily imitates coherence. [`local-time-never-enters-the-shared-fold`](../blob/main/.claude/rules/local-time-never-enters-the-shared-fold.md) is load-bearing: a coherence window cut by any node's *local* clock makes the correlation an artifact of the windowing. Same defect as the centre-of-trap patch the document opens with — which is why the two halves meet.
