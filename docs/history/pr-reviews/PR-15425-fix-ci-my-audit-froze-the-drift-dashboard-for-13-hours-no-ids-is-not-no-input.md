## Description

TRACED CHAIN, each link verified rather than inferred:

  AH006 exits 2 on a telemetry-flush PR
    -> cross-verify goes red
      -> the flush PR cannot merge
        -> it head-of-line blocks its own lane (flush-via-staging buffers behind an open PR)
          -> data/platform-drift.json stays pinned at asOf 2026-08-25T06:35:54Z
            -> the drift dashboard reports 13-hour-old numbers FROM BEHIND A GREEN CHECK

The last line is the class this repo exists to refuse, and my check caused it.

THE DEFECT. `runAudit` set `inputWasEmpty: ids.length === 0` — conflating two events that
are not the same:

  - ZERO BYTES ARRIVED. A broken caller. This is the shallow-CI-checkout fault the exit-2
    path was built for, and it bit this very file on its own first CI run.
  - INPUT ARRIVED AND CARRIED NO IDS. A real answer about a real PR. A machine-generated
    telemetry flush has no work-item and legitimately carries no Task id.

Only the first is a caller fault. Conflating them made every flush PR a configuration
error. Measured on PR #15404: body present, 47 checks completed, one red — this audit,
exit 2, "NO INPUT".

WHY NARROWING IS SAFE AND NOT A WIDENED CHECK. Presence of a `Task` key is enforced by
the AgencySignature gate, which requires all ten keys. THIS file enforces RESOLVABILITY —
that ids which ARE present identify a real work-item. That division of labour is exactly
why the predicate can be tightened without losing coverage: an authored PR that forgets a
Task line is still caught, by the check whose job that is.

Exit 2 now fires only on zero bytes. Four controls, each able to come out the other way:
empty stdin -> 2 · #15404's real body (no ids) -> 0 · a real id from this tree -> 0 · a
fabricated id -> 1.

A PASSING TEST WAS CHANGED, and it is called out rather than slipped in. "runAudit reports
inputWasEmpty so the caller can refuse it" asserted `runAudit([]).inputWasEmpty === true`
— it PINNED THE CONFLATION. Replaced by three tests that pin the distinction instead, with
the reasoning in a block comment at the site. Mutation: collapsing `!inputHadContent` back
to `ids.length === 0` turns one red. 22 pass.

NOTE ON MY EARLIER FIX. #15421 guards this step with `if: github.event_name ==
'pull_request'`, which fixes the push-to-main case and does NOT fix this one — #15404 IS a
pull request. Two distinct bugs in one wiring; the first fix was correct and incomplete,
and I would have called cross-verify solved on the strength of it.
