## Description

Fixes the x86_64 `build-iso` red on `main` since 2026-08-01 (workitem `081KZETP6AT08QG0R003MG1VYN`), driving the install.sh fix Aaron asked for.

## Root cause
`zeta-install.sh` runs under `set -euo pipefail` (line 29). **#9937** removed the `| tail -10 || echo WARN` guard to capture `PIPESTATUS[0]` (correct intent) — but the `||` had been the *only* thing suppressing `errexit` for that pipeline. Without it, a failing `install.sh` pipeline **trips `set -e` and aborts the script** before the rc-capture / WARN / `PARTIAL-PROVISION` marker can run. So `zeta-install` returns non-zero → `zeta-first-boot.sh:250` emits `[zeta-first-boot] Install failed` → QEMU scenario-1 hard-fails. #9937's design was explicitly *non-fatal*; `errexit` silently defeated it.

Verified: the `set +e` at line 1247 is subshell-local (node registration), so errexit is **on** at 1577; live repro `f(){ return 3; }; f | tail` under `set -euo pipefail` aborts the script.

## Fix
Scope `errexit` off around the pipeline only — the **same subshell-local pattern already used at line 1247** — capture the real rc via `PIPESTATUS[0]`, restore `errexit`. #9937's WARN + `PARTIAL-PROVISION` marker preserved (non-fatal but *noticed*). `tail -10`→`-40` to surface more of the underlying mise error.

- `bash -n` clean.
- Behavioral test: `install_rc=7` captured, script continues (non-fatal), WARN fires. ✓

## Scope
This restores the intended **non-fatal** first-boot (node boots, marked partial if the toolchain is incomplete) and **greens build-iso**. It does **not** fix the separate latent bug that `install.sh` itself fails in the x86_64 first-boot VM (uv/python/pipx) — that stays tracked in `081KZETP6AT08QG0R003MG1VYN`, now diagnosable from the wider `tail -40`. This PR triggers `build-ai-cluster-iso`, which validates the fix end-to-end.
