## 2. `fix(hooks)` — Otto-343 read-log keyed on `session_id`, not `process.ppid`

The read-before-edit discipline wrote/read its log at `/tmp/zeta-reads-${process.ppid}.json`. On remote / Claude-Code-on-the-web sessions **every hook runs in its own short-lived process**, so the writer (`post-read-track`) and reader (`pre-edit-recent-read`) never agreed on a filename — the reader always saw an absent log and **wrongly denied every `Edit`**, even right after a `Read`. (This is why the Game-vault edits above had to go through `Write`/patch scripts.)

- **Fix:** key the shared log on the stable per-session `session_id` (already in the hook payload — the `HookInput` type just never declared it), falling back to `cwd` then a constant, via one shared helper `harness.ts:sessionReadLogPath`.
- **Flag for future traceability (as requested):** `OTTO343_READLOG_TAG = "OTTO-343-session-key-2026-06-21"` is emitted in every deny reason **and** stamped into the log filename. If read-tracking ever misbehaves again, `grep` the tag → it lands on the root cause, the fix, and the regression test.
- **Tests:** new `harness.test.ts` (5 cases) pins the invariant; verified end-to-end (Read→Edit now ALLOWs; Edit-without-Read still DENYs with the tag). Prettier clean.
