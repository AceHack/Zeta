## Description

**I broke `main` with #10272 and reported it clean.** Two lint jobs went red on the new `tools/setup/common/fd-limits.sh`, and my `mainFailures=0` checks in the following ticks were wrong — the lint run hadn't finished when I sampled it, so I read an incomplete window as a green result.

Two failures, both mine:

- **bash-retirement inventory** flagged `fd-limits.sh` as an unexpected non-Lean shell file. The repo is retiring bash, so every retained script needs an explicit allowlist entry and category rather than existing quietly. Added under `setup/bootstrap`.
- **SC1091** — shellcheck can't follow the sourced file because CI runs it without `-x`. The existing `# shellcheck source=` directive documents the path for a *reader* but doesn't satisfy the linter, so this adds an explicit disable **with the reason**, not a bare suppression someone later has to reverse-engineer.

**Lesson recorded in the commit**, since I got it wrong twice running: a green result sampled from `gh run list` moments after a merge isn't evidence — the slow jobs haven't reported yet. Same shape as reading a stale build: check the status, then check the status is *complete*.
