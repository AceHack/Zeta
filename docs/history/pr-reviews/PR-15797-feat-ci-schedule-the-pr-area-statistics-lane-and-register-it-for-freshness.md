## Description

## Summary

Wires the PR-categorisation generator (landed separately) to a scheduled lane, and
registers its output so the lane's own silence is caught.

- `.github/workflows/pr-categorization-cadence.yml` — every 6h at `:34`, plus manual
  dispatch.
- `data/pr-categorization/statistics.json` added to `FRESHNESS_ROSTER`.
- `pr-categorization.test.ts` — falsifiers for the seams between the generator and
  the things that publish and watch it.

## Built around how lanes actually die

Three lanes went quiet in the week before this, and none of them died in its
algorithm. Each of those failure modes gets a check here rather than a comment:

| how a lane dies | the guard |
|---|---|
| writes N artifacts, flushes fewer (drift-dashboard: 4 written, 2 flushed, markdown frozen 3 days) | the test asserts the workflow's `--paths` list **equals** the generator's exported `ARTIFACTS`, in both directions |
| pipes a checker through `tee` and reports tee's status | the generator step sets `set -uo pipefail` and reads `PIPESTATUS[0]`; the test asserts all three are present |
| publishes with `\|\| echo` so a refusal is non-fatal | the test scans the flush step for every swallow form |
| pushes at `main`, which ruleset "CI Gate" refuses at push time | parks on `heartbeat/pr-categorization` and flushes via PR; the test asserts nothing targets `main` |
| assumes a credential works | a real `git push --dry-run` preflight, re-probed after the fallback is installed |
| nobody notices it stopped | registered in `FRESHNESS_ROSTER` against its own declared cron |

The cron minute is also checked: `:34` is a minute no other workflow uses, and the
test enforces that against **all** cron forms. Restricting the scan to `*/N` is how a
real overlap gets missed — `mirror-to-fork.yml` runs `13 8 * * *`, which a `*/N`-only
pattern does not match at all, so minute 13 read as free when it was not. That is
exactly what happened on the first draft of this lane.

## `fetch-depth: 0` is load-bearing here, not hygiene

The ground-truth label for every PR comes from the files its squash-merge touched,
recovered by walking `git log --name-only`. A shallow clone yields almost no join
hits, so the generator **refuses** (exit 3, with the cause named) rather than
publishing a study of 50 PRs as though it were a study of 13,000.

## Freshness registration

The roster's docstring predicted a third subject would be "a five-line edit, not a
design", and it was. One pre-existing test needed a fixture fix: it handed every
non-`red-state` subject an `{ at: ... }` document, which suited a two-entry roster and
reported `no-field` the moment a third subject named a different key — a fixture
failure that would have read as a subject failure.

The roster entry's declared cadence is asserted against the workflow's actual cron by
the new test, so the two cannot drift into a threshold nobody chose.

## Note on scope

`lint-drift-publication-lands.ts` only matches lanes publishing paths containing
`drift`, so it does not cover this one. Rather than widen a shared guard from here,
the three rules it enforces (no push at `main`, no swallow on the publish step,
capability probed with a real dry-run) are asserted locally for this lane. Widening
that lint to all publication lanes looks worthwhile and is left as its own change.
