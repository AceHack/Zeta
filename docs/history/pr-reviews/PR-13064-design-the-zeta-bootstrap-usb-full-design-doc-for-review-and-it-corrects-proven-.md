## Description

**Aaron asked for a full design doc pulling together the requirements discussed over months, to review and annotate.** This is that document — **§2 is the ledger built to be annotated**, and **§5 + §7 are the sections that need his answer specifically.**

## It corrects a claim I landed hours ago

I said **"proven-on-metal is an empty set."** **That is false as history.** Verified before landing — four node registrations exist with real timestamps and maintainers:

```
node-ad1efd  Addisons820   2026-06-09T09:09:17Z
node-b1e1b5  Addisons820   2026-06-09T09:58:02Z
node-f82aa6  maximdolphin  2026-06-14T17:10:55Z
node-5b2dfa  maximdolphin  2026-06-14T22:20:16Z
```

**Addison flashed from a zflash-made stick, booted two Linux machines on her own GitHub credentials, and both nodes self-registered by PR.** That happened.

> **The true claim is narrower and sharper: nothing built after 2026-06-21 has ever run on metal.** Eight weeks of correct safety work landed on a working pipeline with QEMU as the only witness. That is **regression risk on an unexercised path** — worse than "never worked", because the June evidence makes the current path *feel* proven.

**Second correction:** the roster is **ten** manifests, not eleven — Vault was removed 2026-08-20 and my count did not follow.

## The oldest asks are 74 days old

2026-06-09, verbatim: *"check if the partition exists every time before formatting … **do this now**"*, refined the same day to *"it should NOT ask before format — it should ask to CANCEL for a minute before format; this USB should fully boot headless."* **Neither exists.**

And the script's own comment claims the consent *is* the Ctrl-C window — **a comment describing a window that does not exist**, because there is no `sleep` between the device list and the wipe.

Alongside: a **P0 repair-loop circuit-breaker**, never built. An `install-answers.json` credential **declared in the manifest with no producer** — the same shape as an unread golden vector. And the flasher split, which Aaron escalated from tidiness to **thesis violation** — now with a cost it lacked then, because **all four 2026-08 safety gates are macOS-only, so a Linux operator writes an unverified image with no refusal.**

## Seven decisions are Aaron's

Each framed as a question with options and consequences rather than a recommendation in disguise: the **storage arithmetic** (1499 GiB declared against a 931.5 GiB disk, gate green only because it compares against an **unsigned** aspiration whose own comment says *"awaiting maintainer sign-off"*); **what the credentials bind to**, the blocker under R8 for 74 days — **TPM means a re-paved node remembers *itself*, iSerial means one stick provisions the fleet, and they are different products**; whether the USB **pins a tag or tracks `main`**, which today means **flashing the same ISO twice weeks apart produces different clusters**; **single-ISO vs the GRUB2 multiboot composite**, where both exist on `main` and **nothing chooses**; the wipe-consent model; the FIPS contradiction still in the buy-list; and which node to burn first.

## Two bookkeeping defects found while building the ledger

## Why booting a node ranks first

**Items 2–12 are all preparation for item 1, and several will change shape once a node has booted** — so doing them first risks building the wrong guard for the wrong failure. One hour, one machine, **zero CI minutes**. It closes two P2 bugs whose sole remaining condition is *"one clean boot on Aaron's hardware"*, and two commands afterward separate stage-3-proven from the highest-severity finding, and **separate the storage failure from the ordering failure — which have completely different fixes.**

**Ten known unknowns** are listed so the boot is instrumented to *answer* them. The sharpest: **does the k3s deploy controller retry an apply of an unknown kind?** If not, the cluster stops at seven charts **while `systemctl is-active k3s` reports `active`.** And one worth two seconds first: the registered nodes report `/dev/sda 115.5G` — **exactly 124.0 GB decimal, the size of the PNY stick.** Probably the boot USB, excluded correctly by `TRAN`. **If it is an internal SATA disk, first boot wipes it with no prompt.**

A **"suggested, not asked for"** section is kept separate so enhancements never enter the record as requirements. Best of them is one line: **ship the serial log to the ESP** — otherwise everything learned on the first boot lives in a scrollback buffer a reboot destroys. **The difference between one boot and a repeatable proof.**

**Register:** measured claims are marked; cited claims say so. The storage arithmetic is **cited rather than re-measured** because `bun` could not resolve `yaml` in that worktree — **and an empty run is not a zero.**
