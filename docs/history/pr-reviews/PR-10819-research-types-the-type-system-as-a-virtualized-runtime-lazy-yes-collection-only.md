## Description

Surveys Aaron's 2026-08-15 thesis — *the type system is a virtualized runtime* — against the actual code, and separates the parts that hold from the parts that do not. One doc, one falsifier.

## The answer, short

| claim | verdict |
|---|---|
| "it does not all have to be loaded at once" | **holds** — and is the documented design of erasing type providers |
| "we can GC code generated with type providers / CEs / Roslyn" | **holds far more weakly than it sounds**, and today, in this repo, **nowhere** |
| "we use zetaid for our generated types too" | **design intent, not as-built** |
| Orleans virtual-actor mapping | **holds on 5 of 6 properties; breaks at the collector** |
| content-addressing settles type identity | settles **logical** identity; leaves **runtime** identity untouched |
| epoch-based addressing | **right shape, and it is git's** — and `ace` already ships that split one layer down |
| git subsumes Orleans | **no** — orthogonal; the join is that an activation key is the pair `(type ZetaId, epoch)` |
| epochs may be wall-clock | **no**, and the tempting surface is already in the tree |

## What the survey found (verified, not assumed)

- **There is no F# type provider in this repository.** No `[<TypeProvider>]`, no `ProvidedTypeDefinition`, no SDK reference. The `TypeProvider` project is a Roslyn `IIncrementalGenerator`. This matters because the entire lazy-materialisation half of the thesis is a property of *erasing type providers*.
- **No runtime code generation at all** — zero `Reflection.Emit` / `AssemblyBuilder` / `ILGenerator`. `AssemblyLoadContext` appears **only in prose**, never under `src/`.
- **`Category.ContentAddress` ships in four oracles; no generated type uses it.** `SchemaRegistry` is keyed by a hand-chosen `string` — that one word is the whole seam.
- **The object/ref split already exists one layer down.** `ace/package-hash.ts` (`blake3` content identity) + `ace/semver.ts` (ranges) + `ace/lockfile.ts` (`package_hash` pins) is git's model, implemented, for packages.
- **The breaking-change primitive already exists** — `SchemaEvolution.Migration.Down: option`, where `Down = None` is a typed, computable "this is not invertible".

## The falsifier

`tests/Tests.CSharp/TypeVirtualization/GeneratedTypeLoadContextIdentityTests.cs` — 3 tests over `Zeta.Core.ZSetW_IntegerRing`, a type that exists *only* because the Roslyn generator ran:

1. loaded into two collectible ALCs it is **two distinct CLR `Type`s** with **identical** `AssemblyQualifiedName`, mutually non-assignable;
2. the same two activations **content-address to one ZetaId** (flip a byte, the id changes) — logical identity and versioning both hold in the same test that shows runtime identity failing;
3. a collectible `AssemblyLoadContext` **does** unload.

Mutation-checked: one retained static reference turns test 3 red with its own message; removing it turns it green. Five consecutive runs, no flake. Full project: **398 passed**.

## The two load-bearing conclusions

> **Orleans virtualizes objects, and objects are GC-granular. Types are not — the smallest collectable unit is an `AssemblyLoadContext`. The mapping breaks at the granularity of the collector, not at the identity of the thing.**

> **An epoch is not new machinery. It is a lockfile — a snapshot of the name→content-hash binding set — made content-addressed and given parents. `ace` already ships the lockfile; the work is lifting it from packages to types.**

And the sharpest consequence of putting the two together: **the ALC identity split is a bug for parallelism and a feature for versioning** — two activations of the same `(id, epoch)` should be interchangeable, two activations of *different* epochs should be distinct — so epochs are what let you tell the cases apart. A worktree is an ALC.

## Hazard flagged

`.claude/rules/local-time-never-enters-the-shared-fold.md` — an epoch must be a **logical** clock. The only "which version applies now" resolver in the repo, `ace/deps.ts` `getResolvedVersion`, defaults to an **ambient `new Date()`**. That is *correct* for deployment scheduling and the function is properly parameterised with an injectable `asOf`; it is recorded because it is exactly the wrong shape to generalise into epochs. Not changed here — it is not broken.

## Honest scope — what this PR leaves

No epoch implementation, no `deps.ts` change, no use-site dependency analysis (named as the largest gap in the adoption story), no `ShivaGc.fs` edits (a sibling agent owns the lifetime/regeneration half; this owns type-materialisation). The ladder of smallest next steps is in §10 of the doc; step 1 — key `SchemaRegistry` by a ContentAddress ZetaId — is a small, well-defined next PR.

Corrections to my brief are stated explicitly in §11, including one owned error: the first draft treated the Orleans identity split as purely a cost, which is one-sided.
