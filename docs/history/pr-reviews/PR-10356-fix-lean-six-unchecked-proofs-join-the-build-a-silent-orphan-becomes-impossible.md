## Description

## Why this is a second PR

#10353 was squash-merged mid-push and captured only its first two commits. The Yang–Baxter certificate and the initial wiring landed; **the orphan guard, the six newly-reachable proofs, and the CI simplification did not.** This is that stranded work, rebased onto current `main`.

## The class

A `.lean` file no `defaultTargets` root reaches transitively is **never compiled**. It can hold a compile error, or a `sorry` on a false theorem, and nothing reports it — while its own header claims verification. Three occurrences on record:

1. `ImaginaryStack` — wired in 2026-08-10, held a compile error **and** a `sorry` on a false theorem (recorded in `lakefile.toml`).
2. `Lean4.MenoBraidedRMatrix` — verified only on the author's machine.
3. `Lean4.GenSelfApplication` — did not compile for ~2 months while its footer read *"SORRY-FREE … Expected: NO warnings, NO errors = oracle passes"*. It had never been run.

## Wired in

`Gen`, `Privacy`, `Safety` had **no `lean_lib` and no root module at all** — `lake build` reached none of them, including a child-floor safety invariant and a split-brain reconciliation convergence proof.

```
Gen      -> Gen.HomoiconicFixpoint
Privacy  -> Privacy.IdentityForcesPrivacy, Privacy.UnboundedNeedsInfinitePrivacy
Safety   -> Safety.Bifurcation, Safety.ChildFloor, Safety.NonRegisterCollapse
```

`lake build`: **8307 jobs, green.**

## The guard

`src/Core.TypeScript/hygiene/lean-orphan-modules.ts` walks `defaultTargets` transitively and fails on:

- an orphan **absent** from the allow-list — the silent-omission case
- a listed entry with an **empty reason** — the `""` escape hatch
- a listed module that is **no longer an orphan** — so the list cannot rot

Wired into `lean-proof.yml` **before** the build so a failure names the cause. It needed a pinned `setup-bun` step: `bun` is not otherwise present in that job, so the guard would have failed with *command not found* — a guard that only errors is not a guard.

## CI simplification

16 of 17 per-file `lake env lean <module>.lean` steps removed — each re-type-checked a module `lake build` now compiles. `ImaginaryStack/ToyModel` keeps its step. The 16 **axiom-audit** steps are untouched; they check axioms, not compilation.

The workflow *separation* stays — `lean-proof.yml` is out-of-band from `gate.yml` because Mathlib's lake cache is multi-GB, and it's path-filtered. Folding it in would make every docs-only PR pay for it.

## Corrections carried in this PR

- An earlier commit message said *"six unchecked proofs"*. Wrong: `Privacy/*` and `Safety/*` each already had a per-file type-check step — they were missing from the build **graph**, not from CI. Genuinely unchecked were **three**.
- `main` had already repaired `GenSelfApplication` with a better verification comment than mine, so the conflict was resolved in main's favour and a duplicate import removed.
- `FinDataProcessing.lean` carries a `sorry` in the gated root. **Not filed as a bug** — the file states it deliberately and explains why: *"a false 'what is proven' header is a WORSE failure mode than a `sorry`, because `sorry` is loud and a missing declaration is not."* That is the discipline working.
