## Description

fix(ci): the required check that never ran reads as green — and 1,162 of 1,219 tests block nothing

Routed to me as a floor-scope hole: PR #14858 reported `fail=0, pend=0` while the
ace DRIFT GATE was red locally, so "no job the PR surfaces ran that test."

THE FLOOR-SCOPE HALF IS FALSE, and I could not confirm it without disproving it.
`bun test src/Core.TypeScript/ace/` is a step of `cross-verify`, `cross-verify` is
named in `gate-required.needs`, and it carries no `if:` and no `continue-on-error`.
Sabotage control, reconstructing the actual defect class — add a `<ProjectReference>`
to `clis/Zeta.Clis.fsproj` and do not regenerate `build-graph.json`:

    baseline        bun test src/Core.TypeScript/ace/   rc=0   703 pass / 0 fail
    under sabotage  bun test src/Core.TypeScript/ace/   rc=1   701 pass / 2 fail
    restored        bun test .../build-graph.test.ts    rc=0    84 pass / 0 fail

The two failures under sabotage are by name the two reported on #14858. The gate
works, it is in the floor, and it would have gone red.

WHAT ACTUALLY HAPPENED IS WORSE. `gate.yml` produced ZERO runs for that branch —
ever. `CI Gate` is the only ruleset with a required_status_checks rule and it names
exactly one context, so zero gate runs means zero required checks, and:

    gh pr checks 14858             rc=0   6 pass / 0 fail / 0 pending
    gh pr checks 14858 --required  rc=1   "no required checks reported"

Both captured directly, not through a pipe. The bare form answers a different
question than the one being asked — "did everything that reported, pass" instead of
"did everything that must report, pass" — and with nothing required reported the two
diverge completely, with the wrong one green.

POPULATION, NOT ANECDOTE: of 42 open PRs, four carry no `gate (required)` at all —
#12058, #12066, #12321, #14858.

THE SURVEY, WHICH IS THE LARGER FINDING. Of 1,219 bun-discoverable tracked test
files, 57 (4.7%) are executed by a job whose red blocks a merge; 1,162 (95.3%) run
on every PR and block nothing. Zero are unrun — the 23 the existing checker reports
are all declared with reasons, and that surface is healthy. The floor's whole
`bun test` surface is 13 invocations across `cross-verify` and `full-verify`.
Derived, not declared: the floor is parsed out of `gate-required.needs` and every
invocation attributed to its enclosing job, 0 of 62 unattributed.

WHAT THIS LANDS — DETECTION ONLY. Nothing here changes what blocks a merge.

- `required-check-started.ts` already was the right detector for this exact class,
  built in August and scoped by a hard-coded `headRef.startsWith("heartbeat/")` —
  blind to every ordinary PR. Generalised to a `--ref-prefix` parameter defaulting
  to `heartbeat/`; `heartbeatPrsMissingRequiredCheck` stays as that lane's entry
  point so its verdict cannot move by accident. Verified live: heartbeat scope
  rc=0, repo-wide rc=1 naming #14858/#12066/#12058 stalled and #12321 queued, 8.7s.
- The listing became its own falsifier. `gh pr list --limit 50` against 42 open PRs
  was eight PRs from silently measuring a subset and reporting a clean sheet — the
  vacuity class, inside the detector written to name it. A full page now exits 2
  (unmeasured), distinct from 1 (measured absence) and 0 (clean).
- `.github/workflows/pr-gate-presence.yml` — hourly, level-triggered, least
  privilege, SHA-pinned, 5-min runaway cap, ~730 free runner-minutes/month, ABSENT
  FROM THE FLOOR. It re-runs nothing: a workflow_dispatch gate run's checks cannot
  enter a PR rollup (measured, #11182), so a dispatch belt would burn a matrix to
  move nothing.
- The `cross-verify` header comment claiming the job "does not block auto-merge" is
  corrected. It is what made the routed hypothesis credible, and a comment saying a
  gate does not gate is today's defect pointed the other way.

NOT DECIDED HERE. Widening the floor and the permanently-red-check policy are
governance calls with real costs in both directions, written up with six numbered
questions in the design doc rather than settled unilaterally.

Falsifier: reverting the ref-prefix generalisation to the hard-coded `heartbeat/`
turns the new repo-wide test red (18 pass / 1 fail). The heartbeat-scope test is
the defect stated as a test — it asserts the ordinary PR is invisible at the old
scope — so deleting the widening cannot leave the suite green.
