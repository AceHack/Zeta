## Description

The Security tab on `main` reports "Could not process some files due to syntax errors -- a
parse error occurred: Invalid character", and 40 more like it.

THE COST IS THE PART THAT MATTERS. A file CodeQL cannot parse is a file CodeQL does not
analyse -- and a file that is never analysed reports ZERO alerts, which is indistinguishable
from a file that is clean. The scanner looked green on those files because it had been
silently blinded. That is this repository's worst failure class, at repository scale, inside
the tool we rely on to find it everywhere else.

THE CAUSE: raw C0 control bytes in source, every one a DELIBERATE separator or escape written
as a raw byte instead of an escape sequence.

  0x1F  unit separator    liveness-ledger.ts, erasure-derivation.ts, shadow-observer.ts
  0x01  commit separator  oracle-stack-evidence.ts
  0x1B  ANSI escape       AdinkraViz.fs, ClaimLane.fs, SwarmBoardAnsi.fs, ReportTriage.fs
                          and three F# test files

Each is semantically correct and none is load-bearing AS A RAW BYTE: the backslash-u escape is
byte-identical at runtime in TS and F# alike. Verified rather than assumed -- the escaped
`shadow-observer` separator still yields code point 31, and CodeQL now builds a database from
the previously unparseable files with no error.

WHY IT SURVIVED: the audit that exists for exactly this is `audit-no-raw-nul-in-source`, and it
checked ONLY 0x00. Every one of these bytes sat underneath it. It now refuses the whole C0
class plus 0x7F, excluding tab, LF and CR, which are ordinary text.

It went red the moment it was widened -- seven more files it had never been able to see. All
are fixed here, so the audit is green on a tree it can now actually judge.

A NOTE ON THE IRONY, because it is the same defect: the first draft of this commit message was
REFUSED for containing a raw control byte. Writing about the class is not the same as avoiding
it, and the tooling caught the author.

`dotnet build -c Release` 0 warnings / 0 errors. 139 ANSI/Adinkra/Avatar tests pass -- the F#
files changed here are the ones whose subject IS terminal escapes, so they are the strongest
available check that the escapes are equivalent. `bun run typecheck` rc=0.

One file is deliberately NOT in this PR: `corporate/observe-org.ts` carries the same defect but
does not exist on `main` -- it arrives with #17249, and is fixed on that branch instead so this
one stays reviewable against the tree it targets.
