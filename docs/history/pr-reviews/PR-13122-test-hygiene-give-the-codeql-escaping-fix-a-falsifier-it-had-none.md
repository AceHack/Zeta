## Description

**Found by a reviewing agent, not by me:** reverting the metacharacter-escaping fix in `alloyEdges` to the original `.replace(/\./g, "\\.")` left the suite at **47 pass / 0 fail**. A CodeQL HIGH ("Incomplete string escaping") was fixed with nothing able to prove the fix mattered or catch its regression — the vacuity class, pointed at my own work.

## The interesting failure is not the crash — it's the false edge

`alloyEdges` decides **whether a sink has a source**. A pattern that matches text it should not reports a sink as **sourced when it is not** — precisely the false-green this audit exists to prevent. And `producer.id` is parsed out of a Helm valuesObject, so a label carrying a metacharacter is *reachable input*, not a hypothetical.

Two tests, and the second is what keeps the first honest:

- **a `+` in a label must not quantify into a spurious edge.** Under `.`-only escaping the pattern becomes `prometheus\.scrape\.a+\.…`, where `a+` means "one or more `a`" — so it matches `…scrape.aaa.receiver` and invents an edge to a producer nothing references.
- **a literal reference to that same label must still be found** — otherwise the first test could be satisfied by matching nothing, ever.

## A third test was written and removed

Recorded rather than silently dropped: an unbalanced `[` in a label, asserting `new RegExp` does not throw. **It passed under the pre-fix escaping too**, because `a[` followed by `\.` happens to form a *valid* character class. It guarded nothing — and padding a suite whose own header promises every rule is "planted as a mutation and asserted to fail" with a test that cannot fail would have been the same defect this PR is closing.

## Checked, not assumed

Reverting the escaping fix now fails **both** tests (57 → 55 pass / 2 fail) where it previously left the suite green. Restored: 57 pass / 0 fail, `tsc --noEmit` clean.
