## Metered vs unmetered

**Metered:** fw 2.4.1 identity; attestation emits DER X.509 with Yubico OID extensions and `Not-After 9999` / no clock; the firmware parses a caller-supplied DER X.509 template and copies its subject DN (a DER parser in the trusted path); wrapped-import is encrypt-then-parse (tamper rejected); opaque-x509 DER-validated but opaque-data not; audit log hash-chained with a monotonic tick, no on-device time; object namespace is (id,type); reset returns to a known-credential auth key.

**Unmetered (falsifiers named, work items filed):** the SSH-certificate template parser (deepest, backs the NixOS SSH-CA), malformed attestation-template DER, asymmetric-wrap BYOK import, and the dogfood enrol/issue/expire/rotate loop.

## Key custody without a CA

Attestation is a signed capability statement (checkable evidence, not a verdict -- the anti-DVD-drive property). The trust root is unavoidable, so witness it in a transparency log rather than pretend it is absent. The device has **no clock**, so binding expiry must come from agreed cluster phase, never the device (`local-time-never-enters-the-shared-fold`, in hardware). Non-Itron answer: one device per trust domain over a narrow-scoped connector, closed command set, no mediating hub.
