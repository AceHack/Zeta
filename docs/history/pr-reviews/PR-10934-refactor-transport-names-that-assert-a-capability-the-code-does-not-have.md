## Description

## The defect class

**A name that asserts a capability the code does not have.** Today `genomeToAdinkraByte` became
`genomeToParityByte` for exactly this — the name claimed the doubly-even self-dual `[8,4,4]` adinkra
code while the body emitted a single-parity `[8,7,2]` byte. This is the same class, in transport
naming.

Every row below was verified by reading **imports and call sites**, not filenames. Where my finding
differs from the report I was handed, I say so.

### The stub is worse than mislabelled

`SimulatedReticulumLatencyTransport` is the reason this is not a cosmetic pass. It satisfies
`ITransport` completely, never throws, never logs, and returns a latency indistinguishable from a
successful mesh round-trip. Two consequences:

1. A caller who adds it to `OracleTransport.emitAll` gets **silent total data loss** — the reading is
   not serialised and not sent anywhere.
2. Its **fabricated latency propagates into the science.** Under `ρ = 1/(1+L)` a large `L` means high
   Condorcet independence, so the stub takes the **largest weight in the fused posterior** while
   having measured nothing. A stub that merely failed would be safer than one that lies upward.

It is now marked not-implemented at the type, in the module header table, and in its runtime `Name`.
**Implementing it is separate work and is deliberately not done here.**

### The name collision this also dissolves

`ReticulumTransport` named three unrelated things: the Bayesian module, a class in
`OracleTransport.fs:224`, and the TypeScript `discovery/reticulum-transport.ts`. Two remain, and
they are now distinguishable.

## Corrections to the findings I was relaying

Two rows do **not** belong in the defect class, and I would rather say so than round up.

- **`src/Core.TypeScript/discovery/udp-lossy-transport.ts` — correctly named. Not renamed.** The
  "no `node:dgram`, no socket, therefore not a wire" reading is right about the imports and wrong as
  a verdict on the name. `LossyUdpChannel`'s constructor takes an **injected**
  `{broadcast, onMessage}` substrate, and `gossip-mesh-transport.ts:330 lossyUdpMeshTransport()`
  supplies the real UDP socket to it. That is textbook ports-and-adapters and is precisely what §13
  noninterference and DST-determinism *require* — a transport that owned its socket would be the
  defect. Its blast radius is also 86 references across 18 live code files, so even a marginal
  improvement would not have been worth it.
- **`src/Bayesian/ReticulumBusMeter.fs` — name kept.** It is a meter, it says so, and it states its
  own epistemic limit up front. Renaming it reflexively would have been the over-broad move. Its
  *docstring* did overclaim — "the armed readout runs on the actual wire, end to end" — and that
  sentence is withdrawn, because the wire end of it was never attached.

## How broad is the class?

Narrower than expected, and concentrated in F#. I inventoried names asserting capability
(`*Transport`, `*Client`, `*Server`, `*Store`, `*Cache`, `*Socket`) and spot-checked imports:

- **26 TS `*transport*` files — no further instances found.** They are conspicuously self-declaring.
  `fetch-transport.ts` opens with *"the ONE real HttpTransport … the single place the real network is
  crossed"*; `reticulum-transport.ts` states *"the Reticulum core imports no socket"* and cites §13.
- **F# `*Store` / `*Cache` — clean.** The `InMemory*` / `Disk*` / `File*` prefixes are load-bearing and
  accurate; every `Disk*`/`File*` store I checked does real `System.IO`.

So this PR is close to the whole class as it stands today, not a first slice of a large one.
