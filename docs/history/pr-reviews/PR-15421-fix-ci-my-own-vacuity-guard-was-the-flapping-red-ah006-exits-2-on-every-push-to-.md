## Description

`cross-verify (trust-core oracles + ace suite)` has been appearing and disappearing on
`main` all session. I labelled it "pre-existing, not from today's work" three separate
times and moved on. It was mine, and the exit code said so from the start.

MECHANISM, verified rather than inferred:

  - the AH006 step is fed `PR_BODY: ${{ github.event.pull_request.body }}`
  - on a PUSH to main there is no pull request, so PR_BODY is EMPTY
  - `audit-task-zetaid-resolves.ts --stdin` on empty input exits **2** with
    "NO INPUT — found no Task ids to check. This is NOT a pass."
  - measured both ways: empty stdin -> rc=2; a real `Task:` line -> rc=0
  - the step carried NO `if:` guard

The audit's refusal is CORRECT and stays exactly as it is. I built that exit-2 path on
purpose so a check with nothing to check could never read as a check that passed. What
was wrong is that I wired a pull-request-body check into a job that also runs on push,
where empty input is the NORMAL condition rather than a fault. Guard right, wiring wrong.

The fix is `if: github.event_name == 'pull_request'`. That is not widening a check: a
push has no PR body to validate, and the commit trailer is validated separately. Applying
a check only where its input can exist is the opposite of relaxing it.

TWO LESSONS I PAID FOR TWICE OVER:

  1. `exit code 2 is a check that never ran, not one that failed` is already a rule I
     wrote down, and the annotation said "Process completed with exit code 2" the whole
     time. I read the red as a subject failure for hours because I never fetched the
     annotation — the parent run was still in progress, so `gh run view --log-failed`
     refused, and I treated "cannot read the log" as "cannot diagnose".
  2. It passed every local reproduction (all audits rc=0, cross-verify-all 33/33, ace
     suite 724/724) and I recorded that as evidence the failure was environmental. It WAS
     environmental — the environment is "is there a PR" — and that was diagnosable from
     the exit code alone without any reproduction at all.

Controls: `actionlint` clean; empty-vs-real stdin measured in both directions; the other
steps in the job were checked for the same unguarded PR-only pattern.
