# ZetaId cross-verification — what this gate does and does NOT check

**Verified 2026-08-14.** Notes for anyone changing the ZetaId bit layout. A
2026-08-11 read-only audit found two gaps invisible from a green run; both
are closed (Gap 1 = fixture pin; Gap 2 = MUMPS is executed, not just compared).

## The byte-lock holds today

Checked directly, rather than inferred from CI being green: every `expected_hex` in
`vectors.yaml` is present in each oracle's committed output.

| oracle | expected_hex matched |
|---|---|
| TypeScript · F# · C# · Rust · Python · Go · MUMPS | **16 / 16** |

## Gap 1 — `compare.ts` used to ignore `vectors.yaml`

`compare.ts` used to compare the six committed output JSONs **against each
other**, with TypeScript as reference. It never opened `vectors.yaml`.

> **A fully stale but mutually consistent set of outputs passed cleanly.**

That hole is closed. `compare.ts` now loads `vectors.yaml` via the YAML
port and pins every present oracle's `hex` / `crockford` to
`expected_hex` / `expected_crockford` (parse-reject oracles emit the
`rejected` token; the yaml `expected_crockford` stays the illegal
input). Green cross-verify is still *necessary, not sufficient* for a
layout change — per-language suites still have to regenerate outputs —
but a missed regen can no longer hide behind a consistent stale set.

After any layout change, run all six suites so each rewrites its output
— do not rely on `compare.ts` to regenerate a missed one.

## Gap 2 — MUMPS used to be unread

`compare.ts` now loads `mumps-output.json` as a **required** oracle.
A missing file fails closed (assert-don't-skip). The committed output
carries the same 16 fixture keys as the other languages; the stale
`workitem-v1-standard` key is gone.

`mumps_zeta_id.m` is still a hand-rolled packer with the layout hardcoded
(`mumps_zeta_id.m:13-14`). CI now **executes** that file via
`run-mumps.ts` (existing `cross-verify` job + the TS suite). A weight
edit in the routine changes the live hex and turns the gate red.
Regenerate the committed JSON with `bun run-mumps.ts --write` from this
directory.

The two degenerates still give **false confidence** in a layout change:

- `all-zero` — packs to zero under *any* layout, so it constrains nothing;
- `max-128` — built as all-ones directly in `cross-verify.ts:151-153` and never packed at all.

If those are the only vectors still passing, the change is untested. Judge
a layout edit by the 12 packed vectors.

## If you are changing the layout

1. `vectors.yaml` is shared by every oracle and each asserts `expected_hex`. Changing it turns every
   un-updated language red simultaneously — **there is no green intermediate state**, so the layout,
   codecs, fixtures and regenerated outputs must land as one commit.
2. Regenerate outputs by running **all six** suites (`bun test`, `dotnet test`, `cargo test`,
   `pytest`, `go test`), then `bun src/Core.TypeScript/ci/cross-verify-all.ts`.
3. **`mumps-output.json` is regenerated by `bun run-mumps.ts --write`** from this
   directory. CI executes the `.m` and diffs the live pack against the committed
   file — a forgotten regen or a silent weight edit both fail.
4. Ignore `all-zero` and `max-128` when judging whether a change is covered. If they are the only
   vectors still passing, the change is untested.

## Related

- `docs/zeta-id-v1-layout.yaml` — the source of truth; `src/Core.TypeScript/zeta-id/zeta-id-generator.ts`
  regenerates six `.gen` files from it. **Gap 3, closed 2026-08-15**: there used to be no CI gate
  verifying the `.gen` files match the YAML, so an edit without regeneration failed nowhere until a
  codec stopped compiling. `gen-layout-drift.ts` now compares every offset/width in all six lanes
  against the YAML, and `gate.yml`'s blocking `cross-verify` job runs it.
  It was sharper than it read: for **Go and Rust** the phrase "until a codec stops compiling" was
  optimistic, because those codecs compile-and-run in no CI job at all
  (`gate.yml` runs only `go test ./algebra/` and `cargo test … Core.Rust.Observe`, 1 of 36 crates).
  A wrong constant in `zeta_id.gen.go` or `bit_layout.gen.rs` produced no compile error, no test
  failure and no oracle disagreement — because the oracle it would have disagreed with is a JSON
  file committed beside it. Their codec *logic* is still unexecuted: `081M02ZTG2G087G0R002YFR8DJ`.
- `tests/Tests.FSharp/ZetaId/BitLayoutAgreement.Tests.fs` ·
  `tests/Tests.CSharp/ZetaId/BitLayoutAgreementTests.cs` — added 2026-08-11. F#, C# and Rust each
  build the layout by two independent paths (`TopDown` / `BottomUp`); only Rust previously asserted
  they agree, so a half-applied edit in F# or C# produced no compile error and no test failure.
