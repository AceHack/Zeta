## The statement (corrected — ONE OF, not THE)

**A CHIP-8 cart is ONE OF the repo's common sources of meaning** — a meaning-bearing object whose renders are
**projections** (regenerated, never the source). It is **not the sole** source: the **golden vectors** (μένω /
"what remains" / Amara), the **common seed** (S=4), **memory / soulfiles**, and the **proofs** are other
common sources of meaning. The cart is the *executable / homoiconic / render* one.

Within the cart's domain (grounded in code, not metaphor):

- **`src/Core/ShapeRender.fs:15`** — *"cartridge stays the single source: SVG/HTML are pure projections,
  regenerated, never edited."* Renders are views of the cart.
- **`src/Core/CartridgeLaw.fs`** — the cart is **homoiconic**: it carries its own integer laws *in-file*,
  re-checkable in any oracle in a screen of code, so *"the file means the SAME thing everywhere."*
- **`src/Core/SoftEmu.fs`** (cart as a soft ensemble) · **`Chip8Citizen.fs`** (identity from the cart/seed) ·
  **`HtmlCssBinding.fs`** (cart → pure HTML+CSS) · `gen/` emits carts (`gen(gen)===gen`). Each is *the cart
  through a lens.*

## Why it matters

The cart is the concrete carrier of **"Zeta is null; a lens over null = identity"**
([[zeta-is-null-lens-over-null-is-identity-meaning-is-remembered-links-qpg]]) **for the executable/render/sim
domain**: SVG / CSS / soft-emu / citizen / the NCA-sim are lenses projecting a cart. It is also why the
**four-oracle byte-lock** works for cart-derived artifacts — the oracles agree *on the cart*, their outputs
round-trip to it. But meaning in Zeta has **several** common sources; the cart is one of them, and
over-claiming it as *the* source would flatten the golden-vectors / seed / memory / proof sources that stand
beside it.
